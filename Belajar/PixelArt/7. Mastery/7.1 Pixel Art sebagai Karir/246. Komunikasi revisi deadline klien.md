# 246. Komunikasi Revisi Deadline Klien

## Definisi Singkat
Komunikasi revisi dan deadline adalah proses manajemen ekspektasi antara pixel artist dan klien mengenai batasan perubahan aset, jadwal pengerjaan, dan prosedur deliveri.

## Analogi
Seperti kontrak bangunan—arsitek tidak akan mengubah fondasi setelah rumah jadi. Semakin awal klien request perubahan, semakin murah biaya dan waktu revisinya.

## Poin-Poin Penting
- Selalu tentukan jumlah revisi (2-3x) di awal kontrak
- Bedakan revisi minor (warna, posisi 1-2px) dan mayor (ubah pose, animasi baru)
- Dokumentasi setiap revisi via email atau Trello board
- Gunakan milestone pembayaran: DP 30-50%, progress 30%, final
- Jangan lanjut ke step berikutnya sebelum klien approve step sebelumnya
- Deadline mundur karena revisi = charge tambahan
- Klien tidak reply >48 jam? Kirim gentle reminder via DM/email
- Buat changelog agar klien tahu apa yang diubah tiap revisi

## Shortcut & Fitur Aseprite
- **Ctrl+Z / Ctrl+Shift+Z** — Undo/redo untuk kembali ke versi sebelumnya
- **File > Save As > versi_revisi_1.aseprite** — Simpan history file
- **Ctrl+Shift+E** — Export specific frame untuk preview ke klien
- **Layer > Duplicate Layer** — Backup layer sebelum perubahan besar
- **Windows > Timeline** — Track animasi frame untuk revisi terstruktur

## Contoh Kasus Nyata (Step-by-Step)
1. Klien request karakter 32x32 dengan "cape merah, animation idle"
2. Kirim WIP lineart setelah 1 hari, minta feedback
3. Klien bilang "cape-nya ungu, bukan merah" (revisi minor — 1st revision)
4. Ganti warna cape: Select warna merah → Edit > Replace Color → ungu
5. Kirim preview GIF animasi idle (4 frame)
6. Klien request "tambah animasi lari" (revisi mayor — di luar kontrak)
7. Jelaskan: "Ini revisi mayor di luar paket. Tambahan $50 untuk 8 frame walk cycle. Timeline bertambah 3 hari. Setuju?"
8. Jika setuju, kirim invoice tambahan; mulai setelah dibayar
9. Final deliver: .aseprite + .png + .gif via Google Drive
10. Minta testimoni/rating untuk portofolio
