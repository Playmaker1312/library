# 43. Membuat Auth Store — User dan Token Management

## Penjelasan

Auth store adalah **sumber kebenaran** untuk data autentikasi user di seluruh aplikasi. Dibuat menggunakan `defineStore('auth', ...)` dari Pinia. Store ini menyimpan:

- **`user`** — objek user (id, name, email, role, avatar, dll)
- **`accessToken`** — JWT token pend pendek (15 menit) untuk akses API
- **`refreshToken`** — JWT token panjang (7 hari) untuk memperbarui accessToken

Dengan persist ke `localStorage`, data auth tetap ada meskipun halaman di-refresh.

```ts
// stores/auth.ts
import { defineStore } from 'pinia'
import { ref, computed } from 'vue'

export const useAuthStore = defineStore('auth', () => {
  // —— State ——
  const user = ref<User | null>(JSON.parse(localStorage.getItem('user') || 'null'))
  const accessToken = ref<string | null>(localStorage.getItem('accessToken'))
  const refreshToken = ref<string | null>(localStorage.getItem('refreshToken'))

  // —— Getters ——
  const isAuthenticated = computed(() => !!accessToken.value)
  const isAdmin = computed(() => user.value?.role === 'admin')

  // —— Actions ——
  function setAuth(data: { user: User; accessToken: string; refreshToken: string }) {
    user.value = data.user
    accessToken.value = data.accessToken
    refreshToken.value = data.refreshToken

    localStorage.setItem('user', JSON.stringify(data.user))
    localStorage.setItem('accessToken', data.accessToken)
    localStorage.setItem('refreshToken', data.refreshToken)
  }

  function clearAuth() {
    user.value = null
    accessToken.value = null
    refreshToken.value = null

    localStorage.removeItem('user')
    localStorage.removeItem('accessToken')
    localStorage.removeItem('refreshToken')
  }

  return { user, accessToken, refreshToken, isAuthenticated, isAdmin, setAuth, clearAuth }
})

interface User {
  id: number
  name: string
  email: string
  role: 'user' | 'admin'
  avatar?: string
}
```

## Fungsi

Mengelola state autentikasi secara terpusat — satu pintu untuk tahu "siapa user saat ini" dan "apakah user sudah login".

## Cara Implementasi

1. Buat file `stores/auth.ts` seperti kode di atas.
2. Pasang `pinia` dan plugin persist jika menggunakan `pinia-plugin-persistedstate` — atau lakukan persist manual seperti contoh (set/get localStorage langsung).
3. Gunakan di komponen dengan `const auth = useAuthStore()`.
4. Panggil `auth.setAuth(response)` saat login/register sukses.
5. Panggil `auth.clearAuth()` saat logout.

## Analogi — Toko Buku

Auth store seperti **kartu anggota toko buku**. Setelah pelanggan mendaftar dan login, mereka dapat kartu (token). Kartu ini berisi:

- **Foto pelanggan** → `user` (data diri)
- **Nomor anggota** → `accessToken` (identitas untuk akses)
- **Tanggal kadaluarsa** → masa berlaku token

Setiap kali pelanggan mau masuk area anggota (wishlist, profil), mereka tunjukkan kartu ini (`isAuthenticated`). Kalau kartu hilang (`clearAuth` / logout), akses area anggota ditolak.

## Dipakai untuk Apa

- Login form — simpan data setelah berhasil login
- Register form — simpan data langsung setelah daftar
- Router guard — cek apakah user login
- AppHeader — tampilkan avatar/nama user
- Axios interceptor — lampirkan token ke setiap request

## Kesalahan Umum

| Kesalahan | Akibat | Solusi |
|-----------|--------|--------|
| Menyimpan password di store | Bocor via XSS atau devtools | **JANGAN PERNAH simpan password** |
| Lupa persist token | User login, refresh halaman → login lagi | Simpan token + user ke localStorage |
| Menyimpan token di sessionStorage | Token hilang saat tab ditutup | Pakai localStorage |

## Hubungan dengan Materi Sebelumnya

**Level 3 (Poin 31):** Di Level 3, router guard cek `isAuthenticated = false` — palsu, tidak ada store. Sekarang `isAuthenticated` dari auth store yang **NYATA**: user login → token disimpan → `isAuthenticated` jadi `true`.

**Bagian I (Axios+API):** Store ini bekerja sama dengan `authApi` dari Bagian I. API login/register mengembalikan user + tokens → disimpan ke store via `setAuth()`.

Buat action baru `updateProfile(data: Partial<User>)` di auth store yang memperbarui data user tanpa mengubah token. Pastikan localStorage ikut terupdate.

function updateProfile(data: Partial<User>) {
  if (!user.value) return
  user.value = { ...user.value, ...data }
  localStorage.setItem('user', JSON.stringify(user.value))
}

### Soal 2

Mengapa `isAuthenticated` dibuat sebagai `computed` bukan `ref`? Jelaskan dengan analogi toko buku.

<details>
<summary>Jawaban</summary>

Karena nilai `isAuthenticated` **bergantung** pada `accessToken`. Jika `accessToken` berubah (login/logout), `isAuthenticated` otomatis berubah tanpa perlu di-set manual.

**Analogi toko buku:** `isAuthenticated` seperti lampu indikator "KARTU TERDETEKSI" di pintu area anggota. Lampu ini otomatis menyala saat kartu (accessToken) ditempelkan, dan otomatis mati saat kartu diambil. Tidak ada tombol manual untuk menyalakan/mematikannya.
</details>
