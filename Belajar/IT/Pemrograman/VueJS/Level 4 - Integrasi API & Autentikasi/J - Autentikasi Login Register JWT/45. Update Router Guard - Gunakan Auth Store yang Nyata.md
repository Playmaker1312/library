# 45. Update Router Guard — Gunakan Auth Store yang Nyata

## Penjelasan

Router guard di-upgrade dari **guard palsu** (Level 3) menjadi **guard nyata** yang membaca `authStore.isAuthenticated`. Dua meta field digunakan:

- **`requiresAuth: true`** — halaman yang hanya bisa diakses user login. Jika belum login → redirect ke `/login?redirect=...`
- **`guestOnly: true`** — halaman yang hanya bisa diakses user belum login (login, register). Jika sudah login → redirect ke `/`

```ts
// router/index.ts
import { createRouter, createWebHistory } from 'vue-router'
import { useAuthStore } from '@/stores/auth'

const router = createRouter({
  history: createWebHistory(),
  routes: [
    {
      path: '/profile',
      component: () => import('@/views/ProfileView.vue'),
      meta: { requiresAuth: true },
    },
    {
      path: '/login',
      component: () => import('@/views/LoginView.vue'),
      meta: { guestOnly: true },
    },
    {
      path: '/register',
      component: () => import('@/views/RegisterView.vue'),
      meta: { guestOnly: true },
    },
    {
      path: '/',
      component: () => import('@/views/HomeView.vue'),
    },
  ],
})

router.beforeEach((to, from, next) => {
  const auth = useAuthStore()

  if (to.meta.requiresAuth && !auth.isAuthenticated) {
    return next({ path: '/login', query: { redirect: to.fullPath } })
  }

  if (to.meta.guestOnly && auth.isAuthenticated) {
    return next({ path: '/' })
  }

  next()
})

export default router
```

## Fungsi

Proteksi route berdasarkan status autentikasi **nyata** — cek token yang benar-benar ada di store, bukan variabel palsu. User yang belum login tidak bisa mengakses halaman protected, user yang sudah login tidak bisa mengakses halaman login.

## Cara Implementasi

1. Tambahkan `meta: { requiresAuth: true }` pada route yang perlu proteksi.
2. Tambahkan `meta: { guestOnly: true }` pada route login/register.
3. Update `router.beforeEach` untuk membaca `authStore.isAuthenticated`.
4. Simpan `redirect` query agar user diarahkan kembali setelah login.
5. Hapus variabel `isAuthenticated` palsu dari Level 3.

## Analogi — Toko Buku

**Dulu (Level 3):** Satpam di depan area anggota pura-pura ngecek kartu — semua dibilang "belum punya kartu" (`isAuthenticated = false`). Semua pengunjung ditolak.

**Sekarang:** Satpam punya **alat pembaca kartu ASLI**:

- Pengunjung tempel kartu → `authStore.isAuthenticated`
- Kartu valid → silakan masuk ke area anggota (`requiresAuth`)
- Kartu tidak valid → arahkan ke meja registrasi (`guestOnly` — redirect ke `/login`)
- Sudah punya kartu tapi mau ke meja registrasi lagi → "Anda sudah punya kartu, silakan masuk" (`guestOnly` + sudah login → redirect ke home)

## Dipakai untuk Apa

- Proteksi halaman profil, wishlist, dashboard, admin
- Cegah user login akses halaman login/register
- Sistem role-based nanti (`meta.requiresAdmin`)

## Kesalahan Umum

| Kesalahan | Akibat | Solusi |
|-----------|--------|--------|
| Infinite redirect loop | Guard redirect ke login → login redirect ke guard lagi | Pastikan halaman login TIDAK punya `requiresAuth` |
| Lupa pass `query.redirect` | User login tidak diarahkan ke halaman asal | Selalu kirim `query: { redirect: to.fullPath }` |
| Guard dipanggil sebelum Pinia siap | Error `useAuthStore()` di luar setup | Panggil di dalam `beforeEach`, bukan di root file |
| GuestOnly tidak diterapkan | User login bisa akses halaman login | Tambahkan `meta.guestOnly` pada route login/register |

## Hubungan dengan Materi Sebelumnya

**Poin 44:** Sekarang user bisa login, guard harus cek token beneran. Tanpa guard, user bisa akses halaman profil tanpa login.

**Level 3 (Poin 31):** Guard Level 3 adalah "pura-pura" — semua route dianggap belum login. Sekarang guard sungguhan: `isAuthenticated` dari auth store yang benar-benar mengecek token di localStorage.

**Poin 43:** Guard membaca `authStore.isAuthenticated` — computed yang bergantung pada `accessToken`. Jika token ada → `isAuthenticated = true` → akses diizinkan.

### Soal 2

Apa yang menyebabkan infinite redirect loop pada router guard? Berikan contoh skenario dan cara memperbaikinya.

<details>
<summary>Jawaban</summary>

**Penyebab:** Guard mengarahkan ke halaman yang juga memicu guard yang sama.

**Contoh skenario:**
1. Route `/dashboard` punya `requiresAuth: true`
2. Route `/login` punya `requiresAuth: true` (SALAH!)
3. User belum login buka `/dashboard` → guard redirect ke `/login`
4. Guard cek `/login` → ternyata juga `requiresAuth: true` → redirect ke `/login` lagi → **LOOP!**

**Cara memperbaiki:** Route login/register harus punya `guestOnly: true`, bukan `requiresAuth`. Guard `guestOnly` mengizinkan akses jika user belum login, dan redirect ke home jika sudah login — tidak pernah redirect ke login lagi.

**Analogi toko buku:** Satpam yang bingung — menyuruh pengunjung ke "meja registrasi", tapi meja registrasinya juga dijaga satpam yang sama yang menyuruh ke meja registrasi lagi. Lingkaran setan!
</details>
