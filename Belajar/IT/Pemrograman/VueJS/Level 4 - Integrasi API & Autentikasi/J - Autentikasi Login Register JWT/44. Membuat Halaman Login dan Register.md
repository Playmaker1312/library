# 44. Membuat Halaman Login dan Register

## Penjelasan

Halaman **Login** dan **Register** adalah gerbang masuk ke aplikasi. Dibuat sebagai dua view terpisah dengan form validasi dan error handling.

**LoginView:** form email + password + tombol "Masuk".  
**RegisterView:** form name + email + password + confirmPassword + tombol "Daftar".

Keduanya menggunakan `useRouter()` + `useRoute()` untuk redirect, dan `useAuthStore()` untuk menyimpan data setelah sukses.

```vue
<!-- views/LoginView.vue -->
<script setup lang="ts">
import { ref } from 'vue'
import { useRouter, useRoute } from 'vue-router'
import { useAuthStore } from '@/stores/auth'
import { authApi } from '@/api/auth'

const router = useRouter()
const route = useRoute()
const auth = useAuthStore()

const form = ref({ email: '', password: '' })
const error = ref('')
const loading = ref(false)

async function handleLogin() {
  error.value = ''
  loading.value = true
  try {
    const res = await authApi.login(form.value)
    auth.setAuth(res.data)
    router.push((route.query.redirect as string) || '/')
  } catch (err: any) {
    error.value = err.response?.data?.message || 'Email atau password salah'
  } finally {
    loading.value = false
  }
}
</script>

<template>
  <form @submit.prevent="handleLogin">
    <h1>Masuk</h1>
    <p v-if="error" class="error">{{ error }}</p>
    <input v-model="form.email" type="email" placeholder="Email" required />
    <input v-model="form.password" type="password" placeholder="Password" required />
    <button :disabled="loading">{{ loading ? 'Memproses...' : 'Masuk' }}</button>
    <p>Belum punya akun? <RouterLink to="/register">Daftar</RouterLink></p>
  </form>
</template>
```

```vue
<!-- views/RegisterView.vue -->
<script setup lang="ts">
import { ref } from 'vue'
import { useRouter } from 'vue-router'
import { useAuthStore } from '@/stores/auth'
import { authApi } from '@/api/auth'

const router = useRouter()
const auth = useAuthStore()

const form = ref({ name: '', email: '', password: '', confirmPassword: '' })
const error = ref('')
const loading = ref(false)

async function handleRegister() {
  error.value = ''
  if (form.value.password !== form.value.confirmPassword) {
    error.value = 'Konfirmasi password tidak cocok'
    return
  }
  loading.value = true
  try {
    const res = await authApi.register({
      name: form.value.name,
      email: form.value.email,
      password: form.value.password,
    })
    auth.setAuth(res.data)
    router.push('/')
  } catch (err: any) {
    error.value = err.response?.data?.message || 'Registrasi gagal'
  } finally {
    loading.value = false
  }
}
</script>

<template>
  <form @submit.prevent="handleRegister">
    <h1>Daftar</h1>
    <p v-if="error" class="error">{{ error }}</p>
    <input v-model="form.name" placeholder="Nama Lengkap" required />
    <input v-model="form.email" type="email" placeholder="Email" required />
    <input v-model="form.password" type="password" placeholder="Password" required />
    <input v-model="form.confirmPassword" type="password" placeholder="Konfirmasi Password" required />
    <button :disabled="loading">{{ loading ? 'Memproses...' : 'Daftar' }}</button>
    <p>Sudah punya akun? <RouterLink to="/login">Masuk</RouterLink></p>
  </form>
</template>
```

## Fungsi

Gerbang masuk aplikasi — user bisa login (kembali) atau mendaftar sebagai anggota baru. Setelah sukses, user diarahkan ke halaman tujuan.

## Cara Implementasi

1. Buat `views/LoginView.vue` dan `views/RegisterView.vue`.
2. Daftarkan route `/login` dan `/register` di router.
3. Buat `api/auth.ts` dengan fungsi `login()` dan `register()` yang memanggil endpoint API.
4. Panggil `auth.setAuth()` setelah sukses.
5. Tampilkan error dari API (email sudah terdaftar, password salah, dll).

## Analogi — Toko Buku

**Halaman Login** seperti **meja registrasi** di pintu masuk toko:

- Pengunjung isi formulir (email + password)
- Petugas cek ke database (`authApi.login`)
- Kalau cocok → beri kartu anggota (`setAuth`) dan antar ke tujuan (`redirect`)
- Kalau salah → tampilkan pesan error sopan ("Email atau password salah")

**Halaman Register** seperti **meja pendaftaran anggota baru**:

- Isi data diri (nama, email, password)
- Petugas buatkan kartu anggota baru
- Dapat kartu langsung, tidak perlu login lagi

**Conditional link:** "Belum punya akun? Daftar" / "Sudah punya akun? Masuk" — seperti ramuan di toko yang mengarahkan pengunjung ke meja yang sesuai.

## Dipakai untuk Apa

- Form login standar aplikasi
- Form registrasi user baru
- Login admin terpisah (bisa pakai role-based guard nanti)

## Kesalahan Umum

| Kesalahan | Akibat | Solusi |
|-----------|--------|--------|
| Tidak handle redirect query | User login tetap di halaman login | Gunakan `route.query.redirect` |
| Error message tidak user-friendly | User bingung | Tampilkan dari API atau fallback pesan yang jelas |
| Tidak validasi confirmPassword | User bisa daftar dengan password beda | Cek di client sebelum kirim |
| Loading state tidak ada | User klik ganda → submit 2x | Disabled button saat loading |

## Hubungan dengan Materi Sebelumnya

**Poin 43:** Auth store adalah **tujuan akhir** — login/register sukses → data user dan token disimpan ke store via `setAuth()`. Tanpa auth store, login tidak berguna — user login tapi tidak ada data tersimpan.

**Bagian I (Axios):** `authApi.login()` dan `authApi.register()` menggunakan instance Axios yang sudah dikonfigurasi di Bagian I (base URL, header, dll).

Buat validasi client-side di RegisterView: password minimal 8 karakter, mengandung minimal 1 huruf kapital dan 1 angka. Tampilkan error spesifik jika tidak sesuai.

function validatePassword(password: string): string | null {
  if (password.length < 8) return 'Password minimal 8 karakter'
  if (!/[A-Z]/.test(password)) return 'Password harus mengandung huruf kapital'
  if (!/[0-9]/.test(password)) return 'Password harus mengandung angka'
  return null
}

### Soal 2

Mengapa di LoginView kita menggunakan `route.query.redirect` untuk redirect? Apa yang terjadi jika redirect dihilangkan?

<details>
<summary>Jawaban</summary>

`query.redirect` menyimpan URL halaman asal yang ingin diakses user sebelum dicegat router guard. Contoh: user buka `/profile`, guard redirect ke `/login?redirect=%2Fprofile`. Setelah login, user langsung diarahkan ke `/profile`.

**Jika redirect dihilangkan:** user login akan selalu diarahkan ke halaman default (misal `/`), meskipun awalnya mereka ingin mengakses halaman tertentu. Ini pengalaman buruk karena user harus navigasi manual kembali ke halaman tujuan.

**Analogi toko buku:** Pengunjung ingin ke area anggota (profil), tapi dicegat satpam karena belum punya kartu. Satpam bilang "Silakan ke meja registrasi dulu" dan mencatat "setelah registrasi, antar ke area anggota" (`redirect`). Kalau catatan ini hilang, pengunjung akan diantar ke lobi utama (home) meskipun tujuannya area anggota.
</details>
