# 69. CI/CD dengan GitHub Actions

## Penjelasan

CI/CD (Continuous Integration / Continuous Deployment) adalah praktik di mana setiap perubahan kode otomatis diuji dan di-deploy. GitHub Actions adalah platform workflow automation bawaan GitHub yang memungkinkan kita membuat pipeline CI/CD tanpa perlu alat pihak ketiga.

Alur CI/CD:

1. Developer push kode ke branch `main`
2. GitHub Actions menjalankan **test** (type-check, lint, unit test)
3. Jika test lulus, jalankan **E2E test**
4. Jika semua test lolos, **deploy** ke Vercel
5. Jika gagal di salah satu tahap — deploy tidak terjadi, developer mendapat notifikasi

## Fungsi

- **Quality gate** — kode yang rusak tidak akan sampai ke production
- **Otomatis** — tidak perlu manual build + deploy
- **Parallel jobs** — test berjalan paralel untuk efisiensi
- **Traceability** — setiap deploy tercatat berasal dari commit mana
- **Feedback cepat** — developer tahu dalam hitungan menit jika ada yang salah

## Cara Implementasi / Kode

### 1. Buat struktur folder

```
.github/
  workflows/
    ci.yml
```

### 2. File `.github/workflows/ci.yml`

```yaml
name: CI/CD Pipeline

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true

env:
  NODE_VERSION: 20

jobs:
  test:
    name: Quality Check
    runs-on: ubuntu-latest

    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Type check
        run: npm run type-check

      - name: Lint
        run: npm run lint

      - name: Unit tests
        run: npm run test -- --coverage

      - name: Upload coverage
        uses: actions/upload-artifact@v4
        with:
          name: coverage
          path: coverage/

  e2e:
    name: E2E Tests
    needs: test
    runs-on: ubuntu-latest

    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Run E2E tests
        run: npm run test:e2e
        env:
          VITE_API_BASE_URL: ${{ secrets.VITE_API_BASE_URL }}

  deploy:
    name: Deploy to Vercel
    needs: e2e
    runs-on: ubuntu-latest
    if: github.ref == 'refs/heads/main'

    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}
          cache: 'npm'

      - name: Install Vercel CLI
        run: npm i -g vercel

      - name: Deploy to Vercel
        run: vercel --prod --token=${{ secrets.VERCEL_TOKEN }}
```

### 3. Set secrets di GitHub

Buka repository → **Settings → Secrets and variables → Actions**, tambahkan:

| Secret | Nilai |
|--------|-------|
| `VITE_API_BASE_URL` | URL API production |
| `VERCEL_TOKEN` | Token dari Vercel dashboard (Account → Tokens) |

### 4. Script `package.json` yang diperlukan

Pastikan `package.json` memiliki script berikut:

```json
{
  "scripts": {
    "type-check": "vue-tsc --noEmit",
    "lint": "eslint src --max-warnings 0",
    "test": "vitest run",
    "test:e2e": "playwright test",
    "build": "vite build"
  }
}
```

### 5. Cache node_modules (opsional — sudah di-handle oleh `actions/setup-node@v4` dengan `cache: 'npm'`)

## Analogi — Toko Buku

CI/CD seperti **sistem quality control** di toko buku. Setiap kali ada pengiriman barang baru (push ke main), barang melewati 3 checkpoint:

1. **QC Umum** (`test` job) — cek apakah barang sesuai spesifikasi: buku tidak robek (type-check), label harga tidak salah (lint), isi halaman lengkap (unit test).

2. **QC Detail** (`e2e` job) — uji coba barang secara langsung: buka buku, baca halaman, pastikan tidak ada halaman terbalik (E2E test simulasi user).

3. **Kalau lolos semua** — barang masuk ke etalase (`deploy` ke Vercel). Pengunjung bisa membeli.

Kalau gagal di salah satu checkpoint, barang ditolak dan tim gudang diberi tahu — **barang cacat tidak akan pernah sampai ke pelanggan**.

**Parallel jobs**: seperti memiliki 3 tim QC yang bekerja bersamaan — tidak perlu menunggu satu per satu.

## Dipakai untuk Apa

- **Setiap project Vue.js production** — memastikan kode berkualitas sebelum deploy
- **Team collaboration** — beberapa developer push ke repo yang sama
- **Monorepo** — CI bisa diatur untuk build hanya bagian yang berubah
- **Compliance / audit** — setiap deploy tercatat, bisa dilacak ke commit tertentu

## Kesalahan Umum

| Kesalahan | Akibat | Solusi |
|-----------|--------|--------|
| Cache node_modules tidak di-setup | Install dependency tiap kali (lambat — 2-3 menit) | Gunakan `cache: 'npm'` di `actions/setup-node` |
| Secret/API key hardcode di workflow | Ekspos credential ke publik | Gunakan GitHub Secrets (`${{ secrets.XXX }}`) |
| Semua branch di-deploy | Preview deployment untuk branch tidak penting | Gunakan kondisi `if: github.ref == 'refs/heads/main'` |
| Test tidak dijalankan sebelum deploy | Kode error sampai ke production | Gunakan `needs:` agar deploy hanya jalan jika test lulus |
| `npm ci` vs `npm install` | `npm install` bisa mengubah `package-lock.json` | Selalu gunakan `npm ci` di CI (lebih cepat, deterministik) |

## Hubungan dengan Materi Sebelumnya

Di Poin 68, deploy dilakukan manual via Vercel dashboard. Sekarang semuanya otomatis — push ke GitHub → pipeline berjalan → deploy ke Vercel tanpa perlu menyentuh dashboard.

Ini melengkapi siklus development: kode ditulis (Level 1-5), diuji (Level 6), di-build (Poin 67), di-deploy manual (Poin 68), dan akhirnya diotomatisasi dengan CI/CD (Poin 69).

## Soal Latihan

### Soal 1

Seorang developer menambahkan secret token langsung di file `ci.yml` sebagai berikut:

```yaml
- name: Deploy
  run: vercel --prod --token=abc123secret
```

Apa masalahnya dan bagaimana cara yang benar?

<details>
<summary>Jawaban</summary>
Token rahasia ter-expose di repository — siapa pun yang memiliki akses ke repo bisa melihatnya. Selain itu, file workflow ada di publik (jika repo publik). Cara yang benar: simpan token sebagai **GitHub Secret**, lalu panggil dengan `${{ secrets.VERCEL_TOKEN }}`. Token tidak akan muncul di log workflow, dan hanya bisa digunakan oleh workflow itu sendiri.
</details>

### Soal 2

Pipeline CI/CD memiliki 3 job: test, e2e, dan deploy. Seorang push kode baru. Test gagal karena lint error, tapi anehnya deploy tetap berjalan. Apa yang salah dengan konfigurasi workflow?

<details>
<summary>Jawaban</summary>
Job `deploy` kemungkinan tidak memiliki properti `needs:` yang benar, atau properti tersebut tidak merantai ke job test. Akibatnya deploy berjalan independen meskipun test gagal. Solusi: pastikan konfigurasi `needs` berantai dengan benar:
```yaml
test:
  ...
e2e:
  needs: test
deploy:
  needs: e2e
```
Dengan rantai ini, jika test gagal, maka e2e dan deploy tidak akan dijalankan.
</details>
