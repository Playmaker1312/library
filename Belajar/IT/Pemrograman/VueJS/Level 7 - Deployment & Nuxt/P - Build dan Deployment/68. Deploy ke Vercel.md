# 68. Deploy SPA ke Vercel

## Penjelasan

Vercel adalah platform deploy termudah untuk Vue SPA. Cukup hubungkan repository GitHub, Vercel akan otomatis mendeteksi framework (Vite), menentukan build command, dan men-deploy aplikasi.

Hal penting yang perlu dikonfigurasi:

- **Framework preset** — Vercel mendeteksi Vite secara otomatis
- **Build command** — `npm run build`
- **Output directory** — `dist`
- **SPA fallback** — semua route diarahkan ke `index.html` (agar tidak 404 saat refresh)
- **Environment variables** — di-set melalui Vercel dashboard
- **Custom domain** — (opsional) menghubungkan domain sendiri

## Fungsi

- Aplikasi live di internet dan bisa diakses siapa saja
- Auto-deploy setiap kali ada push ke branch tertentu
- HTTPS otomatis (tanpa konfigurasi)
- Preview deployment untuk setiap PR
- Integration dengan Git — mudah rollback

## Cara Implementasi / Kode

### 1. Buat `vercel.json` di root project

```json
{
  "framework": "vite",
  "buildCommand": "npm run build",
  "outputDirectory": "dist",
  "rewrites": [
    {
      "source": "/(.*)",
      "destination": "/index.html"
    }
  ]
}
```

Baris `rewrites` inilah yang menangani SPA fallback — semua request diarahkan ke `index.html`.

### 2. Deploy via Vercel Dashboard

1. Push kode ke GitHub
2. Buka [vercel.com](https://vercel.com), login dengan GitHub
3. Klik **Add New → Project**
4. Pilih repository Vue.js kamu
5. Vercel otomatis mendeteksi framework: Vite
6. Tambahkan environment variables:

| Variable | Value |
|----------|-------|
| `VITE_API_BASE_URL` | `https://api.bukuku.com/v1` |
| `VITE_AUTH_DOMAIN` | `auth.bukuku.com` |
| `VITE_SENTRY_DSN` | `https://xxxxx@sentry.io/123` |

7. Klik **Deploy**

### 3. Deploy via Vercel CLI

```bash
npm i -g vercel

# Login
vercel login

# Deploy
vercel --prod
```

### 4. Setup custom domain (opsional)

1. Di dashboard Vercel, buka project → **Domains**
2. Masukkan domain (misal: `bukuku.com`)
3. Ikuti petunjuk untuk mengupdate DNS (arahkan nameserver ke Vercel)
4. Vercel urus SSL certificate otomatis

### 5. Environment variables di Vercel

Environment variables harus di-set di **dua tempat**:

- **Production**: dipakai saat build dan runtime production
- **Preview**: dipakai untuk preview deployment tiap PR

Cara set via Vercel CLI:

```bash
vercel env add VITE_API_BASE_URL production
vercel env add VITE_API_BASE_URL preview
```

Vercel seperti **penyewa tempat toko** yang menyediakan lokasi strategis di pusat perbelanjaan internet. Kamu tinggal bawa barang (kodemu), mereka siapkan rak, kasir, dan papan nama (server, CDN, SSL).

**GitHub → Vercel auto-deploy** seperti: setiap kali ada perubahan di gudang (push ke GitHub), toko otomatis di-update — pegawai tinggal push, Vercel urus sisanya.

**vercel.json dengan rewrites** memastikan semua pintu masuk (route) mengarah ke pintu utama (`index.html`). Jadi pengunjung yang buka `/books/clean-code` langsung diarahkan ke aplikasi Vue — tidak dapat error 404.

## Dipakai untuk Apa

- **Deploy production** — aplikasi Vue.js live di internet
- **Preview deployment** — cek tiap PR sebelum merge (Vercel bikin URL unik tiap PR)
- **Staging environment** — branch `staging` auto-deploy ke URL staging
- **Team collaboration** — semua anggota tim bisa lihat hasil deploy

## Kesalahan Umum

| Kesalahan | Akibat | Solusi |
|-----------|--------|--------|
| Lupa setup SPA fallback | Refresh halaman selain `/` → 404 | Tambahkan `rewrites` di `vercel.json` |
| Environment variables tidak di-set | Build error di Vercel (tapi sukses di lokal) | Validasi env di build, set via dashboard |
| Mengabaikan preview deployment | PR yang sudah di-merge ternyata broken di production | Cek preview URL setiap PR |
| Build command salah | Output folder tidak sesuai | Pastikan `buildCommand: "npm run build"` dan `outputDirectory: "dist"` |

## Soal Latihan

### Soal 1

Setelah deploy ke Vercel, halaman utama (`/`) berfungsi, tapi saat pengguna merefresh halaman `/books/clean-code` muncul error 404. Apa penyebabnya dan bagaimana cara memperbaikinya?

<details>
<summary>Jawaban</summary>
Server Vercel mencoba mencari file `books/clean-code` di folder `dist/` yang tidak ada (karena Vue adalah SPA — hanya ada `index.html`). Solusi: tambahkan rewrite rule di `vercel.json`:
```json
{
  "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }]
}
```
Semua request akan diarahkan ke `index.html`, dan Vue Router akan menangani routing selanjutnya.
</details>

### Soal 2

Build berhasil di lokal (`npm run build` sukses), tapi gagal di Vercel dengan error `'VITE_API_BASE_URL' is not defined`. Apa yang salah?

<details>
<summary>Jawaban</summary>
Environment variable `VITE_API_BASE_URL` ada di file `.env.local` tapi tidak di-set di Vercel dashboard. Vercel tidak membaca file `.env.local` secara otomatis. Solusi:
1. Buka Vercel dashboard → project → Settings → Environment Variables
2. Tambahkan `VITE_API_BASE_URL` dengan value yang sesuai
3. Redeploy

Sebagai pencegahan, gunakan validasi env seperti di Poin 67 agar error langsung terdeteksi saat build — baik di lokal maupun di CI.
</details>
