# 76. Deploy Nuxt ke Vercel — SSR di Production

## Penjelasan

Vercel adalah platform deployment yang paling populer untuk Nuxt. Vercel mendeteksi Nuxt secara otomatis dan mengatur serverless functions untuk SSR.

**Perbedaan dengan deploy SPA (Level 6, poin 68):**

| Aspek | SPA (Vue) | Nuxt SSR |
|---|---|---|
| Build output | File statis (`dist/`) | Serverless functions + statis |
| `vercel.json` | Butuh `rewrites` untuk SPA fallback | Tidak perlu — Nuxt sudah handle routing |
| Konfigurasi | Build command: `npm run build` | Build command: `npm run build` (sama) |
| Output directory | `dist` | `.output/public` (otomatis) |
| Server | Tidak ada | Vercel serverless functions otomatis |

---

## Fungsi

- Nuxt SSR berjalan di production dengan serverless functions
- Halaman cepat, SEO optimal — konten di-render di server
- Skalabilitas otomatis — Vercel menangani traffic spike
- Edge Network — cache global untuk response cepat

## Cara Implementasi

### 1. Setup di Vercel Dashboard

#### Opsi A: Deploy via Git (rekomendasi)

1. Push project Nuxt ke GitHub/GitLab/Bitbucket
2. Buka [vercel.com](https://vercel.com) → Import Repository
3. Vercel otomatis mendeteksi Nuxt 3
4. Klik **Deploy**

#### Opsi B: Deploy via CLI

```bash
# Install Vercel CLI
npm i -g vercel

# Login
vercel login

# Deploy dari folder project
cd bookstore-nuxt
vercel --prod
```

### 2. Environment Variables

Di Vercel dashboard → Project Settings → Environment Variables:

```
# Server-side (tidak terekspos ke client)
BACKEND_API_URL=https://api.bookstore.com
API_SECRET=supersecretkey

# Client-side (prefix NUXT_PUBLIC_ atau di public.runtimeConfig)
NUXT_PUBLIC_SITE_URL=https://bookstore.vercel.app
```

Di `nuxt.config.ts`:

```ts
export default defineNuxtConfig({
  runtimeConfig: {
    apiSecret: '', // dari env API_SECRET
    backendUrl: '', // dari env BACKEND_API_URL
    public: {
      siteUrl: '' // dari env NUXT_PUBLIC_SITE_URL
    }
  }
})
```

### 3. Konfigurasi Node Version

Vercel terkadang menggunakan Node.js versi lama. Set di `package.json`:

```json
{
  "engines": {
    "node": "18.x"
  }
}
```

Atau set environment variable di Vercel:

```
NODE_VERSION=18
```

### 4. Verifikasi Deployment

Setelah deploy selesai:

1. Buka URL Vercel yang diberikan
2. Klik kanan → **View Page Source**
3. Scroll dan pastikan **konten buku** ada di HTML (bukan hanya `<div id="__nuxt"></div>`)
4. Cek meta tags — title dan description sesuai dengan halaman

### 5. Test SEO

```bash
# Cek meta tags (contoh)
curl https://bookstore.vercel.app | grep -o '<title>[^<]*</title>'
curl https://bookstore.vercel.app/books/1 | grep -o '<meta name="description"[^>]*>'
```

### 6. Custom Domain

Di Vercel dashboard → Project → Domains → tambah domain `bookstore.com`

Update `nuxt.config.ts`:

```ts
export default defineNuxtConfig({
  runtimeConfig: {
    public: {
      siteUrl: process.env.NUXT_PUBLIC_SITE_URL || 'https://bookstore.com'
    }
  }
})
```

## Analogi — Toko Buku

**Grand opening TOKO BARU** — versi Nuxt dari BookStore.

Toko ini lebih modern:
- **Etalase sudah terisi dari luar** (SSR) — Google bisa lihat isi toko
- **Papan nama jelas** (SEO) — setiap halaman punya title dan deskripsi
- **Ada back office** (server API) — pegawai tidak perlu bawa kunci gudang kemana-mana

Proses bukanya juga beda dengan SPA:

| SPA (Level 68) | Nuxt SSR (Level 76) |
|---|---|
| Bangun toko dari kardus — barang dijejer belakangan | Toko sudah jadi lengkap dengan etalase terisi |
| Google cuma lihat pintu tertutup | Google lihat semua pajangan dari luar |
| Pengunjung pertama lihat "Toko baru buka, barang masih di gudang" (loading) | Pengunjung pertama langsung lihat barang |

Vercel mendeteksi Nuxt dan otomatis menyiapkan **pegawai server** (serverless functions) yang melayani setiap pengunjung. Setiap kali seseorang datang, pegawai server menyiapkan etalase (render HTML di server) sebelum pintu dibuka. Pengunjung tidak pernah melihat toko kosong.

## Kesalahan Umum

| Kesalahan | Akibat | Solusi |
|---|---|---|
| Lupa set `NODE_VERSION` | Build gagal — Nuxt 3 butuh Node 18+ | Set env `NODE_VERSION=18` atau di `package.json` |
| Runtime config server tidak di-set | Error di server — `undefined` | Set environment variable di Vercel dashboard |
| Mengira environment variable otomatis terbaca | `process.env.X` undefined | Gunakan `runtimeConfig` — Nuxt menerjemahkan env vars otomatis |
| Pakai `VITE_` prefix dari SPA | Tidak terbaca di Nuxt | Nuxt tidak pakai `VITE_` — pakai `runtimeConfig` + env |
| Build berhasil tapi konten kosong | Halaman statis, bukan SSR | Cek `nuxt.config.ts` — pastikan tidak forced `ssr: false` |
| Lupa ganti `siteUrl` di OG tags | OG image broken di production | Gunakan `runtimeConfig.public.siteUrl` yang di-set dari env |

## Hubungan dengan Materi Sebelumnya

**Poin 68 (Deploy SPA):** Di Level 7, poin 68, kita deploy SPA ke Vercel. Saat itu kita butuh `vercel.json` dengan `rewrites` agar SPA routing berfungsi. Source HTML hanyalah `<div id="app">` — konten tidak terbaca Google.

**Poin 76 (Deploy Nuxt):** Sekarang deploy Nuxt. Tidak perlu `vercel.json`. Vercel mendeteksi Nuxt otomatis. Source HTML berisi konten lengkap. Inilah pembeda fundamental antara **aplikasi yang berjalan** (SPA) dan **aplikasi yang bisa ditemukan Google** (Nuxt SSR).

**Seluruh Level 7, poin 69–75:** Semua komponen sebelumnya — project setup, routing, data fetching, server API, SEO — sekarang berjalan di production. Deployment adalah **final check** apakah semua fitur Nuxt berfungsi dengan benar.

## Soal Latihan

### Soal 1

Sebutkan 3 perbedaan deployment antara Vue SPA dan Nuxt SSR di Vercel.

<details>
<summary>Jawaban</summary>

1. **vercel.json:** SPA butuh `rewrites` untuk fallback routing — Nuxt tidak perlu
2. **Serverless functions:** SPA hanya file statis — Nuxt perlu serverless functions untuk SSR
3. **Source HTML:** SPA output HTML kosong (`<div id="app">`) — Nuxt output HTML berisi konten lengkap
4. **Node version:** Nuxt 3 butuh Node 18+ — SPA bisa dengan Node versi lebih lama
</details>

### Soal 2

Setelah deploy Nuxt ke Vercel, bagaimana cara memastikan bahwa SSR berfungsi dengan benar?

<details>
<summary>Jawaban</summary>

1. Buka URL aplikasi di browser
2. Klik kanan → **View Page Source** (atau `Ctrl+U`)
3. Cari konten dinamis di HTML — misalnya judul buku, deskripsi, atau data dari `useFetch`
4. Jika konten ada di source HTML, SSR berfungsi
5. Jika source HTML hanya berisi `"Memuat..."` atau `<div id="__nuxt"></div>`, berarti SSR tidak berjalan
6. Alternatif: gunakan `curl` — `curl https://url-app.vercel.app | grep "Clean Code"`
</details>
