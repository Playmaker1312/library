# 73. useFetch dan useAsyncData — Data Fetching SSR-Aware

## Penjelasan

Di Vue SPA, data biasanya di-fetch di dalam `onMounted`:

```ts
onMounted(async () => {
  const res = await fetch('/api/books')
  data.value = await res.json()
})
```

Masalahnya: `onMounted` hanya jalan di **client**. Server tidak menunggu fetch ini selesai. Akibatnya, HTML yang dikirim server **kosong** — tidak ada data yang tercantum di source HTML. Google bot tidak melihat konten.

Nuxt menyediakan `useFetch` dan `useAsyncData` — composable yang jalan di **server + client**. Data di-fetch saat SSR, lalu HTML yang dikirim sudah berisi konten.

```ts
const { data, pending, error } = await useFetch('/api/books')
```

- `data` — ref berisi response
- `pending` — ref boolean, true saat loading
- `error` — ref berisi error jika gagal
- Jalan di server (SSR) **dan** client (hydration)

---

## Fungsi

- SSR-ready data fetching — konten sudah ada di HTML pertama yang diterima browser
- Tidak ada loading spinner saat pertama kali buka halaman (data sudah siap)
- Hybrid SSG — beberapa halaman statis (data di-fetch saat build), beberapa server-rendered
- Deduplication — request yang sama tidak di-fetch dua kali (server + client)

---

## Cara Implementasi

### 1. `useFetch` — Fetching sederhana

```vue
<!-- pages/books/index.vue -->
<template>
  <div>
    <h1>Daftar Buku</h1>
    <div v-if="pending">Memuat...</div>
    <div v-else-if="error">Error: {{ error.message }}</div>
    <BookCard
      v-for="book in books"
      :key="book.id"
      :title="book.title"
      :author="book.author"
    />
  </div>
</template>

<script setup lang="ts">
const { data: books, pending, error } = await useFetch<Book[]>('/api/books')
</script>
```

### 2. `useFetch` dengan dynamic params

```vue
<!-- pages/books/[id].vue -->
<template>
  <div v-if="pending">Memuat...</div>
  <div v-else-if="book">
    <h1>{{ book.title }}</h1>
    <p>{{ book.author }}</p>
    <p>{{ book.description }}</p>
  </div>
</template>

<script setup lang="ts">
const route = useRoute()

const { data: book, pending } = await useFetch(`/api/books/${route.params.id}`)
</script>
```

### 3. `useAsyncData` — Custom fetch logic

Gunakan jika butuh transformasi data atau fetch dari sumber non-API:

```vue
<script setup lang="ts">
const { data: featuredBooks } = await useAsyncData('featured', async () => {
  const books = await $fetch('/api/books')
  return books.filter(b => b.rating >= 4.5)
})
</script>
```

### 4. Menangani error dan fallback

```vue
<script setup lang="ts">
const { data: books, error } = await useFetch('/api/books', {
  default: () => [] as Book[],
  onResponseError({ response }) {
    console.error('Gagal fetch:', response.status)
  }
})

if (error.value) {
  console.error('Error detail:', error.value.message)
}
</script>
```

### 5. Refetch secara manual

```vue
<script setup lang="ts">
const { data: books, refresh } = await useFetch('/api/books')

const reloadBooks = () => {
  refresh()
}
</script>
```

## Analogi — Toko Buku

Dulu (**SPA**), pengunjung buka toko → pintu terbuka → etalase **KOSONG** → loading spinner muncul → "Tunggu, barang sedang diambil dari gudang" (`onMounted` + fetch). Google yang lewat hanya melihat toko kosong — tidak ada buku di etalase.

Sekarang (**Nuxt SSR**), pengunjung buka toko → etalase **SUDAH TERISI** dari server → langsung lihat barang. Ini terjadi karena pegawai (server) sudah menyiapkan etalase SEBELUM pintu dibuka (pre-render di server). Google juga senang karena HTML langsung berisi konten — tidak perlu nunggu JavaScript jalan.

`useFetch` adalah pegawai yang **pintar** — dia menyiapkan buku di rak (server), lalu saat pengunjung masuk (client), dia cukup **memeriksa** apakah buku masih ada — tidak perlu ambil dari gudang lagi. Ini yang disebut **hydration**: server sudah render, client tinggal mengaktifkan interaktivitas.

---

## Dipakai untuk Apa

- Fetch data dari API eksternal atau internal (`server/api/`)
- Halaman yang membutuhkan SEO — data harus muncul di source HTML
- Dashboard atau laman yang butuh data real-time — tetap bisa pakai `refresh()`
- SSG — fetch data saat build, hasilnya statis

---

## Kesalahan Umum

| Kesalahan | Akibat | Solusi |
|---|---|---|
| Masih pakai `onMounted` untuk data utama | HTML kosong — tidak SEO | Ganti dengan `useFetch` atau `useAsyncData` |
| Memanggil `useFetch` di luar `pages/` atau `components/` | Error — tidak tersedia di store biasa | Panggil di halaman, lalu passing data ke store |
| Lupa `await` pada `useFetch` | `data` masih Promise, bukan nilai | Gunakan `await useFetch(...)` |
| Mengubah `data.value` langsung setelah fetch | Reactivity putus | Gunakan `data.value = newValue` dengan benar |
| Fetch URL hardcoded di komponen | Tidak reusable | Ambil URL dari runtimeConfig atau props |

---

## Hubungan dengan Materi Sebelumnya

**Poin 72:** Halaman sudah dipindahkan ke `pages/`. Tapi data masih di-fetch dengan `onMounted` (copy dari SPA). Sekarang ganti dengan `useFetch` agar data di-render di server.

**Level 5 (Fetch & Axios):** Di SPA, fetch dilakukan di client. `onMounted` + `fetch()` atau `axios` menghasilkan HTML kosong. Di Nuxt, `useFetch` menggantikan keduanya untuk SSR. Untuk non-SSR fetch (event click, form submit), bisa tetap pakai `$fetch` (bawaan Nuxt) atau `axios`.

## Soal Latihan

### Soal 1

Apa perbedaan antara `useFetch` dan `onMounted + fetch` dalam konteks SSR?

<details>
<summary>Jawaban</summary>

`useFetch` dijalankan di **server** saat SSR — data sudah ada di HTML yang dikirim ke browser. `onMounted + fetch` hanya dijalankan di **client** — HTML awal kosong, data baru muncul setelah JavaScript dieksekusi. Untuk SEO, `useFetch` wajib digunakan.

</details>

### Soal 2

Buat kode untuk halaman `/authors/[id]` yang menampilkan data penulis menggunakan `useFetch`. Tampilkan loading state dan error state.
