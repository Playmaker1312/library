# 48. Setup VeeValidate dan Zod — Validasi Form yang Proper

## Penjelasan

**VeeValidate** adalah library untuk manajemen form state di Vue. Ia menangani nilai (*value*), pesan error, status `touched`, `dirty`, `pending`, dan `submitted` — semua yang diperlukan form tanpa harus menulis boilerplate manual.

**Zod** adalah library validasi schema berbasis TypeScript. Schema dideklarasikan sekali, lalu otomatis menghasilkan tipe TypeScript (`z.infer`) dan menjalankan validasi runtime.

**@vee-validate/zod** adalah jembatan (adapter) yang menggabungkan keduanya: schema Zod diterjemahkan ke format yang bisa dibaca VeeValidate.

## Fungsi

- Validasi form yang **terstruktur** — semua aturan ditulis dalam satu schema, bukan tersebar di template
- **Type-safe** — TypeScript otomatis tahu bentuk data form dari schema Zod
- **Pesan error konsisten** — setiap field punya pesan error yang sudah ditentukan di schema
- **Extensible** — mudah menambah field, aturan baru, atau schema turunan

## Cara Implementasi

### 1. Instalasi

```bash
npm install vee-validate @vee-validate/zod zod
```

### 2. Buat folder dan file schema

```
src/
└── schemas/
    └── auth.schema.ts
```

### 3. Tulis schema dengan Zod

```typescript
// src/schemas/auth.schema.ts
import { z } from 'zod'

export const loginSchema = z.object({
  email: z
    .string()
    .min(1, 'Email harus diisi')
    .email('Format email tidak valid'),
  password: z
    .string()
    .min(1, 'Password harus diisi')
    .min(8, 'Password minimal 8 karakter'),
})

export const registerSchema = z
  .object({
    name: z.string().min(1, 'Nama harus diisi'),
    email: z
      .string()
      .min(1, 'Email harus diisi')
      .email('Format email tidak valid'),
    password: z
      .string()
      .min(1, 'Password harus diisi')
      .min(8, 'Password minimal 8 karakter')
      .regex(/[A-Z]/, 'Password harus mengandung huruf besar')
      .regex(/[0-9]/, 'Password harus mengandung angka'),
    confirmPassword: z.string().min(1, 'Konfirmasi password harus diisi'),
    phone: z
      .string()
      .min(10, 'Nomor telepon minimal 10 digit')
      .regex(/^[0-9]+$/, 'Nomor telepon hanya boleh angka'),
  })
  .refine((data) => data.password === data.confirmPassword, {
    message: 'Password dan konfirmasi password harus sama',
    path: ['confirmPassword'],
  })

// Type otomatis dari schema
export type LoginForm = z.infer<typeof loginSchema>
export type RegisterForm = z.infer<typeof registerSchema>
```

## Analogi — Toko Buku

Dulu (Level 4), formulir pendaftaran anggota toko pakai **sistem kehormatan** — pelanggan bilang emailnya valid, petugas percaya saja. Kalau salah, baru ketahuan pas surat balasan tidak sampai.

Sekarang ada **mesin pemeriksa otomatis** (Zod) yang ngecek dengan ketat:

- "Ini format email beneran? Ada `@` dan domain?"
- "Password minimal 8 karakter? Ada huruf besar? Ada angka?"
- "Nomor HP cuma angka semua?"
- "Password dan konfirmasi cocok?"

Kalau tidak sesuai, mesin tolak langsung dan kasih tahu alasannya dengan jelas — **sebelum** formulir dikirim ke meja pendaftaran.

## Dipakai untuk Apa

- Form login dan register user
- Form checkout (alamat, pembayaran)
- Form input data dengan aturan bisnis yang kompleks
- API payload validation di frontend sebelum dikirim ke server

## Kesalahan Umum

| Kesalahan | Solusi |
|-----------|--------|
| Lupa install `@vee-validate/zod` (hanya `vee-validate`) | Pastikan install ketiga package |
| Schema terlalu longgar — misal `z.string()` tanpa `min()` | Selalu tambahkan `min(1)` untuk required field |
| Schema terlalu ketat — regex menghalangi input valid | Uji schema dengan berbagai input nyata |
| Lupa `z.infer` — tipe data ditulis manual, tidak sinkron | Selalu gunakan `z.infer<typeof schema>` |

## Hubungan dengan Materi Sebelumnya (Level 4, Poin 44)

Di Level 4, form login menggunakan validasi HTML bawaan:

```html
<input type="email" required />
```

Masalahnya:
- Pesan error **tidak konsisten** — setiap browser tampilkan pesan berbeda
- **Tidak type-safe** — data mentah string tanpa jaminan bentuk
- **Terbatas** — tidak bisa validasi `confirmPassword`, regex, atau aturan custom

Dengan Zod, semua aturan ditulis dalam satu schema, pesan error ditentukan sendiri, dan tipe TypeScript otomatis mengikuti.

## Soal Latihan

### Soal 1

Buat schema Zod untuk form **ganti password** yang memiliki field: `currentPassword`, `newPassword`, `confirmNewPassword`. `newPassword` harus berbeda dari `currentPassword` (pakai `.refine()`).

<details>
<summary>Jawaban</summary>

```typescript
import { z } from 'zod'

export const changePasswordSchema = z
  .object({
    currentPassword: z.string().min(1, 'Password saat ini harus diisi'),
    newPassword: z
      .string()
      .min(1, 'Password baru harus diisi')
      .min(8, 'Password baru minimal 8 karakter')
      .regex(/[A-Z]/, 'Harus mengandung huruf besar')
      .regex(/[0-9]/, 'Harus mengandung angka'),
    confirmNewPassword: z.string().min(1, 'Konfirmasi password harus diisi'),
  })
  .refine((data) => data.newPassword === data.confirmNewPassword, {
    message: 'Password baru dan konfirmasi tidak cocok',
    path: ['confirmNewPassword'],
  })
  .refine((data) => data.currentPassword !== data.newPassword, {
    message: 'Password baru harus berbeda dari password saat ini',
    path: ['newPassword'],
  })

export type ChangePasswordForm = z.infer<typeof changePasswordSchema>
```

</details>

### Soal 2

Buat schema untuk form **alamat pengiriman** dengan field: `namaPenerima` (required), `noHp` (min 10 digit, angka saja), `alamat` (required, min 10), `kodePos` (exactly 5 digit angka).

<details>
<summary>Jawaban</summary>

```typescript
import { z } from 'zod'

export const alamatSchema = z.object({
  namaPenerima: z.string().min(1, 'Nama penerima harus diisi'),
  noHp: z
    .string()
    .min(10, 'Nomor HP minimal 10 digit')
    .regex(/^[0-9]+$/, 'Nomor HP hanya boleh angka'),
  alamat: z.string().min(10, 'Alamat minimal 10 karakter'),
  kodePos: z
    .string()
    .length(5, 'Kode pos harus 5 digit')
    .regex(/^[0-9]+$/, 'Kode pos hanya boleh angka'),
})

export type AlamatForm = z.infer<typeof alamatSchema>
```

</details>
