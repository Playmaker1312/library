# 50. Refactor LoginView — Menggunakan VeeValidate dan Zod

## Penjelasan

Setelah schema Zod dan komponen FormField siap, saatnya **merefactor** `LoginView` yang sebelumnya menggunakan validasi HTML biasa (Level 4) menjadi form yang proper menggunakan VeeValidate + Zod.

Komponen utama yang digunakan dari VeeValidate:

| API | Fungsi |
|-----|--------|
| `useForm()` | Mengelola state form dan validasi |
| `defineField()` | Mengikat field ke form — mengembalikan value ref dan attrs |
| `handleSubmit()` | Callback submit yang hanya jalan jika validasi lolos |
| `errors` | Object reaktif berisi pesan error per field |
| `isSubmitting` | Boolean — true saat form sedang diproses (loading state) |
| `toTypedSchema()` | Adapter dari Zod schema ke format VeeValidate |

## Fungsi

- **Validasi otomatis** sebelum submit — form tidak bisa dikirim jika ada error
- **Loading state** — tombol login disabled otomatis saat proses server berlangsung
- **Error per field** — setiap field menampilkan pesan error spesifik dari Zod
- **TypeScript terintegrasi** — data form memiliki tipe dari Zod schema

## Cara Implementasi

```vue
<!-- src/views/LoginView.vue -->
<script setup lang="ts">
import { useForm, defineField, handleSubmit } from 'vee-validate'
import { toTypedSchema } from '@vee-validate/zod'
import { loginSchema, type LoginForm } from '@/schemas/auth.schema'
import FormField from '@/components/common/FormField.vue'
import { useAuthStore } from '@/stores/auth'
import { useRouter } from 'vue-router'

const authStore = useAuthStore()
const router = useRouter()

const { errors, isSubmitting, setFieldError } = useForm<LoginForm>({
  validationSchema: toTypedSchema(loginSchema),
})

const [email, emailAttrs] = defineField('email')
const [password, passwordAttrs] = defineField('password')

const onSubmit = handleSubmit(async (values) => {
  try {
    await authStore.login(values.email, values.password)
    router.push('/dashboard')
  } catch (err: any) {
    // Server error — tampilkan di field terkait
    if (err.response?.data?.field) {
      setFieldError(err.response.data.field, err.response.data.message)
    }
  }
})
</script>

<template>
  <form class="login-form" @submit="onSubmit" novalidate>
    <h1 class="login-form__title">Masuk</h1>

    <FormField
      v-model="email"
      label="Email"
      type="email"
      placeholder="contoh@email.com"
      :error-message="errors.email"
      required
      v-bind="emailAttrs"
    />

    <FormField
      v-model="password"
      label="Password"
      type="password"
      placeholder="Masukkan password"
      :error-message="errors.password"
      required
      v-bind="passwordAttrs"
    />

    <button
      type="submit"
      class="login-form__submit"
      :disabled="isSubmitting"
    >
      {{ isSubmitting ? 'Memproses...' : 'Masuk' }}
    </button>
  </form>
</template>
```

## Analogi — Toko Buku

Formulir pendaftaran anggota toko sekarang punya **3 lapis perlindungan**:

1. **Mesin pemeriksa** (Zod) — cek format data: "Email ada @-nya? Password 8 karakter?"
2. **Petugas formulir** (VeeValidate) — pastikan semua kolom diisi dengan benar **sebelum** dikirim ke meja pendaftaran. Kalau ada error, tombol "Daftar" tidak bisa diklik
3. **Formulir standar** (FormField) — tampilkan error dengan jelas di setiap kolom yang salah

Pelanggan tidak bisa "menerobos" dengan data tidak valid. Semuanya dicek otomatis sebelum sampai ke server.

## Dipakai untuk Apa

- Form login dan register
- Form edit profil
- Form dengan validasi kompleks dan integrasi API
- Semua form yang sebelumnya pakai validasi HTML biasa dan perlu ditingkatkan

## Kesalahan Umum

| Kesalahan | Solusi |
|-----------|--------|
| Salah import `toTypedSchema` dari `vee-validate` (harusnya dari `@vee-validate/zod`) | `import { toTypedSchema } from '@vee-validate/zod'` |
| Lupa menangani error dari server — validasi client lolos tapi server tolak | Gunakan `setFieldError()` untuk menampilkan error dari server |
| `novalidate` tidak ditambahkan ke `<form>` | HTML native validation bisa bentrok dengan VeeValidate |
| `handleSubmit` tidak dipanggil — langsung `@submit="submitHandler"` | Submit handler harus dibungkus `handleSubmit()` |

## Hubungan dengan Materi Sebelumnya (Poin 48 + 49)

- **Poin 48**: Schema Zod (`loginSchema`) — aturan validasi
- **Poin 49**: Komponen `FormField` — UI untuk menampilkan error
- **Poin 50**: Keduanya digabung dengan VeeValidate — jembatan yang menghubungkan schema ke UI, plus manajemen form state

Dulu di Level 4 (Poin 44) form login ditulis seperti ini:

```vue
<input type="email" required v-model="email" />
<button type="submit">Login</button>
```

Validasi hanya mengandalkan browser. Error muncul sebagai tooltip native yang jelek dan tidak bisa dikustomisasi. Sekarang, error muncul di bawah input dengan styling yang konsisten, validasi lebih ketat (minimal 8 karakter, format email, dll.), dan tipe data aman.

### Soal 2

Buat sebuah form login yang memiliki tombol "Tampilkan/Sembunyikan Password" menggunakan `type` yang berubah antara `"password"` dan `"text"`.

<details>
<summary>Jawaban</summary>

```vue
<script setup lang="ts">
import { ref } from 'vue'
import { useForm, defineField, handleSubmit } from 'vee-validate'
import { toTypedSchema } from '@vee-validate/zod'
import { loginSchema, type LoginForm } from '@/schemas/auth.schema'
import FormField from '@/components/common/FormField.vue'

const showPassword = ref(false)
const { errors, isSubmitting } = useForm<LoginForm>({
  validationSchema: toTypedSchema(loginSchema),
})

const [email, emailAttrs] = defineField('email')
const [password, passwordAttrs] = defineField('password')

const onSubmit = handleSubmit(async (values) => {
  console.log('Login:', values)
})

function togglePassword() {
  showPassword.value = !showPassword.value
}
</script>

<template>
  <form @submit="onSubmit" novalidate>
    <FormField v-model="email" label="Email" type="email" placeholder="email@contoh.com" :error-message="errors.email" required v-bind="emailAttrs" />
    <div class="password-wrapper">
      <FormField v-model="password" label="Password" :type="showPassword ? 'text' : 'password'" placeholder="Password" :error-message="errors.password" required v-bind="passwordAttrs" />
      <button type="button" class="toggle-btn" @click="togglePassword">
        {{ showPassword ? 'Sembunyikan' : 'Tampilkan' }}
      </button>
    </div>
    <button type="submit" :disabled="isSubmitting">{{ isSubmitting ? 'Memproses...' : 'Masuk' }}</button>
  </form>
</template>

<style scoped>

  top: 2rem;
  background: none;

  color: #6366f1;
  cursor: pointer;

</style>
```
