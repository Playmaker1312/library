# 15. Membuat Layout Component — AppHeader dan AppFooter

## Penjelasan

Layout component adalah komponen yang menentukan **struktur kerangka** halaman — biasanya header, footer, sidebar, atau main content wrapper. Di aplikasi Vue, kita membuat layout terpisah agar:

- Semua halaman punya struktur yang konsisten
- Perubahan di header/footer cukup di satu tempat
- App.vue tetap bersih dan fokus pada routing

Kita akan membuat:

```
src/
└── components/
    └── layout/
        ├── AppHeader.vue   ← logo, navigasi, search bar
        └── AppFooter.vue   ← copyright, links
```

## Fungsi

- **Konsistensi visual**: Header dan footer yang sama muncul di semua halaman
- **Pemisahan tanggung jawab**: App.vue hanya sebagai entry point; layout dikelola komponen terpisah
- **Kemudahan maintenance**: Ubah navigasi sekali, efek ke seluruh aplikasi
- **Struktur sticky**: Header tetap di atas meskipun halaman di-scroll

### 3. Update App.vue

Sekarang saatnya menggabungkan semuanya di `src/App.vue`:

```vue
<template>
  <div class="app-layout">
    <AppHeader />
    <main class="main-content">
      <RouterView />
    </main>
    <AppFooter />
  </div>
</template>

<script setup lang="ts">
import AppHeader from '@/components/layout/AppHeader.vue'
import AppFooter from '@/components/layout/AppFooter.vue'
</script>

<style scoped>
.app-layout {
  display: flex;
  flex-direction: column;
  min-height: 100vh;
}

.main-content {
  flex: 1;
}
</style>
```

Dengan `flex: 1` di `.main-content`, footer akan selalu berada di bawah meskipun konten halaman sedikit (sticky footer).

### 4. Struktur akhir folder komponen

```
src/
└── components/
    ├── features/
    │   └── BookCard.vue
    └── layout/
        ├── AppHeader.vue
        └── AppFooter.vue
```

Struktur ini memisahkan komponen berdasarkan **peran**:
- `features/` — komponen bisnis yang spesifik fitur (BookCard)
- `layout/` — komponen kerangka aplikasi (Header, Footer)
- Nanti akan ada `ui/` — komponen umum seperti button, input, modal

## Analogi — Toko Buku

**AppHeader dan AppFooter seperti "seragam toko" — semua halaman pakai seragam yang sama.**

Bayangkan sebuah toko buku besar dengan banyak bagian: bagian fiksi, non-fiksi, anak-anak, dan café. Setiap bagian punya tampilan yang berbeda, tetapi semuanya tetap punya:
1. **Papan nama toko di atas** (Header): Logo "Pustaka Kita" dan navigasi ke bagian-bagian toko. Di manapun pelanggan berada, mereka selalu bisa melihat papan nama ini.
2. **Tanda terima kasih di bawah** (Footer): Informasi kontak, jam buka, dan ucapan terima kasih. Sama di semua sudut toko.

| Konsep Vue | Analogi Toko Buku |
|------------|-------------------|
| `AppHeader.vue` | Papan nama dan rambu navigasi toko — dipasang di atas |
| `AppFooter.vue` | Stiker ucapan terima kasih dan info kontak — ditempel di bawah |
| `App.vue` | Bangunan toko — header di atas, konten di tengah, footer di bawah |
| `RouterView` | Ruangan yang berubah-ubah tergantung bagian toko yang dikunjungi |
| Sticky header | Papan nama yang terus terlihat meskipun pengunjung berjalan ke rak belakang |

Header dan footer hanya dibuat **satu kali**, dan semua halaman (beranda, katalog, keranjang) akan mewarisi tampilan yang sama. Ini konsisten dan profesional.

## Dipakai untuk Apa di Dunia Nyata

- **Semua web aplikasi** yang memiliki >1 halaman pasti punya layout component
- **Aplikasi dashboard**: Sidebar + Topbar + Main Content adalah layout
- **E-commerce**: Header dengan logo + search + cart icon + user menu adalah layout
- **Blog/Portal**: Header navigasi + footer dengan social links adalah layout

## Kesalahan Umum

| Kesalahan | Dampak | Solusi |
|-----------|--------|--------|
| **Navigasi langsung di App.vue** | App.vue jadi panjang dan susah dipelihara | Pisahkan ke `AppHeader.vue` |
| **Lupa import di App.vue** | Komponen tidak muncul — error atau blank | Import dan daftarkan komponen di `<script setup>` |
| **Header tidak sticky** | Header ikut scroll, navigasi hilang saat scroll down | Tambahkan `position: sticky; top: 0;` di CSS |
| **Footer tidak di bawah** | Footer naik ke tengah jika konten pendek | Gunakan flex column dengan `min-height: 100vh` dan `flex: 1` di main |
| **RouterLink tanpa `to`** | Link tidak bisa diklik | Pastikan properti `to` diisi dengan path yang benar |
| **Lupa `active-class`** | Tidak ada indikator halaman aktif di navigasi | Tambahkan `active-class="active"` di RouterLink |

## Soal Latihan + Jawaban

### Soal 1
Mengapa lebih baik memisahkan `AppHeader` dan `AppFooter` ke file komponen terpisah daripada menulisnya langsung di `App.vue`?

<details>
<summary>Jawaban</summary>

1. **Single Responsibility**: App.vue tugasnya hanya sebagai entry point dan routing layout. Header/footer adalah tanggung jawab terpisah.
2. **Reusability**: Jika suatu saat ada halaman khusus (misal halaman login) yang tidak perlu header, kita bisa mengatur layout tanpa mengutak-atik App.vue.
3. **Maintenance**: Perubahan navigasi cukup di satu file kecil (AppHeader.vue), bukan file App.vue yang mungkin panjang.
4. **Testing**: Komponen kecil lebih mudah di-test dibanding satu file besar.
5. **Kolaborasi**: Tim berbeda bisa mengerjakan header dan footer secara paralel tanpa konflik merge.
</details>

### Soal 2
Apa fungsi `flex: 1` pada `.main-content` di App.vue? Apa yang terjadi jika properti ini dihapus?

<details>
<summary>Jawaban</summary>

`flex: 1` membuat elemen main mengisi **seluruh ruang yang tersisa** di antara header dan footer. Karena `.app-layout` menggunakan `display: flex; flex-direction: column; min-height: 100vh`, flex container akan setinggi viewport.

Jika `flex: 1` dihapus, main content hanya setinggi kontennya saja. Akibatnya, jika konten halaman pendek (misal hanya 200px), footer akan **naik ke tengah halaman** — tidak menempel di bawah. Pengunjung akan melihat area kosong di bawah footer, yang terlihat tidak profesional.

Dengan `flex: 1`, main content "mendorong" footer ke bawah, memastikan footer selalu di dasar viewport ketika konten sedikit.
</details>
