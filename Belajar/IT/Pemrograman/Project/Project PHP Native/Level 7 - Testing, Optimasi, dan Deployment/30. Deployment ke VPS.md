# 30. Deployment ke VPS

> **Level 7 · Testing, Optimasi, dan Deployment** — Penutup roadmap: dari komputer lokal ke server produksi yang aman, cepat, dan teruji.

---

## 1. Penjelasan Singkat & Konsep Dasar

**Deployment** = memindahkan aplikasi dari *development* (komputer kamu) ke *production* (server yang melayani user). Server production bisa berupa VPS (Ubuntu), shared hosting, atau PaaS.

**Yang BERUBAH total antara dev vs prod:**

| Aspek | Development | Production |
|---|---|---|
| `APP_ENV` | `development` | `production` |
| `display_errors` | `1` (tampil error) | `0` (log saja) |
| Web server | Apache/XAMPP (buatan lokal) | **Nginx** + PHP-FPM |
| Database | MySQL di lokal | MySQL di server |
| Domain | `localhost` / `.test` | domain asli + **HTTPS** |
| Storage writable | Windows user | `www-data` |
| Performance | tidak optimal | OPcache, gzip, caching (29) |

**Stack deployment (LEMP):**

```
Browser → HTTPS → Nginx (server web)
                    ├─ serve static files (css/js/images) langsung
                    └─ request .php → PHP-FPM (executor)
                                        └─ MySQL (data)
```

**Peran penting:**
- **PHP-FPM** — manajer proses PHP (lebih cepat & terisolasi daripada mod_php).
- **`public/` sebagai web root** — hanya `public/` yang diekspos; `src/`, `storage/`, `.env`, `vendor/` tidak bisa diakses (materi 25).
- **`.env` production** — credential asli di server, TIDAK di commit.
- **`try_files $uri $uri/ /index.php?...`** — setara `.htaccess` Apache untuk router (materi 26) di Nginx.

**Benang Merah:** seluruh roadmap bermuara di sini: arsitektur (25-27) memudahkan deployment (`index.php` tunggal), keamanan (22-24) diaktifkan ulang (`display_errors=0`), testing (28) dijalankan di CI sebelum deploy, optimasi (29) diaktifkan (OPcache).

---

## 2. Fungsi & Kegunaan Utama

- **Melayani user nyata** dengan cepat & aman.
- **Menjaga konsistensi konfigurasi** — filenya `try_files` dan vhost mengarah hanya ke `public/`.
- **Menerapkan keamanan lapis produksi** — error tersembunyi, headers, secret di `.env`, HTTPS.
- **OTAKU CI** — deploy otomatis setelah test hijau (untuk proyek yang berkembang).

## 3. Contoh Kode & Implementasi Real-World

### Langkah 1 — Siapkan server (Ubuntu VPS)

```bash
# Update & install LEMP
sudo apt update && sudo apt upgrade -y
sudo apt install -y nginx mysql-server php8.3-fpm \
    php8.3-mysql php8.3-mbstring php8.3-xml \
    php8.3-curl php8.3-zip php8.3-intl

# Composer
curl -sS https://getcomposer.org/installer | php
sudo mv composer.phar /usr/local/bin/composer

# Clone & install
cd /var/www
sudo git clone https://github.com/username/perpustakaan.git
cd perpustakaan
sudo chown -R www-data:www-data .

# Production install (tanpa dev deps, autoload optimal)
composer install --optimize-autoloader --no-dev

# Environment
cp .env.example .env
# Edit .env: APP_ENV=production, APP_DEBUG=false, DB_*, dst.

# Database
mysql -u root -p -e "CREATE DATABASE perpustakaan_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci"
# jalankan migrasi/jejak SQL sesuai dokumen Anda (schema Level 4)

# Permission storage (writeable oleh PHP-FPM)
sudo find storage/ -type d -exec chmod 755 {} \;
sudo find storage/ -type f -exec chmod 644 {} \;
sudo chown -R www-data:www-data storage/ public/
```

### Langkah 2 — Konfigurasi Nginx

```nginx
# /etc/nginx/sites-available/perpustakaan
server {
    listen 80;
    server_name perpustakaan.kota.id www.perpustakaan.kota.id;

    root /var/www/perpustakaan/public;
    index index.php;

    # ─── Security headers ───
    server_tokens off;
    add_header X-Frame-Options "DENY" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-XSS-Protection "1; mode=block" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;

    # ─── Sembunyikan file sensitif ───
    location ~ /\.(env|git|htaccess|gitignore)$ {
        deny all;
        return 404;
    }

    # ─── Blokir akses ke direktori non-publik ───
    location ~ ^/(src|tests|storage|vendor)/ {
        deny all;
        return 404;
    }

    # ─── PHP-FPM ───
    location ~ \.php$ {
        fastcgi_pass unix:/var/run/php/php8.3-fpm.sock;
        fastcgi_param SCRIPT_FILENAME $realpath_root$fastcgi_script_name;
        include fastcgi_params;
        fastcgi_hide_header X-Powered-By;
    }

    # ─── Front controller (pengganti .htaccess Apache) ───
    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }

    # ─── Cache asset statis ───
    location ~* \.(jpg|jpeg|png|gif|ico|css|js|woff2|svg)$ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }
}
```

```bash
# Aktifkan site & mulai
sudo ln -s /etc/nginx/sites-available/perpustakaan /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx

# HTTPS gratis (Let's Encrypt)
sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d perpustakaan.kota.id

# Auto-renewal
sudo crontab -e
# 0 0 * * * certbot renew --quiet
```

### Langkah 3 — Verifikasi & onboarding produksi

```bash
# Test pertama (tanpa detail error)
curl -i http://perpustakaan.kota.id/          # cek status & headers

# Uji endpoint yang ter-proteksi (materi 27)
curl -H "Authorization: Bearer <TOKEN>" http://perpustakaan.kota.id/api/buku

# Cek log jika bermasalah
sudo tail -f /var/log/nginx/error.log
sudo tail -f /var/log/php8.3-fpm.log
sudo tail -f /var/www/perpustakaan/storage/logs/php_errors.log
```

### CI/CD minimal (GitHub Actions — sketsa)

```yaml
# .github/workflows/deploy.yml
name: Test & Deploy
on:
  push:
    branches: [ main ]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: shivammathur/setup-php@v2
        with: { php-version: '8.3' }
      - run: composer install --no-interaction
      - run: ./vendor/bin/phpunit
  deploy:
    needs: test
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Deploy via SSH
        run: |
          sshpass -p "${{ secrets.SSH_PASS }}" ssh root@${{ secrets.SERVER_IP }} '
            cd /var/www/perpustakaan &&
            git pull &&
            composer install --optimize-autoloader --no-dev &&
            php bin/migrate.php &&
            sudo systemctl reload php8.3-fpm
          '
```

## 4. Analogi Sederhana

Dalam **Sistem Administrasi Kantor**:

- **Development** = **ruang uji di belakang**: meja kosong, lampu terang untuk membantu, gaun (error) diaktifkan — tidak ada pelanggan yang melihat.
- **Deployment ke VPS** = **meresmikan kantor cabang**: pindahkan perabot (aplikasi), sambungkan arsip (DB), tempel papan nama (domain), pasang pintu pengaman (HTTPS), ganti lampu (laras error dimatikan — ada lampu merah private lain, log).
- **Nginx + PHP-FPM** = **penjaga pintu & staf pengolah** yang profesional: file statis (gambar/css) dilayani tanpa menunggu staf; permintaan PHP dilanjutkan ke staf cepat (FPM).
- **`.env`** = **brankas kunci** di belakang yang hanya berada di kantor cabang, tidak pernah dicopy ke meja umum.
- **`try_files`** = *papan penunjuk dari pintu depan*: semua alamat → jalan ke pintu utama (front controller).
- **CI/CD** = **prosedur tes wajib sebelum pindah kantor**: hanya pindah jika semua kartu tes hijau.

## 5. Kapan Harus Digunakan & Kasus Penggunaan

- **Tahap production** — begitu aplikasi siap melayani user nyata (Level 1-7 checkpoint semua lulus).
- **Migrasi pembaruan** — dengan `git pull` + `composer install` + migrate di server.
- **HTTPS wajib** — untuk login & API (data sensitif). Cerrtbot memberi cert otomatis.
- **CI untuk proyek yang berkembang** — test di CI sebelum deploy; rollback mudah (git).
- **Kapan tidak perlu** — tahap development masih lokal; deployment setiap commit kecil tanpa checklist = risiko.

---

## 6. Aspek Keamanan & Best Practices (Critical)

- **`APP_DEBUG=false` / `display_errors=0`** — stack trace & detail DB tidak pernah tampil ke user (materi 4/20). Error hanya di log dengan path `storage/logs`.
- **`.env` tidak pernah di commit** — `.gitignore`; gunakan `.env.example`; credential asli dipasang saat deploy (secret di CI, bukan di repo).
- **Web root = `public/`** — Nginx `root /var/www/perpustakaan/public`; blokir `/src`, `/storage`, `/vendor`, file dot-env/dot-git.
- **HTTPS** — `certbot` + HSTS (sertakan `Strict-Transport-Security` di production).
- **Permissions** — `storage/` & upload dir dimiliki `www-data` (PHP-FPM user); owner tidak `root` agar proses web bisa menulis; chmod ketat (755 dir, 644 file).
- **Jangan jalankan `composer install`/`php -S` sebagai production** — gunakan PHP-FPM & Nginx; `php -S` hanya development.
- **Backup & rollback** — dump DB rutin; simpan commit lama agar bisa `git checkout`.
- **Security headers** di vhost (X-Frame, nosniff) — konsisten dengan materi 22.

## 7. Kesalahan Umum & Debugging

- **Halaman 404 / index tak tampil** — Nginx: `try_files` salah atau `root` tidak menunjuk `public/`. Cek `/etc/nginx/sites-available` dan `sudo nginx -t`.
- **`File not found` error di PHP-FPM** — `fastcgi_param SCRIPT_FILENAME` harus `$realpath_root` — salah → FPM cari file di path salah. Periksa config.
- **Blank page / 500** — `display_errors` off di production. Baca log (`storage/logs/php_errors.log`, `nginx error.log`). Jangan "stuck" — nonaktifkan alert hanya setelah log ditelaah.
- **`404` pada `.env` request** — header `deny all; return 404;` memblokir; pastikan blok `location ~ /\.` aktif.
- **Upload gagal di production** — direktori tidak writable oleh `www-data` (materi 24). `chown -R www-data:www-data storage/` dan cek permission.
- **Koneksi DB gagal di prod** — `.env` belum dibuat/belum diisi credential, atau MySQL belum `CREATE DATABASE`. Cek `DB_NAME`/`DB_USER`/`DB_PASSWORD`.
- **Composer memori** — `composer install` bisa kekurangan memory di `--no-dev`; set `COMPOSER_MEMORY_LIMIT=-1` sementara.
- **HTTPS mixed content** — pastikan semua URL internal `https`; gunakan `baseUrl()` (materi 13) yang menghormati `HTTPS`.

## 8. Soal Latihan & Kunci Jawaban

### Tantangan 1
Tulis checklist deployment 10 poin dari materi + kaitkan tiap poin ke materi sebelumnya (misal: "root→public/ ↔ materi 25"). Jelaskan apa dampak jika satu poin dilanggar (contoh: membiarkan `display_errors=1`).

### Tantangan 2
Saat pertama deploy, user membuka halaman tetapi dapat **HTTP 500** kosong. Sebutkan 5 lokasi yang kamu periksa untuk diagnosa, urutkan dari yang paling cepat, dan kenapa.

### Jawaban & Pembahasan

**Tantangan 1** — Checklist (10 poin):

| # | Checklist | Terkait materi | Dampak jika dilanggar |
|---|---|---|---|
| 1 | `APP_ENV=production`, `APP_DEBUG=false`, `display_errors=0` | 4 | Stack trace & detail DB bocor ke user |
| 2 | Web root hanya `public/` (nginx `root`) + blokir `/src`, `/storage`, `/vendor`, dot-files | 25 | `.env`, storage, file upload bisa diunduh |
| 3 | `.env` di server (bukan di commit); `.gitignore` | 25/20 | Credential DB bocor ke repo/CI log |
| 4 | HTTPS via certbot + HSTS | 30 | Data login & token terkirim plaintext |
| 5 | Permissions: `storage/` & upload dir milik `www-data` (755/644) | 24 | Upload & session gagal menulis |
| 6 | `composer install --no-dev --optimize-autoloader` | 25 | Dev deps (PHPUnit) ikut di-host = RCE risk; autoload lambat |
| 7 | Security headers di vhost (X-Frame, nosniff, X-XSS) | 22 | Clickjacking & MIME sniffing terbuka |
| 8 | DB terpisah + migrasi dijalankan; credential sesuai `.env` | 20 | Query gagal / penyusupan DB |
| 9 | Error hanya ke log (`error_log`, `storage/logs/`) | 4/20 | Debug lambat tanpa jejak |
| 10 | CI test hijau sebelum deploy (GitHub Actions) | 28 | Regresi terdeploy tanpa disadari |

> **Contoh dampak**: mempertahankan `display_errors=1` di production → penyerang melihat `PDOException` berisi DSN/nama DB → membantu serangan lanjutan; dan UX user "blank page" tanpa makna.

**Tantangan 2** — Urutan cepat → menyeluruh:

1. **`/var/log/nginx/error.log`** — `tail -f` saat request — apakah Nginx menolak / file not found / 500 disertai baris konteks. Tercepat, sering sudah cukup.
2. **`/var/www/perpustakaan/storage/logs/php_errors.log`** — log aplikasi (sejak `error_log` diarahkan) — berisi exception PHP dengan file & baris. Ini biasanya lokasi *penyebab* asli.
3. **`/var/log/php8.3-fpm.log`** — error startup FPM atau segfault; cek juga service: `sudo systemctl status php8.3-fpm`.
4. **Test langsung lewat CLI** — `cd /var/www/perpustakaan && php public/index.php` (dengan `APP_ENV=development` sementara) agar exception tampil → cek apakah masalah di bootstrap/router.
5. **Periksa konfigurasi Nginx/FPM** — `sudo nginx -t`, `SCRIPT_FILENAME` (materi ini), permissions, PHP-FPM socket; lalu log MySQL (`/var/log/mysql/error.log`) bila mencurigakan DB.

> **Pembahasan:** 500 kosong = *silent failure production by design*. Urutan di atas memaksimalkan kecepatan: Nginx (jaringan/path) → log aplikasi (penyebab logika) → FPM (executor) → CLI (reproduksi) → konfigurasi/DB (lingkungan). Jangan pernah "mati angkat tangan" di produksi tanpa log — itulah pelajaran materi 4 yang berdampak paling nyata di akhir roadmap.
