# 20. Setup Database dan Koneksi PDO

> **Level 4 · OOP dan Database PDO** — Penyimpanan yang scalable: dari file JSON (materi 17) ke MySQL dengan koneksi PDO yang aman.

---

## 1. Penjelasan Singkat & Konsep Dasar

**PDO (PHP Data Objects)** adalah *interface abstrak* PHP ke banyak database — MySQL, PostgreSQL, SQLite. Alih-alih fungsi spesifik seperti `mysqli_*`, kamu memakai API seragam yang sama untuk database mana pun.

Mengapa **PDO** bukan `mysqli`?

| | PDO | MySQLi |
|---|---|---|
| Dukungan DB | MySQL, PostgreSQL, SQLite, dll. | Hanya MySQL |
| Prepared statement | Native + ergonomis | Ada, API beda |
| Exception / error mode | Konsisten (PDOException) | Campuran |
| Modernitas | Standar de facto framework | Legacy |

**Prinsip koneksi PDO (4 pengaturan kunci):**

```php
$pdo = new PDO($dsn, $user, $pass, [
    PDO::ATTR_ERRMODE            => PDO::ERRMODE_EXCEPTION, // error → exception
    PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,       // fetch → array asosiatif
    PDO::ATTR_EMULATE_PREPARES   => false,                  // prepared statement NATIVE (kunci keamanan)
    PDO::MYSQL_ATTR_INIT_COMMAND => "SET NAMES utf8mb4",
]);
```

**Benang Merah:** file JSON (17) mengajarkan CRUD; sekarang CRUD itu berpindah ke SQL yang lebih kuat. `Connection` singleton (satu koneksi PDO untuk seluruh app) — nanti dipakai semua Repository (21), dan di Level 6 menjadi "service" di Container.

---

## 2. Fungsi & Kegunaan Utama

- **Koneksi aman + reusable** — satu koneksi, disimpan instance-nya (singleton), dipakai semua class — hemat sumber daya.
- **`ERRMODE_EXCEPTION`** — error DB menjadi exception yang bisa di-catch, bukan warning sepi. Ini mengubah cara kamu men-debug DB secara fundamental.
- **`FETCH_ASSOC`** — hasil query langsung array asosiatif (`$row['judul']`) — konsisten dengan `Buku::fromArray()` (materi 18).
- **`ATTR_EMULATE_PREPARES=false`** — PHP memakai prepared statement **asli MySQL** (protokol dua fase), bukan emulasi string — lapisan keamanan tambahan terhadap SQLi dan caching binari yang lebih efisien.
- **`utf8mb4`** — karakter Unicode lengkap (emoji, aksen) tersimpan rapi, mencegah data rusak.

## 3. Contoh Kode & Implementasi Real-World

**1) Setup database (SQL) — phpMyAdmin atau CLI:**

```sql
-- Buat database dengan charset yang mendukung unicode penuh
CREATE DATABASE perpustakaan_db
    CHARACTER SET utf8mb4
    COLLATE utf8mb4_unicode_ci;

USE perpustakaan_db;

CREATE TABLE buku (
    id          INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    judul       VARCHAR(200) NOT NULL,
    pengarang   VARCHAR(100) NOT NULL,
    isbn        CHAR(13) UNIQUE,
    penerbit    VARCHAR(100),
    tahun       YEAR NOT NULL,
    harga       DECIMAL(12,2) NOT NULL DEFAULT 0,
    stok        INT UNSIGNED NOT NULL DEFAULT 0,
    kategori    ENUM('Fiksi','Non-Fiksi','Sains','Teknologi','Sejarah','Umum') DEFAULT 'Umum',
    deskripsi   TEXT,
    created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    deleted_at  TIMESTAMP NULL DEFAULT NULL,
    INDEX idx_judul     (judul),
    INDEX idx_pengarang (pengarang),
    INDEX idx_kategori  (kategori)
);
```

**2) Koneksi PDO (singleton):**

```php
<?php
// File: src/Database/Connection.php
declare(strict_types=1);

class Connection {
    private static ?PDO $instancia = null;

    private function __construct() {}  // cegah new Connection()
    private function __clone() {}      // cegah clone

    public static function getInstance(): PDO {
        if (self::$instancia === null) {
            self::$instancia = self::buatKoneksi();
        }
        return self::$instancia;
    }

    private static function buatKoneksi(): PDO {
        // Credential dari environment (bukan di-hardcode; di Level 6 pakai .env)
        $host     = getenv('DB_HOST')     ?: 'localhost';
        $port     = getenv('DB_PORT')     ?: '3306';
        $dbname   = getenv('DB_NAME')     ?: 'perpustakaan_db';
        $username = getenv('DB_USER')     ?: 'root';
        $password = getenv('DB_PASSWORD') ?: '';

        $dsn = "mysql:host={$host};port={$port};dbname={$dbname};charset=utf8mb4";

        try {
            return new PDO($dsn, $username, $password, [
                PDO::ATTR_ERRMODE            => PDO::ERRMODE_EXCEPTION,
                PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
                PDO::ATTR_EMULATE_PREPARES   => false,
                PDO::MYSQL_ATTR_INIT_COMMAND => "SET NAMES utf8mb4 COLLATE utf8mb4_unicode_ci",
            ]);
        } catch (PDOException $e) {
            // JANGAN tampilkan detail ke user (info DB = amunisi penyerang)
            error_log('Koneksi DB gagal: ' . $e->getMessage());
            throw new RuntimeException('Layanan database sedang tidak tersedia.');
        }
    }
}
```

**Pemakaian dari halaman:**

```php
<?php
// buku/katalog.php
require_once 'src/Database/Connection.php';

$pdo  = Connection::getInstance();
$stmt = $pdo->query('SELECT id, judul, harga FROM buku WHERE deleted_at IS NULL');
$buku = $stmt->fetchAll();

echo "<ul>";
foreach ($buku as $row) {
    echo "<li>" . htmlspecialchars($row['judul'])
       . " — Rp " . number_format((float) $row['harga'], 0, ',', '.') . "</li>";
}
echo "</ul>";
```

> **Catatan:** `$pdo->query()` di atas hanya untuk *query statis*. Untuk query dengan input user, wajib **prepared statement** (materi 21).

## 4. Analogi Sederhana

Dalam **Sistem Administrasi Kantor**:

- **MySQL (database)** = **gudang arsip besar** dengan rak berlabel (tabel: `buku`, `anggota`), tiap rak punya kolom. Jauh lebih rapi & cepat daripada lemari arsip JSON yang dibaca penuh setiap kali.
- **PDO** = **kurir antar-surat (standard courier)** yang bisa mengantar ke semua gudang (MySQL, PostgreSQL, SQLite) dengan aturan resmi yang sama. Kamu menulis sekali, gudang mana pun dilayani — itulah kenapa dipilih daripada kurir khusus MySQL (mysqli).
- **`Connection` (singleton)** = **satu kontak resmi** kurir: seluruh kantor memakai satu pintu yang sama, tidak membuat kurir baru setiap berkas (hemat, konsisten).
- **Pengaturan PDO** = *standar pengiriman*: exception mode (kalau surat nyasar → teriak, bukan diam), FETCH_ASSOC (surat sampail di meja sebagai kertas berlabel kolom), emulate=false (surat diantarkan ke gudang *asli*, bukan fotokopi).
- **Credential di environment** = kunci gudang disimpan di brankas (env), bukan ditulis di meja (kode) — mater 25/30 memperkuat.

---

## 5. Kapan Harus Digunakan & Kasus Penggunaan

- **Seluruh aplikasi mulai Level 4** — setiap operasi data melewati `Connection::getInstance()`.
- **Kapan DB dibutuhkan:** data banyak & relasional (buku ↔ peminjaman ↔ anggota), concurrency, query kompleks, transaksi.
- **Batas penggunaan JSON (17):** data kecil, prototipe. Begitu butuh `JOIN`, `WHERE`, `ORDER BY`, dan ribuan record → DB.
- **Kasus nyata:** `BukuRepository` (materi 21) memanggil `Connection::getInstance()` untuk semua method CRUD; halaman web memanggil repository — bukan PDO langsung.

---

## 6. Aspek Keamanan & Best Practices (Critical)

- **Credential jangan di-hardcode** — tutup dengan `getenv()` / `.env` (Level 6), tanpa commit ke git (`.gitignore`). Menambah secret = bocor → *leak*.
- **Jangan tampilkan `PDOException` ke user** — log detail, lempar pesan umum. Bocornya string koneksi = amunisi serangan.
- **`ATTR_EMULATE_PREPARES=false` WAJIB** — memakai prepared statement *native*. Ini salah satu garis pertahanan SQLi (materi 21). 
- **Hampir seluruh query dinamis harus prepared** — `$pdo->query()` hanya untuk query statis tanpa input.
- **Best practices:**
  - Singleton `Connection` (getInstance) — satu koneksi, tidak membuat berulang di tiap halaman.
  - Selalu `utf8mb4` (charset DB, DSN, dan init command) — hindari data rusak & XSS encoding issues.
  - Error log satu tempat; environment file terpisah (dev vs prod — materi 4/30).
  - Arahkan operasi data lewat Repository (21) — jangan menyebar SQL di view/controller.

---

## 7. Kesalahan Umum & Debugging

- **`PDOException: SQLSTATE[HY000] [1045] Access denied for user`** — credential salah (pass/user). Cek env & user MySQL. Jangan tampilkan detail saat production.
- **`SQLSTATE[HY000] [2002] Connection refused`** — server MySQL tidak berjalan. Start via Laragon/XAMPP Control. Jika pakai port beda (`getenv('DB_PORT')`), sesuaikan DSN.
- **`SQLSTATE[42000] [1049] Unknown database`** — nama database tidak ada / salah ketik. Pastikan sudah `CREATE DATABASE`; cek `DB_NAME`.
- **`driver not found`** — ekstensi `pdo_mysql` belum aktif (`php -m`, materi 2). Aktifkan di `php.ini`.
- **Warning `Uncaught PDOException`** dengan detail panjang — itu desainnya: dengan `ERRMODE_EXCEPTION`, error jadi exception. Baca pesan *pertama* baris `PDOException:`.
- **Singleton bermasalah saat testing** — `self::$instancia` terkunci; untuk tes/unit berpindah DB, sediakan cara reset instance (misal `Connection::reset()` saat testing — materi 28).

## 8. Soal Latihan & Kunci Jawaban

### Tantangan 1
Buat koneksi PDO dengan pengaturan yang benar (singleton + env), lalu jalankan `SELECT 1` sebagai tes kesehatan, dan `SELECT DATABASE()`, `SELECT VERSION()`. Tampilkan versi tanpa bocor credential. Jika gagal, perbaiki dengan membaca pesan `PDOException`.

### Tantangan 2
Jelaskan perbedaan hasil antara dua kode berikut saat query gagal (misal tabel tidak ada), dan mengapa membedakannya penting:

```php
$a = new PDO($dsn, $u, $p);            // tanpa opsi
$b = Connection::getInstance();          // singleton dengan ERRMODE_EXCEPTION
```

### Jawaban & Pembahasan

**Tantangan 1**

```php
<?php
require_once 'src/Database/Connection.php';

try {
    $pdo = Connection::getInstance();

    $versi   = $pdo->query('SELECT VERSION() AS v')->fetchColumn();
    $database = $pdo->query('SELECT DATABASE()')->fetchColumn();

    printf("DB: %s — MySQL %s\n", htmlspecialchars((string) $database), htmlspecialchars((string) $versi));
} catch (Throwable $e) {
    error_log($e->getMessage());
    echo 'Koneksi ke database gagal. Periksa service/localhost di control panel & kredensial.';
}
```

> **Pembahasan alur:** Semua query statis boleh `query()`; hasil dibaca dengan `fetchColumn()` (nilai pertama). Blok `try/catch` memastikan kegagalan tidak menampilkan detail — di log tertulis `PDOException` yang sebenarnya, di layar hanya pesan umum. Ini pola error-handling DB yang akan kamu bawa ke aplikasi penuh.

**Tantangan 2** — `$a` dibuat tanpa opsi → **default mode PDO adalah `ERRMODE_SILENT`**: query yang gagal hanya menyetor `errorCode()`/`errorInfo()`, tanpa teriakan; kode akan melanjutkan eksekusi dengan `false`/kosong — bug "database error diam-diam". `$b` (Connection singleton) menggunakan `ERRMODE_EXCEPTION` → setiap kegagalan melempar `PDOException`, sehingga *harus* ditangkap; kamu tidak bisa kehilangan error. Perbedaan ini penting karena mode silent menyamarkan kesalahan SQL dan menyulitkan debugging — sementara exception memaksa kamu menangani kegagalan dengan sadar (dan bisa di-log).

> **Pembahasan:** Ini satu alasan besar kamu menggunakan `Connection::getInstance()` (dengan options) di seluruh aplikasi — bukan membuat `new PDO` acak di tiap file tanpa opsi.
