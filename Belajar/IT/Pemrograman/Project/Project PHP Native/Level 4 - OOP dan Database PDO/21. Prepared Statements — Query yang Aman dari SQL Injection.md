# 21. Prepared Statements — Query yang Aman dari SQL Injection

> **Level 4 · OOP dan Database PDO** — Fondasi keamanan paling penting di PHP: setiap query yang menyentuh data dari user.

---

## 1. Penjelasan Singkat & Konsep Dasar

**Prepared Statement** = memisahkan dua hal yang sampai sekarang dicampur: **struktur SQL** dan **nilai data**. Query dikirim ke database *dalam dua tahap*:

1. **Prepare**: `prepare("SELECT * FROM buku WHERE id = :id")` — MySQL mem-parse & menyusun rencana eksekusi. Simbol `:id` adalah *placeholder*, bukan nilai.
2. **Execute**: `execute([':id' => 5])` — nilai dikirim **secara terpisah**, DB memperlakukan seluruh nilai sebagai *data*, bukan *kode*.

Karena nilai tidak pernah disuntikkan ke dalam string SQL, **SQL injection secara arsitektural mustahil** lewat nilai placeholder.

```php
// ❌ Aplikasi rentan — nilai dicampur ke string SQL
$stmt = $pdo->query("SELECT * FROM buku WHERE id = $id");

// ✅ Aman — struktur & nilai dipisah
$stmt = $pdo->prepare("SELECT * FROM buku WHERE id = :id");
$stmt->execute([':id' => $id]);
```

**Dengan `ATTR_EMULATE_PREPARES=false`** (materi 20), prepared statement dijalankan *native* di mesin MySQL (protokol dua fase) — bukan didorong oleh PHP sebagai string. Keamanan & kecepatan maksimal.

**Benang Merah:** materi 20 memberi koneksi; materi ini memberi kebiasaan query yang benar. Ini yang dicari-cari: "prepared statement di SETIAP query — tanpa pengecualian" adalah *rule #4* di roadmap. Kelanjutannya membangun `BukuRepository` — class yang memuat CRUD + transaksi.

---

## 2. Fungsi & Kegunaan Utama

- **Mencegah SQL Injection** — sebab utama keberadaannya. User yang input `1; DROP TABLE buku; --` tidak akan pernah dianggap kode.
- **Kecepatan** — query yang sama dengan nilai berbeda bisa di-prepare sekali lalu di-execute banyak kali (terutama saat reuse statement).
- **Kebersihan kode** — nilai tetap terpisah, mudah dibaca; placeholder memberi nama (`:id`) yang memperjelas maksud.
- **Konsistensi type handling** — placeholder di-bind dengan tipe eksplisit (`PDO::PARAM_INT`) sehingga lolos ke "strict typing" sisi database.

## 3. Contoh Kode & Implementasi Real-World

Struktur Repository:

```
src/
├── Database/Connection.php       ← materi 20
└── Repositories/
    └── BukuRepository.php
```

```php
<?php
// File: src/Repositories/BukuRepository.php
declare(strict_types=1);

require_once __DIR__ . '/../Database/Connection.php';

class BukuRepository {
    private PDO $db;

    public function __construct() {
        $this->db = Connection::getInstance();
    }

    // ─── READ ────────────────────────────────────────────────────────────

    public function findAll(
        int $halaman = 1,
        int $perHalaman = 10,
        string $keyword = '',
        string $kategori = ''
    ): array {
        $offset = ($halaman - 1) * $perHalaman;
        $params = [];

        $sql = "SELECT * FROM buku WHERE deleted_at IS NULL";

        // Bangun query DINAMIS dengan aman: hanya tambahkan klausa + placeholder
        if ($keyword !== '') {
            $sql .= " AND (judul LIKE :keyword OR pengarang LIKE :keyword2)";
            $params[':keyword']  = "%{$keyword}%";
            $params[':keyword2'] = "%{$keyword}%";
        }
        if ($kategori !== '' && $kategori !== 'semua') {
            $sql .= " AND kategori = :kategori";
            $params[':kategori'] = $kategori;
        }

        $sql .= " ORDER BY judul ASC LIMIT :limit OFFSET :offset";

        $stmt = $this->db->prepare($sql);

        // LIMIT/OFFSET harus di-bind sebagai integer!
        $stmt->bindValue(':limit', $perHalaman, PDO::PARAM_INT);
        $stmt->bindValue(':offset', $offset, PDO::PARAM_INT);

        foreach ($params as $key => $value) {
            $stmt->bindValue($key, $value, PDO::PARAM_STR);
        }

        $stmt->execute();
        return $stmt->fetchAll();
    }

    public function hitungTotal(string $keyword = '', string $kategori = ''): int {
        $params = [];
        $sql = "SELECT COUNT(*) FROM buku WHERE deleted_at IS NULL";

        if ($keyword !== '') {
            $sql .= " AND (judul LIKE :keyword OR pengarang LIKE :keyword2)";
            $params[':keyword']  = "%{$keyword}%";
            $params[':keyword2'] = "%{$keyword}%";
        }
        if ($kategori !== '' && $kategori !== 'semua') {
            $sql .= " AND kategori = :kategori";
            $params[':kategori'] = $kategori;
        }

        $stmt = $this->db->prepare($sql);
        $stmt->execute($params);
        return (int) $stmt->fetchColumn();
    }

    public function findById(int $id): ?array {
        $stmt = $this->db->prepare(
            "SELECT * FROM buku WHERE id = :id AND deleted_at IS NULL"
        );
        $stmt->execute([':id' => $id]);
        $row = $stmt->fetch();
        return $row !== false ? $row : null;
    }

    // ─── CREATE ──────────────────────────────────────────────────────────

    public function create(array $data): int {
        $stmt = $this->db->prepare(
            "INSERT INTO buku (judul, pengarang, isbn, tahun, harga, stok, kategori, deskripsi)
             VALUES (:judul, :pengarang, :isbn, :tahun, :harga, :stok, :kategori, :deskripsi)"
        );
        $stmt->execute([
            ':judul'     => $data['judul'],
            ':pengarang' => $data['pengarang'],
            ':isbn'      => $data['isbn'] ?? null,
            ':tahun'     => $data['tahun'],
            ':harga'     => $data['harga'],
            ':stok'      => $data['stok'],
            ':kategori'  => $data['kategori'],
            ':deskripsi' => $data['deskripsi'] ?? null,
        ]);
        return (int) $this->db->lastInsertId();
    }

    // ─── UPDATE ──────────────────────────────────────────────────────────

    public function update(int $id, array $data): bool {
        $stmt = $this->db->prepare(
            "UPDATE buku SET
                judul = :judul, pengarang = :pengarang, isbn = :isbn,
                tahun = :tahun, harga = :harga, stok = :stok,
                kategori = :kategori, deskripsi = :deskripsi,
                updated_at = NOW()
             WHERE id = :id AND deleted_at IS NULL"
        );
        $stmt->execute([
            ':judul'     => $data['judul'],
            ':pengarang' => $data['pengarang'],
            ':isbn'      => $data['isbn'] ?? null,
            ':tahun'     => $data['tahun'],
            ':harga'     => $data['harga'],
            ':stok'      => $data['stok'],
            ':kategori'  => $data['kategori'],
            ':deskripsi' => $data['deskripsi'] ?? null,
            ':id'        => $id,
        ]);
        return $stmt->rowCount() > 0;
    }

    // ─── DELETE (Soft Delete) ────────────────────────────────────────────

    public function delete(int $id): bool {
        $stmt = $this->db->prepare(
            "UPDATE buku SET deleted_at = NOW() WHERE id = :id AND deleted_at IS NULL"
        );
        $stmt->execute([':id' => $id]);
        return $stmt->rowCount() > 0;
    }

    // ─── TRANSACTION — operasi atomic (semua berhasil, atau semua batal) ──

    public function pinjamBuku(int $bukuId, int $anggotaId): int {
        try {
            $this->db->beginTransaction();

            // Cek stok DENGAN LOCKING (mencegah double-borrow saat concurrency)
            $stmt = $this->db->prepare(
                "SELECT stok FROM buku WHERE id = :id AND deleted_at IS NULL FOR UPDATE"
            );
            $stmt->execute([':id' => $bukuId]);
            $buku = $stmt->fetch();

            if (!$buku || (int) $buku['stok'] < 1) {
                throw new \RuntimeException('Stok buku tidak tersedia.');
            }

            // Kurangi stok
            $this->db->prepare("UPDATE buku SET stok = stok - 1 WHERE id = :id")
                     ->execute([':id' => $bukuId]);

            // Catat peminjaman
            $stmt = $this->db->prepare(
                "INSERT INTO peminjaman (buku_id, anggota_id, tanggal_pinjam, batas_kembali)
                 VALUES (:buku_id, :anggota_id, CURDATE(), DATE_ADD(CURDATE(), INTERVAL 14 DAY))"
            );
            $stmt->execute([':buku_id' => $bukuId, ':anggota_id' => $anggotaId]);

            $peminjamanId = (int) $this->db->lastInsertId();
            $this->db->commit();

            return $peminjamanId;
        } catch (\Exception $e) {
            $this->db->rollBack();
            throw $e;
        }
    }
}
```

## 4. Analogi Sederhana

Dalam **Sistem Administrasi Kantor**:

- Query tanpa prepared statement = staf menulis surat dengan **menggabungkan teks user mentah** ke dalam formulir resmi. Kalau user menulis "catatan: beri tahu semua orang — HAPUS semua berkas", kalimat itu jadi *instruksi eksekusi*, bukan isian.
- **Prepared statement** = staf menyiapkan **formulir dengan kolom kosong yang sudah diberi label** (placeholder `:id`), lalu user hanya **mengisi kolom** dalam langkah terpisah. Apapun yang diisi user — termasuk kalimat jahat — tetap diperlakukan sebagai *isi kolom*, bukan instruksi baru.
- **`bindValue(..., PDO::PARAM_INT)`** = staf menegaskan "kolom ini harus berupa angka" sebelum dikirim ke arsip.
- **Transaction** = sekumpulan langkah yang **disahkan bersamaan** (selesai semua atau batal semua) — seperti "tandatangani berkas pinjam sekaligus stok berkurang"; kalau satu gagal, seluruh transaksi urung (rollback).

## 5. Kapan Harus Digunakan & Kasus Penggunaan

- **SETIAP query yang menyentuh data dari user** — itu artinya: hampir semua query CRUD. Tidak ada pengecualian, bahkan untuk integer (`$id = (int) $_GET['id'] ?? 0` masih harus via prepared).
- **Query dinamis dengan banyak kondisi** — `findAll` dengan filter keyword/kategori — struktur SQL dibangun *(whitelisted keys)* sementara *nilai* selalu placeholder.
- **INSERT / UPDATE / DELETE** — selalu prepared.
- **SELECT statis tanpa input** — boleh `$pdo->query()` (misal `SELECT 1`, materi 20), tapi kebiasaan konsisten tetap prepared jika ada peluang berkembang.
- **Transaksi** — operasi multi-tabel yang harus *atomic* (pinjam buku = cek stok + kurangi + insert).

---

## 6. Aspek Keamanan & Best Practices (Critical)

- **JANGAN menyambung input user ke string SQL** (`"WHERE id = $id"`) — ini *definisi* SQL injection. Semua nilai lewat placeholder.
- **Jangan hanya "escape string untuk SQL"** — `mysqli_real_escape_string` & `addslashes` adalah pola lama yang rapuh (bug encoding, emulasi). Prepared statement native = standar.
- **Bagian SQL yang *strutural* (nama kolom, keyword ORDER BY) TIDAK bisa di-placeholder** — untuk bagian itu, gunakan **whitelist** (materi 11 pola `$fieldValid`): pastikan nilai ada di daftar sah *sebelum* dimasukkan ke string. Contoh di `findAll`: `LIMIT`, `OFFSET` di-bind sebagai int.
- **`rowCount()` untuk UPDATE/DELETE** — untuk mengetahui effect; perhatikan sebagian driver menolaknya setelah `SELECT` (untuk SELECT gunakan `fetch`/`fetchAll`).
- **Best practices:**
  - Repository satu tempat untuk semua SQL (bukan tersebar di view).
  - `bindValue` untuk type hinting (int vs string); `execute()` ke array cukup untuk sebagian besar.
  - Gunakan `FETCH_ASSOC` + `Buku::fromArray()` (materi 18) untuk mem-produce object.
  - Pakai transaksi `beginTransaction`/`commit`/`rollBack` untuk atomicity.
  - Log exception DB, tampilkan pesan umum (materi 20).

## 7. Kesalahan Umum & Debugging

- **`SQLSTATE[HY093]: Invalid parameter number`** — placeholder tidak cocok jumlah/nama antara query & array. Cek: `:keyword` `:keyword2` harus sama persis di query & bind (sering typo `:keyword2`).
- **`SQLSTATE[42000]: Syntax error` pada LIMIT** — `LIMIT :limit` tidak bisa di-execute sebagai string; harus `bindValue(..., PDO::PARAM_INT)` (materi pola di atas). Ini error paling umum.
- **`Cannot pass value by reference`** — memakai `bindParam()` dengan nilai langsung (bukan variabel); gunakan `bindValue()` atau variabel.
- **`fetchAll` selalu array kosong padahal data ada** — cek: query salah (misal f& `deleted_at IS NULL` menghilangkan semua data), salah tabel/kolom, atau `FETCH_ASSOC` tepat tapi kolom tidak ada. Baca `errorInfo()`.
- **Prepared statement bernilai "tidak terpakai"** — membangun ulang string SQL tiap loop itu tidak efisien; siapkan sekali, lakukan `execute` berulang (misal bulk insert).
- **`rollBack()` dipanggil tanpa transaksi aktif** → `ActiveRecordException`/warning; hanya panggil di dalam `catch` ketika `inTransaction()`.

## 8. Soal Latihan & Kunci Jawaban

### Tantangan 1
Tulis method `cariByKategoriDanHarga(BukuRepository)` (atau fungsi) yang menerima `kategori` dan `hargaMaks` dari user, menggunakan prepared statement, mengembalikan array judul-harga. Khusus: `hargaMaks` harus diproses sebagai argumen numerik tanpa bisa mengganti query secara injeksi. Sertakan versi "salah" untuk melihat apa yang dicegah.

### Tantangan 2
Perhatikan query dinamis di bawah — di mana celahnya, dan bagaimana memperbaikinya dengan whitelist + prepared?

```php
$sort = $_GET['sort'] ?? 'judul';
$stmt = $pdo->query("SELECT * FROM buku ORDER BY $sort");
```

### Jawaban & Pembahasan

**Tantangan 1**

```php
<?php
declare(strict_types=1);

function cariByKategoriDanHarga(PDO $pdo, string $kategori, string $hargaMaks): array {
    $stmt = $pdo->prepare(
        "SELECT judul, harga FROM buku
         WHERE kategori = :kategori AND harga <= :harga_maks AND deleted_at IS NULL"
    );
    // bind dengan tipe eksplisit
    $stmt->bindValue(':kategori', $kategori, PDO::PARAM_STR);
    $stmt->bindValue(':harga_maks', (float) $hargaMaks, PDO::PARAM_STR);

    $stmt->execute();
    return $stmt->fetchAll();
}

// ❌ Versi rentan (untuk dibandingkan):
// $sql = "SELECT judul, harga FROM buku WHERE kategori = '$kat' AND harga <= $h;
// → input "teknologi' OR '1'='1" bisa mengosongkan filter, dsb.

// ✅ Pemakaian yang akan dijalankan:
$hasil = cariByKategoriDanHarga($pdo, 'Teknologi', '200000');
```

> **Pembahasan alur:** Struktur SQL statis; seluruh nilai masuk lewat placeholder. `hargaMaks` di-cast ke `float` sebelum bind (validasi numerik sisi aplikasi + tipe di DB). Karena seluruh nilai buta hurufnya hanya *data*, payload injeksi — misal `"Teknologi' OR '1'='1"` — menjadi nilai kabur yang tidak mengubah logika query. Inilah zero-SQLi architecture.

**Tantangan 2** — Celah: bagian `ORDER BY $sort` **menggabungkan nilai user langsung ke string SQL**. Placeholder TIDAK bisa dipakai untuk nama kolom/order. Jika user kirim `sort=harga; DROP TABLE buku;--` (atau `judul ASC, ...`), seluruhnya dieksekusi.

Perbaikan: **whitelist** untuk kolom dan arah:

```php
$kolomDiizinkan = ['judul', 'pengarang', 'harga', 'tahun'];
$arahDiizinkan  = ['asc' => 'ASC', 'desc' => 'DESC'];

$sort = $_GET['sort'] ?? 'judul';
$arah = ($_GET['arah'] ?? 'asc') === 'desc' ? 'DESC' : 'ASC';

if (!in_array($sort, $kolomDiizinkan, true)) {
    $sort = 'judul';            // default aman
}

$sql = "SELECT * FROM buku ORDER BY {$sort} {$arah}";
// ↑ $sort hanya bernilai dari whitelist, $arah hanya ASC/DESC → tidak ada injeksi
$stmt = $pdo->query($sql);
$buku = $stmt->fetchAll();
```

> **Pembahasan:** Ambiguitas penting: *nilai data* selalu lewat placeholder; *bagian struktural* (nama kolom ORDER BY) hanya boleh dari **whitelist deterministik** yang tidak bisa dimanipulasi. Inilah dua sisi aturan "query dinamis aman" yang akan dipakai di Router/Controller (materi 26) dan REST API (27).
