# 27. Membangun REST API yang Proper

> **Level 6 · Arsitektur MVC dan REST API** — Output JSON yang konsisten, keras status code, dan aman untuk dikonsumsi aplikasi lain.

---

## 1. Penjelasan Singkat & Konsep Dasar

**REST API** = aplikasi web yang *tidak* mengembalikan HTML, melainkan **data (JSON)** — untuk dikonsumsi frontend (JS), aplikasi mobile, aplikasi lain, atau satu sama lain. Pola yang sudah kamu kenal (router, controller, repository) **tetap dipakai**; yang berubah: **format respons** (JSON) dan **status code** yang dimaknai dengan benar.

**Konsep REST singkat:**

| Method | Makna | Contoh endpoint |
|---|---|---|
| GET | baca (tanpa efek samping) | `GET /api/buku` |
| GET (dengan id) | baca satu | `GET /api/buku/5` |
| POST | buat baru | `POST /api/buku` |
| PUT / PATCH | perbarui | `PUT /api/buku/5` |
| DELETE | hapus | `DELETE /api/buku/5` |

**Konteks:** bisa **dipakai langsung `curl`** atau `fetch()` JS. Router (materi 26) sudah mendukung method; tinggal controller-nya fokus JSON.

**Struktur respons JSON yang konsisten** — kunci kebisaan bagi klien:

```json
// Sukses
{ "success": true, "data": { ... }, "meta": { ... } }

// Error
{ "success": false, "message": "...", "errors": { "field": "msg" } }
```

**Benang Merah:** semua yang sudah dipelajari dikonversi ke "API kontrak": router (26) → endpoint; repository (21) → data; validasi (14) → 422; keamanan (22-23) → token & rate limit. Ini titik puncak arsitektur sebelum mengunci dengan testing & deployment (28-30).

---

## 2. Fungsi & Kegunaan Utama

- **Reusability lintas platform** — data yang sama bisa dipakai web app, mobile, atau dashboard partner.
- **Pemisahan front-back yang tegas** — frontend tinggal panggil endpoint; backend fokus data & keamanan. Interchangeable.
- **Status code sebagai bahasa** — 200 sukses, 201 created, 400 bad request, 401 unauthorized, 403 forbidden, 404 not found, 422 validation, 429 rate limited, 500 server error.
- **Throttling / rate limiting** — `429 Too Many Requests` dengan `Retry-After`.
- **Token-based auth** — API tidak memakai session browser; memakai `Bearer <token>` (Authorization header).

**`src/Security/ApiAuth.php` — token auth helper:**

```php
<?php
// File: src/Security/ApiAuth.php
declare(strict_types=1);

namespace App\Security;

class ApiAuth {
    /** Ambil token Bearer dari header Authorization. */
    public static function berikanToken(): ?string {
        $header = $_SERVER['HTTP_AUTHORIZATION'] ?? '';
        if (preg_match('/^Bearer\s+(.+)$/', $header, $matches)) {
            return trim($matches[1]);
        }
        return null;
    }

    /** Verifikasi token terhadap tabel api_tokens. */
    public static function userDariToken(PDO $pdo, string $token): ?array {
        // Hash token saat simpan: simpan SHA256 hash, bandingkan hash_equals
        $hash = hash('sha256', $token);
        $stmt = $pdo->prepare(
            "SELECT id, nama, role FROM api_tokens t
             JOIN anggota u ON u.id = t.user_id
             WHERE t.token_hash = :h AND t.expired_at > NOW() LIMIT 1"
        );
        $stmt->execute([':h' => $hash]);
        $user = $stmt->fetch();
        return $user !== false ? $user : null;
    }
}
```

**`src/Controllers/Api/BukuApiController.php`:**

```php
<?php
// File: src/Controllers/Api/BukuApiController.php
declare(strict_types=1);

namespace App\Controllers\Api;

use App\Core\Request;
use App\Repositories\BukuRepository;
use App\Security\ApiAuth;

class BukuApiController {
    private BukuRepository $bukuRepo;
    private \PDO $db;

    public function __construct() {
        $this->bukuRepo = new BukuRepository();
        $this->db = \App\Database\Connection::getInstance();
        header('Content-Type: application/json; charset=utf-8');
    }

    // GET /api/buku
    public function index(Request $request): void {
        $this->requireToken(['admin', 'pustakawan', 'anggota']);

        $halaman    = max(1, (int) ($request->getQuery('halaman') ?? 1));
        $perHalaman = min(100, max(1, (int) ($request->getQuery('per_halaman') ?? 15)));
        $keyword    = (string) ($request->getQuery('q') ?? '');
        $kategori   = (string) ($request->getQuery('kategori') ?? '');

        $buku  = $this->bukuRepo->findAll($halaman, $perHalaman, $keyword, $kategori);
        $total = $this->bukuRepo->hitungTotal($keyword, $kategori);

        $this->jsonResponse([
            'data' => $buku,
            'meta' => [
                'halaman'         => $halaman,
                'per_halaman'     => $perHalaman,
                'total'           => $total,
                'total_halaman'   => (int) ceil($total / $perHalaman),
            ],
        ]);
    }

    // GET /api/buku/{id}
    public function show(Request $request, array $params): void {
        $this->requireToken(['admin', 'pustakawan', 'anggota']);

        $id   = (int) ($params['id'] ?? 0);
        $buku = $this->bukuRepo->findById($id);

        if ($buku === null) {
            $this->jsonError('Buku tidak ditemukan.', 404);
            return;
        }
        $this->jsonResponse(['data' => $buku]);
    }

    // POST /api/buku
    public function store(Request $request): void {
        $this->requireToken(['admin']);

        $body = $this->jsonBody($request);
        $errors = $this->validasiBuku($body);

        if (!empty($errors)) {
            $this->jsonError('Validasi gagal.', 422, $errors);
            return;
        }

        try {
            $id = $this->bukuRepo->create($body);
            $buku = $this->bukuRepo->findById($id);
            $this->jsonResponse(['data' => $buku], 201);
        } catch (\Exception $e) {
            error_log($e->getMessage());
            $this->jsonError('Gagal menyimpan buku.', 500);
        }
    }

    // PUT /api/buku/{id}
    public function update(Request $request, array $params): void {
        $this->requireToken(['admin']);

        $id = (int) ($params['id'] ?? 0);
        $body = $this->jsonBody($request);
        $errors = $this->validasiBuku($body);

        if (!empty($errors)) {
            $this->jsonError('Validasi gagal.', 422, $errors);
            return;
        }

        if (!$this->bukuRepo->update($id, $body)) {
            $this->jsonError('Buku tidak ditemukan atau tidak diubah.', 404);
            return;
        }
        $this->jsonResponse(['data' => $this->bukuRepo->findById($id)]);
    }

    // DELETE /api/buku/{id}
    public function destroy(Request $request, array $params): void {
        $this->requireToken(['admin']);

        $id = (int) ($params['id'] ?? 0);
        if (!$this->bukuRepo->delete($id)) {
            $this->jsonError('Buku tidak ditemukan.', 404);
            return;
        }
        $this->jsonResponse(['message' => 'Buku dihapus.']);
    }

    // ─── Helpers ─────────────────────────────────────────────────────────

    private function requireToken(array $roles): array {
        $token = ApiAuth::berikanToken();
        $user  = $token !== null ? ApiAuth::userDariToken($this->db, $token) : null;

        if ($user === null) {
            $this->jsonError('Token tidak valid atau kedaluwarsa.', 401);
            exit;
        }
        if (!in_array($user['role'], $roles, true)) {
            $this->jsonError('Akses ditolak.', 403);
            exit;
        }
        return $user;
    }

    private function jsonBody(Request $request): array {
        $raw = file_get_contents('php://input');
        $data = json_decode($raw, true);
        if (!is_array($data)) {
            $this->jsonError('Body JSON tidak valid.', 400);
            exit;
        }
        return $data;
    }

    private function validasiBuku(array $d): array {
        $errors = [];
        if (empty(trim($d['judul'] ?? ''))) $errors['judul'] = 'Judul wajib diisi.';
        if (empty(trim($d['pengarang'] ?? ''))) $errors['pengarang'] = 'Pengarang wajib diisi.';
        $harga = $d['harga'] ?? null;
        if (!is_numeric($harga) || (int) $harga < 0) $errors['harga'] = 'Harga harus angka ≥ 0.';
        return $errors;
    }

    private function jsonResponse(array $data, int $status = 200): void {
        http_response_code($status);
        echo json_encode(
            ['success' => true] + $data,
            JSON_UNESCAPED_UNICODE | JSON_PRETTY_PRINT
        );
        exit;
    }

    private function jsonError(string $pesan, int $status, array $errors = []): void {
        http_response_code($status);
        $resp = ['success' => false, 'message' => $pesan];
        if (!empty($errors)) $resp['errors'] = $errors;
        echo json_encode($resp, JSON_UNESCAPED_UNICODE);
        exit;
    }
}
```

# POST buat (admin only)

# Tanpa token → 401
curl -i http://localhost:8000/api/buku

## 4. Analogi Sederhana

Dalam **Sistem Administrasi Kantor**:

- **REST API** = **layanan kurir antar-lembaga**: bukan memberikan *surat (HTML)* kepada manusia, melainkan **data terstruktur (formulir JSON)** kepada sistem lain.
- **Endpoint** (`/api/buku/5`) = **alamat layanan khusus** — kalau kamu tahu alamatnya, kamu bisa meminta data.
- **Method** = *jenis permintaan*: AMBIL (GET), BUAT (POST), GANTI (PUT), HAPUS (DELETE).
- **Status code** = *nomor kode jawaban* resepsionis: 200 "ini datanya", 201 "data baru dibuat", 401 "kamu belum punya kartu masuk", 403 "kartumu tidak berhak ke ruang ini", 404 "ruang itu tidak ada", 422 "formulirmu salah isi", 429 "terlalu sering meminta".
- **Bearer token** = **kartu khusus API** yang menunjukkan identitas & wewenang tanpa memberi tahu password. Dicocokkan dengan hash tersimpan (materi 23-prinsipel `hash_equals`).
- **JSON yang konsisten** = *format standar surat* — semua kurir tahu persis di mana isi & pesannya, samping pertama kali.

## 5. Kapan Harus Digunakan & Kasus Penggunaan

- **Butuh konsumsi lintas platform** — SPA (JS), mobile, integrasi partner.
- **Operasi yang diprogram** — bot/script mengambil data, sync data, dasbor external.
- **API publik/internal** — katalog untuk aplikasi lain, atau dashboard admin yang memuat data via fetch.
- **Kapan TIDAK**: aplikasi internal kecil yang halaman-nya server-rendered (bisa memakai form biasa). API menambah lapisan (auth token, JSON) dengan harga tetap.
- **Praktik baik produk**: versi API (`/api/v1/buku`) → perubahan non-backward-compatible tidak merusak klien lama.

---

## 6. Aspek Keamanan & Best Practices (Critical)

- **Token untuk API, BUKAN session cookie** — browser-form (session+CSRF) vs API (Bearer token). Jangan campur pola tanpa sadar.
- **Simpan token TERHASH** (`token_hash`) & bandingkan `hash_equals` — jangan simpan token plaintext di DB.
- **Role en route** — `requireToken(['admin'])` untuk aksi mutasi; GET mungkin terbuka untuk lebih banyak role.
- **Jangan mengembalikan data sensitif** — API `Buku` jangan pernah menyertakan `password_hash`, data internal, atau kolom yang tidak diperlukan (`select` hanya kolom yang hendak diekspos).
- **Rate limit API** — gunakan RateLimiter (materi 23) dengan identifier token/IP → `429`.
- **Validasi ulang di server** — body JSON dari `php://input` sama tidak tepercayanya dengan `$_POST`; non tepekan.
- **CORS jika diperlukan** — jika dikonsumsi dari domain lain, set header `Access-Control-Allow-Origin` secara ketat (bukan `*` untuk data sensitif).
- **Status code yang tepat** — jangan pernah mengembalikan 200 untuk error; klien bergantung pada kode.

---

## 7. Kesalahan Umum & Debugging

- **`json_decode` null walaupun body valid** — encoding salah (pastikan `Content-Type: application/json` dari klien) atau body kosong. Gunakan `json_last_error_msg()` saat debug.
- **401 padahal token ada** — token hash di DB beda (mungkin disimpan plaintext vs hash), atau cookie session tertukar dengan header Bearer. Debug: log decode header `HTTP_AUTHORIZATION`.
- **Route API ke Controller prime belum** — ketika route `/api/buku` tidak tercocok di router (pattern tidak cocok), controller `Api\BukuApiController` tidak ter-resolve. Cek urutan rute & classexists.
- **`headers already sent`** — `echo` sebelum `header()` (jalankan `Content-Type` di constructor sebelum output). Ingat: JSON output hanya di akhir.
- **Content-Type raw** — browser mengembalikan JSON tapi ditampilkan teks; pastikan `Content-Type: application/json` dan tidak ada output lain sebelumnya.
- **Cross-origin (CORS)** — request dari JS di domain lain tanpa header CORS akan diblokir browser. Tambah header sesuai whitelist origin.
- **Pengujian**: selalu cek status code & body di `curl -i`; jangan hanya lihat "ada output".

## 8. Soal Latihan & Kunci Jawaban

### Tantangan 1
Tambahkan endpoint `GET /api/kategori` yang mengembalikan daftar kategori beserta jumlah buku per kategori. Tentukan struktur respons & status code yang tepat; batasi dengan token (role mana pun yang diizinkan membaca). Tulis query prepared statement yang menghitungnya (satu `JOIN`/`GROUP BY`).

### Tantangan 2
Dapatkan contoh alur permintaan saat klien memanggil `DELETE /api/buku/3` dengan token **non-admin** (role `anggota`). Jelaskan setiap status code yang mungkin.

### Jawaban & Pembahasan

**Tantangan 1**

```sql
-- Query: kategori + jumlah buku (soft delete dipertimbangkan)
SELECT kategori, COUNT(*) AS jumlah
FROM buku
WHERE deleted_at IS NULL
GROUP BY kategori
ORDER BY kategori;
```

```php
// Endpoint di controller API (di dalam class):
public function kategori(Request $request): void {
    $this->requireToken(['admin', 'pustakawan', 'anggota']);

    $stmt = $this->db->prepare(
        "SELECT kategori, COUNT(*) AS jumlah
         FROM buku WHERE deleted_at IS NULL
         GROUP BY kategori ORDER BY kategori"
    );
    $stmt->execute();
    $kategori = $stmt->fetchAll();

    $this->jsonResponse(['data' => $kategori]);
}

// Route:
$router->get('/api/kategori', 'Api\\BukuApiController@kategori');
```

> **Pembahasan:** Endpoint read-only, semua role dengan token sah boleh akses (`requireToken` daftar role). Query `GROUP BY` menghitung jumlah per kategori — prepared statement untuk bagian nilai (di sini statis, tidak ada placeholder, tapi disiplin tetap). Respons `{success:true, data:[...]}` konsisten.

**Tantangan 2** — Alur `DELETE /api/buku/3` dengan token ber-role `anggota`:

1. Front controller → router cocok `delete('/api/buku/{id}')` → `BukuApiController@destroy`.
2. `router` memanggil `destroy`; di dalam: `requireToken([...]))` → `ApiAuth::berikanToken()` → valid → `userDariToken()` → user role `anggota`.
3. `requireToken(['admin'])` untuk destroy: `in_array('anggota', ['admin'])` → **false** → `jsonError('Akses ditolak.', 403)` → exit.
4. Status code: **401** jika token hilang/kedaluwarsa/buruk; **403** pada kasus di atas (token valid tapi role tidak diizinkan). Jika role admin dan buku tidak ada → **404**; jika sukses → **200** dengan `{success:true, message:...}`.

> **Pembahasan:** kunci membaca status: 401 = "saya tidak tahu siapa kamu", 403 = "saya tahu siapa kamu, tapi tidak berhak". Ini bahasa yang harus dipelihara konsisten di seluruh API (dan halaman web).
