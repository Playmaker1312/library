# 13. $_POST, $_GET, dan Superglobal PHP

> **Level 3 · Form, Session, dan File** — Pintu masuk data dari user ke aplikasi. Titik awal semua yang berhubungan dengan keamanan.

---

## 1. Penjelasan Singkat & Konsep Dasar

**Superglobal** adalah variabel khusus PHP yang **tersedia otomatis di mana pun** (tanpa `global`, tanpa deklarasi). Fungsinya menampung data yang datang bersama request HTTP dari browser.

```php
$_GET     // data dari URL query string (?q=clean)
$_POST    // data dari body form (method="POST")
$_SERVER  // informasi server & request (method, URI, IP, headers)
$_FILES   // file yang di-upload
$_SESSION // data sesi (materi 16)
$_COOKIE  // data cookie dari browser
$_REQUEST // gabungan GET+POST+COOKIE — HINDARI (ambigu & tidak jelas asal)
$_ENV     // variabel environment
```

**Fakta kritis yang wajib diingat:** semua superglobal yang dibawa user — `$_GET`, `$_POST`, `$_COOKIE` (dan isi `$_FILES`) — berisi **hanya string**, dan mereka **SELALU bisa dimanipulasi user**. Nilai di dalamnya adalah *data mentah*, bukan data tepercaya.

**GET vs POST:**

| | GET | POST |
|---|---|---|
| Data | di URL (`?a=1&b=2`) | di body request |
| Terlihat di history/log | Ya | Tidak |
| Bookmarkable / shareable | Ya | Tidak |
| Batas ukuran | Terbatas (URL length) | Lebih besar |
| Penggunaan | Pencarian, filter, navigasi | Form yang *mengubah data* |

**Benang Merah:** data di Level 1-2 masih *hardcode*. Superglobal adalah cara PHP menerima data yang betulan dikirim browser — jembatan ke validasi (14), form (15), session (16), dan akhirnya masukan ke database (Level 4).

---

## 2. Fungsi & Kegunaan Utama

- **Menangkap input user**: pencarian `katalog.php?q=clean`, filter `?kategori=Teknologi`, pagination `?halaman=2`.
- **Membedakan aksi HTTP method**: form POST ("simpan data") vs GET ("ambil/menyaring data").
- **Mengetahui konteks request**: `$_SERVER['REQUEST_METHOD']`, `$_SERVER['REQUEST_URI']`, `$_SERVER['REMOTE_ADDR']` — dipakai untuk routing (materi 26), rate limiting (materi 23), dan logging.
- **Menampung upload**: `$_FILES` (detail di materi 24).

---

## 3. Contoh Kode & Implementasi Real-World

`katalog.php` — pola pengambilan input yang AMAN (selalu dengan default & cast):

```php
<?php
// File: katalog.php
// SUPER PENTING: semua input dimulai dengan ?? (null coalescing) sebagai default
$keyword  = $_GET['q'] ?? '';                 // '' jika tidak ada
$kategori = $_GET['kategori'] ?? 'semua';
$halaman  = max(1, (int) ($_GET['halaman'] ?? 1)); // minimal 1
$id       = (int) ($_GET['id'] ?? 0);

echo "Method: " . htmlspecialchars($_SERVER['REQUEST_METHOD']) . "<br>";
echo "URI: " . htmlspecialchars($_SERVER['REQUEST_URI']) . "<br>";
echo "Mencari: " . htmlspecialchars($keyword) . ", kategori: " . htmlspecialchars($kategori);
```

`form.php` — pola handling POST (pembeda antara tampil form & proses submit):

```php
<?php
// File: login.php
// Pola POST-redirect-GET sederhana: jika request POST, proses; jika GET, tampil form

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $email = trim($_POST['email'] ?? '');
    $password = $_POST['password'] ?? '';

    // … validasi & proses login (materi 14, 16) …
} else {
    // tampilkan form
}
?>
<form method="POST" action="">
    <input type="email" name="email" required>
    <input type="password" name="password" required>
    <button type="submit">Login</button>
</form>
```

**Superglobal `$_SERVER` yang sering kamu pakai:**

```php
echo $_SERVER['REQUEST_METHOD'];   // GET / POST / PUT / DELETE
echo $_SERVER['REQUEST_URI'];      // /perpustakaan/katalog.php?q=clean
echo $_SERVER['HTTP_HOST'];        // localhost / perpustakaan.test
echo $_SERVER['REMOTE_ADDR'];      // IP address client
echo $_SERVER['HTTP_USER_AGENT'];  // string browser
echo $_SERVER['HTTPS'] ?? '';      // 'on' jika HTTPS

// Base URL dinamis (penting saat pindah server):
function baseUrl(): string {
    $protokol = (!empty($_SERVER['HTTPS']) && $_SERVER['HTTPS'] !== 'off') ? 'https' : 'http';
    $host = $_SERVER['HTTP_HOST'];
    $path = dirname($_SERVER['SCRIPT_NAME']);
    return $protokol . '://' . $host . ($path !== '/' ? $path : '');
}
```

## 4. Analogi Sederhana

Dalam **Sistem Administrasi Kantor**:

- **Browser/tamu** menitipkan **amplop permintaan** ke loket (web server).
- **`$_GET`** = permintaan yang ditulis **di amplop** (terlihat semua orang): "cari buku: Clean Code, kategori: Teknologi, halaman: 2". Siapa pun bisa lihat amplopnya.
- **`$_POST`** = permintaan yang ditulis di **lembar isian di dalam amplop** (tersembunyi): "simpan data anggota ini". Isinya tidak terlihat di URL.
- **Form** = lembar isian kosong yang dibagikan staf untuk diisi tamu.
- **`$_SERVER`** = *informasi tamu & waktu kedatangan* yang dicatat resepsionis: method yang dipakai, alamat, jam kedatangan.
- **Aturan "default & cast"** = staf mengantisipasi amplop kosong: "kalau tidak ada permintaannya, anggap 'semua'/halaman 1". Jangan pernah panik karena amplop kosong.

---

## 5. Kapan Harus Digunakan & Kasus Penggunaan

- **GET** → pencarian, filter, sorting, pagination, link detail (`show.php?id=5`): *tidak mengubah data* & bisa dibookmark.
- **POST** → semua form yang *menyimpan/mengubah/menghapus* data: tambah buku, login, edit, hapus.
- **PENTING**: jangan memasukkan data sensitif (password, token) ke GET — akan tercatat di history browser & server log.
- **`$_SERVER['REQUEST_METHOD']`** → routing & handling: pisahkan GET (tampil form) vs POST (proses) dalam satu file.
- **`$_FILES`** → form upload sampul buku (materi 24).
- **Kasus nyata:** `katalog.php?q=clean&kategori=Teknologi&halaman=2` → semua nilai dibaca dengan `??`, di-cast, lalu dipakai untuk filtering & pagination (materi 11/21).

## 6. Aspek Keamanan & Best Practices (Critical)

- **`$_GET`/`$_POST`/`$_COOKIE` = data tidak tepercaya.** Ini aturan #1 keamanan web: *never trust user input*. Setiap nilai bisa diubah user.
- **Selalu `??` + cast + validasi** sebelum dipakai (materi 14). Jangan pernah langsung concat ke SQL (materi 21) atau output tanpa escape (materi 22).
- **Jangan gunakan `$_REQUEST`** — asal datanya ambigu (GET/POST/COOKIE campur) — sulit diaudit & rawan bug dari namespace yang bertabrakan.
- **Jangan pernah meletakkan rahasia di URL** — token, password, session id harus lewat header/POST.
- **Best practices:**
  - Pisahkan *ia berubah data?* → POST, *ia hanya baca?* → GET.
  - Normalisasi: `trim()`, `strtolower()` untuk email dsb. (materi 9).
  - Batasi panjang input (`maxlength` di HTML TIDAK cukup — validasi ulang di server, materi 14).
  - Jangan tampilkan `$_GET`/`$_POST` mentah tanpa `htmlspecialchars`.

## 7. Kesalahan Umum & Debugging

- **`Undefined array key "q"`** — mengakses `$_GET['q']` saat key tidak ada. Solusi: `?? ''` atau `isset()`.
- **"Data dari form tidak sampai"** —
  - Saat ada `name` yang salah eja (PHP hanya melihat atribut `name`, bukan `id`).
  - Method form (`GET`/`POST`) tidak cocok dengan cara baca di PHP.
  - `enctype` salah saat upload file (`multipart/form-data` wajib — materi 24).
- **Bug "string vs int"** — semua `$_GET`/`$_POST` adalah **string**; `$_GET['halaman'] = "2"` perlu `(int)` sebelum dipakai aritmatika/pagination.
- **`Cannot modify header information`** — terjadi ketika `header()` dipanggil *setelah* ada output. Sering karena ada spasi/HTML sebelum `<?php`. Solusi: struktur file (materi 3/16).
- **Debug superglobal: `var_dump($_POST)` / `print_r($_GET)`** di awal handler — cara tercepat melihat data yang benar-benar dikirim browser.

## 8. Soal Latihan & Kunci Jawaban

### Tantangan 1
Buat `katalog.php` yang membaca `?q=&kategori=&halaman=` dengan pola aman (`??`, cast, `max`), lalu membangun pesan: *"Halaman 2 — 5 buku ditemukan untuk kategori Teknologi, query 'clean'."* Gunakan `htmlspecialchars` untuk semua output dari input.

### Tantangan 2
Sebuah halaman login menerima password lewat GET (`login.php?password=rahasia`). Sebutkan tiga alasan mengapa ini buruk dan bagaimana seharusnya.

### Jawaban & Pembahasan

**Tantangan 1**

```php
<?php
$q        = trim($_GET['q'] ?? '');
$kategori = $_GET['kategori'] ?? 'semua';
$halaman  = max(1, (int) ($_GET['halaman'] ?? 1));

$msg = sprintf(
    'Halaman %d — untuk kategori "%s", query "%s".',
    (int) $halaman,
    htmlspecialchars($kategori),
    htmlspecialchars($q)
);
echo $msg;
```

> **Pembahasan alur:** Setiap input diambil dengan default (`??`), dinormalisasi (`trim`, cast, `max` untuk halaman ≥ 1). Saat dipakai di output, semua input di-escape (`htmlspecialchars`) — sehingga jika user menaruh `<script>` di query string, yang tampil adalah teks polos, bukan eksekusi. Pola ini konsisten dari materi 3 hingga 22.

**Tantangan 2** — Alasan buruk:
1. **Bocor di URL & history** — password terlihat di browser history, referer header, server access log, dan bilah URL.
2. **Tidak bisa dibookmark/dibagikan tanpa bocor** — URL yang berisi password rawan disalin dan disebar.
3. **Hanya string, tidak cocok untuk data sensitif** — lewat GET berarti melewati URL; aturan umum data sensitif tidak boleh di URL.

Seharusnya: gunakan **POST** (data di body, tidak di URL), kirim lewat form `<form method="POST">`, kombinasikan dengan HTTPS (materi 30) dan proteksi CSRF (materi 14/22). Juga jangan pernah menampilkan/echo password di respons.

> **Pembahasan:** Ini contoh penerapan aturan "GET untuk membaca, POST untuk mengubah/aman". Data sensitif masuk kategori ketiga: **masa hidup di URL**. Penegasan penting: superglobal tidak membuat data otomatis aman — *cara penggunaannya* yang menentukan.
