# 17. Penyimpanan Data dengan File JSON

> **Level 3 · Form, Session, dan File** — Penutup Level 3: data mulai *menetap* — tanpa database dulu, dengan file JSON sederhana.

---

## 1. Penjelasan Singkat & Konsep Dasar

Selama Level 1-2 data ditulis hardcode di dalam kode — tiap refresh isinya sama. Level 3 menutup siklus dengan **persistence**: data bertahan di file, bisa ditambah/diubah/dihapus (CRUD) antar request.

**JSON (JavaScript Object Notation)** — format teks yang representasi arraynya sangat mirip struktur array PHP:

```php
$data = ['judul' => 'Clean Code', 'harga' => 150000];

// PHP array → string JSON
$json = json_encode($data, JSON_PRETTY_PRINT | JSON_UNESCAPED_UNICODE);
// {"judul":"Clean Code","harga":150000}

// string JSON → PHP array
$kembali = json_decode($json, true);   // true = jadi associative array
```

Kenapa JSON untuk storage sederhana? Karena **strukturnya persis array PHP**, mudah dibaca manusia (debug), dan mudah dipindah ke DB nanti. Ini adalah *jembatan*: pola CRUD-nya (tambah/Update/hapus/cari) identik dengan Repository + PDO di Level 4.

**Benang Merah:** form (13-15) sekarang benar-benar *menyimpan* data; session (16) mengidentifikasi siapa yang melakukan. Class `JsonStorage` di materi ini adalah "prototype" dari `BukuRepository` (materi 21). Semua konsep — autogenerate ID, update parsial, hapus via filter, transaksi (LOCK_EX) — akan kamu temui lagi dalam bentuk query SQL.

---

## 2. Fungsi & Kegunaan Utama

- **Menyimpan CRUD tanpa database** — mudah untuk prototipe/learning; tidak butuh install MySQL.
- **File JSON sebagai penyimpanan "berdasarkan kasus ringan"** — config, cache kecil, data yang jarang berubah.
- **Mengajarkan pola Repository** — interface (bacaSemua/tambah/update/hapus/cariById) = apa yang nanti dilakukan `SELECT/INSERT/UPDATE/DELETE`.
- **Praktis untuk data portable** — bisa di-backup/salin sebagai satu file, dibaca tool lain.

**Batas penting:** file JSON **bukan** pengganti database — tidak ada indexing, concurrency lambat, dan seluruh file dibaca-tulis setiap aksi. Gunakan sesuai porsinya.

## 3. Contoh Kode & Implementasi Real-World

Struktur file:

```
perpustakaan/
├── functions/
│   └── storage.php       ← class JsonStorage
├── data/
│   └── buku.json          ← dibuat otomatis
└── buku/
    ├── tambah.php         ← pakai materi 15
    └── katalog.php
```

```php
<?php
// File: functions/storage.php
declare(strict_types=1);

define('DATA_DIR', __DIR__ . '/../data/');

class JsonStorage {
    public function __construct(private string $namaFile) {
        if (!is_dir(DATA_DIR)) {
            mkdir(DATA_DIR, 0755, true);
        }
    }

    private function filePath(): string {
        return DATA_DIR . $this->namaFile . '.json';
    }

    /** Baca seluruh data dari file. */
    public function bacaSemua(): array {
        if (!file_exists($this->filePath())) {
            return [];
        }
        $json = file_get_contents($this->filePath());
        if ($json === false) {
            throw new RuntimeException("Gagal membaca file: {$this->filePath()}");
        }
        return json_decode($json, true) ?? [];
    }

    /** Tulis seluruh data ke file. */
    public function simpanSemua(array $data): bool {
        $json = json_encode($data, JSON_PRETTY_PRINT | JSON_UNESCAPED_UNICODE);
        // LOCK_EX: cegah race condition saat dua request menulis bersamaan
        return file_put_contents($this->filePath(), $json, LOCK_EX) !== false;
    }

    /** Tambah record baru dengan ID otomatis. */
    public function tambah(array $item): array {
        $data = $this->bacaSemua();
        $maxId = array_reduce($data, fn($carry, $d) => max($carry, $d['id'] ?? 0), 0);

        $item['id']         = $maxId + 1;
        $item['created_at'] = date('Y-m-d H:i:s');
        $item['updated_at'] = date('Y-m-d H:i:s');

        $data[] = $item;
        $this->simpanSemua($data);
        return $item;
    }

    /** Update sebagian field record by id. */
    public function update(int $id, array $dataUpdate): bool {
        $data  = $this->bacaSemua();
        $found = false;

        foreach ($data as &$item) {
            if (($item['id'] ?? null) === $id) {
                $item = array_merge($item, $dataUpdate);
                $item['updated_at'] = date('Y-m-d H:i:s');
                $found = true;
                break;
            }
        }
        unset($item);   // PENTING: lepas referensi setelah foreach!

        if ($found) {
            return $this->simpanSemua($data);
        }
        return false;
    }

    /** Hapus record by id. */
    public function hapus(int $id): bool {
        $data   = $this->bacaSemua();
        $before = count($data);
        $data   = array_values(array_filter($data, fn($d) => ($d['id'] ?? null) !== $id));

        return count($data) < $before && $this->simpanSemua($data);
    }

    /** Cari record by id. */
    public function cariById(int $id): ?array {
        foreach ($this->bacaSemua() as $item) {
            if (($item['id'] ?? null) === $id) return $item;
        }
        return null;
    }
}
```


## 4. Analogi Sederhana

Dalam **Sistem Administrasi Kantor**:

- **File JSON `buku.json`** = **lemari arsip pusat** tempat booklet berkas disimpan, satu baris per buku.
- **`bacaSemua()`** = staf *membuka lemari dan membaca seluruh map* ke meja kerja (array). MAHAL — sebab itu untuk DB nanti, `SELECT` tidak selalu mengambil semua.
- **`tambah()`** = staf *menulis nomor rekam baru* (autogenerate) lalu memasukkan map ke lemari.
- **`update()`** = staf *menemukan map by nomor* lalu memperbarui sebagian isi dengan spidol.
- **`hapus()`** = staf menarik map keluar dan *menulis ulang daftar* (filter + array_values).
- **`cariById()`** = staf menelusuri satu per satu sampai menemukan nomor yang diminta.
- **`LOCK_EX`** = staf *mengunci meja* saat menulis — dua staf tidak boleh menulis berkas yang sama bersamaan (mencegah data korup).

---

## 5. Kapan Harus Digunakan & Kasus Penggunaan

- **Prototipe & pembelajaran** — semua checkpoint Level 3 memakai JSON. Cepat, tanpa setup DB.
- **Data kecil & jarang berubah** — config, daftar statis, cache.
- **Sampai kapan?** — begitu data berkembang (banyak record, butuh query kompleks, relasi, concurrence), pindah ke MySQL (Level 4). JSON storage mempersiapkan mental model yang sama.
- **Kasus nyata:** sistem perpustakaan Level 3 menyimpan `buku.json`, `anggota.json` — halaman `katalog.php` membaca dari `bacaSemua()`, `tambah.php` menulis via `tambah()`.

---

## 6. Aspek Keamanan & Best Practices (Critical)

- **Jangan pernah menaruh storage di web root yang bisa diakses publik** — file `data/*.json` bisa diunduh kalau URL bisa diakses (`/data/buku.json`). Letakkan di **luar** `public/` atau lindungi via `.htaccess` `deny all` (di arsitektur MVC materi 25, seluruh `storage/` ditaruh di luar web root).
- **Validasi & sanitasi tetap berlaku** — data masuk `tambah()` harus sudah lolos Validator (materi 14). File JSON tidak menggantikan validasi.
- **Jangan percaya isi file** — `json_decode(..., true)` bisa menghasilkan null jika file korup; beri fallback `[]`.
- **Best practices:**
  - Autogenerate ID dengan `array_reduce` maxId+1 — konsisten dengan auto-increment DB.
  - `LOCK_EX` untuk tulis — mencegah korupsi pada penulisan bersamaan.
  - `unset($item)` setelah foreach by-reference (materi 11 & 10) — mencegah bug referensi yang membayang.
  - Pisahkan storage ke class (DRY) — jangan menulis baca-tulis JSON manual di tiap halaman.
  - Gunakan `JSON_UNESCAPED_UNICODE` agar aksen/UTF-8 tersimpan rapi.

---

## 7. Kesalahan Umum & Debugging

- **File rusak / `json_decode` gagal** → file tertulis oleh eksekusi yang terputus, atau karakter tidak valid. Solusi: backup isi, cek dengan `json_decode` di script debug; tambahkan fallback `[]` saat baca.
- **`Fatal error: Class 'JsonStorage' not found`** — file belum di-`require_once`, atau path salah (`__DIR__` vs path relatif). Gunakan `__DIR__` secara konsisten.
- **ID gagal / tidak unik** — autogenerate menghitung `maxId+1` saat data sudah besar bisa collision saat concurrent write; untuk JSON scale ini OK, tapi jangan dibawa ke production tanpa transaction DB.
- **Update tidak menyimpan** — lupa `unset($item)` setelah foreach-by-ref, sehingga array `$data` tidak benar-benar berubah. Inilah mengapa `unset($item)` dicatat sebagai "PENTING".
- **`file_put_contents` return false** — permission direktori tidak ditulis. Cek kepemilikan/direktori writable (pada production: `www-data` — materi 30).
- **Bug: file membaca data lama** — caching oleh OPcache tidak berlaku untuk file data, tapi browser cache untuk file statis bisa muncul. Untuk JSON cukup clear browser/karyakan ulang.

## 8. Soal Latihan & Kunci Jawaban

### Tantangan 1
Buat `katalog.php` yang membaca `JsonStorage('buku')`, menampilkan tabel semua buku (judul, pengarang, harga format Rupiah, stok, kategori) dengan `foreach` + `esc()`, dan menghapus buku saat `?hapus=<id>` dikirim via POST+CSRF (dengan konfirmasi dan flash message).

### Tantangan 2
Jelaskan mengapa `update()` di class `JsonStorage` memakai `foreach ($data as &$item)` (by reference) dan mengapa wajib `unset($item)` setelahnya. Apa yang terjadi jika keduanya tidak dilakukan?

### Jawaban & Pembahasan

**Tantangan 1**

```php
<?php
// katalog.php
session_start();
require_once __DIR__ . '/../functions/storage.php';
require_once __DIR__ . '/../functions/helpers.php';
require_once __DIR__ . '/../functions/csrf.php';

// Hapus via POST (bukan GET) + CSRF
if ($_SERVER['REQUEST_METHOD'] === 'POST' && isset($_POST['hapus'])) {
    if (!verifyCsrfToken($_POST['csrf_token'] ?? '')) { http_response_code(403); die('Forbidden'); }
    $storage = new JsonStorage('buku');
    if ($storage->hapus((int) $_POST['hapus'])) {
        setFlash('sukses', 'Buku berhasil dihapus.');
    }
    header('Location: katalog.php');
    exit;
}

$storage = new JsonStorage('buku');
$katalog = $storage->bacaSemua();
?>
<table>
    <tr><th>Judul</th><th>Pengarang</th><th>Harga</th><th>Kategori</th><th></th></tr>
    <?php foreach ($katalog as $buku): ?>
        <tr>
            <td><?= esc($buku['judul'] ?? '') ?></td>
            <td><?= esc($buku['pengarang'] ?? '') ?></td>
            <td><?= esc(formatHarga((int) ($buku['harga'] ?? 0))) ?></td>
            <td><?= esc($buku['kategori'] ?? '') ?></td>
            <td>
                <form method="POST" onsubmit="return confirm('Hapus buku ini?')">
                    <input type="hidden" name="csrf_token" value="<?= esc(generateCsrfToken()) ?>">
                    <input type="hidden" name="hapus" value="<?= (int) $buku['id'] ?>">
                    <button type="submit">Hapus</button>
                </form>
            </td>
        </tr>
    <?php endforeach; ?>
</table>
```

> **Pembahasan alur:** Penghapusan dipisahkan ke handler POST di atas (PRG — materi 15): verifikasi CSRF → `hapus(id)` → flash → redirect → exit. Tabel di-render sesudahnya dengan `bacaSemua()`. Semua output di-escape, dan konfirmasi hapus via `onsubmit` (UX) **serta** validasi server (keamanan) — bukan hanya JS.

**Tantangan 2** — `foreach ($data as &$item)` menciptakan **referensi** ke elemen asli array, sehingga `$item = array_merge(...)` benar-benar mengubah `$data` (tanpa `&`, `$item` hanyalah *salinan* dan perubahan tidak tersimpan). `unset($item)` melepas referensi tersebut setelah loop.

Tanpa `unset($item)`:
- `$item` (referensi ke elemen terakhir) tetap hidup setelah loop.
- Loop atau kode berikutnya yang memakai `$item` akan secara tak sadar memodifikasi elemen terakhir — sumber bug tersembunyi yang terkenal.

Tanpa `&` di `foreach`:
- `$item` menjadi salinan → update tidak pernah tersimpan → fungsi `update()` mengembalikan `false` secara diam-diam.

> **Pembahasan:** Ini pola yang paling sering menyebabkan "kenapa datanya tidak berubah?" di PHP. Akurasi referensi di `foreach` adalah benteng yang sama yang kamu kagumi di materi 11 (array asli vs salinan) — dan alasan kenapa di materi 18 (OOP) kamu akan lebih banyak memakai *object* (yang selalu by-reference) daripada array untuk mutasi.
