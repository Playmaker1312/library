# 2. Setup Environment — Laragon untuk Windows, Herd untuk macOS

> **Level 1 · Fondasi PHP** — Setelah memahami *bahwa* PHP berjalan di server (materi 1), sekarang kamu siapkan server-nya di komputer sendiri.

---

## 1. Penjelasan Singkat & Konsep Dasar

Untuk menjalankan PHP, kamu butuh **environment**: sekumpulan software yang objektifnya satu — membuat komputer kamu berperan sebagai server. Materi 1 sudah menjelaskan alur *browser → server → PHP engine → HTML*. Environment adalah *instalasi* dari komponen-komponen tersebut.

**Istilah singkat yang wajib kamu kenal:**

- **PHP Engine** — program yang mengeksekusi kode `.php`.
- **Web Server** (Apache/Nginx) — program yang menerima request HTTP dari browser dan mengarahkan ke file yang sesuai. Ketika request masuk untuk `index.php`, Apache memanggil PHP engine untuk memprosesnya lalu menyerahkan hasil HTML kembali.
- **MySQL** — database server (dibutuhkan penuh di Level 4+, tapi sudah terpasang sejak sekarang).
- **phpMyAdmin** — aplikasi web (berjalan di atas PHP + MySQL) untuk mengelola database lewat browser.

Kamu **tidak** perlu menginstall semuanya satu per satu secara manual. Tool seperti **Laragon** (Windows), **XAMPP** (semua OS), dan **Herd** (macOS) membungkus semua komponen itu dalam satu paket dan mengurus konfigurasi rumitnya.

**Benang Merah:** Harus ada satu komponen penting tambahan — **path** dari *workspace kamu* ke *server*. Di sinilah letak perbedaan "folder project biasa" vs "folder project yang bisa diakses browser". PHP hanya mau mengeksekusi file yang berada di dalam area yang dikelola webserver (web root).

---

## 2. Fungsi & Kegunaan Utama

Tanpa environment:

- File `.php` **tidak akan pernah dijalankan**. Kalau kamu klik file `.php` langsung dari Explorer, browser menampilkan teks kodenya atau menolak membukanya — karena tidak ada yang "menjalankan".
- Tidak ada cara untuk menguji halaman dinamis yang kamu bangun di seluruh roadmap.

Fungsinya secara teknis:

| Komponen | Peran dalam project perpustakaan |
|---|---|
| PHP 8.x | Menjalankan seluruh logika aplikasi |
| Apache/Nginx | Melayani request ke `http://localhost/perpustakaan/` |
| MySQL | Menyimpan data buku, anggota, peminjaman (Level 4+) |
| phpMyAdmin | Membuat tabel & menguji query dengan mudah |

> **Kenapa harus "path khusus"?** Web server hanya mengekspos folder tertentu sebagai "halaman web". Untuk Anda (sang developer), ini seperti *ruang publik* kantor yang boleh dilihat tamu — selain folder ini, semuanya privat.

## 3. Contoh Kode & Implementasi Real-World

Pilih **satu** setup. Rekomendasi: **Laragon untuk Windows** (ringan, cepat, modern).

### Opsi A — Laragon (Windows, direkomendasikan)

1. Unduh dari [laragon.org](https://laragon.org/download/), instal sebagai **portable** (tidak perlu admin).
2. Jalankan **Laragon → Start All** (Apache + MySQL hidup).
3. Klik **Root** untuk membuka folder web root, biasanya `C:\laragon\www\`.
4. Buat folder project: `C:\laragon\www\perpustakaan\`.
5. Akses di browser: `http://perpustakaan.test` (Laragon otomatis membuat virtual host!) atau `http://localhost/perpustakaan/`.

### Opsi B — XAMPP (Windows/macOS/Linux, paling universal)

1. Unduh dari [apachefriends.org](https://www.apachefriends.org/download.html).
2. Buka **XAMPP Control Panel → Start** di Apache (dan belakangan MySQL).
3. Buat folder: `C:\xampp\htdocs\perpustakaan\`.
4. Akses: `http://localhost/perpustakaan/`.

> **Kenapa `htdocs`?** Itu adalah *web root* bawaan XAMPP — satu-satunya direktori yang dilayani Apache. File di luar folder ini tidak bisa diakses lewat URL.

### Opsi C — Herd (macOS, paling mudah)

1. Unduh dari [herd.laravel.com](https://herd.laravel.com/), install, drag ke Applications.
2. Buat folder di `~/Herd/perpustakaan/`.
3. Akses: `http://perpustakaan.test` (otomatis).

### Verifikasi instalasi (semua OS)

```bash
# Pastikan PHP terpasang dan versinya 8.x
php --version        # misal: PHP 8.3.0 (cli)

# Pastikan ekstensi penting aktif (Level 4+ butuh pdo, pdo_mysql)
php -m               # harus ada: pdo, pdo_mysql, mbstring, json, openssl
```

**Tes pertama:**

```php
<?php
// Buat di web root: cd web-root; file "info.php"
phpinfo();
```

Buka `http://localhost/perpustakaan/test.php` — jika muncul halaman besar berisi konfigurasi PHP, maka environment **berfungsi**. Hapus file itu setelah selesai (membocorkan konfigurasi server tidak aman).

## 4. Analogi Sederhana

Lanjutan analogi **Sistem Administrasi Kantor**:

- Kamu punya berkas-berkas (project PHP), dan kamu membutuhkan sebuah **ruang administrasi** dengan peralatan lengkap agar berkas itu bisa "diproses menjadi surat keluar" (halaman HTML). **Web root** adalah ruang tersebut — berkas di luar ruangan tidak akan pernah diproses staf.
- **Laragon/XAMPP/Herd** = menyalakan lampu dan mengaktivasi seluruh staf secara bersamaan (Apache staf resepsionis, PHP engine staf pengolah, MySQL arsip besar). Satu tombol "Start All" menyalakan seluruh kantor sekaligus.
- **`http://localhost/perpustakaan/`** = alamat meja resepsionis untuk kantor cabang kamu. Semua permintaan lewat sini.

## 5. Kapan Harus Digunakan & Kasus Penggunaan

- **Wajib dari baris pertama** materi 3. Tidak ada cara menjalankan project PHP native tanpa ini.
- **Selalu** digunakan di development; pilihan di production sedikit berbeda (VPS + Nginx + PHP-FPM, dibahas di [[30. Deployment ke VPS]]).
- **Kasus: testing halaman baru.** Setiap kali kamu membuat file di web root, kamu langsung bisa cek hasilnya lewat browser punya kamu sendiri.

---

## 6. Aspek Keamanan & Best Practices (Critical)

- **Jangan pernah menaruh file sensitif dalam web root** — misal: database password di `config.php` yang bisa diakses publik, `test.php` yang menampilkan `phpinfo()`. Semua request ke web root diproses server. (Di Level 6, seluruh kode app dipindah ke luar web root; hanya isi satu folder `public/`.)
- **Nama virtual host / domain lokal** — jangan bikin bendahara data sensitif pada halaman yang bisa diakses orang lain; di komputer lokal ini relatif aman, tetapi biasakan aturan *private-before-publish*.
- **Permission direktori** — pada production, direktori upload harus `www-data` (materi 24 & 30).
- **Best practices:**
  - Gunakan PHP 8.x (bukan 5.x), sesuai gap yang ditulis roadmap — fitur & keamanan jauh lebih baik.
  - Pastikan ekstensi `pdo`, `pdo_mysql`, `mbstring` aktif — akan dipakai di Level 4+.

## 7. Kesalahan Umum & Debugging

- **"Halaman tidak bisa dibuka / 404"**
  - Server belum aktif → buka Control Panel Laragon/XAMPP dan Start ulang.
  - Folder tidak berada di web root → pindahkan ke `www\` / `htdocs\`.
  - Salah penulisan URL → pastikan `http://localhost/perpustakaan/` dan case nama folder sinkron (URL case-sensitive di banyak OS).
- **"Kode PHP muncul sebagai teks mentah di browser"**
  - Biasanya file diakses lewat `file://` atau `C:\...` langsung dari Explorer (bukan via `http://`). Server tidak terlibat → PHP tidak dijalankan.
  - Verifikasi: URL harus diawali `http://localhost` atau `http://perpustakaan.test`, bukan `C:\`.
- **`php` command not recognized (terminal)**
  - PHP tidak ada di `PATH` → saat `php --version` gagal, perbaiki environment variable atau gunakan terminal yang disediakan tool (Laragon punya tombol "Terminal" yang sudah diset).
- **Port 80 / 3306 already in use**
  - Software lain (Skype, Docker, IIS) memakai port yang sama → ganti port di config Apache/MySQL, atau stop software tersebut.

## 8. Soal Latihan & Kunci Jawaban

### Tantangan 1
Siapkan environment Laragon/XAMPP/Herd. Buat folder `perpustakaan` di web root, tulis file `info.php` berisi `phpinfo();`, buka di browser, dan pastikan halaman konfigurasi PHP tampil. Sebutkan tiga baris versi yang tampil: versi PHP, Server API, dan `Loaded Configuration File`.

### Tantangan 2
Buat file `salam.php` di web root:

```php
<?php
echo "Server berjalan! Waktu: " . date('H:i:s');
```

Jawab: kenapa file ini TIDAK bisa dibuka kalau pathnya `C:\laragon\www\perpustakaan\salam.php` dimasukkan ke address bar? Bagaimana cara yang benar?

### Jawaban & Pembahasan

**Tantangan 1** — Langkahnya sesuai materi bagian 3. Pada halaman `phpinfo()` cek:
- **PHP Version** misalnya `8.3.0` → bukti PHP engine aktif.
- **Server API** = `Apache 2.0 Handler` → bukti request masuk lewat Apache.
- **Loaded Configuration File** = path file `php.ini` yang digunakan → berguna saat debugging nanti (misal menyalakan ekstensi).

> **Pembahasan:** Tiga baris itu membuktikan tiga lapis environment bekerja: PHP ada, web server ada, dan konfigurasi PHP terbaca. Jika salah satu kosong/error, prinsip proses debugging dimulai di sini.

**Tantangan 2** — Path `C:\laragon\www\perpustakaan\salam.php` adalah **path file sistem**, bukan alamat web. Browser tidak memasukkan ini ke dalam request HTTP yang dipahami server. Alamat yang benar selalu lewat **URL**: `http://localhost/perpustakaan/salam.php`.

> **Pembahasan alur:** Browser memparsing URL → `localhost` (HTTP_HOST) diarahkan ke Apache → `perpustakaan/salam.php` diterjemahkan ke file di dalam web root → Apache memanggil PHP engine → hasil HTML dikembalikan. Path `C:\` tidak memiliki "penerjemahan" ini, sehingga request tidak pernah sampai ke server.
