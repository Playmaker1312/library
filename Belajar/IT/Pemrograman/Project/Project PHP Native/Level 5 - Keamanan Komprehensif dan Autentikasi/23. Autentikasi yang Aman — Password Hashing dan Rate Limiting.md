# 23. Autentikasi yang Aman — Password Hashing dan Rate Limiting

> **Level 5 · Keamanan Komprehensif dan Autentikasi** — Login yang benar bukan cuma "benar password" — tapi seluruh rantai: hash, rate limit, session aman, dan rehash.

---

## 1. Penjelasan Singkat & Konsep Dasar

Autentikasi yang aman terdiri dari beberapa lapisan yang saling menopang:

| Lapisan | Tujuan | Bahaya jika ditinggal |
|---|---|---|
| **`password_hash`** | simpan password sebagai *hash* (bukan teks) | DB bocor → seluruh password terbaca |
| **`password_verify`** | cek sangataman dalam constant time | timing attack / brute-force |
| **`password_needs_rehash`** | perbarui hash saat standar naik | hash lemah dibiarkan |
| **Rate limiting** | batasi percobaan login | brute-force tak terbatas |
| **Session regenerasi** (materi 16) | anti session fixation | hijack session |
| **Pesan ambigu "email/password salah"** | tidak membocorkan mana yang salah | user enumeration |

**Kenapa HASH, bukan enkripsi?**
- Hashing = **satu arah** — tidak bisa dibalik (tanpa brute-force). `password_hash` memakai BCRYPT/ARGON2 yang di-desain lambat — sangat lambat untuk brute-force.
- Enkripsi = reversible → kalau kunci bocor, password semua bocor. Jangan simpan password terenkripsi.
- **Input dari form selalu string** — tapi disimpan hash; `password_verify` membandingkan input dengan hash.

**Kenapa `random`/salt?** `password_hash` menambahkan salt acak per-password → dua user dengan password sama punya **hash berbeda**, dan hash ini berisi semua info yang dibutuhkan untuk verifikasi (termasuk algoritma & cost). Tidak perlu menyimpan salt terpisah.

**Rate limiting** — batasi berapa kali user boleh mencoba login dalam jendela waktu. Implementasi berbasis DB (email & IP) → di tabel `login_attempts`.

**Benang Merah:** materi 16 memberi session; materi 22 memberi mindset. Materi ini mengisi inti: *bagaimana kredensial diproses* dengan aman, termasuk upaya luar (brute-force). Level berikutnya (24) upload, dan Level 6 meletakkan auth dalam arsitektur MVC & middleware.

---

## 2. Fungsi & Kegunaan Utama

- **`password_hash($pass, PASSWORD_BCRYPT|PASSWORD_ARGON2ID)`** — hashing sombong (expensive) dengan salt + parameter cost yang bisa naik seiring waktu. Algoritma: prefer `PASSWORD_ARGON2ID` (PHP 7.4+) atau `BCRYPT` dengan cost 12.
- **`password_verify($pass, $hash)`** — verifikasi tanpa tahu algoritma yang dipakai hash (otomatis dibaca dari hash).
- **`password_needs_rehash`** — deteksi bahwa hash dibuat dengan standar lama (cost/hash algo beda) → minta di-update pada login berikutnya (rehash seamless).
- **Rate limiter** — memblokir sementara setelah N percobaan gagal — serangan brute-force (mencoba jutaan kombinasi) diperlambat drastis.
- **`hash_equals`** — perbandingan token/hash dalam *constant time* — mencegah timing attack.

**1) Password Hashing helper:**

```php
<?php
// File: src/Security/Password.php
declare(strict_types=1);

function hashPassword(string $password): string {
    // cost 12 = default yang baik; BCRYPT (atau ARGON2ID lebih kuat/kaku)
    return password_hash($password, PASSWORD_BCRYPT, ['cost' => 12]);
}

function verifyPassword(string $password, string $hash): bool {
    return password_verify($password, $hash);
}

function passwordPerluRehash(string $hash): bool {
    return password_needs_rehash($hash, PASSWORD_BCRYPT, ['cost' => 12]);
}
```

**2) Rate limiter (berbasis DB):**

```php
<?php
// File: src/Security/RateLimiter.php
declare(strict_types=1);

require_once __DIR__ . '/../Database/Connection.php';

class RateLimiter {
    private PDO $db;

    public function __construct(
        private int $maxPercobaan = 5,
        private int $windowDetik = 900,   // 15 menit
    ) {
        $this->db = Connection::getInstance();
    }

    public function cekLimit(string $identifier): bool {
        $stmt = $this->db->prepare(
            "SELECT COUNT(*) FROM login_attempts
             WHERE identifier = :id
               AND attempted_at > DATE_SUB(NOW(), INTERVAL :win SECOND)"
        );
        // bind tanpa parameter di LIMIT—Gunakan angka integer langsung (whitelist)
        $stmt->execute([':id' => $identifier]);
        $count = (int) $stmt->fetchColumn();
        return $count < $this->maxPercobaan;
    }
```
> *(nota: `INTERVAL :win` tempat placeholder tidak valid — gunakan literal int karena jendela selalu angka tua dari config.)*

```php
    public function catatGagal(string $identifier): void {
        $this->db->prepare(
            "INSERT INTO login_attempts (identifier, attempted_at) VALUES (:id, NOW())"
        )->execute([':id' => $identifier]);
    }

    public function resetLimit(string $identifier): void {
        $this->db->prepare("DELETE FROM login_attempts WHERE identifier = :id")
                 ->execute([':id' => $identifier]);
    }

    public function sisaWaktu(string $identifier): int {
        $stmt = $this->db->prepare(
            "SELECT TIMESTAMPDIFF(SECOND, MIN(attempted_at), NOW())
             FROM login_attempts WHERE identifier = :id"
        );
        $stmt->execute([':id' => $identifier]);
        $elapsed = (int) $stmt->fetchColumn();
        return max(0, $this->windowDetik - $elapsed);
    }
}
```

**3) AuthService — proses login utuh:**

```php
<?php
// File: src/Services/AuthService.php
declare(strict_types=1);

class AuthService {
    private RateLimiter $limiter;
    private PDO $db;

    public function __construct() {
        $this->db = Connection::getInstance();
        $this->limiter = new RateLimiter();
    }

    public function prosesLogin(string $email, string $password): array {
        $ip = $_SERVER['REMOTE_ADDR'] ?? '0.0.0.0';

        // Rate limit untuk IP DAN email
        if (!$this->limiter->cekLimit($ip) || !$this->limiter->cekLimit($email)) {
            $sisa = ceil($this->limiter->sisaWaktu($ip) / 60);
            return ['sukses' => false, 'pesan' => "Coba lagi dalam {$sisa} menit."];
        }

        $stmt = $this->db->prepare(
            "SELECT * FROM anggota WHERE email = :email AND status = 'aktif' LIMIT 1"
        );
        $stmt->execute([':email' => strtolower(trim($email))]);
        $user = $stmt->fetch();

        if (!$user || !password_verify($password, $user['password_hash'])) {
            $this->limiter->catatGagal($ip);
            $this->limiter->catatGagal($email);
            return ['sukses' => false, 'pesan' => 'Email atau password salah.'];
        }

        $this->limiter->resetLimit($ip);
        $this->limiter->resetLimit($email);

        // Rehash bila standar naik (misalnya cost 10 → 12)
        if (password_needs_rehash($user['password_hash'], PASSWORD_BCRYPT, ['cost' => 12])) {
            $newHash = hashPassword($password);
            $this->db->prepare("UPDATE anggota SET password_hash = :hash WHERE id = :id")
                     ->execute([':hash' => $newHash, ':id' => $user['id']]);
        }

        return ['sukses' => true, 'user' => $user];
    }
}
```

**Tabel pendukung:**

```sql
CREATE TABLE login_attempts (
    id           INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    identifier   VARCHAR(255) NOT NULL,      -- email ATAU IP
    attempted_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_identifier (identifier)
);
```

## 4. Analogi Sederhana

Dalam **Sistem Administrasi Kantor**:

- **password_hash** = staf **tidak pernah menulis password di berkas** — dia menulis *sidik jari hash* yang rumit (dengan garam acak per orang). Bahkan kalau lemari arsip dirampok, isinya cuma "sidik jari", bukan kata sandi asli.
- **password_verify** = tamu menyebut sandi; staf *menghitung sidik jarinya* dan mencocokkan dengan arsip — tapi **selalu dengan tempo yang sama** (constant time), agar pencuri tidak bisa menebak dari "berapa cepat" jawaban.
- **password_needs_rehash** = kebijakan ganti kunci gudang tiap tahun; saat pegawai masuk lagi, staf memperbarui *sidik jarinya* ke standar baru secara diam-diam (tanpa mengganggu).
- **Rate limiting** = **batas antrean di loket**: hanya maksimal 5 percobaan masuk dalam 15 menit; kalau lewat, loket tutup sementara. Ini mematikan strategi "coba jutaan kombinasi".
- **Pesan ambigu** = staf tak pernah bilang "password salah, tapi email benar" — kalau pun, itu memberi petunjuk yang bisa dieksploitasi untuk profiling. Jawaban netral: "kombinasi salah."

## 5. Kapan Harus Digunakan & Kasus Penggunaan

- **Registrasi / ubah password / reset password** — selalu `hashPassword` (jangan pernah simpan plaintext).
- **Login** — `prosesLogin` memakai rate limit + verify + rehash.
- **Proteksi aksi sensitif** (ubah email, tambah anggota) — rate limiting juga sesuai (misal verifikasi SMS/OTP).
- **`password_needs_rehash` saat login** — pembaruan diam-diam supaya seluruh user naik standar tanpa intervensi manual.
- **Kasus nyata:** halaman login perpustakaan membatasi 5 percobaan; saat gagal ke-6, muncul "coba lagi dalam N menit" (berbasis IP & email). Password selalu hash; DB bocor tidak langsung membuka akun.

---

## 6. Aspek Keamanan & Best Practices (Critical)

- **JANGAN PERNAH**: simpan password plaintext, MD5, SHA1, atau "encode/decode" (base64/mcrypt). MD5/SHA1 untuk password = malpraktik (roadmap rule 6); `password_hash` wajib.
- **Gunakan BCRYPT cost ≥ 10-12, atau ARGON2ID** — lebih tinggi = lebih lambat (buat brute-force lebih mahal), tapi seimbang dengan UX login.
- **Jangan expose apakah email terdaftar** (user enumeration): pakai satu pesan error untuk "email salah" maupun "password salah".
- **Jangan pernah menaruh hash di log / output / API** — `toArray()` (materi 18) tidak boleh memuat `password_hash`.
- **Rate limit pada IP dan identitas** — kombinasi lebih kuat daripada satu saja.
- **Rate limit juga untuk halaman login API** — cek `sisaWaktu` & respon 429 Too Many Requests.
- **`hash_equals`** untuk semua perbandingan token (CSRF) maupun hash — non-timing.

---

## 7. Kesalahan Umum & Debugging

- **`password_verify` selalu false walau password "benar"** — biasanya: hash di-generate dengan cost/param yang beda (misal reinstall app), atau `password_hash` dipanggil dua kali ke dua user dengan hash dimix. Validasi: simpan output `password_hash('a', ...)` & verifikasi `password_verify('a', $hash)` di script tes. Cek juga bahwa kolom `password_hash` tidak terpotong (VARCHAR terlalu pendek — 255).
- **Plaintext bocor ke log** — jangan log `$password`. Jaga logging tetap steril (jangan `error_log(print_r($_POST,true))` saat post mengandung password) — pilih field tertentu.
- **Rate limiter selalu "blokir"** — `login_attempts` menumpuk; pastikan `resetLimit` pada sukses & `catatGagal` hanya saat gagal. Cek juga timezone server (`DATE_SUB NOW()` konsistensi).
- **`type` SQL interval placeholder** — `INTERVAL :win` error; gunakan literal integer dari config (RateLimiter di atas).
- **DDoS ke DB karena banyak request** — rate limit jauh lebih ringan dipakai di cache/laporan; untuk skala besar gunakan layer tambahan (Redis/nginx limit).
- **Waktu server** — TIMEZONE berpengaruh pada `NOW()`; set timezone konsisten (`date_default_timezone_set('Asia/Jakarta')`).

## 8. Soal Latihan & Kunci Jawaban

### Tantangan 1
Bangun `AuthService` lengkap (dari materi) dan halaman `login.php` yang: verifikasi CSRF, panggil `prosesLogin`, bila sukses lakukan `login($user)` + regenerasi session (materi 16) + redirect; bila gagal tampilkan pesan + rate limit message. Uji alur dengan 6 percobaan salah sampai rate limit aktif.

### Tantangan 2
Jelaskan perbedaan konsep: (a) hashing vs encryption; (b) mengapa salt per-user penting; (c) mengapa `password_needs_rehash` perlu dipanggil saat login, bukan sekali-sekali.

### Jawaban & Pembahasan

**Tantangan 1**

```php
<?php
// login.php
require_once 'config/session.php';
setupSession();
require_once 'functions/csrf.php';
require_once 'functions/helpers.php';
require_once 'src/Database/Connection.php';
require_once 'src/Security/Password.php';
require_once 'src/Security/RateLimiter.php';
require_once 'src/Services/AuthService.php';

$errors = [];

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    if (!verifyCsrfToken($_POST['csrf_token'] ?? '')) { http_response_code(403); die('Forbidden'); }

    $service = new AuthService();
    $hasil = $service->prosesLogin(
        $_POST['email'] ?? '',
        $_POST['password'] ?? ''
    );

    if ($hasil['sukses']) {
        login($hasil['user']);            // session_regenerate_id + set $_SESSION (materi 16)
        header('Location: dashboard.php');
        exit;
    }
    $errors['general'] = $hasil['pesan'];
}
?>
<form method="POST">
    <input type="hidden" name="csrf_token" value="<?= esc(generateCsrfToken()) ?>">
    <input type="email" name="email" value="<?= esc($_POST['email'] ?? '') ?>" required>
    <input type="password" name="password" required>
    <button type="submit">Login</button>
    <?php if (isset($errors['general'])): ?>
        <p class="error"><?= esc($errors['general']) ?></p>
    <?php endif; ?>
</form>
```

> **Pembahasan alur:** CSRF dicek; `AuthService::prosesLogin` melakukan rate limit → query (prepared) → verify → rehash → reset. Saat sukses, `login()` meregenerasi session ID (anti fixation) dan menyimpan identitas. Kegagalan rate limit menampilkan hitungan menit. Seluruh harness yang butuh keamanan, dibundel di service — ini juga pola yang akan di-refactor ke `AuthController` (materi 26).

**Tantangan 2**

- (a) **Hashing**: satu arah — tidak bisa dibalik; untuk verifikasi, bandingkan hash input vs hash tersimpan (dengan salt & cost). **Encryption**: dua arah (bisa dekripsi dengan kunci) — cocok untuk data yang *perlu dibaca kembali* (misal alamat), TIDAK untuk password: jika kunci bocor, semua password terbaca.
- (b) **Salt per-user**: dua user dengan password sama menghasilkan hash berbeda → serangan *rainbow table* (tabel hash pra-komputasi) tidak berguna; dan jika satu user bocor, tidak secara otomatis mengungkap yang lain.
- (c) **`password_needs_rehash` saat login**: saat standar naik (cost/algoritma lebih kuat), kamu ingin seluruh hash tidak berubah *waktu aktif* ke yang lebih lemah. Dengan memanggilnya **pada login**, kamu meng-upgrade hash user saat dia masuk lagi — tanpa mengharuskan semua user login ulang secara massal, dan tanpa pekerjaan batch yang berisiko. Ini adalah "pembaruan progressif".

> **Pembahasan:** Ketiga jawaban menjelaskan kenapa rantai login aman = bukan satu fungsi, tapi *kebijakan*: hashing + salt + rehash + rate limit + regenerasi session.
