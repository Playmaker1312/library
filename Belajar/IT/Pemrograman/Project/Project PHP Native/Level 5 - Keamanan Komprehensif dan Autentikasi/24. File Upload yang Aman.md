# 24. File Upload yang Aman

> **Level 5 · Keamanan Komprehensif dan Autentikasi** — Penutup Level 5: upload file = pintu masuk salah satu serangan paling sering dieksploitasi jika tidak diawasi.

---

## 1. Penjelasan Singkat & Konsep Dasar

Form upload (`<input type="file">` + method POST) mengirim file ke server. Data file sampai di PHP lewat superglobal **`$_FILES`** bersama metadata:

```php
$_FILES['sampul'] = [
    'name'     => 'buku.png',        // nama asli dari user — JANGAN PERCAYA
    'type'     => 'image/png',       // MIME yang DIAKUI browser — JANGAN PERCAYA
    'tmp_name' => '/tmp/phpXyZ',     // lokasi sementara di server
    'error'    => 0,                 // kode error upload
    'size'     => 123456,            // ukuran dalam byte
];
```

**Bahaya upload** — mengapa harus hati-hati:
1. **Webshell** — penyerang upload `shell.php` yang dieksekusi server → kendali penuh.
2. **Gambar berbahaya** — file gambar yang mengandung script (jika dipanggil lewat URL/eksekusi).
3. **Ukuran raksasa** → DoS (memenuhi disk).
4. **Nama file jahat / path traversal** — `../../../etc/passwd` ke path tak terduga.

**Kunci persepsi yang benar:** file upload harus dipakai seperti "barang kiriman dari tamu yang tidak dikenal" — **semua metadata dikontrol penyerang** dan patut diperiksa isinya, bukan labelnya.

**Benang Merah:** materi 13-17 mengelola input teks; upload menangani *input biner*. Prinsip yang sama berlaku (tidak percaya input) — tapi memerlukan cek ekstra: ukuran, tipe isi, nama, dan storage yang tidak bisa dieksekusi. Level 6+ menempatkan upload dalam `storage/` di luar web root dengan kontrol akses.

---

## 2. Fungsi & Kegunaan Utama

- **Profil pengguna** — upload foto profil; **buku** — upload sampul/gambar.
- **Dokumen** — sertifikat, berkas peminjaman.
- **Import/export** — CSV data anggota.
- Masalah yang dipecahkan: *validasi isi* (bukan hanya ekstensi), *storage aman* (di luar eksekusi), *nama unik*, dan *akses terkontrol*.

PHP menyediakan `$_FILES` + `move_uploaded_file()` khusus: fungsi ini **memverifikasi bahwa file benar-benar hasil upload** (bukan file server) sebelum dipindahkan.

## 3. Contoh Kode & Implementasi Real-World

Struktur:

```
storage/
└── sampul/            ← di luar web root (atau dilindungi)
```

```php
<?php
// File: src/Services/UploadService.php
declare(strict_types=1);

class UploadService {
    public function __construct(
        private string $storageDir,
        private int $maxSize = 2 * 1024 * 1024,   // 2MB
        private array $mimeDiizinkan = ['image/jpeg', 'image/png', 'image/webp', 'image/gif'],
    ) {
        if (!is_dir($storageDir)) {
            mkdir($storageDir, 0755, true);
        }
    }

    /**
     * Proses upload dengan semua lapisan keamanan.
     * @throws RuntimeException jika file gagal/tidak valid
     */
    public function simpan(array $file, int $refId): string {
        // 1. Cek kode error upload
        if (($file['error'] ?? UPLOAD_ERR_NO_FILE) !== UPLOAD_ERR_OK) {
            $pesan = match ($file['error']) {
                UPLOAD_ERR_INI_SIZE   => 'File melebihi batas server.',
                UPLOAD_ERR_FORM_SIZE  => 'File melebihi batas form.',
                UPLOAD_ERR_PARTIAL    => 'Upload tidak lengkap.',
                UPLOAD_ERR_NO_FILE    => 'Tidak ada file yang dipilih.',
                default               => 'Upload gagal.',
            };
            throw new RuntimeException($pesan);
        }

        // 2. Batasi ukuran
        if (($file['size'] ?? 0) > $this->maxSize) {
            throw new RuntimeException('File terlalu besar (maks 2MB).');
        }

        // 3. Cek MIME dari ISI file (bukan label $file['type']!)
        $finfo    = new finfo(FILEINFO_MIME_TYPE);
        $mimeType = $finfo->file($file['tmp_name']);

        if (!in_array($mimeType, $this->mimeDiizinkan, true)) {
            throw new RuntimeException('Tipe file tidak diizinkan.');
        }

        // 4. Cek ekstensi dari nama (ganda: MIME + ekstensi)
        $ekstensi = strtolower(pathinfo($file['name'], PATHINFO_EXTENSION));
        $ekstensiMime = [
            'image/jpeg' => ['jpg', 'jpeg'],
            'image/png'  => ['png'],
            'image/webp' => ['webp'],
            'image/gif'  => ['gif'],
        ];
        if (!in_array($ekstensi, $ekstensiMime[$mimeType] ?? [], true)) {
            throw new RuntimeException('Ekstensi tidak cocok dengan isi file.');
        }

        // 5. Nama file unik & aman (JANGAN pakai nama asli user)
        $namaFile = sprintf('sampul_%d_%s.%s', $refId, bin2hex(random_bytes(8)), $ekstensi);
        $tujuan   = rtrim($this->storageDir, '/\\') . DIRECTORY_SEPARATOR . $namaFile;

        // 6. Pindahkan dengan move_uploaded_file (verifikasi file asli upload)
        if (!move_uploaded_file($file['tmp_name'], $tujuan)) {
            throw new RuntimeException('Gagal menyimpan file.');
        }

        // 7. Restriksi permission
        chmod($tujuan, 0644);

        return $namaFile;
    }

    public function hapus(string $namaFile): void {
        $path = rtrim($this->storageDir, '/\\') . DIRECTORY_SEPARATOR . basename($namaFile);
        if (is_file($path)) {
            unlink($path);
        }
    }
}
```

## 4. Analogi Sederhana

Dalam **Sistem Administrasi Kantor**:

- **Upload file** = tamu menitipkan **paket ke loket**. Nama yang tertulis di paket (`$_FILES['name']`) dan label jenis (`$_FILES['type']`) tidak boleh dipercaya — bisa saja paket keamanan dari orang tak dikenal.
- **Cek MIME dari isi** = petugas **membuka paket dan melihat isinya** (bukan membaca label). Label bisa bohong; isi yang menentukan.
- **Nama file unik acak** = petugas **memberi nomor inventaris baru** (`sampul_1_AB123456.png`) — nama asli tamu tidak pernah dipakai — mencegah tabrakan, path traversal, dan menjadinya nama berbahaya.
- **`move_uploaded_file`** = petugas **memindahkan paket resmi** ke gudang; tidak menerima "paket yang tiba-tiba ada" asal-asalan.
- **Di luar web root + endpoint** = paket disimpan di **ruang stok belakang** yang tidak bisa dibuka langsung dari pintu depan; hanya dikeluarkan via resepsionis (endpoint) yang memeriksa dulu.

## 5. Kapan Harus Digunakan & Kasus Penggunaan

- **Form profil** — foto anggota (nilai refId = id anggota).
- **Form buku** — sampul (nilai refId = id buku).
- **Dokumen umum** — dengan daftar MIME yang diizinkan (PDF, DOCX, XLSX) dan ukuran sesuai.
- **Import CSV/Excel** — validasi MIME `text/csv`, `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`.
- **Jangan upload tanpa kebutuhan** — setiap tipe file menambah permukaan serangan; batasi jenis yang benar-benar dipakai.

---

## 6. Aspek Keamanan & Best Practices (Critical)

- **JANGAN percaya `$_FILES['type']`** (bisa dimanipulasi) — buka isi dengan `finfo` untuk MIME asli.
- **JANGAN pakai nama asli user** — generate nama unik (`bin2hex(random_bytes(8))`).
- **JANGAN pernah langsung mengeksekusi/dir served file di web root** — prefer simpan di luar web root & sajikan lewat endpoint dengan cek `basename()` (anti-path-traversal).
- **Batasan dobel**: ukuran (php.ini `upload_max_filesize`, `post_max_size`) + ukuran max aplikasi.
- **Nonaktifkan eksekusi di folder upload** (jika di web root) — lewat `.htaccess` Apache / `location` Nginx (materi 30).
- **Cek ekstensi+ganda MIME**: hanya kombinasi yang cocok diterima.
- **CSRF tetap wajib** — form upload tidak mengecualikan token (materi 22).
- **Orphan cleanup** — hapus file lama saat update/hapus (jangan menumpuk).

---

## 7. Kesalahan Umum & Debugging

- **`$_FILES` kosong (`Undefined array key "sampul"`)** — biasanya `<form>` **tidak** `enctype="multipart/form-data"`, atau `name` salah.
- **`UPLOAD_ERR_INI_SIZE`** (`1`) atau `UPLOAD_ERR_FORM_SIZE` (`2`) — melewati batas `upload_max_filesize`/`post_max_size`. Perbesar di `php.ini` atau turunkan file.
- **`move_uploaded_file` gagal** — target dir tidak writable, atau `/tmp` upload gagal. Cek permission & space disk; pastikan direktori tujuan dibuat (`mkdir`).
- **File isi bukan sebenarnya** — MIME dari label berbeda dengan isi (misal file `shell.php` berlabel `image/png`). Dengan `finfo`, ini tertangkap. Baca MIME dari `tmp_name` (isi). 
- **Shelly error di log** — selalu periksa directory `storage` writable (chown/chmod) pada produksi (materi 30).
- **Nama file duplikat** — kejar dengan random suffix — bukan overwrite.
- **Debug**: `var_dump($_FILES)` saat method POST — lihat apakah file benar-benar terkirim & kode errornya (jangan di production).

## 8. Soal Latihan & Kunci Jawaban

### Tantangan 1
Bangun kelas `UploadService` lengkap (dari materi) untuk foto anggota (`storage/foto/`, max 1MB, MIME: jpg/png/webp). Integrasikan ke halaman `anggota/tambah.php`: form `enctype`, CSRF, validasi, simpan file, dan simpan nama file ke DB via prepared statement.

### Tantangan 2
Jelaskan membedakan tiga masalah keamanan ini dan bagaimana masing-masing dicegah di class di atas: webshell, path traversal, DoS ukuran file.

### Jawaban & Pembahasan

**Tantangan 1** — Kerangka inti:

```php

// anggota/tambah.php

require_once 'config/session.php';
setupSession();

        $stmt->execute([':n' => $nama, ':e' => $email, ':f' => $namaFile]);

        header('Location: daftar.php');
        exit;
    } catch (RuntimeException $e) {
        $errors['foto'] = $e->getMessage();

?>
<form method="POST" enctype="multipart/form-data">
    <input type="hidden" name="csrf_token" value="<?= esc(generateCsrfToken()) ?>">
    <input type="file" name="foto" accept="image/jpeg,image/png,image/webp">
    <?php if (isset($errors['foto'])): ?><p class="error"><?= esc($errors['foto']) ?></p><?php endif; ?>
```

> **Pembahasan alur:** handler dimulai dengan CSRF; setelah validasi field, `UploadService` menangani file (error code → size → MIME isi → ekstensi → nama unik → `move_uploaded_file` → permis). Jika semua lolos, nama file unik disimpan ke DB via prepared statement. Kegagalan parsing punya satu titik: exception di-catch dan muncul sebagai error di samping field — alur yang konsisten dengan form lain.

**Tantangan 2** — Di class di atas:

1. **Webshell** — dicegah lewat: (a) MIME diperiksa dari *isi* (`finfo`) sehingga file eksekusi `shell.php` berlabel `image/png` GAGA; (b) ekstensi harus cocok dengan MIME (`image/png`→`png`) sehingga `shell.php` tidak lolos; (c) file disimpan dengan nama acak tanpa ekstensi berbahaya. Bonus: simpan di luar web root → tidak bisa dieksekusi langsung.
2. **Path traversal** — nama asli user **tidak pernah dipakai**; nama file dihasilkan sendiri (`sampul_%d_%s.%s`). Jika nanti disajikan lewat endpoint, `basename()` menegakkan bahwa path hanya folder storage + nama satu level.
3. **DoS ukuran** — `size` dibatasi di aplikasi (`maxSize`), plus batas server `upload_max_filesize`/`post_max_size` sebagai lapisan; ukuran terlalu besar ditolak sebelum dipindahkan ke storage permanen.

> **Pembahasan:** klasifikasi ini penting karena *ketiga* ancaman masuk via satu mekanisme (upload), tetapi memerlukan pencegahan berbeda — isi vs nama vs ukuran. Merawat ketiganya secara bersama = pertahanan menyeluruh.
