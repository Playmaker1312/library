# 51. Tambah Model Loan di Prisma Schema

## Penjelasan

Setelah berhasil membangun modul User, Book, dan Auth, langkah selanjutnya adalah menambahkan fitur inti dari sistem perpustakaan digital: **Peminjaman Buku**. Domain ini membutuhkan model `Loan` yang merepresentasikan setiap transaksi peminjaman yang terjadi. Model ini akan mencatat secara detail siapa yang meminjam, buku apa yang dipinjam, kapan harus dikembalikan, serta status peminjaman saat ini.

Model `Loan` memiliki field penting seperti `userId` (siapa yang meminjam), `bookId` (buku yang dipinjam), `borrowedAt` (waktu peminjaman), `dueDate` (batas pengembalian), `returnedAt` (waktu pengembalian, null jika belum), dan `status` yang menggunakan enum `LoanStatus` dengan tiga nilai: `ACTIVE`, `RETURNED`, dan `OVERDUE`. Relasi ke `User` dan `Book` memungkinkan kita melakukan query peminjaman berdasarkan user atau buku dengan mudah menggunakan Prisma's relation queries.

## Fungsi

Model `Loan` berfungsi sebagai catatan transaksional utama dalam sistem peminjaman. Ia menyimpan seluruh riwayat peminjaman buku, memungkinkan tracking status pengembalian, mendeteksi buku yang terlambat (overdue), serta menjadi dasar untuk perhitungan denda atau notifikasi pengembalian.

## Cara Implementasi / Code

### 1. Update Prisma Schema

Tambahkan enum `LoanStatus` dan model `Loan` di `prisma/schema.prisma`:

```prisma
enum LoanStatus {
  ACTIVE
  RETURNED
  OVERDUE
}

model User {
  id        String   @id @default(cuid())
  email     String   @unique
  password  String
  name      String
  role      UserRole @default(MEMBER)
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  books     Book[]
  loans     Loan[]
}

model Book {
  id          String   @id @default(cuid())
  title       String
  author      String
  isbn        String   @unique
  description String?
  stock       Int      @default(1)
  coverUrl    String?
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt

  categoryId  String
  category    Category @relation(fields: [categoryId], references: [id])

  loans       Loan[]
}

model Loan {
  id         String     @id @default(cuid())
  userId     String
  bookId     String
  borrowedAt DateTime   @default(now())
  dueDate    DateTime
  returnedAt DateTime?
  status     LoanStatus @default(ACTIVE)
  createdAt  DateTime   @default(now())
  updatedAt  DateTime   @updatedAt

  user       User       @relation(fields: [userId], references: [id])
  book       Book       @relation(fields: [bookId], references: [id])

  @@index([userId])
  @@index([bookId])
  @@index([status])
}
```

### 2. Jalankan Migrasi

```bash
npx prisma migrate dev --name add-loan-model
npx prisma generate
```

## Analogi

Di perpustakaan fisik, setiap kali seorang anggota meminjam buku, petugas akan mencatat di **kartu peminjaman**: nama peminjam, judul buku, tanggal pinjam, dan batas kembali. Kartu ini kemudian disimpan di rak khusus. Model `Loan` dalam database adalah versi digital dari kartu peminjaman tersebut. Enum `LoanStatus` adalah stempel yang memberi tahu apakah buku masih dipinjam (`ACTIVE`), sudah dikembalikan (`RETURNED`), atau terlambat (`OVERDUE`). Relasi `userId` dan `bookId` ibarat referensi silang ke data anggota dan data buku di katalog perpustakaan.

## Penggunaan

Model ini dipakai di seluruh fitur peminjaman: saat anggota meminjam buku (membuat record `Loan` dengan status `ACTIVE`), saat mengembalikan buku (update `returnedAt` dan status `RETURNED`), saat mengecek buku yang sedang dipinjam, saat menampilkan riwayat peminjaman user, dan saat cron job mendeteksi peminjaman yang melewati `dueDate` untuk diubah statusnya menjadi `OVERDUE`.

## Kesalahan Umum yang Sering Terjadi

1. **Lupa menambahkan index pada field yang sering di-query** seperti `userId`, `bookId`, dan `status`. Tanpa index, query riwayat peminjaman akan lambat seiring bertambahnya data.
2. **Tidak membuat `dueDate` wajib (required)** sehingga ada peminjaman tanpa batas waktu pengembalian.
3. **Mengubah enum `LoanStatus` tanpa migrasi baru** — Prisma membutuhkan migrasi terpisah setiap kali enum atau model berubah.
4. **Lupa menambahkan relasi balik (`loans`) di model User dan Book**, padahal ini penting untuk query seperti "tampilkan semua buku yang dipinjam user ini".

## Hubungan dengan Materi Sebelumnya

Model `Loan` adalah jembatan yang menghubungkan modul **User** (Level 2) dan **Book** (Level 3) dalam sebuah transaksi nyata. Di materi sebelumnya kita sudah membuat CRUD untuk User dan Book secara terpisah. Sekarang, dengan model `Loan`, kedua domain tersebut "berbicara" satu sama lain — seorang User dapat meminjam sebuah Book. Ini adalah contoh konkret dari **relasi many-to-one** yang merupakan pengembangan dari pemahaman dasar tentang model dan Prisma ORM.

## Soal Latihan

**Soal:**
Buatlah migration untuk menambahkan field `fine` (denda) dengan tipe `Decimal?` dan `notes` (String?) pada model `Loan`, lalu tulis query Prisma untuk mendapatkan semua loan yang sudah `OVERDUE` beserta data user dan buku-nya.

**Jawaban:**

1. Tambahkan di schema:
```prisma
model Loan {
  // ... field existing
  fine  Decimal?
  notes String?
}
```

2. Migrasi:
```bash
npx prisma migrate dev --name add-fine-and-notes
```

3. Query:
```typescript
const overdueLoans = await prisma.loan.findMany({
  where: { status: LoanStatus.OVERDUE },
  include: {
    user: { select: { id: true, name: true, email: true } },
    book: { select: { id: true, title: true, author: true } },
  },
  orderBy: { dueDate: 'asc' },
});
```
