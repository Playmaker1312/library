# 53. Endpoint Peminjaman — Pinjam, Kembalikan & Riwayat

## Penjelasan

Setelah service dan repository siap, langkah terakhir di domain peminjaman adalah membuat **REST API endpoints** melalui `LoansController`. Controller ini akan mengekspos enam endpoint yang mencakup seluruh operasi peminjaman: meminjam buku, mengembalikan buku, melihat riwayat pribadi, melihat semua peminjaman (admin), dan melihat peminjaman yang terlambat. Setiap endpoint dilindungi oleh **auth guard** dan ada yang dibatasi dengan **role guard** (hanya admin yang bisa melihat semua data).

Endpoint `POST /loans` menerima body `{ bookId }` dan mengambil `userId` dari token JWT yang sudah di-decode oleh auth guard. `PATCH /loans/:id/return` hanya bisa dilakukan oleh pemilik loan atau admin. `GET /loans/my` menampilkan riwayat user yang sedang login, sementara `GET /loans` dan `GET /loans/overdue` hanya untuk admin.

## Fungsi

Controller ini menyediakan antarmuka HTTP untuk seluruh operasi peminjaman. Dengan endpoint-endpoint ini, frontend atau client API dapat: melakukan peminjaman buku, mengembalikan buku, melihat status peminjaman saat ini, serta memonitor peminjaman yang terlambat dari dashboard admin.

## Cara Implementasi / Code

### 1. LoansController

```typescript
// src/loans/controllers/loans.controller.ts
import {
  Controller, Get, Post, Patch, Param, Body, Query,
  UseGuards, Req,
} from '@nestjs/common';
import { JwtAuthGuard } from '../../auth/guards/jwt-auth.guard';
import { RolesGuard } from '../../auth/guards/roles.guard';
import { Roles } from '../../auth/decorators/roles.decorator';
import { LoansService } from '../services/loans.service';
import { CreateLoanDto } from '../dto/create-loan.dto';
import { LoanStatus } from '@prisma/client';
import { ApiTags, ApiOperation, ApiBearerAuth } from '@nestjs/swagger';

@ApiTags('Loans')
@ApiBearerAuth()
@UseGuards(JwtAuthGuard)
@Controller('loans')
export class LoansController {
  constructor(private readonly loansService: LoansService) {}

  @Post()
  @ApiOperation({ summary: 'Meminjam buku' })
  async borrowBook(@Body() dto: CreateLoanDto, @Req() req: any) {
    return this.loansService.borrowBook(dto, req.user.id);
  }

  @Patch(':id/return')
  @ApiOperation({ summary: 'Mengembalikan buku' })
  async returnBook(@Param('id') id: string, @Req() req: any) {
    return this.loansService.returnBook(id);
  }

  @Get('my')
  @ApiOperation({ summary: 'Riwayat peminjaman saya' })
  async getMyLoans(@Req() req: any) {
    return this.loansService.getMyLoans(req.user.id);
  }

  @Get('overdue')
  @UseGuards(RolesGuard)
  @Roles('ADMIN')
  @ApiOperation({ summary: 'Daftar peminjaman terlambat' })
  async getOverdueLoans() {
    return this.loansService.getAllLoans(LoanStatus.OVERDUE);
  }

  @Get()
  @UseGuards(RolesGuard)
  @Roles('ADMIN')
  @ApiOperation({ summary: 'Semua peminjaman (admin)' })
  async getAllLoans(@Query('status') status?: LoanStatus) {
    return this.loansService.getAllLoans(status);
  }
}
```

## Analogi

Bayangkan meja sirkulasi di perpustakaan. Di meja ini ada beberapa **antrean layanan**: satu pintu untuk meminjam buku (POST /loans), satu pintu untuk mengembalikan (PATCH /loans/:id/return), satu papan pengumuman untuk melihat riwayat pribadi (GET /loans/my), dan satu meja admin yang bisa melihat seluruh transaksi (GET /loans). Setiap meja hanya bisa diakses oleh orang yang berhak — anggota biasa hanya bisa ke meja peminjaman dan riwayat sendiri, sementara petugas (admin) bisa ke meja monitoring. Ini persis seperti role-based access control pada controller di atas.

## Penggunaan

Endpoint-endpoint ini digunakan oleh:
- **Frontend anggota**: halaman pinjam buku, halaman riwayat peminjaman, tombol kembalikan buku
- **Dashboard admin**: tabel semua peminjaman, filter status, notifikasi overdue
- **Mobile app**: scan QR code buku lalu pinjam via API
- **Sistem integrasi**: API digunakan oleh self-service kiosk di perpustakaan fisik

## Kesalahan Umum yang Sering Terjadi

1. **Tidak memvalidasi kepemilikan loan** saat return — user A bisa mengembalikan buku yang dipinjam user B. Tambahkan pengecekan `req.user.id === loan.userId || isAdmin`.
2. **Lupa menambahkan guard** di endpoint admin-only sehingga anggota biasa bisa melihat semua data peminjaman.
3. **Tidak menangkap error dari service** — misalnya error "stok habis" harus dikembalikan sebagai 400 Bad Request, bukan 500 Internal Server Error.
4. **Mengembalikan password user** di response loan — gunakan select/inklud yang tepat.
5. **Overfetching data** — tidak menggunakan `include` atau `select` yang spesifik sehingga response mengandung data yang tidak perlu.

## Hubungan dengan Materi Sebelumnya

Di **Level 3 (Fitur REST API Lanjutan)** kita telah belajar membuat controller dengan guard, decorator, dan DTO. Sekarang kita menerapkan semua itu dalam konteks yang lebih kompleks: endpoint yang membutuhkan kombinasi auth + role guard, parameter dari body + param + query, serta response yang berelasi dengan data user dan book. Ini adalah puncak dari pemahaman routing di NestJS.

## Soal Latihan

**Soal:**
Buat endpoint `GET /loans/active` yang mengembalikan semua peminjaman aktif milik user yang sedang login (tanpa admin). Gunakan `findMany` dengan filter `userId` dari token dan `status: ACTIVE`.

**Jawaban:**

```typescript
// Di controller
@Get('active')
@ApiOperation({ summary: 'Peminjaman aktif saya' })
async getActiveLoans(@Req() req: any) {
  return this.loansService.getMyActiveLoans(req.user.id);
}

// Di service
async getMyActiveLoans(userId: string) {
  return this.loansRepo.findAll({ userId, status: 'ACTIVE' as LoanStatus });
}

// Di repository
async findAll(filter?: { userId?: string; status?: LoanStatus }): Promise<Loan[]> {
  return this.prisma.loan.findMany({
    where: filter,
    include: { book: true },
    orderBy: { borrowedAt: 'desc' },
  });
}
```
