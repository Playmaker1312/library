# 67. Update Schema Book — Tambahkan Field coverUrl

## Penjelasan

Fitur upload cover buku dimulai dari perubahan di database. Model `Book` yang sudah ada perlu ditambahkan field `coverUrl` bertipe `String?` (nullable) untuk menyimpan URL atau path file gambar cover buku. Field ini nullable karena tidak semua buku memiliki cover — buku lama atau buku yang belum di-upload cover-nya akan bernilai `null`.

Penting untuk memutuskan strategi penyimpanan: apakah file disimpan di lokal server (public folder) atau di cloud storage (AWS S3, Cloudinary, dll.). Untuk development, kita akan menyimpan di lokal dengan path relatif seperti `/uploads/covers/`. Di production, bisa diganti dengan URL dari cloud storage tanpa mengubah struktur database — cukup mengubah isi `coverUrl`.

## Fungsi

Field `coverUrl` berfungsi sebagai referensi ke file gambar cover buku. Nilai yang disimpan bisa berupa path lokal (`/uploads/covers/abc123.webp`) atau URL absolut (`https://cdn.library.com/covers/abc123.webp`). Field ini digunakan oleh frontend untuk menampilkan gambar cover di katalog buku dan halaman detail.

## Cara Implementasi / Code

### 1. Update Prisma Schema

```prisma
// prisma/schema.prisma
model Book {
  id          String   @id @default(cuid())
  title       String
  author      String
  isbn        String   @unique
  description String?
  stock       Int      @default(1)
  coverUrl    String?  // <-- TAMBAHKAN INI (nullable)
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt

  categoryId  String
  category    Category @relation(fields: [categoryId], references: [id])
  loans       Loan[]
}
```

## Analogi

Di perpustakaan fisik, setiap buku memiliki **sampul** yang memperlihatkan judul dan gambar covernya. Untuk buku baru yang belum disampul, petugas akan menempelkan sampul plastik kosong — ini setara dengan `coverUrl: null`. Ketika sampul sudah siap (di-upload), petugas menempelkannya ke buku dan mencatat lokasi penyimpanannya di katalog. `coverUrl` adalah catatan lokasi sampul di katalog digital: "Cover buku 'Clean Code' ada di rak display sampul, baris ke-3".

## Penggunaan

`coverUrl` digunakan di:
- **Katalog buku**: ditampilkan sebagai thumbnail di grid/list view
- **Halaman detail buku**: ditampilkan besar di bagian atas
- **API response**: dikirim ke frontend untuk dirender sebagai `<img src={coverUrl} />`
- **Notifikasi email**: ditampilkan di template email konfirmasi peminjaman
- **SEO**: meta tag `og:image` untuk preview di media sosial

## Kesalahan Umum yang Sering Terjadi

1. **coverUrl tidak nullable** — jika dibuat required (`String` bukan `String?`), semua buku existing harus diisi cover, menyebabkan migrasi gagal.
2. **Penyimpanan path absolut lokal** — menggunakan `C:/Users/.../uploads/cover.jpg` yang hanya bisa diakses dari server yang sama. Gunakan path relatif atau URL.
3. **Lupa update type TypeScript** — TypeScript tidak akan komplain karena `coverUrl` baru. Tapi jika ada kode yang mengakses `book.coverUrl.length` tanpa null check, bisa error di runtime.
4. **Tidak regenerate Prisma Client** — setelah migrasi, Prisma Client harus di-generate ulang agar type baru tersedia.
5. **CoverUrl tidak di-include di query** — jika menggunakan `select` atau `include` yang eksplisit, pastikan `coverUrl` disertakan.

## Hubungan dengan Materi Sebelumnya

Di **Level 3**, kita telah membuat model `Book` dengan field dasar (title, author, isbn, stock). Sekarang kita menambahkan field multimedia (`coverUrl`). Ini adalah langkah pertama menuju fitur **file upload** yang akan dilanjutkan di materi #68 (konfigurasi Multer) dan #69 (endpoint upload + image processing dengan Sharp). Secara umum, ini adalah pengayaan domain Book dari data tekstual menjadi data yang kaya media.
