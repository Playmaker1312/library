# 59. Membuat Email Queue Processor — Konsumer Job Email

## Penjelasan

Setelah queue terdaftar, kita perlu **Processor** — consumer yang akan mengambil job dari queue dan memprosesnya. Di BullMQ, processor adalah class yang didekorasi dengan `@Processor('nama-queue')` dan meng-extend `WorkerHost`. Setiap method di dalamnya yang didekorasi dengan `@Process('job-name')` akan menangani job dengan nama tertentu.

Processor untuk queue `email` akan menangani berbagai jenis email: `send-loan-confirmation` (konfirmasi peminjaman), `send-return-reminder` (pengingat pengembalian), `send-overdue-notice` (notifikasi keterlambatan), dan `send-welcome-email` (selamat datang anggota baru). Penting untuk menambahkan handler `@OnQueueFailed` untuk logging dan monitoring saat job gagal setelah semua retry habis.

## Fungsi

EmailQueueProcessor berfungsi sebagai konsumen yang mengambil job dari queue `email`, merender template HTML, dan mengirim email melalui EmailService. Ia juga menangani error dengan logging yang proper dan menyediakan mekanisme retry otomatis.

## Cara Implementasi / Code

### 1. Buat EmailProcessor

```typescript
// src/queues/processors/email.processor.ts
import { Processor, WorkerHost, OnWorkerEvent } from '@nestjs/bullmq';
import { Job } from 'bullmq';
import { Logger } from '@nestjs/common';
import { EmailService } from '../../email/services/email.service';

@Processor('email')
export class EmailProcessor extends WorkerHost {
  private readonly logger = new Logger(EmailProcessor.name);

  constructor(private readonly emailService: EmailService) {
    super();
  }

  async process(job: Job): Promise<any> {
    this.logger.log(`Processing job ${job.id} of type ${job.name}`);

    switch (job.name) {
      case 'send-loan-confirmation':
        await this.handleLoanConfirmation(job);
        break;
      case 'send-return-reminder':
        await this.handleReturnReminder(job);
        break;
      case 'send-overdue-notice':
        await this.handleOverdueNotice(job);
        break;
      case 'send-welcome-email':
        await this.handleWelcomeEmail(job);
        break;
      default:
        this.logger.warn(`Unknown job type: ${job.name}`);
    }
  }

  private async handleLoanConfirmation(job: Job) {
    const { email, userName, bookTitle, dueDate } = job.data;
    await this.emailService.sendLoanConfirmation({
      to: email,
      userName,
      bookTitle,
      dueDate: new Date(dueDate).toLocaleDateString('id-ID'),
    });
  }

  private async handleReturnReminder(job: Job) {
    const { email, userName, bookTitle, dueDate } = job.data;
    await this.emailService.sendReturnReminder({
      to: email,
      userName,
      bookTitle,
      dueDate: new Date(dueDate).toLocaleDateString('id-ID'),
    });
  }

  private async handleOverdueNotice(job: Job) {
    const { email, userName, bookTitle, daysOverdue } = job.data;
    await this.emailService.sendOverdueNotice({
      to: email,
      userName,
      bookTitle,
      daysOverdue,
    });
  }

  private async handleWelcomeEmail(job: Job) {
    const { email, userName } = job.data;
    await this.emailService.sendWelcomeEmail({
      to: email,
      userName,
    });
  }

  @OnWorkerEvent('failed')
  onFailed(job: Job, error: Error) {
    this.logger.error(
      `Job ${job.id} (${job.name}) failed after ${job.attemptsMade} attempts: ${error.message}`,
      error.stack,
    );
  }

  @OnWorkerEvent('completed')
  onCompleted(job: Job) {
    this.logger.log(`Job ${job.id} (${job.name}) completed successfully`);
  }
}
```

### 2. Daftarkan Processor di Module

```typescript
// src/queues/queues.module.ts
import { Module } from '@nestjs/common';
import { BullModule } from '@nestjs/bullmq';
import { EmailProcessor } from './processors/email.processor';
import { EmailModule } from '../email/email.module';

@Module({
  imports: [
    BullModule.registerQueue({ name: 'email' }),
    BullModule.registerQueue({ name: 'notification' }),
    EmailModule, // Import karena EmailProcessor butuh EmailService
  ],
  providers: [EmailProcessor],
  exports: [BullModule],
})
export class QueuesModule {}
```

## Analogi

Di perpustakaan, ada **petugas khusus** yang duduk di ruang belakang dengan tugas hanya memproses surat. Setiap kali ada kertas masuk ke keranjang "Email", petugas ini mengambilnya, membaca instruksinya (job name), menulis surat sesuai template (render template), dan mengirimkannya. Jika amplop sobek (error), petugas mencoba lagi dengan amplop baru (retry). Setelah beberapa kali gagal, dia melapor ke kepala perpustakaan (OnQueueFailed). Petugas ini adalah **EmailProcessor**, dan keranjangnya adalah **queue email**.

## Penggunaan

Processor digunakan untuk semua tugas asynchronous yang perlu dieksekusi di background:
- **Email notifications**: konfirmasi, reminder, overdue, welcome
- **Push notifications**: notifikasi in-app atau mobile
- **Data processing**: kompresi gambar, generate PDF
- **Integrasi pihak ketiga**: sinkronisasi dengan Google Drive, Slack webhook
- **Batch operations**: update status massal, backup data

## Kesalahan Umum yang Sering Terjadi

1. **Processor tidak terdaftar di module** — jika `EmailProcessor` tidak ada di `providers`, job akan tetap antri dan tidak pernah diproses (stuck).
2. **Tidak meng-handle semua job name** — jika ada job name baru tapi tidak ada case di switch, job akan di-skip dengan warning saja tanpa error.
3. **Error di processor tidak di-catch** — jika method melempar error tanpa try-catch, BullMQ akan menganggap job gagal dan melakukan retry. Pastikan error handling yang proper.
4. **EmailService tidak di-import** — processor membutuhkan EmailService. Jika `EmailModule` tidak di-import di `QueuesModule`, akan error `Nest can't resolve dependencies`.
5. **Overwhelming the email service** — jika ribuan job email dikirim sekaligus, SMTP server bisa kewalahan. Atur concurrency di processor.

## Hubungan dengan Materi Sebelumnya

Di **#58 (Setup BullMQ)**, kita mendaftarkan queue. Sekarang kita membuat **consumernya**. Queue tanpa processor ibarat kotak surat yang tidak pernah diambil. Processor adalah mesin yang menghidupkan queue. Setelah processor siap, kita akan belajar di **#60** bagaimana cara **mengirim (dispatch) job** dari service, misalnya setelah peminjaman berhasil.

## Soal Latihan

**Soal:**
Buat processor untuk queue `notification` yang menangani job `send-borrow-notification` (notifikasi in-app) dan `send-return-notification`. Simpan notifikasi ke tabel `Notification` di database.

**Jawaban:**

```typescript
@Processor('notification')
export class NotificationProcessor extends WorkerHost {
  constructor(private prisma: PrismaService) { super(); }

  async process(job: Job): Promise<any> {
    switch (job.name) {
      case 'send-borrow-notification':
        await this.prisma.notification.create({
          data: {
            userId: job.data.userId,
            title: 'Peminjaman Berhasil',
            message: `Buku "${job.data.bookTitle}" berhasil dipinjam. Kembalikan sebelum ${job.data.dueDate}.`,
            type: 'BORROW',
          },
        });
        break;
      case 'send-return-notification':
        await this.prisma.notification.create({
          data: {
            userId: job.data.userId,
            title: 'Pengembalian Berhasil',
            message: `Buku "${job.data.bookTitle}" telah dikembalikan. Terima kasih!`,
            type: 'RETURN',
          },
        });
        break;
    }
  }
}
```
