# Membuat Namespace Configuration — Kelompokkan Config Terkait

## Penjelasan

Seiring pertumbuhan aplikasi, jumlah environment variable bisa menjadi sangat banyak. Misalnya, kita punya konfigurasi database (DATABASE_URL, DB_POOL_SIZE), konfigurasi Redis (REDIS_HOST, REDIS_PORT, REDIS_PASSWORD), konfigurasi JWT (JWT_SECRET, JWT_EXPIRES_IN), konfigurasi email (SMTP_HOST, SMTP_PORT), dan sebagainya. Jika semua diakses via `configService.get('DATABASE_URL')`, kode kita akan dipenuhi string literal yang rawan typo dan tidak terorganisir.

NestJS menyediakan fitur **namespace configuration** melalui fungsi `registerAs()` dari `@nestjs/config`. Dengan namespace, kita bisa mengelompokkan environment variable yang terkait ke dalam satu objek konfigurasi. Misalnya, semua konfigurasi database dikelompokkan dalam `database.config.ts` dan diakses via `configService.get('database')`. Hasilnya selain terorganisir, juga memberikan type safety karena kita bisa mendefinisikan tipe return dari setiap namespace.

Namespace configuration menggunakan Injection Token yang unik (nama namespace). Kita mendaftarkannya di `ConfigModule.forRoot()` melalui opsi `load: [databaseConfig, appConfig]`. Setelah terdaftar, kita bisa mengaksesnya dengan `configService.get('database')` yang akan mengembalikan seluruh objek konfigurasi database, atau `configService.get('database.host')` untuk nilai spesifik. NestJS juga mendukung nested path dengan dot notation.

## Fungsi

Mengelompokkan environment variable yang terkait ke dalam namespace configuration yang terstruktur, type-safe, dan mudah diakses, sehingga kode lebih rapi dan terorganisir.

## Cara Implementasi / Code

Buat folder `src/config/` untuk menyimpan semua file namespace:

```typescript
// src/config/database.config.ts
import { registerAs } from '@nestjs/config';

export default registerAs('database', () => ({
  url: process.env.DATABASE_URL || 'postgresql://postgres:postgres@localhost:5432/perpustakaan_db',
  host: process.env.DB_HOST || 'localhost',
  port: parseInt(process.env.DB_PORT, 10) || 5432,
  user: process.env.DB_USER || 'postgres',
  password: process.env.DB_PASSWORD || 'postgres',
  name: process.env.DB_NAME || 'perpustakaan_db',
}));
```

```typescript
// src/config/app.config.ts
import { registerAs } from '@nestjs/config';

export default registerAs('app', () => ({
  port: parseInt(process.env.PORT, 10) || 3000,
  prefix: process.env.GLOBAL_PREFIX || 'api/v1',
  nodeEnv: process.env.NODE_ENV || 'development',
  name: process.env.APP_NAME || 'Perpustakaan API',
}));
```

```typescript
// src/config/redis.config.ts
import { registerAs } from '@nestjs/config';

export default registerAs('redis', () => ({
  host: process.env.REDIS_HOST || 'localhost',
  port: parseInt(process.env.REDIS_PORT, 10) || 6379,
}));
```

Buat index file untuk memudahkan import:

```typescript
// src/config/index.ts
export { default as appConfig } from './app.config';
export { default as databaseConfig } from './database.config';
export { default as redisConfig } from './redis.config';
```

Daftarkan semua namespace di `ConfigModule`:

```typescript
// src/app.module.ts
import { Module } from '@nestjs/common';
import { ConfigModule } from '@nestjs/config';
import * as Joi from 'joi';
import { appConfig, databaseConfig, redisConfig } from './config';
import { PrismaModule } from './prisma/prisma.module';
import { BooksModule } from './books/books.module';

@Module({
  imports: [
    ConfigModule.forRoot({
      isGlobal: true,
      load: [appConfig, databaseConfig, redisConfig],
      validationSchema: Joi.object({
        PORT: Joi.number().default(3000),
        DATABASE_URL: Joi.string().required(),
        NODE_ENV: Joi.string().valid('development', 'production', 'test').default('development'),
      }),
    }),
    PrismaModule,
    BooksModule,
  ],
})
export class AppModule {}
```

Cara akses namespace di service:

```typescript
import { Injectable } from '@nestjs/common';
import { ConfigService } from '@nestjs/config';

@Injectable()
export class AppService {
  constructor(private configService: ConfigService) {
    // Akses seluruh objek namespace
    const dbConfig = this.configService.get('database');
    console.log(dbConfig.host); // 'localhost'

    // Akses nilai spesifik dengan dot notation
    const port = this.configService.get('app.port');
    console.log(port); // 3000

    // Dengan type safety (generic)
    const dbUrl = this.configService.get<string>('database.url');
  }
}
```

## Analogi

Namespace configuration adalah **lemari arsip perpustakaan** yang memiliki laci-laci terpisah. Ada laci khusus "Database" yang berisi: alamat gudang buku, nomor telepon gudang, dan password pintu gudang. Ada laci "Aplikasi" yang berisi: jam buka perpustakaan, prefix nomor antrian, dan nama kepala perpustakaan. Ada laci "Redis" yang berisi: alamat ruang server dan port server.

Sebelum ada lemari arsip, semua informasi dicampur jadi satu di papan pengumuman (ConfigModule tanpa namespace). Petugas harus mencari informasi di antara puluhan catatan yang tidak terurut. Dengan lemari arsip, petugas tinggal membuka laci "Database" untuk menemukan semua informasi tentang database. Jika ingin tahu jam buka perpustakaan, buka laci "Aplikasi". Jauh lebih cepat dan terorganisir. Setiap laci juga punita label yang jelas (`registerAs('database', ...)`) sehingga tidak ada kebingungan.

## Penggunaan

Dipakai di aplikasi NestJS skala menengah hingga besar yang memiliki banyak environment variable. Namespace configuration sangat berguna untuk memisahkan konfigurasi berdasarkan domain: database, cache, authentication, email, logging, dan sebagainya. Juga memudahkan pembuatan unit test karena kita bisa override namespace tertentu.

## Kesalahan Umum yang Sering Terjadi

1. **Lupa daftarkan di `load` array**: Namespace tidak terdaftar, `configService.get('database')` mengembalikan `undefined`.
2. **Nama namespace bentrok**: Dua file menggunakan `registerAs('database', ...)` dengan nama yang sama, salah satu akan ditimpa.
3. **Tidak handle nilai default**: Jika environment variable tidak di-set, nilai menjadi `undefined` dan bisa menyebabkan error runtime.
4. **`parseInt` tanpa radix**: `parseInt(process.env.PORT, 10)` — radix 10 penting untuk memastikan bilangan desimal.
5. **Namespace terlalu detail**: Setiap environment variable dibuat namespace sendiri, jadi tidak ada manfaat pengelompokan.
6. **Lupa export default**: Fungsi `registerAs` harus di-export sebagai default export.

## Hubungan dengan Materi Sebelumnya

Setelah ConfigModule (materi 27) di-setup, kita sekarang mengelompokkan environment variable ke dalam namespace yang terstruktur. Namespace configuration ini akan digunakan di `main.ts` (materi 29) untuk mengambil port dan prefix, serta di service-service lain yang membutuhkan konfigurasi spesifik seperti konfigurasi database untuk Prisma atau konfigurasi Redis untuk caching.
