# Menjalankan Migrasi Pertama — Schema ke Database

## Penjelasan

Migrasi database adalah proses menerjemahkan definisi model di Prisma Schema menjadi tabel-tabel nyata di database PostgreSQL. Prisma Migrate bekerja dengan membandingkan state schema saat ini dengan state database yang sudah ada, lalu menghasilkan file SQL migration yang berisi perintah `CREATE TABLE`, `ALTER TABLE`, atau `DROP TABLE` yang diperlukan. Setiap kali kita mengubah Prisma Schema (misalnya menambah field, mengubah tipe data, atau menambah model baru), kita harus menjalankan migrasi baru untuk menyelaraskan database.

Perintah utama untuk migrasi di environment development adalah `npx prisma migrate dev`. Perintah ini akan otomatis membuat file migration baru di folder `prisma/migrations/`, menjalankannya ke database, dan meregenerasi Prisma Client. Setiap file migration diberi nama berdasarkan timestamp dan deskripsi yang kita berikan (misalnya `20240101000001_init`). File-file ini harus di-commit ke git karena menjadi sejarah perubahan struktur database.

Sangat penting untuk memahami bahwa migrasi bersifat idempoten untuk environment development, tetapi harus ditangani dengan hati-hati di production. Di production, kita menggunakan `npx prisma migrate deploy` yang hanya menjalankan migration yang belum pernah dijalankan, tanpa membuat migration baru. Prisma Migrate juga menyimpan riwayat migrasi di tabel `_prisma_migrations` di database, sehingga tahu migration mana yang sudah diterapkan.

## Fungsi

Menerjemahkan definisi model di Prisma Schema menjadi tabel database nyata melalui SQL migration yang terekam dan ter-versioning, serta memastikan database selalu sinkron dengan schema.

## Cara Implementasi / Code

Pastikan container PostgreSQL sudah berjalan:

```bash
docker compose ps
```

Jalankan migrasi pertama:

```bash
npx prisma migrate dev --name init
```

Output yang diharapkan:

```
Environment variables loaded from .env
Prisma schema loaded from prisma/schema.prisma
Datasource "db": PostgreSQL database "perpustakaan_db", schema "public" at "localhost:5432"

Applying migration `20240101000001_init`

The following migration(s) have been created and applied from new schema changes:

migrations/
  └─ 20240101000001_init/
    └─ migration.sql

Your database is now in sync with your schema.

✔ Generated Prisma Client (v5.x.x) to node_modules/.prisma/client
```

Lihat file SQL migration yang dihasilkan di `prisma/migrations/20240101000001_init/migration.sql`:

```sql
-- Prisma generated SQL
-- Create enum type
CREATE TYPE "BookGenre" AS ENUM (
    'FIKSI', 'NON_FIKSI', 'SAINS', 'TEKNOLOGI',
    'SEJARAH', 'BIOGRAFI', 'FILSAFAT', 'PSIKOLOGI',
    'EKONOMI', 'SENI', 'AGAMA', 'PENDIDIKAN',
    'KESEHATAN', 'HUKUM'
);

-- Create table books
CREATE TABLE "books" (
    "id" TEXT NOT NULL,
    "title" TEXT NOT NULL,
    "author" TEXT NOT NULL,
    "isbn" TEXT NOT NULL,
    "published_year" INTEGER NOT NULL,
    "genre" "BookGenre" NOT NULL,
    "description" TEXT,
    "stock" INTEGER NOT NULL DEFAULT 1,
    "is_deleted" BOOLEAN NOT NULL DEFAULT false,
    "created_at" TIMESTAMP(3) NOT NULL DEFAULT CURRENT_TIMESTAMP,
    "updated_at" TIMESTAMP(3) NOT NULL,

    CONSTRAINT "books_pkey" PRIMARY KEY ("id")
);

-- Create unique index for isbn
CREATE UNIQUE INDEX "books_isbn_key" ON "books"("isbn");
```

Cek apakah tabel sudah dibuat:

```bash
npx prisma studio
```

Atau via psql:

```bash
docker exec -it nestjs-postgres psql -U postgres -d perpustakaan_db -c "\dt"
docker exec -it nestjs-postgres psql -U postgres -d perpustakaan_db -c "\d books"
```

Perintah migrasi lainnya:

```bash
# Membuat migrasi tanpa menjalankan (review dulu)
npx prisma migrate dev --create-only --name nama_migrasi

# Reset database (hapus semua data dan jalankan migrasi dari awal)
npx prisma migrate reset

# Di production
npx prisma migrate deploy
```

## Analogi

Migrasi database seperti **proses pembangunan rak buku di perpustakaan** berdasarkan cetak biru (Prisma Schema). Arsitek memberikan cetak biru ke tukang, lalu tukang membuat rak buku sungguhan dari kayu. Setiap kali cetak biru diubah (misalnya mau nambah rak khusus untuk buku langka), tukang akan mencatat perubahannya di buku catatan (`migration.sql`): "Hari ini, 1 Januari 2024, saya menambah rak langka di sebelah barat". Buku catatan ini disimpan rapi di folder arsip (`prisma/migrations/`). Jika suatu saat perpustakaan roboh dan harus dibangun ulang, tukang tinggal membaca buku catatan dari awal sampai akhir untuk membangun rak yang sama persis. Inilah mengapa file migration harus di-commit ke git — seperti menyimpan buku catatan di brankas pusat, bukan di perpustakaan yang bisa roboh.

## Penggunaan

Dipakai setiap kali ada perubahan struktur database: menambah model baru, mengubah field, menambah relasi, atau mengubah tipe data. Di development menggunakan `migrate dev`, di production menggunakan `migrate deploy`. Juga digunakan untuk rollback dengan `migrate reset` (development) atau migration down (manual).

## Kesalahan Umum yang Sering Terjadi

1. **Lupa jalankan Docker sebelum migrasi**: Database tidak bisa dijangkau, migrasi gagal dengan error koneksi.
2. **Mengubah migration.sql secara manual**: File migration yang sudah di-generate sebaiknya tidak diedit langsung, karena bisa menyebabkan inkonsistensi.
3. **Migrasi gagal di tengah jalan**: Data di database tidak konsisten. Gunakan `npx prisma migrate reset` untuk development.
4. **Lupa ngasih `--name`**: Migrasi akan diberi nama timestamp tanpa deskripsi, sulit dilacak.
5. **Tidak commit folder migrations**: Anggota tim lain tidak punya riwayat migrasi dan harus migrate dari awal.
6. **Merge conflict di migration.sql**: Dua branch mengubah schema yang sama. Solusi: reset migration di salah satu branch.

Setelah mendefinisikan model `Book` di Prisma Schema (materi 19), kita sekarang mewujudkannya menjadi tabel nyata di PostgreSQL yang sudah berjalan via Docker (materi 17). Migrasi ini menghasilkan tabel `books` di database, yang nantinya akan kita isi data melalui seeder (materi 22) dan kita akses melalui PrismaService (materi 21).
