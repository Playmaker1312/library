# Inisialisasi Prisma — Schema, .env & Konfigurasi Awal

## Penjelasan

Prisma adalah ORM (Object-Relational Mapping) modern untuk Node.js dan TypeScript yang mengubah interaksi dengan database menjadi type-safe dan mudah digunakan. Berbeda dengan ORM tradisional seperti Sequelize atau TypeORM yang menggunakan pendekatan active record atau data mapper, Prisma menggunakan pendekatan declarative schema-first. Artinya, kita mendefinisikan model data di file `schema.prisma`, lalu Prisma secara otomatis menghasilkan TypeScript types yang sesuai. Ini memberikan developer experience yang luar biasa karena autocompletion dan type checking bekerja penuh hingga ke level query database.

Langkah awal menggunakan Prisma adalah menginstall package `prisma` sebagai devDependency dan `@prisma/client` sebagai dependency utama. Setelah install, kita jalankan `npx prisma init` yang akan membuat dua hal penting: folder `prisma/` berisi `schema.prisma`, dan file `.env` di root project. File `schema.prisma` adalah tempat kita mendefinisikan koneksi database, generator (untuk menghasilkan Prisma Client), dan model-model data. File `.env` menyimpan DATABASE_URL yang digunakan Prisma untuk terhubung ke database.

Konfigurasi DATABASE_URL mengikuti format connection string PostgreSQL: `postgresql://USER:PASSWORD@HOST:PORT/DATABASE`. Sangat penting untuk tidak pernah meng-commit file `.env` ke git karena berisi kredensial database. Sebagai gantinya, kita buat file `.env.example` yang berisi template tanpa nilai sensitif. File `.env.example` ini di-commit ke repository agar developer lain tahu environment variable apa saja yang dibutuhkan.

## Fungsi

Menginisialisasi Prisma ORM dalam project NestJS dan menyiapkan konfigurasi koneksi database yang aman melalui environment variable, serta menyediakan template `.env.example` untuk kolaborasi tim.

## Cara Implementasi / Code

Install Prisma di project NestJS:

```bash
npm install prisma --save-dev
npm install @prisma/client
```

Jalankan inisialisasi Prisma:

```bash
npx prisma init
```

Setelah inisialisasi, struktur folder akan seperti ini:

```
project-root/
  prisma/
    schema.prisma
  .env
  src/
    ...
```

Isi file `prisma/schema.prisma` setelah inisialisasi (sebelum dimodifikasi):

```prisma
// This is your Prisma schema file,
// learn more about it in the docs: https://pris.ly/d/prisma-schema

generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}
```

Update file `.env` dengan konfigurasi PostgreSQL:

```env
# .env
DATABASE_URL="postgresql://postgres:postgres@localhost:5432/perpustakaan_db"
```

Buat file `.env.example` sebagai template untuk developer lain:

```env
# .env.example
DATABASE_URL="postgresql://USER:PASSWORD@HOST:PORT/DATABASE_NAME"
```

Pastikan `.env` ada di `.gitignore`:

```gitignore
# .gitignore
node_modules/
dist/
.env
*.log
```

Generate Prisma Client setelah schema siap:

```bash
npx prisma generate
```

Perintah ini akan membaca `schema.prisma` dan menghasilkan Prisma Client di `node_modules/.prisma/client/` yang siap digunakan di aplikasi NestJS.

## Analogi

Proses inisialisasi Prisma seperti mendatangkan seorang **arsitek database** ke perpustakaan. Arsitek ini membawa cetak biru kosong (`schema.prisma`) yang nantinya akan diisi dengan denah rak buku, katalog, dan sistem peminjaman. Arsitek juga memasang panel kontrol (`DATABASE_URL`) yang menghubungkan perpustakaan ke gudang penyimpanan bawah tanah (PostgreSQL). Agar aman, panel kontrol ini disimpan di brankas khusus (`.env`) yang tidak boleh dilihat pengunjung. Tapi arsitek juga membuat salinan petunjuk (`.env.example`) yang menunjukkan: "Isi dengan user, password, alamat gudang, dan nama database kamu" — tanpa menuliskan nilai aslinya. Dengan begitu, arsitek lain yang datang bisa dengan mudah menyambungkan perpustakaannya ke gudang masing-masing.

## Penggunaan

Dipakai di setiap project NestJS yang membutuhkan database relasional. Inisialisasi Prisma adalah langkah wajib sebelum mendefinisikan model, menjalankan migrasi, atau melakukan query ke database. File `.env` digunakan oleh seluruh aplikasi untuk mengakses konfigurasi sensitif, bukan hanya Prisma.

## Kesalahan Umum yang Sering Terjadi

1. **Lupa install `@prisma/client`**: Hanya install `prisma` sebagai devDependency, padahal `@prisma/client` diperlukan di runtime untuk query.
2. **Tidak menjalankan `prisma generate`**: Prisma Client tidak tergenerate, akibatnya import dari `@prisma/client` gagal.
3. **Typo di DATABASE_URL**: Format salah, port salah, atau nama database tidak sesuai dengan yang ada di Docker.
4. **Meng-commit `.env` ke git**: Kredensial database terekspos. Selalu pastikan `.env` ada di `.gitignore`.
5. **Lupa buat `.env.example`**: Developer baru tidak tahu environment variable apa yang harus diisi.
6. **Versi Prisma tidak cocok**: Antara `prisma` CLI dan `@prisma/client` harus versi yang sama.

## Hubungan dengan Materi Sebelumnya

Setelah Docker Compose menyediakan database PostgreSQL (materi 17), sekarang kita menghubungkan project NestJS ke database tersebut melalui Prisma. Inisialisasi Prisma adalah jembatan antara infrastruktur (Docker) dan kode aplikasi. Tanpa inisialisasi ini, kita tidak bisa mendefinisikan model atau menjalankan migrasi di materi selanjutnya.
