# Implementasi PrismaBooksRepository — Query Database

## Penjelasan

PrismaBooksRepository adalah implementasi konkrit dari interface `IBooksRepository` yang menggunakan PrismaService untuk berinteraksi dengan database PostgreSQL. Class ini berisi logika query yang spesifik ke Prisma, seperti `prisma.book.findMany()`, `prisma.book.findUnique()`, `prisma.book.create()`, dan `prisma.book.update()`. Semua method diimplementasikan dengan type-safe berkat Prisma Client yang sudah di-generate dari schema.

Selain CRUD dasar, repository ini juga mengimplementasikan soft delete — artinya data tidak benar-benar dihapus dari database, melainkan hanya ditandai dengan field `isDeleted` menjadi `true`. Ini penting untuk menjaga integritas data dan memungkinkan pemulihan data yang terhapus. Dalam query `findAll`, kita menambahkan filter `where: { isDeleted: false }` agar buku yang sudah di-soft-delete tidak muncul di daftar aktif.

Repository juga merupakan tempat yang tepat untuk menambahkan optimasi query seperti pagination, search, dan filtering. Meskipun parameter pagination bisa diterima di method `findAll`, untuk menjaga agar interface tetap sederhana, kita bisa membuat method terpisah seperti `findAllPaginated` atau menggunakan DTO khusus. Implementasi di repository harus efisien — misalnya menggunakan `skip` dan `take` untuk pagination, serta `contains` (case-insensitive) untuk search.

## Fungsi

Mengimplementasikan operasi CRUD database untuk entity Book menggunakan Prisma, termasuk soft delete, validasi duplikasi ISBN, dan query filtering dasar.

## Cara Implementasi / Code

Buat file `src/books/repositories/prisma-books.repository.ts`:

```typescript
// src/books/repositories/prisma-books.repository.ts
import { Injectable } from '@nestjs/common';
import { Book } from '@prisma/client';
import { PrismaService } from '../../prisma/prisma.service';
import {
  IBooksRepository,
  CreateBookDto,
  UpdateBookDto,
} from '../interfaces/books-repository.interface';

@Injectable()
export class PrismaBooksRepository implements IBooksRepository {
  constructor(private readonly prisma: PrismaService) {}

  async findAll(): Promise<Book[]> {
    return this.prisma.book.findMany({
      where: { isDeleted: false },
      orderBy: { createdAt: 'desc' },
    });
  }

  async findById(id: string): Promise<Book | null> {
    return this.prisma.book.findFirst({
      where: {
        id,
        isDeleted: false,
      },
    });
  }

  async findByIsbn(isbn: string): Promise<Book | null> {
    return this.prisma.book.findUnique({
      where: { isbn },
    });
  }

  async create(dto: CreateBookDto): Promise<Book> {
    return this.prisma.book.create({
      data: {
        title: dto.title,
        author: dto.author,
        isbn: dto.isbn,
        publishedYear: dto.publishedYear,
        genre: dto.genre,
        description: dto.description,
        stock: dto.stock ?? 1,
      },
    });
  }

  async update(id: string, dto: UpdateBookDto): Promise<Book> {
    return this.prisma.book.update({
      where: { id },
      data: {
        title: dto.title,
        author: dto.author,
        isbn: dto.isbn,
        publishedYear: dto.publishedYear,
        genre: dto.genre,
        description: dto.description,
        stock: dto.stock,
      },
    });
  }

  async softDelete(id: string): Promise<Book> {
    return this.prisma.book.update({
      where: { id },
      data: { isDeleted: true },
    });
  }
}
```

## Analogi

PrismaBooksRepository adalah **petugas perpustakaan yang bertugas di gudang buku**. Ketika pengunjung mengisi formulir permintaan buku (interface), formulir itu sampai ke petugas gudang ini. Petugas ini tahu persis bagaimana cara mengambil buku dari rak (query Prisma). Misalnya:

- "Tolong cari buku 'Pemrograman NestJS'" → petugas melihat daftar buku yang tidak dibuang (`isDeleted: false`), lalu mencari judul yang cocok.
- "Tolong catat buku baru" → petugas menambahkan buku ke rak dengan data lengkap.
- "Tolong buang buku ini" → petugas tidak benar-benar membuang buku, tapi memberi stiker "DIBUANG" di sampulnya (soft delete), sehingga buku masih ada di gudang tapi tidak muncul di katalog utama.
- "Cek apakah ISBN ini sudah ada?" → petugas mengecek katalog unik ISBN.

Petugas gudang ini sangat terlatih dalam urusan teknis pergudangan (Prisma query), tapi tidak perlu tahu aturan bisnis seperti "buku tidak bisa dipinjam jika stok habis" — itu urusan petugas layanan (service).

## Penggunaan

Dipakai oleh BooksService (materi 26) untuk semua operasi database terkait buku. Repository ini didaftarkan sebagai provider menggunakan token `BOOKS_REPOSITORY` sehingga bisa diganti dengan implementasi lain (misalnya untuk testing). Juga bisa digunakan oleh module lain yang membutuhkan akses data buku.

## Kesalahan Umum yang Sering Terjadi

1. **Lupa filter `isDeleted: false` di query findAll**: Buku yang sudah di-soft-delete masih muncul di daftar.
2. **Tidak handle `findByIsbn` untuk mengecek duplikasi**: Buku dengan ISBN sama bisa dibuat dua kali.
3. **Error handling `update` tidak ada**: Jika ID tidak ditemukan, Prisma throw error yang tidak tertangani.
4. **Field null tidak dihandle**: `dto.description` undefined dikirim ke Prisma, menyebabkan error.
5. **Tidak menggunakan transaction**: Operasi yang melibatkan multiple table tidak atomic.
6. **N+1 query problem**: Memanggil repository dalam loop, lebih baik batch query.

## Hubungan dengan Materi Sebelumnya

Interface `IBooksRepository` (materi 23) mendefinisikan kontrak, dan `PrismaBooksRepository` adalah implementasi nyata dari kontrak tersebut. Repository ini menggunakan `PrismaService` (materi 21) yang sudah kita buat sebelumnya. Dengan adanya implementasi ini, aplikasi sekarang bisa membaca dan menulis data ke PostgreSQL melalui Prisma, bukan lagi array in-memory seperti di Level 1.

async searchByTitle(keyword: string): Promise<Book[]> {
  return this.prisma.book.findMany({
    where: {
      title: {
        contains: keyword,
        mode: 'insensitive', // case-insensitive
      },
      isDeleted: false,
    },
  });
}
