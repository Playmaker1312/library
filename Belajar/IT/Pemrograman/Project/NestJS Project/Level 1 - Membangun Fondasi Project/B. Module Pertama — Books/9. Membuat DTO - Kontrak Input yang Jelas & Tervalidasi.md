# Membuat DTO — Kontrak Input yang Jelas & Tervalidasi

## Penjelasan

**DTO (Data Transfer Object)** adalah objek yang mendefinisikan bagaimana data akan dikirim melalui jaringan. Dalam konteks NestJS, DTO digunakan untuk mendefinisikan bentuk data yang diterima dari client (request body) dan data yang akan dikembalikan ke client (response). DTO berbeda dengan interface — DTO adalah class (bukan interface) sehingga bisa menggunakan decorator validasi dari library `class-validator`.

NestJS sangat merekomendasikan penggunaan **class** untuk DTO, bukan interface. Alasan utamanya adalah class tetap ada setelah kompilasi TypeScript, sehingga bisa digunakan oleh `ValidationPipe` untuk melakukan validasi runtime. Decorator seperti `@IsString()`, `@IsNumber()`, `@IsOptional()` dari `class-validator` bisa ditambahkan ke properti DTO untuk memvalidasi input secara otomatis.

Selain itu, kita menggunakan `@nestjs/mapped-types` untuk membuat UpdateDto dari CreateDto. Package ini menyediakan fungsi `PartialType` yang mengubah semua properti menjadi opsional — sangat berguna untuk operasi UPDATE di mana client hanya perlu mengirim field yang ingin diubah. Dengan pendekatan ini, kita tidak perlu menulis ulang semua properti untuk setiap DTO.

## Fungsi

DTO berfungsi sebagai **kontrak input** yang jelas antara client dan server. CreateBookDto mendefinisikan data apa yang wajib dikirim saat membuat buku baru — title, author, isbn, year, stock — lengkap dengan aturan validasinya (misalnya ISBN harus string, year harus number). UpdateBookDto adalah versi opsional dari CreateBookDto untuk operasi update. QueryBookDto mendefinisikan parameter query yang valid untuk filtering dan sorting.

## Cara Implementasi / Code

### 1. Install dependencies

```bash
cd perpustakaan-api
pnpm add class-validator class-transformer @nestjs/mapped-types
```

### 2. CreateBookDto — DTO untuk membuat buku baru

Buat file `src/modules/books/dto/create-book.dto.ts`:

```typescript
import { IsString, IsNumber, IsISBN, IsInt, Min, Max, IsNotEmpty } from 'class-validator';

export class CreateBookDto {
  @IsString()
  @IsNotEmpty()
  title: string;

  @IsString()
  @IsNotEmpty()
  author: string;

  @IsString()
  @IsISBN()
  isbn: string;

  @IsInt()
  @Min(1000)
  @Max(new Date().getFullYear())
  year: number;

  @IsInt()
  @Min(0)
  stock: number;
}
```

### 3. UpdateBookDto — DTO untuk update buku

Buat file `src/modules/books/dto/update-book.dto.ts`:

```typescript
import { PartialType } from '@nestjs/mapped-types';
import { CreateBookDto } from './create-book.dto';

// PartialType membuat semua properti CreateBookDto menjadi opsional
export class UpdateBookDto extends PartialType(CreateBookDto) {}
```

**Catatan:** `PartialType` akan menghasilkan class yang sama persis dengan `CreateBookDto` tetapi semua propertinya ditandai sebagai `@IsOptional()`. Ini sangat berguna karena client hanya perlu mengirim field yang ingin diubah.

### 4. QueryBookDto — DTO untuk parameter query (filtering)

Buat file `src/modules/books/dto/query-book.dto.ts`:

```typescript
import { IsOptional, IsString, IsInt, Min, IsEnum } from 'class-validator';
import { Type } from 'class-transformer';

export enum SortOrder {
  ASC = 'asc',
  DESC = 'desc',
}

export class QueryBookDto {
  @IsOptional()
  @IsString()
  search?: string; // Pencarian berdasarkan judul atau author

  @IsOptional()
  @IsString()
  author?: string; // Filter berdasarkan penulis

  @IsOptional()
  @IsInt()
  @Min(1000)
  @Type(() => Number) // Transform query string ke number
  year?: number; // Filter berdasarkan tahun

  @IsOptional()
  @IsString()
  sortBy?: string; // Field untuk sorting: 'title' | 'year'

  @IsOptional()
  @IsEnum(SortOrder)
  sortOrder?: SortOrder; // asc | desc

  @IsOptional()
  @IsInt()
  @Min(1)
  @Type(() => Number)
  page?: number; // Pagination: halaman ke-n

  @IsOptional()
  @IsInt()
  @Min(1)
  @Type(() => Number)
  limit?: number; // Pagination: jumlah per halaman
}
```

**Catatan:** Decorator `@Type(() => Number)` dari `class-transformer` sangat penting karena parameter query selalu berupa string. Tanpa decorator ini, `year` akan tetap string meskipun dideklarasikan sebagai `number`.

### 5. Struktur folder DTO setelah selesai

```
src/modules/books/dto/
├── create-book.dto.ts
├── update-book.dto.ts
└── query-book.dto.ts
```

### 6. Contoh penggunaan DTO di controller (pratinjau)

```typescript
import { Body, Param, Query } from '@nestjs/common';
import { CreateBookDto } from './dto/create-book.dto';
import { UpdateBookDto } from './dto/update-book.dto';
import { QueryBookDto } from './dto/query-book.dto';

@Post()
create(@Body() createBookDto: CreateBookDto) {
  return this.booksService.create(createBookDto);
}

@Patch(':id')
update(@Param('id') id: string, @Body() updateBookDto: UpdateBookDto) {
  return this.booksService.update(id, updateBookDto);
}

@Get()
findAll(@Query() queryBookDto: QueryBookDto) {
  return this.booksService.findAll(queryBookDto);
}
```

## Analogi

Bayangkan petugas perpustakaan sedang merancang **formulir peminjaman** yang harus diisi oleh pengunjung:

- **CreateBookDto** adalah **formulir pendaftaran buku baru** — ada kolom wajib yang harus diisi (Judul, Penulis, ISBN) dengan aturan tertentu (ISBN harus valid, Tahun harus angka antara 1000-2026). Petugas akan memeriksa kelengkapan dan validitas isian sebelum menerima buku.

- **UpdateBookDto** adalah **formulir perbaikan data** yang sama, tapi pengunjung hanya perlu mengisi kolom yang ingin diperbaiki. Mau ganti judul saja? Isi kolom judul, biarkan lainnya kosong.

- **QueryBookDto** adalah **formulir pencarian** — pengunjung bisa mengisi satu atau beberapa filter: cari buku berdasarkan judul, penulis, tahun, atau kombinasi ketiganya. Bisa juga mengatur apakah hasilnya diurutkan A-Z atau Z-A, dan berapa banyak hasil per halaman.

Dengan formulir-formulir ini, interaksi antara pengunjung (client) dan petugas (server) menjadi terstruktur dan tidak membingungkan. Kedua pihak tahu persis data apa yang diharapkan dan dalam format apa.

## Penggunaan

DTO digunakan di setiap endpoint yang menerima input dari client. `CreateBookDto` digunakan di endpoint `POST /books`, `UpdateBookDto` di `PATCH /books/:id`, dan `QueryBookDto` di `GET /books` untuk filtering dan sorting. DTO juga bisa digunakan untuk dokumentasi Swagger/OpenAPI otomatis nantinya.

## Kesalahan Umum yang Sering Terjadi

1. **Menggunakan interface untuk DTO** — Interface tidak bisa digunakan dengan `ValidationPipe` karena tidak ada saat runtime. Selalu gunakan **class** untuk DTO.

2. **Lupa menambah decorator validasi** — Tanpa decorator, DTO tidak akan divalidasi meskipun `ValidationPipe` sudah dipasang. Setiap properti harus diberi decorator yang sesuai.

3. **Tidak menggunakan `@Type()` untuk query parameter** — Query parameter selalu string. `@Type(() => Number)` diperlukan untuk transformasi tipe data.

4. **UpdateDto dibuat manual dengan semua properti opsional** — Gunakan `PartialType` dari `@nestjs/mapped-types` untuk menghindari duplikasi dan memastikan konsistensi.

5. **Mendeklarasikan DTO dengan properti yang tidak sesuai entity** — Misalnya properti `fullDescription` di DTO tapi entity hanya punya `description`. Pastikan DTO dan entity sinkron.

## Hubungan dengan Materi Sebelumnya

Setelah mendefinisikan entity Book (materi 8), kita sekarang membuat DTO yang merupakan **turunan** dari entity tersebut untuk keperluan input/output. CreateBookDto mirip dengan CreateBookInput (interface) tapi dalam bentuk class dengan validasi. DTO ini akan digunakan langsung oleh controller (materi 11) dan service (materi 10) untuk menerima data dari client.

## Soal Latihan

**Soal:** Buatlah DTO untuk module Members dengan spesifikasi berikut:

1. **CreateMemberDto:** Validasi — `memberCode` (string, tidak boleh kosong), `fullName` (string, tidak boleh kosong, minimal 3 karakter), `email` (string, format email valid), `phone` (string, tidak boleh kosong), `address` (string, tidak boleh kosong)
2. **UpdateMemberDto:** Partial dari CreateMemberDto menggunakan PartialType
3. **QueryMemberDto:** `search` (string, opsional), `isActive` (boolean, opsional), `page` dan `limit` (number, opsional, minimal 1)

**Jawaban:**

`src/modules/members/dto/create-member.dto.ts`:
```typescript
import { IsString, IsNotEmpty, IsEmail, MinLength } from 'class-validator';

export class CreateMemberDto {
  @IsString()
  @IsNotEmpty()
  memberCode: string;

  @IsString()
  @IsNotEmpty()
  @MinLength(3)
  fullName: string;

  @IsEmail()
  email: string;

  @IsString()
  @IsNotEmpty()
  phone: string;

  @IsString()
  @IsNotEmpty()
  address: string;
}
```

`src/modules/members/dto/update-member.dto.ts`:
```typescript
import { PartialType } from '@nestjs/mapped-types';
import { CreateMemberDto } from './create-member.dto';

export class UpdateMemberDto extends PartialType(CreateMemberDto) {}
```

`src/modules/members/dto/query-member.dto.ts`:
```typescript
import { IsOptional, IsString, IsBoolean, IsInt, Min } from 'class-validator';
import { Type } from 'class-transformer';

export class QueryMemberDto {
  @IsOptional()
  @IsString()
  search?: string;

  @IsOptional()
  @IsBoolean()
  @Type(() => Boolean)
  isActive?: boolean;

  @IsOptional()
  @IsInt()
  @Min(1)
  @Type(() => Number)
  page?: number;

  @IsOptional()
  @IsInt()
  @Min(1)
  @Type(() => Number)
  limit?: number;
}
```
