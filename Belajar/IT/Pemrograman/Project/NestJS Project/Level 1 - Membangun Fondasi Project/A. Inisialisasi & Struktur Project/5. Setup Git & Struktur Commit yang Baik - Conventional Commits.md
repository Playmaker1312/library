# Setup Git & Struktur Commit yang Baik — Conventional Commits

## Penjelasan

Git adalah version control system yang wajib digunakan dalam pengembangan perangkat lunak profesional. Setelah membuat project NestJS, langkah selanjutnya adalah menginisialisasi Git repository dan menetapkan standar commit yang baik. NestJS CLI secara otomatis sudah membuat file `.gitignore` yang berisi daftar file dan folder yang tidak perlu di-track oleh Git, seperti `node_modules/`, `dist/`, dan file environment.

**Conventional Commits** adalah standar penulisan pesan commit yang terstruktur. Formatnya sederhana: `type(scope): description`. Contoh: `feat(auth): menambah fitur login`, `fix(books): memperbaiki validasi ISBN`. Standar ini memudahkan pembuatan changelog otomatis, menentukan versi semantic (major/minor/patch), dan memberikan konteks yang jelas tentang apa yang berubah dalam sebuah commit. Banyak tools seperti `standard-version` atau `semantic-release` yang bergantung pada format ini.

Untuk memastikan setiap commit mengikuti standar ini, kita menggunakan **Husky** (git hooks manager) dan **lint-staged** (menjalankan linter hanya pada file yang diubah). Dengan Husky, kita bisa menjalankan ESLint dan Prettier secara otomatis sebelum setiap commit — memastikan tidak ada kode kotor yang masuk ke repository. Kombinasi ini adalah praktik terbaik yang diadopsi oleh tim-tim pengembang profesional.

## Fungsi

Git berfungsi untuk melacak setiap perubahan kode, memungkinkan kolaborasi tim, dan menyediakan safety net untuk kembali ke versi sebelumnya jika terjadi kesalahan. Conventional Commits berfungsi untuk memberikan struktur dan makna pada setiap commit — memudahkan code review, debugging, dan rilis. Husky dan lint-staged berfungsi sebagai **automated gatekeeper** yang menegakkan standar kualitas kode sebelum kode masuk ke repository.

## Cara Implementasi / Code

### 1. Inisialisasi Git (jika NestJS CLI tidak melakukannya otomatis)

```bash
# Cek apakah git sudah terinisialisasi
git status

# Jika belum, inisialisasi
git init

# Cek file .gitignore (seharusnya sudah ada)
type .gitignore
```

### 2. File `.gitignore` bawaan NestJS CLI

```
node_modules
dist
.tmp
.env
.env.local
*.log
.DS_Store
coverage
```

### 3. Setup Conventional Commits — panduan tim

Buat file `COMMIT_CONVENTION.md` di root project:

```markdown
# Conventional Commits Guide

## Format
type(scope): description

## Types
- feat: Fitur baru (→ minor version)
- fix: Perbaikan bug (→ patch version)
- chore: Tugas rutin, update dependencies
- docs: Perubahan dokumentasi
- style: Perubahan format (spasi, indentasi) — bukan logic
- refactor: Refactor kode — bukan fitur/bug
- test: Menambah/memperbaiki test
- perf: Perubahan untuk meningkatkan performa

## Contoh
feat(books): menambah endpoint GET /books
fix(auth): memperbaiki validasi token expired
docs(readme): update instruksi instalasi
refactor(modules): memisahkan user dan auth module
```

### 4. Setup Husky untuk pre-commit hook

```bash
# Install Husky dan lint-staged
pnpm add -D husky lint-staged

# Inisialisasi Husky
npx husky init

# Buat folder .husky jika belum ada
# Edit file .husky/pre-commit
```

Isi file `.husky/pre-commit`:

```bash
#!/usr/bin/env sh
. "$(dirname "$0")/_/husky.sh"

npx lint-staged
```

### 5. Konfigurasi lint-staged di `package.json`

```json
{
  "lint-staged": {
    "*.ts": [
      "eslint --fix",
      "prettier --write"
    ],
    "*.json": [
      "prettier --write"
    ]
  }
}
```

### 6. Commit pertama dengan Conventional Commits

```bash
# Tambahkan semua file ke staging
git add .

# Commit pertama
git commit -m "chore(init): inisialisasi project NestJS perpustakaan-api

- Setup project dengan NestJS CLI
- Konfigurasi ESLint dan Prettier
- Setup environment variables
- Tambah Husky dan lint-staged"

# Jika ada error dari lint-staged, perbaiki lalu commit lagi
git add .
git commit -m "fix(lint): perbaiki error ESLint pada controller"
```

### 7. Contoh siklus commit yang baik

```bash
# Saat menambah fitur baru
git add src/modules/books/
git commit -m "feat(books): menambah CRUD books module"

# Saat memperbaiki bug
git add src/modules/books/books.service.ts
git commit -m "fix(books): perbaiki validasi stock tidak boleh negatif"

# Saat update dokumentasi
git add README.md
git commit -m "docs(readme): tambah instruksi testing"

# Saat refactor
git add src/common/
git commit -m "refactor(common): pisahkan interceptor ke file terpisah"
```

### 8. Melihat riwayat commit yang rapi

```bash
# Melihat log commit
git log --oneline --graph

# Melihat log dengan format
git log --pretty=format:"%h - %s (%an, %ar)"
```

## Analogi

Bayangkan perpustakaan memiliki **sistem katalog buku** yang sangat ketat:

- **Git** adalah **sistem katalog utama perpustakaan** — setiap kali ada buku baru masuk (perubahan kode), petakan dicatat di katalog: kapan masuk, siapa yang menyerahkan, dan apa isi bukunya. Jika ada buku yang bermasalah, kita bisa melihat kapan dan oleh siapa buku itu pertama kali dimasukkan.

- **Conventional Commits** adalah **format standar penulisan kartu katalog**. Setiap kartu harus mencantumkan: jenis buku (feat/fix/docs), lokasi rak (scope), dan deskripsi singkat. Kartu yang tidak sesuai format akan ditolak oleh petugas katalog.

- **Husky** adalah **petugas keamanan di pintu masuk perpustakaan** — sebelum buku baru bisa masuk ke katalog, petugas akan memeriksa apakah bukunya bersih (linter) dan rapi (formatter). Buku yang kotor atau tidak rapi akan dikembalikan ke pengirim untuk diperbaiki.

- **lint-staged** adalah **asisten petugas keamanan** yang hanya memeriksa buku-buku yang baru masuk (file yang diubah), bukan memeriksa seluruh perpustakaan dari awal. Ini menghemat waktu karena hanya fokus pada perubahan.

Dengan sistem ini, perpustakaan (kode) selalu dalam kondisi bersih, rapi, dan setiap perubahan tercatat dengan jelas.

## Penggunaan

Git dan Conventional Commits digunakan di **setiap project profesional tanpa terkecuali**. Saat bekerja dalam tim, standar commit memudahkan code review — reviewer langsung tahu jenis perubahan dari prefix commit. Saat rilis, changelog bisa digenerate otomatis dari commit messages. Saat debugging, `git bisect` bisa mencari commit mana yang memperkenalkan bug dengan membaca pesan commit yang deskriptif.

## Kesalahan Umum yang Sering Terjadi

1. **Commit dengan pesan tidak jelas** — Pesan seperti `update`, `fix bug`, `perbaikan` tidak memberikan konteks. Selalu gunakan format Conventional Commits.

2. **Commit terlalu besar** — Satu commit berisi banyak perubahan yang tidak terkait. Pisahkan menjadi beberapa commit kecil berdasarkan jenis perubahan.

3. **Lupa setup .gitignore sebelum commit** — File `node_modules/`, `.env`, atau `dist/` ikut tercommit. Jika sudah terlanjur, gunakan `git rm --cached` untuk menghapus dari tracking.

4. **Melewati Husky dengan `--no-verify`** — Menggunakan `git commit --no-verify` untuk bypass linting adalah kebiasaan buruk. Sebaiknya perbaiki error daripada melewatinya.

5. **Tidak membuat branch untuk fitur baru** — Langsung commit ke branch `main` atau `master`. Praktik yang benar: buat branch `feature/nama-fitur`, commit di sana, lalu pull request.

## Hubungan dengan Materi Sebelumnya

Setelah kita membuat project (materi 1), memahami struktur filenya (materi 2), mengkonfigurasi main.ts (materi 3), dan setup ESLint/Prettier (materi 4), sekarang kita mengamankan semua progress dengan Git. Materi ini adalah **pengaman** dari semua kerja keras kita sebelumnya — memastikan semua perubahan tercatat dengan rapi dan bisa di-recover jika terjadi kesalahan di materi-materi berikutnya.

## Soal Latihan

**Soal:** Lakukan setup Git pada project `perpustakaan-api` dengan spesifikasi berikut:
1. Inisialisasi Git repository
2. Konfigurasi Husky dengan pre-commit hook yang menjalankan `pnpm run lint`
3. Buatlah 3 commit terpisah dengan Conventional Commits:
   - Commit 1: Setup project awal (chore)
   - Commit 2: Konfigurasi ESLint dan Prettier (chore)
   - Commit 3: Setup Husky dan lint-staged (chore)
4. Tampilkan git log yang menunjukkan 3 commit tersebut

**Jawaban:**

```bash
# Langkah 1: Inisialisasi Git
cd perpustakaan-api
git init

# Langkah 2: Setup Husky
pnpm add -D husky lint-staged
npx husky init

# Edit .husky/pre-commit
# Isi file:
# npx lint-staged

# Tambahkan lint-staged di package.json
# "lint-staged": { "*.ts": ["eslint --fix", "prettier --write"] }

# Langkah 3: Commit 1 — Setup project awal
git add package.json pnpm-lock.yaml nest-cli.json tsconfig.json tsconfig.build.json
git add src/ test/
git commit -m "chore(init): inisialisasi project NestJS perpustakaan-api

Project awal menggunakan NestJS dengan pnpm sebagai package manager"

# Langkah 4: Commit 2 — ESLint & Prettier
git add .eslintrc.js .prettierrc
git commit -m "chore(lint): konfigurasi ESLint dan Prettier

Menambahkan aturan kustom untuk project NestJS"

# Langkah 5: Commit 3 — Husky & lint-staged
git add .husky/ package.json
git commit -m "chore(hooks): setup husky dan lint-staged untuk pre-commit"

# Langkah 6: Lihat log
git log --oneline

# Output:
# 3a1b2c3 chore(hooks): setup husky dan lint-staged untuk pre-commit
# 4d5e6f7 chore(lint): konfigurasi ESLint dan Prettier
# 8g9h0i1 chore(init): inisialisasi project NestJS perpustakaan-api
```
