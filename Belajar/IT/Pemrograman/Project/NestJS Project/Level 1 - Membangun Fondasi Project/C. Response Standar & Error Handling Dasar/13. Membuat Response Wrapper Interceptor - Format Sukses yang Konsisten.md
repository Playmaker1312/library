# Membuat Response Wrapper Interceptor — Format Sukses yang Konsisten

## Penjelasan

Saat ini, ketika client memanggil endpoint `GET /books`, mereka mendapatkan response berupa array JSON langsung — tanpa wrapper, tanpa metadata. Masalahnya, ini tidak konsisten dengan response error yang nantinya akan memiliki format `{statusCode, message, error}`. Untuk memberikan pengalaman API yang konsisten, semua response sukses juga perlu dibungkus dalam format standar. Di sinilah **Interceptor** berperan.

**Interceptor** adalah class yang diberi decorator `@Injectable()` dan mengimplementasikan interface `NestInterceptor`. Interceptor bisa memodifikasi response sebelum dikirim ke client, memodifikasi request sebelum sampai ke handler, atau bahkan mengubah alur eksekusi. Dalam kasus kita, kita akan membuat interceptor yang menangkap response dari controller dan membungkusnya dalam format: `{ statusCode: number, message: string, data: any, timestamp: string }`.

Interceptor ini akan didaftarkan secara **global** di `main.ts` menggunakan `app.useGlobalInterceptors()`, sehingga semua endpoint akan secara otomatis mendapatkan format response yang sama. Jika ada endpoint yang perlu mengembalikan response mentah (raw), kita bisa menggunakan metadata atau decorator kustom untuk mengecualikannya dari wrapper.

## Fungsi

Response Wrapper Interceptor berfungsi untuk **menstandarisasi format response sukses** di seluruh aplikasi. Dengan format yang konsisten, client (frontend, mobile app) bisa membuat generic response handler yang sama untuk semua endpoint. Interceptor ini juga menambahkan informasi timestamp yang berguna untuk debugging dan logging.

## Cara Implementasi / Code

### 1. Buat interface untuk response API

Buka file `src/common/interfaces/api-response.interface.ts`:

```typescript
export interface ApiResponse<T> {
  statusCode: number;
  message: string;
  data: T;
  timestamp: string;
}
```

### 2. Buat Response Wrapper Interceptor

Buat file `src/common/interceptors/response-wrapper.interceptor.ts`:

```typescript
import {
  Injectable,
  NestInterceptor,
  ExecutionContext,
  CallHandler,
} from '@nestjs/common';
import { Observable } from 'rxjs';
import { map } from 'rxjs/operators';
import { ApiResponse } from '../interfaces/api-response.interface';

@Injectable()
export class ResponseWrapperInterceptor<T>
  implements NestInterceptor<T, ApiResponse<T>>
{
  intercept(
    context: ExecutionContext,
    next: CallHandler,
  ): Observable<ApiResponse<T>> {
    const response = context.switchToHttp().getResponse();
    const statusCode = response.statusCode;

    return next.handle().pipe(
      map((data) => ({
        statusCode,
        message: 'Sukses',
        data,
        timestamp: new Date().toISOString(),
      })),
    );
  }
}
```

### 3. Daftarkan interceptor secara global di `main.ts`

```typescript
import { NestFactory } from '@nestjs/core';
import { AppModule } from './app.module';
import { ResponseWrapperInterceptor } from './common/interceptors/response-wrapper.interceptor';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);

  // Global prefix
  app.setGlobalPrefix('api/v1');

  // Daftarkan interceptor global
  app.useGlobalInterceptors(new ResponseWrapperInterceptor());

  await app.listen(process.env.PORT ?? 3000);
}
bootstrap();
```

### 4. Response Sebelum vs Sesudah Interceptor

**Sebelum Interceptor:**
```json
[
  {
    "id": "uuid-1",
    "title": "Laskar Pelangi",
    "author": "Andrea Hirata"
  }
]
```

**Sesudah Interceptor:**
```json
{
  "statusCode": 200,
  "message": "Sukses",
  "data": [
    {
      "id": "uuid-1",
      "title": "Laskar Pelangi",
      "author": "Andrea Hirata"
    }
  ],
  "timestamp": "2026-06-12T08:30:00.000Z"
}
```

### 5. Tambahkan decorator kustom untuk mengecualikan endpoint

Ada kalanya endpoint tertentu tidak perlu di-wrapper (misalnya endpoint yang mengembalikan file atau redirect). Kita bisa menggunakan decorator kustom + Reflector:

Buat file `src/common/decorators/public.decorator.ts`:

```typescript
import { SetMetadata } from '@nestjs/common';

export const SKIP_WRAPPER_KEY = 'skipWrapper';
export const SkipWrapper = () => SetMetadata(SKIP_WRAPPER_KEY, true);
```

Modifikasi interceptor untuk mengecek metadata:

```typescript
import {
  Injectable,
  NestInterceptor,
  ExecutionContext,
  CallHandler,
} from '@nestjs/common';
import { Reflector } from '@nestjs/core';
import { Observable } from 'rxjs';
import { map } from 'rxjs/operators';
import { SKIP_WRAPPER_KEY } from '../decorators/public.decorator';
import { ApiResponse } from '../interfaces/api-response.interface';

@Injectable()
export class ResponseWrapperInterceptor<T>
  implements NestInterceptor<T, ApiResponse<T>>
{
  constructor(private readonly reflector: Reflector) {}

  intercept(
    context: ExecutionContext,
    next: CallHandler,
  ): Observable<ApiResponse<T>> {
    // Lewati wrapper jika endpoint punya decorator @SkipWrapper()
    const skipWrapper = this.reflector.getAllAndOverride<boolean>(
      SKIP_WRAPPER_KEY,
      [context.getHandler(), context.getClass()],
    );

    if (skipWrapper) {
      return next.handle();
    }

    const response = context.switchToHttp().getResponse();
    const statusCode = response.statusCode;

    return next.handle().pipe(
      map((data) => ({
        statusCode,
        message: 'Sukses',
        data,
        timestamp: new Date().toISOString(),
      })),
    );
  }
}
```

### 6. Alternatif: Provider-based registration (recommended untuk production)

Cara yang lebih NestJS-style adalah menggunakan APP_INTERCEPTOR token:

Di `app.module.ts`:

```typescript
import { Module } from '@nestjs/common';
import { APP_INTERCEPTOR } from '@nestjs/core';
import { ResponseWrapperInterceptor } from './common/interceptors/response-wrapper.interceptor';

@Module({
  providers: [
    {
      provide: APP_INTERCEPTOR,
      useClass: ResponseWrapperInterceptor,
    },
  ],
})
export class AppModule {}
```

Cara ini memungkinkan interceptor untuk menggunakan dependency injection (misalnya meng-inject service lain jika diperlukan).

### 7. Custom message berdasarkan status code

Kita bisa memperhalus interceptor dengan menambahkan message yang dinamis:

```typescript
private getMessageForStatus(statusCode: number): string {
  switch (statusCode) {
    case 200: return 'Data berhasil diambil';
    case 201: return 'Data berhasil dibuat';
    case 204: return 'Data berhasil dihapus';
    default: return 'Sukses';
  }
}
```

## Analogi

Bayangkan perpustakaan memiliki **standar amplop** untuk semua dokumen yang keluar:

- **Response tanpa interceptor** — Setiap petugas memberikan dokumen dalam bentuk yang berbeda-beda. Ada yang memberikan kertas lepas, ada yang pakai klip kertas, ada yang map. Pengunjung bingung karena formatnya tidak konsisten.

- **Response dengan interceptor** — Semua dokumen **wajib dimasukkan ke dalam amplop resmi perpustakaan** yang sudah mencantumkan: tanggal (timestamp), nomor surat (statusCode), keterangan (message), dan isi surat (data).

- **Decorator @SkipWrapper()** — Kadang ada dokumen khusus (seperti poster atau peta) yang tidak bisa dimasukkan amplop. Petugas bisa menempel stempel "TANPA AMPLOP" pada dokumen tersebut agar interceptor melewatinya.

Dengan amplop standar ini, pengunjung (client) tahu persis di mana mencari informasi yang mereka butuhkan — selalu di `data`, selalu ada `statusCode`, selalu ada `timestamp`. Frontend bisa membuat satu fungsi `handleApiResponse()` yang bekerja untuk semua endpoint.

## Penggunaan

Response Wrapper Interceptor digunakan di **semua REST API** yang membutuhkan format response konsisten. Ini sangat penting ketika API digunakan oleh banyak client (web, mobile, third-party) yang membutuhkan struktur response yang dapat diprediksi. Interceptor ini juga memudahkan perubahan format response di masa depan — cukup ubah satu file, semua endpoint terpengaruh.

## Kesalahan Umum yang Sering Terjadi

1. **Interceptor tidak menangani response yang sudah berbentuk pagination** — Jika data sudah punya struktur `{items, total, page, limit}`, wrapper akan membungkusnya lagi menjadi `{data: {items, total, page, limit}}`. Pertimbangkan untuk tidak me-wrap response pagination.

2. **Lupa mendaftarkan interceptor** — Interceptor yang sudah dibuat tapi tidak didaftarkan di `main.ts` atau `AppModule` tidak akan berfungsi.

3. **Interceptor melempar error untuk response non-JSON** — Jika ada endpoint yang mengembalikan file (stream), interceptor akan error. Gunakan `SkipWrapper()` decorator untuk endpoint tersebut.

4. **Message yang statis** — Semua response sukses memiliki message "Sukses". Akan lebih baik jika message bersifat dinamis berdasarkan operasi.

5. **Tidak menangani response null** — Jika service mengembalikan `null`, pastikan interceptor tetap bisa membungkusnya.

## Hubungan dengan Materi Sebelumnya

Setelah semua endpoint Books berfungsi (materi 7-12), kita sekarang meningkatkan kualitas API dengan format response yang konsisten. Interceptor ini bekerja di **lapisan yang lebih tinggi** dari controller — ia membungkus response setelah controller selesai memproses request. Bersama dengan Global Exception Filter (materi 14), Logging Interceptor (materi 15), dan ValidationPipe (materi 16), keempat komponen ini membentuk **lapisan infrastruktur global** yang melayani semua module.

## Soal Latihan

**Soal:** Buatlah Response Wrapper Interceptor yang:
1. Membungkus response dengan format `{success, statusCode, message, data, timestamp}`
2. Field `success` adalah `true` untuk semua response sukses
3. Untuk status code 201, message-nya "Data berhasil dibuat"
4. Untuk status code 204, data-nya tidak perlu dikirim (kosongkan saja)
5. Daftarkan secara global menggunakan `APP_INTERCEPTOR`

**Jawaban:**

`src/common/interceptors/response-wrapper.interceptor.ts`:
```typescript
import {
  Injectable,
  NestInterceptor,
  ExecutionContext,
  CallHandler,
  HttpStatus,
} from '@nestjs/common';
import { Observable } from 'rxjs';
import { map } from 'rxjs/operators';

interface WrappedResponse<T> {
  success: boolean;
  statusCode: number;
  message: string;
  data: T;
  timestamp: string;
}

@Injectable()
export class ResponseWrapperInterceptor<T>
  implements NestInterceptor<T, WrappedResponse<T>>
{
  intercept(
    context: ExecutionContext,
    next: CallHandler,
  ): Observable<WrappedResponse<T>> {
    const response = context.switchToHttp().getResponse();
    const statusCode: number = response.statusCode;

    const messageMap: Record<number, string> = {
      [HttpStatus.OK]: 'Data berhasil diambil',
      [HttpStatus.CREATED]: 'Data berhasil dibuat',
      [HttpStatus.NO_CONTENT]: 'Data berhasil dihapus',
    };

    const message = messageMap[statusCode] || 'Sukses';

    return next.handle().pipe(
      map((data) => ({
        success: true,
        statusCode,
        message,
        data: statusCode === HttpStatus.NO_CONTENT ? undefined : data,
        timestamp: new Date().toISOString(),
      })),
    );
  }
}
```

`app.module.ts`:
```typescript
import { Module } from '@nestjs/common';
import { APP_INTERCEPTOR } from '@nestjs/core';
import { ResponseWrapperInterceptor } from './common/interceptors/response-wrapper.interceptor';

@Module({
  providers: [
    {
      provide: APP_INTERCEPTOR,
      useClass: ResponseWrapperInterceptor,
    },
  ],
})
```
