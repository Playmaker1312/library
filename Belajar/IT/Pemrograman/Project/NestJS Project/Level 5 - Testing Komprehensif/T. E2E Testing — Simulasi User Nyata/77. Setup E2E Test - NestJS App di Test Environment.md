# 77. Setup E2E Test — NestJS App di Test Environment

## Penjelasan

E2E (End-to-End) testing adalah level pengujian tertinggi dalam piramida testing. Di level ini, kita menjalankan seluruh aplikasi NestJS secara utuh — termasuk semua modul, controller, service, repository, guards, interceptors, dan filters — dan mengirim request HTTP nyata menggunakan library seperti `supertest`. Tujuannya adalah mensimulasikan perilaku pengguna nyata dari ujung ke ujung: request masuk, melewati pipeline NestJS (pipe, guard, interceptor, controller, service, repository, database), dan mengembalikan response. Tidak ada yang di-mock di level ini kecuali environment eksternal yang tidak bisa dijalankan di CI (seperti email service atau payment gateway).

Setup E2E test membutuhkan pembuatan NestJS application instance yang terpisah dari aplikasi production. Kita menggunakan `Test.createTestingModule` dari `@nestjs/testing` untuk mengimpor modul aplikasi utama (`AppModule`) dan membuat `NestApplication` dengan `createNestApplication()`. Setelah itu, kita pasang global pipe (seperti `ValidationPipe`), global filter (`GlobalExceptionFilter`), dan global interceptor (`ResponseWrapperInterceptor`) yang sama dengan yang digunakan di production. Ini memastikan bahwa pipeline request yang diuji identik dengan production.

`supertest` adalah library yang menyediakan API tinggi-level untuk mengirim request HTTP ke aplikasi NestJS tanpa harus menjalankan server di port terpisah. Dengan `supertest(app.getHttpServer())`, kita bisa mengirim GET, POST, PUT, DELETE request dan memverifikasi status code, header, dan body response. Supertest mendukung chainable API yang intuitif: `request(app.getHttpServer()).get('/api/books').expect(200)`. Semua request dijalankan dalam memory tanpa jaringan TCP, sehingga test berjalan sangat cepat.

## Fungsi

- Membuat NestJS application instance yang terisolasi untuk testing
- Memasang global pipes, filters, dan interceptors yang identik dengan production
- Menyediakan HTTP client (supertest) untuk mensimulasikan request pengguna
- Menginisialisasi koneksi database dan menjalankan migrasi sebelum test
- Memastikan pipeline aplikasi berfungsi dari HTTP request hingga database response
- Menyediakan struktur dasar untuk semua test case e2e selanjutnya

## Cara Implementasi / Code

### 1. `test/app.e2e-spec.ts` — Setup Utama

```typescript
// test/app.e2e-spec.ts
import { Test, TestingModuleBuilder } from '@nestjs/testing';
import { INestApplication, ValidationPipe } from '@nestjs/common';
import * as request from 'supertest';
import { AppModule } from '../src/app.module';
import { GlobalExceptionFilter } from '../src/common/filters/global-exception.filter';
import { ResponseWrapperInterceptor } from '../src/common/interceptors/response-wrapper.interceptor';

describe('App E2E Test Setup', () => {
  let app: INestApplication;
  let httpServer: any;

  beforeAll(async () => {
    // 1. Buat testing module dengan AppModule lengkap
    const moduleBuilder: TestingModuleBuilder = Test.createTestingModule({
      imports: [AppModule],
    });

    const moduleRef = await moduleBuilder.compile();

    // 2. Buat NestJS application instance
    app = moduleRef.createNestApplication();

    // 3. Pasang global pipe — sama dengan di main.ts
    app.useGlobalPipes(
      new ValidationPipe({
        whitelist: true,
        forbidNonWhitelisted: true,
        transform: true,
        transformOptions: {
          enableImplicitConversion: true,
        },
      }),
    );

    // 4. Pasang global filter
    app.useGlobalFilters(new GlobalExceptionFilter());

    // 5. Pasang global interceptor
    app.useGlobalInterceptors(new ResponseWrapperInterceptor());

    // 6. Set global prefix (jika ada)
    app.setGlobalPrefix('api');

    // 7. Inisialisasi aplikasi (listen)
    await app.init();

    // 8. Dapatkan HTTP server untuk supertest
    httpServer = app.getHttpServer();
  });

  afterAll(async () => {
    // Bersihkan resource setelah semua test selesai
    await app.close();
  });

  // ============== TEST SETUP VALIDATION ==============

  describe('App Health Check', () => {
    it('should respond with 404 for unknown routes', async () => {
      const response = await request(httpServer).get('/api/nonexistent');

      expect(response.status).toBe(404);
      expect(response.body).toHaveProperty('statusCode', 404);
      expect(response.body).toHaveProperty('message');
    });

    it('should have CORS headers enabled', async () => {
      const response = await request(httpServer)
        .options('/api/books')
        .set('Origin', 'http://localhost:3000')
        .set('Access-Control-Request-Method', 'GET');

      expect(response.headers['access-control-allow-origin']).toBe('*');
    });

    it('should apply global prefix /api', async () => {
      // Endpoint tanpa /api harus 404
      await request(httpServer).get('/books').expect(404);

      // Endpoint dengan /api boleh 200 atau 401 (tergantung auth)
      const response = await request(httpServer).get('/api/books');
      expect([200, 401]).toContain(response.status);
    });
  });

  describe('Validation Pipe', () => {
    it('should reject request with invalid body', async () => {
      // Kirim body kosong untuk endpoint yang membutuhkan validasi
      const response = await request(httpServer)
        .post('/api/auth/register')
        .send({})
        .expect(400);

      expect(response.body).toHaveProperty('message');
      expect(Array.isArray(response.body.message)).toBe(true);
    });

    it('should strip unknown properties when whitelist is true', async () => {
      const response = await request(httpServer)
        .post('/api/auth/register')
        .send({
          email: 'test@example.com',
          password: 'password123',
          name: 'Test User',
          unknownField: 'should be stripped',
        });

      // Jika berhasil atau error karena validasi, field unknown tidak ada di body
      expect(response.body).toBeDefined();
    });
  });

  describe('Exception Filter', () => {
    it('should return consistent error format for all errors', async () => {
      const response = await request(httpServer)
        .get('/api/books/nonexistent-id')
        .expect(401); // Karena tidak ada token

      // Format error harus konsisten
      expect(response.body).toEqual(
        expect.objectContaining({
          statusCode: expect.any(Number),
          message: expect.any(String),
        }),
      );
    });
  });

  describe('Response Wrapper', () => {
    it('should wrap successful responses', async () => {
      // Endpoint publik seperti health check
      const response = await request(httpServer)
        .get('/api/books')
        .expect(401); // Belum login, tapi format harus wrapped

      // Response error tetap di-wrap oleh filter, bukan interceptor
      expect(response.body).toBeDefined();
    });
  });
});
```

### 2. `test/app.e2e-spec.ts` — Versi Modular dengan Helper Class

```typescript
// test/utils/e2e-helper.ts
import { INestApplication, ValidationPipe } from '@nestjs/common';
import { Test, TestingModuleBuilder } from '@nestjs/testing';
import * as request from 'supertest';
import { AppModule } from '../../src/app.module';
import { GlobalExceptionFilter } from '../../src/common/filters/global-exception.filter';
import { ResponseWrapperInterceptor } from '../../src/common/interceptors/response-wrapper.interceptor';

export class E2EHelper {
  public app: INestApplication;
  public httpServer: any;

  async setup(customModule?: TestingModuleBuilder): Promise<void> {
    const moduleBuilder = customModule ?? Test.createTestingModule({
      imports: [AppModule],
    });

    const moduleRef = await moduleBuilder.compile();

    this.app = moduleRef.createNestApplication();
    this.app.useGlobalPipes(
      new ValidationPipe({
        whitelist: true,
        forbidNonWhitelisted: true,
        transform: true,
      }),
    );
    this.app.useGlobalFilters(new GlobalExceptionFilter());
    this.app.useGlobalInterceptors(new ResponseWrapperInterceptor());
    this.app.setGlobalPrefix('api');

    await this.app.init();
    this.httpServer = this.app.getHttpServer();
  }

  async teardown(): Promise<void> {
    await this.app?.close();
  }

  // Helper methods untuk test yang sering digunakan
  async registerUser(email: string, password: string, name: string) {
    return request(this.httpServer)
      .post('/api/auth/register')
      .send({ email, password, name });
  }

  async loginUser(email: string, password: string) {
    return request(this.httpServer)
      .post('/api/auth/login')
      .send({ email, password });
  }

  async createBook(accessToken: string, bookData: any) {
    return request(this.httpServer)
      .post('/api/books')
      .set('Authorization', `Bearer ${accessToken}`)
      .send(bookData);
  }

  getRequest() {
    return request(this.httpServer);
  }
}
```

## Analogi

Bayangkan perpustakaan ingin menguji **seluruh sistem peminjaman dari awal hingga akhir**. Mereka tidak hanya menguji petugas loket (unit test) atau database (integration test), tetapi mereka menguji **skenario lengkap**: seorang pengunjung datang ke perpustakaan (request HTTP), melewati pintu masuk (guard), mencari buku di katalog (controller), memproses data (service), menyimpan catatan di buku besar (repository), mendapat struk peminjaman (response), dan pulang. Untuk simulasi ini, perpustakaan menyiapkan **perpustakaan tiruan** yang lengkap dengan semua staf, rak buku, dan sistem yang sama persis dengan perpustakaan asli — hanya saja bukunya adalah buku uji coba. Seorang **penguji berpakaian seperti pengunjung biasa** (supertest) masuk, meminjam buku, mengembalikan buku, dan mencoba masuk ke area terlarang — semua untuk memastikan seluruh sistem bekerja bersama dengan harmonis.

## Penggunaan

- Sebagai fondasi untuk semua test e2e selanjutnya (auth flow, books CRUD)
- Memvalidasi konfigurasi global aplikasi (pipe, filter, interceptor, prefix)
- Mendeteksi masalah integrasi antar modul yang tidak terdeteksi di unit test
- Verifikasi bahwa setup aplikasi di main.ts sudah benar
- Dokumentasi bagaimana aplikasi berperilaku dari perspektif HTTP

## Kesalahan Umum yang Sering Terjadi

1. **Global pipe/filter/interceptor tidak dipasang**: Aplikasi test tidak memiliki `ValidationPipe` atau `GlobalExceptionFilter`, sehingga behavior response berbeda dengan production. Solusi: copy semua global setup dari `main.ts` ke setup e2e.

2. **Lupa memanggil `app.init()`**: Aplikasi tidak diinisialisasi sehingga semua request gagal dengan error. Solusi: selalu panggil `await app.init()` setelah semua konfigurasi.

3. **Database tidak dibersihkan antar test suite**: Data dari e2e test sebelumnya mengganggu test berikutnya. Solusi: gunakan `beforeEach` untuk truncate tabel di setiap test file.

4. **Test saling bergantung**: Urutan eksekusi test mempengaruhi hasil. Solusi: setiap test harus independen — setup data sendiri, cleanup setelah selesai.

5. **`detectOpenHandles: true` tidak diset**: Sulit mendeteksi koneksi database yang tidak ditutup. Solusi: aktifkan opsi ini dan pastikan `app.close()` dipanggil di `afterAll`.

6. **Module reference tidak dikompilasi ulang**: Semua test menggunakan modul yang sama, menyebabkan state bocor. Solusi: buat module baru untuk setiap test file (kompilasi ulang).
