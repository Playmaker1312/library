# 50. Test API dari Swagger UI - Authorize & Test Endpoint

## Penjelasan

Swagger UI bukan hanya dokumentasi pasif — ia adalah **klien API interaktif** yang bisa digunakan untuk menguji setiap endpoint secara langsung dari browser. Fitur "Authorize" memungkinkan kita memasukkan token JWT yang akan dikirim otomatis ke semua endpoint yang membutuhkan autentikasi. Ini sangat memudahkan proses testing dan debugging tanpa perlu menggunakan tools terpisah seperti Postman atau curl.

Proses testing di Swagger UI mengikuti alur yang sama seperti aplikasi nyata: (1) Register atau login untuk mendapatkan token, (2) Klik tombol Authorize dan masukkan token, (3) Test endpoint yang membutuhkan autentikasi, (4) Logout untuk mengakhiri session. Semua interaksi ini dilakukan langsung dari UI Swagger tanpa perlu tool tambahan.

## Fungsi

Testing API dari Swagger UI berfungsi untuk: (1) memvalidasi bahwa endpoint bekerja sesuai harapan, (2) memverifikasi autentikasi dan otorisasi berfungsi dengan benar, (3) memberikan demonstrasi langsung kepada developer atau stakeholder, (4) mempercepat proses debugging dengan feedback visual langsung, (5) menghasilkan contoh request dan response yang bisa digunakan untuk dokumentasi.

## Cara Implementasi / Code

**Langkah-langkah Testing API dari Swagger UI:**

### Langkah 1: Buka Swagger UI

Buka browser dan akses:
```
http://localhost:3000/api
```

Anda akan melihat halaman Swagger UI dengan dua grup tag:
- **Authentication** — endpoint untuk autentikasi
- **Books** — endpoint untuk manajemen buku

### Langkah 2: Register User Baru

1. Klik tag **Authentication** untuk memperluas
2. Klik endpoint `POST /auth/register`
3. Klik tombol **"Try it out"** di pojok kanan atas
4. Di bagian **Request body**, masukkan data berikut:

```json
{
  "email": "testuser@example.com",
  "name": "Test User",
  "password": "Password123"
}
```

5. Klik tombol **"Execute"**
6. Lihat **Response** di bawah:
   - Status: `201 Created`
   - Response body akan berisi:
     ```json
     {
       "user": {
         "id": 1,
         "email": "testuser@example.com",
         "name": "Test User",
         "role": "USER"
       },
       "accessToken": "eyJhbGciOiJIUzI1NiIs...",
       "refreshToken": "eyJhbGciOiJIUzI1NiIs..."
     }
     ```

### Langkah 3: Authorize dengan Token

**Cara 1: Authorize setelah login (menggunakan access token):**
1. Salin nilai `accessToken` dari response register (atau login)
2. Klik tombol **"Authorize"** (ikon gembok 🔓) di pojok kanan atas
3. Di dialog **"Available authorizations"**, paste token di kolom **"Value"** dengan format:
   ```
   eyJhbGciOiJIUzI1NiIs...
   ```
   **(Jangan tambahkan prefix "Bearer " — Swagger akan melakukannya otomatis)**
4. Klik tombol **"Authorize"**
5. Klik tombol **"Close"**
6. Perhatikan bahwa ikon gembok sekarang terkunci 🔒 — artinya token sudah aktif

**Cara 2: Salin token dari response register/login (langkah alternatif):**
- Di response register/login, salin nilai `accessToken` (tanpa tanda petik)
- Tempel di dialog Authorize

### Langkah 4: Test Endpoint yang Memerlukan Autentikasi

**Test GET /auth/me:**
1. Klik endpoint `GET /auth/me`
2. Klik **"Try it out"**
3. Klik **"Execute"**
4. Response yang diharapkan:
   ```json
   {
     "user": {
       "id": 1,
       "email": "testuser@example.com",
       "name": "Test User",
       "role": "USER"
     }
   }
   ```
5. Jika Anda mendapatkan `401 Unauthorized`, berarti token tidak terkirim — periksa kembali langkah Authorize

**Test POST /auth/logout:**
1. Klik endpoint `POST /auth/logout`
2. Klik **"Try it out"**
3. Klik **"Execute"**
4. Response:
   ```json
   {
     "message": "Logged out successfully"
   }
   ```

### Langkah 5: Test Endpoint Public (Tanpa Autentikasi)

**Test GET /books — tanpa token:**
1. Klik tag **Books**
2. Klik endpoint `GET /books`
3. Klik **"Try it out"**
4. Klik **"Execute"**
5. Response: `200 OK` dengan array buku (meskipun token sudah tidak aktif setelah logout)

**Test POST /books — harus gagal (karena role USER):**
1. Klik endpoint `POST /books`
2. Klik **"Try it out"**
3. Masukkan data buku:
   ```json
   {
     "title": "Test Book",
     "author": "Test Author",
     "isbn": "978-1234567890",
     "publishedYear": 2024
   }
   ```
4. Klik **"Execute"**
5. Response: `403 Forbidden` — karena user dengan role USER tidak punya akses

### Langkah 6: Login sebagai Librarian/Admin

Untuk menguji endpoint dengan role LIBRARIAN atau ADMIN, kita perlu user dengan role tersebut.

**Opsi A: Update role langsung di database:**
```bash
npx prisma studio
```
Cari user yang sudah dibuat, ubah `role` dari `USER` menjadi `LIBRARIAN` atau `ADMIN`, lalu save.

**Opsi B: Buat user baru dengan role berbeda (via Prisma Studio):**
1. Buka Prisma Studio: `npx prisma studio`
2. Tambahkan user baru dengan role yang diinginkan
3. Atau gunakan langsung endpoint register, lalu update role via database

**Login sebagai Librarian:**
1. Kembali ke endpoint `POST /auth/login` di Swagger
2. Masukkan email dan password user yang sudah di-update role-nya
3. Execute dan dapatkan token baru
4. Update token di **Authorize** dengan token yang baru

### Langkah 7: Test Endpoint dengan Role yang Sesuai

**Test POST /books sebagai LIBRARIAN:**
1. Pastikan sudah Authorize dengan token LIBRARIAN
2. Klik endpoint `POST /books`
3. **"Try it out"**
4. Masukkan data buku:
   ```json
   {
     "title": "Clean Code",
     "author": "Robert C. Martin",
     "isbn": "978-0132350884",
     "publishedYear": 2008
   }
   ```
5. Klik **"Execute"**
6. Response: `201 Created` — buku berhasil ditambahkan

**Test DELETE /books/1 sebagai ADMIN:**
1. Login sebagai user dengan role ADMIN
2. Authorize dengan token ADMIN
3. Klik endpoint `DELETE /books/{id}`
4. Masukkan `id`: 1
5. Klik **"Execute"**
6. Response: `200 OK` — buku berhasil dihapus

### Langkah 8: Test Refresh Token Flow

1. Login terlebih dahulu, dapatkan `refreshToken` dari response
2. Klik endpoint `POST /auth/refresh`
3. Klik **"Try it out"**
4. Masukkan refresh token:
   ```json
   {
     "refreshToken": "eyJhbGciOiJIUzI1NiIs..."
   }
   ```
5. Klik **"Execute"**
6. Response: access token dan refresh token baru
7. Perhatikan bahwa token lama sudah tidak valid (refresh token rotation)

### Langkah 9: Verifikasi Keamanan

**Test endpoint setelah logout:**
1. Lakukan logout (POST /auth/logout)
2. Update token di Authorize dengan token baru dari refresh (atau biarkan kosong)
3. Coba akses `GET /auth/me` — harus gagal dengan `401 Unauthorized`

**Test akses tanpa token ke endpoint terproteksi:**
1. Hapus token dari Authorize (klik "Authorize" → "Logout")
2. Coba akses `POST /books` — harus gagal dengan `401 Unauthorized`

### Troubleshooting di Swagger UI

| Masalah | Penyebab | Solusi |
|---------|----------|--------|
| 401 Unauthorized | Token tidak dikirim atau expired | Login ulang dan update token di Authorize |
| 403 Forbidden | Role tidak mencukupi | Login dengan user yang memiliki role sesuai |
| 409 Conflict | Email sudah terdaftar | Gunakan email yang berbeda |
| 500 Internal Server Error | Bug di kode backend | Cek log console NestJS |
| CORS error | Backend tidak mengizinkan origin | Tambahkan `enableCors()` di main.ts |

```typescript
// Di main.ts
async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  app.enableCors(); // Izinkan semua origin
  // ... setup lainnya
}
```

## Analogi

Testing API dari Swagger UI seperti **mencoba langsung semua layanan perpustakaan** dari meja informasi utama:
1. **Register**: Isi formulir pendaftaran anggota baru dan dapatkan kartu perpustakaan
2. **Login**: Tunjukkan kartu identitas dan dapatkan stempel masuk
3. **Authorize**: Tempel stempel di dada Anda agar semua petugas tahu Anda sudah terverifikasi
4. **Cari Buku (GET /books)**: Langsung coba cari buku di rak — tanpa perlu stempel
5. **Tambah Buku (POST /books)**: Coba masuk ke ruang staf — petugas memeriksa stempel Anda, jika bukan pustakawan, ditolak
6. **Hapus Buku (DELETE /books)**: Coba masuk ruang arsip — hanya kepala perpustakaan yang bisa
7. **Refresh**: Stempel mau habis? Dapatkan stempel baru dari meja resepsionis
8. **Logout**: Kembalikan stempel — kartu Anda dinonaktifkan untuk sementara

## Penggunaan

Swagger UI untuk testing digunakan di berbagai skenario: (1) development — menguji endpoint baru sebelum integrasi frontend, (2) debugging — memverifikasi apakah bug di frontend atau backend, (3) QA — regression testing sebelum rilis, (4) onboarding — membantu developer baru memahami API dengan cepat, (5) demo — menunjukkan fungsionalitas API ke stakeholder.

## Kesalahan Umum yang Sering Terjadi

1. **Lupa re-authorize setelah refresh token**: Setelah refresh, token baru harus di-update di dialog Authorize. Token lama tidak lagi valid.
2. **Memasukkan prefix "Bearer " di kolom Authorize**: Swagger otomatis menambahkan "Bearer ". Masukkan hanya token saja.
3. **Tidak mencoba skenario error**: Pastikan untuk menguji tidak hanya sukses, tapi juga error cases (email duplikat, password salah, akses ditolak).
4. **Tidak membersihkan data testing**: Data yang dibuat saat testing akan tersimpan di database. Hapus setelah selesai testing.

## Soal Latihan

**Soal 1:** Urutkan langkah-langkah yang benar untuk menguji endpoint POST /books yang membutuhkan role LIBRARIAN di Swagger UI.

**Jawaban:**
1. Buka Swagger UI di `http://localhost:3000/api`
2. Register user baru melalui `POST /auth/register` (atau login jika sudah punya akun)
3. Update role user menjadi LIBRARIAN via Prisma Studio (`npx prisma studio`)
4. Login dengan user tersebut melalui `POST /auth/login`
5. Salin `accessToken` dari response login
6. Klik tombol "Authorize", paste token, klik "Authorize"
7. Buka endpoint `POST /books` di tag Books
8. Klik "Try it out", masukkan data buku
9. Klik "Execute" — seharusnya response 201 Created

**Soal 2:** Apa yang terjadi jika Anda mencoba mengakses `GET /auth/me` setelah logout tanpa re-login?

**Jawaban:** Anda akan mendapatkan response `401 Unauthorized`. Ini karena setelah logout, refresh token dihapus dari database. Tapi perlu diingat: access token yang sama masih berlaku sampai kedaluwarsa (15 menit) karena JwtAuthGuard hanya memvalidasi token, bukan mengecek logout status. Untuk mencegah akses setelah logout dengan access token yang sama, diperlukan implementasi blacklist atau short-lived access token.

**Soal 3:** Bagaimana cara mengetes endpoint yang membutuhkan query parameter (misalnya `GET /books?search=clean`) di Swagger UI?

**Jawaban:** Di endpoint `GET /books`, klik "Try it out". Di bagian "Parameters", biasanya akan ada field untuk mengisi query parameters jika sudah didefinisikan dengan `@Query()` di controller. Jika belum ada, tambahkan parameter query di controller:

```typescript
@Public()
@Get()
@ApiOperation({ summary: 'Mendapatkan semua buku' })
@ApiQuery({ name: 'search', required: false, description: 'Kata kunci pencarian' })
async findAll(@Query('search') search?: string) {
  if (search) {
    return this.booksService.search(search);
  }
  return this.booksService.findAll();
}
```

Setelah itu, di Swagger UI akan muncul kolom input "search" di bawah parameter.
