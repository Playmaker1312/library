# 37. Membuat Login Endpoint - Verifikasi & Generate JWT Tokens

## Penjelasan

Login adalah endpoint paling kritis dalam sistem autentikasi. Prosesnya dimulai ketika user mengirimkan email dan password. AuthService akan mencari user berdasarkan email di database, memverifikasi apakah password yang dikirim cocok dengan hash yang tersimpan menggunakan `bcrypt.compare()`, dan jika cocok, menghasilkan dua token JWT: **access token** (berumur pendek, biasanya 15 menit) untuk mengakses API yang dilindungi, dan **refresh token** (berumur panjang, biasanya 7 hari) untuk memperpanjang session tanpa login ulang.

Access token dan refresh token menggunakan secret key yang berbeda untuk meningkatkan keamanan. Jika access token bocor, masa berlakunya singkat. Refresh token disimpan di database (di-hash atau plain) sehingga bisa di-invalidasi kapan saja oleh server. Payload JWT biasanya berisi `sub` (subject = user ID), `email`, dan `role` yang akan digunakan untuk otorisasi nanti.

## Fungsi

Login endpoint berfungsi untuk memverifikasi identitas pengguna dan memberikan credential berupa token JWT. Token ini akan digunakan untuk mengakses endpoint-endpoint lain yang membutuhkan autentikasi. Sistem dual-token (access + refresh) memberikan keseimbangan antara keamanan dan kenyamanan pengguna.

**2. Update AuthService — tambahkan method login:**

```typescript
import {
  Injectable,
  ConflictException,
  UnauthorizedException,
} from '@nestjs/common';
import { ConfigType } from '@nestjs/config';
import { JwtService } from '@nestjs/jwt';
import * as bcrypt from 'bcrypt';
import authConfig from './auth.config';
import { UsersService } from '../users/users.service';
import { RegisterDto } from './dto/register.dto';
import { LoginDto } from './dto/login.dto';

@Injectable()
export class AuthService {
  constructor(
    private readonly usersService: UsersService,
    private readonly jwtService: JwtService,
    @Inject(authConfig.KEY)
    private readonly config: ConfigType<typeof authConfig>,
  ) {}

  async register(dto: RegisterDto) {
    const existing = await this.usersService.findByEmail(dto.email);
    if (existing) {
      throw new ConflictException('Email already registered');
    }

    const saltRounds = 12;
    const hashedPassword = await bcrypt.hash(dto.password, saltRounds);

    const user = await this.usersService.create({
      email: dto.email,
      password: hashedPassword,
      name: dto.name,
    });

    const tokens = await this.generateTokens(user.id, user.email, user.role);
    await this.usersService.updateRefreshToken(user.id, tokens.refreshToken);

    return {
      user: {
        id: user.id,
        email: user.email,
        name: user.name,
        role: user.role,
      },
      ...tokens,
    };
  }

  async login(dto: LoginDto) {
    // Cari user berdasarkan email
    const user = await this.usersService.findByEmail(dto.email);
    if (!user) {
      throw new UnauthorizedException('Invalid email or password');
    }

    // Verifikasi password dengan bcrypt
    const isPasswordValid = await bcrypt.compare(
      dto.password,
      user.password,
    );
    if (!isPasswordValid) {
      throw new UnauthorizedException('Invalid email or password');
    }

    // Generate access + refresh token
    const tokens = await this.generateTokens(user.id, user.email, user.role);

    // Simpan refresh token di database
    await this.usersService.updateRefreshToken(user.id, tokens.refreshToken);

    return {
      user: {
        id: user.id,
        email: user.email,
        name: user.name,
        role: user.role,
      },
      ...tokens,
    };
  }

  async generateTokens(userId: number, email: string, role: string) {
    const payload = { sub: userId, email, role };

    const accessToken = this.jwtService.sign(payload, {
      secret: this.config.jwtSecret,
      expiresIn: this.config.jwtExpiresIn,
    });

    const refreshToken = this.jwtService.sign(payload, {
      secret: this.config.jwtRefreshSecret,
      expiresIn: this.config.jwtRefreshExpiresIn,
    });

    return { accessToken, refreshToken };
  }
}
```

**3. Update AuthController:**

```typescript
import { Controller, Post, Body } from '@nestjs/common';
import { AuthService } from './auth.service';
import { RegisterDto } from './dto/register.dto';
import { LoginDto } from './dto/login.dto';

@Controller('auth')
export class AuthController {
  constructor(private readonly authService: AuthService) {}

  @Post('register')
  async register(@Body() dto: RegisterDto) {
    return this.authService.register(dto);
  }

  @Post('login')
  async login(@Body() dto: LoginDto) {
    return this.authService.login(dto);
  }
}
```

## Analogi

Login di perpustakaan seperti **menunjukkan kartu identitas** di pintu masuk. Pengunjung (user) memberikan nama dan menunjukkan KTP (email & password) ke satpam (AuthService). Satpam mengecek apakah namanya ada di daftar anggota (findByEmail) dan apakah KTP-nya asli (bcrypt.compare). Jika cocok, satpam memberikan dua stempel: stempel **akses harian** (access token, berlaku 15 menit) untuk masuk ke ruang baca, dan stempel **anggota** (refresh token, berlaku 7 hari) untuk memperpanjang kunjungan tanpa harus menunjukkan KTP lagi.

## Penggunaan

Login endpoint dipanggil oleh aplikasi frontend (web/mobile) saat pengguna memasukkan email dan password di halaman login. Token yang didapat akan disimpan di localStorage (web) atau secure storage (mobile) dan dikirim sebagai header Authorization untuk setiap request ke API yang membutuhkan autentikasi.

## Kesalahan Umum yang Sering Terjadi

1. **Informasi error yang terlalu spesifik**: Jangan memberitahu user apakah email salah atau password salah. Gunakan pesan umum "Invalid email or password" untuk mencegah attacker mengetahui email mana yang terdaftar.
2. **Lupa menggunakan `await` pada bcrypt.compare**: bcrypt.compare bersifat asynchronous. Tanpa await, hasilnya akan selalu truthy (karena Promise object) dan login akan selalu berhasil.
3. **Menyimpan password di log**: Jangan pernah log payload request login karena bisa menyertakan password.
4. **Token tidak memiliki expiry**: Access token harus memiliki waktu kedaluwarsa yang pendek untuk membatasi kerusakan jika bocor.

## Hubungan dengan Materi Sebelumnya

Login menggunakan metode `generateTokens` yang sudah dibuat di materi 36. UsersService digunakan untuk mencari user dan menyimpan refresh token. Validasi password menggunakan bcrypt yang sudah diinstal di materi 35. Endpoint login akan menjadi dasar untuk refresh token di materi 38 dan logout di materi 39.

## Soal Latihan

**Soal 1:** Apa yang terjadi jika `bcrypt.compare()` mengembalikan `false`? Jelaskan penanganannya.

**Jawaban:** Jika `bcrypt.compare()` mengembalikan `false`, artinya password yang dikirim tidak cocok dengan hash di database. AuthService harus melempar `UnauthorizedException` dengan pesan "Invalid email or password". Ini akan menghasilkan response HTTP 401 Unauthorized yang memberi tahu client bahwa autentikasi gagal.

**Soal 2:** Mengapa kita menggunakan pesan error yang sama untuk email tidak ditemukan dan password salah?

**Jawaban:** Untuk mencegah user enumeration attack. Jika pesan error berbeda (misalnya "Email not found" vs "Wrong password"), attacker bisa mengetahui email mana yang terdaftar di sistem. Dengan pesan yang sama, attacker tidak bisa membedakan apakah emailnya yang salah atau passwordnya.

**Soal 3:** Modifikasi kode login agar user bisa login menggunakan email ATAU username (field `name`).

**Jawaban:**

```typescript
async login(dto: LoginDto) {

  if (!isPasswordValid) {
    throw new UnauthorizedException('Invalid email or password');
  }

  const tokens = await this.generateTokens(user.id, user.email, user.role);
  await this.usersService.updateRefreshToken(user.id, tokens.refreshToken);

      email: user.email,
```
