# 89. Deploy ke VPS - SSH & Docker Pull

## Penjelasan
Setelah Docker image berhasil di-build dan di-push ke GitHub Container Registry (file 88), langkah selanjutnya adalah mendeploy image tersebut ke **VPS (Virtual Private Server)** — server production yang menjalankan aplikasi NestJS. Proses deployment melibatkan: (1) SSH ke VPS menggunakan SSH key yang disimpan sebagai GitHub secret, (2) login ke ghcr.io dengan token, (3) pull image terbaru, (4) restart container dengan docker compose, (5) menjalankan database migration jika ada perubahan schema.

Pendekatan yang digunakan adalah **SSH deploy** — GitHub Actions terhubung ke VPS via SSH dan menjalankan serangkaian perintah shell. Alternatif yang lebih aman adalah menggunakan **self-hosted runner**, tetapi SSH deploy lebih sederhana dan cukup untuk sebagian besar kasus. Penting untuk menyimpan SSH private key dan GitHub Token sebagai **repository secrets** (Settings → Secrets and variables → Actions) agar tidak ter-expose.

## Fungsi
- Mengotomatiskan deployment aplikasi NestJS ke VPS setelah build sukses
- Memastikan container berjalan dengan image terbaru tanpa downtime (zero-downtime deployment)
- Menjalankan database migration otomatis sebagai bagian dari deployment

## Cara Implementasi / Code

**SSH deploy job — tambahkan ke workflow yang sama (file 88):**

```yaml
# .github/workflows/deploy.yml (lanjutan)

jobs:
  # ... test job, build-and-push job ...

  deploy:
    needs: [build-and-push]
    if: github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest

    steps:
      - uses: actions/checkout@v4

      - name: Setup SSH
        uses: webfactory/ssh-agent@v0.9.0
        with:
          ssh-private-key: ${{ secrets.VPS_SSH_KEY }}

      - name: Add VPS to known hosts
        run: |
          ssh-keyscan -H ${{ secrets.VPS_HOST }} >> ~/.ssh/known_hosts

      - name: Deploy to VPS
        run: |
          ssh ${{ secrets.VPS_USER }}@${{ secrets.VPS_HOST }} '
            # Masuk ke direktori project
            cd /opt/nestjs-app

            # Login ke GitHub Container Registry
            echo "${{ secrets.GITHUB_TOKEN }}" | docker login ghcr.io -u ${{ github.actor }} --password-stdin

            # Pull image terbaru
            docker compose pull app

            # Restart service app (tanpa hentikan db/redis)
            docker compose up -d --no-deps --force-recreate app

            # Tunggu health check
            echo "Menunggu health check..."
            for i in {1..30}; do
              if curl -sf http://localhost:3000/api/health > /dev/null 2>&1; then
                echo "Health check sukses!"
                break
              fi
              echo "Menunggu... ($i/30)"
              sleep 2
            done

            # Prune unused images
            docker image prune -f
          '
```

**docker-compose.prod.yml di VPS:**

```yaml
# Di VPS: /opt/nestjs-app/docker-compose.prod.yml
version: "3.8"

services:
  app:
    image: ghcr.io/username/nestjs-app:latest
    container_name: nestjs-app
    restart: unless-stopped
    expose:
      - "3000"
    env_file:
      - .env.production
    depends_on:
      db:
        condition: service_healthy
      redis:
        condition: service_started
    networks:
      - nestjs-network

  nginx:
    image: nginx:alpine
    container_name: nestjs-nginx
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx.conf:/etc/nginx/conf.d/default.conf:ro
      - ./certbot/www:/var/www/certbot:ro
      - ./certbot/conf:/etc/letsencrypt:ro
    depends_on:
      - app
    networks:
      - nestjs-network

  db:
    image: postgres:16-alpine
    container_name: nestjs-db
    restart: unless-stopped
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: ${DB_PASSWORD}
      POSTGRES_DB: nestjs_db
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 10s
      timeout: 5s
      retries: 5
    networks:
      - nestjs-network

  redis:
    image: redis:7-alpine
    container_name: nestjs-redis
    restart: unless-stopped
    networks:
      - nestjs-network

volumes:
  postgres_data:

networks:
  nestjs-network:
    driver: bridge
```

**Deploy dengan migrasi database (opsi terpisah):**

```yaml
- name: Run database migration
  run: |
    ssh ${{ secrets.VPS_USER }}@${{ secrets.VPS_HOST }} '
      cd /opt/nestjs-app
      docker compose exec -T app npx prisma migrate deploy
    '
```

**Setup secrets di GitHub (wajib):**

| Secret Name | Description |
|---|---|
| `VPS_SSH_KEY` | Private key SSH untuk akses ke VPS |
| `VPS_HOST` | IP address atau domain VPS |
| `VPS_USER` | Username SSH (biasanya `root` atau `ubuntu`) |
| `GITHUB_TOKEN` | Otomatis tersedia, tapi perlu `write:packages` |

**Zero-downtime deployment strategy (blue-green):**

```yaml
# Alternatif dengan multiple instance untuk zero-downtime
- name: Blue-green deploy
  run: |
    ssh ${{ secrets.VPS_USER }}@${{ secrets.VPS_HOST }} '
      # Pull image baru
      docker compose pull app

      # Start app dengan container baru (scale up)
      docker compose up -d --no-deps --scale app=2 --no-recreate app

      # Tunggu health check container baru
      sleep 10

      # Hentikan container lama
      docker container stop nestjs-app
      docker container rm nestjs-app

      # Scale down ke 1
      docker compose up -d --no-deps --scale app=1 --no-recreate app
    '
```

## Analogi
Bayangkan perpustakaan menerima **kiriman buku baru** dari gudang pusat (ghcr.io) setiap minggu. Petugas (SSH deploy) mengambil buku-buku baru, mengganti buku lama di rak (restart container), dan memastikan label buku sudah sesuai (health check). Proses ini dilakukan di luar jam buka atau dengan sistem shift agar pengunjung tidak terganggu — jika ada buku yang salah, petugas bisa langsung mengembalikan ke gudang (rollback).

## Penggunaan
Dipakai untuk mendeploy aplikasi NestJS ke VPS production. Workflow ini adalah jembatan terakhir antara kode di GitHub dan aplikasi yang berjalan di server. Setelah deploy, aplikasi bisa diakses publik melalui domain yang sudah dipointing ke VPS.

## Kesalahan Umum yang Sering Terjadi
1. **SSH private key tidak valid** — Key tidak cocok dengan public key di VPS. Generate baru dan update di VPS dan GitHub secrets.
2. **Container crash karena environment variable tidak ada** — File `.env.production` tidak ada di VPS. Pastikan file ini ada dan diisi dengan benar sebelum deployment pertama.
3. **Database migration gagal karena schema tidak cocok** — Migration dijalankan sebelum pull image baru, atau sebaliknya. Urutan yang benar: pull image → migration → restart.
4. **Health check timeout** — Aplikasi butuh waktu lebih lama dari yang diperkirakan untuk start. Perbesar `start-period` di Docker HEALTHCHECK atau timeout di script deploy.
5. **Permission denied pada folder certbot** — Nginx tidak bisa membaca SSL certificate. Pastikan permission folder certbot correct: `chmod 755`.

## Hubungan dengan Materi Sebelumnya
Ini adalah kelanjutan dari file 88 — image yang sudah di-build dan di-push ke registry sekarang dideploy ke VPS. File 90 akan melengkapi dengan SSL certificate untuk Nginx.

## Soal Latihan

**Soal:** Kamu ingin menambahkan **rollback mechanism** di job deploy: jika health check gagal setelah 30 detik, otomatis rollback ke image sebelumnya. Tulis script bash untuk rollback yang menghentikan container baru dan menjalankan container lama.

**Jawaban:**

```bash
# Setelah for loop health check gagal:
if ! curl -sf http://localhost:3000/api/health > /dev/null 2>&1; then
  echo "Health check gagal! Melakukan rollback..."
  
  # Rollback ke image sebelumnya
  docker compose stop app
  docker compose rm -f app
  
  # Pull image sebelumnya (tag sebelumnya disimpan di variable)
  PREVIOUS_TAG=$(docker images --format "{{.Tag}}" ghcr.io/username/nestjs-app | head -2 | tail -1)
  docker compose pull app
  docker compose up -d --no-deps --force-recreate app
  
  # Kirim notifikasi
  curl -s -X POST https://api.telegram.org/bot$TOKEN/sendMessage \
    -d chat_id=$CHAT_ID \
    -d text="🚨 Rollback ke $PREVIOUS_TAG karena health check gagal"
  
  exit 1
fi
```
