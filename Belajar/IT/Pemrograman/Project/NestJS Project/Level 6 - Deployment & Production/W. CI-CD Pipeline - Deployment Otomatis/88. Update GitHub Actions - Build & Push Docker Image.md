# 88. Update GitHub Actions - Build & Push Docker Image

## Penjelasan
GitHub Actions adalah CI/CD platform bawaan GitHub yang memungkinkan kita mengotomatiskan build, test, dan deployment langsung dari repository. Dalam konteks ini, kita akan membuat workflow yang secara otomatis membangun Docker image NestJS dan mendorongnya (push) ke **GitHub Container Registry (ghcr.io)** setiap kali ada commit ke branch `main` atau `develop`. ghcr.io adalah registry container pribadi dari GitHub yang terintegrasi langsung dengan repository — tidak perlu akun Docker Hub terpisah.

Workflow ini terdiri dari beberapa job: **test** (menjalankan unit test dan integration test), **build-and-push** (membangun image multi-platform dan push ke ghcr.io), dan opsional **security-scan** (memindai kerentanan image dengan tools seperti Trivy). Setiap job berjalan di runner Ubuntu yang disediakan GitHub secara gratis. Image yang di-push akan memiliki tag berdasarkan: (1) `latest` untuk branch `main`, (2) `develop` untuk branch `develop`, (3) `v*` untuk Git tag (semantic versioning), dan (4) SHA commit untuk referensi unik.

## Fungsi
- Mengotomatiskan build Docker image setiap kali ada perubahan kode
- Menyimpan image di GitHub Container Registry yang aman dan terintegrasi
- Memberikan traceability — setiap image bisa dilacak ke commit tertentu

## Cara Implementasi / Code

**CI workflow — build-and-push job:**

```yaml
# .github/workflows/deploy.yml
name: CI/CD Pipeline

on:
  push:
    branches: [main, develop]
    tags: ['v*']
  pull_request:
    branches: [main]

env:
  REGISTRY: ghcr.io
  IMAGE_NAME: ${{ github.repository }}

jobs:
  test:
    runs-on: ubuntu-latest
    services:
      postgres:
        image: postgres:16-alpine
        env:
          POSTGRES_USER: postgres
          POSTGRES_PASSWORD: password
          POSTGRES_DB: nestjs_test
        ports:
          - 5432:5432
        options: >-
          --health-cmd pg_isready
          --health-interval 10s
          --health-timeout 5s
          --health-retries 5
      redis:
        image: redis:7-alpine
        ports:
          - 6379:6379

    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Generate Prisma client
        run: npx prisma generate

      - name: Run database migrations
        run: npx prisma migrate deploy
        env:
          DATABASE_URL: postgresql://postgres:password@localhost:5432/nestjs_test

      - name: Run lint
        run: npm run lint

      - name: Run tests
        run: npm run test:e2e
        env:
          DATABASE_URL: postgresql://postgres:password@localhost:5432/nestjs_test
          REDIS_HOST: localhost
          REDIS_PORT: 6379

  build-and-push:
    needs: [test]
    if: github.event_name != 'pull_request'
    runs-on: ubuntu-latest
    permissions:
      contents: read
      packages: write
      attestations: write
      id-token: write

    steps:
      - uses: actions/checkout@v4

      - name: Log in to GitHub Container Registry
        uses: docker/login-action@v3
        with:
          registry: ${{ env.REGISTRY }}
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - name: Extract metadata for Docker
        id: meta
        uses: docker/metadata-action@v5
        with:
          images: ${{ env.REGISTRY }}/${{ env.IMAGE_NAME }}
          tags: |
            type=raw,value=latest,enable=${{ github.ref == 'refs/heads/main' }}
            type=raw,value=develop,enable=${{ github.ref == 'refs/heads/develop' }}
            type=semver,pattern={{version}}
            type=semver,pattern={{major}}.{{minor}}
            type=sha,format=short

      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v3

      - name: Build and push Docker image
        id: push
        uses: docker/build-push-action@v6
        with:
          context: .
          file: ./Dockerfile
          push: true
          tags: ${{ steps.meta.outputs.tags }}
          labels: ${{ steps.meta.outputs.labels }}
          cache-from: type=gha
          cache-to: type=gha,mode=max
          platforms: linux/amd64,linux/arm64

      - name: Generate artifact attestation
        uses: actions/attest-build-provenance@v1
        with:
          subject-name: ${{ env.REGISTRY }}/${{ env.IMAGE_NAME }}
          subject-digest: ${{ steps.push.outputs.digest }}
          push-to-registry: true
```

**Penjelasan detail workflow:**
1. **Trigger:** Workflow berjalan saat push ke `main`/`develop`, push tag `v*`, atau pull request ke `main`.
2. **Job `test`:** Menjalankan Postgres dan Redis sebagai service container, lalu menjalankan lint dan test. Jika test gagal, pipeline berhenti di sini.
3. **Job `build-and-push`:** Bergantung pada `test` (hanya jalan jika test sukses). Login ke ghcr.io menggunakan `GITHUB_TOKEN` (otomatis tersedia), ekstrak metadata tag, lalu build image multi-platform (AMD64 + ARM64) dan push ke registry.
4. **Caching:** Menggunakan GitHub Actions cache (`type=gha`) untuk mempercepat build berikutnya dengan memanfaatkan Docker layer cache.
5. **Attestation:** Membuat bukti provenance bahwa image dibangun dari repository ini (SLSA level 2 compliance).

## Analogi
Bayangkan perpustakaan memiliki **jalur konveyor otomatis** (CI/CD pipeline). Setiap kali penulis mengirimkan naskah buku baru (push kode), konveyor akan: (1) memeriksa ejaan dan tata bahasa (test), (2) menjilid buku (build Docker image), (3) memberi label ISBN dan kategori (tagging), (4) mengirimkan buku jadi ke gudang pusat (push ke ghcr.io). Petugas perpustakaan (developer) tinggal mengambil buku dari gudang untuk dipajang di rak (deploy ke server).

## Penggunaan
Dipakai di setiap proyek NestJS yang akan dideploy ke production. Workflow ini memastikan bahwa setiap kode yang masuk ke branch `main` sudah teruji (lolos test) dan siap dideploy kapan saja — cukup dengan mengambil image terbaru dari ghcr.io.

## Kesalahan Umum yang Sering Terjadi
1. **GITHUB_TOKEN tidak memiliki permission packages:write** — Error 403 saat push ke ghcr.io. Pastikan `permissions: packages: write` diset di workflow.
2. **Cache miss terus-menerus** — Layer cache tidak efektif karena urutan instruksi Dockerfile berubah setiap commit. Patuhi urutan standar (copy package.json dulu, baru source code).
3. **Test tidak menggunakan service container** — Integration test gagal karena database dan Redis tidak tersedia di runner GitHub.
4. **Tag image tidak sesuai** — Image `latest` di-push meskipun dari branch feature. Gunakan kondisi `enable` pada metadata-action untuk mengontrol tag.
5. **Image tidak kompatibel dengan arsitektur server** — Jika server ARM64 (misal AWS Graviton), image harus di-build untuk platform `linux/arm64`.

## Hubungan dengan Materi Sebelumnya
Workflow ini menggunakan Dockerfile dari file 81 untuk membangun image. Setelah image siap di ghcr.io, file 89 akan mengambil image tersebut dan mendeploy ke VPS. File 90 akan menambahkan SSL certificate.

## Soal Latihan

**Soal:** Kamu ingin workflow di atas juga menjalankan **security scan** menggunakan Trivy pada image setelah build. Tambahkan step Trivy scan setelah build yang memeriksa kerentanan HIGH dan CRITICAL, lalu fail jika ditemukan.

**Jawaban:**

```yaml
- name: Run Trivy vulnerability scanner
  uses: aquasecurity/trivy-action@master
  with:
    image-ref: ${{ env.REGISTRY }}/${{ env.IMAGE_NAME }}:${{ steps.meta.outputs.version }}
    format: sarif
    output: trivy-results.sarif
    severity: HIGH,CRITICAL
    exit-code: 1

- name: Upload Trivy results to GitHub Security
  uses: github/codeql-action/upload-sarif@v3
  with:
    sarif_file: trivy-results.sarif
```
