# Form dan Input — Interaksi dengan Pengguna

Form adalah jembatan antara pengguna dan aplikasi: user mengisi data, halaman menerimanya. Materi ini adalah penutup Level 1 — seluruh elemen sebelumnya (heading, list, link, gambar, struktur semantik) dipakai untuk membangun satu halaman pendaftaran anggota yang lengkap, dan menjadi titik sambung menuju JavaScript di Level 4 (validasi lanjutan) dan backend.

## 1. Penjelasan Singkat & Konsep Dasar

Sejauh ini semua konten yang kita tulis adalah "satu arah": halaman menampilkan, user membaca. Form mengubah arah itu sendiri menjadi "dua arah" — user **memberi input**, dan halaman **menerima input untuk diproses**. Form HTML adalah kesepakatan: cara meminta data dengan cara yang terstruktur sehingga user dan mesin (dan aksesibilitas) saling paham.

Kerangka dasar form:

```html
<form action="/daftar" method="POST">
    <!-- field input di sini -->
    <button type="submit">Kirim</button>
</form>
```

- **`action`** — ke mana data dikirim (alamat di server/backend). Saat belum ada backend, tulis `action="#"` sebagai placeholder.
- **`method`** — bagaimana dikirim: `GET` (data tampil di URL, cocok untuk pencarian) atau `POST` (data di badan request, cocok untuk data rahasia/lengkap seperti pendaftaran). Detail lengkapnya dipelajari di Level 6 (Fetch API).
- **`novalidate`** — menonaktifkan validasi bawaan browser; dipakai bila validasi ditangani JavaScript atau di sisi server supaya pesan errornya seragam.

Setiap field input harus punya **`label` yang terhubung**. Hubungannya melalui atribut `for` pada `label` dan `id` pada `input` — wajib sama persis. Ini bukan formalitas: label adalah target klik (klik teks → fokus ke input) dan nama yang dibacakan screen reader.

Tipe `input` yang dipelajari: `text` (teks bebas), `email` (otomatis cek format email), `tel` (format telepon tanpa memaksa, cocok dengan `pattern`), `date` (picker tanggal). Kelengkapan atribut: `placeholder` (contoh teks — bukan pengganti label!), `required` (wajib diisi), `pattern` (pola regex), `autocomplete` (minta browser isi otomatis). Selain `input` tunggal ada juga `select` (dropdown pilihan), `textarea` (teks multi-baris dengan `rows`/`cols`/`maxlength`), serta grup `radio` (pilih satu) dan `checkbox` (pilih banyak). Kelompok field yang berhubungan dibungkus `fieldset` + `legend` (legend = judul kelompok, dibacakan screen reader).

Benang merah: form berdiri di atas semua materi sebelumnya — butuh struktur semantik (`section`, `fieldset`) dari materi 7, kadang list dari materi 5, dan teks dari materi 4. Di Level 2, form ini akan digaya CSS; di Level 4+, peristiwa `submit` dan `input` menjadi pintu masuk JavaScript pertama.

## 2. Fungsi & Kegunaan Utama dalam Web

Tanpa form, web hanyalah papan pengumuman — tidak ada cara "mendaftar", "login", "mencari", "memesan". Form adalah titik masuk data dari dunia nyata ke aplikasi:

- **Mengumpulkan data terstruktur**: pendaftaran, pencarian katalog, pesan kontak, keluhan. Data yang seragam formatnya mudah diproses server.
- **Validasi dibandingkan dengan label**: browser memberi validasi gratis (`required`, `email`, `pattern`, `min`/`max`) — input salah tidak terkirim, user dapat umpan balik tanpa menulis satu baris JavaScript.
- **Aksesibilitas**: `label` + `for`/`id` membuat tiap field dikenali program pembaca layar; `fieldset`/`legend` mengelompokkan secara bermakna. Form yang inaccessible membuat sebagian pengguna tidak bisa mendaftar sama sekali.
- **Router data**: `autocomplete` menghemat waktu (browser menyarankan nama, email, dll). `type` yang benar (email/date/tel) menampilkan keypad yang sesuai di perangkat seluler — misal keypad angka untuk `tel`.
- **Minimalkan kesalahan**: `placeholder` memberi contoh pengisian tanpa menyembunyikan label; `maxlength` membatasi teks; radio dengan `name` sama memaksa hanya satu pilihan.

Untuk **Perpustakaan Digital Kota**, form adalah gerbang utama: halaman keanggotaan (pendaftaran nama, email, telepon, tanggal lahir, kategori favorit, jenis keanggotaan, notifikasi), halaman pencarian katalog, dan halaman kontak. Tanpa form ini, "anggota" tidak pernah ada.

## 3. Contoh Kode & Implementasi Real-World

```html
<!-- Form pendaftaran anggota perpustakaan -->
<!-- action="#" karena backend belum ada (Level 6) -->
<!-- method POST karena data pendaftaran bersifat lengkap/privasi -->
<!-- novalidate hanya bila validasi dipegang JS. Di contoh ini TIDAK dipakai,
     agar browser memberi validasi bawaan secara gratis -->
<form action="#" method="POST">

    <!-- fieldset: kelompok field yang saling terkait -->
    <!-- legend: judul kelompok, dibacakan screen reader sebagai konteks -->
    <fieldset>
        <legend>Informasi Pribadi</legend>

        <!-- label WAJIB + for harus sama dgn id input -->
        <div class="form-group">
            <label for="nama-lengkap">Nama Lengkap *</label>
            <input
                type="text"
                id="nama-lengkap"
                name="nama"
                placeholder="Contoh: Budi Santoso"
                required
                autocomplete="name"
            >
        </div>

        <div class="form-group">
            <label for="email">Alamat Email *</label>
            <input
                type="email"
                id="email"
                name="email"
                placeholder="budi@email.com"
                required
                autocomplete="email"
            >
        </div>

        <div class="form-group">
            <label for="telepon">Nomor Telepon (opsional)</label>
            <input
                type="tel"
                id="telepon"
                name="telepon"
                placeholder="08123456789"
                pattern="[0-9]{10,13}"
                autocomplete="tel"
            >
            <!-- pattern regex: 10-13 digit angka saja.
                 type=tel menampilkan keypad numerik di HP -->
        </div>

        <div class="form-group">
            <label for="tanggal-lahir">Tanggal Lahir *</label>
            <input
                type="date"
                id="tanggal-lahir"
                name="tanggal_lahir"
                required
            >
        </div>
    </fieldset>

    <fieldset>
        <legend>Preferensi Buku</legend>

        <!-- Select dropdown: pilih satu dari daftar -->
        <div class="form-group">
            <label for="kategori-favorit">Kategori Favorit</label>
            <select id="kategori-favorit" name="kategori">
                <!-- option pertama dipakai sebagai opsi "belum memilih" -->
                <option value="">-- Pilih Kategori --</option>
                <option value="fiksi">Fiksi</option>
                <option value="non-fiksi">Non-Fiksi</option>
                <option value="sains">Sains &amp; Teknologi</option>
                <option value="sejarah">Sejarah</option>
                <option value="biografi">Biografi</option>
            </select>
        </div>

        <!-- Radio: PILIH SATU. Semua radio satu grup WAJIB name yang SAMA,
             jika berbeda name maka bisa terpilih semua (bug klasik) -->
        <div class="form-group">
            <p>Jenis Keanggotaan *</p>
            <label>
                <input type="radio" name="jenis-anggota" value="reguler" checked>
                Reguler (gratis)
            </label>
            <label>
                <input type="radio" name="jenis-anggota" value="premium">
                Premium (Rp 50.000/tahun)
            </label>
        </div>

        <!-- Checkbox: PILIH BANYAK. name sama menandakan "grup" berbeda dgn radio -->
        <div class="form-group">
            <p>Notifikasi yang diinginkan:</p>
            <label>
                <input type="checkbox" name="notif" value="buku-baru">
                Buku baru tersedia
            </label>
            <label>
                <input type="checkbox" name="notif" value="jatuh-tempo">
                Pengingat jatuh tempo
            </label>
            <label>
                <input type="checkbox" name="notif" value="promo">
                Promosi dan event
            </label>
        </div>
    </fieldset>

    <fieldset>
        <legend>Pesan Tambahan</legend>

        <!-- textarea: teks panjang / multi-baris -->
        <!-- rows=tinggi awal, cols=lebar awal (bisa diganti CSS),
             maxlength=maksimal karakter -->
        <div class="form-group">
            <label for="pesan">Pertanyaan atau Pesan (opsional)</label>
            <textarea
                id="pesan"
                name="pesan"
                rows="5"
                cols="50"
                maxlength="500"
                placeholder="Tulis pertanyaan atau permintaan khusus di sini..."
            ></textarea>
        </div>
    </fieldset>

    <!-- Tombol aksi: submit = kirim, reset = kosongkan form -->
    <button type="submit">Daftar Sekarang</button>
    <button type="reset">Reset Form</button>

</form>
```

**Catatan placeholder:** `placeholder` hanya contoh format, **bukan pengganti `label`** — saat form berisi text, placeholder hilang sehingga user kehilangan panduan. Label tetap wajib.

## 4. Analogi Sederhana — Membangun Rumah

Form adalah **formulir pendaftaran di pintu masuk perpustakaan** — namun dengan kolom yang terstandar (sanksi dari konvensi HTML):

- **`form`** = papan registrasi di meja depan. `action` = alamat kantor tujuan formulir diserahkan. `method` = cara pengantaran (di kantong atau di amplop tertutup).
- **`fieldset` + `legend`** = map/amplop biru yang memisahkan "Data Diri" dan "Preferensi", dengan label mapnya tertulis di atas.
- **`label for`** = **kode gantungan nama di setiap kolom** — gayung dan gantungannya dipasangkan, jadi petugas tahu kolom ini "Nama Lengkap", "Email", dst.
- **`input type="email"`** = kolom yang otomatis menolak tulisan yang bukan format email sebelum diserahkan ke server.
- **`required`** = garis merah "wajib diisi" — formulir tidak diterima bila kosong.
- **`pattern`** = aturan format ketat, misal nomor telepon harus 10-13 angka.
- **`select`** = kotak pilihan yang sudah tercetak opsi; **`radio`** = pilih satu dari beberapa tombol pilihan (tombol yang ditekan membatalkan yang lain); **`checkbox`** = centang sebanyak yang kamu mau.
- **`button submit/reset`** = "Serahkan" vs "Buang dan isi ulang".

Semua aturan ini bikin pengunjung (user) dan petugas (aplikasi/server) tidak salah paham — itulah inti dari sebuah form yang baik.

## 5. Kapan Harus Digunakan & Kasus Penggunaan (Use Cases)

1. **Formulir pendaftaran anggota** — kombinasi lengkap: `text`, `email`, `tel` (dengan `pattern`), `date`, `select`, radio, checkbox, `textarea`; wajib `fieldset` grup "Data Diri" vs "Preferensi".
2. **Form pencarian katalog** — `input type="search"` di dalam `<form action="/cari" method="GET">` (data pencarian boleh tampil di URL sehingga bisa di-bookmark).
3. **Form kontak** — nama, email, subjek (`select`), dan `textarea` pesan dengan `maxlength`; `autocomplete="email"` memudahkan pengulangan.
4. **Form login / permintaan buku** — validasi `required` + sertakan `novalidate` bila validasi dipegang JavaScript (Level 4) agar pesan error seragam.
5. **Kuisioner / survei kepuasan** — radio "puas/cukup/kurang" (`name` sama), checkbox multi-pilihan topik, `select` umur.

## 6. Poin-poin Penting & Best Practices

- **Setiap `input`/`select`/`textarea` wajib punya `label` terhubung** via `for` = `id`. Ini aturannya, bukan saran; validasi aksesibilitas akan menganggapnya sebagai error.
- **Gunakan `type` yang paling spesifik**: `email`, `tel`, `date` — dapat keyboard spesifik di HP dan validasi gratis di browser.
- **`name` harus unik antar field** untuk data yang benar; dan radio dalam satu grup **wajib `name` yang sama** agar saling men-exclude, checkbox yang sama `name` menandakan satu "kelompok pilihan".
- **`placeholder` jangan mengganti `label`** — ia panduan saat kosong; label adalah identitas permanen.
- **`required` vs `pattern`**: `required` memaksa field terisi; `pattern` memaksa format. Untuk nomor telpon gunakan keduanya bila wajib.
- **`autocomplete`** dibutuhkan terutama `name`, `email`, `tel` — untuk gelandangan isi otomatis browser (misal saat ingin mendaftar ulang di bulan berikutnya).
- **`fieldset` + `legend`** untuk kelompok (informasi pribadi, preferensi, dsb.). Ini konteks yang dibacakan screen reader.
- **`novalidate`** hanya ketika kamu menangani validasi sendiri (JavaScript). Kalau tidak, biarkan validasi bawaan bekerja — gratis dan konsisten.
- Tombol submit harus `type="submit"`, tombol reset `type="reset"` — `button` tanpa type didalam form secara default berperilaku submit (sumber kebingungan umum).

## 7. Kesalahan Umum (Common Pitfalls & Bugs)

1. **Input tanpa `label` (atau label tidak terhubung `for`/`id`).** Akibat: screen reader tidak bisa memberi nama field, klik pada teks tidak memfokuskan input. Perbaikan: tulis `<label for="nama-lengkap">` + `<input id="nama-lengkap">`.
2. **Radio tidak saling men-exclude karena `name` berbeda.** User bisa mencentang "Reguler" dan "Premium" sekaligus padahal seharusnya hanya satu. Perbaikan: semua radio satu grup harus `name` yang **sama persis**.
3. **`placeholder` dipakai sebagai pengganti label.** Saat user mengetik, contoh teks hilang dan konteks field pun hilang. Perbaikan: tetap sertakan `label`; `placeholder` hanya contoh format.
4. **`pattern` yang keliru / tidak disertai label jelas**, misal `pattern="[0-9]{10,13}"` tapi tidak menjelaskan "diisi 10-13 angka". Perbaikan: beri keterangan bantu, misal `title="10-13 digit angka"`, sekaligus di teks label.
5. **`novalidate` ditulis tanpa alasan** — semua validasi mati padahal tidak ada JS/server. Perbaikan: hapus `novalidate` selama belum ada penangan validasi kustom.
6. **Tombol tanpa `type` di dalam form.** Defaultnya `type="submit"` sehingga tombol "Reset" yang lupa type justru mengirim form. Perbaikan: selalu eksplisit `type="submit"` atau `type="reset"`.

## 8. Mini Project / Soal Latihan & Kunci Jawaban

**Tantangan:** Buat **formulir pendaftaran anggota Perpustakaan Digital Kota** yang lengkap: field pribadi (nama, email, telepon wajib format, tanggal lahir), grup preferensi memakai `fieldset`, `select` kategori, radio "jenis keanggotaan", checkbox notifikasi, `textarea` pesan, dan dua tombol (submit/ reset). Gunakan validasi bawaan (`required`, `pattern`, `autocomplete`).

**Kunci Jawaban & Pembahasan:**

```html
<!DOCTYPE html>
<html lang="id">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Pendaftaran Anggota — Perpustakaan Digital Kota</title>
</head>
<body>

    <header>
        <nav aria-label="Navigasi Utama">
            <ul>
                <li><a href="index.html">Beranda</a></li>
                <li><a href="katalog.html">Katalog</a></li>
                <li><a href="anggota.html">Keanggotaan</a></li>
            </ul>
        </nav>
        <h1>Daftar Sebagai Anggota</h1>
        <p>Gratis dan langsung aktif setelah data terverifikasi.</p>
    </header>

    <main>
        <!-- form utama. action="#" = backend belum ada (Level 6) -->
        <form action="#" method="POST">

            <fieldset>
                <legend>1. Data Pribadi</legend>

                <div class="form-group">
                    <label for="nama-lengkap">Nama Lengkap *</label>
                    <input
                        type="text"
                        id="nama-lengkap"
                        name="nama"
                        placeholder="Contoh: Budi Santoso"
                        required
                        autocomplete="name"
                    >
                </div>

                <div class="form-group">
                    <label for="email">Email *</label>
                    <input
                        type="email"
                        id="email"
                        name="email"
                        placeholder="budi@email.com"
                        required
                        autocomplete="email"
                    >
                </div>

                <div class="form-group">
                    <label for="telepon">Telepon *</label>
                    <input
                        type="tel"
                        id="telepon"
                        name="telepon"
                        placeholder="08123456789"
                        pattern="[0-9]{10,13}"
                        title="10-13 digit angka, tanpa spasi atau tanda minus"
                        required
                        autocomplete="tel"
                    >
                </div>

                <div class="form-group">
                    <label for="tanggal-lahir">Tanggal Lahir *</label>
                    <input type="date" id="tanggal-lahir" name="tanggal_lahir" required>
                </div>
            </fieldset>

            <fieldset>
                <legend>2. Preferensi Anggota</legend>

                <div class="form-group">
                    <label for="kategori">Kategori Favorit *</label>
                    <select id="kategori" name="kategori" required>
                        <option value="">-- Pilih kategori --</option>
                        <option value="fiksi">Fiksi</option>
                        <option value="non-fiksi">Non-Fiksi</option>
                        <option value="sains">Sains &amp; Teknologi</option>
                        <option value="sejarah">Sejarah</option>
                    </select>
                </div>

                <!-- Radio satu grup: name SAMA -->
                <div class="form-group">
                    <p>Jenis Keanggotaan *</p>
                    <label>
                        <input type="radio" name="jenis-anggota" value="reguler" checked>
                        Reguler (gratis)
                    </label>
                    <label>
                        <input type="radio" name="jenis-anggota" value="premium">
                        Premium (Rp 50.000/tahun)
                    </label>
                </div>

                <!-- Checkbox boleh banyak -->
                <div class="form-group">
                    <p>Notifikasi:</p>
                    <label><input type="checkbox" name="notif" value="buku-baru"> Buku baru baru rilis</label>
                    <label><input type="checkbox" name="notif" value="jatuh-tempo"> Pengingat pengembalian</label>
                </div>
            </fieldset>

            <fieldset>
                <legend>3. Pesan Tambahan</legend>
                <div class="form-group">
                    <label for="pesan">Catatan atau permintaan khusus (opsional)</label>
                    <textarea id="pesan" name="pesan" rows="5" cols="50"
                              maxlength="500"
                              placeholder="Misal: butuh buku braille, atau penjemputan buku..."></textarea>
                </div>
            </fieldset>

            <button type="submit">Daftar Sekarang</button>
            <button type="reset">Reset Form</button>
        </form>
    </main>

    <footer>
        <p>&copy; 2024 Perpustakaan Digital Kota. Hak cipta dilindungi.</p>
        <address>
            Jl. Merdeka No. 1, Kota Bandung |
            <a href="mailto:info@perpustakaan.id">info@perpustakaan.id</a>
        </address>
    </footer>

</body>
</html>
```

**Pembahasan:** Setiap field punya `label` yang terhubung `for`/`id`. `method="POST"` karena ini data pribadi lengkap; `action="#"` sebagai penanda backend belum ada. Radios memakai `name="jenis-anggota"` yang sama sehingga hanya satu yang terpilih. `pattern="[0-9]{10,13}"` + `title` menjelaskan format jika pola gagal — screen reader juga membacakan `title`. Validasi `required` dibiarkan bekerja (tanpa `novalidate`) agar browser memberi penangan error gratis. Latihan lanjutan: tambahkan field `input type="number"` untuk "jumlah buku yang biasa dipinjam per bulan", lalu validasi hasilnya di validator.w3.org hingga 0 error — maka Level 1 selesai dan kamu siap menatap CSS di Level 2.
