# 27. Membuat dan Menghapus Elemen — CRUD di DOM

Materi ini mengajarkan siklus penuh "hidup" sebuah elemen: membuat dengan `document.createElement`, mengisinya, menyisipkannya ke DOM dengan `append`/`prepend`/`insertBefore` (atau `appendChild`), merender banyak elemen secara efisien dengan `DocumentFragment`, lalu menghapusnya dengan `remove`/`removeChild`. Inilah jantung katalog dinamis.

## 1. Penjelasan Singkat & Konsep Dasar

Di materi 25 kamu menemukan elemen yang sudah ada, dan di materi 26 kamu mengubah isi serta tampilannya. Namun katalog buku tidak akan pernah lengkap kalau halamannya hanya berisi elemen yang ditulis tangan di HTML. Jumlah buku terus berubah: ada buku baru ditambahkan, ada yang dihapus, dan halaman harus mengikuti tanpa reload. Itulah urusan materi ini: **menciptakan** elemen dan **menghapusnya** — operasi "C" (Create) dan "D" (Delete) dalam istilah **CRUD** (Create, Read, Update, Delete), di mana R dan U sudah kamu pelajari di materi 26.

Cara paling dasar membuat elemen adalah `document.createElement("article")`. Penting dipahami: sampai kamu **menyisipkannya ke DOM**, elemen itu hanyalah objek di memori — tidak terlihat di layar, tidak berada dalam pohon dokumen. Setelah dibuat, kamu isi dengan `className`, `dataset`, lalu `textContent`/`append` untuk anak-anaknya, dan baru disisipkan ke wadah dengan `appendChild(elemen)`, `prepend(elemen)`, atau `insertBefore(elemen, acuan)`.

Ada dua pendekatan besar dalam membuat elemen. Pertama, **imperatif**: `createElement` + properti + `append` — aman, eksplisit, dan tanpa parsing string. Kedua, **template string + `innerHTML`**: lebih ringkas untuk struktur yang rumit, tetapi hanya boleh dipakai untuk template yang **kamu kontrol sendiri**, bukan untuk data user (ingat materi 26: XSS). Pada praktiknya, developer sering menggabungkan: kerangka HTML lewat template string, sedangkan setiap nilai yang berasal dari user/API dimasukkan lewat `textContent` atau disetelah dulu sebelum disisipkan.

Untuk memasukkan elemen, `append` lebih modern: menerima beberapa argumen sekaligus (`container.append(a, b, c)`), bisa menerima string, dan tidak mengembalikan nilai. `appendChild` hanya menerima satu node, mengembalikan node itu (berguna untuk rantaian operasi), dan lebih "tua". `prepend` meletakkan di posisi paling atas anak; `insertBefore` membutuhkan elemen acuan. Untuk **menghapus**, `elemen.remove()` adalah cara modern dan mudah; `parent.removeChild(elemen)` lebih eksplisit tapi memerlukan referensi parent.

Masalah performa pun menjadi perhatian. Jika kamu menambahkan 100 kartu dengan `appendChild` satu per satu di dalam loop, browser menghitung ulang layout berkali-kali. Solusinya **`DocumentFragment`**: wadah di memori yang bisa diisi banyak elemen lalu disisipkan **satu kali** ke DOM — browser hanya perlu satu kali update layout. Pola ini penting untuk render katalog yang besar.

**Benang merah**: materi 25 menemukan, materi 26 mengubah; materi 27 membuat dunia dari nol. Seluruh logika data Level 4 (array `katalog`, `map`, `filter`) kini benar-benar "menjadi" tampilan: satu array → sekumpulan kartu di layar, dan perubahan data → render ulang. Materi 28 kemudian mengikat semua ini ke aksi user.

## 2. Fungsi & Kegunaan Utama dalam Web

Fitur paling jelas di **Perpustakaan Digital Kota** adalah **katalog dinamis**: array `katalog` yang berisi objek buku di-render menjadi deretan kartu buku lewat `createElement`/`innerHTML`. Ketika user menambahkan buku lewat form, objek baru masuk ke array lalu halaman di-render ulang (atau satu kartu dibuat dan disisipkan) — tanpa memuat ulang. Ketika user menghapus buku, kartu terkait dihapus dari DOM dan objeknya dihapus dari array; tampilan dan data selalu sinkron.

Konteks lain yang sama penting: **modal dan notifikasi** dibuat secara dinamis. Pesan notifikasi "Buku berhasil dipinjam" adalah elemen `div` yang dibuat dengan `createElement`, diisi `textContent`, disisipkan ke wadah notifikasi, lalu dihapus setelah beberapa detik. `DocumentFragment` berguna saat merender ulang seluruh grid katalog: hasil filter digabung dalam satu fragment lalu disisipkan sekaligus — cepat dan tidak berkedip saat user mengetik di pencarian.

Halaman juga memakai elemen penghapus untuk UX: saat kategori diubah, grid lama dihapus dan diganti grid baru; saat modal ditutup, konten lama dibersihkan agar tidak bertumpuk. Semua ini menekankan satu prinsip: **data adalah kebenaran, DOM adalah proyeksinya**. Ketika data berubah, DOM diperbarui untuk menyesuaikan — bukan sebaliknya.

```javascript
// js/main.js

// ─── Data "kebenaran" aplikasi: array buku (logika dari Level 4) ──────────
let katalog = [
    { id: 1, judul: "Clean Code",       stok: 3 },
    { id: 2, judul: "Laskar Pelangi",   stok: 0 },
    { id: 3, judul: "Cosmos",           stok: 5 },
];

const kontainerKatalog = document.querySelector("#katalog-grid");
const infoHasil        = document.querySelector("#info-hasil");

// ─── 1. Membuat SATU kartu: createElement + className + dataset + textContent ──
function buatKartuBuku(buku) {
    const kartu = document.createElement("article");
    kartu.className = "kartu-buku";
    kartu.dataset.id = buku.id;               // identitas untuk event (materi 28)

    // textContent untuk data dari array (aman — data "user/API")
    const judul = document.createElement("h3");
    judul.textContent = buku.judul;

    const badge = document.createElement("span");
    badge.className = `badge ${buku.stok > 0 ? "baik" : "habis"}`;
    badge.textContent = buku.stok > 0 ? `Stok: ${buku.stok}` : "Habis";

    const tombol = document.createElement("button");
    tombol.className = "btn-hapus";
    tombol.textContent = "Hapus";
    tombol.dataset.id = buku.id;              // tombol tahu buku mana yang dituju

    kartu.append(judul, badge, tombol);       // append bisa banyak argumen sekaligus
    return kartu;
}

// ─── 2. Alternatif template string + innerHTML (hanya untuk template sendiri) ──
// Jika struktur rumit, boleh dipakai asal TIDAK ada data user di dalamnya.
// Perhatikan: judul dikirim lewat textContent di helper di atas, jadi aman.
function buatKartuBukuTemplate(buku) {
    // HATI-HATI: jangan menulis `${buku.judul}` langsung di sini untuk data user.
    const kartu = document.createElement("article");
    kartu.className = "kartu-buku";
    kartu.innerHTML = `
        <h3 class="judul-js"></h3>
        <span class="badge"></span>
        <button class="btn-hapus">Hapus</button>
    `;
    // Nilai dinamis dimasukkan lewat textContent — aman dari XSS
    kartu.querySelector(".judul-js").textContent = buku.judul;
    const badge = kartu.querySelector(".badge");
    badge.className = `badge ${buku.stok > 0 ? "baik" : "habis"}`;
    badge.textContent = buku.stok > 0 ? `Stok: ${buku.stok}` : "Habis";
    kartu.querySelector(".btn-hapus").dataset.id = buku.id;
    return kartu;
}

// ─── 3. Render banyak kartu: DocumentFragment → satu insert ──────────────
function renderKatalog() {
    // Kosongkan dulu (hapus kartu lama)
    kontainerKatalog.innerHTML = "";

    if (katalog.length === 0) {
        const pesan = document.createElement("p");
        pesan.className = "pesan-kosong";
        pesan.textContent = "Tidak ada buku. Tambahkan buku baru di atas.";
        kontainerKatalog.appendChild(pesan);
        infoHasil.textContent = "0 buku dalam katalog.";
        return;
    }

    // DocumentFragment: kumpulkan semua kartu di memori…
    const fragment = document.createDocumentFragment();
    katalog.forEach(buku => fragment.appendChild(buatKartuBuku(buku)));

    // …lalu sisipkan SEKALI. Browser hanya melakukan satu update layout.
    kontainerKatalog.appendChild(fragment);
    infoHasil.textContent = `${katalog.length} buku dalam katalog.`;
}

// ─── 4. CRUD: tambah dan hapus → update data + render ulang ──────────────
function tambahBuku(judul, stok) {
    const bukuBaru = {
        id: Date.now(),            // id unik sederhana (timestamp)
        judul: judul,
        stok: Number(stok) || 0,
    };
    katalog.push(bukuBaru);        // update data dulu
    renderKatalog();               // baru render ulang
    return bukuBaru;
}

function hapusBuku(id) {
    // Hapus dari array data (filter: Level 4)
    katalog = katalog.filter(buku => buku.id !== id);

    // Hapus dari DOM: dua cara setara
    // Cara 1 (modern): elemen.remove()
    const kartuLama = document.querySelector(`[data-id="${id}"]`);
    if (kartuLama) kartuLama.remove();

    // Cara 2 (lama): parent.removeChild(elemen) — butuh parent
    // const induk = kartuLama.parentElement;
    // induk.removeChild(kartuLama);

    renderKatalog(); // tetap dipanggil agar info & layout konsisten
}

// ─── 5. Event listener (detail di materi 28) ─────────────────────────────
// Event delegation dipakai karena tombol hapus dibuat DINAMIS
kontainerKatalog.addEventListener("click", (event) => {
    const tombolHapus = event.target.closest(".btn-hapus");
    if (tombolHapus) {
        hapusBuku(Number(tombolHapus.dataset.id));
    }
});

document.querySelector("#form-tambah").addEventListener("submit", (event) => {
    event.preventDefault();  // jangan reload halaman
    const inputJudul = document.querySelector("#input-judul");
    const inputStok  = document.querySelector("#input-stok");

    const judul = inputJudul.value.trim();
    if (!judul) return;                    // input kosong tidak usah diproses

    tambahBuku(judul, inputStok.value);
    event.target.reset();                  // kosongkan form
    inputJudul.focus();                    // kembalikan fokus untuk mengetik lagi
});

// Mulai: render katalog pertama kali
renderKatalog();
```

## 4. Analogi Sederhana — Membangun Rumah

Di rumah analogi kita, **HTML** adalah kerangka dan tata ruang, **CSS** adalah cat dan dekorasi, dan **JavaScript** adalah instalasi listriknya. Membuat elemen di DOM paling cocok dianalogikan sebagai **memasang terminal lampu baru untuk ruangan baru**. Kamu tidak melubangi dinding asal-asalan — kamu pasang titik terminal (`document.createElement`), rangkai kabelnya ke titik-titik yang sudah ada (menyisipkan ke DOM dengan `append`), beri saklarnya (`dataset`, `classList`), dan begitu kabelnya tersambung, ruangan itu "hidup". Sebelum disambung, terminal itu hanyalah komponen di gudang: ada, tapi tidak memengaruhi rumah sama sekali. Itulah mengapa elemen harus **disisipkan ke DOM** untuk benar-benar muncul.

`innerHTML` dengan template string diibaratkan **menempelkan pemasangan kabel secara utuh sekaligus**: satu lembar kerja berisi semua kabel dan sambungan dalam satu tindakan — cepat dan rapi untuk susunan yang kamu gambar sendiri. Bahayanya muncul begitu "kabel dari luar" (konten user/API) ikut ditempelkan ke lembar itu tanpa isolasi. Sebuah kabel liar yang memuat perintah "cabut semua kabel" akan dieksekusi rumah itu, persis seperti skrip jahat dalam `innerHTML`. Itulah kenapa untuk bagian data yang tidak kamu kendalikan, kamu harus memasangnya lewat `textContent` — menempel tulisan polos, tanpa perintah apa pun.

`DocumentFragment` adalah **meja kerja sebelum pemasangan**: kamu menyusun semua terminal di atas meja lebih dulu, merapikannya, baru menempelkan semuanya ke dinding dalam satu gerakan. Tanpa meja kerja, setiap lampu baru dipasang satu-satu, dan setiap kali kamu menyentuh dinding seluruh rumah ikut berguncang (layout dihitung ulang terus). Dengan meja kerja, dinding hanya disentuh sekali — itulah sebabnya render katalog yang besar terasa jauh lebih halus.

Sedangkan menghapus elemen (`remove`) adalah **mencabut terminal dari dinding**: satu tarikan bersih — kabelnya terlepas, ruangannya gelap, dan semua referensi terhadapnya tak lagi berguna. `removeChild` pada dasarnya perintah yang sama, tapi kamu harus menyebutkan dinding mana yang dimaksud (parent) sebelum mencabutnya.

## 5. Kapan Harus Digunakan & Kasus Penggunaan (Use Cases)

- **Render daftar dari array** — katalog buku diubah menjadi kartu grid dengan `forEach` + `appendChild`, disisipkan lewat `DocumentFragment` untuk performa.
- **Tambah data lewat form** — submit form (materi 28) memanggil fungsi yang membuat satu kartu baru dan menambah objek ke array, lalu render ulang.
- **Hapus item dinamis** — tombol "Hapus" pada setiap kartu memanggil `kartu.remove()` dan menyaring array agar data sinkron dengan tampilan.
- **Render ulang hasil filter/pencarian** — grid lama dihapus (`innerHTML = ""`), hasil baru dibangun dalam fragment, dan disisipkan — pola yang sama untuk setiap perubahan filter.
- **Notifikasi & pesan sementara** — elemen dibuat saat event terjadi, dimasukkan ke container, lalu dihapus dengan `remove()` setelah beberapa detik.

## 6. Poin-poin Penting & Best Practices

- Selalu **update data (array/state) dan DOM secara konsisten** — jangan hapus kartu dari DOM tapi meninggalkan objek di array, atau sebaliknya.
- Utamakan **`textContent` untuk nilai dinamis**; gunakan `innerHTML` template hanya untuk struktur yang kamu kontrol penuh dan tanpa data user.
- **`append`** bisa menerima banyak node dan string (`container.append(a, b, "teks")`); **`appendChild`** hanya satu node dan mengembalikan node (berguna untuk chain). Pilih `append` untuk kode modern.
- Gunakan **`DocumentFragment`** untuk batch render (render ulang katalog, daftar hasil filter) — satu insert, bukan satu per item.
- **Hapus DOM lama sebelum render ulang** (`kontainer.innerHTML = ""` atau bersihkan children) agar tidak ada kartu ganda yang menumpuk.
- Untuk elemen yang akan dihapus/diubah, simpan id unik di **`dataset`** agar event handler (materi 28) tahu persis item mana yang dimaksud.
- Pilih `Date.now()` atau counter sebagai id sementara sebelum ada backend (Level 6 akan mengganti dengan id dari server).
- Pastikan selalu ada **kondisi "kosong"**: saat array kosong, tampilkan pesan daripada grid yang kosong tak berisi.

## 7. Kesalahan Umum (Common Pitfalls & Bugs)

- **Elemen dibuat tapi tidak disisipkan.** `document.createElement("article")` saja tidak menampilkan apa pun; tanpa `append`/`prepend`/`insertBefore` elemen hanya hidup di memori. Perbaikan: selalu sisipkan setelah diisi.
- **Render ulang yang bertumpuk.** Memanggil `renderKatalog()` tanpa membersihkan wadah akan menghasilkan kartu dobel setiap kali fungsi dipanggil. Perbaikan: kosongkan `kontainer.innerHTML = ""` (atau loop `remove`) di awal render.
- **`innerHTML` dengan data user = XSS.** `${buku.judul}` yang berasal dari form langsung di-template ke `innerHTML` memungkinkan skrip user dieksekusi. Perbaikan: masukkan nilai via `textContent`.
- **Mencoba `.map` pada hasil `querySelectorAll`.** Untuk iterasi koleksi gunakan `forEach` atau konversi dulu `[...collection]`. Ini akan menimbulkan error jika disalahgunakan di render loop.
- **Hapus dari DOM tapi tidak dari data.** Tombol Hapus memanggil `kartu.remove()` namun array `katalog` tidak difilter; hasil filter berikutnya menampilkan buku yang "sudah dihapus". Perbaikan: saring array dan render ulang (atau hapus keduanya).

```javascript
    const stokInput  = document.querySelector("#input-stok");

    const judul = judulInput.value.trim();
    if (!judul) return;

    tambahBuku(judul, stokInput.value);
    event.target.reset();
    judulInput.focus();
});

renderKatalog();
```

**Pembahasan**: Latihan ini menggabungkan seluruh materi 25-27. Setiap buku adalah elemen yang dibuat dengan `createElement`, diisi `dataset.id`, dan nilai dinamisnya selalu lewat `textContent` — tidak ada XSS walau judul berasal dari form. `renderKatalog` dijalankan setelah setiap perubahan data, sehingga array dan tampilan selalu sinkron; `DocumentFragment` membuat render ulang katalog (yang dijalankan berkali-kali saat filter aktif nanti di materi 29) tetap efisien. Tombol hapus memakai **event delegation** di grid karena tombol lahir dan mati secara dinamis — menempelkan listener langsung ke tombol yang baru dibuat setiap kali render tidak praktis dan rawan bocor. Terakhir, kasus kosong ditangani: bila semua buku dihapus, grid menampilkan pesan alih-alih halaman yang tampak rusak. Konsep ini semuanya akan dilengkapi di materi 28 (event) dan dipakai bertubi-tubi di materi 29-30 (pencarian, filter, modal, notifikasi).
