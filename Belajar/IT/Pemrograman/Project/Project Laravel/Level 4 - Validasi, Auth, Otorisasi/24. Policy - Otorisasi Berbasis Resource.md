# 24. Policy — Otorisasi Berbasis Resource

Setelah kamu paham autentikasi (siapa kamu) di materi sebelumnya, sekarang saatnya menjawab pertanyaan yang lebih penting: "apa yang boleh kamu lakukan?". **Policy** adalah jawaban rapi Laravel untuk itu — sebuah class yang berisi semua aturan otorisasi untuk satu resource (misalnya Buku). Materi ini melengkapi Auth (Level 4) dan jadi fondasi sebelum kita belajar Middleware kustom di materi 25.

## 1. Penjelasan Singkat & Konsep Dasar

**Auth** menjawab **"siapa kamu?"** — proses login, session, mengidentifikasi pengguna.
**Authorization** menjawab **"apa yang boleh kamu lakukan?"** — apakah pengguna yang sudah teridentifikasi berhak melakukan aksi tertentu (misalnya menghapus buku).

**Policy** adalah class PHP yang berisi kumpulan aturan otorisasi untuk satu resource. Satu policy satu resource: `BukuPolicy` untuk Buku, `AnggotaPolicy` untuk Anggota, `PeminjamanPolicy` untuk Peminjaman. Setiap method di policy mewakili satu aksi (view, create, update, delete, dll).

```php
// Penanda visual: konsep alur akses
//
// Request masuk
//    -> Auth (23): siapa kamu? (sudah login / guest?)
//    -> Policy (24): bolehkah dia lakukan aksi ini pada resource ini?
//    -> Middleware (25): gerbang tambahan sebelum controller
//    -> Controller: baru dieksekusi
```

Konsep ini bersambung ke materi 25 (Middleware) karena keduanya sering dipakai bersama: middleware mengontrol akses di level route (grup, halaman), sedangkan policy mengontrol aksi spesifik di level resource.

## 2. Fungsi & Kegunaan Utama dalam Laravel

Tanpa policy, kamu akan menulis kode pengecekan role berulang-ulang:

```php
if (auth()->user()->role !== 'admin') {
    abort(403);
}
```

...di setiap controller, setiap method. Itu disebut *logic berulang* dan mudah sekali lupa di satu tempat. Policy menyelesaikan masalah ini dengan **memusatkan semua aturan otorisasi di satu tempat yang teruji dan mudah diubah**.

Fungsi utama policy:

- **Satu sumber kebenaran** untuk aturan "siapa boleh apa" per resource.
- **Mudah dipanggil** dari controller (`authorize()`), Blade (`@can`), dan route (`can:...`).
- **Mendukung role super admin** lewat `before()` untuk bypass semua aturan.
- **Auto-discovery**: Laravel menemukan policy secara otomatis lewat konvensi penamaan, tanpa registrasi manual.

## 3. Contoh Kode & Implementasi (Real-world Example)

Lokasi standar: `app/Policies/BukuPolicy.php`

Buat dengan perintah artisan:

```bash
php artisan make:policy BukuPolicy --model=Buku
```

Implementasi lengkap untuk aplikasi Perpustakaan Digital:

```php
<?php

namespace App\Policies;

use App\Models\Buku;
use App\Models\User;

class BukuPolicy
{
    /**
     * Bypass: super_admin selalu diizinkan, apa pun aturannya.
     * Method before() dieksekusi paling awal.
     */
    public function before(User $user, string $ability): bool|null
    {
        if ($user->role === 'super_admin') {
            return true; // langsung lolos semua aksi
        }

        return null; // null artinya lanjut ke method spesifik
    }

    /**
     * viewAny: boleh melihat daftar semua buku.
     * User nullable => guest (belum login) juga boleh lihat katalog.
     */
    public function viewAny(?User $user): bool
    {
        return true;
    }

    /**
     * view: boleh melihat detail satu buku. Guest juga boleh.
     */
    public function view(?User $user, Buku $buku): bool
    {
        return true;
    }

    /**
     * create: siapa yang boleh menambah buku baru.
     * Admin dan pustakawan boleh.
     */
    public function create(User $user): bool
    {
        return in_array($user->role, ['admin', 'pustakawan']);
    }

    /**
     * update: siapa yang boleh mengubah data buku.
     * Admin dan pustakawan boleh.
     */
    public function update(User $user, Buku $buku): bool
    {
        return in_array($user->role, ['admin', 'pustakawan']);
    }

    /**
     * delete: hanya admin yang boleh menghapus buku.
     */
    public function delete(User $user, Buku $buku): bool
    {
        return $user->role === 'admin';
    }

    /**
     * restore & forceDelete untuk soft delete (jika dipakai).
     * Sama: hanya admin.
     */
    public function restore(User $user, Buku $buku): bool
    {
        return $user->role === 'admin';
    }

    public function forceDelete(User $user, Buku $buku): bool
    {
        return $user->role === 'admin';
    }
}
```

**Penggunaan di Controller** (`app/Http/Controllers/BukuController.php`):

```php
use App\Models\Buku;

class BukuController extends Controller
{
    public function store(BukuRequest $request)
    {
        // Throw 403 kalau user tidak boleh create Buku
        $this->authorize('create', Buku::class);

        $buku = Buku::create($request->validated());

        return redirect()->route('buku.index');
    }

    public function destroy(Buku $buku)
    {
        // Model Buku otomatis di-inject dari route binding
        $this->authorize('delete', $buku);

        $buku->delete();

        return redirect()->route('buku.index');
    }
}
```

**Penggunaan di Blade** — untuk menyembunyikan/menampilkan tombol sesuai hak:

```blade
{{-- Tampilkan tombol hapus hanya untuk yang berhak --}}
@can('delete', $buku)
    <form action="{{ route('buku.destroy', $buku) }}" method="POST">
        @csrf
        @method('DELETE')
        <button type="submit">Hapus</button>
    </form>
@endcan

{{-- Atau kebalikannya: pesan untuk yang tidak boleh --}}
@cannot('create', App\Models\Buku::class)
    <p>Kamu tidak punya hak untuk menambah buku.</p>
@endcannot
```

**Penggunaan di Route** — dengan middleware `can`:

```php
// Di routes/web.php
Route::delete('/buku/{buku}', [BukuController::class, 'destroy'])
    ->middleware('can:delete,buku');
```

Perhatikan format: `can:delete,buku` artinya ability `delete` dengan model bernama route parameter `buku`.

**Auto-discovery**: karena kamu memakai `--model=Buku`, Laravel otomatis tahu `BukuPolicy` untuk model `Buku` lewat konvensi penamaan (nama model + `Policy`). Tidak perlu registrasi manual di `AppServiceProvider`.

## 4. Analogi Sederhana

Bayangkan Perpustakaan Digital ini seperti sebuah **restoran**:

- **Auth** = petugas di pintu masuk yang memeriksa KTP: "siapa kamu, sudah punya kartu member atau belum?". Dia hanya memastikan identitasmu, belum memutuskan apa yang boleh kamu lakukan di dalam.
- **Policy** = **level akses restoran**. Begitu kamu masuk:
  - **Tamu/anggota** boleh lihat menu dan duduk di ruang tamu (view buku, baca katalog).
  - **Koki (pustakawan)** boleh masuk dapur (create/update buku).
  - **Manajer (admin)** bisa kelola karyawan dan kasir (delete buku, kelola staf).
  - **Pencuri (pengunjung tak punya hak)** tidak bisa masuk dapur sama sekali (403).
  - **Pemilik restoran (super_admin)** bisa melakukan apa saja, bahkan membuka lemari rahasia — ini `before()` yang mengembalikan `true`.
  Policy adalah "aturan siapa boleh melakukan apa" untuk satu menu/resource tertentu (menu buku, menu anggota, menu peminjaman).
- **Middleware (materi 25)** = **satpam di pintu dapur**. Sebelum koki benar-benar mulai memasak, satpam memeriksa dulu: "kamu punya seragam dapur? kartu akses dapur ada?". Kalau tidak memenuhi syarat, langsung ditolak sebelum kerja dapur dimulai.

Perbedaannya: auth = identitas, authorization (policy) = izin per resource, middleware = gerbang sebelum aksi dimulai.

## 5. Kapan Harus Digunakan & Kasus Penggunaan (Use Cases)

| Situasi | Alat yang Tepat |
|---|---|
| Controller menerima request lalu butuh cek "bolehkah user ini hapus buku ini?" | `$this->authorize('delete', $buku)` di dalam controller |
| Tombol "Hapus" hanya muncul untuk user yang berhak | `@can('delete', $buku)` di Blade |
| Aksi dilakukan di luar controller (command, job, service) | `Gate::authorize('delete', $buku)` |
| Satu grup route hanya boleh diakses role tertentu (misal halaman dashboard admin) | Middleware `can:create,App\Models\Buku` atau middleware kustom (materi 25) |
| Aturan berlaku untuk SEMUA aksi super_admin | `before()` di policy |

**Panduan umum:**

- **Policy**: untuk otorisasi berbasis resource (Buku, Anggota, Peminjaman). Pakai di controller via `authorize()`.
- **Middleware**: untuk otorisasi berbasis route/halaman (misal hanya admin yang bisa akses `/admin/*`).
- **Keduanya**: middleware menahan di gerbang halaman, policy menahan di level aksi. Contoh: middleware `auth` memastikan sudah login, lalu policy `delete` memastikan boleh menghapus.
- **@can di Blade**: untuk UI yang adaptif (sembunyikan/tampilkan tombol).
- **Gate::authorize**: untuk logika non-HTTP (seeder, job, event listener).

## 6. Poin-poin Penting & Best Practices

- **Satu policy per resource**: `BukuPolicy`, `AnggotaPolicy`, `PeminjamanPolicy` — jangan satukan semua aturan dalam satu class besar.
- **Method naming konsisten**: `viewAny`, `view`, `create`, `update`, `delete`, `restore`, `forceDelete`. Laravel memanggil method ini secara otomatis sesuai aksinya.
- **Gunakan `before()` untuk super admin**: kembalikan `true` untuk bypass, `null` untuk lanjut ke aturan spesifik. Jangan menulis cek role di setiap method kalau ada `before()`.
- **Gunakan `$this->authorize()` di controller**: itu melempar `403` otomatis, lebih bersih daripada `abort(403)` manual.
- **@can/@cannot di Blade** untuk menyembunyikan tombol dari user yang tidak berhak — jangan hanya mengandalkan pengecekan di controller.
- **Definisikan capability di satu tempat**: semua aturan di policy, jangan sebar di controller.
- **Buat policy via artisan**: `php artisan make:policy BukuPolicy --model=Buku` agar model binding sudah siap.
- **Manfaatkan auto-discovery**: beri nama policy sesuai konvensi (`BukuPolicy`) dan Laravel akan menemukannya sendiri.

## 7. Kesalahan Umum (Common Pitfalls & Anti-patterns)

- **403 tak terduga**:
  - `authorize('create', Buku::class)` dipanggil tapi method `create` di policy mengecek hal yang salah — cek lagi kondisinya.
  - Policy belum didaftarkan / nama file tidak sesuai konvensi (`BukuPolici` typo, dsb).
  - Route model binding salah: param di route bernama `$bukuId` tapi policy mengharapkan `Buku $buku`. Pastikan nama parameter route sama (`/buku/{buku}`).
- **Logic berulang di tiap controller**: menulis `if ($user->role === ...)` berulang-ulang. Pindahkan ke policy.
- **Cek role manual berulang-ulang di Blade**: pakai `@can` bukan `@if(auth()->user()->role === 'admin')`.
- **Menaruh business logic di policy**: policy hanya *menilai* boleh atau tidak, bukan *melakukan* aksi. Simpan logika bisnis (misal aturan denda) di model/service, bukan di policy.
- **`before()` menulis ulang semua logika**: kalau `before()` selalu return `true`, method lain tidak pernah dijalankan. Gunakan `return null` untuk delegasi ke method spesifik.
- **Troubleshooting 403**: tambahkan sementara `dd($user->role, $buku)` di method policy untuk melihat kondisi, atau cek `php artisan route:list` apakah middleware `can` sudah terpasang di route.

## 8. Soal Latihan & Kunci Jawaban

### Tantangan

1. Buat policy `AnggotaPolicy` untuk aplikasi Perpustakaan Digital dengan aturan: semua user yang login bisa melihat daftar anggota (`viewAny`), hanya admin yang bisa melihat detail anggota, hanya admin dan pustakawan yang bisa membuat anggota baru, hanya admin yang bisa menghapus anggota. Sertakan `before()` untuk `super_admin`.
2. Di controller `PeminjamanController@destroy`, panggil otorisasi agar hanya `admin` yang bisa menghapus data peminjaman. Jelaskan alur pengecekannya.

### Jawaban & Pembahasan

**Soal 1:**

```bash
php artisan make:policy AnggotaPolicy --model=Anggota
```

```php
<?php

namespace App\Policies;

use App\Models\Anggota;
use App\Models\User;

class AnggotaPolicy
{
    public function before(User $user, string $ability): bool|null
    {
        if ($user->role === 'super_admin') {
            return true;
        }

        return null;
    }

    // Semua user login boleh lihat daftar anggota
    public function viewAny(User $user): bool
    {
        return true;
    }

    // Hanya admin boleh lihat detail anggota
    public function view(User $user, Anggota $anggota): bool
    {
        return $user->role === 'admin';
    }

    // Admin dan pustakawan boleh membuat anggota
    public function create(User $user): bool
    {
        return in_array($user->role, ['admin', 'pustakawan']);
    }

    public function update(User $user, Anggota $anggota): bool
    {
        return in_array($user->role, ['admin', 'pustakawan']);
    }

    // Hanya admin boleh menghapus anggota
    public function delete(User $user, Anggota $anggota): bool
    {
        return $user->role === 'admin';
    }
}
```

**Alur penjelasan:** Super admin selalu lolos via `before()`. User lain diarahkan ke method spesifik — `viewAny` terbuka untuk semua yang login, sedangkan `view`, `create`, `update`, `delete` punya pembatasan per role.

**Soal 2:**

```php
use App\Models\Peminjaman;

class PeminjamanController extends Controller
{
    public function destroy(Peminjaman $peminjaman)
    {
        // Alur: middleware auth memastikan sudah login,
        // lalu authorize() mengecek policy PeminjamanPolicy@delete.
        // Kalau tidak boleh -> lempar 403 otomatis.
        $this->authorize('delete', $peminjaman);

        $peminjaman->delete();

        return redirect()->route('peminjaman.index');
    }
}
```

```php
// app/Policies/PeminjamanPolicy.php
public function delete(User $user, Peminjaman $peminjaman): bool
{
    return $user->role === 'admin';
}
```

**Alur pengecekan:** Request masuk ke route `DELETE /peminjaman/{peminjaman}` → route binding inject model `Peminjaman` → `authorize('delete', $peminjaman)` memanggil `PeminjamanPolicy::delete($user, $peminjaman)` → `before()` bypass super_admin, jika bukan, `delete()` dieksekusi → jika `false`, Laravel melempar `403 Forbidden`; jika `true`, controller melanjutkan ke `$peminjaman->delete()`.
