# 39. Livewire — Reactive UI Tanpa Full SPA

Livewire adalah framework full-stack untuk Laravel yang membuat UI jadi reaktif tanpa menulis JavaScript framework (Vue/React). Cukup dengan Blade dan beberapa direktif seperti `wire:model`, komponen langsung merespons input pengguna lewat request AJAX di belakang layar. Materi ini memakai pola Blade komponen (materi 12) dan menjadi fondasi interaktivitas Filament (materi 38).

## 1. Penjelasan Singkat & Konsep Dasar

Konsep inti Livewire: **setiap komponen adalah class PHP + satu Blade view**. Saat pengguna mengetik atau mengklik, Livewire mengirim request AJAX yang mengeksekusi ulang class komponen di server, lalu mengirim *diff* (hanya bagian yang berubah) untuk diperbarui di browser. Hasilnya: pengalaman SPA-like, tapi kamu tetap menulis PHP dan Blade — tidak ada state management JavaScript yang rumit.

Dua hal yang harus selalu kamu pegang:
1. **State hidup di server** dalam property public class (misal `public string $pencarian`).
2. **Blade dirender ulang di server** setiap ada interaksi, lalu perbedaan DOM-nya dikirim ke browser.

## 2. Fungsi & Kegunaan Utama dalam Laravel

Masalah yang dipecahkan: **memperbarui halaman secara parsial tanpa reload penuh dan tanpa membangun SPA**.

- Blade biasa (materi 12) bagus untuk halaman statis, tapi setiap interaksi butuh form submit + reload penuh.
- SPA (Vue/React) memberi responsivitas penuh tapi butuh API, state management, dan membagi logika di dua tempat (frontend & backend).
- **Livewire ada di tengah-tengah**: responsivitas tinggi, tapi logika tetap satu bahasa (PHP), state tetap di server (aman dari manipulasi client), dan kamu memakai Blade yang sudah kamu kenal.

Untuk perpustakaan: halaman katalog publik dengan pencarian real-time, filter kategori, dan pagination adalah kasus penggunaan yang sangat pas — pengguna mengetik, daftar buku langsung menyaring tanpa reload.

## 3. Contoh Kode & Implementasi (Real-world Example)

Lokasi file standar:
- `app/Livewire/KatalogBuku.php` — class komponen.
- `resources/views/livewire/katalog-buku.blade.php` — view Blade-nya.
- `routes/web.php` — pendaftaran route.

### 3.1 Install

```bash
# 1. Install package (Laravel 11 otomatis mendaftarkan provider)
composer require livewire/livewire

# 2. Buat komponen
php artisan make:livewire KatalogBuku
#     menghasilkan:
#     app/Livewire/KatalogBuku.php
#     resources/views/livewire/katalog-buku.blade.php
```

### 3.2 Class Komponen

```php
<?php

namespace App\Livewire;

use App\Models\Buku;
use Livewire\Component;
use Livewire\WithPagination;

class KatalogBuku extends Component
{
    use WithPagination;

    // Property public = state yang hidup di server
    public string $pencarian = '';
    public string $kategori = '';

    // Reset halaman ke 1 saat pencarian berubah
    public function updatingPencarian(): void
    {
        $this->resetPage();
    }

    // Reset halaman saat kategori dipilih
    public function updatingKategori(): void
    {
        $this->resetPage();
    }

    public function render()
    {
        $buku = Buku::query()
            ->when($this->pencarian, fn ($query) =>
                $query->where('judul', 'like', '%' . $this->pencarian . '%')
                      ->orWhere('pengarang', 'like', '%' . $this->pencarian . '%'))
            ->when($this->kategori, fn ($query) =>
                $query->where('kategori', $this->kategori))
            ->paginate(12); // 12 buku per halaman

        return view('livewire.katalog-buku', [
            'buku' => $buku,
        ]);
    }
}
```

### 3.3 Blade View

```blade
<div>
    {{-- Pencarian real-time dengan debounce 300ms --}}
    <input
        type="text"
        wire:model.live.debounce.300ms="pencarian"
        placeholder="Cari judul atau pengarang..."
    >

    {{-- Filter kategori --}}
    <select wire:model.live="kategori">
        <option value="">Semua kategori</option>
        <option value="fiksi">Fiksi</option>
        <option value="nonfiksi">Non-fiksi</option>
        <option value="teknologi">Teknologi</option>
        <option value="anak">Anak-anak</option>
    </select>

    {{-- Indikator loading: tampil saat request berjalan --}}
    <div wire:loading>
        Memuat...
    </div>
    <div wire:loading.class="opacity-50" wire:target="pencarian">
        {{-- Konten dikurangi opacity saat pencarian berjalan --}}
    </div>

    <div class="grid grid-cols-3 gap-4">
        @foreach ($buku as $item)
            {{-- wire:key WAJIB di dalam loop --}}
            <div wire:key="buku-{{ $item->id }}" class="card">
                <h3>{{ $item->judul }}</h3>
                <p>{{ $item->pengarang }}</p>
                <p>Rp {{ number_format($item->harga, 0, ',', '.') }}</p>
                <p>Stok: {{ $item->stok }}</p>
            </div>
        @endforeach
    </div>

    {{-- Pagination Livewire --}}
    {{ $buku->links() }}
</div>
```

### 3.4 Daftarkan Route

```php
// routes/web.php
use App\Livewire\KatalogBuku;

// Langsung render komponen sebagai halaman penuh
Route::get('/katalog', KatalogBuku::class);
```

Buka `http://localhost:8000/katalog` — ketik di kolom pencarian, dan daftar buku menyaring tanpa reload.

## 4. Analogi Sederhana

Bayangkan Livewire sebagai **pelayan restoran yang responsif tanpa bolak-balik ke dapur**. Ketika pelanggan bertanya "menu mana yang masih ada stoknya?", pelayan modern ini langsung mengecek dari mejanya tanpa harus lari ke dapur untuk memuat ulang seluruh menu (itu analogi reload halaman penuh). Hanya bagian yang relevan — misalnya daftar menu di meja itu — yang diperbarui, bukan seluruh ruangan.

Di sisi lain, **Filament (38) adalah panel manajemen / meja kasir** yang dibangun di atas pelayan cerdas ini: semua interaksi di dashboard admin memakai Livewire di dalamnya. Sedangkan **Scheduling (40) adalah timer oven otomatis** yang berjalan sendiri di dapur — bukan tentang interaksi pelanggan, melainkan tugas yang dieksekusi otomatis.

## 5. Kapan Harus Digunakan & Kasus Penggunaan (Use Cases)

| Kebutuhan | Pilihan | Alasan |
|---|---|---|
| Pencarian real-time, filter, pagination di halaman publik (katalog buku) | **Livewire** | Responsif tanpa reload, logika tetap PHP |
| Halaman statis, konten yang jarang berubah | **Blade biasa** | Tidak perlu interaktivitas; Livewire menambah overhead |
| UI sangat kompleks, real-time kolaboratif, drag & drop berat | **Full SPA (Vue/React)** | Butuh kontrol client-side penuh, state di browser |
| Dashboard admin internal (kelola buku, anggota) | **Filament** | Dibangun di atas Livewire, tinggal definisi resource |

**Aturan praktis**: mulai dari Blade biasa; tambahkan Livewire hanya di bagian yang butuh interaksi parsial; gunakan SPA hanya bila interaksinya benar-benar butuh responsivitas level aplikasi client-side (contoh: editor teks, papan kanban). Jangan gunakan Livewire untuk seluruh halaman bila sebenarnya kontennya statis.

## 6. Poin-poin Penting & Best Practices

- **Install & generate**: `composer require livewire/livewire`, lalu `php artisan make:livewire KatalogBuku`. File class + view dibuat otomatis.
- **State dengan property public**: `public string $pencarian` — setiap perubahan property memicu re-render. Type-hint property (string, int) membantu serialisasi.
- **Binding dua arah**: `wire:model.live.debounce.300ms="pencarian"` — `.live` langsung memproses di server, `.debounce.300ms` menunda 300ms agar tidak membanjiri server per karakter. Gunakan debounce untuk input teks.
- **Pagination**: `use WithPagination;` lalu `->paginate(12)`; panggil `$buku->links()` di view. Selalu `resetPage()` saat filter/pencarian berubah lewat `updatingPencarian()` agar tetap di halaman 1.
- **Query dinamis**: di `render()`, susun query bertingkat dengan `when($this->pencarian, fn ($q) => ...)` sehingga filter opsional.
- **Loading state**: `wire:loading` menampilkan indikator saat request berjalan; `wire:loading.class="opacity-50"` menambahkan class ke elemen saat loading (bisa dibatasi dengan `wire:target`).
- **Loop & key**: SELALU pasang `wire:key` (`wire:key="buku-{{ $item->id }}"`) di dalam `@foreach` agar Livewire tahu mana elemen yang berubah.
- **Integrasi route**: `Route::get('/katalog', KatalogBuku::class)` merender komponen sebagai halaman penuh; untuk menyisipkan di layout, gunakan `@livewire('katalog-buku')` atau komponen Livewire di dalam Blade (konsep materi 12).
- **Security**: property public yang di-bound bisa diubah user — validasi di server dan jangan pernah binding property yang sensitif (misal `password`).

## 7. Kesalahan Umum (Common Pitfalls & Anti-patterns)

| Gejala | Penyebab | Solusi |
|---|---|---|
| `wire:model` tidak bereaksi | Javascript Livewire belum ke-load; npm build belum jalan di produksi | Pastikan `@livewireStyles` / `@livewireScripts` ada di layout; jalankan `npm run build` bila asset belum dibuild |
| Tampilan duplikat / salah posisi di loop | Lupa `wire:key` dalam `@foreach` | Tambahkan `wire:key="buku-{{ $item->id }}"` pada elemen loop |
| Pagination membuka halaman aneh / 404 | Konflik parameter `page` dengan query string lain | Gunakan `WithPagination` dan atur `protected $paginationTheme` bila perlu; hindari nama parameter `page` untuk hal lain |
| Halaman 1 tak kembali saat filter berubah | Tidak `resetPage()` | Tambahkan `updatingX()` yang memanggil `$this->resetPage()` |
| Request terlalu banyak per karakter | Tanpa debounce | `wire:model.live.debounce.300ms` |
| Filter `like` salah mengambil data | Query `when()` salah urutan / `orWhere` mengacaukan grouping | Bungkus kondisi dengan closure: `where(fn ($q) => $q->where('judul','like',...)->orWhere('pengarang','like',...))` |
| Komponen lambat | Render ulang seluruh halaman setiap interaksi | Batasi state yang memicu render; gunakan `wire:target` pada loading; hindari query berat di render (gunakan cache bila perlu) |
| Validasi tidak jalan | Cuma validate di client | Validasi tetap di server (`$this->validate(...)`) karena state di server |

**Troubleshooting**: cek Network tab di browser — Livewire mengirim request POST dengan payload; kalau ada error 500, buka log di `storage/logs/laravel.log`. Gunakan `@if ($errors->any())` untuk menampilkan error validasi di view.

## 8. Soal Latihan & Kunci Jawaban

### Tantangan

1. Buat komponen Livewire `CariBuku` dengan satu input pencarian. Tampilkan daftar buku (judul + pengarang) yang cocok, dengan `wire:key`, debounce 500ms, dan pagination 5 per halaman. Tambahkan tombol "Hapus pencarian" yang mengosongkan input.
2. Tambahkan filter `Select` kategori yang kombinasinya dengan pencarian tetap bekerja (filter + pencarian sekaligus), dan tampilkan indikator "Memuat..." saat request berjalan.

### Jawaban & Pembahasan

**Jawaban 1**

```bash
php artisan make:livewire CariBuku
```

```php
// app/Livewire/CariBuku.php
<?php

namespace App\Livewire;

use App\Models\Buku;
use Livewire\Component;
use Livewire\WithPagination;

class CariBuku extends Component
{
    use WithPagination;

    public string $pencarian = '';

    public function updatingPencarian(): void
    {
        $this->resetPage();
    }

    public function hapusPencarian(): void
    {
        $this->pencarian = '';
        $this->resetPage();
    }

    public function render()
    {
        $buku = Buku::query()
            ->when($this->pencarian, fn ($query) =>
                $query->where('judul', 'like', '%' . $this->pencarian . '%'))
            ->paginate(5);

        return view('livewire.cari-buku', ['buku' => $buku]);
    }
}
```

```blade
{{-- resources/views/livewire/cari-buku.blade.php --}}
<div>
    <input
        type="text"
        wire:model.live.debounce.500ms="pencarian"
        placeholder="Cari judul buku..."
    >
    <button wire:click="hapusPencarian">Hapus pencarian</button>

    <div wire:loading>Memuat...</div>

    @foreach ($buku as $item)
        <div wire:key="buku-{{ $item->id }}">
            {{ $item->judul }} — {{ $item->pengarang }}
        </div>
    @endforeach

    {{ $buku->links() }}
</div>
```

**Pembahasan**: Property `public string $pencarian` adalah satu-satunya state. Setiap ketikan memicu `updatingPencarian()` yang mereset halaman ke 1 sebelum query dijalankan ulang. Tombol "Hapus pencarian" memanggil method `hapusPencarian()` lewat `wire:click`. `wire:key` memastikan Livewire melacak tiap baris dengan benar saat daftar berubah.

**Jawaban 2**

```php
// Tambahkan property di class
public string $kategori = '';

public function updatingKategori(): void
{
    $this->resetPage();
}

// render() menjadi:
public function render()
{
    $buku = Buku::query()
        ->when($this->pencarian, fn ($query) =>
            $query->where(fn ($q) =>
                $q->where('judul', 'like', '%' . $this->pencarian . '%')
                  ->orWhere('pengarang', 'like', '%' . $this->pencarian . '%')))
        ->when($this->kategori, fn ($query) =>
            $query->where('kategori', $this->kategori))
        ->paginate(5);

    return view('livewire.cari-buku', ['buku' => $buku]);
}
```

```blade
<select wire:model.live="kategori">
    <option value="">Semua kategori</option>
    <option value="fiksi">Fiksi</option>
    <option value="nonfiksi">Non-fiksi</option>
</select>

{{-- Indikator loading spesifik ke input pencarian --}}
<div wire:loading wire:target="pencarian">Memuat...</div>
```

**Pembahasan**: Kunci kombinasi filter adalah penggunaan `when()` bertingkat — kedua filter menumpuk secara kondisional di query yang sama. Yang penting: `orWhere` untuk pencarian dibungkus dalam closure (`where(fn ($q) => ...)`) agar tidak merusak kondisi `kategori` karena operator OR akan menimpa scope pencarian bila tidak digrouping. `wire:loading` dengan `wire:target="pencarian"` hanya menampilkan indikator saat input pencarian yang berubah, bukan saat select kategori berubah.
