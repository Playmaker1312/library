# 17. Seeder dan Factory — Data Awal dan Data Test

Setelah tabel dibangun lewat migration (materi 16), database-mu masih kosong. Seeder dan factory adalah dua alat untuk mengisi data: **seeder untuk data awal yang nyata dan deterministik**, **factory untuk data palsu massal untuk testing/development**. Materi ini menjembatani struktur database dengan Eloquent ORM (materi 18) — karena `Buku::create()` dan `Buku::factory()` sebenarnya adalah API Eloquent.

## 1. Penjelasan Singkat & Konsep Dasar

- **Seeder** = kode PHP yang mengisi database dengan data spesifik yang kamu tulis tangan. Cocok untuk data yang *harus* ada: buku contoh, anggota contoh, kategori awal. Hasilnya deterministik — dijalankan kapan pun, isinya sama.
- **Factory** = generator data palsu dalam jumlah besar pakai `fake()`. Cocok untuk data *percobaan*: 40 buku dengan judul acak, harga acak, pengarang acak. Hasilnya non-deterministik tapi "masuk akal".

Alur belajar: Level 2 menyimpan data di array controller (resep ditulis tangan) → migration (16) membangun gudang/database → seeder & factory (17) mengisi gudang → Eloquent (18) mengambil dan menulis data lewat model.

## 2. Fungsi & Kegunaan Utama dalam Laravel

1. **Data awal yang konsisten untuk semua developer** — tim baru tinggal `php artisan db:seed`, database langsung punya data dasar yang sama, tanpa copy-paste query SQL manual.
2. **Environment test yang realistis** — factory menghasilkan 100 peminjaman palsu dengan `fake()` untuk menguji logika denda, laporan, dan performa query tanpa menyentuh data produksi.
3. **Demo & staging cepat** — `migrate:fresh --seed` menghidupkan aplikasi dengan tampilan data penuh dalam hitungan detik.
4. **Memisahkan data produksi vs data uji** — seeder berisi data nyata (mis. 5 buku sediaan awal), factory berisi data acak massal (mis. 40 buku latihan). Dua hal ini tidak dicampur.
5. **Testing yang andal** — dalam test otomatis, factory bisa dipakai membuat record spesifik (mis. `Buku::factory()->habis()->create()`) sehingga pengujian tidak bergantung pada kondisi database global.

## 3. Contoh Kode & Implementasi (Real-world Example)

Semua file berada di `database/factories/` (factory) dan `database/seeders/` (seeder). Buat dulu filenya:

```bash
# Factory untuk model Buku
php artisan make:factory BukuFactory --model=Buku

# Seeder untuk data awal
php artisan make:seeder BukuSeeder
php artisan make:seeder AnggotaSeeder
php artisan make:seeder PeminjamanSeeder
```

### 3.1 `database/factories/BukuFactory.php`

```php
<?php

namespace Database\Factories;

use Illuminate\Database\Eloquent\Factories\Factory;

/**
 * @extends \Illuminate\Database\Eloquent\Factories\Factory<\App\Models\Buku>
 */
class BukuFactory extends Factory
{
    public function definition(): array
    {
        return [
            // fake() = Faker; data palsu tapi realistis
            'judul'       => fake()->sentence(4),                    // judul acak 4 kata
            'isbn'        => fake()->unique()->isbn13(),             // ISBN 13 digit unik
            'pengarang'   => fake()->name(),
            'penerbit'    => fake()->company(),
            'tahun'       => fake()->numberBetween(1990, (int) date('Y')),
            'harga'       => fake()->randomFloat(2, 20000, 500000),  // 20rb - 500rb
            'stok'        => fake()->numberBetween(0, 50),
            'kategori'    => fake()->randomElement([
                'Teknologi', 'Fiksi', 'Sejarah', 'Sains', 'Novel',
            ]),
            'deskripsi'   => fake()->paragraph(2),
            'sampul'      => null, // biarkan kosong, bisa diisi path gambar
        ];
    }

    // --- State: variasi kondisi khusus ---

    // Stok habis (untuk menguji tampilan "stok kosong")
    public function habis(): static
    {
        return $this->state(fn (array $attributes) => ['stok' => 0]);
    }

    // Buku dengan kategori teknologi
    public function teknologi(): static
    {
        return $this->state(fn (array $attributes) => ['kategori' => 'Teknologi']);
    }

    // Buku mahal (untuk menguji filter harga tinggi)
    public function mahal(): static
    {
        return $this->state(fn (array $attributes) => [
            'harga' => fake()->randomFloat(2, 1_000_000, 5_000_000),
        ]);
    }
}
```

### 3.3 `database/seeders/DatabaseSeeder.php` — orchestrator

`DatabaseSeeder` adalah "conductor" yang memanggil seeder lain. **Urutan pemanggilan penting** karena foreign key: seeder parent harus jalan dulu.

```php
<?php

namespace Database\Seeders;

use Illuminate\Database\Seeder;

class DatabaseSeeder extends Seeder
{
    public function run(): void
    {
        // Urutan: parent (buku, anggota) SEBELUM child (peminjaman),
        // karena peminjaman butuh id dari buku & anggota.
        $this->call([
            BukuSeeder::class,
            AnggotaSeeder::class,
            PeminjamanSeeder::class,
        ]);
    }
}
```

Contoh minimal `AnggotaSeeder` agar pola lengkap:

```php
<?php

namespace Database\Seeders;

use App\Models\Anggota;
use Illuminate\Database\Seeder;

class AnggotaSeeder extends Seeder
{
    public function run(): void
    {
        Anggota::create([
            'nama'    => 'Rina Permata',
            'email'   => 'rina@perpustakaan.test',
            'telepon' => '081234567890',
            'alamat'  => 'Jl. Melati No. 12, Bandung',
            'status'  => 'aktif',
        ]);

        Anggota::factory()->count(15)->create(); // 15 anggota palsu untuk uji
    }
}
```

`PeminjamanSeeder` mengikuti pola yang sama, cukup merujuk id yang sudah ada:

```php
<?php

namespace Database\Seeders;

use App\Models\Buku;
use App\Models\Anggota;
use App\Models\Peminjaman;
use Illuminate\Database\Seeder;

class PeminjamanSeeder extends Seeder
{
    public function run(): void
    {
        // Ambil koleksi id yang ada setelah seeder parent jalan
        $bukuIds    = Buku::pluck('id')->all();
        $anggotaIds = Anggota::pluck('id')->all();

        for ($i = 0; $i < 20; $i++) {
            Peminjaman::create([
                'buku_id'          => fake()->randomElement($bukuIds),
                'anggota_id'       => fake()->randomElement($anggotaIds),
                'tanggal_pinjam'   => fake()->dateTimeBetween('-30 days', '-1 day')->format('Y-m-d'),
                'batas_kembali'    => fake()->dateTimeBetween('now', '+7 days')->format('Y-m-d'),
                'tanggal_kembali'  => null,
                'denda'            => 0,
                'status'           => 'belum_selesai',
            ]);
        }
    }
}
```

### 3.4 Perintah yang dipakai

```bash
# Jalankan semua seeder yang terdaftar di DatabaseSeeder
php artisan db:seed

# Jalankan satu seeder spesifik (hindari menjalankan factory besar bila tak perlu)
php artisan db:seed --class=BukuSeeder

# Reset database + jalankan seeder — paling cepat untuk dev
php artisan migrate:fresh --seed

# Jalankan factory lewat tinker (uji cepat tanpa seeder)
php artisan tinker
```

Di dalam tinker:

```php
<?php
use App\Models\Buku;

// Buat 1 buku acak
Buku::factory()->create();

// Buat buku acak tapi stoknya 0 (state habis)
Buku::factory()->habis()->create();

// Buat buku mahal kategori teknologi
Buku::factory()->mahal()->teknologi()->create();
```

## 4. Analogi Sederhana

Tetap di dapur restoran.

- **Seeder = menyiapkan stok awal gudang** — bahan dasar yang *selalu* harus ada saat cabang baru buka: tepung, gula, garam. Tanpa seeder, database kosong dan aplikasi terlihat mati. Ini data yang nyata dan terencana.
- **Factory = uji coba bahan masakan dalam jumlah banyak untuk latihan koki** — koki berlatih dengan 40 potong adonan palsu agar mahir, lalu dibuang. Tidak untuk disajikan ke pelanggan (produksi), tapi sangat berguna untuk latihan (testing/development).
- **Migration (16) = blueprint renovasi dapur** — dulu koki menulis resep sementara di kertas tangan (array hardcode di controller Level 2). Sekarang resep pindah ke gudang terpusat (database) yang dibangun dengan blueprint. Seeder dan factory adalah orang yang mengangkut bahan masuk ke gudang yang sudah jadi itu.

Jadi urutannya: blueprint jadi (migration) → gudang diisi bahan dasar (seeder) → koki berlatih dengan bahan palsu (factory) → pelanggan akhirnya dilayani dari gudang yang terisi (Eloquent, materi 18).

## 5. Kapan Harus Digunakan & Kasus Penggunaan (Use Cases)

| Situasi | Alat yang tepat |
|---|---|
| Data wajib ada di semua environment (contoh buku & anggota) | Seeder dengan `Buku::create()` |
| Ingin database penuh data realistis untuk demo/staging | Seeder + `Buku::factory()->count(40)->create()` |
| Test logika denda (butuh 100 peminjaman bermacam status) | Factory dengan state, mis. `Peminjaman::factory()->count(100)->create()` |
| Menguji tampilan "stok habis" | Factory state: `Buku::factory()->habis()->create()` |
| Menyiapkan environment produksi | Seeder saja (tanpa factory massal), jalankan sekali |
| Reset total database dev | `migrate:fresh --seed` |
| Ingin data acak satu-dua record di terminal | `php artisan tinker` + factory |

## 6. Poin-poin Penting & Best Practices

- **Pisahkan peran**: seeder untuk data nyata & deterministik; factory untuk data palsu massal. Jangan campur keduanya secara membabi buta.
- **`make:factory NamaFactory --model=NamaModel`** membuat factory yang otomatis terhubung ke modelnya; tanpa `--model` kamu harus set properti `$model` manual.
- **`definition()` adalah "template default"**; method state (`habis()`, `teknologi()`, `mahal()`) membuat variasi dengan `$this->state(fn () => [...])`. State bisa di-chain: `Buku::factory()->mahal()->teknologi()->create()`.
- **`fake()`** adalah Faker — konsisten dengan konfigurasi `faker_locale` di `config/app.php` (mis. `id_ID` untuk nama/alamat Indonesia).
- **`DatabaseSeeder` adalah orchestrator** — daftarkan semua seeder di `run()` lewat `$this->call([...])`, jangan memanggil `db:seed --class` satu per satu.
- **Urutan call penting karena foreign key**: `buku` dan `anggota` (parent) harus di-seed lebih dulu daripada `peminjaman` (child). Urutan pembuatan migration di materi 16 juga mengikuti prinsip yang sama.
- **`Buku::create()` butuh properti `$fillable`** di model (mass assignment protection) — ini dibahas tuntas di materi Eloquent (18). Tanpa itu, muncul `MassAssignmentException`.
- **`migrate:fresh --seed` HANYA untuk development** — menghapus semua data.
- **Factory wajib dimiliki jika model akan diuji** — Laravel membuang test error "factory state not defined" bila model dipakai di test tanpa factory.
- **Gunakan data unik dengan hati-hati** — `isbn` di factory dipaksa unik via `fake()->unique()->isbn13()`, sehingga mengisi 40 buku tidak pernah menabrak constraint `unique` dari migration.

## 7. Kesalahan Umum (Common Pitfalls & Anti-patterns)

| Gejala | Penyebab | Solusi |
|---|---|---|
| `MassAssignmentException: judul is not fillable` | `Buku::create()` tanpa `$fillable` di model | Tambahkan `protected $fillable = [...]` di model (materi 18) |
| `Unique constraint violation` saat `db:seed` | Menjalankan seeder dua kali dengan data unik (`isbn`, `email`) | Jalankan `migrate:fresh --seed` sekali, atau pakai `Buku::updateOrCreate()` untuk data yang boleh di-idempoten |
| `factory state not defined` / `class not found` | Factory tidak dibuat, atau `--model` salah | `php artisan make:factory BukuFactory --model=Buku` |
| Foreign key gagal saat seed | Seeder child (`PeminjamanSeeder`) jalan sebelum parent terisi | Perbaiki urutan `$this->call([...])` di `DatabaseSeeder` |
| Tabel tidak ada saat `db:seed` | Migration belum dijalankan | `php artisan migrate` dulu, baru `db:seed` |
| Data acak terlihat tidak masuk akal (harga negatif, dst.) | `fake()` diisi tanpa batasan | Beri range: `fake()->numberBetween(0, 50)`, `fake()->randomFloat(2, 20000, 500000)` |
| Factory dipakai di produksi | Salah environment | Jangan pernah `migrate:fresh --seed` di produksi; data palsu hanya untuk dev/test |

**Troubleshooting cepat:** gagal seed biasanya karena salah satu dari tiga hal — model belum punya `$fillable`, urutan seeder salah (foreign key), atau constraint unik bentrok dengan data yang sudah ada. Cek pesan error di terminal: Laravel menyebutkan tabel dan kolom yang bermasalah, lalu perbaiki sesuai tabel di atas.

## 8. Soal Latihan & Kunci Jawaban

### Tantangan

1. Buat `BukuFactory` dengan `definition()` yang memakai `fake()`, lalu tambahkan dua state: `habis()` (stok 0) dan `murah()` (harga di bawah Rp 30.000). Buat `BukuSeeder` berisi 3 buku nyata + 30 buku factory. Daftarkan di `DatabaseSeeder` bersama `AnggotaSeeder`, dan jalankan `migrate:fresh --seed`.
2. Kamu menjalankan `db:seed` dua kali dan terkena error `Unique constraint violation` pada kolom `isbn`. Jelaskan penyebabnya dan dua cara memperbaikinya.

**Alur pembahasan:** factory menetapkan template `definition()` dengan `fake()`; state `habis()` dan `murah()` hanya menimpa sebagian atribut lewat `state()`, sehingga pemanggilan `Buku::factory()->murah()->create()` menghasilkan buku harga < 30rb sementara atribut lain tetap acak. Seeder memakai `Buku::create()` untuk 3 buku nyata dan `Buku::factory()->count(30)->create()` untuk data latihan. `migrate:fresh --seed` mereset skema lalu menjalankan semua seeder dalam satu baris — urutan di `$this->call` menentukan ketersediaan id untuk foreign key.

**Soal 2**

**Penyebab:** `db:seed` bukan operasi idempoten. Saat dijalankan kedua kalinya, `BukuSeeder` mencoba membuat lagi buku dengan `isbn` yang sama, menabrak constraint `unique` yang dibuat di migration (`$table->char('isbn', 13)->unique()`).

**Solusi:**

1. **Reset dulu** — paling sederhana untuk development: `php artisan migrate:fresh --seed` (data lama dihapus, tabel dibuat ulang, seeder diisi ulang).
2. **Buat seeder idempoten** — pakai `updateOrCreate()` untuk data nyata agar aman dijalankan berulang:

```php
Buku::updateOrCreate(
    ['isbn' => '9786020821975'],                     // kondisi unik
    ['judul' => 'Laravel untuk Pemula', 'stok' => 10] // data yang di-update
);
```

**Alur pembahasan:** memahami perbedaan "data dibuat sekali" vs "data harus selalu ada" menentukan strategi. Data nyata yang boleh dijalankan berulang pakai `updateOrCreate()`; data percobaan massal cukup di-reset dengan `migrate:fresh --seed`. Kebiasaan ini mencegah error constraint unik dan menjaga database tetap konsisten — prinsip yang juga berlaku saat kamu menulis testing di level berikutnya.
