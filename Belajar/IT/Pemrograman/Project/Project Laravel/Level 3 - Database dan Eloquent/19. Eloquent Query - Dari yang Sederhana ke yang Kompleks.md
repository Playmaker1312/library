# 19. Eloquent Query — Dari yang Sederhana ke yang Kompleks

Setelah punya Model yang rapi, saatnya kita "bertanya" ke database. Materi ini membahas cara mengambil data dengan Eloquent, mulai dari yang sederhana (`where`, `get`) sampai yang kompleks (filter kombinasi, paginasi, agregasi, dan query kondisional). Semua tetap lewat Model yang kamu buat di materi 18.

## 1. Penjelasan Singkat & Konsep Dasar

Di materi 18, Model `Buku` kita lengkapi dengan fillable, casts, accessor, dan scope. Sekarang kita gunakan model itu sebagai pintu masuk query: `Buku::where(...)->get()`. Eloquent mengubah rangkaian metode PHP menjadi satu query SQL di belakang layar.

Materi ini menjadi jembatan antara **model (18)** dan **CRUD plus relasi (20)**. Kamu akan paham bagaimana data dibaca dan difilter dulu, sebelum belajar menulis, mengubah, dan menghapus data serta menarik data dari tabel yang berelasi. Tanpa kemampuan query yang baik, controller di materi 20 akan terasa melayang.

## 2. Fungsi & Kegunaan Utama dalam Laravel

Query Eloquent memberi kamu:

- **Cara ekspresif membaca data**: `Buku::tersedia()->latest()->get()` jauh lebih jelas daripada menulis `SELECT * FROM buku WHERE stok > 0 ORDER BY created_at DESC`.
- **Keamanan otomatis**: parameter otomatis di-binding, jadi pencarian dengan input user tidak rentan SQL injection.
- **Komposabilitas**: metode bisa di-chain tanpa batas — filter, sort, paginasi, agregasi dalam satu alur baca.
- **Paginasi & query kompleks yang hemat kode**: `paginate(12)` menghasilkan data plus navigasi halaman, dan `when()` membuat query yang menyesuaikan kondisi request tanpa if-else panjang.

Singkatnya: query Eloquent menggantikan kebiasaan menulis string SQL atau query manual yang sulit dibaca dan rawan error.

## 3. Contoh Kode & Implementasi (Real-world Example)

Studi kasus: halaman katalog buku dengan filter kombinasi — kata kunci, kategori, dan filter "hanya yang tersedia". Semua dibungkus paginasi.

**Lokasi file:** `app/Http/Controllers/BukuController.php`

```php
<?php

namespace App\Http\Controllers;

use App\Models\Buku;
use Illuminate\Http\Request;

class BukuController extends Controller
{
    /**
     * Katalog buku dengan filter kombinasi.
     * Semua filter bersifat opsional berkat when().
     */
    public function index(Request $request)
    {
        $buku = Buku::query()
            // when(): hanya tambah kondisi bila nilai dari request ada
            ->when($request->filled('q'), function ($query) use ($request) {
                // where(function) agar AND antar kolom, bukan OR yang merusak filter lain
                $query->where(function ($q) use ($request) {
                    $q->where('judul', 'like', "%{$request->q}%")
                      ->orWhere('pengarang', 'like', "%{$request->q}%");
                });
            })
            ->when($request->filled('kategori'), function ($query) use ($request) {
                $query->where('kategori', $request->kategori);
            })
            // pakai scope lokal dari materi 18
            ->when($request->boolean('tersedia'), fn ($query) => $query->tersedia())
            // urutkan terbaru dulu, lalu paginasi 12 per halaman
            ->latest()
            ->paginate(12)
            // denganQueryString: bawa parameter filter ke halaman berikutnya
            ->withQueryString();

        $kategoriList = Buku::distinct()->pluck('kategori');

        return view('buku.index', compact('buku', 'kategoriList'));
    }

    /**
     * Detail satu buku. findOrFail -> data tidak ada otomatis 404.
     */
    public function show(int $id)
    {
        $buku = Buku::findOrFail($id);

        return view('buku.show', compact('buku'));
    }
}
```

Contoh query lain yang sering dipakai di aplikasi perpustakaan:

```php
// Ambil satu record: find / findOrFail (WAJIB untuk detail)
$buku = Buku::findOrFail(10);          // 404 bila tidak ada
$buku = Buku::find(10);                // null bila tidak ada (sering bikin error di view)
$buku = Buku::first();                 // record pertama
$buku = Buku::where('isbn', '978...')->firstOrFail();
$buku = Buku::firstOrCreate(           // cari, kalau tidak ada langsung buat
    ['isbn' => '978-602-1234-56-7'],
    ['judul' => 'Laravel untuk Pemula', 'stok' => 5]
);

// Ambil banyak record
$buku = Buku::all();                   // HINDARI untuk data besar, memuat semua baris
$buku = Buku::where('kategori', 'Fiksi')->get();
$buku = Buku::tersedia()->latest()->limit(10)->get();

// Agregasi
$totalJudul  = Buku::count();                              // jumlah record
$hargaRata2  = Buku::avg('harga');                         // rata-rata harga
$hargaTermahal = Buku::max('harga');                       // harga tertinggi
$totalStok   = Buku::sum('stok');                          // total stok seluruh buku
$adaKosong   = Buku::where('stok', 0)->exists();           // true/false

// Local scope dari model 18
$buku = Buku::tersedia()->kategori('Fiksi')->get();

```

## 4. Analogi Sederhana

Masih di restoran kita:

- **Controller (koki)** memesan bahan ke gudang.
- **Staf gudang (Eloquent)** mendengarkan pesanan dan menerjemahkannya ke bahasa persediaan.

Contoh dialognya:

- Koki: "Ambilkan 5 kg terigu yang stoknya masih ada." -> staf menggrep rak dan mencatat kartu persediaan.
- Di kode: `Buku::tersedia()->paginate(12)`.

Bedanya dengan materi 18: kalau di materi 18 kita belajar **siapa staf gudang itu dan bagaimana dia menata kartu persediaan (model)**, di materi 19 ini kita belajar **macam-macam cara memesan (query)**. Koki yang baik tahu kapan memesan "semua bahan" (`all()`) dan kapan memesan "5 kg, kategori terigu, stok > 0, 12 per batch" (`paginate(12)`). Pesanan yang tidak spesifik (`all()`) bikin dapur kewalahan membawa ratusan kotak ke atas meja — sama seperti `all()` yang membebani server untuk data besar.

## 5. Kapan Harus Digunakan & Kasus Penggunaan (Use Cases)

- **Daftar katalog** -> `Buku::query()->filters()->paginate(12)->withQueryString()`.
- **Detail buku** -> `Buku::findOrFail($id)`.
- **Dropdown kategori unik** -> `Buku::distinct()->pluck('kategori')`.
- **Dashboard admin** -> agregasi: total buku, total stok, rata-rata harga (`count`, `sum`, `avg`).
- **Pencarian real-time** -> kombinasi `when()` + `like` + `paginate`.
- **Cek apakah ISBN sudah terdaftar** -> `Buku::where('isbn', $isbn)->exists()`.
- **Auto-create data referensi** -> `firstOrCreate` untuk kategori atau pengarang yang belum ada.

## 6. Poin-poin Penting & Best Practices

- **`paginate(12)` + `withQueryString()`** selalu untuk daftar data yang bisa banyak. `withQueryString()` memastikan filter tetap terbawa saat pindah halaman.
- **Hindari `all()`** di production untuk tabel yang besar; gunakan `paginate()` atau `limit()->get()`.
- **`findOrFail` / `firstOrFail`** untuk detail: data tidak ada langsung melempar 404, tidak perlu if-else manual.
- **`latest()`** (`orderBy('created_at', 'desc')`) untuk konten terbaru.
- **`when()`** untuk filter opsional dari request; jauh lebih bersih daripada if-else yang menumpuk.
- **Grouping `where(function) { ... }`** saat memakai `orWhere` bersama `and`, supaya logika kondisi tidak tercampur.
- **Gunakan local scope** untuk kondisi yang sering dipakai (misal `tersedia()`, `kategori()`).
- **`firstOrCreate`** untuk data yang seharusnya unik; hindari race condition dengan menambah unique constraint di migration.
- **Query Builder vs Eloquent**: keduanya bisa dipakai via model (`Buku::where(...)`, `DB::table('buku')->where(...)`). Untuk entitas domain dan relasi, pilih Eloquent karena hasilnya berupa objek model yang punya relasi, scope, dan casts.

## 7. Kesalahan Umum (Common Pitfalls & Anti-patterns)

- **Lupa `->get()`** -> query baru dijalankan; kode berikutnya menerima objek Builder, bukan collection. Hasilnya error di view seperti "Call to a member function ... on Builder".
- **Menggunakan `all()` untuk data besar** -> memuat seluruh tabel ke memori, halaman menjadi lambat.
- **`find()` tanpa cek null** -> view mengakses properti dari `null` dan error. Pakai `findOrFail` atau `optional()`.
- **Kolom tidak ada** -> salah ketik nama kolom (`tgl_pinjam` vs `tanggal_pinjam`). Cek migration dulu.
- **`orWhere` merusak filter lain** -> `where('kategori', 'X')->orWhere('judul', 'like', ...)` bisa mengembalikan buku dari kategori lain. Bungkus dengan `where(function ($q) { ... })`.
- **Filter + paginate tanpa `withQueryString()`** -> pindah halaman kehilangan parameter pencarian.
- **N+1 tidak terasa di query sederhana** -> masalah ini akan menyerang saat relasi ditambahkan di materi 20; antisipasi dengan `with()`.

### Troubleshooting cepat

- Hasil kosong padahal data ada -> cek apakah `deleted_at` terisi (soft delete menyembunyikan baris). 
- Pagination link rusak saat difilter -> tambahkan `->withQueryString()`.
- Error "Property [x] does not exist" -> cek casts dan nama kolom di migration.

## 8. Soal Latihan & Kunci Jawaban

### Tantangan

1. Di `BukuController@index`, tampilkan buku dengan filter kategori dan urutan termurah dulu, paginasi 15 per halaman, dan pertahankan query string saat pindah halaman. Tulis query Eloquent-nya.
2. Tulis query untuk mengecek: berapa jumlah total buku, rata-rata harga, dan apakah masih ada buku yang stoknya nol — dalam satu potong kode ringkas.

### Jawaban & Pembahasan

**Jawaban 1**

```php
$buku = Buku::where('kategori', $request->kategori)
    ->orderBy('harga')
    ->paginate(15)
    ->withQueryString();
```

Alur: `where('kategori', ...)` memfilter baris, `orderBy('harga')` mengurutkan termurah ke termahal (default ascending), `paginate(15)` mengambil 15 record per halaman beserta metadata navigasi, dan `withQueryString()` menyisipkan `?kategori=...` ke setiap link halaman agar filter tidak hilang.

**Jawaban 2**

```php
$totalBuku = Buku::count();
$hargaRata = Buku::avg('harga');
$adaStokNol = Buku::where('stok', 0)->exists();
```

Alur: `count()` menjalankan `SELECT COUNT(*)`, `avg('harga')` menjalankan `SELECT AVG(harga)`, dan `exists()` hanya mengembalikan boolean berdasarkan ada tidaknya baris dengan `stok = 0`. Ketiganya memanfaatkan SQL agregasi sehingga hanya mengirim hasil ringkas, bukan seluruh baris ke PHP — efisien untuk dashboard.
