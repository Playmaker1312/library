# 18. Eloquent Model — Dasar

Eloquent adalah ORM (Object Relational Mapping) bawaan Laravel yang membuat interaksi dengan database terasa seperti bekerja dengan objek PHP biasa. Di level ini kamu akan belajar bahwa 1 Model mewakili 1 tabel, sehingga operasi `SELECT`, `INSERT`, `UPDATE`, dan `DELETE` cukup ditulis sebagai metode PHP yang ekspresif.

## 1. Penjelasan Singkat & Konsep Dasar

Di Level 3 sebelumnya kamu sudah membuat struktur tabel lewat **Migration**, lalu mengisinya dengan **Seeder & Factory**. Tapi sejauh ini kamu masih membayangkan data sebagai baris-baris di MySQL. Nah, Eloquent Model adalah "jembatan" yang menghubungkan baris-baris itu dengan objek PHP. Setiap Model berpasangan dengan tabel sesuai konvensi: Model `Buku` otomatis memetakan ke tabel `buku`, Model `Anggota` ke `anggota`, dan Model `Peminjaman` ke `peminjaman`.

Konsep ini menutup bab "database & Eloquent" bagian pembuatan struktur. Materi 19 akan memanfaatkan model ini untuk menulis query (baca data), dan materi 20 untuk CRUD plus relasi antar tabel. Jadi anggap saja **Model adalah fondasi**; tanpa model yang rapi, query dan CRUD di materi berikutnya akan berantakan.

## 2. Fungsi & Kegunaan Utama dalam Laravel

Sebelum ORM, developer menulis query manual seperti `mysqli_query($conn, "SELECT * FROM buku WHERE stok > 0")` lalu memetakan hasilnya satu per satu ke array. Itu rentan typo, sulit dibaca, dan menguras tenaga untuk fitur sederhana.

Eloquent menyelesaikan masalah itu karena:

- **Jembatan PHP-MySQL**: kamu menulis PHP, Eloquent yang menerjemahkannya menjadi SQL di belakang layar.
- **Hindari query manual**: tidak ada lagi string SQL yang menggantung di dalam controller.
- **Ekspresif & aman**: kode seperti `Buku::tersedia()->get()` lebih mudah dibaca sekaligus otomatis terlindungi dari SQL injection karena Laravel melakukan binding parameter.
- **Bundling logika**: aturan bisnis seperti "buku tersedia" atau format harga bisa diletakkan di model, bukan berserakan di controller.

Intinya Eloquent mengubah cara berpikir dari "tabel dan kolom" menjadi "objek dan properti".

## 3. Contoh Kode & Implementasi (Real-world Example)

Studi kasus: model `Buku` untuk aplikasi Perpustakaan Digital, lengkap dengan fillable, casts, accessor, scope, soft delete, dan relasi awal ke `Peminjaman`.

**Buat model sekaligus migration, factory, dan seeder:**

```bash
php artisan make:model Buku -mfs
```

Penjelasan flag `-mfs`: `-m` membuat Migration, `-f` membuat Factory, `-s` membuat Seeder. Sekali perintah, empat file jadi.

**Lokasi file:** `app/Models/Buku.php`

```php
<?php

namespace App\Models;

use Illuminate\Database\Eloquent\Builder;
use Illuminate\Database\Eloquent\Factories\HasFactory;
use Illuminate\Database\Eloquent\Model;
use Illuminate\Database\Eloquent\SoftDeletes;

class Buku extends Model
{
    // HasFactory: agar bisa dipanggil Buku::factory() oleh seeder
    // SoftDeletes: hapus data secara "lembut", kolom deleted_at ikut terisi
    use HasFactory, SoftDeletes;

    /**
     * $fillable = daftar kolom yang BOLEH diisi lewat mass assignment
     * (create/update dengan array). Kolom di luar daftar ini otomatis
     * ditolak oleh Laravel untuk melindungi dari serangan mass assignment.
     */
    protected $fillable = [
        'judul',
        'pengarang',
        'isbn',
        'penerbit',
        'tahun',
        'harga',
        'stok',
        'kategori',
        'deskripsi',
        'sampul',
    ];

    /**
     * casts() mengubah tipe data kolom otomatis saat dibaca/ditulis.
     * Harga disimpan sebagai string di database tapi diakses sebagai float,
     * stok dan tahun diakses sebagai integer, deleted_at sebagai DateTime.
     */
    protected function casts(): array
    {
        return [
            'harga'      => 'decimal:2',
            'stok'       => 'integer',
            'tahun'      => 'integer',
            'deleted_at' => 'datetime',
        ];
    }

    /**
     * Accessor: membuat atribut virtual $buku->harga_format.
     * Format Rupiah tanpa harus menuliskan logicnya berulang di view.
     */
    public function getHargaFormatAttribute(): string
    {
        return 'Rp ' . number_format($this->harga, 0, ',', '.');
    }

    /**
     * Local scope: query yang bisa di-chain, misal Buku::tersedia()->get().
     * Menampung kondisi "buku yang masih bisa dipinjam".
     */
    public function scopeTersedia(Builder $query): Builder
    {
        return $query->where('stok', '>', 0);
    }

    /**
     * Scope filter kategori. Jika kategori kosong, lewati saja.
     */
    public function scopeKategori(Builder $query, ?string $kategori): Builder
    {
        return $query->when($kategori, fn ($q) => $q->where('kategori', $kategori));
    }

    /**
     * Scope pencarian sederhana: cocokkan judul atau pengarang.
     */
    public function scopePencarian(Builder $query, ?string $kata): Builder
    {
        return $query->when($kata, fn ($q) => $q->where('judul', 'like', "%{$kata}%")
            ->orWhere('pengarang', 'like', "%{$kata}%"));
    }

    /**
     * Relasi dasar: satu buku bisa dipinjam berkali-kali.
     * Dipakai penuh di materi 20 (CRUD & Relasi).
     */
    public function peminjaman()
    {
        return $this->hasMany(Peminjaman::class);
    }

    /**
     * Method bisnis murni (bukan query): cek apakah buku bisa dipinjam.
     * Dipanggil dari controller saat transaksi peminjaman.
     */
    public function tersedia(): bool
    {
        return $this->stok > 0;
    }

    /**
     * booted(): menampung model events. Contoh: setelah buku disimpan,
     * jalankan sesuatu (misal log atau kirim notifikasi). Ini contoh saja.
     */
    protected static function booted(): void
    {
        static::saved(function (Buku $buku) {
            // Contoh: log aktivitas. Ganti dengan kebutuhan asli.
            // activity()->log("Buku {$buku->judul} disimpan.");
        });

        static::deleted(function (Buku $buku) {
            // Berjalan juga saat soft delete, karena model tetap "dihapus".
            // activity()->log("Buku {$buku->judul} dihapus.");
        });
    }
}
```

**Lokasi file:** `app/Models/Peminjaman.php` (relasi balik, sekilas saja)

```php
<?php

namespace App\Models;

use Illuminate\Database\Eloquent\Model;

class Peminjaman extends Model
{
    protected $fillable = [
        'buku_id', 'anggota_id', 'tanggal_pinjam',
        'batas_kembali', 'tanggal_kembali', 'denda', 'status',
    ];

    public function buku()
    {
        return $this->belongsTo(Buku::class);
    }

    public function anggota()
    {
        return $this->belongsTo(Anggota::class);
    }
}
```

Model ini terhubung langsung ke tabel `buku` yang dibuat di materi Migration. Kolom `deleted_at` harus ada di migration tersebut supaya trait `SoftDeletes` bekerja (tambahkan `$table->softDeletes()`).

## 4. Analogi Sederhana

Bayangkan restoran besar:

- **Migration** = blueprint dapur. Berisi cetak biru rak, kulkas, dan tempat penyimpanan.
- **Seeder** = stok awal bahan yang ditaruh di gudang saat dapur baru dibuka.
- **Model/Eloquent** = gudang bahan makanan plus staf gudang yang fasih bahasa persediaan. Koki cukup bilang "5 kg terigu stok > 0", dan staf langsung mengambilkan sesuai permintaan tanpa koki perlu tahu di rak mana terigu berada. Eloquent bekerja seperti itu: kamu bilang `Buku::tersedia()->get()`, staf (Eloquent) yang menerjemahkannya jadi SQL dan mengembalikan objek Buku.
- **Controller** = koki yang memesan ke gudang. Koki tidak pernah turun ke gudang sendiri; dia cukup memesan lewat staf.

Yang penting digarisbawahi: **sebelum Eloquent ada**, koki mencatat persediaan manual di buku tulis sendiri — persis seperti array hardcode di controller. Sekarang gudang digital (database MySQL) dan staf gudang (Eloquent) yang mengurus semuanya. Koki jadi fokus memasak (logika bisnis), bukan mencatat stok.

## 5. Kapan Harus Digunakan & Kasus Penggunaan (Use Cases)

Gunakan Model Eloquent hampir di semua interaksi database:

- **Menampilkan daftar buku di halaman katalog** — `Buku::tersedia()->paginate(12)`.
- **Detail buku** — `Buku::findOrFail($id)` lalu tampilkan `$buku->harga_format`.
- **Cek stok sebelum transaksi peminjaman** — `if ($buku->tersedia()) { ... }`.
- **Pencarian buku** — `Buku::pencarian($request->q)->get()`.
- **Soft delete buku yang tidak layak** — `$buku->delete()` (baris tetap ada di tabel, hanya `deleted_at` terisi).
- **Menjaga konsistensi format harga/stok** — lewat `casts()` dan accessor.

Kalau query-nya sekali pakai dan tidak berhubungan dengan entitas, query builder masih oke. Tapi begitu menyangkut entitas domain (Buku, Anggota, Peminjaman), pakai Model.

## 6. Poin-poin Penting & Best Practices

- **`$fillable` WAJIB diisi.** Ini proteksi mass assignment. Jangan pernah pakai `$guarded = []` — itu membuka semua kolom, dan jika ada field `admin` di tabel, user bisa mengubah dirinya sendiri jadi admin lewat request.
- **Gunakan `casts()`** agar tipe data konsisten: `decimal:2` untuk harga, `integer` untuk stok/tahun, `datetime` untuk `deleted_at`.
- **Accessor & mutator** (`getXxxAttribute`, `setXxxAttribute`) untuk format atribut tanpa mengubah kolom asli.
- **Local scope** untuk kondisi yang dipakai berulang: `scopeTersedia`, `scopeKategori`, `scopePencarian`.
- **`with()` (eager loading)** untuk menghindari N+1 — akan dibahas detail di materi 20.
- **Gunakan `findOrFail` bukan `find`** supaya data tidak ada otomatis memicu 404.
- **Ikuti konvensi penamaan**: tabel plural (`buku`, `anggota`, `peminjaman`), kolom snake_case (`tanggal_pinjam`), foreign key `nama_tabel_id` (`buku_id`, `anggota_id`). Melanggar konvensi berarti harus menulis parameter ekstra di relasi.
- **`php artisan make:model Buku -mfs`** sekali jalan membuat Model + Migration + Factory + Seeder.
- **Model events (`booted()`)** untuk logika yang harus jalan otomatis saat `saved`/`deleted`, bukan ditulis manual di setiap controller.

## 7. Kesalahan Umum (Common Pitfalls & Anti-patterns)

- **Mass Assignment Exception.** Menjalankan `Buku::create($request->all())` padahal `$fillable` kosong. Solusi: isi `$fillable`, atau gunakan `$request->validated()`.
- **`$guarded = []`.** Terlihat praktis tapi berbahaya: semua kolom bisa diisi massal, membuka celah keamanan. Jangan pernah lakukan ini.
- **Soft delete tidak bekerja.** Biasanya karena migration tidak punya `$table->softDeletes()`, sehingga kolom `deleted_at` tidak ada.
- **Accessor tidak muncul.** Cek nama atribut: metode `getHargaFormatAttribute` menghasilkan `$buku->harga_format`, bukan `$buku->hargaFormat`.
- **Lupa menambah `use SoftDeletes;`** padahal ingin soft delete. Tanpa trait ini `delete()` akan menghapus baris permanen.
- **Menaruh logika query di controller.** Kondisi seperti "stok > 0" berulang di banyak tempat. Pindahkan ke scope.
- **Relasi salah nama.** Eloquent menebak foreign key berdasarkan konvensi: `hasMany(Peminjaman::class)` mencari `peminjaman.buku_id`. Kalau kolom aslinya beda (misal `kode_buku`), relasi gagal tanpa error yang jelas.
- **Menampilkan harga mentah di view** padahal sudah ada accessor `harga_format`.

### Troubleshooting cepat

- Error "Column not found" saat akses relasi -> cek nama foreign key sesuai konvensi.
- Data ikut terhapus permanen padahal ingin soft delete -> pastikan trait `SoftDeletes` dan kolom `deleted_at` ada.
- `create()` melempar exception Mass Assignment -> perbaiki `$fillable`.

## 8. Soal Latihan & Kunci Jawaban

### Tantangan

1. Tambahkan accessor `getNamaLengkapAttribute()` di model `Anggota` yang menggabungkan `nama_depan` dan `nama_belakang`, lalu tampilkan `$anggota->nama_lengkap`.
2. Buat scope `scopeKategori` di model `Buku` yang hanya menerima string kategori dan mengembalikan buku pada kategori tersebut. Beri contoh pemakaian dengan chain ke scope `tersedia`.

### Jawaban & Pembahasan

**Jawaban 1** — tambahkan di `app/Models/Anggota.php`:

```php
public function getNamaLengkapAttribute(): string
{
    return trim($this->nama_depan . ' ' . $this->nama_belakang);
}
```

Alur: accessor otomatis mengenali prefix `get`, nama tengah `NamaLengkap`, dan suffix `Attribute`. Laravel mengubah `NamaLengkap` menjadi snake_case `nama_lengkap` sehingga bisa diakses sebagai properti `$anggota->nama_lengkap`. `trim()` menjaga agar tidak ada spasi ganda bila salah satu nama kosong.

**Jawaban 2** — di `app/Models/Buku.php`:

```php
public function scopeKategori(Builder $query, string $kategori): Builder
{
    return $query->where('kategori', $kategori);
}
```

Pemakaian:

```php
$buku = Buku::tersedia()->kategori('Fiksi')->orderBy('judul')->get();
```

Alur: setiap scope menjadi `Builder`, sehingga bisa di-chain. `tersedia()` menambahkan kondisi `stok > 0`, lalu `kategori('Fiksi')` menambahkan `where kategori = 'Fiksi'`, dan `orderBy('judul')` mengurutkan hasil. Eloquent menyusunnya menjadi satu query SQL yang efisien.
