# 13. Membuat dan Menggunakan Controller

Di Level 1 kita menulis logika langsung di dalam closure route. Ini cepat untuk belajar, tapi begitu aplikasi mulai besar, route file akan penuh dan logika bercampur aduk. Controller hadir sebagai pemisah yang rapi: route cukup menunjuk "siapa yang menangani", dan controller yang bekerja. Di materi ini kita akan membangun `BukuController` lengkap untuk katalog buku Perpustakaan Digital — dengan data masih hardcode karena Eloquent baru dipelajari di Level 3.

## 1. Penjelasan Singkat & Konsep Dasar

Controller adalah kelas PHP yang berisi metode (method) untuk menangani request. Kalau di Level 1 route seperti ini:

```php
// routes/web.php (cara lama, Level 1)
Route::get('/buku', function () {
    return 'Daftar buku';
});
```

Maka dengan controller menjadi:

```php
// routes/web.php (cara baru, Level 2)
use App\Http\Controllers\BukuController;

Route::get('/buku', [BukuController::class, 'index']);
```

Route tidak lagi berisi logika, hanya "menu dan alamat tujuannya". Logika berpindah ke method `index()` di dalam `BukuController`.

Konsep ini nyambung langsung dengan Level 1 (sebelumnya logika di closure) dan Level 3 (data hardcode `$katalog` nanti akan diganti query Eloquent seperti `Buku::all()`).

## 2. Fungsi & Kegunaan Utama dalam Laravel

Kenapa tidak tetap pakai closure saja?

- **Scalability (mudah berkembang)** — route file jadi pendek dan hanya berisi "daftar menu", bukan isi masakan. Puluhan route tetap mudah dibaca.
- **Organisasi logika** — setiap bagian aplikasi punya controller sendiri: `BukuController`, `AnggotaController`, `PeminjamanController`. Tidak ada satu file raksasa yang isinya campur aduk.
- **Reusability** — logika filter katalog bisa dipakai dari route yang berbeda tanpa menulis ulang.
- **Konvensi terstruktur** — Laravel menyediakan pola `resource` yang sudah berisi 7 method standar (index, create, store, show, edit, update, destroy) sehingga alur CRUD konsisten antar aplikasi.
- **Mudah diuji & dirawat** — method controller yang kecil dan fokus lebih gampang dibaca, dibenahi, dan dites dibanding closure panjang.

## 3. Contoh Kode & Implementasi (Real-world Example)

Buat controller resource dengan perintah artisan:

```bash
php artisan make:controller BukuController --resource
```

Perintah ini menghasilkan file `app/Http/Controllers/BukuController.php` berisi 7 method kosong: `index`, `create`, `store`, `show`, `edit`, `update`, `destroy`.

Berikut isi lengkapnya untuk katalog buku:

```php
<?php

// app/Http/Controllers/BukuController.php
namespace App\Http\Controllers;

use Illuminate\Http\Request;
use Illuminate\View\View;
use Illuminate\Http\RedirectResponse;

class BukuController extends Controller
{
    // Data hardcode: sementara sebelum kita belajar Eloquent di Level 3.
    // Nanti array ini diganti dengan query model, mis. Buku::all().
    private array $katalog = [
        [
            'id' => 1,
            'judul' => 'Clean Code',
            'pengarang' => 'Robert C. Martin',
            'tahun' => 2008,
            'harga' => 250000,
            'stok' => 12,
            'kategori' => 'Teknologi',
        ],
        [
            'id' => 2,
            'judul' => 'Laravel: Up & Running',
            'pengarang' => 'Matt Stauffer',
            'tahun' => 2023,
            'harga' => 320000,
            'stok' => 8,
            'kategori' => 'Teknologi',
        ],
        [
            'id' => 3,
            'judul' => 'Laskar Pelangi',
            'pengarang' => 'Andrea Hirata',
            'tahun' => 2005,
            'harga' => 85000,
            'stok' => 20,
            'kategori' => 'Fiksi',
        ],
    ];

    // Daftar kategori, dipakai di halaman form tambah buku.
    private array $kategori = ['Teknologi', 'Fiksi', 'Sejarah', 'Anak', 'Pendidikan'];

    // Method index: menampilkan daftar buku, mendukung filter via query string.
    // Type-hint return View agar jelas kembaliannya view.
    public function index(Request $request): View
    {
        // Ambil nilai filter kategori dari query string (?kategori=Fiksi)
        $kategoriDipilih = $request->query('kategori');

        // Filter data jika ada; jika tidak, tampilkan semua buku.
        $buku = collect($this->katalog);

        if ($kategoriDipilih) {
            $buku = $buku->where('kategori', $kategoriDipilih);
        }

        return view('buku.index', [
            'buku' => $buku,
            'kategoriDipilih' => $kategoriDipilih,
        ]);
    }

    // Method show: menampilkan detail satu buku berdasarkan id.
    public function show(int $id): View
    {
        // Cari buku di array hardcode.
        $buku = collect($this->katalog)->firstWhere('id', $id);

        // Jika tidak ketemu, lempar 404. Nanti diganti abort saat Eloquent.
        abort_if(!$buku, 404, 'Buku tidak ditemukan');

        return view('buku.show', compact('buku'));
    }

    // Method create: menampilkan form tambah buku.
    public function create(): View
    {
        // Kirim daftar kategori agar bisa dirender jadi <select>.
        return view('buku.create', ['kategori' => $this->kategori]);
    }

    // Method store: menyimpan buku baru dari data form.
    public function store(Request $request): RedirectResponse
    {
        // Validasi dasar (validasi lanjutan pakai Form Request di Level 4).
        $validated = $request->validate([
            'judul' => 'required|string|max:255',
            'pengarang' => 'required|string|max:255',
            'tahun' => 'required|integer|min:1900|max:2026',
            'harga' => 'required|numeric|min:0',
            'stok' => 'required|integer|min:0',
            'kategori' => 'required|in:Teknologi,Fiksi,Sejarah,Anak,Pendidikan',
        ]);

        // Simpan ke database nanti di Level 3; saat ini cukup log atau abaikan.
        // Buku::create($validated); // <- inilah yang menggantikan baris ini.

        // Redirect kembali ke daftar buku dengan pesan sukses (flash session).
        return redirect()->route('buku.index')->with('sukses', 'Buku berhasil ditambahkan');
    }

    // Catatan: method edit, update, destroy belum diisi untuk menghemat ruang,
    // tapi strukturnya sama: edit() menampilkan form, update() menyimpan hasil edit,
    // destroy() menghapus data lalu redirect.
}
```

Registrasi route di `routes/web.php`:

```php
// routes/web.php
use App\Http\Controllers\BukuController;

// Route biasa dengan array [Controller::class, 'method']
Route::get('/buku', [BukuController::class, 'index']);

// Atau sekali jalan untuk seluruh CRUD (resource):
// Route::resource('buku', BukuController::class);
```

```php

<?php

    // Kelas induk semua controller.
    // Di sini nanti bisa ditambah middleware atau trait global.
}
```

Blade untuk menampilkan pesan sukses di `resources/views/buku/index.blade.php`:

```blade

    <div class="alert alert-sukses">{{ session('sukses') }}</div>
@endif
```

## 4. Analogi Sederhana

Bayangkan restoran. Pelayan (Route) menerima tamu dan membawa slip pesanan (Request) ke koki. Koki di dapur itu adalah **Controller**.

- **Controller = Koki.** Koki menerima slip pesanan, mengoordinasikan seluruh dapur, lalu memberi tahu pelayan "pesanan siap" (mengembalikan view/response). Koki tidak perlu menanam sayur sendiri di kebun belakang — begitu juga controller tidak boleh query database secara manual. Itu tugas gudang bahan (Model / Eloquent, Level 3).
- **Route = Menu & pelayan.** Menu menunjukkan "kalau minta /buku, itu pesanan indeks". Pelayan hanya mengantarkan, tidak memasak.
- **Model = Gudang bahan.** Menyimpan bahan baku (data buku). Koki meminta bahan ke gudang, bukan menanamnya.
- **Request = Slip pesanan.** Berisi apa yang diminta pelanggan: "kategori Fiksi", "buku id 2", dll.
- **Validasi = Koki mengecek order sebelum memasak.** "Kok stoknya habis?" / "Judul kosong, tolong dicek" — ditolak sebelum masuk proses.
- **Service = Bagian dapur khusus.** Misalnya pastry station yang khusus bikin kue. Kalau logika filter buku makin rumit, kita taruh di `BukuService` agar koki utama tidak kewalahan.

Perhatikan peran koki tadi: koki TIDAK menanam sayur (tidak query DB manual), koki menerima slip pesanan (Request), dan koki memberi tahu pelayan pesanan siap (return view/response). Semua pekerjaan koki adalah koordinasi, bukan eksekusi detail.

## 5. Kapan Harus Digunakan & Kasus Penggunaan (Use Cases)

Gunakan controller (bukan closure) ketika:

- **Endpoint CRUD standar** — daftar buku, form tambah, simpan, detail, edit, hapus. Cocok memakai `--resource` agar 7 method langsung terbentuk.
- **Endpoint dengan logika lebih dari 1 baris** — misalnya index katalog yang harus membaca query string, memfilter array, dan menyiapkan data untuk view.
- **Aplikasi yang terus bertumbuh** — project Perpustakaan Digital akan punya modul Anggota dan Peminjaman; setiap modul punya controller sendiri sehingga tim bisa bekerja paralel tanpa konflik di `web.php`.
- **Butuh pesan sukses setelah aksi** — pola `redirect()->route(...)->with('sukses', ...)` plus `session('sukses')` di Blade.
- **Perlu validasi input** — `$request->validate()` di method `store` menjaga data yang masuk.

## 6. Poin-poin Penting & Best Practices

- **Fat Model, Thin Controller.** Controller cukup ramping: ambil input, validasi, panggil service/model, return view. Logika bisnis yang berat ditaruh di service (Level 4/6) dan model (Level 3).
- **Controller hanya koordinasi.** Jangan menulis query DB manual di dalam controller. Itu tugas model Eloquent.
- **Type-hint return type.** Gunakan `: View`, `: RedirectResponse`, `: JsonResponse` agar kembalian method jelas dan PHP ikut memeriksa kesalahan.
- **Konvensi penamaan method.** `index` (daftar), `create` (form tambah), `store` (simpan), `show` (detail), `edit` (form ubah), `update` (simpan ubah), `destroy` (hapus). Ikuti selalu supaya konsisten.
- **Gunakan perintah artisan** untuk membuat controller:
  ```bash
  php artisan make:controller NamaController --resource --model=NamaModel
  ```
  `--model` otomatis menambahkan type-hint model di method (berguna di Level 3).
- **Return type view yang benar.** Halaman = `View`, redirect setelah aksi = `RedirectResponse`, API/JSON = `JsonResponse`. Jangan asal `return view()` untuk aksi simpan karena browser akan meminta halaman ulang.
- **abort(404) untuk data tidak ditemukan**, bukan `return redirect()` diam-diam, agar status HTTP benar.
- **Setiap controller extend `Controller`** induk bawaan Laravel.

## 7. Kesalahan Umum (Common Pitfalls & Anti-patterns)

- **Controller gemuk (fat controller).** Semua logika ditulis di controller sampai ratusan baris. Solusi: pindahkan logika ke service (`BukuService`) dan model (Level 3).
- **Duplicate logic antar method.** Filter katalog ditulis ulang di `index` dan juga di `show`. Solusi: buat method private helper atau taruh di `BukuService` / `BukuFilter`.
- **`abort` vs `find`.** Di level ini kita pakai `abort_if(!$buku, 404)`. Nanti dengan Eloquent jangan pakai `Buku::where(...)->first()` lalu `abort` manual terus-terusan — pakai `Buku::findOrFail($id)` yang otomatis melempar 404. (Rincian di Level 3.)
- **Lupa import class.** Error `Class "App\Http\Controllers\BukuController" not found` biasanya karena lupa `use App\Http\Controllers\BukuController;` di `web.php`, atau lupa `use Illuminate\Http\Request;` di controller. Cek bagian atas file.
- **Pakai `$this->validate()` vs Form Request.** Validasi inline di method (`$request->validate(...)`) cukup untuk kasus kecil, tapi begitu aturan dipakai di banyak tempat, pindah ke Form Request (Level 4) agar tidak duplikasi.
- **Mengembalikan view setelah aksi simpan.** Setelah `store`, harus `redirect()` (prinsip PRG — Post/Redirect/Get) agar refresh browser tidak mengirim ulang data form. Return view di sini salah.
- **Error umum saat mulai: "Target class [BukuController] does not exist"** — artinya controller belum dibuat atau nama di route tidak sesuai. Jalankan `php artisan make:controller BukuController` dulu.

## 8. Soal Latihan & Kunci Jawaban

### Tantangan

1. Buat `BukuController` dengan method `index` yang menerima filter `?kategori=` dan `?cari=` (cari di judul), menampilkan view `buku.index`. Registrasikan route `GET /buku`. Gunakan data hardcode `$katalog` dan type-hint return `View`.
2. Tambahkan method `show($id)` yang menampilkan detail buku, melempar 404 jika id tidak ada, dan method `store` yang memvalidasi `judul` (required, max 255) lalu redirect ke `buku.index` dengan pesan sukses.

### Jawaban & Pembahasan

```php
<?php

// app/Http/Controllers/BukuController.php
namespace App\Http\Controllers;

use Illuminate\Http\Request;
use Illuminate\View\View;
use Illuminate\Http\RedirectResponse;

class BukuController extends Controller
{
    private array $katalog = [
        ['id' => 1, 'judul' => 'Clean Code', 'pengarang' => 'Robert C. Martin', 'tahun' => 2008, 'harga' => 250000, 'stok' => 12, 'kategori' => 'Teknologi'],
        ['id' => 2, 'judul' => 'Laravel Up & Running', 'pengarang' => 'Matt Stauffer', 'tahun' => 2023, 'harga' => 320000, 'stok' => 8, 'kategori' => 'Teknologi'],
        ['id' => 3, 'judul' => 'Laskar Pelangi', 'pengarang' => 'Andrea Hirata', 'tahun' => 2005, 'harga' => 85000, 'stok' => 20, 'kategori' => 'Fiksi'],
    ];

    // Tantangan 1: filter kategori + pencarian judul.
    public function index(Request $request): View
    {
        $kategoriDipilih = $request->query('kategori');
        $kataCari = $request->query('cari');

        // Koleksi data untuk difilter.
        $buku = collect($this->katalog);

        if ($kategoriDipilih) {
            $buku = $buku->where('kategori', $kategoriDipilih);
        }

        if ($kataCari) {
            // contains: cek apakah judul mengandung kata kunci (case-insensitive).
            $buku = $buku->filter(fn ($item) =>
                str_contains(strtolower($item['judul']), strtolower($kataCari))
            );
        }

        return view('buku.index', [
            'buku' => $buku,
            'kategoriDipilih' => $kategoriDipilih,
            'kataCari' => $kataCari,
        ]);
    }

    // Tantangan 2a: detail buku + 404 jika tidak ada.
    public function show(int $id): View
    {
        $buku = collect($this->katalog)->firstWhere('id', $id);

        abort_if(!$buku, 404, 'Buku tidak ditemukan');

        return view('buku.show', compact('buku'));
    }

    // Tantangan 2b: validasi minimal lalu redirect dengan flash.
    public function store(Request $request): RedirectResponse
    {
        $validated = $request->validate([
            'judul' => 'required|string|max:255',
        ]);

        // Nanti: Buku::create($validated);

        return redirect()->route('buku.index')->with('sukses', 'Buku berhasil ditambahkan');
    }
}
```

```php
// routes/web.php
use App\Http\Controllers\BukuController;

Route::get('/buku', [BukuController::class, 'index']);
Route::get('/buku/{id}', [BukuController::class, 'show']);
Route::post('/buku', [BukuController::class, 'store']);
```

Penjelasan alur:

1. Pengguna membuka `GET /buku?kategori=Fiksi&cari=pelangi`. Route memanggil `BukuController@index`.
2. `index()` membaca query string lewat `$request->query(...)`, lalu memfilter koleksi `$katalog`.
3. Data hasil filter dikirim ke view `buku.index` bersama nilai filter yang sedang aktif (agar checkbox/select tetap tercentang).
4. Method `show` memakai `firstWhere` pada array; jika tidak ketemu, `abort_if` menghentikan proses dengan status 404.
5. Method `store` memvalidasi input. Kalau lolos, redirect ke daftar buku membawa flash `sukses` yang dirender Blade. Ketika Eloquent hadir di Level 3, `collect($this->katalog)->firstWhere(...)` cukup diganti `Buku::findOrFail($id)` dan array `$katalog` dibuang.
