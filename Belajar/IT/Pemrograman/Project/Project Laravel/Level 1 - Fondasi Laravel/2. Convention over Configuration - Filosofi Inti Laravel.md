# 2. Convention over Configuration — Filosofi Inti Laravel

Kalau di materi pertama kamu sudah paham apa yang Laravel gantikan dari PHP native, pertanyaan berikutnya pasti muncul: "kenapa Laravel bisa langsung tahu harus menghubungi controller mana, tanpa konfigurasi?" Jawabannya ada di satu filosofi: **Convention over Configuration**. Ini bukan sekadar gaya, tapi keputusan desain yang membuat kamu menulis jauh lebih sedikit kode. Di materi ini kita bedah cara kerjanya, lalu kita siap melangkah ke instalasi Laravel di materi berikutnya.

## 1. Penjelasan Singkat & Konsep Dasar

**Convention over Configuration (CoC)** artinya: framework punya aturan baku ("konvensi") soal bagaimana sesuatu harus diberi nama dan diletakkan. Kalau kamu mengikuti aturan itu, framework langsung tahu maksudmu **tanpa kamu harus menyuruh-nyuruh lewat konfigurasi**. Konfigurasi baru kamu tulis ketika kamu menyimpang dari konvensi.

Contoh paling nyata di Laravel:

- Model `Buku` secara otomatis terhubung ke tabel `buku` di database.
- Model `AnggotaPustaka` terhubung ke tabel `anggota_pustakas` (nama tabel = bentuk jamak dari nama model, dengan aturan pluralisasi bahasa Inggris).
- Method controller bernama `index/create/store/show/edit/update/destroy` otomatis terpetakan ke 7 route resource standar.
- File disimpan di lokasi yang sudah ditentukan: model di `app/Models`, controller di `app/Http/Controllers`, view di `resources/views`, migration di `database/migrations`, seeder di `database/seeders`.

Karena materi ini berdiri setelah "Apa yang Laravel Gantikan dari PHP Native", bayangkan ini: di PHP native kamu harus menulis konfigurasi sendiri untuk semuanya. Di Laravel, **konvensi menggantikan konfigurasi**, jadi kamu kerja lebih sedikit. Dan di materi berikutnya, Instalasi Laravel akan terasa ringan karena kamu sudah tahu ke mana setiap file akan diletakkan.

## 2. Fungsi & Kegunaan Utama dalam Laravel

CoC ada untuk menyelesaikan tiga masalah:

- **Menghilangkan keputusan remeh** — kamu tidak perlu berpikir "file ini taruh di mana? fungsi ini namanya apa?". Jawabannya sudah ada, dan konsisten di semua proyek Laravel.
- **Kolaborasi antar developer** — karena semua orang mengikuti konvensi yang sama, pindah dari satu proyek Laravel ke proyek lain terasa familier. Tidak ada "cara aneh" masing-masing developer.
- **Lebih sedikit kode = lebih sedikit bug** — tiap baris konfigurasi adalah kesempatan untuk salah ketik. CoC memangkas konfigurasi, sehingga permukaan error ikut mengecil.

Dalam aplikasi **Perpustakaan Digital**, CoC membuat hal-hal ini berjalan otomatis:

- `app/Models/Buku.php` -> tabel `buku`.
- `app/Models/AnggotaPustaka.php` -> tabel `anggota_pustakas`.
- Controller `BukuController` dengan method resource -> 7 route sekaligus via `Route::resource('buku', BukuController::class)`.
- Migration di `database/migrations/` -> skema tabel yang ikut dijalankan `php artisan migrate`.

## 3. Contoh Kode & Implementasi (Real-world Example)

### Model dan koneksi tabel otomatis

File `app/Models/Buku.php` — tidak ada satu pun baris yang menyebut tabel:

```php
<?php

namespace App\Models;

use Illuminate\Database\Eloquent\Model;

class Buku extends Model
{
    // Laravel menyimpulkan tabel 'buku' dari nama class 'Buku' (tanpa namespace)
    // primary key otomatis 'id' (incrementing integer)

    protected $fillable = [
        'judul',
        'pengarang',
        'isbn',
        'penerbit',
        'tahun',
        'harga',
        'stok',
        'kategori',
        'deskripsi',
        'sampul',
    ];
}
```

Model `AnggotaPustaka` di `app/Models/AnggotaPustaka.php`:

```php
<?php

namespace App\Models;

use Illuminate\Database\Eloquent\Model;

class AnggotaPustaka extends Model
{
    // Konvensi pluralisasi: nama model 'AnggotaPustaka'
    // -> tabel 'anggota_pustakas' (snake_case + jamak)
    // Laravel melakukan ini otomatis, tidak perlu dikonfigurasi manual
}
```

### 7 route resource dari satu baris

File `routes/web.php` — satu baris menghasilkan 7 route:

```php
<?php

use App\Http\Controllers\BukuController;
use Illuminate\Support\Facades\Route;

// Membuat 7 route sekaligus dengan konvensi REST:
// GET  /buku            -> index   (daftar)
// GET  /buku/create     -> create  (form tambah)
// POST /buku            -> store   (simpan baru)
// GET  /buku/{buku}     -> show    (detail)
// GET  /buku/{buku}/edit-> edit    (form ubah)
// PUT/PATCH /buku/{buku}-> update  (simpan ubah)
// DELETE /buku/{buku}   -> destroy (hapus)
Route::resource('buku', BukuController::class);
```

Jalankan `php artisan route:list` untuk melihat 7 baris route itu terdaftar lengkap — inilah bukti CoC bekerja.

### Kapan harus override konvensi?

Tidak semua kasus mengikuti konvensi. Kamu bisa menyimpang dengan properti tertentu:

```php
<?php

namespace App\Models;

use Illuminate\Database\Eloquent\Model;

class Buku extends Model
{
    // Override nama tabel jika tabelmu memang tidak mengikuti konvensi
    protected $table = 'koleksi_buku';

    // Override primary key jika bukan 'id'
    protected $primaryKey = 'kode_buku';

    // Override tipe key jika primary key bukan integer increment
    public $incrementing = false;
    protected $keyType = 'string';
}
```

Aturan praktis: **ikuti konvensi selama tidak ada alasan kuat**, dan override hanya ketika memang dibutuhkan (misal tabel warisan dari sistem lama yang tidak bisa diubah).

### Migration sesuai konvensi

File `database/migrations/xxxx_create_buku_table.php` (dibuat via `php artisan make:migration create_buku_table --table=buku`):

```php
<?php

use Illuminate\Database\Migrations\Migration;
use Illuminate\Database\Schema\Blueprint;
use Illuminate\Support\Facades\Schema;

return new class extends Migration
{
    public function up(): void
    {
        Schema::create('buku', function (Blueprint $table) {
            $table->id();                      // primary key 'id' (konvensi)
            $table->string('judul');
            $table->string('pengarang');
            $table->string('isbn')->unique();
            $table->string('penerbit');
            $table->year('tahun');
            $table->decimal('harga', 10, 2);
            $table->unsignedInteger('stok')->default(0);
            $table->string('kategori');
            $table->text('deskripsi')->nullable();
            $table->string('sampul')->nullable();  // path gambar sampul
            $table->timestamps();                  // created_at & updated_at
        });
    }

    public function down(): void
    {
        Schema::dropIfExists('buku');
    }
};
```

## 4. Analogi Sederhana

Masih dengan restoran favorit kita.

- PHP native = dapur yang **setiap hidangan harus dijelaskan resepnya dari nol** setiap kali ada pesanan masuk, bahkan untuk menu yang sama. Memakan waktu dan rawan beda rasa antar koki.
- Convention over Configuration = dapur yang punya **Resep/SOP standar tiap hidangan (Action Pattern)** dan standar letak bahan di gudang. Koki (Controller) cukup tahu "nama hidangan" (nama route), langsung mengikuti alur standar (method index/create/store/...) tanpa ditanya ulang. Kalau ada hidangan spesial, baru diberi catatan tambahan (override).

Tabel analogi yang relevan untuk materi ini:

| Konsep Laravel | Analogi Restoran |
|---|---|
| Route | Menu & pelayan restoran (cara pesanan sampai ke dapur) |
| Controller | Koki |
| Model/Eloquent | Gudang bahan makanan |
| Migration | Blueprint renovasi dapur (versi kontrak) |
| Action Pattern | Resep/SOP standar tiap hidangan |

CoC itu seperti "SOP standar": kamu tidak perlu menjelaskan ke staf bagaimana menyajikan nasi — semua sudah tahu, karena memang begitulah aturan dapur ini.

## 5. Kapan Harus Digunakan & Kasus Penggunaan (Use Cases)

- **Pembuatan CRUD standar** — fitur CRUD adalah 90% aplikasi perpustakaan: kelola Buku, Anggota, Peminjaman. Gunakan `Route::resource` + controller resource. Itu kasus CoC paling nyata.
- **Nama file & lokasi** — selalu ikuti lokasi standar Laravel 11. Jangan taruh controller di `app/Services` atau view di akar proyek.
- **Penamaan tabel** — ikuti pluralisasi otomatis; gunakan override `protected $table` hanya untuk tabel legacy atau kasus khusus.
- **Model Peminjaman** — relasinya juga otomatis: `Peminjaman` punya `buku_id` dan `anggota_id`; dengan menamai method relasi sesuai konvensi (`belongsTo(Buku::class)`) Laravel menyimpulkan foreign key-nya sendiri.
- **Tidak digunakan saat** kamu punya aturan bisnis non-standar: tabel dari sistem lama, primary key non-integer, atau endpoint yang sengaja menyimpang dari REST — di situ override konfigurasi baru dibenarkan.

## 6. Poin-poin Penting & Best Practices

- **Model = singular, tabel = plural**: `Buku` -> `buku`, `AnggotaPustaka` -> `anggota_pustakas`, `Peminjaman` -> `peminjamans`.
- **Method resource standar**: `index`, `create`, `store`, `show`, `edit`, `update`, `destroy`. Urutannya sudah diatur Laravel.
- **Lokasi standar Laravel 11**:
  - `app/Models/` untuk model.
  - `app/Http/Controllers/` untuk controller.
  - `resources/views/` untuk Blade view.
  - `database/migrations/` untuk migration.
  - `database/seeders/` untuk seeder.
- **Override yang umum**: `protected $table`, `protected $primaryKey`, `public $incrementing`, `protected $keyType`. Pakai seperlunya.
- **Konvensi nama file migration**: `xxxxx_create_buku_table.php` — berurut oleh timestamp, dan `php artisan migrate` menjalankannya sesuai urutan.
- **Best practice**: buat controller dengan `php artisan make:controller BukuController --resource` agar kerangka 7 method langsung ter-generate. Ini CoC dalam bentuk perintah.
- **Fat Model Thin Controller**: simpan logika domain di Model (misal method `tandaiTerlambat()` pada `Peminjaman`), biarkan controller tipis.

## 7. Kesalahan Umum (Common Pitfalls & Anti-patterns)

- **Model `Buku` tapi tabel ternyata `bukus`** — jika kamu tidak mengikuti konvensi dan lupa override, Eloquent akan mencari tabel yang tidak ada. Error umum: `Table "perpustakaan.bukus" doesn't exist`. Solusi: pastikan tabel bernama `buku`, atau set `protected $table = 'buku'`.
- **Method controller tidak cocok dengan route resource** — `Route::resource('buku', BukuController::class)` akan error `Target class ... does not exist` atau `Method not allowed` jika method resource tidak lengkap. Jalankan `php artisan route:list` untuk memverifikasi.
- **Meletakkan file di lokasi salah** — controller di folder aneh tidak akan ter-detect oleh autoload. Simpan di lokasi standar, lalu jalankan `composer dump-autoload` jika perlu.
- **Over-konfigurasi** — menulis `$table`/`$primaryKey` padahal konvensi sudah benar. Ini anti-pattern: konfigurasi berlebih justru membuat kode bising dan sulit dibaca.
- **Nama migration tidak konsisten** — jika penamaan tabel di migration tidak sinkron dengan nama model, `php artisan migrate` tetap jalan tapi query Eloquent gagal. Selalu sinkronkan konvensi nama.
- **Troubleshooting**:
  - `Table "xxx" doesn't exist` -> cek pluralisasi atau `protected $table`.
  - `No query results for model` di show -> cek apakah primary key sesuai (`$primaryKey`).
  - Route resource error -> `php artisan route:list` untuk lihat apakah 7 route terdaftar.

## 8. Soal Latihan & Kunci Jawaban

### Tantangan

1. Buat model `Anggota` dan migration tabel untuk anggota (kolom: nama, alamat, no_hp, email). Kemudian buat controller resource-nya dan daftarkan 7 route resource di `routes/web.php`. Verifikasi dengan `php artisan route:list`.
2. Buat model `Peminjaman` beserta relasi `belongsTo` ke `Buku` dan `Anggota`, lengkap dengan kolom `tanggal_pinjam`, `batas_kembali`, `tanggal_kembali`, `denda`, `status`. Sebutkan nama tabel otomatis yang disimpulkan Laravel dan apa yang kamu override jika tabelnya diberi nama `peminjaman_buku`.

### Jawaban & Pembahasan

Soal 1 — jalankan perintah generate:

```bash
# generate model + migration + resource controller sekaligus
php artisan make:model Anggota -m -c --resource
```

Model `app/Models/Anggota.php`:

```php
<?php

namespace App\Models;

use Illuminate\Database\Eloquent\Model;

class Anggota extends Model
{
    protected $fillable = [
        'nama',
        'alamat',
        'no_hp',
        'email',
    ];
}
```

Migration `database/migrations/xxxxx_create_anggota_table.php`:

```php
<?php

use Illuminate\Database\Migrations\Migration;
use Illuminate\Database\Schema\Blueprint;
use Illuminate\Support\Facades\Schema;

return new class extends Migration
{
    public function up(): void
    {
        Schema::create('anggota', function (Blueprint $table) {
            $table->id();
            $table->string('nama');
            $table->text('alamat');
            $table->string('no_hp');
            $table->string('email')->unique();
            $table->timestamps();
        });
    }

    public function down(): void
    {
        Schema::dropIfExists('anggota');
    }
};
```

Route di `routes/web.php`:

```php
<?php

use App\Http\Controllers\AnggotaController;
use Illuminate\Support\Facades\Route;

Route::resource('anggota', AnggotaController::class);
```

`php artisan route:list` akan menampilkan 7 route `/anggota` (index, create, store, show, edit, update, destroy). Alurnya: browser meminta URL -> Route Matching menemukan pola resource -> memetakan ke method controller sesuai konvensi -> Eloquent mengakses tabel `anggota`. Tanpa CoC, kamu harus menulis 7 baris route dan 7 method manual yang isinya hampir sama.

Soal 2 — model `app/Models/Peminjaman.php`:

```php
<?php

namespace App\Models;

use Illuminate\Database\Eloquent\Model;

class Peminjaman extends Model
{
    protected $fillable = [
        'buku_id',
        'anggota_id',
        'tanggal_pinjam',
        'batas_kembali',
        'tanggal_kembali',
        'denda',
        'status',
    ];

    // Konvensi relasi: nama method = nama model tujuan (lowercase/singular)
    public function buku()
    {
        // Laravel menyimpulkan foreign key 'buku_id' dari nama method 'buku'
        return $this->belongsTo(Buku::class);
    }

    public function anggota()
    {
        // foreign key 'anggota_id' disimpulkan otomatis
        return $this->belongsTo(Anggota::class);
    }
}
```

Nama tabel otomatis yang disimpulkan Laravel dari model `Peminjaman` adalah **`peminjamans`** (plural). Jika tabelmu bernama `peminjaman_buku` (menyimpang dari konvensi), kamu override:

```php
class Peminjaman extends Model
{
    // Override karena nama tabel tidak mengikuti pluralisasi otomatis
    protected $table = 'peminjaman_buku';
}
```

Alurnya: dengan konvensi, `Peminjaman::all()` membaca tabel `peminjamans`, dan `$peminjaman->buku` memanggil relasi `belongsTo` yang otomatis mencocokkan `peminjaman_buku.buku_id` ke `buku.id`. Semua ini tanpa satu baris pun konfigurasi SQL manual — itulah kekuatan Convention over Configuration.

Latihan selesai, kamu sudah menguasai filosofi inti Laravel. Berikutnya kita siap masuk ke materi Instalasi Laravel, dan semua lokasi file serta nama-nama ini akan langsung terasa familier.
