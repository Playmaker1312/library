# 7. Route Dasar dan Named Route

Setelah instalasi dan konfigurasi `.env`, sekarang kita masuk ke "pintu masuk" aplikasi: route. Route menentukan URL mana yang bisa diakses pengguna dan ke mana permintaan diteruskan. Di materi ini kita akan membahas route dasar, parameter, constraint, dan named route yang menjadi fondasi sebelum belajar Blade di materi berikutnya.

## 1. Penjelasan Singkat & Konsep Dasar

Route adalah jembatan antara browser pengguna dan kode aplikasi kita. Saat pengguna mengetik `https://perpustakaan.test/buku`, Laravel membaca URL tersebut, mencocokkannya dengan daftar route di `routes/web.php`, lalu menjalankan logika yang terhubung.

Laravel mendukung beberapa method HTTP:

- `Route::get()` -- untuk mengambil data / menampilkan halaman
- `Route::post()` -- untuk mengirim data baru (membuat)
- `Route::put()` -- untuk memperbarui data secara penuh
- `Route::patch()` -- untuk memperbarui sebagian data
- `Route::delete()` -- untuk menghapus data

Hubungan dengan materi lain: setelah URL cocok, permintaan diteruskan ke **Controller** (materi Level 2) atau langsung ke **closure** jika logikanya sederhana. Hasilnya nanti dirender oleh **Blade** (materi berikutnya). Jadi alurnya: URL -> Route -> Controller/Closure -> Blade.

## 2. Fungsi & Kegunaan Utama dalam Laravel

Tanpa route, aplikasi tidak bisa diakses sama sekali. Route menyelesaikan beberapa masalah:

1. **Pemetaan URL ke logika** -- satu URL hanya memiliki satu "tugas".
2. **Kontrol method HTTP** -- Laravel memastikan `POST`, `PUT`, `DELETE` tidak bisa diakses lewat `GET` biasa, sehingga operasi yang mengubah data lebih aman.
3. **Ekstraksi parameter dinamis** -- URL seperti `/buku/5` bisa ditangkap nilai `5`-nya.
4. **Validasi format parameter** -- constraint seperti `{id}` hanya angka.
5. **Nama yang stabil** -- nama route tidak berubah walau URL berubah, sehingga kode di view tetap aman.

## 3. Contoh Kode & Implementasi (Real-world Example)

Semua contoh berikut berada di **`routes/web.php`** pada proyek "Perpustakaan Digital".

```php
<?php

use Illuminate\Support\Facades\Route;
use App\Http\Controllers\BukuController;
use App\Http\Controllers\TentangController;
use App\Http\Controllers\KategoriController;

// ===== Route dengan Closure (logika sederhana) =====
// Beranda aplikasi
Route::get('/', function () {
    return view('beranda');
});

// Halaman tentang -- tetap pakai closure untuk redirect singkat
Route::redirect('/info', '/tentang');

// Fallback route -- menangkap URL yang tidak cocok (jangan lupa diletakkan paling akhir)
Route::fallback(function () {
    return response('Halaman tidak ditemukan', 404);
});

// ===== Route ke Controller (logika lebih kompleks) =====
// Katalog buku utama
Route::get('/buku', [BukuController::class, 'index'])
    ->name('buku.index');

// Detail buku -- parameter {id} menangkap angka di URL
Route::get('/buku/{id}', [BukuController::class, 'show'])
    ->name('buku.show')
    ->where('id', '[0-9]+'); // constraint: id hanya boleh angka

// Detail buku versi slug (nama lengkap yang ramah URL)
Route::get('/buku/{slug}/detail', [BukuController::class, 'detailBySlug'])
    ->name('buku.slug')
    ->where('slug', '[a-z0-9\-]+');

// Halaman kategori -- tanpa constraint karena slug memang teks
Route::get('/kategori/{slug}', [KategoriController::class, 'show'])
    ->name('kategori.show');

// Halaman tentang dari controller (logika bisa lebih besar)
Route::get('/tentang', [TentangController::class, 'index'])
    ->name('tentang.index');
```

### Membuat URL dari nama route

Salah satu keunggulan named route adalah kita tidak perlu menulis URL secara manual. Di dalam Blade (materi berikutnya) kita cukup menulis:

```blade
{{-- Tanpa parameter --}}
<a href="{{ route('buku.index') }}">Daftar Buku</a>

{{-- Dengan parameter (cara panjang) --}}
<a href="{{ route('buku.show', ['id' => 5]) }}">Detail Buku 5</a>

{{-- Dengan parameter (shortcut, tanpa key) --}}
<a href="{{ route('buku.show', 5) }}">Detail Buku 5</a>
```

Contoh pengalihan setelah aksi (akan dipakai penuh di Level 2 saat belajar form & controller):

```php
return redirect()->route('buku.index'); // arahkan kembali ke daftar buku
```

## 4. Analogi Sederhana

Bayangkan restoran. **Route adalah Menu sekaligus Pelayan.**

Menu menentukan apa saja yang bisa dipesan -- itulah daftar URL yang tersedia. Pelayan adalah jembatan: pengunjung menyebut "saya mau buku nomor 5", pelayan membaca pesanan itu (route mencocokkan URL `/buku/5`), lalu membawanya ke dapur. **Controller adalah Koki** -- dialah yang benar-benar menyiapkan hidangan (mengambil data buku dari database, menyiapkan respons). Setelah koki selesai, pelayan membawa hasilnya kembali ke meja pengunjung (browser merender halaman).

Nama route itu seperti nomor meja atau nama panggilan pelanggan: kita bisa memindahkan meja (mengubah URL), tapi selama pelayan tetap mengenali "Pak Buku 5", pesanan tetap sampai dengan benar.

Perhatikan: jika menu tidak mencantumkan `/buku/5`, pelayan akan bilang "maaf, menu tidak ada" (404). Itulah kerja fallback route di bagian paling bawah menu.

## 5. Kapan Harus Digunakan & Kasus Penggunaan (Use Cases)

| Skenario | Route yang Tepat |
|---|---|
| Menampilkan beranda / halaman statis | `Route::get()` dengan closure atau view |
| Membuka detail buku dari daftar | `Route::get('/buku/{id}')` dengan constraint angka |
| Katalog per kategori ramah SEO | `Route::get('/kategori/{slug}')` tanpa constraint angka |
| Mengalihkan URL lama ke baru | `Route::redirect('/info', '/tentang')` |
| URL yang tidak dikenal | `Route::fallback()` paling akhir |
| URL yang akan dipakai banyak view | Selalu beri `->name()` agar mudah dipanggil |

Route wajib diberi nama (`->name()`) setiap kali URL-nya akan ditautkan dari lebih dari satu tempat -- ini mencegah URL dihapal manual dan memudahkan refactor.

## 6. Poin-poin Penting & Best Practices

- **Selalu beri nama route** yang dipakai di view: `->name('buku.index')`. URL bisa berubah, nama tidak.
- **Konvensi nama**: dot-notation berbasis resource noun, misalnya `buku.index`, `buku.show`, `kategori.show`, `tentang.index`.
- **Konvensi URL**: kebab-case untuk slug, misalnya `/katalog-buku`, dan gunakan `{id}` untuk primary key.
- **Gunakan closure hanya untuk logika sederhana** (1-3 baris seperti `view()` atau `redirect()`). Logika yang melibatkan database, validasi, atau banyak langkah harus dipindah ke controller.
- **Letakkan route paling spesifik di atas** yang lebih umum. Contoh: `/buku/{slug}/detail` harus dideklarasikan sebelum route yang bisa menelan slug tersebut.
- **Constraint itu wajib** untuk `{id}` angka agar URL seperti `/buku/abc` tidak lolos ke controller.
- **Cek daftar route** kapan saja dengan:
  ```bash
  php artisan route:list
  ```
  Gunakan `php artisan route:list --path=buku` untuk filter berdasarkan URL.
- `redirect()->route('buku.index')` akan dipakai intensif di Level 2 setelah form submit.

## 7. Kesalahan Umum (Common Pitfalls & Anti-patterns)

1. **404 "Page not found" padahal route ada**
   - Pastikan route benar-benar berada di `routes/web.php` dan tidak di-nested dengan typo.
   - Cek dengan `php artisan route:list`. Jika tidak muncul, kemungkinan route dideklarasikan di dalam group yang salah.

2. **Salah nama route di `route('buku.indx')`**
   - Akan muncul error `Route [buku.indx] not defined`. Cek ejaan dengan `php artisan route:list --name=buku`.

3. **Duplikasi route untuk method yang sama**
   - Laravel akan memakai route yang pertama kali ditemukan. Route kedua tidak akan pernah terpanggil. Hapus yang tidak perlu.

4. **Lupa constraint `->where('id', '[0-9]+')`**
   - URL seperti `/buku/abc` tetap cocok dengan `/buku/{id}`, membuat controller menerima string. Tambahkan constraint atau ubah parameter menjadi `{slug}`.

5. **Salah urutan route**
   - `Route::get('/buku/{slug}')` yang dideklarasikan sebelum `/buku/terlaris` akan menangkap kata "terlaris" sebagai slug. Letakkan route statis lebih dulu, atau buat lebih spesifik.

6. **`Route::fallback()` tidak bekerja**
   - Fallback hanya berfungsi jika diletakkan di paling bawah. Route apa pun setelah fallback tidak akan pernah dijalankan.

7. **Lupa import controller**
   - Error `Class "App\Http\Controllers\BukuController" not found` biasanya karena lupa `use App\Http\Controllers\BukuController;` di bagian atas `routes/web.php`.

## 8. Soal Latihan & Kunci Jawaban

### Tantangan

1. Buat route untuk halaman "katalog buku" yang memakai `BukuController@index` dengan nama `buku.index`, lalu buat route detail buku dengan parameter `{id}` bernama `buku.show` yang hanya menerima angka. Tambahkan route fallback 404 di paling akhir.

2. Dari sebuah view, buat tautan ke halaman detail buku id 7 tanpa menulis URL secara manual, dan buat redirect dari URL `/perpustakaan` menuju route `buku.index`.

### Jawaban & Pembahasan

**Soal 1 -- deklarasi route:**

```php
use App\Http\Controllers\BukuController;

// Katalog buku
Route::get('/buku', [BukuController::class, 'index'])
    ->name('buku.index');

// Detail buku -- hanya angka
Route::get('/buku/{id}', [BukuController::class, 'show'])
    ->name('buku.show')
    ->where('id', '[0-9]+');

// Fallback harus paling akhir
Route::fallback(function () {
    return response('Halaman tidak ditemukan', 404);
});
```

**Alur:** saat pengguna mengakses `/buku`, Laravel mencocokkan ke route pertama lalu memanggil method `index` pada `BukuController`. Saat mengakses `/buku/7`, parameter `7` ditangkap `{id}`, lolos constraint angka, lalu diteruskan ke `show(7)`. URL `/buku/abc` tidak lolos constraint, dan karena tidak ada route lain yang cocok, Laravel jatuh ke fallback 404.

**Soal 2 -- tautan dan redirect:**

```blade
{{-- Memakai shortcut tanpa key --}}
<a href="{{ route('buku.show', 7) }}">Detail Buku 7</a>

{{-- Alternatif dengan key eksplisit --}}
<a href="{{ route('buku.show', ['id' => 7]) }}">Detail Buku 7</a>
```

Redirect dari URL lama:

```php
// Dari URL /perpustakaan menuju route bernama buku.index
Route::redirect('/perpustakaan', route('buku.index'));
```

**Alur:** `route('buku.show', 7)` menghasilkan `/buku/7` tanpa harus menulis string URL. `Route::redirect` mengembalikan respons 302 ke tujuan yang dihitung dari nama route -- jika URL `buku.index` nanti berubah, redirect ini otomatis ikut berubah, inilah manfaat utama named route.
