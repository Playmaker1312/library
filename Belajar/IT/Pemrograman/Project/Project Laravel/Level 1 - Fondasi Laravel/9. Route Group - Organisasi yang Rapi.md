# 9. Route Group — Organisasi yang Rapi

Saat aplikasi makin besar, `routes/web.php` bisa penuh sesak dengan route admin, member, tamu, dan API yang campur aduk. Route group memungkinkan kita mengelompokkan route yang berbagi prefix URL, middleware, dan awalan nama dalam satu blok. Ini materi terakhir di Level 1 -- setelah ini kita sudah siap masuk ke Blade.

## 1. Penjelasan Singkat & Konsep Dasar

Route group adalah cara membungkus beberapa route sekaligus dengan atribut yang sama: **prefix** (awalan URL), **middleware** (filter sebelum route dijalankan), dan **name** (awalan nama route). Atribut ini bisa dikombinasikan secara berantai (chained).

Contoh: seluruh route area admin pasti diawali `/admin`, harus dilindungi autentikasi, dan dinamai `admin.*`. Daripada menulisnya berulang di tiap route, kita buat satu group.

Konsep ini menyambung materi sebelumnya:

- Dari materi 7: named route (`buku.index`) tetap berlaku di dalam group, hanya nama depan ditambah.
- Dari materi 8: `Route::resource` bisa dimasukkan ke dalam group, menghasilkan `admin.buku.*` secara otomatis.
- Ke materi berikutnya: kita sudah paham struktur URL dan nama sebelum masuk ke Blade.
- Ke Level 4: `middleware(['auth'])` baru dibahas tuntas di sana.

## 2. Fungsi & Kegunaan Utama dalam Laravel

Route group menyelesaikan masalah-masalah berikut:

1. **Menghilangkan repetisi** -- prefix, middleware, dan awalan nama cukup ditulis sekali.
2. **Menjaga keamanan** -- semua route admin bisa dilindungi satu middleware sekaligus; tidak ada yang "ketinggalan".
3. **Memudahkan pemeliharaan** -- saat struktur URL berubah (misal `/admin` jadi `/panel`), cukup ubah satu tempat.
4. **Organisasi yang jelas** -- `route:list` menjadi lebih mudah dibaca karena nama dan URL berpola.
5. **Namespace controller otomatis** -- group bisa memakai `->controller(...)` untuk menyingkat referensi controller di dalamnya (Laravel 11+).

## 3. Contoh Kode & Implementasi (Real-world Example)

File: **`routes/web.php`**

```php
<?php

use Illuminate\Support\Facades\Route;
use App\Http\Controllers\BukuController;
use App\Http\Controllers\Admin\DashboardController;

// ===== Group dengan prefix URL saja =====
// Semua route di dalamnya otomatis diawali /admin
Route::prefix('admin')->group(function () {
    Route::get('/dashboard', [DashboardController::class, 'index'])
        ->name('admin.dashboard');

    // Resource buku di dalam group admin
    // Hasilkan nama admin.buku.* dan URL /admin/buku/*
    Route::resource('buku', BukuController::class);
});
```

### Memakai name prefix agar nama route rapi

```php
// ===== Group dengan prefix URL + name prefix =====
// URL: /admin/buku, Nama: admin.buku.index, dll.
Route::prefix('admin')
    ->name('admin.')
    ->group(function () {
        Route::get('/dashboard', [DashboardController::class, 'index'])
            ->name('dashboard'); // lengkap: admin.dashboard

        // Lengkap: admin.buku.index, admin.buku.store, dst.
        Route::resource('buku', BukuController::class);
    });
```

### Menambahkan middleware (dibahas detail di Level 4)

```php
// ===== Group dengan prefix + name + middleware =====
use Illuminate\Support\Facades\Auth; // contoh penggunaan Auth (Level 4)

Route::prefix('admin')
    ->name('admin.')
    ->middleware(['auth']) // hanya pengguna login yang bisa lewat
    ->group(function () {
        Route::get('/dashboard', [DashboardController::class, 'index'])
            ->name('dashboard');
        Route::resource('buku', BukuController::class);
    });
```

### Nested group: area member yang punya sub-bagian

```php
// ===== Nested group (group di dalam group) =====
// URL: /member/profile, Nama: member.profile.edit
Route::prefix('member')
    ->name('member.')
    ->middleware(['auth'])
    ->group(function () {
        Route::get('/profile', function () {
            return view('member.profile');
        })->name('profile');
    });
```

## 4. Analogi Sederhana

Bayangkan restoran dengan ruangan VIP. **Route group adalah aturan area restoran.**

- **Prefix** adalah nama area: semua meja di ruangan VIP harus dipanggil dengan awalan "VIP" (URL `/admin/...`).
- **Middleware** adalah seragam khusus: hanya karyawan berbadge "staff" yang boleh melayani area VIP (`middleware(['auth'])`).
- **Name prefix** adalah aturan penomoran meja: semua meja VIP diberi nomor `VIP-1`, `VIP-2` (nama `admin.dashboard`, `admin.buku.index`).

Head Waiter (Router) hanya perlu memberi instruksi sekali: "meja di ruangan VIP semua pakai awalan VIP, dilayani karyawan berbadge staff, dan diberi nomor VIP-". Dari situ seluruh daftar meja mengikuti aturan yang sama tanpa harus diulang per meja. Itulah cara kerja `Route::prefix()->name()->middleware()->group()`.

## 5. Kapan Harus Digunakan & Kasus Penggunaan (Use Cases)

| Skenario | Solusi Group |
|---|---|
| Seluruh halaman admin diawali `/admin` | `Route::prefix('admin')` |
| Halaman admin hanya boleh diakses pengguna login | Tambah `->middleware(['auth'])` |
| Nama route admin harus konsisten `admin.*` | Tambah `->name('admin.')` |
| Member punya halaman profile, riwayat, pengaturan | `Route::prefix('member')->name('member.')->middleware(['auth'])` |
| Resource buku dikelola admin | Taruh `Route::resource('buku', ...)` di dalam group admin |

Route group **wajib** digunakan begitu aplikasi memiliki lebih dari satu area fungsional (admin vs member vs publik). Untuk aplikasi kecil dengan 5 route, group belum terlalu diperlukan.

## 6. Poin-poin Penting & Best Practices

- **Kombinasikan atribut secara berantai**: `Route::prefix('admin')->name('admin.')->middleware(['auth'])->group(...)`.
- **Nama group menggunakan dot di akhir**: `->name('admin.')` supaya nama route menjadi `admin.buku.index`.
- **Prefix URL pakai lowercase dan tanpa trailing slash**: `prefix('admin')`, bukan `prefix('/admin/')`.
- **Resource di dalam group otomatis mengikuti prefix & name**: `Route::resource('buku', ...)` di group admin menghasilkan `admin.buku.*`.
- **Hindari group yang terlalu dalam** (nested berlebihan) karena membuat URL panjang dan sulit dibaca.
- **Nested group boleh dipakai untuk sub-area**, tetapi tetap jaga kedalaman maksimal 2-3 level.
- **Verifikasi selalu**:
  ```bash
  php artisan route:list
  php artisan route:list --name=admin
  ```
- **Middleware `auth` akan dibahas tuntas di Level 4** -- untuk sekarang cukup tahu fungsinya mengunci route dari pengunjung yang belum login.
- Controller namespace khusus untuk admin (`App\Http\Controllers\Admin\DashboardController`) adalah pola yang rapi: folder `app/Http/Controllers/Admin/`.

## 7. Kesalahan Umum (Common Pitfalls & Anti-patterns)

1. **Name prefix tanpa titik**
   - `->name('admin')` menghasilkan nama `adminbuku.index` (menempel). Selalu gunakan `->name('admin.')`.

2. **Prefix dengan trailing slash**
   - `prefix('/admin/')` membuat URL jadi `/admin//buku`. Gunakan `prefix('admin')`.

3. **Salah menempatkan route di luar group**
   - Route yang harusnya `admin.buku.*` tapi dideklarasikan di luar group akan menghasilkan `buku.index` tanpa proteksi. Periksa dengan `php artisan route:list --name=admin`.

4. **Duplikasi prefix di dalam group**
   - Jangan tulis `Route::get('/admin/dashboard', ...)` di dalam group `prefix('admin')` -- hasilnya `/admin/admin/dashboard`.

5. **Closure di dalam group yang berperilaku sama dengan group biasa**
   - Closure di dalam group ikut atribut group, tetapi jika logikanya mulai kompleks, segera pindah ke controller.

6. **Middleware salah nama**
   - `middleware(['auth'])` adalah nama bawaan Laravel. Jika menulis `middleware(['is_admin'])` pastikan middleware tersebut sudah didaftarkan (dibahas di Level 4).

7. **Nested group tanpa manfaat**
   - Group berlapis yang tidak menambah prefix/nama/middleware hanya membuat file sulit dibaca. Buat group hanya jika benar-benar mengelompokkan atribut.

## 8. Soal Latihan & Kunci Jawaban

### Tantangan

1. Buat group `admin` dengan prefix `/admin`, name `admin.`, dan middleware `auth`. Di dalamnya daftarkan dashboard (`DashboardController@index` bernama `admin.dashboard`) dan resource buku bernama `admin.buku.*`. Verifikasi dengan `php artisan route:list --name=admin`.

2. Buat group `member` dengan prefix `/member` dan middleware `auth` untuk halaman profile. Dari sebuah view, buat tautan ke halaman dashboard admin menggunakan `route('admin.dashboard')`.

### Jawaban & Pembahasan

**Soal 1 -- group admin lengkap:**

```php
use Illuminate\Support\Facades\Route;
use App\Http\Controllers\Admin\DashboardController;
use App\Http\Controllers\BukuController;

Route::prefix('admin')
    ->name('admin.')
    ->middleware(['auth'])
    ->group(function () {
        // URL /admin/dashboard, nama admin.dashboard
        Route::get('/dashboard', [DashboardController::class, 'index'])
            ->name('dashboard');

        // URL /admin/buku/*, nama admin.buku.*
        Route::resource('buku', BukuController::class);
    });
```

**Pembahasan:** `->name('admin.')` membuat nama `dashboard` menjadi `admin.dashboard`, dan resource `buku` otomatis menjadi `admin.buku.index`, `admin.buku.show`, dst. `->middleware(['auth'])` mengunci seluruh route di dalamnya. Verifikasi dengan `php artisan route:list --name=admin` -- semua route admin muncul dengan nama berawalan `admin.` dan URL berawalan `/admin`.

**Alur:** pengguna membuka `/admin/dashboard` -> Laravel memeriksa middleware `auth` (belum login? arahkan ke halaman login) -> setelah lolos, memanggil `DashboardController@index` -> Blade (materi berikutnya) merender tampilan.

**Soal 2 -- group member dan tautan:**

```php
Route::prefix('member')
    ->name('member.')
    ->middleware(['auth'])
    ->group(function () {
        Route::get('/profile', function () {
            return view('member.profile');
        })->name('profile');
    });
```

Di dalam view:

```blade
{{-- Berhasil menghasilkan URL /admin/dashboard tanpa menulis string manual --}}
<a href="{{ route('admin.dashboard') }}">Buka Dashboard Admin</a>
```

**Pembahasan:** nama `member.profile` dihasilkan dari `->name('member.')` + `->name('profile')`. Karena group admin memakai name prefix `admin.`, maka `route('admin.dashboard')` tetap valid meskipun URL prefix `/admin` nanti berubah -- inilah kekuatan kombinasi named route dan route group yang dibahas sejak materi 7.
