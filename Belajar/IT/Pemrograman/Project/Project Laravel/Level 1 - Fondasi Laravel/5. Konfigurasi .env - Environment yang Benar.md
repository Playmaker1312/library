# 5. Konfigurasi .env — Environment yang Benar

File `.env` adalah "otak konfigurasi" project `perpustakaan` kamu. Di materi 3, file ini dibuat otomatis saat instalasi; di materi 4 kita lihat ia terpisah dari `config/`. Sekarang waktunya paham betul isinya — karena kesalahan konfigurasi `.env` adalah sumber 80% error di awal belajar Laravel. Materi ini juga jadi jembatan ke Routing: URL aplikasi (`APP_URL`) dan koneksi database ditentukan di sini.

## 1. Penjelasan Singkat & Konsep Dasar

Prinsip utama `.env` adalah **memisahkan konfigurasi yang spesifik environment dari kode aplikasi**. Kode kamu sama di semua mesin, tetapi nilai konfigurasi (nama database, password, mode debug) bisa berbeda-beda: di laptop kamu (`local`), di server staging, dan di server produksi.

- `.env` berisi nilai nyata untuk mesin kamu dan **TIDAK di-commit ke git**.
- `.env.example` adalah template aman (tanpa rahasia) dan **WAJIB di-commit**, agar developer lain tahu variabel apa saja yang dibutuhkan.
- Nilai di `.env` dibaca oleh file-file di `config/` dan diakses di kode.

Hubungan dengan materi lain:
- **Materi 3**: `.env` dibuat otomatis saat `laravel new`. Isinya berasal dari pilihan database (MySQL) dan nilai default.
- **Materi 4**: `.env` dibaca oleh file di `config/` (mis. `config/database.php` membaca `DB_*`).
- **Materi berikutnya (Routing)**: `APP_URL` dipakai framework untuk membangun URL absolut.

## 2. Fungsi & Kegunaan Utama dalam Laravel

1. **Konfigurasi per environment** — `local` vs `production` bisa punya nilai berbeda tanpa mengubah kode.
2. **Keamanan** — kredensial database, kunci enkripsi (APP_KEY), dan secret API tidak pernah masuk repository git.
3. **Kolaborasi tim** — setiap developer punya `.env` sendiri; `.env.example` jadi acuan bersama.
4. **Performa produksi** — Laravel bisa me-cache seluruh konfigurasi dengan `php artisan config:cache` sehingga `.env` tidak dibaca per-request.
5. **Debug yang aman** — `APP_DEBUG` bisa `true` saat development (tampil error detail) dan `false` di produksi (tampil halaman 500 generik, tidak membocorkan stack trace).

## 3. Contoh Kode & Implementasi (Real-world Example)

### 3.1 Isi `.env` untuk project perpustakaan

Berikut `.env` yang relevan untuk sistem manajemen perpustakaan (lokasi: root project, `perpustakaan/.env`):

```bash
APP_NAME="Perpustakaan Digital"
APP_ENV=local
APP_KEY=base64:xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx=
APP_DEBUG=true
APP_TIMEZONE=Asia/Jakarta
APP_URL=http://localhost:8000

APP_LOCALE=id
APP_FALLBACK_LOCALE=en

LOG_CHANNEL=stack

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=perpustakaan_db
DB_USERNAME=root
DB_PASSWORD=

# Cache & Session
CACHE_STORE=database
SESSION_DRIVER=database
SESSION_LIFETIME=120

# Queue & Mail (bawaan saat development)
QUEUE_CONNECTION=sync
MAIL_MAILER=log
```

Penjelasan variabel penting:

| Variabel | Nilai yang disarankan | Keterangan |
|---|---|---|
| `APP_NAME` | `"Perpustakaan Digital"` | Nama aplikasi (muncul di email, judul, dsb.) |
| `APP_ENV` | `local` | `local`/`staging`/`production` — penanda environment |
| `APP_KEY` | hasil `key:generate` | Kunci enkripsi; **jangan pernah kosong** |
| `APP_DEBUG` | `true` (local) / `false` (production) | Menampilkan error detail jika `true` |
| `APP_URL` | `http://localhost:8000` | URL utama aplikasi |
| `DB_CONNECTION` | `mysql` | Driver database |
| `DB_HOST` / `DB_PORT` | `127.0.0.1` / `3306` | Alamat & port MySQL |
| `DB_DATABASE` | `perpustakaan_db` | Nama database |
| `DB_USERNAME` / `DB_PASSWORD` | `root` / kosong (Laragon/XAMPP default) | Kredensial MySQL |
| `CACHE_STORE` | `database` | Driver cache |
| `SESSION_DRIVER` | `database` | Tempat simpan session |
| `SESSION_LIFETIME` | `120` | Masa aktif session (menit) |
| `QUEUE_CONNECTION` | `sync` | `sync` = langsung diproses, cocok untuk belajar |
| `MAIL_MAILER` | `log` | Email disimpan ke file log, tidak benar-benar dikirim |

### 3.2 Menyinkronkan `.env` dan `.env.example`

Setiap kali menambah variabel baru di `.env`, tambahkan juga di `.env.example` (tanpa nilai rahasia). Contoh potongan `.env.example`:

```bash
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=perpustakaan_db
DB_USERNAME=root
DB_PASSWORD=
```

> **Lokasi file:** `.env` dan `.env.example` berada di root project. Jangan pernah menambahkan `.env` ke git — pastikan ada di `.gitignore` (Laravel sudah menyertakannya secara default).

### 3.3 Membuat database

Buat database lewat terminal MySQL atau Laragon:

```sql
CREATE DATABASE perpustakaan_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

Atau via `php artisan` (setelah `.env` benar, material ini dipakai di materi Migration):

```bash
php artisan db:show   # cek koneksi & nama database
```

### 3.4 Mengakses nilai di kode

Di Laravel, akses lewat **`config()`**, bukan `env()` langsung, kecuali di file `config/`:

```php
<?php
// config/app.php
return [
    'name' => env('APP_NAME', 'Laravel'),
    'timezone' => env('APP_TIMEZONE', 'UTC'),
];

// Di Controller/Model — PAKAI config(), bukan env()
$namaAplikasi = config('app.name');
$timezone     = config('app.timezone');
```

### 3.5 Cache konfigurasi

```bash
# Setelah mengubah .env — bersihkan dulu cache
php artisan config:clear

# Di production, cache semua config agar cepat
php artisan config:cache
```

## 4. Analogi Sederhana

`.env` seperti **buku catatan rahasia pemilik restoran** berisi resep rahasia, kunci gudang, dan jam buka yang berbeda tiap cabang.

- `.env.example` adalah **template fotokopian** yang bisa dibagikan ke semua manajer cabang: "ini daftar yang perlu kamu isi, nilai aslinya jangan disebar."
- `.env` di laptopmu (`local`) bisa berisi `DB_PASSWORD=` kosong, sedangkan di server (`production`) password-nya kuat — kode restoran tetap sama, tapi data rahasianya berbeda.
- `APP_DEBUG=true` seperti **membuka pintu dapur lebar-lebar saat ada masalah** (kamu lihat detail semuanya) — berbahaya kalau dibuka di depan pelanggan. Di produksi pintunya tertutup (`false`), pelanggan hanya lihat "maaf, ada kendala" tanpa detail.

## 5. Kapan Harus Digunakan & Kasus Penggunaan (Use Cases)

| Skenario | Aksi |
|---|---|
| Mengubah nama aplikasi / timezone | Edit `APP_NAME`, `APP_TIMEZONE` di `.env` |
| Menghubungkan project ke MySQL | Isi `DB_*` sesuai kredensial, lalu `php artisan db:show` |
| Pindah ke server produksi | Salin `.env.example` ke `.env`, isi nilai produksi, set `APP_DEBUG=false`, jalankan `config:cache` |
| Project baru untuk developer lain | Ia copy `.env.example` → `.env`, jalankan `php artisan key:generate` |
| Ingin email hanya disimpan ke log | Biarkan `MAIL_MAILER=log` saat development |
| Butuh session lebih lama | Naikkan `SESSION_LIFETIME` |

## 6. Poin-poin Penting & Best Practices

- **Jangan commit `.env`.** Pastikan ada di `.gitignore`. Commit `.env.example` sebagai template.
- **Jangan pernah `APP_DEBUG=true` di produksi** — bisa membocorkan struktur database dan rahasia ke publik.
- **Wajib punya `APP_KEY`** — dihasilkan dengan `php artisan key:generate`. Tanpa ini, session dan enkripsi tidak berfungsi.
- **Jangan mengubah `.env` saat `config:cache` aktif** — bersihkan dulu dengan `php artisan config:clear`, ubah, baru cache ulang.
- **Gunakan `config()` di kode**, bukan `env()` — `env()` akan mengembalikan `null` setelah `config:cache`, sedangkan `config()` selalu aman.
- **Gunakan driver ringan saat belajar**: `QUEUE_CONNECTION=sync`, `MAIL_MAILER=log`, `CACHE_STORE=database` atau `file`.
- **Sertakan charset `utf8mb4`** saat membuat database agar mendukung emoji & huruf khusus (mis. judul buku beraksara).
- **Ubah `APP_URL`** sesuai environment (`http://localhost:8000` di lokal).
- **Saat meng-clone project baru**: `composer install` → salin `.env.example` ke `.env` → `php artisan key:generate`.

## 7. Kesalahan Umum (Common Pitfalls & Anti-patterns)

| Gejala | Penyebab | Solusi |
|---|---|---|
| Halaman 500 "No application encryption key" | `APP_KEY` kosong | Jalankan `php artisan key:generate` |
| Perubahan `.env` tidak berefek | Config masih di-cache | `php artisan config:clear` |
| `env()` mengembalikan `null` | Dipakai setelah `config:cache` | Ganti ke `config('...')` |
| Koneksi DB gagal "Access denied" | `DB_USERNAME`/`DB_PASSWORD` salah | Sesuaikan kredensial MySQL; default Laragon: `root` + kosong |
| "Unknown database" | Database belum dibuat | Buat `perpustakaan_db` via SQL |
| Error "Connection refused" saat pakai Sail | `DB_HOST` harus `mysql` (nama service), bukan `127.0.0.1` | Sesuaikan `DB_HOST` dengan docker-compose |
| `.env` ikut ter-commit ke git | `.gitignore` tidak menutupinya | Tambahkan `.env` ke `.gitignore`; hapus dari git dengan `git rm --cached .env` |
| Email error "Failed to authenticate" | `MAIL_MAILER=smtp` tanpa kredensial | Gunakan `MAIL_MAILER=log` saat development |
| Error bahasa/emoji disimpan aneh | Tabel dibuat tanpa `utf8mb4` | Buat DB dengan `utf8mb4_unicode_ci` |

## 8. Soal Latihan & Kunci Jawaban

### Tantangan

1. Project `perpustakaan` baru saja di-clone dari git dan muncul error "No application encryption key has been specified". Apa dua langkah pertama yang harus kamu lakukan, dan kenapa?
2. Kamu mau menghubungkan project ke MySQL. Tulis isi blok `DB_*` yang benar untuk Laragon lokal (username root, password kosong, database `perpustakaan_db`), lalu jelaskan perintah untuk memverifikasi koneksi.

### Jawaban & Pembahasan

**Soal 1**

```bash
# Langkah 1: salin template ke .env (nilai asli tidak ikut di git)
copy .env.example .env

# Langkah 2: buat APP_KEY unik untuk project ini
php artisan key:generate
```

**Alur pembahasan:** `.env` tidak pernah di-commit, jadi setelah clone yang ada hanyalah `.env.example`. Menyalinnya menjadi `.env` memberi Laravel variabel konfigurasi yang dibutuhkan, lalu `php artisan key:generate` membuat `APP_KEY` acak yang dipakai untuk enkripsi session dan data. Tanpa kedua langkah ini, aplikasi menolak berjalan demi keamanan.

**Soal 2**

```bash
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=perpustakaan_db
DB_USERNAME=root
DB_PASSWORD=
```

Lalu buat database (bila belum ada):

```sql
CREATE DATABASE perpustakaan_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

Dan verifikasi:

```bash
php artisan db:show
```

**Alur pembahasan:** `DB_HOST=127.0.0.1` dan `DB_PORT=3306` menunjuk ke MySQL lokal (default Laragon/XAMPP). `DB_USERNAME=root` dengan password kosong adalah kredensial default Laragon. Database `perpustakaan_db` dibuat dengan `utf8mb4` agar mendukung karakter Indonesia dan simbol. Terakhir, `php artisan db:show` membaca konfigurasi dari `.env` dan menampilkan detail koneksi — kalau berhasil, berarti konfigurasi kamu benar dan siap untuk Migration di materi berikutnya.
