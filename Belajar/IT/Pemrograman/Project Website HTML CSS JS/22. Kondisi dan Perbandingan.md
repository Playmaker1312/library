# Kondisi dan Perbandingan

Ini materi pertama JavaScript yang membuat kode kita "berpikir" — memutuskan apa yang harus dilakukan berdasarkan keadaan data. Materi ini melanjutkan variabel dan tipe data (materi 20-21), dan menjadi gerbang menuju Level 5 di mana keputusan ini akan diterapkan langsung ke tampilan halaman (DOM).

## 1. Penjelasan Singkat & Konsep Dasar

Di materi 20-21 kamu sudah bisa menyimpan data ke variabel dan mengenal tipe datanya. Tapi data yang hanya disimpan itu mati — belum melakukan apa-apa. Agar aplikasi hidup, kode harus bisa **mengambil keputusan**: "apakah stok masih ada?", "buku ini kategori apa?", "apakah user sudah login?". Itulah inti materi ini: **logika kondisional** — kode yang memilih jalur eksekusi berdasarkan kondisi yang bernilai benar (`true`) atau salah (`false`).

Semua keputusan ini dimulai dari **perbandingan**. JavaScript punya dua cara membandingkan: `==` (loose equality) dan `===` (strict equality). Aturan emasnya satu kalimat: **selalu pakai `===`**. `==` melakukan *type coercion* — mengubah tipe data secara diam-diam agar bisa dibandingkan — sehingga `5 == "5"` bernilai `true` padahal number dan string jelas berbeda. Ini sumber bug paling klasik di JavaScript. `===` membandingkan nilai **dan** tipe sekaligus, jadi `5 === "5"` adalah `false`. Percayakan pada `===` dan kau tidak akan pernah terjebak kejutan `null == undefined` yang bernilai `true`.

Setiap kondisi, mau berapa panjang rantainya, pada akhirnya mengerucut menjadi satu pertanyaan: **truthy atau falsy?** Nilai yang "falsy" di JavaScript hanya ada beberapa: `false`, `0`, `""` (string kosong), `null`, `undefined`, dan `NaN`. Segala sesuatu yang lain — termasuk array kosong `[]` dan object kosong `{}` — dianggap "truthy". Memahami daftar falsy ini penting karena `if`, `&&`, `||`, dan `??` semuanya bekerja di atas konsep ini. Banyak bug "kok masuk cabang ini?" berakar dari menganggap `0` atau `""` sebagai nilai yang "ada".

Lalu ada alat bantu modern yang menangani kasus-kasus data yang belum tentu ada: **optional chaining (`?.`)** untuk mengakses property yang mungkin `null`/`undefined` tanpa melempar error, dan **nullish coalescing (`??`)** untuk memberi nilai default hanya ketika nilainya `null`/`undefined` (bukan ketika falsy seperti `0` atau `""`). Keduanya sangat penting untuk data yang datang dari API, karena respons server tidak pernah bisa dijamin bentuknya lengkap.

Benang merah menuju Level 5: keputusan yang kamu tulis di materi ini (misal `buku.stok > 0 ? "Tersedia" : "Habis"`) adalah bahan mentah untuk merender tampilan. Di Level 5 kamu akan mengambil hasil keputusan ini lalu menulisnya ke halaman lewat DOM. Jadi logika di sini bukan teka-teki akademik — setiap `if` dan ternary yang kamu tulis hari ini adalah otak dari fitur filter, badge status, dan pesan notifikasi besok.

## 2. Fungsi & Kegunaan Utama dalam Web

Di **Perpustakaan Digital Kota**, kondisi adalah jantung dari hampir semua perilaku aplikasi:

- **Cek ketersediaan stok** — setiap kartu buku harus menampilkan status berbeda: stok banyak, stok terbatas, atau habis. Ini `if/else if/else` langsung.
- **Warna badge kategori** — badge "Teknologi", "Fiksi", "Sains" punya warna berbeda. Ini pekerjaan `switch`.
- **Aturan peminjaman & denda** — berapa hari terlambat menentukan tarif denda per hari; jenis keanggotaan menentukan maksimal buku yang bisa dipinjam.
- **Menampilkan data dari server** — respons API bisa saja tidak punya field `rating` atau `sampul`. Optional chaining mencegah halaman error ketika data tidak lengkap, dan `??` memberi teks default.
- **Tombol yang dinonaktifkan** — tombol "Pinjam" harus disabled saat stok 0 (`buku.stok === 0`), dan banner "Stok habis" hanya muncul saat kondisi tertentu — pola render kondisional dengan `&&`.

Singkatnya: seluruh "kecerdasan" aplikasi — rekomendasi, filter, validasi, status — dibangun di atas kombinasi perbandingan dan percabangan yang akan kamu kuasai di materi ini.

## 3. Contoh Kode & Implementasi Real-World

```javascript
// Data koleksi perpustakaan — selalu pakai const untuk data yang tidak reassign
const katalog = [
    { id: 1, judul: "Clean Code",       stok: 5,  harga: 150000, kategori: "Teknologi" },
    { id: 2, judul: "Laskar Pelangi",   stok: 3,  harga: 95000,  kategori: "Fiksi" },
    { id: 3, judul: "The Great Gatsby", stok: 0,  harga: 120000, kategori: "Fiksi" },
    { id: 4, judul: "Cosmos",           stok: 8,  harga: 200000, kategori: "Sains" },
];

// ─── 1) === vs == ─────────────────────────────────────────────────────────
// === membandingkan nilai DAN tipe → selalu pakai ini
console.log(5 === 5);     // true  — number vs number, sama
console.log(5 === "5");   // false — number vs string, berbeda!
// == melakukan coercion (konversi tipe diam-diam) → SUMBER BUG
console.log(5 == "5");    // true  — JavaScript mengubah "5" jadi 5 dulu
console.log(null == undefined);  // true  ← perilaku membingungkan
console.log(null === undefined); // false ← inilah yang benar

// ─── 2) Truthy / Falsy ────────────────────────────────────────────────────
// Nilai falsy: false, 0, "" (kosong), null, undefined, NaN
// Segala yang lain (termasuk [] dan {}) adalah truthy
if ("")        console.log("tak tampil"); // string kosong = falsy
if (0)         console.log("tak tampil"); // nol = falsy
if ("Sains")   console.log("tampil");     // string tidak kosong = truthy
if ([])        console.log("tampil");     // array kosong tetap truthy!

// Hati-hati: cek keberadaan dengan cara yang benar
const ratingBuku = undefined;
if (ratingBuku)          console.log("ada"); // tidak tampil — undefined falsy
if (ratingBuku ?? false) console.log("ada"); // tetap tidak tampil
console.log(ratingBuku ?? "Belum ada rating"); // "Belum ada rating"

// ─── 3) if / else if / else ───────────────────────────────────────────────
// Cek ketersediaan stok — contoh paling sehari-hari di perpustakaan
function cekKetersediaan(stok) {
    if (stok > 10) {
        return "Stok banyak";
    } else if (stok > 0) {
        return `Stok terbatas (${stok} buku tersisa)`;
    } else {
        return "Stok habis";
    }
}
console.log(cekKetersediaan(8));   // "Stok terbatas (8 buku tersisa)"
console.log(cekKetersediaan(0));   // "Stok habis"
console.log(cekKetersediaan(15));  // "Stok banyak"

// ─── 4) Ternary — jika / jika-tidak dalam satu baris ─────────────────────
// Cocok untuk keputusan dua arah yang sederhana dan dibaca singkat
const buku3 = katalog[2];                          // The Great Gatsby, stok 0
const status = buku3.stok > 0 ? "Tersedia" : "Habis";
console.log(status);                               // "Habis"

// Bisa menyisipkan lebih banyak logika di tiap cabang (hindari yang berlebihan)
function pesanBadge(buku) {
    return buku.stok === 0
        ? "Habis"
        : buku.stok <= 3
        ? "Hampir habis"
        : "Tersedia";
}

// ─── 5) Optional chaining (?.) — aman saat data mungkin null ──────────────
// Data dari API sering tidak lengkap. Tanpa ?. ini akan melempar error.
const anggotaDariAPI = null;   // bisa jadi null jika request gagal
const kota = anggotaDariAPI?.alamat?.kota;  // undefined, bukan error!
console.log(kota);             // undefined — aman

// Contoh realistis: detail buku yang field-nya opsional
const detailBuku = { judul: "Cosmos", rating: 4.9 }; // tidak ada field "review"
console.log(detailBuku.review?.jumlah);  // undefined — tidak error
console.log(detailBuku.rating?.toFixed(1)); // "4.9" — rating ada, dipanggil

// ─── 6) Nullish coalescing (??) — default hanya untuk null/undefined ─────
// Beda dari ||: ?? TIDAK menggantikan 0 atau "" — justru itu yang sering diinginkan
const hargaTampil = detailBuku.harga ?? "Hubungi petugas";
console.log(hargaTampil);   // "Hubungi petugas" (harga memang undefined)

// Kapan ?? vs ||?
const diskon = 0;            // 0 diskon = tidak ada diskon, bukan "default"
console.log(diskon ?? 10);   // 0    ← benar: 0 tetap 0
console.log(diskon || 10);   // 10   ← salah jika 0 punya arti tersendiri!

// ─── 7) Short-circuit && dan || ───────────────────────────────────────────
// && : jika kiri falsy → kembalikan kiri; jika truthy → kembalikan kanan
// Pola render kondisional: hanya tampil jika kondisi benar
const pesanTersedia = buku3.stok > 0 && `${buku3.judul} tersedia ${buku3.stok}`;
console.log(pesanTersedia);  // false (stok 0) → tidak ada pesan

// || : jika kiri truthy → kembalikan kiri; jika falsy → kembalikan kanan
const namaPengguna = "";     // user belum mengisi nama
const namaTampil = namaPengguna || "Tamu";
console.log(namaTampil);     // "Tamu"

// ─── 8) switch — banyak kondisi nilai yang sama ───────────────────────────
// Paling cocok ketika membandingkan SATU nilai dengan banyak kemungkinan
// Contoh: warna badge kategori buku
function warnaBadgeKategori(kategori) {
    switch (kategori) {
        case "Teknologi": return "#3b82f6"; // biru
        case "Fiksi":     return "#8b5cf6"; // ungu
        case "Sains":     return "#10b981"; // hijau
        default:          return "#6b7280"; // abu-abu untuk kategori lain
    }
}
console.log(warnaBadgeKategori("Fiksi"));     // "#8b5cf6"
console.log(warnaBadgeKategori("Filsafat"));  // "#6b7280" (default)
```

## 4. Analogi Sederhana — Membangun Rumah

Jika HTML adalah kerangka rumah dan CSS adalah catnya, maka **JavaScript adalah listrik dan otomatisasi** rumah itu. Kondisi adalah **saklar dan sensor** yang memutuskan.

- `if` biasa = saklar manual satu arah: "jika sensor hujan mendeteksi air → matikan penyiram otomatis". Satu input, satu keputusan.
- `else if` / `else` = panel sensor berjenjang: "jika suhu > 30°C → nyalakan AC; jika tidak, jika suhu < 18°C → nyalakan pemanas; jika tidak → biarkan".
- **Ternary** = saklar pintar dua arah dalam satu gerakan: "jika malam → nyalakan lampu; jika tidak → matikan". Tidak perlu dua baris `if`.
- `===` = cara memeriksa apakah sesuatu itu **benar-benar** sama — seperti mencocokkan dua kunci yang harus sama persis bentuknya, bukan "hampir mirip" (`==` yang seenaknya menafsirkan angka jadi teks).
- `??` dan `?.` = sekring pengaman: saat kabel menuju lampu ternyata tidak terpasang (`null`), listrik tidak meledak — ia berhenti dengan aman (`?.`) dan memberi pencahayaan cadangan (`??`).
- `switch` = papan saklar di pintu masuk: berdasarkan posisi saklar (tekanan kode kategori), ruangan mana yang menyala (warna badge mana yang aktif).

Nanti di Level 5, saklar-saklar ini akan menyalakan "lampu" di halaman — menampilkan badge, menyembunyikan tombol, mengganti pesan — persis seperti otomatisasi rumah yang bereaksi terhadap sensornya.

## 5. Kapan Harus Digunakan & Kasus Penggunaan (Use Cases)

1. **Kartu buku dengan badge status** — setiap buku menampilkan `"Tersedia"`, `"Terbatas"`, atau `"Habis"` berdasarkan stok. Pakai `if/else if/else` di dalam satu fungsi kecil agar mudah dites.
2. **Tombol "Pinjam" dinonaktifkan** — tombol diberi `disabled = true` saat `stok === 0`. Keputusan boolean dua arah → ternary atau `&&` saat merender.
3. **Menampilkan detail buku dari API yang tidak lengkap** — misal `buku.rating` tidak ada untuk beberapa judul. Pakai `?.` agar tidak crash, dan `??` untuk menampilkan "Belum ada rating".
4. **Filter dan kategori** — dropdown kategori memilih warna badge & baris filter; `switch` merapikan banyak `case` kategori.
5. **Form validasi & pesan error** — saat user mengirim form peminjaman, cek dulu "apakah buku tersedia?" (`===`, `>`, `&&`) lalu tampilkan pesan sukses atau galat.

## 6. Poin-poin Penting & Best Practices

- **Selalu `===` dan `!==`**, jangan `==`/`!=`. Koersi `==` menyembunyikan bug tipe data.
- Pahami daftar falsy: `false`, `0`, `""`, `null`, `undefined`, `NaN`. Ini dasar dari `&&`, `||`, dan `??`.
- Gunakan `??` ketika kamu hanya ingin menangani `null`/`undefined`; gunakan `||` ketika kamu benar-benar ingin menangkap semua nilai falsy. Kebanyakan kasus default "data kosong" lebih tepat pakai `??`.
- Optional chaining `?.` untuk akses property yang mungkin tidak ada — wajib untuk data API yang tidak bisa dijamin bentuknya.
- Ternary untuk dua cabang sederhana; `if/else if/else` untuk tiga cabang atau lebih yang kompleks; `switch` untuk membandingkan satu nilai dengan banyak kemungkinan.
- Jangan menumpuk ternary atau nested `if` terlalu dalam — jika kode mulai sulit dibaca, ekstrak ke fungsi kecil dengan nama deskriptif.
- Hindari mengganti `0` atau `""` tanpa sadar lewat `||` — `0` stok adalah informasi penting, bukan "tidak ada data".
- Catatan **Type Safety**: dengan TypeScript, banyak kesalahan tipe ini (misal membandingkan number dengan string) sudah tertangkap saat kompilasi, sebelum bug sampai ke browser.

## 7. Kesalahan Umum (Common Pitfalls & Bugs)

1. **`==` dengan koersi yang tak terduga.** `1 == "1"` → `true`, dan `null == undefined` → `true`, membuat logika mengambil cabang yang salah. **Perbaikan:** selalu `===`, dan gunakan `??` untuk default null/undefined.

```javascript
// ❌ Salah
if (jumlahPinjam == "5") { /* terpilih padahal "5" adalah string */ }
// ✅ Benar
if (jumlahPinjam === 5) { /* hanya terpilih jika number 5 */ }
```

2. **Menganggap `0` dan `""` sebagai "tidak ada".** Jika stok 0 dianggap falsy lalu ditimpa default lewat `||`, angka 0 hilang. **Perbaikan:** gunakan `??` yang hanya merespons `null`/`undefined`.

```javascript
// ❌ Salah — stok 0 berubah menjadi 10
const stokSalah = stok || 10;
// ✅ Benar — stok 0 tetap 0
const stokBenar = stok ?? 10;
```

3. **Optional chaining yang keliru arah.** `data.buku[0]` tanpa `?.` melempar error jika `data.buku` adalah `null`. **Perbaikan:** tulis `data?.buku?.[0] ?? null` dan periksa setiap level yang berpotensi hilang.
4. **Switch lupa `return`/`break`** sehingga semua case di bawahnya ikut tereksekusi (fall-through). **Perbaikan:** selalu akhiri tiap case, dan beri `default` untuk jaring pengaman.

## 8. Mini Project / Soal Latihan & Kunci Jawaban

**Tantangan:** Pakai data `katalog` berikut. (a) Buat fungsi `cekKetersediaan(buku)` yang mengembalikan "Tersedia", "Hampir habis" (stok 1-3), atau "Habis" (stok 0) memakai `if/else if/else`. (b) Buat fungsi `labelStatus(buku)` yang memakai ternary: "Tersedia" jika `stok > 0`, selain itu "Habis". (c) Buat fungsi `warnaBadge(kategori)` dengan `switch` untuk kategori Teknologi, Fiksi, Sains. (d) Dari sebuah object respons API yang **mungkin** null, ambil `buku.reviewer.nama` dengan optional chaining dan beri fallback "Anonim" dengan `??`.

```javascript
const katalog = [
    { id: 1, judul: "Clean Code",       stok: 5,  harga: 150000, kategori: "Teknologi" },
    { id: 2, judul: "Laskar Pelangi",   stok: 0,  harga: 95000,  kategori: "Fiksi" },
    { id: 3, judul: "The Great Gatsby", stok: 2,  harga: 120000, kategori: "Fiksi" },
    { id: 4, judul: "Cosmos",           stok: 8,  harga: 200000, kategori: "Sains" },
];
```

**Solusi & Pembahasan:**

```javascript
// (a) if/else if/else — tiga tingkatan status stok
function cekKetersediaan(buku) {
    if (buku.stok > 3) {
        return "Tersedia";
    } else if (buku.stok > 0) {
        return "Hampir habis";
    } else {
        return "Habis";
    }
}

// (b) Ternary — keputusan dua arah yang ringkas
function labelStatus(buku) {
    return buku.stok > 0 ? "Tersedia" : "Habis";
}

// (c) switch — satu nilai, banyak kemungkinan
function warnaBadge(kategori) {
    switch (kategori) {
        case "Teknologi": return "#3b82f6";
        case "Fiksi":     return "#8b5cf6";
        case "Sains":     return "#10b981";
        default:          return "#6b7280";
    }
}

// (d) optional chaining + nullish coalescing untuk data API yang belum tentu ada
const responAPI = null;                    // simulasi request yang gagal
const namaReviewer = responAPI?.buku?.reviewer?.nama ?? "Anonim";
console.log(namaReviewer);                 // "Anonim"

// Uji hasil:
console.log(cekKetersediaan(katalog[0]));  // "Tersedia"   (stok 5)
console.log(cekKetersediaan(katalog[2]));  // "Hampir habis" (stok 2)
console.log(cekKetersediaan(katalog[1]));  // "Habis"      (stok 0)
console.log(labelStatus(katalog[3]));      // "Tersedia"
console.log(warnaBadge("Fiksi"));          // "#8b5cf6"
console.log(warnaBadge("Sejarah"));        // "#6b7280" (default)
```

**Pembahasan:** Bagian (a) menunjukkan tiga cabang berjenjang — urutan `else if` penting, cek batas `> 3` dulu agar nilai 4 tidak jatuh ke cabang "Hampir habis". Bagian (b) membuktikan ternary cocok untuk tepat dua kemungkinan. Bagian (c) memakai `switch` dengan `default` sebagai jaring pengaman kategori tak dikenal. Bagian (d) adalah pola wajib saat berurusan dengan API: `?.` mencegah crash pada rantai property yang hilang, lalu `??` mengisi nilai fallback. Coba ubah `responAPI` menjadi object valid seperti `{ buku: { reviewer: { nama: "Budi" } } }` dan lihat hasilnya berubah menjadi "Budi".
