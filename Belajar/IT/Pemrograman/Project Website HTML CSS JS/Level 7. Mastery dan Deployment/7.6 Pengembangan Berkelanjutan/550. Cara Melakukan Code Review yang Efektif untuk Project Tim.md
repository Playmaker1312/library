# 550. Cara Melakukan Code Review yang Efektif untuk Project Tim

## Definisi & Target
Code review adalah proses pemeriksaan kode oleh developer lain sebelum digabungkan ke branch utama. Code review efektif meningkatkan kualitas kode, berbagi pengetahuan, dan mencegah bug. Target: setiap pull request di-review dengan fokus pada fungsionalitas, kualitas kode, keamanan, dan best practices.

## Analogi Alur
Code review seperti proofreader untuk buku — penulis (developer) menulis draf (kode), proofreader (reviewer) memeriksa typo (bug), struktur kalimat (kualitas kode), dan konsistensi (standar tim). Buku yang melewati proofreader lebih berkualitas.

## Poin-Poin Penting
- Fokus pada logika, arsitektur, dan keamanan, bukan formatting (biarkan linter yang handle)
- Berikan feedback konstruktif, spesifik, dan actionable
- Review dalam batch kecil (max 200-300 lines per PR)
- Gunakan checklist review: apakah berfungsi? mudah dibaca? sesuai standar? aman?
- Balas comments dengan perubahan atau penjelasan

## Cara Integrasi
Buat branch protection rules: minimal 1 approval untuk merge. Gunakan pull request template. Tetapkan guidelines tim untuk code review. Rotasi reviewer untuk berbagi pengetahuan. Gunakan GitHub "Request changes" vs "Comment" untuk membedakan blocking vs saran. Evaluasi proses review secara berkala.
