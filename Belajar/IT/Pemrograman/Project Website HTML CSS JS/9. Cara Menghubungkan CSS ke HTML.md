# 9. Cara Menghubungkan CSS ke HTML

Di Level 1 kita membangun struktur halaman perpustakaan dengan HTML semantik. Sekarang saatnya membuat halaman itu menarik secara visual dengan CSS — dan langkah pertama yang harus dikuasai adalah **menghubungkan CSS ke HTML** dengan cara yang benar. Ada tiga cara yang tersedia, tapi hanya satu yang direkomendasikan untuk proyek nyata.

## 1. Penjelasan Singkat & Konsep Dasar

CSS adalah bahasa yang berdiri sendiri. Browser tidak akan otomatis tahu mana stylesheet kamu — kamu harus menyatakannya secara eksplisit agar CSS bisa "ditemukan" dan diterapkan ke halaman. Tanpa penghubung ini, halaman tetap tampil sebagai dokumen hitam putih dengan gaya bawaan browser.

Konsep kuncinya: **CSS terpisah dari HTML**. Di Level 1 kita melihat bahwa browser membaca HTML dari atas ke bawah dan membangun struktur DOM. Setelah membaca HTML, browser mencaritahu stylesheet mana yang berlaku lewat informasi di dalam `<head>`. Jika kamu menggunakan file CSS eksternal, browser melakukan *request* tambahan untuk mengambil file tersebut, lalu menghitung tampilan setiap elemen berdasarkan aturan CSS yang terkumpul.

Pemisahan ini bukan sekadar preferensi gaya — ini fondasi arsitektur web. HTML bertanggung jawab atas **struktur dan makna**, CSS atas **tampilan**. Dengan memisahkan keduanya, kamu bisa mengubah penampilan seluruh situs tanpa menyentuh satu baris HTML pun. Ini yang disebut *separation of concerns* dan akan terus berlaku sampai proyekmu besar sekalipun, bahkan saat kamu nanti memakai framework (React, Vue, dll.) — prinsip "style tidak menempel di markup" tetap sama.

Ke depannya, pemahaman ini menjadi prasyarat untuk semua materi CSS lain (selector, cascade, layout). Karena ketika style-mu "tidak jalan", 50% penyebabnya sering kali bukan masalah CSS-nya, melainkan file CSS-nya **tidak terhubung dengan benar** — salah path, salah urutan, atau lupa menuliskannya sama sekali. Kuasai bagian ini dulu, sisanya akan jauh lebih lancar.

## 2. Fungsi & Kegunaan Utama dalam Web

Menghubungkan CSS ke HTML menyelesaikan beberapa masalah nyata yang langsung terasa di proyek "Perpustakaan Digital Kota":

- **Satu sumber kebenaran untuk tampilan.** Perpustakaan kita punya banyak halaman: `index.html`, `katalog.html`, `tentang.html`, `kontak.html`. Dengan satu file `css/style.css` yang di-link di semua halaman, kamu mengubah warna brand satu kali dan seluruh situs ikut berubah. Coba bayangkan mengubah warna header di 4 halaman secara manual — itu buang waktu dan rawan lupa.
- **Performa lebih cepat lewat cache.** Browser meng-cache file CSS eksternal. Saat pengunjung pindah dari beranda ke katalog, file CSS tidak perlu di-download ulang karena sudah tersimpan di browser. Halaman kedua dan seterusnya jadi terasa jauh lebih ringan.
- **Perawatan jangka panjang (maintainability).** Kode CSS terpusat, rapi, dan mudah dicari. Tidak ada style yang "bersembunyi" di tengah tag HTML. Saat ada bug tampilan, kamu cukup membuka satu folder `css/` dan menemukan masalahnya di sana.
- **Workflow tim.** Desainer dan developer bisa bekerja pada file berbeda tanpa bentrok. HTML dikerjakan satu orang, CSS dikerjakan orang lain, dan keduanya bisa digabung tanpa konflik.
- **Eksperimen cepat.** Dengan DevTools, kamu bisa mengedit CSS live, melihat hasilnya secara instan, lalu menyalin perubahannya kembali ke file. Alur kerja ini hanya berfungsi baik jika CSS dipisah dari HTML.

## 3. Contoh Kode & Implementasi Real-World

Ada tiga cara menghubungkan CSS ke HTML. Perhatikan baik-baik mana yang dipakai dan mana yang dihindari.

### Cara 1: External CSS (REKOMENDASI — selalu pakai ini)

File CSS dibuat terpisah, lalu dihubungkan lewat elemen `<link>` di dalam `<head>`.

```html
<!-- index.html -->
<!DOCTYPE html>
<html lang="id">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Perpustakaan Digital Kota</title>

    <!-- Hubungkan stylesheet eksternal -->
    <!-- rel="stylesheet": memberitahu browser ini file CSS -->
    <!-- href: lokasi file CSS relatif dari posisi file HTML ini -->
    <link rel="stylesheet" href="css/style.css">
</head>
<body>
    <h1>Perpustakaan Digital Kota</h1>
    <p>Selamat datang di perpustakaan digital kami.</p>
</body>
</html>
```

```css
/* css/style.css */
h1 {
    color: #2563eb;
}

p {
    color: #475569;
}
```

### Cara 2: Internal CSS (hanya untuk prototyping cepat)

CSS ditulis langsung di dalam `<style>` pada `<head>`. Hanya berlaku untuk satu halaman itu saja.

```html
<!-- index.html (internal CSS) -->
<!DOCTYPE html>
<html lang="id">
<head>
    <meta charset="UTF-8">
    <title>Perpustakaan Digital Kota</title>

    <style>
        /* CSS internal — hanya berlaku di halaman ini */
        h1 {
            color: #2563eb;
        }
    </style>
</head>
<body>
    <h1>Perpustakaan Digital Kota</h1>
</body>
</html>
```

Cara ini oke untuk mencoba-coba cepat, tapi begitu halaman mulai banyak, `<head>` jadi penuh dan kamu tidak bisa memakainya di halaman lain.

### Cara 3: Inline CSS (HINDARI)

Style ditulis langsung di atribut `style` sebuah elemen.

```html
<h1 style="color: red;">Perpustakaan Digital Kota</h1>
```

Ini menyelesaikan masalah satu elemen, tapi menciptakan masalah besar: campur aduk tampilan di dalam struktur, tidak bisa di-reuse, dan paling sulit di-override. Di bagian "Kesalahan Umum" kita bahas mengapa inline style bikin kepala pusing.

### Struktur Folder yang Direkomendasikan

Untuk proyek perpustakaan, pisahkan CSS ke beberapa file sesuai perannya:

```
perpustakaan-web/
├── index.html          ← halaman beranda
├── katalog.html        ← halaman katalog buku
├── tentang.html        ← halaman profil
├── kontak.html         ← halaman form kontak
├── css/
│   ├── reset.css       ← normalisasi gaya bawaan browser
│   ├── style.css       ← stylesheet utama (variabel, tipografi, layout dasar)
│   └── components.css  ← style komponen: kartu buku, form, navbar, dsb.
├── js/
│   └── main.js         ← JavaScript (dipakai mulai Level 4)
└── images/
    ├── logo.png
    └── buku/
        └── *.jpg
```

Urutan `<link>` penting. Jika `reset.css` di-link setelah `style.css`, reset akan menimpa style kamu. Urutan yang benar di `<head>`: reset dulu, baru file yang lebih spesifik:

```html
<link rel="stylesheet" href="css/reset.css">
<link rel="stylesheet" href="css/style.css">
<link rel="stylesheet" href="css/components.css">
```

### Debugging dengan DevTools Style Editor

Cara paling cepat memastikan CSS terhubung: buka halaman di browser → klik kanan elemen → **Inspect** (atau tekan F12) → buka tab **Styles**. Jika file terhubung dengan benar, kamu akan melihat aturan CSS beserta nama file dan nomor barisnya. Jika tab Styles kosong padahal elemennya di-*inspect*, besar kemungkinan link-nya salah.

Di tab Styles ini kamu juga bisa:
- Mencentang/menghilangkan centang pada property untuk melihat efeknya.
- Mengetik property baru untuk bereksperimen tanpa mengubah file.
- Melihat komputasi akhir (tab **Computed**) untuk mengetahui nilai final sebuah elemen.

## 4. Analogi Sederhana — Membangun Rumah

Bayangkan proyek web kamu seperti membangun rumah:

- **HTML** adalah kerangka dan struktur rumah — dinding, pintu, kamar-kamar. Ini yang pertama dibangun dan menentukan bentuk bangunan.
- **CSS** adalah cat, interior, dan dekorasi — warna dinding, jenis lantai, pemasangan keramik, penataan furnitur. Ini yang membuat rumah terasa nyaman dan indah.
- **JavaScript** (nanti di Level 4) adalah instalasi listrik — membuat lampu menyala, saklar berfungsi, perangkat bisa hidup.

Menghubungkan CSS ke HTML itu seperti **memanggil tukang cat yang datang membawa buku panduan warna untuk seluruh rumah**. Kamu memberikan satu buku panduan (file `style.css`) ke tukang cat, dan dia menggunakannya di semua ruangan. 

- **External CSS** = tukang cat datang dengan buku panduan warna untuk seluruh rumah. Satu buku, semua ruangan pakai aturan yang sama. Mau ganti warna semua dinding? Cukup ubah satu buku.
- **Internal CSS** = kamu menulis catatan warna kecil dan menempelnya di dinding satu ruangan saja. Ruangan lain tidak tahu apa-apa soal itu.
- **Inline CSS** = kamu berdiri di depan satu dinding dan berkata "cat dinding ini merah" secara lisan, tanpa menulis di mana pun. Tukang cat hanya ingat saat itu juga; besok dia lupa, dan kamu tidak punya jejak tertulis apa yang sudah dilakukan.

Jelas kan kenapa buku panduan terpisah untuk seluruh rumah jauh lebih masuk akal daripada catatan tempel atau instruksi lisan? Itulah kenapa external CSS selalu jadi pilihan utama.

## 5. Kapan Harus Digunakan & Kasus Penggunaan (Use Cases)

- **Setiap halaman proyek yang lebih dari satu halaman.** Beranda, katalog, tentang, kontak — semuanya share satu `style.css` agar tampilan konsisten. Ini kasus utama kita.
- **Rebranding besar tanpa menyentuh HTML.** Ketika Perpustakaan Digital Kota ganti warna brand (misal dari biru ke hijau), cukup ubah variabel warna di `style.css`. Tidak ada satu pun file HTML yang perlu diubah.
- **Mode maintenance / handover proyek.** Developer baru masuk tim. Dengan CSS yang terpisah dan terstruktur (`reset.css`, `style.css`, `components.css`), dia langsung paham di mana harus mencari bagian tertentu tanpa harus membaca seluruh HTML.
- **Prototyping cepat.** Sedang mencoba gaya heading atau form, dan belum mau komit ke file terpisah? Internal `<style>` sah-sah saja untuk sesi eksperimen singkat — lalu pindahkan hasilnya ke file eksternal begitu sudah mantap.
- **Optimasi performa.** Situs perpustakaan dengan banyak halaman: satu CSS eksternal yang di-cache membuat navigasi antar halaman terasa instan setelah kunjungan pertama.

## 6. Poin-poin Penting & Best Practices

- **Selalu pakai external CSS** dengan `<link rel="stylesheet">` di dalam `<head>`, bukan di akhir `<body>`. `rel` harus `stylesheet`, `href` harus benar.
- **Path relatif dihitung dari file HTML, bukan dari root folder proyek.** Jika `index.html` ada di akar dan CSS ada di `css/style.css`, maka `href="css/style.css"` benar. Jika halaman ada di subfolder, sesuaikan dengan `../`.
- **Gunakan path yang bisa di-cache dan konsisten.** Satu file utama (`style.css`) di semua halaman lebih baik daripada banyak file kecil yang di-include satu per satu.
- **Pisahkan peran file**: reset/normalize di `reset.css`, style global di `style.css`, komponen di `components.css`. Perhatikan urutan `<link>`.
- **Pisahkan concerns**: HTML tidak boleh berisi `style=""`, CSS tidak boleh ditulis di tengah markup.
- **Maksimalkan DevTools**: tab Styles adalah alat debugging paling ampuh. Biasakan inspect sebelum bertanya "kenapa nggak jalan".
- **Jangan campur `@import` dengan `<link>` bila tidak perlu.** `<link>` di HTML lebih cepat dan lebih mudah dideteksi masalahnya oleh DevTools.
- **Gunakan Live Server** (VS Code) agar setiap simpan file CSS langsung ter-refresh di browser.

## 7. Kesalahan Umum (Common Pitfalls & Bugs)

- **Lupa menulis `<link>` di `<head>`.** Style ditulis di file CSS, tapi file itu tidak pernah dipanggil. Gejalanya: tidak ada satu pun style yang jalan. Perbaikannya: tambahkan `<link rel="stylesheet" href="css/style.css">` di `<head>`.
- **Path salah.** Contoh: menulis `href="style.css"` padahal file ada di folder `css/`, atau menulis `href="../css/style.css"` padahal halaman ada di akar. Gejala: tab Styles di DevTools kosong dan ada peringatan 404 di tab Network. Perbaikannya: hitung path relatif dari lokasi file HTML ke file CSS.
- **Salah ketik `rel`.** Menulis `rel="stylesheet"` sebagai `rel="style"` atau `rel="stylesheet"` dalam tanda kutip yang salah membuat browser mengabaikannya. Selalu `rel="stylesheet"`.
- **File CSS di-cache versi lama.** Kamu sudah mengubah CSS tapi browser tetap menampilkan yang lama. Perbaikannya: hard refresh (Ctrl+Shift+R) atau buka DevTools → tab Network → centang **Disable cache**. Di produksi, tambahkan versi pada href: `href="css/style.css?v=2"`.
- **Menggunakan inline style berlebihan.** Mudah dulu, tapi sangat sulit di-override nanti (spesifitas tertinggi). Perbaikannya: pindahkan semua style ke class di file eksternal.
- **Menempel `<style>` di tengah `<body>`.** Boleh secara teknis, tapi membingungkan dan tidak valid secara praktik. Selalu taruh `<style>` di `<head>`, atau lebih baik lagi pakai file eksternal.
- **Urutan `<link>` salah.** `reset.css` yang di-link setelah `style.css` akan menimpa style kamu. Perbaiki urutan: reset → style → components.

## 8. Mini Project / Soal Latihan & Kunci Jawaban

### Tantangan 1

Buat file `css/style.css` dan hubungkan ke `index.html` milik Perpustakaan Digital Kota. Di dalam file CSS, style `h1` dengan warna `#2563eb`, dan `p` dengan warna `#475569` serta ukuran `1.1rem`. Buka halaman di browser, lalu buka DevTools → tab Styles, dan pastikan kamu bisa melihat dua aturan tersebut beserta nama filenya.

### Solusi & Pembahasan 1

```html
<!-- index.html -->
<!DOCTYPE html>
<html lang="id">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Perpustakaan Digital Kota</title>
    <link rel="stylesheet" href="css/style.css">
</head>
<body>
    <h1>Perpustakaan Digital Kota</h1>
    <p>Selamat datang di perpustakaan digital kami.</p>
</body>
</html>
```

```css
/* css/style.css */
h1 {
    color: #2563eb;
}

p {
    color: #475569;
    font-size: 1.1rem;
}
```

**Pembahasan:** Pastikan `index.html` dan folder `css/` berada dalam satu folder yang sama (`perpustakaan-web/`). Karena `index.html` ada di akar, `href` cukup `css/style.css` (relatif dari file HTML). Di DevTools, elemen `<h1>` harus menampilkan aturan `color: #2563eb` dari `style.css`. Jika tidak, cek: file `style.css` benar-benar ada di folder `css`? Nama filenya cocok persis (termasuk huruf besar/kecil)? Apakah tab Network menampilkan status 200 untuk file CSS?

### Tantangan 2

Sebuah halaman katalog baru dibuat di subfolder `halaman/katalog.html`. Struktur foldernya:

```
perpustakaan-web/
├── index.html
├── halaman/
│   └── katalog.html
└── css/
    └── style.css
```

Tuliskan tag `<link>` yang benar di `katalog.html` agar `style.css` terbaca. Kemudian jelaskan apa yang terjadi jika `<link>` tersebut diletakkan di dalam `<body>` bukan `<head>`.

### Solusi & Pembahasan 2

```html
<!-- halaman/katalog.html -->
<head>
    <meta charset="UTF-8">
    <title>Katalog Buku — Perpustakaan Digital Kota</title>
    <link rel="stylesheet" href="../css/style.css">
</head>
```

**Pembahasan:** Dari `halaman/katalog.html`, kamu harus naik satu level keluar dari folder `halaman/` dulu (`../`), baru masuk ke folder `css/`. Maka path-nya `../css/style.css`. Jika `<link>` diletakkan di `<body>`, browser tetap akan memprosesnya (CSS adalah *render-blocking resource*, jadi halaman menunggu CSS dimuat), tapi ini bukan praktik yang baik: tidak konsisten dengan standar, bisa menyebabkan flash-of-unstyled-content (halaman tampil polos sebentar sebelum CSS terbaca), dan membuat struktur HTML kotor. Selalu letakkan `<link rel="stylesheet">` di dalam `<head>`.
