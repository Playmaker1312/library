# 1. Cara Browser Bekerja — Sebelum Menulis Kode

Sebelum menulis satu baris pun HTML, penting untuk memahami bagaimana browser mengubah teks kode menjadi halaman yang bisa dilihat. Materi ini mengupas alur lengkap dari kamu mengetik URL sampai halaman tampil, plus cara memeriksa hasilnya lewat DevTools.

## 1. Penjelasan Singkat & Konsep Dasar

Kita mulai dari pertanyaan paling dasar: apa yang sebenarnya terjadi ketika kamu membuka `google.com`? Banyak pemula mengira browser punya "kumpulan website" di dalamnya. Kenyataannya tidak. Browser hanyalah alat yang **meminta** file ke komputer lain (server) lalu **menampilkan** hasilnya.

Alurnya berjalan kurang lebih seperti ini:

```
Kamu ketik URL di browser
        ↓
Browser tanya ke DNS: "google.com itu IP berapa?"
        ↓
DNS jawab: "142.250.x.x"
        ↓
Browser kirim HTTP request ke server Google
        ↓
Server kirim balik file HTML, CSS, JavaScript
        ↓
Browser baca HTML → buat DOM (pohon struktur halaman)
Browser baca CSS  → hitung tampilan setiap elemen
Browser baca JS   → jalankan logika interaktif
        ↓
Halaman tampil di layarmu
```

Ada beberapa komponen yang perlu dipahami. **DNS (Domain Name System)** adalah "buku telepon internet" — manusia ingat nama (`google.com`), komputer ingat angka (IP address `142.250.x.x`). **HTTP request** adalah permintaan formal browser ke server, sedangkan **HTTP response** adalah kiriman balik dari server berisi file yang diminta.

Yang paling penting untuk diingat di Level 1: **browser membaca HTML dari atas ke bawah, baris per baris**. Satu halaman web minimal terdiri dari satu file `.html`. Browser mengubah struktur tag HTML menjadi **DOM (Document Object Model)** — sebuah pohon struktur yang mewakili halaman secara logis, yang nantinya dipakai sebagai "peta" untuk menampilkan konten, menerapkan CSS, dan menjalankan JavaScript.

**Benang merah**: materi ini adalah gerbang masuk seluruh roadmap. Pemahaman "browser membaca dari atas ke bawah" menjelaskan kenapa struktur HTML harus rapi dan berurutan (materi 3 dan 4). Nanti di Level 2 kamu akan melihat CSS bekerja mengubah tampilan DOM, lalu di Level 4-5 JavaScript memanipulasi DOM yang sama. Semuanya menumpuk di atas pemahaman "browser membaca dan membangun DOM".

## 2. Fungsi & Kegunaan Utama dalam Web

Pemahaman ini menyelesaikan banyak kebingungan klasik pemula: "kenapa tag harus ditutup?", "kenapa salah urutan bisa merusak tampilan?", "kenapa ada file HTML, CSS, dan JS terpisah?". Jawabannya satu: karena browser membaca setiap file dengan peran yang berbeda — HTML membangun struktur, CSS mengatur penampilan, JS mengatur perilaku.

Dalam project **Perpustakaan Digital Kota**, alur ini muncul setiap hari. Saat pengunjung membuka `perpustakaan.kota.id`, browser meminta file `index.html` dari server. Server mengirim file itu beserta CSS-nya. Browser membangun DOM, lalu menampilkan judul, navigasi, dan daftar buku. Dengan memahami alur ini kamu bisa menjawab pertanyaan debugging paling umum: *"kenapa halaman saya tidak muncul?"* — biasanya karena file tidak ditemukan (path salah) atau tag tidak valid, dan keduanya adalah masalah di file yang kamu kirim, bukan di browser.

Selain itu, **DevTools (tekan F12)** adalah jendela ke dalam cara kerja browser. Tab **Elements** menampilkan DOM persis seperti yang sedang ditampilkan browser — bukan sekadar file HTML mentahnya. Kamu bisa melihat hierarki elemen, mengedit sementara, dan mengecek hasilnya secara instan. Ini alat investigasi paling penting sepanjang karirmu sebagai web developer.

**Penting untuk Level 1-3**: kamu tidak perlu menjalankan server sungguhan. File `.html` bisa langsung dibuka di browser, karena browser membaca file lokal persis seperti membaca file dari server.

## 3. Contoh Kode & Implementasi Real-World

Karena materi ini fondasi konseptual, contohnya berupa alur ringkas dan langkah pemeriksaan DevTools. Simpan file berikut sebagai `alur-browser.html` lalu buka di browser.

```html
<!-- alur-browser.html -->
<!-- Contoh: halaman sederhana untuk memeriksa alur "browser → file → tampilan" -->

<!DOCTYPE html>
<html lang="id">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Alur Cara Browser Bekerja</title>
</head>
<body>
    <!-- h1: judul utama halaman — hanya satu per halaman -->
    <h1>Cara Browser Bekerja</h1>

    <p>Alur ketika kamu membuka sebuah website:</p>

    <!-- pre: teks dengan spasi dan baris baru yang dipertahankan -->
    <!-- Biasa dipakai untuk menampilkan diagram teks atau kode -->
    <pre>
Ketik URL        →  Browser tanya DNS
    ↓                      ↓
Server kirim    ←  HTTP request dikirim
    ↓
Browser baca HTML → buat DOM → tampilkan
    </pre>

    <p>
        Tekan <strong>F12</strong> lalu buka tab
        <em>Elements</em> untuk melihat DOM hasil
        pembacaan browser.
    </p>
</body>
</html>
```

**Cara memeriksa hasilnya:**

1. Simpan file di atas, buka dengan dobel klik (atau drag ke jendela browser).
2. Tekan `F12` untuk membuka DevTools, lalu klik tab **Elements**.
3. Perhatikan: yang kamu lihat di tab Elements adalah **DOM**, bukan file mentah. Browser sudah "membaca" HTML dan membangun pohon strukturnya.
4. Coba klik kanan pada teks `<h1>` di tab Elements, lalu pilih **Edit as HTML** dan ubah teksnya. Perhatikan bagaimana tampilan halaman berubah secara langsung — ini bukti nyata bahwa tampilan browser bergantung pada DOM.

## 4. Analogi Sederhana — Membangun Rumah

Bayangkan browser adalah **kontraktor** yang membangun rumah sesuai **gambar kerja (HTML)**.

Sebelum kontraktor mulai, dia harus membaca semua gambar dan memahami urutannya: fondasi harus dicetak lebih dulu, baru tiang, baru dinding. Sama persis dengan browser yang membaca HTML **dari atas ke bawah** — elemen di bawah akan ikut bergeser jika elemen di atasnya berubah. Itulah kenapa urutan di HTML sangat berarti.

Di rumahmu nanti:
- **HTML** adalah pondasi, kerangka, dan ruang-ruangnya — inilah struktur yang sedang kita bangun di Level 1.
- **CSS** adalah cat, interior, dan hiasan dinding — akan datang di Level 2.
- **JavaScript** adalah instalasi listrik dan otomatisasi (lampu yang nyala sendiri saat pintu terbuka) — datang di Level 4 ke atas.

Kesalahpahaman umum: pemula mengecat dinding (CSS) sebelum fondasi (HTML) berdiri, lalu bingung kenapa rumahnya ambruk. Materi ini memastikan kamu tahu cara kontraktor bekerja, sehingga kamu bisa menulis gambar kerja yang benar sejak awal.

## 5. Kapan Harus Digunakan & Kasus Penggunaan (Use Cases)

- **Mencurigai markup rusak atau elemen tidak tampil** — buka tab Elements di DevTools untuk melihat DOM sebenarnya, bukan menebak dari file mentah.
- **Ingin tahu kenapa halaman "tiba-tiba" tidak muncul di HP** — periksa apakah HTML valid; browser yang berbeda sedikit berbeda, dan markup tidak valid bisa ditafsirkan ulang.
- **Membagikan hasil pekerjaan cepat tanpa server** — buka file `.html` langsung di browser; cukup untuk pamer progress di Level 1-3.
- **Belajar memahami file yang sudah ada (misal template atau website orang lain)** — DevTools → Elements membedah struktur halaman siapa pun, jadi kamu bisa belajar dari situs nyata.
- **Sebelum belajar JavaScript** — kamu wajib paham konsep DOM, karena manipulasi DOM (Level 4-5) tidak mungkin dipahami tanpa tahu bahwa browser membangun pohon DOM dari HTML.

## 6. Poin-poin Penting & Best Practices

- Pahami bahwa browser membaca HTML **dari atas ke bawah** secara berurutan.
- Ingat peran tiga file: **HTML = struktur, CSS = tampilan, JS = perilaku** — jangan campur peran sejak awal.
- Biasakan memeriksa hasil dengan **F12 → tab Elements**; itu adalah "X-ray" untuk melihat DOM yang sedang ditampilkan browser.
- Ketika gambar atau file lain tidak muncul, periksa **path** — ini penyebab paling umum masalah di tahap belajar.
- Copy-paste dari Word atau sumber lain sering membawa karakter tersembunyi yang bisa memecah markup tepat di file HTML.
- Satu halaman = minimal satu `.html`. Simpan setiap halaman sebagai file terpisah (`index.html`, `katalog.html`, dst).
- Untuk Level 1-3, tidak perlu server — buka file langsung. Server baru diperlukan saat membahas data dan JavaScript tingkat lanjut (Level 5+).

## 7. Kesalahan Umum (Common Pitfalls & Bugs)

- **Menebak masalah dari file mentah, bukan dari DOM.** File HTML yang tertulis rapi belum tentu tampil rapi jika ada tag yang tidak valid. Solusi: selalu cek tab Elements untuk melihat apa yang *sebenarnya* dipahami browser.
- **Mengira browser "menyimpan" website.** Browser tidak menyimpan semua situs; ia meminta file setiap kali. Itu sebabnya perubahan di editor harus disimpan lalu browser di-refresh.
- **Mengira urutan tidak penting.** Karena browser membaca dari atas ke bawah, markup yang ditaruh asal-asalan menghasilkan struktur DOM yang absurd. Solusi: susun konten secara logis, apa pun tampilannya nanti.
- **Langsung panik saat gambar tidak muncul.** Gambar yang hilang biasanya karena path salah (`images/buku.jpg` tidak ada), bukan karena "internet error". Periksa folder dan nama file dengan teliti.

## 8. Mini Project / Soal Latihan & Kunci Jawaban

### Tantangan

Buat halaman **`cara-browser-bekerja.html`** yang menjelaskan alur "cara browser bekerja" dengan struktur logis: judul utama, penjelasan singkat, dan diagram alur memakai `<pre>`. Di bagian akhir, tambahkan satu paragraf berisi catatan "Tekan F12 untuk melihat DOM". Setelah selesai, buka di browser, tekan F12, dan periksa bahwa tab Elements menampilkan struktur yang kamu tulis.

### Solusi & Pembahasan

```html
<!-- cara-browser-bekerja.html -->
<!DOCTYPE html>
<html lang="id">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Cara Browser Bekerja</title>
</head>
<body>
    <!-- Satu h1: judul utama halaman -->
    <h1>Cara Browser Bekerja</h1>

    <p>Berikut alur ketika kamu membuka sebuah website:</p>

    <!-- pre: diagram alur dengan spasi & baris baru yang persis sama -->
    <pre>
Ketik URL (misal: google.com)
        ↓
Browser tanya DNS untuk mendapatkan IP
        ↓
Browser kirim HTTP request ke server
        ↓
Server mengirim file HTML, CSS, dan JS
        ↓
Browser membangun DOM → halaman tampil
    </pre>

    <p>
        Tekan <strong>F12</strong> dan buka tab
        <em>Elements</em> untuk melihat DOM yang
        sudah dibangun browser.
    </p>
</body>
</html>
```

Langkah pengerjaan:
1. Buat file `cara-browser-bekerja.html` lalu isi dengan kode di atas.
2. Simpan dan buka di browser. Halaman menampilkan judul, penjelasan, dan diagram alur.
3. Tekan F12 → tab Elements. Kamu akan melihat hierarki yang sama dengan struktur di file. Coba ubah teks `<h1>` lewat "Edit as HTML" dan perhatikan perubahannya — itulah bukti DOM bekerja.

**Pembahasan**: latihan ini melatih dua hal sekaligus — kemampuan menulis struktur HTML yang logis (konten berurutan: judul → penjelasan → diagram → catatan), dan kebiasaan memverifikasi hasil lewat DevTools. Kedua kebiasaan ini akan terus dipakai di semua level berikutnya.
