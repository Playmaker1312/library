# 20. Variabel — let, const, dan Mengapa Bukan var

Variabel adalah cara JavaScript menyimpan dan menamai nilai agar bisa dipakai, diubah, dan dibandingkan. Materi ini menjelaskan tiga cara mendeklarasikan variabel di JavaScript modern — `let`, `const`, dan `var` — serta alasan kenapa `var` sebaiknya tidak pernah dipakai lagi.

## 1. Penjelasan Singkat & Konsep Dasar

Sebuah website perpustakaan selalu punya data yang perlu diingat: judul buku, jumlah stok, harga, nama anggota. Di JavaScript, data itu disimpan dalam **variabel** — semacam label yang menunjuk ke sebuah nilai. Misalnya `let stok = 10;` berarti "saya punya wadah bernama `stok` yang berisi 10". Seluruh logika program pada dasarnya membaca dan mengubah wadah-wadah ini.

JavaScript modern punya tiga kata kunci deklarasi, dan masing-masing punya karakter berbeda. **`var`** adalah cara lama yang membawa tiga masalah: *function-scoped* (tidak tahu batas blok `{}`, hanya batas fungsi — paling longgar), *bisa di-redeclare* di scope yang sama, dan *hoisted* (diangkat ke atas scope saat dijalankan, sehingga nilainya `undefined` sebelum baris deklarasinya). Kombinasi tiga hal ini menghasilkan bug yang sulit dilacak. Karena itu komunitas JavaScript sepakat: **jangan gunakan `var`**.

Penggantinya adalah `let` dan `const` dari ES6 (2015). **`let`** bersifat mutable (nilainya bisa diubah) dan **block-scoped** — cuma hidup di dalam blok `{}` tempat dia dideklarasikan. **`const`** bersifat immutable sebagai *binding*: variabelnya tidak bisa **di-reassign** (tidak boleh ditunjuk ke nilai berbeda). Tapi penting dibedakan: **reassign** (mengganti seluruh nilai variabel) berbeda dengan **mutate** (mengubah isi dari object/array yang sudah ditunjuk). `const buku = {}` tidak mengizinkan `buku = {}` kembali, tetapi `buku.stok = 4` **tetap sah** karena kita mengubah *isi object*, bukan mengganti variabelnya.

Lalu ada soal **hoisting** dengan `let`/`const`. Keduanya juga diangkat ke atas scope, tapi tidak seperti `var`, mereka masuk ke **temporal dead zone (TDZ)**: sejak awal blok sampai baris deklarasi, variabel tersebut "ada di zona mati" — mengaksesnya sebelum baris deklarasi melemparkan `ReferenceError`. Ini justru bagus: error di situasi dini lebih jelas daripada diam-diam membaca `undefined`. Ringkasnya, TDZ menjaga kamu dari salah sangka bahwa variabel "sudah kelihatan" padahal belum diisi.

**Benang merah**: di Level 1-3 kamu menulis konten secara statis di HTML. Mulai Level 4, data buku yang tadinya "diingat" oleh tag HTML harus "diingat" oleh variabel JavaScript — nanti di Level 5 variabel itu dipakai untuk membangun dan memperbarui DOM secara dinamis. Memilih `let`/`const` yang tepat sejak sekarang membuat logika aplikasimu lebih mudah ditebak.

## 2. Fungsi & Kegunaan Utama dalam Web

Di **Perpustakaan Digital Kota**, perbedaan `let` vs `const` sering menjadi keputusan desain nyata:

- **Nilai tetap → `const`.** Nama perpustakaan, maksimum buku yang bisa dipinjam, array `katalog` sebagai sumber data, atau tarif denda adalah konstanta. Memakaikan `const` pada nilai-nilai ini mencegah program tidak sengaja mengubah kebijakan di tengah jalan.
- **Nilai berubah → `let`.** Jumlah stok yang berkurang setiap peminjaman, hasil filter yang berubah saat pengunjung mengetik kata kunci pencarian, atau counter nilai keranjang — nilai-nilai ini memang harus bisa di-update, jadi `let`.
- **Data yang "berubah isinya" tapi referensinya tetap → `const` pada array/object.** Misalnya `const katalog = [ ... ]` lalu `katalog.push({ ... })`. Kita *mengubah* isi array (mutate) tapi *tidak mengganti referensinya* — persis seperti mengingat satu buku catatan katalog yang isinya terus bertambah, bukan setiap kali ganti buku catatan.

Pola "konfigurasi pakai `const`, kondisi berjalan pakai `let`, `var` tak pernah" ini menjaga kode katalog tetap terprediksi: konstanta tidak bisa corrupt, dan state yang berubah-ubah lokasinya jelas.

## 3. Contoh Kode & Implementasi Real-World

```javascript
// js/main.js — bagian variabel (materi 20)

// ─── var: cara lama — JANGAN DIPAKAI ─────────────────────────────────────
var nama = "Budi";          // bisa di-redeclare:
var nama = "Siti";          // sah tapi membingungkan (hoisted ke atas scope)
if (true) { var tersembunyi = "bocor keluar blok"; }
console.log(tersembunyi);   // "bocor keluar blok" — var mengabaikan blok!

// ─── let: nilai bisa diubah, block-scoped ────────────────────────────────
let stokBuku = 10;          // deklarasi dengan nilai awal
stokBuku = 8;               // ✅ boleh diubah (mutable)
// let stokBuku = 3;        // ❌ SyntaxError: redeclare tidak diizinkan

if (stokBuku < 10) {
    let pesanRestok = "Stok tipis, ajukan pengadaan";
    console.log(pesanRestok);   // ✅ bisa diakses di dalam blok
}
// console.log(pesanRestok);    // ❌ ReferenceError — di luar blok, tidak terlihat

// ─── const: binding tidak bisa di-reassign, tapi isinya bisa di-mutate ───
const NAMA_PERPUSTAKAAN = "Perpustakaan Digital Kota";
const MAKS_PINJAM = 5;
// NAMA_PERPUSTAKAAN = "Perpustakaan Baru"; // ❌ TypeError: Assignment to constant variable

const buku = { judul: "Clean Code", stok: 5, harga: 150000 };
buku.stok = 4;                 // ✅ mutate: mengubah property object — SAH
buku.rating = 4.8;             // ✅ mutate: menambah property baru — SAH
// buku = { judul: "Lain" };   // ❌ reassign: mengganti variabel — TIDAK SAH

const katalog = [
    { id: 1, judul: "Clean Code",     stok: 5 },
    { id: 2, judul: "Laskar Pelangi", stok: 3 },
];
katalog.push({ id: 3, judul: "Cosmos", stok: 8 }); // ✅ mutate array — SAH
// katalog = [];                  // ❌ reassign — TIDAK SAH

// ─── Reassign vs Mutate — perbedaan penting yang sering salah paham ──────
// Reassign: mengganti seluruh nilai yang ditunjuk variabel (tidak boleh utk const)
// Mutate  : mengubah isi dari objek/array yang sama (boleh utk const)

// ─── TDZ (Temporal Dead Zone) pada let/const ─────────────────────────────
console.log(sebelumDeklarasi);   // ❌ ReferenceError (bukan undefined!)
let sebelumDeklarasi = "sekadar contoh"; // baris inilah akhir TDZ-nya

/*
Aturan emas:
1. Selalu mulai dengan const.
2. Jika nanti ternyata nilai harus diubah, ganti ke let.
3. Jangan pernah pakai var.
*/
```

## 4. Analogi Sederhana — Membangun Rumah

Di rumah kita, **variabel adalah wadah atau terminal kabel yang diberi label**. Kamu punya banyak stop kontak dan kabel, dan setiap kabel harus punya label jelas — "saklar lampu ruang tamu", "saklar AC" — supaya saat listrik diperbaiki, kamu tahu kabel mana yang pegang tegangan apa.

**`const` adalah kabel tetap yang tidak bisa dipindah**: sekali kamu pasang terminal lampu di titik itu, kamu tidak bisa mencabutnya dan memindahkan ke titik lain; nilainya terikat selamanya. **`let` adalah stop kontak yang bisa ganti posisi**: isi tegangan tetap bisa kamu ubah sesuai kebutuhan, dan kamu bebas menyalakan ulang. **`var` adalah kabel yang "diangkat" jauh-jauh dari tempatnya**: di dunia nyata itu artinya kabel acak-acakan yang bisa menyambung ke tempat yang tak kamu duga — persis kebingungan yang diberi `function-scoped` dan hoisting.

Yang harus diingat: menamai variabel dengan jelas (seperti melabeli kabel) adalah perbedaan antara rumah yang nyaman diperbaiki dan rumah yang jalinan kabelnya tidak masuk akal.

## 5. Kapan Harus Digunakan & Kasus Penggunaan (Use Cases)

- **Konstanta kebijakan perpustakaan** — `const MAKS_PINJAM = 5`, `const TARIF_DENDA = 1000`: nilai ini dipakai di banyak halaman dan tidak boleh berubah tanpa disengaja.
- **State yang berubah-ubah** — `let hasilFilter`, `let stokSisa`: nilai baru di-assign setiap kali user meminjam buku atau memfilter katalog.
- **Data utama koleksi** — `const katalog = [...]`: referensinya tetap, tapi elemennya terus di-push/update saat Level 5 (tambah hapus buku), memanfaatkan perbedaan mutate vs reassign.
- **Scope yang rapi di dalam loop dan kondisi** — `let` bisa di-deklarasi ulang di blok berbeda tanpa konflik (variabel identik di dua blok berbeda tidak saling menimpa), berbeda dengan `var`.
- **Debugging misteri "kenapa nilainya berubah-ubah"** — dengan `const` untuk nilai tetap dan `let` untuk nilai dinamis, kesalahan assignment (`TypeError`) langsung muncul dan lebih cepat dilacak.

## 6. Poin-poin Penting & Best Practices

- **Selalu `const` dulu**, ubah ke `let` hanya jika ada kebutuhan reassign; **`var` dihindari total** di kode modern.
- Pahami perbedaan istilah: **reassign** (ganti nilai variabel — dilarang untuk `const`) vs **mutate** (ubah isi object/array — diperbolehkan untuk `const`).
- `let` dan `const` adalah **block-scoped**; `var` function-scoped dan **hoisted dengan nilai `undefined`** — itulah akar bug-nya.
- Ketahuilah **TDZ**: mengakses `let`/`const` sebelum baris deklarasi melempar `ReferenceError`, bukan membaca `undefined`. Ini perlindungan, bukan kekurangan.
- Gunakan **nama deskriptif** dalam camelCase untuk variabel (`stokBuku`, `totalHarga`), dan huruf besar untuk konstanta yang dibedakan (`MAKS_PINJAM`) jika itu konvensi project-mu.
- Sebagai catatan **Type Safety**: di fase awal, disiplinkan dirimu memilih tipe nilai yang konsisten (jangan ubah `let stok = 8` menjadi `stok = "habis"` sembarangan — lihat materi 21). Di project besar, TypeScript akan menormalisasi kebiasaan ini secara otomatis lewat tipe statis.
- Ini bagian dari fondasi ES6+; materi berikutnya (21) memakai `const`/`let`, template literal, dan destructuring sebagai gaya penulisan default.

## 7. Kesalahan Umum (Common Pitfalls & Bugs)

- **Reassign `const` → `TypeError: Assignment to constant variable`.** Contoh: `const MAKS = 5; MAKS = 10;`. Perbaikan: jika nilai harus berubah, gunakan `let`; jika tidak, pertahankan `const`.
- **Mengira "const tapi isinya bisa berubah" itu aneh/bug.** `const katalog.push(...)` berjalan normal dan *memang* diizinkan — yang dilarang hanya mengganti referensinya. Pahami mutate vs reassign untuk tenang memakai `const` pada array/object.
- **Variabel memakai `var` lalu nilainya diam-diam jadi `undefined` atau bocor keluar blok.** Misal akses variabel sebelum deklarasi membaca `undefined` tanpa error. Perbaikan: gunakan `let`/`const` (yang memunculkan `ReferenceError` dengan jelas alias TDZ).
- **Akses `let`/`const` sebelum deklarasi dan bingung kenapa error.** Ini TDZ yang bekerja sebagaimana mestinya; letakkan deklarasi di atas penggunaannya.

## 8. Mini Project / Soal Latihan & Kunci Jawaban

### Tantangan

Buat `js/latihan-20.js` yang merepresentasikan data katalog buku perpustakaan dengan aturan berikut:

1. Deklarasikan dengan `const`: nama perpustakaan, maksimum pinjaman (5), dan array `katalog` berisi 3 object buku (`id`, `judul`, `stok`, `harga`).
2. Gunakan `let` untuk memodelkan peminjaman: kurangi stok buku id 1 sebanyak 1, lalu tambah properti `pinjamanBulanIni` pada object buku tersebut.
3. Tampilkan ke Console: nama perpustakaan, stok buku id 1 setelah dipinjam, dan total isi katalog (`katalog.length`).
4. Jawab dengan komentar singkat: kenapa peminjaman stok bisa dilakukan padahal `katalog` deklarasi `const`? Mengapa memakai `var` untuk bagian ini tidak direkomendasikan?

### Solusi & Pembahasan

```javascript
// js/latihan-20.js
// 1. Konstanta: nilai tetap yang tidak pernah berubah
const NAMA_PERPUSTAKAAN = "Perpustakaan Digital Kota";
const MAKS_PINJAM = 5;

const katalog = [
    { id: 1, judul: "Clean Code",       stok: 8,  harga: 150000 },
    { id: 2, judul: "Laskar Pelangi",   stok: 3,  harga:  95000 },
    { id: 3, judul: "Cosmos",           stok: 12, harga: 200000 },
];

// 2. Simulasi peminjaman: stok berubah → let (state dinamis)
let stokDipinjam = katalog[0].stok - 1;   // nilai berubah → let
katalog[0].stok = stokDipinjam;             // mutate property object di dalam array
katalog[0].pinjamanBulanIni = 1;            // tambah property baru (mutate)

// 3. Output
console.log(`Perpustakaan: ${NAMA_PERPUSTAKAAN}`);
console.log(`Stok "Clean Code" setelah dipinjam: ${katalog[0].stok}`);
console.log(`Jumlah judul di katalog: ${katalog.length}`);

/*
4. Penjelasan:
- Peminjaman mengubah `katalog[0].stok`, bukan mengganti variabel `katalog`
  itu sendiri → itu MUTATE, yang sah dilakukan pada `const`.
- Jika kita menulis `katalog = []` baru error `TypeError` karena itu REASSIGN.
- `var` tidak dipakai karena function-scoped longgar + hoisting membuat stok
  mudah "bocor" dan terbaca `undefined`; `let`/`const` dengan block-scope
  dan TDZ membuat behavior jauh lebih terprediksi.
*/
```

**Pembahasan**: Latihan ini memisahkan dua konsep inti materi 20. **Reassign** = mengganti nilai yang ditunjuk variabel (`stok` diubah via `let`, dan itu diizinkan; mengganti `katalog` dengan tanda `=` tidak). **Mutate** = mengubah isi object/array di balik referensi yang sama (`katalog[0].stok = ...` dan penambahan property `pinjamanBulanIni`), yang tetap sah pada `const`. Aturan "const dulu, let kalau perlu, var tak pernah" membuat data katalog ikut ter-restructuring dengan aman tanpa risiko state tersembunyi.
