# 31. Promise dan Async/Await — Handle Operasi Async

Materi ini mengajarkan cara JavaScript menangani operasi yang memakan waktu — permintaan data ke server — tanpa membekukan halaman: **Promise** sebagai "janji" hasil, lalu pola modern **async/await + try/catch** yang jauh lebih mudah dibaca. Inilah jembatan dari data hardcode (Level 5) menuju data nyata dari API di Level 6.

## 1. Penjelasan Singkat & Konsep Dasar

Di Level 5 kamu bekerja dengan array `katalog` yang ditulis langsung di kode — datanya sudah ada di memori, sehingga DOM langsung ter-render. Tinggal satu masalah: pada aplikasi sungguhan, data tidak ada di laptop user. Data berada di komputer server jauh di sana, dan mengirimkannya butuh waktu — hitungan milidetik bila koneksi baik, atau beberapa detik bila lambat. Jika JavaScript harus menunggu diam-diam sampai data tiba, seluruh halaman membeku dan user mengira aplikasinya macet.

JavaScript adalah bahasa **single-threaded**: satu jalur eksekusi, dan satu perintah tidak bisa berjalan bersamaan dengan perintah lain. Namun jalan keluarnya bukan berhenti menunggu — melainkan **menjadwalkan**. Operasi yang lambat (meminta data ke server) dijalankan sebagai tugas background, sementara kode selanjutnya tetap berjalan. Begitu hasilnya siap, hasil itu dibawa kembali. Mekanisme inilah yang disebut **asynchronous** (async), dan objek yang mewakili "pekerjaan yang sedang berjalan, akan selesai, atau gagal" adalah **Promise**.

**Promise** memiliki tiga keadaan (states): **`pending`** (sedang berjalan, belum ada hasil), **`resolved`**/`fulfilled` (berhasil, membawa nilai hasil), dan **`rejected`** (gagal, membawa alasan berupa objek `Error`). Kamu bisa "mengkonsumsi" sebuah Promise dengan tiga metode: `.then(fn)` untuk merespons keberhasilan, `.catch(fn)` untuk menangkap kegagalan, dan `.finally(fn)` untuk menjalankan kode apa pun hasilnya (misal menutup spinner). Pola ini bekerja, namun untuk alur yang berurutan, `.then` bersarang menjadi mumet.

Solusi modernnya adalah **`async`/`await`**: `async` menandai sebuah fungsi agar selalu mengembalikan Promise, dan `await` membuat JavaScript menunda baris berikutnya sampai Promise selesai — seolah-olah kode berjalan sinkron, padahal tersinkronisasi dengan event loop. Dengan **`try/catch`**, error ditangani dengan blok yang eksplisit. Fungsi inilah yang akan kamu pakai untuk berinteraksi dengan **`fetch`**, fungsi bawaan browser untuk melakukan HTTP request. `fetch` mengembalikan Promise, dan hasil pertamanya adalah objek `Response` — yang isi JSON-nya diambil dengan `await response.json()`.

Kata kunci yang harus selalu diingat: **`response.ok`**. `fetch` hanya menolak Promise bila jaringan benar-benar putus (biasanya berupa `TypeError`). Server yang merespons kode status 404, 400, atau 500 *tidak* membuat fetch gagal — hasilnya tetap "berhasil" secara Promise, tapi isinya adalah halaman error. Maka kita wajib memeriksa `response.ok` dan melemparkan error sendiri bila perlu. Itulah pembeda utama error **network** (tanpa internet, bisa dideteksi lewat `TypeError`) dan error **HTTP** (server merespons, tapi dengan kode kesalahan).

**Benang merah**: data yang di Level 5 berasa di memori kini berpindah ke server; DOM hanya menampilkan apa yang dibawa `await` dari `fetch`. Materi 32 menambahkan penyimpanan lokal untuk persisten, dan Level 7 merapikan seluruh pola ini ke dalam modul-modul `api.js`, `storage.js`, `ui.js` — arsitektur yang benar dimulai dari pemahaman async yang benar.

## 2. Fungsi & Kegunaan Utama dalam Web

Fungsi paling krusial di **Perpustakaan Digital Kota** adalah **katalog yang hidup dari internet**: pencarian buku memanggil `fetch("https://openlibrary.org/search.json?q=...")`, menunggu hasil, lalu merender kartu-kartu buku ke grid. Tanpa async, halaman katalog akan "diam" selama beberapa detik saat pengambilan data — user mengira aplikasi rusak. Dengan async, halaman tetap responsif sambil menunggu (spinner berputar), dan begitu data tiba, grid muncul.

Tiga pola HTTP yang umum dipakai. **GET** (paling sering) mengambil data: daftar buku, detail buku, atau hasil pencarian. **POST** mengirim data baru: menambah catatan peminjaman atau anggota. **PUT** memperbarui data yang sudah ada: mengubah stok buku atau memperpanjang masa pinjam. **DELETE** menghapus data: menghapus reservasi yang batal. Untuk POST/PUT, data dikirim sebagai **JSON body** — di-encode dengan `JSON.stringify` dan di-passing lewat opsi `fetch`, bersama header `Content-Type: application/json`.

Untuk tugas yang bisa berjalan beriringan — misalnya mengambil daftar buku unggulan **dan** daftar peminjaman **dan** profil anggota sekaligus — gunakan **`Promise.all`**. Promise di dalamnya dijalankan paralel, dan hasilnya menunggu yang paling lambat, bukan dijumlahkan berurutan. Jauh lebih cepat daripada `await` tiga kali berturut-turut.

Terakhir, skenario yang sering terjadi di aplikasi nyata: user mengetik cepat di kotak pencarian. Setiap huruf memicu fetch, dan fetch yang lebih lama bisa tiba *setelah* yang lebih baru — hasilnya menimpa yang benar. Ini disebut **race condition**. Solusinya **`AbortController`**: setiap pencarian baru membatalkan request yang masih berjalan, sehingga hanya respons pencarian terakhir yang dirender.

## 3. Contoh Kode & Implementasi Real-World

Satu file `api.js` yang merangkum semua pola: `fetch` + `response.ok`, pembedaan error network vs HTTP, metode GET/POST/PUT/DELETE, `Promise.all`, dan `AbortController`.

```javascript
// js/api.js

// ─── Wrapper fetch dasar: satu tempat untuk semua pengecekan error ─────────
async function request(url, opsi = {}) {
    const response = await fetch(url, {
        headers: { "Content-Type": "application/json", Accept: "application/json" },
        ...opsi,
    });

    if (!response.ok) {
        // Server merespons, tapi dengan kode error (400/404/500...).
        // Coba ambil pesan detail dari body; kalau bukan JSON, berikan pesan umum.
        const detail = await response.json().catch(() => null);
        throw new Error(detail?.message || `Terjadi kesalahan HTTP ${response.status}`);
    }
    return response.json();
}

// ─── CRUD buku dengan Open Library + API internal (GET/POST/PUT/DELETE) ────
const API_OPEN_LIBRARY = "https://openlibrary.org";
const API_INTERNAL     = "/api"; // nanti: backend milik perpustakaan sendiri

// GET: cari buku dari Open Library. Sanitasi query dengan encodeURIComponent!
export async function cariBukuOpenLibrary(query) {
    const url = `${API_OPEN_LIBRARY}/search.json?q=${encodeURIComponent(query)}&limit=20`;
    return request(url);
}

// GET: ambil satu buku dari server internal
export async function ambilBuku(id) {
    return request(`${API_INTERNAL}/buku/${id}`);
}

// POST: kirim buku baru sebagai JSON body
export async function tambahBuku(dataBuku) {
    return request(`${API_INTERNAL}/buku`, {
        method: "POST",
        body: JSON.stringify(dataBuku), // object → string JSON
    });
}

// PUT: update stok buku (keseluruhan data buku)
export async function updateBuku(id, dataBuku) {
    return request(`${API_INTERNAL}/buku/${id}`, {
        method: "PUT",
        body: JSON.stringify(dataBuku),
    });
}

// DELETE: hapus buku
export async function hapusBuku(id) {
    return request(`${API_INTERNAL}/buku/${id}`, { method: "DELETE" });
}

// ─── Promise.all: ambil beberapa data paralel ──────────────────────────────
export async function ambilDashboard() {
    // Ketiga fetch berjalan BERSAMAAN; hasil menunggu yang terlambat.
    const [buku, anggota, peminjaman] = await Promise.all([
        request(`${API_INTERNAL}/buku`),
        request(`${API_INTERNAL}/anggota`),
        request(`${API_INTERNAL}/peminjaman`),
    ]);
    return { buku, anggota, peminjaman };
}

// ─── AbortController: batalkan pencarian lama saat user mengetik lagi ──────
let controller = null;

export async function cariBukuRealTime(query) {
    // Batalkan request yang masih berjalan — hanya pencarian terbaru yang menang.
    if (controller) controller.abort();
    controller = new AbortController();

    try {
        const url = `${API_OPEN_LIBRARY}/search.json?q=${encodeURIComponent(query)}&limit=20`;
        return await request(url, { signal: controller.signal });
    } catch (error) {
        if (error.name === "AbortError") return null; // dibatalkan — bukan error sungguhan
        throw error;
    }
}
```

```javascript
// js/main.js

// ─── Konsumsi dengan async/await + try/catch (pola yang diprioritaskan) ────
async function muatKatalog() {
    try {
        const data = await cariBukuOpenLibrary("pemrograman");
        renderKatalog(data.docs);
    } catch (error) {
        if (error instanceof TypeError) {
            // TypeError dari fetch = gagal terhubung ke jaringan
            renderError("Tidak dapat terhubung ke internet. Periksa koneksi Anda.");
        } else {
            renderError(error.message);
        }
    } finally {
        sembunyikanSpinner(); // jalan apa pun hasilnya
    }
}
```

```javascript
// Perbandingan singkat: .then/.catch vs async/await.
// Async/await lebih mudah dibaca untuk alur berurutan.

// LAMA (dan berantakan bila bersarang):
fetch(url)
    .then((r) => r.json())
    .then((data) => render(data))
    .catch((err) => renderError(err));

// BARU (setara, tapi jauh lebih jelas):
const r = await fetch(url);
const data = await r.json();
render(data);
```

## 4. Analogi Sederhana — Membangun Rumah

Di rumah analogi kita, **HTML** adalah kerangka dan tata ruang, **CSS** adalah cat dan dekorasi, dan **JavaScript** adalah instalasi listriknya. **Promise** paling cocok dianalogikan sebagai **menelepon toko buku**. Kamu menelpon, menyampaikan pesanan buku Langganan Cerdas, lalu menutup telepon — dan **tidak duduk diam menempel telepon di telinga selama pesanan diproses**. Kamu bebas melanjutkan kegiatan lain: melempar bola ke anak, menyapu halaman. Toko berjanji (promise) akan menelepon balik begitu buku tersedia — janji itu terpenuhi (resolved) atau, bila buku sedang habis, dibatalkan dengan alasan (rejected). Hidup di rumahmu tidak pernah membeku selama menunggu.

**async/await** adalah **instruksi "panggil dan tunggu" yang kamu tulis berurutan di kertas kerja**. "Hubungi toko. Tunggu. Setelah buku tiba, bungkus." Warnanya ditulis seperti urutan keseharian, sehingga yang membacanya mengerti jalan cerita tanpa perlu menebak-nebak kapan telepon diangkat. Tanpa async/await, kamu menulis instruksi dengan *callback* bersarang — seperti menulis catatan di dalam catatan di dalam catatan — sehingga mudah hilang arah. `try/catch` adalah **kantor pelayanan yang menangani keluhan**: kalau toko membatalkan pesanan, ada meja khusus yang mencatat alasan dan memutuskan langkah berikut (kirim ulang, atau beri tahu pemilik rumah dengan sopan) — bukan membiarkan telepon berdering sendiri di ruangan kosong.

`fetch` adalah **mengirim pesan kurir ke gudang buku dan menerima paket**: kamu menitipkan permintaan (URL + method), kurir pergi, dan beberapa saat kemudian paket berisi data datang diangkat oleh `await`. Kalau kurir tidak menemukan alamatnya (network error), paket pulang dengan `TypeError` — ini pedas berbeda dengan "gudang bilang buku tidak ada" (HTTP error). `AbortController`, di sisi lain, adalah **sirene pembatalan**: begitu kamu memanggilnya, paket yang masih di perjalanan untuk pesanan lama dipanggil pulang, supaya dua kurir tidak berebut menyerahkan paket yang saling menimpa di depan pintu — persis yang terjadi pada race condition pencarian cepat.

Sedangkan **`Promise.all`** adalah **memesan dari beberapa toko sekaligus dalam satu daftar induk**: buku, kertas sampul, dan stiker dikirim bersamaan dari tiga toko; kamu menunggu paket terakhir tiba sebelum membuka semuanya. Kalau kamu meneleponnya berurutan (await satu per satu), kamu menunggu paket pertama *sebelum* memesan ke toko kedua — boros waktu meski hasilnya sama.

## 5. Kapan Harus Digunakan & Kasus Penggunaan (Use Cases)

- **Pencarian buku real-time (dengan debounce + AbortController)** — kotak pencarian katalog memicu `fetch` ke Open Library; request lama dibatalkan agar hasil terakhir tidak tertimpa.
- **Muat awal halaman katalog** — `await cariBukuOpenLibrary(...)` di `DOMContentLoaded`, dengan spinner selama `pending` dan pesan error bila gagal.
- **CRUD dari form** — submit form peminjaman menggunakan POST; edit data buku memakai PUT; tombol hapus memakai DELETE; semuanya lewat `request()` yang sudah memeriksa `response.ok`.
- **Dashboard dengan beberapa sumber** — `Promise.all` mengambil daftar buku unggulan, anggota aktif, dan statistik peminjaman sekaligus untuk statistik beranda.
- **Detail buku** — klik kartu → fetch detail buku berdasarkan key/nomor ISBN → render halaman detail tanpa berpindah halaman.

## 6. Poin-poin Penting & Best Practices

- **Prioritaskan `async/await` + `try/catch`** untuk alur berurutan; gunakan `.then/.catch` hanya bila benar-benar diperlukan. Kode berurutan jauh lebih mudah dibaca dan di-debug.
- **Selalu periksa `response.ok`** sebelum `await response.json()` — tanpa itu, response 404/500 akan di-parse sebagai JSON dan melempar error yang membingungkan ("Unexpected token <").
- **Bedakan error network dan server**: `error instanceof TypeError` menandakan koneksi putus; error lain (pesan dari body server) menandakan masalah di sisi server. Berikan pesan yang sesuai.
- **Sanitasi semua nilai yang masuk ke URL** dengan `encodeURIComponent` — query yang mengandung spasi, `&`, `?`, atau `#` akan merusak URL dan bisa memanipulasi request.
- **Gunakan `AbortController`** setiap ada operasi yang bisa diulang cepat (pencarian, filter); ini mencegah race condition dan menghemat bandwidth.
- **Manfaatkan `Promise.all`** untuk request independen; hati-hati karena satu kegagalan menggagalkan semua — bisa lompat ke `Promise.allSettled` bila tiap request wajib berdiri sendiri.
- **Kirim data POST/PUT sebagai JSON body** (`JSON.stringify`) dengan header `Content-Type: application/json` agar server tahu bagaimana membaca body.
- **Type Safety**: di TypeScript, kamu bisa mendefinisikan interface untuk bentuk data API (mis. `interface Buku { judul: string; stok: number }`) dan `try/catch` hanya menangkap faktor runtime — fetch tetap harus tetap aman, type tidak menggantikan pengecekan `response.ok`.

## 7. Kesalahan Umum (Common Pitfalls & Bugs)

- **Lupa cek `response.ok`** → mencoba `response.json()` pada halaman error 404 menghasilkan `SyntaxError: Unexpected token < in JSON`. Perbaikan: lemparkan error eksplisit bila `!response.ok` seperti pada `request()` di atas.
- **`await` dipakai di fungsi non-async** → `SyntaxError: await is only valid in async functions`. Setiap fungsi yang memakai `await` wajib diberi awalan `async`.
- **Race condition pencarian tanpa abort** → respons pencarian lama tiba belakangan dan menimpa hasil terbaru. Perbaikan: bunyikan `controller.abort()` sebelum fetch baru, dan abaikan `AbortError`.
- **`Promise.all` menggagalkan semua saat satu request error** → dashboard kosong total hanya karena satu endpoint bermasalah. Perbaikan: gunakan `Promise.allSettled` bila masing-masing request harus berjalan mandiri.
- **Menampilkan `error.message` mentah ke user** → "Error: Failed to fetch" atau "TypeError: NetworkError" tidak membantu siapa pun. Perbaikan: petakan ke pesan ramah ("Koneksi internet bermasalah, coba lagi").

Kemudian buat fungsi `muatDashboard()` yang memakai `Promise.all` untuk mengambil hasil pencarian "fiksi" dan "sejarah" sekaligus (dua URL Open Library berbeda), lalu cetak jumlah hasil keduanya.
2. Buat simulasi pencarian real-time: input pencarian + tombol "Cari". Setiap keystroke memakai **debounce 300ms**, memanggil `cariBuku`, dan request sebelumnya **dibatalkan** dengan `AbortController`. Tampilkan 5 judul buku pertama di konsol atau di `<ul id="hasil">`. Pastikan pencarian cepat tidak menimpa hasil.

### Solusi & Pembahasan

```javascript
// js/latihan.js

// ─── Soal 1: request + pembedaan error ─────────────────────────────────────
async function cariBuku(query) {
    const url = `https://openlibrary.org/search.json?q=${encodeURIComponent(query)}&limit=5`;
    const response = await fetch(url);

    if (!response.ok) {
        // Server merespons tapi dengan kesalahan (mis. 500, 404)
        throw new Error(`Server API bermasalah (HTTP ${response.status}). Coba lagi nanti.`);
    }
    return response.json();
}

async function muatDashboard() {
    try {
        // Dua pencarian independen → jalankan PARALEL.
        const [hasilFiksi, hasilSejarah] = await Promise.all([
            cariBuku("fiksi"),
            cariBuku("sejarah"),
        ]);
        console.log("Buku fiksi :", hasilFiksi.docs.length);
        console.log("Buku sejarah:", hasilSejarah.docs.length);
    } catch (error) {
        if (error instanceof TypeError) {
            console.log("Koneksi internet bermasalah — periksa jaringan Anda.");
        } else {
            console.log(error.message);
        }
    }
}

// ─── Soal 2: pencarian real-time dengan debounce + abort ───────────────────
let timerDebounce = null;
let controller    = null;

document.querySelector("#input-cari").addEventListener("input", (event) => {
    clearTimeout(timerDebounce);          // batalkan timer debounce yang lama

    const query = event.target.value.trim();
    if (!query) return;

    timerDebounce = setTimeout(() => cariOpenLibrary(query), 300); // tunggu diam 300ms
});

async function cariOpenLibrary(query) {
    if (controller) controller.abort();   // batalkan request yang masih berjalan
    controller = new AbortController();

    try {
        const url = `https://openlibrary.org/search.json?q=${encodeURIComponent(query)}&limit=5`;
        const response = await fetch(url, { signal: controller.signal });

        if (!response.ok) throw new Error("Server bermasalah, coba lagi.");
        const data = await response.json();

        // textContent aman untuk data dari API (bukan innerHTML!)
        const daftar = document.querySelector("#hasil");
        daftar.textContent = "";
        data.docs.forEach((buku) => {
            const item = document.createElement("li");
            item.textContent = buku.title;
            daftar.appendChild(item);
        });
    } catch (error) {
        if (error.name === "AbortError") return; // request dibatalkan — bukan error
        console.log(error.message);
    }
}

muatDashboard();
```

**Pembahasan.** Soal 1 menegaskan dua kelas error: `TypeError` (fetch tidak sampai ke server = network) dan error `.message` yang kita buat sendiri (server merespons tapi error HTTP). Soal 2 menggabungkan debounce (menghemat request saat mengetik) dan `AbortController` (memastikan respons tertua tidak menimpa yang terbaru). Perhatikan bahwa judul buku dimasukkan lewat `textContent`, bukan innerHTML, untuk menghindari XSS dari data yang tidak kita kontrol.
