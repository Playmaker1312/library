# 1. PHP adalah Server-Side — Cara Kerja yang Fundamental

> **Level 1 · Fondasi PHP** — Materi pertama yang menentukan cara kamu memandang seluruh sisa roadmap.

---

## 1. Penjelasan Singkat & Konsep Dasar

PHP adalah bahasa **server-side**. Artinya, seluruh kode PHP dieksekusi **di dalam server**, bukan di browser. Browser hanya menerima **hasil akhirnya** (berupa HTML, CSS, dan JavaScript yang sudah jadi) — dia tidak pernah melihat satu baris pun kode PHP.

Ini satu-satunya konsep yang **paling sering disalahpahami** oleh pemula. Kebanyakan orang datang dari JavaScript: "kalau saya tulis kode, langsung jalan di browser." PHP **tidak begitu**. Alurnya selalu:

```
Browser            Web Server (Apache/Nginx)         PHP Engine
   │                        │                              │
   │── GET /index.php ─────▶│                              │
   │                        │── minta PHP jalankan file ──▶│
   │                        │                              │── baca kode .php
   │                        │                              │── eksekusi baris per baris
   │                        │                              │── kumpulkan output (HTML)
   │                        │◀── kirim hasil (HTML) ───────│
   │◀── terima HTML ────────│                              │
   │                       (render di browser)             │
```

**Benang Merah:** kamu sudah paham HTML & CSS (prasyarat). HTML/CSS itu *statis* — isinya tetap, tidak berubah. PHP hadir untuk membuat halaman menjadi *dinamis*: isinya bisa berubah tergantung waktu, database, atau input user. Materi 2-4 (setup, file pertama, error reporting) semua bertumpu di atas pemahaman fundamental ini.

## 2. Fungsi & Kegunaan Utama

Kenapa ada bahasa yang berjalan di server? Karena ada pekerjaan yang **tidak boleh dan tidak bisa** dilakukan browser:

- **Akses database** — browser tidak punya akses langsung ke MySQL. Kalau kamu mau menampilkan stok buku dari database, harus ada perantara di server yang mengambil data, dan PHP adalah perantaranya.
- **Data rahasia** — kode yang menyimpan kredensial database, logika harga, atau kunci API **tidak boleh terkirim ke browser**. Siapa pun yang bisa membuka "view source" tidak boleh melihatnya. PHP menahan semua logika di server.
- **Logika bisnis** — menghitung denda keterlambatan, memvalidasi keanggotaan, mengambil keputusan — semua dilakukan server. Browser hanya menampilkan hasilnya.
- **State & keamanan** — session login, CSRF token, otorisasi — semua bergantung pada data yang disimpan di server, bukan di browser. (Detail di Level 3 & 5.)

Perbandingan cepat:

| PHP (Server-Side) | JavaScript (Client-Side) |
|---|---|
| Berjalan di SERVER | Berjalan di BROWSER |
| User tidak bisa melihat kodenya | User bisa lihat kode via view-source |
| Akses langsung ke database | Butuh API (intermediari) |
| Setiap request = proses baru, lalu selesai | Script tetap hidup setelah halaman dimuat |
| Perubahan kode butuh "restart" request | Perubahan langsung terasa |

> Bayangkan hapus semua file `.php` di server — halaman web kamu berhenti bekerja untuk semua orang. Itu bukti nyata bahwa logika ada di server.

## 3. Contoh Kode & Implementasi Real-World

Struktur minimal project PHP (kita akan pakai pola ini sepanjang roadmap, khususnya **untuk project perpustakaan**):

```
perpustakaan/
├── index.php          ← entry point, yang pertama kali dijalankan
├── profil.php         ← halaman dinamis lainnya
└── css/
    └── style.css      ← aset statis yang TETAP dikirim ke browser
```

`index.php` — halaman dinamis pertama:

```php
<?php
// Karena file ini murni PHP, TIDAK perlu ?> di akhir.
// (Menghilangkan closing tag mencegah error "headers already sent" — materi 7/16)

// Informasi ini semua diproses di SERVER, browser hanya lihat hasilnya
$namaPerpustakaan = "Perpustakaan Digital Kota";
$tahunBerdiri     = 1995;
$jumlahKoleksi    = 12500;

// echo = instruksi "kirim teks ini ke output"
echo "Selamat datang di $namaPerpustakaan!<br>";
echo "Berdiri sejak $tahunBerdiri, dengan $jumlahKoleksi koleksi buku.";
?>
```

`profil.php` — PHP memproduksi HTML (bukan hanya teks). Logika di atas, HTML di bawah:

```php
<?php
$jamBuka = "Senin-Sabtu: 08:00 - 17:00";
$alamat  = "Jl. Merdeka No. 1, Bandung";
?>
<!DOCTYPE html>
<html lang="id">
<head>
    <meta charset="UTF-8">
    <title>Profil Perpustakaan</title>
</head>
<body>
    <h1>Jam Operasional</h1>
    <p><?= htmlspecialchars($jamBuka) ?></p>
    <p><?= htmlspecialchars($alamat) ?></p>
</body>
</html>
```

> `<?= ... ?>` adalah singkatan dari `<?php echo ... ?>`. **htmlspecialchars()** dipakai untuk output ke HTML agar aman dari XSS — akan dibahas tuntas di Level 3 & 5, tapi biasakan from day one.

**Cara verifikasi "PHP itu di server":** buka halaman di browser, klik kanan → *View Page Source*. Kamu akan melihat HTML murni — **tidak ada** `<?php`, `$namaPerpustakaan`, atau `echo`. Kode PHP sudah dieksekusi dan hilang; hanya hasilnya yang tersisa.

## 4. Analogi Sederhana

Bayangkan **Sistem Administrasi Kantor**:

- Browser = **jendela/pelayanan tamu**. Kamu (tamu) hanya melihat lembar jawaban yang sudah jadi di meja, tidak pernah melihat ruang di baliknya.
- Web Server (Apache/Nginx) = **resepsionis**. Menerima permintaan tamu ("saya butuh data koleksi buku"), lalu menyampaikannya ke bagian yang tepat.
- PHP Engine = **staf administrasi di ruang belakang**. Ada yang menyusun berkas (variabel), menulis surat (echo), menghitung (operator), memeriksa arsip (database). Semua pekerjaan terjadi di ruang belakang.
- Hasil yang dikirim ke browser = **surat/lembar jawaban final** yang sudah diketik rapi. Tamu tidak pernah ikut masuk ruang belakang untuk melihat prosesnya.

Intinya: **user hanya melihat hasil cetakan, bukan proses pembuatannya.**

## 5. Kapan Harus Digunakan & Kasus Penggunaan

Wajib dipahami **sebelum** masuk ke materi berikutnya, dan dipakai terus:

- **Setiap halaman dinamis** — daftar buku yang berubah ketika ada buku baru (Level 2+).
- **Form & input user** — login, pencarian buku. Input dikirim ke server untuk diproses (Level 3).
- **Data dari database** — seluruh sistem perpustakaan setelah Level 4.
- **Logika yang tidak boleh terlihat user** — perhitungan denda, verifikasi password.
- **Autentikasi & otorisasi** — membatasi siapa yang boleh mengakses halaman admin.

**Kasus penggunaan nyata:** `katalog.php?q=laskar` — URL ini membuat server menerima kata kunci `laskar`, *menjalankan logika pencarian di server*, lalu mengirim daftar buku yang cocok sebagai HTML. Tanpa pemahaman server-side, kamu tidak akan mengerti kenapa URL bisa "membawa" data (akan dibahas di [[13. \$_POST, \$_GET, dan Superglobal PHP]]).

## 6. Aspek Keamanan & Best Practices (Critical)

- **Jangan pernah menyimpan rahasia di sisi client.** Database password, API key, logika harga — semua di server. Kalau ada di dalam kode, artinya bocor ke semua orang.
- **Output ke HTML selalu lewat `htmlspecialchars()` / `esc()`** untuk data yang berpotensi berasal dari user. Aturan zero-XSS mulai berlaku sekarang.
- **Jangan tampilkan error detail ke user** — ini menyangkut cara kerja server (ada di materi 4). Error report di development vs production dibedakan.
- **Best practices di tahap ini:**
  - Logika PHP ditulis di **atas** sebelum HTML, bukan nyelip di tengah-tengah (memisahkan logika dari tampilan = anti *spaghetti code*).
  - Pisahkan file: `index.php`, `profil.php` — jangan semua dalam satu file raksasa (awal dari DRY).
  - Gunakan nama variabel deskriptif. `$jumlahKoleksi` jauh lebih jelas daripada `$j`.

## 7. Kesalahan Umum & Debugging

- **"Kode PHP ditampilkan mentah di browser"** → artinya server **tidak menjalankan** PHP. Biasanya karena file dibuka lewat `file://` (double-click file) bukan lewat `http://localhost/...`. Solusi: jalankan lewat Laragon/XAMPP/Herd (materi 2) dengan URL yang benar.
- **"Perubahan kode tidak terlihat"** → cek apakah kamu mengedit file yang benar, dan refresh browser dengan hard refresh (Ctrl+Shift+R). PHP tidak punya cache sendiri — kalau halaman masih lama, itu cache browser.
- **Parse error / syntax error** → PHP menolak menjalankan file sama sekali karena ada karakter yang salah (misal lupa `;` atau tanda kutip). File ini dimuat di materi 4.
- **Perbedaan "server tidak jalan" vs "kode salah"**: kalau halaman 404 atau "connection refused", itu masalah server. Kalau halaman muncul tapi terpotong aneh, itu masalah kode PHP.

## 8. Soal Latihan & Kunci Jawaban

### Tantangan 1
Buat file `cek-server.php` berisi PHP yang menampilkan: judul halaman, jam server saat ini, dan versi PHP. Buka di browser, lalu buka *View Page Source*. Tuliskan apa yang kamu lihat — apakah ada kode PHP yang terlihat? Jelaskan kenapa.

### Tantangan 2
Perbaiki file berikut. Jelaskan apa yang salah dan apa output yang benar:

```php
<?php
$nama = "Perpustakaan Kota";
echo "Selamat datang di $nama"
echo "Koleksi: ";
```

### Jawaban & Pembahasan

**Tantangan 1** — Kode:

```php
<?php
$judulHalaman = "Cek Server";
?>
<!DOCTYPE html>
<html lang="id">
<head>
    <meta charset="UTF-8">
    <title><?= htmlspecialchars($judulHalaman) ?></title>
</head>
<body>
    <h1><?= htmlspecialchars($judulHalaman) ?></h1>
    <p>Waktu server: <?= date('H:i:s d-m-Y') ?></p>
    <p>Versi PHP: <?= PHP_VERSION ?></p>
</body>
</html>
```

> **Pembahasan alur:** Server membaca baris 2 (assign variabel), lalu menghasilkan HTML. Di baris 7 dan seterusnya, PHP menyisipkan nilai variabel/fungsi ke dalam HTML sebelum hasilnya dikirim. Saat dibuka di browser → *View Page Source*, kamu **tidak akan melihat** `$judulHalaman`, `date()`, atau `PHP_VERSION` — yang ada hanya nilainya ("Cek Server", tanggal, versi). Itu bukti PHP dieksekusi di server.

**Tantangan 2** — Error: baris pertama `echo` **tidak diakhiri titik koma (`;`)**. PHP akan memunculkan *Parse error: syntax error, unexpected 'echo'*. Perbaikan:

```php
<?php
$nama = "Perpustakaan Kota";
echo "Selamat datang di $nama";   // ← tambah ;
echo "Koleksi: ";
```

> **Pembahasan:** PHP mengeksekusi secara berurutan. Karena `;` hilang, PHP bingung menentukan ujung pernyataan pertama, sehingga seluruh file gagal di-parse (gagal sebelum eksekusi). Setiap pernyataan PHP **wajib** diakhiri `;` kecuali struktur kontrol (materi 8). Output setelah diperbaiki: `Selamat datang di Perpustakaan KotaKoleksi: ` (tanpa spasi — spasi harus ditulis eksplisit di dalam string).
