# 6. Type Juggling — PHP yang Suka Mengubah Tipe

> **Level 1 · Fondasi PHP** — Fleksibilitas PHP adalah pisau bermata dua. Materi ini membedakan keduanya.

---

## 1. Penjelasan Singkat & Konsep Dasar

Karena PHP itu *dynamically typed* (materi 5), PHP **otomatis mengubah tipe variabel** saat dibutuhkan dalam sebuah operasi. Inilah yang disebut **type juggling**. Terdengar praktis, tapi inilah **sumber bug tersembunyi terbesar** di PHP — terutama ketika kamu lupa bahwa input dari user selalu datang sebagai *string*.

```php
$stok = "5";          // string
$total = $stok + 3;   // PHP diam-diam menjadikan "5" → int 5
var_dump($total);     // int(8)  ← sudah berubah tipe
```

Tipe juga berubah saat **perbandingan non-strict** (`==`):

```php
var_dump("1" == "01");   // true — dua-duanya dianggap angka 1
var_dump(""  == null);   // true
var_dump("0" == false);  // true
```

**Aturan emas:** kapan pun kamu *tidak yakin* tipe, atau nilai akan dipakai dalam perbandingan — gunakan **strict comparison `===`** dan **type casting eksplisit**.

**Benang Merah:** materi 5 memperkenalkan tipe data. Type juggling adalah konsekuensi *dinamis*-nya PHP. Memahami ini sekarang mencegah bug yang sama sekali tidak terlihat sampai tiba-tiba nilainya salah — terutama saat berpindah ke input user (materi 13) dan database (materi 20-21).

---

## 2. Fungsi & Kegunaan Utama

- **Kenyamanan** — PHP yang santai mengubah tipe membuat kode ringkas: `$harga = "150000"; echo $harga * 2;` langsung bekerja tanpa casting manual.
- **Koordinasi data antar-sumber** — data dari HTML form adalah string, dari database bisa int/float, dari JSON bisa beragam. Juggling "mencocokkan" mereka dalam operasi.
- **Masalah yang "dipecahkan"** adalah *dua sisi*: di operasi aritmatika dan perbandingan tidak strict, PHP menebak tipe; di perbandingan strict, PHP **menolak** mencbak dan membandingkan tipe + nilai. Pilihan ada di tanganmu.

---

## 3. Contoh Kode & Implementasi Real-World

**Numerik-string dalam operasi (hati-hati!):**

```php
$a = "5 buku";     // string: angka di depan
echo $a + 2;       // int(7) — PHP ambil "5", lalu "buku" dibuang

$c = "buku 5";     // string: angka tidak di depan
echo $c + 2;       // int(2) — PHP 8: Warning 'A non-numeric value encountered'
```

**Casting eksplisit — ini yang harus kamu biasakan:**

```php
$inputHarga = "150000";          // dari form HTML: SELALU string
$harga = (int) $inputHarga;      // 150000 int
$harga = (float) $inputHarga;    // 150000.0 float
$harga = intval($inputHarga);    // fungsi lain
$harga = floatval($inputHarga);
```

**Di real-world web app, polanya:**

```php
<?php
// File: katalog.php — pagination & filter
// Input selalu string; cast SELALU eksplisit sebelum dipakai

$id      = (int) ($_GET['id'] ?? 0);          // URL: katalog.php?id=12
$halaman = max(1, (int) ($_GET['halaman'] ?? 1));
$harga   = (float) ($_POST['harga'] ?? 0);

// STRICT comparison — kunci menghindari juggling:
$kategoriPilih = $_GET['kategori'] ?? 'semua';

if ($kategoriPilih === 'Teknologi') {   // === bukan ==
    // ...
}
```

**Perbandingan yang mengejutkan (tabel pembanding `==` vs `===`):**

```php
var_dump(0 == "php");      // false di PHP 8  (di PHP 7: true!)
var_dump(0 === "php");     // false
var_dump("1" == "01");     // true
var_dump("1" === "01");    // false
var_dump("0" == false);    // true
var_dump("0" === false);   // false
var_dump(""  == null);     // true
var_dump(""  === null);    // false
```

> Versi penting: di **PHP 8**, perbandingan *non-numeric string vs number* berubah — `0 == "php"` menjadi `false` (sebelumnya `true`). Ini membuktikan mengapa mengandalkan `==` sangat rapuh: hasil bisa berubah antar versi PHP.

**Kapan `==` aman?** Hampir tidak pernah. Hanya jika dua-duanya *jelas* bernilai numerik dari sumber yang sama. Standar roadmap: **selalu `===`**.

---

## 4. Analogi Sederhana

Dalam **Sistem Administrasi Kantor**:

- **Type juggling** = staf yang "menebak" maksud berkas. Ketika catatan bertulis *"7"*, dia menganggapnya angka 7 *atau* teks "7" tergantung konteks. Kadang tepat, kadang kacau: menambahkan *"7 kantor"* dengan *5 kantor* → dia menganggap 7 (angka di depan), tapi *"kantor 7"* + 2 → dia bingung dan menghasilkan 2.
- **`==`** = staf yang *longgar* dalam membandingkan: menganggap "01" = "1" (sama-sama satu-manuscript), "" = null (keduanya "kosong").
- **`===`** = staf yang *ketat*: "01" dan "1" jelas beda — satu teks dua karakter, satu teks satu karakter. Tidak ada tafsir.
- **Casting eksplisit** = menuliskan tipe di catatan: *"ini ANGKA 7"* — sehingga tidak ada ruang untuk salah tebak.

---

## 5. Kapan Harus Digunakan & Kasus Penggunaan

- **Wajib `===`** pada: membandingkan ID (materi 11/21), role user (`$role === 'admin'`, materi 16/23), status, dan semua perbandingan yang berpotensi kedua sisi beda tipe.
- **Casting eksplisit wajib** pada: semua input dari `$_GET`/`$_POST` yang akan dipakai sebagai angka (materi 13), dan nilai dari database yang akan dibandingkan.
- **Juggling dibiarkan bekerja** hanya pada operasi murni internal yang sudah jelas tipe-nya (misal mengalikan dua variabel `int`). Itu pun lebih baik cast dulu.
- **Kasus nyata:** Filter harga `katalog.php?harga_max=150000` — jika dibandingkan dengan harga int dari database tanpa casting `(int)`, `==` bisa menganggap `"150000" == 150000` true (beruntung), tapi `"150000e"` juga bisa lolos dengan cara yang tidak terduga. Casting + `===` menghilangkan semua ambiguitas.

---

## 6. Aspek Keamanan & Best Practices (Critical)

- **Type juggling bisa jadi celah keamanan** — ada kelas serangan *loose comparison* (misal `0 == "string"` pernah `true` di PHP 7). Itulah salah satu alasan utama aturan **`===` selalu**.
- **Input dari user JANGAN pernah dipakai mentah** dalam operasi aritmatika/query — selalu **cast & validasi dulu** (materi 14).
- **Best practices:**
  - `===` / `!==` untuk semua perbandingan — bukan `==` / `!=`.
  - Cast eksplisit: `(int)`, `(float)`, `(string)`, atau `intval()`/`floatval()`.
  - Cek nilai sebelum operasi: `is_numeric()` untuk angka dari form.
  - Sadari bahwa `$_GET`, `$_POST`, `$_COOKIE` semuanya **string superglobal** (materi 13).

---

## 7. Kesalahan Umum & Debugging

- **Bug paling klasik:** `$totalStok = "10" + 1; var_dump($totalStok); // int(11)` — terlihat "berhasil", tapi di kode lain `"10"` dipakai sebagai string dan hasilnya beda. Solusi: cast di satu titik, konsisten.
- **`Warning: A non-numeric value encountered`** (PHP 8) — string berisi non-angka dioperasikan secara numerik. Solusi: validasi `is_numeric()` lalu cast; atau perbaiki sumber datanya.
- **`"1" == "01"` mengecoh** — muncul *true* walau keduanya string. Ini contoh paling sering bikin programmer bingung. Pakai `===`, hasilnya `false`.
- **ID yang "berubah"** — `$_GET['id']` = `"12"` string; jika disimpan dan dibandingkan dengan `12` (int) dengan `==` bekerja, tapi dengan `===` tidak. Solusi: cast `(int)` di awal — maka keduanya int dan `===` aman.
- **Debugging cepat:** selalu `var_dump()` untuk melihat tipe sebenarnya sebelum menyalahkan logika. Pesan bug sering terletak di *tipe*, bukan di *nilai*.

## 8. Soal Latihan & Kunci Jawaban

### Tantangan 1
Tuliskan output dari setiap ekspresi berikut (disertai `var_dump`) dan jelaskan mengapa:

```php
$a = "5 buku";
$b = $a + 3;

$c = "buku 5";
$d = $c + 1;

var_dump("02" == "2");    // X
var_dump("02" === "2");   // Y
var_dump(0 === "php");    // Z
var_dump(0 == "php");     // W (PHP 8)
```

### Tantangan 2
Buat fungsi kecil `prosesStok(array $payload): int` yang menerima payload berisi `jumlah_masuk` (string dari form). Fungsi harus mengembalikan total stok (int) dengan aman: `berisi "8"` → 8 + `selisih` (string, misal `"-3"`) → hasil 5. Tunjukkan bagaimana casting + `is_numeric()` menjaga kode dari juggling yang tak terduga.

### Jawaban & Pembahasan

**Tantangan 1**

```php
$a = "5 buku";
$b = $a + 3;          // int(8)   — PHP ambil "5", buang "buku", 5+3=8

$c = "buku 5";
$d = $c + 1;          // int(1)   — PHP 8 Warning; tidak ada angka di awal → 0+1=1

var_dump("02" == "2");    // bool(true)  — loose: keduanya dianggap angka 2
var_dump("02" === "2");   // bool(false) — strict: tipe sama tapi nilai beda ("02"≠"2")
var_dump(0 === "php");    // bool(false) — strict: int ≠ string
var_dump(0 == "php");     // bool(false) — PHP 8: string non-numeric ≠ angka
```

> **Pembahasan:** `$b` menunjukkan PHP "memotong" bagian non-numeric di depan. `$d` menunjukkan string yang diawali teks dianggap 0 + 1. Baris `==`/`===` membuktikan: loos comparison bisa mengubah makna (mis. `"02"=="2"`), strict comparison membandingkan *tipe + nilai* apa adanya. `0 == "php"` yang dulu `true` (PHP ≤7, dan `0==="php"` selalu `false`) kini `false` di PHP 8 — bukti mengapa `===` adalah satu-satunya yang konsisten lintas versi.

**Tantangan 2**

```php
<?php
function prosesStok(array $payload): int {
    // Input dari form: string
    $jumlahMasuk = $payload['jumlah_masuk'] ?? '0';
    $selisih     = $payload['selisih'] ?? '0';

    // Validasi format numerik SEBELUM casting — tolak teks acak
    if (!is_numeric($jumlahMasuk) || !is_numeric($selisih)) {
        throw new InvalidArgumentException('Input stok harus berupa angka');
    }

    return (int) $jumlahMasuk + (int) $selisih;
}

echo prosesStok(['jumlah_masuk' => '8', 'selisih' => '-3']); // 5
echo prosesStok(['jumlah_masuk' => '8', 'selisih' => 'x']);  // InvalidArgumentException
```

> **Pembahasan alur:** Fungsi menerima string, memvalidasi bahwa keduanya benar-benar numerik (`is_numeric`), baru meng-cast ke int dan menjumlahkan. Ini mencegah bug juggling seperti `"8x"` yang diam-diam dibaca 8, dan mencegah `"buku"` menjadi 0 tanpa disadari. Tanpa aturan "validasi → cast → baru operasikan", kode ini akan dengan mudah menghasilkan angka yang salah tanpa error apa pun.
