# 14. Validasi dan Sanitasi — Security dari Hari Pertama

> **Level 3 · Form, Session, dan File** — Materi 13 memberi input mentah. Materi ini mengubahnya menjadi input yang "aman untuk dipakai".

---

## 1. Penjelasan Singkat & Konsep Dasar

Dua konsep yang *sering dicampur* tapi sebenarnya beda:

- **Validasi** = memastikan data **benar** sesuai aturan (email valid, jumlah di range, wajib diisi). Jawabannya *"ya/tidak"*.
- **Sanitasi** = mengubah data agar **tidak berbahaya** (hapus karakter aneh). Jawabannya *"hasil bersih"*.
- **Escape on output** = mengubah data **saat ditampilkan** ke HTML agar tidak dieksekusi (`htmlspecialchars`). Ini bukan sanitasi input — ini perlindungan *di sisi keluar*.

**Prinsip dasar keamanan input (tangga yang tidak bisa diacak kekuatannya):**

1. **Jangan percaya input user** — semua `$_GET`/`$_POST`/`$_COOKIE` = tidak tepercaya.
2. **Validasi** — pastikan sesuai aturan bisnis.
3. **Sanitasi** — bersihkan (untuk kasus khusus seperti email/URL).
4. **Escape saat output** — `htmlspecialchars()` di semua titik tampil.
5. **Prepared statement** — untuk query DB (materi 21).

> **Kesalahpahaman umum:** banyak orang "membersihkan" input dengan `str_replace` lalu merasa aman — it's not. XSS dicegah di **output** (`htmlspecialchars`), SQLi dicegah di **query** (prepared statement). Sanitasi input hanya lapisan tambahan, bukan garis pertahanan utama.

**Benang Merah:** materi 13 memperkenalkan superglobal; materi ini menempatkannya pada jalur aman. Konsep ini akan dipakai di **setiap** halaman form (materi 15), session (16), sampai Level 5 yang membahas XSS/SQLi/CSRF secara mendalam (22-24).

---

## 2. Fungsi & Kegunaan Utama

- **Mencegah XSS** — serangan yang menyisipkan `<script>` melalui input; dicegah saat *output* dengan `htmlspecialchars`.
- **Mencegah SQL Injection** — disisipkan lewat input; dicegah saat *query* dengan prepared statement.
- **Mencegah CSRF** — form palsu dari situs lain; dicegah dengan **CSRF token** (di materi ini).
- **Menjaga data tetap benar** — validasi mencegah data sampah masuk database (usia negatif, email salah format → bug bisnis & keamanan).

**Sanitasi vs escape — di mana masing-masing dipakai:**

```php
// SANITASI INPUT (bukan perlindungan utama XSS):
$email = filter_var($_POST['email'] ?? '', FILTER_SANITIZE_EMAIL);

// JANGAN mengandalkan sanitasi untuk mencegah XSS — lakukan ini:
// ESCAPE OUTPUT (importan):
echo htmlspecialchars($buku['judul'], ENT_QUOTES | ENT_HTML5, 'UTF-8');
```

## 3. Contoh Kode & Implementasi Real-World

**Helper `esc()` — dipakai di semua template:**

```php
<?php
// File: functions/helpers.php
function esc(mixed $nilai, int $flags = ENT_QUOTES | ENT_HTML5): string {
    return htmlspecialchars((string) $nilai, $flags, 'UTF-8');
}
```

**Class `Validator` (berukuran kecil tapi reusable) — pola yang akan di-refactor ke banyak tempat:**

```php
<?php
// File: functions/validasi.php
declare(strict_types=1);

class Validator {
    private array $errors = [];
    private array $data   = [];

    public function __construct(private array $input) {}

    public function required(string $field, string $label): static {
        $nilai = trim($this->input[$field] ?? '');
        if ($nilai === '') {
            $this->errors[$field] = "$label wajib diisi.";
        } else {
            $this->data[$field] = $nilai;
        }
        return $this;
    }

    public function string(string $field, string $label, int $min = 1, int $max = 255): static {
        if (isset($this->errors[$field])) return $this;
        $nilai = $this->data[$field] ?? trim($this->input[$field] ?? '');
        if (mb_strlen($nilai) < $min) {
            $this->errors[$field] = "$label minimal $min karakter.";
        } elseif (mb_strlen($nilai) > $max) {
            $this->errors[$field] = "$label maksimal $max karakter.";
        } else {
            $this->data[$field] = $nilai;
        }
        return $this;
    }

    public function integer(string $field, string $label, int $min = PHP_INT_MIN, int $max = PHP_INT_MAX): static {
        if (isset($this->errors[$field])) return $this;
        $nilai = $this->input[$field] ?? '';
        if (!is_numeric($nilai) || (int) $nilai != $nilai) {
            $this->errors[$field] = "$label harus berupa angka bulat.";
        } elseif ((int) $nilai < $min) {
            $this->errors[$field] = "$label minimal $min.";
        } elseif ((int) $nilai > $max) {
            $this->errors[$field] = "$label maksimal $max.";
        } else {
            $this->data[$field] = (int) $nilai;
        }
        return $this;
    }

    public function email(string $field, string $label): static {
        if (isset($this->errors[$field])) return $this;
        $nilai = trim($this->input[$field] ?? '');
        if (!filter_var($nilai, FILTER_VALIDATE_EMAIL)) {
            $this->errors[$field] = "$label tidak valid.";
        } else {
            $this->data[$field] = strtolower($nilai);
        }
        return $this;
    }

    public function inArray(string $field, string $label, array $allowed): static {
        if (isset($this->errors[$field])) return $this;
        $nilai = $this->input[$field] ?? '';
        if (!in_array($nilai, $allowed, true)) {
            $this->errors[$field] = "$label tidak valid.";
        } else {
            $this->data[$field] = $nilai;
        }
        return $this;
    }

    public function gagal(): bool      { return !empty($this->errors); }
    public function berhasil(): bool   { return empty($this->errors); }
    public function getErrors(): array { return $this->errors; }
    public function getData(): array   { return $this->data; }
}
```

**CSRF token — proteksi minimal yang wajib di semua form POST:**

```php
<?php
// File: functions/csrf.php
function generateCsrfToken(): string {
    if (session_status() === PHP_SESSION_NONE) {
        throw new RuntimeException('Session belum dimulai.');
    }
    if (empty($_SESSION['csrf_token'])) {
        $_SESSION['csrf_token'] = bin2hex(random_bytes(32));
    }
    return $_SESSION['csrf_token'];
}

function verifyCsrfToken(string $token): bool {
    return !empty($_SESSION['csrf_token'])
        && hash_equals($_SESSION['csrf_token'], $token);
}
```

**Pola pemakaian form + validasi + CSRF:**

```php
<?php
session_start();
require_once 'functions/validasi.php';
require_once 'functions/csrf.php';

$errors = [];
$input  = [];

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    if (!verifyCsrfToken($_POST['csrf_token'] ?? '')) {
        http_response_code(403);
        die('Request tidak valid (CSRF).');
    }

    $validator = (new Validator($_POST))
        ->required('judul', 'Judul')
        ->string('judul', 'Judul', 2, 200)
        ->required('tahun', 'Tahun Terbit')
        ->integer('tahun', 'Tahun Terbit', 1000, (int) date('Y'))
        ->required('harga', 'Harga')
        ->integer('harga', 'Harga', 0)
        ->inArray('kategori', 'Kategori', ['Fiksi', 'Non-Fiksi', 'Sains', 'Teknologi']);

    if ($validator->berhasil()) {
        $data = $validator->getData();
        // … simpan ke JSON (materi 17) atau DB (materi 21) …
        $input = [];
    } else {
        $errors = $validator->getErrors();
        $input  = $_POST;  // pertahankan isian form
    }
}
?>
<form method="POST">
    <input type="hidden" name="csrf_token" value="<?= esc(generateCsrfToken()) ?>">
    <!-- … field form, tampilkan error per field … -->
</form>
```

## 4. Analogi Sederhana

Dalam **Sistem Administrasi Kantor**:

- **Validasi** = staf *memeriksa surat* sebelum diproses: "Kolom 'email' harus berformat alamat — yang ini tidak, tolak." Jawabannya ya/tidak, hanya memastikan *kesesuaian format*.
- **Sanitasi** = staf *membersihkan* surat dari coretan/karakter aneh (misal menghapus simbol) agar masuk arsip rapi.
- **Escape saat output (`htmlspecialchars`)** = ketika menyalin isi surat ke papan pengumuman, staf *mengganti* karakter berbahaya (`<`, `>`) dengan penampil aman (`&lt;`, `&gt;`) — sehingga kalau ada yang menuliskan kode, kode itu hanya tampil sebagai teks, bukan dieksekusi.
- **CSRF token** = **stempel segel khusus** di formulir. Staf hanya menerima formulir yang stempelnya cocok dengan buku segel di kantor. Formulir palsu dari luar tanpa stempel → ditolak. Ini melindungi dari "surat palsu" yang dikirim situs lain atas nama anggota.

## 5. Kapan Harus Digunakan & Kasus Penggunaan

- **Setiap form POST** — validasi, CSRF token, escape output. Tanpa kompromi.
- **Setiap output dari data user / DB** — `esc()`/`htmlspecialchars`.
- **Setiap query dinamis** — prepared statement (Level 4).
- **Kasus khusus sanitasi dengan `filter_var`:**
  - Email: `FILTER_SANITIZE_EMAIL` → bersihkan karakter aneh; lalu `FILTER_VALIDATE_EMAIL` untuk konfirmasi.
  - URL: `FILTER_VALIDATE_URL`.
- **Whitelist (inArray)** — kategori, role, status: hanya nilai dari daftar yang diizinkan yang diterima. Ini mencegah data tak dikenal masuk sistem.

---

## 6. Aspek Keamanan & Best Practices (Critical)

- **Lapisan utama**: XSS dicegah di **output**; SQLi dicegah di **query**; CSRF dicegah di **token form**. Sanitasi input **bukan** pengganti ketiganya.
- **`htmlspecialchars` dengan flag yang benar**: selalu `ENT_QUOTES | ENT_HTML5` + UTF-8 agar kutip tunggal/ganda & entitas modern ikut di-escape.
- **Jangan pernah "bersihkan" lalu menganggap aman** — data di output tetap harus `esc()` walaupun sudah disanitasi.
- **Panjang input & tipe**: `maxlength` HTML hanya kenyamanan UI, bukan validasi — validasi ulang di server (class `Validator`).
- **`hash_equals` untuk token** — perbandingan token harus memakai fungsi *timing-safe* `hash_equals`, bukan `==` (membedakan serangan timing).
- **Jangan bocorkan detail**: saat validasi gagal, beri pesan yang jelas tapi jangan ungkap struktur query/logika.

---

## 7. Kesalahan Umum & Debugging

- **XSS tetap jalan walaupun sudah "membersihkan input"** — sanitasi input tidak mencegah XSS saat output; pakai `esc()` di output. Ini kesalahan paling sering dan paling serius.
- **`filter_var(..., FILTER_VALIDATE_EMAIL)` menolak email yang valid** — domain IDN, plus tanda, dsb bisa ditolak; untuk aplikasi internal, validasi sederhana + `filter_var` cukup. Jangan pakai `FILTER_SANITIZE_EMAIL` sebagai "pembersih utama" email untuk disimpan — normalisasi dengan `strtolower` + validasi.
- **CSRF token selalu gagal (403)** — session belum dimulai sebelum `generateCsrfToken()`, atau token dibandingkan dengan `==` (pakai `hash_equals`), atau refresh page membuat token baru (itu normal — double-check flow).
- **`Undefined array key` saat validasi** — input kosong di `$_POST` (form tidak mengirim field). `Validator` sudah mengamankan dengan `?? ''`.
- **Validasi "lolos" tapi data salah saat dipakai** — karena lupa `strict_types` atau juggling pada perbandingan (`==' vs`===`'); Validator men-cast di `getData()` sehingga hint-nya int untuk integer.

## 8. Soal Latihan & Kunci Jawaban

### Tantangan 1
Gunakan class `Validator` untuk memvalidasi `$_POST` berisi `nama`, `email`, `tahun`, `role` (whitelist: `admin|pustakawan|anggota`). Tampilkan error per field di HTML dan pertahankan isian. Tambahkan CSRF.

### Tantangan 2
Data berikut dikirim user ke field "bio":

```
<script>alert('xss')</script> Saya suka baca buku
```

Tunjukkan (a) apa yang terjadi jika aplikasi *hanya* melakukan `echo $_POST['bio']`; (b) apa output jika memakai `esc()`; (c) jelaskan kenapa sanitasi input (`str_replace('<script>','')`) TIDAK cukup mencegah XSS.

### Jawaban & Pembahasan

**Tantangan 1**

```php
<?php
session_start();
require_once 'functions/validasi.php';
require_once 'functions/csrf.php';
require_once 'functions/helpers.php';

$errors = [];
$input  = $_POST;

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    if (!verifyCsrfToken($_POST['csrf_token'] ?? '')) {
        http_response_code(403);
        die('Request tidak valid.');
    }

    $validator = (new Validator($_POST))
        ->required('nama', 'Nama')
        ->string('nama', 'Nama', 2, 100)
        ->required('email', 'Email')
        ->email('email', 'Email')
        ->required('tahun', 'Tahun')
        ->integer('tahun', 'Tahun', 1900, (int) date('Y'))
        ->required('role', 'Role')
        ->inArray('role', 'Role', ['admin', 'pustakawan', 'anggota']);

    if ($validator->berhasil()) {
        // $data = $validator->getData();  → data bersih siap disimpan
        $input = [];
    } else {
        $errors = $validator->getErrors();
    }
}
?>
<form method="POST">
    <input type="hidden" name="csrf_token" value="<?= esc(generateCsrfToken()) ?>">
    <input name="nama" value="<?= esc($input['nama'] ?? '') ?>" maxlength="100">
    <?php if (isset($errors['nama'])): ?><small><?= esc($errors['nama']) ?></small><?php endif; ?>
    <!-- email, tahun, role dengan pola yang sama -->
    <button type="submit">Simpan</button>
</form>
```

> **Pembahasan alur:** Setiap field divalidasi berantai; jika salah satu field error, field berikutnya tetap dicek tapi tidak menimpa error pertama. `getData()` hanya mengisi untuk field yang lolos. CSRF diverifikasi di awal handler POST. Isian dipertahankan lewat `$input` dengan `esc()` saat dirender ulang. Ini alur yang persis sama dengan materi 15 (form tambah buku).

**Tantangan 2**

- (a) **Berbahaya**: `echo $_POST['bio']` mengeluarkan `<script>alert('xss')</script>` sebagai HTML → browser **menjalankannya** → XSS.
- (b) **Aman**: `echo esc($_POST['bio'])` menghasilkan teks `&lt;script&gt;alert('xss')&lt;/script&gt; Saya suka baca buku` → browser menampilkan sebagai teks, tidak mengeksekusi.
- (c) **Sanitasi `str_replace` tidak cukup**: penyerang bisa memakai varian lain yang lolos filter — misal `<scr<script>ipt>`, `%3Cscript%3E`, event handler seperti `<img onerror=...>`, atau encode unicode. Membersihkan "satu bentuk" tidak menutup semua bentuk. Satu-satunya cara yang konsisten adalah **escape pada saat output** (atau memakai templating yang escape-by-default).

> **Pembahasan:** Ini inti materi: *validasi untuk kebenaran, escape untuk keamanan output*. Sanitasi input boleh ada, tapi garis pertahanan XSS yang kuat berada di `esc()` (dan prepared statement untuk SQLi). Prinsip ini akan diperkuat lagi di materi 22.
