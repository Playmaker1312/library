# 15. Contoh Form Lengkap dengan Validasi

> **Level 3 · Form, Session, dan File** — Materi 13-14 memberi komponen; materi ini merakitnya menjadi satu form produksi.

---

## 1. Penjelasan Singkat & Konsep Dasar

Ini materi "tangan": menggabungkan **semua** yang sudah dipelajari — superglobal (13), validasi + CSRF (14) — dalam satu file form lengkap yang siap dipakai di project nyata: **Form Tambah Buku**.

Alur lengkap form POST yang benar (pola *PRG — Post/Redirect/Get*):

```
User isi form → POST /buku/tambah.php
                          │
                          ├─ 1. Verifikasi CSRF token
                          ├─ 2. Validasi semua field
                          ├─ 3. Jika gagal → tampilkan error + isian dipertahankan
                          └─ 4. Jika sukses → SIMPAN data
                                             → set flash message
                                             → redirect (GET) ke katalog
                                             → EXIT (cegah double submit saat refresh)
```

**Konsep kunci baru di materi ini — PRG (Post/Redirect/Get):** setelah POST berhasil, jangan render ulang halaman form — arahkan browser (redirect) ke halaman tujuan dengan GET. Manfaatnya:
- Refresh / F5 tidak mengirim ulang POST (menghindari duplikasi data).
- Tombol back tidak memunculkan "Confirm form resubmission".

**Benang Merah:** komponen lengkap sudah ada; yang tersisa adalah mengorkestrasinya jadi satu halaman utuh yang bisa kamu pakai sebagai *template* untuk semua form lain (buku, anggota, login, edit). Di Level 4, blok "simpan ke JSON" diganti "simpan ke database via PDO".

---

## 2. Fungsi & Kegunaan Utama

- **Satu titik penanganan input POST yang aman** — imperative flow: CSRF → validasi → simpan → redirect.
- **User experience yang benar**: error ditampilkan per field, isian form tidak hilang, tidak ada submit ganda.
- **Flash message** untuk konfirmasi setelah redirect — pola yang akan dipakai di seluruh aplikasi.
- **Reproducibility**: pola yang sama dipakai untuk tambah/edit/delete, jadi sekali paham = bisa semua.

## 3. Contoh Kode & Implementasi Real-World

Struktur file yang disarankan:

```
perpustakaan/
├── functions/
│   ├── helpers.php     ← esc()
│   ├── validasi.php    ← class Validator
│   └── csrf.php        ← generateCsrfToken / verifyCsrfToken
├── storage/            ← data JSON (materi 17) atau DB (materi 20)
└── buku/
    ├── tambah.php      ← form ini
    └── katalog.php     ← tujuan setelah sukses
```

```php
<?php
// File: buku/tambah.php
session_start();
require_once __DIR__ . '/../functions/helpers.php';
require_once __DIR__ . '/../functions/validasi.php';
require_once __DIR__ . '/../functions/csrf.php';

$errors = [];
$input  = [];
$KATEGORI = ['Fiksi', 'Non-Fiksi', 'Sains', 'Teknologi', 'Sejarah'];

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    // 1. CSRF — tolak request tanpa token valid
    if (!verifyCsrfToken($_POST['csrf_token'] ?? '')) {
        http_response_code(403);
        die('Request tidak valid (CSRF).');
    }

    // 2. Validasi seluruh field
    $validator = (new Validator($_POST))
        ->required('judul', 'Judul')
        ->string('judul', 'Judul', 2, 200)
        ->required('pengarang', 'Pengarang')
        ->string('pengarang', 'Pengarang', 2, 100)
        ->required('tahun', 'Tahun Terbit')
        ->integer('tahun', 'Tahun Terbit', 1000, (int) date('Y'))
        ->required('harga', 'Harga')
        ->integer('harga', 'Harga', 0)
        ->required('stok', 'Stok')
        ->integer('stok', 'Stok', 0, 9999)
        ->required('kategori', 'Kategori')
        ->inArray('kategori', 'Kategori', $KATEGORI);

    if ($validator->berhasil()) {
        $data = $validator->getData();

        // 3. Simpan — Level 3: ke JSON (materi 17) / Level 4: ke DB
        // $storage = new JsonStorage('buku');
        // $storage->tambah($data);

        // 4. PRG: flash + redirect + EXIT
        $_SESSION['flash_sukses'] = "Buku '{$data['judul']}' berhasil ditambahkan!";
        header('Location: katalog.php');
        exit;
    }

    // Validasi gagal: tampilkan error, pertahankan isian
    $errors = $validator->getErrors();
    $input  = $_POST;
}
?>
<!DOCTYPE html>
<html lang="id">
<head>
    <meta charset="UTF-8">
    <title>Tambah Buku</title>
</head>
<body>
    <h1>Tambah Buku Baru</h1>

    <?php if (!empty($_SESSION['flash_sukses'])): ?>
        <div class="alert alert--success"><?= esc($_SESSION['flash_sukses']) ?></div>
        <?php unset($_SESSION['flash_sukses']); ?>
    <?php endif; ?>

    <form method="POST">
        <input type="hidden" name="csrf_token" value="<?= esc(generateCsrfToken()) ?>">

        <div class="form-group <?= isset($errors['judul']) ? 'has-error' : '' ?>">
            <label for="judul">Judul *</label>
            <input type="text" id="judul" name="judul"
                   value="<?= esc($input['judul'] ?? '') ?>" maxlength="200">
            <?php if (isset($errors['judul'])): ?>
                <span class="error-msg"><?= esc($errors['judul']) ?></span>
            <?php endif; ?>
        </div>

        <div class="form-group">
            <label for="kategori">Kategori *</label>
            <select id="kategori" name="kategori">
                <option value="">-- Pilih --</option>
                <?php foreach ($KATEGORI as $kat): ?>
                    <option value="<?= esc($kat) ?>"
                        <?= ($input['kategori'] ?? '') === $kat ? 'selected' : '' ?>>
                        <?= esc($kat) ?>
                    </option>
                <?php endforeach; ?>
            </select>
            <?php if (isset($errors['kategori'])): ?>
                <span class="error-msg"><?= esc($errors['kategori']) ?></span>
            <?php endif; ?>
        </div>

        <button type="submit">Simpan Buku</button>
    </form>
</body>
</html>
```

**Flash message helper (bukan inline):**

```php
<?php
// functions/flash.php
function setFlash(string $kunci, string $pesan): void {
    $_SESSION["flash_$kunci"] = $pesan;
}

function getFlash(string $kunci): ?string {
    if (!empty($_SESSION["flash_$kunci"])) {
        $pesan = $_SESSION["flash_$kunci"];
        unset($_SESSION["flash_$kunci"]);
        return $pesan;
    }
    return null;
}
```

## 4. Analogi Sederhana

Dalam **Sistem Administrasi Kantor**, form tambah buku adalah **prosedur pengisian berkas baru**:

- **Form HTML** = lembar isian resmi yang dibagikan ke tamu.
- **CSRF token** = segel cap resmi kantor — formulir tanpa segel ditolak (palsu).
- **Validator** = staf pemeriksa formulir: kolom wajib, panjang, format, pilihan whitelist.
- **Error per field** = staf menandai kolom yang salah dengan stempel merah + komentar, dan mengembalikan formulir yang **sudah terisi** — tamu tidak perlu mengisi dari nol.
- **PRG** = setelah berkas tersimpan, staf **mencetak tanda terima** (flash message) lalu menutup sesi: konsumen tidak "menekan submit dua kali" saat refresh halaman.
- **`exit` setelah redirect** = staf benar-benar berhenti bekerja di lembar ini setelah menyerahkan hasil — tidak ada langkah tambahan yang tidak diinginkan.

---

## 5. Kapan Harus Digunakan & Kasus Penggunaan

Pola form ini adalah **template universal** — bisa dipakai untuk:
- **Tambah buku** (`/buku/tambah.php`) — sekarang.
- **Edit buku** — sama, dengan data di-pre-fill (`$input = $buku;` dari DB/JSON) dan method update.
- **Login** (materi 16) — validasi email/password + CSRF.
- **Profil anggota, upload sampul** (materi 24) — ditambah `$_FILES`.
- **Konfirmasi hapus** — POST tombol hapus + CSRF + PRG.

Selalu terapkan: CSRF di awal → validasi → simpan → flash → redirect → exit. Ini *urutan eksekusi wajib*; mengubah urutannya (misal simpan sebelum validasi) = celah keamanan.

---

## 6. Aspek Keamanan & Best Practices (Critical)

- **CSRF wajib sebelum validasi** — token dasar dari masalah "request palsu"; periksa dulu.
- **Validasi ulang di server** — atribut `required`, `maxlength` di HTML hanya convenience UI; server adalah otoritas terakhir.
- **Semua output di-escape** — value field & pesan error lewat `esc()`.
- **Jangan render ulang setelah simpan** — gunakan PRG untuk menghindari double-submit (duplikasi data).
- **Best practices:**
  - Satu file handler yang jelas (tambah/editpisah, atau satu file dengan mode).
  - `require_once` tidak `require` (mencegah redeclare).
  - `session_start()` **sebelum** output apa pun (HTML); jika `header/redirect` dipakai, pastikan tidak ada output sebelum itu.
  - Pesan error dalam bahasa user (Bahasa Indonesia) — UX.
  - Kelompokkan fungsi (helpers, validasi, csrf, flash) — DRY & testable.

---

## 7. Kesalahan Umum & Debugging

- **`Cannot modify header information - headers already sent`** — `header('Location: ...')` dipanggil **setelah** ada output (spasi/sebelum `<?php`, echo, HTML). Solusi: jalankan handler POST di atas seluruh HTML, hapus `?>` akhir file, dan jangan echo sebelum redirect.
- **Flash message muncul terus / tidak muncul** — lupa `unset` setelah ditampilkan, atau `session_start()` tidak dipanggil, atau redirect sebelum `session_start()`. Gunakan helper `getFlash`.
- **Isian form hilang saat validasi gagal** — jangan reset `$input`; pertahankan `$input = $_POST` di blok gagal.
- **Double submit** — tanpa PRG, refresh mengirim ulang POST → data duplikat. Perbaiki dengan pola PRG.
- **CSRF 403 terus** — pastikan `session_start()` dipanggil sebelum `generateCsrfToken()`, token disisipkan di **form yang sama**, dan `verifyCsrfToken` memakai `hash_equals`. Buka *View Page Source* untuk memastikan token terbentuk.
- **Validation "lolos semua" tapi datanya aneh** — jalankan `var_dump($validator->getData())` untuk lihat hasil cast; pastikan key sesuai nama field HTML.

## 8. Soal Latihan & Kunci Jawaban

### Tantangan 1
Implementasikan `buku/edit.php` memakai pola form di atas — bedanya: menerima `?id=` (GET), mengambil data buku (dari array hardcode sementara), mengisi form (`$input` di-pre-fill), dan saat update menampilkan flash "Buku berhasil diperbarui!" lalu redirect ke `katalog.php`.

### Tantangan 2
Jelaskan alur eksekusi dari form di materi 3 (logika di atas) ketika: (a) request GET pertama; (b) request POST dengan data valid; (c) request POST dengan judul kosong. Pada titik mana CSRF, validasi, simpan, redirect, dan exit bekerja?

### Jawaban & Pembahasan

**Tantangan 1** — Kerangka inti:

```php
<?php
session_start();
require_once __DIR__ . '/../functions/helpers.php';
require_once __DIR__ . '/../functions/validasi.php';
require_once __DIR__ . '/../functions/csrf.php';

$id = (int) ($_GET['id'] ?? 0);

// Ambil data buku (Level 3: hardcode; Level 4: dari DB/JSON)
$katalog = [
    1 => ['judul' => 'Clean Code', 'pengarang' => 'Robert Martin', 'tahun' => 2008, 'harga' => 150000, 'stok' => 5, 'kategori' => 'Teknologi'],
];
$buku  = $katalog[$id] ?? null;
if ($buku === null) {
    http_response_code(404);
    die('Buku tidak ditemukan.');
}

$errors = [];
$input  = $buku;   // pre-fill

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    if (!verifyCsrfToken($_POST['csrf_token'] ?? '')) { http_response_code(403); die('Forbidden'); }

    $validator = (new Validator($_POST))
        ->required('judul', 'Judul')->string('judul', 'Judul', 2, 200)
        ->required('harga', 'Harga')->integer('harga', 'Harga', 0)
        ->required('kategori', 'Kategori')->inArray('kategori', 'Kategori', ['Fiksi','Non-Fiksi','Sains','Teknologi','Sejarah']);

    if ($validator->berhasil()) {
        $data = $validator->getData();
        // … $storage->update($id, $data) — materi 17 …
        setFlash('sukses', 'Buku berhasil diperbarui!');
        header('Location: katalog.php');
        exit;
    }
    $errors = $validator->getErrors();
    $input  = $_POST;
}
// Di HTML: value="<?= esc($input['judul'] ?? '') ?>" — otomatis terisi data lama
```

> **Pembahasan alur:** kali ini `$input` diinisialisasi dari data `$buku` (pre-fill). Saat POST gagal validasi, `$input` menimpa menjadi `$_POST` (isi baru user). Saat sukses, `setFlash` + redirect + `exit`. Pola tambah/edit hanya beda di sumber pre-fill (kosong vs data lama) dan aksi simpan (create vs update).

**Tantangan 2**

- (a) **GET**: method bukan POST → blok `if` dilewati, `$errors=[]`, `$input=[]`; halaman merender form kosong dengan token CSRF baru di hidden field.
- (b) **POST valid**: CSRF dicocokkan (token cocok) → Validator memproses semua field → `getData()` bersih → **simpan** → `setFlash` → `header('Location: katalog.php')` → **`exit`** (kode setelahnya tidak dijalankan).
- (c) **POST judul kosong**: CSRF ok → `required('judul')` menambahkan error `'Judul wajib diisi.'` → `berhasil()` false → `$errors` diisi, `$input = $_POST` (isi lain dipertahankan) → form di-render ulang dengan error + isi lama.

> **Pembahasan:** Perhatikan satu titik kritis: **`exit` setelah redirect** — tanpa itu, script masih bisa menulis output di bawah, merusak header redirect. Inilah mengapa pola PRG selalu: validasi → simpan → flash → redirect → exit.
