# 25. Setup Project dengan Composer dan Autoloading

> **Level 6 · Arsitektur MVC dan REST API** — Akhiri `require_once` manual selamanya; masuk ke project yang terstruktur & bebas `require`.

---

## 1. Penjelasan Singkat & Konsep Dasar

**Composer** adalah *dependency manager* PHP (setara `npm`/`pip`). Selain mengunduh library, Composer menyediakan **autoloader**: satu mekanisme yang memetakan *namespace & class* ke *lokasi file* — sehingga kamu **tidak perlu `require_once` manual** untuk setiap class.

**Autoload PSR-4** — standar cara merekatkan namespace ke direktori:

```
"autoload": { "psr-4": { "App\\": "src/" } }
```

Artinya: class `App\Models\Buku` akan dicari di `src/Models/Buku.php`. Ketika PHP butuh class itu (lewat `new`, type hint, `extends`), autoloader langsung memuat file-nya.

```php
// Sebelum:  require_once 'src/Models/Buku.php'; require_once 'src/Repositories/BukuRepository.php'; ...
// Sesudah:  (satu line) require 'vendor/autoload.php';
//           lalu PHP otomatis memuat class saat dipakai.

use App\Models\Buku;
use App\Repositories\BukuRepository;

$buku = new Buku(...);        // autoloader memuat src/Models/Buku.php
$repo = new BukuRepository(); // autoloader memuat src/Repositories/BukuRepository.php
```

**PSR-4 mapping (korespondensi):**

| Namespace | Direktori |
|---|---|
| `App\` | `src/` |
| `App\Models\` | `src/Models/` |
| `App\Repositories\` | `src/Repositories/` |
| `Tests\` (autoload-dev) | `tests/` |

**Struktur arsitektur MVC (level ini):**

```
perpustakaan/
├── public/                    ← web root SATU-SATUNYA yang diekspos
│   ├── index.php              ← front controller (materi 26)
│   ├── .htaccess              ← URL rewriting
│   ├── css/  js/  images/
├── src/                       ← kode aplikasi (PSR-4)
│   ├── Controllers/  Models/  Views/  Repositories/
│   ├── Core/  Middleware/  Exceptions/
├── storage/  logs/  uploads/  ← DI LUAR public
├── tests/
├── .env  .env.example  .gitignore
└── composer.json
```

> **Keamanan arsitektur**: hanya `public/` yang diekspos web server. `src/`, `storage/`, `vendor/`, `.env` tidak pernah bisa diakses browser. Ini mengatasi "storage.json bisa diunduh" dari materi 17 secara struktural.

**Benang Merah:** seluruh Level 1-5 masih manual `require`. Level 6 meletakkan struktur: autoloading (25) → front controller + router (26) → API (27). Semua framework modern (Laravel, Symfony) mengikuti pola ini persis.

## 2. Fungsi & Kegunaan Utama

- **Menghilangkan `require_once` berantai** — satu `vendor/autoload.php` memuat semua class aplikasi & library. Tidak ada lagi lupa-require → `Class not found`.
- **Manajemen dependency** — `composer require vlucas/phpdotenv` dkk. dengan versi sesuai, lockfile `composer.lock` untuk reproducibilitas.
- **PHPUnit, PHP_CodeSniffer (PSR-12), PHPStan** — sebagai *dev dependencies* (materi 28) — semua via composer.
- **Script composer** — `composer start` = `php -S localhost:8000 -t public/`.
- **Environment via `vlucas/phpdotenv`** — muat `.env` ke `$_ENV`/`getenv()` — credential terpisah dari kode (materi 20; kini dijalankan).

## 3. Contoh Kode & Implementasi Real-World

`composer.json`:

```json
{
    "name": "perpustakaan/sistem",
    "description": "Sistem Manajemen Perpustakaan PHP Native",
    "type": "project",
    "require": {
        "php": ">=8.2",
        "vlucas/phpdotenv": "^5.6"
    },
    "require-dev": {
        "phpunit/phpunit": "^11.0",
        "squizlabs/php_codesniffer": "^3.0",
        "phpstan/phpstan": "^1.0"
    },
    "autoload": {
        "psr-4": { "App\\": "src/" }
    },
    "autoload-dev": {
        "psr-4": { "Tests\\": "tests/" }
    },
    "scripts": {
        "start": "php -S localhost:8000 -t public/",
        "test": "phpunit",
        "analyse": "phpstan analyse src/ --level=6",
        "lint": "phpcs src/ --standard=PSR12"
    }
}
```

Perintah:

```bash
composer install            # install deps + generate vendor/autoload.php
composer dump-autoload      # regenerate autoload setelah tambah file/pindahan
composer require vlucas/phpdotenv
```

`src/Models/Buku.php` (harus namespace `App\Models`, satu file satu class → PSR-4):

```php
<?php
// File: src/Models/Buku.php
declare(strict_types=1);

namespace App\Models;

class Buku {
    // ... (materi 18) ...
}
```

`public/index.php` — entry point awal (front controller dibangun di materi 26):

```php
<?php
// File: public/index.php
declare(strict_types=1);

define('ROOT_PATH', dirname(__DIR__));

// SATU require saja untuk seluruh class:
require ROOT_PATH . '/vendor/autoload.php';

// Environment variables
$dotenv = Dotenv\Dotenv::createImmutable(ROOT_PATH);
$dotenv->safeLoad();

// Mode dev/ prod
if (($_ENV['APP_ENV'] ?? 'development') === 'production') {
    error_reporting(0);
    ini_set('display_errors', '0');
} else {
    error_reporting(E_ALL);
    ini_set('display_errors', '1');
}

// Kode aplikasi dimulai di sini (materi 26 menyambung Router)
```

`.env` / `.env.example`:

```env
APP_ENV=development
APP_DEBUG=true
DB_HOST=localhost
DB_PORT=3306
DB_NAME=perpustakaan_db
DB_USER=root
DB_PASSWORD=
```

`.gitignore` (jangan pernah commit `.env`):

```gitignore
vendor/
.env
storage/*.log
```

## 4. Analogi Sederhana

Dalam **Sistem Administrasi Kantor**:

- **Tanpa autoloading** = setiap kali staf butuh formulir X, dia harus *berjalan ke rak tertentu* dan menemukan berkasnya (`require 'berkas-X.php'`) — dan jika lupa menaruh instruksi, pengawas bilang "berkas tidak ditemukan!" (class not found).
- **Autoloader/Composer** = **pustakawan otomatis**. Begitu kamu menyebut "berkas `App\Models\Buku`", pustakawan tahu persis lokasinya (`src/Models/Buku.php`) dan langsung mengantarnya — tanpa kamu menyebut rak. Kalau file-nya tidak sesuai posisi → "berkas tidak ditemukan" (namun sekarang di satu tempat: autoload).
- **PSR-4** = *sistem penomoran rak standar*: namespace `App\` berarti asal `src/`, lalu setiap bagian namespace = satu folder. Aturan eksplisit, siapa pun stafnya bisa menebak lokasinya.
- **`composer.json`** = **katalog kebutuhan kantor** — daftar alat (library) yang harus tersedia, versi, dan skrip (composer run).
- **`public/` vs `src/`** = hanya *ruang layanan depan* (`public/`) yang boleh dilihat tamu; ruang kerja, arsip, dan kunci (`.env`) ada di belakang (tidak diekspos).

## 5. Kapan Harus Digunakan & Kasus Penggunaan

- **Semua project PHP ≥ Level 6** — wajib Composer + PSR-4.
- **Menambah library** — `composer require ...` sekali, autoload otomatis.
- **Benar-benar semua class di `src/`** — tidak ada `require_once` manual lagi; kalau masih bertebaran, itu sinyal proyek belum teratur.
- **Environment terpisah** — `.env` dev vs prod; kode tidak pernah menyimpan credential (dotenv).
- **Sambungan ke framework else** — setelah ini, memahami `composer install`/autoload membuatmu paham bagaimana Laravel/Symfony memuat segalanya.

---

## 6. Aspek Keamanan & Best Practices (Critical)

- **Web root hanya `public/`** — konfigurasi web server (`.htaccess`/nginx `root`) mengarah ke `public/`. Akses ke `/src`, `/storage`, `/.env`, `/vendor` harus diblokir (deny) — materi 26/30.
- **Jangan commit `.env` (secret)** — `.gitignore`; gunakan `.env.example` sebagai template. Credential hanya di production server.
- **Jangan tampilkan `APP_DEBUG=true` di production** — dengan `display_errors=0`, stack trace tidak bocor.
- **`composer install --no-dev --optimize-autoloader` di production** — tanpa PHPUnit/phpcs (tidak dipakai), dan autoloader dioptimalisasi (classmap). (materi 30 membahas detail deployment.)
- **Best practices:**
  - PSR-4 namespace `App\` → `src/`, `Tests\` → `tests/`.
  - Satu file = satu class; nama file = nama class (PSR-4 law wajib).
  - `declare(strict_types=1)` di semua file.
  - Jalankan `composer dump-autoload` saat menambah/mengganti class baru.
  - Pindahkan semua logika dari `public/index.php` ke `src/` — index sesedikit mungkin kode.

## 7. Kesalahan Umum & Debugging

- **`Class "App\Models\Buku" not found`** — autoload tidak menemukan file. Cek: namespace di file (`namespace App\Models;`), lokasi file sesuai PSR-4 (`src/Models/Buku.php`), lalu `composer dump-autoload`. 
- **`require vendor/autoload.php` path salah** — gunakan `__DIR__ . '/../vendor/autoload.php'` dari `public/` atau konstanta `ROOT_PATH`.
- **File kosong / class duplikat** — dua file dengan nama class sama → *Cannot redeclare class*. Hapus duplikat; satu class satu file.
- **Autoload "bukan class"** — PSR-4 hanya untuk class/interface/trait, bukan fungsi dalam file biasa. Fungsikan: jadikan method statik/class, atau muat manual sekali (`require_once 'helpers.php'`).
- **` composer install` gagal** — versi PHP < requirement (cek `php --version`), atau ekstensi hilang (materi 2).
- **`.env` tidak terbaca** — pastikan `vlucas/phpdotenv` terpasang & `createImmutable(ROOT_PATH)` benar; `safeLoad()` tidak lempar error saat file tidak ada (debug vs stagig).

## 8. Soal Latihan & Kunci Jawaban

### Tantangan 1
Siapkan struktur MVC dari materi: buat `composer.json` (PHP ≥8.2, autoload PSR-4 `App\`→`src/`), file `src/Models/Buku.php` (namespace benar) & `src/Repositories/BukuRepository.php` (namespace benar), `public/index.php` memanggil `vendor/autoload.php` dan menginstantiasi `Buku`, lalu jalankan `composer dump-autoload`. Verifikasi tidak ada `require_once` manual untuk class.

### Tantangan 2
Jelaskan mengapa `.env`, `storage/`, dan `vendor/` tidak boleh berada di dalam `public/` (web root), dan apa dampaknya jika dilanggar.

### Jawaban & Pembahasan

**Tantangan 1**

```bash
# 1. buat composer.json seperti di atas
# 2. instal autoloader
composer install
# 3. file:
#    src/Models/Buku.php  →  namespace App\Models;
#    src/Repositories/BukuRepository.php →  namespace App\Repositories;
#    public/index.php     →  require __DIR__ . '/../vendor/autoload.php';
```

```php
<?php
// public/index.php
declare(strict_types=1);

require __DIR__ . '/../vendor/autoload.php';

use App\Models\Buku;
use App\Repositories\BukuRepository;

$buku = new Buku('Clean Code', 'Robert Martin', 2008, 150000, 5, 'Teknologi');
$repo = new BukuRepository();

echo "Judul: " . htmlspecialchars($buku->judul) . PHP_EOL;
echo get_class($repo) . PHP_EOL;   // App\Repositories\BukuRepository (autoloaded)
```

> **Pembahasan alur:** Composer menghasilkan `vendor/autoload.php` berdasarkan mapping PSR-4. Saat `new Buku(...)` dieksekusi, autoloader mencari `src/Models/Buku.php`; saat `new BukuRepository()`, mencari `src/Repositories/BukuRepository.php`. Tidak ada `require` untuk class-class itu — cukup satu `require` autoload. `get_class($repo)` membuktikan class benar terbentuk.

**Tantangan 2** — Jika `.env`, `storage/`, `vendor/` berada dalam web root (`public/`):

- **`.env` bocor** — berisi `DB_USER`/`DB_PASSWORD`/`APP_DEBUG` — penyerang yang tahu path (`/.env`) bisa **mengunduh credential**. (Di Nginx sering diblokir, tapi Apache `Options -Indexes` + deny belum cukup secara universal — paling aman posisikan di luar.)
- **`storage/` bocor** — hasil upload (foto anggota, dokumen, log) bisa diakses/unduh langsung lewat URL, tanpa kontrol akses. Ini membatalkan desain "gambar.php" (materi 24) yang mengatur MIME; file bisa dieksekusi jika tersimpan `.php`.
- **`vendor/` bocor** — library & file PHAR dengan path dikenal dapat dieksploitasi (PHPUnit RCE klasik), atau digunakan untuk probing versi.

Dampak paling serius: **kedua-duanya menggeser "trust boundary"** — web server kini mengekspos file yang seharusnya hanya dipakai di belakang. Solusi: pisahkan `public/` sebagai **satu-satunya** titik minus — sesuai struktur MVC yang kamu bentuk di level ini.
