# 19. Inheritance, Interface, dan Trait

> **Level 4 · OOP dan Database PDO** — Membangun hierarki & kontrak antar class agar kode adil pakai, tidak mengulang.

---

## 1. Penjelasan Singkat & Konsep Dasar

Tiga mekanisme OOP untuk **berbagi kode & menetapkan kontrak** — beberapa kadang tertukar:

| | **Inheritance** | **Interface** | **Trait** |
|---|---|---|---|
| Apa | `class Admin extends User` — anak mewarisi data+method induk | `implements Searchable` — kontrak "harus punya method X" | `use HasTimestamps;` — potongan method reusable |
| Hubungan | "is-a" (Admin **adalah** User) | "mampu melakukan" (bisa di-*search*) | "menggunakan bagian" (meminjam method) |
| Boleh berapa | **satu** induk | **banyak** interface | **banyak** trait |
| Isi | property + method konkret/abstract | Hanya *signature* method (tanpa body) | Implementasi lengkap |
| Kenapa | code reuse secara hierarki | *polimorfisme*: kode yang memanggil interface tidak peduli class mana | berbagi kode antar class yang tidak ada hubungan waris |

**Konsep pengiring:**

- **`abstract class`** — class yang tidak bisa di-`new` langsung; ia *template* induk (bisa ada method `abstract` yang wajib diimplement anak).
- **Polimorfisme** — banyak class dengan implement berbeda memenuhi *satu kontrak*, sehingga pemanggil berhenti bergantung pada class spesifik.

**Benang Merah:** materi 18 membangun class mandiri; sekarang hubungan antar class: `User` (induk) → `Admin`/`Anggota` (anak); kontrak `Searchable`/`Exportable`; trait `HasTimestamps`/`HasSoftDelete`. Ini persis perancangan yang dipakai framework (model, repository, middleware) di Level 6.

---

## 2. Fungsi & Kegunaan Utama

- **Menghilangkan duplikasi** — `User` memegang `nama`, `email`, `verifyPassword()` sekali; `Admin` & `Anggota` mewarisinya. DRY pada tingkat hierarkis.
- **Kontrak yang terpaksa dipatuhi** — Interface menjamin class *memiliki* method yang dibutuhkan pemanggil; pemanggil menulis kode terhadap *interface*, bukan *implementasi* → mudah ditukar implementasi (misalnya repository interface → penggantian mock).
- **Berbagi lintas "pohon"** — Trait meminjamkan kode ke class yang *tidak* satu induk (misal `HasTimestamps` dipakai User dan Buku sekaligus) — PHP tidak mendukung multiple inheritance.
- **Polimorfisme** — `export($data)` menerima objek apa pun yang `implements Exportable`; berapa pun implementasinya, pekerjaan tetap jalan.

## 3. Contoh Kode & Implementasi Real-World

Struktur:

```
src/
├── Models/
│   ├── User.php      ← abstract
│   ├── Admin.php
│   ├── Anggota.php
│   └── Buku.php
└── Contracts/
    ├── Searchable.php
    └── Exportable.php
```

**Inheritance — abstract User:**

```php
<?php
// File: src/Models/User.php
declare(strict_types=1);

abstract class User {
    public function __construct(
        protected readonly int $id,
        protected string $nama,
        protected string $email,
        protected string $passwordHash,
    ) {}

    // Method konkret — implementasi siap pakai oleh semua anak
    public function verifyPassword(string $password): bool {
        return password_verify($password, $this->passwordHash);
    }

    public function getId(): int    { return $this->id; }
    public function getNama(): string { return $this->nama; }
    public function getEmail(): string { return $this->email; }

    // Method abstract — anak WAJIB mengimplementasi
    abstract public function getRole(): string;
    abstract public function getBatasPinjam(): int;
}

// File: src/Models/Admin.php
class Admin extends User {
    public function getRole(): string     { return 'admin'; }
    public function getBatasPinjam(): int { return PHP_INT_MAX; }
}

// File: src/Models/Anggota.php
class Anggota extends User {
    private array $pinjaman = [];

    public function getRole(): string     { return 'anggota'; }
    public function getBatasPinjam(): int { return 5; }

    public function pinjamBuku(Buku $buku): bool {
        if (count($this->pinjaman) >= $this->getBatasPinjam()) {
            throw new \RuntimeException('Batas pinjam tercapai.');
        }
        $buku->pinjam();
        $this->pinjaman[] = $buku;
        return true;
    }
}
```

**Interface — kontrak:**

```php
<?php
// File: src/Contracts/Searchable.php
interface Searchable {
    public function cari(string $keyword): array;
}

// File: src/Contracts/Exportable.php
interface Exportable {
    public function toCsv(): string;
    public function toJson(): string;
}
```

**Implementasi — polimorfisme:**

```php
<?php
// File: src/Models/KatalogBuku.php
class KatalogBuku implements Searchable, Exportable {
    public function __construct(private array $buku = []) {}

    public function cari(string $keyword): array {
        $kw = strtolower(trim($keyword));
        return array_values(array_filter($this->buku, fn($b) =>
            str_contains(strtolower($b['judul']), $kw)));
    }

    public function toCsv(): string {
        $out = "id,judul,harga\n";
        foreach ($this->buku as $b) {
            $out .= sprintf("%d,%s,%d\n", $b['id'], str_replace(',', ' ', $b['judul']), $b['harga']);
        }
        return $out;
    }

    public function toJson(): string {
        return json_encode($this->buku, JSON_UNESCAPED_UNICODE);
    }
}
```

**Trait — berbagi kode lintas class:**

```php
<?php
// File: src/Traits/HasTimestamps.php
trait HasTimestamps {
    private ?\DateTimeImmutable $createdAt = null;
    private ?\DateTimeImmutable $updatedAt = null;

    public function setCreatedAt(): void {
        $this->createdAt = new \DateTimeImmutable();
    }
    public function touch(): void {
        $this->updatedAt = new \DateTimeImmutable();
    }
    public function getCreatedAt(): ?\DateTimeImmutable { return $this->createdAt; }
    public function getUpdatedAt(): ?\DateTimeImmutable { return $this->updatedAt; }
}

// File: src/Traits/HasSoftDelete.php
trait HasSoftDelete {
    private ?\DateTimeImmutable $deletedAt = null;

    public function softDelete(): void { $this->deletedAt = new \DateTimeImmutable(); }
    public function restore(): void    { $this->deletedAt = null; }
    public function isDeleted(): bool  { return $this->deletedAt !== null; }
}
```

```php
<?php
// Pakai trait di dua class yang tidak berhubungan:
class BukuModel {
    use HasTimestamps;
    use HasSoftDelete;
    // ...
}
class AnggotaModel {
    use HasTimestamps;
    // ...
}
```

## 4. Analogi Sederhana

Dalam **Sistem Administrasi Kantor**:

- **Inheritance** = **jabatan & posisi**. Ada kelas "Pegawai" (semua punya nama, ID, cara verifikasi). "Admin" dan "Anggota" ikut *mewarisi* ketentuan pegawai, tapi jabatan "Admin" punya wewenang lebih (role, batas pinjam tak terbatas). Aturan umum pegawai ditulis sekali di atasan.
- **Abstract method** = *syarat wajib* pada posisi tertentu: "setiap Admin/Anggota HARUS bisa menjawab berapa batas pinjamnya". Kepala kantor tidak peduli caranya, asal ada jawabannya.
- **Interface** = **standar kontrak layanan** (misal "layanan ekspor"). Setiap divisi yang mengaku "bisa ekspor CSV" *wajib* menyediakan fungsi itu — dan departemen pemanggil tidak peduli divisi mana yang mengerjakan, asal kualitasnya sama.
- **Trait** = **modul pelatihan bersama**. Modul "stempel tanggal" (created_at/updated_at) bisa dipakai oleh siapa pun yang butuh, tanpa harus jadi satu jabatan dengan modul itu. Berbagi kemampuan, bukan hierarki.
- **Polimorfisme** = "kirim berkas ke unit Ekspor" — selama unitnya punya SOP ekspor, kamu tidak peduli unit itu Admin atau Anggota.

---

## 5. Kapan Harus Digunakan & Kasus Penggunaan

- **Inheritance**: ketika class memang "is-a" — `Admin extends User`, `Anggota extends User`. Jangan force inheritance untuk "mengeremut code" kalau bukan hubungan is-a (lebih cocok trait/komposisi).
- **Interface**: untuk *kontrak publik* yang dipakai banyak class: repository, gateway pembayaran, exportable. Kode pemanggil mengetik terhadap interface (dependency injection, materi 26).
- **Trait**: untuk *berbagi implementasi* antar class berbeda induk: `HasTimestamps`, `HasSoftDelete` di Buku & Anggota. PHP's "horizontal reuse".
- **Abstract class**: sebagai templat induk dengan sebagian implementasi + wajibkan method tertentu.
- **Kasus nyata (membantu di Level 6)**: interface `BukuRepositoryInterface` → implementasi `BukuRepository` (PDO) → test pakai `FakeRepository` — pemanggil tidak sadar perbedaan implementasi.

## 6. Aspek Keamanan & Best Practices (Critical)

- **Jangan tangani password di turunan non-induk** — `password_verify` hidup di `User` (induk), tidak di `Admin`/`Anggota` — satu titik, satu kebijakan.
- **`protected` untuk data yang diakses anak** — tapi tetap jangan ekspos `passwordHash` lewat method publik/getter yang bisa bocor ke API/JSON.
- **Interface = jangan menaruh logika keamanan rapuh** — implementasi selalu diperiksa (misal `implements Searchable` tidak otomatis aman; isi method harus tetap di-escape/validasi).
- **Best practices:**
  - Utamakan **komposisi & trait** daripada inheritance dalam "dangkal"; gunakan inheritance untuk hubungan is-a yang jujur.
  - Jangan buat hierarki terlalu dalam (kedalaman 1-2 sudah cukup).
  - Interface kecil & fokus (Interface Segregation). `Searchable` jangan digabung `Exportable`.
  - Trait sebaiknya tidak menaruh state bisnis yang berbahaya; pakai untuk concern lintas-cut yang jelas (timestamp, soft-delete).
  - Beri nama trait dengan suffix `...able`/`Has...` agar terbaca.

## 7. Kesalahan Umum & Debugging

- **`Fatal error: Class X abstract and contains 1 abstract method`** — lupa mengimplement method `abstract` di anak. Solusi: implementasikan method yang kurang (pesan menyebut namanya).
- **`Cannot instantiate abstract class`** — kamu `new User()` padahal `User` abstract. Solusi: instansiasi `new Admin()`.
- **Trait method bentrok** — dua trait punya method sama → *Fatal error: Trait method has not been applied*. Solusi: `insteadof` atau `as` untuk memilih/menamai ulang.
- **Interface method signature tidak cocok** — implement harus sesuai tipe parameter/return (lewat `declare(strict_types=1)`, pasti error jelas). Periksa signature di kedua sisi.
- **Overriding method yang salah akses** — method induk `private` tidak bisa dioverride bermakna; jadikan `protected` bila anak perlu.
- **Lupa `use HasTimestamps;`** — method trait tidak ada → `Call to undefined method`. Pastikan `use` trait dideklarasikan di class.

## 8. Soal Latihan & Kunci Jawaban

### Tantangan 1
Lengkapi sistem role untuk perpustakaan: abstract `User` (seperti di atas). Tambahkan entitas concret `Pustakawan` dengan `getRole()='pustakawan'` dan `getBatasPinjam()=10`. Buat method `tampilkanBatas(User $user): string` yang memakai polimorfisme (menerima `User`) dan mengembalikan "Nama (role): batas X buku". Panggil untuk `Admin`, `Anggota`, `Pustakawan`.

### Tantangan 2
Interface `Exportable` memiliki `toCsv(): string` dan `toJson(): string`. Buat class `LaporanDenda` yang `implements Exportable` dan memakai trait `HasTimestamps`. Jelaskan mengapa class ini tidak bisa bisa mendapat dua implementasi dari dua induk/cara apa yang dipakai.

### Jawaban & Pembahasan

**Tantangan 1**

```php
<?php
declare(strict_types=1);

require_once 'src/Models/User.php';
require_once 'src/Models/Admin.php';
require_once 'src/Models/Anggota.php';

class Pustakawan extends User {
    public function getRole(): string     { return 'pustakawan'; }
    public function getBatasPinjam(): int { return 10; }
}

function tampilkanBatas(User $user): string {
    return sprintf(
        '%s (%s): batas %d buku',
        $user->getNama(),
        $user->getRole(),
        $user->getBatasPinjam()
    );
}

$admin      = new Admin(1, 'Budi', 'budi@x.id', 'hash');
$anggota    = new Anggota(2, 'Sari', 'sari@x.id', 'hash');
$pustakawan = new Pustakawan(3, 'Dewi', 'dewi@x.id', 'hash');

echo tampilkanBatas($admin) . "\n";      // Budi (admin): batas 9223372036854775807 buku
echo tampilkanBatas($anggota) . "\n";    // Sari (anggota): batas 5 buku
echo tampilkanBatas($pustakawan) . "\n"; // Dewi (pustakawan): batas 10 buku
```

> **Pembahasan alur:** `tampilkanBatas(User $user)` hanya tahu *kontrak induk* `User` — implementasi `getRole()`/`getBatasPinjam()` dijalankan sesuai object aktual (polimorfisme). Lantaran `Admin` diperlakukan sebagai `User`, perilakunya tetap spesifik class-nya. `PHP_INT_MAX` pada admin mencerminkan batas tak terbatas.

**Tantangan 2**

```php
<?php
declare(strict_types=1);

require_once 'src/Contracts/Exportable.php';
require_once 'src/Traits/HasTimestamps.php';

class LaporanDenda implements Exportable {
    use HasTimestamps;

    public function __construct(private array $data) {
        $this->setCreatedAt();
    }

    public function toCsv(): string {
        $out = "anggota,denda\n";
        foreach ($this->data as $r) {
            $out .= sprintf("%s,%d\n", htmlspecialchars($r['nama'], ENT_NOQUOTES), $r['denda']);
        }
        return $out;
    }

    public function toJson(): string {
        return json_encode(['report' => $this->data], JSON_UNESCAPED_UNICODE);
    }
}

$laporan = new LaporanDenda([['nama' => 'Sari, A', 'denda' => 2000]]);
echo $laporan->getCreatedAt()->format('Y-m-d H:i:s') . "\n";
```

> **Pembahasan:** PHP memakai **single inheritance** — sebuah class hanya bisa `extends` **satu** class. Kebutuhan "dua kelompok method dari sumber berbeda" diselesaikan dengan dua mekanisme berbeda: **interface** (kontrak, tanpa implementasi) untuk `Exportable`, dan **trait** (implementasi yang dipinjam) untuk `HasTimestamps`. Kombinasi `implements ...` + `use ...trait` memberi efek "multiple-inheritance" yang aman tanpa konflik hierarki. Catatan keamanan: data `$nama` di-escape (`htmlspecialchars`) sebelum masuk format CSV agar karakter `,`/`"` tidak merusak struktur kolom.
