# 26. API Resource — Transformasi Data yang Konsisten

Kita mulai Level 5 dengan fondasi API yang rapi: API Resource. Setelah kita selesai membangun auth, policy, dan validasi di Level 4, sekarang waktunya membuka pintu bagi aplikasi lain (mobile app, sistem lain) lewat API. API Resource adalah jembatan antara model Eloquent kita dan format JSON yang konsisten, sekaligus tempat kita mengontrol field apa saja yang boleh terlihat.

## 1. Penjelasan Singkat & Konsep Dasar

Di Level 3 kita belajar eager loading untuk menghindari N+1, di Level 4 kita pakai Form Request untuk validasi. Sekarang di Level 5, API Resource berfungsi sebagai "lapisan presentasi" data: model Buku kita di database tidak selalu boleh ditampilkan apa adanya ke konsumen API. Contohnya `created_at`, atau relasi yang harus di-format ulang.

Konsepnya sederhana: `BukuResource` adalah class yang punya method `toArray()`. Laravel memanggil method ini setiap kali Resource dikirim sebagai response, lalu mengubah hasilnya menjadi JSON. Jadi transformasi data terjadi di satu tempat, konsisten di seluruh endpoint.

Hubungan dengan materi lain:
- Menggunakan Eloquent (Level 3) — kita transformasi hasil query yang sudah di-eager load.
- Menggunakan Form Request (Level 4) — `store` dan `update` tetap menerima input yang sudah tervalidasi.
- Menjadi bahan dasar Sanctum (27) dan Error Handling (28).

## 2. Fungsi & Kegunaan Utama dalam Laravel

Masalah yang dipecahkan API Resource:

1. **Konsistensi format** — semua endpoint mengembalikan struktur JSON yang sama, tidak peduli dari mana data diambil.
2. **Keamanan data** — kita bisa menyembunyikan field sensitif. Bedanya dengan `$hidden` di model: `$hidden` berlaku global, Resource bisa bersifat kondisional (misal admin vs anggota biasa).
3. **Format custom** — membuat `harga_format` (rupiah), menambahkan flag `tersedia`, atau menyisipkan `links` untuk navigasi.
4. **Dekorasi tambahan tanpa mengubah model** — `whenCounted`, `whenLoaded`, `mergeWhen` memungkinkan data muncul hanya jika memang dibutuhkan.
5. **Pagination siap pakai** — `BukuResource::collection()` yang dibungkus paginator otomatis menghasilkan `data`, `links`, dan `meta`.

## 3. Contoh Kode & Implementasi (Real-world Example)

Semua path di bawah adalah path standar Laravel 11.

### 3.1 Membuat Resource

```bash
# Lokasi hasil: app/Http/Resources/BukuResource.php
php artisan make:resource BukuResource
```

### 3.2 app/Http/Resources/BukuResource.php

```php
<?php

namespace App\Http\Resources;

use Illuminate\Http\Request;
use Illuminate\Http\Resources\Json\JsonResource;

class BukuResource extends JsonResource
{
    /**
     * Transformasi resource menjadi array untuk response JSON.
     */
    public function toArray(Request $request): array
    {
        return [
            'id' => $this->id,
            'judul' => $this->judul,
            'pengarang' => $this->pengarang,
            'isbn' => $this->isbn,
            'tahun' => $this->tahun,
            'harga' => $this->harga,
            // Accessor dari model, mis. format rupiah: "Rp 95.000"
            'harga_format' => $this->harga_format,
            // Accessor boolean, cek stok > jumlah peminjaman aktif
            'tersedia' => $this->tersedia(),

            'kategori' => KategoriResource::make($this->whenLoaded('kategori')),

            // Hanya muncul jika query memakai ->withCount('peminjaman')
            'total_peminjaman' => $this->whenCounted('peminjaman'),

            // Hanya di-load kalau eager loading 'peminjaman' dipanggil
            'peminjaman' => PeminjamanResource::collection($this->whenLoaded('peminjaman')),

            // Kondisional: hanya admin yang boleh lihat metadata
            'created_at' => $this->when(
                $request->user()?->tokenCan('admin') ?? false,
                $this->created_at
            ),

            'links' => [
                'self' => route('api.v1.buku.show', $this->id),
                'index' => route('api.v1.buku.index'),
            ],
        ];
    }
}
```

Catatan singkat:
- `whenLoaded('kategori')` mencegah query tambahan dan mengembalikan null kalau relasi tidak di-load.
- `whenCounted('peminjaman')` menampilkan jumlah relasi hanya jika query memakai `withCount`.
- `$request->user()?->tokenCan('admin')` memanfaatkan abilities token Sanctum (akan dibahas di materi 27).
- `links` memudahkan konsumen API menavigasi tanpa menebak URL.

### 3.3 Controller API v1

Lokasi: `app/Http/Controllers/Api/V1/BukuController.php`

```php
<?php

namespace App\Http\Controllers\Api\V1;

use App\Models\Buku;
use App\Http\Requests\StoreBukuRequest;
use App\Http\Requests\UpdateBukuRequest;
use App\Http\Resources\BukuResource;
use App\Http\Controllers\Controller;
use Illuminate\Http\Request;

class BukuController extends Controller
{
    /**
     * GET /api/v1/buku?judul=&kategori_id=&page=
     * Filter + paginate + withCount. BukuResource::collection
     * otomatis membungkus hasil ke struktur {data, links, meta}.
     */
    public function index(Request $request)
    {
        $buku = Buku::query()
            ->with('kategori')                       // eager loading anti N+1
            ->withCount('peminjaman')                // isi whenCounted
            ->when($request->judul, fn ($q) => $q->where('judul', 'like', "%{$request->judul}%"))
            ->when($request->kategori_id, fn ($q) => $q->where('kategori_id', $request->kategori_id))
            ->paginate($request->per_page ?? 15);

        return BukuResource::collection($buku);
    }

    /**
     * POST /api/v1/buku
     * 201 Created + Location header menunjuk ke resource baru.
     */
    public function store(StoreBukuRequest $request)
    {
        $buku = Buku::create($request->validated());

        return BukuResource::make($buku)
            ->response()
            ->setStatusCode(201)
            ->header('Location', route('api.v1.buku.show', $buku));
    }

    /**
     * GET /api/v1/buku/{buku}
     */
    public function show(Buku $buku)
    {
        $buku->load(['kategori', 'peminjaman']); // siapkan whenLoaded

        return BukuResource::make($buku);
    }

    /**
     * PUT/PATCH /api/v1/buku/{buku}
     * ->fresh() memastikan response berisi data terbaru setelah update.
     */
    public function update(UpdateBukuRequest $request, Buku $buku)
    {
        $buku->update($request->validated());

        return BukuResource::make($buku->fresh());
    }

    /**
     * DELETE /api/v1/buku/{buku}
     * 204 No Content — tidak ada body.
     */
    public function destroy(Buku $buku)
    {
        $buku->delete();

        return response()->noContent();
    }
}
```

## 4. Analogi Sederhana

**API = Menu takeaway untuk aplikasi lain.** Restoran tidak hanya melayani tamu yang duduk di meja (web HTML), tapi juga menyediakan menu digital (JSON) untuk aplikasi lain — mobile app atau sistem lain. **API Resource = pramusaji khusus yang selalu menyajikan pesanan dalam format standar yang sama.** Mau pesan lewat meja atau lewat aplikasi, penyajiannya tetap rapi: selalu ada nama menu, harga dalam format yang sama, dan stok ketersediaan. Pramusaji juga tahu kapan harus menahan informasi tertentu — misalnya tidak menceritakan resep rahasia dapur (field sensitif) kepada semua tamu.

## 5. Kapan Harus Digunakan & Kasus Penggunaan (Use Cases)

1. **Mobile app perpustakaan** — aplikasi Android/iOS butuh daftar buku; mereka tidak butuh kolom database mentah, tapi format bersih seperti `harga_format` dan `tersedia`.
2. **Dashboard admin** — butuh `total_peminjaman` dan `created_at`, cukup dengan `whenCounted` dan conditional field.
3. **Sistem lain (integrasi)** — sistem kampus ingin menarik data buku; Resource menjamin format tidak berubah walaupun struktur database berubah.
4. **Setiap kali ada relasi** — menyajikan `peminjaman` sebagai kumpulan resource lain memastikan format nested juga konsisten.
5. **Pagination** — endpoint daftar selalu butuh `data` + `links` + `meta`; Resource collection mengurus ini otomatis.

## 6. Poin-poin Penting & Best Practices

- **API selalu mengembalikan JSON**, bukan HTML atau format campuran.
- **Gunakan API Resource** untuk transformasi konsisten; jangan menulis `$buku->toArray()` manual di controller.
- **Gunakan `whenLoaded`** untuk menghindari N+1 — data relasi hanya muncul kalau memang di-load.
- **Gunakan `whenCounted`** untuk angka jumlah relasi; aktifkan lewat `withCount()` di query.
- **Pakai status code yang tepat**: 200 (ok), 201 (created), 204 (no content), 401 (unauthorized), 403 (forbidden), 404 (not found), 422 (validation error).
- **Gunakan `Route::apiResource`** — otomatis menambahkan route `show`, `update`, `destroy` tanpa `create`/`edit`.
- **Beri prefix `v1` dan name `api.v1.`** — ini memberi versi API dan nama route yang stabil untuk `route()`.
- **Berikan `Location` header** pada response 201.
- **Terapkan rate limiting** pada route API (mis. `throttle:60,1`) untuk melindungi server dari spam request.
- **Jangan pernah mengembalikan `$model` polos** di endpoint API publik — Resource adalah satu-satunya gerbang keluar data.

## 7. Kesalahan Umum (Common Pitfalls & Anti-patterns)

1. **Expose field sensitif** — langsung `return $buku;` akan membocorkan `created_at`, kolom internal, atau relasi yang tidak perlu. Selalu filter lewat Resource.
2. **N+1 di API** — memanggil `BukuResource::collection($buku)` tanpa eager loading membuat query berlipat. Ingat `with()` dan `withCount()`.
3. **Mengembalikan collection mentah** — `BukuResource::collection($buku)` dengan data array polos tidak menghasilkan `links`/`meta`; pakai paginator.
4. **Status code salah** — `store` mengembalikan 200 padahal harus 201; `destroy` mengembalikan data padahal harus 204.
5. **Resource memuat relasi saat tidak dibutuhkan** — tanpa `whenLoaded`, response jadi besar dan query jadi banyak.
6. **Response error masih HTML** — itu dibahas detail di materi 28, karena Laravel default menampilkan halaman error HTML, bukan JSON.
7. **Membuat resource untuk satu penggunaan** — kalau `index` dan `show` beda kebutuhan, buat `BukuResource` dan `BukuCollection`/resource terpisah daripada menjejalkan semua field kondisional.

**Troubleshooting cepat:**
- Response daftar tidak ada `meta`? Pastikan pakai `paginate()` bukan `get()`.
- Relasi `peminjaman` selalu null? Pastikan `->load('peminjaman')` atau `->with('peminjaman')` dipanggil sebelum Resource.
- `total_peminjaman` hilang? Tambahkan `->withCount('peminjaman')` di query.

## 8. Soal Latihan & Kunci Jawaban

### Tantangan

**Tantangan 1: Endpoint daftar buku dengan filter dan pagination.**
Buat endpoint `GET /api/v1/buku` yang mendukung filter `judul`, pagination 15 per halaman, memuat relasi `kategori`, menampilkan `total_peminjaman` via `whenCounted`, dan mengembalikan JSON berformat Resource (`data`, `links`, `meta`).

**Tantangan 2: Resource dengan field kondisional.**
Modifikasi `BukuResource` agar hanya menampilkan `created_at` untuk pengguna yang punya ability token `admin`, dan selalu menampilkan `tersedia` (boolean) berdasarkan stok yang lebih besar dari jumlah peminjaman aktif.

### Jawaban & Pembahasan

**Jawaban Tantangan 1:**

```php
// routes/api.php
Route::prefix('v1')->name('api.v1.')->group(function () {
    Route::apiResource('buku', BukuController::class);
});
```

```php
// app/Http/Controllers/Api/V1/BukuController.php
public function index(Request $request)

        ->with('kategori')
        ->withCount('peminjaman')
        ->when($request->judul, fn ($q) => $q->where('judul', 'like', "%{$request->judul}%"))
```

```php
// app/Models/Buku.php
public function tersedia(): bool
{
    return $this->stok > $this->peminjaman()->where('status', 'aktif')->count();
}
```

Alur: `when()` hanya memasukkan `created_at` jika kondisi true (pengguna punya ability `admin` lewat token Sanctum). Accessor `tersedia()` membandingkan stok dengan jumlah peminjaman berstatus aktif; kita meneleponnya langsung di Resource sehingga selalu dihitung fresh, tanpa mengekspos query mentah ke konsumen API. Dengan pola ini, konsumen non-admin tidak pernah melihat metadata internal, dan format tetap konsisten di seluruh endpoint.
