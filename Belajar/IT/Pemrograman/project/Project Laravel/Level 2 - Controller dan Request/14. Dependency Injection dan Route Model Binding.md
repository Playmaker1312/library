# 14. Dependency Injection dan Route Model Binding

Di materi 13 kita belajar controller memisahkan logika dari route. Tapi bagaimana controller mendapatkan "alat kerjanya" — misalnya service atau data request? Jawabannya ada di dua fitur yang sangat sering dipakai di Laravel: **Dependency Injection (DI)** dan **Route Model Binding**. Keduanya bekerja lewat type-hint di parameter method/constructor, dan keduanya membuat kode lebih bersih serta mudah dirawat. Materi ini kita pelajari di Level 2 sambil menunggu model Eloquent di Level 3.

## 1. Penjelasan Singkat & Konsep Dasar

- **Dependency Injection** artinya sebuah class tidak membuat dependency-nya sendiri, melainkan "disuntikkan" dari luar. Laravel membaca type-hint parameter, lalu otomatis membangun objeknya dan memasukkannya ke method. Konsep ini diatur oleh Service Container (dibahas lebih dalam di Level 6), tapi di level ini kamu cukup tahu: tulis type-hint, Laravel yang kerja.
- **Route Model Binding** adalah jalan pintas Laravel untuk mengambil data berdasarkan id di URL. `Route::get('/buku/{buku}')` dipasangkan dengan parameter `Buku $buku` — Laravel otomatis mencari `buku` dengan id tersebut dari database dan mengisikannya ke parameter. Kalau tidak ketemu, otomatis 404.

Catatan penting untuk level ini: model Eloquent (`Buku`) belum dibuat sampai Level 3. Jadi di sini konsepnya dijelaskan penuh dan contoh kode tetap disediakan — kamu bisa langsung menggunakannya begitu `BukuService` dan `Buku` hadir.

## 2. Fungsi & Kegunaan Utama dalam Laravel

- **Memutus ketergantungan keras.** Controller tidak perlu `new BukuService()` di setiap method. Dependency ditentukan sekali di constructor.
- **Kode lebih mudah diuji.** Karena dependency disuntikkan, kamu bisa menggantinya dengan "versi palsu" (mock) saat menulis test.
- **Otomatis & konsisten.** Tidak ada kode boilerplate untuk menebak-nebak objek mana yang dibutuhkan. Cukup type-hint.
- **Menghindari `findOrFail` manual di controller.** Route Model Binding menghapus baris `$buku = Buku::findOrFail($id);` dari controller — Laravel sudah melakukannya di belakang layar.
- **URL jadi ekspresif.** `/buku/{buku}` dan `/buku/{buku:isbn}` langsung "berbicara" soal data apa yang diambil, tanpa pencarian manual.
- **Menjaga controller tetap thin.** Detail "bagaimana data diambil" tidak lagi jadi tanggung jawab controller.

## 3. Contoh Kode & Implementasi (Real-world Example)

### A. Constructor Injection

Suntik `BukuService` lewat constructor agar tersedia di seluruh method:

```php
<?php

// app/Http/Controllers/BukuController.php
namespace App\Http\Controllers;

use App\Services\BukuService;
use Illuminate\Http\Request;
use Illuminate\View\View;

class BukuController extends Controller
{
    // Property menyimpan dependency yang disuntikkan.
    private BukuService $bukuService;

    // Laravel membaca type-hint BukuService, lalu otomatis
    // membuat instansinya dan memanggil constructor ini.
    public function __construct(BukuService $bukuService)
    {
        $this->bukuService = $bukuService;
    }

    // Sekarang semua method bisa memakai $this->bukuService.
    public function index(Request $request): View
    {
        $buku = $this->bukuService->ambilSemua();

        return view('buku.index', compact('buku'));
    }
}
```

Contoh `BukuService`:

```php
<?php

// app/Services/BukuService.php
namespace App\Services;

class BukuService
{
    // Logika bisnis katalog dipindah ke service agar controller tetap tipis.
    // Saat ini data masih hardcode; nanti di Level 3 menjadi query Eloquent.
    public function ambilSemua(): array
    {
        return [
            ['id' => 1, 'judul' => 'Clean Code', 'kategori' => 'Teknologi'],
            ['id' => 2, 'judul' => 'Laskar Pelangi', 'kategori' => 'Fiksi'],
        ];
    }
}
```

### B. Method Injection (Request)

Tidak semua dependency perlu di constructor. Yang hanya dipakai satu method cukup ditaruh di parameter method:

```php
// app/Http/Controllers/BukuController.php
use Illuminate\Http\Request;

// Request hanya dibutuhkan di method index dan store, jadi disuntikkan per method.
public function index(Request $request): View
{
    $kategori = $request->query('kategori');

    return view('buku.index', compact('kategori'));
}
```

### C. Route Model Binding

Di Level 3, begitu model `Buku` Eloquent ada, binding terlihat sangat sederhana:

```php
<?php

// app/Http/Controllers/BukuController.php
namespace App\Http\Controllers;

use App\Models\Buku;
use Illuminate\View\View;

class BukuController extends Controller
{
    // Parameter {buku} di route diikat ke type-hint Buku $buku.
    // Laravel otomatis menjalankan: SELECT * FROM buku WHERE id = {buku}
    // Jika tidak ada data, otomatis mengembalikan 404.
    public function show(Buku $buku): View
    {
        return view('buku.show', compact('buku'));
    }
}
```

```php
// routes/web.php
use App\Http\Controllers\BukuController;

// Segmen {buku} pada URL diikat ke parameter $buku.
Route::get('/buku/{buku}', [BukuController::class, 'show']);
```

Pola ini juga berlaku untuk update dan destroy:

```php
public function update(Request $request, Buku $buku): RedirectResponse
{
    // $buku sudah berisi instance model dengan id dari URL.
    $buku->update($request->only('judul', 'harga'));

    return redirect()->route('buku.index')->with('sukses', 'Buku diperbarui');
}

public function destroy(Buku $buku): RedirectResponse
{
    $buku->delete();

    return redirect()->route('buku.index')->with('sukses', 'Buku dihapus');
}
```

### D. Custom Key Binding

Secara default Laravel mencocokkan berdasarkan kolom `id`. Kalau URL harus memakai kolom lain, misalnya `isbn`:

```php
// routes/web.php
// {buku:isbn} berarti cocokkan berdasarkan kolom isbn, bukan id.
Route::get('/buku/{buku:isbn}', [BukuController::class, 'show']);

// URL: /buku/978-0132350884  ->  SELECT * FROM buku WHERE isbn = '978-0132350884'
```

### E. Perbandingan Manual vs Route Model Binding

```php
// Cara manual (tanpa binding):
public function show(int $id): View
{
    $buku = Buku::findOrFail($id); // query manual + 404 manual
    return view('buku.show', compact('buku'));
}

// Dengan binding (lebih bersih):
public function show(Buku $buku): View // 404 otomatis, tanpa query manual
{
    return view('buku.show', compact('buku'));
}
```

## 4. Analogi Sederhana

Masih restoran yang sama. Sekarang kita bicara bagaimana koki (Controller) mendapat alat dan bahan.

- **Dependency Injection = Koki menerima peralatan dari pengelola dapur, bukan membeli sendiri.** Koki tidak perlu keluar toko membeli wajan (bikin sendiri `new BukuService()`). Pengelola dapur (Laravel/Service Container) sudah menyiapkan wajan dan menaruhnya di tangan koki saat giliran kerja dimulai. Koki tinggal pakai: `$this->bukuService->ambilSemua()`.
- **Route Model Binding = Pelayan sudah menyiapkan piring sesuai pesanan.** Saat tamu pesan "buku nomor 2", pelayan tidak hanya menulis "2" di slip. Pelayan sudah pergi ke gudang bahan (Model), mengambil buku nomor 2, dan meletakkannya di meja koki. Koki tidak perlu mencari-cari lagi. Kalau buku nomor 2 tidak ada, pelayan langsung bilang "maaf, tidak ada" (404) sebelum koki mulai bekerja.
- **Controller = Koki.** Koki menerima slip pesanan (Request), memakai bahan yang sudah disiapkan (Buku), dan memberi tahu pelayan pesanan siap (return view). Koki tetap tidak menanam sayur sendiri — tidak query DB manual, tidak melakukan `findOrFail` berulang.

Intinya: controller tidak boleh sibuk "cara mendapatkan bahan", cukup "bahan sudah di tangan, tinggal masak".

## 5. Kapan Harus Digunakan & Kasus Penggunaan (Use Cases)

- **Constructor injection**: ketika service dipakai di banyak method — misalnya `BukuService` dipakai `index`, `show`, `store`. Sekali di constructor, semua method bisa pakai.
- **Method injection**: ketika dependency hanya dipakai satu method — paling umum adalah `Request $request` di `index`/`store`.
- **Route model binding**: setiap endpoint yang mengambil data per id — `show`, `update`, `destroy` buku. Juga untuk halaman detail anggota (`/anggota/{anggota}`) dan peminjaman.
- **Custom key binding**: saat URL publik memakai identitas yang ramah, seperti ISBN buku, bukan angka id.
- **Menulis unit test**: karena dependency disuntikkan, `BukuController` mudah dites dengan mengganti `BukuService` dengan mock.

## 6. Poin-poin Penting & Best Practices

- **Dua jenis injection**: constructor (dipakai banyak method) dan method (dipakai satu method). Jangan boros — `Request` tidak perlu jadi property constructor.
- **Laravel resolve otomatis**: cukup type-hint, Service Container yang membangun objek. Detailnya di Level 6.
- **Route Model Binding wajib type-hint model di parameter**: `public function show(Buku $buku)` dan nama parameter harus sama dengan nama segmen route (`{buku}`).
- **Default binding pakai kolom `id`**; pakai sintaks `{buku:isbn}` untuk custom key.
- **404 otomatis**: binding langsung menghasilkan 404 jika data tidak ada — tidak perlu `abort` manual.
- **Tetap thin controller**: binding menghapus boilerplate query, jadi controller makin ramping.
- **Model Eloquent belum ada di level ini**: kamu tetap bisa memahami konsep dan menyiapkan controller; contoh binding baru bisa dipakai penuh setelah model `Buku` dibuat di Level 3.
- **Nama property private dengan type-hint**: `private BukuService $bukuService;` (PHP 8+ property promotion bisa dipakai juga).

## 7. Kesalahan Umum (Common Pitfalls & Anti-patterns)

- **Parameter tidak match dengan route segment.** `Route::get('/buku/{id}', ...)` + `public function show(Buku $id)` — Laravel mencari segmen bernama `id` yang tidak ada di type-hint `$buku`, hasilnya error/resolve gagal. Aturan: nama parameter wajib sama dengan nama segmen route.
- **Lupa `use App\Models\Buku;`** di controller. Laravel tidak bisa menemukan class, muncul error `Class "Buku" not found`. Cek import di atas file.
- **Meng-call `new` untuk service di dalam controller.** `$service = new BukuService();` di dalam method mengalahkan tujuan DI dan menyulitkan test. Biarkan Laravel menyuntikkannya.
- **Menulis `findOrFail` berulang** di controller padahal sudah ada binding. Ini duplikasi yang tidak perlu.
- **Custom key tanpa sintaks benar.** Menulis `{buku}` padahal ingin ISBN berarti tetap pakai `id`. Gunakan `{buku:isbn}` agar kolom pencocokannya ISBN.
- **Constructor terlalu ramai.** Kalau constructor menerima 5+ dependency, itu tanda controller terlalu banyak tanggung jawab; pertimbangkan memecah service.
- **Troubleshooting**: `Route [buku.index] not defined` berarti route belum diberi nama atau belum didaftarkan — pastikan `Route::get('/buku', ...)` ada dan pakai `->name('buku.index')` atau route resource.

## 8. Soal Latihan & Kunci Jawaban

### Tantangan

1. Buat `BukuService` dengan method `filterByKategori(string $kategori): array` yang memfilter katalog hardcode, lalu suntikkan lewat constructor ke `BukuController` dan pakai di method `index(Request $request)`.
2. Jelaskan (tanpa menulis query) apa yang Laravel lakukan saat request `GET /buku/7` diproses oleh `public function show(Buku $buku)`, dan bagaimana perilakunya jika buku id 7 tidak ada. Lalu tulis versi route dengan custom key ISBN.

### Jawaban & Pembahasan

```php
<?php

// app/Services/BukuService.php
namespace App\Services;

class BukuService
{
    // Katalog hardcode sementara; nanti diganti query Eloquent di Level 3.
    private array $katalog = [
        ['id' => 1, 'judul' => 'Clean Code', 'kategori' => 'Teknologi'],
        ['id' => 2, 'judul' => 'Laskar Pelangi', 'kategori' => 'Fiksi'],
        ['id' => 3, 'judul' => 'History of Java', 'kategori' => 'Sejarah'],
    ];

    // Logika filter dipindah dari controller ke service.
    public function filterByKategori(string $kategori): array
    {
        return array_values(
            array_filter($this->katalog, fn ($buku) => $buku['kategori'] === $kategori)
        );
    }
}
```

```php
<?php

// app/Http/Controllers/BukuController.php
namespace App\Http\Controllers;

use App\Models\Buku; // dipakai untuk binding di method show
use App\Services\BukuService;
use Illuminate\Http\Request;
use Illuminate\View\View;

class BukuController extends Controller
{
    private BukuService $bukuService;

    // Tantangan 1: constructor injection.
    public function __construct(BukuService $bukuService)
    {
        $this->bukuService = $bukuService;
    }

    public function index(Request $request): View
    {
        $kategori = $request->query('kategori');

        // Service dipakai, bukan logika filter ditulis ulang di sini.
        $buku = $kategori
            ? $this->bukuService->filterByKategori($kategori)
            : $this->bukuService->ambilSemua(); // asumsikan ada method ini

        return view('buku.index', compact('buku', 'kategori'));
    }

    // Tantangan 2: route model binding.
    public function show(Buku $buku): View
    {
        return view('buku.show', compact('buku'));
    }
}
```

```php
// routes/web.php
use App\Http\Controllers\BukuController;

// Tantangan 2a: binding default id.
Route::get('/buku/{buku}', [BukuController::class, 'show']);

// Tantangan 2b: custom key ISBN.
Route::get('/buku-by-isbn/{buku:isbn}', [BukuController::class, 'show']);
```

Penjelasan alur:

1. `BukuService` menyimpan katalog dan logika filter. Laravel membuat satu instansinya dan menyuntikkannya ke constructor `BukuController` — controller tidak pernah memanggil `new BukuService()`.
2. Request `GET /buku?kategori=Fiksi` masuk; `index` membaca query string, lalu menyerahkan filter ke service. Controller tetap tipis.
3. Saat `GET /buku/7` masuk, Laravel melihat parameter `Buku $buku` dan segmen `{buku}` yang cocok. Ia menjalankan `SELECT * FROM buku WHERE id = 7`. Jika ada, objek `Buku` terisi data dan masuk ke method `show`. Jika tidak ada, Laravel otomatis mengembalikan halaman 404 — tanpa `abort` dan tanpa query manual di controller.
4. Route kedua memakai `{buku:isbn}` sehingga Laravel mencocokkan kolom `isbn`, contoh URL `/buku-by-isbn/978-0132350884`. Setelah model Eloquent `Buku` dibuat di Level 3, kode binding ini langsung berfungsi tanpa perubahan lain di controller.
