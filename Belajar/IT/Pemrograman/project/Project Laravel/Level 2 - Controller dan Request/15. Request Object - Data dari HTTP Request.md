# 15. Request Object — Data dari HTTP Request

Di materi 13 dan 14 kita melihat `Request $request` muncul di parameter method controller, tapi belum kita bedah. Objek `Request` (kelas `Illuminate\Http\Request`) adalah jendela ke seluruh data yang datang dari browser: query string, isi form, header, IP, file upload, bahkan method HTTP-nya. Menguasai objek ini berarti kamu tidak akan pernah menyentuh `$_GET`/`$_POST` lagi. Di materi ini kita bedah Request Object lewat kasus katalog buku Perpustakaan Digital.

## 1. Penjelasan Singkat & Konsep Dasar

Setiap kali browser meminta halaman atau mengirim form, semua data tersebut dibungkus menjadi satu objek `Illuminate\Http\Request`, lalu disuntikkan ke controller lewat dependency injection (metode yang kita pelajari di materi 14). Objek ini punya method bantuan yang aman, mudah dibaca, dan sudah teruji untuk:

- Membaca **query string** (`?kategori=Fiksi&halaman=2`).
- Membaca **input form** (`judul`, `pengarang`, `sampul`, dst).
- Mengetahui **informasi request** (URL, method HTTP, IP).
- Menangani **file upload**.
- Menjaga **old input** ketika validasi gagal (nilai form tidak hilang).

Hubungannya dengan materi lain: materi 13 memakai `$request->query('kategori')` untuk filter, materi 14 menunjukkan `$request` disuntikkan via method injection. Level 4 akan mengganti validasi inline dengan **Form Request** — tapi tetap membaca data lewat objek Request yang sama.

## 2. Fungsi & Kegunaan Utama dalam Laravel

- **Akses data HTTP dengan aman dan konsisten** — tidak peduli request berasal dari GET, POST, atau JSON API, objek Request menyeragamkan cara membacanya.
- **Hindari superglobals** — `$_GET`, `$_POST`, `$_FILES` masih tersedia di PHP, tapi memakainya di Laravel adalah anti-pattern: tidak teruji, tidak bersih, dan menyulitkan kode.
- **Nilai default & helper filter** — `->query('halaman', 1)` memberi nilai default; `->only(...)` dan `->except(...)` memfilter field yang diambil.
- **Mendukung old input** — saat validasi gagal, `old('judul')` mengembalikan nilai yang sebelumnya dikirim sehingga form tidak diketik ulang.
- **Memudahkan unit testing** — request bisa dibuat secara sintetis saat menulis test tanpa HTTP nyata.
- **Menjembatani ke validasi** — `$request->validate()` menjadi fondasi yang nanti digantikan Form Request.

## 3. Contoh Kode & Implementasi (Real-world Example)

### A. Query String — filter katalog

`?kategori=Fiksi&halaman=2` di URL:

```php
<?php

// app/Http/Controllers/BukuController.php
namespace App\Http\Controllers;

use App\Services\BukuFilter;
use Illuminate\Http\Request;
use Illuminate\View\View;

class BukuController extends Controller
{
    private BukuFilter $bukuFilter;

    public function __construct(BukuFilter $bukuFilter)
    {
        $this->bukuFilter = $bukuFilter;
    }

    // Method index: membaca filter dari query string.
    public function index(Request $request): View
    {
        // Ambil nilai query string, dengan default 'Semua' bila tidak ada.
        $kategori = $request->query('kategori', 'Semua');

        // Ambil halaman dengan default 1.
        $halaman = $request->query('halaman', 1);

        // Ambil semua query string sekaligus sebagai array.
        $semuaParameter = $request->query();

        // Kata kunci pencarian.
        $cari = $request->query('cari');

        // Serahkan logika filter ke service agar controller tetap tipis.
        $buku = $this->bukuFilter->terapkan($cari, $kategori);

        return view('buku.index', compact('buku', 'kategori', 'halaman', 'cari'));
    }
}
```

Contoh `BukuFilter`:

```php
<?php

// app/Services/BukuFilter.php
namespace App\Services;

class BukuFilter
{
    // Logika filter dipisah ke service. Nanti data diambil dari Eloquent.
    public function terapkan(?string $cari, ?string $kategori): array
    {
        $buku = $this->katalog();

        if ($kategori && $kategori !== 'Semua') {
            $buku = array_filter($buku, fn ($b) => $b['kategori'] === $kategori);
        }

        if ($cari) {
            $buku = array_filter($buku, fn ($b) =>
                str_contains(strtolower($b['judul']), strtolower($cari))
            );
        }

        return array_values($buku);
    }

    private function katalog(): array
    {
        return [
            ['id' => 1, 'judul' => 'Clean Code', 'kategori' => 'Teknologi', 'harga' => 250000],
            ['id' => 2, 'judul' => 'Laskar Pelangi', 'kategori' => 'Fiksi', 'harga' => 85000],
            ['id' => 3, 'judul' => 'Pemrograman Web', 'kategori' => 'Teknologi', 'harga' => 150000],
        ];
    }
}
```

### B. Cek keberadaan parameter

```php
// has(): true jika parameter ada (termasuk kosong).
if ($request->has('kategori')) {
    // kategori ada di query string
}

// filled(): true jika ada DAN tidak kosong.
if ($request->filled('kategori')) {
    // hanya terisi nilai non-kosong
}

// missing(): kebalikan has().
if ($request->missing('cari')) {
    // parameter cari tidak dikirim
}
```

Controller `store`:

```php
use Illuminate\Http\RedirectResponse;

public function store(Request $request): RedirectResponse
{
    // Validasi dasar; nanti dipindah ke Form Request di Level 4.
    $validated = $request->validate([
        'judul' => 'required|string|max:255',
        'pengarang' => 'required|string|max:255',
    ]);

    // input('judul'): ambil satu field dengan default bila kosong.
    $judul = $request->input('judul');
    $pengarang = $request->input('pengarang', 'Anonim'); // default 'Anonim'

    // only(): ambil hanya field tertentu.
    $dataBuku = $request->only(['judul', 'pengarang', 'kategori', 'harga']);

    // except(): ambil semua kecuali field tertentu (mis. _token).
    $dataTanpaToken = $request->except('_token');

    // all(): ambil semua input sekaligus (hati-hati, termasuk _token).
    $semuaInput = $request->all();

    // Nanti: Buku::create($validated);

    return redirect()->route('buku.index')->with('sukses', 'Buku berhasil ditambahkan');
}
```

### D. Informasi request

```php
public function info(Request $request): View
{
    // URL lengkap tanpa query string: http://localhost:8000/buku
    $url = $request->url();

    // Path saja: /buku
    $path = $request->path();

    // Method HTTP: GET / POST / PUT / DELETE
    $method = $request->method();

    // IP pengunjung (bisa null pada request lokal tertentu).
    $ip = $request->ip();

    // Apakah request mengharapkan respons JSON (mis. API)?
    $memintaJson = $request->expectsJson();

    return view('buku.info', compact('url', 'path', 'method', 'ip', 'memintaJson'));
}
```

### E. File upload

```php
public function uploadSampul(Request $request): RedirectResponse
{
    // Cek apakah file dengan nama 'sampul' ikut terkirim.
    if ($request->hasFile('sampul')) {
        $file = $request->file('sampul');

        // Validasi tipe dan ukuran.
        $validated = $request->validate([
            'sampul' => 'required|image|mimes:jpeg,png,webp|max:2048',
        ]);

        // Simpan ke storage/app/public/sampul dengan nama unik.
        $path = $file->store('sampul', 'public');

        // $path berisi: sampul/abc123_random.jpg
        // Nanti: $buku->sampul = $path; $buku->save();
    }

    return redirect()->route('buku.index')->with('sukses', 'Sampul berhasil diunggah');
}
```

### F. Old input saat validasi gagal

Saat `$request->validate()` gagal, Laravel otomatis me-redirect kembali dengan error dan **old input** tersimpan di session. Di Blade:

```blade
<input type="text" name="judul" value="{{ old('judul') }}" class="@error('judul') is-invalid @enderror">

@error('judul')
    <span class="pesan-error">{{ $message }}</span>
@enderror
```

`old('judul')` mengembalikan nilai yang sebelumnya diketik; `@error` menampilkan pesan error per field. Ini membuat form "menolak" dengan sopan tanpa menghapus isian pengguna.

## 4. Analogi Sederhana

Kembali ke restoran. **Request adalah slip pesanan dari pelayan.**

- Pelayan (Route) menulis pesanan tamu di slip: "kategori Fiksi", "halaman 2", "pakai sampul baru" — ini data HTTP request yang dibungkus objek `Request`.
- Koki (Controller) menerima slip itu sebagai `Request $request`. Koki membacanya untuk tahu apa yang diminta: `$request->query('kategori')` = "pesanan bilang kategori Fiksi", `$request->input('judul')` = "tamu menulis judul buku".
- Koki tidak perlu menebak-nebak atau bertanya ulang — semua informasi yang dikirim tamu sudah ada di slip. Dan koki TIDAK berlari ke dapur lain untuk mengintip meja tamu (tidak menyentuh `$_GET`/`$_POST` langsung).
- Kalau ada file, misalnya foto sampul, slip pesanan berisi lampiran: `$request->file('sampul')`.
- Kalau validasi gagal (misal judul kosong), koki mengembalikan slip itu beserta catatan "tolong isi judul" — ini old input: `old('judul')` menjaga tulisan tamu tidak hilang, dan `@error` menunjukkan catatan kokinya.

Kunci analoginya: koki hanya bekerja dengan slip resmi yang diserahkan sistem, bukan memotong jalur.

## 5. Kapan Harus Digunakan & Kasus Penggunaan (Use Cases)

- **Filter katalog buku** — membaca `?kategori=`, `?cari=`, `?halaman=` di method `index`.
- **Form tambah/ubah buku** — membaca `judul`, `pengarang`, `isbn`, `harga`, `stok` di method `store`/`update`.
- **Pencarian anggota / riwayat peminjaman** — query string `?q=nama` untuk mencari.
- **Upload sampul buku** — `hasFile` + `file` + validasi gambar.
- **Logging & audit** — mencatat `$request->ip()`, `$request->method()`, `$request->url()`.
- **API (nanti)** — `expectsJson()` untuk menentukan respons JSON vs HTML.
- **Menjaga UX saat validasi gagal** — kombinasi `old()` dan `@error` di Blade.

## 6. Poin-poin Penting & Best Practices

- **JANGAN pakai `$_GET`/`$_POST`/`$_FILES` langsung.** Selalu lewat objek `Request`. Ini aturan paling penting di materi ini.
- **Gunakan method yang tepat sesuai sumber data:**
  - Query string (GET) → `$request->query('kunci', 'default')`.
  - Input form (POST/PUT) → `$request->input('kunci', 'default')`.
  - Ambil beberapa field → `only(['a','b'])` atau `except(['_token'])`.
- **Berikan nilai default** pada `query()` dan `input()` untuk menghindari error "undefined key".
- **`filled()` lebih ketat dari `has()`** — gunakan `filled()` saat mengecek nilai yang harus non-kosong.
- **File: selalu cek `hasFile()` sebelum memakai `file()`**, lalu validasi tipe dan ukuran.
- **Kombinasikan `old()` + `@error` di Blade** supaya form ramah pengguna saat validasi gagal.
- **Jangan simpan `$request->all()` mentah ke database** — pakai `only()` atau validasi dulu untuk menghindari mass-assignment (akan dibahas di Level 3).
- **Type-hint `Request` di method** (method injection), bukan membuat instansinya manual.

## 7. Kesalahan Umum (Common Pitfalls & Anti-patterns)

- **Akses superglobal langsung.** `$_GET['kategori']` rawan error "undefined key" dan tidak mengikuti konvensi. Gunakan `$request->query('kategori', 'Semua')`.
- **`all()` yang tidak terkontrol.** `$request->all()` ikut membawa `_token`, `_method`, dan field yang tidak diinginkan. Pakai `only()` atau validasi, lalu simpan hasil validasi.
- **Salah memilih `has()` vs `filled()`.** `has('kategori')` bernilai true walaupun kategori dikirim kosong; kalau butuh nilai non-kosong, pakai `filled()`.
- **Lupa default value.** `$request->query('kategori')` mengembalikan `null` bila tidak dikirim; kalau langsung dipakai untuk `strtolower($x)` bisa error. Beri default.
- **`input()` untuk query string** atau sebaliknya. `$request->input('kategori')` tetap bisa membaca query string, tapi lebih eksplisit memakai `query()`. Konsisten itu penting.
- **File upload gagal diam-diam.** Form tanpa `enctype="multipart/form-data"` membuat upload tidak terkirim. Pastikan attribute itu ada di `<form>`.
- **Old input tidak muncul.** Jika redirect pakai `withErrors()` (dari validasi) — Laravel otomatis menyimpan old input, jadi `old()` biasanya langsung jalan. Kalau tidak muncul, pastikan field pakai `name` yang sama persis.
- **Troubleshooting umum:** `Call to a member function query() on null` berarti `$request` bukan instance `Request` — cek type-hint dan import `Illuminate\Http\Request` di controller.

## 8. Soal Latihan & Kunci Jawaban

### Tantangan

1. Pada method `index`, baca query string `kategori` (default `Semua`), `cari` (default null), dan `halaman` (default 1). Teruskan ketiganya ke view `buku.index`. Jelaskan perbedaan `has` vs `filled` untuk parameter `cari`.
2. Pada method `store`, ambil hanya field `judul`, `pengarang`, `harga` dari request, validasi `judul` required, dan jika ada file `sampul` validasi sebagai gambar lalu simpan ke storage `public`. Redirect ke `buku.index` dengan pesan sukses.

### Jawaban & Pembahasan

```php
<?php

// app/Http/Controllers/BukuController.php
namespace App\Http\Controllers;

use Illuminate\Http\Request;
use Illuminate\View\View;
use Illuminate\Http\RedirectResponse;

class BukuController extends Controller
{
    // Tantangan 1: baca query string dengan default yang aman.
    public function index(Request $request): View
    {
        $kategori = $request->query('kategori', 'Semua');
        $cari = $request->query('cari'); // default null bila tidak dikirim
        $halaman = $request->query('halaman', 1);

        // Perbedaan has vs filled:
        // has('cari')    -> true jika parameter 'cari' ada walaupun kosong.
        // filled('cari') -> true hanya jika ada DAN tidak kosong.
        $adaCari = $request->filled('cari');

        // Data sementara; nanti diganti BukuFilter/Eloquent.
        $buku = [
            ['id' => 1, 'judul' => 'Clean Code', 'kategori' => 'Teknologi', 'harga' => 250000],
            ['id' => 2, 'judul' => 'Laskar Pelangi', 'kategori' => 'Fiksi', 'harga' => 85000],
        ];

        return view('buku.index', compact('buku', 'kategori', 'cari', 'halaman', 'adaCari'));
    }

    // Tantangan 2: input terpilih + validasi + upload sampul.
    public function store(Request $request): RedirectResponse
    {
        // Validasi dasar; nanti dipindah ke Form Request (Level 4).
        $validated = $request->validate([
            'judul' => 'required|string|max:255',
            'harga' => 'required|numeric|min:0',
        ]);

        // only(): ambil hanya field yang dibutuhkan.
        $dataBuku = $request->only(['judul', 'pengarang', 'harga']);

        // Proses upload sampul bila ada.
        if ($request->hasFile('sampul')) {
            $request->validate([
                'sampul' => 'image|mimes:jpeg,png,webp|max:2048',
            ]);

            $path = $request->file('sampul')->store('sampul', 'public');
            $dataBuku['sampul'] = $path;
        }

        // Nanti: Buku::create($dataBuku);

        return redirect()->route('buku.index')->with('sukses', 'Buku berhasil ditambahkan');
    }
}
```

```blade
{{-- resources/views/buku/index.blade.php --}}
<form method="GET" action="{{ route('buku.index') }}">
    <input type="text" name="kategori" value="{{ $kategori }}">
    <input type="text" name="cari" value="{{ $cari ?? '' }}">
    <input type="number" name="halaman" value="{{ $halaman }}">
    <button type="submit">Filter</button>

@foreach ($buku as $b)
```

Penjelasan alur:

1. Browser membuka `GET /buku?kategori=Fiksi&cari=pelangi`. Laravel membuat objek `Request` dan menyuntikkannya ke `index`.
2. `query('kategori', 'Semua')` mengembalikan `Fiksi`; `query('cari')` mengembalikan `'pelangi'`; `query('halaman', 1)` mengembalikan default `1` karena `halaman` tidak dikirim.
3. `filled('cari')` bernilai `true` (ada dan terisi). Kalau URL hanya `?cari=` (kosong), `has('cari')` bernilai `true` tapi `filled('cari')` bernilai `false` — pilih sesuai kebutuhan logika.
4. Method `store` membaca form POST. `only(['judul','pengarang','harga'])` mencegah `_token` ikut tersimpan. Validasi menolak judul kosong dengan redirect otomatis + old input (`old('judul')` di Blade tetap terisi).
5. Jika file `sampul` ikut terkirim (form harus `enctype="multipart/form-data"`), ia divalidasi sebagai gambar lalu disimpan di `storage/app/public/sampul`; path hasil simpan ikut masuk `$dataBuku`.
6. Redirect ke daftar buku membawa flash `sukses`, sesuai pola PRG. Di Level 4, blok `$request->validate(...)` akan dipindah ke Form Request, tapi cara membaca data tetap sama.
