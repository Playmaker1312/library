# 40. Task Scheduling — Otomasi Tugas Berkala

Scheduler Laravel menggantikan pengelolaan cron yang berantakan di tiap server dengan satu titik konfigurasi berbasis PHP. Kamu mendefinisikan jadwal (pengingat peminjaman, hitung denda, backup database, cleanup log) langsung di kode, lalu cukup satu cron entry `schedule:run` — dan semuanya berjalan. Materi ini memakai pola Action (materi 35), berhubungan dengan queue (29) dan deployment (36).

## 1. Penjelasan Singkat & Konsep Dasar

Secara tradisional, tugas berkala (cron job) ditulis sebagai baris di `crontab` tiap server: `0 9 * * * /usr/bin/php /var/www/app/artisan perintah`. Masalahnya: jadwal tersebar, berbeda antar server (staging vs production), tidak ada mekanisme antrean jika sebelumnya gagal, dan sulit dites.

Laravel memusatkan semuanya. Di `routes/console.php`, kamu mendefinisikan jadwal dengan ekspresi yang mudah dibaca — `Schedule::command('perpustakaan:kirim-pengingat')->dailyAt('09:00')`. Lalu di server cukup satu baris cron: `* * * * * php artisan schedule:run`. Setiap menit, scheduler mengecek: "apakah ada tugas yang waktunya tiba?" Jika ya, jalankan.

Konsep kunci: **cron tetap jalan tiap menit, tapi tugas-tugasmu hanya dieksekusi saat jadwalnya cocok**. Semua definisi jadwal tersimpan di satu file PHP yang bisa di-versioning, dites, dan konsisten di semua environment.

## 2. Fungsi & Kegunaan Utama dalam Laravel

Masalah yang dipecahkan scheduler:
- **Satu entry point**: kamu tidak lagi menyebar cron di banyak file `crontab`; cukup satu baris.
- **Jadwal terbaca manusia**: `dailyAt('09:00')`, `weekly()`, `monthly()` jauh lebih jelas daripada `0 9 * * 1`.
- **Kontrol kegagalan**: `withoutOverlapping()` mencegah tugas yang sama berjalan dua kali; `onSuccess()`/`onFailure()` memberi reaksi atas hasil; `emailOutputOnFailure()` mengirim notifikasi saat error.
- **Testable**: jadwal bisa diuji dengan `Schedule::command(...)->daily()` lalu menjalankan `schedule:test` atau `schedule:run` secara manual.
- **Integrasi ekosistem**: bisa menjalankan artisan command, menjalankan closure PHP, memanggil queue job (materi 29), bahkan menjalankan script sistem (`exec`).

Untuk perpustakaan digital, ini mengotomatisasi pekerjaan rutin yang kalau dilakukan manual bisa terlewat: mengingatkan anggota soal buku yang jatuh tempo, menghitung denda keterlambatan, backup database tiap minggu, dan membersihkan log yang sudah tua.

## 3. Contoh Kode & Implementasi (Real-world Example)

Lokasi file standar:
- `app/Console/Commands/KirimPengingatPeminjaman.php` — artisan command kustom.
- `routes/console.php` — pendefinisian jadwal (Laravel 11).

### 3.1 Buat Artisan Command

```bash
php artisan make:command KirimPengingatPeminjaman
# menghasilkan app/Console/Commands/KirimPengingatPeminjaman.php
```

### 3.2 Isi Command (testable, memakai Action)

```php
<?php

namespace App\Console\Commands;

use App\Actions\Peminjaman\KirimPengingatAction;
use Illuminate\Console\Command;

class KirimPengingatPeminjaman extends Command
{
    // Signature inilah yang dipakai oleh scheduler & terminal
    protected $signature = 'perpustakaan:kirim-pengingat';

    protected $description = 'Kirim pengingat untuk peminjaman yang akan jatuh tempo';

    public function handle(KirimPengingatAction $action): int
    {
        // Logika ditaruh di Action agar bisa ditest unit
        // (command cukup jadi "pembungkus" yang tipis)
        $jumlah = $action->handle();

        $this->info("Pengingat terkirim untuk {$jumlah} peminjaman.");

        return self::SUCCESS;
    }
}
```

```php
// app/Actions/Peminjaman/KirimPengingatAction.php
// Logika bisnis di Action (materi 35) — mudah ditest tanpa menjalankan command
class KirimPengingatAction
{
    public function handle(): int
    {
        $peminjaman = Peminjaman::query()
            ->where('status', 'dipinjam')
            ->whereBetween('tanggal_kembali', [
                now()->addDay(),      // besok jatuh tempo
                now()->addDays(3),    // sampai 3 hari lagi
            ])
            ->get();

        foreach ($peminjaman as $item) {
            // Kirim notifikasi (lewat queue bila perlu, materi 29)
            $item->anggota->notify(new PengingatPeminjaman($item));
        }

        return $peminjaman->count();
    }
}
```

### 3.3 Definisikan Jadwal di routes/console.php (Laravel 11)

```php
<?php

use Illuminate\Support\Facades\Schedule;

// Pengingat: tiap hari pukul 09:00, kirim email bila gagal
Schedule::command('perpustakaan:kirim-pengingat')
    ->dailyAt('09:00')
    ->emailOutputOnFailure(config('mail.admin'));

// Hitung denda: tiap hari tengah malam, cegah tumpang tindih
Schedule::command('perpustakaan:hitung-denda')
    ->daily()
    ->withoutOverlapping();

// Backup database saja: tiap minggu pukul 02:00, bereaksi atas hasil
Schedule::command('backup:run', ['--only-db'])
    ->weekly()
    ->at('02:00')
    ->onSuccess(fn () => logger('Backup database berhasil.'))
    ->onFailure(fn () => logger('Backup database GAGAL!'));

// Cleanup log: tiap bulan
Schedule::command('perpustakaan:cleanup-log')
    ->monthly()
    ->onFailure(fn () => logger('Cleanup log gagal.'));
```

### 3.4 Jalankan di Server

```bash
# Opsi A — Cron entry standar (satu-satunya baris yang kamu butuhkan)
# Buka: crontab -e
# Lalu tambahkan (setiap menit, jadwal lain diatur oleh scheduler Laravel):
* * * * * cd /var/www/perpustakaan && php artisan schedule:run >> /dev/null 2>&1

# Opsi B — Tanpa cron, pakai schedule:work (untuk dev / via Supervisor)
php artisan schedule:work
```

### 3.5 Pengujian

```bash
# Lihat daftar tugas yang terjadwal + waktu eksekusi berikutnya
php artisan schedule:list

# Test interaktif: pilih tugas mana yang mau dijalankan sekarang
php artisan schedule:test

# Jalankan semua tugas yang sudah waktunya (simulasi cron)
php artisan schedule:run
```

## 4. Analogi Sederhana

Bayangkan Task Scheduling sebagai **jadwal shift dan timer dapur otomatis** di restoran. Restoran punya oven dan timer yang berjalan sendiri — tanpa harus ada staf yang mengingat manual:
- **09:00** timer mengingatkan: "ada peminjaman buku yang jatuh tempo besok, kirim pesan ke anggotanya" (pengingat otomatis).
- **00:00** timer menghitung otomatis: "hitung denda untuk semua peminjaman yang telat" (denda otomatis).
- **Minggu 02:00** timer melakukan "foto ulang isi kulkas/ruang penyimpanan" (backup database).
- **Awal bulan** timer membersihkan "sisa bahan yang kadaluarsa" (cleanup log).

Koki (developer) tidak perlu selalu mengingat kapan harus mengerjakan hal rutin — timer yang menjalankannya. Dan semua timer itu diatur dari satu papan kontrol (file `routes/console.php`), bukan tersebar di catatan tempel (crontab) yang mudah terlupa.

## 5. Kapan Harus Digunakan & Kasus Penggunaan (Use Cases)

| Situasi | Rekomendasi | Alasan |
|---|---|---|
| Tugas berulang per jam/hari/minggu/bulan (pengingat, denda, backup, cleanup) | **Scheduler Laravel** | Satu definisi PHP, konsisten antar server, mudah dites |
| Tugas di beberapa server dengan environment berbeda | **Scheduler Laravel** | Kode sama, cron cuma satu baris di tiap server |
| Tugas dengan dependency antar-jadwal (backup setelah data stabil) | **Scheduler Laravel** | Bisa `onSuccess()`/`onFailure()` untuk chaining reaksi |
| Hanya 1-2 cron sederhana yang tidak butuh kontrol | Cron manual masih oke | Tidak perlu menambah kompleksitas; tapi tetap lebih rapi pakai scheduler |
| Tugas berat dan lama | **Scheduler + Queue (29)** | Kirim task ke queue agar scheduler tidak tersangkut; kombinasikan `withoutOverlapping()` |

**Kapan jangan pakai scheduler**: untuk tugas yang butuh eksekusi *pasti* sekali saja (misal: kirim email saat event terjadi) — itu urusan queue/listener (event), bukan scheduler. Scheduler untuk pekerjaan *berkala*, bukan *trigger real-time*.

## 6. Poin-poin Penting & Best Practices

- **Jadwal di `routes/console.php`** (Laravel 11+): gunakan `Schedule` facade. Format: `Schedule::command('nama:command')->[frekuensi]()`.
- **Buat command dengan `make:command`**: signature seperti `perpustakaan:kirim-pengingat`, dan isi logika di Action/Service (materi 35) agar **command tetap tipis dan bisa ditest**.
- **Frekuensi umum**: `->dailyAt('09:00')`, `->daily()`, `->weekly()->at('02:00')`, `->monthly()`, `->everyMinute()`, `->everyThirtyMinutes()`, `->hourly()`.
- **`withoutOverlapping()`**: WAJIB untuk tugas yang bisa berjalan lama (hitung denda, backup) agar tidak ada eksekusi ganda saat task sebelumnya masih berjalan.
- **Reaksi hasil**: `->onSuccess()`, `->onFailure()`, `->emailOutputOnFailure(config('mail.admin'))` untuk notifikasi; `->sendOutputTo(...)` untuk menyimpan log output.
- **Jalankan di server**: daftarkan satu cron `* * * * * cd /var/www/perpustakaan && php artisan schedule:run >> /dev/null 2>&1`, atau `schedule:work` untuk dev / via Supervisor di produksi. Pastikan koneksi queue & cache jalan bila task memakainya.
- **Pengujian**: `php artisan schedule:list`, `schedule:test` (pilih interaktif), dan `schedule:run`.
- **Time zone**: set `APP_TIMEZONE` dengan benar; gunakan `->timezone('Asia/Jakarta')` bila butuh zona spesifik.
- **Kaitkan deployment (36)**: jangan lupa menjalankan `php artisan migrate` dan membangun ulang asset; scheduler butuh worker `schedule:run` selalu aktif, jadi pastikan di-cover oleh process manager di server.
- **Kaitkan queue (29)**: untuk tugas berat, dispatch ke queue dari dalam Action agar scheduler tidak memblokir; kombinasikan dengan `withoutOverlapping()`.

## 7. Kesalahan Umum (Common Pitfalls & Anti-patterns)

| Gejala | Penyebab | Solusi |
|---|---|---|
| Tugas tidak pernah jalan | Cron belum didaftarkan, atau `schedule:work` tidak berjalan di supervisor | Pastikan cron `* * * * * php artisan schedule:run` ada di `crontab`; atau pastikan `schedule:work` jalan sebagai service |
| Tugas jalan ganda / tumpang tindih | Tidak memakai `withoutOverlapping()` pada tugas yang lama | Tambahkan `->withoutOverlapping()`; pertimbangkan `->onOneServer()` bila multi-server |
| Command error di produksi tapi tidak terlihat | Tidak ada notifikasi kegagalan | Pakai `->emailOutputOnFailure(...)` dan `->onFailure()` untuk log |
| Scheduler jalan tapi tugas dijalankan dua kali oleh dua server | Multi-server dengan cron sama | `->onOneServer()` (butuh shared cache, misal Redis) |
| Command tidak bisa ditest / susah di-debug | Logika ditulis langsung di `handle()` | Pindahkan logika ke Action/Service (materi 35) — command jadi pembungkus tipis |
| Jadwal memakai zona waktu yang salah | `APP_TIMEZONE` tidak diatur / salah | Set `->timezone('Asia/Jakarta')` bila perlu |
| `schedule:list` kosong | File `routes/console.php` tidak memuat `Schedule` dengan benar | Cek nama namespace/import `Illuminate\Support\Facades\Schedule` |
| Task berat bikin `schedule:run` lama | Scheduler melakukan pekerjaan berat secara sinkron | Dispatch ke queue (materi 29) dari dalam Action; jaga `schedule:run` tetap cepat |

**Troubleshooting**: kalau task tidak jalan, cek `php artisan schedule:list` dulu (apakah jadwalnya terdaftar?), lalu `php artisan schedule:test` untuk menjalankan manual, dan lihat `storage/logs/laravel.log`. Untuk cron di server Linux, pastikan path PHP benar (`which php`) dan direktori proyek bisa diakses user cron.

## 8. Soal Latihan & Kunci Jawaban

### Tantangan

1. Buat artisan command `perpustakaan:hitung-denda` yang menandai peminjaman terlambat (tanggal_kembali < hari ini dan status masih `dipinjam`), menambahkan denda 5000 per hari keterlambatan pada field `denda`, lalu menjadwalkannya tiap hari pukul 00:30 dengan `withoutOverlapping()` dan `emailOutputOnFailure(config('mail.admin'))`.
2. Tulis jadwal untuk perintah `backup:run --only-db` tiap minggu pukul 02:30 yang menulis output ke file log `storage/logs/backup.log`, dan jelaskan perbedaan `onSuccess` vs `emailOutputOnFailure`.

### Jawaban & Pembahasan

**Jawaban 1**

```bash
php artisan make:command HitungDenda
```

```php
// app/Console/Commands/HitungDenda.php
<?php

namespace App\Console\Commands;

use App\Actions\Peminjaman\HitungDendaAction;
use Illuminate\Console\Command;

class HitungDenda extends Command
{
    protected $signature = 'perpustakaan:hitung-denda';

    protected $description = 'Hitung denda untuk peminjaman yang terlambat';

    public function handle(HitungDendaAction $action): int
    {
        $jumlah = $action->handle();

        $this->info("Denda diperbarui untuk {$jumlah} peminjaman.");

        return self::SUCCESS;
    }
}
```

```php
// app/Actions/Peminjaman/HitungDendaAction.php
class HitungDendaAction
{
    public function handle(): int
    {
        $peminjaman = Peminjaman::query()
            ->where('status', 'dipinjam')
            ->where('tanggal_kembali', '<', now()->toDateString())
            ->get();

        foreach ($peminjaman as $item) {
            $hariTerlambat = now()->startOfDay()
                ->diffInDays($item->tanggal_kembali->startOfDay());

            $item->denda = $hariTerlambat * 5000;
            $item->save();
        }

        return $peminjaman->count();
    }
}
```

```php
// routes/console.php
Schedule::command('perpustakaan:hitung-denda')
    ->dailyAt('00:30')
    ->withoutOverlapping()
    ->emailOutputOnFailure(config('mail.admin'));
```

**Pembahasan**: Command hanya memanggil Action — logika (query peminjaman terlambat, hitung `diffInDays`, kalikan 5000, simpan) ada di `HitungDendaAction` sehingga bisa diuji unit tanpa menjalankan command. `dailyAt('00:30')` menjalankannya tiap hari jam 00:30; `withoutOverlapping()` mencegah eksekusi ganda kalau data banyak dan prosesnya lama; `emailOutputOnFailure()` mengirim output ke admin bila command berakhir dengan status gagal.

**Jawaban 2**

```php
// routes/console.php
Schedule::command('backup:run', ['--only-db'])
    ->weekly()
    ->at('02:30')
    ->sendOutputTo(storage_path('logs/backup.log'))
    ->onSuccess(fn () => logger('Backup mingguan berhasil.'))
    ->onFailure(fn () => logger('Backup mingguan GAGAL!'));
```

**Pembahasan**: `weekly()->at('02:30')` menjadwalkan tiap minggu pukul 02:30. `sendOutputTo()` menyimpan seluruh output command ke file `storage/logs/backup.log` — berguna untuk audit. Perbedaan penting: **`onSuccess`/`onFailure`** adalah closure yang kamu definisikan sendiri dan dijalankan saat command berhasil/gagal (cocok untuk logging internal, misal ke `logger()` atau metric). **`emailOutputOnFailure`** adalah shortcut bawaan yang mengirim isi output (email) hanya saat command gagal — berguna untuk notifikasi ke admin tanpa harus menulis kode email manual. Keduanya bisa dikombinasikan: `onFailure` untuk log internal, `emailOutputOnFailure` untuk notifikasi ke manusia.
