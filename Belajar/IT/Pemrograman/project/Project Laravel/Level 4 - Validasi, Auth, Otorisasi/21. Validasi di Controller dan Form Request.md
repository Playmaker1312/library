# 21. Validasi di Controller dan Form Request

Di Level 3 kita sudah berhasil menyimpan data ke database lewat Eloquent, tapi belum ada gerbang pengaman — pengguna bisa mengirim apa saja. Nah, di level ini kita pelajari cara memfilter data sebelum menyentuh model: validasi. Ilmu yang sama nanti juga dipakai saat kita bangun halaman login, jadi pahami baik-baik konsepnya sekarang.

## 1. Penjelasan Singkat & Konsep Dasar

Validasi adalah proses memeriksa data yang dikirim pengguna (dari form atau API) **sebelum** data itu digunakan atau disimpan ke database. Prinsipnya sederhana: jangan pernah percaya input pengguna, dan jangan pernah menyimpan data yang belum terverifikasi.

Di Level 3, `BukuController::store()` langsung menerima request lalu menyimpannya ke model. Itu berbahaya karena pengguna bisa mengirim judul kosong, ISBN asal, harga minus, bahkan file aneh. Sekarang kita sisipkan langkah validasi di tengah: `Request` masuk -> divalidasi -> kalau lolos baru disimpan ke `Buku` -> kalau gagal, kembalikan pengguna ke form dengan pesan error.

Konsep ini berkesinambungan dengan materi berikutnya (Auth). Saat login, data email dan password juga harus divalidasi (email wajib format email, password wajib ada). Jadi pemahaman di materi ini adalah fondasi.

Alur lengkap "Perpustakaan Digital" setelah materi ini:

```
Pengguna isi form tambah buku
        |
        v
Request masuk ke BukuController@store
        |
        v
VALIDASI (Request BukuRequest)
        | lolos                       | gagal
        v                             v
Simpan ke model Buku            Kembali ke form + pesan error
        |                             (old() & @error)
        v
Redirect ke index / show
```

## 2. Fungsi & Kegunaan Utama dalam Laravel

Kenapa validasi dibangun sebagai fitur first-class di Laravel, bukan diserahkan manual `if-else` di controller?

1. **Mencegah data invalid masuk database.** Bayangkan stok buku tertulis `-50` atau tahun terbit `1500`. Data kotor seperti ini merusak laporan, perhitungan, dan fitur lain yang bergantung padanya.
2. **Melindungi dari serangan keamanan.** Data tak tervalidasi bisa membawa injeksi SQL, XSS (script berbahaya yang tereksekusi saat ditampilkan), atau file berbahaya saat upload sampul. Validasi + penanganan input yang benar memblokir ini di pintu masuk.
3. **UX error handling yang rapi.** Laravel otomatis mengembalikan pengguna ke halaman form, mengisi ulang input yang benar (`old()`), dan menampilkan pesan error per field. Tanpa ini, kita harus tulis semua logika redirect dan error manual.
4. **Kode lebih bersih dan terpusat.** Semua aturan berada di satu tempat (Form Request), bukan berserakan di controller dengan banyak `if`. Lebih mudah dibaca dan diuji.

Intinya: validasi di Laravel bukan sekadar "pengecek if", tapi sistem lengkap yang menangani keamanan, UX, dan kebersihan kode sekaligus.

## 3. Contoh Kode & Implementasi (Real-world Example)

Kasus: menambah buku baru di admin panel perpustakaan. Field yang harus divalidasi: judul, pengarang, isbn, penerbit, tahun, harga, stok, kategori, deskripsi (opsional), dan sampul (gambar, opsional).

Kita akan lihat dua pendekatan: validasi inline di controller (untuk form sederhana) dan Form Request (untuk form kompleks seperti ini).

### 3a. Pendekatan 1: `$request->validate()` inline di controller

Untuk form yang simple, cukup di controller saja. Berlokasi di `app/Http/Controllers/BukuController.php`.

```php
<?php

namespace App\Http\Controllers;

use App\Models\Buku;
use Illuminate\Http\Request;

class BukuController extends Controller
{
    // Menyimpan buku baru (pendekatan validasi inline)
    public function store(Request $request)
    {
        $validated = $request->validate([
            'judul'      => ['required', 'string', 'max:255'],
            'pengarang'  => ['required', 'string', 'max:255'],
            'isbn'       => ['required', 'digits:13', 'unique:buku,isbn'],
            'penerbit'   => ['required', 'string', 'max:255'],
            'tahun'      => ['required', 'integer', 'min:1800', 'max:' . date('Y')],
            'harga'      => ['required', 'numeric', 'min:0'],
            'stok'       => ['required', 'integer', 'min:0'],
            'kategori'   => ['required', 'string', 'max:100'],
            'deskripsi'  => ['nullable', 'string'],
            'sampul'     => ['nullable', 'image', 'mimes:jpeg,png,jpg,webp', 'max:2048'],
        ]);

        // Data yang lolos validasi ada di $validated (bukan $request->all())
        $buku = Buku::create($validated);

        return redirect()->route('buku.index')
            ->with('success', 'Buku berhasil ditambahkan.');
    }
}
```

Catatan: gunakan `digits:13` untuk memastikan ISBN persis 13 digit angka, dan `unique:buku,isbn` agar dua buku tidak punya ISBN sama.

### 3b. Pendekatan 2: Form Request class (rekomendasi untuk form kompleks)

Buat class request dulu lewat artisan:

```
php artisan make:request StoreBukuRequest
```

File dihasilkan di `app/Http/Requests/StoreBukuRequest.php`:

```php
<?php

namespace App\Http\Requests;

use Illuminate\Foundation\Http\FormRequest;

class StoreBukuRequest extends FormRequest
{
    // Aturan izin: siapa yang boleh mengakses request ini
    public function authorize(): bool
    {
        // true = semua orang boleh (kita batasi otorisasi di middleware/custom)
        return true;
    }

    // Aturan validasi untuk menyimpan buku baru
    public function rules(): array
    {
        return [
            'judul'      => ['required', 'string', 'max:255'],
            'pengarang'  => ['required', 'string', 'max:255'],
            'isbn'       => ['required', 'digits:13', 'unique:buku,isbn'],
            'penerbit'   => ['required', 'string', 'max:255'],
            'tahun'      => ['required', 'integer', 'min:1800', 'max:' . date('Y')],
            'harga'      => ['required', 'numeric', 'min:0'],
            'stok'       => ['required', 'integer', 'min:0'],
            'kategori'   => ['required', 'string', 'max:100', 'in:Fiksi,Non-Fiksi,Referensi,Anak-Anak'],
            'deskripsi'  => ['nullable', 'string'],
            'sampul'     => ['nullable', 'image', 'mimes:jpeg,png,jpg,webp', 'max:2048'],
        ];
    }

    // Pesan error kustom dalam Bahasa Indonesia
    public function messages(): array
    {
        return [
            'judul.required'     => 'Judul buku wajib diisi.',
            'isbn.unique'        => 'ISBN ini sudah terdaftar di sistem.',
            'isbn.digits'        => 'ISBN harus tepat 13 digit angka.',
            'tahun.min'          => 'Tahun terbit tidak boleh sebelum 1800.',
            'harga.min'          => 'Harga tidak boleh minus.',
            'stok.integer'       => 'Stok harus berupa angka bulat.',
            'kategori.in'        => 'Kategori yang dipilih tidak valid.',
            'sampul.image'       => 'Sampul harus berupa file gambar.',
            'sampul.max'         => 'Ukuran sampul maksimal 2 MB.',
        ];
    }

    // Siapkan data sebelum validasi dijalankan
    protected function prepareForValidation(): void
    {
        // Contoh: trim semua string agar tidak ada spasi berlebih di awal/akhir
        $this->merge([
            'judul'     => trim($this->judul),
            'isbn'      => trim($this->isbn),
        ]);
    }
}
```

Controller sekarang jadi sangat bersih karena logika validasi pindah ke Form Request. Update `app/Http/Controllers/BukuController.php`:

```php
<?php

namespace App\Http\Controllers;

use App\Http\Requests\StoreBukuRequest;
use App\Models\Buku;

class BukuController extends Controller
{
    // Menyimpan buku baru (menggunakan Form Request)
    public function store(StoreBukuRequest $request)
    {
        // Validasi sudah otomatis dijalankan sebelum method ini dieksekusi.
        // Di sini hanya tinggal simpan data yang sudah lolos validasi.
        $buku = Buku::create($request->validated());

        return redirect()->route('buku.index')
            ->with('success', 'Buku berhasil ditambahkan.');
    }
}
```

Jika validasi gagal, Laravel otomatis melempar `ValidationException`, redirect kembali ke halaman sebelumnya (form), dan menyimpan error di session. `$request->validated()` hanya mengembalikan field yang lolos validasi.

- `old('judul')` mengisi ulang nilai input yang sudah dikirim saat validasi gagal, jadi pengguna tidak perlu mengetik ulang.

## 4. Analogi Sederhana

Bayangkan restoran. Ada dapur (backend), koki (Controller), dan slip pesanan dari pelanggan (Request dari form).

**Validasi adalah koki yang memeriksa slip pesanan sebelum mulai memasak.** Koki tidak langsung menyalakan kompor begitu slip diterima. Dia baca dulu: "Telur Mata Sapi, dua piring, minus saus" — eh, minus saus apa maksudnya? Slip aneh. Slip itu langsung dikembalikan ke pelayan (redirect kembali ke form) untuk diperbaiki. Pelanggan tidak akan dimasakkan sampai order-nya valid.

- `$request->validate()` adalah **cek cepat di meja dapur**: "stok bukunya angka, harga bukan huruf" — cukup untuk hal sederhana, ditulis langsung di tempat.
- **Form Request adalah departemen QC terpisah** yang punya SOP pengecekan lengkap (rules, pesan error khusus, persiapan data). Untuk order yang kompleks, dapur tidak perlu pusing memikirkan detail — cukup serahkan slip, QC yang urus.

Kokinya tetap `BukuController@store`. Perbedaannya hanya di mana dan bagaimana slip diperiksa sebelum bahan (data) masuk ke panci (model `Buku`).

## 5. Kapan Harus Digunakan & Kasus Penggunaan (Use Cases)

| Situasi | Pilihan |
|---------|---------|
| Form sederhana 1-3 field | `$request->validate()` inline di controller |
| Form kompleks (banyak field, banyak aturan, dipakai ulang) | Form Request class |
| Store dan Update dengan aturan mirip | Dua Form Request terpisah: `StoreBukuRequest` & `UpdateBukuRequest` |
| Validasi saat update | `unique` harus di-ignore pada record yang sedang diedit |
| API / JSON | Tidak perlu perubahan apa pun, Laravel otomatis balas `422 Unprocessable Entity` berformat JSON |

**Perbedaan unik pada update:** saat membuat buku baru, rule `unique:buku,isbn` memastikan ISBN belum dipakai siapa pun. Tapi saat meng-edit buku yang sama tanpa mengubah ISBN, validasi akan gagal karena record itu sendiri yang punya ISBN tersebut. Solusinya:

```php
use Illuminate\Validation\Rule;

public function rules(): array
{
    return [
        // Edit tanpa mengubah ISBN -> masih lolos karena record ini di-ignore
        'isbn' => [
            'required',
            'digits:13',
            Rule::unique('buku', 'isbn')->ignore($this->route('buku')),
        ],
    ];
}
```

`ignore($this->route('buku'))` memberitahu Laravel: "jangan anggap record dengan id ini sebagai pelanggar".

**Validasi API:** jika request datang dengan header `Accept: application/json` (atau dari frontend JS), Laravel tidak redirect ke form, melainkan mengembalikan respon JSON `422` beserta daftar error:

```json
{
  "message": "The judul field is required.",
  "errors": {
    "judul": ["The judul field is required."],
    "isbn": ["ISBN ini sudah terdaftar di sistem."]
  }
}
```

## 6. Poin-poin Penting & Best Practices

- **Validasi di lapisan Request, bukan menumpuk di controller.** Untuk form kompleks, gunakan Form Request. Controller tetap ramping dan fokus pada logika bisnis.
- **Jangan pernah trust input pengguna.** Semua data yang masuk harus melewati validasi. Prinsip ini menyelamatkan dari data kotor dan serangan.
- **Gunakan `$request->validated()` (atau `$validated`), bukan `$request->all()`.** `validated()` hanya berisi field yang lolos validasi, sehingga mencegah mass-assignment field tersembunyi yang tidak seharusnya dikirim.
- **Ikuti konvensi penamaan**: `StoreBukuRequest` untuk create, `UpdateBukuRequest` untuk update. Laravel dan tim akan langsung paham.
- **Gunakan array rules, bukan string**, untuk rule yang kompleks: `['required', 'string', 'max:255']` lebih terbaca dan mudah ditambahkan kondisi.
- **Sediakan `messages()` kustom** dalam Bahasa Indonesia agar error user-friendly.
- **Gunakan `php artisan make:request`** agar file langsung ter-generate dengan struktur `authorize()` dan `rules()`.
- **Di Blade, selalu pakai `old()` dan `@error()`** agar pengalaman pengguna tidak buruk saat validasi gagal — jangan sampai form kosong lagi setelah error.
- **Gunakan `prepareForValidation()`** untuk membersihkan/menormalkan data (trim, uppercase) sebelum aturan dijalankan.

## 7. Kesalahan Umum (Common Pitfalls & Anti-patterns)

1. **Lupa `@csrf` -> error 419 Page Expired.** Form POST tanpa `@csrf` akan ditolak Laravel karena gagal verifikasi token CSRF. Solusi: selalu tambahkan `@csrf` tepat setelah tag `<form>`.
2. **Validasi inline yang membengkak.** Controller jadi ratusan baris karena semua `if` dan rule ditulis manual. Solusi: pindahkan ke Form Request.
3. **Tidak pakai `$validated` lalu mass-assignment.** Mengirim `$request->all()` ke `Buku::create()` bisa memasukkan field tak diinginkan (misal `is_admin`) jika tidak ada `$fillable` yang ketat. Selalu pakai `$request->validated()`.
4. **Rule `unique` error saat update.** Karena record yang sama ikut dihitung sebagai duplikat. Solusi: `Rule::unique('buku', 'isbn')->ignore($id)`.
5. **Lupa `nullable` untuk field opsional.** Field deskripsi atau sampul yang dikosongkan akan gagal validasi kalau tidak ditandai `nullable`. Tanpa `nullable`, field kosong dianggap gagal `required`? Tidak — malah error pada rule lain. Pastikan field opsional selalu punya `nullable`.
6. **Rule `in:` tidak sync dengan data.** Jika kategorinya berubah di database/list, rule `in:Fiksi,Non-Fiksi,...` di Form Request bisa menolak nilai baru. Solusi: sinkronkan rule dengan data master, atau pakai Rule yang diambil dari database.
7. **Error validasi tidak tampil.** Sering karena nama field di `@error('judul')` tidak cocok dengan `name="judul"` di input, atau pesan error disimpan tapi halaman tidak membaca session. Troubleshoot: cek konsol browser, pastikan redirect kembali ke view yang sama, dan pastikan `@error` menggunakan nama field persis seperti `name` di input.

## 8. Soal Latihan & Kunci Jawaban

### Tantangan

**Soal 1: UpdateBukuRequest dengan unique ignore.**
Buat Form Request `UpdateBukuRequest` untuk meng-edit buku yang sudah ada. Rule ISBN harus tetap `required`, `digits:13`, dan `unique` pada tabel `buku` — tapi meng-ignore record yang sedang diedit (diambil dari route parameter). Sisanya sama dengan `StoreBukuRequest` (judul, pengarang, penerbit, tahun, harga, stok, kategori, deskripsi opsional, sampul opsional).

**Soal 2: Validasi form peminjaman.**
Buat validasi inline di controller `PeminjamanController@store` untuk field: `anggota_id` (required, harus ada di tabel `anggota`), `buku_id` (required, harus ada di tabel `buku`), `tanggal_pinjam` (required, format tanggal), dan `tanggal_kembali` (nullable, format tanggal, dan harus setelah tanggal_pinjam).

### Jawaban & Pembahasan

**Jawaban Soal 1:**

Jalankan `php artisan make:request UpdateBukuRequest`, lalu isi `app/Http/Requests/UpdateBukuRequest.php`:

```php
<?php

namespace App\Http\Requests;

use Illuminate\Foundation\Http\FormRequest;
use Illuminate\Validation\Rule;

class UpdateBukuRequest extends FormRequest
{
    public function authorize(): bool
    {
        return true;
    }

    public function rules(): array
    {
        return [
            'judul'      => ['required', 'string', 'max:255'],
            'pengarang'  => ['required', 'string', 'max:255'],
            'isbn'       => [
                'required',
                'digits:13',
                // ignore record dengan id dari route (misal /buku/{buku})
                Rule::unique('buku', 'isbn')->ignore($this->route('buku')),
            ],
            'penerbit'   => ['required', 'string', 'max:255'],
            'tahun'      => ['required', 'integer', 'min:1800', 'max:' . date('Y')],
            'harga'      => ['required', 'numeric', 'min:0'],
            'stok'       => ['required', 'integer', 'min:0'],
            'kategori'   => ['required', 'string', 'max:100'],
            'deskripsi'  => ['nullable', 'string'],
            'sampul'     => ['nullable', 'image', 'mimes:jpeg,png,jpg,webp', 'max:2048'],
        ];
    }
}
```

Lalu di controller update:

```php
public function update(UpdateBukuRequest $request, Buku $buku)
{
    // Validasi otomatis dijalankan; rule unique meng-ignore $buku yang sedang diedit
    $buku->update($request->validated());

    return redirect()->route('buku.index')
        ->with('success', 'Buku berhasil diperbarui.');
}
```

Pembahasan alur: Laravel menyuntikkan `UpdateBukuRequest` sebagai dependency, sehingga validasi dieksekusi sebelum method `update` berjalan. `$this->route('buku')` mengambil nilai parameter rute (id buku), lalu `Rule::unique()->ignore()` mengecualikan record tersebut dari pemeriksaan duplikat ISBN. Jika ISBN diubah ke milik buku lain, validasi tetap menolak.

**Jawaban Soal 2:**

Validasi inline di `PeminjamanController@store`:

```php
<?php

namespace App\Http\Controllers;

use App\Models\Peminjaman;
use Illuminate\Http\Request;

class PeminjamanController extends Controller
{
    public function store(Request $request)
    {
        $validated = $request->validate([
            'anggota_id'      => ['required', 'integer', 'exists:anggota,id'],
            'buku_id'         => ['required', 'integer', 'exists:buku,id'],
            'tanggal_pinjam'  => ['required', 'date', 'before_or_equal:today'],
            'tanggal_kembali' => ['nullable', 'date', 'after:tanggal_pinjam'],
        ]);

        $peminjaman = Peminjaman::create($validated);

        return redirect()->route('peminjaman.index')
            ->with('success', 'Peminjaman berhasil dicatat.');
    }
}
```

Pembahasan alur:

- `exists:anggota,id` memastikan id anggota benar-benar ada di tabel `anggota`, begitu pula `exists:buku,id` untuk buku. Ini mencegah referensi ke data yang tidak ada (foreign key valid).
- `date` memastikan nilai berupa tanggal yang valid; `before_or_equal:today` mencegah tanggal pinjam di masa depan.
- `after:tanggal_pinjam` memastikan tanggal kembali lebih lambat dari tanggal pinjam. Aturan komparasi antar-field seperti ini hanya bisa berfungsi jika memakai array rules.
- Semua data yang masuk ke `Peminjaman::create()` sudah pasti lolos validasi, sehingga data di tabel `peminjaman` bersih dari nilai invalid.
