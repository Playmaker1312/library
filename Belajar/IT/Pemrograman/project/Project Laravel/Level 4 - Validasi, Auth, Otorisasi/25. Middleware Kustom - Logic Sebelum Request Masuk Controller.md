# 25. Middleware Kustom — Logic Sebelum Request Masuk Controller

Kalau Policy (materi 24) mengatur "siapa boleh melakukan apa pada resource", Middleware adalah **gerbang yang dilewati setiap request sebelum sampai ke controller**. Dengan middleware kustom, kamu bisa menyisipkan logic apa pun — cek status anggota, batasi role, catat log aktivitas — di satu titik terpusat, tanpa menyebar di tiap controller. Ini juga jembatan menuju Queue di Level 5, karena middleware bisa di-queue untuk diproses asinkron.

## 1. Penjelasan Singkat & Konsep Dasar

**Middleware** adalah lapisan filter yang berjalan dalam **HTTP pipeline**. Bayangkan request masuk seperti melewati serangkaian pintu sebelum akhirnya sampai ke controller. Setiap middleware bisa:

- Memeriksa sesuatu (identitas, status, header).
- Mengubah request.
- Menolak request (redirect / abort).
- Meneruskan ke middleware berikutnya / controller dengan `return $next($request)`.

Di Laravel, middleware adalah class dengan satu method `handle(Request $request, Closure $next)` yang selalu mengembalikan `$next($request)` jika lolos.

```php
// Alur HTTP pipeline
//
// Request -> [auth] -> [anggota.aktif] -> [log] -> Controller
//            ^tolak          ^tolak       ^catat
//            redirect 403    redirect 403
```

Materi ini melanjutkan Auth (23) dan Policy (24): auth memverifikasi identitas, policy memverifikasi izin per resource, middleware menjadi gerbang berlapis sebelum semua itu dieksekusi di controller. Ke depan (Level 5), middleware seperti `LogAktivitas` bisa dikirim ke Queue agar tidak memperlambat response.

## 2. Fungsi & Kegunaan Utama dalam Laravel

Tanpa middleware, logic "cek apakah anggota masih aktif" harus ditulis ulang di setiap controller method. Middleware menyelesaikannya dengan **memusatkan logic pra-request di satu class yang terpasang ke banyak route sekaligus**.

Fungsi utama:

- **Menolak akses lebih awal**: kalau user tidak layak, tolak sebelum controller jalan — hemat resource dan rapi.
- **Memusatkan cross-cutting concern**: logging, autentikasi, batasan rate, header security — sekali tulis, dipakai banyak route.
- **Bisa menerima parameter**: `CekRole('admin')` untuk role berbeda tanpa bikin class baru.
- **Global vs route middleware**: global jalan di semua request, route middleware hanya di route tertentu.
- **Dapat di-queue** (Level 5): middleware berat bisa diproses asinkron tanpa mengganggu kecepatan response.

## 3. Contoh Kode & Implementasi (Real-world Example)

Lokasi standar: `app/Http/Middleware/`

Buat middleware dengan artisan:

```bash
php artisan make:middleware CekStatusAnggota
```

**Contoh 1: `CekStatusAnggota` — logout + redirect jika status tidak aktif**

```php
<?php

namespace App\Http\Middleware;

use Closure;
use Illuminate\Http\Request;
use Symfony\Component\HttpFoundation\Response;

class CekStatusAnggota
{
    /**
     * Hanya izinkan user dengan status 'aktif' masuk.
     * Kalau tidak, logout dan arahkan ke halaman login.
     */
    public function handle(Request $request, Closure $next): Response
    {
        if (auth()->check() && auth()->user()->status !== 'aktif') {
            auth()->logout(); // putuskan sesi

            return redirect()->route('login')
                ->with('error', 'Akun kamu tidak aktif. Hubungi pustakawan.');
        }

        return $next($request);
    }
}
```

**Contoh 2: `CekRole` — dengan parameter `$role`**

```php
<?php

namespace App\Http\Middleware;

use Closure;
use Illuminate\Http\Request;
use Symfony\Component\HttpFoundation\Response;

class CekRole
{
    /**
     * Menerima parameter role: ->middleware('role:admin,pustakawan')
     */
    public function handle(Request $request, Closure $next, string ...$roles): Response
    {
        if (! $request->user()) {
            return redirect()->route('login');
        }

        if (! in_array($request->user()->role, $roles)) {
            abort(403, 'Kamu tidak punya akses ke halaman ini.');
        }

        return $next($request);
    }
}
```

**Contoh 3: `LogAktivitas` — logging tanpa mengganggu response**

```php
<?php

namespace App\Http\Middleware;

use Closure;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Log;
use Symfony\Component\HttpFoundation\Response;

class LogAktivitas
{
    /**
     * Catat setiap request yang masuk ke log.
     */
    public function handle(Request $request, Closure $next): Response
    {
        Log::info('Aktivitas user', [
            'user'  => $request->user()?->email,
            'route' => $request->path(),
            'method'=> $request->method(),
        ]);

        return $next($request);
    }
}
```

**Registrasi di Laravel 11** — file `bootstrap/app.php`:

```php
<?php

use App\Http\Middleware\CekRole;
use App\Http\Middleware\CekStatusAnggota;
use App\Http\Middleware\LogAktivitas;
use Illuminate\Foundation\Application;
use Illuminate\Foundation\Configuration\Exceptions;
use Illuminate\Foundation\Configuration\Middleware;

return Application::configure(basePath: dirname(__DIR__))
    ->withRouting(
        web: __DIR__.'/../routes/web.php',
        commands: __DIR__.'/../routes/console.php',
        health: '/up',
    )
    ->withMiddleware(function (Middleware $middleware) {
        // Alias: panggil lewat nama pendek di route
        $middleware->alias([
            'role'          => CekRole::class,
            'anggota.aktif' => CekStatusAnggota::class,
            'log.aktivitas' => LogAktivitas::class,
        ]);

        // Global middleware: jalan di SEMUA request
        // $middleware->append(LogAktivitas::class);
    })
    ->withExceptions(function (Exceptions $exceptions) {
        //
    })->create();
```

**Penggunaan di routes** (`routes/web.php`):

```php
use App\Http\Controllers\PeminjamanController;

// Route middleware via alias — urutan penting: auth dulu, baru cek aktif
Route::middleware(['auth', 'anggota.aktif'])
    ->group(function () {
        Route::get('/peminjaman', [PeminjamanController::class, 'index']);
        Route::post('/peminjaman', [PeminjamanController::class, 'store']);
    });

// Contoh dengan parameter role
Route::middleware(['auth', 'role:admin,pustakawan'])
    ->group(function () {
        Route::get('/dashboard', [DashboardController::class, 'index']);
    });
```

**Global vs route middleware:**

- **Global middleware**: didaftarkan via `$middleware->append(...)` — berjalan di **setiap** request. Cocok untuk logging global atau header security. Berhati-hatilah karena memengaruhi seluruh aplikasi.
- **Route middleware**: didaftarkan via `$middleware->alias([...])` lalu dipakai per route/grup. Cocok untuk cek yang spesifik (status anggota, role).

## 4. Analogi Sederhana

Bayangkan Perpustakaan Digital ini seperti sebuah **restoran** dengan dapur di belakang:

- **Auth (23)** = petugas di pintu masuk yang memeriksa KTP: "siapa kamu, punya kartu member?". Dia hanya memverifikasi **identitas**.
- **Policy (24)** = **level akses restoran**: tamu boleh lihat menu di ruang tamu, koki boleh masuk dapur, manajer kelola karyawan, pemilik restoran boleh apa saja. Ini aturan "siapa boleh melakukan apa" **per resource**.
- **Middleware (25)** = **satpam/petugas di pintu dapur**. Sebelum siapa pun benar-benar mulai bekerja di dapur, satpam memeriksa identitas dan status dulu: "seragam dapur lengkap? kartu akses masih aktif? nama kamu di daftar koki?". Kalau tidak memenuhi syarat, **langsung ditolak sebelum kerja dapur dimulai** — tidak perlu menunggu masakan (controller) dikerjakan dulu baru ketahuan tidak boleh.

Ringkasnya: **auth** = siapa kamu, **authorization (policy)** = izinmu atas resource tertentu, **middleware** = gerbang yang harus kamu lewati sebelum masuk melakukan pekerjaan.

## 5. Kapan Harus Digunakan & Kasus Penggunaan (Use Cases)

| Situasi | Solusi |
|---|---|
| Halaman admin hanya boleh diakses role tertentu | Middleware `role:admin` di route grup |
| Anggota yang statusnya non-aktif tidak boleh meminjam buku | Middleware `anggota.aktif` |
| Mencatat setiap aktivitas login/peminjaman | Middleware `log.aktivitas` (atau kirim ke queue di Level 5) |
| Cek izin spesifik per resource sebelum controller jalan | `Route::middleware('can:delete,buku')` atau kombinasikan dengan policy |
| Proteksi semua route dengan header security | Global middleware via `$middleware->append(...)` |

**Panduan umum:**

- **Middleware** untuk **gerbang berbasis request/route**: cek status, role, maintenance mode, throttling.
- **Policy** untuk **otorisasi berbasis resource**: apakah user boleh update buku ini.
- **Keduanya bersama**: `Route::middleware(['auth', 'role:admin'])` membatasi siapa yang boleh masuk halaman, lalu `$this->authorize('delete', $buku)` di controller membatasi aksi spesifik.
- **Urutan penting**: pasang middleware yang paling dulu menghemat waktu di depan. Contoh: `auth` dulu sebelum `role:admin` — jangan cek role pada user yang belum login.

## 6. Poin-poin Penting & Best Practices

- **Buat via artisan**: `php artisan make:middleware NamaMiddleware`.
- **Struktur standar**: method `handle(Request $request, Closure $next)` yang mengembalikan `Response`. Lolos = `return $next($request)`. Tolak = `abort()` / `redirect()`.
- **Registrasi Laravel 11**: di `bootstrap/app.php` → `withMiddleware(function (Middleware $middleware) { ... })`.
- **Alias middleware**: daftarkan dengan `$middleware->alias(['nama' => Class::class])` supaya route bisa memakai nama pendek (`middleware('anggota.aktif')`).
- **Global vs route middleware**: global (`$middleware->append(...)`) untuk semua request; route (via alias) untuk kebutuhan spesifik. Jangan berlebihan memakai global.
- **Terima parameter**: gunakan variadic `string ...$roles` agar satu class melayani banyak nilai (`role:admin,pustakawan`).
- **Perhatikan urutan**: middleware dieksekusi sesuai urutan terdaftar — pasang `auth` sebelum cek yang bergantung pada user yang login.
- **Jangan taruh business logic berat di middleware**: middleware untuk gerbang cepat, business logic di policy/action/service.
- **Ke arah Queue (Level 5)**: middleware seperti logging bisa diproses asinkron lewat queue job.

## 7. Kesalahan Umum (Common Pitfalls & Anti-patterns)

- **Middleware tidak terdaftar → "Class not found" / `Target class [x] does not exist`**: di Laravel 11 semua middleware yang dipakai di route **wajib** didaftarkan sebagai alias di `bootstrap/app.php`. Lupa mendaftarkan adalah penyebab paling umum.
- **Lupa menambahkan middleware ke route**: policy/controller jadi satu-satunya penjaga, dan gerbang tidak berfungsi. Cek dengan `php artisan route:list` apakah middleware sudah terpasang.
- **Urutan middleware salah**: `role:admin` dipasang sebelum `auth` → `$request->user()` null → error atau akses aneh. Selalu `auth` di depan.
- **Menulis ulang semua logika di middleware**: kalau middleware sudah menangani otorisasi, jangan menulis cek yang sama lagi di controller — pilih salah satu sebagai sumber kebenaran.
- **Menaruh business logic di middleware**: aturan denda, perhitungan stok, dsb. bukan tugas middleware. Letakkan di policy/action/service.
- **Tidak mengembalikan Response**: middleware yang lupa `return $next($request)` akan membuat request menggantung.
- **Troubleshooting**: cek `php artisan route:list` untuk melihat middleware per route; sementara tambahkan `dd($request->user()->role)` di dalam middleware untuk memverifikasi nilai; pastikan alias sudah terdaftar di `bootstrap/app.php`.

## 8. Soal Latihan & Kunci Jawaban

### Tantangan

1. Buat middleware `CekStatusAnggota` yang mengarahkan anggota dengan status `suspend` ke halaman login lengkap dengan pesan error, lalu daftarkan sebagai alias `anggota.aktif` di `bootstrap/app.php` dan pasang di route grup `/peminjaman`.
2. Buat middleware `CekRole` dengan parameter `role:admin,pustakawan`, lalu jelaskan urutan middleware yang benar saat dipasang bersama `auth` dan mengapa.

### Jawaban & Pembahasan

**Soal 1:**

```php
// app/Http/Middleware/CekStatusAnggota.php
<?php

namespace App\Http\Middleware;

use Closure;
use Illuminate\Http\Request;
use Symfony\Component\HttpFoundation\Response;

class CekStatusAnggota
{
    public function handle(Request $request, Closure $next): Response
    {
        if (auth()->check() && auth()->user()->status === 'suspend') {
            auth()->logout();

            return redirect()->route('login')
                ->withErrors(['email' => 'Akun kamu disuspend. Hubungi pustakawan.']);
        }

        return $next($request);
    }
}
```

```php
// bootstrap/app.php
->withMiddleware(function (Middleware $middleware) {
    $middleware->alias([
        'anggota.aktif' => CekStatusAnggota::class,
    ]);
})
```

```php
// routes/web.php
Route::middleware(['auth', 'anggota.aktif'])
    ->group(function () {
        Route::get('/peminjaman', [PeminjamanController::class, 'index']);
        Route::post('/peminjaman', [PeminjamanController::class, 'store']);
    });
```

**Alur:** Request menuju `/peminjaman` → middleware `auth` memastikan sudah login → middleware `anggota.aktif` mengecek status. Jika `suspend`, sesi dihentikan (`logout`) dan redirect ke `login` dengan error. Jika `aktif`, `$next($request)` meneruskan request ke controller.

**Soal 2:**

```php
// app/Http/Middleware/CekRole.php
public function handle(Request $request, Closure $next, string ...$roles): Response
{
    if (! $request->user()) {
        return redirect()->route('login');
    }

    if (! in_array($request->user()->role, $roles)) {
        abort(403, 'Kamu tidak punya akses ke halaman ini.');
    }

    return $next($request);
}
```

```php
// routes/web.php
Route::middleware(['auth', 'role:admin,pustakawan'])
    ->group(function () {
        Route::get('/dashboard', [DashboardController::class, 'index']);
    });
```

**Penjelasan urutan:** `auth` harus **lebih dulu** dari `role:...`. Alasannya, `CekRole` bergantung pada `$request->user()` yang baru tersedia setelah `auth` menjalankan login/session. Kalau `role` dipasang lebih dulu, middleware itu berjalan saat user belum terautentikasi → `$request->user()` bernilai `null` → langsung redirect ke login atau bahkan 403 yang salah. Urutan yang benar: identitas dulu (`auth`), baru izin (`role`).
