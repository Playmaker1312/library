# 23. Auth Manual — Memahami di Balik Layar

Setelah pakai Breeze di materi 22, sekarang kita bongkar rahasianya. Breeze itu sebenarnya tidak melakukan sihir — dia cuma menulis controller dan route yang logikanya persis seperti yang akan kita tulis manual di materi ini. Dengan memahami Auth manual, kamu tahu persis apa yang terjadi setiap kali user login, daftar, atau logout. Ilmu ini juga yang akan kamu butuhkan saat membatasi akses berdasarkan role di materi Policy & Middleware berikutnya.

## 1. Penjelasan Singkat & Konsep Dasar

Auth manual berarti kita menulis sendiri controller dan logika autentikasi, tanpa bantuan starter kit. Konsep intinya:

- **Auth facade & helper** — gerbang utama ke sistem autentikasi Laravel.
- **Session** — setelah login, Laravel menyimpan status login di session sehingga user "diingat" antar request.
- **Guard & Provider** — mekanisme Laravel untuk memilih "cara" autentikasi dan sumber data user.

Kaitan dengan roadmap:

- Materi 22 (Breeze) menghasilkan kode yang sama persis dengan yang kita tulis manual di sini.
- Materi 24-25 (Policy & Middleware) akan memakai info `Auth::user()` untuk memutuskan siapa boleh akses apa.

Inti materi ini: kamu tidak wajib menulis auth manual setiap proyek, tapi kamu WAJIB paham alurnya supaya bisa men-debug dan mengkustomisasi.

## 2. Fungsi & Kegunaan Utama dalam Laravel

Auth di Laravel menyelesaikan masalah-masalah ini:

1. **Verifikasi identitas** — `Auth::attempt` mencocokkan kredensial dengan database.
2. **Session management** — menyimpan status login dan melepaskannya saat logout.
3. **Hashing password** — password selalu di-hash sebelum disimpan, tidak pernah plaintext.
4. **Keamanan session** — regenerate session ID setelah login untuk cegah session fixation.
5. **Akses informasi user** — `Auth::user()` memberi akses cepat ke data user yang login di mana saja.
6. **Integrasi role & otorisasi** — dasar bagi materi Policy/Middleware berikutnya.

Untuk sistem perpustakaan: `Auth::attempt` mengesahkan anggota, dan `Auth::user()->role` akan dipakai nanti untuk menentukan apakah dia admin, pustakawan, atau anggota biasa.

## 3. Contoh Kode & Implementasi (Real-world Example)

### Login Manual Lengkap

```php
<?php

namespace App\Http\Controllers\Auth;

use App\Http\Controllers\Controller;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Auth;

class LoginController extends Controller
{
    // Tampilkan form login
    public function showLoginForm()
    {
        return view('auth.login');
    }

    // Proses login
    public function login(Request $request)
    {
        // 1. Validasi input (bukan sekadar form request manual)
        $credentials = $request->validate([
            'email'    => ['required', 'email'],
            'password' => ['required'],
        ]);

        // 2. Coba autentikasi.
        //    $remember -> user diingat lewat cookie, tetap login setelah browser ditutup
        if (Auth::attempt($credentials, $request->boolean('remember'))) {
            // 3. Regenerate session ID -> cegah session fixation
            $request->session()->regenerate();

            // 4. Arahkan ke halaman yang dituju user sebelum login
            return redirect()->intended('/dashboard');
        }

        // 5. Kredensial salah. Kembali ke form dengan pesan error
        return back()->withErrors([
            'email' => 'Email atau password salah.',
        ])->onlyInput('email');
    }

    // Logout
    public function logout(Request $request)
    {
        Auth::logout();

        // Bersihkan session + regenerate token CSRF
        $request->session()->invalidate();
        $request->session()->regenerateToken();

        return redirect('/');
    }
}
```

### Route untuk Login Manual

```php
// routes/web.php
Route::get('/login', [LoginController::class, 'showLoginForm'])
    ->name('login')
    ->middleware('guest');

Route::post('/login', [LoginController::class, 'login'])
    ->middleware('guest');

Route::post('/logout', [LoginController::class, 'logout'])
    ->middleware('auth');
```

### Registrasi Manual Lengkap

```php
<?php

namespace App\Http\Controllers\Auth;

use App\Http\Controllers\Controller;
use App\Models\User;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Auth;
use Illuminate\Support\Facades\Hash;

class RegisterController extends Controller
{
    // Tampilkan form registrasi
    public function showRegistrationForm()
    {
        return view('auth.register');
    }

    // Proses registrasi
    public function register(Request $request)
    {
        // Validasi data anggota baru
        $validated = $request->validate([
            'name'     => ['required', 'string', 'max:255'],
            'email'    => ['required', 'email', 'max:255', 'unique:users,email'],
            'password' => ['required', 'min:8', 'confirmed'],
        ]);

        // 1. Buat user. Password WAJIB di-hash — jangan pernah simpan plaintext
        $user = User::create([
            'name'     => $validated['name'],
            'email'    => $validated['email'],
            'password' => Hash::make($validated['password']),
            'role'     => 'anggota', // default role untuk member baru
        ]);

        // 2. Loginkan langsung setelah registrasi
        Auth::login($user);

        // 3. Regenerate session biar aman
        $request->session()->regenerate();

        // 4. Redirect ke dashboard
        return redirect()->intended('/dashboard');
    }
}
```

### Auth Facade vs Helper

Keduanya mengakses sistem yang sama, beda cara penulisannya:

```php
use Illuminate\Support\Facades\Auth;

// Memakai Facade (class)
$user = Auth::user();
$id   = Auth::id();

// Memakai helper global (lebih pendek)
$user = auth()->user();
$id   = auth()->id();
```

Method yang sering dipakai:

```php
Auth::attempt($credentials, $remember); // login, return true/false
Auth::user();                          // objek User yang sedang login (null jika belum)
Auth::id();                            // ID user yang login (null jika belum)
Auth::check();                         // true jika sudah login
Auth::guest();                         // true jika belum login (kebalikan check)
Auth::login($user);                    // login langsung tanpa cek kredensial
Auth::logout();                        // keluar
```

### Guard & Provider (config/auth.php)

```php
// config/auth.php

'guards' => [
    // Guard 'web' memakai session untuk menyimpan status login
    'web' => [
        'driver' => 'session',
        'provider' => 'users',
    ],

    // Guard 'api' memakai token (biasanya lewat Sanctum/Passport)
    'api' => [
        'driver' => 'token',
        'provider' => 'users',
        'hash' => false,
    ],
],

'providers' => [
    // Provider 'users' = model yang menyimpan data user
    'users' => [
        'driver' => 'eloquent',
        'model' => App\Models\User::class,
    ],
],
```

Intinya: **guard** menentukan cara login (session atau token), **provider** menentukan sumber data user (model Eloquent mana).

### `redirect()->intended()`

Setelah login, user yang mencoba buka halaman terproteksi akan dicegat middleware `auth` dan diarahkan ke halaman login. `redirect()->intended()` mengirim mereka kembali ke halaman yang tadinya dituju, bukan selalu ke dashboard:

```php
// Setelah login sukses
return redirect()->intended('/dashboard');
// Jika user tadi mau ke '/riwayat-pinjam', dia diarahkan ke sana
```

## 4. Analogi Sederhana

Bayangkan restoran "Perpustakaan Digital" yang memakai sistem reservasi meja.

- **Login** = proses check-in di resepsionis. Kamu menunjukkan **kartu identitas** (email + password). Resepsionis mencocokkannya dengan **buku tamu** (tabel `users`) lewat `Auth::attempt`.
- **Session** = **gelang masuk** yang diberikan setelah identitas terverifikasi. Selama gelang menempel di tanganmu, semua staf tahu kamu adalah tamu sah — tidak perlu tunjukkan kartu lagi setiap kali minta menu.
- **Regenerate session** = resepsionis mengganti gelang lamamu dengan yang baru saat check-in, supaya gelang lama yang mungkin dicuri orang lain tidak bisa dipakai.
- **Logout** = melepas gelang saat pulang. Staf tidak lagi menganggapmu tamu yang sedang berada di restoran.
- **`redirect()->intended()`** = kamu tadinya mau ke meja pojok, resepsionis bilang "tunggu, identitas dulu", setelah jelas langsung mengantarmu ke meja pojok itu lagi.
- **Meja VIP (role admin)** = urusan materi berikutnya. Gelang hanya membuktikan kamu tamu; kartu khusus menentukan kamu boleh duduk di area VIP.

## 5. Kapan Harus Digunakan & Kasus Penggunaan (Use Cases)

Gunakan Auth manual ketika:

- Kamu **ingin memahami cara kerja auth** — bahan utama untuk jadi backend engineer yang solid.
- Kebutuhan loginmu **di luar pola standar** Breeze (misal login pakai NIP pustakawan, atau autentikasi ganda).
- Kamu membuat **API mobile** dengan guard token.
- Kamu perlu **kontrol penuh** atas alur registrasi/login, misal: role default `anggota` saat daftar.

Tidak perlu Auth manual ketika:

- Proyeknya standar dan kamu hanya butuh auth cepat → pakai Breeze (22), lalu modifikasi.
- Kamu butuh login dengan password + OTP, social login (Google), atau LDAP → lebih mudah pakai package seperti Laravel Socialite / Fortify.

## 6. Poin-poin Penting & Best Practices

- **Selalu pakai `Hash::make` atau cast `hashed`** untuk password. JANGAN pernah simpan plaintext.
- **Regenerate session setelah login** dengan `$request->session()->regenerate()` — ini mencegah session fixation.
- **Saat logout, invalidate session + regenerate token CSRF**:

```php
$request->session()->invalidate();
$request->session()->regenerateToken();
```

- **Jangan hardcode credentials** — selalu validasi input dan cocokkan dengan database.
- **Pakai middleware `auth` di route** agar halaman terproteksi tidak bisa diakses tamu:

```php
Route::get('/dashboard', function () {
    return view('dashboard');
})->middleware('auth');
```

- **Pakai `redirect()->intended()`** supaya UX login terasa mulus.
- **Hindari autentikasi berlebihan**: `Auth::login($user)` tanpa verifikasi sebelumnya itu berbahaya — pastikan user sudah diverifikasi (password cocok / token valid) sebelum di-loginkan.
- **Baca `config/auth.php`** untuk memahami guard & provider proyekmu.

## 7. Kesalahan Umum (Common Pitfalls & Anti-patterns)

| Kesalahan | Penyebab & Solusi |
| --- | --- |
| **419 Page Expired** | Token CSRF hilang dari form. Pastikan ada `@csrf` di dalam `<form>`. |
| **Login selalu gagal padahal data benar** | Password di database tidak di-hash (misal di-insert plaintext). Regenerate atau perbaiki data dengan `Hash::make`. |
| **Password tidak cocok** | Membandingkan password plaintext dengan hash (`$user->password == $input`) — selalu bandingkan via `Auth::attempt` / `Hash::check`. |
| **Session fixation** | Lupa `$request->session()->regenerate()` setelah `Auth::attempt`. Attacker bisa reuse session ID lama. |
| **Login "berhasil" tapi halaman terproteksi tetap tertolak** | Salah middleware — pastikan route pakai `->middleware('auth')`, bukan cuma validasi form. |
| **Menyimpan password plaintext lewat mass assignment** | Pastikan model User punya cast `password => hashed`, atau eksplisit `Hash::make` saat `User::create`. |
| **`Auth::login` tanpa verifikasi** | Jangan login user langsung dari input tanpa `attempt`/cek kredensial — celah keamanan serius. |
| **Debug menampilkan password** | Jangan `dd($request->all())`; gunakan `dd($request->validated())` tanpa password. Jangan pernah log kredensial. |

Troubleshooting cepat: gagal login tapi tidak ada error? Cek `storage/logs/laravel.log`, pastikan kolom `password` di DB berformat hash (62 karakter `$2y$...`), dan sesuaikan nama kolom di model jika kamu pakai `username` bukan `email`.

## 8. Soal Latihan & Kunci Jawaban

### Tantangan

1. Buat fitur login manual untuk admin perpustakaan dengan email + password, tanpa Breeze. Pastikan session di-regenerate setelah login, lalu redirect ke `/dashboard` hanya jika user sudah login.
2. Buat fitur registrasi anggota baru yang otomatis diberi role `anggota`, password di-hash dengan `Hash::make`, dan setelah daftar user langsung login.

### Jawaban & Pembahasan

**Tantangan 1**

```php
// app/Http/Controllers/Auth/LoginController.php
namespace App\Http\Controllers\Auth;

use App\Http\Controllers\Controller;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Auth;

class LoginController extends Controller
{
    public function login(Request $request)
    {
        $credentials = $request->validate([
            'email'    => ['required', 'email'],
            'password' => ['required'],
        ]);

        if (Auth::attempt($credentials)) {
            $request->session()->regenerate(); // cegah session fixation

            return redirect()->intended('/dashboard');
        }

        return back()->withErrors([
            'email' => 'Kredensial tidak cocok.',
        ])->onlyInput('email');
    }
}
```

```php
// routes/web.php
Route::middleware('guest')->group(function () {
    Route::get('/login', [LoginController::class, 'showLoginForm'])->name('login');
    Route::post('/login', [LoginController::class, 'login']);
});

// Route yang butuh login
Route::get('/dashboard', function () {
    return view('dashboard');
})->middleware('auth');
```

Alur: form mengirim email + password → validasi → `Auth::attempt` membandingkan dengan hash di tabel `users` → jika cocok, session di-regenerate → `intended()` mengantar ke `/dashboard`. Route `/dashboard` dilindungi `middleware('auth')`, jadi tamu yang belum login otomatis dilempar ke `/login`.

**Tantangan 2**

```php
// app/Http/Controllers/Auth/RegisterController.php
namespace App\Http\Controllers\Auth;

use App\Http\Controllers\Controller;
use App\Models\User;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Auth;
use Illuminate\Support\Facades\Hash;

class RegisterController extends Controller
{
    public function register(Request $request)
    {
        $validated = $request->validate([
            'name'     => ['required', 'string', 'max:255'],
            'email'    => ['required', 'email', 'unique:users,email'],
            'password' => ['required', 'min:8', 'confirmed'],
        ]);

        $user = User::create([
            'name'     => $validated['name'],
            'email'    => $validated['email'],
            'password' => Hash::make($validated['password']),
            'role'     => 'anggota',
        ]);

        Auth::login($user);
        $request->session()->regenerate();

        return redirect('/dashboard');
    }
}
```

Alur: validasi (termasuk `unique:users,email` supaya email ganda ditolak) → `Hash::make` untuk meng-hash password → user dibuat dengan role default `anggota` → `Auth::login` langsung menandai user sebagai login → session di-regenerate → redirect ke dashboard. Perhatikan: `'confirmed'` berarti wajib ada kolom `password_confirmation` di form, dan Laravel otomatis memastikan keduanya sama.

Dengan ini kamu sudah paham seluruh mekanisme di balik layar Breeze. Lanjut ke materi berikutnya: **24-25. Policy & Middleware** — memanfaatkan `Auth::user()->role` untuk membatasi akses berdasarkan role.
