# 22. Laravel Breeze — Scaffolding Auth yang Cepat

Breeze adalah starter kit resmi Laravel untuk men-generate sistem autentikasi secara instan. Dengan sekali perintah, kamu mendapat halaman login, register, lupa password, verifikasi email, plus dashboard — tanpa menulis semuanya dari nol. Materi ini jadi jembatan: kamu sudah paham validasi (Level 4) dan Eloquent (Level 3), sekarang lihat bagaimana Laravel merangkai semuanya jadi fitur auth yang siap pakai.

## 1. Penjelasan Singkat & Konsep Dasar

Breeze adalah "scaffolding" — kerangka kerja awal. Dia menghasilkan file-file auth standar (controller, view, route) yang bisa langsung kamu pakai lalu pelajari atau modifikasi.

Poin penting soal Breeze:

- **Minimal & ringan**: hanya berisi auth dasar, tanpa fitur tambahan.
- **Bukan Jetstream**: Jetstream itu versi "berat" yang menambahkan tim, profile update, dukungan Inertia/Livewire. Breeze justru sengaja sederhana — cocok untuk belajar dan proyek skala kecil seperti sistem perpustakaan kamu.
- **Pendekatan terbaik saat belajar**: baca kode yang di-generate Breeze. Dia adalah contoh implementasi auth yang benar dari tim Laravel sendiri.

Posisi di roadmap kamu:

- Materi sebelumnya: Validasi (Level 4) dan Eloquent (Level 3) — Breeze memakai keduanya.
- Materi ini: Breeze (22) → Auth Manual (23) → Policy & Middleware (24-25).

Breeze memberi hasil akhir yang sama dengan yang akan kamu pelajari di Auth Manual (23), tapi dengan proses yang berbeda: Breeze menyembunyikan logikanya, Auth Manual membongkarnya.

## 2. Fungsi & Kegunaan Utama dalam Laravel

Kenapa auth di ekosistem Laravel itu penting dan masalah apa yang diselesaikannya:

1. **Login & Registrasi** — alur masuk/daftar yang aman tanpa menulis dari nol.
2. **Password reset** — fitur "lupa password" lewat email.
3. **Verifikasi email** — memastikan user memakai email yang benar-benar dimilikinya.
4. **Session management** — mengingat siapa yang login selama mereka berada di aplikasi.
5. **Hashing password** — password tidak pernah disimpan sebagai teks biasa, selalu di-hash dengan bcrypt.
6. **Keamanan** — Laravel menangani CSRF, session fixation, dan best practice keamanan auth lainnya secara bawaan.

Bagi kamu yang membangun "Perpustakaan Digital" dengan role super_admin, admin, pustakawan, dan anggota: Breeze menyediakan lapisan "siapa kamu" (autentikasi). Lapisan "apa yang boleh kamu lakukan" (otorisasi) akan datang di materi Policy & Middleware berikutnya.

## 3. Contoh Kode & Implementasi (Real-world Example)

### Instalasi Breeze (Laravel 11)

```bash
# 1. Install package Breeze sebagai dev dependency
composer require laravel/breeze --dev

# 2. Generate scaffolding. Stack 'blade' = template PHP asli
php artisan breeze:install blade

# 3. Pasang dependency frontend (Tailwind, Alpine.js)
npm install

# 4. Jalankan dev server untuk Tailwind
npm run dev

# 5. Jangan lupa migrate — tabel users harus dibuat dulu
php artisan migrate
```

Pilihan stack `breeze:install`:

- `blade` — template PHP murni, paling sederhana.
- `livewire` — untuk aplikasi yang pakai Livewire.
- `react` dan `vue` — jika frontend kamu berbasis SPA/komponen.
- `api` — hanya API tanpa tampilan (cocok untuk backend mobile).

### Yang Dihasilkan Breeze

Setelah `php artisan breeze:install blade`, muncul file-file ini:

```
routes/auth.php                         <- route auth (login, register, logout, dll.)
app/Http/Controllers/Auth/              <- folder controller auth
    AuthenticatedSessionController.php  <- login + logout
    RegisteredUserController.php        <- registrasi
    PasswordResetLinkController.php     <- lupa password
    NewPasswordController.php           <- reset password
    VerifyEmailController.php           <- verifikasi email
resources/views/auth/                   <- view untuk semua halaman auth
resources/views/layouts/                <- layout blade dasar
resources/views/profile/                <- halaman profile
```

Model `User` kamu (app/Models/User.php) juga di-update otomatis:

```php
class User extends Authenticatable
{
    // Breeze menambahkan 'password' dan kolom lain ke $fillable
    protected $fillable = [
        'name',
        'email',
        'password',
    ];

    // Password otomatis di-hash saat disimpan
    protected function casts(): array
    {
        return [
            'email_verified_at' => 'datetime',
            'password' => 'hashed',
        ];
    }
}
```

### Fitur yang Langsung Tersedia

Setelah instalasi, route berikut sudah aktif:

| URL | Fungsi |
| --- | --- |
| `/login` | Halaman masuk |
| `/register` | Halaman daftar anggota baru |
| `/forgot-password` | Kirim link reset password |
| `/reset-password` | Set password baru |
| `/email/verify` | Halaman verifikasi email |
| `/dashboard` | Halaman setelah login |

### Konfigurasi Redirect Setelah Login

Secara default, setelah login user diarahkan ke `/dashboard`. Di Laravel 11, logikanya ada di `bootstrap/app.php` atau `app/Providers/RouteServiceProvider.php`:

```php
// app/Providers/RouteServiceProvider.php
public const HOME = '/dashboard';

// Jika kamu mau setelah login menuju halaman koleksi buku perpustakaan:
public const HOME = '/koleksi';
```

### Kasus Nyata: Login Admin Perpustakaan

Admin perpustakaan (role `admin`) membuka `/login`, mengisi email dan password. Breeze:

1. Menampilkan form login dari `resources/views/auth/login.blade.php`.
2. Menerima request di `AuthenticatedSessionController@store`.
3. Memvalidasi email + password.
4. Meng-autentikasi lewat `Auth::attempt`.
5. Mengirim user ke dashboard.

Itulah alurnya. Detail logikanya akan kamu bedah di materi 23 (Auth Manual).

## 4. Analogi Sederhana

Bayangkan Breeze sebagai tim resepsionis yang sudah siap bekerja di restoran "Perpustakaan Digital".

Kamu datang ke restoran, menunjukkan **kartu identitas** (form login: email + password). Tim resepsionis (proses yang di-generate Breeze) memverifikasi identitasmu — cocok tidak dengan data di daftar tamu (tabel `users`). Kalau cocok, kamu dapat **gelang masuk** (session) dan dipersilakan ke meja.

Mekanisme ini semua sudah dirakit rapi oleh Breeze. Kamu tidak perlu membangun meja resepsionis dari kayu sendiri — cukup pasang dan langsung pakai. Yang membedakan meja mana yang boleh kamu duduki (meja VIP = role admin) adalah urusan materi berikutnya: Policy & Middleware.

## 5. Kapan Harus Digunakan & Kasus Penggunaan (Use Cases)

Gunakan Breeze ketika:

- Kamu **memulai proyek baru** dan butuh auth langsung jalan — misal proyek "Perpustakaan Digital".
- Kamu **belajar Laravel** dan ingin melihat contoh implementasi auth yang benar dari tim Laravel.
- Kamu butuh **auth sederhana tanpa fitur berat** — tidak butuh tim, subscription, atau SPA penuh.

Jangan pakai Breeze ketika:

- Kamu butuh fitur Jetstream (tim, dukungan Inertia/Livewire penuh) — gunakan `php artisan jetstream:install`.
- Backend kamu murni API untuk mobile — pakai stack `api` atau Sanctum.
- Kamu sudah punya sistem auth kustom sendiri.

## 6. Poin-poin Penting & Best Practices

- **Breeze itu minimal, bukan kaku**: file yang di-generate boleh diedit sesuai kebutuhan. Banyak developer membuat customize Breeze.
- **`php artisan breeze:install blade` dulu, baru `npm install`**: urutan ini wajib karena Breeze menulis file blade/tailwind yang dibutuhkan npm.
- **Jangan lupa `php artisan migrate`**: tanpa migrate, tabel `users` tidak ada dan login pasti error.
- **Baca hasil generate Breeze**: ini cara terbaik paham "auth yang benar" sebelum menulis manual.
- **Password sudah di-hash otomatis**: Breeze memakai cast `hashed` di model User — jangan hapus cast ini.
- **Sesuaikan `HOME` redirect** jika `\dashboard` kurang cocok untuk role-based dashboard.
- **Jangan hardcode credentials**: selalu pakai database dan hashing, bukan array hardcoded.

## 7. Kesalahan Umum (Common Pitfalls & Anti-patterns)

| Kesalahan | Penyebab & Solusi |
| --- | --- |
| **419 Page Expired** | Form Breeze butuh token CSRF. Pastikan `@csrf` ada di form dan `SESSION_DRIVER` di `.env` bernilai `database`/`file`, bukan `array`. |
| **Login gagal terus** | Biasanya karena tabel `users` belum punya data atau password tidak di-hash. Cek isi tabel, jangan insert password plaintext. |
| **Lupa migrate setelah `breeze:install`** | Error "table users does not exist". Jalankan `php artisan migrate`. |
| **Dashboard tidak muncul, selalu ke `/`** | Konstanta `HOME` belum diubah atau route dashboard belum terdaftar. Cek `RouteServiceProvider.php`. |
| **Debug menampilkan password** | Jangan pernah `dd($request->all())` di controller auth. Gunakan `dd($request->validated())` tanpa password, atau hapus kolom password dari array. |
| **`npm run dev` tidak jalan / UI polos** | Jalankan `npm install` dulu, dan pastikan `npm run dev` berjalan bersamaan dengan server Laravel. |

Troubleshooting singkat: kalau ada error, baca pesan error dengan `php artisan --version`, cek `storage/logs/laravel.log`, dan jalankan `php artisan config:clear`.

## 8. Soal Latihan & Kunci Jawaban

### Tantangan

1. Instal Breeze di proyek Laravel 11 baru dengan stack `blade`. Catat file apa saja yang muncul dan uji semua fitur: `/login`, `/register`, `/forgot-password`, dan `/dashboard` setelah login.
2. Ubah redirect default sehingga setelah login admin perpustakaan diarahkan ke `/koleksi` (bukan `/dashboard`). Tulis langkah yang kamu ambil.

### Jawaban & Pembahasan

**Tantangan 1**

```bash
composer create-project laravel/laravel perpustakaan
cd perpustakaan
composer require laravel/breeze --dev
php artisan breeze:install blade
npm install
npm run dev
php artisan migrate
php artisan serve
```

File yang muncul: `routes/auth.php`, folder `app/Http/Controllers/Auth/`, folder `resources/views/auth/`, plus update pada `app/Models/User.php`. Buka `http://127.0.0.1:8000/register`, buat akun, lalu coba login. Cek `routes/auth.php` untuk melihat daftar route yang tersedia — ini bukti bahwa semua fitur tadi sudah terdaftar.

**Tantangan 2**

Di Laravel 11, ubah konstanta di `app/Providers/RouteServiceProvider.php`:

```php
public const HOME = '/koleksi';
```

Pastikan route `/koleksi` terdaftar (misal di `routes/web.php`):

```php
Route::get('/koleksi', function () {
    return view('koleksi');
})->middleware(['auth', 'verified']);
```

Uji: login lalu lihat apakah kamu diarahkan ke `/koleksi`. Alur: setelah login berhasil, `AuthenticatedSessionController` memanggil `redirect()->intended(HomeController::HOME)` — variabel `HOME` inilah yang menentukan tujuan akhir.

Lanjut ke materi berikutnya: **23. Auth Manual** — di sana kamu membongkar apa yang Breeze lakukan di balik layar.
