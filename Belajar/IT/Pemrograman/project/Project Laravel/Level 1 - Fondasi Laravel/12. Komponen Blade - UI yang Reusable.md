# 12. Komponen Blade — UI yang Reusable

Komponen Blade adalah cara modern untuk membungkus UI yang dipakai berulang menjadi sebuah "kotak" mandiri, lengkap dengan data (props) dan konten (slot). Dengan komponen, satu tampilan seperti kartu buku bisa ditulis sekali lalu dipakai di banyak halaman tanpa menyalin HTML.

## 1. Penjelasan Singkat & Konsep Dasar

Di materi sebelumnya kamu belajar menulis tampilan dengan direktif Blade (`@if`, `@foreach`) dan menyusun kerangka halaman dengan `@extends`/`@section`. Masalah berikutnya: komponen kecil seperti kartu buku, tombol, atau alert sering dipakai di banyak halaman. Menyalinnya berulang kali melanggar prinsip DRY.

Komponen Blade menyelesaikan ini dengan dua jenis:

- **Class-based component**: satu kelas PHP (`app/View/Components/BukuCard.php`) + satu file view (`resources/views/components/buku-card.blade.php`). Cocok untuk komponen yang butuh logika (persiapan data, perhitungan).
- **Anonymous component**: cukup file view di `resources/views/components/`, tanpa kelas. Cocok untuk komponen tampilan murni (statis).

Keduanya dipakai lewat tag `<x-...>` di dalam Blade. Materi ini adalah puncak dari alur "Blade Dasar -> Layout -> Komponen", dan menyiapkanmu untuk Level 2 (Controller + Form yang memakai komponen form).

## 2. Fungsi & Kegunaan Utama dalam Laravel

- **Reusable UI**: kartu buku yang sama dipakai di halaman katalog, halaman beranda, dan hasil pencarian — cukup tulis sekali.
- **Data binding eksplisit**: props komponen dideklarasikan dengan jelas (contoh `:buku="$buku"`), sehingga tidak ada variabel "bocor" yang datang dari mana-mana.
- **Logika terenkapsulasi**: untuk class-based component, perhitungan (misal format harga atau status stok) ada di kelas, bukan tersebar di view.
- **Konten fleksibel lewat `$slot`**: bagian dalam tag komponen bisa berupa HTML apapun, menjadikan komponen seperti "template dengan lubang".
- **Perbedaan dengan `@include`**: `@include` hanya menempel file tanpa batasan variabel dan tanpa konsep slot; komponen lebih aman, eksplisit, dan mudah dipakai ulang.

## 3. Contoh Kode & Implementasi (Real-world Example)

### 3.1 Anonymous component: Kartu Buku

Cukup buat file view tanpa kelas.

Lokasi standar: `resources/views/components/buku-card.blade.php`

```blade
{{-- Props diambil lewat direktif @props dengan nilai default --}}
@props([
    'buku',
    'showDetail' => true,
])

<div class="kartu">
    {{-- Menampilkan data buku yang dikirim sebagai prop --}}
    <h2>{{ $buku->judul }}</h2>
    <p class="pengarang">{{ $buku->pengarang }}</p>
    <p class="harga">Rp {{ number_format($buku->harga, 0, ',', '.') }}</p>

    {{-- Badge stok --}}
    @if ($buku->stok > 0)
        <span class="badge badge-hijau">Stok: {{ $buku->stok }}</span>
    @else
        <span class="badge badge-merah">Stok habis</span>
    @endif

    {{-- Slot: konten dari luar komponen dirender di sini --}}
    {{ $slot }}

    {{-- Tombol detail, hanya tampil jika showDetail true --}}
    @if ($showDetail)
        <a class="btn" href="{{ route('buku.show', $buku) }}">Lihat Detail</a>
    @endif
</div>
```

Cara memakai di view:

Lokasi standar: `resources/views/buku/index.blade.php`

```blade
@extends('layouts.app')

@section('content')
    <h1>Katalog Buku</h1>

    <div class="grid">
        @foreach ($buku as $item)
            {{-- :buku="$item" mengirim variabel; $slot diisi tombol Pinjam --}}
            <x-buku-card :buku="$item">
                <a class="btn btn-primer" href="{{ route('peminjaman.create', $item) }}">Pinjam</a>
            </x-buku-card>
        @endforeach
    </div>
@endsection
```

### 3.2 Class-based component: Alert

Komponen dengan logika (jenis pesan menentukan warna icon dan teks).

Perintah untuk membuat class-based component:

```bash
php artisan make:component Alert
```

Perintah ini menghasilkan dua file:

- `app/View/Components/Alert.php` — kelas komponen
- `resources/views/components/alert.blade.php` — view komponen

Lokasi standar: `app/View/Components/Alert.php`

```php
<?php

namespace App\View\Components;

use Closure;
use Illuminate\Contracts\View\View;
use Illuminate\View\Component;

class Alert extends Component
{
    // Properti public otomatis tersedia di view komponen
    public function __construct(
        public string $type = 'sukses',
        public string $message = '',
    ) {
    }

    // Menentukan class CSS berdasarkan tipe alert
    public function className(): string
    {
        return match ($this->type) {
            'error'   => 'alert alert-error',
            'peringatan' => 'alert alert-peringatan',
            default   => 'alert alert-sukses',
        };
    }

    public function render(): View|Closure|string
    {
        return view('components.alert');
    }
}
```

Lokasi standar: `resources/views/components/alert.blade.php`

```blade
@props(['type' => 'sukses', 'message' => ''])

<div {{ $attributes->merge(['class' => $className]) }}>
    {{ $message }}
    {{ $slot }}
</div>
```

Cara memakai — di layout atau halaman mana pun:

```blade
<x-alert type="sukses" message="Buku berhasil ditambahkan." />
{{-- Hasil: <div class="alert alert-sukses">Buku berhasil ditambahkan.</div> --}}

<x-alert type="error">
    Ada masalah saat memproses peminjaman.
</x-alert>
```

### 3.3 Props dengan nilai default dan atribut tambahan

```blade
{{-- Membuat kartu tanpa tombol detail (misal di beranda, versi ringkas) --}}
<x-buku-card :buku="$buku" :show-detail="false" />

{{-- Menambahkan class/custom atribut ke komponen: otomatis ke element lewat $attributes --}}
<x-buku-card :buku="$buku" class="kartu-lebar" id="buku-{{ $buku->id }}" />
```

## 4. Analogi Sederhana

**Blade/View = Penyajian makanan di piring.**

Komponen itu seperti **resep standar restoran** yang sudah terbukti: sekali dicatat, setiap koki bisa membuat porsi yang sama persis tanpa menebak-nebak. Route = pelayan, controller = koki, data = bahan dari gudang (Model).

Prop (`:buku="$buku"`) adalah **bahan yang dimasukkan ke resep**: tiap piring mendapat buku yang berbeda, tapi pengerjaannya sama. `$slot` adalah **piring kosong di tengah hidangan** — pelanggan boleh menaruh tambahan sendiri (saus, taburan) di dalamnya; restoran menyediakan kerangkanya. `<x-buku-card>` itu seperti **memanggil nama resep di menu**, bukan menulis ulang langkah-langkahnya.

Anonymous component = resep sederhana yang diingat semua koki. Class-based component = resep dari **koki khusus** (kelas) yang bisa melakukan perhitungan, misalnya menentukan saus mana yang cocok berdasarkan pesanan — di sini menentukan warna alert berdasarkan tipe error/sukses.

## 5. Kapan Harus Digunakan & Kasus Penggunaan (Use Cases)

- **Komponen WAJIB dipakai saat UI yang sama dipakai di banyak halaman**, contoh: `<x-buku-card>` di katalog, beranda, dan hasil pencarian. Jika kartu berubah, hanya satu file yang diedit.
- **Anonymous component** untuk tampilan statis: `<x-alert>`, `<x-button>`, `<x-badge-stok>`, `<x-input>`. Tidak perlu kelas jika tidak ada logika.
- **Class-based component** saat ada logika perhitungan: `<x-badge-stok>` yang menghitung status dari `$buku->stok` di kelas, atau komponen yang butuh data dari database (misal `<x-daftar-kategori>` yang menarik kategori dari model).
- **Gunakan `$slot`** untuk konten dinamis di dalam komponen, misal tombol "Pinjam" yang berbeda-beda tergantung status peminjaman user.
- **Form field sebagai komponen** (Level berikutnya): `<x-input label="Judul" name="judul" />` menyatukan input, label, dan pesan error validasi dalam satu tempat.

## 6. Poin-poin Penting & Best Practices

- **Konvensi penamaan**: file anonymous component di `resources/views/components/` pakai kebab-case (`buku-card.blade.php`). Tag `<x-buku-card>` memakai kebab-case juga.
- **Class-based component**: `php artisan make:component NamaKomponen` menghasilkan kelas di `app/View/Components/` dan view otomatis dinamai kebab-case di `resources/views/components/`. Kelas PascalCase (`BukuCard`), view `buku-card.blade.php`.
- **Properti public di constructor** otomatis tersedia sebagai variabel di view komponen. Properti non-public tidak.
- **Gunakan `@props`** di view komponen (terutama anonymous) untuk mendeklarasikan prop dan nilai default; `@props(['buku', 'showDetail' => true])`.
- **Pass data dengan colon `:buku="$buku"`** untuk variabel/ekspresi; tanpa colon `buku="judul"` untuk string literal. Ini sumber error yang sering membingungkan pemula.
- **`$slot` selalu ada** untuk konten di dalam tag komponen; jika kosong, render kosong. Default slot bisa ditambah dengan `@slot('nama')`.
- **Gunakan `$attributes`** (`$attributes->merge(...)`) agar class/atribut tambahan dari pemakai komponen bisa diteruskan ke element. Tanpa ini, `<x-buku-card class="x">` akan diabaikan.
- **Komponen vs `@include`**: pilih komponen untuk UI mandiri yang dipakai ulang; `@include` hanya untuk menempel partial kecil yang memang butuh akses variabel dari parent secara langsung dan tanpa slot.
- **Jangan terlalu memecah**: komponen yang terlalu kecil (hanya membungkus satu `<div>`) justru menambah kerumitan. Buat komponen saat benar-benar dipakai ulang.
- **Test dengan `php artisan view:cache`** di production setelah menambah komponen agar cache view diperbarui.

## 7. Kesalahan Umum (Common Pitfalls & Anti-patterns)

- **Lupa colon saat kirim variabel** → `x-buku-card buku="$item"` mengirim string literal `"$item"` (teks `$item`), bukan variabelnya. Solusi: `:buku="$item"` (dengan colon).
- **Nama prop tidak cocok** → view memakai `$buku` tapi prop bernama `$book`. Solusi: samakan penamaan prop di `@props`, constructor, dan pemakaian tag.
- **Lupa mendeklarasikan prop** → anonymous component memakai `$judul` tanpa `@props(['judul'])`; variabel bisa null. Solusi: selalu deklarasikan di `@props`.
- **`$slot` tidak dirender** → pemakai komponen menaruh konten di dalam tag `<x-buku-card>...</x-buku-card>` tapi view komponen tidak memuat `{{ $slot }}`, sehingga konten hilang. Solusi: tambahkan `{{ $slot }}` di tempat yang diinginkan.
- **Class di luar komponen hilang** → `<x-alert class="bg-merah">` tanpa `$attributes->merge(['class' => ...])` di view komponen; class tidak muncul. Solusi: gabungkan `$attributes`.
- **Mencampur `@include` dan komponen** → memakai `@include('components.buku-card')` dengan variabel yang tidak ada. Komponen dipakai lewat tag `<x-...>`; `@include` memakai variabel global parent.
- **Menaruh logika query di view komponen** → komponen mengeksekusi `Buku::where(...)` di dalam blade. Solusi: untuk yang butuh data, jadikan class-based component dan siapkan data di kelas/controller.
- **Komponen tidak muncul setelah dibuat** → cache view belum ter-update (terutama di production). Solusi: `php artisan view:clear` lalu `php artisan view:cache`.
- **Nested component salah arah** → komponen di dalam komponen boleh, tapi pastikan nama tag unik dan tidak membuat rekursi tak berujung (misal komponen memanggil dirinya sendiri tanpa kondisi berhenti).
- **Constructor tanpa tipe / tanpa default** → prop wajib diisi setiap kali; kalau lupa diisi bisa error. Solusi: beri nilai default di constructor (`public string $type = 'sukses'`).

## 8. Soal Latihan & Kunci Jawaban

### Tantangan

1. **Komponen Badge Stok**: Buat anonymous component `resources/views/components/badge-stok.blade.php` yang menerima prop `$stok` (angka) dan menampilkan teks + class CSS:
   - stok > 0: teks "Tersedia ({stok})", class `badge badge-hijau`
   - stok == 0: teks "Stok habis", class `badge badge-merah`
   - stok < 0: teks "Perbaikan", class `badge badge-kuning`
   Pakai di `buku/show.blade.php` dengan `<x-badge-stok :stok="$buku->stok" />`.

2. **Komponen Kartu dengan slot**: Buat class-based component `BukuCard` (gabungkan: kelas PHP + view) yang menerima `$buku`, menampilkan judul dan pengarang, serta memiliki `$slot` untuk tombol aksi. Di `buku/index.blade.php`, pakai `<x-buku-card :buku="$buku">` dengan isi slot berupa tombol "Lihat Detail". Gunakan `php artisan make:component` di langkah pembuatannya.

### Jawaban & Pembahasan

**Jawaban 1** — anonymous component `resources/views/components/badge-stok.blade.php`:

```blade
@props(['stok' => 0])

@if ($stok > 0)
    <span class="badge badge-hijau">Tersedia ({{ $stok }})</span>
@elseif ($stok == 0)
    <span class="badge badge-merah">Stok habis</span>
@else
    <span class="badge badge-kuning">Perbaikan</span>
@endif
```

Cara pakai di `resources/views/buku/show.blade.php`:

```blade
@extends('layouts.app')

@section('title', 'Detail Buku')

@section('content')
    <h1>{{ $buku->judul }}</h1>
    {{-- Stok masuk sebagai prop; komponen memutuskan tampilan badge --}}
    <x-badge-stok :stok="$buku->stok" />
@endsection
```

Alur: prop `$stok` dideklarasikan dengan `@props` dan default 0. Di view, `@if/@elseif/@else` memilih teks dan class sesuai kondisi. Pemakaiannya sangat ringkas: `<x-badge-stok :stok="$buku->stok" />`, tanpa menyalin logika kondisional di setiap halaman. Colon (`:`) wajib agar nilai variabel `$buku->stok` dikirim, bukan string `"$buku->stok"`.

**Jawaban 2** — buat class-based component:

```bash
php artisan make:component BukuCard
```

Lokasi standar: `app/View/Components/BukuCard.php`

```php
<?php

namespace App\View\Components;

use Closure;
use Illuminate\Contracts\View\View;
use Illuminate\View\Component;

class BukuCard extends Component
{
    // Prop public $buku otomatis tersedia di view komponen
    public function __construct(
        public $buku,
    ) {
    }

    public function render(): View|Closure|string
    {
        return view('components.buku-card');
    }
}
```

Lokasi standar: `resources/views/components/buku-card.blade.php`

```blade
@props(['buku'])

<div class="kartu">
    <h2>{{ $buku->judul }}</h2>
    <p class="pengarang">{{ $buku->pengarang }}</p>

    {{-- Slot: diisi oleh konten di dalam <x-buku-card>...</x-buku-card> --}}
    {{ $slot }}
</div>
```

Cara pakai di `resources/views/buku/index.blade.php`:

```blade
@extends('layouts.app')

@section('content')
    <h1>Katalog Buku</h1>

    <div class="grid">
        @foreach ($buku as $item)
            <x-buku-card :buku="$item">
                <a class="btn btn-primer" href="{{ route('buku.show', $item) }}">Lihat Detail</a>
            </x-buku-card>
        @endforeach
    </div>
@endsection
```

Alur: `make:component` membuat pasangan kelas + view sekaligus. Kelas mendeklarasikan prop `$buku` di constructor; karena public, Laravel meneruskan nilainya ke view komponen. View komponen merender judul, pengarang, lalu `{{ $slot }}` yang berisi tombol "Lihat Detail" dari pemakaian. Karena kartu dipakai di katalog (dan bisa dipakai ulang di beranda/hasil pencarian), perubahan desain cukup dilakukan di satu file `buku-card.blade.php`. Inilah kekuatan komponen: UI reusable dengan data dan slot yang jelas.
