# 1. Apa yang Laravel Gantikan dari PHP Native

Selamat datang di level fondasi, Sob. Sebelum terjun ke instalasi dan mengetik perintah artisan, kita wajib paham dulu: apa sebenarnya yang Laravel gantikan? Kalau kita pernah (atau sekadar tahu) menulis PHP murni tanpa framework, kita akan menyadari banyak hal yang selama ini dikerjakan manual ternyata sudah disediakan Laravel secara otomatis. Materi ini jadi jembatan antara dunia "PHP polos" dan dunia "framework", sebelum nanti kita lanjut ke filosofi Convention over Configuration dan akhirnya instalasi Laravel 11.

## 1. Penjelasan Singkat & Konsep Dasar

PHP native itu "mesin mentah": dia bisa mengerjakan apa saja, tapi kamu yang harus merakit semuanya. Setiap proyek PHP native yang serius pasti mengulang pola yang sama: buka koneksi database, cek URL untuk menentukan halaman, sanitasi input dari `$_GET`/`$_POST`, buat session, atur keamanan (CSRF, XSS), redirect, dan masih banyak lagi. Pola berulang inilah yang disebut **boilerplate**.

Laravel mengambil pola-pola berulang itu, membungkusnya jadi fitur yang rapi, dan mengeksekusinya lewat **alur request yang sudah distandarkan**. Intinya: Laravel bukan mengganti PHP, dia berdiri di atas PHP dan mengotomatisasi bagian-bagian yang membosankan. Prinsip yang harus kamu pegang sepanjang belajar: **pahami apa yang digantikan, maka semua konsep Laravel jadi masuk akal.**

Alur request di Laravel 11 cukup sederhana dan konsisten:

```
Browser request
  -> public/index.php        (entry point, hanya mem-bootstrap aplikasi)
  -> bootstrap/app.php       (daftarkan aplikasi & middleware global)
  -> Service Container       (siapkan semua dependency yang dibutuhkan)
  -> HTTP Kernel / pipeline  (jalankan middleware global secara berurutan)
  -> Route Matching          (cocokkan URL yang diminta dengan daftar route)
  -> Route Middleware        (jalankan middleware khusus route, mis. auth)
  -> Controller              (koki yang mengolah request, hubungi Model/View)
  -> Response                (kirim hasil kembali ke browser)
```

Setiap langkah di atas sudah diurus Laravel. Kita tinggal mengisi bagian yang kita mau: definisikan route di `routes/web.php`, buat controller, dan tampilkan view.

## 2. Fungsi & Kegunaan Utama dalam Laravel

Laravel ada untuk menyelesaikan masalah-masalah yang selalu muncul di aplikasi web, tanpa harus menulis ulang dari nol:

- **Routing** — menggantikan manual `if/switch` untuk memilah URL.
- **Database (Eloquent ORM)** — menggantikan `PDO` + query SQL manual yang rawan error.
- **Keamanan output** — `{{ }}` di Blade menggantikan `htmlspecialchars()`.
- **Request handling** — `$request->input()` menggantikan akses mentah `$_POST`/`$_GET`.
- **Session** — dikelola otomatis, menggantikan `session_start()` manual.
- **Redirect** — `redirect()` menggantikan `header("Location: ...")`.
- **Layout/partial** — Blade menggantikan `require header.php` berulang-ulang.
- **JSON/API** — `response()->json()` menggantikan manual `json_encode`.
- **CSRF Protection** — `@csrf` menggantikan pembuatan token manual.
- **Auth & password** — `Hash::make()` menggantikan `password_hash()` manual.
- **Migrations** — skema database sebagai versi kontrak, bukan file `.sql` copy-paste.

Semua fitur ini menyelesaikan satu masalah inti: **developer fokus ke logika bisnis aplikasi, bukan ke plumbing teknis**.

## 3. Contoh Kode & Implementasi (Real-world Example)

### PHP Native yang biasa kita tulis manual

File `index.php` (native) — routing dengan if/switch:

```php
<?php
// routing manual: kalau URL /buku, tampilkan daftar buku
$uri = $_SERVER['REQUEST_URI'];

if ($uri === '/buku') {
    // koneksi PDO manual
    $pdo = new PDO('mysql:host=localhost;dbname=perpustakaan', 'root', '');
    $stmt = $pdo->query('SELECT * FROM buku');
    $buku = $stmt->fetchAll(PDO::FETCH_ASSOC);

    // sanitasi output manual satu per satu
    echo "<h1>Daftar Buku</h1>";
    foreach ($buku as $b) {
        // htmlspecialchars diulang untuk setiap kolom — melelahkan & rawan lupa
        echo "<p>" . htmlspecialchars($b['judul']) . "</p>";
    }
} elseif ($uri === '/buku/create') {
    // form, token CSRF manual, dst...
}
?>
```

### Laravel 11 yang menggantikannya

File `routes/web.php` — daftar URL aplikasi perpustakaan digital:

```php
<?php

use App\Http\Controllers\BukuController;
use Illuminate\Support\Facades\Route;

// Laravel mencocokkan URL '/buku' langsung ke method index controller
Route::get('/buku', [BukuController::class, 'index']);

// URL '/buku/{id}' mengirim parameter id ke method show
Route::get('/buku/{id}', [BukuController::class, 'show'])->whereNumber('id');
```

File `app/Http/Controllers/BukuController.php`:

```php
<?php

namespace App\Http\Controllers;

use App\Models\Buku;
use Illuminate\Http\Request;

class BukuController extends Controller
{
    public function index()
    {
        // Eloquent menggantikan PDO: ambil semua data tabel buku
        $buku = Buku::all();

        // Blade otomatis meng-escape output (menggantikan htmlspecialchars manual)
        return view('buku.index', compact('buku'));
    }

    public function store(Request $request)
    {
        // $request->input() menggantikan $_POST mentah
        Buku::create($request->all());

        // redirect menggantikan header("Location: ...") manual
        return redirect()->route('buku.index')->with('sukses', 'Buku berhasil ditambahkan.');
    }
}
```

### Kenapa `public/index.php` hanya berisi sedikit kode?

File `public/index.php` (Laravel 11) — ini entry point seluruh aplikasi:

```php
<?php

use Illuminate\Foundation\Application;
use Illuminate\Http\Request;

define('LARAVEL_START', microtime(true));

// Cek mode maintenance: jika aplikasi sedang maintenance, tampilkan halaman 503
if (file_exists($maintenance = __DIR__.'/../storage/framework/maintenance.php')) {
    require $maintenance;
}

// Autoload semua class Composer, lalu bootstrap aplikasi
require __DIR__.'/../vendor/autoload.php';

// Buka aplikasi Laravel
$app = require_once __DIR__.'/../bootstrap/app.php';

// Proses request masuk dan kirim response kembali
$response = $app->handleRequest(Request::capture());
$response->send();
```

Sekilas terlihat "kosong", padahal di sinilah semesta dinyalakan. File ini hanya **pintu masuk**: ia memuat Composer autoloader, membuka aplikasi lewat `bootstrap/app.php`, lalu menyerahkan request ke Service Container dan pipeline middleware. Semua kerumitan (routing, session, database, middleware) dieksekusi oleh framework setelah baris ini. **Itulah kenapa kamu tidak perlu menyentuh file ini** — Laravel sudah merancangnya agar minim dan stabil. Yang kamu ubah adalah `routes/web.php`, controller, model, dan view.

## 4. Analogi Sederhana

Bayangkan aplikasi web adalah sebuah **restoran**.

- PHP native = kamu adalah pemilik restoran yang juga merangkap segalanya: pelayan, koki, kasir, gudang, bahkan satpam. Kamu harus membangun semua proses dari nol: menulis pesanan manual, mencari resep sendiri, mengatur pintu dapur, menghitung ongkos — semuanya manual dan capek.
- Laravel = restoran yang sudah punya SOP lengkap dan staf terlatih. Kamu cukup **menulis di menu (Route) pesanan apa saja yang dilayani**, lalu staf yang ada (Controller, Model, Middleware) mengerjakan sisanya. Kamu tidak perlu mengurus bagaimana pesanan sampai ke dapur — sudah ada sistemnya.

Tabel analogi di bawah memetakan istilah Laravel ke peran restoran yang akan kamu pakai di seluruh roadmap ini:

| Konsep Laravel | Analogi Restoran |
|---|---|
| Route | Menu & pelayan restoran (cara pesanan sampai ke dapur) |
| Controller | Koki |
| Model/Eloquent | Gudang bahan makanan |
| Blade/View | Penyajian makanan di piring |
| Middleware | Satpam/petugas di pintu dapur |
| Request | Slip pesanan dari pelayan |
| Migration | Blueprint renovasi dapur (versi kontrak) |
| Auth | Kartu identitas / meja reservasi |
| Service Container | Manajer yang menyiapkan peralatan sesuai kebutuhan |

## 5. Kapan Harus Digunakan & Kasus Penggunaan (Use Cases)

- **Fitur framework vs native**: Hampir selalu gunakan fitur Laravel, bukan versi manual PHP. Manual hanya dibenarkan jika memang butuh kontrol paling rendah (misal operasi file custom), itu pun tetap dibungkus service Laravel.
- **Routing**: wajib lewat `routes/web.php`. Jangan pernah menulis `if ($_SERVER['REQUEST_URI'] === ...)` di controller.
- **Input user**: selalu lewat `$request`, jangan baca `$_POST`/`$_GET` langsung.
- **Output**: selalu lewat Blade `{{ }}` agar XSS tertangani otomatis.
- **Pada aplikasi Perpustakaan Digital**: alur "pengguna buka `perpustakaan.test/buku`, sistem tampilkan daftar buku dari database" adalah contoh nyata route -> controller -> model -> view yang akan kamu pakai setiap hari.

## 6. Poin-poin Penting & Best Practices

- **Entry point adalah `public/index.php`**, tapi jangan diubah. Semua logika ada di `routes`, `app/`, dan `resources/`.
- **Daftarkan URL di route, bukan di controller**. Controller hanya mengeksekusi, tidak menentukan URL.
- **Gunakan helper Laravel**: `redirect()`, `back()`, `route('nama.route')` — lebih ekspresif dan aman daripada `header()`.
- **Selalu escape output** — Blade `{{ }}` sudah otomatis memanggil `htmlspecialchars`.
- **DRY (Don't Repeat Yourself)**: kalau kamu menulis `htmlspecialchars()` di 10 file, itu sinyal kamu butuh Blade. Kalau menulis koneksi PDO di banyak tempat, itu sinyal kamu butuh Eloquent.
- **Baca urutan alur request berulang kali** sampai hafal; semua materi berikutnya berdiri di atas alur ini.

## 7. Kesalahan Umum (Common Pitfalls & Anti-patterns)

- **Membaca `$_GET`/`$_POST` langsung di controller** — Laravel tidak menghalangi, tapi kamu kehilangan fitur validation, file upload, dan session flash. Gunakan `$request->input()`.
- **Mengubah `public/index.php`** untuk menambah fitur — salah tempat. Ini file milik framework, bukan milik kamu.
- **Lupa mengapa ada `@csrf` di form** — ini pengganti token CSRF manual di PHP native. Hapus `@csrf` dan form akan ditolak `419 Page Expired`.
- **Menampilkan data tanpa escape** dengan `{!! !!}` — ini setara dengan `echo $judul` mentah tanpa `htmlspecialchars`; rawan XSS. Hanya pakai untuk HTML yang benar-benar terpercaya.
- **Menulis route satu per satu tanpa memahami alurnya** — kalau route tidak cocok, kamu dapat `404`, bukan "halaman rusak". Cek urutan: URL benar? route terdaftar? controller ada? method ada?

**Troubleshooting singkat:**
- `404` di route yang "sudah dibuat" -> jalankan `php artisan route:list` untuk memastikan route terdaftar.
- `500` yang misterius -> buka `storage/logs/laravel.log` untuk melihat stack trace asli.
- `419` -> ingat `@csrf` di form Blade.

## 8. Soal Latihan & Kunci Jawaban

### Tantangan

1. Buat route `GET /dashboard` di `routes/web.php` yang merespons teks "Selamat datang di Perpustakaan Digital" (boleh langsung return string), lalu jalankan `php artisan route:list` dan perhatikan baris route yang baru.
2. Buat route `GET /buku` yang memanggil method `index` dari `BukuController`, dan di dalam controller tampilkan daftar buku lewat `Buku::all()` dengan view `buku.index`. Tulis versi komentar di sampingnya: "di PHP native bagian mana yang sekarang ditangani Laravel?"

### Jawaban & Pembahasan

Soal 1 — file `routes/web.php`:

```php
<?php

use Illuminate\Support\Facades\Route;

Route::get('/dashboard', function () {
    return 'Selamat datang di Perpustakaan Digital';
});
```

Alurnya: browser meminta `/dashboard` -> `public/index.php` mem-bootstrap aplikasi -> Route Matching menemukan `Route::get('/dashboard', ...)` -> closure dieksekusi -> teks dikembalikan sebagai response. Jalankan `php artisan route:list`; kamu akan melihat baris `GET|HEAD  /dashboard` di tabel route. Itu bukti routing Laravel menggantikan `if/switch` manual.

Soal 2 — route di `routes/web.php`:

```php
<?php

use App\Http\Controllers\BukuController;
use Illuminate\Support\Facades\Route;

// /buku -> controller BukuController method index
Route::get('/buku', [BukuController::class, 'index']);
```

Controller di `app/Http/Controllers/BukuController.php`:

```php
<?php

namespace App\Http\Controllers;

use App\Models\Buku;

class BukuController extends Controller
{
    public function index()
    {
        // Laravel mengambil alih koneksi PDO dan query manual:
        // SELECT * FROM buku dijalankan oleh Eloquent
        $buku = Buku::all();

        // Laravel mengambil alih require header.php + htmlspecialchars:
        // Blade menyusun layout dan meng-escape output otomatis
        return view('buku.index', compact('buku'));
    }
}
```

Mapping "di PHP native bagian mana yang sekarang ditangani Laravel?":

| Yang kamu tulis manual di PHP native | Digantikan oleh Laravel |
|---|---|
| `$uri = $_SERVER['REQUEST_URI']; if ($uri === '/buku')` | `Route::get('/buku', ...)` di `routes/web.php` |
| `new PDO(...)` + `$pdo->query('SELECT * FROM buku')` | `Buku::all()` lewat Eloquent |
| `require 'header.php'; foreach ($buku as ...)` + `htmlspecialchars()` | `view('buku.index')` dengan `{{ }}` di Blade |
| `header("Location: ...")` | `redirect()` |

Jika dua tantangan ini lancar, kamu sudah memahami jantung Laravel: **framework menangani plumbing, kamu menangani logika bisnis.** Selanjutnya kita bahas kenapa semua ini bisa "tiba-tiba bekerja" tanpa banyak konfigurasi, yaitu filosofi Convention over Configuration.
