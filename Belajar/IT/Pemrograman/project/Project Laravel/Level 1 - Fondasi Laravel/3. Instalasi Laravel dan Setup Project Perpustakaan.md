# 3. Instalasi Laravel dan Setup Project Perpustakaan

Materi ini adalah jembatan dari teori ke praktik. Setelah memahami apa yang Laravel gantikan dari PHP Native dan konsep *Convention over Configuration*, sekarang saatnya menyalakan mesin: membuat project Laravel 11 bernama `perpustakaan` yang akan kita bangun bersama sepanjang roadmap ini. Di akhir materi, kita akan punya aplikasi Laravel yang bisa diakses lewat browser — fondasi nyata pertama kamu.

## 1. Penjelasan Singkat & Konsep Dasar

Instalasi Laravel pada dasarnya adalah **membuat skeleton project** — kerangka folder, file konfigurasi, dan dependensi siap pakai yang sudah dirapikan mengikuti *convention*. Kamu tidak menyusun semuanya dari nol seperti di PHP Native; kamu menyalakan template resmi lalu mulai membangun di atasnya.

Konsep ini nyambung langsung dengan materi sebelumnya:
- **PHP Native**: kamu install server, buat folder `htdocs`, bikin file `.php` satu per satu.
- **Laravel**: kamu jalankan satu perintah, dan semua struktur (yang akan dibedah di materi **4. Struktur Direktori**) langsung tercipta secara konsisten — ini buah dari *Convention over Configuration*.

Setelah project jadi, langkah berikutnya adalah mengatur environment lewat `.env` (materi **5**) dan mulai berkenalan dengan `artisan` (materi **6**), lalu masuk ke Routing (materi berikutnya).

## 2. Fungsi & Kegunaan Utama dalam Laravel

Kenapa instalasi ini penting dan berbeda dari cara lama?

1. **Menghemat waktu setup.** Skeleton Laravel sudah berisi autoloading (Composer), error handling, struktur folder, konfigurasi default, dan testing. Di PHP Native, semua ini harus dibangun sendiri.
2. **Memastikan versi yang benar.** `laravel new` atau `composer create-project` otomatis memilih versi stabil dan memvalidasi versi PHP, Composer, dan ekstensi yang dibutuhkan.
3. **Menstandarkan lingkungan tim.** Seluruh developer memakai struktur awal yang sama persis, sehingga konvensi terjaga dari hari pertama.
4. **Memisahkan kode dari konfigurasi.** Project langsung dilengkapi `.env` (environment) dan `.env.example` (template), yang akan kita pelajari detail di materi 5.

## 3. Contoh Kode & Implementasi (Real-world Example)

### 3.1 Prasyarat

Pastikan tool berikut terpasang sebelum mulai:

```bash
# Cek versi PHP (butuh minimal 8.2)
php -v

# Cek Composer (butuh 2.x)
composer --version

# Cek Node.js (butuh 18+ untuk build asset frontend)
node -v

# Cek MySQL sudah berjalan (via Laragon/XAMPP)
mysql --version
```

Jika belum, instal dulu:
- **Windows**: [Laragon](https://laragon.org) (all-in-one: Apache/Nginx, MySQL, PHP) atau XAMPP.
- **macOS**: [Laravel Herd](https://herd.laravel.com) atau Laravel Sail.
- **Semua OS**: Laravel Sail (Docker) — lihat bagian 3.4.

### 3.2 Cara Pertama: Laravel Installer (direkomendasikan)

```bash
# Install installer Laravel secara global lewat Composer
composer global require laravel/installer

# Buat project baru bernama "perpustakaan"
laravel new perpustakaan
```

Saat dijalankan, `laravel new` akan menanyakan beberapa pilihan. Jawab:

```text
? Would you like to install a starter kit?  -> None
? Which testing framework do you prefer?    -> PHPUnit
? Which database will your application use? -> MySQL
```

Setelah selesai, masuk ke folder project:

```bash
cd perpustakaan
```

> **Catatan lokasi file:** Pada setup Windows dengan Laragon, project diletakkan di `C:\laragon\www\perpustakaan`. Di macOS, biasanya di folder `~/Herd` atau folder pilihanmu. Selalu simpan project di lokasi yang di-serve oleh web server lokal, atau pakai `php artisan serve` (bagian 3.5) supaya tidak perlu pindah-pindah.

### 3.3 Cara Kedua: Composer create-project

Tanpa installer global, cukup jalankan:

```bash
composer create-project laravel/laravel perpustakaan
```

Cara ini langsung membuat project dengan konfigurasi default (tidak ada prompt pilihan). Cocok untuk environment yang tidak ingin meng-install tool global tambahan.

### 3.4 Laravel Sail (Docker) — opsional untuk semua OS

Jika kamu nyaman dengan Docker, Sail menyiapkan PHP, MySQL, Redis, dan lainnya dalam container:

```bash
# Di dalam folder project setelah dibuat
composer require laravel/sail --dev

# Terbitkan file docker-compose.yml
php artisan sail:install

# Jalankan container
./vendor/bin/sail up -d
```

Kelebihannya: environment identik di semua mesin (Windows, macOS, Linux). Kekurangannya: butuh Docker Desktop dan lebih berat dari Laragon/Herd.

### 3.5 Menjalankan Server Pengembangan

```bash
# Jalankan server development bawaan Laravel
php artisan serve

# Output: INFO  Server running on [http://127.0.0.1:8000]
```

Buka **http://localhost:8000** di browser. Kamu akan melihat halaman selamat datang khas Laravel. Ini bukti project kamu hidup.

### 3.6 Verifikasi Instalasi

```bash
# Cek versi Laravel yang terpasang
php artisan --version
# Contoh output: Laravel Framework 11.x.x

# Cek kesehatan environment (PHP, cache, folder writable, dll)
php artisan about
```

Saat sudah nyambung ke MySQL nanti (materi 5), verifikasi koneksi dengan:

```bash
php artisan db:show
```

## 4. Analogi Sederhana

Instalasi Laravel seperti **membuka dapur baru untuk restoran**.

Dulu (PHP Native) kamu harus membangun sendiri dapurnya: pasang kompor, buat meja, beli wajan — semua dari nol. Sekarang, franchise bernama "Laravel" memberimu **dapur yang sudah jadi**: denah ruangan sudah diatur (struktur folder), peralatan sudah disusun di tempatnya masing-masing (bootstrap), bahkan resep-resep standar sudah ada (artisan commands). Tugasmu tinggal memasak.

Namun penting diingat: dapur yang dibuka ini masih **kosong** — belum ada bahan baku (database kosong, belum ada data buku, anggota, atau peminjaman). Bahan-bahan itu akan kita isi di materi-materi berikutnya lewat Migration, Seeder, dan Factory. Ini analogi yang konsisten dengan seluruh roadmap: restoran kita sedang dibangun bertahap.

## 5. Kapan Harus Digunakan & Kasus Penggunaan (Use Cases)

Instalasi ini dilakukan **sekali di awal project**, tetapi wawasan ini dipakai terus:

| Skenario | Keputusan |
|---|---|
| Mulai project baru (`perpustakaan`) | Wajib — jalankan `laravel new` |
| Ingin setup cepat tanpa prompt | `composer create-project laravel/laravel perpustakaan` |
| Tim lintas OS (Windows + macOS + Linux) | Laravel Sail / Docker |
| Developer lokal Windows/macOS yang ingin ringan | Laragon / Herd + `php artisan serve` |
| Butuh environment database terisolasi | Sail + MySQL |

Untuk kasus kita: gunakan Laragon di `C:\laragon\www`, project `perpustakaan` dibuat di `C:\laragon\www\perpustakaan`, lalu jalankan `php artisan serve` untuk development cepat.

## 6. Poin-poin Penting & Best Practices

- **Butuh PHP 8.2+, Composer 2.x** untuk Laravel 11. Cek dengan `php -v` dan `composer --version` sebelum instalasi.
- **Selalu buat project lewat tool resmi** (`laravel new` / `composer create-project`), jangan download zip manual — versi dan dependency-nya bisa tidak konsisten.
- **Gunakan starter kit "None"** saat belajar dasar, supaya fokus ke inti Laravel dulu. (Starter kit seperti Breeze/Livewire bisa ditambahkan belakangan.)
- **Pilih PHPUnit** sebagai testing framework bawaan — ringan dan jadi standar materi ini.
- **Pilih MySQL** sebagai database, sesuai kebutuhan project perpustakaan.
- **Simpan project di lokasi yang aman** — untuk Laragon, `C:\laragon\www\perpustakaan`; pastikan path tidak memakai nama folder yang aneh/ber-spasi.
- **Jangan pernah pindah folder project secara paksa** tanpa menjalankan ulang `composer install` jika vendor hilang. Vendor dan `.env` tidak ikut di-commit ke git (lihat materi 5).
- Setelah instalasi, segera cek `php artisan --version` untuk memastikan framework terpasang dengan benar.

## 7. Kesalahan Umum (Common Pitfalls & Anti-patterns)

| Gejala | Penyebab | Solusi |
|---|---|---|
| `Composer could not find a package` | Versi PHP terlalu lama / Composer ketinggalan | Update PHP minimal 8.2 dan Composer ke 2.x |
| `laravel: command not found` | Installer global belum ada di PATH | Install ulang `composer global require laravel/installer`, pastikan folder `~/.composer/vendor/bin` masuk PATH |
| Halaman tidak terbuka di `localhost:8000` | Server lain memakai port 8000 | Pakai port lain: `php artisan serve --port=8080` |
| Tampil halaman error "whoops" | Ada file yang rusak atau env belum benar | Baca pesan error; cek `.env`; jalankan `php artisan config:clear` |
| Proyek tersimpan di `Desktop` atau `OneDrive` dan lambat | Lokasi project disinkronkan cloud / path terlalu dalam | Simpan di `C:\laragon\www` atau folder lokal lain; hindari folder yang di-sync cloud |
| Lupa pakai `php artisan serve` tapi membuka langsung file | Laravel butuh server (router & entry point), bukan file biasa | Selalu jalankan `php artisan serve` atau gunakan vhost Laragon |

## 8. Soal Latihan & Kunci Jawaban

### Tantangan

1. Buat project baru bernama `perpustakaan` menggunakan Laravel Installer dengan pilihan: starter kit **None**, testing **PHPUnit**, database **MySQL**. Setelah jadi, jalankan server dan pastikan halaman welcome tampil di `http://localhost:8000`.
2. Kamu sudah punya project `perpustakaan`. Tanpa mengubah struktur, jelaskan perintah untuk: (a) melihat versi Laravel yang terpasang, dan (b) menjalankan server di port `9000` karena port 8000 sedang dipakai.

### Jawaban & Pembahasan

**Soal 1**

```bash
# 1. Install installer global (hanya sekali, jika belum ada)
composer global require laravel/installer

# 2. Buat project, jawab prompt: None / PHPUnit / MySQL
laravel new perpustakaan

# 3. Masuk ke folder project
cd perpustakaan

# 4. Jalankan server pengembangan
php artisan serve
# Buka http://localhost:8000

# 5. Verifikasi
php artisan --version
```

**Alur pembahasan:** Perintah `laravel new perpustakaan` menciptakan skeleton project dengan struktur folder standar (materi 4) dan file `.env` berisi konfigurasi default (materi 5). Setelah server jalan, `php artisan serve` menggunakan PHP built-in server dan menyambungkan request ke `public/index.php` sebagai entry point. Halaman welcome adalah view default dari framework — bukti bahwa PHP, Composer, dan Laravel bekerja bersama.

**Soal 2**

```bash
# (a) Cek versi Laravel
php artisan --version

# (b) Jalankan server di port 9000 karena 8000 dipakai
php artisan serve --port=9000
# Akses: http://localhost:9000
```

**Alur pembahasan:** Perintah `php artisan serve` mendukung opsi `--port` dan `--host`. Jika port 8000 bentrok dengan service lain, ganti port cukup dengan menambahkan flag `--port=9000`. Ini penyelesaian paling cepat tanpa perlu menyentuh konfigurasi web server (Apache/Nginx).
