# 4. Struktur Direktori Laravel — Setiap Folder Ada Tujuannya

Project `perpustakaan` yang kamu buat di materi 3 tadi bukan sekadar kumpulan file — setiap folder punya peran khusus dan mengikuti *Convention over Configuration*. Kalau kamu paham peta ini, kamu tidak akan tersesat saat menulis code. Ini materi yang paling sering dipakai sebagai "peta" ketika kita membangun sistem manajemen perpustakaan: Buku, Anggota, dan Peminjaman.

## 1. Penjelasan Singkat & Konsep Dasar

Saat `laravel new perpustakaan` selesai, kamu langsung diberi struktur folder standar. Inti konsepnya: **separation of concerns** — pisahkan tanggung jawab. Kode aplikasi (logic) ada di `app/`, konfigurasi di `config/`, tampilan di `resources/views`, route di `routes/`, dan data/skema di `database/`. Dengan konvensi ini, siapa pun yang pernah belajar Laravel langsung tahu harus melihat ke mana.

Koneksi dengan materi lain:
- **Materi 3 (Instalasi)**: struktur ini adalah *hasil* dari proses instalasi.
- **Materi 5 (.env)**: `.env` yang tadi dibuat dipakai oleh file-file di `config/`.
- **Materi berikutnya (Routing)**: `routes/web.php` adalah pintu masuk request — kamu akan menulis route di sana.

## 2. Fungsi & Kegunaan Utama dalam Laravel

1. **Standarisasi lokasi kode.** Tidak ada lagi "file itu di mana ya?" — Controller selalu di `app/Http/Controllers`, Model selalu di `app/Models`, dsb.
2. **Memudahkan autoloading.** Composer dan Laravel memetakan namespace (`App\...`) langsung ke folder `app/`, jadi `use App\Models\Buku;` otomatis merujuk ke `app/Models/Buku.php`.
3. **Mempercepat orientasi developer baru.** Setiap developer Laravel di dunia tahu struktur ini, sehingga kolaborasi tim jadi cepat.
4. **Memisahkan environment dan konfigurasi.** `.env` (rahasia & spesifik machine) dipisahkan dari `config/` (yang bisa di-commit ke git).

## 3. Contoh Kode & Implementasi (Real-world Example)

Berikut struktur project `perpustakaan` (disarikan dari folder utama Laravel 11):

```text
perpustakaan/
├── app/
│   ├── Http/
│   │   ├── Controllers/        # Logika kontrol request-response
│   │   ├── Middleware/         # Filter request sebelum masuk controller
│   │   └── Requests/           # Validasi form (Form Request)
│   ├── Models/                 # Eloquent Model (Buku, Anggota, Peminjaman)
│   ├── Policies/               # Aturan otorisasi per model
│   ├── Providers/              # Registrasi service (AppServiceProvider, dll)
│   └── (Events, Jobs, Mails)   # Dibuat via artisan saat dibutuhkan
├── bootstrap/
│   └── app.php                 # Inisialisasi aplikasi + registrasi middleware (Laravel 11)
├── config/                     # File konfigurasi (app.php, database.php, dsb.)
├── database/
│   ├── migrations/             # Skema tabel (blueprint database)
│   ├── factories/              # Generator data uji untuk model
│   └── seeders/                # Isi data awal (seeder perpustakaan)
├── public/                     # SATU-SATUNYA folder yang diekspos ke web
│   └── index.php               # Entry point semua request
├── resources/
│   ├── views/                  # Template Blade (tampilan)
│   ├── css/  dan  js/          # Asset frontend (sebelum di-build)
├── routes/
│   ├── web.php                 # Route untuk browser
│   ├── api.php                 # Route untuk API (perlu --api saat make)
│   └── console.php             # Command artisan khusus project
├── storage/
│   ├── app/public/             # File upload yang mau diakses publik
│   ├── framework/              # Cache, session, views (internal)
│   └── logs/                   # File log aplikasi
├── tests/                      # Unit & Feature test (PHPUnit/Pest)
├── .env                        # Konfigurasi environment (JANGAN di-commit)
├── .env.example                # Template .env yang aman untuk di-commit
├── artisan                     # Entry point CLI artisan
├── composer.json               # Definisi dependensi & autoload
└── package.json                # Dependensi frontend (Node)
```

> **Lokasi file standar:** Konsep "setiap folder ada tujuannya" juga berlaku ke file konfigurasi. Contoh yang sering disentuh: `config/app.php` (nama aplikasi, timezone, locale), `config/database.php` (koneksi MySQL), dan `composer.json` (dependensi + namespace `App\`).

**File yang PALING SERING disentuh saat development** (tandai ini):

```text
routes/web.php                 # Semua route aplikasi web
app/Http/Controllers/          # Logika bisnis per halaman/aksi
app/Models/                    # Model Eloquent untuk tabel DB
database/migrations/           # Struktur tabel
resources/views/               # Template Blade
.env                          # Konfigurasi environment lokal
```

### 3.1 Bootstrap app (Laravel 11)

Di Laravel 11, `bootstrap/app.php` menggantikan banyak file `Kernel` dari versi lama. Ini tempat registrasi middleware global:

```php
<?php

use App\Http\Middleware\EnsureUserIsActive; // contoh middleware custom
use Illuminate\Foundation\Application;
use Illuminate\Foundation\Configuration\Exceptions;
use Illuminate\Foundation\Configuration\Middleware;

return Application::configure(basePath: dirname(__DIR__))
    ->withRouting(
        web: __DIR__.'/../routes/web.php',
        api: __DIR__.'/../routes/api.php',
        commands: __DIR__.'/../routes/console.php',
    )
    ->withMiddleware(function (Middleware $middleware) {
        // daftarkan middleware global di sini
        $middleware->append(EnsureUserIsActive::class);
    })
    ->withExceptions(function (Exceptions $exceptions) {
        // kustomisasi handling exception di sini
    })->create();
```

### 3.2 Entry point public/index.php

Semua request web masuk lewat file ini (via `php artisan serve`, Apache, atau Nginx). Ia memuat autoloader Composer dan menyalakan aplikasi:

```php
<?php

use Illuminate\Http\Request;

define('LARAVEL_START', microtime(true));

// Autoload dependensi Composer
require __DIR__.'/../vendor/autoload.php';

// Boot aplikasi (membaca .env, config, dsb.)
$app = require_once __DIR__.'/../bootstrap/app.php';

// Teruskan request ke framework
$kernel = $app->make(Illuminate\Contracts\Http\Kernel::class);
$response = $kernel->handle($request = Request::capture())
    ->send();

$kernel->terminate($request, $response);
```

> **Penting:** Di folder `public/` ini lah `storage/app/public` di-symlink supaya file upload bisa diakses browser. Jalankan `php artisan storage:link` saat butuh upload gambar buku.

## 4. Analogi Sederhana

Struktur direktori Laravel seperti **denah dapur restoran**:

- **`routes/web.php`** = daftar menu + pelayan yang menerima pesanan (di mana request diarahkan).
- **`app/Http/Controllers`** = koki yang memasak hidangan sesuai pesanan.
- **`app/Models`** = rak/gudang bahan makanan yang terorganisir (Buku, Anggota, Peminjaman).
- **`resources/views`** = area penyajian di piring (tampilan Blade).
- **`database/migrations`** = blueprint renovasi dapur (skema tabel).
- **`database/seeders` & `factories`** = stok awal gudang (data awal & data uji).
- **`config/`** = buku resep & pengaturan oven standar.
- **`public/index.php`** = pintu masuk tunggal pelanggan ke restoran.
- **`.env`** = kunci gudang & data rahasia yang cuma dimiliki pemilik restoran (jangan disebar).

Denah ini sama di semua franchise Laravel — itulah *convention*. Kamu tinggal belajar satu kali, dan paham semua project Laravel.

## 5. Kapan Harus Digunakan & Kasus Penggunaan (Use Cases)

- **Setiap fitur baru** — selalu tahu file mana yang disentuh. Ingin halaman daftar buku? Ubah `routes/web.php`, buat Controller, tambah Model, ubah View.
- **Menambah tabel baru** (mis. tabel `peminjamans`) — buat di `database/migrations`, isi data awal di `database/seeders`.
- **Menambah validasi** — buat Form Request di `app/Http/Requests`.
- **Menambah aturan akses** (super_admin boleh hapus, anggota tidak) — buat di `app/Policies`.
- **Menambah logika di belakang layar** — buat Job di `app/Jobs`, Event/Listener di `app/Events` & `app/Listeners`.

Singkatnya: **pahami peta ini sebelum menulis baris kode apa pun**, dan gunakan `php artisan make:...` (materi 6) supaya file otomatis diletakkan di lokasi yang benar.

## 6. Poin-poin Penting & Best Practices

- **Selalu buat file lewat artisan**, bukan manual copy — namespace, class, dan lokasinya dijamin benar. Contoh: `php artisan make:model Buku -mfs`.
- **Jangan mengubah nama folder bawaan** (kecuali paham konsekuensinya). Konvensi ini yang membuat autoload dan framework berfungsi.
- **Namespace penting**: folder `app/Models/Buku.php` punya namespace `App\Models`; gunakan `use App\Models\Buku;` di controller.
- **`public/index.php` jangan diedit** tanpa kebutuhan khusus — ia sudah dioptimalkan.
- **Jangan menyimpan file sensitive di `public/`** — simpan di `storage/` atau `config/` yang dijaga.
- **`resources/views`** untuk Blade, jangan taruh HTML mentah di Controller.
- **`bootstrap/app.php`** adalah satu-satunya tempat registrasi middleware global di Laravel 11.
- **Jangan commit `.env`** (materi 5). Commit `.env.example` saja.

## 7. Kesalahan Umum (Common Pitfalls & Anti-patterns)

| Gejala | Penyebab | Solusi |
|---|---|---|
| `Class "App\Models\Buku" not found` | File dibuat manual di folder salah / namespace salah | Hapus file, buat ulang dengan `php artisan make:model Buku` |
| Memindahkan Controller tapi error | Namespace tidak diupdate | Sesuaikan `namespace` di file, atau buat ulang via artisan |
| Halaman 404 untuk halaman yang sudah dibuat | Route tidak ditambahkan di `routes/web.php` | Tambahkan route; cek dengan `php artisan route:list` |
| Upload gambar tidak muncul | Belum symlink `storage` | Jalankan `php artisan storage:link` |
| Edit view tapi tidak berubah | View di-cache | `php artisan view:clear` |
| Meletakkan logic di View/Blade | Salah konsep separation of concerns | Pindahkan logika ke Controller/Model; Blade hanya untuk tampilan |

## 8. Soal Latihan & Kunci Jawaban

### Tantangan

1. Sebutkan file atau folder tempat kamu meletakkan masing-masing hal berikut pada project `perpustakaan`: (a) route halaman daftar buku, (b) tampilan Blade daftar buku, (c) Model `Buku`, (d) skema tabel `bukus`, (e) validasi form tambah buku.
2. Mengapa `public/` adalah satu-satunya folder yang diekspos ke web, dan apa isi file `public/index.php` secara konsep?

### Jawaban & Pembahasan

**Soal 1**

```text
(a) routes/web.php                  -> Route::get('/bukus', ...)
(b) resources/views/bukus/index.blade.php
(c) app/Models/Buku.php             -> namespace App\Models
(d) database/migrations/xxxx_create_bukus_table.php
(e) app/Http/Requests/StoreBukuRequest.php
```

**Alur pembahasan:** Setiap bagian punya lokasi baku karena konvensi. `routes/web.php` memetakan URL ke Controller; Controller memanggil Model (data) dan me-return View (tampilan). Migration mendefinisikan struktur tabel, dan Form Request menampung aturan validasi — bersih dan mudah dirawat.

**Soal 2**

Folder `public/` adalah satu-satunya yang diekspos web demi keamanan: hanya file yang benar-benar butuh diakses browser (CSS, JS, gambar) dan `index.php` yang ditaruh di sana. Seluruh logika aplikasi (`app/`, `config/`, `database/`) disembunyikan dari akses langsung. `public/index.php` bekerja sebagai **front controller**: menerima semua request, memuat autoloader Composer, me-boot aplikasi lewat `bootstrap/app.php`, lalu meneruskan request ke framework yang akhirnya menghasilkan respons.

**Alur pembahasan:** Pola front controller inilah yang membuat semua URL (`/buku`, `/anggota`, `/peminjaman`) melewati satu titik masuk yang sama — fondasi dari bagaimana Routing (materi berikutnya) bekerja.
