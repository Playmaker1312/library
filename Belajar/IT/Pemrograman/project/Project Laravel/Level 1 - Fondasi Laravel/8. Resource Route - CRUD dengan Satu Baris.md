# 8. Resource Route — CRUD dengan Satu Baris

Sistem perpustakaan tentu butuh operasi CRUD: menambah buku, melihat katalog, mengubah data, menghapus. Menulis tujuh route secara manual itu membosankan dan rawan typo. Laravel menyediakan `Route::resource()` yang membuat seluruh route CRUD hanya dengan satu baris. Mari kita bedah.

## 1. Penjelasan Singkat & Konsep Dasar

`Route::resource('buku', BukuController::class)` otomatis mendaftarkan **7 route** untuk operasi CRUD standar terhadap resource `buku`, masing-masing dengan nama dot-notation yang sudah ditentukan: `buku.index`, `buku.create`, `buku.store`, `buku.show`, `buku.edit`, `buku.update`, `buku.destroy`.

Konsep ini menyambung langsung dari materi sebelumnya: named route (`buku.index`) dan parameter `{id}` sekarang dikelola Laravel secara otomatis. Di materi berikutnya kita akan membungkusnya ke dalam route group agar lebih rapi, dan di Level 2 kita akan mengisi controller-nya dengan logika CRUD yang sesungguhnya.

Dua versi lain yang perlu dikenal:

- `Route::apiResource('buku', BukuController::class)` -- untuk API, hanya menghasilkan 5 route (tanpa `create` dan `edit`).
- `Route::apiResource` sangat cocok ketika aplikasi dipakai sebagai backend yang dikonsumsi aplikasi lain / mobile.

## 2. Fungsi & Kegunaan Utama dalam Laravel

`Route::resource` memecahkan masalah-masalah ini:

1. **Menghilangkan boilerplate** -- tujuh baris route berubah menjadi satu baris.
2. **Konvensi yang konsisten** -- nama route, URI, dan method controller sudah distandarkan, sehingga seluruh tim memakai pola yang sama.
3. **Mudah dipangkas** -- dengan `->only()` / `->except()` kita memilih route mana yang benar-benar dibutuhkan.
4. **Menjaga keamanan form** -- route `store`, `update`, `destroy` otomatis terikat pada method `POST`, `PUT`, `DELETE` yang tidak bisa dipanggil lewat `GET`.
5. **Siap untuk route group** -- `resource` bisa dibungkus dalam group prefix/middleware (materi berikutnya) untuk area admin.

## 3. Contoh Kode & Implementasi (Real-world Example)

File: **`routes/web.php`**

```php
<?php

use Illuminate\Support\Facades\Route;
use App\Http\Controllers\BukuController;
use App\Http\Controllers\AnggotaController;
use App\Http\Controllers\PeminjamanController;

// ===== Resource lengkap: 7 route CRUD =====
// Bisa: create, edit, store, update, destroy
Route::resource('buku', BukuController::class);

// ===== Resource anggota TANPA route create & edit =====
// Bayangkan daftar anggota dikelola lewat API mobile, bukan form web.
Route::resource('anggota', AnggotaController::class)
    ->only(['index', 'show', 'store', 'update', 'destroy']);

// ===== Resource peminjaman HANYA beberapa route =====
// Admin hanya perlu mencatat dan menghapus peminjaman di halaman web.
Route::resource('peminjaman', PeminjamanController::class)
    ->except(['create', 'edit']);

// ===== Versi API (jika aplikasi punya mobile client) =====
Route::apiResource('anggota', AnggotaController::class);
```

### Tabel mapping yang dihasilkan `Route::resource('buku', BukuController::class)`

| Method HTTP | URI | Action (Controller) | Route Name |
|---|---|---|---|
| GET | `/buku` | index | `buku.index` |
| GET | `/buku/create` | create | `buku.create` |
| POST | `/buku` | store | `buku.store` |
| GET | `/buku/{buku}` | show | `buku.show` |
| GET | `/buku/{buku}/edit` | edit | `buku.edit` |
| PUT/PATCH | `/buku/{buku}` | update | `buku.update` |
| DELETE | `/buku/{buku}` | destroy | `buku.destroy` |

Perhatikan: parameter yang dipakai adalah `{buku}`, bukan `{id}`, karena Laravel otomatis memakai nama resource sebagai nama parameter. Parameter ini nantinya menjadi instance model `Buku` melalui route model binding (dibahas di Level 2).

### Nested resource: peminjaman milik anggota

File: **`routes/web.php`**

```php
// /anggota/{anggota}/peminjaman  ->  daftar peminjaman milik satu anggota
Route::resource('anggota.peminjaman', PeminjamanController::class)
    ->only(['index', 'create', 'store']);
```

Route di atas menghasilkan nama seperti `anggota.peminjaman.index`, `anggota.peminjaman.create`, dan `anggota.peminjaman.store`.

## 4. Analogi Sederhana

Kembali ke restoran kita. Operasi CRUD itu seperti siklus hidup sebuah menu di restoran:

- **index** = koki menampilkan daftar seluruh menu yang tersedia
- **create** = pelayan mengambil formulir pesanan kosong untuk menu baru
- **store** = formulir diisi dan disimpan ke daftar menu (POST)
- **show** = pelayan menyajikan detail satu menu tertentu
- **edit** = pelayan membawa formulir yang sudah terisi untuk diperbaiki
- **update** = perbaikan disimpan (PUT/PATCH)
- **destroy** = menu dihapus dari daftar (DELETE)

`Route::resource` adalah kepala restoran yang otomatis mencetak 7 posisi karyawan sekaligus dengan jobdesk yang sudah distandarkan. Kalau restoran hanya butuh menyajikan menu tanpa perlu menambah menu baru, kepala restoran cukup memerintahkan `->only(['index', 'show'])` dan karyawan yang lain tidak perlu direkrut.

## 5. Kapan Harus Digunakan & Kasus Penggunaan (Use Cases)

| Skenario | Rekomendasi |
|---|---|
| Kelola katalog buku dengan form CRUD penuh | `Route::resource('buku', BukuController::class)` |
| Kelola anggota yang juga didaftarkan dari aplikasi mobile | `->except(['create', 'edit'])` atau `Route::apiResource` |
| Admin hanya bisa melihat & menghapus peminjaman | `->only(['index', 'show', 'destroy'])` |
| Melihat peminjaman milik satu anggota tertentu | Nested resource `anggota.peminjaman` |
| Backend API murni untuk aplikasi mobile | `Route::apiResource` |

Resource route **wajib** dipakai untuk entitas domain yang punya operasi CRUD penuh (Buku, Anggota, Peminjaman di aplikasi kita). Untuk halaman non-CRUD (beranda, tentang) tetap pakai `Route::get()` biasa.

## 6. Poin-poin Penting & Best Practices

- Gunakan `Route::resource` untuk entitas CRUD, dan `Route::get` biasa untuk halaman statis/seksi.
- **Nama resource harus plural dan kebab-case** saat mengandung banyak kata: `Route::resource('kategori-buku', ...)`.
- **Pangkas route yang tidak dipakai** dengan `->only()` atau `->except()` -- ini membuat `route:list` bersih dan mempersempit permukaan serangan.
- **Parameter route memakai nama resource** (`{buku}`), bukan `{id}`. Jangan menulis method controller dengan parameter `$id` yang salah urut.
- **`Route::apiResource` untuk API** (tanpa `create`/`edit`) dan menghasilkan nama tanpa halaman form.
- **Verifikasi selalu**:
  ```bash
  php artisan route:list
  php artisan route:list --path=buku
  ```
- Route model binding otomatis akan mengisi parameter `{buku}` dengan instance `Buku` saat kita menulis `show(Buku $buku)` di controller (dibahas di Level 2).
- Materi berikutnya: bungkus resource admin dengan route group `->prefix('admin')->name('admin.')` agar jadi `admin.buku.*`.

## 7. Kesalahan Umum (Common Pitfalls & Anti-patterns)

1. **Menambahkan route resource duplikat**
   - Menulis `Route::resource('buku', ...)` dua kali atau menambah `Route::get('/buku', ...)` terpisah akan membuat route duplikat yang membingungkan. Periksa dengan `php artisan route:list`.

2. **Route `store` tidak pernah terpanggil dari form**
   - Form HTML hanya mendukung `GET` dan `POST`. Pastikan form memakai `@method('PUT')` / `@method('DELETE')` di Blade agar request dianggap sebagai PUT/DELETE.

3. **Lupa meng-import controller**
   - `use App\Http\Controllers\BukuController;` wajib ada di `routes/web.php`.

4. **Method controller tidak sesuai konvensi**
   - Resource mengharapkan method `index`, `create`, `store`, `show`, `edit`, `update`, `destroy`. Jika menulis nama lain, Laravel melempar error `Target class [..] does not exist` atau `Method not found`.

5. **Menggunakan `{id}` manual untuk resource**
   - Jangan tulis `Route::get('/buku/{id}', ...)` tambahan di samping resource; biarkan Laravel memakai `{buku}`. Route tambahan justru menimbulkan duplikasi dan kebingungan.

6. **`->only()` dan `->except()` tidak boleh dipakai bersamaan**
   - Pilih salah satu; memakai keduanya akan melempar error `Method does not exist`.

7. **Nested resource terlalu dalam**
   - `anggota.peminjaman.buku` (tiga level) sering berlebihan dan membuat route sulit dibaca. Batasi hingga dua level.

## 8. Soal Latihan & Kunci Jawaban

### Tantangan

1. Di aplikasi perpustakaan, daftarkan resource `buku`, `anggota`, dan `peminjaman`. Untuk `peminjaman`, admin tidak boleh punya halaman `create` dan `edit` (peminjaman dicatat lewat proses lain). Verifikasi hasilnya dengan `php artisan route:list`.

2. Buat nested resource sehingga admin bisa melihat daftar peminjaman milik satu anggota, dengan URL `/anggota/{anggota}/peminjaman`.

### Jawaban & Pembahasan

**Soal 1 -- tiga resource:**

```php
use App\Http\Controllers\BukuController;
use App\Http\Controllers\AnggotaController;
use App\Http\Controllers\PeminjamanController;

// Full CRUD untuk buku dan anggota
Route::resource('buku', BukuController::class);
Route::resource('anggota', AnggotaController::class);

// Tanpa create & edit -- peminjaman tidak dibuat lewat form biasa
Route::resource('peminjaman', PeminjamanController::class)
    ->except(['create', 'edit']);
```

**Pembahasan:** Baris pertama dan kedua masing-masing menghasilkan 7 route. Baris ketiga menghasilkan 5 route: `peminjaman.index`, `peminjaman.show`, `peminjaman.store`, `peminjaman.update`, `peminjaman.destroy`. Jalankan `php artisan route:list --path=peminjaman` untuk melihat hasilnya. Route `create` dan `edit` dihilangkan karena peminjaman dicatat melalui alur lain, bukan form admin.

**Soal 2 -- nested resource:**

```php
// /anggota/{anggota}/peminjaman -> hanya index & create
Route::resource('anggota.peminjaman', PeminjamanController::class)
    ->only(['index', 'create', 'store']);
```

**Pembahasan:** Route ini menghasilkan tiga route:

| Method HTTP | URI | Route Name |
|---|---|---|
| GET | `/anggota/{anggota}/peminjaman` | `anggota.peminjaman.index` |
| GET | `/anggota/{anggota}/peminjaman/create` | `anggota.peminjaman.create` |
| POST | `/anggota/{anggota}/peminjaman` | `anggota.peminjaman.store` |

**Alur:** Saat pengguna membuka `/anggota/3/peminjaman`, Laravel mencocokkan nested resource, mengisi `{anggota}` = 3, lalu memanggil `PeminjamanController@index`. Di dalam controller, kita bisa mengambil peminjaman yang dimiliki anggota id 3. Verifikasi dengan `php artisan route:list --name=peminjaman` untuk melihat semua route peminjaman (standalone maupun nested).
