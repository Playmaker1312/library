# 16. Membuat dan Menjalankan Migration

Migration adalah cara Laravel mengelola struktur database memakai kode PHP alih-alih SQL manual. Di Level 2 kamu menaruh data buku di dalam array di controller — sekarang saatnya "pindah rumah": data akan tinggal di tabel database yang dibuat dan dipelihara lewat migration. Materi ini adalah fondasi sebelum masuk ke Seeder (17) dan Eloquent ORM (18), jadi pahami baik-baik blueprint dan alur migrate/rollback-nya.

## 1. Penjelasan Singkat & Konsep Dasar

**Migration = version control untuk skema database.** Setiap file migration merepresentasikan satu "riwayat perubahan" struktur — seperti git commit, tapi khusus untuk tabel database. Semua anggota tim punya file yang sama, sehingga struktur database di mesin siapa pun bisa dibangun ulang dengan perintah yang sama.

Hubungan dengan materi lain:

- **Level 2 (Controller hardcode)**: data buku hidup di array `$bukus` di dalam method controller. Masalahnya, data itu statis, tidak tersimpan, dan tidak bisa di-query. Migration memindahkan *struktur penyimpanannya* ke database — data nyatanya nanti diisi lewat Seeder (materi 17).
- **Materi 17 (Seeder & Factory)**: seeder mengisi tabel yang sudah dibuat migration dengan data awal. Migrasi dulu, baru seeder — urutan ini tidak bisa dibalik.
- **Materi 18 (Eloquent)**: model Eloquent membaca/menulis tabel. Model butuh tabel yang sudah ada; jadi migration (16) → seeder/factory (17) → model Eloquent (18) adalah alur alami.
- **Materi 16 ini sendiri** juga menyinggung foreign key antara `peminjaman`, `buku`, dan `anggota` — relasi yang nanti benar-benar "dihidupkan" lewat Eloquent.

## 2. Fungsi & Kegunaan Utama dalam Laravel

1. **Version control database** — skema tersimpan sebagai file teks yang bisa di-commit ke git. Bukan lagi "siapa yang punya file SQL terbaru?".
2. **Bisa dibangun ulang (reproducible)** — tim baru, laptop baru, atau server staging tinggal jalankan `php artisan migrate` dan struktur langsung jadi.
3. **Hindari SQL manual yang mudah melenceng** — kamu menulis blueprint PHP (`$table->string('judul', 200)`) yang konsisten, bukan copy-paste `CREATE TABLE` yang bisa beda antar developer.
4. **Mudah di-rollback** — `migrate:rollback` membatalkan perubahan terakhir dengan aman, berkat method `down()`.
5. **Kolaborasi tim yang rapi** — tiap orang menambah migration baru (bukan mengubah file lama), jadi tidak ada konflik "saya tambah kolom tapi file kamu belum".

## 3. Contoh Kode & Implementasi (Real-world Example)

Kita bangun 3 tabel untuk perpustakaan: `buku`, `anggota`, dan `peminjaman` (dengan foreign key ke dua tabel pertama). Buat file-nya dulu lewat Artisan:

```bash
# Nama file di-pecah menjadi class migration. Contoh:
# create_buku_table   -> CreateBukuTable
# create_anggota_table-> CreateAnggotaTable
# create_peminjaman_table -> CreatePeminjamanTable

php artisan make:migration create_buku_table
php artisan make:migration create_anggota_table
php artisan make:migration create_peminjaman_table
```

File akan muncul di `database/migrations/` dengan prefix timestamp. Isi file satu per satu di bawah.

### 3.1 Migration tabel `buku`

```php
<?php

use Illuminate\Database\Migrations\Migration;
use Illuminate\Database\Schema\Blueprint;
use Illuminate\Support\Facades\Schema;

return new class extends Migration
{
    public function up(): void
    {
        Schema::create('buku', function (Blueprint $table) {
            // Primary key auto-increment
            $table->id();

            // string() -> VARCHAR; parameter kedua adalah panjang maksimum
            $table->string('judul', 200);               // judul buku
            $table->char('isbn', 13)->unique()->nullable(); // ISBN 13 digit, unik tapi boleh kosong
            $table->string('pengarang', 100);           // nama pengarang
            $table->string('penerbit', 100)->nullable();// penerbit boleh kosong
            $table->year('tahun');                      // tahun terbit, tipe YEAR
            $table->decimal('harga', 12, 2)->default(0); // harga: 12 digit total, 2 desimal
            $table->unsignedInteger('stok')->default(0); // stok tidak boleh negatif
            $table->string('kategori', 100)->default('umum');
            $table->text('deskripsi')->nullable();      // teks panjang, boleh kosong
            $table->string('sampul')->nullable();       // path gambar sampul, optional

            // Composite index: sering difilter pakai kategori + tahun bersama-sama
            $table->index(['kategori', 'tahun'], 'idx_buku_kategori_tahun');

            // created_at & updated_at otomatis dikelola Eloquent
            $table->timestamps();

            // deleted_at untuk soft delete (buku "dihapus" tapi tetap tersimpan)
            $table->softDeletes();
        });
    }

    public function down(): void
    {
        // Rollback: tabel dibuang. Urutan terbalik dari up().
        Schema::dropIfExists('buku');
    }
};
```

### 3.2 Migration tabel `anggota`

```php
<?php

use Illuminate\Database\Migrations\Migration;
use Illuminate\Database\Schema\Blueprint;
use Illuminate\Support\Facades\Schema;

return new class extends Migration
{
    public function up(): void
    {
        Schema::create('anggota', function (Blueprint $table) {
            $table->id();
            $table->string('nama', 100);
            $table->string('email', 150)->unique();      // email anggota, tidak boleh dobel
            $table->string('telepon', 20)->nullable();
            $table->text('alamat')->nullable();

            // Enum kolom status: pilihan terbatas (aktif / nonaktif)
            $table->enum('status', ['aktif', 'nonaktif'])->default('aktif');

            $table->timestamps();
        });
    }

    public function down(): void
    {
        Schema::dropIfExists('anggota');
    }
};
```

### 3.3 Migration tabel `peminjaman` (dengan foreign key)

```php
<?php

use Illuminate\Database\Migrations\Migration;
use Illuminate\Database\Schema\Blueprint;
use Illuminate\Support\Facades\Schema;

return new class extends Migration
{
    public function up(): void
    {
        Schema::create('peminjaman', function (Blueprint $table) {
            $table->id();

            // foreignId() + constrained() membuat kolom + foreign key sekaligus.
            // constrained('buku') memetakan ke tabel "buku", kolom "id".
            $table->foreignId('buku_id')
                  ->constrained('buku')
                  ->cascadeOnUpdate()    // id buku berubah? ikut ter-update.
                  ->restrictOnDelete();  // buku tidak bisa dihapus jika masih dipinjam.

            $table->foreignId('anggota_id')
                  ->constrained('anggota')
                  ->cascadeOnUpdate()
                  ->restrictOnDelete();  // anggota tidak bisa dihapus jika masih punya riwayat pinjam.

            $table->date('tanggal_pinjam');     // kapan dipinjam
            $table->date('batas_kembali');      // batas wajib kembali (biasanya +7 hari)
            $table->date('tanggal_kembali')->nullable(); // kapan benar-benar dikembalikan
            $table->decimal('denda', 12, 2)->default(0); // denda keterlambatan

            // Status pinjaman: enum (belum_selesai / selesai)
            $table->enum('status', ['belum_selesai', 'selesai'])->default('belum_selesai');

            // Index biasa untuk kolom yang sering difilter (mis. laporan status)
            $table->index('status');

            $table->timestamps();
        });
    }

    public function down(): void
    {
        Schema::dropIfExists('peminjaman');
    }
};
```

### 3.4 Menjalankan & mengelola migration

```bash
# 1. Jalankan semua migration yang belum berjalan (tabel jadi)
php artisan migrate

# 2. Lihat status tiap migration (Ran / Pending)
php artisan migrate:status

# 3. Batalkan batch migration terakhir (biasanya pakai down())
php artisan migrate:rollback

# 4. Reset semua tabel + jalankan ulang dari nol (data HILANG)
php artisan migrate:fresh

# 5. Reset + isi data seeder langsung (HANYA untuk development)
php artisan migrate:fresh --seed
```

Alur yang paling sering dipakai saat mengembangkan: `php artisan make:migration ...` → isi `up()`/`down()` → `php artisan migrate` → cek `migrate:status`.

## 4. Analogi Sederhana

Anggap database perpustakaan adalah **dapur restoran**, dan migration adalah **blueprint renovasi dapur**.

- **Migration = blueprint renovasi dapur** — ini dokumen kontrak yang jelas: "di sini ada kompor (tabel buku), di sini lemari penyimpanan (tabel anggota)". Blueprint ini bisa di-commit ke git, bisa dibangun ulang oleh cabang restoran mana pun dengan menekan satu tombol (`php artisan migrate`), dan bisa dibatalkan (`migrate:rollback`) kalau ternyata desainnya salah — cukup ikuti langkah sebaliknya (`down()`).
- **Seeder (materi 17) = stok awal gudang** — bahan dasar yang harus selalu ada begitu cabang baru buka. Setelah dapur jadi (migrate), tinggal isi raknya.
- **Factory (materi 17) = uji coba bahan masakan dalam jumlah banyak** — koki melatih tangan dengan bahan palsu dalam jumlah besar, tidak untuk disajikan ke pelanggan.

Koneksi dengan Level 2: dulu resep sementara ditulis tangan di secarik kertas (array hardcode di controller) — cepat tapi berantakan dan tidak bisa dibagikan. Sekarang kamu pindah ke **gudang terpusat (database)** yang dibangun dengan **blueprint (migration)**. Controller nanti cukup "memesan" dari gudang via Eloquent (materi 18), bukan lagi mengarang sendiri di tangan.

## 5. Kapan Harus Digunakan & Kasus Penggunaan (Use Cases)

| Situasi | Tindakan |
|---|---|
| Membuat tabel baru (`buku`, `anggota`, `peminjaman`) | `php artisan make:migration create_buku_table` lalu isi `Schema::create()` |
| Menambah kolom di tabel yang sudah ada | `php artisan make:migration add_kode_anggota_to_anggota_table` lalu `Schema::table()` |
| Mengubah tipe kolom / menambah constraint | Migration baru dengan `$table->string('judul')->change()` (butuh `doctrine/dbal` di versi lama) |
| Menambahkan foreign key antar tabel | `foreignId('buku_id')->constrained('buku')` |
| Proyek baru / laptop baru | Cukup `php artisan migrate` — struktur langsung jadi |
| Ingin menguji dari nol di development | `php artisan migrate:fresh --seed` |
| Ada tabel yang sering difilter gabungan kolom | Tambah composite index (`$table->index(['kategori','tahun'])`) |
| Ingin "hapus" buku tapi tetap simpan datanya | `softDeletes()` + `use SoftDeletes` di model |

## 6. Poin-poin Penting & Best Practices

- **Konvensi penamaan tabel**: plural & snake_case — `buku`, `anggota`, `peminjaman`. Laravel otomatis mencari `Buku` → `bukus`, tapi kamu bisa set `protected $table` di model bila perlu.
- **Konvensi penamaan kolom**: snake_case — `tanggal_pinjam`, `batas_kembali`, `buku_id`.
- **Migration selalu dibentuk dengan blueprint**, jangan menulis raw SQL di dalam `up()` kecuali sangat terpaksa.
- **`down()` harus selalu lengkap** — membalik apa yang dibuat `up()`. Kalau `up()` membuat tabel, `down()` menghapusnya; kalau `up()` menambah kolom, `down()` menghapus kolom itu.
- **Jangan pernah mengubah migration yang sudah dijalankan (dan sudah di-commit)**. Buat migration baru. Tim lain tidak akan melihat edit file lama, sehingga struktur mereka melenceng.
- **Index untuk kolom yang sering difilter** (`status`, `kategori`, `tahun`). Foreign key juga otomatis diberi index oleh `constrained()` — jangan dihapus.
- **Foreign key yang tepat untuk domain peminjaman**: `restrictOnDelete()` mencegah buku/anggota terhapus saat masih ada riwayat pinjam, `cascadeOnUpdate()` menjaga relasi tetap konsisten saat id berubah.
- **Perintah wajib**: `make:migration`, `migrate`, `migrate:status`, `migrate:rollback`, `migrate:fresh`, `migrate:fresh --seed`.
- **`migrate:fresh --seed` HANYA di development** — di produksi ia menghapus seluruh data.
- **Urutan pembuatan migration** mengikuti timestamp di nama file: `buku` dan `anggota` harus dibuat sebelum `peminjaman` karena foreign key butuh tabel parent lebih dulu.
- **Gunakan `nullable()` untuk kolom opsional** dan `default()` untuk nilai bawaan, agar data lama tidak patah saat kolom baru ditambahkan.

## 7. Kesalahan Umum (Common Pitfalls & Anti-patterns)

| Gejala | Penyebab | Solusi |
|---|---|---|
| `SQLSTATE[HY000]: General error: 1215 Cannot add foreign key constraint` | Tabel child dibuat sebelum parent, atau tipe kolom tidak cocok | Pastikan urutan: `buku` & `anggota` dulu, lalu `peminjaman`. Cek nama tabel di `constrained('buku')` persis sama |
| `SQLSTATE[42S22]: Column not found` saat migrate | Kolom yang direferensikan belum ada / typo | Cek nama kolom di migration parent, pastikan `id()` ada |
| `migrate` error di tengah batch | Ada migration lama yang diedit setelah dijalankan | Jangan edit migration yang sudah Ran — buat migration baru |
| Foreign key `Delete constraint fails` saat hapus buku | `restrictOnDelete()` sengaja menahan karena masih ada peminjaman | Hapus/buat selesai peminjaman terkait dulu, atau ganti ke `cascadeOnDelete()` bila sesuai aturan bisnis |
| Lupa menambahkan index pada kolom yang sering difilter | Query lambat di data besar | Tambahkan `$table->index('status')` atau composite index |
| `down()` tidak lengkap → rollback gagal | `up()` menambah kolom tapi `down()` tidak menghapusnya | Uji: jalankan `migrate`, lalu `migrate:rollback`, pastikan sukses |
| `Class "X" not found` saat migrate | Migration dibuat manual tanpa `use` yang benar | Selalu pakai `php artisan make:migration` |
| Migration tidak muncul di `migrate:status` padahal file ada | File tanpa timestamp/unik, atau di folder salah | Buat ulang via `make:migration`, jangan menyalin file manual |

**Troubleshooting cepat:** ketika error SQL muncul, jalankan `php artisan migrate --pretend` untuk melihat query SQL yang akan dieksekusi. Kalau stuck di `migrate` lama, `php artisan migrate:status` menunjukkan batch mana yang bermasalah, lalu `migrate:rollback --step=1` untuk mundur selangkah.

## 8. Soal Latihan & Kunci Jawaban

### Tantangan

1. Buat migration tabel `peminjaman` yang lengkap: foreign key ke `buku` dan `anggota` (buku/anggota tidak boleh dihapus saat masih ada riwayat pinjam, tapi mengikuti perubahan id), kolom `tanggal_pinjam`, `batas_kembali`, `tanggal_kembali` (nullable), `denda` decimal, `status` enum, plus index pada `status`. Lalu jalankan `migrate` dan verifikasi.
2. Kamu ingin menambahkan kolom `kode_anggota` (string unik, nullable) ke tabel `anggota` yang sudah terlanjur dijalankan. Tulis langkah yang benar, termasuk nama migration dan isi `up()`/`down()`-nya.

### Jawaban & Pembahasan

**Soal 1**

```bash
php artisan make:migration create_peminjaman_table
```

```php
<?php

use Illuminate\Database\Migrations\Migration;
use Illuminate\Database\Schema\Blueprint;
use Illuminate\Support\Facades\Schema;

return new class extends Migration
{
    public function up(): void
    {
        Schema::create('peminjaman', function (Blueprint $table) {
            $table->id();

            $table->foreignId('buku_id')
                  ->constrained('buku')
                  ->cascadeOnUpdate()
                  ->restrictOnDelete();

            $table->foreignId('anggota_id')
                  ->constrained('anggota')
                  ->cascadeOnUpdate()
                  ->restrictOnDelete();

            $table->date('tanggal_pinjam');
            $table->date('batas_kembali');
            $table->date('tanggal_kembali')->nullable();
            $table->decimal('denda', 12, 2)->default(0);
            $table->enum('status', ['belum_selesai', 'selesai'])->default('belum_selesai');
            $table->index('status');

            $table->timestamps();
        });
    }

    public function down(): void
    {
        Schema::dropIfExists('peminjaman');
    }
};
```

```bash
php artisan migrate
php artisan migrate:status
```

**Alur pembahasan:** `foreignId('buku_id')` membuat kolom `buku_id` bertipe sama dengan `id` di tabel `buku`, dan `constrained('buku')` sekaligus menambahkan foreign key + index. `restrictOnDelete()` melindungi data riwayat: buku/anggota tidak bisa dihapus selama masih ada baris di `peminjaman` yang mereferensinya. `cascadeOnUpdate()` menjaga relasi tetap valid jika primary key parent berubah. Kolom tanggal_kembali nullable karena belum tentu buku sudah dikembalikan. `migrate:status` dipakai untuk memastikan ketiga tabel (dan urutan batch-nya) benar.

**Soal 2**

```bash
# Nama migration menandakan "tambah kolom ke tabel yang sudah ada"
php artisan make:migration add_kode_anggota_to_anggota_table
```

```php
<?php

use Illuminate\Database\Migrations\Migration;
use Illuminate\Database\Schema\Blueprint;
use Illuminate\Support\Facades\Schema;

return new class extends Migration
{
    public function up(): void
    {
        // Pakai Schema::table() BUKAN Schema::create()
        Schema::table('anggota', function (Blueprint $table) {
            $table->string('kode_anggota', 20)->unique()->nullable()->after('id');
        });
    }

    public function down(): void
    {
        Schema::table('anggota', function (Blueprint $table) {
            $table->dropUnique(['kode_anggota']);
            $table->dropColumn('kode_anggota');
        });
    }
};
```

```bash
php artisan migrate
```

**Alur pembahasan:** karena tabel `anggota` sudah pernah dijalankan, kamu **tidak boleh** mengedit file migration lama. Buat migration baru dengan `Schema::table()` (bukan `Schema::create()`). `nullable()` penting agar baris yang sudah ada tidak gagal karena kolom baru tanpa nilai. Di `down()` hapus dulu constraint `unique`-nya (agar tidak error "index masih dipakai"), baru drop kolomnya — kebalikan dari urutan `up()`. Pola ini menjaga riwayat database tetap bersih dan konsisten untuk seluruh tim.
