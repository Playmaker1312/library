# 44. Update AuthController - Semua Endpoint Auth Lengkap

## Penjelasan

Setelah membuat berbagai komponen (DTO, Service, Strategy, Guard, Decorator), saatnya merangkai semuanya di AuthController. Controller ini akan menjadi pintu gerbang untuk semua operasi autentikasi. Ada 5 endpoint utama: register (mendaftar), login (masuk), refresh (perpanjang session), logout (keluar), dan me (lihat profil). Dengan guard global yang sudah terpasang, endpoint register dan login harus ditandai `@Public()` agar bisa diakses tanpa token.

Endpoint logout dan me membutuhkan autentikasi — user harus mengirim access token di header. Data user akan diekstrak menggunakan `@CurrentUser()` decorator yang sudah kita buat. Endpoint refresh menggunakan strategy khusus 'jwt-refresh' untuk memvalidasi refresh token.

## Fungsi

AuthController berfungsi sebagai REST API controller yang mengekspos semua operasi autentikasi ke client. Controller ini menerima HTTP request, memvalidasi input melalui DTO, memanggil AuthService untuk logika bisnis, dan mengembalikan response yang sesuai. Ini adalah satu-satunya controller yang tidak memerlukan autentikasi untuk beberapa endpoint-nya.

## Cara Implementasi / Code

**1. AuthController Lengkap — `src/auth/auth.controller.ts`:**

```typescript
import {
  Controller,
  Post,
  Get,
  Body,
  UseGuards,
  HttpCode,
  HttpStatus,
} from '@nestjs/common';
import { AuthGuard } from '@nestjs/passport';
import { AuthService } from './auth.service';
import { RegisterDto } from './dto/register.dto';
import { LoginDto } from './dto/login.dto';
import { RefreshTokenDto } from './dto/refresh-token.dto';
import { Public } from './decorators/public.decorator';
import { CurrentUser } from './decorators/current-user.decorator';

@Controller('auth')
export class AuthController {
  constructor(private readonly authService: AuthService) {}

  /**
   * POST /auth/register
   * Mendaftarkan user baru (public — tanpa token)
   */
  @Public()
  @Post('register')
  @HttpCode(HttpStatus.CREATED)
  async register(@Body() dto: RegisterDto) {
    return this.authService.register(dto);
  }

  /**
   * POST /auth/login
   * Login dengan email & password (public — tanpa token)
   */
  @Public()
  @Post('login')
  @HttpCode(HttpStatus.OK)
  async login(@Body() dto: LoginDto) {
    return this.authService.login(dto);
  }

  /**
   * POST /auth/refresh
   * Refresh token menggunakan refresh token yang dikirim di body
   * Dilindungi oleh JwtRefreshStrategy
   */
  @UseGuards(AuthGuard('jwt-refresh'))
  @Post('refresh')
  @HttpCode(HttpStatus.OK)
  async refresh(
    @Body() dto: RefreshTokenDto,
    @CurrentUser() user: any,
  ) {
    return this.authService.refreshTokens(user.sub, dto.refreshToken);
  }

  /**
   * POST /auth/logout
   * Logout — menghapus refresh token dari database
   * Memerlukan autentikasi (access token di header)
   */
  @Post('logout')
  @HttpCode(HttpStatus.OK)
  async logout(@CurrentUser('id') userId: number) {
    return this.authService.logout(userId);
  }

  /**
   * GET /auth/me
   * Mendapatkan data user yang sedang login
   * Memerlukan autentikasi (access token di header)
   */
  @Get('me')
  @HttpCode(HttpStatus.OK)
  getProfile(@CurrentUser() user: any) {
    return { user };
  }
}
```

**2. Update AuthService — metode refreshTokens yang baru:**

```typescript
async refreshTokens(userId: number, refreshToken: string) {
  const user = await this.usersService.findById(userId);

  if (!user || !user.refreshToken) {
    throw new ForbiddenException('Access denied');
  }

  if (user.refreshToken !== refreshToken) {
    // Deteksi potensi pencurian token
    await this.usersService.updateRefreshToken(userId, null);
    throw new ForbiddenException('Session expired, please login again');
  }

  const tokens = await this.generateTokens(user.id, user.email, user.role);
  await this.usersService.updateRefreshToken(user.id, tokens.refreshToken);

  return tokens;
}
```

## Analogi

AuthController adalah **meja resepsionis utama** perpustakaan. Ada 5 layanan:
- **Register** (Pendaftaran): "Selamat datang, silakan isi formulir anggota baru"
- **Login** (Masuk): "Silakan tunjukkan kartu identitas Anda"
- **Refresh** (Perpanjangan): "Kartu akses harian Anda mau habis? Silakan perpanjang dengan stempel anggota"
- **Logout** (Keluar): "Terima kasih, kami akan menonaktifkan session Anda"
- **Me** (Profil): "Ini data diri Anda yang tercatat di sistem"

Pintu pendaftaran dan login berada di luar pagar (public), sementara perpanjangan, keluar, dan lihat profil ada di dalam area perpustakaan (private).

## Penggunaan

Controller ini menjadi antarmuka utama antara frontend dan backend untuk urusan autentikasi. Aplikasi web/mobile akan memanggil endpoint-endpoint ini untuk mengelola session pengguna. Semua aplikasi yang membutuhkan sistem login akan menggunakan pola controller seperti ini.

## Kesalahan Umum yang Sering Terjadi

1. **Lupa @Public() di register & login**: Jika guard global aktif, endpoint ini tidak bisa diakses tanpa token — paradoxical.
2. **HTTP status code yang salah**: Register harus 201 Created, login harus 200 OK. Jangan semua endpoint pakai 200.
3. **Tidak menangani error di refresh endpoint**: JwtRefreshStrategy mungkin gagal sebelum mencapai controller. Pastikan error handling berfungsi.
4. **Refresh token dikirim dua kali**: Jika refresh token ada di body dan juga di header Authorization karena strategy salah, akan terjadi konflik.

## Soal Latihan

**Soal 1:** Mengapa endpoint logout menggunakan `@CurrentUser('id')` dan bukan menerima userId dari body?

**Jawaban:** Untuk keamanan. Jika userId diterima dari body, attacker bisa memanipulasi request dan logout user lain. Dengan mengambil userId dari token yang sudah diverifikasi, kita memastikan bahwa user hanya bisa logout dirinya sendiri (kecuali ada fitur admin yang memang dirancang untuk logout user lain).

**Soal 2:** Bagaimana menambahkan endpoint untuk admin yang bisa logout user tertentu?

**Jawaban:**

```typescript
@Roles(Role.ADMIN)
@Post('logout/:userId')
async logoutUser(@Param('userId', ParseIntPipe) userId: number) {
  return this.authService.logout(userId);
}
```

Dengan proteksi @Roles(Role.ADMIN), hanya admin yang bisa memanggil endpoint ini.

**Soal 3:** Modifikasi endpoint /auth/me agar bisa menerima query parameter `?fields=id,email` yang hanya mengembalikan field tertentu.

**Jawaban:**

```typescript
@Get('me')
@HttpCode(HttpStatus.OK)
getProfile(
  @CurrentUser() user: any,
  @Query('fields') fields?: string,
) {
  if (fields) {
    const fieldList = fields.split(',').map(f => f.trim());
    const filtered: Record<string, any> = {};
    for (const field of fieldList) {
      if (field in user) {
        filtered[field] = user[field];
      }
    }
    return { user: filtered };
  }
  return { user };
}
```
