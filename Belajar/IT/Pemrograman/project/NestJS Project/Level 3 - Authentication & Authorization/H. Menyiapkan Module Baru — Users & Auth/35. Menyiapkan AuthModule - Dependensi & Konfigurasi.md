# 35. Menyiapkan AuthModule - Dependensi & Konfigurasi

## Penjelasan

AuthModule adalah pusat dari sistem autentikasi di aplikasi NestJS kita. Modul ini mengatur semua yang berkaitan dengan login, register, refresh token, dan logout. Untuk bekerja, AuthModule membutuhkan beberapa package eksternal: `@nestjs/passport` dan `passport` untuk integrasi strategi autentikasi, `@nestjs/jwt` dan `jsonwebtoken` untuk generate dan verifikasi token JWT, serta `bcrypt` untuk hashing dan verifikasi password.

Konfigurasi JWT diatur menggunakan `JwtModule.registerAsync()` agar kita bisa membaca secret key dan konfigurasi lainnya dari file environment (`.env`) melalui ConfigService. Ini penting untuk keamanan — secret key tidak boleh di-hardcode di kode. Selain JwtModule, kita juga akan membuat auth config namespace menggunakan `@nestjs/config` untuk mengelompokkan konfigurasi terkait autentikasi.

## Fungsi

AuthModule berfungsi sebagai wadah yang mengimpor semua dependency yang diperlukan untuk autentikasi, mendaftarkan providers (AuthService, JwtStrategy, dll), dan mengekspor AuthService untuk digunakan di modul lain. Tanpa modul ini, sistem autentikasi tidak akan memiliki akses ke JWT, Passport, dan Bcrypt.

## Cara Implementasi / Code

**1. Install package yang diperlukan:**

```bash
npm install @nestjs/passport passport @nestjs/jwt passport-jwt bcrypt
npm install @types/passport-jwt @types/bcrypt --save-dev
```

**2. Konfigurasi Auth — `src/auth/auth.config.ts`:**

```typescript
import { registerAs } from '@nestjs/config';

export default registerAs('auth', () => ({
  jwtSecret: process.env.JWT_SECRET || 'super-secret-key',
  jwtExpiresIn: process.env.JWT_EXPIRES_IN || '15m',
  jwtRefreshSecret: process.env.JWT_REFRESH_SECRET || 'super-refresh-secret-key',
  jwtRefreshExpiresIn: process.env.JWT_REFRESH_EXPIRES_IN || '7d',
}));
```

**3. Tambahkan environment variables di `.env`:**

```env
JWT_SECRET=my-super-secret-key-2024
JWT_EXPIRES_IN=15m
JWT_REFRESH_SECRET=my-refresh-secret-key-2024
JWT_REFRESH_EXPIRES_IN=7d
```

**4. AuthService skeleton — `src/auth/auth.service.ts`:**

```typescript
import { Injectable } from '@nestjs/common';
import { ConfigType } from '@nestjs/config';
import { JwtService } from '@nestjs/jwt';
import * as bcrypt from 'bcrypt';
import authConfig from './auth.config';
import { UsersService } from '../users/users.service';

@Injectable()
export class AuthService {
  constructor(
    private readonly usersService: UsersService,
    private readonly jwtService: JwtService,
    @Inject(authConfig.KEY)
    private readonly config: ConfigType<typeof authConfig>,
  ) {}

  // Akan diisi di materi berikutnya
}
```

**5. AuthModule — `src/auth/auth.module.ts`:**

```typescript
import { Module } from '@nestjs/common';
import { ConfigModule, ConfigService } from '@nestjs/config';
import { JwtModule } from '@nestjs/jwt';
import { PassportModule } from '@nestjs/passport';
import { UsersModule } from '../users/users.module';
import authConfig from './auth.config';
import { AuthService } from './auth.service';

@Module({
  imports: [
    ConfigModule.forFeature(authConfig),
    PassportModule.register({ defaultStrategy: 'jwt' }),
    JwtModule.registerAsync({
      imports: [ConfigModule],
      inject: [ConfigService],
      useFactory: (configService: ConfigService) => ({
        secret: configService.get<string>('auth.jwtSecret'),
        signOptions: {
          expiresIn: configService.get<string>('auth.jwtExpiresIn'),
        },
      }),
    }),
    UsersModule,
  ],
  providers: [AuthService],
  exports: [AuthService],
})
export class AuthModule {}
```

**6. Daftarkan ConfigModule secara global di `app.module.ts`:**

```typescript
import { Module } from '@nestjs/common';
import { ConfigModule } from '@nestjs/config';
import authConfig from './auth/auth.config';

@Module({
  imports: [
    ConfigModule.forRoot({
      isGlobal: true,
      load: [authConfig],
    }),
    // modul lain...
  ],
})
export class AppModule {}
```

## Analogi

AuthModule adalah **meja resepsionis** perpustakaan. Meja ini dilengkapi dengan berbagai alat: stempel (JWT) untuk menandai kartu anggota, buku catatan (Passport) untuk mencatat siapa yang masuk, dan mesin hash (bcrypt) untuk menyimpan kata sandi dengan aman. ConfigService seperti **papan petunjuk** yang memberi tahu resepsionis aturan mainnya: berapa lama stempel berlaku (15 menit untuk akses umum, 7 hari untuk stempel perpanjangan). UsersModule adalah **bagian pendaftaran** yang menyimpan data anggota.

## Penggunaan

AuthModule diimpor oleh AppModule dan modul-modul lain yang membutuhkan fitur autentikasi. AuthService yang diekspor akan digunakan di AuthController untuk menangani request HTTP terkait login, register, dll. JwtModule yang terkonfigurasi akan digunakan oleh JwtStrategy untuk memvalidasi token.

## Kesalahan Umum yang Sering Terjadi

1. **Bcrypt error di Windows**: Kadang bcrypt bermasalah di Windows. Solusinya gunakan `bcryptjs` sebagai alternatif.
2. **Lupa import ConfigModule di JwtModule.registerAsync**: Karena JwtModule butuh akses ke ConfigService, pastikan ConfigModule ada di `imports` array JwtModule.
3. **Hardcode secret key**: Jangan pernah menulis secret key langsung di kode. Selalu gunakan environment variable.
4. **Lupa mendaftarkan authConfig di AppModule**: ConfigModule.forRoot harus di-load dengan konfigurasi auth agar bisa diakses.

## Hubungan dengan Materi Sebelumnya

AuthModule menggunakan UsersModule yang kita buat di materi 34. UsersService akan diinjeksi ke AuthService untuk operasi database terkait user. Ini adalah contoh nyata dependency injection di NestJS — modul saling terhubung melalui imports dan exports.

## Soal Latihan

**Soal 1:** Apa fungsi `registerAs` dari `@nestjs/config`?

**Jawaban:** `registerAs` digunakan untuk membuat namespace configuration. Misalnya `registerAs('auth', ...)` memungkinkan kita mengakses konfigurasi dengan `configService.get('auth.jwtSecret')`. Ini membantu mengelompokkan konfigurasi berdasarkan fitur/modul sehingga lebih terorganisir.

**Soal 2:** Mengapa kita menggunakan `JwtModule.registerAsync()` dan bukan `JwtModule.register()`?

**Jawaban:** `registerAsync` memungkinkan kita mengonfigurasi JwtModule secara asinkron dengan inject dependency seperti ConfigService. Jika menggunakan `register`, kita harus memberikan nilai secret secara langsung (hardcode), yang tidak aman dan tidak fleksibel. Dengan `registerAsync`, secret key bisa dibaca dari file .env.

**Soal 3:** Apa perbedaan antara `@nestjs/jwt` dan `jsonwebtoken`?

**Jawaban:** `@nestjs/jwt` adalah wrapper NestJS untuk library `jsonwebtoken`. `@nestjs/jwt` menyediakan dekorator dan integrasi yang lebih baik dengan ekosistem NestJS (seperti dependency injection), sementara `jsonwebtoken` adalah library JWT standar untuk Node.js. Keduanya menggunakan `jsonwebtoken` di bawah hood, tapi `@nestjs/jwt` memberikan abstraksi yang lebih NestJS-friendly.
