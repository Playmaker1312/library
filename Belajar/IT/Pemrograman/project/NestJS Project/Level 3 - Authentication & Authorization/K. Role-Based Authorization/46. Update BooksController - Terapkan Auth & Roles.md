# 46. Update BooksController - Terapkan Auth & Roles

## Penjelasan

Setelah sistem autentikasi dan otorisasi siap, saatnya menerapkannya ke BooksController yang sudah kita buat di Level 2. Dengan guard global (JwtAuthGuard + RolesGuard), semua endpoint di BooksController otomatis terproteksi — hanya user yang terautentikasi yang bisa mengaksesnya. Tapi kita ingin aturan yang lebih spesifik: endpoint GET (melihat buku) harus bisa diakses oleh siapa saja, bahkan yang belum login. Sementara POST, PATCH, dan DELETE hanya untuk role tertentu.

Kita akan menggunakan `@Public()` untuk endpoint GET agar bisa diakses tanpa autentikasi, dan `@Roles()` untuk endpoint POST, PATCH, DELETE dengan role yang sesuai. Endpoint GET tidak perlu `@Roles()` karena tidak ada decorator = semua user terautentikasi boleh akses. Tapi karena kita ingin publik bisa akses, kita tambahkan `@Public()`.

## Fungsi

Update BooksController berfungsi untuk menerapkan aturan akses yang sesuai dengan skenario dunia nyata: pengunjung perpustakaan bisa melihat buku di rak, pustakawan bisa menambah dan memperbarui data buku, dan hanya kepala perpustakaan yang bisa menghapus buku dari katalog.

## Cara Implementasi / Code

**1. BooksController Lengkap — `src/books/books.controller.ts`:**

```typescript
import {
  Controller,
  Get,
  Post,
  Patch,
  Delete,
  Body,
  Param,
  ParseIntPipe,
} from '@nestjs/common';
import { Role } from '@prisma/client';
import { BooksService } from './books.service';
import { CreateBookDto } from './dto/create-book.dto';
import { UpdateBookDto } from './dto/update-book.dto';
import { Public } from '../auth/decorators/public.decorator';
import { Roles } from '../auth/decorators/roles.decorator';
import { CurrentUser } from '../auth/decorators/current-user.decorator';

@Controller('books')
export class BooksController {
  constructor(private readonly booksService: BooksService) {}

  /**
   * GET /books
   * Mendapatkan semua buku
   * Public — bisa diakses siapa saja (termasuk tanpa login)
   */
  @Public()
  @Get()
  async findAll() {
    return this.booksService.findAll();
  }

  /**
   * GET /books/:id
   * Mendapatkan detail buku berdasarkan ID
   * Public — bisa diakses siapa saja
   */
  @Public()
  @Get(':id')
  async findOne(@Param('id', ParseIntPipe) id: number) {
    return this.booksService.findOne(id);
  }

  /**
   * POST /books
   * Membuat buku baru
   * Hanya LIBRARIAN dan ADMIN yang bisa
   */
  @Roles(Role.LIBRARIAN, Role.ADMIN)
  @Post()
  async create(
    @Body() dto: CreateBookDto,
    @CurrentUser('id') userId: number,
  ) {
    return this.booksService.create(dto, userId);
  }

  /**
   * PATCH /books/:id
   * Memperbarui data buku
   * Hanya LIBRARIAN dan ADMIN yang bisa
   */
  @Roles(Role.LIBRARIAN, Role.ADMIN)
  @Patch(':id')
  async update(
    @Param('id', ParseIntPipe) id: number,
    @Body() dto: UpdateBookDto,
  ) {
    return this.booksService.update(id, dto);
  }

  /**
   * DELETE /books/:id
   * Menghapus buku
   * Hanya ADMIN yang bisa
   */
  @Roles(Role.ADMIN)
  @Delete(':id')
  async remove(@Param('id', ParseIntPipe) id: number) {
    return this.booksService.remove(id);
  }
}
```

**2. Update BooksService — tambahkan parameter `userId` di create:**

```typescript
import { Injectable, NotFoundException } from '@nestjs/common';
import { PrismaService } from '../prisma/prisma.service';
import { CreateBookDto } from './dto/create-book.dto';
import { UpdateBookDto } from './dto/update-book.dto';

@Injectable()
export class BooksService {
  constructor(private readonly prisma: PrismaService) {}

  async findAll() {
    return this.prisma.book.findMany();
  }

  async findOne(id: number) {
    const book = await this.prisma.book.findUnique({ where: { id } });
    if (!book) {
      throw new NotFoundException(`Book with ID ${id} not found`);
    }
    return book;
  }

  async create(dto: CreateBookDto, userId?: number) {
    return this.prisma.book.create({
      data: {
        title: dto.title,
        author: dto.author,
        isbn: dto.isbn,
        publishedYear: dto.publishedYear,
        // Jika ada field createdBy di model Book
        // createdById: userId,
      },
    });
  }

  async update(id: number, dto: UpdateBookDto) {
    await this.findOne(id);
    return this.prisma.book.update({
      where: { id },
      data: dto,
    });
  }

  async remove(id: number) {
    await this.findOne(id);
    return this.prisma.book.delete({ where: { id } });
  }
}
```

## Analogi

Di perpustakaan, setelah sistem keamanan terpasang:
- **Pintu masuk (GET /books)**: Terbuka untuk semua orang, bahkan yang tidak punya kartu anggota. Siapa saja boleh melihat-lihat buku di rak.
- **Ruang staf (POST/PATCH /books)**: Hanya pustakawan (LIBRARIAN) dan kepala perpustakaan (ADMIN) yang boleh masuk. Mereka yang menambahkan buku baru ke katalog atau memperbarui informasi buku.
- **Ruang arsip tertutup (DELETE /books)**: Hanya kepala perpustakaan (ADMIN) yang memiliki kunci. Keputusan untuk menghapus buku dari koleksi permanen harus melalui otorisasi tertinggi.

Setiap area memiliki aturan yang jelas, dan satpam (RolesGuard) memastikan tidak ada pelanggaran.

## Penggunaan

Pola proteksi seperti ini digunakan di hampir semua REST API yang memiliki konsep user role. Dengan pendekatan deklaratif (menggunakan decorator), kode menjadi sangat mudah dibaca dan dipelihara. Tinggal lihat decorator di atas endpoint, langsung tahu siapa saja yang boleh mengaksesnya.

## Kesalahan Umum yang Sering Terjadi

1. **Terlalu permisif**: Jika lupa menambahkan @Roles() di endpoint sensitif, semua user (termasuk USER biasa) bisa mengaksesnya.
2. **Terlalu restriktif**: Jika endpoint GET juga butuh autentikasi padahal seharusnya public, API menjadi tidak ramah untuk crawler/search engine.
3. **Role hardcode di controller**: Gunakan enum `Role.ADMIN`, bukan string `'ADMIN'`, untuk menghindari typo.
4. **Tidak update test suite**: Setelah menambahkan guard, pastikan test suite juga mengirim token yang sesuai.

## Soal Latihan

**Soal 1:** Bagaimana jika kita ingin endpoint GET /books bisa diakses oleh semua user terautentikasi (tidak public) tapi juga oleh user yang belum login?

**Jawaban:** Ini bertentangan — endpoint harus memilih: public atau private. Solusinya: buat dua endpoint. Satu public untuk akses umum (tanpa detail sensitif), satu private untuk akses terautentikasi (dengan data lebih lengkap). Atau gunakan mode "optional auth" seperti yang dibahas di soal latihan materi 42.

**Soal 2:** Apa yang harus dilakukan jika ada endpoint yang membutuhkan role berbeda untuk method HTTP yang sama? Misalnya GET /books (semua role) dan GET /books/deleted (hanya admin)?

**Jawaban:** Urutan deklarasi endpoint penting di NestJS. Tempatkan endpoint yang lebih spesifik di atas:

```typescript
@Roles(Role.ADMIN)
@Get('deleted')
async findDeleted() {
  return this.booksService.findDeleted();
}

@Public()
@Get()
async findAll() {
  return this.booksService.findAll();
}
```

**Soal 3:** Buat endpoint baru `GET /books/stats` yang menampilkan statistik buku (jumlah total, jumlah per genre) dan hanya bisa diakses oleh LIBRARIAN dan ADMIN.

**Jawaban:**

```typescript
@Roles(Role.LIBRARIAN, Role.ADMIN)
@Get('stats')
async getStats() {
```
