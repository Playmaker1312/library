# Generate Books Module — Menggunakan NestJS CLI dengan Benar

## Penjelasan

Setelah merencanakan struktur folder, langkah konkret pertama dalam membangun fitur adalah membuat module menggunakan NestJS CLI. CLI NestJS menyediakan generator (disebut **schematics**) yang bisa membuat file-file boilerplate secara otomatis. Perintah seperti `nest g module`, `nest g controller`, dan `nest g service` akan membuat file beserta konfigurasi pendaftarannya di module — menghemat waktu dan mencegah kesalahan manual.

Generator CLI akan secara otomatis mendaftarkan module, controller, atau service yang baru dibuat ke module terdekat. Misalnya, `nest g module modules/books` akan membuat file `books.module.ts` dan langsung mengimportnya ke `app.module.ts`. Ini adalah salah satu keunggulan NestJS dibanding framework lain — developer tidak perlu mengingat untuk mendaftarkan komponen secara manual.

Namun, penting untuk memahami apa yang dilakukan oleh CLI di balik layar. Ketika kita menjalankan `nest g service modules/books --no-spec`, CLI tidak hanya membuat file, tetapi juga menambahkan `BooksService` ke dalam `providers` array di `BooksModule`. Jika kita menjalankan `nest g controller modules/books`, CLI akan menambahkan `BooksController` ke dalam `controllers` array. Pemahaman ini penting agar kita bisa melakukan debugging jika terjadi error dependency injection.

## Fungsi

Perintah `nest g` (generate) berfungsi untuk membuat file boilerplate NestJS secara otomatis. `nest g module` membuat class module baru, `nest g controller` membuat class controller dengan decorator dan method template, `nest g service` membuat class service dengan decorator `@Injectable()`. Semua perintah ini secara otomatis mendaftarkan komponen yang dibuat ke module yang sesuai, mengurangi kemungkinan human error.

## Cara Implementasi / Code

### 1. Generate Books Module

```bash
# Masuk ke project
cd perpustakaan-api

# Generate module books
nest g module modules/books
```

Output:
```
CREATE src/modules/books/books.module.ts
UPDATE src/app.module.ts
```

CLI membuat file `src/modules/books/books.module.ts` dan mengupdate `src/app.module.ts` dengan menambahkan `BooksModule` ke `imports`.

### 2. Generate Books Controller

```bash
nest g controller modules/books --no-spec
```

Output:
```
CREATE src/modules/books/books.controller.ts
UPDATE src/modules/books/books.module.ts
```

CLI membuat controller dan mendaftarkannya ke `BooksModule`. Flag `--no-spec` digunakan agar tidak membuat file test spec.

### 3. Generate Books Service

```bash
nest g service modules/books --no-spec
```

Output:
```
CREATE src/modules/books/books.service.ts
UPDATE src/modules/books/books.module.ts
```

CLI membuat service dan menambahkannya ke `providers` di `BooksModule`.

### 4. Hasil Akhir Setelah Generate

**`src/modules/books/books.module.ts`** (setelah semua generate):

```typescript
import { Module } from '@nestjs/common';
import { BooksController } from './books.controller';
import { BooksService } from './books.service';

@Module({
  controllers: [BooksController],
  providers: [BooksService],
})
export class BooksModule {}
```

**`src/modules/books/books.controller.ts`** (hasil generate):

```typescript
import { Controller } from '@nestjs/common';
import { BooksService } from './books.service';

@Controller('books')
export class BooksController {
  constructor(private readonly booksService: BooksService) {}
}
```

**`src/modules/books/books.service.ts`** (hasil generate):

```typescript
import { Injectable } from '@nestjs/common';

@Injectable()
export class BooksService {}
```

**`src/app.module.ts`** (setelah update oleh CLI):

```typescript
import { Module } from '@nestjs/common';
import { AppController } from './app.controller';
import { AppService } from './app.service';
import { BooksModule } from './modules/books/books.module';

@Module({
  imports: [BooksModule],
  controllers: [AppController],
  providers: [AppService],
})
export class AppModule {}
```

### 5. Generate Langsung dengan Satu Perintah (Alternatif)

Sebenarnya kita bisa membuat sekaligus dengan:

```bash
# Generate resource lengkap (module + controller + service + dto)
nest g resource modules/books

# Pilih REST API saat diminta, pilih Y untuk generate CRUD
```

Namun, untuk pembelajaran, kita lakukan step-by-step agar memahami proses di balik layar.

### 6. Melihat Semua Opsi CLI

```bash
# Melihat daftar semua schematics yang tersedia
nest g --help

# Melihat opsi untuk generate tertentu
nest g controller --help

# Opsi penting:
# --no-spec : Tidak membuat file test
# --flat : Tidak membuat folder terpisah
# --dry-run : Simulasi tanpa benar-benar membuat file
```

Gunakan `--dry-run` untuk melihat apa yang akan dilakukan CLI tanpa benar-benar mengeksekusi:

```bash
nest g module modules/books --dry-run
```

## Analogi

Bayangkan Anda adalah **kepala perpustakaan** yang ingin menambah **rak buku baru** (Books Module). Anda tidak membangun rak dari nol dengan paku dan palu — Anda memanggil **tim kontraktor khusus (NestJS CLI)** yang sudah punya cetak biru standar.

- `nest g module modules/books` — Kontraktor datang dan **membangun ruangan baru** (module) untuk rak buku. Mereka juga memasang **papan nama** di pintu utama perpustakaan (app.module.ts) yang menunjukkan bahwa ruangan ini ada.

- `nest g controller modules/books` — Kontraktor memasang **meja informasi** di depan ruangan (controller) yang siap menerima pertanyaan dari pengunjung.

- `nest g service modules/books` — Kontraktor menyiapkan **petugas rak** (service) yang akan mencari dan mengelola buku. Petugas ini ditempatkan di ruangan yang sesuai.

Yang penting: kontraktor tidak hanya membuat komponennya, tetapi juga **mencatat di papan organisasi** (module file) bahwa meja informasi dan petugas rak sudah tersedia dan terdaftar dengan benar. Inilah yang dimaksud dengan "CLI mendaftarkan komponen secara otomatis".

## Penggunaan

Perintah `nest g` digunakan setiap kali kita menambah fitur baru ke aplikasi NestJS. Setiap fitur bisnis yang signifikan — seperti management anggota, peminjaman, atau otentikasi — akan melalui proses generate module, controller, dan service yang sama. Dengan CLI, kita memastikan konsistensi struktur dan mengurangi boilerplate code yang harus ditulis manual.

## Kesalahan Umum yang Sering Terjadi

1. **Generate tanpa `--no-spec`** — CLI membuat file `.spec.ts` untuk setiap komponen. Jika tidak ingin testing unit di level ini, gunakan `--no-spec` atau hapus file spec yang tidak diperlukan.

2. **Lupa menjalankan generate untuk service** — Controller dan service harus di-generate secara terpisah. Jika lupa generate service, dependency injection akan error.

3. **Mengubah struktur folder setelah generate** — Jika memindahkan file setelah di-generate, jangan lupa update path import dan registrasi di module. Lebih baik generate ulang.

4. **Generate di folder yang salah** — Jika menjalankan `nest g controller books` tanpa prefix `modules/`, controller akan dibuat di `src/books/` bukan `src/modules/books/`. Selalu gunakan path lengkap.

5. **Menggunakan `nest g resource` tanpa memahami** — Perintah `nest g resource` sangat kuat (membuat module + controller + service + entity + dto sekaligus), tapi jika tidak memahami strukturnya, akan sulit melakukan modifikasi manual nantinya.

## Hubungan dengan Materi Sebelumnya

Di materi ke-6, kita merencanakan struktur folder yang akan digunakan. Sekarang kita mulai mengisi folder `modules/books/` dengan file-file hasil generate CLI. Ini adalah langkah pertama dari implementasi konkret. Setelah materi ini, kita akan mendefinisikan entity/interface (materi 8), DTO (materi 9), service (materi 10), dan controller (materi 11) untuk module Books.

## Soal Latihan

**Soal:** Buatlah module baru bernama `Members` untuk mengelola anggota perpustakaan, lengkap dengan controller dan service-nya, menggunakan NestJS CLI. Pastikan:
1. Module berada di `src/modules/members/`
2. Controller dan service tidak membuat file spec
3. Setelah selesai, periksa isi `members.module.ts` dan `app.module.ts`

**Jawaban:**

```bash
# Langkah 1: Generate module
cd perpustakaan-api
nest g module modules/members

# Output:
# CREATE src/modules/members/members.module.ts
# UPDATE src/app.module.ts

# Langkah 2: Generate controller
nest g controller modules/members --no-spec

# Output:
# CREATE src/modules/members/members.controller.ts
# UPDATE src/modules/members/members.module.ts

# Langkah 3: Generate service
nest g service modules/members --no-spec

# Output:
# CREATE src/modules/members/members.service.ts
# UPDATE src/modules/members/members.module.ts
```

**Verifikasi isi file:**

`src/modules/members/members.module.ts`:
```typescript
import { Module } from '@nestjs/common';
import { MembersController } from './members.controller';
import { MembersService } from './members.service';

@Module({
  controllers: [MembersController],
  providers: [MembersService],
})
export class MembersModule {}
```

`src/app.module.ts` (bagian imports):
```typescript
imports: [BooksModule, MembersModule],
```

Keduanya sudah terdaftar dengan benar tanpa perlu edit manual.
