# Mendefinisikan Entity Book — Interface & Type untuk Data

## Penjelasan

Setelah membuat module Books, langkah berikutnya adalah mendefinisikan bentuk data buku. Di NestJS, kita bisa menggunakan **interface** atau **class** untuk mendefinisikan entity. Interface TypeScript lebih ringan karena tidak menghasilkan kode JavaScript setelah kompilasi — hanya digunakan untuk type-checking saat development. Untuk project yang belum menggunakan database, interface adalah pilihan yang tepat karena sederhana dan mudah dipahami.

Entity Book akan memiliki properti-properti yang mencerminkan data buku di perpustakaan. Properti dasar meliputi `id` (identifier unik), `title` (judul buku), `author` (penulis), `isbn` (nomor ISBN), `year` (tahun terbit), `stock` (jumlah stok), serta timestamp `createdAt` dan `updatedAt` untuk tracking waktu. Untuk generate ID, kita akan menggunakan package `uuid` yang menghasilkan identifier unik universal.

Dengan mendefinisikan entity terlebih dahulu, kita memiliki **kontrak data** yang jelas sebelum menulis service dan controller. Setiap operasi CRUD akan merujuk pada interface ini sebagai bentuk data yang dikembalikan. Ini adalah praktik **type-safe** yang merupakan salah satu keunggulan TypeScript — compiler akan mendeteksi jika kita mencoba mengakses properti yang tidak ada pada entity.

## Fungsi

Entity/interface berfungsi sebagai **blueprint** atau cetak biru data dalam aplikasi. Untuk entity Book, interface ini mendefinisikan properti apa saja yang dimiliki sebuah buku, tipe data masing-masing properti, dan properti mana yang wajib (required) vs opsional. Dengan adanya interface, developer dan IDE mendapatkan autocomplete dan type checking yang membantu mencegah bug.

## Cara Implementasi / Code

### 1. Install package uuid

```bash
cd perpustakaan-api
pnpm add uuid
pnpm add -D @types/uuid
```

### 2. Buat interface Book

Buat file `src/modules/books/interfaces/book.interface.ts`:

```typescript
export interface Book {
  id: string;
  title: string;
  author: string;
  isbn: string;
  year: number;
  stock: number;
  createdAt: Date;
  updatedAt: Date;
}
```

### 3. Buat interface untuk partial data (CreateBook)

Buat file `src/modules/books/interfaces/create-book.interface.ts`:

```typescript
import { Book } from './book.interface';

// Omit: menghilangkan properti yang akan di-generate otomatis
export type CreateBookInput = Omit<Book, 'id' | 'createdAt' | 'updatedAt'>;
```

Atau kita bisa membuat interface terpisah yang lebih eksplisit:

```typescript
export interface CreateBookInput {
  title: string;
  author: string;
  isbn: string;
  year: number;
  stock: number;
}
```

### 4. Buat type untuk update data (Partial)

```typescript
// Kita akan gunakan Partial<Book> atau buat interface sendiri
// Untuk update, semua properti opsional kecuali id
export interface UpdateBookInput {
  title?: string;
  author?: string;
  isbn?: string;
  year?: number;
  stock?: number;
}
```

### 5. Buat juga interface response (opsional)

Buat file `src/common/interfaces/api-response.interface.ts`:

export interface ApiResponse<T> {

### 7. Untuk project yang lebih besar, gunakan class entity

Meskipun untuk saat ini kita menggunakan interface, di masa depan (saat menggunakan database ORM seperti TypeORM), kita akan menggunakan class entity seperti ini:

```typescript
// Contoh entity dengan TypeORM (untuk referensi masa depan)
import { Entity, Column, PrimaryGeneratedColumn, CreateDateColumn, UpdateDateColumn } from 'typeorm';

@Entity('books')
export class Book {
  @PrimaryGeneratedColumn('uuid')
  id: string;

  @Column()
  title: string;

  @Column()
  author: string;

  @Column({ unique: true })
  isbn: string;

  @Column()
  year: number;

  @Column({ default: 0 })
  stock: number;

  @CreateDateColumn()
  createdAt: Date;

  @UpdateDateColumn()
  updatedAt: Date;
}
```

### 8. Contoh penggunaan interface di service (pratinjau materi 10)

```typescript
import { v4 as uuidv4 } from 'uuid';
import { Book } from './interfaces/book.interface';
import { CreateBookInput } from './interfaces/create-book.interface';

@Injectable()
export class BooksService {
  private books: Book[] = [];

  create(input: CreateBookInput): Book {
    const book: Book = {
      id: uuidv4(),
      ...input,
      createdAt: new Date(),
      updatedAt: new Date(),
    };
    this.books.push(book);
    return book;
  }
}
```

## Analogi

Bayangkan Anda sedang **mendaftarkan buku-buku baru** ke sistem katalog perpustakaan. Sebelum petugas bisa memasukkan data, Anda harus membuat **formulir standar** yang harus diisi untuk setiap buku:

- **Interface Book** adalah **formulir kosong** yang sudah dicetak — ada kolom untuk ID Buku, Judul, Penulis, ISBN, Tahun Terbit, Stok, dan dua kolom timestamp (tanggal input dan tanggal update). Setiap kolom sudah ditentukan jenis isiannya: ID harus teks, Tahun harus angka, Stok harus angka.

- **CreateBookInput** adalah **formulir yang sama tapi tanpa kolom ID dan timestamp** — karena ID akan diberikan oleh sistem, dan timestamp akan diisi otomatis oleh komputer. Pengunjuk hanya perlu mengisi judul, penulis, ISBN, tahun, dan stok.

- **UpdateBookInput** adalah **formulir yang semua kolomnya opsional** — pengunjuk bisa mengisi hanya kolom yang ingin diubah (misalnya hanya stok), tanpa harus mengisi ulang seluruh data.

Dengan formulir baku ini, petugas perpustakaan (service) selalu tahu data apa yang diharapkan dan dalam format apa. Tidak ada lagi buku yang tercatat tanpa judul atau stok yang terisi teks bukan angka.

## Penggunaan

Interface entity digunakan di **setiap operasi CRUD** yang melibatkan data buku. Service menggunakan interface untuk menentukan tipe parameter dan return value. Controller menggunakan interface untuk menentukan bentuk response. Saat kita beralih ke database sungguhan (PostgreSQL + TypeORM), interface ini akan diganti atau diperluas menjadi entity class dengan decorator database.

## Kesalahan Umum yang Sering Terjadi

1. **Mendefinisikan properti dengan tipe yang salah** — Misalnya `year: string` padahal tahun adalah angka, atau `stock: string` padahal stok harus number. Selalu gunakan tipe data yang sesuai.

2. **Lupa menambahkan `id` dan timestamp** — Tanpa `id`, kita tidak bisa mengidentifikasi buku secara unik. Tanpa timestamp, kita tidak tahu kapan data dibuat atau diubah.

3. **Menggunakan `any` untuk tipe data** — Ini menghilangkan keuntungan TypeScript. Selalu definisikan interface yang eksplisit.

4. **Mendefinisikan interface di file yang salah** — Meletakkan interface Book di folder `common/interfaces/` padahal ini spesifik untuk module Books. Interface spesifik module simpan di folder module tersebut.

5. **Tidak konsisten dengan penamaan** — Di satu tempat menggunakan `BookInterface`, di tempat lain `IBook`. Konsisten dengan konvensi: gunakan `Book` saja (tanpa prefix I) untuk interface.

## Hubungan dengan Materi Sebelumnya

Setelah module Books di-generate (materi 7), sekarang kita mendefinisikan "apa itu Book" melalui interface. Interface ini akan menjadi **dasar** untuk semua kode yang akan kita tulis selanjutnya: DTO (materi 9) akan mendefinisikan input validation berdasarkan properti Book, Service (materi 10) akan mengelola array of Book, dan Controller (materi 11) akan menerima dan mengembalikan data Book.

## Soal Latihan
