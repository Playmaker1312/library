# Menguji Semua Endpoint — REST Client File di VS Code

## Penjelasan

Setelah controller dan service selesai dibangun, langkah selanjutnya adalah menguji apakah semua endpoint berfungsi dengan benar. NestJS tidak mewajibkan工具 testing tertentu, tapi ada cara yang sangat praktis untuk melakukan quick test selama development: **REST Client extension** di VS Code. Extension ini memungkinkan kita mengirim HTTP request langsung dari file `.http` tanpa perlu aplikasi terpisah seperti Postman atau Insomnia.

File `.http` berisi daftar request HTTP yang bisa kita tulis dalam format sederhana. Setiap request dipisahkan oleh `###` dan bisa menyertakan headers, body (JSON), dan variable. Keunggulan utama dibanding Postman adalah file ini bisa di-commit ke Git — sehingga seluruh tim bisa menggunakan request yang sama untuk testing. Ini juga berfungsi sebagai **dokumentasi hidup** yang selalu sinkron dengan kode.

Dengan REST Client, kita bisa menguji skenario sukses (create, get all, get by id, update, delete) maupun skenario error (mencari buku yang tidak ada, mengirim data tidak valid). Ini memastikan bahwa sebelum melanjutkan ke materi berikutnya, semua endpoint di module Books sudah berfungsi dengan benar.

## Fungsi

File `.http` / `.rest` berfungsi sebagai **dokumentasi API yang executable**. Setiap developer bisa mengklik "Send Request" di VS Code untuk menguji endpoint tanpa harus mengingat URL, headers, atau body request. File ini juga berfungsi sebagai **test case manual** yang bisa digunakan untuk verifikasi cepat sebelum menulis automated test.

## Cara Implementasi / Code

### 1. Install REST Client Extension

Buka VS Code, tekan `Ctrl+Shift+X`, cari **REST Client** oleh Huachao Mao, lalu install.

### 2. Buat folder dan file requests

```bash
mkdir -p requests
```

Buat file `requests/books.http`:

```http
### ==========================================
### BOOKS API — REST Client Tests
### ==========================================

### Variable — simpan base URL
@baseUrl = http://localhost:3000/api/v1

### -----------------------------
### 1. CREATE — Membuat Buku Baru
### -----------------------------

### 1a. Membuat buku fiksi
POST {{baseUrl}}/books
Content-Type: application/json

{
  "title": "Laskar Pelangi",
  "author": "Andrea Hirata",
  "isbn": "978-979-3062-79-4",
  "year": 2005,
  "stock": 10
}

### 1b. Membuat buku non-fiksi
POST {{baseUrl}}/books
Content-Type: application/json

{
  "title": "Sapiens: A Brief History of Humankind",
  "author": "Yuval Noah Harari",
  "isbn": "978-006-2316-11-0",
  "year": 2011,
  "stock": 5
}

### 1c. Membuat buku teknologi
POST {{baseUrl}}/books
Content-Type: application/json

{
  "title": "Clean Code",
  "author": "Robert C. Martin",
  "isbn": "978-013-2350-88-4",
  "year": 2008,
  "stock": 7
}

### -----------------------------
### 2. GET ALL — Mendapatkan Semua Buku
### -----------------------------

### 2a. Tanpa filter
GET {{baseUrl}}/books

### 2b. Filter by search (judul)
GET {{baseUrl}}/books?search=clean

### 2c. Filter by author
GET {{baseUrl}}/books?author=Andrea Hirata

### 2d. Filter by year
GET {{baseUrl}}/books?year=2005

### 2e. Sorting
GET {{baseUrl}}/books?sortBy=year&sortOrder=desc

### 2f. Pagination
GET {{baseUrl}}/books?page=1&limit=2

### 2g. Kombinasi filter
GET {{baseUrl}}/books?search=code&sortBy=year&sortOrder=asc

### -----------------------------
### 3. GET BY ID — Mendapatkan Satu Buku
### -----------------------------

### 3a. Cari buku yang ada (ganti ID dengan hasil dari CREATE)
GET {{baseUrl}}/books/REPLACE-WITH-ACTUAL-ID

### 3b. Cari buku yang tidak ada
GET {{baseUrl}}/books/00000000-0000-0000-0000-000000000000

### -----------------------------
### 4. UPDATE — Memperbarui Data Buku
### -----------------------------

### 4a. Update sebagian field (ganti ID)
PATCH {{baseUrl}}/books/REPLACE-WITH-ACTUAL-ID
Content-Type: application/json

{
  "stock": 15
}

### 4b. Update beberapa field (ganti ID)
PATCH {{baseUrl}}/books/REPLACE-WITH-ACTUAL-ID
Content-Type: application/json

{
  "title": "Laskar Pelangi (Edisi Baru)",
  "year": 2024
}

### 4c. Update buku yang tidak ada
PATCH {{baseUrl}}/books/00000000-0000-0000-0000-000000000000
Content-Type: application/json

{
  "title": "Tidak Ada"
}

### -----------------------------
### 5. DELETE — Menghapus Buku
### -----------------------------

### 5a. Hapus buku yang ada (ganti ID)
DELETE {{baseUrl}}/books/REPLACE-WITH-ACTUAL-ID

### 5b. Hapus buku yang tidak ada
DELETE {{baseUrl}}/books/00000000-0000-0000-0000-000000000000

### -----------------------------
### 6. ERROR CASES — Skenario Error
### -----------------------------

### 6a. Create dengan data tidak lengkap (tanpa title)
POST {{baseUrl}}/books
Content-Type: application/json

{
  "author": "Test Author"
}

### 6b. Create dengan ISBN tidak valid
POST {{baseUrl}}/books
Content-Type: application/json

{
  "title": "Test",
  "author": "Test",
  "isbn": "invalid-isbn",
  "year": 2024,
  "stock": 1
}

### 6c. Create dengan tahun tidak masuk akal
POST {{baseUrl}}/books
Content-Type: application/json

{
  "title": "Test",
  "author": "Test",
  "isbn": "978-3-16-148410-0",
  "year": 999,
  "stock": 1
}

### 6d. Create dengan stock negatif
POST {{baseUrl}}/books
Content-Type: application/json

{
  "title": "Test",
  "author": "Test",
  "isbn": "978-3-16-148410-0",
  "year": 2024,
  "stock": -5
}

### 6e. Get by ID dengan format UUID tidak valid
GET {{baseUrl}}/books/bukan-uuid
```

### 3. Cara Menggunakan File .http

1. Jalankan aplikasi: `pnpm run start:dev`
2. Buka file `requests/books.http` di VS Code
3. Klik tombol **"Send Request"** yang muncul di atas setiap request (sebelah method GET/POST)
4. Atau tekan `Ctrl+Alt+R` untuk mengirim request yang sedang aktif
5. Response akan muncul di panel sebelah kanan

### 4. Alur Testing yang Disarankan

```bash
# Jalankan aplikasi terlebih dahulu
pnpm run start:dev
```

Kemudian di file `.http`, jalankan request secara berurutan:

1. **Create 3 buku** (1a, 1b, 1c) — simpan ID dari masing-masing response
2. **Get All** (2a) — pastikan 3 buku muncul
3. **Get by ID** (3a) — ganti placeholder ID dengan ID dari langkah 1
4. **Update** (4a) — ganti ID, ubah stock menjadi 15
5. **Get by ID lagi** — pastikan stock sudah berubah
6. **Filter** (2b-2g) — pastikan filter berfungsi
7. **Delete** (5a) — ganti ID, hapus satu buku
8. **Get All** — pastikan buku terhapus (tersisa 2)
9. **Error cases** (6a-6e) — pastikan error handling berfungsi

### 5. Variable di REST Client

File `.http` mendukung variable yang didefinisikan dengan `@nama = nilai`:

```http
@baseUrl = http://localhost:3000/api/v1
@token = eyJhbGciOiJIUzI1NiIs...

GET {{baseUrl}}/books
Authorization: Bearer {{token}}
```

Variable bisa digunakan untuk menyimpan base URL, token autentikasi, atau ID yang sering digunakan.

### 6. Menyimpan Response ID untuk Digunakan Request Berikutnya

REST Client mendukung **request chaining** dengan menyimpan response ke variable:

```http
### Simpan ID dari response create
POST {{baseUrl}}/books
Content-Type: application/json

{
  "title": "Test Book",
  "author": "Test Author",
  "isbn": "978-3-16-148410-0",
  "year": 2024,
  "stock": 3
}

### Gunakan ID di request berikutnya
@bookId = {{createBook.response.body.$.id}}

GET {{baseUrl}}/books/{{bookId}}
```

Namun untuk pembelajaran, kita akan mengganti ID secara manual agar lebih memahami prosesnya.

## Analogi

Bayangkan Anda adalah **kepala perpustakaan** yang baru saja meresmikan **sistem komputer baru**. Sebelum sistem ini digunakan oleh semua petugas, Anda harus mengujinya terlebih dahulu:

- **File `.http`** adalah **daftar skenario uji coba** yang sudah ditulis di atas kertas — "Tekan tombol A, masukkan data B, pastikan hasilnya C". Setiap skenario sudah didokumentasikan dengan jelas.

- **REST Client Extension** adalah **asisten penguji** yang membaca skenario dari kertas dan menjalankannya satu per satu. Cukup klik, dan asisten akan mengirim perintah ke sistem baru lalu menampilkan hasilnya.

- **Skenario sukses** (create → get all → get by id → update → delete) adalah **alur normal** yang harus berjalan mulus. Seperti pengunjung normal yang meminjam buku — daftar, cari, pinjam, kembalikan.

- **Skenario error** (data tidak lengkap, ISBN salah) adalah **alur abnormal** — menguji apakah sistem bisa menolak dengan sopan dan memberikan pesan error yang jelas, bukannya crash atau memberikan data salah.

Dengan pengujian ini, Anda sebagai kepala perpustakaan bisa tidur nyenyak karena tahu bahwa sistem baru bekerja sesuai harapan.

## Penggunaan

File REST Client digunakan untuk **quick testing** selama development. Setiap kali menambah endpoint baru, tambahkan request baru di file `.http`. Sebelum commit, jalankan semua request untuk memastikan tidak ada yang rusak (regression). File ini juga berguna untuk **onboarding anggota tim baru** — mereka bisa langsung melihat dan mencoba semua endpoint tanpa setup Postman.

## Kesalahan Umum yang Sering Terjadi

1. **Lupa menjalankan aplikasi** — REST Client hanya mengirim request, tidak menjalankan server. Pastikan `pnpm run start:dev` berjalan di terminal terpisah.

2. **Tidak mengganti placeholder ID** — Mengirim request dengan ID "REPLACE-WITH-ACTUAL-ID" akan menyebabkan 404. Selalu ganti dengan ID nyata dari response create.

3. **Lupa menambahkan header Content-Type** — Untuk POST dan PATCH, header `Content-Type: application/json` wajib agar server bisa membaca body JSON.

4. **Tidak mengupdate file .http saat controller berubah** — Jika menambah atau mengubah endpoint, file .http harus diupdate agar tetap sinkron.

5. **Hanya menguji skenario sukses** — Skenario error (validasi gagal, data tidak ditemukan) sama pentingnya untuk diuji karena ini adalah bagian dari UX API.

## Hubungan dengan Materi Sebelumnya

Setelah berturut-turut membuat module (materi 7), interface (materi 8), DTO (materi 9), service (materi 10), dan controller (materi 11), sekarang kita menguji **semua komponen tersebut bekerja bersama**. Ini adalah langkah terakhir dari siklus pembuatan fitur di module Books sebelum kita beralih ke materi-materi global (folder C).

## Soal Latihan

**Soal:** Buat file `requests/members.http` untuk menguji semua endpoint Members API. Sertakan skenario:
1. Buat 2 anggota baru (lengkap dengan semua field)
2. Get all tanpa filter
3. Get by ID (salah satu anggota)
4. Search anggota berdasarkan nama
5. Filter anggota aktif/non-aktif
6. Update data anggota
7. Hapus anggota
8. Skenario error: anggota tidak ditemukan

