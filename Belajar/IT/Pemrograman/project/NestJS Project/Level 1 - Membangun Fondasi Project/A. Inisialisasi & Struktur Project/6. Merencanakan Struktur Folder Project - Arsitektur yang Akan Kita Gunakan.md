# Merencanakan Struktur Folder Project — Arsitektur yang Akan Kita Gunakan

## Penjelasan

Struktur folder dalam project NestJS bukan sekadar organisasi file — ini adalah cerminan dari arsitektur aplikasi yang akan kita bangun. NestJS memberikan kebebasan penuh dalam mengatur folder, tidak seperti framework lain yang memaksakan struktur tertentu. Namun, ada pola yang sudah terbukti efektif untuk aplikasi berskala menengah hingga besar, yaitu struktur berbasis **modular** dan **feature-first** (bukan type-first).

Dalam arsitektur ini, setiap fitur bisnis (seperti Books, Members, Loans) menjadi sebuah module independen yang memiliki controller, service, DTO, entity, dan test-nya sendiri di dalam satu folder. Selain folder module, ada folder `common/` untuk hal-hal yang digunakan bersama (interceptor, filter, guard) dan folder `config/` untuk konfigurasi aplikasi. Pola ini memastikan bahwa ketika aplikasi tumbuh, developer bisa bekerja pada module yang berbeda tanpa saling mengganggu.

Pendekatan ini juga memudahkan **code splitting** di masa depan — jika suatu module perlu dipisah menjadi microservice, tinggal memindahkan foldernya tanpa perlu refactor besar-besaran. Inilah mengapa perencanaan struktur folder di awal sangat penting: struktur yang baik hari ini akan menghemat puluhan jam refactoring di masa depan.

## Fungsi

Struktur folder berfungsi untuk **mengorganisir kode** secara logis berdasarkan domain bisnis, bukan berdasarkan tipe teknis. Dengan pemisahan yang jelas antara module satu dengan lainnya, aplikasi menjadi lebih mudah dinavigasi, di-maintain, dan di-scale. Struktur yang baik juga memudahkan developer baru untuk memahami aplikasi hanya dengan melihat folder hierarchy.

### Cara Membuat Struktur Folder

```bash
# Buat folder utama
cd perpustakaan-api
mkdir -p src/common/{decorators,filters,guards,interceptors,pipes,interfaces}
mkdir -p src/config
mkdir -p src/modules/{books,dto,entities,interfaces}
mkdir -p src/modules/{members/{entities,dto,interfaces}}
mkdir -p src/modules/{loans/{entities,dto,interfaces}}
mkdir -p src/modules/{auth/{entities,dto,interfaces}}
mkdir -p requests
```

### Mengapa Struktur Ini?

| Folder | Fungsi | Kapan Ditambah |
|--------|--------|----------------|
| `common/` | Shared code (interceptor, filter, guard) | Awal project |
| `config/` | Konfigurasi aplikasi | Saat setup environment |
| `modules/books/` | Fitur manajemen buku | Materi 7-12 |
| `modules/members/` | Fitur manajemen anggota | Level 2 |
| `modules/loans/` | Fitur peminjaman | Level 2 |
| `modules/auth/` | Fitur login/register | Level 3 |
| `requests/` | File testing REST Client | Materi 12 |

### Aturan Penting dalam Struktur Ini

1. **Satu module = satu folder** — Jangan mencampur kode dari module berbeda dalam folder yang sama.
2. **DTO dan Entity disimpan di dalam module** — Bukan di folder global. Setiap module punya DTO sendiri.
3. **Hanya kode bersama di `common/`** — Jika suatu kode hanya dipakai satu module, simpan di module tersebut.
4. **Nama file menggunakan konvensi** — `nama-module.nama-fungsi.ts` (contoh: `books.controller.ts`, `create-book.dto.ts`).

## Analogi

Bayangkan perpustakaan yang terorganisir dengan baik:

- **Folder `src/modules/books/`** adalah **rak buku fiksi** — semua yang berhubungan dengan buku fiksi (buku itu sendiri, kartu katalog, label) ada di satu tempat. Petugas yang bertanggung jawab atas rak ini bisa bekerja tanpa mengganggu rak lain.

- **Folder `src/common/`** adalah **ruang administrasi pusat** — berisi formulir peminjaman standar (interceptor), stempel perpustakaan (decorator), dan aturan umum yang berlaku di semua rak. Setiap petugas rak bisa mengambil formulir ini tanpa perlu membuatnya sendiri.

- **Folder `src/config/`** adalah **ruang kontrol perpustakaan** — berisi pengaturan suhu ruangan, jam operasional, dan konfigurasi sistem keamanan. Hanya kepala perpustakaan yang boleh mengubahnya.

- **Folder `requests/`** adalah **meja tamu** — tempat pengunjung bisa mencoba mengisi formulir peminjaman untuk memastikan semuanya berfungsi sebelum benar-benar digunakan.

- **Folder `test/`** adalah **ruang uji coba** — tempat petugas mencoba sistem baru sebelum diterapkan di perpustakaan sebenarnya.

Dengan struktur ini, jika suatu saat perpustakaan ingin memisahkan rak fiksi menjadi cabang sendiri (microservice), tinggal memindahkan satu rak tanpa mengganggu rak lainnya.

## Penggunaan

Struktur folder ini akan menjadi **rumah bagi seluruh kode** yang kita tulis di semua level roadmap. Mulai dari materi 7 (membuat books module), kita akan konsisten menggunakan struktur ini. Ketika project berkembang ke Level 2 (menambah members dan loans module) dan Level 3 (menambah auth module), kita tinggal menambah folder baru di `src/modules/` tanpa mengubah struktur yang sudah ada.

## Kesalahan Umum yang Sering Terjadi

1. **Struktur flat (datar)** — Semua file controller, service, dan entity ditaruh di satu folder `src/`. Saat project tumbuh, folder ini akan berisi puluhan file yang sulit dinavigasi.

2. **Mencampur kode module di folder berbeda** — Menaruh DTO books di folder `src/dto/books/` dan controllernya di `src/controllers/`. Ini memisahkan kode yang secara logis satu kesatuan.

3. **Membuat folder terlalu dalam** — Struktur seperti `src/modules/books/helpers/validators/` tidak perlu. Cukup simpan fungsi validasi di service atau DTO.

4. **Tidak konsisten dengan konvensi penamaan** — Di satu file menggunakan `book.service.ts`, di file lain `BookController.ts`. Pilih satu konvensi dan terapkan konsisten.

5. **Folder `common/` terlalu gemuk** — Memasukkan kode yang hanya dipakai satu module ke `common/` dengan alasan "mungkin akan dipakai nanti". Tunggu sampai benar-benar dibutuhkan oleh dua module atau lebih.

## Soal Latihan

**Soal:** Buatlah struktur folder berikut di project `perpustakaan-api` dan jelaskan fungsi setiap folder yang dibuat:

```
src/
├── common/
│   └── interceptors/
├── config/
├── modules/
│   └── books/
│       ├── dto/
│       └── interfaces/
└── requests/
```

Kemudian, tuliskan perintah `mkdir` yang digunakan untuk membuat struktur tersebut.

**Jawaban:**

Fungsi setiap folder:
- `src/common/interceptors/` — Menyimpan interceptor global seperti response wrapper dan logging
- `src/config/` — Menyimpan konfigurasi aplikasi seperti database dan environment variables
- `src/modules/books/dto/` — Menyimpan Data Transfer Object untuk module books (CreateBookDto, UpdateBookDto)
- `src/modules/books/interfaces/` — Menyimpan interface TypeScript untuk module books (Book interface)
- `src/requests/` — Menyimpan file `.http` untuk menguji endpoint API

Perintah yang digunakan:

```bash
cd perpustakaan-api
mkdir -p src/common/interceptors
mkdir -p src/config
mkdir -p src/modules/books/{dto,interfaces}
mkdir -p requests
```

**Verifikasi:**

```bash
# Di PowerShell
Get-ChildItem -Path "src" -Recurse -Directory | Select-Object FullName
```

Output akan menampilkan semua folder yang baru dibuat.
