# Memahami Setiap File yang Dibuat NestJS CLI

## Penjelasan

Setelah menjalankan `nest new`, NestJS CLI menghasilkan struktur project yang sudah siap pakai. Setiap file yang dibuat memiliki peran spesifik dalam arsitektur aplikasi. Memahami fungsi masing-masing file sangat penting sebelum kita mulai memodifikasinya. File-file ini bisa dikelompokkan menjadi: file konfigurasi project (TypeScript, ESLint, dll), file aplikasi inti (module, controller, service), dan file pendukung (test, README).

File-file konfigurasi seperti `tsconfig.json`, `nest-cli.json`, `.eslintrc.js`, dan `.prettierrc` mengatur bagaimana kode ditulis, dikompilasi, dan ditegakkan aturannya. Sementara itu, file aplikasi inti di folder `src/` — yaitu `main.ts`, `app.module.ts`, `app.controller.ts`, dan `app.service.ts` — membentuk fondasi arsitektur modular NestJS. Memahami keempat file inti ini adalah kunci untuk menguasai pola kerja NestJS.

Tidak semua file perlu diedit di awal, tetapi mengetahui keberadaan dan fungsinya akan membantu saat troubleshooting atau saat ingin melakukan kustomisasi. Seiring bertambahnya materi, kita akan memodifikasi hampir semua file konfigurasi ini untuk menyesuaikan dengan kebutuhan project perpustakaan kita.

## Fungsi

Setiap file yang dihasilkan CLI memiliki fungsi spesifik: `main.ts` sebagai entry point aplikasi, `app.module.ts` sebagai root module yang mengatur seluruh komponen, `app.controller.ts` sebagai penangan request HTTP, `app.service.ts` sebagai logic bisnis, dan file konfigurasi sebagai pengaturan tooling dan compiler. Memahami fungsi masing-masing file ini mencegah kebingungan saat project mulai berkembang dan kita harus menambah file baru.

## Cara Implementasi / Code

Berikut adalah isi setiap file yang dihasilkan oleh NestJS CLI beserta penjelasannya:

### 1. `src/main.ts` — Entry Point Aplikasi

```typescript
import { NestFactory } from '@nestjs/core';
import { AppModule } from './app.module';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  await app.listen(process.env.PORT ?? 3000);
}
bootstrap();
```

**Penjelasan:** File ini adalah pintu masuk aplikasi. Fungsi `bootstrap()` membuat instance aplikasi NestJS menggunakan `NestFactory.create()` dengan `AppModule` sebagai root module. Di sinilah kita akan menambahkan konfigurasi global seperti global prefix, validation pipe, dan exception filter nantinya.

### 2. `src/app.module.ts` — Root Module

```typescript
import { Module } from '@nestjs/common';
import { AppController } from './app.controller';
import { AppService } from './app.service';

@Module({
  imports: [],
  controllers: [AppController],
  providers: [AppService],
})
export class AppModule {}
```

**Penjelasan:** Module adalah unit organisasi utama di NestJS. `AppModule` adalah root module yang akan mengimport module lain, mendaftarkan controller, dan menyediakan provider. Decorator `@Module()` memiliki tiga properti utama: `imports` (module lain yang diimpor), `controllers` (controller dalam module ini), dan `providers` (service/repository yang disediakan).

### 3. `src/app.controller.ts` — Controller Dasar

```typescript
import { Controller, Get } from '@nestjs/common';
import { AppService } from './app.service';

@Controller()
export class AppController {
  constructor(private readonly appService: AppService) {}

  @Get()
  getHello(): string {
    return this.appService.getHello();
  }
}
```

**Penjelasan:** Controller bertanggung jawab menangani request HTTP yang masuk. Decorator `@Controller()` mendefinisikan class sebagai controller dengan prefix route opsional. Method `@Get()` menangani request GET. Dependency injection dilakukan melalui constructor — `AppService` di-inject secara otomatis oleh NestJS.

### 4. `src/app.service.ts` — Service Dasar

```typescript
import { Injectable } from '@nestjs/common';

@Injectable()
export class AppService {
  getHello(): string {
    return 'Hello World!';
  }
}
```

**Penjelasan:** Service berisi logic bisnis aplikasi. Decorator `@Injectable()` menandai class ini sebagai provider yang bisa di-inject ke class lain. Di sini kita bisa menaruh operasi database, perhitungan, atau panggilan API eksternal.

### 5. `nest-cli.json` — Konfigurasi CLI

```json
{
  "$schema": "https://json.schemastore.org/nest-cli",
  "collection": "@nestjs/schematics",
  "sourceRoot": "src",
  "compilerOptions": {
    "deleteOutDir": true
  }
}
```

**Penjelasan:** File ini mengatur perilaku NestJS CLI. `sourceRoot` menentukan folder sumber, `collection` menentukan schematics yang digunakan, dan `compilerOptions.deleteOutDir` membersihkan folder `dist` sebelum build ulang.

### 6. `tsconfig.json` — Konfigurasi TypeScript

```json
{
  "compilerOptions": {
    "module": "commonjs",
    "declaration": true,
    "removeComments": true,
    "emitDecoratorMetadata": true,
    "experimentalDecorators": true,
    "allowSyntheticDefaultImports": true,
    "target": "ES2021",
    "sourceMap": true,
    "outDir": "./dist",
    "baseUrl": "./",
    "incremental": true,
    "skipLibCheck": true,
    "strictNullChecks": true,
    "noImplicitAny": true,
    "strictBindCallApply": true,
    "forceConsistentCasingInFileNames": true,
    "noFallthroughCasesInSwitch": true
  }
}
```

**Penjelasan:** Konfigurasi TypeScript untuk project NestJS. Dua opsi penting adalah `emitDecoratorMetadata` dan `experimentalDecorators` yang memungkinkan penggunaan decorator — fitur utama NestJS. `outDir: "./dist"` menentukan folder output hasil kompilasi.

### 7. `.eslintrc.js` & `.prettierrc` — Konfigurasi Linter dan Formatter

`.eslintrc.js` mengatur aturan penulisan kode TypeScript, sementara `.prettierrc` mengatur format otomatis seperti indentasi, tanda kutip, dan trailing comma. Keduanya akan dibahas lebih detail di materi ke-4.

### 8. `package.json` — Manajemen Dependencies

File ini berisi daftar dependencies NestJS, devDependencies (testing, TypeScript, ESLint), dan script yang bisa dijalankan. Inilah yang dibaca oleh pnpm saat menginstall packages.

## Analogi

Bayangkan Anda memasuki **perpustakaan yang baru dibangun**. Setiap area memiliki fungsi spesifik:

- **main.ts** adalah **pintu utama perpustakaan** — tempat pertama yang dilewati semua pengunjung. Di sinilah kita menentukan jam buka (port), aturan masuk (global prefix), dan sistem keamanan (guard/filter).

- **app.module.ts** adalah **bagian administrasi perpustakaan** — papan organisasi yang mencatat di mana setiap ruangan berada, rak buku apa saja yang ada, dan staf (service) mana yang bertanggung jawab atas apa.

- **app.controller.ts** adalah **meja informasi/resepsionis** — ketika pengunjung datang dan bertanya, resepsionis yang menerima pertanyaan dan mengarahkannya ke staf yang tepat.

- **app.service.ts** adalah **staf perpustakaan** yang bekerja di belakang meja — mereka yang benar-benar mencari buku, mencatat peminjaman, dan menjalankan operasi sehari-hari.

- **nest-cli.json** adalah **denah gedung** yang memberi tahu kontraktor (CLI) di mana harus meletakkan ruangan baru saat perpustakaan diperluas.

- **tsconfig.json** adalah **aturan standar penulisan katalog** — bagaimana setiap buku (kode) harus ditulis dan dikelompokkan.

## Penggunaan

Pemahaman tentang file-file ini digunakan setiap hari dalam pengembangan NestJS. Saat ingin menambah fitur baru, developer akan membuat module baru (seperti `app.module.ts`), controller baru, dan service baru. File `main.ts` akan dimodifikasi saat menambah konfigurasi global. `nest-cli.json` jarang disentuh tapi penting diketahui saat ingin kostumisasi build process.

## Kesalahan Umum yang Sering Terjadi

1. **Mengedit `main.ts` tanpa memahami struktur** — Banyak pemula langsung menambahkan kode ke `main.ts` tanpa memahami urutan eksekusi. Misalnya, meletakkan `app.useGlobalPipes()` setelah `app.listen()` yang tidak akan pernah tereksekusi.

2. **Lupa mendaftarkan provider di module** — Jika membuat service baru tapi lupa menambahkannya di `providers` array module, NestJS akan melempar error `Nest can't resolve dependencies`.

3. **Menghapus `experimentalDecorators` dari tsconfig** — Tanpa opsi ini, decorator TypeScript tidak akan berfungsi dan aplikasi akan error.

4. **Mengubah `sourceRoot` tanpa menyesuaikan struktur folder** — Jika mengubah `sourceRoot` di `nest-cli.json`, struktur folder juga harus disesuaikan.

5. **Bingung antara controller dan service** — Menaruh logic bisnis di controller adalah kesalahan umum. Controller hanya boleh memanggil service, bukan menjalankan logic itu sendiri.

## Hubungan dengan Materi Sebelumnya

Materi ini adalah **kelanjutan langsung** dari materi ke-1. Setelah project berhasil dibuat dengan `nest new`, sekarang kita memahami isi setiap file yang dihasilkan. Pemahaman ini menjadi bekal untuk materi ke-3 (konfigurasi main.ts) dan materi ke-6 (perencanaan struktur folder), di mana kita akan memodifikasi dan menambah file-file baru ke dalam project.

## Soal Latihan

**Soal:** Dari file `app.controller.ts` yang dihasilkan CLI, jelaskan:
1. Decorator apa saja yang digunakan?
2. Bagaimana cara `AppService` tersedia di dalam controller?
3. Apa yang terjadi jika kita menghapus `AppService` dari `providers` di `app.module.ts`?

**Jawaban:**

1. **Decorator yang digunakan:**
   - `@Controller()` — menandai class sebagai controller NestJS. Bisa diberi prefix route seperti `@Controller('books')`.
   - `@Get()` — menandai method sebagai handler untuk HTTP GET request.
   - `@Injectable()` — digunakan di `AppService` (bukan di controller) untuk menandai class sebagai provider yang bisa di-inject.

2. **Cara `AppService` tersedia di controller** — Melalui **Dependency Injection**. NestJS melihat constructor `AppController` membutuhkan `AppService`, lalu mencarinya di registry module. Karena `AppService` sudah terdaftar di `providers: [AppService]` pada `app.module.ts`, NestJS membuat instance `AppService` dan meng-inject-nya ke controller.

3. **Jika `AppService` dihapus dari `providers`** — NestJS akan melempar error saat runtime:
   ```
   Nest can't resolve dependencies of the AppController (?). 
   Please make sure that the argument AppService at index [0] is available in the AppModule context.
   ```
   Ini karena NestJS tidak bisa menemukan provider yang dibutuhkan oleh controller. Solusinya adalah mendaftarkan `AppService` kembali ke `providers` array.
