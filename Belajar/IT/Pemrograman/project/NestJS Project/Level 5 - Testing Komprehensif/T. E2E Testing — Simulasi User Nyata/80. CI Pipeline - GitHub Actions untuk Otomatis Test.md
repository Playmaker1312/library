# 80. CI Pipeline — GitHub Actions untuk Otomatis Test

## Penjelasan

Continuous Integration (CI) adalah praktik di mana setiap perubahan kode yang di-push ke repository secara otomatis di-build dan di-test. GitHub Actions adalah platform CI/CD bawaan GitHub yang memungkinkan kita mendefinisikan workflow dalam file YAML. Pipeline CI untuk aplikasi NestJS mencakup beberapa tahapan (jobs) yang dijalankan secara berurutan atau paralel: linting untuk memeriksa kualitas kode, unit test untuk validasi cepat, integration test untuk validasi database, dan e2e test untuk validasi end-to-end. Pipeline ini bertindak sebagai quality gate — jika salah satu tahap gagal, pull request tidak bisa di-merge.

Salah satu fitur paling kuat dari GitHub Actions adalah `services`. Dengan services, kita bisa menjalankan container PostgreSQL dan Redis sebagai bagian dari pipeline tanpa perlu Docker Compose terpisah. GitHub Actions menyediakan PostgreSQL dan Redis sebagai service container yang bisa diakses dari job runner. Ini menghilangkan kebutuhan untuk mengelola database test secara manual di CI. Service container ini akan aktif selama job berjalan dan otomatis dihentikan setelah selesai.

Workflow CI yang baik juga mencakup caching untuk mempercepat instalasi dependency, caching untuk Prisma client generation, dan strategi matrix untuk menguji di multiple Node.js versions. Selain itu, kita perlu mengelola secrets seperti `DATABASE_URL` untuk environment test. GitHub Actions menyediakan `secrets` dan `variables` yang bisa dikonfigurasi di level repository. Pipeline juga bisa dikonfigurasi untuk hanya berjalan pada event tertentu: push ke branch tertentu, pull request ke main, atau manual trigger via workflow_dispatch.

## Fungsi

- Mengotomatiskan eksekusi test pada setiap push dan pull request
- Menyediakan service database (PostgreSQL, Redis) untuk integration dan e2e test
- Menjalankan linting untuk memastikan konsistensi kode
- Menghasilkan laporan coverage yang bisa diakses via GitHub
- Mencegah merge kode yang melanggar quality gate (test gagal, coverage turun)
- Memberikan feedback cepat ke developer tentang status kode mereka

## Cara Implementasi / Code

### 1. `.github/workflows/ci.yml` — Pipeline Lengkap

```yaml
# .github/workflows/ci.yml
name: CI Pipeline

# Event trigger
on:
  push:
    branches: [main, develop, 'feature/**']
  pull_request:
    branches: [main]
  workflow_dispatch: # Manual trigger

# Environment variables untuk seluruh workflow
env:
  NODE_VERSION: '20'
  PNPM_VERSION: '8'
  DATABASE_URL: 'postgresql://test_user:test_pass@localhost:5432/library_test'
  REDIS_URL: 'redis://localhost:6379'

jobs:
  # ============== JOB 1: LINTING ==============
  lint:
    name: Lint Code
    runs-on: ubuntu-latest
    timeout-minutes: 10

    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Setup PNPM
        uses: pnpm/action-setup@v2
        with:
          version: ${{ env.PNPM_VERSION }}

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}
          cache: 'pnpm'

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Run ESLint
        run: pnpm lint
        continue-on-error: false

      - name: Run Prettier Check
        run: pnpm format:check
        continue-on-error: true

  # ============== JOB 2: UNIT TEST ==============
  unit-test:
    name: Unit Tests
    runs-on: ubuntu-latest
    timeout-minutes: 15
    needs: [lint] # Menunggu lint selesai

    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Setup PNPM
        uses: pnpm/action-setup@v2
        with:
          version: ${{ env.PNPM_VERSION }}

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}
          cache: 'pnpm'

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Run unit tests with coverage
        run: pnpm test:coverage

      - name: Upload coverage report
        uses: actions/upload-artifact@v4
        if: always() # Upload bahkan jika test gagal
        with:
          name: unit-coverage
          path: coverage/
          retention-days: 7

      - name: Comment coverage on PR
        uses: davelosert/vitest-coverage-report-action@v2
        if: github.event_name == 'pull_request'
        with:
          json-summary-path: coverage/coverage-summary.json

  # ============== JOB 3: INTEGRATION TEST ==============
  integration-test:
    name: Integration Tests
    runs-on: ubuntu-latest
    timeout-minutes: 20
    needs: [lint]

    # Service containers untuk database
    services:
      postgres:
        image: postgres:16-alpine
        env:
          POSTGRES_USER: test_user
          POSTGRES_PASSWORD: test_pass
          POSTGRES_DB: library_test
        ports:
          - 5432:5432
        # Health check untuk memastikan PostgreSQL siap
        options: >-
          --health-cmd pg_isready -U test_user -d library_test
          --health-interval 10s
          --health-timeout 5s
          --health-retries 5

      redis:
        image: redis:7-alpine
        ports:
          - 6379:6379
        options: >-
          --health-cmd "redis-cli ping"
          --health-interval 10s
          --health-timeout 5s
          --health-retries 5

    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Setup PNPM
        uses: pnpm/action-setup@v2
        with:
          version: ${{ env.PNPM_VERSION }}

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}
          cache: 'pnpm'

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Generate Prisma client
        run: npx prisma generate

      - name: Run database migrations
        run: npx prisma migrate deploy
        env:
          DATABASE_URL: ${{ env.DATABASE_URL }}

      - name: Run integration tests
        run: pnpm test:e2e
        env:
          DATABASE_URL: ${{ env.DATABASE_URL }}
          REDIS_URL: ${{ env.REDIS_URL }}
          NODE_ENV: test
          JWT_ACCESS_SECRET: ci-access-secret
          JWT_REFRESH_SECRET: ci-refresh-secret

      - name: Upload integration coverage
        uses: actions/upload-artifact@v4
        if: always()
        with:
          name: e2e-coverage
          path: coverage-e2e/
          retention-days: 7

  # ============== JOB 4: BUILD CHECK ==============
  build:
    name: Build Check
    runs-on: ubuntu-latest
    timeout-minutes: 10
    needs: [unit-test, integration-test]

    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Setup PNPM
        uses: pnpm/action-setup@v2
        with:
          version: ${{ env.PNPM_VERSION }}

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}
          cache: 'pnpm'

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Build application
        run: pnpm build

      - name: Verify build output
        run: ls -la dist/

  # ============== JOB 5: DEPLOY STAGING (Opsional) ==============
  deploy-staging:
    name: Deploy to Staging
    runs-on: ubuntu-latest
    timeout-minutes: 15
    needs: [build]
    if: github.ref == 'refs/heads/main' && github.event_name == 'push'

    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Deploy to staging
        run: echo "Deploying to staging server..."
        # Implementasi deployment aktual:
        # - uses: peaceiris/actions-gh-pages@v3
        # - atau deploy ke VPS/Railway/Fly.io

      - name: Run smoke tests against staging
        run: echo "Running smoke tests..."
        # curl https://staging.example.com/api/health
```

### 2. `.github/workflows/ci.yml` — Versi Minimal (Cepat)

```yaml
# .github/workflows/ci-minimal.yml
# Versi minimal untuk feedback cepat — hanya unit test dan build
name: CI Minimal

on:
  push:
    branches: ['**']
  pull_request:
    branches: [main]

jobs:
  quick-check:
    name: Lint & Unit Test
    runs-on: ubuntu-latest
    timeout-minutes: 10

    services:
      postgres:
        image: postgres:16-alpine
        env:
          POSTGRES_USER: test_user
          POSTGRES_PASSWORD: test_pass
          POSTGRES_DB: library_test
        ports:
          - 5432:5432
        options: >-
          --health-cmd pg_isready
          --health-interval 10s
          --health-timeout 5s
          --health-retries 5

    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v2
        with:
          version: 8
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: 'pnpm'

      - run: pnpm install --frozen-lockfile
      - run: pnpm lint
      - run: pnpm test -- --maxWorkers=2
      - run: pnpm build
```

## Analogi

Bayangkan perpustakaan memiliki **asisten robot** yang secara otomatis memeriksa setiap **buku baru** yang akan ditambahkan ke koleksi. Setiap kali seorang penulis mengirimkan naskah baru (push code), robot ini melakukan serangkaian pemeriksaan: (1) **Pemeriksaan ejaan dan tata bahasa** (linting) — memastikan naskah ditulis dengan format yang benar. (2) **Pemeriksaan setiap bab secara terpisah** (unit test) — memastikan setiap bagian cerita masuk akal. (3) **Pemeriksaan dengan membaca buku dari sampul ke sampul** (integration test) — memastikan bab-bab terhubung dengan baik menggunakan kertas sungguhan. (4) **Simulasi pembaca sungguhan** (e2e test) — seorang sukarelawan membaca buku dari awal hingga akhir dan melaporkan pengalamannya. (5) **Pencetakan buku** (build) — memastikan buku bisa dicetak tanpa error. Jika semua pemeriksaan lulus, buku ditambahkan ke koleksi utama (merge ke main). Robot ini bekerja 24/7 tanpa lelah, memastikan tidak ada buku rusak yang masuk ke perpustakaan.

## Penggunaan

- Otomatisasi quality assurance untuk setiap perubahan kode
- Mencegah regresi dengan menjalankan semua test secara konsisten
- Memberikan transparansi tim tentang status kode (via badge dan PR status)
- Mempercepat review dengan confidence bahwa test sudah lulus
- Dokumentasi infrastructure CI/CD untuk onboarding developer baru

## Kesalahan Umum yang Sering Terjadi

1. **Service container tidak siap saat test dimulai**: PostgreSQL masih booting saat Prisma mencoba koneksi. Solusi: tambahkan health check (`--health-cmd`) dan `--health-retries 5`.

2. **Cache tidak efektif**: `pnpm install` tetap lambat karena cache key tidak tepat. Solusi: gunakan `cache: 'pnpm'` di `setup-node` dan pastikan `pnpm-lock.yaml` di-track.

3. **Secret bocor di log**: Environment variable seperti `DATABASE_URL` tercetak di log CI. Solusi: gunakan `secrets` GitHub Actions untuk nilai sensitif dan jangan `echo` variabel tersebut.

4. **Test timeout di CI**: Test yang berjalan di CI lebih lambat dari local. Solusi: set `testTimeout: 60000` di Jest config untuk e2e test dan `--maxWorkers=2` untuk membatasi paralelisme.

5. **Gagal karena missing Prisma Client**: Prisma Client tidak di-generate sebelum test. Solusi: jalankan `npx prisma generate` sebagai `pretest` script.

6. **Pipeline terlalu lama (>30 menit)**: Developer menunggu terlalu lama untuk feedback. Solusi: gunakan pipeline paralel (unit test dan integration test berjalan bersamaan), atau pipeline bertahap (lint → unit test cepat → integration test).

7. **Disk space habis**: Coverage report dan artifact menumpuk. Solusi: set `retention-days` untuk artifact dan bersihkan `node_modules` antar job jika perlu.
