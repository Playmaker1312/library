# 52. Membuat LoansModule — Service, Repository & Controller

## Penjelasan

Setelah model `Loan` selesai di Prisma, langkah berikutnya adalah membangun modul NestJS yang menangani seluruh logika peminjaman. Mengikuti pola arsitektur yang sudah digunakan di modul Book, kita akan membuat `LoansModule` dengan komponen lengkap: repository interface (`ILoansRepository`), implementasi repository (`PrismaLoansRepository`), service (`LoansService`), dan controller (`LoansController`). Pola Repository digunakan agar logika bisnis terpisah dari akses data, memudahkan testing dan penggantian ORM di masa depan.

Fitur paling kritis dalam service ini adalah method `borrowBook()` yang harus menjalankan logika dalam **Prisma transaction**. Di dalam satu transaksi, kita perlu: mengecek stok buku (apakah masih ada), mengurangi stok, dan membuat record loan baru. Jika salah satu langkah gagal, seluruh operasi di-rollback sehingga data tetap konsisten. Ini mencegah kondisi "race condition" di mana dua user meminjam buku terakhir secara bersamaan.

## Fungsi

`LoansModule` berfungsi sebagai pusat logika bisnis peminjaman yang mencakup validasi stok, pembuatan record peminjaman dengan transaction, pengembalian buku, dan query riwayat peminjaman. Module ini memisahkan tanggung jawab antara repository (data layer), service (business logic), dan controller (HTTP layer).

## Cara Implementasi / Code

### 1. Buat Interface Repository

```typescript
// src/loans/interfaces/loans-repository.interface.ts
import { Loan, LoanStatus } from '@prisma/client';
import { CreateLoanDto } from '../dto/create-loan.dto';

export interface ILoansRepository {
  create(data: CreateLoanDto, userId: string): Promise<Loan>;
  findById(id: string): Promise<Loan | null>;
  findMyLoans(userId: string): Promise<Loan[]>;
  findAll(filter?: { status?: LoanStatus }): Promise<Loan[]>;
  updateStatus(id: string, status: LoanStatus): Promise<Loan>;
  returnBook(id: string): Promise<Loan>;
}
```

### 2. Implementasi Repository

```typescript
// src/loans/repositories/prisma-loans.repository.ts
@Injectable()
export class PrismaLoansRepository implements ILoansRepository {
  constructor(private prisma: PrismaService) {}

  async create(data: CreateLoanDto, userId: string): Promise<Loan> {
    return this.prisma.$transaction(async (tx) => {
      const book = await tx.book.findUniqueOrThrow({
        where: { id: data.bookId },
      });

      if (book.stock < 1) {
        throw new BadRequestException('Stok buku habis');
      }

      await tx.book.update({
        where: { id: data.bookId },
        data: { stock: { decrement: 1 } },
      });

      return tx.loan.create({
        data: {
          userId,
          bookId: data.bookId,
          dueDate: new Date(Date.now() + 14 * 24 * 60 * 60 * 1000), // 14 hari
        },
      });
    });
  }

  async findById(id: string): Promise<Loan | null> {
    return this.prisma.loan.findUnique({ where: { id } });
  }

  async findMyLoans(userId: string): Promise<Loan[]> {
    return this.prisma.loan.findMany({
      where: { userId },
      include: { book: true },
      orderBy: { createdAt: 'desc' },
    });
  }

  async findAll(filter?: { status?: LoanStatus }): Promise<Loan[]> {
    return this.prisma.loan.findMany({
      where: filter,
      include: { user: true, book: true },
      orderBy: { createdAt: 'desc' },
    });
  }

  async updateStatus(id: string, status: LoanStatus): Promise<Loan> {
    return this.prisma.loan.update({ where: { id }, data: { status } });
  }

  async returnBook(id: string): Promise<Loan> {
    return this.prisma.$transaction(async (tx) => {
      const loan = await tx.loan.findUniqueOrThrow({ where: { id } });

      if (loan.status === 'RETURNED') {
        throw new BadRequestException('Buku sudah dikembalikan');
      }

      await tx.book.update({
        where: { id: loan.bookId },
        data: { stock: { increment: 1 } },
      });

      return tx.loan.update({
        where: { id },
        data: {
          status: 'RETURNED',
          returnedAt: new Date(),
        },
      });
    });
  }
}
```

### 3. Service

```typescript
// src/loans/services/loans.service.ts
@Injectable()
export class LoansService {
  constructor(
    @Inject('ILoansRepository')
    private readonly loansRepo: ILoansRepository,
  ) {}

  async borrowBook(createLoanDto: CreateLoanDto, userId: string) {
    return this.loansRepo.create(createLoanDto, userId);
  }

  async returnBook(id: string) {
    return this.loansRepo.returnBook(id);
  }

  async getMyLoans(userId: string) {
    return this.loansRepo.findMyLoans(userId);
  }

  async getAllLoans(status?: LoanStatus) {
    const filter = status ? { status } : undefined;
    return this.loansRepo.findAll(filter);
  }
}
```

## Analogi

Di perpustakaan nyata, proses peminjaman buku melibatkan beberapa langkah yang dilakukan **sekaligus dalam satu kesempatan**: petugas mengecek kartu anggota, memastikan buku tersedia di rak, menurunkan jumlah stok di catatan, dan mengisi kartu peminjaman. Jika kartu anggota ternyata bermasalah, semua langkah batal — buku tidak jadi dipinjam. Ini persis seperti **Prisma transaction** di method `borrowBook()`: semua operasi terjadi dalam satu atomic transaction. Jika stok habis di tengah jalan, rollback terjadi dan tidak ada data yang berubah setengah-setengah.

## Penggunaan

`borrowBook()` dipanggil saat anggota melakukan peminjaman melalui endpoint `POST /loans`. `returnBook()` dipanggil saat pengembalian. Di aplikasi nyata, service ini bisa diperluas dengan validasi tambahan seperti: cek apakah user sedang memiliki denda, cek apakah buku sudah dipinjam oleh user yang sama, limit maksimal peminjaman per user, dan notifikasi email setelah peminjaman berhasil.

## Kesalahan Umum yang Sering Terjadi

1. **Tidak menggunakan transaction** saat create + update stock — risiko data inkonsisten jika salah satu operasi gagal di tengah jalan.
2. **Lupa mengecek stok** sebelum membuat loan — bisa menyebabkan stok negatif.
3. **Tidak mencegah duplicate return** — user bisa mengembalikan buku yang sudah dikembalikan, menyebabkan stok bertambah dua kali.
4. **Hardcode dueDate** tanpa konfigurasi — sebaiknya durasi pinjaman (14 hari) disimpan di environment variable.

## Hubungan dengan Materi Sebelumnya

Di Level 3, kita telah belajar membuat **CRUD module** (Book, Category, User) dengan pola Repository dan Service. `LoansModule` menerapkan pola yang persis sama, tetapi dengan tambahan kompleksitas: **Prisma transaction** dan **relationship management**. Ini adalah natural evolution dari CRUD sederhana menuju business logic yang melibatkan multiple entities sekaligus.

## Soal Latihan

**Soal:**
Tulis method `borrowBook()` beserta DTO dan validasinya yang mengecek: (1) apakah user sudah meminjam buku yang sama dan belum dikembalikan, (2) apakah stok tersedia, (3) buat loan dengan dueDate 14 hari dari sekarang. Gunakan transaction.

**Jawaban:**

```typescript
async borrowBook(dto: CreateLoanDto, userId: string) {
  return this.prisma.$transaction(async (tx) => {
    const existing = await tx.loan.findFirst({
      where: { userId, bookId: dto.bookId, status: 'ACTIVE' },
    });

    if (existing) {
      throw new BadRequestException('Anda masih meminjam buku ini');
    }

    const book = await tx.book.findUniqueOrThrow({ where: { id: dto.bookId } });

    if (book.stock < 1) {
      throw new BadRequestException('Stok buku habis');
    }

    await tx.book.update({
      where: { id: dto.bookId },
      data: { stock: { decrement: 1 } },
    });

    return tx.loan.create({
      data: {
        userId,
        bookId: dto.bookId,
        dueDate: new Date(Date.now() + 14 * 24 * 60 * 60 * 1000),
      },
      include: { book: true },
    });
  });
}
```
