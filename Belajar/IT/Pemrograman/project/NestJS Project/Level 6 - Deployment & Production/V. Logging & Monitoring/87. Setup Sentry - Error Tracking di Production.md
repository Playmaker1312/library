# 87. Setup Sentry - Error Tracking di Production

## Penjelasan
Sentry adalah platform error tracking yang memungkinkan developer melihat, mendiagnosis, dan memperbaiki error di production secara real-time. Ketika terjadi error di aplikasi NestJS, Sentry menangkap detail lengkap: stack trace, environment, browser/user-agent, request URL, parameter, headers, dan bahkan kode sumber yang menyebabkan error (source maps). Semua informasi ini ditampilkan di dashboard Sentry dengan grouping otomatis — error yang sama akan dikelompokkan menjadi satu issue, tidak peduli berapa ribu kali terjadi.

Di NestJS, integrasi Sentry dilakukan di `main.ts` (inisialisasi global) dan di GlobalExceptionFilter (untuk menangkap semua exception yang tidak tertangani). Sentry juga bisa diintegrasikan dengan Winston (file 85) sehingga setiap log error otomatis dikirim ke Sentry. Penting untuk menggunakan **source maps** (peta dari kode JavaScript hasil kompilasi ke TypeScript asli) agar stack trace yang ditampilkan readable — tanpa source maps, kamu hanya melihat kode JavaScript yang sudah di-minify.

## Fungsi
- Menangkap dan mengelompokkan error production secara otomatis
- Menyediakan konteks lengkap (stack trace, request data, environment) untuk setiap error
- Membantu prioritasi bug dengan melihat frekuensi, jumlah user terdampak, dan trend error

## Cara Implementasi / Code

**Install package:**
```bash
npm install @sentry/node @sentry/profiling-node
```

**Inisialisasi di main.ts:**

```typescript
import { NestFactory } from '@nestjs/core';
import { AppModule } from './app.module';
import * as Sentry from '@sentry/node';
import { nodeProfilingIntegration } from '@sentry/profiling-node';

async function bootstrap() {
  // Inisialisasi Sentry SEBELUM NestFactory.create
  Sentry.init({
    dsn: process.env.SENTRY_DSN,
    environment: process.env.NODE_ENV || 'development',
    release: process.env.APP_VERSION || '1.0.0',
    tracesSampleRate: process.env.NODE_ENV === 'production' ? 0.1 : 1.0,
    profilesSampleRate: 0.1,
    integrations: [
      nodeProfilingIntegration(),
    ],
    // Hanya kirim error di production (kecuali debug)
    enabled: process.env.NODE_ENV === 'production',
    // Filter error tertentu (misal 404 tidak perlu dilaporkan)
    beforeSend(event, hint) {
      const exception = hint?.originalException;
      if (exception instanceof HttpException && exception.getStatus() < 500) {
        return null; // Abaikan 4xx error
      }
      return event;
    },
  });

  const app = await NestFactory.create(AppModule);

  // Global prefix
  app.setGlobalPrefix('api');

  await app.listen(3000);
}
bootstrap();
```

**Update GlobalExceptionFilter:**

```typescript
import {
  ExceptionFilter,
  Catch,
  ArgumentsHost,
  HttpException,
  HttpStatus,
  Logger,
} from '@nestjs/common';
import * as Sentry from '@sentry/node';
import { Request, Response } from 'express';

@Catch()
export class AllExceptionsFilter implements ExceptionFilter {
  private readonly logger = new Logger(AllExceptionsFilter.name);

  catch(exception: unknown, host: ArgumentsHost) {
    const ctx = host.switchToHttp();
    const response = ctx.getResponse<Response>();
    const request = ctx.getRequest<Request>();

    let status = HttpStatus.INTERNAL_SERVER_ERROR;
    let message = 'Internal server error';

    if (exception instanceof HttpException) {
      status = exception.getStatus();
      const exResponse = exception.getResponse();
      message = typeof exResponse === 'string' ? exResponse : (exResponse as any).message || message;
    }

    // Kirim error ke Sentry — hanya untuk 500 Internal Server Error
    if (status >= 500) {
      Sentry.withScope((scope) => {
        scope.setTag('httpMethod', request.method);
        scope.setTag('url', request.url);
        scope.setUser({ id: (request as any).user?.id, ip: request.ip });
        scope.setExtra('body', request.body);
        scope.setExtra('query', request.query);
        scope.setExtra('params', request.params);
        scope.setExtra('headers', {
          'user-agent': request.headers['user-agent'],
          'content-type': request.headers['content-type'],
          'x-correlation-id': request.headers['x-correlation-id'],
        });

        Sentry.captureException(exception);
      });
    }

    // Log lokal
    this.logger.error({
      message: exception instanceof Error ? exception.message : 'Unknown error',
      statusCode: status,
      path: request.url,
      method: request.method,
      stack: exception instanceof Error ? exception.stack : undefined,
      correlationId: request.headers['x-correlation-id'],
    });

    response.status(status).json({
      statusCode: status,
      message: status >= 500 ? 'Internal server error' : message,
      correlationId: request.headers['x-correlation-id'],
      timestamp: new Date().toISOString(),
    });
  }
}
```

```yaml
- name: Upload source maps to Sentry
  env:
    SENTRY_AUTH_TOKEN: ${{ secrets.SENTRY_AUTH_TOKEN }}
    SENTRY_ORG: your-org
    SENTRY_PROJECT: your-project
  run: |
    npx @sentry/cli releases new ${{ github.sha }}
    npx @sentry/cli releases files ${{ github.sha }} upload-sourcemaps dist/
    npx @sentry/cli releases set-commits ${{ github.sha }} --auto
    npx @sentry/cli releases finalize ${{ github.sha }}
```

## Analogi
Bayangkan perpustakaan memiliki **sistem alarm otomatis** (Sentry) yang terhubung ke setiap meja petugas. Jika ada meja yang rusak atau terjadi masalah (error), alarm langsung berbunyi dan mengirimkan laporan detail ke kantor pusat: meja mana yang rusak, jam berapa, buku apa yang sedang diproses, dan siapa petugasnya. Laporan ini langsung dikelompokkan — semua laporan tentang meja yang sama digabung jadi satu. Kepala perpustakaan (developer) bisa melihat laporan ini di dashboard dan segera mengambil tindakan sebelum pengunjung (user) merasa terganggu.

## Penggunaan
- **Error monitoring** — Melihat semua error yang terjadi di production secara real-time
- **Performance monitoring** — Melacak response time endpoint dan database query yang lambat (dengan tracing)
- **Crash reporting** — Mendeteksi error yang menyebabkan proses crash (uncaught exception, unhandled rejection)
- **Release tracking** — Melihat apakah versi baru meningkatkan atau mengurangi jumlah error

## Kesalahan Umum yang Sering Terjadi
1. **Tidak memfilter error 4xx** — Sentry dibanjiri error 404, 400, 401 yang bukan bug aplikasi. Gunakan `beforeSend` untuk memfilter.
2. **DSN ter-expose di frontend atau public repo** — DSN adalah public key (tidak terlalu rahasia), tapi sebaiknya tetap di environment variable.
3. **Lupa upload source maps** — Stack trace hanya menampilkan kode JavaScript yang sudah di-minify, sangat sulit dibaca. Upload source maps setiap deploy.
4. **Sentry diaktifkan di development** — Error development yang tidak relevan membanjiri dashboard. Set `enabled: process.env.NODE_ENV === 'production'`.
5. **Tidak menyertakan konteks** — Error di Sentry hanya menampilkan message tanpa request data, user, atau correlation ID. Scope harus diisi dengan informasi yang berguna.

## Hubungan dengan Materi Sebelumnya
Sentry melengkapi Winston (file 85) dan Correlation ID (file 86). Winston mencatat semua log, Correlation ID menghubungkan log yang berkaitan, dan Sentry memberikan dashboard visual untuk error dengan konteks lengkap. Di CI/CD (file 88-90), Source Maps di-upload ke Sentry setiap kali ada release baru.

## Soal Latihan

**Soal:** Kamu ingin menambahkan performance monitoring dengan Sentry untuk endpoint tertentu. Gunakan `Sentry.startSpan` untuk mengukur durasi eksekusi fungsi `processBookLoan` di service. Tulis kode implementasinya.

**Jawaban:**

```typescript
import * as Sentry from '@sentry/node';

@Injectable()
export class BookLoanService {
  async processBookLoan(loanId: string) {
    return await Sentry.startSpan(
      {
        op: 'db.query',
        name: 'Process book loan',
        attributes: { loanId },
      },
      async () => {
        // Logika bisnis di sini
        const loan = await this.prisma.loan.findUnique({ where: { id: loanId } });
        await this.prisma.book.update({
          where: { id: loan.bookId },
          data: { status: 'BORROWED' },
        });
        return loan;
      },
    );
  }
}
```
