# 83. Setup Nginx sebagai Reverse Proxy

## Penjelasan
Nginx adalah web server sekaligus reverse proxy yang sangat populer dan ringan. Dalam konteks deployment NestJS, Nginx ditempatkan **di depan** aplikasi NestJS dan bertugas meneruskan (proxy) semua request HTTP/HTTPS dari client ke aplikasi NestJS yang berjalan di port internal (misalnya `http://localhost:3000`). Mengapa perlu Nginx? Karena NestJS (Express/Fastify) tidak dirancang untuk menangani static file serving, SSL termination, load balancing, atau mitigasi serangan DDoS secara optimal — Nginx unggul di semua itu.

Fungsi utama Nginx di sini: (1) **Reverse proxy** — menerima request dari internet dan meneruskannya ke NestJS; (2) **SSL termination** — menangani enkripsi/decrypt HTTPS, sehingga NestJS tidak perlu repot mengelola certificate; (3) **Static file serving** — melayani file statis seperti gambar, CSS, JS langsung dari Nginx tanpa membebani Node.js; (4) **Security** — menyembunyikan detail internal aplikasi, membatasi rate request, dan memblokir serangan umum.

## Fungsi
- Menyediakan reverse proxy yang handal antara client internet dan aplikasi NestJS
- Menangani SSL/TLS termination sehingga komunikasi client-server terenkripsi
- Meningkatkan keamanan dan performa dengan caching, rate limiting, dan load balancing

## Cara Implementasi / Code

**nginx.conf:**

```nginx
upstream nestjs_app {
    server app:3000;
    keepalive 64;
}

server {
    listen 80;
    server_name api.domain.com;
    return 301 https://$server_name$request_uri;
}

server {
    listen 443 ssl http2;
    server_name api.domain.com;

    # SSL configuration — certificate dari Let's Encrypt / Certbot
    ssl_certificate /etc/letsencrypt/live/api.domain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/api.domain.com/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;

    # Security headers
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-XSS-Protection "1; mode=block" always;

    # Maximum upload size (sesuaikan dengan kebutuhan)
    client_max_body_size 10M;

    # Gzip compression
    gzip on;
    gzip_types application/json text/plain text/css application/javascript;

    location / {
        proxy_pass http://nestjs_app;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;

        # Timeouts
        proxy_connect_timeout 60s;
        proxy_send_timeout 60s;
        proxy_read_timeout 60s;
    }

    # Block akses ke file sensitive
    location ~ /\.(env|git|md) {
        deny all;
        return 404;
    }
}
```

**docker-compose.prod.yml (Nginx service):**

```yaml
version: "3.8"

services:
  nginx:
    image: nginx:alpine
    container_name: nestjs-nginx
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx.conf:/etc/nginx/conf.d/default.conf:ro
      - ./certbot/www:/var/www/certbot:ro
      - ./certbot/conf:/etc/letsencrypt:ro
    depends_on:
      - app
    networks:
      - nestjs-network

  app:
    image: ghcr.io/username/nestjs-app:latest
    container_name: nestjs-app
    restart: unless-stopped
    expose:
      - "3000"
    env_file:
      - .env.production
    networks:
      - nestjs-network

  # ... db, redis services (sama seperti sebelumnya)

networks:
  nestjs-network:
    driver: bridge
```

Beberapa catatan penting:
- Nginx menggunakan `upstream` block untuk mendefinisikan group server (dalam hal ini satu server: `app:3000`). Jika nanti ada multiple instance NestJS, kita tinggal tambahkan `server app2:3000;` di sini.
- Header `X-Forwarded-For`, `X-Real-IP`, dan `X-Forwarded-Proto` sangat penting agar NestJS mengetahui IP asli client dan protokol yang digunakan (HTTP/HTTPS). Tanpa header ini, semua request akan terlihat berasal dari IP container Nginx.
- Di NestJS, kamu perlu mengaktifkan `trust proxy` setting di main.ts: `app.set('trust proxy', 1)` (Express) atau konfigurasi serupa.

## Analogi
Bayangkan perpustakaan memiliki **pintu masuk utama** (Nginx) yang dilengkapi **satpam** dan **meja informasi**. Semua pengunjung (client) masuk melalui pintu ini. Satpam memeriksa identitas (SSL), meja informasi mengarahkan pengunjung ke ruangan yang tepat (reverse proxy ke NestJS). Jika ada buku yang sering diminta, satpam langsung memberikan salinan dari rak depan (caching) tanpa perlu ke gudang belakang. Pengunjung tidak perlu tahu di mana ruang penyimpanan sebenarnya berada — pintu utama adalah satu-satunya pintu yang mereka lihat.

## Penggunaan
Dipakai di semua environment production yang membutuhkan reverse proxy, SSL termination, dan security layer tambahan. Juga digunakan jika kamu menjalankan beberapa aplikasi (NestJS API + frontend React + Adminer) di satu server dengan domain berbeda.

## Kesalahan Umum yang Sering Terjadi
1. **Lupa mengatur `proxy_set_header Host`** — NestJS tidak tahu hostname asli, bisa menyebabkan redirect ke localhost atau error pada aplikasi.
2. **Tidak mengaktifkan `trust proxy` di NestJS** — Rate limiter atau fitur yang bergantung pada IP client akan salah karena mendeteksi IP container Nginx, bukan IP asli.
3. **Ukuran `client_max_body_size` terlalu kecil** — Upload file besar (misal gambar profil 5MB) ditolak Nginx dengan error 413.
4. **SSL certificate tidak di-renew** — Setelah 90 hari, browser menampilkan peringatan "Not Secure". Solusinya: setup Certbot auto-renewal.
5. **Konfigurasi Nginx tidak di-validasi** — Typo di nginx.conf menyebabkan Nginx gagal start. Selalu jalankan `nginx -t` untuk validasi.

## Hubungan dengan Materi Sebelumnya
Sebelumnya (file 82) kita menguji aplikasi di `localhost:3000` langsung. Sekarang kita menambahkan Nginx di depan sebagai proxy, sehingga akses via port 80/443 akan diteruskan ke port 3000 internal. Ini adalah tipikal arsitektur production — aplikasi NestJS tidak boleh terpapar langsung ke internet.

## Soal Latihan

**Soal:** Kamu memiliki aplikasi NestJS dan frontend React yang berjalan di dua container berbeda: `app:3000` dan `frontend:80`. Buat konfigurasi Nginx di `api.domain.com` yang me-route:
- `/api/*` → NestJS backend
- `/` → React frontend
- Tambahkan SSL redirect dari HTTP ke HTTPS

**Jawaban:**

```nginx
upstream backend {
    server app:3000;
}

upstream frontend {
    server frontend:80;
}

server {
    listen 80;
    server_name api.domain.com;
    return 301 https://$server_name$request_uri;
}

server {
    listen 443 ssl http2;
    server_name api.domain.com;

    ssl_certificate /etc/letsencrypt/live/api.domain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/api.domain.com/privkey.pem;

    location /api/ {
        proxy_pass http://backend;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location / {
        proxy_pass http://frontend;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```
