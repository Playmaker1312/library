# 100. DataLoader - Solve N+1 Problem di GraphQL

## Penjelasan
**N+1 problem** adalah masalah klasik di GraphQL (dan ORM pada umumnya). Ketika client melakukan query seperti `{ books { title, category { name } } }`, GraphQL akan memanggil resolver `Book.category` untuk **setiap buku** secara individu. Jika ada 100 buku, akan terjadi 1 query untuk daftar buku + 100 query untuk kategori = 101 query. Ini sangat tidak efisien dan bisa membuat API lambat.

**DataLoader** adalah utility yang dibuat oleh Facebook untuk solve masalah ini. Prinsip kerjanya sederhana: **batch** dan **cache**. DataLoader mengumpulkan semua request dalam satu event loop tick, lalu mengeksekusinya dalam satu batch query (misal: SELECT * FROM category WHERE id IN (id1, id2, ... id100) — cukup 1 query). Selain itu, DataLoader juga **caches** hasil per request — jika kategori yang sama diminta dua kali dalam satu request, DataLoader hanya memanggilnya sekali. DataLoader dibuat per request (bukan singleton global) untuk menghindari cache leak antar request. Di NestJS, kita membuat class DataLoader yang di-inject ke resolver, atau menggunakan module seperti `nestjs-dataloader` untuk integrasi yang lebih rapi.

## Fungsi
- Menghilangkan N+1 problem dengan batching query — ratusan query jadi 1 query
- Caching dalam satu request — data yang sudah di-fetch tidak akan di-fetch ulang
- Meningkatkan performa GraphQL resolver secara drastis, terutama untuk relasi
- Menjaga response time tetap stabil meskipun jumlah data besar

## Cara Implementasi / Code

**1. Install DataLoader:**

**2. Category DataLoader — books.dataloader.ts:**
```typescript
import * as DataLoader from 'dataloader';
import { Injectable, OnModuleInit } from '@nestjs/common';
import { PrismaService } from '../prisma/prisma.service';

@Injectable()
export class CategoryLoader implements OnModuleInit {
  private loader: DataLoader<string, any>;

  constructor(private readonly prisma: PrismaService) {}

  onModuleInit() {
    this.loader = new DataLoader<string, any>(async (ids: string[]) => {
      // Batch query: SELECT * FROM category WHERE id IN (...ids)
      const categories = await this.prisma.category.findMany({
        where: { id: { in: ids as string[] } },
      });

      // Map: hasil harus dalam urutan yang sama dengan input ids
      const categoryMap = new Map(
        categories.map((cat) => [cat.id, cat]),
      );

      return ids.map((id) => categoryMap.get(id) || null);
    });
  }

  getLoader(): DataLoader<string, any> {
    return this.loader;
  }
}
```

import * as DataLoader from 'dataloader';

  getLoader(): DataLoader<string, any> {
    return this.loader;
  }
}

**4. Multi-purpose Loader — Generic pattern:**
```typescript
import * as DataLoader from 'dataloader';
import { Injectable } from '@nestjs/common';

@Injectable()
export class DataLoaderService {
  constructor(private readonly prisma: PrismaService) {}

  createLoader<T>(
    modelName: string,
    keyField: string = 'id',
  ): DataLoader<string, T | null> {
    return new DataLoader<string, T | null>(async (keys: string[]) => {
      const records = await (this.prisma as any)[modelName].findMany({
        where: { [keyField]: { in: keys } },
      });

      const map = new Map(
        records.map((r: any) => [r[keyField], r]),
      );

      return keys.map((key) => map.get(key) || null);
    });
  }
}
```

**5. Gunakan DataLoader di Resolver — books.resolver.ts:**
```typescript
import { Resolver, ResolveField, Parent, Context } from '@nestjs/graphql';
import { BookType, CategoryType } from './book.type';
import { CategoryLoader } from './books.dataloader';

@Resolver(() => BookType)
export class BooksResolver {
  constructor(
    private readonly booksService: BooksService,
    private readonly categoryLoader: CategoryLoader,
  ) {}

  // ... query & mutation methods ...

  @ResolveField(() => CategoryType, {
    name: 'category',
    description: 'Kategori buku (di-load dengan DataLoader)',
  })
  async getCategory(@Parent() book: BookType) {
    // Tanpa DataLoader:
    // return this.booksService.getCategory(book.categoryId);
    // → 1 query PER buku = N+1

    // Dengan DataLoader:
    return this.categoryLoader.getLoader().load(book.categoryId);
    // → batch semua categoryId, 1 query total
  }
}
```

**6. DataLoader untuk multiple levels — Book → Loans → User:**
```typescript
import { Injectable, OnModuleInit } from '@nestjs/common';
import * as DataLoader from 'dataloader';
import { PrismaService } from '../prisma/prisma.service';

@Injectable()
export class LoanLoader implements OnModuleInit {
  private loader: DataLoader<string, any[]>;

  constructor(private readonly prisma: PrismaService) {}

  onModuleInit() {
    // Loader untuk list loans per book (one-to-many)
    this.loader = new DataLoader<string, any[]>(async (bookIds: string[]) => {
      const loans = await this.prisma.loan.findMany({
        where: { bookId: { in: bookIds as string[] } },
        include: { member: true },
        orderBy: { borrowedAt: 'desc' },
      });

      // Group loans by bookId
      const loansByBook = new Map<string, any[]>();
      for (const loan of loans) {
        if (!loansByBook.has(loan.bookId)) {
          loansByBook.set(loan.bookId, []);
        }
        loansByBook.get(loan.bookId)!.push(loan);
      }

      return bookIds.map((id) => loansByBook.get(id) || []);
    });
  }

  getLoader(): DataLoader<string, any[]> {
    return this.loader;
  }
}
```

**8. Benchmark — Sebelum dan Sesudah DataLoader:**
```
Query: { books(limit: 50) { title, category { name } } }

TANPA DataLoader (N+1):
  - 1 query: SELECT * FROM book LIMIT 50
  - 50 query: SELECT * FROM category WHERE id = $1 (×50)
  - Total: 51 queries
  - Response time: ~850ms

DENGAN DataLoader:
  - 1 query: SELECT * FROM book LIMIT 50
  - 1 query: SELECT * FROM category WHERE id IN ($1,$2,...,$50)
  - Total: 2 queries
  - Response time: ~45ms

Peningkatan: ~18x lebih cepat!
```

## Analogi
Bayangkan perpustakaan memiliki **100 pengunjung** yang masing-masing bertanya "di rak mana buku ini berada?". Tanpa DataLoader, petugas harus lari ke rak **100 kali** (sekali untuk setiap buku). Dengan DataLoader, petugas mengumpulkan semua pertanyaan dulu — "oh, kalian menanyakan rak dari 100 buku" — lalu melihat **satu peta besar** yang menunjukkan lokasi semua buku sekaligus. Hanya perlu 1 kali perjalanan ke peta, bukan 100. Inilah esensi DataLoader: **kumpulkan semua ID, batch query, distribusikan hasil**.

## Penggunaan
- Setiap `@ResolveField()` yang mengambil data dari tabel lain (relasi belongsTo, hasMany)
- Query yang mengakses field `category`, `author`, `loans` dari Book
- Query bertingkat: `books → category → books` (circular reference)
- REST API migration ke GraphQL — terutama jika sebelumnya sudah ada N+1 problem

## Kesalahan Umum yang Sering Terjadi
1. **Membuat DataLoader sebagai singleton global** — DataLoader punya cache per instance. Jika singleton, cache dari request A bocor ke request B. Buat instance baru per request atau gunakan module scoped provider.
2. **Tidak handle null** — Jika ID tidak ditemukan, DataLoader harus mengembalikan `null` di posisi yang sesuai. Jangan throw error — kembalikan `null` dan biarkan resolver yang handle.
3. **Batch function tidak mengembalikan dalam urutan yang sama** — Jika input `[3, 1, 2]`, output harus `[cat3, cat1, cat2]`. Urutan harus persis sama dengan input, atau peta data akan salah.
4. **Lupa register di module** — DataLoader harus didaftarkan sebagai provider di module, jika tidak decorator `@Injectable()` tidak akan bekerja.
5. **Tidak menggunakan DataLoader untuk semua relasi** — Hanya menggunakan DataLoader di satu resolver tapi melewatkannya di resolver lain tetap menyebabkan N+1 parsial. Gunakan DataLoader secara konsisten.

## Hubungan dengan Materi Sebelumnya
Di materi 98 kita setup GraphQL, di materi 99 kita membuat resolver dasar. Sekarang kita solve masalah performa utama GraphQL: N+1 problem yang juga kita bahas di materi 93 (database indexing). DataLoader adalah solusi di layer aplikasi, sedangkan indexing adalah solusi di layer database — keduanya bekerja bersama untuk performa optimal. Dengan DataLoader, arsitektur GraphQL NestJS kita sudah production-ready.

**Soal:** Buat DataLoader untuk resolve field `author` di BookType. Author disimpan sebagai `authorId` di Book, dan ada tabel Author terpisah dengan field `id`, `name`, `bio`. Tulis: (1) AuthorLoader, (2) ResolveField di BooksResolver, (3) Prisma query untuk batch loading.
