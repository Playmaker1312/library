# 98. Setup GraphQL di NestJS - Code-First Approach

## Penjelasan
GraphQL adalah query language untuk API yang memungkinkan client meminta data spesifik yang mereka butuhkan — tidak lebih, tidak kurang. Berbeda dengan REST yang memiliki banyak endpoint (GET /books, GET /books/:id, GET /books/:id/loans), GraphQL memiliki satu endpoint (`/graphql`) di mana client mengirim query dan mendapatkan response sesuai struktur query. NestJS mendukung GraphQL melalui `@nestjs/graphql` dengan dua pendekatan: **Code-First** (kita mendefinisikan tipe menggunakan decorator TypeScript, dan NestJS otomatis generate schema GraphQL dari kode) dan **Schema-First** (kita menulis file `.graphql` schema terlebih dahulu, lalu NestJS generate TypeScript types).

**Code-First Approach** adalah pilihan utama karena: (1) kita hanya perlu menulis TypeScript, (2) schema selalu sinkron dengan kode, (3) decorator memberikan type safety penuh, (4) IDE autocomplete bekerja sempurna. Dengan `autoSchemaFile: true`, NestJS akan men-generate file `schema.graphql` otomatis di memory (atau di path tertentu untuk dilihat). **GraphQL Playground** atau **Apollo Sandbox** adalah UI interaktif untuk mengeksplorasi API GraphQL — kita bisa menulis query, melihat dokumentasi schema, dan menguji mutation.

## Fungsi
- Menyediakan satu endpoint yang fleksibel untuk client — client menentukan data apa yang dibutuhkan
- Menghilangkan over-fetching (kelebihan data) dan under-fetching (data kurang) yang umum di REST
- Schema yang terdefinisi dengan jelas (type system) — dokumentasi hidup untuk frontend dan backend
- Playground interaktif untuk eksplorasi API tanpa postman

## Cara Implementasi / Code

**1. Install dependencies:**
```bash
npm install @nestjs/graphql @nestjs/apollo @apollo/server graphql
```

**2. app.module.ts — Konfigurasi GraphQLModule:**
```typescript
import { Module } from '@nestjs/common';
import { GraphQLModule } from '@nestjs/graphql';
import { ApolloDriver, ApolloDriverConfig } from '@nestjs/apollo';
import { join } from 'path';
import { BooksModule } from './books/books.module';

@Module({
  imports: [
    GraphQLModule.forRoot<ApolloDriverConfig>({
      driver: ApolloDriver,
      autoSchemaFile: join(process.cwd(), 'src/schema.gql'), // generate ke file
      // autoSchemaFile: true, // atau simpan di memory
      playground: true, // aktifkan playground
      introspection: process.env.NODE_ENV !== 'production', // nonaktifkan di prod
      sortSchema: true, // urutkan schema alphabetically
      definitions: {
        path: join(process.cwd(), 'src/graphql.ts'), // generate TypeScript types
      },
    }),
    BooksModule,
  ],
})
export class AppModule {}
```

**3. main.ts — Jangan lupa ValidationPipe untuk input:**
```typescript
import { NestFactory } from '@nestjs/core';
import { AppModule } from './app.module';
import { ValidationPipe } from '@nestjs/common';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);

  app.useGlobalPipes(new ValidationPipe({ whitelist: true }));
  app.enableCors();

  await app.listen(3000);
  console.log(`GraphQL API: http://localhost:3000/graphql`);
}
bootstrap();
```

**4. Struktur folder untuk GraphQL module:**
```
src/
  books/
    books.module.ts
    books.resolver.ts    # Resolver — handler query/mutation
    books.service.ts     # Business logic (sama seperti REST)
    book.type.ts         # @ObjectType() — tipe GraphQL
    book.input.ts        # @InputType() — input untuk mutation
    books-loader.ts      # DataLoader (materi 100)
  schema.gql             # Auto-generated schema
  graphql.ts             # Auto-generated TypeScript types
```

**5. Konfigurasi tambahan — Context (untuk auth):**
```typescript
// main.ts atau app.module
GraphQLModule.forRoot<ApolloDriverConfig>({
  driver: ApolloDriver,
  autoSchemaFile: true,
  context: ({ req }) => {
    // Extract token dari header, attach user ke context
    const token = req.headers.authorization?.replace('Bearer ', '');
    return { req, token };
  },
  // Atau gunakan format function
  context: ({ req, res }) => ({ req, res }),
}),
```

**6. package.json script untuk generate schema:**
```json
{
  "scripts": {
    "start:dev": "nest start --watch",
    "generate:graphql": "nest start --entryFile generate-graphql"
  }
}
```

**7. Konfigurasi production — Nonaktifkan playground:**
```typescript
GraphQLModule.forRoot<ApolloDriverConfig>({
  driver: ApolloDriver,
  autoSchemaFile: true,
  playground: false,
  introspection: false,
  // Batasi query complexity untuk mencegah abuse
  plugins: [
    ApolloServerPluginLandingPageDisabled(),
  ],
}),
```

## Analogi
Bayangkan perpustakaan mengganti **sistem katalog kertas** (REST — setiap lemari punya kategori tetap) dengan **asisten digital** (GraphQL). Pengunjung cukup berkata "saya ingin tahu judul buku karya Tere Liye yang terbit setelah 2020, cukup judul dan tahunnya saja" — asisten digital akan pergi ke database, mengambil persis data itu, dan mengembalikannya (query). Jika pengunjung ingin meminjam buku, ia bisa berkata "pinjamkan buku ini untuk saya" (mutation). Asisten digital bekerja dengan **panduan fungsi** yang jelas (schema) — ia tahu persis data apa yang tersedia dan bagaimana cara mengaksesnya. Tidak ada lagi pengunjung yang menerima seluruh data buku padahal hanya butuh judulnya saja (over-fetching), atau harus ke beberapa meja berbeda untuk mendapatkan informasi lengkap (under-fetching).

## Penggunaan
- Aplikasi dengan frontend yang membutuhkan fleksibilitas data (React, Vue, mobile apps)
- API publik di mana client (third-party developer) ingin memilih field yang mereka butuhkan
- Dashboard dengan banyak view berbeda yang membutuhkan kombinasi data unik
- Sistem dengan relasi data kompleks (book → author → loans → user) yang bisa di-query dalam satu request

## Kesalahan Umum yang Sering Terjadi
1. **Lupa install @nestjs/apollo** — Hanya install `@nestjs/graphql` akan error karena driver tidak ditemukan. NestJS 10+ mewajibkan driver eksplisit.
2. **Playground aktif di production** — Jika lupa set `playground: false` di production, schema API terekspos ke publik. Set `introspection: false` juga.
3. **autoSchemaFile conflict** — Jika dua module mendefinisikan `@ObjectType()` dengan nama yang sama, akan error. Pastikan nama tipe unik.
4. **Class-validator tidak jalan** — GraphQL menggunakan `ValidationPipe` juga. Jika ada `@InputType()` tanpa validasi, input tidak tervalidasi. Tambahkan `@IsString()`, `@IsOptional()`, dll.
5. **Tidak mengatur context** — Tanpa context function, resolver tidak bisa mengakses request headers (token JWT). Tambahkan context untuk auth.

## Hubungan dengan Materi Sebelumnya
Di Level 1–6 kita membangun REST API. Sekarang kita memperkenalkan GraphQL sebagai alternatif atau pelengkap. Service, Prisma, Guards, dan semua konsep NestJS yang sudah dipelajari tetap bisa digunakan — hanya controller/gateway diganti dengan resolver. Materi 99 dan 100 akan membangun resolver lengkap dengan DataLoader untuk solve N+1.

## Soal Latihan

**Soal:** Konfigurasi GraphQLModule dengan ketentuan: (1) menggunakan ApolloDriver, (2) schema digenerate ke file `src/schema.graphql`, (3) playground hanya aktif di development, (4) context mengekstrak `x-tenant-id` dari header. Tulis kode konfigurasinya.

**Jawaban:**
```typescript
// app.module.ts
import { Module } from '@nestjs/common';
import { GraphQLModule } from '@nestjs/graphql';
import { ApolloDriver, ApolloDriverConfig } from '@nestjs/apollo';
import { join } from 'path';

@Module({
  imports: [
    GraphQLModule.forRoot<ApolloDriverConfig>({
      driver: ApolloDriver,
      autoSchemaFile: join(process.cwd(), 'src/schema.graphql'),
      playground: process.env.NODE_ENV !== 'production',
      introspection: process.env.NODE_ENV !== 'production',
      context: ({ req }) => ({
        req,
        tenantId: req.headers['x-tenant-id'] || 'default',
      }),
    }),
  ],
})
export class AppModule {}
```
