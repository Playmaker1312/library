# 97. Event-Driven dengan RabbitMQ - Komunikasi Async Antar Service

## Penjelasan
Dalam arsitektur microservices, tidak semua komunikasi perlu bersifat **synchronous** (request-response seperti TCP). Operasi seperti mengirim email notifikasi, memperbarui stok, atau mencatat log tidak perlu menunggu response real-time. Untuk skenario ini, **event-driven communication** menggunakan message broker seperti **RabbitMQ** adalah pilihan tepat. Service yang memproduksi event (publisher) cukup mengirim pesan ke exchange, dan service yang tertarik (subscriber) akan menerimanya secara async tanpa publisher perlu tahu siapa subscriber-nya.

RabbitMQ menggunakan konsep **Exchange**, **Queue**, dan **Binding**. Publisher mengirim pesan ke Exchange dengan **routing key**. Exchange akan me-routing pesan ke Queue yang terikat (bind) dengan routing key yang cocok. Consumer mengambil pesan dari Queue dan memprosesnya. Di NestJS, `@nestjs/microservices` mendukung `Transport.RMQ` yang mengabstraksi kompleksitas RabbitMQ. Publisher menggunakan `ClientProxy.emit()` (bukan `send()` — emit tidak menunggu response), subscriber menggunakan `@EventPattern()` (bukan `@MessagePattern`). Pola **Event-Driven** membuat system lebih **decoupled** — jika Notification Service mati, Loans Service tetap bisa memproses peminjaman; notifikasi akan di-queue dan diproses ketika Notification Service kembali hidup.

## Fungsi
- Komunikasi async antar service tanpa blocking — publisher tidak menunggu response
- Decoupling: service tidak perlu tahu satu sama lain, cukup tahu format event
- Resilience: jika subscriber mati, event tetap di-queue dan diproses saat subscriber kembali
- Scalability: multiple instance subscriber bisa membaca dari queue yang sama (competing consumers)
- Audit trail: semua event bisa dicatat untuk debugging dan replay

**2. Loans Service — Publisher (emit event saat peminjaman dibuat):**
```typescript
// loans.module.ts — register ClientsModule untuk RabbitMQ
import { Module } from '@nestjs/common';
import { ClientsModule, Transport } from '@nestjs/microservices';
import { LoansController } from './loans.controller';
import { LoansService } from './loans.service';

@Module({
  imports: [
    ClientsModule.register([
      {
        name: 'NOTIFICATION_SERVICE',
        transport: Transport.RMQ,
        options: {
          urls: ['amqp://nestjs:nestjs@localhost:5672'],
          queue: 'notification_queue',
          queueOptions: {
            durable: true, // queue tetap ada meski restart
          },
        },
      },
    ]),
  ],
  controllers: [LoansController],
  providers: [LoansService],
})
export class LoansModule {}
```

```typescript
// loans.service.ts — emit event setelah create loan
import { Injectable, Inject } from '@nestjs/common';
import { ClientProxy } from '@nestjs/microservices';

@Injectable()
export class LoansService {
  constructor(
    @Inject('NOTIFICATION_SERVICE')
    private readonly notificationClient: ClientProxy,
  ) {}

  async createLoan(bookId: string, memberId: string) {
    // 1. Proses bisnis: simpan loan ke database
    const loan = await this.prisma.loan.create({
      data: { bookId, memberId, status: 'ACTIVE' },
      include: { book: true, member: true },
    });

    // 2. Emit event async — tidak perlu menunggu
    this.notificationClient.emit('loan.created', {
      loanId: loan.id,
      memberEmail: loan.member.email,
      memberName: loan.member.name,
      bookTitle: loan.book.title,
      borrowedAt: loan.borrowedAt,
      dueDate: new Date(Date.now() + 14 * 24 * 60 * 60 * 1000), // 14 hari
    });

    console.log(`Event loan.created emitted for loan ${loan.id}`);
    return loan;
  }

  async returnBook(loanId: string) {
    const loan = await this.prisma.loan.update({
      where: { id: loanId },
      data: { status: 'RETURNED', returnedAt: new Date() },
      include: { book: true, member: true },
    });

    // Emit event buku dikembalikan
    this.notificationClient.emit('loan.returned', {
      loanId: loan.id,
      memberEmail: loan.member.email,
      memberName: loan.member.name,
      bookTitle: loan.book.title,
      returnedAt: loan.returnedAt,
    });

    return loan;
  }
}
```

**3. Notification Service — Subscriber (menerima event dan kirim email):**
```typescript
// main.ts — Notification Service sebagai microservice RabbitMQ
import { NestFactory } from '@nestjs/core';
import { MicroserviceOptions, Transport } from '@nestjs/microservices';
import { NotificationModule } from './notification.module';

async function bootstrap() {
  const app = await NestFactory.createMicroservice<MicroserviceOptions>(
    NotificationModule,
    {
      transport: Transport.RMQ,
      options: {
        urls: ['amqp://nestjs:nestjs@localhost:5672'],
        queue: 'notification_queue',
        queueOptions: { durable: true },
        noAck: false, // manual acknowledge — agar pesak tidak hilang
      },
    },
  );

  await app.listen();
  console.log('Notification Service listening for events');
}
bootstrap();
```

```typescript
// notification.controller.ts — @EventPattern handler
import { Controller } from '@nestjs/common';
import { EventPattern, Payload, Ctx, RmqContext } from '@nestjs/microservices';

@Controller()
export class NotificationController {
  constructor(private readonly notificationService: NotificationService) {}

  @EventPattern('loan.created')
  async handleLoanCreated(
    @Payload() data: {
      loanId: string;
      memberEmail: string;
      memberName: string;
      bookTitle: string;
      borrowedAt: Date;
      dueDate: Date;
    },
    @Ctx() context: RmqContext,
  ) {
    console.log(`Received loan.created event: ${data.loanId}`);

    try {
      await this.notificationService.sendEmail({
        to: data.memberEmail,
        subject: 'Peminjaman Buku Berhasil',
        template: 'loan-confirmation',
        context: {
          name: data.memberName,
          bookTitle: data.bookTitle,
          borrowedAt: data.borrowedAt,
          dueDate: data.dueDate,
        },
      });

      // Acknowledge — hapus pesan dari queue
      const channel = context.getChannelRef();
      const originalMsg = context.getMessage();
      channel.ack(originalMsg);
    } catch (error) {
      // Jika gagal, jangan ack — pesan akan dikirim ulang
      console.error(`Failed to process loan.created: ${error.message}`);
      const channel = context.getChannelRef();
      const originalMsg = context.getMessage();
      channel.nack(originalMsg, false, true); // requeue
    }
  }

  @EventPattern('loan.returned')
  async handleLoanReturned(
    @Payload() data: {
      loanId: string;
      memberEmail: string;
      memberName: string;
      bookTitle: string;
      returnedAt: Date;
    },
    @Ctx() context: RmqContext,
  ) {
    console.log(`Received loan.returned event: ${data.loanId}`);

    await this.notificationService.sendEmail({
      to: data.memberEmail,
      subject: 'Buku Telah Dikembalikan',
      template: 'loan-returned',
      context: {
        name: data.memberName,
        bookTitle: data.bookTitle,
        returnedAt: data.returnedAt,
      },
    });

    const channel = context.getChannelRef();
    const originalMsg = context.getMessage();
    channel.ack(originalMsg);
  }
}
```

```typescript
// notification.service.ts:
import { Injectable } from '@nestjs/common';
import { MailerService } from '@nestjs-modules/mailer';

@Injectable()
export class NotificationService {
  constructor(private readonly mailerService: MailerService) {}

  async sendEmail(options: {
    to: string;
    subject: string;
    template: string;
    context: Record<string, any>;
  }) {
    await this.mailerService.sendMail({
      to: options.to,
      subject: options.subject,
      template: options.template,
      context: options.context,
    });

    // Catat log notifikasi
    console.log(`Email sent to ${options.to}: ${options.subject}`);
  }
}

## Analogi
Bayangkan perpustakaan memiliki **papan pengumuman** (RabbitMQ Exchange) di ruang staf. Ketika **Bagian Sirkulasi** (Loans Service) memproses peminjaman buku, ia menempelkan pengumuman di papan: "Buku Laskar Pelangi dipinjam oleh Budi — 12 Juni 2026" — ini adalah **event** `loan.created`. **Bagian Notifikasi** (Notification Service) secara rutin mengecek papan pengumuman (queue), membaca pengumuman baru, lalu mengirim surat pemberitahuan ke rumah Budi. Yang penting: Bagian Sirkulasi tidak perlu menunggu surat selesai dikirim — ia sudah kembali melayani pengunjung berikutnya. Jika Bagian Notifikasi sedang tutup (service down), pengumuman tetap tertempel di papan dan akan dibaca saat bagian itu buka lagi.

## Penggunaan
- Mengirim email notifikasi (konfirmasi peminjaman, reminder overdue, denda)
- Memperbarui stok/ inventaris setelah peminjaman atau pengembalian
- Mencatat log aktivitas ke central logging system
- Sinkronisasi data antar service (misal: user update profile → sinkron ke service lain)
- Pipeline processing yang memerlukan antrian (upload cover buku → resize image)

## Kesalahan Umum yang Sering Terjadi
1. **Menggunakan `send()` bukan `emit()`** — `send()` mengharapkan response dan akan timeout karena subscriber menggunakan `@EventPattern` yang tidak mengembalikan response. Gunakan `emit()` untuk event-driven.
2. **Tidak handle `noAck: false`** — Jika `noAck: true` (default), pesan akan dianggap berhasil meski terjadi error di consumer. Set `noAck: false` dan manual `ack()`/`nack()`.
3. **Queue tidak durable** — Jika RabbitMQ restart, queue dan pesan hilang. Set `queueOptions.durable: true`.
4. **Event terlalu besar** — Event seharusnya berisi data minimal (ID + context). Jangan kirim seluruh objek Book dengan 20 field. Cukup `{ bookId, title }` — subscriber bisa request detail jika perlu.
5. **Tidak ada idempotency** — Event bisa dikirim lebih dari sekali (misal karena retry). Pastikan handler idempoten: memproses event yang sama dua kali tidak boleh menghasilkan efek ganda.

## Hubungan dengan Materi Sebelumnya
Di Level 4 kita menggunakan BullMQ untuk background jobs dalam satu aplikasi monolith. Sekarang kita naik level: RabbitMQ untuk komunikasi antar service yang terpisah secara fisik. Bedanya, BullMQ adalah queue internal dalam satu proses Node.js, sedangkan RabbitMQ adalah message broker eksternal yang bisa menghubungkan banyak service berbeda. Konsep queue, job, dan consumer yang dipelajari di Level 4 sangat relevan di sini.

// Books Service — main.ts (subscriber)
import { NestFactory } from '@nestjs/core';
import { MicroserviceOptions, Transport } from '@nestjs/microservices';
import { BooksModule } from './books.module';

async function bootstrap() {
  // Tetap jalan sebagai TCP untuk request-response
  const app = await NestFactory.createMicroservice(BooksModule, {
    transport: Transport.TCP,
    options: { host: '0.0.0.0', port: 3001 },
  });

  // Juga subscribe ke RabbitMQ untuk event
  const rmqApp = await NestFactory.createMicroservice(BooksModule, {
    transport: Transport.RMQ,
    options: {
      urls: ['amqp://nestjs:nestjs@localhost:5672'],
      queue: 'books_event_queue',
      queueOptions: { durable: true },
    },
  });

  await app.listen();
  await rmqApp.listen();
}
bootstrap();
```
