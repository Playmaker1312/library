# Membuat PaginatedResult Type — Format Response Pagination Standar

## Penjelasan

Setelah pagination, filter, dan sorting siap di sisi query, kita perlu standarisasi format response agar konsisten di seluruh API. Tanpa standarisasi, setiap endpoint bisa mengembalikan format pagination yang berbeda — ada yang mengembalikan `{ data, total, page }`, ada yang `{ result, totalPage, currentPage }`, dan sebagainya. Ini menyulitkan client (frontend) karena harus menyesuaikan parsing untuk setiap endpoint.

PaginatedResult adalah generic type yang membungkus data hasil query dengan metadata pagination. Dengan generic type `PaginatedResult<T>`, kita bisa menggunakannya untuk entity apa pun: `PaginatedResult<Book>`, `PaginatedResult<Member>`, `PaginatedResult<Loan>`, dan seterusnya. Type ini berisi: `data` (array hasil), `meta` (metadata seperti total, page, limit, totalPages), dan helper boolean `hasNextPage` serta `hasPrevPage` untuk navigasi.

Implementasi di repository/service akan menghitung total data (tanpa pagination) menggunakan `prisma.book.count()`, lalu menggabungkannya dengan data yang sudah di-paginate. Perhitungan `totalPages = Math.ceil(total / limit)` dan `hasNextPage = page < totalPages` memudahkan frontend menentukan apakah tombol "Next" perlu ditampilkan. Response yang konsisten ini membuat frontend bisa membuat komponen pagination reusable sendiri.

## Fungsi

Menyediakan type dan implementasi standar untuk response pagination yang konsisten di seluruh endpoint API, termasuk metadata dan helper navigasi.

## Cara Implementasi / Code

Buat generic type `src/common/types/paginated-result.type.ts`:

```typescript
// src/common/types/paginated-result.type.ts
export interface PaginationMeta {
  total: number;
  page: number;
  limit: number;
  totalPages: number;
  hasNextPage: boolean;
  hasPrevPage: boolean;
}

export class PaginatedResult<T> {
  data: T[];
  meta: PaginationMeta;

  constructor(data: T[], total: number, page: number, limit: number) {
    this.data = data;
    this.meta = {
      total,
      page,
      limit,
      totalPages: Math.ceil(total / limit),
      hasNextPage: page < Math.ceil(total / limit),
      hasPrevPage: page > 1,
    };
  }

  static from<T>(
    data: T[],
    total: number,
    page: number,
    limit: number,
  ): PaginatedResult<T> {
    return new PaginatedResult(data, total, page, limit);
  }
}
```

Implementasi di repository:

```typescript
// Di PrismaBooksRepository, tambahkan method:
async findAllPaginated(
  query: QueryBookDto,
): Promise<PaginatedResult<Book>> {
  const { page, limit, search, genre, year, minStock, sortBy, sortOrder } = query;
  const skip = (page - 1) * limit;

  // Build where clause
  const where: Prisma.BookWhereInput = { isDeleted: false };

  if (search) {
    where.OR = [
      { title: { contains: search, mode: 'insensitive' } },
      { author: { contains: search, mode: 'insensitive' } },
    ];
  }

  if (genre) {
    where.genre = genre;
  }

  if (year) {
    where.publishedYear = year;
  }

  if (minStock !== undefined) {
    where.stock = { gte: minStock };
  }

  // Hitung total dan ambil data secara paralel
  const [data, total] = await this.prisma.$transaction([
    this.prisma.book.findMany({
      skip,
      take: limit,
      where,
      orderBy: { [sortBy || 'createdAt']: sortOrder || 'desc' },
    }),
    this.prisma.book.count({ where }),
  ]);

  return PaginatedResult.from(data, total, page, limit);
}
```

## Analogi

PaginatedResult adalah **paket buku yang sudah dibungkus rapi** untuk dikirim ke pengunjung perpustakaan. Jika sebelumnya petugas hanya memberikan tumpukan buku (array data) tanpa informasi tambahan, sekarang setiap paket dilengkapi dengan catatan:

- **Data**: Isi paket — buku-buku yang diminta (array of books).
- **Meta**: Informasi paket — total buku yang cocok dengan pencarian (100), paket ini adalah paket nomor 1 dari 10 paket (totalPages), maksimal 10 buku per paket (limit), apakah ada paket berikutnya (hasNextPage: true), apakah ada paket sebelumnya (hasPrevPage: false).

Dengan paket yang terstandarisasi, pengunjung (frontend) bisa dengan mudah membuat sistem navigasi: "Ada 10 halaman total, saya di halaman 1, ada tombol Next untuk ke halaman 2, tombol Prev tidak aktif." Tanpa standarisasi, setiap petugas membungkus paket dengan cara berbeda — ada yang pakai kertas coklat, ada yang pakai plastik, ada yang tulis informasinya di luar, ada yang di dalam. Standarisasi ini membuat frontend bisa membaca paket mana pun tanpa kebingungan.

## Penggunaan

Dipakai di semua endpoint yang mengembalikan daftar data dengan pagination: `GET /books`, `GET /members`, `GET /loans`, dan seterusnya. Generic type `PaginatedResult<T>` memungkinkan penggunaan ulang tanpa perubahan kode untuk entity yang berbeda.

## Kesalahan Umum yang Sering Terjadi

1. **Total dihitung tanpa filter yang sama**: `count()` menggunakan where clause yang berbeda dengan `findMany()`, menyebabkan total tidak akurat.
2. **Lupa handle `$transaction`**: Query `count()` dan `findMany()` dijalankan terpisah, dalam aplikasi high-concurrency bisa menghasilkan data inkonsisten.
3. **`Math.ceil` tidak digunakan**: `totalPages = total / limit` menghasilkan desimal, misal 5.5 halaman.
4. **Page 0 menyebabkan error**: Jika page = 0, skip = -1, Prisma error. Pastikan validasi page minimal 1.
5. **HasNextPage salah saat total = 0**: `page < Math.ceil(0 / limit)` → `1 < 0` = false (benar, tidak ada next page).
6. **Limit = 0**: `Math.ceil(total / 0)` = Infinity. Pastikan validasi limit minimal 1.

## Hubungan dengan Materi Sebelumnya

PaginatedResult adalah puncak dari rangkaian pagination: PaginationDto (materi 30) menyediakan input, QueryBookDto (materi 31) menambahkan filter dan sort, dan PaginatedResult (materi 32) membungkus output. Semua materi sebelumnya — repository (materi 24), service (materi 26), PrismaService (materi 21) — berkontribusi pada implementasi `findAllPaginated` di repository. Ini adalah contoh arsitektur yang bersih dan reusable.
