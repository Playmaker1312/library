# Membuat PaginationDto — Reusable di Semua Module

## Penjelasan

Pagination adalah teknik membagi hasil query besar menjadi halaman-halaman kecil sehingga response API lebih cepat dan mudah diproses oleh client. Tanpa pagination, jika database memiliki ribuan buku, satu request `GET /books` akan mengembalikan semua data sekaligus — boros bandwidth, memori, dan waktu processing. Dengan pagination, client cukup meminta halaman tertentu dengan jumlah data per halaman yang diinginkan.

Daripada membuat DTO pagination terpisah untuk setiap entity (misalnya `BookPaginationDto`, `MemberPaginationDto`, `LoanPaginationDto`), kita bisa membuat satu **PaginationDto** reusable yang bisa digunakan di semua module. Pendekatan ini menggunakan **class inheritance**: module-specific DTO (seperti `QueryBookDto`) akan mengextend `PaginationDto` dan menambahkan field spesifik yang diperlukan.

PaginationDto memiliki dua field utama: `page` (halaman yang diminta, mulai dari 1) dan `limit` (jumlah data per halaman). Keduanya bertipe number dan memiliki nilai default (page = 1, limit = 10). Kita menggunakan `@Type(() => Number)` dari `class-transformer` karena query parameter dari HTTP request selalu berupa string, sehingga perlu di-transform ke number. `@IsOptional()` dengan `@IsInt()` dan `@Min(1)` memastikan validasi yang tepat.

## Fungsi

Menyediakan DTO pagination yang reusable untuk semua endpoint yang membutuhkan pagination, dengan validasi dan transformasi tipe data otomatis.

## Cara Implementasi / Code

Install class-validator dan class-transformer jika belum ada:

```bash
npm install class-validator class-transformer
```

Buat `src/common/dto/pagination.dto.ts`:

```typescript
// src/common/dto/pagination.dto.ts
import { IsOptional, IsInt, Min, Max } from 'class-validator';
import { Type } from 'class-transformer';

export class PaginationDto {
  @IsOptional()
  @Type(() => Number)
  @IsInt()
  @Min(1)
  page?: number = 1;

  @IsOptional()
  @Type(() => Number)
  @IsInt()
  @Min(1)
  @Max(100)
  limit?: number = 10;
}
```

Buat index file untuk common exports:

```typescript
// src/common/dto/index.ts
export * from './pagination.dto';
```

```typescript
// src/common/index.ts
export * from './dto';
```

Cara menggunakan PaginationDto di controller:

```typescript
import { Controller, Get, Query } from '@nestjs/common';
import { PaginationDto } from '../common/dto';

@Controller('books')
export class BooksController {
  @Get()
  async findAll(@Query() query: PaginationDto) {
    console.log(query.page);  // number (default: 1)
    console.log(query.limit); // number (default: 10)
    // Kirim ke service
  }
}
```

Di service, kita hitung skip untuk Prisma:

```typescript
async findAllPaginated(page: number, limit: number) {
  const skip = (page - 1) * limit;
  return this.prisma.book.findMany({
    skip,
    take: limit,
    where: { isDeleted: false },
  });
}
```

## Analogi

PaginationDto adalah **nomor antrian di perpustakaan**. Ketika banyak pengunjung datang, petugas tidak bisa melayani semua sekaligus. Petugas memasang sistem antrian: "Halaman 1 (page=1), maksimal 10 orang per halaman (limit=10)." Pengunjung yang datang tahu persis berapa nomor antrian mereka dan berapa lama kira-kira harus menunggu.

Tanpa PaginationDto (tanpa antrian), semua pengunjung berebut ke loket sekaligus — kacau balau, petugas kewalahan, dan banyak pengunjung yang tidak terlayani. Dengan PaginationDto yang reusable, setiap loket (endpoint) bisa menggunakan sistem antrian yang sama. Loket peminjaman buku, loket pendaftaran anggota, dan loket pengembalian buku — semuanya pakai sistem antrian yang seragam. Cukup buat satu kali, pakai di mana saja.

## Penggunaan

Dipakai di semua endpoint GET yang mengembalikan daftar data (list resources). Sangat berguna untuk endpoint yang berpotensi mengembalikan banyak data seperti daftar buku, daftar anggota, daftar peminjaman, dan laporan. PaginationDto bisa langsung digunakan atau di-extend oleh DTO spesifik.

## Kesalahan Umum yang Sering Terjadi

1. **Lupa `@Type(() => Number)`**: Query parameter `?page=1` tetap bertipe string, `@IsInt()` gagal karena menerima string.
2. **Lupa default value**: `page` menjadi `undefined` jika tidak dikirim oleh client, menyebabkan `skip = NaN`.
3. **Limit tidak dibatasi**: Client bisa minta `limit=999999`, membebani database. Gunakan `@Max(100)`.
4. **Page mulai dari 0 vs 1**: Konsisten mulai dari 1. Jika page = 0, skip jadi negatif.
5. **Tidak implement di repository**: Pagination di service tapi query tetap `findMany()` tanpa skip/take.
6. **Lupa `whitelist: true` di ValidationPipe**: Property asing (seperti `sort`) tidak di-strip jika belum ada validasi.
