# Setup ConfigModule — Akses Environment Variable yang Terstruktur

## Penjelasan

Dalam aplikasi NestJS, environment variable (seperti DATABASE_URL, PORT, JWT_SECRET) biasanya disimpan di file `.env`. Namun, mengakses `process.env` secara langsung di seluruh aplikasi bukanlah praktik yang baik karena beberapa alasan: (1) tidak ada type safety — semua nilai bertipe `string | undefined`, (2) tidak ada validasi — jika environment variable tidak di-set, aplikasi akan berjalan dengan nilai `undefined` yang bisa menyebabkan error misterius, dan (3) tidak ada structuring — environment variable tersebar di berbagai file tanpa organisasi.

`@nestjs/config` adalah package resmi NestJS yang menyediakan solusi terstruktur untuk mengelola konfigurasi. Module ini membaca file `.env` dan menyediakan `ConfigService` yang bisa di-inject ke mana saja. Lebih penting lagi, `@nestjs/config` dapat diintegrasikan dengan **Joi** untuk validasi schema. Dengan Joi, kita mendefinisikan schema yang menentukan tipe data, nilai default, dan apakah suatu variable wajib diisi atau tidak. Jika ada environment variable yang tidak valid atau tidak sesuai schema, aplikasi akan gagal start dengan pesan error yang jelas.

ConfigModule perlu di-import di `AppModule` menggunakan `ConfigModule.forRoot()`. Opsi `isGlobal: true` membuat ConfigModule tersedia di seluruh aplikasi tanpa perlu di-import ulang. Opsi `validationSchema` digunakan untuk menyertakan validasi Joi. Dengan setup ini, kita bisa mengakses konfigurasi di mana pun melalui `ConfigService` dengan method `.get()`.

## Fungsi

Menyediakan akses terstruktur, type-safe, dan tervalidasi ke environment variable aplikasi, serta memastikan semua konfigurasi yang diperlukan sudah di-set sebelum aplikasi berjalan.

## Cara Implementasi / Code

Install package yang diperlukan:

```bash
npm install @nestjs/config joi
```

Buat file `.env` di root project:

```env
# .env
PORT=3000
GLOBAL_PREFIX=api/v1
DATABASE_URL="postgresql://postgres:postgres@localhost:5432/perpustakaan_db"
REDIS_HOST=localhost
REDIS_PORT=6379
NODE_ENV=development
```

Setup ConfigModule di `app.module.ts`:

```typescript
// src/app.module.ts
import { Module } from '@nestjs/common';
import { ConfigModule } from '@nestjs/config';
import * as Joi from 'joi';
import { PrismaModule } from './prisma/prisma.module';
import { BooksModule } from './books/books.module';

@Module({
  imports: [
    ConfigModule.forRoot({
      isGlobal: true,
      envFilePath: '.env',
      validationSchema: Joi.object({
        PORT: Joi.number().default(3000),
        GLOBAL_PREFIX: Joi.string().default('api/v1'),
        DATABASE_URL: Joi.string().uri().required(),
        REDIS_HOST: Joi.string().default('localhost'),
        REDIS_PORT: Joi.number().default(6379),
        NODE_ENV: Joi.string()
          .valid('development', 'production', 'test')
          .default('development'),
      }),
      validationOptions: {
        abortEarly: true, // Stop validasi pada error pertama
      },
    }),
    PrismaModule,
    BooksModule,
  ],
})
export class AppModule {}
```

Sekarang akses konfigurasi di service mana pun:

```typescript
import { Injectable } from '@nestjs/common';
import { ConfigService } from '@nestjs/config';

@Injectable()
export class AppService {
  constructor(private configService: ConfigService) {
    const port = this.configService.get<number>('PORT');
    const dbUrl = this.configService.get<string>('DATABASE_URL');
    console.log(`App running on port ${port}`);
  }
}
```

## Analogi

ConfigModule adalah **papan pengumuman resmi perpustakaan** yang ditempatkan di pintu masuk. Papan ini berisi semua informasi penting yang harus diketahui semua petugas: jam buka perpustakaan (`PORT`), alamat gudang buku (`DATABASE_URL`), nomor telepon darurat (`REDIS_PORT`), dan status hari ini libur atau tidak (`NODE_ENV`). Sebelum papan ini ada, setiap petugas bertanya-tanya sendiri: "Jam berapa kita buka ya?" dan jawabannya berbeda-beda tergantung siapa yang ditanya. Sekarang, semua informasi sudah terpusat, tervalidasi (papan pengumuman tidak boleh salah tulis), dan bisa diakses siapa saja dengan tinggal melihat ke papan (`ConfigService.get()`). Jika ada informasi yang salah atau kurang, papan akan menolak untuk dipasang (aplikasi tidak mau start) sampai semuanya benar.

## Penggunaan

Dipakai di seluruh aplikasi untuk mengakses environment variable secara terstruktur. Digunakan untuk mengatur port server, konfigurasi database, konfigurasi Redis, JWT secret, API key, dan semua nilai konfigurasi yang berbeda antara development dan production.

## Kesalahan Umum yang Sering Terjadi

1. **Tidak install `joi`**: Validasi schema gagal karena package tidak ditemukan.
2. **Lupa `isGlobal: true`**: Setiap module harus import ConfigModule lagi.
3. **Typo di validation schema**: Nama field berbeda dengan yang ada di `.env`, validasi selalu gagal.
4. **Lupa set required: true**: Environment variable penting tidak di-set, aplikasi tetap jalan dan error di runtime.
5. **File `.env` tidak ada di root**: ConfigModule tidak menemukan file dan menggunakan nilai default, bisa membingungkan.
6. **Tipe data salah**: `PORT` didefinisikan sebagai number di schema, tapi di `.env` diisi string "tiga ribu".
