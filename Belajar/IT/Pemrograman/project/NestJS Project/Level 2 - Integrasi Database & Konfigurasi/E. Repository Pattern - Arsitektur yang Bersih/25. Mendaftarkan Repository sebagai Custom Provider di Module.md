# Mendaftarkan Repository sebagai Custom Provider di Module

## Penjelasan

NestJS memiliki dependency injection (DI) container yang secara default mendaftarkan class `@Injectable()` sebagai provider. Jika kita punya interface dan beberapa implementasi, kita perlu menggunakan **custom provider** untuk memberi tahu DI container implementasi mana yang harus digunakan untuk token tertentu. Dalam kasus repository pattern, kita ingin mengikat token `BOOKS_REPOSITORY` ke class `PrismaBooksRepository` menggunakan opsi `useClass`.

Custom provider memungkinkan kita mengontrol bagaimana suatu dependency dibuat dan disediakan. Ada beberapa jenis custom provider: `useClass` (mengikat token ke class tertentu), `useValue` (mengikat token ke nilai statis), `useFactory` (membuat dependency via factory function), dan `useExisting` (alias). Untuk repository, `useClass` adalah pilihan yang tepat karena kita hanya perlu mengganti implementasi tanpa mengubah logika pembuatan.

Dengan pendekatan ini, ketika service meminta `@Inject(BOOKS_REPOSITORY) private readonly booksRepository: IBooksRepository`, NestJS akan mencari provider dengan token `BOOKS_REPOSITORY` dan mengembalikan instance `PrismaBooksRepository`. Jika kita ingin menggunakan implementasi lain (misalnya `MockBooksRepository` untuk testing), kita cukup mengganti `useClass` di module. Service tidak perlu diubah sama sekali.

## Fungsi

Mendaftarkan repository ke dalam dependency injection NestJS menggunakan custom provider pattern, sehingga interface repository dapat di-inject ke service dengan implementasi yang sesuai.

## Cara Implementasi / Code

Buat file `src/books/books.module.ts`:

```typescript
// src/books/books.module.ts
import { Module } from '@nestjs/common';
import { BooksController } from './books.controller';
import { BooksService } from './books.service';
import { PrismaBooksRepository } from './repositories/prisma-books.repository';
import { BOOKS_REPOSITORY } from './constants/tokens';

@Module({
  controllers: [BooksController],
  providers: [
    BooksService,
    {
      provide: BOOKS_REPOSITORY,
      useClass: PrismaBooksRepository,
    },
  ],
  exports: [BooksService],
})
export class BooksModule {}
```

Buat file constants token jika belum ada:

```typescript
// src/books/constants/tokens.ts
export const BOOKS_REPOSITORY = 'BOOKS_REPOSITORY';
```

Index file untuk memudahkan import:

```typescript
// src/books/constants/index.ts
export * from './tokens';
```

```typescript
// src/books/repositories/index.ts
export * from './prisma-books.repository';
```

```typescript
// src/books/interfaces/index.ts
export * from './books-repository.interface';
```

Dengan setup ini, struktur folder `src/books/` menjadi:

```
src/books/
├── constants/
│   ├── index.ts
│   └── tokens.ts
├── interfaces/
│   ├── index.ts
│   └── books-repository.interface.ts
├── repositories/
│   ├── index.ts
│   └── prisma-books.repository.ts
├── books.controller.ts
├── books.module.ts
├── books.service.ts
└── dto/
    └── ...
```

## Analogi

Proses pendaftaran repository di module seperti **membuat papan nama di loket perpustakaan**. Di papan nama itu tertulis: "Loket Peminjaman Buku → Hubungi Petugas Andi". Token `BOOKS_REPOSITORY` adalah label "Loket Peminjaman Buku", dan `PrismaBooksRepository` adalah petugas bernama Andi yang duduk di loket tersebut. Pengunjung (service) cukup melihat papan nama dan tahu persis ke mana harus berbicara. Jika suatu hari petugas Andi diganti dengan Budi (`MockBooksRepository`), papan nama tidak perlu diganti — cukup ganti orang yang duduk di belakang loket. Pengunjung tetap antre di loket yang sama dan tetap mendapat pelayanan yang sama (method yang sama), meskipun cara Budi melayani mungkin berbeda.

Dengan menggunakan token (`provide: BOOKS_REPOSITORY`), kita memberi NestJS instruksi: "Jika ada yang meminta `BOOKS_REPOSITORY`, berikan instance dari `PrismaBooksRepository`." NestJS kemudian akan membuatkan instance singleton dan menyimpannya di DI container.

## Penggunaan

Dipakai di setiap module yang menggunakan repository pattern. Custom provider dengan `useClass` adalah standar untuk mendaftarkan implementasi repository. Untuk module testing, kita bisa menggunakan `useValue` untuk memasukkan mock repository langsung.

## Kesalahan Umum yang Sering Terjadi

1. **Lupa daftarkan provider**: Service mencoba inject repository tapi tidak terdaftar, error `Nest can't resolve dependencies`.
2. **Salah token**: Token yang digunakan di `@Inject()` berbeda dengan token di `provide:`, sehingga dependency tidak ditemukan.
3. **Lupa export module**: Module lain tidak bisa menggunakan BooksService karena tidak di-export.
4. **Daftar provider tanpa `useClass`**: Langsung menggunakan class name, tapi karena interface bukan class, NestJS tidak bisa resolve.
5. **Circular dependency**: Module A membutuhkan module B, dan module B membutuhkan module A.

**Soal 2:** Bagaimana cara menggunakan `useValue` untuk mendaftarkan mock repository di testing module?

<details>
<summary>Jawaban</summary>

```typescript
import { Test, TestingModule } from '@nestjs/testing';
import { BOOKS_REPOSITORY } from './constants/tokens';

const mockRepository = {
  findAll: jest.fn().mockResolvedValue([]),
  findById: jest.fn().mockResolvedValue(null),
  create: jest.fn().mockResolvedValue({}),
  update: jest.fn().mockResolvedValue({}),
  softDelete: jest.fn().mockResolvedValue({}),
};

const module: TestingModule = await Test.createTestingModule({
  providers: [
    BooksService,
    {
      provide: BOOKS_REPOSITORY,
      useValue: mockRepository,
    },
  ],
}).compile();
```
