# Membuat PrismaService — Koneksi Database yang Dikelola NestJS

## Penjelasan

PrismaService adalah service khusus di NestJS yang mengextend PrismaClient dan mengimplementasikan `OnModuleInit` dari lifecycle hooks NestJS. Tujuannya adalah mengintegrasikan Prisma Client ke dalam dependency injection system NestJS, sehingga koneksi database dikelola sepenuhnya oleh NestJS. Tanpa ini, kita harus membuat instance PrismaClient secara manual di setiap module atau service, yang menyebabkan koneksi database tidak terkelola dengan baik — misalnya koneksi tidak tertutup saat aplikasi dimatikan.

Dengan membuat PrismaService sebagai Global Module, kita tidak perlu mengimport PrismaModule lagi di setiap feature module. Cukup daftarkan sekali di `AppModule`, dan semua module di aplikasi bisa mengakses PrismaService melalui dependency injection. Ini mengikuti prinsip DRY (Don't Repeat Yourself) dan memastikan hanya ada satu instance PrismaClient di seluruh aplikasi (singleton pattern).

PrismaService mengimplementasikan `OnModuleInit` dengan method `onModuleInit()` yang memanggil `this.$connect()` untuk memastikan koneksi database terbentuk saat aplikasi NestJS启动. Kita juga perlu mengimplementasikan `OnModuleDestroy` (atau `beforeApplicationShutdown`) untuk memanggil `this.$disconnect()` agar koneksi database ditutup dengan bersih saat aplikasi berhenti. Ini mencegah kebocoran koneksi (connection leak) yang bisa menghabiskan resource database.

## Fungsi

Mengelola lifecycle koneksi database Prisma dalam ekosistem NestJS, memastikan koneksi terhubung saat aplikasi start dan terputus dengan bersih saat aplikasi shutdown, serta menyediakan akses Prisma Client ke seluruh module.

## Cara Implementasi / Code

Buat `src/prisma/prisma.service.ts`:

```typescript
import { Injectable, OnModuleInit, OnModuleDestroy } from '@nestjs/common';
import { PrismaClient } from '@prisma/client';

@Injectable()
export class PrismaService
  extends PrismaClient
  implements OnModuleInit, OnModuleDestroy
{
  async onModuleInit() {
    await this.$connect();
    console.log('Database connected successfully');
  }

  async onModuleDestroy() {
    await this.$disconnect();
    console.log('Database disconnected');
  }
}
```

Buat `src/prisma/prisma.module.ts` sebagai Global Module:

```typescript
import { Global, Module } from '@nestjs/common';
import { PrismaService } from './prisma.service';

@Global()
@Module({
  providers: [PrismaService],
  exports: [PrismaService],
})
export class PrismaModule {}
}

Daftarkan di `AppModule`:

```typescript
import { Module } from '@nestjs/common';
import { PrismaModule } from './prisma/prisma.module';
import { BooksModule } from './books/books.module';

@Module({
  imports: [PrismaModule, BooksModule],
})
export class AppModule {}
```

Sekarang setiap service bisa inject PrismaService:

```typescript
import { Injectable } from '@nestjs/common';
import { PrismaService } from '../prisma/prisma.service';

@Injectable()
export class BooksService {
  constructor(private readonly prisma: PrismaService) {}

  async findAll() {
    return this.prisma.book.findMany();
  }
}
```

## Analogi

PrismaService adalah **kepala petugas perpustakaan** yang memegang kunci gudang buku. Kepala petugas ini (PrismaService) adalah satu-satunya orang yang punya akses langsung ke gudang. Saat perpustakaan dibuka di pagi hari (`onModuleInit`), kepala petugas membuka pintu gudang (`$connect`) dan memastikan semua rak bisa diakses. Saat perpustakaan tutup di malam hari (`onModuleDestroy`), ia mengunci gudang kembali (`$disconnect`). Para petugas lain (BooksService, MembersService) tidak perlu tahu cara membuka gudang — mereka cukup minta buku ke kepala petugas, dan kepala petugas yang mengambilkan dari gudang. Dengan hanya satu kepala petugas (singleton), tidak ada risiko dua orang mencoba membuka gudang yang sama dan membuat kekacauan.

## Penggunaan

Dipakai di semua service yang membutuhkan akses database. PrismaService menjadi single entry point untuk semua query Prisma di aplikasi NestJS. Cocok untuk aplikasi skala kecil hingga enterprise karena pengelolaan koneksi yang rapi dan terintegrasi dengan lifecycle NestJS.

## Kesalahan Umum yang Sering Terjadi

1. **Lupa deklarasi `@Global()`**: Setiap feature module harus import PrismaModule, menyebabkan boilerplate.
2. **Tidak implement `OnModuleDestroy`**: Koneksi database tidak tertutup saat aplikasi berhenti, bisa menyebabkan connection leak di production.
3. **Membuat instance PrismaClient baru di setiap service**: Melewati dependency injection, mengakibatkan banyak koneksi database paralel.
4. **Lupa export PrismaService di module**: Module lain tidak bisa mengakses PrismaService meskipun sudah di-import.
5. **Error koneksi tidak di-handle**: Jika database mati, aplikasi tetap berjalan tanpa koneksi. Sebaiknya tambahkan error handling atau retry logic.

## Hubungan dengan Materi Sebelumnya

Setelah migrasi (materi 20) berhasil membuat tabel di database, kita sekarang perlu menghubungkan NestJS ke database tersebut. PrismaService adalah jembatan antara aplikasi NestJS dan Prisma Client. Tanpa PrismaService, kita tidak bisa melakukan query ke database dari kode NestJS. Service ini akan digunakan oleh repository (materi 24) dan service (materi 26) untuk operasi CRUD.
