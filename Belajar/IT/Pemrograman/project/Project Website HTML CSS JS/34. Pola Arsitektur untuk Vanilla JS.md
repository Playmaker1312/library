# 34. Pola Arsitektur untuk Vanilla JS

Materi ini mengajarkan cara mengorganisasi project vanilla JS yang sudah berjalan dari Level 1-6 menjadi kode yang **maintainable** dan **scalable**: ES Modules, folder `src/modules/`, state management dengan subscribe, satu entry point, dan catatan peningkatan ke TypeScript. Ini adalah fondasi pertama sebelum masuk ke performa, aksesibilitas, build tools, dan deploy.

## 1. Penjelasan Singkat & Konsep Dasar

Sampai Level 6, semua kode JavaScript biasanya menumpuk di satu file `main.js` (atau bahkan di dalam tag `<script>`). Saat aplikasi masih kecil, file tunggal terasa nyaman. Tapi saat katalog bertambah, fitur pencarian, filter, modal, notifikasi, penyimpanan lokal, dan panggilan API saling menyentuh, satu file raksasa menjadi mimpi buruk: sulit dicari, sulit diuji, dan setiap perbaikan kecil berisiko merusak bagian lain. **Arsitektur kode** hadir untuk menjawab persoalan ini — bukan menambah fitur, tapi mengatur supaya fitur yang ada bisa terus bertumbuh tanpa hancur.

Konsep intinya adalah **separation of concerns** (pemisahan tanggung jawab): pisahkan kode berdasarkan *apa yang dikerjakannya*, bukan berdasarkan alur tampilan. Kode yang berhubungan dengan jaringan (fetch ke API) hanya hidup di satu tempat; kode yang memanipulasi DOM hanya hidup di tempat lain; state aplikasi dipisahkan agar semua bagian membaca dan menulis data dari satu sumber yang sama. Hasilnya: satu masalah → satu tempat untuk memperbaikinya.

Sarana resminya di JavaScript modern adalah **ES Modules** (`import` / `export`). Setiap berkas menjadi modul dengan lingkup (scope) tersendiri — variabel di dalamnya tidak bocor ke global, dan modul hanya memperlihatkan apa yang memang di-`export`. Aspek ini memecahkan salah satu masalah tertua JavaScript: variabel global yang saling menabrak. Modul juga memungkinkan **lazy loading** dan menjadi syarat utama agar bundler seperti Vite (materi 37) bisa menganalisis dan mengecilkan kode.

Pola yang dipakai adalah **layered + central state**. Empat modul inti — `api.js` (jaringan), `storage.js` (persistensi localStorage), `ui.js` (DOM & render), `state.js` (data + notifikasi) — ditambah `events.js` (listen aksi user) dan dirajut oleh satu entry point `main.js`. Alur datanya satu arah: user mengetik/klik → `events.js` memanggil `api.js` → hasil disimpan ke state via `state.set()` → `ui.js` yang *subscribe* ke state otomatis me-render ulang. UI tidak pernah menulis data langsung; data tidak pernah menyentuh DOM secara liar. Inilah yang disebut **unidirectional data flow** — kunci memahami framework-framework berikutnya.

**Benang merah**: seluruh roadmap di level bawah membangun *fitur*; Level 7 membangun *disiplin*. Materi 35, 36, 37, dan 38 semuanya berdiri di atas struktur ini — performa menyangkut cara modul memuat aset, aksesibilitas menyangkut bagaimana modul `ui.js` merender elemen, Vite membutuhkan ES Modules untuk dibundle, dan deploy membutuhkan struktur yang rapi agar build reproducible. Aplikasi "production-ready" bukan soal fitur paling banyak, melainkan kode yang bisa terus dirawat.

## 2. Fungsi & Kegunaan Utama dalam Web

**Perpustakaan Digital Kota** sudah punya banyak fitur di atas `main.js` tunggal. Tanpa arsitektur, menambah satu fitur baru (misal daftar favorit) berarti mengutak-atik baris demi baris di file yang sama dan berdoa tidak ada yang rusak. Dengan modul, menambah fitur berarti *menambah modul atau fungsi*, sementara bagian yang sudah stabil tidak disentuh. Tim bisa bekerja paralel: satu orang mengerjakan `api.js`, orang lain mengerjakan `ui.js`, tanpa pindah-pindah file dan konflik.

State management bermanfaat besar untuk konsistensi. Sebelumnya, pencarian me-render ulang grid dengan `innerHTML`, filter kategori memperbarui `info-hasil`, modal menulis judul ke satu elemen — semua mengubah DOM dari banyak tempat, dan rawan lupa menyinkronkan satu sama lain. Dengan `StateManager`, cukup satu sumber kebenaran (state), dan setiap UI yang *subscribe* otomatis diamati: **satu perubahan data → seluruh tampilan yang relevan diperbarui**. Ini menghilangkan kelas bug klasik "tampilan bilang 5 buku, data bilang 3".

Bagi tim, modul memberi **kejelasan ritme kerja**: aturan main "data lewat state, tampilan lewat ui, jaringan lewat api" membuat bug mudah dilacak. Bagi user, arsitektur merupakan janji tidak langsung: aplikasi bisa punya lebih banyak fitur tanpa melambat atau rusak, karena kode yang teratur lebih mudah dioptimasi (materi 35) dan di-deploy dengan benar (materi 37-38).

```javascript
// Fetch dengan validasi status. Lempar Error yang bisa ditampilkan ui.js.
```

```javascript
// src/modules/storage.js — satu-satunya tempat localStorage diakses
// Bungkus JSON.parse/stringify agar pemanggil tidak perlu tahu detailnya.

const NS = "perpustakaan"; // namespace: hindari bentrok kunci antar fitur

export const Storage = {
    simpan(key, value) {
        // Simpan snapshot JSON; gagal diam-diam jika kuota penuh.
        try {
            localStorage.setItem(`${NS}:${key}`, JSON.stringify(value));
        } catch (e) {
            console.warn("Gagal menyimpan ke localStorage:", e);
        }
    },

    ambil(key, fallback) {
        try {
            const raw = localStorage.getItem(`${NS}:${key}`);
            return raw === null ? fallback : JSON.parse(raw);
        } catch (e) {
            return fallback; // data korup → kembali ke nilai default
        }
    },

    hapus(key) {
        localStorage.removeItem(`${NS}:${key}`);
    },
};
```

```javascript
// src/modules/state.js — StateManager sederhana + instance aplikasi
// Pola "publish/subscribe": ui.js berlangganan, otomatis dirrender ulang.

export class StateManager {
    #state;      // properti privat: tidak bisa diakses dari luar instance
    #listeners = [];

    constructor(stateAwal) {
        this.#state = stateAwal;
    }

    // get() mengembalikan SALINAN, bukan reference — pemanggil
    // tidak bisa memutasi state secara diam-diam.
    get() {
        return { ...this.#state };
    }

    // set(updater): masukkan perubahan. updater bisa berupa objek parsial
    // atau fungsi lain untuk transformasi (seperti setState dari React).
    set(updater) {
        const stateLama = this.#state;
        this.#state = typeof updater === "function"
            ? updater(this.#state)
            : { ...this.#state, ...updater };

        // Beritahu semua pelanggan setelah state benar-benar berubah.
        this.#listeners.forEach((fn) => fn(this.#state, stateLama));
    }

    subscribe(listener) {
        this.#listeners.push(listener);
        // Kembalikan fungsi unsubscribe agar UI bisa berhenti berlangganan
        // (misal saat komponen dihapus) — mencegah kebocoran memori.
        return () => {
            this.#listeners = this.#listeners.filter((fn) => fn !== listener);
        };
    }
}

import { Storage } from "./storage.js";

export const appState = new StateManager({
    buku: [],                        // hasil pencarian dari API
    filter: { keyword: "", kategori: "semua" },
    loading: false,                  // kendalikan penampil loading
    error: null,                     // pesan error yang siap ditampilkan
    favorit: Storage.ambil("favorit", []),
});
```

```javascript
// src/modules/ui.js — satu-satunya tempat DOM ditulis
import { appState } from "./state.js";

export function renderKatalog(buku, kontainer) {
    if (buku.length === 0) {
        kontainer.innerHTML = '<p class="kosong">Tidak ada buku ditemukan.</p>';
        return;
    }
    const fragment = document.createDocumentFragment();
    for (const item of buku) {
        fragment.appendChild(buatKartu(item));
    }
    kontainer.replaceChildren(fragment); // replaceChildren: bersih + satu operasi
}

function buatKartu(buku) {
    const kartu = document.createElement("article");
    kartu.className = "kartu-buku";

    const judul = document.createElement("h3");
    judul.textContent = buku.title; // textContent: aman dari XSS

    const info = document.createElement("p");
    info.textContent = `Penulis: ${(buku.author_name || []).join(", ") || "Tidak diketahui"}`;

    const tombol = document.createElement("button");
    tombol.className = "btn-favorit";
    tombol.textContent = appState.get().favorit.includes(buku.key)
        ? "Batal favorit" : "Tambah favorit";
    tombol.dataset.key = buku.key;

    kartu.append(judul, info, tombol);
    return kartu;
}

export function tampilkanLoading(kontainer) {
    kontainer.innerHTML = '<p role="status" aria-live="polite">Memuat buku...</p>';
}

export function tampilkanError(kontainer, pesan) {
    kontainer.innerHTML = `<p role="alert">Gagal memuat: ${pesan}</p>`;
}

export function perbaruiStatus(kontainer, teks) {
    kontainer.textContent = teks;
}
```

```javascript
// src/modules/events.js — jembatan input user → aksi aplikasi
import { appState } from "./state.js";
import { fetchBuku } from "./api.js";
import { Storage } from "./storage.js";

export function setupEventListeners() {
    const inputCari = document.querySelector("#input-cari");
    const grid = document.querySelector("#katalog-grid");

    // Delegation: satu listener untuk tombol favorit yang lahir/mati tiap render.
    grid.addEventListener("click", (event) => {
        const tombol = event.target.closest(".btn-favorit");
        if (!tombol) return;

        const key = tombol.dataset.key;
        const favorit = appState.get().favorit;

        if (favorit.includes(key)) {
            appState.set({ favorit: favorit.filter((k) => k !== key) });
        } else {
            appState.set({ favorit: [...favorit, key] });
        }
        Storage.simpan("favorit", appState.get().favorit);
        // UI favorit otomatis diperbarui lewat subscriber, bukan manual.
    });

    inputCari.addEventListener("input", () => {
        const keyword = inputCari.value.trim();
        if (!keyword) return;
        cari(keyword);
    });
}

async function cari(keyword) {
    appState.set({ loading: true, error: null });
    try {
        const data = await fetchBuku(keyword);
        appState.set({ buku: data.docs, loading: false });
    } catch (err) {
        appState.set({ error: err.message, loading: false });
    }
}
```

```javascript
// src/main.js — entry point tunggal, rajut semua modul di sini.
// Tidak ada logika bisnis di main: ia hanya mengorkestrasi.
import { appState } from "./modules/state.js";
import { setupEventListeners } from "./modules/events.js";
import { renderKatalog, tampilkanLoading, tampilkanError, perbaruiStatus } from "./modules/ui.js";

function inisialisasi() {
    const kontainer = document.querySelector("#katalog-grid");
    const status = document.querySelector("#info-hasil");

    // Sekali subscribe, UI diperbarui otomatis setiap state berubah.
    appState.subscribe((state) => {
        if (state.loading) {
            tampilkanLoading(kontainer);
        } else if (state.error) {
            tampilkanError(kontainer, state.error);
        } else {
            renderKatalog(state.buku, kontainer);
            perbaruiStatus(status, `${state.buku.length} buku ditemukan`);
        }
    });

    const unsubscribe = appState.subscribe(() => {
        // Contoh: subscriber kedua untuk tombol favorit di header
        // (angka favorit). Kembalikan fungsi jika tak lagi dipakai.
    });

    setupEventListeners();

    // Muat data perdana.
    const bukuAwal = Storage.ambil("buku-terakhir", null);
    if (bukuAwal) appState.set({ buku: bukuAwal });
}

document.addEventListener("DOMContentLoaded", inisialisasi);
```

## 4. Analogi Sederhana — Membangun Rumah

**HTML** adalah kerangka dan tata ruang, **CSS** adalah cat dan dekorasi, **JS** (listrik) dulu dipasang sebagai satu kabel raksasa yang menyambungkan semua lantai — itulah `main.js` tunggal. Material 34 mengajarkan untuk mengganti kabel tunggal itu dengan **departemen tukang**. Tukang listrik punya kotak alatnya sendiri, tukang pipa punya kotak alternya, tukang cat punya rol dan kuasnya; masing-masing bekerja di area yang jelas. Kalau lampu di lantai dua mati, kamu tahu siapa yang bertanggung jawab — kamu tidak perlu membongkar seluruh rumah. Itulah `api.js`, `storage.js`, `ui.js`, `state.js`, `events.js`: setiap kotak alat hanya berisi peralatan "satu jenis pekerjaan".

**State management** adalah **panel kontrol pusat** rumah — sebuah dashboard yang menjadi satu-satunya sumber kebenaran soal lampu mana yang menyala, AC mana yang aktif, suhu ruangan berapa. Semua ruangan (UI) *berlangganan* ke panel ini: begitu panel berubah, setiap ruangan yang relevan otomatis menyesuaikan pencahayaannya. Dulu, ruangan-ruangan saling berteriak menyalakan lampu seenaknya dan sering tidak sinkron; sekarang semuanya membaca dari satu panel yang sama. Tidak ada ruangan yang mengubah panel tanpa prosedur (`state.set()`), dan tidak ada ruangan yang menyalakan lampu langsung tanpa lewat panel.

**Single entry point `main.js`** ibarat **supervisor proyek** yang berdiri di pintu masuk: ia yang mempekerjakan semua departemen (`import ...`), memberi tahu siapa berlangganan panel mana (`subscribe`), dan memerintahkan pekerjaan pertama hari ini (load data awal). Departemen tidak saling memanggil sembarangan tanpa lewat supervisor — alur tetap satu arah dan mudah dibaca. Rumah yang dibangun dengan departemen terpisah bisa direnovasi tanpa merobohkan tembok lainnya; rumah dengan satu kabel raksasa harus selalu dibongkar untuk memperbaiki satu titik.

## 5. Kapan Harus Digunakan & Kasus Penggunaan (Use Cases)

- **Perkembangan fitur berkelanjutan** — ketika aplikasi sudah punya pencarian, filter, favorit, modal, notifikasi, dan ditambah fitur baru lagi; modul membuat penambahan tidak mengganggu fitur lama (Perpustakaan Digital Kota persis di titik ini).
- **State yang dipakai banyak UI** — misal jumlah hasil pencarian tampil di grid, header, dan halaman lain sekaligus; StateManager membuat ketiganya sinkron lewat subscribe, bukan hardcode manual.
- **Pemrograman paralel tim** — modul `api.js` dikerjakan anggota A sementara `ui.js` dikerjakan anggota B tanpa konflik merge (asalkan kontrak antar modul disepakati dulu).
- **Persistensi terpusat** — semua baca/tulis localStorage lewat satu `storage.js`, sehingga mengganti mekanisme penyimpanan (ke IndexedDB misalnya) cukup menyentuh satu file.
- **Jembatan menuju framework & TypeScript** — pola *module + central state + unidirectional flow* adalah fondasi yang sama di React (context/reducer, Vite) dan membuat migrasi ke TypeScript murah karena modul sudah terisolasi. Tanpa struktur ini, adopt TypeScript ke file raksasa hampir mustahil.

## 6. Poin-poin Penting & Best Practices

- **Separation of concerns**: satu modul satu tanggung jawab — jaringan (`api`), penyimpanan (`storage`), DOM (`ui`), data (`state`), interaksi (`events`). Dorong logika bisnis keluar dari `main.js`.
- **ES Modules**: gunakan `import`/`export` (bukan banyak `<script>` urutan yang rapuh). Export hanya API publik; jadikan variabel internal privat (`#field`).
- **State via subscribe**: `state.set()` selalu lewat updater, `state.get()` selalu mengembalikan salinan, dan UI diperbarui lewat `subscribe` — jangan pernah me-render manual lagi setelah mutasi data.
- **Satu sumber kebenaran**: UI membaca dari state, tidak menggandakan data di variabel lokal yang bisa 'basi'. Event delegation (materi 28) tetap dipakai untuk elemen dinamis.
- **Keamanan**: render data user dengan `textContent` / `replaceChildren`, hindari `innerHTML` untuk data tak tepercaya (materi 26, 27).
- **Type Safety (TypeScript)**: tambahkan tipe `interface` untuk kontrak API (Buku, HasilPencarian, State) dan tipe param fungsi tiap modul. Keuntungan terbesar adalah refactor yang aman karena compiler menangkap pemakaian yang salah.
- **Jangan ekspos state privat**: `state.get()` harus menyalin objek agar pemanggil tidak bisa memutasi state dari luar mekanisme `set()`.

## 7. Kesalahan Umum (Common Pitfalls & Bugs)

- **Circular import** — `ui.js` meng-import `state.js`, lalu `state.js` meng-import `ui.js` (misal state memanggil render langsung). Akibatnya nilai `undefined` saat load dan bug acak. Perbaikan: arahkan dependensi satu arah — `state` tidak boleh tahu soal DOM; biarkan `ui` yang berlangganan ke `state`.
- **State global berantakan / setel dari mana-mana** — `appState.favorit.push(...)` langsung dari `ui.js`, atau memakai objek yang sama dengan reference sehingga perubahan tak tercatat oleh subscriber. Perbaikan: jadikan `#state` privat, selalu lewat `set()` / `get()` copy, dan semua mutasi mengalir melalui `events.js`/aksi.
- **Subscribe menumpuk (memory leak)** — setiap render menambah subscriber baru tanpa membuang yang lama, sehingga render makin lambat dan dipanggil berkali-kali. Perbaikan: simpan hasil `subscribe()` (fungsi unsubscribe) dan panggil saat modul/komponen dibongkar.
- **Mengembangkan `main.js` sebagai 'segalanya'** — semua logika ditulis di entry point sehingga ia kembali menjadi file raksasa. Perbaikan: entry point hanya mengorkestrasi; setiap pekerjaan diserahkan ke modul bersangkutan.

```javascript
    #listeners = [];

    set(updater) {
```

```javascript
        else renderKatalog(state.buku, grid);
    });
    appState.subscribe((state) => renderFavorit(badge, state.favorit));

    const favoritAwal = Storage.ambil("favorit", []);
    appState.set({ favorit: favoritAwal });

    setupEventListeners();
});
```

**Pembahasan**: Tantangan 1 berhasil ketika `main.js` hanya berisi inisialisasi + `subscribe` dan `ui.js` menjadi satu-satunya file yang memanggil API DOM (`document.querySelector`, `createElement`, dsb.). Alur satu arah terlihat jelas: `input` event mengubah state → subscriber me-render ulang tanpa ada *satu pun* pemanggilan render manual di `events.js` atau setelah aksi favorit. Untuk tantangan 2, tombol favorit di kartu memanggil `appState.set({ favorit: ... })` dan **bukan** `renderKatalog()` lagi; dua UI yang berbeda (grid kartu + badge header) otomatis sinkron karena keduanya berlangganan ke state yang sama. Simpan hasil favorit via `Storage.simpan("favorit", ...)` agar persisten antar sesi (Level 6). Jika kamu menulis ulang `state.js`, `event.js`, dan `ui.js` di TypeScript dengan tipe `Buku` dan `AppState`, refactor dunia nyata kamu sudah siap untuk materi 37 (Vite) dan 38 (deploy).
