# 19. Cara JavaScript Bekerja di Browser

Materi ini menjelaskan bagaimana JavaScript masuk ke dalam halaman web: cara memasangnya via tag `<script>`, bagaimana browser memprosesnya, dan cara kerjanya sebagai bahasa single-threaded. Ini adalah fondasi yang menjelaskan mengapa halaman bisa "lambat" tanpa pemasangan script yang benar.

## 1. Penjelasan Singkat & Konsep Dasar

Di Level 1-3 kamu punya HTML yang memberi **struktur** dan CSS yang memberi **tampilan**, tapi keduanya statis — tidak bisa bereaksi terhadap klik, ketikan, atau apa pun. JavaScript (JS) adalah bahasa yang **berjalan di dalam browser** dan memberi **perilaku**: menghitung, mengambil keputusan, menunggu aksi user, lalu mengubah halaman. Sekali kamu paham cara JS "duduk" di dalam halaman, separuh perjalanan Level 4 selesai.

Cara paling umum memasang JS adalah lewat tag `<script src="js/main.js"></script>`. Namun **posisinya sangat menentukan**. Browser membaca HTML **dari atas ke bawah**. Ketika menemukan `<script>` biasa, browser mem-**blokir** (berhenti) parsing HTML: ia mengunduh file JS, menjalankannya, baru melanjutkan membaca sisa HTML. Akibatnya, halaman tampak lebih lambat, dan jika script mencoba mengakses elemen yang belum dibaca di bawahnya, hasilnya `null` (tidak ditemukan). Karena itu ada dua pola yang benar: letakkan `<script>` **di akhir `body`** (HTML sudah selesai di-parse sebelum JS dijalankan), atau pasang di `<head>` dengan atribut **`defer`** — browser mengunduh script lebih awal tapi menahannya hingga seluruh HTML selesai di-parse. `defer` juga menjamin script dijalankan **setelah HTML selesai**, jadi elemen sudah pasti ada.

Poin berikutnya: JavaScript adalah bahasa **single-threaded** — satu thread, satu pekerjaan pada satu waktu. Tidak ada dua perintah JS berjalan bersamaan di dalam satu halaman. Urutan eksekusi diatur oleh **call stack** (tumpukan fungsi yang sedang berjalan) dan **callback queue** (antrean fungsi yang menunggu giliran). Mekanismenya disebut **event loop** sederhana: ketika sebuah fungsi selesai (callback) waktunya tiba — misalnya `setTimeout` kembali setelah intervalnya — fungsi itu dipindahkan dari callback queue ke call stack untuk dijalankan. Artinya, operasi yang lama seperti menunggu respon dari server **tidak boleh** memblokir call stack, nanti di Level 6 kamu melihat bagaimana `async/await` dan `fetch` memanfaatkan lawan ini.

Satu hal penting lagi: JavaScript tidak mengubah file HTML yang kamu simpan — ia bekerja pada **DOM**, representasi halaman yang dibangun browser di memori. Jadi perintah `console.log("Halo")` hanya berefek di konsol, sedangkan nanti di Level 5 kamu akan mengubah DOM lewat perintah seperti `document.querySelector(...)` dan browser otomatis memperbarui tampilan.

**Benang merah**: HTML/CSS yang kamu bangun di Level 1-3 adalah objek yang akan dipegang dan diubah JavaScript. Materi ini memastikan kamu tahu *kapan JS aktif dan bisa menjangkau elemen halaman*, yang menjadi prasyarat mutlak sebelum belajar memanipulasi DOM di Level 5.

## 2. Fungsi & Kegunaan Utama dalam Web

Dalam project **Perpustakaan Digital Kota**, JavaScript mulai "menghidupkan" halaman statis. Katalog buku yang tadinya hanya deretan `<article>` diam sekarang bisa punya logika: menghitung **total stok** koleksi, mengecek **ketersediaan** buku, merespons kata kunci yang diketik pengunjung di kotak **pencarian**, dan nantinya (Level 5) merender ulang daftar buku tanpa memuat ulang halaman.

Tanpa pemasangan script yang benar, semua ini gagal di akar. Script yang diblokir di `<head>` membuat halaman terasa berat dan — lebih parah — kode yang menunggu elemen yang belum ter-parse akan gagal dengan error "null". Itu sebabnya setiap halaman perpustakaan (`index.html`, `katalog.html`, dst.) memakai pola yang sama: satu `<script src="js/main.js" defer>` atau script di akhir `body`.

Fungsi lainnya adalah **debugging**. DevTools (tekan F12) bukan cuma untuk melihat tab Elements; tab **Console** menampilkan semua output `console.log`, `console.warn`, dan `console.error`. Inilah "bengkel" utama untuk mengamati apakah logika JS berjalan sesuai harapan sebelum menyentuh tampilan.

## 3. Contoh Kode & Implementasi Real-World

Ada dua cara memasang script. Yang pertama, di akhir `body` — HTML selesai dibaca dulu, baru JS jalan:

```html
<!-- index.html -->
<!DOCTYPE html>
<html lang="id">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Perpustakaan Digital Kota</title>
    <style>
        body { font-family: sans-serif; max-width: 600px; margin: 0 auto; }
        .kartu-buku { border: 1px solid #ccc; border-radius: 8px; padding: 12px; margin-bottom: 8px; }
        .habis { opacity: 0.5; }
    </style>
</head>
<body>
    <h1>Perpustakaan Digital Kota</h1>
    <main id="katalog"></main>

    <!-- Script dipasang di AKHIR body:
         browser selesai membaca semua HTML dulu, baru menjalankan JS.
         Elemen #katalog dijamin sudah ada. -->
    <script src="js/main.js"></script>
</body>
</html>
```

Cara kedua, di `<head>` dengan `defer`. Fungsinya sama — eksekusi ditunda sampai HTML selesai — tapi file sudah mulai diunduh lebih awal:

```html
<head>
    <!-- defer: unduh sekarang, tapi jalankan SETELAH HTML selesai di-parse -->
    <script src="js/main.js" defer></script>
</head>
```

```javascript
// js/main.js
// Semua ini kamu ketik di file JS, lalu lihat hasilnya di DevTools → Console

// console.log: pesan informatif biasa
console.log("JavaScript aktif di Perpustakaan Digital Kota");

// console.warn: peringatan (kuning) — misal stok tipis
let stok = 8;
if (stok <= 10) {
    console.warn(`Stok "${"Clean Code"}" tersisa ${stok} — ajukan restok.`);
}

// console.error: rekap error (merah)
console.error("Gagal memuat data katalog.");

// console.table: tampilkan array of objects sebagai tabel rapi
const katalog = [
    { id: 1, judul: "Clean Code",        stok: 8,  harga: 150000 },
    { id: 2, judul: "Laskar Pelangi",    stok: 0,  harga:  95000 },
    { id: 3, judul: "Cosmos",            stok: 12, harga: 200000 },
];
console.table(katalog);

// Analogi call stack sederhana: fungsi berjalan satu per satu
function hitungTotalStok(daftar) {
    return daftar.reduce((total, buku) => total + buku.stok, 0);
}
const totalStok = hitungTotalStok(katalog); // call stack: hitungTotalStok → reduce
console.log("Total stok seluruh koleksi:", totalStok);

// Event loop sederhana: setTimeout tidak memblokir kode di bawahnya
console.log("Langkah 1");
setTimeout(() => console.log("Langkah 3 (setelah 1 detik, dari callback queue)"), 1000);
console.log("Langkah 2 — dijalankan tanpa menunggu setTimeout selesai");
```

## 4. Analogi Sederhana — Membangun Rumah

Dalam analogi rumah yang kita pakai dari Level 1: **HTML** adalah kerangka dan ruang-rumahnya, **CSS** adalah cat dan interiornya, dan **JavaScript** adalah instalasi listrik beserta otomatisasinya (lampu yang nyala sendiri saat orang masuk).

Rumah listrik itu tidak bisa menyalakan lampu sebelum tembok berdiri — kabelnya harus dipasang setelah struktur ada. Tag `<script>` adalah **titik sambungan listrik rumah**. Kalau kamu sambung listrik sambil temboknya masih setengah dibangun (script di `<head>` tanpa `defer`), tukang pintu berhenti kerja menunggu instalasi selesai — itulah halaman yang "macet" saat loading. Memasang script di akhir `body` berarti: tembok selesai dulu, baru listrik dipasang. Atribut `defer` sedikit lebih cerdik: kabelnya (file JS) sudah diangkut ke lokasi lebih awal, tapi tetap **dipasang setelah struktur selesai** — bukan sambil menutup tembok.

Setelah terpasang, listrik bekerja lewat satu jalur (single-threaded). Bayangkan satu tukang listrik yang menangani satu pekerjaan pada satu waktu: dia tidak pernah mengerjakan dua kabel secara bersamaan. Ketika pekerjaan kecil datang bertanya-tanya (callback), tukang itu menyelesaikan yang sedang dia pegang dulu di call stack, baru melayani yang antre di callback queue.

## 5. Kapan Harus Digunakan & Kasus Penggunaan (Use Cases)

- **Verifikasi halaman sudah terhubung dengan script** — bisa karena adegan `<script>` salah posisi atau salah path; buka Console dan pastikan `console.log` muncul.
- **Debugging data yang dihitung JavaScript** — misal `console.table(katalog)` untuk melihat apakah array data buku benar; `console.warn` untuk stok menipis, `console.error` saat fetch gagal (Level 6).
- **Memastikan elemen tersedia sebelum diakses JS** — pakai script di akhir `body` atau `defer`; tanpa ini, `document.querySelector` di `head` mengembalikan `null`.
- **Menjelaskan kenapa halaman terasa lambat** — biasanya karena `<script>` besar di `<head>` tanpa `defer` memblokir parsing HTML; perbaiki dengan memindah posisi atau menambah `defer`.
- **Menjaga responsivitas saat ada animasi/notifikasi** — memahami call stack & event loop membuat kamu tahu mengapa satu operasi berat di JS harus dipecah, sehingga UI perpustakaan tidak "membeku".

## 6. Poin-poin Penting & Best Practices

- Letakkan `<script>` di **akhir `body`**, atau di `<head>` dengan **`defer`**. Jangan pasang script biasa di `<head>` (memblokir parsing).
- Hubungkan file eksternal dengan `<script src="path/ke/file.js">`; hindari menulis JS panjang di dalam atribut `onclick` atau tag `<script>` di tengah body.
- Biasakan **`console.log` saat mulai** sebagai penanda bahwa file sudah ter-load, lalu `console.table` untuk melihat array/object.
- Gunakan `console.warn` untuk kondisi menyimpang yang belum fatal, dan `console.error` untuk error sungguhan — jauh lebih mudah dibaca daripada deretan `console.log`.
- Sadari bahwa JS **single-threaded**: pemrosesan berat (loop raksasa, request yang menunggu) sebaiknya ditangani lewat mekanisme async dan event loop, bukan memblokir call stack; hal ini dipelajari penuh di Level 6.
- Kebiasaan debugging: buka **DevTools (F12) → Console** dan jadikan itu tempat membaca output JS; tab Sources untuk melihat file dan breakpoint.
- Modern JS (ES6+) yang kita pakai dari sekarang: `const`/`let` untuk deklarasi, template literal `${...}`, dan arrow functions — lihat materi 20 dan 21.

## 7. Kesalahan Umum (Common Pitfalls & Bugs)

- **Script di `<head>` tanpa `defer`.** Halaman tampak lambat karena browser berhenti mem-parse HTML saat mengunduh dan menjalankan JS. Perbaikan: pindahkan script ke akhir `body` atau tambahkan `defer`.
- **Script mencoba akses elemen yang belum di-parse.** Menghasilkan `null` (misal `document.querySelector("#katalog")` mengembalikan `null` lalu `.innerHTML` melemparkan error). Perbaikan: pastikan script dieksekusi setelah HTML selesai (akhir body / `defer`).
- **Path script salah.** `<script src="js/main.js">` tapi folder `js/` tidak ada → Console menunjukkan `Failed to load resource: 404`. Perbaikan: cek struktur folder dan nama file, sama seperti debugging path gambar di Level 1.
- **Mengira dua operasi JS berjalan bersamaan.** JavaScript single-threaded; `setTimeout` tidak diproses hingga call stack kosong. Memahami ini mencegah asumsi "kode berjalan paralel" yang keliru.

## 8. Mini Project / Soal Latihan & Kunci Jawaban

### Tantangan

1. Buat file `index.html` dengan struktur sederhana (judul perpustakaan + satu `<main id="katalog">`), lalu hubungkan `js/main.js` menggunakan `<script src="js/main.js" defer></script>` di `head`.
2. Di `js/main.js`, definisikan array `katalog` berisi 3 buku (id, judul, stok, harga), lalu hitung total stok seluruh koleksi dan tampilkan ke Console dengan `console.log` (total "… stok"), `console.warn` jika ada buku yang stoknya 0, `console.table(katalog)` untuk melihat tabel data.
3. Amati urutan log: tambahkan `console.log("Script dimulai")` di baris pertama, lalu `setTimeout(() => console.log("Setelah timeout"), 0)` di tengah, dan `console.log("Script selesai")` di akhir. Perhatikan urutannya dan jawab: kenapa `"Setelah timeout"` muncul terakhir walau delaynya 0?

### Solusi & Pembahasan

```html
<!-- index.html -->
<!DOCTYPE html>
<html lang="id">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Perpustakaan Digital Kota — Latihan 19</title>
    <!-- defer: JS diunduh lebih awal, dijalankan setelah HTML selesai di-parse -->
    <script src="js/main.js" defer></script>
</head>
<body>
    <h1>Perpustakaan Digital Kota</h1>
    <main id="katalog"></main>
</body>
</html>
```

```javascript
// js/main.js
console.log("Script dimulai");

const katalog = [
    { id: 1, judul: "Clean Code",       stok: 8,  harga: 150000 },
    { id: 2, judul: "Laskar Pelangi",   stok: 0,  harga:  95000 },
    { id: 3, judul: "Cosmos",           stok: 12, harga: 200000 },
];

// Hitung total stok dengan reduce (lihat materi 23)
const totalStok = katalog.reduce((total, buku) => total + buku.stok, 0);
console.log(`Total stok seluruh koleksi: ${totalStok}`);

// Peringatan jika ada buku habis
if (katalog.some(buku => buku.stok === 0)) {
    console.warn("Ada buku dengan stok 0 — perlu restok!");
}

console.table(katalog); // tampilkan array sebagai tabel di Console

// Demonstrasi urutan eksekusi (event loop)
setTimeout(() => console.log("Setelah timeout"), 0); // delay 0 ms
console.log("Script selesai");

/*
Output di Console (perhatikan urutan):
Script dimulai
Total stok seluruh koleksi: 20
Console Warning: Ada buku dengan stok 0 — perlu restok!
┌────┬────┬──────────────────┬──────┬────────┐ ...
Script selesai
Setelah timeout

Kenapa "Setelah timeout" paling akhir padahal delay-nya 0?
Karena setTimeout selalu menaruh callback-nya ke callback queue,
dan callback baru dijalankan setelah call stack kosong —
yaitu setelah seluruh baris kode lain pada script selesai dieksekusi.
Ini contoh paling sederhana dari event loop JavaScript.
*/
```

**Pembahasan**: Latihan ini memakai `defer` yang tepat, menunjukkan bahwa karena `defer` menjamin eksekusi *setelah* HTML ter-parse, elemen `<main id="katalog">` sudah tersedia ketika script berjalan. Latihan ini juga membangun gambaran tentang **event loop**: kode berurutan didorong langsung ke call stack, sementara callback `setTimeout` (meskipun delay 0) diantrekan dan baru dieksekusi setelah call stack kosong.
