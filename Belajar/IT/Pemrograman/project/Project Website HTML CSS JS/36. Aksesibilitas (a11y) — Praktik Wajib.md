# 36. Aksesibilitas (a11y) — Praktik Wajib

Materi ini membahas aksesibilitas (disingkat **a11y** — huruf pertama, 11 huruf tengah, huruf terakhir dari "accessibility") sebagai praktik wajib, bukan bonus: ARIA roles, `aria-label`/`aria-expanded`/`aria-hidden`/`aria-live`/`aria-current`, skip link, `:focus-visible`, `.sr-only`, focus management dengan **trap focus** di modal, navigasi keyboard, dan kontras WCAG AA. Fokus: web yang bisa dipakai semua orang.

## 1. Penjelasan Singkat & Konsep Dasar

Aksesibilitas berarti website bisa digunakan oleh **semua orang**, termasuk pengguna yang tidak bisa melihat layar (memakai **screen reader** seperti NVDA, VoiceOver, atau JAWS), yang mengandalkan **keyboard penuh** (sulit atau tidak bisa memakai mouse karena kondisi motorik), yang buta warna, atau yang membaca dengan pembesar layar. Aksesibilitas bukan fitur untuk sebagian kecil orang — audiensnya menyentuh miliaran pengguna, dan sering kali tanpa sadar: tak seorang pun mengetik URL dengan kecepatan jari, tapi cacatnya tetap nyata. Perbaikan aksesibilitas juga memudahkan SEMUA orang: kontras yang baik membantu di siang yang terang, `aria-live` membantu saat layar tidak diperhatikan, dan navigasi keyboard membantu mereka yang lebih suka efisien.

Konsep inti aksesibilitas dimulai dari **HTML semantik** yang sudah dipelajari di Level 1 (materi 7). Browser dan screen reader membaca makna dari elemen: `<nav>`, `<main>`, `<button>`, `<label>`. Jadi aturan pertama a11y adalah *tidak perlu ARIA kalau elemen HTML sudah tersedia* — jangan memakai `<div onclick>` sebagai tombol; pakai `<button>`. **ARIA** (Accessible Rich Internet Applications) adalah lapisan kedua: atribut `role`, `aria-*` untuk memberi tahu teknologi bantu tentang perilaku yang tidak bisa diekspresikan di HTML standar — misal dialog modal (`role="dialog"`, `aria-modal`), status buka/tutup menu (`aria-expanded`), label untuk ikon tanpa teks (`aria-label`), atau pengumuman perubahan dinamis (`aria-live`).

Menggunakan keyboard dengan benar adalah bagian kedua yang tak tergantikan. Pengguna keyboard berpindah elemen dengan **Tab** (maju) dan **Shift+Tab** (mundur), memicu aksi dengan **Enter/Space**, dan menutup modal dengan **Escape**. Untuk itu dibutuhkan: **skip link** (link tersembunyi untuk melompat langsung ke konten utama, menghindari mem-Tab lewat menu yang panjang), **focus indicator yang jelas** (`:focus-visible`), dan **focus management** di komponen yang membuka lapisan baru — saat modal dibuka, fokus *dipindahkan ke dalam* modal; saat ditutup, fokus *dikembalikan* ke elemen yang membukanya; dan di dalam modal, tabbing harus **dikurung (trap focus)** supaya tidak tersesat ke area belakang modal.

Bagian visual: **kontras warna** memenuhi standar **WCAG AA** (Web Content Accessibility Guidelines, level AA: kontras minimal 4,5:1 untuk teks normal, 3:1 untuk teks besar). Teks abu-abu pucat di atas putih yang "membosankan" tapi biasanya dipakai sering kali di bawah ambang ini dan sulit dibaca para lansia. Dan kelas **`.sr-only`** (screen-reader-only): elemen yang tidak terlihat di layar tapi tetap dibacakan — pasangan klasik `aria-hidden="true"` (sembunyikan dari screen reader) untuk ikon dekoratif bintang.

**Benang merah**: Level 1-6 membangun fungsionalitas; Level 7 menyempurnakannya. Arsitektur material 34 memberi kita satu tempat modifikasi yang terpusat (`ui.js` misalnya) untuk memperbaiki label, role, dan fokus. Performa material 35 justru saling menopang — CLS yang dihindari dengan reserve ruang gambar juga menolong pembaca screen reader dan navigasi keyboard yang tidak suka elemen berpindah-pindah. Vite (37) dan deploy (38) memungkinkan audit Lighthouse di atas build produksi. Checkpoint Level 7 menargetkan skor Accessibility > 90, keyboard navigation sempurna, dan semua gambar punya `alt` deskriptif.

## 2. Fungsi & Kegunaan Utama dalam Web

**Perpustakaan Digital Kota** akan dipakai pengunjung beragam: mahasiswa yang buta total yang mencari buku lewat keyboard + screen reader, pejabat daerah yang menavigasi hanya dengan keyboard di rapat, atau pengunjung dengan layar kecil dan mata lelah yang membutuhkan kontras nyaman. Bagi mereka, modal detail buku harus bisa dibuka-ditutup tanpa tersesat fokus, menu harus diberi label yang jelas, dan hasil pencarian harus "diumumkan" (`aria-live`) begitu tiba — bukan MESAN yang hanya terlihat jika mereka kebetulan melihat layar.

Bagi tim dan institusi, a11y adalah persyaratan hukum di banyak wilayah (misalnya kebijakan akses layanan publik) dan bagian dari skor audit otomatis (Lighthouse). Aplikasi yang tidak aksesibel bukan hanya merugikan user — ia menutup pintu layanan yang seharusnya terbuka untuk semua. Secara teknis, accessibility memperbaiki struktur UX untuk semua orang: label yang jelas membantu mesin pencari memahami halaman (SEO naik), HTML semantik mudah dipakai dependency di library, dan navigasi keyboard membuat tombol "buka detail" punya urutan yang logis.

Dan praktik ini juga ditegakkan lewat **audit**: Lighthouse (tab Accessibility) memberi skor 0-100 dan daftar kekurangan spesifik (kontras, alt, label, fokus). Fokus yang rapi, trap focus yang benar, dan `aria-*` yang tepat menaikkan skor ini — cukup untuk checkpoint "Accessibility > 90" di akhir roadmap. Sebagai prinsip: **aksesibilitas bukan opsional**; ia adalah persyaratan kualitas yang setara dengan performa dan keamanan.

```javascript
// js/main.js

const modal = document.querySelector("#modal-detail");
let elemenSebelumModal = null; // ingat elemen pembuka modal

// ─── Menu keyboard ke semua elemen focus-able secara terurut ─────────────
function elemenFokusable(root) {
    return [...root.querySelectorAll(
        'a[href], button:not([disabled]), input, textarea, select, [tabindex]:not([tabindex="-1"])',
    )];
}

// ─── Trap focus: juarai Tab di dalam lingkaran modal ─────────────────────
function trapFokus(event) {
    if (event.key !== "Tab") return;

    const elemen = elemenFokusable(modal);
    const pertama = elemen[0];
    const terakhir = elemen[elemen.length - 1];

    if (event.shiftKey && document.activeElement === pertama) {
        terakhir.focus();
        event.preventDefault(); // cegah Tab mendarat di belakang modal
    } else if (!event.shiftKey && document.activeElement === terakhir) {
        pertama.focus();
        event.preventDefault();
    }
}

function bukaModal(idBuku) {
    elemenSebelumModal = document.activeElement; // SULIT sebelum fokus dipindah

    // Isi konten (data contoh; di aplikasi nyata lewat state.js → ui.js)
    const buku = LIBROK.get(idBuku);
    if (!buku) return;

    modal.querySelector("#modal-judul").textContent = buku.judul;
    modal.querySelector("#modal-deskripsi").textContent =
        "Informasi lengkap tentang buku yang dipilih.";
    modal.querySelector("#modal-info").textContent =
        `Oleh ${buku.penulis} — ${buku.tahun}. Kategori: ${buku.kategori}.`;

    modal.hidden = false;                        // pakai hidden, bukan display:none manual
    document.body.classList.add("no-scroll");

    // Fokus ke elemen focusable PERTAMA di modal
    elemenFokusable(modal)[0].focus();

    modal.addEventListener("keydown", trapFokus); // kunci fokus di dalam
}

function tutupModal() {
    modal.hidden = true;
    document.body.classList.remove("no-scroll");
    modal.removeEventListener("keydown", trapFokus);

    // KEMBALIKAN fokus ke elemen yang membuka modal — wajib
    if (elemenSebelumModal) elemenSebelumModal.focus();
}

// ─── Buka lewat tombol detail (delegation — materi 28) ───────────────────
document.querySelector("#katalog-grid").addEventListener("click", (event) => {
    const tombol = event.target.closest(".btn-detail");
    if (tombol) bukaModal(Number(tombol.dataset.id));
});

// ─── Tutup: tombol ×, overlay, atau Escape ────────────────────────────────
document.querySelector("#modal-tutup").addEventListener("click", tutupModal);
document.querySelector(".modal-overlay").addEventListener("click", tutupModal);
document.addEventListener("keydown", (event) => {
    if (event.key === "Escape" && !modal.hidden) tutupModal();
});
```

## 4. Analogi Sederhana — Membangun Rumah

**HTML** adalah kerangka dan tata ruang, **CSS** adalah cat dan dekorasi, **JS** adalah instalasi listrik. Material 36 adalah **rumah yang bisa dimasuki semua orang**: pintu yang cukup lebar untuk kursi roda dan **rambu-rambu yang terbaca** di setiap sudut. Rumah perpustakaan digital kita harus bisa dimasuki pengunjung yang tidak bisa melihat denah, yang mengarungi ruangan hanya dengan meraba dinding (keyboard + screen reader) — jadi setiap ruangan harus punya **papan keterangan bermakna** (`aria-label`, `role`, teks `sr-only`) di tempat yang tepat, bukan sekadar dekorasi.

**Trap focus** seperti **jembatan yang tidak membiarkan orang tersesat**. Saat modal detail dibuka, itu seperti portal antar-ruangan: pengunjung yang memasuki portal harus *dipandu* — begitu masuk, mereka tidak boleh berjalan terus melewati portal ke ruangan berikutnya tanpa sadar (fokus kabur keluar modal). Dekorator jaga menempatkan pengunjung tepat di kursi pertama ruangan itu (fokus berpindah ke tombol tutup), dan ketika portal ditutup, pengunjung *dikembalikan* ke tempat semula di ruang terbuka sebelum masuk (fokus kembali ke tombol "Lihat detail"). Itulah kepedulian yang terasa: tidak ada yang hilang di koridor.

**Skip link** seperti **pintu rahasia petugas di tengah museum yang panjang**: pengunjung yang tidak ingin berjalan lewat deretan mazhab yang sama tiap kali (menu) bisa langsung melompat ke ruang pamer utama. **Kontras** adalah **penerangan yang cukup di setiap balkon** — tanda ruangan jangan memakai tulisan abu-abu di dinding putih yang hampir tak terlihat saat mata lelah. Prinsip besarnya: rumah yang bagus bukan hanya bagus dilihat, tapi **bisa dinikmati setiap penghuni tanpa harus berlari mengelilingi gedung untuk membuktikannya**.

## 5. Kapan Harus Digunakan & Kasus Penggunaan (Use Cases)

- **Modal detail buku** — `role="dialog"` + `aria-modal`, fokus saat pembukaan, trap focus (Tab melingkar), Escape untuk menutup, dan fokus kembali ke tombol "Lihat detail" setelah ditutup.
- **Pencarian dengan hasil dinamis** — kotak pencarian diberi `aria-label` (jika tidak punya `<label>` visible), hasil diberi `aria-live="polite"` supaya screen reader membacakan jumlah hasil baru tanpa diminta.
- **Menu/navigasi** — `<nav aria-label="Navigasi utama">` membedakan beberapa nav (misal header vs footer); `aria-current="page"` menandai Beranda aktif; `aria-expanded` + `aria-controls` pada hamburger menu; keyboard (Tab) menelusuri item menu.
- **Rating bintang** — ikon `★` dibungkus `aria-hidden="true"` (hanya dekorasi) + teks `.sr-only` "Rating: 4 dari 5" yang dibacakan (lihat materi 36-nya di ujung contoh).
- **Form** — tiap `<label>` terhubung ke input via `for`/`id`; pesan error memakai `role="alert"` atau `aria-live`; field wajib dijelaskan tanpa bergantung semata pada warna.
- **Tombol ikon** — tombol berisi hanya ikon (×, ☰) diberi `aria-label` (atau `aria-labelledby`) dan `title` sebagai fallback hover.

## 6. Poin-poin Penting & Best Practices

- **Semantik dulu, ARIA kemudian**: pakai elemen HTML yang benar (`<button>`, `<nav>`, `<label>`) sebelum menimba ARIA. Aturan emas ARIA: *"No ARIA is better than bad ARIA"* — role dan label yang salah lebih membingungkan daripada tidak ada.
- **Label & referensi**: setiap elemen interaktif harus punya nama aksesibel — label terlihat (`<label>`), `aria-label`, atau `aria-labelledby`. `aria-hidden="true"` hanya untuk ikon/ornamen; pasangkan dengan teks `.sr-only` bila berfungsi.
- **Skip link + target**: skip link harus elemen nyata `<a href="#id">`, dan target harus elemen dengan `tabindex="-1"` bila bukan header (agar bisa menerima fokus) — atau cukup `id` pada `<main>`.
- **Focus management wajib untuk kode-springboard**: saat modal/drawer/menu dibuka: simpan `document.activeElement`, pindahkan fokus ke elemen pertama yang fokusable; saat ditutup: kembalikan. Trap Tab di dalam lapisan dengan `trapFokus`; `Escape` selalu menutup.
- **`:focus-visible`** — jangan hilangkan outline global dengan `outline: none`. Ganti indikator fokus global dengan `:focus-visible` agar mouse user tidak diganggu, tapi keyboard user tetap tahu posisinya.
- **Kontras WCAG AA**: teks normal ≥ 4.5:1, teks besar/serta-ikon ≥ 3:1. Audit tiap palet dengan alat kontras checker; jangan andalkan tebakan.
- **`aria-live` dengan benar**: gunakan `polite` untuk update hasil yang wajar dibaca (hasil pencarian), `assertive` (jarang) hanya untuk kesalahan kritis; jangan menandai seluruh halaman sebagai live.
- **Aksesibilitas bukan opsional**: audit dengan Lighthouse (skor Accessibility > 90 target), uji manual dengan Tab, dan coba NVDA/VoiceOver. Masukkan item a11y ke definisi-done setiap fitur.

## 7. Kesalahan Umum (Common Pitfalls & Bugs)

- **ARIA label duplikat / overlabeling** — setiap kontrol di-modal diberi `aria-label` yang sama ("Detail buku") sehingga screen reader tak bisa membedakan, atau `aria-label` diletakkan di elemen yang punya teks terlihat sehingga ada dua nama. Perbaikan: beri label unik; jangan timpa teks terlihat yang sudah menjelaskan; pakai `aria-labelledby` untuk mengambil teks yang ada.
- **Fokus tidak ke modal saat dibuka** — modal tampil tapi focus tetap di halaman belakang; user keyboard terus men-Tab ke belakang layar yang tertutup overlay. Perbaikan: panggil `focus()` elemen pertama + pasang `trapFokus` pada `keydown` modal dan lepaskan saat tutup.
- **Outline dihapus tanpa pengganti** — `*:focus { outline: none }` (atau `:focus`) membuat keyboard user tidak tahu posisi kursor. Perbaikan: gaya `:focus-visible` dengan kontras jelas, setidaknya 2-3px + offset.
- **`display:none` untuk elemen sr-only** — teks "Rating: 4 dari 5" disimpan dengan `display:none`, sehingga screen reader tidak membacanya sama sekali. Perbaikan: pola `.sr-only` (clip rect) yang menyingkirkan visual tapi tetap di hierarki aksesibilitas.
- **Kontras di bawah ambang** — teks abu-abu (#cbd5e1) atau biru muda di putih dipakai sebagai teks normal. Perbaikan: ukur rasio dengan checker; naikkan kegelapan atau perbesar ikon/teks sampai ≥4.5:1 (AA).
- **Modal shadow tanpa akses keyboard** — overlay modal menutupi halaman tapi halaman belakang masih bisa di-Tab (fokus bocor). Perbaikan: trap focus + `aria-modal="true"` (dan pertimbangkan `inert` di belakang).

```javascript
    return [...root.querySelectorAll(
        'a[href], button:not([disabled]), input, select, textarea, [tabindex]:not([tabindex="-1"])',
    )];
}

function trapFocus(event) {
    if (event.key !== "Tab") return;
    const el = fokusable(modal);
    const pertama = el[0], terakhir = el[el.length - 1];
    if (event.shiftKey && document.activeElement === pertama) {
        terakhir.focus();
        event.preventDefault();
    } else if (!event.shiftKey && document.activeElement === terakhir) {
        pertama.focus();
        event.preventDefault();
    }
}

function bukaModal(judul, penulis) {
    elemenPembuka = document.activeElement;
    modal.querySelector("#m-judul").textContent = judul;
    modal.querySelector("#m-desk").textContent = `Detail buku "${judul}".`;
    modal.querySelector("#m-info").textContent = `Ditulis oleh ${penulis}.`;
    modal.hidden = false;
    fokusable(modal)[0].focus();        // fokus pindah ke tombol tutup
    modal.addEventListener("keydown", trapFocus);
}

function tutupModal() {
    modal.hidden = true;
    modal.removeEventListener("keydown", trapFocus);
    if (elemenPembuka) elemenPembuka.focus(); // fokus kembali ke pembuka
}

document.querySelector("#grid").addEventListener("click", (e) => {
    const tombol = e.target.closest(".btn-detail");
    if (tombol) bukaModal(tombol.dataset.judul, tombol.dataset.penulis);
});
document.querySelector("#m-tutup").addEventListener("click", tutupModal);
document.querySelector(".modal-overlay").addEventListener("click", tutupModal);
document.addEventListener("keydown", (e) => {
    if (e.key === "Escape" && !modal.hidden) tutupModal();
});

// (a) Menu hamburger: aria-expanded sinkron dengan visibility
const btnMenu = document.querySelector("#btn-menu");
const menu = document.querySelector("#menu-mobile");
btnMenu.addEventListener("click", () => {
    const terbuka = menu.hidden;
    menu.hidden = !terbuka;
    btnMenu.setAttribute("aria-expanded", String(!terbuka));
});

// (b) Hasil pencarian: aria-live sudah di HTML; contoh update via state
setTimeout(() => {
    document.querySelector("#info-hasil").textContent = "Menampilkan 10 buku.";
}, 1500);
```

**Pembahasan**: Tantangan 1 selesai ketika tiga hal berlaku: (1) saat modal dibuka fokus pindah ke elemen fokusable pertama di dalam dan `trapFocus` membelit Tab di lingkaran modal (tombol tutup → konten → tombol tutup), jadi keyboard user tidak pernah tersesat ke halaman belakang; (2) `Escape` serta klik overlay × menutup modal; (3) fokus **dikembalikan** ke tombol `Lihat ...` via `elemenPembuka` — ini yang membuat screen reader user kembali menemukan tempat semula tanpa tersasar. Skip link di HTML menuju `#konten` yang diberi `tabindex="-1"` supaya `<main>` bisa menerima fokus saat melompat.

Latihan 2: `aria-expanded` di tombol menu disinkronkan dengan properti `hidden` dari nav (nilai true/false) sehingga asistensi tahu status; `aria-controls` menunjuk ke id menu. `aria-live="polite"` di `#info-hasil` membuat perubahan teks (hasil pencarian) diumumkan otomatis tanpa memotong kalimat yang sedang dibaca — jangan pakai `assertive` untuk hal sepele seperti ini. Rating bintang memisahkan visual (`aria-hidden`) dari info (`sr-only`), memenuhi salah satu pola paling umum di katalog. Kontras dicek dengan rumus/warna yang dipilih: `#1e3a8a` di atas `#dbeafe` ≈ 7:1 (di atas ambang 4.5:1 AA), `#1e293b` di atas putih ≈ 14:1 — semua teks utama lulus WCAG AA. Coba di Lighthouse: skor Accessibility di atas 90, dan semua check interaktif "manually verify" bisa dicentang.
