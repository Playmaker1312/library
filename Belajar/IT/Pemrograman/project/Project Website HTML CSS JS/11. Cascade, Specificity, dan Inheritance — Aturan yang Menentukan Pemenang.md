# 11. Cascade, Specificity, dan Inheritance — Aturan yang Menentukan Pemenang

Pertanyaan paling sering dari developer pemula: "Aku sudah menulis style, tapi kenapa tidak jalan?" Dua materi sebelumnya membahas cara menautkan CSS (materi 9) dan memilih elemen dengan selector (materi 10). Kali ini kita membahas **mengapa style bisa kalah atau menang** — tiga mekanisme CSS yang menentukan hasil akhir tampilan: cascade, specificity, dan inheritance.

## 1. Penjelasan Singkat & Konsep Dasar

CSS adalah bahasa yang luar biasa, tapi perilakunya tidak intuitif: kamu bisa menulis aturan yang benar secara syntax, tapi hasilnya tidak seperti yang kamu bayangkan. Penyebab utamanya adalah CSS bekerja dengan tiga mekanisme simultan yang saling bersaing:

1. **Cascade** — menentukan urutan sumber aturan. Ketika dua aturan sama-sama relevan, aturan dari sumber yang "lebih tinggi" menang (misal inline style mengalahkan external). Ini sebabnya urutan `<link>` di materi 9 penting.
2. **Specificity** — menentukan seberapa "spesifik" sebuah selector. Selector dengan specificity lebih tinggi menang atas yang lebih rendah, terlepas dari urutan penulisan. Ini sebabnya `.judul` mengalahkan `h1`, dan `#header .judul` mengalahkan keduanya.
3. **Inheritance** — property yang diwariskan. Beberapa property (seperti `color` dan `font-family`) mengalir dari parent ke child, sementara yang lain (seperti `margin` dan `padding`) tidak. Ini menghemat ribuan baris CSS: kamu set font sekali di `body`, semua elemen di dalamnya ikut.

Ketiganya bekerja bersama menentukan **nilai final (computed value)** setiap elemen. Saat kamu membuka DevTools → tab Styles → tab Computed, yang kamu lihat adalah hasil dari ketiga mekanisme ini.

Benang merah dari seluruh roadmap: di Level 1 kamu memahami HTML sebagai struktur hierarkis; di materi 9 kamu menghubungkan CSS; di materi 10 kamu memilih elemen. Sekarang kamu memahami "hukum" yang mengatur konflik antar aturan. Hukum ini tidak hilang di level manapun — bahkan di proyek berskala besar dengan ratusan file CSS, cascade dan specificity tetap yang menentukan apakah tombolmu biru atau hijau. Kuasai ini, dan 90% rasa frustasi "style-ku tidak jalan" akan sirna.

## 2. Fungsi & Kegunaan Utama dalam Web

Tanpa rule cascade, CSS menjadi huru-hara: tidak ada kepastian aturan mana yang berlaku ketika dua file CSS bentrok. Secara praktis, mekanisme ini penting bagi Perpustakaan Digital Kota karena:

- **Konflik antar sumber terselesaikan secara deterministik.** Reset di `reset.css` bentrok dengan style di `components.css`? Browser punya aturan pasti siapa menang — kamu bisa memprediksi dan mengkontrolnya, bukan menebak.
- **Component yang bisa diisi ulang tanpa menghancurkan gaya lain.** Tombol `.btn--primary` di navbar dan tombol highlight di hero bisa hidup berdampingan karena specificity owner tiap komponen terkontrol.
- **Kustomisasi terpusat vs lokal.** Set `color` dan `font-family` di `body` sekali, seluruh halaman (ribuan elemen) terpengaruhi — ini kerja inheritance yang luar biasa efisien.
- **Men-debug dengan DevTools bukan dengan menebak.** Memahami specificity berarti kamu bisa membaca tab Computed di DevTools: kenapa property ini tercoret dengan strikethrough? Karena aturan lain yang lebih spesifik menang. Kamu langsung tahu harus mengubah apa.
- **Menghindari "perang CSS".** Tim developer yang tidak paham cascade akan menumpuk `!important` dan selector panjang-panjang hanya untuk memenangkan konflik. Tim yang paham, menulis CSS dengan specificity rendah dan bertambah inkremental — mudah diprediksi, mudah dipelihara.

## 3. Contoh Kode & Implementasi Real-World

### Specificity — Mengukur Kekuatan Selector

Specificity dihitung dengan tiga angka `(A, B, C)`:
- **A** = banyaknya **ID selector** (`#...`)
- **B** = banyaknya **class, attribute selector, pseudo-class** (`.`, `[...]`, `:`)
- **C** = banyaknya **element dan pseudo-element** (`h1`, `::before`)

```css
/*
CONTOH PERHITUNGAN:

h1                    → 0 ID, 0 class, 1 element    → (0, 0, 1)
.judul                → 0 ID, 1 class, 0 element    → (0, 1, 0)
#header               → 1 ID, 0 class, 0 element    → (1, 0, 0)
h1.judul              → 0 ID, 1 class, 1 element    → (0, 1, 1)
#header h1            → 1 ID, 0 class, 1 element    → (1, 0, 1)
#header .judul        → 1 ID, 1 class, 0 element    → (1, 1, 0)
.kartu-buku h3 a:hover → 0 ID, 2 class, 2 element   → (0, 2, 2)
*/

/* Contoh di halaman perpustakaan: */
h1 { color: #2563eb; }                    /* (0,0,1) — biru */
.judul-hero { color: #dc2626; }           /* (0,1,0) — merah, MENANG karena lebih spesifik */
#judul-beranda { color: #16a34a; }        /* (1,0,0) — hijau, MENANG lagi karena ID */

/* Perbandingan mana yang menang:
   #judul-beranda (1,0,0)  → menang → judul hijau
*/
```

### Cascade — Urutan Sumber, dari Terendah ke Tertinggi

```css
/*
URUTAN CASCADE (dari yang paling "kalah" ke paling "menang"):

1. Gaya bawaan browser (default stylesheet / user agent)
2. External CSS    (file yang di-link, materi 9)
3. Internal CSS    (<style> di <head>)
4. Inline CSS      (atribut style=""  — mengalahkan external dan internal)
5. !important      (bisa mengalahkan semuanya — hati-hati!)

Aturan perbandingan:
- Specificity dibandingkan lebih dulu.
- Jika specificity SAMA, baru urutan cascade & posisi terakhir yang tampil menang.
*/

/* Contoh nyata — akses link yang TIDAK berjalan: */
a {
    color: #2563eb;   /* dalam style.css — kalah dalam cascade */
}

a {
    color: #dc2626;   /* dalam components.css, later in file — SAMA specificity, posisi belakang menang */
}

/* jika masih dua-duanya sama, inline style menang: */
<a style="color: #16a34a;">Link</a>   <!-- mengalahkan kedua file di atas -->
```

### Inheritance — Property yang Mengalir ke Anak

```css
/*
DIWARISKAN (inherited):
  color, font-family, font-size, line-height, font-weight,
  text-align, cursor, visibility, list-style, dsb.

TIDAK DIWARISKAN (non-inherited):
  margin, padding, border, background, width, height,
  display, position, float, box-sizing, dsb.
*/

body {
    color: #1e293b;             /* diwariskan ke SEMUA elemen di dalam body */
    font-family: sans-serif;    /* diwariskan juga */
}

/* Di HTML, <p> di dalam <body> akan memakai #1e293b + sans-serif */
/* tanpa perlu ditulis lagi di CSS. Efisiensi besar! */

/* Tetapi jangan set property seperti ini berharap mengalir: */
.container {
    padding: 16px;              /* margin/padding TIDAK diwariskan */
    background: #f8fafc;        /* background TIDAK diwariskan */
}

/* Mengontrol inheritance secara eksplisit: */
child {
    color: inherit;    /* paksa ambil warna dari parent */
    margin: initial;   /* kembalikan ke nilai default browser */
}
```

### Mengapa "Style Tidak Jalan" — Ilustrasi Lengkap

```css
/* Skenario: kamu ingin h2 di artikel jadi biru, ternyata tetap hitam. */

/* 1. Ada aturan lebih spesifik lain yang menang: */
h2 { color: #2563eb; }              /* (0,0,1) */
.artikel h2 { color: #000000; }     /* (0,1,1) → MENANG! Artinya tetap hitam */
#kategori-teknologi h2 { color: #1e293b; }  /* (1,0,1) → menang lagi */

/* 2. Grammar/typo: property salah nama → browser abaikan */
h2 { colour: #2563eb; }  /* 'colour' tidak dikenal → diabaikan */

/* 3. Urutan sama specificity: posisi terakhir menang */
h2 { color: #2563eb; }    /* kedua aturan specificity sama */
h2 { color: #000000; }    /* aturan ini di posisi lebih akhir → MENANG */
```

Yang perlu digarisbawahi: **specificity dibandingkan dulu, selama itu juga urutan.** Setting ini membuat seluruh sistem konsisten dan bisa diprediksi.

## 4. Analogi Sederhana — Membangun Rumah

Kembali ke proyek rumah kita: HTML kerangkanya, CSS tukang cat, JS instalasi listrik. Kali ini fokus pada **bagaimana keputusan warna diambil ketika instruksi bertentangan**.

Bayangkan dalam satu hari rumahmu menerima beberapa perintah yang saling bertentangan tentang warna cat dinding kamar tidur. Siapa yang menang? Itu *cascade* dan *specificity* dalam kehidupan nyata:

- **Specificity** = aturan keputusan berdasarkan **siapa yang memberi perintah dan seberapa spesifik perintahnya**. Perintah **pemilik rumah** yang spesifik ("cat kamar tidur nomor 3 hijau", `#kamar-3`) lebih berkuasa daripada perintah umum **kontraktor** ("semua kamar cat biru", `h2`). Pemilik yang menunjuk ruangan tertentu menang atas kontraktor yang bicara umum tentang semua ruangan. Semakin spesifik siapa yang memerintah, semakin tinggi kekuatannya.
- **Cascade** = urutan **kapan perintah datang**. Jika pemilik rumah dua kali memerintah hal yang sama spesifiknya, perintah yang diucapkan **terakhir** yang berlaku ("ah, ganti jadi biru tua"). Kamu bicara ke tukang cat paling penghujung hari, kata-katamu itulah yang dipakai.
- **Inline** = pemilik berdiri di depan dinding kamar paling malam dan bilang "ganti merah!". Instruksi lisan yang paling langsung dan terakhir itu mengalahkan semua catatan tertulis.
- **`!important`** = pemilik berteriak sambil menghentakkan kaki. Efektif memenangkan segalanya, tapi bikin kemudian hari semua orang hanya tahu teriak, dan aturan tertulis jadi kehilangan makna. Hindari.
- **Inheritance** = warna cat **ruangan mengalir ke semua barang dan perabot di dalamnya**. Kamar dicat kuning, semua alat dan furnitur di dalamnya ikut tersentuh aksen kuning. Begitu pula `color` yang diinduksi di `body` mengalir ke semua teks anaknya. Tapi ingat: tidak semua hal mengalir — **margin/padding itu seperti jarak antar perabot**, tidak ikut mengalir ke interior barang di dalamnya (mereka bukan si content).

Semua analogi ini bermuara ke hal yang sama: CSS *menentukan pemenangnya* dengan hukum yang jelas, dan kamu bisa menjadi penguasa hukum itu alih-alih korbannya.

## 5. Kapan Harus Digunakan & Kasus Penggunaan (Use Cases)

- **Reset vs component styling.** `reset.css` menghapus gaya default browser (margin body, dsb.); `components.css` memberikan gaya spesifik komponen. Kamu mengandalkan cascade: component lebih spesifik dari reset.
- **Kustomisasi brand di satu tempat.** Set `color` dan `font-family` di `body` (inheritance), lalu ubah sedikit saja di komponen tertentu (misal heading). Ini pola "set global, override lokal" yang terstruktur rapi.
- **State interaktif yang saling berimba.** `a:hover` dan `a:visited` bisa saling menimpa; memahami specificity (masing-masing `(0,1,1)`) dan urutan membantu menulis urutan yang benar: `a:link`, `a:hover`, `a:visited`, `a:focus`.
- **Tema (dark mode) nanti di Level 3+.** Pergantian nilai variabel CSS (materi 12) hampir tidak bersentuhan dengan specificity karena nilainya diubah pada satu tempat. Familiar dengan cascade membuat transisi tema itu mulus.
- **Debugging style yang "tidak jalan".** Setiap kali elemen tampil tidak sesuai harapan, kamu buka DevTools → tab Styles → lihat aturan mana yang *strikethrough*, baca specificity-nya, lalu putuskan: pangkas selector, pindah urutan, atau (terakhir) gunakan `!important`.

## 6. Poin-poin Penting & Best Practices

- **Hindari `!important`.** Kekuatan tanpa batas menggoda, tapi efeknya merusak: setiap orang sesudahmu akan mengira aturannya kalah dan ikut menembak dengan `!important` — akhirnya semua jadi perang. Jika menemukan diri sendiri butuh `!important`, itu tanda specificity-mu sudah berantakan: perbaiki sumbernya.
- **Jaga specificity tetap rendah dan inkremental.** Ditulis dari global (spesificity rendah) ke komponen spesifik (dengan kenaikan kecil), bukan melompat. Cita-citanya: specificity angka kecil yang konsisten, mudah diprediksi.
- **Hindari ID selector untuk styling.** Satu ID = `(1,0,0)` yang nyaris mustahil dilawan. Pakai class; ID untuk JS.
- **Biasakan gunakan CSS Custom Properties (variabel).** Warna dan spacing di `:root` (materi 12) membuat perubahan tema tidak menabrak specificity sama sekali — nilai berubah di satu tempat.
- **Batas kedalaman selector maksimal 3 kombinator.** Panduan dari materi 10 — sekaligus menjaga specificity tetap rendah.
- **Gunakan DevTools sebagai "wasit".** Tab Styles dan Computed adalah sumber kebenaran: lihat apakah aturan yang kamu harapkan benar-benar terapkan. Biasakan *strikethrough* berarti kalah, bukan berarti CSS tidak dipanggil.
- **Bekerjalah dengan cascade, bukan melawan.** Tulis file reset dulu, style global kedua, komponen ketiga — dan pastikan urutan `<link>` mengikuti. Style yang "terakhir dan paling berbeda-beda" yang menang.
- **Pahami daftar property yang diwariskan.** Manfaatkan untuk efisiensi. Jika ingin memberangus warisan, gunakan `inherit` / `initial` secara eksplisit.

## 7. Kesalahan Umum (Common Pitfalls & Bugs)

- **Style "tidak jalan" karena specificity lebih rendah.** Kamu yakin menulis `h1 { color: blue; }` tapi judul tetap merah karena ada `.hero h1 { color: red; }` yang lebih spesifik. Perbaikannya: pahami perhitungan `(A,B,C)`, atau raih keandalan dengan menulis selector yang setara (`.hero h1`) agar bisa saling mengalahkan dengan urutan.
- **Style "tidak jalan" karena urutan cascade salah.** Dua aturan specificity sama, yang terakhir yang menang. Sering terjadi karena file component di-link sebelum style utama, atau aturan duplikat tersebar tidak rapi. Perbaikannya: periksa urutan `<link>` dan tulis komponen setelah global.
- **Inline style menyulitkan override.** Semua aturan dari external/internal kalah oleh `style=""` di elemen itu sendiri. Menambal dengan `!important` hanya menambah kekacauan. Perbaikannya: hapus inline style, pindahkan semua styling ke class.
- **`!important` berantakan.** `color: red !important;` di beberapa tempat dengan nilai saling bertentangan → ketidakpastian total, file tidak bisa dipahami. Perbaikannya: bersihkan semua `!important`, perbaiki specificity, baru atur ulang dengan terstruktur.
- **Selector terlalu spesifik.** `body #main .container .kartu-buku .harga span strong` — spesificity meledak teks ini, mustahil di-override tanpa `!important`, dan rapuh terhadap perubahan struktur. Perbaikannya: pangkas selector, atau tandai elemen langsung dengan class (BEM).
- **Salah menduga property diwariskan.** Menulis `margin: 16px` pada `body` lalu bingung kenapa setiap `<p>` tidak dapat margin. Perbaikannya: hafal daftar property yang diwariskan (font & text) vs yang tidak (layout & box). `inherit`/`initial` untuk yang ingin diatur secara terang-tebasan.
- **Cab dari typo property.** `colour`, `padding-top : 10px` (spasi), atau nilai yang salah format → browser mengabaikan. DevTools akan menandainya. Perbaikannya: periksa tab Styles, hapus strikethrough yang tidak diinginkan dengan memperbaiki penulisan.

## 8. Mini Project / Soal Latihan & Kunci Jawaban

### Tantangan 1

Perbaiki kode berikut sehingga `<h2>` di section `.artikel` berwarna hijau (`#16a34a`), tanpa mengubah HTML, dan tanpa `!important`:

```css
/* css/style.css */
h2 { color: #1e293b; }
.artikel h2 { color: #dc2626; }
h2.artikel { color: #2563eb; }
```

Hitung specificity setiap aturan, jelaskan aturan mana yang menang dan mengapa.

### Solusi & Pembahasan 1

```css
/* Perbaikan: aturan yang paling spesifik untuk target kita */
.artikel h2 { color: #16a34a; }
```

**Perhitungan specificity:**
- `h2` → `(0,0,1)`
- `.artikel h2` → `(0,1,1)`
- `h2.artikel` → `(0,1,1)` (sama nilainya tapi menargetkan elemen yang kebetulan punya class `.artikel` di dirinya sendiri — bukan h2 di dalam `.artikel`)
- Perbaikan `.artikel h2` → `(0,1,1)` menang atas `h2` `(0,0,1)`, dan karena targetnya cocok untuk semua h2 di dalam `.artikel`, hasilnya hijau sesuai harapan.

**Pembahasan:** Aturan `.artikel h2` dan `h2.artikel` punya specificity yang sama `(0,1,1)`, jadi urutan penulisan jadi penentu — yang terakhir menang. Kuncinya bukan menambah specificity setinggi mungkin, tapi memilih selector yang *tepat sasaran*: elemen h2 yang berada di dalam container ber-class `.artikel`. Dengan aturan yang tepat, kamu tidak perlu `!important` sama sekali.

### Tantangan 2

Diberikan HTML berikut:

```html
<article id="kartu-unggulan" class="kartu-buku">
    <h3>Clean Code</h3>
    <p class="kategori">Teknologi</p>
    <a href="buku/clean-code.html">Lihat Detail</a>
</article>
```

Hitung specificity untuk selector-selector ini dan tentukan warna `h3` final jika kesemuanya ditulis berurutan dalam satu file CSS:

```css
h3 { color: #1e293b; }
.kartu-buku h3 { color: #2563eb; }
#kartu-unggulan h3 { color: #dc2626; }
```

### Solusi & Pembahasan 2

- `h3` → `(0,0,1)`
- `.kartu-buku h3` → `(0,1,1)`
- `#kartu-unggulan h3` → `(1,0,1)` → **MENANG** → warna akhir h3: `#dc2626` (merah)

**Pembahasan:** ID selector `#kartu-unggulan` memberi bobot `(1,0,0)` saja sudah mengalahkan kombinasi class dan element mana pun yang tidak memuat ID. Urutan penulisan tidak berpengaruh di sini karena specificity sudah berbeda jauh. Ini juga mengapa menggunakan `id` untuk styling itu "mahal": begitu sebuah ID masuk selector, hanya selector lain yang juga memuat ID yang bisa mengalahkannya. Lebih aman menaruh styling pada class `.kartu-buku h3` yang spesificity-nya kecil dan bisa di-override dengan mudah (materi 10: ID untuk JS hooks).
