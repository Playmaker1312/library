# 35. Optimasi Performa — Teknik yang Paling Berdampak

Materi ini membahas cara membuat aplikasi web terasa cepat: lazy loading gambar, **debounce vs throttle** (kapan yang mana), `requestAnimationFrame` untuk animasi mulus, **virtual list** untuk ribuan item, cache API, minifikasi, serta metrik **LCP/CLS** dan audit **Lighthouse**. Fokusnya praktik: teknik kecil yang berdampak besar pada pengalaman nyata user.

## 1. Penjelasan Singkat & Konsep Dasar

Performa bukan soal angka abstrak — ia soal **seberapa cepat user bisa melakukan hal yang mereka inginkan**. Riset konsisten menunjukkan: halaman yang lambat membuat pengunjung pergi. Di era web modern, performa diukur dengan metrik yang berpusat pada *apa yang benar-benar dirasakan user*, bukan sekadar "waktu load". Lighthouse (alat audit otomatis dari Google) merangkumnya dalam skor 0-100 yang memperhitungkan **LCP** (Largest Contentful Paint: kapan konten terbesar muncul, sebaiknya di bawah 2,5 detik) dan **CLS** (Cumulative Layout Shift: seberapa banyak tata letak "melompat-lompat", sebaiknya di bawah 0,1). Dua inilah yang paling sering dievaluasi bersama kecepatan.

Salah satu penyebab website langganan lambat adalah **lazy loading gambar**. Katalog yang menampilkan 100 sampul buku yang semuanya dimuat saat halaman pertama dibuka jelas boros: user belum tentu menggulir sampai bawah, tapi bandwidth sudah habis duluan. Solusinya memuat gambar hanya saat mendekati viewport. Paling mudah dengan atribut `loading="lazy"` native; untuk kontrol lebih (misal placeholder custom, atau animasi fade-in saat muncul), gunakan **IntersectionObserver** — API yang memberi tahu kapan elem masuk area pandang tanpa perlu memutar-mutar logika scroll.

Dua teknik lain yang kerap tertukar: **debounce** dan **throttle**. Keduanya membatasi seberapa sering fungsi dijalankan, tetapi dengan semantik berbeda. *Debounce* menunda eksekusi sampai user **berhenti** memicu — pas untuk pencarian real-time (tunggu user berhenti mengetik). *Throttle* memastikan fungsi dijalankan **paling banyak** sekali tiap interval — pas untuk scroll/resize yang terus menerus. Menukar posisi keduanya menghasilkan bug: pencarian yang lemot, atau efek scroll yang tersendat. Untuk animasi (bukan sekadar event), **requestAnimationFrame (rAF)** adalah senjata yang benar: browser memanggil callback tepat sekali per frame layar (biasanya 60 fps), sinkron dengan repaint sehingga tidak terjadi pekerjaan yang membuang-buang frame.

Ketika daftar menjadi sangat panjang (misal 10.000 buku di katalog digital), bahkan render yang "benar" pun lambat karena DOM telanjur ditumbuhi ribuan elemen. **Virtual list** hanya me-render item yang terlihat (plus buffer kecil), memakai sebuah spacer untuk mengatur tinggi scrollbar. Dengan begitu, 10.000 item hanya melahirkan ~20 elemen DOM yang diperbarui saat scroll. Cache API (misal ke localStorage atau memori) melengkapi: respons yang sudah pernah diambil tidak di-fetch ulang, memangkas jaringan dan rendering. Terakhir, di produksi, **minifikasi** (menghapus spasi & memperpendek nama variabel) dan **bundle kecil** (hanya kode yang dipakai yang disertakan) membuat JavaScript yang dikirim ke browser jauh lebih ringan — pekerjaan yang otomatis ditangani Vite di materi 37.

**Benang merah**: arsitektur materi 34 membuat optimasi ini tertata — lazy loading lahir di `ui.js`, debounce di `events.js`, cache di `api.js`. Performa bukan kontras dengan arsitektur dan aksesibilitas; ketiganya diperiksa bersama oleh Lighthouse (skor Performance dan Accessibility) di checkpoint Level 7, lalu dikunci lewat build Vite (37) dan deploy (38). Tujuan akhirnya satu: aplikasi yang *terasa* instan untuk semua orang.

## 2. Fungsi & Kegunaan Utama dalam Web

**Perpustakaan Digital Kota** punya katalog yang ringkasan API-nya bisa ratusan buku dengan sampul masing-masing. Tanpa lazy loading, halaman katalog pertama kali dibuka memuat ratusan gambar sekaligus — di jaringan lambat, LCP anjlok dan user mengira situsnya rusak. Dengan `loading="lazy"` + IntersectionObserver, hanya sampul yang mendekati layar yang diunduh; sisanya dimuat saat digulir. Hasilnya lebih cepat mulai-mulai dan hemat kuota bagi pemakai seluler.

Pencarian katalog mengetik tiap huruf memicu fetch ke API (Level 6). Tanpa debounce, setiap keystroke = satu request = tekanan server + respons yang berantakan (hasil lama bisa menimpa hasil baru). Debounce 300 ms memastikan satu request per kalimat yang "jeda" — jauh lebih sopan ke server dan ke user. Di sisi lain, efek scroll seperti navbar yang mengubah bayangan atau tombol "kembali ke atas" memakai throttle supaya tetap responsif tanpa menjalankan logika di setiap 1 piksel gerakan.

Semua ini bermuara pada user: halaman yang terbuka cepat dan tetap stabil (tanpa konten melompat saat gambar telat) meningkatkan kepercayaan dan menurunkan bounce. Skor Lighthouse memudahkan tim mengukur kemajuan secara objektif — target dari checkpoint Level 7 adalah Performance > 90. Secara tidak langsung, performa juga merawat core web vitals yang memengaruhi peringkat pencarian Google di seluler: situs lambat = posisi turun, situs cepat = traffic naik.

// src/modules/ui.js — lazy loading via IntersectionObserver
// Memuat gambar asli saat elemen mulai mendekati viewport (200px sebelum masuk).

const lazyObserver = new IntersectionObserver(
    (entries, observer) => {
        for (const entry of entries) {
            if (!entry.isIntersecting) continue;

            const img = entry.target;
            const src = img.dataset.src;
            if (src) {
                img.src = src;                       // ganti placeholder → asli
                if (img.dataset.srcset) {
                    img.srcset = img.dataset.srcset; // dukungan layar retina
                }
                img.removeAttribute("data-src");
                img.removeAttribute("data-srcset");
            }
            observer.unobserve(img);                 // lepas pengamatan, ramai lagi
        }
    },
    { rootMargin: "200px" }, // mulailah muat 200px sebelum kelihatan
);

export function amatiGambarLazy(container) {
    container.querySelectorAll("img[data-src]")
        .forEach((img) => lazyObserver.observe(img));
}

// Fallback tanpa IntersectionObserver (peramban sangat lama):
if (!("IntersectionObserver" in window)) {
    document.querySelectorAll("img[data-src]").forEach((img) => {
        if (img.dataset.src) img.src = img.dataset.src;
    });
}

// src/modules/api.js — cache API sederhana di localStorage
// Request yang sudah pernah diambil tidak di-fetch ulang (hemat jaringan).

import { Storage } from "./storage.js";

const TTL = 1000 * 60 * 10; // cache berlaku 10 menit

export async function fetchBukuQuery(query) {
    const key = `query:${query}`;
    const cached = Storage.ambil(key, null);

    if (cached && Date.now() - cached.ts < TTL) {
        return cached.data;                 // langsung pakai, tanpa jaringan
    }

    const response = await fetch(
        `https://openlibrary.org/search.json?q=${encodeURIComponent(query)}&limit=20`,
    );
    if (!response.ok) throw new Error(`API error: ${response.status}`);
    const data = await response.json();

    Storage.simpan(key, { ts: Date.now(), data }); // simpan untuk kunjungan berikutnya
    return data;
}

```javascript
// ═══ DEBOUNCE vs THROTTLE — jangan tertukar ═══════════════════════════════

function debounce(fn, delay = 300) {
    // Eksekusi hanya setelah pemanggil BERHENTI selama `delay` ms.
    // Pangilan paling cocok: pencarian real-time, resize (akhirnya saja).
    let timer;
    return function (...args) {
        clearTimeout(timer);
        timer = setTimeout(() => fn.apply(this, args), delay);
    };
}

function throttle(fn, limit = 150) {
    // Eksekusi PALING BANYAK satu kali tiap `limit` ms (versi timestamp).
    // Pangilan paling cocok: scroll, mousemove — peristiwa yang berulang terus.
    let last = 0;
    return function (...args) {
        const now = Date.now();
        if (now - last >= limit) {
            last = now;
            fn.apply(this, args);
        }
    };
}

// Pencarian: user berhenti mengetik 300ms baru fetch → debounce.
const cari = debounce(async (keyword) => {
    appState.set({ loading: true });
    const data = await fetchBukuQuery(keyword);
    appState.set({ buku: data.docs, loading: false });
}, 300);

inputCari.addEventListener("input", (e) => cari(e.target.value.trim()));

// Pedoman: atur status scroll PLING sering tiap 100ms → throttle.
window.addEventListener("scroll", throttle(() => {
    navbar.classList.toggle("navbar--scrolled", window.scrollY > 10);
}, 100), { passive: true });
```

```javascript
// ═══ Virtual list: 10.000 item tanpa meledakkan DOM ═══════════════════════

class VirtualList {
    constructor(container, items, itemHeight, renderItem) {
        this.container = container;
        this.items = items;
        this.itemHeight = itemHeight;
        this.renderItem = renderItem;

        // Spacer menempati total tinggi semua item sehingga scrollbar BENAR
        // walaupun yang di-render hanya segelintir elemen.
        this.spacer = document.createElement("div");
        this.spacer.style.height = `${items.length * itemHeight}px`;
        this.content = document.createElement("div"); // wadah item yang virtual
        this.container.appendChild(this.content);
        this.container.appendChild(this.spacer);

        this.scrollHandler = throttle(() => this.render(), 16);
        this.container.addEventListener("scroll", this.scrollHandler);
        this.render();
    }

    render() {
        const { scrollTop, clientHeight } = this.container;
        const buffer = 5; // item ekstra di atas/bawah sebagai jaring pengaman

        const from = Math.max(0, Math.floor(scrollTop / this.itemHeight) - buffer);
        const to = Math.min(
            this.items.length,
            Math.ceil((scrollTop + clientHeight) / this.itemHeight) + buffer,
        );

        // Tandai posisi absolut item pertama lewat transform.
        this.content.style.transform = `translateY(${from * this.itemHeight}px)`;

        const fragment = document.createDocumentFragment();
        for (let i = from; i < to; i++) {
            fragment.appendChild(this.renderItem(this.items[i], i));
        }
        this.content.replaceChildren(fragment);
    }
}

// Pemakaian:
const list = new VirtualList(
    document.querySelector("#daftar-buku"),
    dataBuku,                        // mis. 10.000 buku
    340,                             // tinggi tiap kartu (sampul + teks)
    (buku) => buatKartu(buku),
);
```

```javascript
// ═══ requestAnimationFrame: animasi yang selaras dengan repaint ═══════════

// rAF dipanggil OLEH BROWSER ~1x per frame (60fps), sebelum repaint.
// Ini menjamin animasi mulus: tidak ada conflict dengan layar, tidak ada
// satu frame yang dilewati seperti kalau pakai setInterval(16ms).

function animasiScrollHalus(targetY, durasi = 500) {
    const mulaiY = window.scrollY;
    const jarak = targetY - mulaiY;
    let mulaiWaktu;

    function step(waktu) {
        if (mulaiWaktu === undefined) mulaiWaktu = waktu;
        const progress = Math.min((waktu - mulaiWaktu) / durasi, 1);
        // Easing ease-in-out: pelan → cepat → pelan (terasa alami).
        const ease = progress < 0.5
            ? 2 * progress ** 2
            : 1 - (-2 * progress + 2) ** 2 / 2;

        window.scrollTo(0, mulaiY + jarak * ease);

        if (progress < 1) window.requestAnimationFrame(step);
    }
    window.requestAnimationFrame(step);
}

// Tombol "kembali ke atas":
tombolAtas.addEventListener("click", () => animasiScrollHalus(0));

// Aturan cepat: animasi → rAF; scroll/resize listener → throttle;
// input/ukuran kontinu → debounce. Ketiganya saling melengkapi.
```

## 4. Analogi Sederhana — Membangun Rumah

**HTML** adalah kerangka dan tata ruang, **CSS** adalah cat dan dekorasi, **JS** adalah instalasi listrik. Material 35 berbicara soal **menyalakan lampu ruangan hanya saat ruangan itu dipakai**. Rumah perpustakaan punya 100 kamar baca yang masing-masing berisi lampu; menyalakan semuanya serentak saat tamu masuk adalah pemborosan (lazy loading). Lampu menyala saat kamar mulai didekati — itulah pekerjaan observer di pintu tiap kamar: begitu seseorang mendekat, lampu baru dinyalakan (gambar baru diunduh), lalu penjaga kamar itu pensiun dari tugasnya (`unobserve`).

**Debounce vs throttle** seperti **sensor gerak pintu** yang berbeda. *Debounce* adalah sensor yang menunggu tamu *berhenti* melintas baru menyalakan lampu koridor — kalau kamar dibuka-tutup berulang, lampu tidak menyalakan-mematikan secara gagap; ia menunggu jeda. *Throttle* adalah sistem AC koridor yang *selalu menyala tapi hanya diperbarui berkala* — terlepas seberapa sering sensor mengirim data (tiap piksel scroll), AC cukup menyesuaikan tiap 100ms. Tertukar keduanya membuat ruangan jadi gelap-gelap tanpa henti (debounce di scroll) atau pencahayaan yang telat merespons karena menunggu seseorang benar-benar berhenti (throttle di pencarian).

**requestAnimationFrame** adalah **gerbang waktu yang disinkronkan dengan jam kota**. Animasi satu frame disetel agar dimulai tepat saat jarum jam (refresh rate layar) bolak; tidak ada frame yang terlewat seperti jika kita memaksa menyetelnya sendiri dengan timer naif yang tidak peduli kapan layar benar-benar menggambar. **Virtual list** ibarat **rumah pameran yang memperlihatkan hanya ruangan yang sedang dilihat pengunjung**; sisa 9.900 ruangan ada di brosur (spacer tinggi) yang membuat peta rumah benar-benar besar, tetapi pengunjung tidak perlu menjejalkan semua barang rumah ke ruang pamer sekaligus. **Cache** adalah **kotak penyimpanan barang yang sudah dikenal**: resep buku yang sudah pernah dicari tidak perlu dibaca ulang dari pusat kota — cukup dibuka dari lemari rumah.

## 5. Kapan Harus Digunakan & Kasus Penggunaan (Use Cases)

- **Katalog gambar sampul buku** — ratusan `<img>` di grid: pasang `loading="lazy"` untuk semuanya, plus IntersectionObserver jika ingin efek fade-in saat tampil. Pastikan `width`/`height` ter-set untuk menekan CLS.
- **Pencarian di perpustakaan digital** — kotak pencarian yang memfilter data atau memanggil API di setiap keystroke: bungkus handler dengan **debounce ~300ms** agar hanya ada satu request per jeda ketik.
- **Efek navbar / tombol muncul saat scroll** — `window.addEventListener("scroll", ...)`: pakai **throttle ~100ms** (+ `{ passive: true }`) supaya tidak menjalankan logika di setiap piksel.
- **Daftar berisi ribuan item** (10.000 buku hasil search, daftar peminjaman, log aktivitas) — virtual list menggantikan render penuh; item yang tak terlihat tak pernah menyentuh DOM.
- **Animasi (scroll halus, dropdown animasi, badge count)** — selalu pakai `requestAnimationFrame`; jangan `setInterval` dengan angka milidetik yang bisa membuang atau menumpuk frame.
- **Data yang mahal untuk diambil ulang** — hasil pencarian populer, detail buku, konfigurasi: cache dengan TTL di `storage.js` untuk menghindari fetch berulang (materi 34 punya `storage.js` yang siap pakai).

## 6. Poin-poin Penting & Best Practices

- **Lazy loading**: pakai atribut native `loading="lazy"` sebagai default; IntersectionObserver untuk kontrol penuh. Selalu reserve ruang gambar (`width`/`height` atau CSS `aspect-ratio`) — ini bagian terpenting dalam menekan **CLS** (layout shift).
- **Debounce** untuk peristiwa yang berhenti sebentar (pencarian, resize), **throttle** untuk peristiwa kontinu (scroll, mousemove). Latih membedakannya: kalau tujuannya "menunggu berhenti" → debounce; kalau "batasi frekuensi" → throttle.
- **rAF**: satu-satunya cara menulis animasi yang mulus — sinkron dengan repaint, berhenti otomatis saat tab tidak fokus (hemat battery). Jangan paksa `setTimeout(fn, 16)`; browser bisa melewatkan frame.
- **Virtual list**: hanya render `from..to` yang terlihat (plus buffer), active spacer untuk tinggi scrollbar. Optimasi batch DOM dengan `DocumentFragment`/`replaceChildren`.
- **Cache API**: bungkus di modul `api.js` (SENTRAL), beri TTL, tangani kegagalan parsing; jangan cache di dalam handler UI.
- **Bundle kecil & minifikasi**: di produksi Vite otomatis minify & tree-shake (materi 37); di kode sehari-hari hindari import seluruh library kalau hanya perlu satu fungsi.
- **Lighthouse**: jalankan di setiap milestone (Performance target > 90, CLS mendekati 0). Ukur sebelum memutuskan optimasi — jangan berasumsi; optimasi harus berbasis data.
- **Ukur dulu, optimasi kemudian**: profil dengan DevTools (tab Performance, Network) sebelum menebak bentuk bottleneck. Optimasi yang tidak diukur hanya judgement, bukan engineering.

## 7. Kesalahan Umum (Common Pitfalls & Bugs)

- **Lazy loading tanpa reserve ruang → CLS memburuk** — semua `<img loading="lazy">` tanpa `width`/`height`: placeholder kosong lalu melompat ke ukuran penuh begitu gambar tiba, konten di bawah bergeser dan LCP/CLS rusak. Perbaikan: selalu sertakan `width`/`height` atau `aspect-ratio` pada CSS gambar.
- **Debounce & throttle tertukar** — pencarian dibungkus race-to-first (tiap ketik langsung eksekusi) atau efek scroll ditunda "sampai berhenti" sehingga terasa lag. Perbaikan: ingat semantiknya: debounce = menunggu jeda; throttle = membatasi laju; atau uji dengan console.log waktu eksekusi.
- **Race condition pencarian / ungulates async** — dua fetch berjalan bersamaan dan hasil yang lebih lambat menimpa hasil pencarian terbaru (user mengetik "ha" lalu "harry"; jawaban "ha" tiba belakangan). Perbaikan: debounce (mengurangi), plus tutup request lama: simpan nomor urut request atau gunakan `AbortController` di `api.js`; hanya `set` hasil yang sesuai request terakhir.
- **Mengisi DOM langsung saat scroll tanpa virtualisasi** — daftar 10.000 item semua dirender (atau di-append terus) sehingga scroll makin berat sampai freezer. Perbaikan: virtual list yang hanya me-render rentang terlihat.
- **Cache tanpa TTL atau cache di UI layer** — hasil lama tersaji selamanya, atau logika cache menempel di handler sehingga sulit dibersihkan. Perbaikan: cache + timestamp di modul `api.js` pusat dengan masa berlaku.

```javascript
// src/main.js — gabungan lazy load + debounce + throttle + guard stale
import { Storage } from "./modules/storage.js";

// ─── 1. Lazy loading dengan fade-in ─────────────────────────────────────
const observer = new IntersectionObserver(
    (entries, obs) => {
        for (const entry of entries) {
            if (!entry.isIntersecting) continue;
            const img = entry.target;
            if (img.dataset.src) {
                img.addEventListener("load", () => img.classList.add("dimuat"));
                img.src = img.dataset.src;
                img.removeAttribute("data-src");
            }
            obs.unobserve(img);
        }
    },
    { rootMargin: "200px" },
);
const amati = (root) =>
    root.querySelectorAll("img[data-src]").forEach((img) => observer.observe(img));

// ─── 2. Debounce + guard hasil kedaluwarsa ───────────────────────────────-
const API = "https://openlibrary.org/search.json";

const cacheKey = (q) => `query:${q.toLowerCase()}`;

let nomorRequest = 0; // penomoran agar jawaban basi bisa diabaikan

const cariTerdefer = debounce(async (keyword) => {
    const kunci = cacheKey(keyword);
    const tersimpan = Storage.ambil(kunci, null);
    const data = tersimpan
        ? tersimpan
        : await fetch(`${API}?q=${encodeURIComponent(keyword)}&limit=20`)
            .then((r) => {
                if (!r.ok) throw new Error(`API ${r.status}`);
                return r.json();
            })
            .then((d) => {
                Storage.simpan(kunci, d);
                return d;
            });

    const saya = ++nomorRequest;         // tandai request saat ini
    if (saya !== nomorRequest) return;   // sudah ada yang lebih baru → abaikan
    renderKatalog(data.docs);
}, 300);

// ─── 3. Throttle untuk efek scroll navbar ───────────────────────────────
window.addEventListener("scroll", throttle(() => {
    const navbar = document.querySelector(".navbar");
    navbar.classList.toggle("navbar--scrolled", window.scrollY > 10);
}, 100), { passive: true });

// gabung di inisialisasi
document.addEventListener("DOMContentLoaded", () => {
    amati(document.querySelector("#katalog-grid"));
    document.querySelector("#input-cari")
        .addEventListener("input", (e) => cariTerdefer(e.target.value.trim()));
});

// (definisi debounce & throttle seperti di materi, taruh di src/modules/utils.js)
function debounce(fn, delay = 300) {
    let timer;
    return function (...args) {
        clearTimeout(timer);
        timer = setTimeout(() => fn.apply(this, args), delay);
    };
}

function throttle(fn, limit = 150) {
    let last = 0;
    return function (...args) {
        const now = Date.now();
        if (now - last >= limit) {
            last = now;
            fn.apply(this, args);
        }
    };
}
```

**Pembahasan**: Tantangan 1 selesai ketika setiap gambar memakai `aspect-ratio` yang sama dengan ukuran atribut — ini yang menjamin tidak ada CLS; tanpa itu, placeholder kosong akan "melompat" saat gambar tiba. IntersectionObserver memuat gambar asli sesaat sebelum masuk viewport (rootMargin 200px) sehingga user tidak pernah melihat kartu kosong, dan class `dimuat` memberi fade-in yang halus — semua efek ini dikemas di satu observer yang di-`unobserve` setelah selesai agar ringan. Untuk tantangan 2, debounce 300ms mencegah satu request per keystroke; nomor request (`nomorRequest`) adalah penjaga *stale response* — request yang lebih lama menulis hasil dengan nomor yang bukan terbaru dan langsung dibuang; alternatif yang lebih rapi adalah `AbortController` yang benar-benar membatalkan fetch lama. Cache di `storage.js` membuat pencarian berulang tidak menyentuh jaringan (hemat 10x). Throttle 100ms + `{ passive: true }` adalah celah yang tepat untuk efek scroll navbar: responsif tapi tidak menguras CPU. Semua teknik ini ringkas dan terpusat di modul yang sudah dibangun di materi 34, sehingga skor Lighthouse (Perf > 90) bisa dicapai dengan perubahan kecil.
