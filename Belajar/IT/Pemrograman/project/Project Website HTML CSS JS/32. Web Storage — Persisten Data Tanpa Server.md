# 32. Web Storage — Persisten Data Tanpa Server

Materi ini mengajarkan cara menyimpan data **di dalam browser** (bukan di server) dengan **`localStorage`** dan **`sessionStorage`**: membaca/menulis dengan `JSON.stringify`/`JSON.parse`, membungkusnya dalam utility yang aman, menyimpan preferensi dan buku favorit, hingga membangun cache API ber-TTL untuk mengurangi request. Ini membuat aplikasi "mengingat" user di kunjungan berikutnya.

## 1. Penjelasan Singkat & Konsep Dasar

Setelah materi 31, aplikasi kamu bisa mengambil data dari server. Tapi masih ada gap: setiap kali user membuka halaman, semuanya di-fetch ulang — tema yang sudah dipilih kembali terang, buku favoritnya hilang, dan hasil pencarian yang tadi diambil harus diambil lagi. Padahal sebagian data milik user ini tidak butuh server sama sekali. Di sinilah **Web Storage** bekerja: ruang penyimpanan yang dimiliki browser, diisolasi per domain, yang bisa dibaca dan ditulis JavaScript secara sinkron.

Ada dua jenis yang perlu dibedakan tegas. **`localStorage`** bertahan tanpa batas waktu — data tetap ada bahkan setelah browser ditutup dan komputer mati, sampai dihapus eksplisit oleh kode atau user membersihkan cache browser. **`sessionStorage`** hanya hidup selama *session*: data hilang begitu tab ditutup. Pilihan di antara keduanya ditentukan oleh pertanyaan sederhana: "apakah data ini perlu ada lagi di kunjungan berikutnya?" Kalau ya → `localStorage`; kalau hanya untuk tab ini sebentar → `sessionStorage`.

Kedua storage hanya bisa menyimpan **string**. Untuk menyimpan object atau array — dan hampir semua data aplikasi berbentuk object/array — kamu harus meng-encode dengan **`JSON.stringify`** saat menulis, dan menguraikan dengan **`JSON.parse`** saat membaca. Lupa langkah ini menghasilkan string yang tidak berguna seperti `"[object Object]"`. Mengecewakan, dan sering jadi bug yang membingungkan pemula.

Operasi dasarnya sederhana: `setItem(key, value)`, `getItem(key)`, `removeItem(key)`, dan `clear()`. Namun aplikasi nyata jarang menyentuh `localStorage` langsung — kamu membungkusnya dalam **utility/wrapper** bernama `Storage` yang menangani tiga hal sekaligus: meng-encode object (stringify/parse), memberi nilai default bila key belum ada, dan **menangkap error dengan `try/catch`**. Error penting karena `localStorage` punya **quota** (sekitar 5 MB per origin) — saat penuh, `setItem` melempar `QuotaExceededError`. Juga, di *private mode* atau saat storage diblokir, akses bisa gagal. Wrapper yang aman membuat aplikasi tetap hidup walau penyimpanan bermasalah.

Dua kegunaan praktis yang paling bertahan lama: **preferensi user** (tema terang/gelap, tampilan grid/daftar, kategori favorit) yang di-restore saat reload, dan **cache hasil fetch ber-TTL**. Dengan pattern **Cache class**, hasil pencarian disimpan dengan tanda waktu kedaluwarsa (mis. 5 menit); saat query yang sama diminta ulang, data dibaca dari storage alih-alih mengulang request ke server. Ini memangkas jumlah request, mempercepat halaman, dan nyaman saat sinyal buruk.

**Benang merah**: Level 5 punya data di array memori; materi 31 membuat aliran data dari server lewat `fetch`. Materi 32 menutup lingkaran dengan membuat sebagian data **bertahan** antar kunjungan: preferensi, favorit, dan cache. Level 7 lalu merapikan semua ini ke modul `storage.js` yang satu dengan yang lain.

## 2. Fungsi & Kegunaan Utama dalam Web

Di **Perpustakaan Digital Kota**, Web Storage menghidupkan tiga fitur yang membuat pengalaman personal dan hemat. Pertama, **preferensi user**: user memilih tema gelap dan tampilan daftar — pilihan disimpan ke `localStorage`; saat halaman dimuat, sebelum re-render, aplikasi membaca preferensi dan langsung menerapkannya. User tidak perlu mengatur ulang setiap kunjungan; itulah definisi persisten yang terasa.

Kedua, **buku favorit**: tombol "♥ Favorit" pada setiap kartu menambah id buku ke array di storage. Di halaman "Favorit Saya", daftar di-render dari penyimpanan itu — tanpa server, tanpa login, tanpa reload. Ini memodelkan "bookmark" yang umum di toko buku online.

Ketiga, **cache pencarian**: hasil `cariBukuOpenLibrary("pemrograman")` disimpan dengan TTL 5 menit. User yang mengganti posisi filter dan kembali ke query yang sama tidak perlu menunggu request ulang — data tampil instan dari cache. Ini memangkas beban jaringan dan membuat aplikasi terasa responsif, terutama di koneksi lambat.

**Keamanan & batasan penting**: Web Storage itu terenkripsi? Tidak. Datanya bisa dibaca siapa pun yang membuka DevTools browser kamu. Maka aturan emasnya: **jangan pernah simpan data sensitif** — password, token autentikasi, nomor KTP, data kartu kredit. Sandi dan token ada di dalam memory dan cookie yang diatur aman oleh server; localStorage hanya untuk data non-sensitif seperti preferensi dan id buku.

## 3. Contoh Kode & Implementasi Real-World

Mulai dari wrapper `Storage` yang aman, lalu `Cache` ber-TTL, lalu integrasi penuh: preferensi tema, buku favorit, dan cache pencarian Open Library.

```javascript
// js/storage.js

// ─── Wrapper storage: stringify/parse otomatis + try/catch (quota, private mode) ──
export const Storage = {
    // localStorage vs sessionStorage bisa dipilih lewat parameter storage.
    simpan(key, nilai, penyimpanan = localStorage) {
        try {
            penyimpanan.setItem(key, JSON.stringify(nilai)); // object → string
        } catch (error) {
            // QuotaExceededError / storage diblokir: jangan sampai mematikan aplikasi
            console.warn("Gagal menyimpan data:", error);
        }
    },

    // Nilai default bila key hilang / JSON korup → aplikasi tetap berjalan
    ambil(key, defaultValue = null, penyimpanan = localStorage) {
        try {
            const item = penyimpanan.getItem(key);
            return item ? JSON.parse(item) : defaultValue; // string → object
        } catch (error) {
            console.warn("Gagal membaca data:", error);
            return defaultValue;
        }
    },

    hapus(key, penyimpanan = localStorage) { penyimpanan.removeItem(key); },
    bersihkan(penyimpanan = localStorage) { penyimpanan.clear(); },
    ada(key, penyimpanan = localStorage)   { return penyimpanan.getItem(key) !== null; },
};

// ─── Cache class: simpan hasil fetch dengan TTL (time-to-live) ─────────────
export class Cache {
    constructor(prefix = "cache", penyimpanan = localStorage) {
        this.prefix = prefix;
        this.storage = penyimpanan;
    }

    simpan(key, data, ttlDetik = 300) {
        Storage.simpan(`${this.prefix}_${key}`, {
            data,
            expired: Date.now() + ttlDetik * 1000, // tanggal kedaluwarsa
        }, this.storage);
    }

    // Return null kalau tidak ada atau sudah basi — pemanggil lalu fetch ulang.
    ambil(key) {
        const entry = Storage.ambil(`${this.prefix}_${key}`, null, this.storage);
        if (!entry) return null;
        if (Date.now() > entry.expired) {
            Storage.hapus(`${this.prefix}_${key}`, this.storage); // buang yang basi
            return null;
        }
        return entry.data;
    }
}

const cacheKatalog = new Cache("katalog");
```

```javascript
// js/main.js

import { Storage, Cache } from "./js/storage.js";
import { cariBukuOpenLibrary } from "./js/api.js"; // dari materi 31

const cacheKatalog = new Cache("katalog");

// ─── 1. Preferensi tema (terang/gelap) + tampilan (grid/daftar) ────────────
const KUNCI_PREFERENSI = "preferensi";

function ambilPreferensi() {
    // Default dipakai kalau user belum pernah menyimpan apa pun.
    return Storage.ambil(KUNCI_PREFERENSI, {
        tema: "terang",
        tampilan: "grid",
    });
}

function simpanPreferensi(delta) {
    const baru = { ...ambilPreferensi(), ...delta }; // gabung preferensi lama + baru
    Storage.simpan(KUNCI_PREFERENSI, baru);
    terapkanPreferensi(baru); // terapkan segera (tanpa menunggu reload)
}

// Panggil saat halaman dimuat — mendahului render katalog
function terapkanPreferensi(pref = ambilPreferensi()) {
    document.body.dataset.tema = pref.tema;      // CSS membaca data-tema
    document.body.dataset.tampilan = pref.tampilan;
}

// Tie moment ketika user menekan tombol tema
document.querySelector("#btn-ganti-tema").addEventListener("click", () => {
    const sekarang = ambilPreferensi().tema;
    simpanPreferensi({ tema: sekarang === "terang" ? "gelap" : "terang" });
});

// ─── 2. Buku favorit: array id di localStorage ──────────────────────────────
const KUNCI_FAVORIT = "buku_favorit";

function toggleFavorit(idBuku) {
    const favorit = Storage.ambil(KUNCI_FAVORIT, []);
    const ada = favorit.includes(idBuku);

    Storage.simpan(KUNCI_FAVORIT, ada ? favorit.filter((id) => id !== idBuku)
                                       : [...favorit, idBuku]);
    renderFavorit(); // perbarui tombol ♥ di semua kartu
}

// Halaman "Favorit Saya": render murni dari storage, tanpa request ke server.
function renderFavorit() {
    const ids = Storage.ambil(KUNCI_FAVORIT, []);
    document.querySelector("#favorit-grid").textContent = "";
    ids.forEach((id) => buatKartuFavorit(id)); // kartu disusun dari detail yang di-cache
}

// ─── 3. Cache pencarian: hit cache dulu, fetch hanya bila basi ──────────────
async function ambilHasilPencarian(query) {
    const key = `cari_${query}`;

    // 1) Coba dari cache — langsung selesai bila masih fresh (dalam 5 menit).
    const cached = cacheKatalog.ambil(key);
    if (cached) return cached;

    // 2) Cache kosong/basi → fetch ke Open Library, lalu simpan untuk reuse.
    const data = await cariBukuOpenLibrary(query);
    cacheKatalog.simpan(key, data, 300); // TTL 5 menit
    return data;
}
```

## 4. Analogi Sederhana — Membangun Rumah

Di rumah analogi kita, **HTML** adalah kerangka, **CSS** adalah cat, dan **JavaScript** adalah instalasi listrik. **`localStorage`** adalah **lemari arsip rumah** yang tetap ada walau lampu mati (mati = browser/browser komputer mati). Catatan tema yang kamu pilih, daftar buku favorit, semuanya tersimpan di lemari itu dan ditemukan utuh keesokan paginya — karena lemari arsip tidak bergantung pada listrik. Selama kamu tidak sengaja membuangnya (atau mengosongkan lemari lewat pengaturan browser), datanya tinggal di sana untuk waktu yang lama.

**`sessionStorage`** adalah kebalikannya: **kertas tempel di pintu** yang hanya berlaku selama rumah ini berdiri di sesi ini. Kamu menulis catatan "buku sedang dibaca: Bab 4", bersandar nyaman, tapi begitu pintu ditutup (tab ditutup), kertas tempel ikut luruh — sengaja, karena memang tidak semua info perlu selamanya. Data satu-satunya yang muat pun hanya string; untuk menaruh *daftar* di lemari arsip, kamu menuliskannya dalam satu helai dokumen rapi (`JSON.stringify`) dan membacanya kembali (`JSON.parse`) — persis cara meletakkan isi rak empat buku sebagai satu daftar dalam satu amplop.

**`JSON.stringify`/`parse`** adalah **mengemas** arsip: object yang kompleks (koleksi buku, preferensi) ditekan menjadi satu baris teks agar pas di slot lemari, lalu dibongkar kembali saat dibutuhkan. Tanpa pengemasan, yang tersimpan hanyalah tulisan `[object Object]` — seperti menaruh amplop tapi lupa menulis isinya.

Cache ber-TTL adalah **lemari inventory dengan tanggal stempel**: kamu menempel etiket "segar sampai jam 15:00" pada paket hasil pencarian. Saat dibutuhkan lagi, cek dulu etiketnya — kalau masih segar, pakai yang di lemari (tanpa menghubungi kurir lagi); kalau sudah lewat, baru kirim kurir baru. Inilah yang menghemat request dan membuat rumah terasa lebih henat tenaganya. Dan **jangan pernah menaruh surat berharga (password, nomor KTP) di lemari arsip ini** — siapa pun yang lewat bisa membuka pintu lemari lewat DevTools.

## 5. Kapan Harus Digunakan & Kasus Penggunaan (Use Cases)

- **Preferensi user tanpa akun** — tema terang/gelap, ukuran teks, tampilan grid/daftar yang di-restore otomatis di kunjungan berikutnya (`localStorage`).
- **Daftar favorit/bookmark** — id buku yang disukai tetap ada lintas sesi; bisa dirender tanpa server dan tanpa login (`localStorage`).
- **Cache hasil API (query yang sering berulang)** — hasil pencarian katalog disimpan 5 menit; query sama tidak menimbulkan request ulang (`Cache` + `localStorage`).
- **State sementara dalam satu tab** — posisi scroll, draft form yang belum dikirim, atau hasil filter sementara yang tidak perlu bertahan setelah tab ditutup (`sessionStorage`).
- **Pesanan keranjang yang belum user simpan akun** — dipertahankan selama tab masih terbuka, lalu bisa dipromosikan ke server saat checkout (kapan simpan di browser vs server: apapun yang harus aman dan disinkronkan lintas perangkat → server).

## 6. Poin-poin Penting & Best Practices

- **`localStorage` untuk persisten, `sessionStorage` untuk sementara** — pilih berdasarkan pertanyaan "apakah perlu ada lagi di kunjungan berikutnya?".
- **Selalu `JSON.stringify`/`JSON.parse`** untuk object/array; storage hanya menyimpan string.
- **Bungkus dengan wrapper (`Storage`) yang punya `try/catch`** — `localStorage` bisa gagal karena quota penuh, private mode, atau storage diblokir; aplikasi tidak boleh mati karenanya.
- **Selalu sediakan nilai default** saat membaca key yang mungkin belum ada.
- **Cache dengan TTL** — simpan `timestamp` kedaluwarsa; buang entri yang basi saat dibaca. Tanpa TTL, cache bisa menyajikan data usang selamanya.
- **Jangan pernah simpan data sensitif** ke localStorage: password, token autentikasi, data kartu kredit, atau data pribadi terkait hukum. Simpan itu di server (cookie `httpOnly` + `secure`).
- **Pikirkan size**: quota sekitar 5 MB per origin — cukup untuk preferensi dan cache kecil, tidak untuk puluhan ribu record.
- **Type Safety**: di TypeScript, bentuk data preferensi (`theme: "terang" | "gelap"`, `tampilan: "grid" | "daftar"`) bisa di-typed sehingga `JSON.parse` yang kembalinya `any` dipaksa menjadi shape yang diketahui, mempersempit bug saat membaca storage.

## 7. Kesalahan Umum (Common Pitfalls & Bugs)

- **Menyimpan object tanpa `JSON.stringify`** → `localStorage.setItem("favorit", [1,2,3])` tersimpan sebagai string `"1,2,3"` sehingga `includes` dan `filter` tetap jalan tetapi bentuknya salah; menyimpan `{a:1}` menghasilkan `"[object Object]"` yang tidak bisa di-parse. Perbaikan: selalu `JSON.stringify`.
- **`JSON.parse` gagal karena data korup** → user sebelumnya memakai versi lama aplikasi atau data rusak di tengah; `JSON.parse` melempar `SyntaxError` dan mematikan aplikasi. Perbaikan: bungkus baca dalam `try/catch` dan return default seperti pada `Storage.ambil`.
- **Quota penuh / storage diblokir** → `setItem` melempar `QuotaExceededError`, aplikasi crash di tengah interaksi. Perbaikan: penulisan juga dalam `try/catch` + `console.warn`, dan pertimbangkan membersihkan cache yang sudah kadaluwarsa lebih dulu.
- **Menyimpan data sensitif di localStorage** → token/password mudah dibaca siapa pun lewat DevTools. Perbaikan: simpan di server; localStorage hanya untuk data non-sensitif.
- **Menyajikan data stale tanpa TTL** → hasil pencarian kemarin selalu tampil padahal katalog sudah berubah. Perbaikan: selalu sertakan `expired` timestamp dan periksa saat `ambil`.

Buat di `sessionStorage`, versi variabelnya yang hanya berlaku selama tab terbuka.

### Solusi & Pembahasan

```javascript
// js/latihan.js (gabungan solusi 1 & 2)

// ─── Utility Storage (soal 1) ──────────────────────────────────────────────
const Storage = {
    simpan(key, nilai, penyimpanan = localStorage) {
        try {
            penyimpanan.setItem(key, JSON.stringify(nilai));
        } catch (error) {
            console.warn("Gagal menyimpan ke storage:", error);
        }
    },
    ambil(key, defaultValue = null, penyimpanan = localStorage) {
        try {
            const item = penyimpanan.getItem(key);
            return item ? JSON.parse(item) : defaultValue;
        } catch (error) {
            console.warn("Gagal membaca storage:", error);
            return defaultValue;
        }
    },
    hapus(key, penyimpanan = localStorage) { penyimpanan.removeItem(key); },
};

const KUNCI_TEMA = "preferensi_tema";

function terapkanTema(tema) {
    document.body.dataset.tema = tema;
    Storage.simpan(KUNCI_TEMA, tema);
}

document.querySelector("#btn-tema").addEventListener("click", () => {
    const sekarang = Storage.ambil(KUNCI_TEMA, "terang");
    terapkanTema(sekarang === "terang" ? "gelap" : "terang");
});

// Saat load: restore preferensi. Kalau belum ada → default "terang".
terapkanTema(Storage.ambil(KUNCI_TEMA, "terang"));

// Variasi sessionStorage: versi ini hilang saat tab ditutup.
Storage.ambil(KUNCI_TEMA, "terang", sessionStorage);

// ─── Cache ber-TTL (soal 2) ─────────────────────────────────────────────────
class Cache {
    constructor(prefix = "cache", penyimpanan = localStorage) {
        this.prefix = prefix;
        this.storage = penyimpanan;
    }
    simpan(key, data, ttlDetik = 300) {
        Storage.simpan(`${this.prefix}_${key}`, {
            data,
            expired: Date.now() + ttlDetik * 1000,
        }, this.storage);
    }
    ambil(key) {
        const entry = Storage.ambil(`${this.prefix}_${key}`, null, this.storage);
        if (!entry) return null;
        if (Date.now() > entry.expired) {
            Storage.hapus(`${this.prefix}_${key}`, this.storage);
            return null;
        }
        return entry.data;
    }
}

const cacheKatalog = new Cache("katalog");

async function ambilKatalog(query) {
    const key = `q=${query}`;
    const cached = cacheKatalog.ambil(key);
    if (cached) return cached;               // masih fresh → tanpa request

    const url = `https://openlibrary.org/search.json?q=${encodeURIComponent(query)}&limit=10`;
    const response = await fetch(url);
    if (!response.ok) throw new Error(`API error: ${response.status}`);

    const data = await response.json();
    cacheKatalog.simpan(key, data, 300);     // TTL 5 menit
    return data;
}

const data = await ambilKatalog("pemrograman");
console.log("Jumlah hasil:", data.docs.length);
```
