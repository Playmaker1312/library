### 12. Tipe Khusus: Null dan Undefined — strictNullChecks

Dua tipe ini sering menjadi sumber _bug_ paling menyebalkan dalam pemrograman (terkenal dengan sebutan _"The Billion Dollar Mistake"_). TypeScript hadir untuk menjinakkan keduanya melalui fitur `strictNullChecks`.

---

### Definisi Singkat

**`null`** adalah nilai yang sengaja diberikan untuk menunjukkan bahwa sebuah variabel "kosong" atau "tidak ada isinya", sedangkan **`undefined`** berarti sebuah variabel telah dideklarasikan tetapi "belum pernah diberi nilai".

---

### Analogi

Bayangkan Anda memiliki sebuah kotak sereal di dapur.

- **`undefined`**: Anda baru saja membeli kotak baru, tetapi Anda belum membukanya. Anda belum tahu apakah di dalamnya ada sereal atau hadiah (Variabel ada, tapi isinya belum ditentukan).
    
- **`null`**: Anda sudah memakan habis semua serealnya. Kotaknya ada, tapi Anda secara sadar tahu bahwa isinya **kosong** (Variabel ada, dan isinya sengaja dikosongkan).
    
- **`strictNullChecks`**: Ini seperti memiliki asisten dapur yang sangat cerewet. Jika Anda mencoba menuangkan sereal dari kotak yang kosong atau belum dibuka, asisten tersebut akan langsung menahan tangan Anda sebelum Anda menumpahkan angin ke mangkuk.
    

---

### Poin-Poin Penting

- **Tipe Mandiri:** Di TypeScript, `null` dan `undefined` adalah tipe data tersendiri.
    
- **strictNullChecks (Opsi Penting):** Jika opsi ini `true` di `tsconfig.json`, Anda tidak bisa memasukkan `null` ke variabel `string` secara sembarangan. Ini memaksa Anda menangani kemungkinan data kosong.
    
- **Union Types:** Untuk mengizinkan variabel berisi `null`, Anda harus menggunakan tanda `|` (OR), contoh: `string | null`.
    
- **Optional Chaining (`?.`):** Fitur untuk mengakses properti objek yang mungkin `null` tanpa membuat aplikasi _crash_.
    

---

### Contoh Implementasi

**Tanpa strictNullChecks (Berbahaya):**

TypeScript

```
let nama: string = "Budi";
nama = null; // Diizinkan, tapi bisa bikin error saat memanggil nama.toUpperCase()
```

**Dengan strictNullChecks: true (Aman):**

TypeScript

```
let nama: string = "Budi";
// @ts-expect-error
nama = null; // Error! Tipe 'null' tidak bisa masuk ke tipe 'string'

// Cara yang benar jika data bisa kosong:
let namaUser: string | null = "Andi";
namaUser = null; // Sekarang diizinkan

// Cara akses aman:
console.log(namaUser?.toUpperCase()); // Tidak akan crash jika namaUser adalah null
```

---

### Koneksi dalam Bidang Web Development

Dalam pengembangan **Web Development**, pemahaman ini sangat krusial untuk:

1. **Data dari API:** Seringkali data yang kita minta dari server (misal: `user.profile_picture`) bernilai `null` jika user belum mengunggah foto. TypeScript akan memaksa Anda membuat _fallback_ (gambar default) agar website tidak _blank_.
    
2. **DOM Elements:** Saat Anda menggunakan `document.getElementById('tombol')`, TypeScript akan memberitahu bahwa hasilnya bisa berupa `HTMLElement` atau `null` (jika ID tidak ditemukan). Ini mencegah error "Cannot read property 'addEventListener' of null".
    
3. **Form Input:** Saat meriset form, Anda mungkin mengatur nilai ke `undefined` atau `null`. TypeScript membantu memastikan fungsi pengiriman data Anda siap menangani kondisi "tanpa input" tersebut.
