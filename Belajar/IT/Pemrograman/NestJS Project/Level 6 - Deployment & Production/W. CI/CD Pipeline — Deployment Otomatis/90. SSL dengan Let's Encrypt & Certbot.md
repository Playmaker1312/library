# 90. SSL dengan Let's Encrypt & Certbot

## Penjelasan
**SSL/TLS certificate** adalah komponen wajib untuk aplikasi production — mengenkripsi komunikasi antara client dan server sehingga data sensitif (password, token, data pribadi) tidak bisa dibaca oleh pihak ketiga. **Let's Encrypt** adalah Certificate Authority (CA) gratis yang menyediakan SSL certificate dengan validitas 90 hari. **Certbot** adalah alat (agent) yang berjalan di server untuk mengajukan, memperbarui, dan mengelola certificate secara otomatis.

Arsitektur yang umum digunakan: Certbot berjalan sebagai container Docker yang berkomunikasi dengan Let's Encrypt server. Certbot menggunakan **HTTP-01 challenge** — Let's Encrypt memberikan token, Certbot menempatkannya di folder `/var/www/certbot/`, dan Let's Encrypt memverifikasi dengan mengakses `http://domain/.well-known/acme-challenge/<token>`. Nginx harus dikonfigurasi agar path `.well-known` bisa diakses publik. Setelah certificate didapatkan, Nginx dikonfigurasi untuk menggunakan certificate tersebut di port 443 (HTTPS) dan redirect semua traffic HTTP (port 80) ke HTTPS.

## Fungsi
- Mendapatkan SSL certificate gratis dari Let's Encrypt untuk mengamankan komunikasi HTTPS
- Mengotomatiskan perpanjangan (renewal) certificate setiap 90 hari
- Mengkonfigurasi Nginx untuk SSL termination dan redirect HTTP → HTTPS

## Cara Implementasi / Code

**docker-compose certbot service:**

```yaml
# Tambahkan di docker-compose.prod.yml
services:
  # ... nginx, app, db, redis ...

  certbot:
    image: certbot/certbot
    container_name: nestjs-certbot
    restart: unless-stopped
    volumes:
      - ./certbot/conf:/etc/letsencrypt:rw
      - ./certbot/www:/var/www/certbot:rw
    entrypoint: "/bin/sh -c 'trap exit TERM; while :; do certbot renew; sleep 12h & wait $${!}; done;'"
```

**Nginx configuration dengan SSL:**

```nginx
# /opt/nestjs-app/nginx.conf
upstream nestjs_app {
    server app:3000;
}

# Server block untuk HTTP — serve .well-known untuk Certbot + redirect
server {
    listen 80;
    server_name api.domain.com;

    # Path untuk Certbot HTTP-01 challenge
    location /.well-known/acme-challenge/ {
        root /var/www/certbot;
    }

    # Redirect semua request lain ke HTTPS
    location / {
        return 301 https://$server_name$request_uri;
    }
}

# Server block untuk HTTPS
server {
    listen 443 ssl http2;
    server_name api.domain.com;

    # SSL certificate
    ssl_certificate /etc/letsencrypt/live/api.domain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/api.domain.com/privkey.pem;

    # SSL best practices
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;
    ssl_prefer_server_ciphers on;
    ssl_session_cache shared:SSL:10m;
    ssl_session_timeout 10m;

    # HSTS (HTTP Strict Transport Security)
    add_header Strict-Transport-Security "max-age=63072000; includeSubDomains; preload" always;

    # Security headers
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-XSS-Protection "1; mode=block" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;

    # Reverse proxy ke NestJS
    location / {
        proxy_pass http://nestjs_app;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
    }
}
```

**Cara mendapatkan SSL certificate pertama kali:**

```bash
# SSH ke VPS
ssh user@vps-ip

# Masuk ke direktori project
cd /opt/nestjs-app

# Jalankan certbot untuk mendapatkan certificate (manual, sekali saja)
docker compose run --rm certbot certonly --webroot \
  --webroot-path /var/www/certbot \
  -d api.domain.com \
  --email email@domain.com \
  --agree-tos \
  --no-eff-email

# Restart Nginx agar membaca certificate baru
docker compose restart nginx
```

**Cron job untuk auto-renewal (via systemd timer atau cron):**

```bash
# Buka crontab
sudo crontab -e

# Tambahkan baris ini — jalan setiap hari jam 3 pagi
0 3 * * * cd /opt/nestjs-app && docker compose run --rm certbot renew && docker compose restart nginx
```

**Atau gunakan systemd service + timer:**

```ini
# /etc/systemd/system/certbot-renew.service
[Unit]
Description=Certbot Renewal

[Service]
Type=oneshot
WorkingDirectory=/opt/nestjs-app
ExecStart=/usr/bin/docker compose run --rm certbot renew
ExecStartPost=/usr/bin/docker compose restart nginx

# /etc/systemd/system/certbot-renew.timer
[Unit]
Description=Run certbot renewal daily

[Timer]
OnCalendar=daily
Persistent=true

[Install]
WantedBy=timers.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable certbot-renew.timer
sudo systemctl start certbot-renew.timer
```

**Script deploy lengkap dengan SSL renewal:**

```yaml
# Di GitHub Actions (file 89), tambahkan step:
- name: Ensure SSL certificate exists
  run: |
    ssh ${{ secrets.VPS_USER }}@${{ secrets.VPS_HOST }} '
      cd /opt/nestjs-app
      
      # Cek apakah certificate sudah ada
      if [ ! -d "./certbot/conf/live/api.domain.com" ]; then
        echo "Certificate belum ada. Mendapatkan certificate baru..."
        docker compose run --rm certbot certonly --webroot \
          --webroot-path /var/www/certbot \
          -d api.domain.com \
          --email email@domain.com \
          --agree-tos \
          --no-eff-email
        
        docker compose restart nginx
      else
        echo "Certificate sudah ada. Mencoba renewal..."
        docker compose run --rm certbot renew
        docker compose restart nginx
      fi
    '
```

## Analogi
Bayangkan perpustakaan ingin mengamankan **pintu masuk utama** dengan **kunci digital** (SSL certificate). Let's Encrypt adalah **tukang kunci** yang memberikan kunci gratis, dan Certbot adalah **asisten** yang secara otomatis mengganti kunci setiap 3 bulan. Pintu yang tidak terkunci (HTTP) akan mengarahkan pengunjung ke pintu yang terkunci (HTTPS 301 redirect). Perpustakaan juga memasang **papan pengumuman** (HSTS) yang memberi tahu browser bahwa perpustakaan ini SELALU menggunakan kunci — jangan pernah masuk tanpa kunci.

## Penggunaan
- **Wajib** untuk setiap aplikasi production yang menerima data pengguna (login, pembayaran, data pribadi)
- **SEO boost** — Google memberikan peringkat lebih tinggi untuk situs HTTPS
- **Browser trust** — Browser modern menampilkan peringatan "Not Secure" untuk situs HTTP
- **Compliance** — Banyak standar keamanan (PCI-DSS, HIPAA) mewajibkan HTTPS

## Kesalahan Umum yang Sering Terjadi
1. **Certbot gagal karena port 80 tidak terbuka** — Let's Encrypt harus bisa mengakses `http://domain/.well-known/acme-challenge/` melalui port 80. Pastikan firewall VPS mengizinkan port 80 dan Nginx berjalan.
2. **Certificate tidak auto-renew** — Cron job atau systemd timer tidak berjalan. Periksa dengan `sudo systemctl status certbot-renew.timer`.
3. **Folder certbot tidak di-mount dengan benar** — Nginx tidak bisa membaca certificate karena path salah. Periksa volume mount di docker-compose.
4. **Menggunakan self-signed certificate di production** — Self-signed certificate menyebabkan browser menampilkan peringatan bahaya. Hanya gunakan untuk development.
5. **HSTS preload tanpa persiapan** — Jika domain di-submit ke HSTS preload list, semua subdomain HARUS HTTPS. Jika ada subdomain yang masih HTTP, akan rusak. Aktifkan HSTS secara bertahap.

## Hubungan dengan Materi Sebelumnya

## Soal Latihan

**Soal:** Kamu memiliki dua domain: `api.domain.com` (NestJS backend) dan `app.domain.com` (React frontend) di server yang sama. Buat konfigurasi Nginx untuk kedua domain dengan SSL certificate terpisah (masing-masing punya certificate sendiri dari Let's Encrypt).

**Jawaban:**

```nginx
# api.domain.com — NestJS API
server {
    listen 443 ssl http2;
    server_name api.domain.com;

    ssl_certificate /etc/letsencrypt/live/api.domain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/api.domain.com/privkey.pem;

    location / {
        proxy_pass http://app:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

# app.domain.com — React Frontend
server {
    listen 443 ssl http2;
    server_name app.domain.com;

    ssl_certificate /etc/letsencrypt/live/app.domain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/app.domain.com/privkey.pem;

    location / {
        root /usr/share/nginx/html;
        try_files $uri $uri/ /index.html;
    }
}

# Redirect HTTP ke HTTPS untuk kedua domain
server {
    listen 80;
    server_name api.domain.com app.domain.com;

    location /.well-known/acme-challenge/ {
        root /var/www/certbot;
    }

    location / {
        return 301 https://$host$request_uri;
    }
}
```

Untuk mendapatkan certificate kedua domain sekaligus:
```bash
docker compose run --rm certbot certonly --webroot \
  --webroot-path /var/www/certbot \
  -d api.domain.com -d app.domain.com \
  --email email@domain.com \
  --agree-tos
```
