# Update main.ts — Gunakan ConfigService untuk Semua Config

## Penjelasan

File `main.ts` adalah entry point aplikasi NestJS. Di sinilah kita membuat instance aplikasi dengan `NestFactory.create()`, mengatur global prefix, mengaktifkan CORS, memasang global pipes, dan menentukan port listening. Sebelum menggunakan ConfigModule, kita biasanya melakukan hardcode nilai-nilai ini atau membaca `process.env` secara langsung. Pendekatan ini kurang fleksibel karena jika port berubah, kita harus mengubah kode, bukan sekadar mengubah file `.env`.

Dengan menggunakan `ConfigService` di `main.ts`, kita bisa mengambil semua konfigurasi dari environment variable yang sudah tervalidasi dan terstruktur. Namun ada satu tantangan: `ConfigService` tersedia melalui dependency injection, sedangkan `main.ts` bukan class yang terdaftar di DI container. Solusinya adalah mengambil instance `ConfigService` dari aplikasi yang sudah dibuat menggunakan `app.get(ConfigService)`. NestJS memungkinkan kita mengakses provider yang sudah terdaftar setelah aplikasi dibuat, sebelum `app.listen()` dipanggil.

Dengan pendekatan ini, semua konfigurasi aplikasi — port, global prefix, CORS origins, rate limiting, dan lainnya — diatur dari satu tempat (file `.env` dan namespace configuration). Ini memudahkan deployment karena kita bisa mengubah perilaku aplikasi tanpa mengubah kode. Cukup set environment variable yang berbeda di server production, staging, dan development.

## Fungsi

Mengupdate main.ts untuk membaca port, global prefix, dan konfigurasi lainnya dari ConfigService, sehingga aplikasi dapat dikonfigurasi sepenuhnya melalui environment variable tanpa mengubah kode.

## Cara Implementasi / Code

```typescript
// src/main.ts
import { NestFactory } from '@nestjs/core';
import { ValidationPipe } from '@nestjs/common';
import { ConfigService } from '@nestjs/config';
import { AppModule } from './app.module';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);

  // Ambil ConfigService
  const configService = app.get(ConfigService);

  // Ambil konfigurasi dari namespace
  const port = configService.get<number>('app.port', 3000);
  const prefix = configService.get<string>('app.prefix', 'api/v1');
  const nodeEnv = configService.get<string>('app.nodeEnv', 'development');

  // Set global prefix
  app.setGlobalPrefix(prefix);

  // Aktifkan CORS (bisa juga dari config)
  app.enableCors({
    origin: nodeEnv === 'production'
      ? ['https://perpustakaan.com']
      : '*',
    methods: 'GET,HEAD,PUT,PATCH,POST,DELETE',
  });

  // Global validation pipe
  app.useGlobalPipes(
    new ValidationPipe({
      whitelist: true,
      forbidNonWhitelisted: true,
      transform: true,
    }),
  );

  await app.listen(port);
  console.log(`Aplikasi berjalan di http://localhost:${port}/${prefix}`);
}

bootstrap();
```

Atau jika ingin menggunakan namespace yang lebih terstruktur:

```typescript
// src/main.ts (alternatif dengan object destructuring)
import { NestFactory } from '@nestjs/core';
import { ValidationPipe } from '@nestjs/common';
import { ConfigService } from '@nestjs/config';
import { AppModule } from './app.module';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  const configService = app.get(ConfigService);

  const { port, prefix } = {
    port: configService.get<number>('app.port', 3000),
    prefix: configService.get<string>('app.prefix', 'api/v1'),
  };

  app.setGlobalPrefix(prefix);
  app.enableCors();
  app.useGlobalPipes(
    new ValidationPipe({ whitelist: true, forbidNonWhitelisted: true, transform: true }),
  );

  await app.listen(port);
}

bootstrap();
```

Pastikan file `.env` memiliki nilai yang sesuai:

```env
PORT=3000
GLOBAL_PREFIX=api/v1
NODE_ENV=development
APP_NAME=Perpustakaan API
```

## Analogi

`main.ts` adalah **pintu utama perpustakaan** yang pertama kali dilihat pengunjung. Di pintu ini ada papan yang bertuliskan jam buka, alamat, dan peraturan CORS (siapa saja yang boleh masuk). Sebelumnya, semua informasi ini dicat permanen di pintu: "Buka pukul 08.00", "Buka untuk umum". Jika ingin mengubah jam buka menjadi 09.00, kita harus mengecat ulang seluruh pintu.

Sekarang, pintu utama memiliki layar digital yang membaca informasi dari lemari arsip (ConfigService). Cukup ubah catatan di lemari arsip (file `.env`), dan keesokan harinya layar digital akan menampilkan jam buka yang baru. Tidak perlu mengecat ulang pintu. Bahkan, untuk cabang perpustakaan yang berbeda, kita tinggal memberikan lemari arsip yang berbeda — pintunya tetap sama. Inilah yang dimaksud dengan konfigurasi berbasis environment: kode tidak berubah, hanya konfigurasi yang berbeda.

## Penggunaan

Dipakai di semua aplikasi NestJS untuk bootstrap configuration. `main.ts` yang baik harus bisa membaca port, prefix, CORS origins, dan pengaturan global lainnya dari ConfigService. Ini sangat penting untuk deployment di berbagai environment (development, staging, production).

## Kesalahan Umum yang Sering Terjadi

1. **Mengakses ConfigService sebelum `app.create()`**: Tidak bisa, karena DI container belum terbentuk.
2. **Lupa import ConfigModule**: `app.get(ConfigService)` akan throw error karena ConfigService tidak terdaftar.
3. **Typo nama field**: `configService.get('app.port')` salah tulis jadi `configService.get('app.portt')`, mengembalikan undefined tanpa error.
4. **Tidak provide default value**: Jika environment variable tidak di-set, nilai menjadi `undefined` dan port jadi `undefined`.
5. **Hardcode masih tersisa**: Beberapa nilai masih di-hardcode di `main.ts` meskipun sudah ada di config.
6. **Lupa set `transform: true` di ValidationPipe**: DTO tidak di-transform secara otomatis, properti tetap string.

## Hubungan dengan Materi Sebelumnya

Setelah ConfigModule (materi 27) dan namespace configuration (materi 28) siap, kita integrate semuanya di `main.ts`. Ini adalah langkah terakhir dari setup konfigurasi. Mulai sekarang, semua pengaturan aplikasi dikelola melalui environment variable. Dengan `main.ts` yang sudah menggunakan ConfigService, kita siap melanjutkan ke pembuatan pagination DTO (materi 30) dan fitur-fitur lainnya.

**Soal 2:** Mengapa kita perlu memanggil `app.get(ConfigService)` setelah `NestFactory.create()` dan bukan sebelumnya?

<details>
<summary>Jawaban</summary>

Karena `ConfigService` adalah provider yang didaftarkan di DI container NestJS. Instance aplikasi (`app`) harus dibuat terlebih dahulu melalui `NestFactory.create(AppModule)` agar semua module dan provider terdaftar di DI container. Setelah itu, kita bisa mengambil instance `ConfigService` dari container menggunakan `app.get()`. Sebelum `create()`, container belum ada sehingga tidak bisa mengakses provider.

</details>
