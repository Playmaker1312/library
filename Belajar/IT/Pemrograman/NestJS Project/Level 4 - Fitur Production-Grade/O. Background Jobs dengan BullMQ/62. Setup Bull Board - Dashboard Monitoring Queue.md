# 62. Setup Bull Board — Dashboard Monitoring Queue

## Penjelasan

Ketika aplikasi sudah memiliki banyak queue dan job, kita membutuhkan **dashboard visual** untuk memonitoring: melihat job yang antri, job yang sedang diproses, job yang gagal, dan performa queue secara real-time. **Bull Board** adalah package UI untuk BullMQ yang menyediakan dashboard berbasis web. Dengan Bull Board, developer dan admin dapat melihat status queue, melakukan retry job gagal, menghapus job, dan memeriksa detail error tanpa harus akses Redis CLI.

Bull Board untuk NestJS disediakan oleh package `@bull-board/nestjs`. Dashboard ini bisa diakses melalui endpoint `/queues` atau `/admin/queues`. Penting untuk **melindungi endpoint ini dengan guard** karena dashboard ini memberikan akses penuh ke sistem queue — siapa pun yang masuk bisa melihat data dan memicu ulang job.

## Fungsi

Bull Board berfungsi sebagai antarmuka visual untuk memonitoring dan mengelola queue BullMQ. Dashboard ini membantu developer dan admin dalam: melihat jumlah job antrian, memeriksa job yang gagal beserta stack trace-nya, melakukan retry job, dan memonitor performa worker.

## Cara Implementasi / Code

### 1. Install Dependencies

```bash
npm install @bull-board/nestjs @bull-board/express
```

### 2. Setup Bull Board Module

```typescript
// src/queues/queues.module.ts (update)
import { Module } from '@nestjs/common';
import { BullModule } from '@nestjs/bullmq';
import { BullBoardModule } from '@bull-board/nestjs';
import { ExpressAdapter } from '@bull-board/express';
import { EmailProcessor } from './processors/email.processor';
import { EmailModule } from '../email/email.module';

@Module({
  imports: [
    BullModule.forRootAsync({ /* ... config ... */ }),

    BullModule.registerQueue(
      { name: 'email' },
      { name: 'notification' },
    ),

    // Setup Bull Board
    BullBoardModule.forRoot({
      route: '/queues',
      adapter: ExpressAdapter, // atau FastifyAdapter
    }),

    BullBoardModule.forFeature({
      name: 'email',
      adapter: ExpressAdapter,
    }),

    BullBoardModule.forFeature({
      name: 'notification',
      adapter: ExpressAdapter,
    }),

    EmailModule,
  ],
  providers: [EmailProcessor],
  exports: [BullModule],
})
export class QueuesModule {}
```

### 3. Proteksi Dashboard dengan Guard

```typescript
// src/queues/guards/queue-dashboard.guard.ts
import { Injectable, CanActivate, ExecutionContext } from '@nestjs/common';

@Injectable()
export class QueueDashboardGuard implements CanActivate {
  canActivate(context: ExecutionContext): boolean {
    const request = context.switchToHttp().getRequest();
    const user = request.user;

    // Hanya admin yang bisa akses dashboard queue
    return user?.role === 'ADMIN';
  }
}
```

### 4. Apply Guard ke Route Bull Board

Bull Board menggunakan router-nya sendiri, jadi kita perlu mengaplikasikan guard melalui middleware.

```typescript
// src/main.ts
import { NestFactory } from '@nestjs/core';
import { AppModule } from './app.module';
import { QueueDashboardGuard } from './queues/guards/queue-dashboard.guard';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);

  // Middleware auth untuk Bull Board
  app.use('/queues', (req, res, next) => {
    // Parse JWT dari cookie atau header
    const token = req.headers.authorization?.split(' ')[1];
    if (!token) return res.status(401).json({ message: 'Unauthorized' });

    try {
      const payload = jwt.verify(token, process.env.JWT_SECRET);
      if (payload.role !== 'ADMIN') {
        return res.status(403).json({ message: 'Forbidden' });
      }
      req.user = payload;
      next();
    } catch {
      return res.status(401).json({ message: 'Invalid token' });
    }
  });

  await app.listen(3000);
}
```

### 5. Alternative: Integrasi dengan Express Router

```typescript
// src/queues/queues.controller.ts
import { Controller, Get, Res, Req, UseGuards } from '@nestjs/common';
```

## Analogi

Bayangkan perpustakaan memiliki **papan monitor besar** di ruang admin yang menampilkan status semua kotak saran (queue). Di papan ini terlihat: ada 5 surat menunggu di kotak "Email", 2 sedang diproses, 1 gagal dengan catatan "alamat email tidak valid". Admin bisa langsung menekan tombol "kirim ulang" untuk surat yang gagal. Ini Bull Board. Tanpa papan ini, admin harus membuka setiap kotak secara manual (Redis CLI) untuk melihat isinya — tidak efisien dan rawan kesalahan.

## Penggunaan

Bull Board digunakan untuk:
- **Monitoring real-time**: lihat jumlah job antrian, proses, dan gagal
- **Debugging**: periksa stack trace job yang gagal tanpa login ke server
- **Operasional**: retry job gagal, hapus job yang stuck
- **Kapasitas planning**: lihat tren volume job untuk scaling worker
- **Demo**: tunjukkan ke stakeholder bagaimana sistem background job bekerja

## Kesalahan Umum yang Sering Terjadi

1. **Dashboard tidak terproteksi** — endpoint `/queues` bisa diakses siapa pun tanpa autentikasi. Ini risiko keamanan serius karena dashboard memperlihatkan data internal.
2. **Lupa register queue di BullBoardModule.forFeature** — queue tidak akan muncul di dashboard meskipun sudah terdaftar di BullModule.
3. **Versi Bull Board tidak kompatibel** — pastikan `@bull-board/nestjs` versinya cocok dengan `@nestjs/bullmq` yang digunakan.
4. **CORS issue** — jika dashboard diakses dari domain berbeda, atur CORS di main.ts.
5. **Performance issue dengan banyak queue** — Bull Board melakukan polling ke Redis. Dengan ratusan queue, pertimbangkan untuk refresh manual.
