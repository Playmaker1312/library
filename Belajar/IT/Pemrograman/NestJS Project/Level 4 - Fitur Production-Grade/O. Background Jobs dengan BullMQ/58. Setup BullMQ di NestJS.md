# 58. Setup BullMQ di NestJS

## Penjelasan

Di aplikasi production, beberapa operasi tidak boleh dilakukan secara synchronous di request-response cycle karena akan memperlambat response. Contoh: mengirim email konfirmasi, memproses gambar, generate laporan PDF, atau update status massal. Operasi-operasi ini sebaiknya dijalankan di **background** menggunakan **job queue**. BullMQ adalah library antrian (queue) berbasis Redis yang handal, cepat, dan banyak digunakan di ekosistem Node.js.

NestJS menyediakan package `@nestjs/bullmq` yang mengintegrasikan BullMQ secara native dengan dekorator dan module system. Konsep dasarnya: **Queue** sebagai tempat mengantrikan job, dan **Processor/Worker** sebagai konsumen yang memproses job. Kita akan mendaftarkan beberapa queue seperti `email` (untuk notifikasi email) dan `notification` (untuk notifikasi in-app). Semua queue terhubung ke Redis yang sama.

## Fungsi

Setup BullMQ bertujuan untuk mengkonfigurasi koneksi Redis untuk queue, mendaftarkan queue-queue yang tersedia di aplikasi, dan menyediakan infrastructure agar service-service dapat mengirim job ke queue dan worker dapat memprosesnya secara asynchronous.

## Cara Implementasi / Code

### 1. Install Dependencies

```bash
npm install @nestjs/bullmq bullmq ioredis
```

### 2. Konfigurasi Queue Module

```typescript
// src/queues/queues.module.ts
import { Module } from '@nestjs/common';
import { BullModule } from '@nestjs/bullmq';
import { ConfigModule, ConfigService } from '@nestjs/config';

@Module({
  imports: [
    BullModule.forRootAsync({
      imports: [ConfigModule],
      inject: [ConfigService],
      useFactory: async (config: ConfigService) => ({
        connection: {
          host: config.get<string>('redis.host'),
          port: config.get<number>('redis.port'),
          password: config.get<string>('redis.password'),
        },
        defaultJobOptions: {
          attempts: 3,
          backoff: {
            type: 'exponential',
            delay: 2000,
          },
          removeOnComplete: true,
          removeOnFail: false,
        },
      }),
    }),
    BullModule.registerQueue(
      { name: 'email' },
      { name: 'notification' },
    ),
  ],
  exports: [BullModule],
})
export class QueuesModule {}
```

### 3. Environment Variables

```bash
# .env (tambahkan)
REDIS_HOST=localhost
REDIS_PORT=6379
```

### 4. Import QueuesModule di AppModule

```typescript
// src/app.module.ts
@Module({
  imports: [
    ConfigModule.forRoot({ isGlobal: true }),
    QueuesModule,  // <-- import module queue
    // ... module lainnya
  ],
})
export class AppModule {}
```

### 5. Inject Queue ke Service

```typescript
// Contoh inject queue di service
import { InjectQueue } from '@nestjs/bullmq';
import { Queue } from 'bullmq';

@Injectable()
export class LoansService {
  constructor(
    @InjectQueue('email') private emailQueue: Queue,
    @InjectQueue('notification') private notificationQueue: Queue,
  ) {}
}
```

### 6. Verifikasi Setup

```bash
# Setelah aplikasi jalan, cek apakah queue terdaftar:
# Bisa melalui Redis CLI atau dashboard Bull Board (materi #62)
redis-cli keys *
# Output: bull:email:*  bull:notification:*
```

## Analogi

Bayangkan perpustakaan memiliki **kotak saran** (queue) di depan meja sirkulasi. Anggota bisa memasukkan kertas berisi permintaan (job) ke kotak yang berbeda: kotak "Email" untuk permintaan kirim notifikasi, kotak "Cetak" untuk permintaan cetak ulang kartu anggota. Setiap jam, petugas khusus (worker) mengambil kertas dari kotak, memprosesnya (mengirim email, mencetak kartu), lalu menandai selesai. Jika proses gagal, kertas dikembalikan ke kotak untuk dicoba lagi nanti (retry). Kotak saran ini memisahkan permintaan dari eksekusi — anggota tidak perlu menunggu selesai, cukup memasukkan dan lanjut aktivitas lain.

## Penggunaan

BullMQ digunakan untuk berbagai skenario background processing:
- **Mengirim email** (konfirmasi pinjam, pengingat kembali, notifikasi overdue)
- **Memproses file upload** (kompres gambar, generate thumbnail)
- **Sinkronisasi data** dengan sistem eksternal
- **Generate laporan** periodik
- **Membersihkan data** expired atau sampah
- **Webhook** dan integrasi pihak ketiga

## Kesalahan Umum yang Sering Terjadi

1. **Redis tidak dikonfigurasi** — BullMQ membutuhkan Redis. Pastikan Redis berjalan sebelum aplikasi NestJS starts.
2. **Queue name tidak konsisten** — nama queue di `registerQueue` harus sama persis dengan nama di `@InjectQueue()` dan `@Processor()`.
3. **Lupa defaultJobOptions** — tanpa `attempts: 3`, job gagal akan langsung hilang tanpa retry. Di production, selalu set retry strategy.
4. **Memory leak** — job yang selesai tidak di-remove (`removeOnComplete: false`) akan menumpuk di Redis.
5. **Koneksi Redis timeout** — jika Redis terpisah di server berbeda, set `maxRetriesPerRequest` dan `retryStrategy`.

## Hubungan dengan Materi Sebelumnya

Di **Level 3** kita telah bekerja secara synchronous: request masuk → proses → response keluar. Sekarang dengan BullMQ, kita memperkenalkan **asynchronous processing**. Ini adalah konsep penting dalam arsitektur microservices dan event-driven. Caching (#54-57) membuat response cepat, background jobs membuat response tetap cepat meskipun ada pekerjaan berat di belakang layar.

## Soal Latihan

**Soal:**
Konfigurasikan BullMQ dengan dua queue terpisah (`email` dan `report`) di mana queue `email` memiliki default `attempts: 5` dan `report` memiliki `attempts: 2`. Gunakan konfigurasi terpisah per queue.

**Jawaban:**

```typescript
BullModule.forRootAsync({ /* ... konfigurasi global ... */ }),

// Queue email dengan konfigurasi spesifik
BullModule.registerQueue({
  name: 'email',
  defaultJobOptions: {
    attempts: 5,
    backoff: { type: 'exponential', delay: 1000 },
    removeOnComplete: 100,
    removeOnFail: 50,
  },
}),

// Queue report dengan konfigurasi berbeda
BullModule.registerQueue({
  name: 'report',
  defaultJobOptions: {
    attempts: 2,
    backoff: { type: 'fixed', delay: 5000 },
    removeOnComplete: true,
    removeOnFail: true,
  },
}),
```
