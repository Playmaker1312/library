# 60. Dispatch Job dari LoansService — Kirim Email Setelah Pinjam

## Penjelasan

Setelah queue (`email`) dan processor (`EmailProcessor`) siap, langkah selanjutnya adalah menghubungkan keduanya dengan cara **mendispatch (mengirim) job** dari service ke queue. Dalam kasus kita, setiap kali seorang anggota berhasil meminjam buku melalui `LoansService.borrowBook()`, kita ingin mengirim email konfirmasi. Daripada mengirim email secara langsung (synchronous) yang akan memperlambat response, kita masukkan job ke queue `email` dan biarkan processor memprosesnya di background.

BullMQ menyediakan method `queue.add(jobName, data, options)` untuk menambahkan job ke queue. Parameter penting di options meliputi: `attempts` (jumlah maksimal percobaan jika gagal), `backoff` (strategi jeda antar percobaan), `delay` (tunda eksekusi), dan `priority` (prioritas job). Dengan pendekatan ini, response API tetap cepat (< 100ms) sementara email dikirim secara asynchronous.

## Fungsi

Dispatch job berfungsi untuk mengirim tugas ke queue agar diproses secara asynchronous oleh worker/processor. Ini memisahkan operasi cepat (response HTTP) dari operasi lambat (kirim email, proses file), sehingga pengguna tidak perlu menunggu operasi lambat selesai.

## Cara Implementasi / Code

### 1. Inject Queue ke LoansService

```typescript
// src/loans/services/loans.service.ts
import { Injectable } from '@nestjs/common';
import { InjectQueue } from '@nestjs/bullmq';
import { Queue } from 'bullmq';
import { ILoansRepository } from '../interfaces/loans-repository.interface';
import { LoanConfirmationJobData } from '../../queues/interfaces/email-job.interface';

@Injectable()
export class LoansService {
  constructor(
    @Inject('ILoansRepository')
    private readonly loansRepo: ILoansRepository,
    @InjectQueue('email') private emailQueue: Queue,
    @InjectQueue('notification') private notificationQueue: Queue,
  ) {}

  async borrowBook(createLoanDto: CreateLoanDto, userId: string) {
    // 1. Proses peminjaman (transaction)
    const loan = await this.loansRepo.create(createLoanDto, userId);

    // 2. Dispatch job email konfirmasi (fire-and-forget)
    const jobData: LoanConfirmationJobData = {
      email: loan.user.email,
      userName: loan.user.name,
      bookTitle: loan.book.title,
      dueDate: loan.dueDate.toISOString(),
    };

    await this.emailQueue.add('send-loan-confirmation', jobData, {
      attempts: 3,
      backoff: { type: 'exponential', delay: 2000 },
      removeOnComplete: true,
      removeOnFail: false,
    });

    // 3. Dispatch job notifikasi in-app
    await this.notificationQueue.add('send-borrow-notification', {
      userId: loan.userId,
      bookTitle: loan.book.title,
      dueDate: loan.dueDate.toLocaleDateString('id-ID'),
    });

    return loan;
  }

  async returnBook(id: string) {
    const loan = await this.loansRepo.returnBook(id);

    // Dispatch email konfirmasi pengembalian
    await this.emailQueue.add('send-return-reminder', {
      email: loan.user.email,
      userName: loan.user.name,
      bookTitle: loan.book.title,
      returnedAt: new Date().toISOString(),
    });

    return loan;
  }
}
```

### 3. Job Options yang Tersedia

```typescript
// Contoh berbagai opsi job
await this.emailQueue.add('send-loan-confirmation', jobData, {
  // Retry configuration
  attempts: 5,
  backoff: {
    type: 'exponential', // atau 'fixed'
    delay: 1000, // Delay awal (ms)
  },

  // Timing
  delay: 5000, // Tunda 5 detik sebelum proses
  timestamp: Date.now(),

  // Lifecycle
  removeOnComplete: {
    age: 3600, // Hapus 1 jam setelah selesai
    count: 100, // Maks 100 job completed
  },
  removeOnFail: {
    age: 24 * 3600, // Simpan failed job 24 jam
  },

  // Priority (1 = tertinggi)
  priority: 10,
});
```

### 3. Dispatch dengan Delay — Email Reminder

```typescript
async sendReturnReminder(loanId: string) {
  const loan = await this.loansRepo.findById(loanId);

  // Kirim reminder 1 hari sebelum dueDate
  const oneDayBeforeDue = loan.dueDate.getTime() - Date.now() - 24 * 60 * 60 * 1000;

  if (oneDayBeforeDue > 0) {
    await this.emailQueue.add('send-return-reminder', {
      email: loan.user.email,
      userName: loan.user.name,
      bookTitle: loan.book.title,
      dueDate: loan.dueDate.toISOString(),
    }, {
      delay: oneDayBeforeDue, // Job baru diproses H-1
      attempts: 3,
    });
  }
}
```

## Analogi

Setelah petugas sirkulasi selesai memproses peminjaman buku (mencatat di kartu, mengurangi stok), dia mengambil **kertas pesanan** dan menuliskannya: "Kirim email konfirmasi ke Andi — buku 'Clean Code' — batas 14 hari". Kertas ini lalu dimasukkan ke keranjang "Email" (queue). Petugas tidak perlu menunggu sampai email benar-benar terkirim — dia bisa langsung melayani anggota berikutnya. Petugas lain di ruang belakang (processor) akan mengambil kertas itu, mengetik email, dan mengirimkannya. Jika gagal (salah alamat), kertas dikembalikan ke keranjang untuk dicoba lagi nanti.

## Penggunaan

Dispatch job digunakan di semua skenario di mana operasi asynchronous diperlukan setelah operasi utama selesai:
- **Setelah registrasi**: dispatch welcome email
- **Setelah peminjaman**: dispatch konfirmasi + notifikasi
- **Setelah upload gambar**: dispatch job kompresi/resize
- **Setelah pembayaran**: dispatch invoice email
- **Scheduled reminder**: dispatch job dengan delay untuk pengingat

## Kesalahan Umum yang Sering Terjadi

1. **Job dispatch di dalam transaction** — jika job dispatch gagal, transaction sudah commit. Lebih baik dispatch setelah transaction berhasil, atau gunakan pola Outbox.
2. **Tidak handle error dispatch** — method `queue.add()` bisa throw error jika Redis down. Jangan sampai error ini menggagalkan response utama. Gunakan try-catch atau fire-and-forget.
3. **Data terlalu besar di job** — job data disimpan di Redis. Jangan masukkan data besar seperti file base64 atau array ribuan item. Simpan reference (ID) saja.
4. **Duplicate job** — jika dispatch dipanggil dua kali (misal retry dari sisi client), bisa terjadi duplikasi email. Usahakan idempotent dengan jobId option.
5. **Lupa inject queue** — `@InjectQueue('email')` butuh queue 'email' terdaftar. Jika typo atau lupa register, akan error.

## Hubungan dengan Materi Sebelumnya

Di **#52 (Membuat LoansModule)**, `borrowBook()` hanya melakukan operasi database dalam transaction. Sekarang kita memperluasnya dengan **side effect**: dispatch job email dan notifikasi. Ini adalah pola **event-driven** yang memisahkan operasi utama dari operasi tambahan. Setelah ini, di **#61** kita akan belajar **cron job** yang mendispatch job secara periodik tanpa campur tangan user.

## Soal Latihan

**Soal:**
Buat method `dispatchOverdueNotices()` di LoansService yang mencari semua loan dengan status `OVERDUE` dan mendispatch job email `send-overdue-notice` untuk masing-masing. Gunakan `Promise.allSettled` agar satu kegagalan tidak menghentikan yang lain.

**Jawaban:**

```typescript
async dispatchOverdueNotices() {
  const overdueLoans = await this.loansRepo.findAll({ status: 'OVERDUE' });

  const jobs = overdueLoans.map((loan) => {
    const daysOverdue = Math.floor(
      (Date.now() - loan.dueDate.getTime()) / (1000 * 60 * 60 * 24),
    );

    return this.emailQueue.add('send-overdue-notice', {
      email: loan.user.email,
      userName: loan.user.name,
      bookTitle: loan.book.title,
      daysOverdue,
    }, {
      attempts: 3,
      backoff: { type: 'exponential', delay: 2000 },
    }).catch((err) => ({
      status: 'rejected',
      loanId: loan.id,
      error: err.message,
    }));
  });

  const results = await Promise.allSettled(jobs);
  const failed = results.filter(r => r.status === 'rejected');
  
  if (failed.length > 0) {
    this.logger.warn(`${failed.length} overdue notices failed to dispatch`);
  }
}
```
