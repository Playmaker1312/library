# Membangun BooksController — Routing & HTTP Method yang Benar

## Penjelasan

**Controller** adalah lapisan yang menangani request HTTP masuk dan mengembalikan response ke client. Di NestJS, controller didefinisikan dengan decorator `@Controller()` yang bisa diberi prefix route. Controller menerima request, memanggil service yang sesuai, dan mengembalikan hasilnya. Controller **tidak boleh** mengandung logic bisnis — tugasnya hanya sebagai **penerjemah** antara HTTP dan service.

Setiap method di controller ditandai dengan decorator HTTP method: `@Get()`, `@Post()`, `@Patch()`, `@Put()`, `@Delete()`. Decorator ini bisa diberi parameter path seperti `@Get(':id')` untuk route parameter. NestJS juga menyediakan decorator parameter seperti `@Param()` (mengambil path parameter), `@Body()` (mengambil request body), `@Query()` (mengambil query string), dan `@Headers()` (mengambil header).

Penting untuk memahami kapan menggunakan `@Patch()` vs `@Put()`. **PATCH** digunakan untuk update **sebagian** data — client hanya mengirim field yang ingin diubah. **PUT** digunakan untuk mengganti seluruh resource — client harus mengirim data lengkap. Di project kita, kita akan menggunakan PATCH sesuai dengan UpdateBookDto yang semua propertinya opsional.

## Fungsi

BooksController berfungsi sebagai **router** dan **handler HTTP** untuk semua endpoint yang berkaitan dengan buku. Controller menerima request dari client, memvalidasi input (melalui DTO + ValidationPipe), memanggil method yang sesuai di BooksService, dan mengembalikan response dalam format yang sudah ditentukan. Controller adalah satu-satunya bagian aplikasi yang "tahu" tentang HTTP — service tidak perlu tahu apakah dipanggil dari HTTP, WebSocket, atau CLI.

## Cara Implementasi / Code

### 1. BooksController Lengkap

Buka file `src/modules/books/books.controller.ts` dan tulis kode berikut:

```typescript
import {
  Controller,
  Get,
  Post,
  Patch,
  Delete,
  Body,
  Param,
  Query,
  ParseUUIDPipe,
  HttpCode,
  HttpStatus,
} from '@nestjs/common';
import { BooksService } from './books.service';
import { CreateBookDto } from './dto/create-book.dto';
import { UpdateBookDto } from './dto/update-book.dto';
import { QueryBookDto } from './dto/query-book.dto';
import { Book } from './interfaces/book.interface';

@Controller('books')
export class BooksController {
  constructor(private readonly booksService: BooksService) {}

  @Post()
  create(@Body() createBookDto: CreateBookDto): Book {
    return this.booksService.create(createBookDto);
  }

  @Get()
  findAll(@Query() queryBookDto: QueryBookDto): Book[] {
    return this.booksService.findAll(queryBookDto);
  }

  @Get(':id')
  findById(@Param('id', ParseUUIDPipe) id: string): Book {
    return this.booksService.findById(id);
  }

  @Patch(':id')
  update(
    @Param('id', ParseUUIDPipe) id: string,
    @Body() updateBookDto: UpdateBookDto,
  ): Book {
    return this.booksService.update(id, updateBookDto);
  }

  @Delete(':id')
  @HttpCode(HttpStatus.NO_CONTENT)
  remove(@Param('id', ParseUUIDPipe) id: string): void {
    this.booksService.remove(id);
  }
}
```

### 2. Daftar Endpoint yang Tersedia

| HTTP Method | Route | Deskripsi | Request Body / Param |
|------------|-------|-----------|---------------------|
| `POST` | `/books` | Membuat buku baru | JSON `CreateBookDto` |
| `GET` | `/books` | Mendapatkan semua buku | Query `?search=&author=&year=` |
| `GET` | `/books/:id` | Mendapatkan satu buku | Path parameter `id` (UUID) |
| `PATCH` | `/books/:id` | Update data buku | JSON `UpdateBookDto` |
| `DELETE` | `/books/:id` | Menghapus buku | Path parameter `id` (UUID) |

### 3. Penjelasan Detail Setiap Endpoint

**POST /books** — Membuat buku baru:
```typescript
@Post()
create(@Body() createBookDto: CreateBookDto): Book {
  return this.booksService.create(createBookDto);
}
```
- Decorator `@Body()` mengambil request body dan memetakannya ke `CreateBookDto`
- ValidationPipe (akan dipasang di materi 16) akan memvalidasi body secara otomatis
- Mengembalikan objek Book yang baru dibuat

**GET /books** — Mendapatkan daftar buku:
```typescript
@Get()
findAll(@Query() queryBookDto: QueryBookDto): Book[] {
  return this.booksService.findAll(queryBookDto);
}
```
- Decorator `@Query()` mengambil semua query parameter dan memetakannya ke `QueryBookDto`
- Jika tidak ada query parameter, semua buku dikembalikan
- Jika ada filter, service akan memprosesnya

**GET /books/:id** — Mendapatkan buku berdasarkan ID:
```typescript
@Get(':id')
findById(@Param('id', ParseUUIDPipe) id: string): Book {
  return this.booksService.findById(id);
}
```
- `ParseUUIDPipe` memvalidasi bahwa `id` adalah UUID yang valid
- Jika id tidak valid, NestJS otomatis mengembalikan error 400 Bad Request
- Jika buku tidak ditemukan, service melempar 404 NotFoundException

**PATCH /books/:id** — Update buku:
```typescript
@Patch(':id')
update(
  @Param('id', ParseUUIDPipe) id: string,
  @Body() updateBookDto: UpdateBookDto,
): Book {
  return this.booksService.update(id, updateBookDto);
}
```
- Kombinasi path parameter `id` dan request body
- Client hanya perlu mengirim field yang ingin diubah

**DELETE /books/:id** — Hapus buku:
```typescript
@Delete(':id')
@HttpCode(HttpStatus.NO_CONTENT)
remove(@Param('id', ParseUUIDPipe) id: string): void {
  this.booksService.remove(id);
}
```
- `@HttpCode(HttpStatus.NO_CONTENT)` mengubah status code menjadi 204
- Tidak mengembalikan body response (void)
- 204 No Content adalah standar untuk response DELETE yang sukses

### 4. Pattern Penting: ParseUUIDPipe

```typescript
@Param('id', ParseUUIDPipe) id: string
```

`ParseUUIDPipe` adalah built-in pipe NestJS yang memvalidasi apakah string parameter adalah UUID yang valid. Jika tidak valid, NestJS akan mengembalikan response:

```json
{
  "statusCode": 400,
  "message": "Validation failed (uuid is expected)",
  "error": "Bad Request"
}
```

Ini mencegah kita memproses ID yang tidak valid di service.

### 5. Response Status Code (default vs custom)

| HTTP Method | Default Status Code | Yang Dikembalikan |
|------------|-------------------|-------------------|
| POST | 201 Created | Objek Book yang baru |
| GET | 200 OK | Array atau objek Book |
| PATCH | 200 OK | Objek Book yang diupdate |
| DELETE | 204 No Content (custom) | Tidak ada body |

## Analogi

Bayangkan **BooksController** adalah **meja informasi/resepsionis** di perpustakaan. Resepsionis ini adalah titik kontak pertama bagi semua pengunjung:

- **POST /books** — Seorang penerbit datang membawa buku baru. Resepsionis mengambil formulir (CreateBookDto), memeriksa kelengkapannya, lalu memberikan ke petugas rak (service) untuk disimpan. Resepsionis lalu memberi tanda terima ke penerbit (response Book).

- **GET /books** — Seorang pengunjung bertanya "buku apa saja yang ada?" Resepsionis bertanya apakah ada kriteria tertentu (filter), lalu mengecek ke petugas rak dan menyampaikan daftarnya ke pengunjung.

- **GET /books/:id** — Pengunjung memiliki nomor ID buku. Resepsionis mencari di catatan dan memberitahu detail buku tersebut. Jika tidak ada, resepsionis berkata "maaf, tidak ditemukan" (404).

- **PATCH /books/:id** — Pengunjung ingin melaporkan kesalahan data. Resepsionis menerima perbaikan, memverifikasi ID buku, dan menyampaikan koreksi ke petugas rak.

- **DELETE /books/:id** — Buku akan ditarik dari peredaran. Resepsionis memproses penghapusan dan mengangguk (204 No Content) sebagai tanda selesai.

Yang penting: resepsionis **tidak pernah pergi ke rak buku sendiri**. Dia hanya menerima permintaan, mencatatnya, dan menyampaikan ke petugas rak. Ini adalah pemisahan tugas yang jelas antara controller (resepsionis) dan service (petugas rak).

## Penggunaan

Controller digunakan untuk **semua endpoint REST API** di aplikasi NestJS. Setiap module bisnis akan memiliki controllernya sendiri — BooksController, MembersController, LoansController, AuthController. Dengan pola ini, penambahan endpoint baru tinggal menambah method baru di controller yang sesuai, tanpa mengganggu endpoint lain.

## Kesalahan Umum yang Sering Terjadi

1. **Menaruh logic bisnis di controller** — Controller memanggil `this.booksService.processLoan()` padahal logic peminjaman seharusnya ada di service. Controller hanya boleh memanggil service, bukan menjalankan logic.

2. **Tidak menggunakan ParseUUIDPipe** — Menerima ID tanpa validasi UUID bisa menyebabkan error di service saat mencari, atau bahkan security issue.

3. **Salah memilih HTTP method** — Menggunakan PUT untuk update parsial (seharusnya PATCH) atau menggunakan GET untuk operasi yang mengubah data (seharusnya POST/PATCH/DELETE).

4. **Lupa mendaftarkan controller di module** — Jika `BooksController` tidak ada di `controllers` array `BooksModule`, NestJS tidak akan mengenali endpoint-endpointnya.

5. **Mengembalikan status code yang salah** — POST seharusnya 201, DELETE seharusnya 204. NestJS memberikan default yang tepat, tapi jika menggunakan custom response, pastikan status code-nya sesuai standar.

## Hubungan dengan Materi Sebelumnya

Controller adalah **penghubung** antara HTTP (dunia luar) dan service (logic bisnis). Materi ini memanfaatkan:
- Service yang sudah dibuat di materi 10
- DTO yang sudah dibuat di materi 9
- Interface Book dari materi 8
- Module yang sudah di-generate di materi 7

Setelah controller selesai, aplikasi Books API kita sudah fungsional dan bisa diuji melalui HTTP (materi 12).

## Soal Latihan

**Soal:** Buatlah `MembersController` lengkap dengan 5 endpoint:
1. `POST /members` — Membuat anggota baru
2. `GET /members` — Mendapatkan semua anggota dengan filter query
3. `GET /members/:id` — Mendapatkan anggota berdasarkan ID
4. `PATCH /members/:id` — Update data anggota
5. `DELETE /members/:id` — Hapus anggota (204 No Content)

Gunakan `ParseUUIDPipe` untuk parameter ID dan jangan lupa deklarasi constructor dengan dependency injection `MembersService`.

**Jawaban:**

`src/modules/members/members.controller.ts`:
```typescript
import {
```
