# 41. Membuat JwtRefreshStrategy - Validasi Refresh Token

## Penjelasan

JwtRefreshStrategy adalah strategy khusus yang digunakan untuk memvalidasi refresh token. Berbeda dengan JwtStrategy yang memvalidasi access token menggunakan secret key `jwtSecret`, JwtRefreshStrategy menggunakan `jwtRefreshSecret` yang berbeda. Strategy ini digunakan untuk endpoint yang membutuhkan autentikasi dengan refresh token, seperti endpoint refresh token itu sendiri.

Dengan memisahkan strategy untuk access token dan refresh token, kita bisa memberikan proteksi yang berbeda untuk endpoint yang berbeda. Refresh token strategy biasanya tidak perlu mengecek database terlebih dahulu karena validasi utama sudah dilakukan di service layer (pencocokan dengan database). Strategy ini lebih sederhana — hanya memverifikasi JWT dan mengembalikan payload.

## Fungsi

JwtRefreshStrategy berfungsi untuk memvalidasi refresh token yang dikirim oleh client. Strategy ini memastikan bahwa refresh token memiliki signature yang valid dan belum expired menggunakan secret key khusus. Payload yang dihasilkan dapat digunakan untuk mengidentifikasi user dan melanjutkan proses refresh token rotation.

## Cara Implementasi / Code

**1. JwtRefreshStrategy — `src/auth/strategies/jwt-refresh.strategy.ts`:**

```typescript
import { Injectable } from '@nestjs/common';
import { ConfigService } from '@nestjs/config';
import { PassportStrategy } from '@nestjs/passport';
import { ExtractJwt, Strategy } from 'passport-jwt';
import { Request } from 'express';

interface JwtPayload {
  sub: number;
  email: string;
  role: string;
  iat: number;
  exp: number;
}

@Injectable()
export class JwtRefreshStrategy extends PassportStrategy(Strategy, 'jwt-refresh') {
  constructor(private readonly configService: ConfigService) {
    super({
      // Ekstrak refresh token dari body request
      jwtFromRequest: ExtractJwt.fromBodyField('refreshToken'),
      // Jangan abaikan expired
      ignoreExpiration: false,
      // Gunakan secret key khusus untuk refresh token
      secretOrKey: configService.get<string>('auth.jwtRefreshSecret'),
      // Berikan akses ke request object di validate()
      passReqToCallback: true,
    });
  }

  async validate(req: Request, payload: JwtPayload) {
    const refreshToken = req.body?.refreshToken;
    return {
      ...payload,
      refreshToken,
    };
  }
}
```

**2. Update AuthController dengan endpoint refresh yang terproteksi:**

```typescript
import { Controller, Post, Body, UseGuards } from '@nestjs/common';
import { AuthGuard } from '@nestjs/passport';
import { AuthService } from './auth.service';
import { RegisterDto } from './dto/register.dto';
import { LoginDto } from './dto/login.dto';

@Controller('auth')
export class AuthController {
  constructor(private readonly authService: AuthService) {}

  @Post('register')
  async register(@Body() dto: RegisterDto) {
    return this.authService.register(dto);
  }

  @Post('login')
  async login(@Body() dto: LoginDto) {
    return this.authService.login(dto);
  }

  @UseGuards(AuthGuard('jwt-refresh'))
  @Post('refresh')
  async refresh(@Body() body: { refreshToken: string }) {
    return this.authService.refreshTokens(body.refreshToken);
  }
}
```

**3. Update AuthService.validate — dengan guard JwtRefreshStrategy:**

Sebelumnya kita memverifikasi refresh token manual di AuthService. Sekarang kita bisa memanfaatkan JwtRefreshStrategy untuk verifikasi awal, lalu AuthService menangani logika rotasi.

```typescript
async refreshTokens(userId: number, refreshToken: string) {
  const user = await this.usersService.findById(userId);

  if (!user || !user.refreshToken) {
    throw new ForbiddenException('Access denied');
  }

  if (user.refreshToken !== refreshToken) {
    // Deteksi potensi pencurian — invalidasi semua token
    await this.usersService.updateRefreshToken(userId, null);
    throw new ForbiddenException('Session expired, please login again');
  }

  const tokens = await this.generateTokens(user.id, user.email, user.role);
  await this.usersService.updateRefreshToken(user.id, tokens.refreshToken);

  return tokens;
}
```

**4. Daftarkan JwtRefreshStrategy di AuthModule:**

```typescript
import { Module } from '@nestjs/common';
import { ConfigModule, ConfigService } from '@nestjs/config';
import { JwtModule } from '@nestjs/jwt';
import { PassportModule } from '@nestjs/passport';
import { UsersModule } from '../users/users.module';
import authConfig from './auth.config';
import { AuthService } from './auth.service';
import { AuthController } from './auth.controller';
import { JwtStrategy } from './strategies/jwt.strategy';
import { JwtRefreshStrategy } from './strategies/jwt-refresh.strategy';

@Module({
  imports: [
    ConfigModule.forFeature(authConfig),
    PassportModule.register({ defaultStrategy: 'jwt' }),
    JwtModule.registerAsync({
      imports: [ConfigModule],
      inject: [ConfigService],
      useFactory: (configService: ConfigService) => ({
        secret: configService.get<string>('auth.jwtSecret'),
        signOptions: {
          expiresIn: configService.get<string>('auth.jwtExpiresIn'),
        },
      }),
    }),
    UsersModule,
  ],
  controllers: [AuthController],
  providers: [AuthService, JwtStrategy, JwtRefreshStrategy],
  exports: [AuthService],
})
export class AuthModule {}
```

## Analogi

Di perpustakaan, JwtRefreshStrategy seperti **pintu khusus anggota** yang memeriksa stempel keanggotaan jangka panjang. Berbeda dengan satpam di pintu utama (JwtStrategy) yang memeriksa stempel harian, petugas di pintu khusus ini menggunakan buku referensi yang berbeda (secret key berbeda) untuk memverifikasi stempel anggota. Stempel anggota memiliki masa berlaku lebih panjang (7 hari vs 15 menit). Petugas cukup memastikan stempel asli dan belum luntur, lalu mencatatnya — validasi lebih detail dilakukan oleh supervisor di dalam (AuthService).

## Penggunaan

JwtRefreshStrategy digunakan terutama di endpoint `POST /auth/refresh` untuk memvalidasi refresh token sebelum memberikan token baru. Strategy ini juga bisa digunakan di endpoint lain yang membutuhkan autentikasi dengan refresh token, meskipun ini jarang dilakukan.

## Kesalahan Umum yang Sering Terjadi

1. **Menggunakan secret key yang sama dengan JwtStrategy**: Jika secret key sama, maka access token yang sudah expired bisa digunakan sebagai "refresh token". Gunakan secret key yang berbeda (`jwtRefreshSecret`).
2. **Tidak menggunakan `passReqToCallback: true`**: Jika kita perlu mengakses refresh token mentah dari body di method validate(), kita harus mengaktifkan option ini.
3. **Salah strategi ekstraksi**: JwtRefreshStrategy menggunakan `ExtractJwt.fromBodyField('refreshToken')`, bukan `fromAuthHeaderAsBearerToken()`, karena refresh token dikirim di body, bukan header.
4. **Lupa mendaftarkan strategy di AuthModule**: Strategy harus menjadi provider agar bisa digunakan oleh Passport.

## Hubungan dengan Materi Sebelumnya

JwtRefreshStrategy adalah pendamping JwtStrategy (materi 40). Keduanya menggunakan PassportStrategy, tapi dengan perbedaan: (1) secret key berbeda, (2) metode ekstraksi token berbeda (header vs body), (3) tujuan berbeda (proteksi endpoint biasa vs proteksi endpoint refresh). Materi ini akan digunakan oleh JwtAuthGuard (materi 42) yang bisa memilih strategy mana yang akan dipakai.

## Soal Latihan

**Soal 1:** Mengapa JwtRefreshStrategy menggunakan `ExtractJwt.fromBodyField('refreshToken')` dan bukan dari header?

**Jawaban:** Refresh token berbeda dengan access token. Access token dikirim di header Authorization untuk setiap request. Refresh token hanya dikirim saat memperbarui token, dan lebih aman dikirim di body request (POST body) daripada di URL atau header. Ini juga memudahkan implementasi di frontend karena tidak perlu mengatur header khusus untuk satu endpoint.

**Soal 2:** Apa keuntungan memiliki strategy terpisah untuk access token dan refresh token?

**Jawaban:** (1) Secret key berbeda — jika satu secret bocor, yang lain masih aman. (2) Konfigurasi berbeda — refresh token bisa memiliki `ignoreExpiration` yang berbeda. (3) Validasi berbeda — refresh strategy bisa menambahkan validasi khusus. (4) Guard bisa memilih strategy yang tepat untuk endpoint tertentu.

**Soal 3:** Bagaimana jika kita ingin refresh token dikirim di header Authorization, bukan di body? Bagaimana mengubah JwtRefreshStrategy?

**Jawaban:**

```typescript
// Ubah jwtFromRequest
super({
  jwtFromRequest: ExtractJwt.fromAuthHeaderAsBearerToken(),
  ignoreExpiration: false,
  secretOrKey: configService.get<string>('auth.jwtRefreshSecret'),
  passReqToCallback: true,
});
```

Tapi ini tidak disarankan karena akan membingungkan: endpoint yang sama menerima dua jenis token di header yang sama. Lebih baik gunakan header khusus jika ingin di header:

```typescript
// Atau dari custom header
jwtFromRequest: ExtractJwt.fromHeader('x-refresh-token'),
```
