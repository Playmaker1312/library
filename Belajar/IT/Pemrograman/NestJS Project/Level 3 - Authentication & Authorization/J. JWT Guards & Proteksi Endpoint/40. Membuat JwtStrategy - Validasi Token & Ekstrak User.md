# 40. Membuat JwtStrategy - Validasi Token & Ekstrak User

## Penjelasan

JwtStrategy adalah jantung dari autentikasi berbasis JWT di NestJS. Strategy ini menggunakan library `passport-jwt` untuk memvalidasi token JWT yang dikirim oleh client melalui header Authorization (Bearer token). Jika token valid, Passport akan mengekstrak payload dari token dan meneruskannya ke method `validate()` yang kita definisikan. Method validate() inilah yang menentukan apakah request boleh dilanjutkan atau tidak.

Strategy ini didaftarkan sebagai provider di AuthModule dan secara otomatis akan digunakan oleh PassportModule ketika kita menggunakan `AuthGuard('jwt')`. Prosesnya: (1) Token diekstrak dari header, (2) Secret key digunakan untuk memverifikasi signature, (3) Payload didekode, (4) Method `validate()` dipanggil dengan payload, (5) Hasil validasi disimpan di `req.user`.

## Fungsi

JwtStrategy berfungsi sebagai middleware autentikasi yang memvalidasi setiap request yang membutuhkan proteksi. Strategy ini memastikan bahwa hanya request dengan token JWT valid yang bisa mengakses endpoint tertentu. Selain memvalidasi token, strategy ini juga bertanggung jawab untuk menyediakan data user ke controller melalui `req.user`.

## Cara Implementasi / Code

**1. JwtStrategy — `src/auth/strategies/jwt.strategy.ts`:**

```typescript
import { Injectable, UnauthorizedException } from '@nestjs/common';
import { ConfigService } from '@nestjs/config';
import { PassportStrategy } from '@nestjs/passport';
import { ExtractJwt, Strategy } from 'passport-jwt';
import { UsersService } from '../../users/users.service';

interface JwtPayload {
  sub: number;
  email: string;
  role: string;
  iat: number;
  exp: number;
}

@Injectable()
export class JwtStrategy extends PassportStrategy(Strategy, 'jwt') {
  constructor(
    private readonly configService: ConfigService,
    private readonly usersService: UsersService,
  ) {
    super({
      // Ekstrak token dari Authorization header (Bearer token)
      jwtFromRequest: ExtractJwt.fromAuthHeaderAsBearerToken(),
      // Pastikan token yang expired akan ditolak
      ignoreExpiration: false,
      // Gunakan secret key dari konfigurasi
      secretOrKey: configService.get<string>('auth.jwtSecret'),
    });
  }

  // Method ini dipanggil setelah Passport memverifikasi token
  // Return value akan disimpan di req.user
  async validate(payload: JwtPayload) {
    // Cari user di database untuk memastikan user masih ada
    const user = await this.usersService.findById(payload.sub);

    if (!user) {
      throw new UnauthorizedException('User not found');
    }

    // Return data yang akan disimpan di req.user
    return {
      id: user.id,
      email: user.email,
      name: user.name,
      role: user.role,
    };
  }
}
```

**2. Daftarkan JwtStrategy di AuthModule:**

```typescript
import { Module } from '@nestjs/common';
import { ConfigModule, ConfigService } from '@nestjs/config';
import { JwtModule } from '@nestjs/jwt';
import { PassportModule } from '@nestjs/passport';
import { UsersModule } from '../users/users.module';
import authConfig from './auth.config';
import { AuthService } from './auth.service';
import { AuthController } from './auth.controller';
import { JwtStrategy } from './strategies/jwt.strategy';

@Module({
  imports: [
    ConfigModule.forFeature(authConfig),
    PassportModule.register({ defaultStrategy: 'jwt' }),
    JwtModule.registerAsync({
      imports: [ConfigModule],
      inject: [ConfigService],
      useFactory: (configService: ConfigService) => ({
        secret: configService.get<string>('auth.jwtSecret'),
        signOptions: {
          expiresIn: configService.get<string>('auth.jwtExpiresIn'),
        },
      }),
    }),
    UsersModule,
  ],
  controllers: [AuthController],
  providers: [AuthService, JwtStrategy],
  exports: [AuthService],
})
export class AuthModule {}
```

**3. Cara menggunakan JwtStrategy untuk melindungi endpoint:**

```typescript
import { Controller, Get, UseGuards } from '@nestjs/common';
import { AuthGuard } from '@nestjs/passport';

@Controller('protected')
export class ProtectedController {
  @UseGuards(AuthGuard('jwt'))
  @Get()
  getProtectedData() {
    return { message: 'This is protected data' };
  }
}
```

## Analogi

JwtStrategy seperti **satpam di pintu masuk perpustakaan**. Setiap pengunjung yang datang harus menunjukkan kartu anggota (token JWT) yang valid. Satpam memeriksa: (1) apakah kartu ada di header (dari tas coat), (2) apakah stempel di kartu masih berlaku (ignoreExpiration: false), (3) apakah tanda tangan di kartu asli (secret key cocok). Jika semua lolos, satpam mencatat identitas pengunjung di buku tamu (req.user) dan mempersilakan masuk. Jika tidak, pengunjung ditolak dengan pesan "Anda tidak diizinkan masuk" (401 Unauthorized).

## Penggunaan

JwtStrategy digunakan secara global atau per-endpoint untuk melindungi resource dari akses tidak sah. Setiap endpoint yang membutuhkan autentikasi akan menggunakan `AuthGuard('jwt')` atau `JwtAuthGuard` (materi 42). Strategy ini juga menjadi fondasi untuk role-based authorization di materi 45.

## Kesalahan Umum yang Sering Terjadi

1. **Lupa mengimpor UsersModule di AuthModule**: JwtStrategy membutuhkan UsersService. Jika UsersModule tidak diimpor, akan terjadi error dependency injection.
2. **Mengabaikan user yang dihapus (soft delete)**: Di validate(), pastikan user masih aktif dan tidak dihapus. Jika user sudah dihapus, throw UnauthorizedException.
3. **ignoreExpiration: true**: Jangan set ignoreExpiration ke true kecuali Anda punya alasan khusus. Token expired harus ditolak.
4. **Tidak menggunakan SecretOrKeyProvider**: Untuk dynamic key rotation, gunakan secretOrKeyProvider daripada secretOrKey.

## Hubungan dengan Materi Sebelumnya

JwtStrategy menggunakan UsersService (materi 34) untuk memvalidasi bahwa user masih ada di database. ConfigService (materi 35) digunakan untuk membaca jwtSecret. Strategy ini akan digunakan oleh JwtAuthGuard (materi 42) dan menjadi dasar untuk @CurrentUser() decorator (materi 43).

## Soal Latihan

**Soal 1:** Apa yang terjadi jika method `validate()` mengembalikan `null`?

**Jawaban:** Jika `validate()` mengembalikan `null`, Passport akan menganggap autentikasi gagal dan melempar error. NestJS akan mengembalikan response 401 Unauthorized. Oleh karena itu, jika user tidak ditemukan di database, kita harus throw `UnauthorizedException` sebelum return, bukan return null.

**Soal 2:** Bagaimana cara menambahkan validasi tambahan di validate(), misalnya memeriksa apakah user sedang di-banned?

**Jawaban:**

```typescript
async validate(payload: JwtPayload) {
  const user = await this.usersService.findById(payload.sub);

  if (!user) {
    throw new UnauthorizedException('User not found');
  }

  // Validasi tambahan: cek apakah user di-banned
  if (user.isBanned) {
    throw new UnauthorizedException('Your account has been banned');
  }

  return {
    id: user.id,
    email: user.email,
    name: user.name,
    role: user.role,
  };
}
```

**Soal 3:** Apa perbedaan `ExtractJwt.fromAuthHeaderAsBearerToken()` dengan `ExtractJwt.fromHeader()`?

**Jawaban:** `fromAuthHeaderAsBearerToken()` mengekstrak token dari header `Authorization` dengan format `Bearer <token>`. Sedangkan `fromHeader('x-auth-token')` akan mengekstrak token dari custom header `x-auth-token` tanpa prefix "Bearer". Format Bearer adalah standar JWT yang paling umum digunakan dan direkomendasikan oleh OAuth 2.0.
