# 34. Membuat UsersModule - CRUD User & Repository

## Penjelasan

UsersModule adalah modul NestJS yang menangani semua operasi terkait data pengguna. Dengan mengadopsi pola **Repository Pattern**, kita memisahkan logika akses database (repository) dari logika bisnis (service). Pendekatan ini membuat kode lebih terstruktur, mudah di-test, dan fleksibel jika suatu saat kita ingin mengganti Prisma dengan ORM lain.

Dalam implementasi ini, kita akan membuat interface `IUsersRepository` sebagai kontrak, kemudian implementasinya di `PrismaUsersRepository` yang menggunakan PrismaService. UsersService akan bertindak sebagai facade yang menggunakan repository interface. Dengan cara ini, UsersService tidak peduli bagaimana data disimpan — yang penting kontraknya terpenuhi. UsersModule juga akan mengekspor UsersService agar bisa digunakan oleh AuthModule nanti.

## Fungsi

UsersModule berfungsi sebagai pusat manajemen data pengguna. Mulai dari mencari user berdasarkan email atau ID, memperbarui data user (seperti menyimpan refresh token), hingga operasi CRUD dasar. Modul ini menjadi dependency utama bagi AuthModule yang membutuhkan akses ke data user untuk proses autentikasi.

## Cara Implementasi / Code

**1. Interface Repository — `src/users/interfaces/users-repository.interface.ts`:**

```typescript
import { User, Role } from '@prisma/client';

export interface IUsersRepository {
  create(data: {
    email: string;
    password: string;
    name: string;
    role?: Role;
  }): Promise<User>;

  findByEmail(email: string): Promise<User | null>;
  findById(id: number): Promise<User | null>;
  updateRefreshToken(userId: number, refreshToken: string | null): Promise<void>;
}
```

**2. Implementasi Repository — `src/users/prisma-users.repository.ts`:**

```typescript
import { Injectable } from '@nestjs/common';
import { User, Role } from '@prisma/client';
import { PrismaService } from '../prisma/prisma.service';
import { IUsersRepository } from './interfaces/users-repository.interface';

@Injectable()
export class PrismaUsersRepository implements IUsersRepository {
  constructor(private readonly prisma: PrismaService) {}

  async create(data: {
    email: string;
    password: string;
    name: string;
    role?: Role;
  }): Promise<User> {
    return this.prisma.user.create({
      data: {
        email: data.email,
        password: data.password,
        name: data.name,
        role: data.role ?? 'USER',
      },
    });
  }

  async findByEmail(email: string): Promise<User | null> {
    return this.prisma.user.findUnique({
      where: { email },
    });
  }

  async findById(id: number): Promise<User | null> {
    return this.prisma.user.findUnique({
      where: { id },
    });
  }

  async updateRefreshToken(
    userId: number,
    refreshToken: string | null,
  ): Promise<void> {
    await this.prisma.user.update({
      where: { id: userId },
      data: { refreshToken },
    });
  }
}
```

**3. Service — `src/users/users.service.ts`:**

```typescript
import {
  Injectable,
  ConflictException,
  NotFoundException,
} from '@nestjs/common';
import { User } from '@prisma/client';
import { IUsersRepository } from './interfaces/users-repository.interface';
import { PrismaUsersRepository } from './prisma-users.repository';

@Injectable()
export class UsersService {
  constructor(
    private readonly usersRepository: PrismaUsersRepository,
  ) {}

  async create(data: {
    email: string;
    password: string;
    name: string;
  }): Promise<User> {
    const existing = await this.usersRepository.findByEmail(data.email);
    if (existing) {
      throw new ConflictException('Email already registered');
    }
    return this.usersRepository.create(data);
  }

  async findByEmail(email: string): Promise<User | null> {
    return this.usersRepository.findByEmail(email);
  }

  async findById(id: number): Promise<User> {
    const user = await this.usersRepository.findById(id);
    if (!user) {
      throw new NotFoundException('User not found');
    }
    return user;
  }

  async updateRefreshToken(
    userId: number,
    refreshToken: string | null,
  ): Promise<void> {
    await this.usersRepository.updateRefreshToken(userId, refreshToken);
  }
}
```

**4. Module — `src/users/users.module.ts`:**

```typescript
import { Module } from '@nestjs/common';
import { PrismaModule } from '../prisma/prisma.module';
import { UsersService } from './users.service';
import { PrismaUsersRepository } from './prisma-users.repository';

@Module({
  imports: [PrismaModule],
  providers: [
    UsersService,
    {
      provide: 'IUsersRepository',
      useClass: PrismaUsersRepository,
    },
    PrismaUsersRepository,
  ],
  exports: [UsersService],
})
export class UsersModule {}
```

**5. Controller sederhana (opsional) — `src/users/users.controller.ts`:**

```typescript
import { Controller, Get, Param } from '@nestjs/common';
import { UsersService } from './users.service';

@Controller('users')
export class UsersController {
  constructor(private readonly usersService: UsersService) {}

  @Get(':id')
  async findOne(@Param('id', ParseIntPipe) id: number) {
    return this.usersService.findById(id);
  }
}
```

## Analogi

Di perpustakaan, UsersModule adalah **bagian pendaftaran anggota**. Pustakawan di bagian ini (repository) bertugas mencatat data anggota baru ke dalam buku besar (database), mencari data anggota yang sudah ada, dan memperbarui informasi kartu anggota. Sedangkan supervisor bagian pendaftaran (service) memastikan tidak ada data ganda, memvalidasi informasi, dan mengoordinasikan tugas. Modul ini mengekspor "layanan pendaftaran" agar bagian lain seperti "pintu masuk utama" (AuthModule) bisa menggunakannya untuk memverifikasi anggota yang datang.

## Penggunaan

UsersService akan di-inject ke AuthService untuk kebutuhan autentikasi: mencari user saat login, menyimpan refresh token setelah login, dan menghapus refresh token saat logout. UsersModule sendiri perlu diimpor oleh AuthModule.

## Kesalahan Umum yang Sering Terjadi

1. **Tidak mengekspor UsersService**: Jika lupa menambahkan `exports: [UsersService]`, modul lain tidak bisa menggunakan UsersService.
2. **Lupa mengimpor PrismaModule**: UsersModule membutuhkan PrismaService. Pastikan PrismaModule ada di `imports`.
3. **Tidak menangani error duplikasi email**: Validasi email unik harus dilakukan di service layer, bukan hanya mengandalkan constraint database.
4. **Mengembalikan password dalam response**: Pastikan response user tidak menyertakan field password atau refreshToken.

## Hubungan dengan Materi Sebelumnya

Di materi sebelumnya (33), kita membuat model User di Prisma. Sekarang kita membuat module yang akan mengoperasikannya. PrismaModule yang dibuat di Level 2 adalah dependency penting karena menyediakan PrismaService. AuthModule (materi 35) akan mengimpor UsersModule untuk mendapatkan akses ke UsersService.

## Soal Latihan

**Soal 1:** Apa keuntungan menggunakan repository pattern dibandingkan langsung menggunakan PrismaService di service?

**Jawaban:** Repository pattern memberikan abstraksi yang memisahkan logika bisnis dari detail implementasi database. Keuntungannya: (1) lebih mudah di-test karena kita bisa mock repository, (2) jika ingin mengganti Prisma dengan ORM lain, kita hanya perlu membuat implementasi repository baru tanpa mengubah service, (3) kode lebih terstruktur dan mengikuti prinsip Single Responsibility.

**Soal 2:** Jika kita ingin mencari user berdasarkan ID beserta data peminjamannya (relasi), bagaimana cara memodifikasi repository?

**Jawaban:**

```typescript
async findByIdWithBorrowings(id: number): Promise<User | null> {
  return this.prisma.user.findUnique({
    where: { id },
    include: {
      borrowings: true,
    },
  });
}
```

**Soal 3:** Bagaimana cara menghapus user dari database menggunakan Prisma? Tulis kodenya.

**Jawaban:**

```typescript
// Tambahkan di interface
deleteById(id: number): Promise<void>;

// Tambahkan di repository
async deleteById(id: number): Promise<void> {
  await this.prisma.user.delete({
    where: { id },
  });
}
```
