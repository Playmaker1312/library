# 45. Membuat @Roles() Decorator & RolesGuard

## Penjelasan

Setelah autentikasi berhasil (user terbukti siapa dirinya), langkah selanjutnya adalah **otorisasi** — menentukan apa yang boleh dilakukan user berdasarkan role-nya. Di NestJS, kita bisa membuat sistem RBAC (Role-Based Access Control) menggunakan kombinasi custom decorator `@Roles()` dan `RolesGuard`. Decorator `@Roles()` menempelkan metadata role yang diizinkan ke handler, sedangkan `RolesGuard` membaca metadata tersebut dan membandingkannya dengan role user dari request.

Guard ini bekerja setelah JwtAuthGuard — artinya user sudah terautentikasi sebelum dicek role-nya. RolesGuard mengakses `req.user.role` (yang sudah di-set oleh JwtStrategy) dan mencocokkannya dengan role yang diizinkan oleh decorator. Jika role user tidak termasuk dalam daftar, guard akan mengembalikan 403 Forbidden. RolesGuard bisa didaftarkan secara global atau per-endpoint.

## Fungsi

`@Roles()` decorator dan `RolesGuard` berfungsi untuk membatasi akses ke endpoint tertentu hanya untuk user dengan role tertentu. Misalnya, endpoint membuat buku hanya bisa diakses oleh LIBRARIAN dan ADMIN, sedangkan menghapus buku hanya untuk ADMIN. Ini adalah implementasi dari prinsip **least privilege** — setiap user hanya memiliki akses minimum yang diperlukan untuk tugasnya.

## Cara Implementasi / Code

**1. @Roles() Decorator — `src/auth/decorators/roles.decorator.ts`:**

```typescript
import { SetMetadata } from '@nestjs/common';
import { Role } from '@prisma/client';

export const ROLES_KEY = 'roles';

// @Roles(Role.ADMIN, Role.LIBRARIAN)
export const Roles = (...roles: Role[]) => SetMetadata(ROLES_KEY, roles);
```

**2. RolesGuard — `src/auth/guards/roles.guard.ts`:**

```typescript
import {
  Injectable,
  CanActivate,
  ExecutionContext,
  ForbiddenException,
} from '@nestjs/common';
import { Reflector } from '@nestjs/core';
import { Role } from '@prisma/client';
import { ROLES_KEY } from '../decorators/roles.decorator';

@Injectable()
export class RolesGuard implements CanActivate {
  constructor(private readonly reflector: Reflector) {}

  canActivate(context: ExecutionContext): boolean {
    // Baca metadata roles dari decorator @Roles()
    const requiredRoles = this.reflector.getAllAndOverride<Role[]>(ROLES_KEY, [
      context.getHandler(),
      context.getClass(),
    ]);

    // Jika endpoint tidak memiliki @Roles(), izinkan akses
    if (!requiredRoles || requiredRoles.length === 0) {
      return true;
    }

    // Ambil user dari request (sudah di-set oleh JwtStrategy)
    const request = context.switchToHttp().getRequest();
    const user = request.user as { role: Role };

    if (!user) {
      throw new ForbiddenException('User not authenticated');
    }

    // Cek apakah role user termasuk dalam requiredRoles
    const hasRole = requiredRoles.includes(user.role);

    if (!hasRole) {
      throw new ForbiddenException(
        `Access denied. Required role: ${requiredRoles.join(', ')}`,
      );
    }

    return true;
  }
}
```

**3. Daftarkan RolesGuard secara global di AppModule (setelah JwtAuthGuard):**

```typescript
import { Module } from '@nestjs/common';
import { APP_GUARD } from '@nestjs/core';
import { ConfigModule } from '@nestjs/config';
import { PrismaModule } from './prisma/prisma.module';
import { BooksModule } from './books/books.module';
import { UsersModule } from './users/users.module';
import { AuthModule } from './auth/auth.module';
import { JwtAuthGuard } from './auth/guards/jwt-auth.guard';
import { RolesGuard } from './auth/guards/roles.guard';

@Module({
  imports: [
    ConfigModule.forRoot({ isGlobal: true }),
    PrismaModule,
    BooksModule,
    UsersModule,
    AuthModule,
  ],
  providers: [
    {
      provide: APP_GUARD,
      useClass: JwtAuthGuard,
    },
    {
      provide: APP_GUARD,
      useClass: RolesGuard,
    },
  ],
})
export class AppModule {}
```

**5. Penggunaan @Roles() di controller:**

```typescript
import { Controller, Get, Post, Patch, Delete, Body, Param } from '@nestjs/common';
import { Role } from '@prisma/client';
import { Roles } from '../auth/decorators/roles.decorator';
import { Public } from '../auth/decorators/public.decorator';
import { BooksService } from './books.service';

@Controller('books')
export class BooksController {
  constructor(private readonly booksService: BooksService) {}

  @Public() // Semua orang bisa melihat buku
  @Get()
  async findAll() {
    return this.booksService.findAll();
  }

  @Roles(Role.LIBRARIAN, Role.ADMIN) // Hanya pustakawan & admin
  @Post()
  async create(@Body() dto: CreateBookDto) {
    return this.booksService.create(dto);
  }

  @Roles(Role.LIBRARIAN, Role.ADMIN) // Hanya pustakawan & admin
  @Patch(':id')
  async update(@Param('id') id: string, @Body() dto: UpdateBookDto) {
    return this.booksService.update(+id, dto);
  }

  @Roles(Role.ADMIN) // Hanya admin
  @Delete(':id')
  async remove(@Param('id') id: string) {
    return this.booksService.remove(+id);
  }
}
```

## Analogi

Di perpustakaan, sistem role-based authorization seperti **area terbatas** yang hanya bisa dimasuki oleh petugas tertentu:
- **Area publik** (semua buku di rak): Semua pengunjung bisa mengakses — `@Public()`
- **Ruang penyimpanan buku baru** (POST/PATCH buku): Hanya pustakawan (LIBRARIAN) dan kepala perpustakaan (ADMIN) yang boleh masuk — `@Roles(Role.LIBRARIAN, Role.ADMIN)`
- **Ruang arsip & data sensitif** (DELETE buku): Hanya kepala perpustakaan (ADMIN) yang berwenang — `@Roles(Role.ADMIN)`

`@Roles()` decorator adalah **papan nama** di pintu yang bertuliskan "Hanya untuk: Pustakawan, Admin". RolesGuard adalah **satpam** yang berdiri di depan pintu dan memeriksa kartu identitas pengunjung. Jika role-nya sesuai, satpam mempersilakan masuk. Jika tidak, satpam berkata tegas: "Maaf, Anda tidak memiliki akses ke area ini" (403 Forbidden).

## Penggunaan

Role-based authorization digunakan di hampir semua aplikasi yang memiliki tipe pengguna berbeda. Contoh: aplikasi e-commerce (admin, seller, buyer), aplikasi sekolah (admin, guru, siswa), aplikasi rumah sakit (admin, dokter, perawat, pasien), dan aplikasi perpustakaan (admin, librarian, user).

## Kesalahan Umum yang Sering Terjadi

1. **RolesGuard berjalan sebelum JwtAuthGuard**: Jika RolesGuard dipanggil lebih dulu, `req.user` mungkin belum di-set. Pastikan urutan guard benar atau daftarkan JwtAuthGuard lebih dulu.
2. **Lupa menambahkan @Roles() pada endpoint penting**: Endpoint yang tidak memiliki @Roles() akan bisa diakses oleh semua user yang terautentikasi, tanpa memandang role.
3. **Role di metadata tidak konsisten dengan enum**: Pastikan role yang digunakan di decorator sesuai dengan enum Role di Prisma.
4. **Menggunakan string literal 'ADMIN' daripada Role.ADMIN**: Gunakan enum untuk menghindari typo.

## Hubungan dengan Materi Sebelumnya

RolesGuard bergantung pada JwtAuthGuard (materi 42) karena membutuhkan `req.user` yang di-set oleh JwtStrategy (materi 40). Decorator @Roles() menggunakan SetMetadata seperti @Public() (materi 42). Kedua guard ini daftar secara global di AppModule untuk memberikan proteksi berlapis: pertama autentikasi (siapa kamu), lalu otorisasi (apa yang boleh kamu lakukan).

## Soal Latihan

**Soal 1:** Apa perbedaan antara status 401 Unauthorized dan 403 Forbidden?

**Jawaban:** 401 Unauthorized berarti user belum terautentikasi — client tidak mengirim token atau token tidak valid. 403 Forbidden berarti user sudah terautentikasi tapi tidak memiliki hak akses — token valid, role tidak sesuai. Analogi perpustakaan: 401 = "Anda belum menunjukkan kartu anggota", 403 = "Anda sudah punya kartu tapi kartu Anda tidak memiliki akses ke ruangan ini".

**Soal 2:** Bagaimana jika kita ingin endpoint tertentu bisa diakses oleh SEMUA role, termasuk USER?

**Jawaban:** Ada dua opsi: (1) tidak menggunakan @Roles() sama sekali — endpoint bisa diakses semua user terautentikasi, (2) menggunakan `@Roles(Role.USER, Role.LIBRARIAN, Role.ADMIN)` — eksplisit. Opsi 1 lebih sederhana.

**Soal 3:** Bagaimana menambahkan fitur "multiple role check" di mana user harus memiliki SEMUA role yang disebutkan (bukan salah satu)?

**Jawaban:**

```typescript
@Injectable()
export class RolesGuard implements CanActivate {
  constructor(private readonly reflector: Reflector) {}

  canActivate(context: ExecutionContext): boolean {
    const requiredRoles = this.reflector.getAllAndOverride<Role[]>(ROLES_KEY, [
      context.getHandler(),
      context.getClass(),
    ]);

    if (!requiredRoles || requiredRoles.length === 0) {
      return true;
    }

    const request = context.switchToHttp().getRequest();
    const user = request.user as { role: Role[] }; // User memiliki ARRAY role

    // User harus memiliki SEMUA role yang dibutuhkan
    const hasAllRoles = requiredRoles.every((role) =>
      user.role.includes(role),
    );

    if (!hasAllRoles) {
      throw new ForbiddenException('Access denied. You need all required roles.');
    }

    return true;
  }
}
```
