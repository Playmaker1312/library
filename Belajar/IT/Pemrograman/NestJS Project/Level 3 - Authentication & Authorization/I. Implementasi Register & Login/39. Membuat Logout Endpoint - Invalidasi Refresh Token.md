# 39. Membuat Logout Endpoint - Invalidasi Refresh Token

## Penjelasan

Logout adalah endpoint yang menandai berakhirnya session pengguna. Ketika user logout, refresh token yang tersimpan di database harus dihapus (di-set menjadi `null`) agar tidak bisa digunakan lagi untuk mendapatkan access token baru. Ini penting karena meskipun refresh token di sisi client sudah dihapus, token yang tersimpan di database masih valid jika tidak di-invalidasi secara eksplisit.

Proses logout sebenarnya sederhana — kita hanya perlu mengupdate field `refreshToken` user menjadi `null`. Namun, ada yang perlu diperhatikan: endpoint ini membutuhkan autentikasi (user harus login) agar kita tahu user mana yang akan di-logout. Kita perlu mendapatkan user ID dari token JWT yang dikirim di header Authorization. Di sinilah nanti `@CurrentUser()` decorator (materi 43) akan berperan.

## Fungsi

Logout endpoint berfungsi untuk mengakhiri session pengguna secara aman. Dengan menghapus refresh token dari database, user tidak bisa lagi memperpanjang session-nya. Access token yang masih berlaku (belum expired) memang masih bisa digunakan sampai kedaluwarsa, tapi tidak bisa diperpanjang. Ini memberikan kontrol penuh kepada pengguna atas session mereka.

## Cara Implementasi / Code

**1. Update AuthService — tambahkan method logout:**

```typescript
import {
  Injectable,
  ConflictException,
  UnauthorizedException,
  ForbiddenException,
} from '@nestjs/common';
import { ConfigType } from '@nestjs/config';
import { JwtService } from '@nestjs/jwt';
import * as bcrypt from 'bcrypt';
import authConfig from './auth.config';
import { UsersService } from '../users/users.service';
import { RegisterDto } from './dto/register.dto';
import { LoginDto } from './dto/login.dto';
import { RefreshTokenDto } from './dto/refresh-token.dto';

@Injectable()
export class AuthService {
  constructor(
    private readonly usersService: UsersService,
    private readonly jwtService: JwtService,
    @Inject(authConfig.KEY)
    private readonly config: ConfigType<typeof authConfig>,
  ) {}

  // ... register, login, refreshTokens, generateTokens methods ...

  async logout(userId: number) {
    // Hapus refresh token dari database
    await this.usersService.updateRefreshToken(userId, null);
    return { message: 'Logged out successfully' };
  }
}
```

**2. Update AuthController — endpoint logout sementara (manual user ID):**

```typescript
import { Controller, Post, Body, Param } from '@nestjs/common';
import { AuthService } from './auth.service';
import { RegisterDto } from './dto/register.dto';
import { LoginDto } from './dto/login.dto';
import { RefreshTokenDto } from './dto/refresh-token.dto';

@Controller('auth')
export class AuthController {
  constructor(private readonly authService: AuthService) {}

  @Post('register')
  async register(@Body() dto: RegisterDto) {
    return this.authService.register(dto);
  }

  @Post('login')
  async login(@Body() dto: LoginDto) {
    return this.authService.login(dto);
  }

  @Post('refresh')
  async refresh(@Body() dto: RefreshTokenDto) {
    return this.authService.refreshTokens(dto);
  }

  @Post(':userId/logout')
  async logout(@Param('userId', ParseIntPipe) userId: number) {
    return this.authService.logout(userId);
  }
}
```

> **Catatan:** Sementara kita menggunakan `:userId/logout` untuk testing. Setelah `@CurrentUser()` decorator dibuat di materi 43, kita akan mengubahnya menjadi endpoint yang mengambil user ID dari token.

**3. Implementasi logout di sisi client (contoh):**

```typescript
// Pseudocode logout di frontend
async function logout() {
  try {
    const accessToken = localStorage.getItem('accessToken');
    const userId = parseJwt(accessToken).sub;

    await http.post(`/auth/${userId}/logout`, {}, {
      headers: {
        Authorization: `Bearer ${accessToken}`,
      },
    });

    localStorage.removeItem('accessToken');
    localStorage.removeItem('refreshToken');
    window.location.href = '/login';
  } catch (error) {
    // Jika gagal, hapus token lokal tetap dilakukan
    localStorage.removeItem('accessToken');
    localStorage.removeItem('refreshToken');
    window.location.href = '/login';
  }
}
```

## Analogi

Logout di perpustakaan seperti **mengembalikan kartu anggota** ke petugas saat akan pulang. Di meja resepsionis, anggota menyerahkan kartunya. Petugas mencoret data anggota dari daftar session aktif (set refreshToken = null). Setelah itu, jika ada orang lain yang mencoba menggunakan kartu lama untuk masuk, petugas akan menolak karena data di buku besar sudah dihapus. Access token yang masih ada di tangan anggota seperti **stempel di tangan** — masih bisa digunakan selama belum luntur (expired), tapi tidak bisa diperpanjang lagi.

## Penggunaan

Logout endpoint dipanggil saat pengguna menekan tombol "Logout" atau "Keluar" di aplikasi. Setelah logout, semua token di sisi client harus dihapus. Endpoint ini juga berguna untuk fitur "logout dari semua perangkat" — cukup dengan menghapus refresh token dari database.

## Kesalahan Umum yang Sering Terjadi

1. **Hanya menghapus token di client side**: Jika hanya menghapus token dari localStorage tanpa memanggil endpoint logout, refresh token di database masih valid dan bisa digunakan untuk mendapatkan access token baru.
2. **Tidak mengirim token di header**: Logout endpoint harus diautentikasi. Pastikan client mengirim header Authorization.
3. **Tidak menangani error di sisi client**: Jika request logout gagal (misalnya karena network error), user mungkin mengira sudah logout padahal belum. Pastikan client tetap menghapus token lokal.
4. **Lupa endpoint untuk "logout all devices"**: Untuk keamanan, sediakan fitur untuk menginvalidasi semua session user.

## Hubungan dengan Materi Sebelumnya

Logout menggunakan `UsersService.updateRefreshToken` (materi 34) untuk meng-set refreshToken menjadi null. Ini adalah kebalikan dari login (materi 37) yang menyimpan refresh token. Nanti di materi 43, kita akan menyempurnakan endpoint logout dengan menggunakan `@CurrentUser()` decorator sehingga user ID diambil dari token, bukan dari URL parameter.

## Soal Latihan

**Soal 1:** Apa perbedaan antara logout dan expired token?

**Jawaban:** Logout adalah tindakan aktif oleh user untuk mengakhiri session — refresh token dihapus dari database. Expired token adalah kondisi pasif ketika access token mencapai batas waktu kedaluwarsanya — token masih valid di database tetapi sudah tidak bisa digunakan karena signature time check gagal. Setelah logout, refresh token langsung tidak valid. Setelah expired, user bisa mendapatkan token baru melalui refresh token (selama belum logout).

**Soal 2:** Bagaimana cara mengimplementasikan fitur "logout dari semua perangkat"?

**Jawaban:** Cukup dengan meng-set refreshToken menjadi null untuk user ID tertentu. Ini akan menginvalidasi semua refresh token yang pernah diberikan ke user tersebut, sehingga semua perangkat yang menggunakan refresh token tersebut tidak bisa memperpanjang session.

```typescript
async logoutAllDevices(userId: number) {
  await this.usersService.updateRefreshToken(userId, null);
  return { message: 'Logged out from all devices' };
}
```

**Soal 3:** Jika logout tidak pernah dipanggil (user langsung menutup browser), apa risikonya?

**Jawaban:** Refresh token tetap valid di database sampai kedaluwarsa (7 hari). Jika ada pihak ketiga yang berhasil mencuri refresh token (misalnya dari local storage yang tidak aman), mereka bisa mendapatkan access token baru selama refresh token belum kedaluwarsa. Risiko ini bisa dimitigasi dengan menggunakan refresh token rotation (setiap refresh, token lama menjadi invalid) dan memperpendek masa berlaku refresh token.
