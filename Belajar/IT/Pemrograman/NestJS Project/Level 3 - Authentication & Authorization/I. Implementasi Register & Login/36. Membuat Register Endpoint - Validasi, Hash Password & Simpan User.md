# 36. Membuat Register Endpoint - Validasi, Hash Password & Simpan User

## Penjelasan

Register adalah gerbang pertama bagi pengguna baru untuk masuk ke sistem. Endpoint ini menerima data registrasi (email, password, name), memvalidasi input menggunakan DTO (Data Transfer Object) dengan class-validator, memastikan email belum terdaftar, men-hash password dengan bcrypt agar aman disimpan di database, lalu menyimpan user baru ke dalam tabel users. Proses hashing sangat penting karena password tidak boleh disimpan dalam bentuk plain text — jika database bocor, password user tetap aman.

Kita akan menggunakan `class-validator` (yang sudah terintegrasi dengan NestJS) untuk validasi DTO, dan `bcrypt` untuk hashing password. NestJS secara otomatis akan memvalidasi DTO ketika kita menggunakan `ValidationPipe` di main.ts. Hash yang dihasilkan bcrypt bersifat satu arah (one-way), artinya tidak bisa didekripsi kembali — hanya bisa diverifikasi dengan membandingkan hash.

## Fungsi

Register endpoint berfungsi untuk membuat akun pengguna baru. Prosesnya meliputi: validasi format data, pengecekan duplikasi email, hashing password, dan penyimpanan data ke database. Hasil akhirnya adalah user baru dengan role default USER yang siap untuk login.

## Cara Implementasi / Code

**1. RegisterDto — `src/auth/dto/register.dto.ts`:**

```typescript
import { IsEmail, IsString, MinLength, MaxLength } from 'class-validator';

export class RegisterDto {
  @IsEmail()
  email: string;

  @IsString()
  @MinLength(6)
  @MaxLength(50)
  name: string;

  @IsString()
  @MinLength(8)
  @MaxLength(100)
  password: string;
}
```

**2. Update AuthService — tambahkan method register:**

```typescript
import {
  Injectable,
  ConflictException,
  BadRequestException,
} from '@nestjs/common';
import { ConfigType } from '@nestjs/config';
import { JwtService } from '@nestjs/jwt';
import * as bcrypt from 'bcrypt';
import authConfig from './auth.config';
import { UsersService } from '../users/users.service';
import { RegisterDto } from './dto/register.dto';

@Injectable()
export class AuthService {
  constructor(
    private readonly usersService: UsersService,
    private readonly jwtService: JwtService,
    @Inject(authConfig.KEY)
    private readonly config: ConfigType<typeof authConfig>,
  ) {}

  async register(dto: RegisterDto) {
    const existing = await this.usersService.findByEmail(dto.email);
    if (existing) {
      throw new ConflictException('Email already registered');
    }

    const saltRounds = 12;
    const hashedPassword = await bcrypt.hash(dto.password, saltRounds);

    const user = await this.usersService.create({
      email: dto.email,
      password: hashedPassword,
      name: dto.name,
    });

    // Generate tokens langsung setelah registrasi (opsional)
    const tokens = await this.generateTokens(user.id, user.email, user.role);

    await this.usersService.updateRefreshToken(user.id, tokens.refreshToken);

    return {
      user: {
        id: user.id,
        email: user.email,
        name: user.name,
        role: user.role,
      },
      ...tokens,
    };
  }

  async generateTokens(userId: number, email: string, role: string) {
    const payload = { sub: userId, email, role };

    const accessToken = this.jwtService.sign(payload, {
      secret: this.config.jwtSecret,
      expiresIn: this.config.jwtExpiresIn,
    });

    const refreshToken = this.jwtService.sign(payload, {
      secret: this.config.jwtRefreshSecret,
      expiresIn: this.config.jwtRefreshExpiresIn,
    });

    return { accessToken, refreshToken };
  }
}
```

**3. AuthController — `src/auth/auth.controller.ts`:**

```typescript
import { Controller, Post, Body } from '@nestjs/common';
import { AuthService } from './auth.service';
import { RegisterDto } from './dto/register.dto';

@Controller('auth')
export class AuthController {
  constructor(private readonly authService: AuthService) {}

  @Post('register')
  async register(@Body() dto: RegisterDto) {
    return this.authService.register(dto);
  }
}
```

**4. Validasi global di `main.ts`:**

```typescript
import { ValidationPipe } from '@nestjs/common';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);

  app.useGlobalPipes(
    new ValidationPipe({
      whitelist: true,
      forbidNonWhitelisted: true,
      transform: true,
    }),
  );

  await app.listen(3000);
}
bootstrap();
```

## Analogi

Register di perpustakaan seperti **proses pendaftaran anggota baru**. Calon anggota (user) mengisi formulir pendaftaran (RegisterDto) dengan nama, email, dan kata sandi. Pustakawan (AuthService) memeriksa apakah email sudah terdaftar (cek database), lalu mengubah kata sandi menjadi kode rahasia (hash dengan bcrypt) sebelum menyimpannya di buku besar. Setelah selesai, anggota baru mendapat kartu anggota (tokens: access + refresh token) yang bisa langsung digunakan untuk mengakses perpustakaan.

## Penggunaan

Register endpoint digunakan pada halaman pendaftaran aplikasi. Biasanya diakses oleh pengguna baru yang belum memiliki akun. Endpoint ini bersifat public — tidak memerlukan token autentikasi.

## Kesalahan Umum yang Sering Terjadi

1. **Salt rounds terlalu rendah**: bcrypt dengan salt rounds di bawah 10 terlalu cepat dan rentan terhadap brute force. Gunakan minimal 10-12.
2. **Validasi hanya di frontend**: Validasi harus dilakukan di backend juga. Jangan percaya input dari client.
3. **Mengembalikan password dalam response**: Pastikan response tidak menyertakan field `password` atau `refreshToken`.
4. **Tidak menggunakan `whitelist: true` di ValidationPipe**: Property yang tidak ada di DTO akan tetap diproses jika whitelist tidak diaktifkan.

## Hubungan dengan Materi Sebelumnya

Register menggunakan UsersService (materi 34) untuk membuat user dan menyimpan refresh token. Proses hashing menggunakan bcrypt yang sudah diinstal di materi 35. DTO menggunakan class-validator yang merupakan package standar NestJS. Endpoint ini akan dilindungi atau dibuka aksesnya menggunakan JwtAuthGuard di materi 42.

## Soal Latihan

**Soal 1:** Apa itu salt rounds di bcrypt dan apa pengaruhnya terhadap keamanan?

**Jawaban:** Salt rounds adalah jumlah iterasi yang digunakan bcrypt untuk menghasilkan hash. Semakin tinggi salt rounds, semakin lama waktu yang dibutuhkan untuk menghasilkan hash (dan juga untuk brute force). Nilai 12 berarti 2^12 = 4096 iterasi. Nilai yang lebih tinggi lebih aman tapi lebih lambat. Untuk aplikasi produksi, 10-12 adalah angka yang direkomendasikan.

**Soal 2:** Bagaimana cara memastikan bahwa property tambahan yang tidak ada di DTO akan ditolak?

**Jawaban:** Aktifkan option `forbidNonWhitelisted: true` di ValidationPipe. Jika ada property yang tidak didefinisikan di DTO, NestJS akan mengembalikan error 400 Bad Request. Contoh:

```typescript
app.useGlobalPipes(
  new ValidationPipe({
    whitelist: true,
    forbidNonWhitelisted: true,
  }),
);
```

**Soal 3:** Tulis kode untuk menambahkan validasi bahwa password harus mengandung minimal 1 huruf kapital dan 1 angka.

**Jawaban:**

```typescript
import {
  IsEmail,
  IsString,
  MinLength,
  MaxLength,
  Matches,
} from 'class-validator';

export class RegisterDto {
  @IsEmail()
  email: string;

  @IsString()
  @MinLength(6)
  @MaxLength(50)
  name: string;

  @IsString()
  @MinLength(8)
  @MaxLength(100)
  @Matches(/(?=.*[A-Z])(?=.*\d)/, {
    message: 'Password must contain at least one uppercase letter and one number',
  })
  password: string;
}
```
