# 70. Setup Testing Infrastructure - Jest Config & Coverage

## Penjelasan

Testing infrastructure adalah fondasi yang memastikan semua pengujian di NestJS berjalan konsisten, cepat, dan dapat diandalkan. Di tingkat paling dasar, Jest — framework testing bawaan NestJS — membutuhkan konfigurasi yang matang agar test runner mengenali environment, module resolver, dan pola file test yang digunakan. Konfigurasi ini mencakup `jest.config.ts` (atau `package.json` bagian jest), `tsconfig.spec.json` untuk kompilasi TypeScript khusus testing, serta setup file yang menjalankan inisialisasi sebelum seluruh suite test dieksekusi.

Salah satu aspek paling kritis adalah **coverage threshold**. Coverage threshold adalah batas minimum persentase kode yang harus di-cover oleh test. Dengan menetapkan threshold untuk `branches`, `functions`, `lines`, dan `statements`, tim pengembang dapat mempertahankan standar kualitas kode secara otomatis. Jika coverage turun di bawah threshold, pipeline CI akan gagal. Ini mencegah penurunan kualitas secara bertahap dan memaksa setiap kontributor untuk menulis test yang memadai bersamaan dengan fitur baru.

Fitur `collectCoverageFrom` memberikan kontrol granular atas file mana saja yang dimasukkan atau dikecualikan dari laporan coverage. Misalnya, kita bisa mengecualikan file DTO, interface, atau file migrasi yang tidak perlu di-test. Kombinasi `coverageThreshold` dan `collectCoverageFrom` memungkinkan tim untuk fokus pada logika bisnis yang benar-benar membutuhkan pengujian tanpa terganggu oleh boilerplate code.

## Fungsi

- Menyediakan konfigurasi terpusat untuk seluruh test suite (unit, integration, e2e)
- Menetapkan batas minimum coverage yang harus dipenuhi sebelum kode di-deploy
- Mengontrol file mana yang dilaporkan coverage-nya melalui `collectCoverageFrom`
- Mengintegrasikan Jest dengan TypeScript melalui `ts-jest` atau bawaan NestJS
- Menyediakan environment testing yang terisolasi dari environment produksi
- Memungkinkan custom setup dan teardown global melalui `globalSetup`/`globalTeardown`

## Cara Implementasi / Code

### 1. `jest.config.ts` untuk Unit Test

```typescript
// jest.config.ts
import type { Config } from 'jest';

const config: Config = {
  moduleFileExtensions: ['js', 'json', 'ts'],
  rootDir: '.',
  testRegex: '.*\\.spec\\.ts$',
  transform: {
    '^.+\\.(t|j)s$': 'ts-jest',
  },
  collectCoverageFrom: [
    '**/*.(t|j)s',
    '!**/*.module.ts',
    '!**/*.dto.ts',
    '!**/*.entity.ts',
    '!**/*.interface.ts',
    '!**/main.ts',
    '!**/index.ts',
    '!dist/**',
    '!node_modules/**',
    '!coverage/**',
  ],
  coverageDirectory: './coverage',
  coverageReporters: ['text', 'lcov', 'json-summary'],
  coverageThreshold: {
    global: {
      branches: 80,
      functions: 85,
      lines: 85,
      statements: 85,
    },
    './src/books/': {
      branches: 90,
      functions: 90,
      lines: 90,
      statements: 90,
    },
    './src/auth/': {
      branches: 90,
      functions: 90,
      lines: 90,
      statements: 90,
    },
  },
  testEnvironment: 'node',
  moduleNameMapper: {
    '^@/(.*)$': '<rootDir>/src/$1',
  },
  setupFilesAfterSetup: ['<rootDir>/test/setup.ts'],
  verbose: true,
  maxWorkers: 4,
};

export default config;
```

### 2. `tsconfig.spec.json`

```json
{
  "extends": "./tsconfig.json",
  "compilerOptions": {
    "outDir": "./dist",
    "module": "commonjs",
    "types": ["jest", "node"]
  },
  "include": ["src/**/*.spec.ts", "src/**/*.d.ts", "test/**/*.ts"]
}
```

### 3. `test/setup.ts` — Global Setup

```typescript
// test/setup.ts
import { config } from 'dotenv';

// Load environment test variables sebelum semua test
config({ path: '.env.test' });

// Matikan log selama testing untuk mengurangi noise
process.env.NODE_ENV = 'test';

// Mock global jika diperlukan
jest.setTimeout(30000); // 30 detik timeout untuk integration test
```

### 4. Script di `package.json`

```json
{
  "scripts": {
    "test": "jest",
    "test:watch": "jest --watch",
    "test:coverage": "jest --coverage",
    "test:unit": "jest --testPathPattern='\\.spec\\.ts$' --coverage",
    "test:e2e": "jest --config ./test/jest-e2e.config.ts --coverage",
    "test:ci": "jest --coverage --ci --maxWorkers=2 --forceExit"
  }
}
```

### 5. Menjalankan Coverage


## Analogi

Bayangkan perpustakaan ingin memastikan bahwa **setiap rak buku diperiksa secara rutin**. Staf perpustakaan membuat **daftar periksa (checklist)** yang berisi: rak fiksi harus diperiksa 90%, rak non-fiksi 85%, dan seterusnya. Ini adalah **coverage threshold**. Kemudian mereka menentukan **rak mana saja yang masuk daftar periksa** — rak buku langka, rak referensi, dan rak anak-anak — sementara rak kosong dan area administrasi dikecualikan. Ini adalah **collectCoverageFrom**. Jest config adalah **papan pengumuman** yang berisi semua aturan: kapan pemeriksaan dilakukan (testRegex), bagaimana mencatat hasilnya (coverageReporters), dan berapa banyak staf yang dilibatkan (maxWorkers).

## Penggunaan

- Digunakan di awal project untuk menginisialisasi framework testing
- Dipakai di pipeline CI untuk memvalidasi coverage sebelum merge
- Membantu developer memahami area kode mana yang belum di-test
- Menjaga standar kualitas kode secara otomatis tanpa review manual untuk coverage
- Menghemat waktu dengan mengecualikan file boilerplate yang tidak perlu di-test
- Memisahkan konfigurasi testing untuk unit, integration, dan e2e test

## Kesalahan Umum yang Sering Terjadi

1. **Lupa mengecualikan file di `collectCoverageFrom`**: File seperti `main.ts`, module, dan DTO ikut dihitung coverage, menurunkan persentase secara tidak adil. Solusi: gunakan glob pattern negasi (`!**/*.module.ts`).

2. **Threshold terlalu rendah atau terlalu tinggi**: Threshold 50% tidak berguna karena tidak mendorong kualitas. Threshold 100% sering tidak realistis untuk kode yang sulit di-test seperti error boundary. Solusi: mulai dari 80% dan naikkan bertahap.

3. **Tidak membedakan konfigurasi unit vs e2e**: Jest config untuk unit test seharusnya lebih ringan (tanpa database), sementara e2e membutuhkan setup terpisah. Solusi: buat file konfigurasi terpisah (`jest.config.ts` vs `test/jest-e2e.config.ts`).

4. **Mengabaikan moduleNameMapper**: Path alias seperti `@/books/books.service` tidak dikenal Jest tanpa `moduleNameMapper`, menyebabkan error `Cannot find module`. Solusi: selalu sinkronkan path alias dari `tsconfig.json` ke Jest config.

5. **Timeout terlalu pendek**: Integration test yang melibatkan database sering membutuhkan waktu lebih dari 5 detik. Solusi: set `jest.setTimeout(30000)` di setup global.

6. **Tidak menggunakan `--forceExit` di CI**: Jest kadang tidak keluar secara otomatis jika ada handle yang masih terbuka (seperti koneksi database). Solusi: tambahkan `--forceExit` di script CI.

## Hubungan dengan Materi Sebelumnya

Di Level 4 (Microservices & Deployment), kita telah menyiapkan infrastructure produksi seperti Docker, environment variables, dan deployment. Sekarang kita melengkapi infrastruktur tersebut dengan **quality gate** — pengujian otomatis yang memvalidasi bahwa kode yang di-deploy benar-benar berfungsi. Jest config adalah gerbang pertama yang harus dilewati sebelum kita bisa menulis test apa pun. Materi ini menjadi prasyarat untuk seluruh sesi testing selanjutnya, mulai dari unit test (file 71-74) hingga integration test (file 75-76) dan e2e test (file 77-79). Bahkan pipeline CI di file 80 akan bergantung sepenuhnya pada konfigurasi yang kita buat di sini.

## Soal Latihan

**Soal 1:** Buatlah `jest.config.ts` untuk unit test dengan ketentuan berikut:
- Threshold global: lines 85%, branches 80%, functions 85%
- Threshold khusus modul `auth`: 95% untuk semua metric
- Kecualikan folder `migrations/`, `*.dto.ts`, `main.ts`
- Coverage reporter: `text` dan `lcov`

**Jawaban 1:**

```typescript
// jest.config.ts
import type { Config } from 'jest';

const config: Config = {
  moduleFileExtensions: ['js', 'json', 'ts'],
  rootDir: '.',
  testRegex: '.*\\.spec\\.ts$',
  transform: { '^.+\\.(t|j)s$': 'ts-jest' },
  collectCoverageFrom: [
    '**/*.(t|j)s',
    '!**/*.module.ts',
    '!**/*.dto.ts',
    '!**/main.ts',
    '!**/migrations/**',
    '!dist/**',
    '!node_modules/**',
  ],
  coverageDirectory: './coverage',
  coverageReporters: ['text', 'lcov'],
  coverageThreshold: {
    global: {
      branches: 80,
      functions: 85,
      lines: 85,
      statements: 85,
    },
    './src/auth/': {
      branches: 95,
      functions: 95,
      lines: 95,
      statements: 95,
    },
  },
  testEnvironment: 'node',
};

export default config;
```

**Soal 2:** Apa yang terjadi jika coverage suatu service turun di bawah threshold saat `jest --coverage` dijalankan? Jelaskan output dan perilaku Jest.

**Jawaban 2:** Jest akan tetap menyelesaikan semua test dan menghasilkan laporan coverage, tetapi pada akhirnya akan **gagal (exit code non-zero)** dengan pesan kesalahan seperti:

```
Jest: Coverage for lines (83.33%) does not meet global threshold (85%)
Jest: Coverage for functions (75%) does not meet global threshold (80%)
```

Pipeline CI yang mendeteksi exit code non-zero akan menandai build sebagai gagal, mencegah deployment. Ini memaksa developer untuk menulis test tambahan sebelum kode bisa di-merge.
