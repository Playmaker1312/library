# 91. Load Testing dengan k6 - Temukan Bottleneck

## Penjelasan
k6 adalah tool load testing open-source yang ditulis dalam bahasa Go, tetapi script testnya ditulis dalam JavaScript. k6 memungkinkan kita mensimulasikan ribuan virtual users (VUs) yang mengakses API secara simultan untuk mengukur performa sistem. Tiga konsep utama dalam k6 adalah: **stages** (bagaimana jumlah VU berubah seiring waktu), **thresholds** (batas performa yang harus dipenuhi), dan **metrics** (data yang dikumpulkan seperti durasi request, error rate, dan throughput).

Stages terdiri dari tiga fase: **ramp up** (menaikkan VU secara bertahap dari 0 ke target), **stabilize** (mempertahankan VU di target selama beberapa waktu), dan **ramp down** (menurunkan VU kembali ke 0). Pola ini penting karena aplikasi perlu diuji secara bertahap — bukan tiba-tiba dihajar 1000 user — sehingga kita bisa melihat di titik mana performa mulai menurun. Thresholds adalah aturan lulus/gagal seperti `http_req_duration < 200` (95% request harus selesai di bawah 200ms). Metrics yang direkam meliputi `http_req_duration`, `http_req_failed`, `iterations`, dan `vus`.

## Fungsi
- Mengidentifikasi bottleneck performa sebelum aplikasi masuk production
- Menentukan kapasitas maksimal server (berapa request per detik yang bisa ditangani)
- Memvalidasi apakah optimasi (seperti caching, indexing, Fastify) benar-benar meningkatkan performa
- Membuat Service Level Agreement (SLA) berbasis data untuk tim operasional

**Script test dasar — load-test.js:**
```javascript
import http from 'k6/http';
import { check, sleep } from 'k6';
import { Rate, Trend } from 'k6/metrics';

// Custom metrics
const errorRate = new Rate('errors');
const booksTrend = new Trend('books_duration');

export const options = {
  stages: [
    { target: 50, duration: '30s' },   // Ramp up ke 50 VU
    { target: 50, duration: '1m' },    // Stabil di 50 VU
    { target: 100, duration: '30s' },  // Ramp up ke 100 VU
    { target: 100, duration: '1m' },   // Stabil di 100 VU
    { target: 0, duration: '30s' },    // Ramp down
  ],
  thresholds: {
    http_req_duration: ['p(95)<500'], // 95% request < 500ms
    http_req_failed: ['rate<0.01'],   // Error rate < 1%
    errors: ['rate<0.05'],            // Custom error rate < 5%
  },
};

const BASE_URL = 'http://localhost:3000/api';

export default function () {
  // Test GET /books
  const res = http.get(`${BASE_URL}/books?page=1&limit=20`, {
    tags: { endpoint: 'books' },
  });

  // Check response
  check(res, {
    'status is 200': (r) => r.status === 200,
    'response time < 300ms': (r) => r.timings.duration < 300,
  });

  // Record custom metric
  booksTrend.add(res.timings.duration);
  errorRate.add(res.status !== 200);

  sleep(1); // 1 detik jeda antar iterasi
}
```

**Script test skenario realistis — scenario-test.js:**
```javascript
import http from 'k6/http';
import { check, sleep, group } from 'k6';

export const options = {
  scenarios: {
    list_books: {
      executor: 'ramping-vus',
      startVUs: 0,
      stages: [
        { target: 100, duration: '1m' },
        { target: 100, duration: '2m' },
        { target: 0, duration: '30s' },
      ],
      exec: 'listBooks',
    },
    create_loan: {
      executor: 'per-vu-iterations',
      vus: 20,
      iterations: 100,
      startTime: '30s',
      exec: 'createLoan',
    },
  },
  thresholds: {
    'http_req_duration{scenario:list_books}': ['p(95)<200'],
    'http_req_duration{scenario:create_loan}': ['p(95)<500'],
  },
};

export function listBooks() {
  const res = http.get('http://localhost:3000/api/books?page=1&limit=20');
  check(res, { 'list books OK': (r) => r.status === 200 });
  sleep(0.5);
}

export function createLoan() {
  const payload = JSON.stringify({
    bookId: 'cm123...',
    memberId: 'cm456...',
  });
  const res = http.post('http://localhost:3000/api/loans', payload, {
    headers: { 'Content-Type': 'application/json' },
  });
  check(res, { 'loan created': (r) => r.status === 201 });
  sleep(2);
}
```

## Analogi
Bayangkan perpustakaan ingin menguji **seberapa kuat pintu masuknya** menampung pengunjung. Stages seperti: buka pintu bertahap (ramp up) — 10 orang masuk, lalu 20, lalu 50 — lalu biarkan mereka antre (stabil), lalu tutup pintu (ramp down). Thresholds adalah aturan: "antrian tidak boleh lebih dari 5 menit". Metrics seperti: berapa lama rata-rata orang masuk, berapa yang berhasil, berapa yang kecewa dan pulang. Hasilnya menunjukkan apakah perlu **pintu tambahan** (horizontal scaling), **petugas lebih cepat** (query optimization), atau **jalur express untuk anggota** (caching).

## Penggunaan
- Sebelum rilis ke production untuk memvalidasi performa
- Setelah deploy optimasi (index, caching, Fastify) untuk membuktikan peningkatannya
- Dalam pipeline CI/CD untuk mencegah deploy yang menurunkan performa
- Untuk menentukan kapasitas server dan kebutuhan auto-scaling

## Kesalahan Umum yang Sering Terjadi
1. **Test di local vs production** — Local database dengan 10 baris data tidak sama dengan production yang jutaan baris. Selalu test dengan volume data mendekati production.
2. **Tidak memisahkan skenario** — Mencampur test list buku (read-heavy) dengan test peminjaman (write-heavy) dalam satu script tanpa segmentasi metrics.
3. **Threshold terlalu longgar/ketat** — p(95) 5000ms tidak berguna (terlalu longgar), p(95) 50ms tidak realistis untuk aplikasi yang query database.
4. **Skip ramp up** — Langsung 1000 VU dari detik 0 bisa membanjiri koneksi database dan menghasilkan false positive.
5. **Tidak ada sleep time** — Tanpa sleep, VU akan mengirim request secepat mungkin yang tidak realistis. Tambahkan `sleep(1)` atau distribusi think time.

## Hubungan dengan Materi Sebelumnya
Di Level 6 kita sudah mendeploy aplikasi ke server. Sekarang kita perlu menguji apakah aplikasi di server itu sanggup menangani beban nyata. Hasil load testing akan menentukan: apakah kita perlu **caching** (Level 4), **indexing database**, atau **ganti adapter ke Fastify** (materi 92). Load testing adalah pintu gerbang menuju performance optimization.

## Soal Latihan

**Soal:** Buatlah script k6 untuk test endpoint GET `/books/:id` dengan skenario: ramp up ke 50 VU selama 20 detik, stabil 30 detik, ramp down 10 detik. Threshold: p(95) < 300ms dan error rate < 0.5%. Gunakan sleep 1 detik antar request.

**Jawaban:**
```javascript
import http from 'k6/http';
import { check, sleep } from 'k6';

export const options = {
  stages: [
    { target: 50, duration: '20s' },
    { target: 50, duration: '30s' },
    { target: 0, duration: '10s' },
  ],
  thresholds: {
    http_req_duration: ['p(95)<300'],
    http_req_failed: ['rate<0.005'],
  },
};

const BASE_URL = 'http://localhost:3000/api';
const BOOK_ID = 'cm1abc123...';

export default function () {
  const res = http.get(`${BASE_URL}/books/${BOOK_ID}`);

  check(res, {
    'status 200': (r) => r.status === 200,
    'duration < 300ms': (r) => r.timings.duration < 300,
  });

  sleep(1);
}
```
