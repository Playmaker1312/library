# 95. Buat Books Microservice - NestJS Transport TCP

## Penjelasan
NestJS menyediakan dukungan microservices melalui package `@nestjs/microservices`. Service dapat berkomunikasi menggunakan berbagai transport layer, termasuk **TCP** (sederhana, cocok untuk komunikasi internal), **Redis**, **RabbitMQ**, **Kafka**, **gRPC**, dan **NATS**. Untuk service internal seperti Books Service, TCP adalah pilihan ideal karena ringan, reliable, dan sudah built-in tanpa perlu infrastruktur tambahan.

Books Microservice akan menjadi service mandiri yang berjalan di port 3001, dengan **PrismaService** terhubung ke database books_db sendiri, dan mengekspos method-method via `@MessagePattern()`. Setiap pattern adalah string unik yang mengidentifikasi operasi: `{ cmd: 'get_books' }`, `{ cmd: 'get_book_by_id' }`, `{ cmd: 'create_book' }`, dll. Controller tetap ada, tetapi tidak melayani HTTP request — hanya menangani pesan TCP dari API Gateway. Service ini tidak punya HTTP listener sama sekali.

## Fungsi
- Melayani operasi CRUD Books melalui transport TCP, bukan HTTP
- Mengisolasi data buku di database sendiri (data isolation)
- Berjalan sebagai proses mandiri yang bisa di-scale terpisah
- Menggunakan MessagePattern sebagai kontrak API antar service

**1. Membuat project microservice:**

**2. main.ts — Bootstrap microservice TCP:**
```typescript
import { NestFactory } from '@nestjs/core';
import { MicroserviceOptions, Transport } from '@nestjs/microservices';
import { BooksModule } from './books.module';

async function bootstrap() {
  const app = await NestFactory.createMicroservice<MicroserviceOptions>(
    BooksModule,
    {
      transport: Transport.TCP,
      options: {
        host: '0.0.0.0',
        port: 3001,
      },
    },
  );

  await app.listen();
  console.log('Books Microservice is running on TCP port 3001');
}
bootstrap();
```

**3. books.controller.ts — MessagePattern handler:**
```typescript
import { Controller } from '@nestjs/common';
import { MessagePattern, Payload } from '@nestjs/microservices';
import { BooksService } from './books.service';

@Controller()
export class BooksController {
  constructor(private readonly booksService: BooksService) {}

  @MessagePattern({ cmd: 'get_books' })
  async getBooks(@Payload() payload: { page: number; limit: number }) {
    return this.booksService.findAll(payload.page, payload.limit);
  }

  @MessagePattern({ cmd: 'get_book_by_id' })
  async getBookById(@Payload() payload: { id: string }) {
    return this.booksService.findById(payload.id);
  }

  @MessagePattern({ cmd: 'create_book' })
  async createBook(@Payload() payload: {
    title: string;
    author: string;
    isbn: string;
    categoryId: string;
  }) {
    return this.booksService.create(payload);
  }

  @MessagePattern({ cmd: 'update_book' })
  async updateBook(
    @Payload() payload: {
      id: string;
      data: { title?: string; author?: string };
    },
  ) {
    return this.booksService.update(payload.id, payload.data);
  }

  @MessagePattern({ cmd: 'delete_book' })
  async deleteBook(@Payload() payload: { id: string }) {
    return this.booksService.delete(payload.id);
  }

  @MessagePattern({ cmd: 'search_books' })
  async searchBooks(@Payload() payload: { query: string }) {
    return this.booksService.search(payload.query);
  }
}
```

**4. books.service.ts — Business logic dengan Prisma:**
```typescript
import { Injectable, NotFoundException } from '@nestjs/common';
import { PrismaClient } from '@prisma/client';

@Injectable()
export class BooksService {
  private prisma = new PrismaClient();

  async findAll(page: number = 1, limit: number = 20) {
    const skip = (page - 1) * limit;
    const [data, total] = await Promise.all([
      this.prisma.book.findMany({
        skip,
        take: limit,
        include: { category: true },
        orderBy: { createdAt: 'desc' },
      }),
      this.prisma.book.count(),
    ]);

    return {
      data,
      meta: { page, limit, total, totalPages: Math.ceil(total / limit) },
    };
  }

  async findById(id: string) {
    const book = await this.prisma.book.findUnique({
      where: { id },
      include: { category: true },
    });
    if (!book) throw new NotFoundException(`Book ${id} not found`);
    return book;
  }

  async create(data: {
    title: string;
    author: string;
    isbn: string;
    categoryId: string;
  }) {
    return this.prisma.book.create({
      data,
      include: { category: true },
    });
  }

  async update(id: string, data: { title?: string; author?: string }) {
    await this.findById(id); // throw if not found
    return this.prisma.book.update({
      where: { id },
      data,
      include: { category: true },
    });
  }

  async delete(id: string) {
    await this.findById(id); // throw if not found
    return this.prisma.book.delete({ where: { id } });
  }

  async search(query: string) {
    return this.prisma.book.findMany({
      where: {
        OR: [
          { title: { contains: query, mode: 'insensitive' } },
          { author: { contains: query, mode: 'insensitive' } },
        ],
      },
      include: { category: true },
    });
  }
}
```

## Analogi
Bayangkan Books Microservice sebagai **Bagian Katalog** di perpustakaan — sebuah ruangan terpisah dengan pintu khusus (TCP port 3001) dan lemari arsip sendiri (database books_db). Di dalam ruangan ada pustakawan (BooksController) yang tidak melayani pengunjung langsung (tidak ada HTTP endpoint). Sebagai gantinya, ia menerima **surat perintah** (MessagePattern) dari meja informasi utama (API Gateway) melalui tabung pneumatik (TCP). Surat itu berisi perintah seperti "cari buku dengan judul Laskar Pelangi". Pustakawan mencari di lemari arsip (Prisma query) dan mengirimkan hasilnya kembali melalui tabung yang sama.

## Penggunaan
- Service yang perlu di-scale terpisah karena beban baca/tulis yang berbeda dari service lain
- Service yang memiliki aturan bisnis kompleks dan perlu diisolasi dari service lain
- Komunikasi internal antar service dalam satu cluster (bukan untuk publik)
- Service yang harus independen dalam hal database, deployment, dan versioning

## Kesalahan Umum yang Sering Terjadi
1. **Lupa install @nestjs/microservices** — `NestFactory.createMicroservice` tidak akan dikenali.
2. **Port bentrok** — Pastikan Books Service (3001), Users (3002), Loans (3003) menggunakan port berbeda.
3. **MessagePattern tidak match** — Jika client mengirim `{ cmd: 'getBooks' }` tetapi server mengharapkan `{ cmd: 'get_books' }`, akan timeout. Buat kontrak pattern sebagai konstanta bersama.
4. **Error handling** — Exception seperti `NotFoundException` harus ditangani; jika tidak, response error tidak akan sampai ke client. Gunakan `catch` atau filter.
5. **Tidak menutup koneksi Prisma** — Setiap panggilan `new PrismaClient()` di service membuat koneksi baru. Gunakan singleton PrismaService seperti di Level 2.

## Hubungan dengan Materi Sebelumnya
Di materi 94 kita mengidentifikasi service boundaries. Sekarang kita implementasi service pertama — Books Service — yang tadinya hanya module di monolith NestJS, kini menjadi microservice mandiri dengan database sendiri. Prisma schema, service, dan repository pattern dari Level 2 masih berlaku, hanya saja transportnya berubah dari HTTP ke TCP. Selanjutnya (materi 96), API Gateway akan mengirim request ke service ini.

## Soal Latihan

**Soal:** Buatlah `MessagePattern` handler baru di BooksController untuk pattern `{ cmd: 'get_books_by_category' }` yang menerima payload `{ categoryId: string, page: number, limit: number }`. Implementasi di BooksService: query buku berdasarkan categoryId dengan pagination.

**Jawaban:**
```typescript
// books.controller.ts — tambahkan handler
@MessagePattern({ cmd: 'get_books_by_category' })
async getBooksByCategory(
  @Payload() payload: { categoryId: string; page: number; limit: number },
) {
  return this.booksService.findByCategory(
    payload.categoryId,
    payload.page,
    payload.limit,
  );
}
```
