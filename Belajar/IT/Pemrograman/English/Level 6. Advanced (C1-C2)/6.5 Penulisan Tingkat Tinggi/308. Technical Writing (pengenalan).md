# 308. Technical Writing (Pengenalan)

## Definisi & Target
Mempelajari dasar-dasar technical writing — penulisan yang menjelaskan informasi kompleks secara jelas, akurat, dan efisien. Target: mampu menulis dokumentasi teknis, manual, dan instruksi yang user-friendly.

## Analogi
Seperti memasang furnitur IKEA — instruksi harus jelas, urut, dan tidak ambigu, karena pembaca hanya ingin hasil akhir tanpa kebingungan.

## Poin-Poin Penting
1. **Principles**: 
   - *Clarity*: satu interpretasi, bukan dua
   - *Accuracy*: informasi benar dan terkini
   - *Conciseness*: sesingkat mungkin tanpa kehilangan makna
   - *Accessibility*: mudah dipahami target audiens
2. **Common documents**: user manual, API documentation, SOP, white paper, proposal
3. **Audience analysis**: siapa pembaca? — beginner, intermediate, expert?
4. **Structure**: 
   - Task-oriented: langkah demi langkah
   - Heading hierarchy: H1, H2, H3 yang logis
   - Visuals: diagram, screenshot, flowchart
5. **Style**: 
   - Active voice: *"Click the button"* bukan *"The button should be clicked"*
   - Imperative mood: *"Install the software"*
   - Consistent terminology: jangan berganti-ganti istilah

## Struktur Penulisan
- **Title**: clear and descriptive
- **Overview**: what this document covers
- **Prerequisites**: what user needs before starting
- **Step-by-step instructions**: numbered, one action per step
- **Troubleshooting**: common problems and solutions
- **Glossary**: define technical terms

## Contoh
- **Good**: *"Open the Settings menu. Select Network. Click Wi-Fi."* — imperative, clear, active
- **Bad**: *"The user should open the settings menu and then the network option should be selected, after which clicking on Wi-Fi is recommended."* — passive, wordy, unclear
- **Audience-specific**: Untuk developer: *"Implement the getData() method."* Untuk end-user: *"To view your data, click the Download button."*

## Latihan
1. Tulis instruksi 5 langkah untuk tugas sederhana (membuat kopi, install app).
2. Ubah kalimat passive ke active: *"The file should be saved before closing."*
3. Analisis satu technical document — apa yang baik dan apa yang kurang?
4. Tulis glossary untuk 5 istilah teknis di bidangmu.
5. Buat audience analysis untuk: dokumentasi API vs user manual.
