Structural Patterns - Decorator OOP dengan TypeScript **Definisi Singkat:** Decorator menambahkan behavior baru ke objek secara dinamis tanpa mengubah struktur kelas yang sudah ada. **Analogi:** Decorator seperti stiker pada laptop—Anda menambahkan stiker tanpa mengubah fungsi laptop, tapi tampilannya berubah. **Poin-Poin Penting:** - Menggunakan komposisi, bukan inheritance - Setiap decorator mengimplementasikan interface yang sama - Decorator membungkus decorator lain (chain) **Contoh Kode:** ```typescript // BENAR: interface Coffee { cost(): number; description(): string; } class SimpleCoffee implements Coffee { cost() { return 10; } description() { return "Simple coffee"; } } class MilkDecorator implements Coffee { constructor(private coffee: Coffee) {} cost() { return this.coffee.cost() + 2; } description() { return this.coffee.description() + ", milk"; } } class SugarDecorator implements Coffee { constructor(private coffee: Coffee) {} cost() { return this.coffee.cost() + 1; } description() { return this.coffee.description() + ", sugar"; } } const coffee = new SugarDecorator(new MilkDecorator(new SimpleCoffee())); console.log(coffee.description()); // "Simple coffee, milk, sugar" // ERROR: class BadDecorator { // Tidak implement Coffee, error kompilasi } ``` **Kasus Penggunaan Nyata:** Middleware di Express.js, logging, caching, atau authorization layer yang ditambahkan secara bertumpuk.
