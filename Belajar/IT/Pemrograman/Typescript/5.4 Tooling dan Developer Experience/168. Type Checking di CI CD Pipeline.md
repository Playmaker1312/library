# 168. Type Checking di CI CD Pipeline

**Definisi Singkat:** Type checking di CI/CD memastikan bahwa semua kode TypeScript lolos pemeriksaan tipe sebelum di-merge atau di-deploy, biasanya dengan `tsc --noEmit`.

**Analogi:** Seperti pemeriksaan keamanan di bandara — sebelum naik pesawat (deploy), setiap penumpang (kode) harus melewati pemeriksaan (type check) untuk memastikan tidak ada barang berbahaya (bug).

**Poin-Poin Penting:**
- Gunakan `tsc --noEmit` untuk type checking saja (tanpa output file)
- Jalankan setelah install dependencies
- Cache node_modules dan .tsbuildinfo untuk mempercepat
- Gunakan GitHub Actions, GitLab CI, atau tools CI lainnya
- Bedakan antara dev (type checking ringan) dan CI (full strict)

**Contoh Kode:**
```yaml
# .github/workflows/typecheck.yml
name: Type Check
on: [push, pull_request]
jobs:
  typecheck:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
      - run: npm ci
      - run: npx tsc --noEmit
```

```bash
# Type check saja
npx tsc --noEmit

# Dengan incremental cache
npx tsc --noEmit --incremental

# BENAR: CI gagal jika ada error tipe
# ERROR: lupa install dependencies -> tsc error module not found
```

**Kasus Penggunaan Nyata:** Mencegah kode dengan error tipe masuk ke branch utama, menjaga kualitas kode di setiap pull request.
