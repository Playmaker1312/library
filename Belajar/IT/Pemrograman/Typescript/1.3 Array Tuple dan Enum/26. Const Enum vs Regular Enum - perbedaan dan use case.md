# 26. Const Enum vs Regular Enum - perbedaan dan use case

**Definisi Singkat:** `const enum` dihapus saat kompilasi (zero-cost) — nilai enum langsung di-inline ke kode. Regular enum tetap sebagai objek JS di runtime.

**Analogi:** Regular enum seperti buku resep yang dibawa ke dapur (objek utuh). Const enum seperti menghafal resep — Anda hanya mengingat angka/nilai yang diperlukan, bukunya tidak perlu dibawa.

**Poin-Poin Penting:**
- `const enum` tidak menghasilkan kode JS — nilai di-inline: `Color.Red` jadi `0` langsung
- Regular enum menghasilkan objek JS — punya reverse mapping untuk numeric
- `const enum` tidak bisa digunakan di `--isolatedModules` (bundle modern) tanpa `isolatedDeclarations`

**Contoh Kode:**
```typescript
// Contoh yang BENAR (valid) - const enum:
const enum Direction { Up = 1, Down = 2 }
let dir = Direction.Up; // JS: let dir = 1; (inline)

// Regular enum:
enum DirectionReg { Up = 1, Down = 2 }
let dirReg = DirectionReg.Up; // JS: tetap objek DirectionReg

// Contoh yang akan ERROR:
const enum Color { Red = "RED", Blue = "BLUE" }
Color.Red = "PINK"; // /* error: Cannot assign to 'Red' because it is a constant */
```

**Kasus Penggunaan Nyata:**
Library/utility dengan banyak enum — `const enum` mengurangi bundle size karena enum tidak ikut di-output, cocok untuk library yang dipakai banyak aplikasi.
