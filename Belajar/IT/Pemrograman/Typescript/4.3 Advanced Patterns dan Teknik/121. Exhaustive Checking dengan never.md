# 121. Exhaustive Checking dengan never

**Definisi Singkat:** Menggunakan tipe `never` untuk memastikan semua kemungkinan dalam union type sudah ditangani (exhaustive checking) oleh switch-case atau if-else.

**Analogi:** Seperti petugas bandara yang mencocokkan tiket — dia harus menangani semua tujuan (union) yang terdaftar; jika ada tujuan baru yang tidak ada di daftar, sistem harus memberi peringatan.

**Poin-Poin Penting:**
- Variabel bertipe `never` setelah exhaustive check mengkonfirmasi semua kasus tertangani
- Jika ada anggota union baru yang tidak ditangani, kompiler akan error
- Pola ini bisa menggunakan fungsi helper `assertNever`

**Contoh Kode:**
```typescript
type Action =
  | { type: "ADD"; payload: number }
  | { type: "REMOVE"; payload: number }
  | { type: "RESET" };

// BENAR: exhaustive check
function reducer(action: Action): number {
  switch (action.type) {
    case "ADD":
      return action.payload;
    case "REMOVE":
      return -action.payload;
    case "RESET":
      return 0;
    default:
      // exhaustive check — jika semua case tertangani, action di sini adalah never
      const _exhaustive: never = action;
      return _exhaustive; // ✅
  }
}

// ERROR: jika ada case yang terlewat, misalnya RESET tidak ditangani
// Maka _exhaustive akan error karena action masih bertipe RESET
```

**Kasus Penggunaan Nyata:** Reducer dalam state management (Redux), state machine handler, atau command pattern di mana setiap kode baru harus ditangani secara eksplisit.
