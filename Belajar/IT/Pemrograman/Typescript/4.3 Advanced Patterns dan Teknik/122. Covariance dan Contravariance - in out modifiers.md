# 122. Covariance dan Contravariance - in out modifiers

**Definisi Singkat:** Covariance (tipe mengikuti arah yang sama) dan contravariance (tipe mengikuti arah berlawanan) mengatur hubungan subtype antar generic types. `in` = contravariant, `out` = covariant.

**Analogi:** Covariance seperti mengambil buah dari keranjang — jika keranjang berisi apel, kamu bisa mengambil buah (apel adalah buah). Contravariance seperti memasukkan buah ke keranjang — jika keranjang untuk buah, kamu bisa memasukkan apel (buah bisa menerima apel).

**Poin-Poin Penting:**
- `out` (covariant): tipe hanya di posisi output (return type) — `Producer<T>` bisa dianggap `Producer<Parent>` jika `Child extends Parent`
- `in` (contravariant): tipe hanya di posisi input (parameter) — `Consumer<T>` bisa dianggap `Consumer<Child>` jika `Child extends Parent`
- `in out` (invariant): tipe di kedua posisi — tidak bisa variance

**Contoh Kode:**
```typescript
// BENAR: covariant dengan out
interface Producer<out T> {
  produce(): T;
}

// BENAR: contravariant dengan in
interface Consumer<in T> {
  consume(value: T): void;
}

class Animal {}
class Dog extends Animal {}

const dogProducer: Producer<Dog> = { produce: () => new Dog() };
const animalProducer: Producer<Animal> = dogProducer; // ✅ covariance

const animalConsumer: Consumer<Animal> = { consume: (a: Animal) => {} };
const dogConsumer: Consumer<Dog> = animalConsumer; // ✅ contravariance

// ERROR: tanpa in/out, generic bersifat invariant
// interface Box<T> { value: T; }
// const boxDog: Box<Dog> = { value: new Dog() };
// const boxAnimal: Box<Animal> = boxDog; // ❌ invariant
```

**Kasus Penggunaan Nyata:** Mendesain API library dengan variance yang benar — misalnya `ReadonlyArray<T>` bersifat covariant (`out`), `Promise<T>` juga covariant.
