# 136. Namespaces - dan mengapa jarang dipakai sekarang

**Definisi Singkat:** Namespaces (dulu disebut internal modules) adalah cara TypeScript mengorganisir kode sebelum ES Modules populer. Kini jarang dipakai karena ES Modules sudah menjadi standar.

**Analogi:** Seperti laci dokumen di dalam satu ruangan — dulu semua dokumen dalam satu laci, sekarang lebih baik disimpan di ruangan berbeda (module files).

**Poin-Poin Penting:**
- Namespaces membuat kode tetap dalam satu file global
- Tidak mendukung code splitting dan tree-shaking
- ES Modules lebih unggul dalam hal isolasi dan dependency management
- Namespaces masih berguna untuk konfigurasi global sederhana

**Contoh Kode:**
```typescript
// Namespace (cara lama - tidak disarankan)
namespace MyApp {
  export interface User { name: string; }
  export function greet(u: User) { console.log(u.name); }
}

// BENAR: namespace bisa dipakai
MyApp.greet({ name: 'Alice' });

// ES Modules (cara modern - disarankan)
// user.ts
export interface User { name: string; }
export function greet(u: User) { console.log(u.name); }

// ERROR: namespace tidak bisa di-split ke file berbeda
// secara native tanpa triple-slash directive
```

**Kasus Penggunaan Nyata:** Namespaces hanya disarankan untuk proyek kecil non-module atau saat migrasi kode lama ke TypeScript.
