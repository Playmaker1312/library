# 171. Typing Functional Components - React.FC vs explicit

**Definisi Singkat:** Dua cara utama untuk men-tipe functional components di React: menggunakan `React.FC` (Function Component) atau mendeklarasikan tipe secara explicit untuk props dan return type.

**Analogi:** Seperti memesan makanan - `React.FC` adalah paket lengkap (sudah termasuk children default), sedangkan explicit typing adalah pesan custom (Anda tentukan sendiri apa yang termasuk).

**Poin-Poin Penting:**
- `React.FC<Props>` otomatis menyertakan `children` (opsional)
- `React.FC` menyertakan tipe return secara implisit (`React.ReactElement | null`)
- Explicit typing memberi kontrol lebih penuh
- `React.FC` tidak lagi direkomendasikan secara default di React 18+
- Explicit: `function Component(props: Props): React.ReactNode { ... }`

**Contoh Kode:**
```typescript
// BENAR: Menggunakan React.FC (cara lama, masih valid)
interface GreetingProps {
  name: string;
}

const Greeting: React.FC<GreetingProps> = ({ name, children }) => {
  return (
    <div>
      <h1>Hello, {name}!</h1>
      {children /* Otomatis tersedia */}
    </div>
  );
};

// BENAR: Explicit typing (direkomendasikan React 18+)
interface GreetingProps {
  name: string;
  children?: React.ReactNode; // Harus didefinisikan manual
}

function Greeting({ name, children }: GreetingProps): React.ReactNode {
  return (
    <div>
      <h1>Hello, {name}!</h1>
      {children}
    </div>
  );
}

// ERROR: React.FC dengan children yang required
interface Props {
  children: React.ReactNode; // React.FC membuatnya opsional
}
const Comp: React.FC<Props> = ({ children }) => <div>{children}</div>;
// children tetap opsional meskipun didefinisikan required!
```

**Kasus Penggunaan Nyata:**
- Explicit typing lebih fleksibel dan menghindari kebingungan tentang `children`
- `React.FC` masih bagus untuk komponen sederhana yang membutuhkan children opsional
- Team dapat memilih konsistensi: pilih satu pendekatan dan gunakan secara konsisten
