# 49. Interface vs Type Alias - perbandingan dan kapan pakai yang mana **Definisi Singkat:** Interface dan type alias memiliki banyak kesamaan tetapi dengan perbedaan perilaku penting dalam extensibility, merging, dan komposisi. **Analogi:** Interface seperti tanah kosong yang bisa diperluas (extends/merge); type seperti patung yang sudah jadi — bentuknya tetap, tidak bisa ditambah lagi. **Poin-Poin Penting:** - Interface bisa declaration merging; type tidak - Interface bisa extends; type pakai intersection (&) - Type bisa merepresentasikan union, tuple, primitif; interface hanya object **Contoh Kode:** ```typescript // BENAR (valid):
// Interface — bisa extends & merging
interface Animal { name: string; }
interface Animal { age: number; } // merging
interface Dog extends Animal { bark(): void; }

// Type — lebih fleksibel untuk komposisi
type Status = "active" | "inactive"; // union
type Pair<T> = [T, T];               // tuple
type FullDog = Animal & { bark(): void };

// ERROR (type-error):
interface User { name: string; }
// type User = { age: number }; // error: Duplicate identifier — tidak bisa merge dengan interface /* error */

// pedoman: pakai interface untuk object publik/API, type untuk union/tuple/utility
``` **Kasus Penggunaan Nyata:** Gunakan `interface` untuk library API / objek yang mungkin diperluas; gunakan `type` untuk union types, intersection types, conditional types, dan utility types.
