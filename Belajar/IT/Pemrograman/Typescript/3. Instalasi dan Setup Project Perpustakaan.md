# 3. Instalasi dan Setup Project Perpustakaan

> 🟢 **Level 1 — Bagian B** | 🧩 **Melanjutkan [[2. Mengapa TypeScript? — Masalah yang Dipecahkan]]**

---

## 1. Penjelasan Singkat & Konsep Dasar

Setelah paham *mengapa* TypeScript ada, sekarang waktunya **membangun fondasi teknis**: memasang tooling agar kita bisa menulis `.ts`, mengompilasi, dan menjalankannya di Node.js.

Konsep kunci yang perlu dipahami sekarang:

```text
Tiga tool yang akan kita pakai:
1. Node.js        → runtime yang menjalankan JavaScript (dan TS hasil kompilasi)
2. TypeScript (tsc) → compiler yang mengubah .ts → .js + type checking
3. ts-node + nodemon → mengeksekusi .ts DILANGSUNG saat development (tanpa file .js)
```

Perbedaan penting:

| Tool | Fungsi | Kapan dipakai |
|---|---|---|
| `tsc` | Kompilasi + type-check | Build/production |
| `ts-node` | Jalankan `.ts` langsung | Development |
| `ts-node` + `nodemon` | Auto-restart saat file berubah | Development (watch mode) |

**SSH ke materi sebelumnya**: materi 2 menunjukkan TS menangkap bug *sebelum runtime*. Untuk merasakan itu, kita butuh compiler yang benar-benar berjalan — itulah tujuan materi ini. Setelah environment siap, materi 4 (`tsconfig.json`) akan mengatur *perilaku* compiler, dan materi 5 mulai menulis tipe.

---

## 2. Fungsi & Kegunaan Utama

- **Menjalankan "loop" TypeScript**: tulis ➝ type-check ➝ jalankan ➝ ulangi. Inilah ritme harian developer TS.
- **Membedakan dependensi "dev" vs "produksi"**: TypeScript, ts-node, nodemon hanya dibutuhkan saat development; output `.js` yang dikompilasi yang dikirim ke production.
- **Mendapatkan type definitions**: `@types/node` menyediakan tipe untuk API Node (`process`, `fs`, `path`, dsb.) sehingga `process.env.PORT` tidak jadi `any`.
- **Membiasakan alur project nyata**: materi 3-7 membangun CLI perpustakaan yang persis akan dibawa terus sampai full-stack (Level 7).

## 3. Contoh Kode & Implementasi (Real-world Example)

### Langkah 1 — Persiapkan Node.js

```bash
node --version    # pastikan minimal Node.js 18 (misal: v20.x.x)
npm --version     # package manager
```

### Langkah 2 — Install TypeScript

```bash
# Opsi global — untuk alat CLI tsc di mana saja
npm install -g typescript
tsc --version     # misal: Version 5.5.x

# Opsi project (REKOMENDASI untuk project nyata)
mkdir perpustakaan-ts
cd perpustakaan-ts
npm init -y
npm install --save-dev typescript
```

> **Mengapa `--save-dev`?** Karena TypeScript hanya dipakai saat development. Setelah di-build, `dist/` berisi `.js` murni yang tidak butuh TypeScript.

### Langkah 3 — Tooling Development

```bash
# Type definitions untuk API Node.js
npm install --save-dev @types/node

# Jalankan .ts langsung tanpa build manual
npm install --save-dev ts-node

# Auto-restart saat file berubah
npm install --save-dev nodemon
```

### Langkah 4 — Struktur & file pertama

```bash
perpustakaan-ts/
├── src/
│   └── index.ts      ← source TypeScript (kita tulis di sini)
├── dist/             ← output JS hasil kompilasi (dibuat otomatis)
├── tsconfig.json     ← (dibuat di materi 4 via npx tsc --init)
└── package.json
```

```typescript
// src/index.ts
console.log("Hello TypeScript!");
```

### Langkah 5 — Jalankan

```bash
# Cara 1: jalankan langsung dengan ts-node
npx ts-node src/index.ts          # → Hello TypeScript!

# Cara 2: development watch (auto-restart)
npx nodemon --exec ts-node src/index.ts
```

### package.json scripts yang direkomendasikan

```json
{
  "scripts": {
    "build": "tsc",
    "build:watch": "tsc --watch",
    "start": "node dist/index.js",
    "dev": "nodemon --exec ts-node src/index.ts",
    "type-check": "tsc --noEmit"
  }
}
```

## 4. Analogi Sederhana

**Sistem Perpustakaan** kembali menjadi kerangka analogi.

Bayangkan pustakawan menulis katalog kartu (kode `.ts`). Kartu-kartu itu belum "dibaca" siapa pun — perlu **proses cetak** menjadi buku fisik (kompilasi ke `.js`) yang bisa diambil pembaca.

- **TypeScript (`tsc`)** = mesin cetak + pemeriksa kualitas di percetakan. Ia memeriksa *apakah kartu tidak cacat* (type-check) lalu mencetaknya menjadi buku (`dist/`).
- **ts-node** = mode "baca langsung dari draf". Pustakawan membacakan langsung isi kartu tanpa perlu menunggu cetak — sempurna untuk latihan cepat di development.
- **nodemon** = pemantau percetakan yang *mencetak ulang otomatis* setiap kali draf diubah, sehingga versi terbaru selalu tersedia.
- **npm (package manager)** = gudang pasokan alat: saat pustakawan butuh mesin baru ("typescript", "@types/node"), `npm` yang mengantarkannya dan mencatat di `package.json`.

Jadi "setup project" = **mengisi gudang dengan semua mesin (npm), lalu memastikan jalur pencetakan (tsc) dan jalur draf (ts-node) berfungsi**.

## 5. Kapan Harus Digunakan (Use Cases)

- **Memulai project TypeScript baru** — selalu lakukan setup dasar sekali di awal project (bukan menyalin seluruh `node_modules`).
- **Development loop yang lancar**: `npm run dev` memakai ts-node+nodemon untuk iterasi cepat.
- **Production**: `npm run build` lalu `npm start` memakai JS murni — lebih cepat, tidak butuh dev dependencies.
- **Type-check di CI/commit**: `npm run type-check` (dipakai terus sampai Level 6, 7).
- **Tim**: skrip tersebut di `package.json` menjadi **kontrak bersama** — semua anggota tim menjalankan perintah yang sama.

---

## 6. Poin-poin Penting & Best Practices

1. **Install TypeScript sebagai devDependency** (`--save-dev`), bukan global, agar versi terkunci per project.
2. **Selalu sediakan `@types/node`** untuk project Node — tanpa itu API Node dianggap `any`.
3. **Pisahkan `src/` (source) dan `dist/` (output)** — atur via `rootDir` & `outDir` di materi 4.
4. **Tambahkan `node_modules` dan `dist` ke `.gitignore`** — jangan pernah commit hasil build.
5. **Gunakan `npm run type-check` (`tsc --noEmit`) sebagai "pintu masuk"** sebelum commit.
6. **Simpan semua perintah di `scripts`** — supaya tim tidak menghafal perintah panjang.
7. **Simpan versi Node di `package.json` (`engines`)** atau `.nvmrc` agar konsisten.

```gitignore
# .gitignore
node_modules/
dist/
*.log
.env
```

## 7. Kesalahan Umum (Common Pitfalls & Anti-patterns)

| Kesalahan | Gejala | Perbaikan |
|---|---|---|
| Install TS global saja | versi beda antar project / CI gagal | `npm install --save-dev typescript` |
| Lupa `@types/node` | `process` error "Cannot find name" atau jadi `any` | `npm install --save-dev @types/node` |
| Jalankan `.ts` dengan `node` | `SyntaxError: Unexpected token ':'` | pakai `ts-node` atau build dulu |
| Commit `node_modules` dan `dist` | repo membengkak, konflik | `.gitignore` |
| Tidak menaruh skrip di `package.json` | perintah ditulis-ulang / tidak konsisten antar anggota tim | tambahkan `scripts` |
| Mengandalkan `tsc src/index.ts` per file | salah karena module resolution & tsconfig dilewati | selalu `npx tsc` (membaca tsconfig) |

## 8. Soal Latihan & Kunci Jawaban

### Soal 1
Buat project TypeScript baru bernama `perpustakaan-ts` dari nol di terminal, install TypeScript + `@types/node` sebagai devDependencies, create file `src/index.ts` berisi `console.log("Perpustakaan aktif!")`, lalu jalankan dengan `ts-node` dan pastikan muncul output. Tuliskan urutan perintah lengkapnya.

### Soal 2
Dalam `package.json` kamu, tambahkan dua skrip:
- `"dev"` yang menjalankan `src/index.ts` dengan nodemon + ts-node.
- `"type-check"` yang menjalankan `tsc --noEmit`.

Jelaskan kenapa kita *tidak* menjalankan `.ts` dengan `node` langsung.

---

### Jawaban & Pembahasan

```bash
# Soal 1
mkdir perpustakaan-ts && cd perpustakaan-ts
npm init -y
npm install --save-dev typescript @types/node ts-node nodemon

# Buat folder & file
mkdir src
# (buat src/index.ts berisi console.log("Perpustakaan aktif!"))

npx ts-node src/index.ts
# Output: Perpustakaan aktif!
```

```json
// Soal 2 — package.json scripts
{
  "scripts": {
    "dev": "nodemon --exec ts-node src/index.ts",
    "type-check": "tsc --noEmit"
  }
}
```

**Pembahasan kenapa tidak `node src/index.ts`:**
- `node` tidak mengenali sintaks TypeScript (`: number`). File `.ts` harus **dikompilasi dulu** ke `.js` (`npx tsc`) baru bisa dieksekusi Node.
- `ts-node` melakukannya *transparan* untuk development, namun untuk production kita tetap memakai `tsc` (build ke `dist/`) lalu `node dist/index.js` — lebih cepat dan memisahkan dev/dev & production.
