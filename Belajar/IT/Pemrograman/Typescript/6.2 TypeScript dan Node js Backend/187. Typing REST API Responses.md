# 187. Typing REST API Responses

**Definisi Singkat:** Mendefinisikan tipe yang jelas untuk response API REST, memastikan konsistensi format response dan memudahkan konsumsi API di client.

**Analogi:** Seperti format surat resmi - semua response API harus memiliki struktur yang sama (status, data, pesan) agar penerima tahu cara membacanya tanpa kebingungan.

**Poin-Poin Penting:**
- Definisikan interface untuk setiap response API
- Gunakan generic untuk wrapper response standar
- Bedakan antara success response dan error response
- `Express.Response<ResBody>` untuk men-tipe response body
- Dokumentasi otomatis dari type definitions

**Contoh Kode:**
```typescript
import express, { Request, Response } from 'express';

const app = express();

// BENAR: Wrapper response standar dengan generic
interface ApiResponse<T = never> {
  success: boolean;
  message: string;
  data: T;
  timestamp: string;
}

interface PaginatedResponse<T> extends ApiResponse<T[]> {
  pagination: {
    page: number;
    limit: number;
    total: number;
    totalPages: number;
  };
}

interface ErrorResponse extends ApiResponse<null> {
  success: false;
  errorCode: string;
  details?: Record<string, string[]>;
}

// Tipe data untuk resource
interface User {
  id: string;
  name: string;
  email: string;
  role: 'admin' | 'user';
  createdAt: Date;
}

interface Product {
  id: string;
  name: string;
  price: number;
  category: string;
}

// BENAR: Route dengan typed response
// GET /api/users/:id
app.get('/api/users/:id', (
  req: Request<{ id: string }>,
  res: Response<ApiResponse<User> | ErrorResponse>
) => {
  const { id } = req.params;
  
  // Simulasi: Cari user di database
  const user: User | undefined = {
    id,
    name: 'John Doe',
    email: 'john@example.com',
    role: 'user',
    createdAt: new Date()
  };
  
  if (!user) {
    return res.status(404).json({
      success: false,
      message: 'User not found',
      data: null,
      timestamp: new Date().toISOString(),
      errorCode: 'USER_NOT_FOUND'
    });
  }
  
  res.json({
    success: true,
    message: 'User retrieved successfully',
    data: user,
    timestamp: new Date().toISOString()
  });
});

// BENAR: Paginated response
app.get('/api/products', (
  req: Request<{}, {}, {}, { page?: string; limit?: string }>,
  res: Response<PaginatedResponse<Product> | ErrorResponse>
) => {
  const page = parseInt(req.query.page || '1');
  const limit = parseInt(req.query.limit || '10');
  
  const products: Product[] = [
    { id: '1', name: 'Laptop', price: 1500, category: 'electronics' },
    { id: '2', name: 'Phone', price: 800, category: 'electronics' }
  ];
  
  res.json({
    success: true,
    message: 'Products retrieved successfully',
    data: products,
    timestamp: new Date().toISOString(),
    pagination: {
      page,
      limit,
      total: 100,
      totalPages: 10
    }
  });
});

// ERROR: Response tidak konsisten
app.get('/api/bad-practice', (req, res) => {
  // Kadang mengembalikan langsung, kadang di-wrap
  if (Math.random() > 0.5) {
    res.json({ name: 'John' });  // Tanpa wrapper
  } else {
    res.json({ data: { name: 'John' } });  // Dengan wrapper
  }
  // Client akan bingung!
});
```

**Kasus Penggunaan Nyata:**
- Konsistensi format response di semua endpoint API
- Client dapat mengandalkan tipe response untuk type safety
- Dokumentasi API yang akurat dari type definitions
- Memudahkan testing dan validasi response API
