# 193. Typing Environment Variables - type-safe env

**Definisi Singkat:** Memastikan environment variables memiliki tipe yang benar dan tersedia saat runtime, mencegah bug karena variabel lingkungan yang hilang atau memiliki format salah.

**Analogi:** Seperti pemeriksaan kelengkapan dokumen sebelum perjalanan - Anda memastikan semua dokumen penting (env vars) ada dan valid sebelum berangkat (menjalankan aplikasi).

**Poin-Poin Penting:**
- Gunakan library seperti `zod`, `joi`, atau `envalid` untuk validasi
- Cast `process.env` ke tipe yang aman
- Validasi saat startup - jika ada variabel yang hilang, aplikasi langsung error
- Default values untuk variabel opsional
- Type inference dari schema validasi

**Contoh Kode:**
```typescript
// Install: npm install zod dotenv
// npm install -D @types/node

// BENAR: Validasi dengan Zod (paling populer untuk TypeScript)
import 'dotenv/config';
import { z } from 'zod';

// Definisikan schema untuk environment variables
const envSchema = z.object({
  // Database - required
  DATABASE_URL: z.string().url(),
  
  // Server
  PORT: z.coerce.number().default(3000),
  NODE_ENV: z.enum(['development', 'test', 'production']).default('development'),
  
  // Auth - required
  JWT_SECRET: z.string().min(32),
  JWT_EXPIRES_IN: z.string().default('7d'),
  
  // Third party services
  AWS_ACCESS_KEY_ID: z.string().optional(),
  AWS_SECRET_ACCESS_KEY: z.string().optional(),
  
  // Redis (opsional tapi jika ada, harus valid)
  REDIS_URL: z.string().url().optional()
});

// Infer TypeScript type dari schema
type Env = z.infer<typeof envSchema>;

// Validasi semua env vars saat startup
const result = envSchema.safeParse(process.env);

if (!result.success) {
  console.error('❌ Invalid environment variables:');
  console.error(result.error.format());
  process.exit(1);
}

// Export env yang sudah tervalidasi dan type-safe
export const env: Env = result.data;

// Penggunaan di aplikasi
console.log(env.PORT);           // Tipe: number
console.log(env.NODE_ENV);       // Tipe: 'development' | 'test' | 'production'
console.log(env.JWT_SECRET);     // Tipe: string
console.log(env.AWS_ACCESS_KEY_ID);  // Tipe: string | undefined

// BENAR: Menggunakan envalid (alternatif)
import { str, port, url, bool, cleanEnv } from 'envalid';

export const env2 = cleanEnv(process.env, {
  DATABASE_URL: url(),
  PORT: port({ default: 3000 }),
  NODE_ENV: str({ choices: ['development', 'test', 'production'] }),
  JWT_SECRET: str({ devDefault: 'dev-secret-at-least-32-characters-long' }),
  ENABLE_LOGGING: bool({ default: true })
});
// Tipe otomatis tersedia!
env2.DATABASE_URL;  // string
env2.PORT;          // number
env2.ENABLE_LOGGING;  // boolean

// BENAR: Menggunakan module augmentation untuk process.env
// File: src/types/env.d.ts
declare global {
  namespace NodeJS {
    interface ProcessEnv {
      DATABASE_URL: string;
      PORT: string;
      NODE_ENV: 'development' | 'test' | 'production';
      JWT_SECRET: string;
      // ... lainnya
    }
  }
}

export {};

// Sekarang process.env memiliki autocomplete!
process.env.DATABASE_URL;  // Tipe: string | undefined

// BENAR: Fungsi helper untuk memastikan env var ada
function getRequiredEnv(key: string): string {
  const value = process.env[key];
  if (!value) {
    throw new Error(`Environment variable ${key} is required but not set`);
  }
  return value;
}

function getOptionalEnv(key: string, defaultValue: string): string {
  return process.env[key] || defaultValue;
}

// Penggunaan
const dbUrl = getRequiredEnv('DATABASE_URL');  // Jika hilang -> error
const port = getOptionalEnv('PORT', '3000');   // Jika hilang -> '3000'

// ERROR: Mengakses process.env tanpa validasi
// Masalah 1: Tidak tahu apakah variabel ada
const secret = process.env.JWT_SECRET;  // string | undefined
// Jika JWT_SECRET tidak ada, secret menjadi undefined dan bisa menyebabkan bug halus

// Masalah 2: Semua environment variable bertipe string
const portStr = process.env.PORT;  // string | undefined
const portNum = parseInt(portStr || '3000');  // Perlu parsing manual

// Masalah 3: Tidak ada validasi format
const url = process.env.DATABASE_URL;  // Bisa jadi string kosong atau URL tidak valid
```

**Kasus Penggunaan Nyata:**
- Mencegah deployment dengan konfigurasi yang tidak lengkap
- Validasi format environment variables (URL, number, enum)
- Auto-completion dan type-safety saat mengakses env vars
- Default values untuk development yang aman
- Dokumentasi eksplisit tentang variabel apa yang dibutuhkan aplikasi
