# 194. Error Handling Patterns di Backend TypeScript

**Definisi Singkat:** Pola-pola untuk menangani error secara type-safe di backend TypeScript, termasuk custom error classes, typed error responses, dan consistent error handling middleware.

**Analogi:** Seperti sistem tanggap darurat - setiap jenis bencana (error) memiliki penanganan khusus, kode respon yang jelas, dan pesan yang informatif untuk korban (client API).

**Poin-Poin Penting:**
- Gunakan custom error classes untuk membedakan jenis error
- `instanceof` untuk type narrowing pada catch block
- Middleware error handler di Express/Fastify
- Consistent error response format untuk client
- Type guard untuk membedakan error types

**Contoh Kode:**
```typescript
// BENAR: Custom Error Classes dengan status code
export class AppError extends Error {
  public readonly statusCode: number;
  public readonly isOperational: boolean;

  constructor(message: string, statusCode: number, isOperational = true) {
    super(message);
    this.statusCode = statusCode;
    this.isOperational = isOperational;
    
    // Mempertahankan stack trace
    Error.captureStackTrace(this, this.constructor);
  }
}

// Error spesifik
export class NotFoundError extends AppError {
  constructor(resource: string) {
    super(`${resource} not found`, 404);
  }
}

export class BadRequestError extends AppError {
  constructor(message: string, public readonly details?: Record<string, string[]>) {
    super(message, 400);
  }
}

export class UnauthorizedError extends AppError {
  constructor(message = 'Unauthorized') {
    super(message, 401);
  }
}

export class ForbiddenError extends AppError {
  constructor(message = 'Access forbidden') {
    super(message, 403);
  }
}

export class ConflictError extends AppError {
  constructor(message: string) {
    super(message, 409);
  }
}

// BENAR: Middleware Error Handler di Express
import { Request, Response, NextFunction } from 'express';

interface ErrorResponse {
  success: false;
  message: string;
  errorCode?: string;
  details?: Record<string, string[]>;
  stack?: string;
}

export function errorHandler(
  err: Error | AppError,
  req: Request,
  res: Response<ErrorResponse>,
  next: NextFunction
) {
  // Type narrowing dengan instanceof
  if (err instanceof AppError) {
    return res.status(err.statusCode).json({
      success: false,
      message: err.message,
      ...(err instanceof BadRequestError && err.details && { details: err.details })
    });
  }

  // Error tidak terduga (programming errors)
  console.error('UNEXPECTED ERROR:', err);
  
  // Jangan ekspos detail error internal di production
  const isProduction = process.env.NODE_ENV === 'production';
  
  res.status(500).json({
    success: false,
    message: isProduction ? 'Internal server error' : err.message,
    ...(!isProduction && { stack: err.stack })
  });
}

// BENAR: Penggunaan di route handler
import { Router, Request, Response, NextFunction } from 'express';
import { NotFoundError, BadRequestError, UnauthorizedError } from './errors';

const router = Router();

// Async wrapper untuk menangkap error di async handler
function asyncHandler(
  fn: (req: Request, res: Response, next: NextFunction) => Promise<void>
) {
  return (req: Request, res: Response, next: NextFunction) => {
    Promise.resolve(fn(req, res, next)).catch(next);
  };
}

router.get('/users/:id', asyncHandler(async (req, res) => {
  const { id } = req.params;
  
  // Simulasi pencarian user
  const user = await db.users.findUnique({ where: { id } });
  
  if (!user) {
    throw new NotFoundError(`User with id ${id}`);
  }
  
  res.json({ success: true, data: user });
}));

  const { email, password } = req.body;

// BENAR: Result pattern (alternatif tanpa throw)
interface SuccessResult<T> {
  success: true;
  data: T;
}

interface ErrorResult {
  success: false;
  error: AppError;
}

type Result<T> = SuccessResult<T> | ErrorResult;

// Fungsi yang mengembalikan Result, tidak melempar error
async function findUser(id: string): Promise<Result<User>> {
  const user = await db.users.findUnique({ where: { id } });
  
  if (!user) {
    return {
      success: false,
      error: new NotFoundError(`User ${id}`)
    };
  }
  
  return { success: true, data: user };
}

// Penggunaan dengan type narrowing
async function handleUserRequest(id: string) {
  const result = await findUser(id);
  
  if (result.success) {
    // Type narrowing: result.data bertipe User
    console.log(result.data.name);
  } else {
    // Type narrowing: result.error bertipe AppError
    console.log(result.error.statusCode, result.error.message);
  }
}

// ERROR: Error handling yang buruk
app.get('/bad-practice', async (req, res) => {
  try {
    const data = await riskyOperation();

  } catch (err) {
    // ❌ err bertipe unknown di TypeScript strict mode
    res.status(500).json({ error: err.message });  // Error!
  }
});

// Perbaiki dengan type guard
function isError(err: unknown): err is Error {
  return err instanceof Error;
}

try {
  // ...
} catch (err) {
  if (isError(err)) {
    console.log(err.message);  // Sekarang aman
  }
}
```

**Kasus Penggunaan Nyata:**
- Konsistensi error response untuk semua endpoint API
- Mudah menangani error berdasarkan jenisnya (404, 400, 401, dll)
- Logging error yang terstruktur
- Client API dapat mengandalkan format error yang konsisten
- Membedakan antara operational error dan programming error
