# 197. TypeScript dan Jest - setup dan konfigurasi

**Definisi Singkat:** Cara mengkonfigurasi Jest untuk bekerja dengan TypeScript, termasuk menginstal dependencies, mengatur babel/ts-jest, dan menulis test yang type-safe.

**Analogi:** Seperti memasang alat inspeksi kualitas di pabrik - Jest adalah mesin pemeriksa, dan TypeScript memastikan semua bagian yang diperiksa memiliki spesifikasi yang jelas.

**Poin-Poin Penting:**
- `ts-jest` adalah transformer TypeScript untuk Jest
- `@types/jest` untuk type definitions
- Konfigurasi di `jest.config.js` atau `package.json`
- File test menggunakan `.test.ts` atau `.spec.ts`
- `jest.config.js` perlu mengatur `preset: 'ts-jest'`

**Contoh Kode:**

```typescript
// BENAR: Menulis test untuk fungsi TypeScript
// File: src/math.ts
export function add(a: number, b: number): number {
  return a + b;
}

export function subtract(a: number, b: number): number {
  return a - b;
}

export function multiply(a: number, b: number): number {
  return a * b;
}

export function divide(a: number, b: number): number {
  if (b === 0) {
    throw new Error('Cannot divide by zero');
  }
  return a / b;
}

// File: src/__tests__/math.test.ts
import { add, subtract, multiply, divide } from '../math';

describe('math functions', () => {
  describe('add', () => {
    it('should add two numbers correctly', () => {
      // TypeScript memastikan argumen bertipe number
      const result = add(2, 3);
      expect(result).toBe(5);
    });

    it('should handle negative numbers', () => {
      expect(add(-1, -1)).toBe(-2);
      expect(add(5, -3)).toBe(2);
    });
  });

  describe('subtract', () => {
    it('should subtract two numbers correctly', () => {
      expect(subtract(10, 3)).toBe(7);
    });
  });

  describe('multiply', () => {
    it('should multiply two numbers correctly', () => {
      expect(multiply(4, 5)).toBe(20);
    });
  });

  describe('divide', () => {
    it('should divide two numbers correctly', () => {
      expect(divide(10, 2)).toBe(5);
    });

    it('should throw error when dividing by zero', () => {
      // Menguji error dengan toThrow
      expect(() => divide(10, 0)).toThrow('Cannot divide by zero');
    });
  });
});

// BENAR: Test dengan async/await
// File: src/api.ts
export interface User {
  id: string;
  name: string;
  email: string;
}

export async function fetchUser(id: string): Promise<User> {
  const response = await fetch(`/api/users/${id}`);
  if (!response.ok) {
    throw new Error('Failed to fetch user');
  }
  return response.json();
}

// File: src/__tests__/api.test.ts
import { fetchUser, User } from '../api';

// Mock fetch
global.fetch = jest.fn();

describe('fetchUser', () => {
  const mockUser: User = {
    id: '1',
    name: 'John Doe',
    email: 'john@example.com'
  };

  beforeEach(() => {
    jest.clearAllMocks();
  });

  it('should fetch user successfully', async () => {
    // Mock successful response
    (global.fetch as jest.Mock).mockResolvedValueOnce({
      ok: true,
      json: async () => mockUser
    });

    const result = await fetchUser('1');
    
    expect(result).toEqual(mockUser);
    expect(global.fetch).toHaveBeenCalledWith('/api/users/1');
  });

  it('should throw error when response is not ok', async () => {
    // Mock error response
    (global.fetch as jest.Mock).mockResolvedValueOnce({
      ok: false
    });

    await expect(fetchUser('invalid')).rejects.toThrow('Failed to fetch user');
  });
});

// BENAR: Setup global test (jest.setup.ts)
// import '@testing-library/jest-dom';  // Untuk React testing
// File: jest.config.js tambahkan:
// setupFilesAfterEnv: ['<rootDir>/src/jest.setup.ts']

// ERROR: Test tanpa type safety
// ❌ Jangan lakukan ini!
test('bad test', () => {
  // Menggunakan any menghilangkan type safety
  const result: any = add(2, 3);
  expect(result.nonexistent).toBe(true);  // Tidak ada error compile-time!
});

// ✅ Lebih baik: biarkan TypeScript infer tipe
test('good test', () => {
  const result = add(2, 3);  // Tipe: number
  result.toFixed();  // OK, method number
  result.nonexistent;  // Error! Property tidak ada
});
```

**Kasus Penggunaan Nyata:**
- Menulis unit test untuk fungsi TypeScript dengan type safety
- Memastikan test selalu menggunakan tipe yang benar
- Auto-completion saat menulis assertion (expect(result).toBe(...))
- Refactoring kode akan memunculkan error di test jika ada yang rusak
- Coverage report untuk melihat seberapa banyak kode yang diuji
