# 17. Mapped Types dan Conditional Types

> 🟠 **Level 4 — Bagian H** | 🧩 **Melanjutkan [[16. Built-in Utility Types — Yang Paling Sering Dipakai]]**

---

## 1. Penjelasan Singkat & Konsep Dasar

Materi 16 memperkenalkan utility types *bawaan*. Materi 17 mengajarkan **cara membuat utility types sendiri** lewat dua mekanisme transformasi tipe:

- **Mapped types** — mengiterasi *setiap property* dari sebuah tipe dan mentransformasikannya:
  ```typescript
  type FormErrors<T> = { [K in keyof T]?: string };
  ```

- **Conditional types** — tipe yang hasilnya *bergantung pada kondisi* tipe:
  ```typescript
  type IsString<T> = T extends string ? true : false;
  type Flatten<T> = T extends Array<infer Item> ? Item : T;
  ```

- **`infer`** — kata kunci untuk *mengekstrak* tipe dari dalam tipe lain (misal "bagian dalam" `Array<...>` atau `Promise<...>`).
- **Key remapping (`as`)** — mengubah nama key saat mapping.

**Konsep hubungan**: Mapped types = transformasi *structure object*; Conditional types = transformasi *berdasar kondisi* (sering dikombinasikan: `{ [K in keyof T]: T[K] extends X ? Y : Z }`).

**Benang merah**: dari utility bawaan (materi 16) ke *pembuat* utility sendiri — puncak ekspresi type system di Level 4, yang menjadi dasar API generik yang diramping di Level 5-7.

---

## 2. Fungsi & Kegunaan Utama

- **Membuat `FormErrors<T>`** — untuk setiap field, buat pesan error opsional.
- **`Asyncify<T>`** — membuat semua method jadi async (persiapan layer service di Level 5).
- **`Flatten<T>` / `UnwrapPromise<T>`** — membuka array/promise.
- **Type-safe event map** — mapped types dengan key remapping (`on${K}`) — dipakai di materi 24 (EventEmitter).
- **Conditional types untuk transformasi tipe berbasis kondisi** — pengatur logika compile-time.
- **`infer`** untuk memperoleh tipe dari library/type kompleks tanpa menduplikasi.

## 3. Contoh Kode & Implementasi (Real-world Example)

```typescript
// src/types/advanced.ts

interface Buku {
    id: number;
    judul: string;
    pengarang: string;
    isbn: string;
    tahun: number;
    harga: number;
    stok: number;
    kategori: string;
    deskripsi?: string;
}

// ─── Mapped type: setiap field jadi string ───────────────────────────
type Stringified<T> = { [K in keyof T]: string };

// ─── Mapped type + optional: form errors ─────────────────────────────
type FormErrors<T> = { [K in keyof T]?: string };

type BukuFormErrors = FormErrors<Buku>;
const errors: BukuFormErrors = {
    judul: "Judul wajib diisi",
    isbn: "ISBN harus 13 digit",
    // field lain opsional
};

// ─── Mapped type + kondisi: Asyncify<T> ──────────────────────────────
type Asyncify<T> = {
    [K in keyof T]: T[K] extends (...args: infer A) => infer R
        ? (...args: A) => Promise<R>
        : T[K];
};

// ─── Conditional types dasar ─────────────────────────────────────────
type IsString<T> = T extends string ? true : false;
type CekJudul = IsString<string>;   // true
type CekHarga = IsString<number>;   // false

// ─── Conditional + infer: ekstraksi dari dalam tipe ──────────────────
type Flatten<T> = T extends Array<infer Item> ? Item : T;
type ItemBuku = Flatten<Buku[]>;        // Buku
type ItemStr  = Flatten<string>;        // string (bukan array → as-is)

type UnwrapPromise<T> = T extends Promise<infer U> ? U : T;
type HasilFetch = UnwrapPromise<Promise<Buku[]>>;   // Buku[]
type BukanPro  = UnwrapPromise<string>;             // string

// ─── Key remapping (as) — buat event handler types otomatis ──────────
type Aksi = "tambah" | "update" | "hapus";
type CapitalizeString<S extends string> =
    S extends `${infer First}${infer Rest}`
        ? `${Uppercase<First>}${Rest}` : S;

type EventHandler = {
    [K in Aksi as `on${CapitalizeString<K>}`]: (id: number) => void;
};
// { onTambah: (id: number) => void; onUpdate: ...; onHapus: ... }

// ─── Komposisi: transformasi + kondisi dalam satu mapped type ────────
type NullableFields<T> = { [K in keyof T]: T[K] | null };
type BukuNullable = NullableFields<Buku>;   // setiap field: T[K] | null
```

## 4. Analogi Sederhana

**Sistem Perpustakaan.**

- **Mapped type** = **mesin pengolah formulir massal**: satu kali set "setiap kolom" — misal "semua kolom jadi teks" (`Stringified`), "semua kolom boleh kosong" (`NullableFields`), atau "setiap kolom diberi ruang catatan error" (`FormErrors`). Mesin menyalin *semua* kolom tanpa kamu menulisnya satu per satu.

- **Conditional type** = **kebijakan dua jalur** di pintu masuk: *jika* barang adalah kotak (`Array`), buka kotak & ambil isinya (`infer Item`); *jika* bukan, biarkan apa adanya. Petugas melakukan pemeriksaan "bila X maka ... selain itu ..." — persis pola `T extends X ? A : B`.

- **`infer`** = **pustakawan yang "membongkar" untuk tahu isi**: saat membuka kardus berlabel "Array", ia menyimpulkan isinya (`Item`) tanpa kamu perlu menyebutkannya. Ini ekstraksi otomatis.

- **Key remapping (`as`)** = **menempelkan stempel awalan ke setiap label rak**: "tambah" → `onTambah`, "update" → `onUpdate` — membuat serangkaian rak bernama konsisten dari daftar aksi yang ada.

## 5. Kapan Harus Digunakan (Use Cases)

- **Membuat utility types sendiri** yang transformasinya berulang: `FormErrors<T>`, `Asyncify<T>`, `NullableFields<T>`, `DeepReadonly<T>`.
- **Memberi validasi ke objek dari tipe lain** — misal "untuk setiap field Buku, ada kemungkinan error".
- **`infer` untuk menurunkan tipe dari library/API** — ekstrak isi Promise/Array/tuple tanpa hardcode.
- **Event systems** (materi 24) — mapped + key remapping untuk menghasilkan `on${Event}` handler yang typed.
- **State machine / DTO** — mengubah entitas jadi DTO optional/readonly/nullable untuk berbagai konteks.

---

## 6. Poin-poin Penting & Best Practices

1. **`keyof T` adalah dasar mapped type** — pahami `keyof` (materi 14) sebelum mapping.
2. **Mapped types bisa digabung dengan `?` dan `readonly`** — gunakan saat mau property opsional/immutable.
3. **Conditional types bersifat "distributive"** atas union — `IsString<number | string>` berlaku per anggota.
4. **Gunakan `infer` hanya di conditional types** — dan beri nama yang jelas (`Item`, `A`, `R`).
5. **Jangan berlebihan**: buat utility type bila dipakai berulang & memberi makna; satu-off lebih baik ditulis eksplisit.
6. **Tes dengan contoh kecil**: `type X = MyUtil<Buku>` lalu lihat hover di editor — konfirmasi hasil transformasi.

---

## 7. Kesalahan Umum (Common Pitfalls & Anti-patterns)

| Kesalahan | Contoh | Akibat | Perbaikan |
|---|---|---|---|
| Mapped type tanpa `keyof` | `{ [K in string]: ... }` | index signature longgar | `[K in keyof T]` |
| Conditional type digunakan di luar context `infer` | `infer` di tempat tak valid | TS1308 | hanya di `T extends ... ? ...` |
| Mengira conditional bersifat non-distributive | `IsString<number | string>` | hasil per anggota | pahami distributive |
| Key remapping lupa `as` | `{ [K in Aksi as \`on${...}\`] }` | jadi property biasa | tambahkan `as` |
| Terlalu dalam nesting | utility dalam utility dalam utility | sulit dibaca | pisah & beri nama |
| `never` saat kondisi tidak pernah terpenuhi | conditional type menghasilkan `never` di `false` branch yang tak diharapkan | error aneh di pemakai | beri fallback tipe jelas |

## 8. Soal Latihan & Kunci Jawaban

### Soal 1
Buat mapped type `ReadonlyNullable<T>` di mana setiap property menjadi `readonly T[K] | null`. Terapkan pada `interface Buku` dan buktikan hasil dengan mengisi objek.

### Soal 2
Buat conditional type `IsArray<T>` yang menghasilkan `true` jika `T` adalah array (misal `number[]`), `false` jika bukan. Lalu buat `ElementType<T>` yang mengembalikan elemen array (`infer`). Tes dengan `number[]` dan `string`.

---

### Jawaban & Pembahasan

```typescript
// Soal 1
type ReadonlyNullable<T> = { readonly [K in keyof T]: T[K] | null };

interface Buku { id: number; judul: string; stok: number; }

type BukuRn = ReadonlyNullable<Buku>;
// { readonly id: number | null; readonly judul: string | null; readonly stok: number | null }

const b: BukuRn = { id: 1, judul: "Clean Code", stok: 5 };
// b.id = 2;   // ❌ readonly
```

**Pembahasan**: setiap key di-iterasi, setiap nilai menjadi union dengan `null`, dan seluruhnya dibuat readonly — satu ekspresi untuk seluruh transformasi.

```typescript
// Soal 2
type IsArray<T> = T extends unknown[] ? true : false;
type CekArr = IsArray<number[]>;   // true
type CekStr = IsArray<string>;     // false

type ElementType<T> = T extends Array<infer U> ? U : never;
type El1 = ElementType<number[]>;  // number
type El2 = ElementType<string[]>;  // string
type El3 = ElementType<string>;    // never
```

**Pembahasan**: `IsArray` menyederhanakan union check `unknown[]`; `ElementType` memakai `infer U` untuk mengekstrak tipe elemen — dan untuk input non-array menghasilkan `never` (tidak ada elemen). Ini prinsip dasar yang melandasi `Flatten` dan `Awaited` bawaan TS.
