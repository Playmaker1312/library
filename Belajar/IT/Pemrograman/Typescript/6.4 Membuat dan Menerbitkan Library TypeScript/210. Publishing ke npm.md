# 210. Publishing ke npm

**Definisi Singkat:** Langkah-langkah mempublikasikan package TypeScript ke npm registry, termasuk konfigurasi package.json, build, versioning, dan actual publish.

**Analogi:** Seperti membuka toko online - Anda menyiapkan barang (build package), memberi label (package.json), menetapkan harga (version), dan mendaftarkan toko ke marketplace (npm publish).

**Poin-Poin Penting:**
- Buat akun npm di npmjs.com
- Login dengan `npm login`
- Pastikan `package.json` memiliki `name`, `version`, `main`, `exports`
- Build sebelum publish (`npm run build`)
- Gunakan `npm publish` untuk scoped package, tambahkan `--access public`

**Contoh Kode:**
```typescript
// ========== PERSIAPAN AWAL ==========

// 1. Buat akun di https://www.npmjs.com/signup

// 2. Login ke npm di terminal
// npm login
// Masukkan username, password, dan email

// Cek apakah sudah login
// npm whoami

// ========== KONFIGURASI PACKAGE.JSON ==========

// ✅ BENAR: package.json untuk publish
{
  // Nama package (harus unik di npm)
  // Gunakan scope untuk organisasi/user: @username/package-name
  "name": "@johndoe/my-awesome-library",
  
  // Versi mengikuti SemVer (Major.Minor.Patch)
  "version": "1.0.0",
  
  // Deskripsi singkat package
  "description": "An awesome TypeScript library that does amazing things",
  
  // Penulis
  "author": "John Doe <john@example.com>",
  
  // Kontributor (opsional)
  "contributors": [
    "Jane Doe <jane@example.com>"
  ],
  
  // Lisensi
  "license": "MIT",
  
  // Kata kunci untuk pencarian di npm
  "keywords": [
    "typescript",
    "library",
    "awesome",
    "utilities"
  ],
  
  // Repository
  "repository": {
    "type": "git",
    "url": "https://github.com/johndoe/my-awesome-library.git"
  },
  
  // Homepage
  "homepage": "https://github.com/johndoe/my-awesome-library#readme",
  
  // Bug reports
  "bugs": {
    "url": "https://github.com/johndoe/my-awesome-library/issues"
  },
  
  // Entry points (PENTING!)
  "type": "module",
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "import": "./dist/index.mjs",
      "require": "./dist/index.cjs"
    }
  },
  "main": "./dist/index.cjs",
  "module": "./dist/index.mjs",
  "types": "./dist/index.d.ts",
  
  // File yang akan dipublish ke npm
  "files": [
    "dist",
    "src",  // Opsional: untuk debugging
    "README.md",
    "LICENSE"
  ],
  
  // Scripts
  "scripts": {
    "build": "tsup src/index.ts --format cjs,esm --dts --clean",
    "dev": "tsup src/index.ts --format cjs,esm --dts --watch",
    "test": "vitest run",
    "test:watch": "vitest",
    "lint": "eslint src --ext .ts,.tsx",
    "typecheck": "tsc --noEmit",
    
    // Pre-publish hook (otomatis jalan sebelum publish)
    "prepublishOnly": "npm run lint && npm run test && npm run build",
    
    // Untuk melihat apa yang akan dipublish
    "prepublish": "npm pack --dry-run"
  },
  
  // Peer dependencies (jika ada)
  "peerDependencies": {
    "react": ">=17.0.0",
    "react-dom": ">=17.0.0"
  },
  
  // Dependencies (akan diinstall pengguna)
  "dependencies": {
    "zod": "^3.22.0"
  },
  
  // Dev dependencies (TIDAK diinstall pengguna)
  "devDependencies": {
    "@types/node": "^20.0.0",
    "typescript": "^5.0.0",
    "tsup": "^8.0.0",
    "vitest": "^1.0.0",
    "eslint": "^8.0.0"
  },
  
  // Untuk scoped packages (@username/package) yang ingin dipublish public
  "publishConfig": {
    "access": "public"
  },
  
  // Engine yang dibutuhkan
  "engines": {
    "node": ">=18.0.0"
  }
}

// ========== FILE YANG PERLU ADA ==========

// Struktur sebelum publish:
// my-awesome-library/
// ├── src/
// │   └── index.ts
// ├── dist/                   # Hasil build (DIHASILKAN OLEH npm run build)
// │   ├── index.cjs
// │   ├── index.mjs
// │   └── index.d.ts
// ├── tests/
// │   └── index.test.ts
// ├── package.json
// ├── tsconfig.json
// ├── tsup.config.ts
// ├── README.md              # PENTING! Dokumentasi
// ├── LICENSE                 # Lisensi (MIT, Apache, dll)
// ├── CHANGELOG.md            # Riwayat perubahan
// ├── .gitignore
// └── .npmignore              # Opsional (lebih baik gunakan "files" di package.json)

// ========== .GITIGNORE DAN .NPMIGNORE ==========

// .gitignore (file yang TIDAK dipush ke Git)
// node_modules/
// dist/
// .env
// .env.local
// coverage/
// *.log
// .DS_Store

// .npmignore (file yang TIDAK dipublish ke npm)
// Opsional, karena "files" di package.json lebih baik
// Jika menggunakan .npmignore:
// tests/
// .github/
// .vscode/
// tsconfig.json
// vitest.config.ts
// eslint.config.js

// ========== LANGKAH PUBLISH ==========

// 1. Pastikan semua test lewat
// npm test

// 2. Build package
// npm run build

// 3. Cek apa yang akan dipublish (opsional tapi direkomendasikan)
// npm pack --dry-run
// atau
// npm publish --dry-run

// 4. Untuk scoped package pertama kali:
// npm publish --access public

// 5. Publish biasa (jika package sudah public atau bukan scoped)
// npm publish

// 6. Jika menggunakan npm organizations:
// npm publish --access=restricted  // Hanya anggota organisasi
// npm publish --access=public      // Semua orang bisa install

// ========== VERSIONING (SEBELUM PUBLISH) ==========

// Gunakan npm version untuk menaikkan versi
// Ini akan mengubah version di package.json dan membuat git tag

// Patch version (1.0.0 -> 1.0.1) - Bug fixes
// npm version patch

// Minor version (1.0.0 -> 1.1.0) - Fitur baru, backward compatible
// npm version minor

// Major version (1.0.0 -> 2.0.0) - Breaking changes
// npm version major

// Pre-release versions
// npm version premajor --preid beta   // 2.0.0-beta.0
// npm version prerelease              // 2.0.0-beta.1

// Setelah npm version, jangan lupa push:
// git push && git push --tags

// ========== TAG YANG BERGUNA ==========

// Publish dengan dist-tag (selain default "latest")
// Berguna untuk beta, rc, atau versi lama

// Publish sebagai beta
// npm publish --tag beta

// Publish sebagai next
// npm publish --tag next

// Install versi beta:
// npm install my-package@beta

// Lihat semua versi dan tag:
// npm view my-package versions --json
// npm view my-package dist-tags

// ========== CONTOH WORKFLOW LENGKAP ==========

// Workflow untuk rilis versi baru:

// 1. Pastikan working directory clean
// git status

// 2. Pull perubahan terbaru
// git pull origin main

// 3. Install dependencies
// npm ci

// 4. Jalankan test dan build
// npm test
// npm run build

// 5. Update CHANGELOG.md (manual atau dengan tools)

// 6. Naikkan versi
// npm version patch  // atau minor/major

// 7. Push ke Git
// git push origin main --follow-tags

// 8. Publish ke npm
// npm publish

// ========== DENGAN CHANGED SETS (REKOMENDASI UNTUK MONOREPO) ==========

// Untuk project/monorepo yang kompleks, gunakan @changesets/cli

// Install:
// npm install -D @changesets/cli

// Inisialisasi:
// npx changeset init

// Saat membuat perubahan:
// npx changeset
// -> Pilih package apa yang berubah
// -> Pilih jenis perubahan (major, minor, patch)
// -> Tulis ringkasan perubahan

// Sebelum publish:
// npx changeset version
// -> Ini akan mengupdate semua version dan CHANGELOG

// Publish:
// npx changeset publish

// Contoh .changeset/config.json:
// {
//   "$schema": "https://unpkg.com/@changesets/config@3.0.0/schema.json",
//   "changelog": "@changesets/cli/changelog",
//   "commit": false,
//   "fixed": [],
//   "linked": [],
//   "access": "public",
//   "baseBranch": "main",
//   "updateInternalDependencies": "patch",
//   "ignore": []
// }

// ========== TIPS DAN BEST PRACTICES ==========

// ✅ 1. Selalu build sebelum publish
// Gunakan prepublishOnly hook untuk otomatis:
// "prepublishOnly": "npm run lint && npm run test && npm run build"

// ✅ 2. Test package sebelum publish
// Gunakan npm pack atau yalc untuk test lokal:

// Cara 1: npm pack
// npm pack
// Ini membuat file .tgz yang bisa diinstall di project lain:
// npm install ../path/to/package-1.0.0.tgz

// Cara 2: yalc (lebih baik untuk development)
// npm install -g yalc
// yalc publish  # Di folder library
// yalc add my-package  # Di folder project konsumer

// ✅ 3. Gunakan "files" di package.json, bukan .npmignore
// Lebih eksplisit dan mudah di-maintain

// ✅ 4. Sertakan README.md yang bagus
// Minimal berisi:
// - Deskripsi singkat
// - Cara install
// - Contoh penggunaan dasar
// - Lisensi

// ✅ 5. Gunakan Semantic Versioning (SemVer) dengan benar
// - MAJOR: Breaking changes (tidak kompatibel dengan versi sebelumnya)
// - MINOR: Fitur baru, tetap kompatibel
// - PATCH: Bug fixes, tetap kompatibel

// ✅ 6. Jangan publish secret key atau .env
// Pastikan .gitignore dan .npmignore sudah benar

// ✅ 7. Deprecate versi lama jika perlu
// npm deprecate my-package@"< 1.0.0" "This version is no longer supported"

// ✅ 8. Unpublish jika benar-benar perlu (hati-hati!)
// Hanya bisa unpublish dalam 72 jam pertama
// npm unpublish my-package@1.0.0
// npm unpublish my-package --force  // Hapus semua versi

// ========== CONTOH WORKFLOW OTOMATIS DENGAN GITHUB ACTIONS ==========

// File: .github/workflows/publish.yml
// on:
//   push:
//     tags:
//       - 'v*'
// 
// jobs:
//   publish:
//     runs-on: ubuntu-latest
//     steps:
//       - uses: actions/checkout@v4
//       - uses: actions/setup-node@v4
//         with:
//           node-version: '20'
//           registry-url: 'https://registry.npmjs.org'
//       
//       - name: Install dependencies
//         run: npm ci
//       
//       - name: Run tests
//         run: npm test
//       
//       - name: Build
//         run: npm run build
//       
//       - name: Publish to npm
//         run: npm publish --access public
//         env:
//           NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}

// Setup:
// 1. Dapatkan token dari npmjs.com (Settings → Access Tokens)
// 2. Tambahkan ke GitHub repo: Settings → Secrets and variables → Actions
// 3. Tambahkan secret dengan nama NPM_TOKEN
```

**Kasus Penggunaan Nyata:**
- Membagikan library/reusable code ke developer lain
- Mendistribusikan update dan perbaikan bug
- Versioning yang jelas untuk tracking perubahan
- Memisahkan kode yang bisa digunakan ulang dari aplikasi utama
- Monetisasi library (jika package berbayar)
- Kontribusi ke open source community
