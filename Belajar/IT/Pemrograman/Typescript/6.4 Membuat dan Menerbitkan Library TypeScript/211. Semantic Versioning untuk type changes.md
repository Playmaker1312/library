# 211. Semantic Versioning untuk type changes

**Definisi Singkat:** Cara menerapkan Semantic Versioning (SemVer) dengan benar untuk library TypeScript, terutama saat ada perubahan pada type definitions yang bisa memengaruhi pengguna.

**Analogi:** Seperti pemberitahuan renovasi gedung - versi PATCH adalah perbaikan keran (tidak mengganggu), MINOR adalah penambahan ruangan (tambah fitur tapi tidak merusak), MAJOR adalah perubahan struktur yang mengharuskan penghuni menyesuaikan diri.

**Poin-Poin Penting:**
- SemVer: `MAJOR.MINOR.PATCH`
- Type changes seringkali merupakan breaking changes (MAJOR)
- Menambah tipe baru = MINOR (backward compatible)
- Mengubah tipe fungsi yang ada = MAJOR (breaking)
- Menambah optional property = MINOR
- Mengubah property dari optional jadi required = MAJOR

**Contoh Kode:**
```typescript
// ========== ATURAN SEMVER UNTUK TYPESCRIPT ==========

/*
  PATCH Version (1.0.0 → 1.0.1)
  - Bug fixes yang tidak mengubah API
  - Perbaikan type yang salah tapi tidak breaking
  - Menambah JSDoc comments
  - Perbaikan internal implementation tanpa perubahan signature

  MINOR Version (1.0.0 → 1.1.0)
  - Menambah fungsi, class, atau type baru
  - Menambah properti opsional ke interface/type yang ada
  - Menambah overload function yang baru
  - Men-deprecate (bukan menghapus) API lama

  MAJOR Version (1.0.0 → 2.0.0)
  - Menghapus API yang ada
  - Mengubah signature fungsi (parameter/return type)
  - Mengubah properti dari optional menjadi required
  - Mengubah nama type/interface yang di-export
  - Menambah constraint ke generic type
  - Mengubah union type dengan menghapus anggota
*/

// ========== CONTOH PERUBAHAN PATCH (TIDAK BREAKING) ==========

// VERSI 1.0.0
/**
 * Menambahkan dua angka
 * @bug Seharusnya menangani angka negatif dengan benar
 */
export function add(a: number, b: number): number {
  // Bug: Tidak menangani edge case dengan benar
  return a + b;
}

// VERSI 1.0.1 (PATCH - memperbaiki bug tanpa ubah signature)
export function add(a: number, b: number): number {
  // Bug fix: Menambah validasi
  if (typeof a !== 'number' || typeof b !== 'number') {
    throw new TypeError('Arguments must be numbers');
  }
  return a + b;
}

// ✅ PATCH: Perbaikan JSDoc tanpa perubahan kode
// VERSI 1.0.0
export interface User {
  id: string;
  name: string;
}

// VERSI 1.0.1 (PATCH - menambah dokumentasi)
export interface User {
  /** ID unik pengguna */
  id: string;
  /** Nama lengkap pengguna */
  name: string;
}

// ========== CONTOH PERUBAHAN MINOR (BACKWARD COMPATIBLE) ==========

// VERSI 1.0.0
export interface ApiClientConfig {
  baseUrl: string;
  apiKey: string;
}

export class ApiClient {
  constructor(config: ApiClientConfig) {}
  
  async get<T>(endpoint: string): Promise<T> {
    return {} as T;
  }
}

// VERSI 1.1.0 (MINOR - menambah fitur tanpa merusak)
export interface ApiClientConfig {
  baseUrl: string;
  apiKey: string;
  // ✅ MINOR: Menambah properti OPSIONAL
  timeout?: number;
  // ✅ MINOR: Menambah properti OPSIONAL
  headers?: Record<string, string>;
}

export class ApiClient {
  constructor(config: ApiClientConfig) {}
  
  async get<T>(endpoint: string): Promise<T> {
    return {} as T;
  }
  
  // ✅ MINOR: Menambah method BARU
  async post<T>(endpoint: string, body: unknown): Promise<T> {
    return {} as T;
  }
}

// ✅ MINOR: Menambah type/interface BARU
export interface User {
  id: string;
  name: string;
}

// TYPE BARU - tidak merusak yang lama
export interface AdminUser extends User {
  permissions: string[];
}

// ✅ MINOR: Menambah overload function
// Overload LAMA
export function formatDate(date: Date): string;

// ✅ MINOR: Menambah overload BARU
export function formatDate(date: Date, format: 'iso' | 'locale'): string;

export function formatDate(date: Date, format: string = 'iso'): string {
  if (format === 'locale') {
    return date.toLocaleDateString();
  }
  return date.toISOString().split('T')[0];
}

// Penggunaan lama TETAP BERFUNGSI:
// formatDate(new Date());  // Masih works!

// ========== CONTOH PERUBAHAN MAJOR (BREAKING CHANGES) ==========

// ❌ MAJOR: Menghapus API yang ada
// VERSI 1.0.0
export function oldFunction(): void {}

// VERSI 2.0.0 - DIHAPUS!
// Pengguna yang memanggil oldFunction() akan ERROR

// ❌ MAJOR: Mengubah signature fungsi
// VERSI 1.0.0
export function fetchUser(id: number): Promise<User> {
  return Promise.resolve({} as User);
}

// VERSI 2.0.0 - BREAKING!
// Parameter berubah dari number ke string
export function fetchUser(id: string): Promise<User> {
  return Promise.resolve({} as User);
}

// Pengguna versi 1.0.0:
// fetchUser(123);  // ❌ ERROR di versi 2.0.0!
// fetchUser('123');  // ✅ Baru ini yang works

// ❌ MAJOR: Mengubah properti dari optional ke required
// VERSI 1.0.0
export interface Config {
  apiKey: string;
  baseUrl?: string;  // Opsional
}

// VERSI 2.0.0 - BREAKING!
export interface Config {
  apiKey: string;
  baseUrl: string;  // ❌ SEKARANG WAJIB!
}

// Pengguna versi 1.0.0:
// const config: Config = { apiKey: 'xxx' };  // ❌ ERROR! baseUrl hilang

// ❌ MAJOR: Mengubah return type
// VERSI 1.0.0
export function getData(): Promise<{ data: string[] }> {
  return Promise.resolve({ data: ['a', 'b'] });
}

// VERSI 2.0.0 - BREAKING!
export function getData(): Promise<{ items: string[]; total: number }> {
  return Promise.resolve({ items: ['a', 'b'], total: 2 });
}

// Pengguna versi 1.0.0:
// const result = await getData();
// console.log(result.data);  // ❌ ERROR! Sekarang result.items

// ❌ MAJOR: Menambah constraint ke generic
// VERSI 1.0.0
export function first<T>(array: T[]): T | undefined {
  return array[0];
}

// VERSI 2.0.0 - BREAKING!
interface HasId {
  id: string;
}

// Sekarang generic T HARUS extends HasId
export function first<T extends HasId>(array: T[]): T | undefined {
  return array[0];
}

// Pengguna versi 1.0.0:
// first([1, 2, 3]);  // ❌ ERROR! number tidak punya id

// ❌ MAJOR: Mengubah nama type yang di-export
// VERSI 1.0.0
export interface User {
  id: string;
  name: string;
}

// VERSI 2.0.0 - BREAKING! Nama berubah
export interface Person {  // ❌ Dulu namanya User
  id: string;
  name: string;
}

// Pengguna versi 1.0.0:
// import { User } from 'my-lib';  // ❌ ERROR! User tidak ada lagi

// ========== STRATEGI MENGHINDARI BREAKING CHANGES ==========

// ✅ Strategi 1: Deprecate sebelum menghapus
// VERSI 1.1.0 - Tandai deprecated tapi tetap ada
/**
 * @deprecated Gunakan newFunction() sebagai gantinya
 */
export function oldFunction(): void {
  console.warn('oldFunction is deprecated, use newFunction instead');
}

export function newFunction(): void {
  // Implementation yang baru
}

// VERSI 2.0.0 - Baru hapus setelah memberi waktu

// ✅ Strategi 2: Tambah overload daripada mengubah yang ada
// VERSI 1.0.0
export function createUser(data: { name: string }): User {
  return { id: '1', name: data.name };
}

// VERSI 1.1.0 - Tambah overload baru
export function createUser(data: { name: string }): User;
export function createUser(name: string, email: string): User;  // ✅ OVERLOAD BARU

export function createUser(
  dataOrName: { name: string } | string,
  email?: string
): User {
  if (typeof dataOrName === 'string') {
    return { id: '1', name: dataOrName };
  }
  return { id: '1', name: dataOrName.name };
}

// ✅ Strategi 3: Gunakan optional untuk properti baru
// VERSI 1.0.0
export interface Config {
  apiKey: string;
}

// VERSI 1.1.0 - Tambah properti OPSIONAL
export interface Config {
  apiKey: string;
  timeout?: number;  // ✅ OPSIONAL, tidak breaking
}

// ✅ Strategi 4: Type guards untuk membantu migrasi
// Saat merubah struktur, sediakan type guard
interface OldUser {
  username: string;
}

interface NewUser {
  name: string;
}

type User = OldUser | NewUser;

function isNewUser(user: User): user is NewUser {
  return 'name' in user;
}

// Pengguna bisa migrasi bertahap
function processUser(user: User) {
  if (isNewUser(user)) {
    console.log(user.name);  // Tipe: NewUser
  } else {
    console.log(user.username);  // Tipe: OldUser
  }
}

// ========== DOKUMENTASI BREAKING CHANGES ==========

// ✅ Selalu dokumentasikan breaking changes di CHANGELOG.md

// Contoh CHANGELOG.md:
/*
# Changelog

## [2.0.0] - 2024-01-15

### BREAKING CHANGES

- `fetchUser()` sekarang menerima `string` sebagai parameter, bukan `number`
  - Sebelum: `fetchUser(123)`
  - Sesudah: `fetchUser('123')`

- Interface `Config` sekarang membutuhkan `baseUrl`
  - Sebelum: `{ apiKey: 'xxx' }`
  - Sesudah: `{ apiKey: 'xxx', baseUrl: 'https://api.example.com' }`

- Menghapus `oldFunction()`, gunakan `newFunction()` sebagai gantinya

### Migration Guide

```typescript
// Dari:
const user = await fetchUser(123);

// Ke:
const user = await fetchUser('123');

// Dari:
const config = { apiKey: 'xxx' };

// Ke:
const config = { apiKey: 'xxx', baseUrl: 'https://api.example.com' };
```

## [1.1.0] - 2024-01-01

### Features

- Menambah method `post()` ke `ApiClient`
- Menambah properti opsional `timeout` ke `ApiClientConfig`

## [1.0.1] - 2023-12-15

### Bug Fixes

- Memperbaiki validasi di `add()` function
*/

// 2. @changesets/cli
// npx changeset init

// 3. conventional commits + semantic-release

// - Conventional commits format:
//   feat:     -> MINOR
//   fix:      -> PATCH
//   BREAKING CHANGE: -> MAJOR

// Contoh commit message:
// feat: menambah method post() ke ApiClient  -> MINOR
// fix: memperbaiki bug di add() function        -> PATCH

// Contoh breaking change:
// feat: mengubah parameter fetchUser dari number ke string
// 
// BREAKING CHANGE: fetchUser sekarang menerima string
// Sebelum: fetchUser(123)
// Sesudah: fetchUser('123')

// ========== RINGKASAN ATURAN TYPESCRIPT ==========

/*
  JENIS PERUBAHAN                    | VERSI
  -----------------------------------|-------
  Menambah JSDoc/comments            | PATCH
  Memperbaiki bug tanpa ubah API     | PATCH
  Menambah type/function BARU        | MINOR
  Menambah properti OPSIONAL         | MINOR
  Menambah overload function         | MINOR
  Deprecate API (bukan hapus)        | MINOR
  -----------------------------------|-------
  Mengubah signature fungsi          | MAJOR
  Menghapus API                      | MAJOR
  Ubah properti optional → required  | MAJOR
  Ubah nama type/function            | MAJOR
  Tambah constraint ke generic       | MAJOR
  Ubah struktur return type          | MAJOR
  Hapus anggota dari union type      | MAJOR
*/
```

**Kasus Penggunaan Nyata:**
- Memastikan pengguna tahu kapan mereka harus mengubah kode
- Mencegah kejutan saat pengguna update versi library
- Dokumentasi yang jelas tentang perubahan apa yang terjadi
- Membantu pengguna merencanakan migrasi
- Menjaga kepercayaan pengguna terhadap library Anda
- Mempermudah debugging ketika ada masalah setelah update
