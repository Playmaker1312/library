# 212. Testing library di project konsumer

**Definisi Singkat:** Cara memastikan library TypeScript berfungsi dengan benar di project konsumen sebelum dipublish, termasuk test installation, import patterns, dan type compatibility.

**Analogi:** Seperti test drive mobil sebelum dijual - Anda memastikan mobil berjalan dengan baik di berbagai kondisi (jalan raya, kota, tanjakan) dan cocok dengan berbagai pengemudi (konsumen dengan setup berbeda).

**Poin-Poin Penting:**
- Gunakan `npm pack` atau `yalc` untuk test lokal tanpa publish
- Test berbagai skenario import (ESM, CJS, TypeScript)
- Test dengan module bundler berbeda (Vite, Webpack, Rollup)
- Test dengan TypeScript versi berbeda
- Pastikan type definitions berfungsi dengan benar (tidak ada `any`)

// ========== MASALAH UMUM DAN SOLUSI ==========

// MASALAH 1: "Cannot find module 'my-library' or its corresponding type declarations"
// SOLUSI:
// - Pastikan "types" di package.json menunjuk ke file yang benar
// - Pastikan file .d.ts benar-benar ada di dist
// - Cek exports field di package.json

// MASALAH 2: "Module 'my-library' declares '...' locally, but it is not exported"
// SOLUSI:
// - Pastikan semua type yang ingin digunakan konsumen di-export
// - Gunakan `export type { MyType }` bukan cuma `type MyType`

// MASALAH 3: Types bekerja tapi runtime error
// SOLUSI:
// - Cek exports field: apakah import dan require menunjuk ke file yang benar
// - Cek apakah .js/.mjs/.cjs file benar-benar ada
// - Test di konsumen nyata (bukan cek types saja)

// MASALAH 4: "The inferred type of '...' cannot be named without a reference to '...'"
// SOLUSI:
// - Ekspor tipe dependency yang digunakan di public API
// - Atau gunakan `export type * from 'dependency'`
// - Atau tambahkan dependency ke peerDependencies

// MASALAH 5: Implicit any di type definitions
// SOLUSI:
// - Pastikan tidak ada `any` di type definitions
// - Gunakan `unknown` daripada `any` jika benar-benar perlu
// - Test dengan `noImplicitAny: true`

**Kasus Penggunaan Nyata:**
- Memastikan library benar-benar bekerja sebelum publish
- Menemukan bug di type definitions yang tidak ketahuan di development
- Memastikan kompatibilitas dengan berbagai environment (ESM, CJS, bundler)
- Menemukan masalah interop antara TypeScript versi berbeda
- Mencegah breaking change yang tidak disengaja
- Memastikan dokumentasi dan contoh penggunaan benar
- Memberikan keyakinan sebelum rilis versi baru
