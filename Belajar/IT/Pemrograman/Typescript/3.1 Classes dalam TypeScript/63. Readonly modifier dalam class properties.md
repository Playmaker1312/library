# 63. Readonly modifier dalam class properties

**Definisi Singkat:** `readonly` menandai properti class agar hanya bisa di-assign saat deklarasi atau di dalam constructor, tidak bisa diubah setelahnya.

**Analogi:** Seperti Nomor Induk Kependudukan (NIK) di KTP — dicetak sekali dan tidak bisa diedit lagi setelah kartu jadi.

**Poin-Poin Penting:**
- `readonly` bisa dikombinasikan dengan `public`, `private`, `protected`
- Assignment hanya diperbolehkan saat deklarasi atau di constructor (bukan di method lain)
- Tidak menjamin immutability objek — hanya mencegah reassignment properti

**Contoh Kode:**
```typescript
// BENAR: readonly properti hanya diisi sekali
class User {
  readonly id: string;
  readonly createdAt: Date;
  public name: string;

  constructor(id: string, name: string) {
    this.id = id;           // OK: assignment di constructor
    this.name = name;
    this.createdAt = new Date(); // OK
  }

  updateName(newName: string): void {
    this.name = newName;    // OK: name bukan readonly
    // ERROR: tidak bisa reassign properti readonly
    // this.id = "new-id";
    // Cannot assign to 'id' because it is a read-only property
  }
}

const user = new User("USR-001", "Budi");
user.name = "Budi Baru";     // OK
// user.id = "USR-002";     // ERROR: readonly

// readonly dengan modifier lain
class Config {
  public readonly API_KEY: string;
  private readonly secret: string;

  constructor(apiKey: string, secret: string) {
    this.API_KEY = apiKey;
    this.secret = secret;
  }
}
```

**Kasus Penggunaan Nyata:** Identifier permanen (UUID/ID unik), timestamp creation dates, konfigurasi yang tidak boleh berubah setelah inisialisasi, referensi ke dependency yang di-inject.
