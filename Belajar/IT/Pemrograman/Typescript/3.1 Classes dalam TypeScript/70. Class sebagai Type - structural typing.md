# 70. Class sebagai Type - structural typing

**Definisi Singkat:** Di TypeScript, class dapat digunakan sebagai tipe, dan karena structural typing, dua class dengan bentuk (shape) yang sama dianggap kompatibel meskipun tidak ada hubungan inheritance.

**Analogi:** Seperti dua merek kunci yang berbeda bentuknya — jika keduanya punya gigi yang sama persis, keduanya bisa membuka gembok yang sama, meskipun buatan pabrik berbeda.

**Poin-Poin Penting:**
- Class name bisa dipakai sebagai tipe untuk variabel, parameter, return type
- Structural typing: jika struktur properti cocok, tipe dianggap kompatibel
- Class membawa informasi tipe instance — bukan tipe static/constructor
- Berbeda dengan nominal typing (Java/C#) yang memerlukan hubungan eksplisit

**Contoh Kode:**
```typescript
// BENAR: class sebagai tipe dengan structural typing
class Person {
  constructor(public name: string, public age: number) {}
}

class Employee {
  constructor(public name: string, public age: number, public role: string) {}
}

// Person bisa diisi dengan objek yang punya shape sama
let someone: Person = new Person("Budi", 25);

// Structural typing: Employee punya name + age (sama dengan Person)
someone = new Employee("Siti", 30, "Manager");
// OK karena Employee punya minimal semua properti Person

// Fungsi dengan parameter bertipe class
function greet(entity: Person): string {
  return `Halo ${entity.name}, ${entity.age} tahun`;
}

console.log(greet(new Person("Budi", 25)));  // OK
console.log(greet(new Employee("Siti", 30, "Manager")));  // OK: structural

// Objek literal juga bisa (structural typing)
console.log(greet({ name: "Ali", age: 20 })); // OK

// ERROR: tidak punya properti yang dibutuhkan
// greet({ name: "Ali" }); // Error: 'age' missing

// Class dengan private member — structural typing BERBEDA
class UserWithSecret {
  private secret: string = "hidden";
  constructor(public name: string) {}
}
class FakeUser {
  private secret: string = "fake";
  constructor(public name: string) {}
}
// let u: UserWithSecret = new FakeUser(); // ERROR: private berbeda brand
```

**Kasus Penggunaan Nyata:** Dependency injection (class sebagai token), DTO/ViewModel dengan struktural kompatibilitas, unit testing (mock objek dengan shape sama), polyglot sistem yang perlu kompatibilitas antar entitas.
