# 154 — Open Source Contribution

## 1. Penjelasan
Open source adalah kode yang tersedia publik untuk dilihat, digunakan, dan dikontribusi. Berkontribusi di open source bukan hanya untuk "developer senior". Banyak repositori punya label `good first issue` khusus untuk pemula. Kontribusi tidak selalu kode — dokumentasi, desain, testing, dan triaging issue juga sangat berharga.

## 2. Fungsi
- Portfolio nyata (kode Anda dipakai ribuan orang)
- Belajar dari codebase level production
- Networking dengan developer global
- Membangun reputasi dan kredibilitas
- Memberi kembali ke komunitas yang sudah membantu Anda

## 3. Tips / Cara
- **Mulai dari dokumentasi**: Perbaiki typo, tambah contoh, perjelas penjelasan. Ini yang paling dibutuhkan dan paling aman untuk pemula.
- **Cari good first issue**: GitHub label `good first issue` atau `help wanted`. Baca issue, tanya jika kurang jelas sebelum mulai.
- **Baca CONTRIBUTING.md**: Setiap repo punya aturan sendiri (branch naming, commit message, testing).
- **Alur standar**: Fork → clone → buat branch baru → coding → commit → push → open PR ke repo asli.
- **Jangan takut ditolak**: PR ditolak bukan berarti Anda gagal. Tanya kenapa, perbaiki, coba lagi.
- **Mulai kecil**: Satu PR perbaikan typo lebih baik daripada 0 PR.

## 4. Analogi
Kontribusi open source seperti **bergotong royong membangun jembatan desa**. Anda tidak perlu jadi arsitek utama untuk ikut. Bisa bantu angkat batu (dokumentasi), aduk semen (testing), atau Cat jembatan (UI fix). Semua kontribusi berarti, sekecil apapun.

## 5. Praktik Langsung
Cari 3 good-first-issue di repositori favorit Anda. Analisis:
1. Apa yang diminta?
2. Bahasa/stack apa yang dibutuhkan?
3. Apakah ada petunjuk cara memulai?
4. Apakah issue sudah diassign orang lain?
5. Tulis rencana pendekatan Anda (1 paragraf per issue).

## 6. Kesalahan Umum
- Langsung ambil issue besar tanpa diskusi → PR ditolak karena tidak sesuai ekspektasi maintainer.
- Tidak baca CONTRIBUTING.md → PR ditutup karena format tidak sesuai.
- Fork satu repo, lupa sinkronisasi → konflik merge besar.
- Frustrasi karena ditolak lalu berhenti total. Ini proses belajar, bukan ujian.
- Hanya kontribusi saat "butuh portfolio" → tidak sustain. Kontribusi rutin (1x/bulan) lebih dihargai.

## 7. Benang Merah
Materi 153 (portfolio) adalah tentang project pribadi. Materi 154 adalah tentang project orang lain — berkontribusi ke ekosistem yang lebih besar. Open source mengajarkan kolaborasi, komunikasi asinkron, dan cara kerja tim global. Selanjutnya: 155 (Technical Interview) — mengonversi pengalaman open source jadi jawaban wawancara.

## 8. Soal + Jawaban

**Soal 1:** Sebutkan 3 jenis kontribusi open source selain menulis kode.

**Jawaban 1:** Dokumentasi (perbaiki typo/tambah contoh), testing (cari bug, tulis test case), dan triaging issue (bantu maintainer kategorisasi/mereproduksi bug).

**Soal 2:** Apa yang harus dilakukan sebelum membuat pull request?

**Jawaban 2:** Baca CONTRIBUTING.md, pastikan issue belum diassign orang lain, diskusi di issue thread jika perlu, fork dan buat branch terpisah.

**Soal 3:** Bagaimana cara menemukan issue yang cocok untuk pemula?

**Jawaban 3:** Cari label `good first issue` atau `help wanted` di repositori yang diminati, filter yang masih open, baca deskripsi dan pastikan sesuai kemampuan.
