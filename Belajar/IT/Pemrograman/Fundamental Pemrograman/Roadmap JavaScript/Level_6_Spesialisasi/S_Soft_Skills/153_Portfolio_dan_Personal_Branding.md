# 153 — Portfolio & Personal Branding

## 1. Penjelasan
Portfolio bukan sekadar kumpulan project — ini adalah cerita tentang siapa Anda sebagai engineer. Di era digital, personal branding Anda adalah kombinasi dari GitHub profile, blog, LinkedIn, dan project yang Anda bangun. Perekrut tidak hanya melihat *apa* yang Anda buat, tapi *bagaimana* Anda berpikir, *mengapa* Anda membuatnya, dan *bagaimana* Anda berkomunikasi.

## 2. Fungsi
- Membuktikan kemampuan (show, don't tell)
- Menarik perhatian perekrut dan klien
- Membangun jaringan dan kredibilitas di komunitas
- Dokumentasi perjalanan belajar Anda sendiri

## 3. Tips / Cara
- **GitHub Profile**: README yang bagus (perkenalan, tech stack, pinned repos terbaik). Contribution graph aktif.
- **Pinned repos**: Pilih yang paling representatif. Bukan yang paling sulit, tapi yang paling menunjukkan kemampuan.
- **README project**: Tulis *why you built this*, apa masalahnya, apa yang dipelajari.
- **Blog**: Tulis di DEV, Hashnode, atau Medium. Satu artikel bagus per bulan > 10 artikel asal-asalan.
- **LinkedIn**: Headline yang jelas, sertakan link portfolio, minta rekomendasi.
- **Side projects > certificates**: Sertifikat kursus tidak ada artinya tanpa project real. 1 project dibangun dengan baik > 10 tutorial selesai.

## 4. Analogi
Portfolio seperti **etalase toko**. Orang lewat melihat dari kaca: apakah tokonya menarik? Apakah barang yang dipajang berkualitas? Jika etalase berantakan atau kosong, mereka tidak akan masuk — meskipun di dalam toko ada barang bagus.

## 5. Praktik Langsung
Audit GitHub profile Anda sendiri:
1. Apakah README profile ada? Jika tidak, buat.
2. Apakah pinned repos menampilkan project terbaik? Atau malah fork dari tutorial?
3. Apakah contribution graph hijau (aktif) atau putih (tidak aktif 3 bulan)?
4. Apakah setiap repo punya README yang menjelaskan what, why, how?
5. Buat daftar perbaikan minimal 3 item.

## 6. Kesalahan Umum
- Pinned repos berisi project tutorial/ikuti course → perekrut bisa bedakan.
- Tidak ada README di repos → kode tidak bisa dinilai.
- Contribution graph kosong → seperti tidak aktif belajar/berkarya.
- Terlalu fokus kuantitas: 20 project setengah jadi > 3 project solid.
- Mengabaikan LinkedIn: padahal banyak perekrut mulai dari sana.

## 7. Benang Merah
Materi 152 (code review) memastikan kode yang Anda tulis berkualitas. Materi 153 mengajarkan cara memamerkan kode itu. Portfolio yang baik adalah bukti nyata dari kemampuan coding + komunikasi + konsistensi. Selanjutnya: 154 (Open Source) — dari portfolio pribadi ke kontribusi global.

## 8. Soal + Jawaban

**Soal 1:** Apa yang lebih penting dalam portfolio: banyak project atau 1 project yang dibangun dengan baik?

**Jawaban 1:** 1 project yang dibangun dengan baik. Kualitas > kuantitas. Perekrut lebih tertarik melihat kedalaman daripada banyaknya project setengah jadi.

**Soal 2:** Sebutkan 3 komponen minimum GitHub profile yang baik.

**Jawaban 2:** README profile (perkenalan singkat), pinned repos (project terbaik), contribution graph (menunjukkan aktivitas konsisten).

**Soal 3:** Mengapa "why you built this" penting di README project?

**Jawaban 3:** Menunjukkan motivasi, proses berpikir, dan kemampuan identifikasi masalah — lebih berharga dari sekadar kode yang berfungsi.
