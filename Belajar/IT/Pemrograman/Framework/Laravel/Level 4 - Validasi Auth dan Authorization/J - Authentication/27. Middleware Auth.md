# 27. Middleware Auth — Proteksi Route

## Penjelasan

**Middleware** adalah lapisan filter yang berjalan sebelum request mencapai controller. Middleware `auth` memeriksa apakah user sudah login — jika belum, redirect ke halaman login.

Laravel menyediakan middleware auth bawaan:
- `auth` — user harus login
- `guest` — user harus BELUM login (untuk halaman login/register)

Middleware didaftarkan di `bootstrap/app.php` (Laravel 11).

## Fungsi

- Melindungi route dari akses yang tidak berizin
- Mengarahkan user yang belum login ke halaman login
- Memisahkan area publik (tanpa middleware) dan area terproteksi
- Middleware kustom untuk logika tambahan (cek status, role, dll)

## Cara Pengimplementasian

```php
<?php
// routes/web.php

// Route publik — semua orang bisa akses
Route::get('/', [LandingController::class, 'index'])->name('beranda');
Route::get('/buku', [BukuController::class, 'index'])->name('buku.index');
Route::get('/buku/{buku}', [BukuController::class, 'show'])->name('buku.show');

// Route terproteksi — hanya yang sudah login
Route::middleware(['auth'])->group(function () {
    Route::get('/dashboard', [DashboardController::class, 'index'])->name('dashboard');
    Route::get('/profil', [ProfilController::class, 'show'])->name('profil');
    Route::post('/pinjam/{buku}', [PeminjamanController::class, 'store'])->name('pinjam.store');

    // Resource route — hanya index dan show publik, sisanya terproteksi
    Route::resource('buku', BukuController::class)
         ->except(['index', 'show']);
});

// Route khusus guest — hanya yang BELUM login
Route::middleware(['guest'])->group(function () {
    Route::get('/login', [AuthController::class, 'showLogin'])->name('login');
    Route::post('/login', [AuthController::class, 'login']);
});
```

```php
<?php
// Di controller — alternatif: pakai middleware di constructor
class BukuController extends Controller
{
    public function __construct()
    {
        // Proteksi semua method kecuali index dan show
        $this->middleware('auth')->except(['index', 'show']);

        // Atau hanya untuk method tertentu
        $this->middleware('auth')->only(['create', 'store', 'update', 'destroy']);
    }
}
```

```php
<?php
// bootstrap/app.php — daftarkan middleware (Laravel 11)
->withMiddleware(function (Middleware $middleware) {
    // Middleware global — semua request
    $middleware->append(LogAktivitas::class);

    // Alias — untuk dipakai di route
    $middleware->alias([
        'anggota.aktif' => CekStatusAnggota::class,
        'role'          => CekRole::class,
    ]);

    // Group middleware
    $middleware->appendToGroup('web', [
        CekStatusAnggota::class,
    ]);
})
```

```php
{{-- Di Blade: @auth dan @guest untuk conditional UI --}}
<nav>
    @auth
        <span>{{ auth()->user()->nama }}</span>
        <a href="{{ route('dashboard') }}">Dashboard</a>
        <form action="{{ route('logout') }}" method="POST">
            @csrf
            <button type="submit">Logout</button>
        </form>
    @else
        <a href="{{ route('login') }}">Login</a>
        <a href="{{ route('register') }}">Daftar</a>
    @endauth
</nav>
```

## Analogi

Middleware auth seperti **pintu keamanan perpustakaan**:

- **Area publik** (tanpa middleware) = **Lobi perpustakaan** — semua orang bisa masuk: lihat papan info, lihat katalog umum
- **Area terproteksi** (middleware auth) = **Ruang baca khusus anggota** — hanya yang punya kartu anggota yang boleh masuk
- **Middleware `guest`** = **Pintu keluar** — hanya pengunjung yang BELUM punya kartu, diarahkan ke meja pendaftaran

```
Pintu Masuk (/) → Lobi (publik)
    ↓
Pintu Keamanan (middleware: auth)
    ├── Punya kartu? → Silakan masuk (dashboard, profil, pinjam buku)
    └── Tidak punya? → Arahkan ke meja pendaftaran (/login)
```

**Redirection:** Jika user belum login mencoba mengakses `/dashboard`:
1. Middleware `auth` cek: tidak ada session → redirect ke `/login`
2. Setelah login sukses → redirect kembali ke `/dashboard` (via `intended()`)

## Dipakai untuk Apa

- **Setiap route yang butuh login** — dashboard, profil, form CRUD
- **Pemisahan area** — publik vs anggota vs admin
- **Guest-only routes** — halaman login/register untuk yang belum login
- **Middleware kustom** — cek status anggota, cek role, logging

## Kesalahan Umum

1. **Lupa middleware di route** — route tidak terproteksi — siapa pun bisa akses
2. **Route publik dan terproteksi campur aduk** — gunakan group agar jelas
3. **Redirect loop** — jika halaman yang dituju setelah login juga butuh login → loop
4. **Middleware di controller dan route tumpang tindih** — jika di kedua tempat, dijalankan keduanya
5. **Salah guard** — `auth:admin` vs `auth` — pastikan guard sesuai
6. **Tidak ada route login yang didefinisikan** — middleware auth akan error karena tidak tahu redirect ke mana

1. **Proteksi route:**

   Atau di controller:
   ```php
   public function __construct()
   {
       $this->middleware('auth')->except(['index', 'show']);
   }
   ```

2. **Perbedaan:**
   - **`auth`** — user harus login. Jika belum → redirect ke login. Untuk dashboard, profil, dll.
   - **`guest`** — user harus BELUM login. Jika sudah → redirect ke dashboard. Untuk login/register page.

3. **Group admin:**
   ```php
   Route::middleware(['auth'])
        ->prefix('admin')
        ->name('admin.')
        ->group(function () {
            Route::get('/dashboard', [AdminController::class, 'dashboard'])->name('dashboard');
            Route::resource('buku', Admin\BukuController::class);
            Route::resource('anggota', Admin\AnggotaController::class);
        });
   ```
