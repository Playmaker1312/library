# 42. Laravel Telescope dan Pulse — Monitoring Aplikasi

## Penjelasan

**Monitoring** adalah proses memantau aplikasi yang sedang berjalan — untuk mendeteksi masalah, menganalisis performa, dan memahami perilaku pengguna.

**Telescope** (Development) — debugger cantik untuk development: lihat request, query, mail, queue, log, dll.
**Pulse** (Production) — dashboard real-time untuk production: performa server, slow query, queue, job, dll.

```bash
# Telescope (development only)
composer require laravel/telescope --dev
php artisan telescope:install
php artisan migrate

# Pulse (production)
composer require laravel/pulse
php artisan vendor:publish --provider="Laravel\Pulse\PulseServiceProvider"
php artisan migrate
```

## Fungsi

- **Debugging**: lihat request terakhir, query SQL, exception
- **Performa**: deteksi slow query, slow job, bottleneck
- **Monitoring**: pantau queue, cache, server resources
- **Audit**: lihat aktivitas pengguna, email terkirim

## Cara Pengimplementasian

```bash
# ├── TELESCOPE ──────────────────────────────────────
composer require laravel/telescope --dev

# Akses: /telescope (hanya di local)
```

```php
<?php
// app/Providers/AppServiceProvider.php
// Telescope hanya aktif di local

use Laravel\Telescope\TelescopeServiceProvider;

public function register(): void
{
    if ($this->app->environment('local')) {
        $this->app->register(TelescopeServiceProvider::class);
    }
}
```

```bash
# Yang bisa dilihat di Telescope:
# ─────────────────────────────────────────────
# Request     → detail setiap request (method, URL, durasi)
# Query       → semua query SQL (lengkap dengan bindings)
# Mail        → email yang dikirim (isi email preview)
# Notification → notifikasi (database, email, SMS)

# Log         → semua log entry
# Dump        → hasil dd() / dump() terekam
# Exception   → exception dengan stack trace lengkap
# Cache       → cache hit/miss/perintah
```

```bash
# ─── PULSE ──────────────────────────────────────────
composer require laravel/pulse

php artisan migrate

# Akses: /pulse
```

```php
<?php
// config/pulse.php — atur apa yang dipantau

return [
    'recorders' => [
        \Laravel\Pulse\Recorders\SlowJobs::class => [
            'enabled' => env('PULSE_SLOW_JOBS_ENABLED', true),
            'threshold' => 1000, // job lambat > 1 detik
        ],
        \Laravel\Pulse\Recorders\SlowQueries::class => [
            'enabled' => env('PULSE_SLOW_QUERIES_ENABLED', true),
            'threshold' => 200, // query lambat > 200ms
        ],
        \Laravel\Pulse\Recorders\SlowRequests::class => [
            'enabled' => env('PULSE_SLOW_REQUESTS_ENABLED', true),
            'threshold' => 500, // request lambat > 500ms
        ],
        \Laravel\Pulse\Recorders\UserSessions::class => [
            'enabled' => env('PULSE_USER_SESSIONS_ENABLED', true),
        ],
    ],
];

// Dashboard Pulse menampilkan:
// ─────────────────────────────────────────────
// ● Server resources (CPU, Memory)
// ● Slow requests
// ● Slow queries
// ● Slow jobs
// ● Queue throughput
// ● Cache hit/miss ratio
// ● User sessions
```

## Analogi

Telescope dan Pulse seperti **CCTV dan dashboard perpustakaan**:

**Telescope (development)** = **CCTV di ruang server**:
- Bisa lihat detail setiap "pengunjung" (request): siapa, ke mana, jam berapa
- Lihat "catatan" yang dibuat (query SQL)
- Lihat "surat" yang dikirim (email)
- Cocok untuk debugging: "Kenapa error jam 10.15?"
- HANYA untuk development — terlalu detail untuk production

**Pulse (production)** = **Dashboard utama perpustakaan**:
- Jam buka: berapa banyak pengunjung sekarang?
- Antrian: berapa banyak yang menunggu di loket?
- Kinerja: apakah komputer meja sirkulasi lambat?
- Peringatan: "Rak buku fiksi penuh 90%"
- Cocok untuk monitoring real-time

**Mengapa Telescope tidak untuk production:**
- Telescope menyimpan SEMUA data request — cepat penuh
- Telescope memperlambat aplikasi
- Data sensitif (password, token) ikut tercatat

## Dipakai untuk Apa

- **Development**: Telescope untuk debugging cepat
- **Production**: Pulse untuk memantau health aplikasi
- **Tim**: Developer lihat Telescope, Ops lihat Pulse
- **Troubleshooting**: "Kenapa aplikasi lambat?" → lihat slow query di Pulse/Telescope

## Kesalahan Umum

1. **Telescope di production** — jangan! Berat, penuh storage, bocor data. Hanya untuk `local`/`development`
2. **Lupa `pulse:check` di scheduler** — Pulse tidak mengumpulkan data tanpa ini
3. **Tidak membatasi akses ke dashboard** — /telescope dan /pulse harus diproteksi (middleware auth + admin)
4. **Data Pulse tidak dibersihkan** — Pulse menyimpan data 1 minggu secara default, bisa diatur
5. **Tidak memonitor Pulse setelah deploy** — pasang dashboard di monitor terpisah

## Koneksi dengan Materi Sebelumnya

Poin 40 (Deployment) membuat aplikasi berjalan. Sekarang aplikasi perlu dimonitor. Query lambat (poin 21), queue (poin 33), dan cache (poin 38) semuanya terpantau di Telescope/Pulse.
