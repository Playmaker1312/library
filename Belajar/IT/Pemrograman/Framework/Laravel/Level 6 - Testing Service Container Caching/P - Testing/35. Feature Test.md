# 35. Feature Test — Test HTTP Request

## Penjelasan

**Feature Test** menguji alur lengkap dari HTTP request hingga response — mirip seperti user menggunakan aplikasi. Test ini memastikan bahwa route, controller, middleware, dan view bekerja bersama dengan benar.

**Prinsip:**
- Test satu skenario per method
- Nama method test deskriptif: `test_halaman_katalog_bisa_diakses_publik()`
- Gunakan `RefreshDatabase` — setiap test dimulai dengan database bersih

## Fungsi

- Memastikan fitur bekerja sesuai harapan
- Mencegah regresi — perubahan baru tidak merusak fitur lama
- Dokumentasi hidup — test menjelaskan bagaimana fitur seharusnya bekerja
- Confident refactoring — ubah kode dengan tenang, test akan tangkap error

## Cara Pengimplementasian

```bash
php artisan make:test BukuTest
php artisan make:test Api/BukuApiTest
php artisan make:test Auth/LoginTest
```

```php
<?php
// tests/Feature/BukuTest.php

namespace Tests\Feature;

use App\Models\Anggota;
use App\Models\Buku;
use Illuminate\Foundation\Testing\RefreshDatabase;
use Tests\TestCase;

class BukuTest extends TestCase
{
    use RefreshDatabase; // Reset database sebelum setiap test

    // ─── PUBLIC ROUTES ───────────────────────────────────

    public function test_halaman_katalog_bisa_diakses_publik(): void
    {
        Buku::factory()->count(5)->create();

        $response = $this->get(route('buku.index'));

        $response->assertStatus(200);
        $response->assertViewIs('buku.index');
        $response->assertViewHas('buku');
    }

    public function test_halaman_detail_tampilkan_info_buku(): void
    {
        $buku = Buku::factory()->create([
            'judul' => 'Clean Code',
            'pengarang' => 'Robert Martin',
        ]);

        $response = $this->get(route('buku.show', $buku));

        $response->assertStatus(200);
        $response->assertSee('Clean Code');
        $response->assertSee('Robert Martin');
    }

    public function test_halaman_detail_return_404_jika_buku_tidak_ada(): void
    {
        $response = $this->get(route('buku.show', 99999));
        $response->assertStatus(404);
    }

    // ─── PROTECTED ROUTES ────────────────────────────────

    public function test_tambah_buku_redirect_jika_belum_login(): void
    {
        $response = $this->get(route('buku.create'));
        $response->assertRedirect(route('login'));
    }

    public function test_admin_bisa_tambah_buku(): void
    {
        $admin = Anggota::factory()->create(['role' => 'admin']);

        $response = $this->actingAs($admin)
            ->post(route('buku.store'), [
                'judul'     => 'Buku Test',
                'pengarang' => 'Penulis Test',
                'tahun'     => 2024,
                'harga'     => 100000,
                'stok'      => 5,
                'kategori'  => 'Teknologi',
            ]);

        $response->assertRedirect();
        $response->assertSessionHas('sukses');
        $this->assertDatabaseHas('buku', ['judul' => 'Buku Test']);
    }

    public function test_anggota_biasa_tidak_bisa_tambah_buku(): void
    {
        $anggota = Anggota::factory()->create(['role' => 'anggota']);

        $response = $this->actingAs($anggota)
            ->post(route('buku.store'), [
                'judul' => 'Test',
                'pengarang' => 'Test',
                'tahun' => 2024,
                'harga' => 0,
                'stok' => 0,
                'kategori' => 'Umum',
            ]);

        $response->assertStatus(403);
        $this->assertDatabaseMissing('buku', ['judul' => 'Test']);
    }

    // ─── VALIDATION ──────────────────────────────────────

    public function test_validasi_judul_wajib_diisi(): void
    {
        $admin = Anggota::factory()->create(['role' => 'admin']);

        $response = $this->actingAs($admin)
            ->post(route('buku.store'), [
                'judul' => '',  // kosong
                'pengarang' => 'Test',
                'tahun' => 2024,
                'harga' => 0,
                'stok' => 0,
                'kategori' => 'Umum',
            ]);

        $response->assertSessionHasErrors('judul');
    }

    // ─── API TEST ────────────────────────────────────────

    public function test_api_buku_mengembalikan_list(): void
    {
        Buku::factory()->count(5)->create();

        $response = $this->getJson('/api/v1/buku');

        $response->assertStatus(200)
                 ->assertJsonStructure([
                     'data' => [['id', 'judul', 'pengarang']],
                     'links', 'meta',
                 ]);
    }

    public function test_api_login_berhasil(): void
    {
        $user = Anggota::factory()->create([
            'email' => 'test@test.com',
            'password' => bcrypt('password'),
        ]);

        $response = $this->postJson('/api/v1/auth/login', [
            'email' => 'test@test.com',
            'password' => 'password',
        ]);

        $response->assertStatus(200)
                 ->assertJsonStructure(['token', 'user']);
    }
}
```

## Analogi

Feature Test seperti **quality control (QC) perpustakaan**:

Setiap kali perpustakaan menambah fitur baru atau memperbaiki sesuatu, QC menguji:
1. "Apakah halaman katalog bisa dibuka?" → `test_halaman_katalog_bisa_diakses_publik()`
2. "Apakah detail buku menampilkan judul dengan benar?" → `test_halaman_detail_tampilkan_info_buku()`
3. "Apakah yang belum login diarahkan ke halaman login?" → `test_tambah_buku_redirect_jika_belum_login()`
4. "Apakah anggota biasa tidak bisa menambah buku?" → `test_anggota_biasa_tidak_bisa_tambah_buku()`

**`RefreshDatabase`** = Setiap kali QC selesai test, mereka mereset perpustakaan ke keadaan semula — buku palsu dihapus, data test dibersihkan. Test berikutnya mulai dari kondisi bersih.

## Dipakai untuk Apa

- **Setiap fitur baru** — tulis test sebelum atau setelah coding (TDD)
- **Setiap bug fix** — tulis test yang mereproduksi bug, lalu perbaiki
- **Regression testing** — pastikan perubahan tidak merusak yang sudah berfungsi
- **CI/CD** — test otomatis berjalan di GitHub Actions setiap push

## Kesalahan Umum

1. **Test terlalu panjang** — satu test sebaiknya menguji SATU skenario
2. **Nama test tidak deskriptif** — `test_buku()` vs `test_halaman_katalog_bisa_diakses_publik()` — yang kedua lebih jelas
3. **Lupa `RefreshDatabase`** — data dari test sebelumnya mengganggu test berikutnya
4. **Lupa `use RefreshDatabase`** — trait tidak aktif, database tidak di-reset
5. **Test terhadap route yang tidak ada** — pastikan route sudah terdaftar
6. **Menggunakan data hardcode di test** — gunakan Factory untuk konsistensi
7. **Assert tidak spesifik** — `assertStatus(200)` saja tidak cukup. Juga cek view, data, atau konten

## Koneksi dengan Materi Sebelumnya

Semua materi sebelumnya (Level 1-5) sekarang bisa diuji. Feature test memastikan bahwa seluruh alur Route → Controller → View/API → Database bekerja dengan benar.

**Benang merah ke depan:**
- Poin 36 (Unit Test): Unit test untuk method spesifik, feature test untuk alur lengkap
- Poin 41 (CI/CD): Test berjalan otomatis di pipeline

## Soal Latihan

1. **Praktik**: Buat test untuk route `buku.index` — pastikan status 200 dan view-nya benar!
2. **Praktik**: Buat test untuk API login dengan kredensial salah — pastikan response 401!
3. **Analisis**: Apa perbedaan `assertSee()`, `assertViewHas()`, dan `assertDatabaseHas()`? Kapan menggunakan masing-masing?

   ```php
   public function test_api_login_gagal_dengan_password_salah(): void
   {
       Anggota::factory()->create([
           'email' => 'test@test.com',
           'password' => bcrypt('password'),
       ]);

       $response = $this->postJson('/api/v1/auth/login', [
           'email' => 'test@test.com',
           'password' => 'salah',
       ]);

       $response->assertStatus(401);
       $response->assertJson(['message' => 'Email atau password salah.']);
   }
   ```

3. **Perbedaan assert:**
   - **`assertSee('Clean Code')`** — cek apakah teks "Clean Code" muncul di response HTML
   - **`assertViewHas('buku')`** — cek apakah view menerima variabel `$buku` dari controller
   - **`assertDatabaseHas('buku', ['judul' => 'Test'])`** — cek apakah ada record di database
   - Gunakan sesuai konteks: assertSee untuk UI, assertViewHas untuk data, assertDatabaseHas untuk database
