# 6. Artisan CLI — Swiss Army Knife Laravel

## Penjelasan

**Artisan** adalah command-line tool bawaan Laravel yang mengotomatiskan tugas-tugas repetitif. Semua perintah dipanggil dengan `php artisan [command]`.

Artisan bukan sekadar "alat bantu" — ini adalah **cara standar** untuk membuat file, menjalankan tugas, dan mengelola aplikasi Laravel. Menggunakan Artisan memastikan file yang dibuat memiliki boilerplate yang benar di lokasi yang benar.

```bash
# Lihat SEMUA perintah yang tersedia
php artisan list

# Bantuan untuk perintah tertentu
php artisan help make:controller
```

**Perintah Paling Sering Dipakai:**

| Perintah | Fungsi | Setara Manual |
|----------|--------|---------------|
| `php artisan serve` | Jalankan server dev | Setup Apache/Nginx |
| `php artisan tinker` | REPL interaktif | - |
| `php artisan route:list` | Lihat semua route | Buka file satu per satu |
| `php artisan make:model Buku -mfs` | Buat model + migration + factory + seeder | Buat 4 file manual |
| `php artisan migrate` | Jalankan migration | Execute SQL manual |
| `php artisan make:controller BukuController --resource` | Buat controller CRUD | Tulis 7 method manual |
| `php artisan db:seed` | Isi data awal | Insert SQL satu per satu |
| `php artisan optimize:clear` | Clear semua cache | Hapus file cache satu per satu |

## Fungsi

- **Generate file**: membuat boilerplate kode dengan struktur yang benar
- **Manage database**: migration, seeding, factory
- **Manage cache**: clear dan cache config, route, view
- **Development**: server, tinker, route list
- **Maintenance**: down/up mode, optimize

## Cara Pengimplementasian

```bash
# ─── DEVELOPMENT ─────────────────────────────────────────

# Jalankan server di port tertentu
php artisan serve --port=8080

# Tinker — REPL untuk eksperimen langsung
php artisan tinker
>>> App\Models\Buku::count()
>>> App\Models\Buku::find(1)
>>> exit

# ─── GENERATE FILE ───────────────────────────────────────

# Controller
php artisan make:controller BukuController --resource
php artisan make:controller LandingController --invokable

# Model + migration + factory + seeder (satu perintah!)
php artisan make:model Buku -mfs

# Migration saja
php artisan make:migration create_buku_table

# Middleware
php artisan make:middleware CekStatusAnggota

# Form Request (validasi)
php artisan make:request StoreBukuRequest

# ─── DATABASE ────────────────────────────────────────────

php artisan migrate              # jalankan migration
php artisan migrate:fresh --seed  # reset + isi data
php artisan db:seed --class=BukuSeeder
php artisan make:seeder BukuSeeder

# ─── INFORMASI ───────────────────────────────────────────

php artisan route:list           # semua route
php artisan route:list --path=buku  # filter
php artisan about                 # info aplikasi
php artisan db:show               # info database
```

## Analogi

Artisan adalah **asisten pustakawan otomatis**:

- **`make:controller`** = asisten yang menyiapkan formulir standar untuk menangani permintaan pengunjung. Daripada menulis sendiri dari nol, asisten sudah menyediakan template dengan 7 bagian (index, create, store, show, edit, update, destroy).

- **`migrate`** = asisten yang membangun rak buku sesuai blueprint. Perintah satu baris, puluhan rak terbangun.

- **`tinker`** = asisten yang bisa diajak ngobrol: "Ada berapa buku?" jawab langsung.

- **`route:list`** = peta perpustakaan yang menunjukkan semua ruangan beserta petugas yang bertugas.

Tanpa asisten (Artisan), kamu harus membuat semuanya manual — lebih lambat dan rentan error.

## Dipakai untuk Apa

- **Setiap kali membuat file baru** — jangan copy-paste file lama, gunakan `php artisan make:...`
- **Setiap kali mengubah struktur database** — gunakan `php artisan make:migration`, bukan SQL manual
- **Setiap kali debugging** — `php artisan route:list`, `php artisan tinker`
- **Setiap kali deploy** — `php artisan optimize`, `php artisan migrate --force`

## Kesalahan Umum

1. **Membuat file manual tanpa Artisan** — rentan salah lokasi, salah namespace, atau boilerplate tidak lengkap
2. **Lupa `php artisan config:clear`** — perubahan `.env` tidak terbaca karena cache
3. **Menjalankan `php artisan migrate` di production tanpa backup** — gunakan `--force` di production, dan selalu backup dulu
4. **Mengetik perintah di folder yang salah** — pastikan berada di root project (ada file `artisan`)
5. **`php artisan optimize` di local** — sebaiknya hanya di production; di local gunakan `optimize:clear`
6. **Mengabaikan perintah `key:generate`** — aplikasi error terkait enkripsi

## Koneksi dengan Materi Sebelumnya

Poin 5 menjelaskan `.env` — Artisan berperan penting di sini: `php artisan key:generate` membuat APP_KEY, `php artisan config:cache` mengoptimasi konfigurasi. Tanpa Artisan, setup project (poin 3) akan jauh lebih merepotkan.

**Benang merah ke depan:**
- Poin 7-10 (Routing): `php artisan route:list` akan kamu gunakan setiap kali membuat route baru
- Poin 14 (Controller): `php artisan make:controller --resource` adalah cara standar membuat controller

## Soal Latihan

1. **Praktik**: Jalankan `php artisan list | grep make` — perintah Artisan apa saja yang berawalan "make"? Catat 5 di antaranya!
2. **Praktik**: Buat model `Buku` dengan migration, factory, dan seeder menggunakan satu perintah Artisan!
3. **Analisis**: Mengapa kita harus menggunakan Artisan untuk membuat file, bukan copy-paste file yang sudah ada?

1. Perintah `make` yang tersedia (contoh):
   - `make:controller` — buat controller
   - `make:model` — buat model
   - `make:migration` — buat migration
   - `make:seeder` — buat seeder
   - `make:factory` — buat factory
   - `make:middleware` — buat middleware
   - `make:request` — buat form request
   - `make:policy` — buat policy
   - `make:event` — buat event class
   - `make:job` — buat queue job

2. **Satu perintah:**
   ```bash
   php artisan make:model Buku -mfs
   ```
   Perintah ini membuat:
   - `app/Models/Buku.php` (model)
   - `database/migrations/..._create_buku_table.php` (migration)
   - `database/factories/BukuFactory.php` (factory)
   - `database/seeders/BukuSeeder.php` (seeder)

3. **Alasan menggunakan Artisan:**
   - **Namespace dan lokasi tepat** — file ditempatkan di folder yang benar
   - **Boilerplate lengkap** — tidak perlu menulis ulang kode standar (use statement, class definition)
   - **Konsisten** — semua file mengikuti pola yang sama
   - **Efisien** — satu perintah vs 4 file manual
