# 7. Route Dasar — Mapping URL ke Handler

## Penjelasan

**Route** adalah jembatan antara URL yang diminta browser dengan kode yang menanganinya. Di Laravel, semua route didefinisikan di file `routes/web.php` (untuk web) atau `routes/api.php` (untuk API).

Setiap route punya tiga komponen:
1. **HTTP Method** — GET, POST, PUT, PATCH, DELETE
2. **URL Path** — `/buku`, `/buku/{id}`
3. **Handler** — Closure atau Controller

```php
Route::get('/buku', function () {
    return 'Daftar Buku';
});
```

**Parameter Route:** Data dinamis dari URL, ditandai dengan `{...}`.

```php
Route::get('/buku/{id}', function (string $id) {
    return "Buku ID: $id";
});

// Parameter opsional (dengan default)
Route::get('/buku/kategori/{kategori?}', function (string $kategori = 'semua') {
    return "Kategori: $kategori";
});

// Constraint (validasi format parameter)
Route::get('/buku/{id}', function (int $id) {
    return "Buku ID: $id";
})->where('id', '[0-9]+');
```

## Fungsi

- Menentukan URL apa saja yang bisa diakses pengguna
- Mengarahkan request ke handler yang tepat (controller atau closure)
- Menangkap data dinamis dari URL (parameter)
- Memvalidasi format parameter (constraint)

## Cara Pengimplementasian

```php
<?php
// routes/web.php

use Illuminate\Support\Facades\Route;

// GET: menampilkan halaman
Route::get('/', function () {
    return view('welcome');
});

Route::get('/tentang', function () {
    return view('tentang', [
        'namaPerpustakaan' => 'Perpustakaan Digital',
        'tahunBerdiri' => 1995,
    ]);
});

// POST: mengirim data (form submission)
Route::post('/kontak', function (Request $request) {
    return redirect('/')->with('sukses', 'Pesan terkirim!');
});

// Route dengan parameter
Route::get('/buku/{id}', function (string $id) {
    return "Detail buku dengan ID: " . htmlspecialchars($id);
});

// Route dengan parameter + constraint
Route::get('/buku/{id}', function (int $id) {
    return "Buku ID: $id";
})->where('id', '[0-9]+');

Route::get('/artikel/{slug}', function (string $slug) {
    return "Artikel: $slug";
})->where('slug', '[a-z0-9-]+');

// Multiple parameter
Route::get('/buku/{kategori}/{tahun}', function (string $kategori, int $tahun) {
    return "Buku $kategori tahun $tahun";
})->where(['tahun' => '[0-9]{4}', 'kategori' => '[a-z]+']);
```

## Analogi

Route adalah **papan informasi perpustakaan**:

```
┌─────────────────────────────────────┐
│         PANDUAN RUANGAN             │
├─────────────────────────────────────┤
│ / (beranda)     → Halaman Depan     │
│ /tentang        → Profil Perpus     │
│ /buku           → Katalog Buku      │
│ /buku/{id}      → Detail Buku       │
│ /buku/{kategori}→ Buku per Kategori │
│ /kontak         → Hubungi Kami      │
└─────────────────────────────────────┘
```

Setiap pengunjung datang dengan tujuan tertentu. Papan informasi (route) mengarahkan mereka ke ruangan yang tepat (handler). Parameter `{id}` seperti nomor rak — pengunjung bilang "saya mau buku nomor 5", petugas langsung ke rak 5.

**Constraint** (`where`) seperti aturan: "nomor rak hanya angka". Jika ada yang bilang "rak ABC", petugas tahu itu tidak valid.

## Dipakai untuk Apa

- Setiap halaman di aplikasi butuh route — tanpa route, halaman tidak bisa diakses
- API endpoint untuk komunikasi server-to-server
- Form submission (POST)
- Redirect ke halaman lain

## Kesalahan Umum

1. **Lupa menentukan HTTP Method** — route GET tidak bisa menerima form POST
2. **Dua route dengan URL yang sama** — hanya yang pertama diproses
3. **Parameter route bentrok dengan route lain** — `{id}` dan `{slug}` dengan pola yang sama bisa bentrok
4. **Tidak menggunakan htmlspecialchars() untuk parameter** — rentan XSS (tapi di Blade, `{{ }}` otomatis aman)
5. **Constraint terlalu longgar** — `{id}` menerima string 'abc' jika tanpa constraint
6. **Meletakkan route spesifik setelah route generik** — route spesifik harus di atas

```php
// SALAH: route spesifik di bawah → tidak akan pernah tercapai
Route::get('/buku/{id}', ...);
Route::get('/buku/create', ...);  // ini tidak akan pernah diakses!

// BENAR: route spesifik di atas
Route::get('/buku/create', ...);
Route::get('/buku/{id}', ...);
```

## Koneksi dengan Materi Sebelumnya

Di poin 4, kamu tahu bahwa `routes/web.php` adalah tempat definisi URL. Sekarang kamu tahu cara mengisinya. Di poin 1, kamu paham lifecycle — route adalah titik setelah middleware dan sebelum controller dalam alur request.

**Benang merah ke depan:**

- Poin 9 (Resource Route): Membuat 7 route CRUD dengan satu baris

## Soal Latihan

1. **Praktik**: Buat route GET `/buku/{id}` dengan constraint `id` hanya angka, yang mengembalikan "Buku ID: {id}"!
2. **Analisis**: Mengapa route spesifik (contoh: `/buku/create`) harus ditempatkan di atas route generik (contoh: `/buku/{id}`)?
3. **Pemecahan Masalah**: Route `GET /buku/habis` tidak bisa diakses — selalu masuk ke `GET /buku/{id}` dengan `id = 'habis'`. Bagaimana solusinya?

<details>
<summary>Jawaban</summary>

1. **Kode:**
   ```php
   Route::get('/buku/{id}', function (int $id) {
       return "Buku ID: $id";
   })->where('id', '[0-9]+');
   ```

2. **Penjelasan:** Laravel membaca route dari atas ke bawah. Route `/buku/create` akan cocok dengan pola `/buku/{id}` jika `{id}` tidak punya constraint. Karena `create` adalah string, bukan angka, jika ada constraint `[0-9]+` maka route `/buku/create` tetap bisa diakses. Tapi lebih aman menempatkan route spesifik di atas untuk menghindari kebingungan.

3. **Solusi:**
   ```php
   // Taruh route spesifik di atas route generik
   Route::get('/buku/habis', [BukuController::class, 'habis']);
   Route::get('/buku/{id}', [BukuController::class, 'show'])->where('id', '[0-9]+');
   ```
   Atau gunakan route pattern di `AppServiceProvider`:
   ```php
   public function boot(): void
   {
       Route::pattern('id', '[0-9]+');
   }
   ```
</details>
