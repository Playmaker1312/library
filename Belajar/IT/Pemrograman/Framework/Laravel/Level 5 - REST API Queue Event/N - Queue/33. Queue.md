# 33. Queue — Setup dan Penggunaan Dasar

## Penjelasan

**Queue** memindahkan tugas yang memakan waktu (kirim email, proses gambar, generate PDF) ke **background**. Response ke user tetap cepat karena tugas berat tidak perlu selesai saat request.

**Masalah:**
```php
// Tanpa Queue — user menunggu 5 detik!
public function store(Request $request)
{
    $peminjaman = Peminjaman::create([...]);
    Mail::send(...); // 5 detik kirim email
    return redirect()->back(); // Response setelah 5 detik
}
```

**Solusi dengan Queue:**
```php
public function store(Request $request)
{
    $peminjaman = Peminjaman::create([...]);
    KirimEmail::dispatch($peminjaman); // Langsung return
    return redirect()->back(); // Response cepat!
    // Email dikirim di background oleh queue worker
}
```

Komponen Queue:
- **Job** — tugas yang akan dikerjakan di background
- **Queue** — antrian tempat job menunggu
- **Worker** — proses yang mengambil job dari antrian dan menjalankannya

## Fungsi

- Mempercepat response — tugas berat tidak blocking request
- Meningkatkan UX — user tidak perlu menunggu
- Retry otomatis — jika gagal, job diulang
- Prioritas — job penting bisa didahulukan

## Cara Pengimplementasian

```bash
# Setup queue with database driver
php artisan queue:table
php artisan migrate

# Buat job
php artisan make:job KirimEmailKonfirmasi
php artisan make:job GenerateLaporanBulanan
```

```php
<?php
// app/Jobs/KirimEmailKonfirmasi.php

namespace App\Jobs;

use App\Mail\KonfirmasiPeminjamanMail;
use App\Models\Peminjaman;
use Illuminate\Bus\Queueable;
use Illuminate\Contracts\Queue\ShouldQueue;
use Illuminate\Foundation\Bus\Dispatchable;
use Illuminate\Queue\InteractsWithQueue;
use Illuminate\Queue\SerializesModels;
use Illuminate\Support\Facades\Mail;

class KirimEmailKonfirmasi implements ShouldQueue
{
    use Dispatchable, InteractsWithQueue, Queueable, SerializesModels;

    public int $tries = 3;          // max percobaan
    public int $timeout = 60;       // timeout per job (detik)
    public array $backoff = [30, 60, 120]; // delay antar retry

    public function __construct(
        public Peminjaman $peminjaman,  // data yang dibutuhkan job
    ) {}

    public function handle(): void
    {
        // Kode ini berjalan di BACKGROUND, bukan saat request
        Mail::to($this->peminjaman->anggota->email)
            ->send(new KonfirmasiPeminjamanMail($this->peminjaman));
    }

    // Jika semua percobaan gagal
    public function failed(\Throwable $e): void
    {
        Log::error('Gagal kirim email', [
            'peminjaman_id' => $this->peminjaman->id,
            'error' => $e->getMessage(),
        ]);
        // Kirim notifikasi ke admin
    }
}
```

```php
<?php
// Di controller — dispatch job
class PeminjamanController extends Controller
{
    public function store(Request $request): RedirectResponse
    {
        $peminjaman = Peminjaman::create([...]);

        // Dispatch ke queue — langsung return, tidak menunggu
        KirimEmailKonfirmasi::dispatch($peminjaman);

        // Dispatch dengan delay 10 menit
        KirimEmailKonfirmasi::dispatch($peminjaman)->delay(now()->addMinutes(10));

        // Dispatch ke queue khusus
        KirimEmailKonfirmasi::dispatch($peminjaman)->onQueue('email');

        return redirect()->route('peminjaman.show', $peminjaman)
            ->with('sukses', 'Peminjaman berhasil!');
    }
}
```

```bash
# Jalankan worker — proses yang mengambil job dari antrian
php artisan queue:work

# Dengan opsi:
php artisan queue:work --queue=email,default  # proses queue tertentu dulu
php artisan queue:work --tries=3              # max 3 percobaan
php artisan queue:work --timeout=60           # timeout per job
php artisan queue:work --sleep=3              # sleep 3 detik jika antrian kosong

# Di production: jalankan dengan Supervisor (agar auto-restart)
# /etc/supervisor/conf.d/laravel-worker.conf
```

```env
# .env — pilih driver queue
QUEUE_CONNECTION=database  # sync | database | redis

# sync = langsung jalan (untuk development)
# database = antrian di tabel MySQL
# redis = performa terbaik (untuk production)
```

## Analogi

Queue seperti **sistem pengiriman buku antar perpustakaan**:

- **Job** = Paket buku yang harus dikirim ke cabang lain
- **Queue (antrian)** = Meja "akan dikirim" — paket menunggu di sini
- **Worker** = Kurir yang terus mengambil paket dari meja dan mengirimkannya
- **Dispatch** = Letakkan paket di meja "akan dikirim" — selesai, petugas tidak perlu menunggu kurir

**Tanpa Queue:**
```
Anggota pinjam buku → petugas harus ANTAR sendiri buku ke gudang → 
anggota tunggu 10 menit → baru dapat konfirmasi
```

**Dengan Queue:**
```
Anggota pinjam buku → petugas taruh slip di meja "akan diantar" → 
anggota langsung dapat konfirmasi (1 detik) → 
kurir nanti yang antar buku ke gudang (background)
```

**Driver Queue:**
- **`sync`** = Kurir bayangan: "antar now!" — langsung diantar, tidak ada antrian. Cocok untuk development.
- **`database`** = Meja fisik dengan slip antrian. Cocok untuk production sederhana.
- **`redis`** = Meja digital super cepat. Cocok untuk production dengan volume tinggi.

## Dipakai untuk Apa

- **Email** — kirim konfirmasi, notifikasi, newsletter
- **Upload & Resize gambar** — proses gambar di background
- **Generate PDF/Laporan** — laporan besar digenerate async
- **Webhook** — kirim data ke API eksternal
- **Import/Export data** — file besar diproses di background

## Kesalahan Umum

1. **Driver `sync` di production** — job jalan synchronous = user menunggu. Ganti ke `database` atau `redis`
2. **Worker tidak jalan** — job masuk antrian tapi tidak dieksekusi. Jalankan `php artisan queue:work`
3. **Memory leak** — job yang tidak selesai menumpuk. Set timeout dan tries
4. **Serialization error** — job menerima object yang tidak bisa di-serialize. Hanya kirim data yang dibutuhkan (ID)
5. **Terlalu banyak retry** — job gagal terus sampai 10 kali, baru sadar ada error permanen. Set tries sesuai
6. **Lupa `ShouldQueue` interface** — job berjalan synchronous, bukan di queue
