# 39. Membuat Books API — Semua Endpoint Buku

## Penjelasan

Setelah Axios instance siap, langkah berikutnya adalah membuat *API service module* untuk setiap resource. Untuk resource buku, kita buat `src/api/books.api.ts` yang berisi fungsi-fungsi yang memanggil endpoint backend NestJS.

Setiap fungsi mewakili satu operasi CRUD, mengembalikan Promise dengan tipe yang sesuai (Type-safe) sehingga komponen Vue tahu persis bentuk data yang diterima.

## Fungsi

- Memisahkan logic API call per resource (buku, user, auth, dll)
- Memberikan type safety — return type diketahui sejak compile time
- Memudahkan unit testing — fungsi API bisa di-mock
- Menyediakan reusable logic pagination, filter, dan search

## Cara Implementasi

### 1. Tipe Data (`src/types/book.ts`)

```typescript
export interface Book {
  id: number
  title: string
  author: string
  isbn: string
  price: number
  stock: number
  coverImage: string
  description: string
  categoryId: number
  createdAt: string
  updatedAt: string
}

export interface PaginatedResult<T> {
  data: T[]
  meta: {
    page: number
    limit: number
    total: number
    totalPages: number
  }
}

export interface BookQueryParams {
  page?: number
  limit?: number
  search?: string
  categoryId?: number
  sortBy?: string
  sortOrder?: 'asc' | 'desc'
}
```

### 2. Books API (`src/api/books.api.ts`)

```typescript
import apiClient from './axios.instance'
import type { Book, PaginatedResult, BookQueryParams } from '@/types/book'

export interface CreateBookPayload {
  title: string
  author: string
  isbn: string
  price: number
  stock: number
  categoryId: number
  description?: string
}

export interface UpdateBookPayload extends Partial<CreateBookPayload> {}

export const booksApi = {
  getAll(params?: BookQueryParams): Promise<PaginatedResult<Book>> {
    return apiClient.get('/books', { params })
  },

  getById(id: number): Promise<Book> {
    return apiClient.get(`/books/${id}`)
  },

  search(query: string): Promise<PaginatedResult<Book>> {
    return apiClient.get('/books/search', { params: { q: query } })
  },

  create(data: CreateBookPayload): Promise<Book> {
    return apiClient.post('/books', data)
  },

  update(id: number, data: UpdateBookPayload): Promise<Book> {
    return apiClient.patch(`/books/${id}`, data)
  },

  delete(id: number): Promise<void> {
    return apiClient.delete(`/books/${id}`)
  },
}
```

### 3. Contoh Penggunaan di Komponen

```vue
<script setup lang="ts">
import { ref, onMounted } from 'vue'
import { booksApi } from '@/api/books.api'
import type { Book } from '@/types/book'

const books = ref<Book[]>([])

onMounted(async () => {
  const result = await booksApi.getAll({ page: 1, limit: 10 })
  books.value = result.data
})
</script>
```

## Analogi — Toko Buku

Books API seperti **"katalog telepon"** gudang pusat. Masing-masing fungsi adalah nomor khusus yang sudah tercatat:

| Fungsi | Nomor Telepon | Arti |
|---|---|---|
| `getAll()` | `(021) 555-0001` | Minta daftar semua buku |
| `getById(5)` | `(021) 555-0005` | Minta detail buku ID 5 |
| `search('vue')` | `(021) 555-SEARCH` | Cari buku "vue" |
| `create(...)` | `(021) 555-NEW` | Pesan buku baru ke gudang |
| `update(5, ...)` | `(021) 555-UPD5` | Ubah data buku ID 5 |
| `delete(5)` | `(021) 555-DEL5` | Hapus buku ID 5 dari katalog |

Setiap pegawai tinggal melihat buku telepon ini — tidak perlu hafal nomor, cukup tahu nama fungsinya.

## Dipakai untuk Apa

- Menampilkan daftar buku di halaman utama (HomeView)
- Menampilkan detail buku di halaman detail (BookDetailView)
- Pencarian buku (search)
- Admin panel: tambah, edit, hapus buku
- Integrasi dengan komponen pagination dan filter

## Kesalahan Umum

| Kesalahan | Akibat | Solusi |
|---|---|---|
| Tidak handle pagination | Halaman hanya muat 10 data, sisanya hilang | Gunakan `PaginatedResult<T>` dan tampilkan pagination |
| Tidak ada error handling try/catch | Aplikasi crash saat API error | Bungkus setiap panggilan dengan try/catch |
| Tipe data tidak sesuai backend | Error runtime karena field tidak cocok | Sinkronkan tipe TypeScript dengan response NestJS |
| Query params tidak dikirim | Filter dan search tidak bekerja | Periksa object params yang dikirim |
| Lupa method HTTP yang benar | 405 Method Not Allowed | `create` → `POST`, `update` → `PATCH`, `delete` → `DELETE` |

## Hubungan dengan Materi Sebelumnya

Di **Poin 38**, kita buat Axios instance sebagai "saluran telepon". Sekarang kita buat **buku teleponnya** — daftar nomor yang bisa dihubungi.

Di **Level 3**, operasi "ambil semua buku" adalah satu baris:

```typescript
const books = ref<Book[]>(MOCK_BOOKS)
```

Sekarang dengan Books API:

```typescript
const books = ref<Book[]>([])
const result = await booksApi.getAll({ page: 1, limit: 20 })
books.value = result.data
```

Data tidak lagi tetap — setiap render bisa berbeda tergantung data di server.

### Soal 2

Buat sebuah custom error handler di books API yang mengubah error 404 menjadi pesan: "Buku dengan ID tersebut tidak ditemukan."

<details>
<summary>Jawaban</summary>

```typescript
// Di dalam books.api.ts
async getByIdSafe(id: number): Promise<Book | null> {
  try {
    return await this.getById(id)
  } catch (error: any) {
    if (error.response?.status === 404) {
      console.warn(`Buku dengan ID ${id} tidak ditemukan.`)
      return null
    }
    throw error
  }
}
```
