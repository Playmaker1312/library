# 31. Navigation Guards

## Penjelasan

**Navigation guards** adalah fungsi yang dijalankan sebelum/ketika/sesudah navigasi terjadi. Yang paling umum adalah **global guard** `router.beforeEach((to, from) => {...})` — dijalankan SEBELUM route berubah.

Guard digunakan untuk:
- **Proteksi halaman**: Cek apakah user sudah login
- **Redirect**: Arahkan user ke halaman tertentu
- **Validasi params**: Cek apakah parameter valid
- **Set title**: Ubah document.title tiap halaman

## Fungsi

Mencegah user mengakses halaman tertentu jika **tidak memenuhi syarat**. Di aplikasi BookStore: halaman wishlist dan profile hanya boleh diakses oleh **anggota yang sudah login**.

## Cara Implementasi

### 1. Tambah `meta` di route definition

```typescript
// src/router/index.ts
const routes = [
  {
    path: '/',
    name: 'home',
    component: () => import('../views/HomeView.vue')
  },
  {

    name: 'book-detail',
    component: () => import('../views/BookDetailView.vue')
  },
  {
    path: '/cart',
    name: 'cart',
    component: () => import('../views/CartView.vue')
  },
  {
    path: '/wishlist',
    name: 'wishlist',
    meta: { requiresAuth: true },
    component: () => import('../views/WishlistView.vue')
  },
  {
    path: '/profile',
    name: 'profile',
    meta: { requiresAuth: true },
    component: () => import('../views/ProfileView.vue')
  },
  {
    path: '/login',
    name: 'login',
    meta: { guestOnly: true },
    component: () => import('../views/LoginView.vue')
  },
  {
    path: '/:pathMatch(.*)*',
    name: 'not-found',
    component: () => import('../views/NotFoundView.vue')
  }

```

### 2. Tambah guard di file router

```typescript
// src/router/index.ts (lanjutan)
import { createRouter, createWebHistory } from 'vue-router'

// Sementara pakai variable palsu — nanti diganti Pinia auth store (Level 4)
let isAuthenticated = false

const router = createRouter({
  history: createWebHistory(import.meta.env.BASE_URL),
  routes: [
    // ... routes di atas ...
  ]
})

router.beforeEach((to, from) => {
  // Set document title
  document.title = to.meta?.title
    ? `BookStore | ${to.meta.title}`
    : 'BookStore'

  // Cek halaman yang butuh auth
  if (to.meta.requiresAuth && !isAuthenticated) {
    // Redirect ke login, simpan URL tujuan di query
    return {
      name: 'login',
      query: { redirect: to.fullPath }
    }
  }

  // Cek halaman guest-only (login page)
  if (to.meta.guestOnly && isAuthenticated) {
    return { name: 'home' }
  }
})

export default router
```

### 3. LoginView.vue — handle redirect after login

```vue
<script setup lang="ts">
import { ref } from 'vue'
import { useRoute, useRouter } from 'vue-router'

const route = useRoute()
const router = useRouter()

const email = ref('')
const password = ref('')

function handleLogin() {
  // Simulasi login sukses
  isAuthenticated = true

  // Ambil redirect URL dari query, fallback ke home

</script>

<template>

    <h1>Login Anggota BookStore</h1>
    <p v-if="route.query.redirect">
      Silakan login untuk mengakses {{ route.query.redirect }}
    </p>
    <input v-model="email" type="email" placeholder="Email" required />
    <input v-model="password" type="password" placeholder="Password" required />
    <button type="submit">Login</button>
  </form>
</template>
```

## to.meta

`meta` adalah objek yang bisa diisi data **custom** di setiap route. Berguna untuk:
- `requiresAuth: true` — butuh login
- `guestOnly: true` — hanya untuk guest (halaman login/register)
- `title: '...'` — title halaman
- `roles: ['admin', 'user']` — role-based access (lanjutan)

## Redirect URL via Query

```typescript
return {
  name: 'login',
  query: { redirect: to.fullPath }
}
```

Saat user belum login klik Wishlist → guard tangkap → redirect ke `/login?redirect=%2Fwishlist`. Setelah login, kita baca `route.query.redirect` dan `router.push` ke sana. User langsung sampai ke tujuan awal tanpa perlu navigasi manual.

## Analogi — Satpam di Toko Buku

Toko buku punya **area khusus**:

| Area | Akses | Guard |
|---|---|---|
| Beranda, Rak Buku, Kasir | Semua pengunjung | Tidak ada satpam |
| Wishlist | Hanya anggota | **Satpam: "Tunjukkan kartu anggota!"** |
| Profil | Hanya anggota | **Satpam: "Tunjukkan kartu anggota!"** |
| Login | Hanya non-anggota | **Satpam: "Anda sudah punya kartu, silakan masuk"** |

**Flow satpam (guard)**:
1. Pengunjung mau masuk ke Wishlist (`/wishlist`)
2. Satpam tanya: "Punya kartu anggota?" (`isAuthenticated?`)
3. **Tidak punya**: "Silakan daftar dulu di meja pendaftaran, nanti saya catat tujuan Anda" → redirect ke `/login?redirect=/wishlist`
4. **Punya**: "Silakan masuk" → route Wishlist di-load

**Catatan redirect**: Satpam mencatat tujuan awal. Setelah daftar, pengunjung langsung diantar ke Wishlist, bukan cuma ke pintu masuk toko.

## Dipakai untuk Apa

- **Auth protection**: Halaman dashboard, profil, settings
- **Role-based access**: Admin panel hanya untuk admin
- **Route validation**: Cek apakah `id` valid sebelum render
- **Analytics tracking**: Kirim event navigasi ke Google Analytics
- **Persistence guard**: "Anda punya perubahan yang belum disimpan" — konfirmasi sebelum leave page (`beforeRouteLeave`)

## Kesalahan Umum

1. **Lupa `return` dari guard** → Guard tidak ngapa-ngapain, navigasi lanjut tanpa hambatan
2. **Infinite loop redirect** → Guard redirect ke `/login`, halaman `/login` juga guard `requiresAuth` → redirect lagi → loop tak berujung. Solusi: pastikan halaman login punya `guestOnly: true` atau tidak dicek `requiresAuth`
3. **Guard dijalankan sebelum Pinia siap** → Jika guard akses Pinia store saat app baru start, store mungkin belum diinisialisasi. Solusi: pastikan `app.use(pinia)` sebelum `app.use(router)`, atau akses store di dalam guard secara lazy
4. **`isAuthenticated` masih variable global palsu** → Di kode kita `let isAuthenticated = false` bersifat sementara. Nanti di Level 4 diganti dengan Pinia auth store yang proper dengan persistence (token, refresh)

## Hubungan dengan Materi Sebelumnya

- **Poin 30**: Navigasi sudah bisa (RouterLink, router.push). Sekarang kita kontrol **siapa yang boleh** navigasi.
- **Poin 28**: Route `/wishlist`, `/profile` sudah didefinisikan. Sekarang ditambah `meta: { requiresAuth: true }`.
- **Level 1 (Poin 5)**: Event handling `@submit.prevent` di form login.
- **Level 2 (Poin 22)**: Form binding `v-model` di input email dan password.
- **Level 4 (nanti)**: `let isAuthenticated = false` → Pinia `useAuthStore().isAuthenticated` dengan JWT token persistence.

### Soal 2
Apa yang terjadi jika guard di bawah ini dipasang, lalu user yang SUDAH login mengakses `/login`?

```typescript
router.beforeEach((to) => {
  if (to.meta.requiresAuth && !isAuthenticated) {
    return { name: 'login', query: { redirect: to.fullPath } }
  }
```

<details>
<summary>Jawaban</summary>

Tidak ada yang terjadi — guard hanya mengecek `requiresAuth`. Karena `/login` tidak punya `meta.requiresAuth`, guard dilewati dan user yang sudah login tetap bisa mengakses halaman login.

Ini **tidak ideal** — seharusnya user yang sudah login tidak perlu melihat halaman login lagi. Solusi: tambahkan guard untuk `guestOnly`:

```typescript
if (to.meta.guestOnly && isAuthenticated) {
  return { name: 'home' }
}
```
