# 56. Aktifkan TypeScript Strict Mode dan Audit Types

## Penjelasan

TypeScript strict mode mengaktifkan semua opsi type-checking ketat di `tsconfig.json`. Selama Level 1–5, TypeScript sudah dipakai tapi dalam mode longgar — banyak `any` yang lolos tanpa sengaja. Strict mode memaksa kita menulis tipe secara eksplisit dan menangkap potensi bug di **compile time**, bukan runtime.

Satu properti `strict: true` di `tsconfig.json` mengaktifkan beberapa aturan sekaligus:

- `strictNullChecks` — variabel tidak bisa diisi `null` / `undefined` tanpa dideklarasikan
- `noImplicitAny` — TypeScript tidak boleh diam saja saat tipe tidak bisa di-infer; harus ditulis eksplisit
- `strictFunctionTypes` — parameter fungsi di-check lebih ketat soal kontravarian
- `strictBindCallApply` — `bind`, `call`, `apply` di-check ketat signature-nya
- `alwaysStrict` — setiap file menggunakan strict mode JavaScript
- `noUnusedLocals` — error jika ada variabel lokal yang tidak dipakai
- `noUnusedParameters` — error jika ada parameter fungsi yang tidak dipakai

### tsconfig.json sebelum strict

```json
{
  "compilerOptions": {
    "target": "ES2020",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "strict": false,
    "noUnusedLocals": false,
    "noUnusedParameters": false
  }
}
```

### tsconfig.json setelah strict

```json
{
  "compilerOptions": {
    "target": "ES2020",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "strict": true,
    "noUnusedLocals": true,
    "noUnusedParameters": true,
    "skipLibCheck": true
  }
}
```

## Fungsi

- **Mencegah bug** di production — null reference, undefined access, missing properties
- **Self-documenting code** — tipe eksplisit lebih mudah dibaca dan di-maintain
- **Refactoring aman** — saat ganti struktur data, compiler langsung kasih tahu error di semua tempat yang perlu diubah
- **Developer experience lebih baik** — IDE autocompletion lebih akurat, IntelliSense bekerja optimal

## Cara Implementasi

### 1. Aktifkan strict di tsconfig.json

```json
{
  "compilerOptions": {
    "strict": true,
    "noUnusedLocals": true,
    "noUnusedParameters": true
  }
}
```

### 2. Jalankan type-check

```bash
npm run type-check
```

### 3. Perbaiki error satu per satu — contoh sebelum vs sesudah

#### strictNullChecks — potensi null/undefined

```vue
<script setup lang="ts">
// ❌ Sebelum: error Object is possibly 'undefined'
const props = defineProps<{ book?: Book }>()
console.log(props.book.title)

// ✅ Sesudah: guard atau default
const title = computed(() => props.book?.title ?? 'Unknown')
console.log(title.value)
</script>
```

#### noImplicitAny — parameter tanpa tipe

```vue
<script setup lang="ts">
// ❌ Sebelum: parameter 'item' implicitly has 'any' type
function formatPrice(item) {
  return `Rp ${item.price.toLocaleString('id-ID')}`
}

// ✅ Sesudah: tipe eksplisit
function formatPrice(item: { price: number }): string {
  return `Rp ${item.price.toLocaleString('id-ID')}`
}
</script>
```

#### noUnusedLocals — variabel tidak terpakai

```vue
<script setup lang="ts">
const bookCount = ref(0)       // ✅ dipakai
const storeName = 'BookStore'  // ❌ error: 'storeName' is declared but its value never read
</script>
<template>{{ bookCount }}</template>
```

### 4. Strategi bertahap (jika codebase besar)

```json
// Fase 1: aktifkan strictNullChecks saja dulu
{
  "compilerOptions": {
    "strictNullChecks": true
  }
}
```

```json
// Fase 2: tambah noImplicitAny
{
  "compilerOptions": {
    "strictNullChecks": true,
    "noImplicitAny": true
  }
}
```

```json
// Fase 3: strict penuh
{
  "compilerOptions": {
    "strict": true,
    "noUnusedLocals": true,
    "noUnusedParameters": true
  }
}
```

## Analogi — Toko Buku

Selama 5 level, **Toko Buku "Baca Lagi"** beroperasi dengan aturan longgar:

- Pegawai bisa menaruh barang di rak **tanpa label harga** (implicit any) — label ditulis nanti... tapi sering tidak ditulis sama sekali.
- **Kotak misterius** (*any*) ada di mana-mana — isinya bisa buku, bisa alat tulis, bisa kosong. Tidak ada yang tahu pasti.
- Stok barang **tidak pernah dicek** sebelum dijual (strictNullChecks longgar) — kadang pelanggan beli buku yang ternyata sudah habis.
- Barang **tidak terpakai** menumpuk di gudang (noUnusedLocals) — pegawai capek nyari tempat, barangnya tidak laku.

**TypeScript Strict adalah SOP ketat:**

- Setiap barang harus punya **label jenis yang jelas** (type) — noImplicitAny
- Setiap barang harus dicek **apakah ada stoknya** sebelum dijual — strictNullChecks
- Tidak ada **kotak misterius** — semua wadah harus diisi barang yang diketahui jenisnya
- Tidak ada barang **menumpuk tak terpakai** — kalau tidak dipakai, dibuang

Awalnya semua pegawai protes: "Ribet banget!" Tapi setelah sebulan, **kecelakaan kerja menurun drastis** — tidak ada lagi jual buku yang tidak ada stok, tidak ada lagi label harga ketinggalan. Toko jadi lebih profesional.

## Dipakai untuk Apa

- **Semua proyek Vue 3 + TypeScript** — standar minimum untuk production-grade app
- **Large-scale frontend apps** — tim besar butuh strict type safety untuk koordinasi
- **Library / component library** — strict mode menjamin API komponen jelas bagi pengguna
- **Migrasi JavaScript ke TypeScript** — strict mode diterapkan setelah migrasi dasar selesai

## Kesalahan Umum

| Kesalahan | Dampak | Solusi |
|---|---|---|
| Langsung aktivasi strict penuh di codebase 500+ file | Ratusan error, tim frustrasi, balik lagi ke `strict: false` | Lakukan bertahap: strictNullChecks → noImplicitAny → sisanya |
| SkipLibCheck tidak diaktifkan | Error dari library node_modules yang tidak strict | Tambahkan `"skipLibCheck": true` |
| Gunakan `// @ts-ignore` atau `// @ts-nocheck` berlebihan | Menonaktifkan TypeScript di file yang justru butuh | Kurangi, lebih baik perbaiki tipe dengan benar |
| Tidak jalankan type-check di CI | Error strict baru lolos ke staging | Tambahkan script type-check di pipeline CI/CD |
| Lupa update `tsconfig.json` di test folder | Test punya aturan strict berbeda, error tidak konsisten | Gunakan `references` di tsconfig atau extends config terpisah |

## Hubungan dengan Level 1–5

- **Level 1 (Dasar)** — Mulai dengan JavaScript biasa, lalu tambah TypeScript tanpa strict. Banyak kode `: any` karena belum paham tipe.
- **Level 2 (Reactivity)** — `ref<Book>({} as Book)` — Type assertion paksa yang sebenarnya menutupi masalah.
- **Level 3 (Komponen)** — Props dan emit bertipe, tapi masih longgar — `defineProps<{book: Book | null}>()` tanpa handle null.
- **Level 4 (Router & API)** — `useApi` mulai pakai tipe, tapi masih ada `any` di error handling.
- **Level 5 (State Management)** — Store Pinia dengan tipe dasar, tapi banyak `as any` di action yang mutasi data kompleks.

Sekarang di Level 6, **semua kelonggaran itu diperbaiki**. TypeScript strict adalah fondasi yang membuat semua materi sebelumnya lebih kokoh.

## Soal Latihan

### Soal 1

Kode di bawah menghasilkan error strictNullChecks. Perbaiki tanpa Type Assertion (`as`):

```vue
<script setup lang="ts">
import { ref, computed } from 'vue'

const selectedBook = ref<Book | null>(null)

const bookTitle = computed(() => {
  return selectedBook.value.title.toUpperCase()
})
</script>
```

<details>
<summary>Jawaban</summary>

```vue
<script setup lang="ts">
import { ref, computed } from 'vue'

const selectedBook = ref<Book | null>(null)

const bookTitle = computed(() => {
  return selectedBook.value?.title.toUpperCase() ?? 'Belum ada buku'
})
</script>
```

Gunakan optional chaining (`?.`) untuk akses properti kalau null, dan nullish coalescing (`??`) untuk fallback value.

</details>

### Soal 2

Dari kode berikut, temukan dan perbaiki pelanggaran `noUnusedLocals` dan `noImplicitAny`.

```vue
<script setup lang="ts">
import { ref, onMounted } from 'vue'

const books = ref([])
const tempData = ref('')
const UNUSED_CONSTANT = 'tidak dipakai'

function fetchBooks() {
  return api.getBooks()
}

function processItem(item) {
  console.log(item.title)
}

onMounted(() => {
  fetchBooks().then((data: any) => {
    books.value = data
  })
})
</script>
<template>
  <div>{{ books }}</div>
</template>
```

<details>
<summary>Jawaban</summary>

```vue
<script setup lang="ts">
import { ref, onMounted } from 'vue'

const books = ref<Book[]>([])

function fetchBooks(): Promise<Book[]> {
  return api.getBooks()
}

function processItem(item: Book): void {
  console.log(item.title)
}

onMounted(() => {
  fetchBooks().then((data: Book[]) => {
    books.value = data
  })
})
</script>
<template>
  <div>{{ books }}</div>
</template>
```

Perubahan:
- Hapus `tempData` (tidak dipakai) dan `UNUSED_CONSTANT` (tidak dipakai)
- Ganti `: any` di `.then()` dengan `Book[]`
- Tambah tipe parameter `item: Book` di `processItem` dan return type fungsi
- Tambah type parameter `ref<Book[]>([])`

</details>
