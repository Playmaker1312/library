# 65. Bundle Analysis dan Tree Shaking

## Penjelasan

**Bundle Analysis** adalah proses memeriksa isi file bundle production untuk melihat library/paket mana yang paling besar. Dengan informasi ini, kita bisa membuat keputusan tepat untuk memperkecil ukuran bundle.

**Tree Shaking** adalah mekanisme otomatis dari Vite (via Rollup) yang membuang kode JavaScript **yang tidak dipakai** (dead code) dari bundle akhir. Syaratnya: gunakan import bernama (named import) bukan import seluruh modul.

Vite sudah menyalakan tree shaking secara default. Tugas kita adalah memastikan kode ditulis dengan cara yang memungkinkan tree shaking bekerja optimal.

## Fungsi

- Mengetahui isi bundle: package apa yang paling besar, mana yang bisa diperkecil
- Menemukan package duplikat atau tidak terpakai
- Memastikan tree shaking berjalan dengan benar — bundle tidak mengandung kode mati
- Membantu pengambilan keputusan: ganti library, split chunk, atau code-split
- Target: bundle production < 200 KB (gzip) untuk aplikasi menengah

## Cara Implementasi

### 1. Install dan Setup Bundle Visualizer

```bash
npm install --save-dev rollup-plugin-visualizer
```

```typescript
// vite.config.ts
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import { visualizer } from 'rollup-plugin-visualizer'

export default defineConfig({
  plugins: [
    vue(),
    visualizer({
      filename: 'dist/stats.html',
      open: true,           // otomatis buka browser setelah build
      gzipSize: true,       // tampilkan ukuran setelah gzip
      brotliSize: true,     // tampilkan ukuran setelah brotli
      template: 'treemap'   // 'sunburst' | 'treemap' | 'network'
    })
  ]
})
```

Jalankan build:

```bash
npm run build
```

Buka `dist/stats.html` — lihat visualisasi interaktif berbentuk treemap. Setiap kotak adalah file chunk, ukuran sesuai proporsi.

### 2. Membaca Hasil Bundle Analysis

Setelah build, cari:

- **3 package terbesar** — apa saja?
- **Apakah ada duplikasi?** (misal: lodash dan lodash-es)
- **Apakah ada library besar yang hanya dipakai sedikit fungsinya?**
- **Apakah chunk vendor terlalu besar?**

Contoh temuan:

| Package | Ukuran | Masalah | Solusi |
|---------|--------|---------|--------|
| `lodash` | 120 KB | Import seluruh library | Ganti dengan `lodash-es` + named import |
| `moment` | 231 KB | Hanya pakai `format()` | Ganti dengan `date-fns` (17 KB) |
| `chart.js` | 200 KB | Hanya dipakai di 1 halaman | Lazy load via `defineAsyncComponent` |

### 3. Tree Shaking — Praktik yang Benar

```typescript
// ========================
// ✅ BAIK — tree shaking bisa bekerja
// ========================

// Named import — Rollup tahu fungsi mana yang dipakai
import { useIntersectionObserver } from '@vueuse/core'
import { format, addDays } from 'date-fns'
import { debounce } from 'lodash-es'

// Import komponen Vue — tree shaking hapus komponen yang tidak dipakai

// Re-export selektif

// ========================
// ❌ BURUK — tree shaking tidak bisa bekerja
// ========================

// Default import — Rollup tidak bisa analisis properti mana yang dipakai

import dateFns from 'date-fns'

import * as Icons from '@heroicons/vue' // ribuan icon, hanya dipakai 10
```

## Analogi — Toko Buku

**Bundle Analysis** seperti **"laporan inventaris toko"** — menunjukkan persis berapa banyak ruang gudang yang dipakai setiap barang:

- Rak buku (Vue, Vue Router, Pinia) 30% dari gudang — wajar, ini inti toko
- Ada **"patung marmer besar"** (package besar seperti Moment.js 231 KB) yang memakan 20% ruang tapi hanya dipakai untuk melihat tanggal hari ini — kita ganti dengan **"kalender meja kecil"** (date-fns 17 KB)
- Ada **"mesin kopi"** (Chart.js) yang hanya dipakai saat rapat bulanan (1 halaman) — kita pindahkan ke ruangan terpisah (lazy loading, poin 63)

**Tree Shaking** adalah **"sistem efisien"** yang otomatis membuang barang yang tidak laku dari gudang — tanpa harus manual. Setiap barang yang masuk ke gudang harus punya label jelas (named import). Barang yang tidak berlabel (default import) akan disimpan semuanya — termasuk yang tidak laku.

Setelah laporan inventaris, kita bisa buang barang tidak perlu dan tata ulang gudang — aplikasi jadi lebih ringan.

## Dipakai untuk Apa

- **Audit bulanan** — bundle size review untuk menjaga performa
- **Sebelum rilis** — pastikan tidak ada kode mati atau library membengkak
- **Memilih library baru** — cek BundlePhobia sebelum install
- **Mengganti library lama** — validasi ukuran sebelum dan sesudah migrasi
- **CI/CD pipeline** — otomatis gagal build jika bundle size melebihi threshold
- **Mengidentifikasi import yang salah** — misal import seluruh lodash padahal hanya pakai `debounce`

## Kesalahan Umum

| Kesalahan | Dampak | Solusi |
|-----------|--------|--------|
| Import default library (`import _ from 'lodash'`) | Tree shaking tidak jalan — seluruh library masuk bundle | Gunakan named import (`import { debounce } from 'lodash-es'`) |
| Terlalu fokus pada bundle size sampai mengorbankan fungsionalitas | Developer experience turun, kode jadi rumit | Ukur bundle size, tapi jangan korbankan keterbacaan |
| Tidak menjalankan bundle analysis secara berkala | Bundle membengkak tanpa sadar | Jadwalkan audit tiap bulan / sebelum rilis |
| Manual chunks berlebihan | Banyak file kecil → overhead HTTP | Hanya chunk library > 50 KB |
| Lupa `--production` saat build | Bundle development = besar (sourcemap, HMR) | Selalu build dengan `NODE_ENV=production` |
| Mengabaikan ukuran font/asset | Font bisa > 100 KB | Subset font, gunakan WOFF2, lazy load font |

## Hubungan dengan Materi Sebelumnya

**Level 1 (Dasar Vue & TypeScript):** Saat pertama belajar, bundle size tidak penting. Aplikasi kecil. Tapi setelah ribuan baris kode, bundle membengkak dan perlu dianalisis.

**Level 2 (State Management & Composables):** Store dan composable yang di-export selektif memudahkan tree shaking. Jangan export semua fungsi jika tidak dipakai.

**Level 3 (Vue Router):** Route-level lazy loading (poin 63) sudah memisahkan chunk. Bundle analysis memvalidasi apakah chunk sudah optimal atau masih ada yang bocor.

**Level 4 (Testing):** Library testing (Vitest, Testing Library) termasuk dalam bundle development — pastikan tidak masuk bundle production. Vite otomatis mengecualikannya.

**Level 5 (Backend Integration):** Axios, fetch wrapper, dan library API lainnya sering menjadi package besar. Analysis membantu menemukan alternatif yang lebih ringan.

**Level 6 (Sekarang):** Setelah lazy loading (poin 63) dan optimasi rendering (poin 64), kita analisis hasilnya dengan bundle visualizer. Selanjutnya optimasi aset gambar (poin 66). Keempat poin ini saling melengkapi: bundle kecil + render efisien + aset ringan = aplikasi super cepat.

## Soal Latihan

### Soal 1

Anda menemukan kode berikut di project BookStore:

```typescript
// utils/format.ts
import _ from 'lodash'

export function formatCurrency(amount: number): string {
  return _.round(amount, 2).toLocaleString('id-ID', {
    style: 'currency',
    currency: 'IDR'
  })
}

export function truncateText(text: string, max: number): string {
  return _.truncate(text, { length: max })
}
```

Jelaskan mengapa ini masalah untuk tree shaking. Perbaiki agar bundle size lebih kecil. Setelah diperbaiki, berapa estimasi pengurangan ukuran bundle?

<details>
<summary>Jawaban</summary>

**Masalah:** `import _ from 'lodash'` adalah default import — Rollup tidak bisa menentukan fungsi mana yang benar-benar dipakai. Seluruh library lodash (~70 KB minified) masuk ke bundle, padahal hanya dipakai `_.round()` dan `_.truncate()`.

**Perbaikan:**

```typescript
import { round, truncate } from 'lodash-es'  // lodash-es mendukung ESM

export function formatCurrency(amount: number): string {
  return round(amount, 2).toLocaleString('id-ID', {
    style: 'currency',
    currency: 'IDR'
  })
}

export function truncateText(text: string, max: number): string {
  return truncate(text, { length: max })
}
```

Atau alternatif lebih ringan — fungsi vanilla JavaScript tanpa library:

```typescript
export function formatCurrency(amount: number): string {
  return Math.round(amount * 100) / 100
    .toLocaleString('id-ID', { style: 'currency', currency: 'IDR' })
}

export function truncateText(text: string, max: number): string {
  return text.length > max ? text.slice(0, max).trimEnd() + '...' : text
}
```

**Estimasi pengurangan:**
- Lodash (default import): ~70 KB minified, ~25 KB gzip
- Named import dari lodash-es: ~5 KB (hanya 2 fungsi), ~2 KB gzip
- Vanilla JS: 0 KB (tidak perlu library)
- Penghematan: ~65 KB minified atau ~23 KB gzip

Buat rencana optimasi untuk ketiga temuan di atas. Sertakan langkah konkret dan estimasi penghematan total.
