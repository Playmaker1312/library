# 64. v-memo dan shallowRef — Optimasi Rendering List

## Penjelasan

Dua alat utama untuk mengoptimasi rendering daftar/list di Vue 3:

### `v-memo`

Directive yang membuat Vue **melewati** proses diffing dan re-render komponen dalam `v-for` jika nilai dependency-nya tidak berubah. Biasanya digunakan bersama `v-for`.

```vue
<div v-for="book in books" :key="book.id" v-memo="[book.id, book.price]">
  <BookCard :book="book" />
</div>
```

BookCard hanya akan di-render ulang jika `book.id` atau `book.price` berubah.

### `shallowRef`

Ref yang hanya membuat **level pertama** menjadi reaktif. Nilai di dalam objek/array **tidak** dilacak secara mendalam (deep). Cocok untuk data besar yang diganti secara utuh, bukan dimutasi.

```typescript
import { shallowRef } from 'vue'

const books = shallowRef<Book[]>([])

// ✅ BAIK — replace seluruh array
books.value = newBooks

// ❌ BURUK — mutate array, tidak terdeteksi
books.value.push(newBook)
```

## Fungsi

- **`v-memo`**: Menghilangkan re-render tidak perlu pada item list yang tidak berubah — komponen besar seperti `BookCard` dengan gambar dan tombol jadi jauh lebih ringan.
- **`shallowRef`**: Menghilangkan overhead deep reactivity pada array raksasa (ribuan item). Tidak perlu Proxy di setiap properti tiap objek.
- Keduanya bekerja bersama: `shallowRef` untuk menyimpan data, `v-memo` untuk mengontrol render.

## Cara Implementasi

### 1. Daftar Buku dengan `v-memo`

```vue
<!-- BookList.vue -->
<script setup lang="ts">
import { computed } from 'vue'
import BookCard from './BookCard.vue'
import { useBookStore } from '@/stores/bookStore'

interface Book {
  id: number
  title: string
  price: number
  image: string
  isSelected: boolean
}

const bookStore = useBookStore()

const books = computed(() => bookStore.books)
const selectedIds = computed(() => bookStore.selectedIds)

function isSelected(id: number): boolean {
  return selectedIds.value.has(id)
}
</script>

<template>
  <div class="book-list">
    <div
      v-for="book in books"
      :key="book.id"
      v-memo="[book.id, book.price, isSelected(book.id)]"
    >
      <BookCard
        :book="book"
        :is-selected="isSelected(book.id)"
        @toggle="bookStore.toggleSelection(book.id)"
      />
    </div>
  </div>
</template>
```

Dengan `v-memo` di atas:
- Jika hanya `book.title` yang berubah → BookCard **tetap tidak re-render** (title tidak ada di dependency)
- Jika `book.price` berubah → BookCard **re-render** (price ada di dependency)
- Kita sengaja tidak memasukkan semua properti ke `v-memo` — hanya properti yang digunakan oleh komponen anak

### 2. Array Besar dengan `shallowRef`

```typescript
// stores/bookStore.ts
import { defineStore } from 'pinia'
import { shallowRef } from 'vue'
import type { Book } from '@/types'

export const useBookStore = defineStore('bookStore', () => {
  // shallowRef — tidak deep reactive
  const books = shallowRef<Book[]>([])

  // State lain — tetap ref biasa karena kecil
  const selectedIds = shallowRef<Set<number>>(new Set())
  const loading = ref(false)

  async function fetchBooks() {
    loading.value = true
    try {
      const response = await fetch('/api/books')
      const data: Book[] = await response.json()

      // ✅ Replace seluruh array — shallowRef mendeteksi perubahan
      books.value = data
    } finally {
      loading.value = false
    }
  }

  function toggleSelection(id: number) {
    const newSet = new Set(selectedIds.value)

    if (newSet.has(id)) {
      newSet.delete(id)
    } else {
      newSet.add(id)
    }

    // ✅ Replace dengan Set baru
    selectedIds.value = newSet
  }

  // ❌ JANGAN LAKUKAN INI — shallowRef tidak mendeteksi
  // books.value[0].title = 'New Title' // tidak akan trigger re-render

  return { books, selectedIds, loading, fetchBooks, toggleSelection }
})
```

### 3. Kombinasi — List Besar dengan Update Parsial

```typescript
function updateBookPrice(bookId: number, newPrice: number) {
  // shallowRef — kita harus replace seluruh array
  const updated = books.value.map(book =>
    book.id === bookId
      ? { ...book, price: newPrice }
      : book
  )

  books.value = updated
  // ✅ v-memo akan mendeteksi perubahan price → re-render hanya item itu
}
```

## Analogi — Toko Buku

**`v-memo`** seperti **"daftar periksa"** pegawai toko. Daripada ngecek ulang **SEMUA rak** setiap kali ada perubahan (re-render semua), pegawai cek: "Apakah rak ini berubah sejak terakhir kulihat?" (`v-memo`). Kalau tidak ada perubahan, lewati. Kalau ada buku baru (id berubah) atau harga berubah (price berubah), baru rak itu diperiksa ulang.

**`shallowRef`** seperti **"rak buku display"** — isinya buku-buku yang sudah jadi (data matang dari server). Tidak perlu sensor di setiap buku — cukup tahu kapan **seluruh rak** diganti. Kalau harga 1 buku berubah, kita ganti seluruh rak dengan yang baru (`books.value = [...newBooks]`). Vue lihat referensi rak berubah → trigger re-render. `v-memo` kemudian memastikan hanya kartu harga buku itu yang berubah, bukan semua buku.

Cocok untuk daftar buku yang tidak sering berubah isi individunya.

## Dipakai untuk Apa

- **Daftar produk** (e-commerce) — ratusan item dengan kartu kompleks
- **Tabel data** dengan ribuan baris (data grid)
- **Daftar chat / pesan** — update hanya pada pesan baru
- **Grid gambar** — komponen kartu berat karena thumbnail
- **List yang sering di-filter atau di-sort** — item tidak berubah, hanya urutan
- **Data dari API** yang di-fetch ulang secara periodik

## Kesalahan Umum

| Kesalahan | Dampak | Solusi |
|-----------|--------|--------|
| `v-memo` dengan **terlalu banyak dependency** | Overhead pengecekan > benefit penghematan render | Masukkan hanya dependency yang benar-benar digunakan anak |
| `shallowRef` di-mutasi dengan `push()` / direct mutation | Vue tidak mendeteksi perubahan — UI tidak update | Selalu replace dengan array/objek baru |
| `shallowRef` untuk form/data yang sering diubah per-field | Kehilangan reaktivitas — form tidak update | Gunakan `ref()` biasa untuk data yang sering dimutasi |
| `v-memo` tanpa `:key` | Vue warning, perilaku tidak terdefinisi | Selalu gunakan `:key` bersama `v-for` |
| `v-memo` pada list kecil (< 20 item) | Overhead lebih besar dari manfaat | Hanya gunakan untuk list panjang (> 50-100 item) |
| `shallowRef` untuk objek yang di-edit propertinya | Perubahan tidak terdeteksi | Ganti seluruh objek `{ ...oldObj, prop: newVal }` |

## Hubungan dengan Materi Sebelumnya

**Level 1 (Dasar Vue & TypeScript):** Dulu kita pakai `ref()` dan `reactive()` untuk semuanya. `v-for` sederhana dengan `:key` — cukup untuk 10 item, tapi tidak untuk 1000 item.

**Level 2 (State Management & Composables):** Store Pinia awal pakai `ref()` biasa. Setelah store membesar dengan ribuan buku, kita perlu `shallowRef` dan pola replace array.

**Level 3 (Vue Router):** Setiap halaman di-lazy load (poin 63), tapi komponen di dalamnya masih re-render semua — `v-memo` memperbaiki runtime.

**Level 4 (Testing):** Test harus tahu bahwa `shallowRef` butuh replace, bukan mutate. Test yang melakukan `books.value.push()` akan gagal.

**Level 5 (Backend Integration):** Data dari API biasanya di-fetch sebagai array utuh — cocok untuk `shallowRef` karena kita replace seluruh data setiap fetch.

**Level 6 (Sekarang):** Setelah bundle size dioptimasi (poin 63), sekarang optimasi runtime. Selanjutnya bundle analysis (poin 65) dan image optimization (poin 66).

## Soal Latihan

### Soal 1

Anda punya daftar 500 buku. Setiap buku punya `id`, `title`, `price`, `stock`, `imageUrl`, `description`. Komponen `BookCard` hanya menampilkan `title`, `price`, dan tombol "Beli". Saat ini semua properti buku dijadikan dependency `v-memo`:

```vue
v-memo="[book.id, book.title, book.price, book.stock, book.imageUrl, book.description]"
```

Apa masalahnya? Perbaiki daftar dependency dan jelaskan alasannya.

<details>
<summary>Jawaban</summary>

**Masalah:** Dependency terlalu banyak. Vue harus mengecek 6 properti setiap kali ada perubahan di daftar buku. Overhead pengecekan hampir sama besar dengan re-render itu sendiri. Apalagi `stock`, `imageUrl`, dan `description` tidak digunakan `BookCard` — perubahan properti itu tidak perlu memicu re-render.

**Perbaikan:**

```vue
v-memo="[book.id, book.title, book.price]"
```

Hanya properti yang benar-benar digunakan oleh `BookCard` yang perlu dijadikan dependency. `id` untuk key, `title` dan `price` untuk tampilan. Jika tombol "Beli" bergantung pada `stock`, barulah `stock` ditambahkan.

Prinsip: **semakin sedikit dependency, semakin cepat pengecekan**.

</details>

### Soal 2

Tim Anda menggunakan `shallowRef` untuk menyimpan daftar buku:

```typescript
const books = shallowRef<Book[]>([])

// Di komponen, pengguna bisa update stok buku
function updateStock(bookId: number, newStock: number) {
  const book = books.value.find(b => b.id === bookId)
  if (book) {
    book.stock = newStock  // Tidak terdeteksi!
  }
}
```

Mengapa Vue tidak mendeteksi perubahan? Perbaiki fungsi `updateStock` tanpa kehilangan keuntungan performa `shallowRef`.

<details>
<summary>Jawaban</summary>

`shallowRef` hanya membuat **referensi level-1** menjadi reaktif (yaitu `books.value`). Properti di dalam objek buku (`book.stock`) tidak dibungkus Proxy — mutasi langsung tidak memicu reaktivitas.

**Perbaikan — replace dengan objek baru (immutable update):**

```typescript
function updateStock(bookId: number, newStock: number) {
  books.value = books.value.map(book =>
    book.id === bookId
      ? { ...book, stock: newStock }  // Objek baru
      : book                           // Referensi yang sama
  )
}
```

Dengan `map`, kita membuat array baru → `shallowRef` mendeteksi perubahan referensi. Buku yang tidak berubah tetap mempertahankan referensi objek lama — `v-memo` bisa memanfaatkannya untuk skip re-render. Hanya kartu buku dengan `id === bookId` yang akan di-render ulang.

</details>
