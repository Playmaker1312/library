# 70. Setup Error Monitoring — Sentry

## Penjelasan

Sentry adalah platform error monitoring yang menangkap error yang terjadi di production. Saat pengguna mengalami error di browser, Sentry mengirimkan laporan lengkap ke dashboard developer — termasuk stack trace, browser yang dipakai, langkah-langkah yang dilakukan pengguna sebelum error, dan data konteks lainnya.

Tanpa Sentry, developer hanya tahu ada error jika pengguna melapor. Dengan Sentry, developer bisa tahu dan memperbaiki error **bahkan sebelum pengguna sadar ada masalah**.

Integrasi Sentry dengan Vue.js mencakup:

- **Error boundary** — tangkap error di komponen Vue
- **Routing tracing** — lihat halaman mana yang error
- **Performance monitoring** — lihat performa halaman (opsional)
- **Source maps** — stack trace yang bisa dibaca (kode asli, bukan minified)

## Fungsi

- Developer tahu ketika ada error di production — tanpa nunggu user lapor
- Informasi lengkap: browser, OS, route, actions sebelum error
- Prioritaskan bug berdasarkan frekuensi dan jumlah user terkena dampak
- Integrasi dengan CI/CD — tag version agar tahu error muncul di rilis mana
- Performance monitoring — lihat halaman mana yang lambat

## Cara Implementasi / Kode

### 1. Install Sentry

```bash
npm install @sentry/vue @sentry/browser
```

### 2. Setup di `src/main.ts`

```ts
import { createApp } from 'vue'
import { createRouter, createWebHistory } from 'vue-router'
import * as Sentry from '@sentry/vue'
import App from './App.vue'
import { validateEnv } from './utils/env'

const app = createApp(App)
const router = createRouter({
  history: createWebHistory(),
  routes: [
    // ... routes
  ],
})

const env = import.meta.env.PROD ? validateEnv() : null

Sentry.init({
  app,
  dsn: import.meta.env.VITE_SENTRY_DSN,
  environment: import.meta.env.MODE, // 'production', 'staging', dll
  release: `bukuku@${__APP_VERSION__}`, // versi aplikasi
  integrations: [
    Sentry.browserTracingIntegration({ router }),
    Sentry.replayIntegration({
      // Rekam 30 detik sebelum error (tanpa data sensitif)
      maskAllText: true,
      blockAllMedia: true,
    }),
  ],
  // Sampling rate: 10% di production, 100% di dev
  tracesSampleRate: import.meta.env.PROD ? 0.1 : 1.0,
  replaysSessionSampleRate: 0.1,
  replaysOnErrorSampleRate: 1.0,
})

app.use(router)
app.mount('#app')
```

### 3. Tambahkan version di `vite.config.ts`

```ts
import { defineConfig } from 'vite'

export default defineConfig({
  define: {
    __APP_VERSION__: JSON.stringify(process.env.npm_package_version),
  },
})
```

### 4. Upload source maps (agar stack trace bisa dibaca)

```bash
npx @sentry/cli releases files bukuku@1.0.0 upload-sourcemaps dist/assets/
```

Atau otomatis via Sentry Vite Plugin:

```bash
npm install @sentry/vite-plugin
```

```ts
// vite.config.ts
import { sentryVitePlugin } from '@sentry/vite-plugin'

export default defineConfig({
  plugins: [
    vue(),
    sentryVitePlugin({
      org: 'nama-org-sentry',
      project: 'bukuku',
      authToken: process.env.SENTRY_AUTH_TOKEN,
      release: {
        name: `bukuku@${process.env.npm_package_version}`,
      },
    }),
  ],
  build: {
    sourcemap: true, // diperlukan untuk upload source maps
  },
})
```

### 5. Test Sentry

```ts
// Buat tombol di komponen untuk test
function triggerError() {
  throw new Error('Test error — Sentry integration')

```

Klik tombol tersebut → error akan muncul di Sentry dashboard dalam beberapa detik.

### 6. Error Boundary (opsional)

```vue
<template>
  <SentryErrorBoundary
    :showDialog="true"
    @onError="handleError"
  >
    <router-view />
  </SentryErrorBoundary>
</template>
```

## Analogi — Toko Buku

Sentry seperti **CCTV di seluruh toko** yang merekam SETIAP kali ada yang salah:

- Buku jatuh dari rak (error)
- Pegawai tersandung kabel
- Mesin kasir error saat transaksi
- Lampu mati di sudut toko

Semua terekam dengan detail: **kapan** (timestamp), **di rak mana** (route), **browser apa yang dipakai pengunjung** (Chrome/Firefox), **langkah apa yang dilakukan sebelum jatuh** (user actions replay).

Tanpa Sentry, kita tidak tahu ada masalah sampai pelanggan komplain — "Buku saya terjatuh ketika halaman 5!" — dan itu pun kita tidak tahu persis apa yang terjadi.

Dengan Sentry, kita bisa **FIX sebelum pelanggan sadar ada masalah**. Bahkan kadang kita sudah fix sebelum pelanggan mengalami error berikutnya.

**Session replay** seperti rekaman CCTV yang bisa diputar ulang — melihat persis apa yang dilakukan pengguna sebelum error terjadi.

## Dipakai untuk Apa

- **Production monitoring** — aplikasi Vue.js yang sudah live
- **Tracking bug** — lihat frekuensi error, prioritaskan perbaikan
- **Performance monitoring** — halaman mana yang lambat dimuat
- **User feedback** — Sentry bisa menampilkan dialog "Oops, ada error" ke pengguna
- **Release tracking** — tahu versi mana yang memperkenalkan bug baru

## Kesalahan Umum

| Kesalahan | Akibat | Solusi |
|-----------|--------|--------|
| DSN dianggap rahasia | Developer takut memasukkan DSN di frontend | DSN adalah **public key** — aman dibundel. Jangan expose auth token! |
| Sampling rate terlalu tinggi | Boros kuota Sentry (berbayar per event) | Set `tracesSampleRate: 0.1` (10%) di production |
| Source maps tidak di-upload | Stack trace isinya kode minified (tidak terbaca) | Upload source maps otomatis via Sentry plugin |
| Error diabaikan | Banyak error kecil membuat noise, error serius tenggelam | Gunakan `beforeSend` untuk filter error tertentu |
| Lupa setup di staging | Error yang muncul di staging tidak terdeteksi | Set `environment` dengan benar di setiap environment |

## Hubungan dengan Materi Sebelumnya

Di Poin 69, CI/CD mencegah error **sebelum** deploy — testing, linting, type-check. Tapi tetap ada error yang lolos (logic error, error yang hanya muncul di browser/user tertentu). Sentry menangkap error yang **lolos** dari CI/CD dan terjadi di production.

Ini adalah lapisan pertahanan terakhir: kode diuji (Level 6), di-build (Poin 67), di-deploy (Poin 68), melalui CI/CD (Poin 69), dan dimonitoring (Poin 70). Siklus development lengkap.

## Soal Latihan

### Soal 1

Seorang developer memasukkan DSN Sentry langsung di kode:

```ts
Sentry.init({
  dsn: 'https://rahasia@sentry.io/123',
})
```

Ia khawatir DSN ini terexpose karena ada di bundle frontend. Apakah ini masalah?

<details>
<summary>Jawaban</summary>
**Tidak masalah.** DSN Sentry adalah **public key** yang memang dirancang untuk dimasukkan di client-side. DSN hanya berfungsi untuk mengirim event ke project Sentry — tidak bisa digunakan untuk mengakses data, mengubah konfigurasi, atau hal berbahaya lainnya. Yang harus dijaga adalah **auth token** (digunakan untuk upload source maps, manage project) — auth token tidak boleh dimasukkan di bundle frontend dan hanya boleh dipakai di server-side atau CI/CD.
</details>

### Soal 2

Setelah deploy, Sentry menangkap ribuan error per jam — padahal aplikasi tidak sedang dikunjungi banyak orang. Setelah diselidiki, semua error berasal dari bot/crawler yang mencoba mengakses route invalid. Bagaimana cara mengatasi noise ini?

<details>
<summary>Jawaban</summary>
Gunakan hook `beforeSend` untuk memfilter error dari bot yang tidak relevan, atau filter berdasarkan pola URL:

```ts
Sentry.init({
  // ...
  beforeSend(event) {
    // Abaikan error dari bot
    const userAgent = event.request?.headers?.['User-Agent'] ?? ''
    if (/bot|crawler|spider/i.test(userAgent)) {
      return null // tidak dikirim ke Sentry
    }

    // Abaikan error 404 di route yang tidak dikenal
    if (event.exception?.values?.[0]?.type === 'NotFoundError') {
      return null
    }

    return event
  },
})
```

Atau tingkatkan `tracesSampleRate` dan set `replaysSessionSampleRate` lebih rendah jika kuota cepat habis.
</details>
