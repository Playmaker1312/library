# 74. Server API Routes — Backend Ringan di Nuxt

## Penjelasan

Nuxt memiliki folder `server/api/` yang berfungsi sebagai backend endpoint. File di folder ini secara otomatis menjadi API endpoint yang hanya jalan di **server** — tidak pernah terekspos ke client-side JavaScript.

**Pemetaan file ke endpoint:**

| File | HTTP Method | Endpoint |
|---|---|---|
| `server/api/books.get.ts` | GET | `/api/books` |
| `server/api/books.post.ts` | POST | `/api/books` |
| `server/api/books/[id].get.ts` | GET | `/api/books/:id` |
| `server/api/books/[id].delete.ts` | DELETE | `/api/books/:id` |
| `server/api/contact.post.ts` | POST | `/api/contact` |

`defineEventHandler()` — function untuk menangani request. `getQuery(event)` untuk query params, `readBody(event)` untuk request body.

---

## Fungsi

- Backend ringan di dalam Nuxt — proxy, transform data, handle secret
- BFF (Backend For Frontend) — menggabungkan beberapa API eksternal menjadi satu endpoint yang nyaman untuk frontend
- API proxy — panggil NestJS/Laravel dari sisi server, API key tidak terekspos ke client
- Serverless-ready — deploy ke Vercel, Netlify, atau Node server

---

## Cara Implementasi

### 1. Server API sederhana — `server/api/books.get.ts`

```ts
// server/api/books.get.ts
export default defineEventHandler(async (event) => {
  const books = [
    { id: '1', title: 'Clean Code', author: 'Robert Martin', price: 120000 },
    { id: '2', title: 'Design Patterns', author: 'Gang of Four', price: 150000 },
    { id: '3', title: 'Refactoring', author: 'Martin Fowler', price: 135000 }
  ]
  return books
})
```

### 2. Dynamic route — `server/api/books/[id].get.ts`

```ts
// server/api/books/[id].get.ts
export default defineEventHandler(async (event) => {
  const id = getRouterParam(event, 'id')

  const books = [
    { id: '1', title: 'Clean Code', author: 'Robert Martin', price: 120000 },
    { id: '2', title: 'Design Patterns', author: 'Gang of Four', price: 150000 }
  ]

  const book = books.find(b => b.id === id)

  if (!book) {
    throw createError({
      statusCode: 404,
      statusMessage: 'Buku tidak ditemukan'
    })
  }

  return book
})
```

### 3. POST endpoint — `server/api/books.post.ts`

```ts
// server/api/books.post.ts
export default defineEventHandler(async (event) => {
  const body = await readBody(event)

  // Validasi sederhana
  if (!body.title || !body.author) {
    throw createError({
      statusCode: 400,
      statusMessage: 'Title dan author wajib diisi'
    })
  }

  // Simulasi simpan ke database
  const newBook = {
    id: Date.now().toString(),
    title: body.title,
    author: body.author,
    price: body.price ?? 0
  }

  return newBook
})
```

### 4. Proxy ke backend eksternal (NestJS)

```ts
// server/api/books.get.ts — proxy ke NestJS
export default defineEventHandler(async (event) => {
  const config = useRuntimeConfig()
  const backendUrl = config.backendBaseUrl // dari nuxt.config.ts

  const books = await $fetch(`${backendUrl}/books`, {
    headers: {
      'Authorization': `Bearer ${config.apiSecret}` // tidak terekspos ke client!
    }
  })

  return books
})
```

### 5. Konfigurasi runtimeConfig di `nuxt.config.ts`

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  runtimeConfig: {
    apiSecret: 'rahasia-server',    // hanya di server
    backendBaseUrl: 'http://localhost:3001', // hanya di server
    public: {
      siteUrl: 'https://bookstore.com' // di client & server
    }
  }
})
```

### 6. Query parameter — `server/api/books/search.get.ts`

```ts
// server/api/books/search.get.ts
export default defineEventHandler(async (event) => {
  const query = getQuery(event)
  const keyword = String(query.q || '').toLowerCase()

  const allBooks = [
    { id: '1', title: 'Clean Code', author: 'Robert Martin' },
    { id: '2', title: 'Design Patterns', author: 'Gang of Four' }
  ]

  return allBooks.filter(b =>
    b.title.toLowerCase().includes(keyword) ||
    b.author.toLowerCase().includes(keyword)
  )
})
```

Akses: `/api/books/search?q=clean`

## Analogi — Toko Buku

Server API routes adalah **meja back office** di toko.

Pelanggan (browser) minta buku ke pegawai etalase (`useFetch` → `/api/books`). Pegawai etalase tidak langsung ke gudang utama (NestJS) — dia lewat **meja back office** (`server/api/`) yang meneruskan permintaan.

**Keuntungan:**
- **Kunci gudang (API key)** hanya ada di back office — tidak perlu dibawa keliling toko oleh pegawai etalase.
- Meja back office bisa **mengubah format pesanan** (transform data) sebelum sampai ke etalase.
- Jika gudang utama pindah alamat (backend migration), cukup ganti di satu tempat — meja back office.

Tanpa server API routes, pegawai etalase harus lari langsung ke gudang — dan membawa kunci gudang kemana-mana (API key di client-side = bocor).

## Kesalahan Umum

| Kesalahan | Akibat | Solusi |
|---|---|---|
| File `server/` hanya jalan di development | Error 404 di production | Butuh adapter deployment (vercel, netlify, node middleware) |
| Route collision — nama file sama | Method tidak dikenali | Gunakan suffix `.get.ts`, `.post.ts`, dll |
| `useRuntimeConfig().xxx` tidak terdefinisi | `undefined` — crash | Pastikan `runtimeConfig` di-set di `nuxt.config.ts` |
| Menyimpan secret di `public.runtimeConfig` | Secret bocor ke client | Gunakan `runtimeConfig` (tanpa `public`) untuk server-only |
| `readBody` untuk GET request | Error — body tidak tersedia di GET | Gunakan `getQuery(event)` untuk query params |

## Hubungan dengan Materi Sebelumnya

**Poin 73:** `useFetch` sekarang bisa memanggil `/api/books` — endpoint yang baru dibuat di `server/api/`. Client tidak tahu apakah data berasal dari file lokal, database, atau NestJS.

**Level 6 (NestJS):** Di Level 6, kita membuat backend NestJS sendiri. Server API routes Nuxt bisa menjadi **proxy** atau **middleware** antara frontend dan NestJS. Ini memisahkan `apiSecret` dan `backendUrl` dari client-side bundle.

**Alur lengkap:**

```
Browser → useFetch('/api/books')
        → server/api/books.get.ts (proxy)
        → $fetch('http://localhost:3001/books', { headers: { Authorization } })
        → NestJS backend
        → Response kembali
```

### Soal 2

Apa fungsi `readBody(event)` dan method HTTP apa yang mendukungnya?

<details>
<summary>Jawaban</summary>

`readBody(event)` digunakan untuk membaca request body dari client. Hanya mendukung method HTTP yang memiliki body: **POST, PUT, PATCH, DELETE**. Untuk **GET** request, gunakan `getQuery(event)` untuk membaca query parameter.

</details>
