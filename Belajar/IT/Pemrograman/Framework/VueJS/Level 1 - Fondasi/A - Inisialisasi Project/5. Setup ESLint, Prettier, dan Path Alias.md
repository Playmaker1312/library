# 5. Setup ESLint, Prettier, dan Path Alias

## Penjelasan

**ESLint** adalah *linter* yang mendeteksi error dan *code smell* di JavaScript/TypeScript. **Prettier** adalah *formatter* yang merapikan kode secara otomatis (spasi, kutip, indentasi). **Path alias** (`@/`) adalah fitur yang membuat import lebih pendek dan mudah dibaca.

Ketiganya sudah disediakan oleh `create-vue` jika kita memilih YES saat prompt. Namun kita perlu memastikan konfigurasinya sudah benar dan saling terintegrasi.

## Fungsi

| Tool | Fungsi |
|------|--------|
| ESLint | Menangkap error sebelum runtime: variabel tidak dipakai, `any` tersembunyi, import salah |
| Prettier | Format kode konsisten di seluruh tim: indentasi 2 spasi, pakai single quote, trailing comma |
| Path alias | Import relatif `../../../components/Foo.vue` → `@/components/Foo.vue` |

## Cara Implementasi

### Path Alias

#### 1. Di `vite.config.ts`

Jika belum ada, tambahkan resolve alias:

```typescript
import { fileURLToPath, URL } from 'node:url'
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import tailwindcss from '@tailwindcss/vite'

export default defineConfig({
  plugins: [
    vue(),
    tailwindcss(),
  ],
  resolve: {
    alias: {
      '@': fileURLToPath(new URL('./src', import.meta.url)),
    },
  },
})
```

#### 2. Di `tsconfig.json` (atau `tsconfig.app.json`)

```json
{
  "compilerOptions": {
    "target": "ESNext",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "paths": {
      "@/*": ["./src/*"]
    },
    "baseUrl": "."
  },
  "include": ["src/**/*.ts", "src/**/*.vue"]
}
```

**WAJIB**: Path alias harus di dua tempat: `vite.config.ts` (agar Vite bisa resolve saat build) dan `tsconfig.json` (agar TypeScript dan IDE pahum). Kalau hanya di Vite, TypeScript akan error merah.

### ESLint

`create-vue` sudah menggenerate `.eslintrc.cjs` dengan aturan Vue 3 + TypeScript. Untuk integrasi dengan Prettier:

```bash
# Install plugin agar ESLint dan Prettier tidak bertabrakan
npm install -D eslint-config-prettier
```

Update `.eslintrc.cjs`:

```javascript
/* eslint-env node */
require('@rushstack/eslint-patch/modern-module-resolution')

module.exports = {
  root: true,
  extends: [
    'plugin:vue/vue3-essential',
    'eslint:recommended',
    '@vue/eslint-config-typescript',
    '@vue/eslint-config-prettier/skip-formatting',  // Nonaktifkan aturan ESLint yang bentrok dengan Prettier
  ],
  parserOptions: {
    ecmaVersion: 'latest',
  },
  rules: {
    'vue/multi-word-component-names': 'off',  // Izinkan nama komponen 1 kata
    '@typescript-eslint/no-unused-vars': 'warn',
  },
}
```

### Prettier

Edit `.prettierrc.json`:

```json
{
  "$schema": "https://json.schemastore.org/prettierrc",
  "semi": false,
  "singleQuote": true,
  "tabWidth": 2,
  "trailingComma": "all",
  "printWidth": 100,
  "arrowParens": "always"
}
```

### Script di `package.json`

Pastikan script berikut ada:

```json
{
  "scripts": {
    "dev": "vite",
    "build": "vue-tsc && vite build",
    "preview": "vite preview",
    "lint": "eslint . --ext .vue,.js,.jsx,.cjs,.mjs,.ts,.tsx,.cts,.mts --fix",
    "format": "prettier --write src/"
  }
}
```

### Test Path Alias

Buat file `src/types/index.ts`:

```typescript
export interface IBook {
  id: number
  title: string
  author: string
  price: number
  stock: number
}
```

Lalu di komponen:

```vue
<script setup lang="ts">
import { ref } from 'vue'
import type { IBook } from '@/types'  // ← path alias, bukan ../../types

const books = ref<IBook[]>([])
</script>
```

## Analogi: Toko Buku

Bayangkan toko buku yang dikelola oleh tim yang terdiri dari 5 orang. Tanpa ESLint & Prettier, setiap orang menulis dengan gaya masing-masing — ada yang pakai tanda petik ganda (`"`), ada yang petik tunggal (`'`), ada yang indentasi 4 spasi, ada yang 2 spasi. Hasilnya? Kode berantakan seperti rak buku yang buku-bukunya ditaruh sembarangan.

**Path alias** seperti memberi nama pintu belakang toko — daripada harus mutar lewat depan (`../../../gudang/pengiriman`), Anda cukup masuk lewat pintu khusus (`@/gudang/pengiriman`). Lebih cepat, lebih pendek, dan tidak pusing hitung `../`.

**ESLint** adalah aturan toko: "Buku harus tegak, label harga menghadap ke depan, sampul tidak boleh terbalik."
**Prettier** adalah petugas toko yang setiap malam membereskan semua buku agar rapi kembali.

## Dipakai Untuk Apa

- **Tim development > 1 orang**: Konsistensi kode mutlak diperlukan.
- **Open source project**: Kontributor dari berbagai latar belakang harus mengikuti satu standar.
- **Code review**: Dengan ESLint, error dasar tidak perlu dibahas di review — fokus ke logika bisnis.
- **CI/CD pipeline**: `npm run lint` di pipeline menjamin kode yang masuk ke main branch sudah sesuai standar.

## Kesalahan Umum

| Kesalahan | Dampak | Cara Hindari |
|-----------|--------|--------------|
| Path alias hanya di `vite.config.ts`, lupa di `tsconfig.json` | Vite jalan, TypeScript error merah | **Selalu setup di kedua tempat** |
| ESLint dan Prettier konflik (misal: ESLint minta `semi: true`, Prettier `semi: false`) | Save → format Prettier → ESLint error | Pakai `eslint-config-prettier` untuk nonaktifkan aturan ESLint yang redundant |
| Lupa `npm run lint` sebelum commit | Kode kotor masuk ke repo | Integrasikan dengan Husky + lint-staged (materi poin 6) |
| Menonaktifkan ESLint rules terlalu agresif | TypeScript jadi tidak berguna | Jangan `off` rules seperti `no-unused-vars` — ubah ke `warn` jika perlu |
| Path alias `@/` juga digunakan di `index.html` | Build error | Path alias hanya untuk TypeScript/JavaScript import, bukan untuk HTML |

## Hubungan dengan Materi Sebelumnya

**Poin 4** kita setup Tailwind untuk styling. Sekarang kita setup ESLint (kualitas kode), Prettier (format), dan Path Alias (import bersih). Semua tools ini akan dipakai di seluruh siklus pengembangan.

## Soal Latihan

**Soal 1:** Apa yang terjadi jika kita hanya setup path alias di `vite.config.ts` tetapi tidak di `tsconfig.json`? Apa error yang muncul?

**Jawaban:**
Vite akan berhasil melakukan build karena Vite membaca `vite.config.ts`. Namun TypeScript (dan ekstensi VSCode/Volar) akan memberikan error merah:
- `Cannot find module '@/types' or its corresponding type declarations.`
- Semua import yang menggunakan `@/` akan ditandai error.
- `vue-tsc` akan gagal saat `npm run build` (karena `npm run build` menjalankan `vue-tsc && vite build`).
- IDE suggestions dan auto-import juga tidak akan bekerja.

**Soal 2:** Di file `.prettierrc.json`, apa arti dari `"semi": false`? Dan kenapa tim perlu menyepakati aturan seperti ini?

**Jawaban:**
`"semi": false` berarti Prettier akan **menghapus titik koma** (`;`) di akhir statement JavaScript jika tidak diperlukan. Contoh:
```typescript
// Dengan semi: true
const name = "Vue";

// Dengan semi: false
const name = "Vue"
```
Tim perlu menyepakati aturan ini agar:
1. **Tidak ada perdebatan di code review** tentang preferensi gaya pribadi.
2. **Git diff lebih bersih** — tidak ada perubahan yang hanya karena titik koma.
3. **Onboarding lebih cepat** — developer baru langsung mengikuti standar tim tanpa tanya "pake semi atau nggak?".
