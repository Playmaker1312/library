# 9. Membuat HomeView — Halaman Katalog Buku Statis

## Penjelasan

Setelah bisa menampilkan satu buku, sekarang kita akan menampilkan **banyak buku** dalam bentuk daftar/katalog. Kita akan menggunakan:

1. **Interface TypeScript** — untuk mendefinisikan struktur data Book
2. **Array of books** — data buku yang di-hardcode
3. **`v-for`** — looping direktif Vue untuk merender elemen berulang kali
4. **`:key`** — atribut wajib untuk membantu Vue melacak setiap item

## Fungsi

| Bagian | Fungsi |
|--------|--------|
| `interface Book` | Mendefinisikan bentuk data buku (title, author, price, dll.) — memastikan konsistensi data |
| `books: Book[]` | Array berisi data buku statis |
| `v-for="book in books"` | Mengulang elemen template untuk setiap item di array |
| `:key="book.id"` | Memberi identitas unik ke setiap elemen hasil loop — penting untuk performa update/re-render |

### Mengapa `:key` Penting?

Vue menggunakan `:key` untuk melacak setiap elemen di DOM virtual. Saat array berubah (ditambah/dihapus/diurut ulang), Vue bisa meminimalkan manipulasi DOM karena tahu elemen mana yang tetap sama.

**Aturan:** `:key` harus bernilai unik dan stabil — biasanya gunakan `id` dari database, bukan `index` array.

### Langkah-langkah
1. Definisikan `interface Book` dengan properti yang dibutuhkan
2. Buat array `books: Book[]` berisi data statis
3. Di template, gunakan `v-for="book in books"` pada elemen yang ingin diulang
4. Selalu tambahkan `:key="book.id"` untuk setiap item
5. Akses properti setiap buku dengan `book.title`, `book.price`, dll.

## Analogi — Toko Buku

| Teknik Vue | Analogi Toko Buku |
|------------|-------------------|
| `interface Book` | **Cetak biru / formulir data buku** — setiap buku harus punya: judul, pengarang, harga, sampul. Semua seragam formatnya. |
| `books: Book[]` | **Tumpukan kartu katalog** di meja — semua data buku ditulis manual di atas kertas (hardcode). |
| `v-for="book in books"` | **Mesin fotokopi** yang menggandakan template kartu buku untuk setiap buku. Satu template `div.book-card` difotokopi 4 kali, masing-masing diisi data buku berbeda. |
| `:key="book.id"` | **Nomor ISBN** — setiap buku punya nomor unik. Kalau ada buku baru datang, kita tahu persis di mana menaruhnya tanpa mengacak urutan rak. |

## Dipakai untuk Apa di Dunia Nyata

- **Halaman katalog produk** di e-commerce (buku, pakaian, elektronik)
- **Daftar artikel / blog posts**
- **Grid foto** di galeri
- **Tabel data** (daftar pengguna, transaksi)
- **Dropdown menu** (daftar opsi)

## Kesalahan Umum

| Kesalahan | Penjelasan | Solusi |
|-----------|------------|--------|
| **Lupa `:key`** | Vue memunculkan warning di console. Performa update jadi buruk. | Selalu tambahkan `:key` dengan nilai unik. |
| **Pakai `index` sebagai `:key`** | Saat array diubah (ditambah/dihapus), index berubah dan Vue salah melacak elemen. | Gunakan `book.id` atau nilai unik lain. |
| **Array dianggap immutable** | Data statis memang tidak berubah, tapi nanti dengan data dinamis kita harus menghindari mutasi langsung. | Gunakan method immutable seperti `filter`, `map`, atau spread operator. |
| **Menaruh `v-for` dan `v-if` di elemen yang sama** | Keduanya punya prioritas yang membingungkan. | Pisahkan ke elemen `<template>` atau gunakan computed. |

## Hubungan dengan Materi Sebelumnya

Di **Poin 8**, kita belajar interpolasi `{{ }}` untuk satu buku. Sekarang kita **skalakan** dengan `v-for` untuk menampilkan banyak buku sekaligus. Konsep interpolasi tetap sama — kita hanya memasukkannya ke dalam loop.

Selanjutnya, di **Poin 10**, kita akan menambahkan logika kondisional (`v-if`/`v-show`) untuk menampilkan badge stok pada setiap buku.

## Soal Latihan + Jawaban

### Soal 1
Apa fungsi `:key` pada `v-for`? Mengapa tidak disarankan menggunakan index array sebagai key?

<details>
<summary>Jawaban</summary>

`:key` memberi identitas unik ke setiap elemen hasil loop sehingga Vue bisa melacak perubahan array secara efisien. Index array tidak disarankan karena saat array berubah (item dihapus/ditambah di tengah), index akan bergeser dan Vue salah mengidentifikasi elemen mana yang berubah, menyebabkan bug pada state komponen (misal: input field, animasi transisi).
</details>
