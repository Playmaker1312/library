# 51. Checkout Form — Form Multi-Step yang Kompleks

## Penjelasan

**Checkout form** adalah form multi-step (multi-langkah) yang membagi proses input data panjang menjadi beberapa tahap kecil. Di sini kita membuat form checkout 3 langkah:

| Step | Nama | Deskripsi |
|------|------|-----------|
| 1 | Informasi Pengiriman | Nama, alamat, no. HP, kode pos |
| 2 | Metode Pembayaran | Pilihan metode (transfer, kartu, e-wallet) + detail |
| 3 | Konfirmasi Pesanan | Ringkasan data + total harga |

Setiap step memiliki **schema Zod sendiri** dan validasi dijalankan saat user berpindah step. Data antar step disimpan di `reactive()` agar tidak hilang saat navigasi.

## Fungsi

- **Memecah form panjang** menjadi langkah kecil — user tidak kewalahan
- **Validasi per step** — error terdeteksi lebih awal sebelum lanjut
- **Progress indicator** — user tahu posisi mereka dalam alur
- **State persistent** — data tidak hilang saat bolak-balik antar step

## Cara Implementasi

### 1. Schema per step

```typescript
// src/schemas/checkout.schema.ts
import { z } from 'zod'

export const shippingSchema = z.object({
  namaLengkap: z.string().min(1, 'Nama lengkap harus diisi'),
  noHp: z
    .string()
    .min(10, 'Nomor HP minimal 10 digit')
    .regex(/^[0-9]+$/, 'Nomor HP hanya boleh angka'),
  alamat: z.string().min(10, 'Alamat minimal 10 karakter'),
  kota: z.string().min(1, 'Kota harus diisi'),
  kodePos: z
    .string()
    .length(5, 'Kode pos harus 5 digit')
    .regex(/^[0-9]+$/, 'Kode pos hanya boleh angka'),
})

export const paymentSchema = z.object({
  metode: z.enum(['transfer', 'kartu', 'ewallet'], {
    errorMap: () => ({ message: 'Pilih metode pembayaran' }),
  }),
  nomorRekening: z.string().optional(),
  namaBank: z.string().optional(),
  nomorKartu: z
    .string()
    .length(16, 'Nomor kartu harus 16 digit')
    .regex(/^[0-9]+$/, 'Nomor kartu hanya boleh angka')
    .optional()
    .or(z.literal('')),
})

export type ShippingForm = z.infer<typeof shippingSchema>
export type PaymentForm = z.infer<typeof paymentSchema>
```

<script setup lang="ts">
import { ref, reactive, computed } from 'vue'
import { useForm, useField, handleSubmit } from 'vee-validate'
import { toTypedSchema } from '@vee-validate/zod'
import { shippingSchema, paymentSchema, type ShippingForm, type PaymentForm } from '@/schemas/checkout.schema'
import FormField from '@/components/common/FormField.vue'

const currentStep = ref(1)
const totalSteps = 3

// Data checkout gabungan — persistent antar step (reactive)
const checkoutData = reactive<{
  shipping: Partial<ShippingForm>
  payment: Partial<PaymentForm>
}>({
  shipping: {},
  payment: {},
})

// ---- STEP 1: Shipping ----
const shippingForm = useForm<ShippingForm>({
  validationSchema: toTypedSchema(shippingSchema),
  initialValues: checkoutData.shipping,
})

const [namaLengkap, namaAttrs] = shippingForm.defineField('namaLengkap')
const [noHp, noHpAttrs] = shippingForm.defineField('noHp')
const [alamat, alamatAttrs] = shippingForm.defineField('alamat')
const [kota, kotaAttrs] = shippingForm.defineField('kota')
const [kodePos, kodePosAttrs] = shippingForm.defineField('kodePos')

// ---- STEP 2: Payment ----
const paymentForm = useForm<PaymentForm>({
  validationSchema: toTypedSchema(paymentSchema),
  initialValues: checkoutData.payment,
})

const [metode, metodeAttrs] = paymentForm.defineField('metode')
const [nomorKartu, kartuAttrs] = paymentForm.defineField('nomorKartu')

// ---- NAVIGASI ----
const stepValidity = reactive({ 1: false, 2: false })

async function nextStep() {
  if (currentStep.value === 1) {
    const { valid } = await shippingForm.validate()
    if (!valid) return
    stepValidity[1] = true
    Object.assign(checkoutData.shipping, shippingForm.values)
    currentStep.value++
  } else if (currentStep.value === 2) {
    const { valid } = await paymentForm.validate()
    if (!valid) return
    stepValidity[2] = true
    Object.assign(checkoutData.payment, paymentForm.values)
    currentStep.value++
  }
}

function prevStep() {
  if (currentStep.value > 1) currentStep.value--
}

const isFirstStep = computed(() => currentStep.value === 1)
const isLastStep = computed(() => currentStep.value === totalSteps)

## Analogi — Toko Buku

Checkout seperti proses belanja di toko yang terdiri dari 3 langkah:

1. **Step 1 (Pengiriman)** — Pegawai membungkus barang dan bertanya: "Alamatnya dikirim ke mana? Nama penerima siapa? No. HP-nya berapa?" — semua diisi, dicek dulu sebelum lanjut
2. **Step 2 (Pembayaran)** — "Mau bayar pakai apa? Tunai, kartu, atau QRIS?" — kalau kartu, dimintain nomor kartu
3. **Step 3 (Konfirmasi)** — Pegawai menunjukkan semua barang + total harga: "Ini barangnya, ini alamatnya, ini totalnya. **Sudah benar?**" — kalau sudah, pencet "Ya, pesan!"

Setiap langkah ada validasinya sendiri. Tidak bisa loncat ke langkah 3 sebelum langkah 1 selesai.

## Dipakai untuk Apa

- **E-commerce checkout** — form yang paling umum
- **Form pendaftaran multi-step** — register bertahap (profil, verifikasi, selesai)
- **Survey/Wizard** — kuesioner panjang yang dipecah per halaman
- **Setup wizards** — konfigurasi aplikasi langkah demi langkah

## Kesalahan Umum

| Kesalahan | Solusi |
|-----------|--------|
| State antar step hilang saat bolak-balik | Gunakan `reactive()` di level komponen — jangan local state per step |
| Validasi tidak dijalankan saat ganti step | Panggil `form.validate()` sebelum `currentStep++` |
| Progress bar tidak sinkron dengan step | Gunakan `computed` untuk persentase berdasarkan `currentStep` |
| Schema tumpang tindih antar step | Buat schema terpisah per step, jangan satu schema besar |
| Lupa `novalidate` di `<form>` | HTML validation bisa mengganggu navigasi multi-step |

## Hubungan dengan Materi Sebelumnya (Poin 48–50)

| Poin | Kontribusi di Checkout |
|------|------------------------|
| 48 (Schema Zod) | `shippingSchema` + `paymentSchema` — validasi per step |
| 49 (FormField) | Input seragam di semua step |
| 50 (VeeValidate + Login) | Pola `useForm`, `defineField`, `handleSubmit`, `errors`, `isSubmitting` di-*reuse* untuk setiap step |
| 51 (Checkout) | Semua digabung + manajemen navigasi multi-step + `reactive` state |
