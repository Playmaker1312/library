# Utility-First vs Component-Based

## Penjelasan
- CSS tradisional menggunakan pendekatan **component-based**: kita menulis class CSS kustom (`.btn-primary`, `.card-header`) yang diisi properti-properti di file `.css` terpisah.
- Masalah utama component-based:
  - **Naming**: Kamu harus memikirkan nama class setiap kali, apalagi untuk variasi kecil. Nama jadi panjang dan tidak konsisten.
  - **Specificity**: Selektor bertingkat (`.card .header .title span`) menyebabkan specificity tabrakan dan butuh `!important` yang berantakan.
  - **Unused CSS**: File CSS membengkak dengan class yang tidak terpakai karena kita takut menghapus sesuatu yang dipakai di tempat lain.
- Tailwind menggunakan pendekatan **utility-first**: kamu menulis class utility kecil (seperti `p-4`, `text-center`, `bg-blue-500`) langsung di HTML.
- Setiap utility class hanya melakukan satu hal dan tidak bentrok specificity karena semua flat (satu level).
- Kamu tetap bisa membuat component — lewat `@apply` di CSS atau dengan komponen framework JS — tapi pondasi tetap utility.

## Fungsi
Pendekatan utility-first membuat styling lebih cepat, konsisten, dan mudah dipelihara karena kamu tidak perlu bolak-balik HTML-CSS, tidak ada masalah naming, dan CSS yang dihasilkan lebih kecil.

## Cara Pengimplementasian / Kode

```html
<!-- Component-Based (CSS tradisional) -->
<div class="card">
  <div class="card-header">
    <h2 class="card-title">Judul</h2>
  </div>
  <div class="card-body">
    <p class="card-text">Deskripsi singkat</p>
  </div>
</div>

<!-- Utility-First (Tailwind) -->
<div class="border rounded-lg shadow-md p-6 bg-white">
  <div class="mb-4">
    <h2 class="text-xl font-bold text-gray-900">Judul</h2>
  </div>
  <div>
    <p class="text-gray-600">Deskripsi singkat</p>
  </div>
</div>
```

## Analogi
Bayangkan kamu membangun rumah. **Utility-first** seperti menggunakan **bata lego** — bata kecil standar yang bisa kamu rangkai jadi bentuk apa pun. **Component-based** seperti membeli **rumah prefab** — tinggal pakai, tapi kalau mau ubah sedikit saja kamu harus bongkar total atau pesan ulang. Tailwind kasih kamu bata legonya, kamu yang tentuin bentuk rumahmu.

## Dipakai untuk Apa
- Proyek baru yang ingin cepat develop tanpa mikirin nama class.
- Tim besar yang butuh konsistensi desain tanpa standarisasi nama class manual.
- Prototype hingga production — Tailwind cocok di semua tahap.

## Kesalahan Umum yang Sering Terjadi
- **Membuat utility class sendiri sebelum lihat dokumentasi**: Padahal hampir semua yang kamu butuh sudah ada di Tailwind.
- **Mencampur utility dan CSS kustom tanpa @apply**: Akhirnya malah tambah berantakan. Kalau butuh component, gunakan `@apply` atau komponen framework.
- **Khawatir HTML jadi panjang**: Itu memang desainnya. Gunakan partial/view component di framework (React, Vue, Laravel, dll) untuk tetap rapi.

## Koneksi dengan Materi Sebelumnya
Ini adalah fondasi filosofis dari semua materi selanjutnya. Setiap utility class yang akan kamu pelajari (font size, warna, spacing, dll) adalah "bata lego" yang kamu rangkai jadi bangunan utuh.

## Soal Latihan

Buat sebuah card profile sederhana dengan data diri kamu menggunakan utility-first Tailwind (bisa coba di Tailwind Play). Gunakan class: padding, margin, border, rounded, shadow, dan font utility. Jangan buat satupun CSS kustom.
