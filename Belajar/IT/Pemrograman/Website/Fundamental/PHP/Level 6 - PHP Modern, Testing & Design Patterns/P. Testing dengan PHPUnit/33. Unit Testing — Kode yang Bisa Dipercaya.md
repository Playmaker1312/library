# Unit Testing — Kode yang Bisa Dipercaya

## Penjelasan

**Unit Testing** adalah cara menguji **bagian terkecil** dari kode (biasanya satu method atau fungsi) secara **terpisah** untuk memastikan hasilnya sesuai harapan. Kita menulis kode penguji yang otomatis memanggil method itu, lalu memeriksa apakah hasilnya benar.

Istilah penting:

- **Unit** = satuan terkecil yang masuk akal diuji, misal method `tersedia()`, `pinjam()`, `hitungDenda()`.
- **Test Case** = satu skenario pengujian (input + hasil yang diharapkan).
- **Assertion** = pernyataan pemeriksa, misal `assertTrue()`, `assertEquals()`, `assertCount()`.
- **AAA Pattern** = **Arrange–Act–Assert**: siapkan data → jalankan aksi → periksa hasil.
- **Positive & Negative Test** = menguji kasus yang benar **dan** kasus yang salah.
- **Isolation** = unit diuji sendiri, idealnya tanpa database/HTTP, supaya penyebab gagal jelas.
- **Regression Test** = pengujian yang mencegah bug lama muncul lagi setelah kode diubah.
- **PHPUnit** = framework pengujian PHP paling populer (dipasang lewat Composer).

Konteks perpustakaan: kita menguji class `Buku` yang menangani stok saat dipinjam dan dikembalikan.

## Fungsi

- **Menangkap bug lebih awal** sebelum sampai ke pengguna.
- **Memberi keberanian saat refactor** — ada jaring pengaman bila kode diubah.
- **Menjadi dokumentasi hidup** — test menunjukkan perilaku yang diharapkan.
- **Memaksa kode lebih rapi** — class yang sulit diuji biasanya terlalu bercampur tanggung jawab.
- **Menghemat waktu jangka panjang** — bug ketahuan otomatis, bukan dari laporan pengguna.
- **Pintu masuk ke TDD** (menulis test dulu, baru kode).

## Cara Pengimplementasian / Code

Siapkan project kecil ber-Composer dengan PSR-4 dan PHPUnit.

```json
// composer.json
{
  "autoload": { "psr-4": { "App\\": "src/" } },
  "require-dev": { "phpunit/phpunit": "^11.0" }
}
```

```bash
composer install          # memasang PHPUnit
```

**Class yang diuji — `src/Buku.php`:**

```php
<?php
// src/Buku.php
namespace App;

class Buku
{
    public function __construct(
        public int $id,
        public string $judul,
        public string $pengarang,
        public int $stok = 0
    ) {
    }

    // Buku tersedia jika stok lebih dari nol
    public function tersedia(): bool
    {
        return $this->stok > 0;
    }

    // Pinjam buku: kurangi stok, gagal jika stok habis
    public function pinjam(): bool
    {
        if (! $this->tersedia()) {
            return false;
        }
        $this->stok--;
        return true;
    }

    // Kembalikan buku: tambah stok
    public function kembalikan(): void
    {
        $this->stok++;
    }

    public function getStok(): int
    {
        return $this->stok;
    }
}
```

**Test — `tests/BukuTest.php`:**

```php
<?php
// tests/BukuTest.php
namespace Tests;

use PHPUnit\Framework\TestCase;
use App\Buku;

class BukuTest extends TestCase
{
    public function testTersediaKetikaStokLebihDariNol(): void
    {
        // Arrange: siapkan buku dengan stok 5
        $buku = new Buku(1, 'Clean Code', 'Robert C. Martin', 5);

        // Act: tanyakan apakah tersedia
        $tersedia = $buku->tersedia();

        // Assert: harus benar
        $this->assertTrue($tersedia);
    }

    public function testTidakTersediaKetikaStokNol(): void
    {
        $buku = new Buku(2, 'Atomic Habits', 'James Clear', 0);
        $this->assertFalse($buku->tersedia());
    }

    public function testBerhasilPinjamJikaTersedia(): void
    {
        $buku = new Buku(3, 'Refactoring', 'Martin Fowler', 3);

        $berhasil = $buku->pinjam();

        $this->assertTrue($berhasil);            // pinjam berhasil
        $this->assertEquals(2, $buku->getStok()); // stok berkurang
    }

    public function testGagalPinjamJikaStokHabis(): void
    {
        $buku = new Buku(4, 'Domain-Driven Design', 'Eric Evans', 0);

        $berhasil = $buku->pinjam();

        $this->assertFalse($berhasil);           // pinjam gagal
        $this->assertEquals(0, $buku->getStok()); // stok tidak berubah
    }

    public function testKembalikanBukuMenambahStok(): void
    {
        $buku = new Buku(5, 'Test Driven Development', 'Kent Beck', 1);

        $buku->pinjam();      // stok jadi 0
        $buku->kembalikan();  // stok kembali jadi 1

        $this->assertEquals(1, $buku->getStok());
    }
}
```

**Konfigurasi `phpunit.xml` (opsional tapi rapi):**

```xml
<?xml version="1.0" encoding="UTF-8"?>
<phpunit bootstrap="vendor/autoload.php" colors="true">
  <testsuites>
    <testsuite name="Application Test Suite">
      <directory>tests</directory>
    </testsuite>

```

**Cara menjalankan/menguji:**

```bash
vendor/bin/phpunit                 # jalankan semua test
vendor/bin/phpunit --testdox       # tampilkan dengan nama yang mudah dibaca
vendor/bin/phpunit tests/BukuTest.php
```

## Tracing Code (Step-by-Step)

Kita telusuri test `testBerhasilPinjamJikaTersedia()` seolah-olah mengikuti PHPUnit menjalankannya.

**Langkah 1 — Arrange: `new Buku(3, 'Refactoring', 'Martin Fowler', 3)`**

PHP membuat objek `Buku`. Constructor mengisi property: `id = 3`, `judul = "Refactoring"`, `pengarang = "Martin Fowler"`, `stok = 3`.

**Langkah 2 — Act: `$buku->pinjam()`**

PHP masuk ke method `pinjam()`:

- Baris `if (! $this->tersedia())` memanggil `tersedia()`. Karena `stok = 3`, nilai `3 > 0` adalah `true`, jadi `tersedia()` mengembalikan `true`.
- `! true` bernilai `false`, sehingga blok `return false` **dilewati**.
- Baris `$this->stok--` menurunkan stok dari `3` menjadi `2`.
- `return true` mengembalikan `true` ke pemanggil.

Sekarang `$berhasil = true` dan `stok` buku berisi `2`.

**Langkah 3 — Assert: `$this->assertTrue($berhasil)`**

PHPUnit memeriksa: apakah `$berhasil` benar-benar `true`? Ya. Assertion ini **lolos**.

**Langkah 4 — Assert: `$this->assertEquals(2, $buku->getStok())`**

`getStok()` mengembalikan `2`. PHPUnit membandingkan: `2 == 2`? Ya. Assertion **lolos**.

**Langkah 5 — hasil test**

Kedua assertion lolos → test dinyatakan **PASS**. Bila salah satu gagal, PHPUnit menandai test **FAIL** dan menampilkan nilai yang diharapkan vs yang terjadi.

**Tabel ringkas perjalanan nilai:**

| Tahap | Aksi | `stok` sebelum | Hasil | `stok` sesudah |
|---|---|---|---|---|
| Arrange | buat Buku stok 3 | — | objek siap | 3 |
| Act | `pinjam()` | 3 | `true` | 2 |
| Assert | `assertTrue` | 2 | lolos | 2 |
| Assert | `assertEquals(2, getStok())` | 2 | lolos | 2 |

**Output akhir:**

```text
PHPUnit 11.x by Sebastian Bergmann and contributors.

.....                                                               5 / 5 (100%)

OK (5 tests, 5 assertions)
```

## Analogi

Bayangkan **petugas quality control perpustakaan** yang memeriksa tiap peralatan sebelum dipakai.

- **Unit Test** = **lembar pemeriksaan** satu alat (misal mesin pencatat peminjaman).
- **Arrange** = menyiapkan alat & kondisi (stok 3 buku).
- **Act** = mencoba memakai alat (tekan tombol "pinjam").
- **Assert** = membandingkan "seharusnya stok jadi 2" dengan "kenyataan stok jadi 2".
- **Test Case** = satu baris checklist.
- **PHPUnit** = **mesin penguji otomatis** yang menjalankan semua checklist dan melaporkan mana yang lolos/gagal.
- **Regression Test** = memastikan alat yang dulu pernah rusak **tidak rusak lagi** setelah diperbaiki.

## Dipakai untuk Apa

- **Memverifikasi logika bisnis** seperti pinjam/kembalikan dan perhitungan denda.
- **Aman saat refactor** kode OOP (materi 23–25).
- **Menjadi dokumentasi** perilaku method.
- **Dipasang di CI/CD** agar setiap perubahan diuji otomatis.
- **Latihan TDD** untuk fitur baru.
- **Menguji class repository & service** dengan bantuan mock (materi 34).

## Kesalahan Umum yang Sering Terjadi

- **Menguji terlalu luas** → bukan lagi unit test, tapi integration test yang rapuh.
- **Bergantung pada database/HTTP** → test jadi lambat & tidak stabil. Pakai data palsu/mock.
- **Nama test tidak jelas** (`test1`) → sulit tahu apa yang gagal. Pakai nama deskriptif.
- **Assertion kurang lengkap** → hanya cek satu hal, padahal ada efek samping (mis. lupa cek stok).
- **Lupa `composer install`/autoload** → class `App\Buku` tidak ditemukan.
- **Tidak mengaktifkan `declare(strict_types=1)`** → tipe salah lolos diam-diam.
- **Menulis test setelah kode rusak** tanpa memperbaiki kode → test merah terus dan diabaikan.

## Soal Latihan & Jawaban

### Soal

Buat class `DendaCalculator` pada `src/DendaCalculator.php` dengan satu method:

```php
public function hitung(int $telatHari, int $tarifPerHari = 2000): int
```

Aturan: jika `telatHari <= 0` kembalikan `0`; selain itu hasilnya `telatHari * tarifPerHari`. Lalu tulis test PHPUnit yang menguji:

1. Telat 0 hari → menghasilkan `0`.
2. Telat 3 hari dengan tarif default → `6000`.
3. Telat negatif (mis. `-2`) → tetap `0`.

### Jawaban

```php
<?php
// src/DendaCalculator.php
namespace App;

class DendaCalculator
{
    public function hitung(int $telatHari, int $tarifPerHari = 2000): int
    {
        if ($telatHari <= 0) {
            return 0; // tidak terlambat, tanpa denda
        }
        return $telatHari * $tarifPerHari;
    }
}
```

```php
<?php
// tests/DendaCalculatorTest.php
namespace Tests;

use PHPUnit\Framework\TestCase;
use App\DendaCalculator;

class DendaCalculatorTest extends TestCase
{
    public function testTanpaDendaJikaTidakTerlambat(): void
    {
        $calc = new DendaCalculator();
        $this->assertEquals(0, $calc->hitung(0));
    }

    public function testDendaTigaHariTarifDefault(): void
    {
        $calc = new DendaCalculator();
        $this->assertEquals(6000, $calc->hitung(3));
    }

    public function testTelatNegatifMenghasilkanNol(): void
    {
        $calc = new DendaCalculator();
        $this->assertEquals(0, $calc->hitung(-2));
    }
}
```

Jalankan dengan `vendor/bin/phpunit tests/DendaCalculatorTest.php` → harus muncul `OK (3 tests, 3 assertions)`.
