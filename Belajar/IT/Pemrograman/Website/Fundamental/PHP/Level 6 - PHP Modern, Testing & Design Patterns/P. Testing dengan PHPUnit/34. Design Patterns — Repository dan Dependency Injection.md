# Design Patterns — Repository dan Dependency Injection

## Penjelasan

**Design Pattern** adalah solusi umum yang sudah terbukti untuk masalah yang sering berulang. Di materi ini kita fokus pada dua pola yang paling sering dipakai di aplikasi PHP modern: **Repository** dan **Dependency Injection**.

**Repository Pattern** adalah pola untuk memisahkan **logika akses data** dari **logika bisnis**. Class bisnis tidak perlu tahu data disimpan di MySQL, file JSON, atau API lain — ia cukup memanggil method repository.

Komponennya:

- **Entity/Model** (mis. `Buku`) — bentuk datanya.
- **Interface Repository** (`BukuRepositoryInterface`) — kontrak method yang tersedia.
- **Implementasi konkret** (`PdoBukuRepository`) — isi sebenarnya, memakai PDO.
- **Service / Use Case** (`BukuService`) — logika bisnis yang memakai repository.

**Dependency Injection (DI)** adalah cara memberi "alat bantu" ke sebuah class dari luar, bukan membuatnya sendiri di dalam. Bentuk paling umum adalah **constructor injection**: alat dikirim lewat parameter constructor.

Konsep penting:

- **Program to an interface** — kode bisnis bergantung pada *kontrak*, bukan pada implementasi.
- **Loose coupling** — mengganti MySQL ke file JSON tidak perlu mengubah service.
- **Testability** — repository bisa diganti **mock/stub** saat unit test (materi 33).
- **Single Responsibility** — repository hanya mengurus data, service hanya mengurus aturan bisnis.

Konteks perpustakaan: `BukuService` meminta daftar buku lewat `BukuRepositoryInterface`, tanpa peduli datanya datang dari MySQL atau file.

## Fungsi

- **Memisahkan tanggung jawab** antara data dan bisnis.
- **Memudahkan penggantian sumber data** (MySQL, JSON, API) tanpa mengubah service.
- **Membuat kode mudah diuji** karena repository bisa dipalsukan.
- **Menghindari duplikasi query** di banyak tempat.
- **Menyiapkan struktur** yang mirip framework (Laravel repository, Symfony service).
- **Menjaga kode tetap rapi** saat aplikasi membesar.

## Cara Pengimplementasian / Code

Struktur folder (PSR-4 `App\` → `src/`):

```text

```

**Entity — `src/Entity/Buku.php`:**

```php
<?php
// src/Entity/Buku.php
namespace App\Entity;

class Buku
{
    public function __construct(
        public int $id,
        public string $judul,
        public string $pengarang,
        public int $stok = 0
    ) {
    }
}
```

**Kontrak — `src/Repository/BukuRepositoryInterface.php`:**

```php
<?php
// src/Repository/BukuRepositoryInterface.php
namespace App\Repository;

use App\Entity\Buku;

interface BukuRepositoryInterface
{
    /** @return Buku[] */
    public function semua(): array;

    public function cariId(int $id): ?Buku;

    public function simpan(Buku $buku): bool;
}
```

**Implementasi PDO — `src/Repository/PdoBukuRepository.php`:**

```php
<?php
// src/Repository/PdoBukuRepository.php
namespace App\Repository;

use App\Entity\Buku;
use PDO;

class PdoBukuRepository implements BukuRepositoryInterface
{
    // Dependency (koneksi PDO) dikirim dari luar — inilah Dependency Injection
    public function __construct(private PDO $pdo)
    {
    }

    public function semua(): array
    {
        // Ambil semua baris, ubah tiap baris jadi objek Buku
        $rows  = $this->pdo->query('SELECT * FROM buku ORDER BY id')->fetchAll();
        $hasil = [];
        foreach ($rows as $r) {
            $hasil[] = new Buku((int) $r['id'], $r['judul'], $r['pengarang'], (int) $r['stok']);
        }
        return $hasil;
    }

    public function cariId(int $id): ?Buku
    {
        // Prepared statement (materi 27)
        $stmt = $this->pdo->prepare('SELECT * FROM buku WHERE id = :id LIMIT 1');
        $stmt->execute([':id' => $id]);
        $r = $stmt->fetch();
        return $r !== false
            ? new Buku((int) $r['id'], $r['judul'], $r['pengarang'], (int) $r['stok'])
            : null;
    }

    public function simpan(Buku $buku): bool
    {
        $stmt = $this->pdo->prepare(
            'INSERT INTO buku (judul, pengarang, stok) VALUES (:judul, :pengarang, :stok)'
        );
        return $stmt->execute([
            ':judul'     => $buku->judul,
            ':pengarang' => $buku->pengarang,
            ':stok'      => $buku->stok,
        ]);
    }
}
```

**Service — `src/Service/BukuService.php`:**

```php
<?php
// src/Service/BukuService.php
namespace App\Service;

use App\Repository\BukuRepositoryInterface;

class BukuService
{
    // Service hanya tahu KONTRAK, bukan MySQL. Ini inti Repository + DI.
    public function __construct(private BukuRepositoryInterface $repo)
    {
    }

    public function daftarBuku(): array
    {
        return $this->repo->semua();
    }

    public function detailBuku(int $id): ?array
    {
        $buku = $this->repo->cariId($id);
        return $buku === null ? null : [
            'id'        => $buku->id,
            'judul'     => $buku->judul,
            'pengarang' => $buku->pengarang,
            'status'    => $buku->stok > 0 ? 'Tersedia' : 'Habis',
        ];
    }
}
```

**Perakitan — `demo.php`:**

```php
<?php
// demo.php
require __DIR__ . '/vendor/autoload.php';

use App\Repository\PdoBukuRepository;
use App\Service\BukuService;

// Koneksi database (materi 26)
$pdo = new PDO('mysql:host=localhost;dbname=perpustakaan;charset=utf8mb4', 'root', '', [
    PDO::ATTR_ERRMODE            => PDO::ERRMODE_EXCEPTION,
    PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
]);

// "Alat" (repository) disuntikkan ke service
$repo    = new PdoBukuRepository($pdo);
$service = new BukuService($repo);

foreach ($service->daftarBuku() as $b) {
    echo "#{$b->id} {$b->judul} — {$b->pengarang}" . PHP_EOL;
}
```

**Cara menjalankan/menguji:** `php demo.php` (pastikan tabel `buku` ada). Ganti `PdoBukuRepository` dengan implementasi lain untuk membuktikan service tidak perlu diubah.

## Tracing Code (Step-by-Step)

Kita telusuri baris `$service->detailBuku(1)`.

**Langkah 1 — baris `new PdoBukuRepository($pdo)`**

PHP membuat objek repository. Constructor menyimpan koneksi PDO ke property `$pdo`. Inilah **Dependency Injection**: koneksi datang dari luar.

**Langkah 2 — baris `new BukuService($repo)`**

PHP membuat objek service. Constructor menyimpan repository ke property `$repo`. Service **tidak membuat** repository sendiri — ia menerimanya. Karena tipenya `BukuRepositoryInterface`, service hanya percaya pada kontrak.

**Langkah 3 — baris `$service->detailBuku(1)`**

PHP masuk ke `BukuService::detailBuku(1)`. Baris pertama `$buku = $this->repo->cariId(1)` memanggil method lewat **kontrak**.

**Langkah 4 — method `cariId(1)` dijalankan**

Karena objek nyatanya `PdoBukuRepository`, maka yang berjalan adalah `PdoBukuRepository::cariId(1)`:

- `prepare('SELECT * FROM buku WHERE id = :id LIMIT 1')` menyiapkan template.
- `execute([':id' => 1])` mengirim nilai `1`.
- `fetch()` mengambil satu baris. Misal `['id'=>1,'judul'=>'Clean Code','pengarang'=>'Robert C. Martin','stok'=>5]`.
- Baris itu dibungkus jadi objek `Buku`, lalu dikembalikan.

**Langkah 5 — kembali ke `detailBuku`**

`$buku` bukan `null`, jadi dibuat array ringkas: `id = 1`, `judul = "Clean Code"`, `pengarang = "Robert C. Martin"`, `status = "Tersedia"` (karena `stok 5 > 0`). Array itu dikembalikan.

**Langkah 6 — jika data tidak ada**

Bila `cariId()` mengembalikan `null`, `detailBuku()` mengembalikan `null`. Pemanggil bisa memutuskan menampilkan "buku tidak ditemukan".

**Titik penting:** seluruh alur **tidak pernah menyebut MySQL** di dalam service. Kalau besok repository diganti `JsonBukuRepository`, `BukuService` tetap sama.

## Analogi

Bayangkan **perpustakaan dengan pembagian tugas yang jelas**.

- **Repository** = **petugas gudang** yang khusus mengurus akses koleksi (mengambil & menyimpan buku di rak). Ia satu-satunya yang tahu seluk-beluk rak.
- **Interface Repository** = **SOP gudang**: "Untuk minta daftar buku, panggil `semua()`. Untuk cari satu, panggil `cariId()`."
- **Implementasi PDO** = gudang **yang memakai sistem rak MySQL**.
- **Service** = **petugas layanan** yang melayani pengunjung dan tahu aturan ("buku stok 0 = Habis"). Ia **meminta ke gudang lewat SOP**, tidak menyusuri rak sendiri.
- **Dependency Injection** = pimpinan **menyerahkan petugas gudang** ke petugas layanan di awal shift, bukan menyuruh petugas layanan mencari gudang sendiri.
- **Swap implementasi** = gudang pindah ke sistem penyimpanan lain; selama SOP-nya sama, petugas layanan tidak perlu dilatih ulang.
- **Mock saat test** = gudang **palsu** berisi data contoh untuk melatih petugas layanan tanpa menyentuh rak asli.

Intinya: **petugas layanan (bisnis) dan petugas gudang (data) saling lepas**, dihubungkan oleh **SOP (interface)**.

## Dipakai untuk Apa

- **Aplikasi dengan banyak query** agar tidak berulang di sana-sini.
- **Menyiapkan penggantian sumber data** (dari file JSON → MySQL, atau sebaliknya).
- **Memudahkan unit test** service tanpa database.
- **Struktur standar project menengah** (Entity, Repository, Service).
- **Integrasi dengan framework** yang memakai konsep service container & DI (Laravel, Symfony).
- **Amankan perubahan** — satu perubahan skema cukup di satu repository.

## Kesalahan Umum yang Sering Terjadi

- **Service membuat koneksi/PDO sendiri** (`new PDO` di dalam) → sulit diuji & diganti. Suntikkan dari luar.
- **Bekerja langsung dengan array mentah** di service → kehilangan manfaat entity. Ubah baris jadi objek di repository.
- **Menaruh logika bisnis di repository** → repository kembali bercampur. Batasi repository hanya akses data.
- **Bergantung pada class konkret, bukan interface** → sulit diganti. Ketik parameter sebagai `BukuRepositoryInterface`.
- **Merangkai dependency berantakan** di banyak titik → kumpulkan perakitan di satu tempat (`demo.php`/bootstrap).
- **Interface kekurangan method** lalu memaksa menambah terus → rancang kontrak sesuai kebutuhan bisnis.
- **Over-engineering** untuk project sangat kecil → pola ini baru terasa manfaatnya saat kode bertambah banyak.

### Soal

Terapkan pola yang sama untuk data **anggota**:

1. Buat `App\Entity\Anggota` dengan property `id`, `nama`, `email`.

3. Buat `App\Repository\PdoAnggotaRepository` yang mengimplementasikannya memakai PDO.
4. Buat `App\Service\AnggotaService` yang menerima repository lewat constructor dan punya method `daftarNama(): array` yang mengembalikan daftar nama anggota.
5. Buat `demo.php` yang merangkai ketiganya.

namespace App\Repository;

use App\Entity\Anggota;

class PdoAnggotaRepository implements AnggotaRepositoryInterface
