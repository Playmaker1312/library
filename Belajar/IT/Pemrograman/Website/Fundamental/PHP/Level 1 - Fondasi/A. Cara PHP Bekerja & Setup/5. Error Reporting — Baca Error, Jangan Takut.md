# Error Reporting — Baca Error, Jangan Takut

## Penjelasan

Saat belajar pemrograman, **error adalah hal yang wajar**. Justru dengan membaca error, kita jadi lebih cepat paham cara kerja PHP dan belajar memperbaiki kode sendiri.

Di PHP, ada beberapa jenis error yang sering muncul. Tujuannya bukan untuk ditakuti, tapi untuk **dibaca pesannya dengan teliti**. Pesan error di PHP biasanya sangat jelas: menunjukkan **nama file**, **nomor baris**, dan **penjelasan singkat** penyebab error.

Namun, secara default di beberapa environment, error bisa **disembunyikan** (terutama di production). Saat development (belajar), kita justru **ingin melihat SEMUA error** agar bisa langsung memperbaiki.

Untuk itu, kita perlu mengaktifkan **error reporting** saat belajar.

## Fungsi

- **Membantu debugging** — tahu persis baris mana yang salah dan kenapa salah.
- **Menghemat waktu** — tidak perlu nebak-nebak penyebab bug.
- **Mendidik cara berpikir sistematis** — belajar membaca log error dengan tenang.
- **Mencegah bug tersembunyi** — Notice/Warning bisa jadi petunjuk potensi masalah.
- **Membedakan lingkungan** — saat development tampilkan error, saat production **sebaiknya sembunyikan** dari user (tapi simpan di log).
- **Membentuk habit baik** — terbiasa membaca pesan error alih-alih panik.

## Cara Pengimplementasian / Code

Kita bisa mengaktifkan error reporting dengan 2 cara: **langsung di file PHP** (praktis saat belajar), atau **di file `php.ini`** (global). Untuk pemula, cara langsung di file PHP paling aman & mudah dipahami.

### Cara 1: Aktifkan di awal file PHP (Rekomendasi saat belajar)

Tambahkan kode ini di **baris paling atas** file PHP kamu.

```php
<?php
// Aktifkan error reporting untuk development
error_reporting(E_ALL);
ini_set('display_errors', 1);
ini_set('display_startup_errors', 1);
```

**Penjelasan:**

- `error_reporting(E_ALL)` → Tampilkan **semua jenis error** (Parse Error, Fatal Error, Warning, Notice, Deprecated, dsb)
- `ini_set('display_errors', 1)` → Tampilkan error langsung di browser
- `ini_set('display_startup_errors', 1)` → Tampilkan error saat PHP mulai berjalan (jarang tapi berguna)

### Cara 2: Contoh melihat berbagai jenis error

Kita buat file `latihan-error.php` untuk melihat perbedaan jenis error.

```php
<?php
// File: latihan-error.php

// Aktifkan error reporting
error_reporting(E_ALL);
ini_set('display_errors', 1);

// 1. NOTICE - Mengakses variabel yang belum dideklarasikan
echo $variabelBelumAda; // Notice: Undefined variable

// 2. WARNING - Pembagian dengan nol
$hasil = 10 / 0; // Warning: Division by zero
echo "<br>Hasil: " . $hasil;

// 3. PARSE ERROR - Kesalahan sintaks (akan menghentikan eksekusi)
// echo "Halo" // Lupa titik koma -> Parse error

// 4. FATAL ERROR - Memanggil fungsi yang tidak ada
// fungsiTidakAda(); // Fatal error: Uncaught Error: Call to undefined function
```

**Cara menjalankan:**

- Laragon: `http://perpustakaan.test/latihan-error.php`
- XAMPP: `http://localhost/perpustakaan/latihan-error.php`

**Perhatikan:** Jika kamu aktifkan baris `Parse Error` atau `Fatal Error`, eksekusi akan **berhenti tepat di error tersebut**. Itulah bedanya dengan Notice/Warning yang **tidak menghentikan** jalannya script.

### Cara 3: Praktik aman di project perpustakaan

Saat kita buat halaman seperti `profil-perpustakaan.php`, kita bisa tambahkan error reporting di paling atas **hanya saat belajar**.

```php
<?php
// HANYA untuk development/belajar
error_reporting(E_ALL);
ini_set('display_errors', 1);

$namaPerpustakaan = "Perpustakaan Digital Kota";
// ... kode lainnya
?>
```

**PENTING untuk production (sudah online):**

Di server hosting, **JANGAN** tampilkan error ke user. Ganti jadi:

```php
<?php
// Untuk production
error_reporting(0); // Matikan semua error reporting
ini_set('display_errors', 0); // Jangan tampilkan di browser
ini_set('log_errors', 1); // Tapi simpan di error log server
```

Tapi untuk **tujuan belajar saat ini**, kita tetap pakai `display_errors = 1`.

## Tracing Code (Step-by-Step)

Kita telusuri contoh `Notice: Undefined variable`.

Kode yang ditelusuri:

```php
<?php
error_reporting(E_ALL);
ini_set('display_errors', 1);

echo $variabelBelumAda;
```

**Langkah 1 — Baris `error_reporting(E_ALL);`**

PHP mengatur level pelaporan error menjadi **tertinggi** (`E_ALL`). Artinya PHP akan "melaporkan" semua jenis error yang terdeteksi.

**Langkah 2 — Baris `ini_set('display_errors', 1);`**

PHP diperintahkan: **"Tampilkan pesan error ini langsung di browser"**. Tanpa baris ini, di beberapa setup pesan error bisa tidak muncul.

**Langkah 3 — Baris `echo $variabelBelumAda;`**

PHP mencoba menjalankan perintah `echo`. Ia mencari variabel bernama `$variabelBelumAda` di memori.

Ternyata **variabel tersebut belum pernah dideklarasikan** sebelumnya (`$variabelBelumAda = ...` belum ada).

PHP mendeteksi ini sebagai **potensi masalah**. Karena level error kita `E_ALL`, PHP mengeluarkan **Notice**:

> Notice: Undefined variable: variabelBelumAda in D:\laragon\www\perpustakaan\latihan-error.php on line 6

**Langkah 4 — PHP tetap melanjutkan eksekusi**

Berbeda dengan Fatal Error, Notice **bukan error yang fatal**. PHP tetap melanjutkan baris berikutnya (kalau ada). Di contoh ini, setelah Notice muncul, script selesai (tidak ada baris lain).

**Output di browser:**

```
Notice: Undefined variable: variabelBelumAda in D:\laragon\www\perpustakaan\latihan-error.php on line 6
```

**Pelajaran dari tracing:** Pesan error memberitahu **3 hal penting**:
1. **Jenis error** → `Notice`
2. **Penyebab** → `Undefined variable: variabelBelumAda` (variabel belum dideklarasikan)
3. **Lokasi** → `latihan-error.php on line 6` (baris ke-6 yang bermasalah)

Kuncinya: **baca ketiganya, lalu perbaiki di baris yang disebutkan.**

## Analogi

Bayangkan kamu sedang belajar mengemudi mobil di **tempat parkir perpustakaan**.

Saat pertama kali belajar, instruktur **tidak menutup mata**mu. Justru ia membiarkan kamu mendengar **bunyi peringatan**: klakson kalau terlalu dekat tiang, bunyi mundur, atau lampu indikator di dashboard.

Bunyi-bunyi peringatan itu **tidak berarti mobil rusak total**, tapi memberi tahu: *"Hati-hati, ada yang perlu kamu perbaiki cara nyetirnya."*

Kalau instruktur mematikan semua peringatan, kamu bisa saja menabrak tiang tanpa sadar.

Begitu juga dengan **error reporting** di PHP. Notice/Warning itu ibarat **peringatan dashboard**. Fatal Error/Parse Error itu ibarat peringatan tegas "ada yang salah, harus diperbaiki". **Jangan matikan peringatan saat sedang belajar. Baca dan pahami peringatannya.**

Konteks perpustakaan: bayangkan sistem peminjaman buku. Kalau ada petugas yang mencoba meminjamkan buku ke anggota yang **belum terdaftar**, sistem bisa memberi **peringatan** (warning) ketimbang langsung crash. Itulah gunanya pesan error yang jelas.

## Dipakai untuk Apa

- **Belajar membaca bug** — melatih kemampuan debugging sejak awal.
- **Mencari lokasi kesalahan dengan cepat** — langsung tahu file + nomor baris.
- **Mendeteksi typo** — sering karena salah ketik nama variabel/fungsi.
- **Mencegah kebiasaan "coding asal jalan"** — belajar kode yang lebih teliti.
- **Menguji kode saat development** — melihat semua potensi masalah.
- **Membedakan development vs production** — tahu kapan harus tampilkan/sembunyikan error.
- **Memahami kualitas kode** — Notice seperti `Undefined variable` bisa dihindari dengan deklarasi yang benar.

## Kesalahan Umum yang Sering Terjadi

- **Panik saat lihat error** — Reaksi pertama pemula: "kok error?!". Padahal pesan error justru **solusi awal** untuk memperbaiki.
- **Mematikan error reporting saat belajar** — `error_reporting(0)` justru bikin sulit tahu penyebab bug.
- **Lupa aktifkan saat buat file baru** — Terutama kalau file baru belum ditambah kode error reporting.
- **Mencari kesalahan di baris salah** — Selalu fokus ke **baris yang disebutkan** di pesan error.
- **Mengabaikan Notice** — Meskipun tidak fatal, Notice bisa jadi tanda logika yang kurang aman (mis. akses variabel belum ada).
- **Menyimpan error reporting aktif di production** — Sangat tidak disarankan. Bisa membocorkan info sensitif (path file, struktur kode).
- **Membaca pesan setengah-setengah** — Baca **seluruh pesan**: tipe error + deskripsi + file + line number.

## Hubungan dengan Materi Sebelumnya

**Materi sebelumnya (Poin 4):** `Menggabungkan PHP dan HTML — Cara yang Benar`. Kita mulai menulis kode yang lebih panjang (campur PHP-HTML), jadi potensi typo/salah sintaks jadi lebih besar.

**Hubungan:** Materi ini jadi **"alat bantu"** untuk poin-poin selanjutnya. Setiap kali kita salah ketik, salah tanda, atau lupa deklarasi, error reporting akan membantu kita langsung menemukan dan memperbaiki.

**Materi selanjutnya (Poin 6):** `Variabel — Wadah Data dengan Tanda Dollar`. Kita akan mulai banyak deklarasi variabel. Dengan error reporting aktif, kita bisa langsung sadar kalau ada variabel yang typo atau belum dideklarasi.

## Soal Latihan & Jawaban

### Soal

Buat file `debugging-praktik.php` dengan ketentuan berikut:

1. Aktifkan **error reporting** untuk development di baris paling atas.
2. Buat 2 variabel: `$judulBuku = "Clean Code"` dan `$pengarang = "Robert C. Martin"`.
3. Tampilkan keduanya dengan format: **"Judul: [judulBuku] | Pengarang: [pengarang]"** menggunakan pola campur PHP-HTML.
4. **Sengaja** buat 1 Notice dengan mengakses variabel yang belum dideklarasikan, misalnya `echo $tahunTerbit;`
5. Amati pesan error yang muncul: sebutkan **jenis error**, **penyebab**, dan **nomor baris** yang bermasalah.
6. Setelah mengamati, **perbaiki** dengan menghapus baris Notice tersebut, lalu jalankan ulang dan pastikan error hilang.

### Jawaban

**Langkah 1: Buat file dengan Notice (sengaja)**

```php
<?php
// File: debugging-praktik.php

// Aktifkan error reporting untuk development
error_reporting(E_ALL);
ini_set('display_errors', 1);
ini_set('display_startup_errors', 1);

// Deklarasi variabel
$judulBuku = "Clean Code";
$pengarang = "Robert C. Martin";
?>
<!DOCTYPE html>
<html lang="id">
<head>
    <meta charset="UTF-8">
    <title>Latihan Debugging</title>
</head>
<body>
    <h1>Data Buku</h1>
    <p>Judul: <?= $judulBuku ?> | Pengarang: <?= $pengarang ?></p>
    
    <!-- Sengaja buat Notice -->
    <p>Tahun Terbit: <?= $tahunTerbit ?></p>
</body>
</html>
```

**Langkah 2: Amati pesan error**

Saat dijalankan, akan muncul pesan seperti ini:

```
Notice: Undefined variable: tahunTerbit in D:\laragon\www\perpustakaan\debugging-praktik.php on line 19
```

**Analisis:**

- **Jenis error:** Notice
- **Penyebab:** Undefined variable: tahunTerbit → variabel `$tahunTerbit` belum dideklarasikan
- **Nomor baris:** line 19 (baris `<p>Tahun Terbit: <?= $tahunTerbit ?></p>`)

**Langkah 3: Perbaiki (hapus baris Notice)**

```php
<?php
// File: debugging-praktik.php (setelah diperbaiki)

error_reporting(E_ALL);
ini_set('display_errors', 1);
ini_set('display_startup_errors', 1);

$judulBuku = "Clean Code";
$pengarang = "Robert C. Martin";
?>
<!DOCTYPE html>
<html lang="id">
<head>
    <meta charset="UTF-8">
    <title>Latihan Debugging</title>
</head>
<body>
    <h1>Data Buku</h1>
    <p>Judul: <?= $judulBuku ?> | Pengarang: <?= $pengarang ?></p>
</body>
</html>
```

Setelah diperbaiki, halaman akan tampil bersih tanpa pesan error. Ini membuktikan: **membaca error = tahu cara memperbaikinya.**
