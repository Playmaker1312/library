# Type Juggling — PHP yang Suka Mengubah Tipe

## Penjelasan

**Type Juggling** (permainan tipe data) adalah kebiasaan PHP untuk **secara otomatis mengubah tipe data** suatu nilai, saat kita melakukan operasi tertentu (penjumlahan, pembandingan, dsb).

Kebalikan dari bahasa seperti Java atau C#, di PHP kita **tidak wajib** mendeklarasikan tipe data. PHP akan "menyesuaikan" tipe datanya sendiri agar operasi bisa berjalan.

Contoh paling sederhana: kita punya string `"5"`, lalu kita **jumlahkan** dengan angka `3`. PHP akan **mengubah string `"5"` menjadi angka `5`**, lalu menghitung `5 + 3 = 8`.

Fenomena ini memang praktis, tapi juga bisa **menjebak** kalau kita tidak paham. Terutama saat **membandingkan** nilai dengan `==` (loose comparison).

Di sinilah pentingnya membedakan **loose comparison (`==`)** vs **strict comparison (`===`)**.

## Fungsi

- **Mempermudah penulisan kode** — PHP berusaha agar operasi tetap bisa dijalankan meski tipe datanya beda.
- **Cocok untuk pemrosesan input** — data dari form HTML selalu berupa **string**, tapi kita bisa langsung hitung/jumlahkan setelah dikonversi otomatis.
- **Membantu memahami perilaku PHP** — biar kita tidak heran saat hasil perbandingan tidak sesuai ekspektasi.
- **Mencegah bug tak terduga** — dengan paham type juggling, kita tahu kapan harus pakai `===` bukan `==`.
- **Fondasi untuk validasi** — penting saat memvalidasi input user di sistem perpustakaan (form pinjam/kembali buku).

## Tracing Code (Step-by-Step)

Kita fokus ke 2 bagian paling penting: **operasi penjumlahan** dan **perbandingan loose vs strict**.

### Tracing A: `$stok = "5"; $ditambah = $stok + 3;`

**Langkah 1 — `$stok = "5";`**

Variabel `$stok` diisi dengan string `"5"`. Tipe saat ini: **string**.

> `$stok` = `"5"` (string)

**Langkah 2 — `$ditambah = $stok + 3;`**

PHP melihat operator `+` (penjumlahan aritmatika). Untuk operasi `+`, PHP **tidak bisa menjumlahkan string dengan angka secara harfiah**. PHP berusaha membuat keduanya "bisa dihitung".

Karena ada angka `3` (integer), PHP **mengkonversi string `"5"` menjadi angka `5`** secara otomatis.

Proses ini disebut **type juggling**.

**Langkah 3 — Perhitungan dilakukan**

Setelah konversi: `5 + 3 = 8`. Hasilnya adalah **integer** `8`.

> `$ditambah` = `8` (integer)

**Kesimpulan A:** PHP mengubah tipe **hanya untuk kebutuhan operasi** saat itu. Variabel `$stok` **tetap** bertipe string `"5"`. Yang berubah adalah cara PHP menafsirkan nilainya saat dijumlahkan.

### Tracing B: `$a = "5 ekor kucing"; $b = $a + 2;`

**Langkah 1 — `$a = "5 ekor kucing";` (string)**

Berisi angka di **awal** string.

**Langkah 2 — `$b = $a + 2;`**

PHP membaca string dari kiri ke kanan, mencari **urutan digit angka** di paling awal. Ditemukan `"5"`. PHP mengambil `"5"` dan mengubahnya jadi integer `5`. Sisa string `" ekor kucing"` **diabaikan** untuk operasi penjumlahan.

Maka `5 + 2 = 7`.

> `$b` = `7`

### Tracing C: `$c = "ekor 5 kucing"; $d = $c + 2;`

**Langkah 1 — String diawali huruf, bukan angka**

Tidak ada digit angka di **posisi paling awal**.

**Langkah 2 — PHP gagal menemukan angka valid di awal**

Saat PHP mencoba mengkonversi string non-numerik ke angka, hasilnya adalah **0** (nol). Di PHP 8, ini biasanya disertai **Warning**: `Non-numeric value encountered`.

Maka `0 + 2 = 2`.

> `$d` = `2`

### Tracing D: Perbandingan `0 == "php"`

**Loose comparison `==`**: PHP **tidak membandingkan tipe**, tapi **mencoba menyamakan tipe** dulu (type juggling), baru membandingkan nilainya.

**Langkah 1 — Bandingkan `0` (integer) dengan `"php"` (string)**

Karena pakai `==`, PHP melihat bahwa salah satunya angka, satunya string. PHP memutuskan: **"Ubah string jadi angka biar bisa dibandingkan"**.

**Langkah 2 — Konversi `"php"` ke angka**

String `"php"` tidak diawali angka. Saat dikonversi ke integer/float, PHP menghasilkan **0**.

**Langkah 3 — Bandingkan `0 == 0`**

Hasilnya **true**.

> `0 == "php"` → **true**

**Bandingkan dengan strict `===`:**

`===` artinya **"tipe HARUS sama DAN nilai HARUS sama"**. `0` adalah integer, `"php"` adalah string → **tipe beda**. Langsung hasilnya **false**, tanpa konversi.

> `0 === "php"` → **false**

### Tracing E: `"1" == "01"`

**Loose `==`:** PHP melihat kedua sisi berupa string. Namun untuk perbandingan numeric-like, PHP kadang mengkonversi ke angka.

Kedua string bisa ditafsirkan sebagai angka: `"1"` → `1`, `"01"` → `1`. Jadi `1 == 1` → **true**.

**Strict `===`:** Membandingkan **string persis**. `"1"` beda karakter dengan `"01"` (ada `'0'` di depan). Tipe sama (string), tapi **nilai string beda** → **false**.

> `"1" == "01"` → true | `"1" === "01"` → false

## Analogi

Bayangkan **petugas perpustakaan** sedang mencocokkan data anggota.

Ada dua cara mencocokkan:

- **Cara longgar (loose `==`)**: Petugas hanya melihat **"kesan"** datanya. Misalnya lihat nomor ID yang tertulis `00123` di kertas vs `123` di sistem. Karena maksudnya sama (nomor anggota 123), petugas bilang: *"Ya, ini orang yang sama."*
- **Cara ketat (strict `===`)**: Petugas melihat **persis apa adanya**. Ia bandingkan bentuk lengkap: `00123` vs `123` → **berbeda bentuk**. Kalau sistem mengharuskan format persis, ia akan bilang: *"Beda, formatnya tidak sama."*

Konteks perpustakaan kita: saat user mengisi form **"Jumlah buku yang dipinjam"** dengan nilai `"2"` (string dari input), lalu kita bandingkan dengan stok `2` (integer). Kalau pakai `==`, PHP akan bilang "sama". **Secara logika untuk bisnis, boleh. Tapi secara tipe, beda.**

Tapi ada kasus berbahaya. Bayangkan kita cek: `if ($akses == "admin")` — aman. Tapi saat bandingkan angka vs string aneh seperti `0 == "php"`, hasilnya **true** padahal jelas beda.

Karena itu, **untuk perbandingan yang kritikal (validasi, hak akses, cek ID)**, lebih aman pakai **`===` (strict)**.

## Dipakai untuk Apa

- **Memproses input form** — nilai dari `$_POST`/`$_GET` selalu **string**. Type juggling mempermudah saat langsung dihitung.
- **Perbandingan kondisi** — `if ($stok > 0)` tetap aman meski `$stok` bisa string `"5"`.
- **Validasi sederhana** — tapi **hindari** loose comparison untuk hal sensitif.
- **Konversi implisit** — berguna saat menghitung denda: `hari * tarif` meski datanya dari form (string).
- **Memahami perilaku fungsi bawaan** — beberapa fungsi PHP juga bergantung pada tipe.
- **Belajar bijak pakai `==` vs `===`** — kebiasaan penting yang akan terbawa ke OOP & framework.

## Kesalahan Umum yang Sering Terjadi

- **Menganggap `==` selalu aman** — Contoh `0 == "php"` benar-benar mengejutkan pemula.
- **Lupa bahwa input form adalah string** — `$input = $_POST['harga'];` tipenya **string**, meski user isi angka.
- **Pakai `==` untuk validasi login** — Kurang aman. Lebih baik strict + validasi terpisah.
- **Kebingungan `"5"` vs `5`** — Secara nilai sama untuk perhitungan, tapi beda untuk `===`.
- **Mengabaikan Warning saat konversi aneh** — `"ekor 5" + 2` memberi hasil 2 dengan warning. Tanda ada yang tidak beres.
- **Mengandalkan type juggling untuk logika bisnis penting** — Lebih aman **konversi eksplisit** (`(int)`, `(bool)`) biar maksud kode jelas.
- **Membandingkan boolean dengan sembarangan** — `1 == true` true, `0 == false` true. Bisa membingungkan kalau tidak sadar.
