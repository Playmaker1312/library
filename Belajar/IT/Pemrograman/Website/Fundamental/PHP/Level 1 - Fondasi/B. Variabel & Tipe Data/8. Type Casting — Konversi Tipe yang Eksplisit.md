# Type Casting — Konversi Tipe yang Eksplisit

## Penjelasan

Setelah melihat **Type Juggling** yang otomatis, sekarang kita belajar **Type Casting**: cara **memaksa konversi tipe data secara eksplisit**.

Type casting artinya kita "mengubah bentuk" suatu nilai ke tipe data yang kita inginkan, dengan cara menuliskannya secara jelas di kode. Tujuannya agar **maksud kita terbaca dengan jelas** dan **mengurangi risiko bug** akibat konversi otomatis yang tak terduga.

Di PHP, kita bisa melakukan type casting dengan menambahkan **nama tipe di dalam tanda kurung** sebelum variabel: `(int)`, `(float)`, `(string)`, `(bool)`, `(array)`, `(object)`.

Ini sangat penting terutama saat **menerima input dari user** (form HTML). Semua data dari `$_GET`, `$_POST`, atau input form **selalu berupa string**. Jadi kalau user mengisi angka `150000` di form, PHP menerimanya sebagai `"150000"` (string). Kalau kita mau menghitungnya, lebih aman kita **konversi dulu secara eksplisit** ke integer/float.

## Fungsi

- **Membuat kode lebih jelas** — kita sengaja memberitahu PHP "ubah ini ke tipe apa".
- **Menghindari jebakan type juggling** — terutama untuk perbandingan (`===`) dan perhitungan.
- **Aman untuk input user** — memvalidasi dan menormalisasi data dari form sebelum diproses.
- **Mencegah kesalahan logika** — saat simpan ke database, atau saat hitung stok, harga, denda perpustakaan.
- **Mengontrol hasil konversi** — kita tahu persis hasilnya, bukan bergantung pada perilaku otomatis PHP.
- **Praktik yang baik (defensive programming)** — kode jadi lebih prediktabel dan aman.

## Tracing Code (Step-by-Step)

Kita telusuri contoh paling relevan: **konversi input form buku** (bagian 5).

### Tracing: `$tahun = (int) ($_POST['tahun'] ?? 0);`

**Langkah 1 — Ambil nilai dari $_POST**

`$_POST['tahun']` bernilai `"2008"` (string). Karena dari form input text, selalu string.

**Langkah 2 — Null coalescing `?? 0` (pengaman)**

`$_POST['tahun'] ?? 0` artinya: jika key `'tahun'` ada dan tidak null, ambil nilainya. Kalau tidak ada (misal form tidak dikirim), ambil `0` sebagai default. Ini mencegah Notice `Undefined index`.

Hasil sementara: `"2008"`

**Langkah 3 — Type casting `(int)`**

Operator `(int)` memaksa nilai `"2008"` diubah menjadi **integer 2008**.

Proses: PHP membaca digit `"2008"`, mengubahnya menjadi angka bulat 2008, menghapus tanda kutip.

> `$tahun` berisi `2008` (tipe: integer)

### Tracing: `$stok = (int) ($_POST['stok'] ?? 0);`

Sama. `"5"` → `5` (int).

### Tracing: `$tersedia = (bool) ($_POST['tersedia'] ?? 0);`

Nilai `"1"` (biasanya dari checkbox yang dicentang) di-cast ke bool. `"1"` adalah non-empty string → hasilnya **true**.

Kalau tidak dicentang, nilainya `0` → `(bool)0` = **false**.

> `$tersedia` berisi `true` (tipe: boolean)

### Tracing: Casting string campur `"4.9 bintang"`

`(float) "4.9 bintang"` → PHP mengambil **angka di awal** yang valid (`4.9`), mengabaikan sisanya `" bintang"`. Hasilnya `4.9` (float).

Ini perilaku konversi numerik PHP yang berguna, tapi kita tetap sebaiknya **membersihkan/sanitasi** input dulu kalau perlu.

## Analogi

Bayangkan petugas perpustakaan menerima **form peminjaman buku** yang diisi pengunjung di kertas.

Di kertas tertulis: *"Jumlah buku: 3"* (tulisan angka). Tapi sistem perpustakaan bekerja dengan **angka murni** untuk menghitung sisa kuota (batas pinjam 5 buku).

Ada dua cara petugas memprosesnya:

- **Cara otomatis (Type Juggling):** Petugas "mengerti maksudnya" dan langsung menghitung seolah itu angka 3. Praktis, tapi kadang bisa salah paham kalau tulisannya ambigu.
- **Cara eksplisit (Type Casting):** Petugas **mengonversi/mentranskrip** tulisan "3" di kertas menjadi **nilai angka 3** di sistem dengan sengaja, lalu mencatatnya dengan tipe data angka. Ini jelas, terukur, dan minim salah tafsir.

Konteks perpustakaan kita: input dari form web itu seperti "kertas isian". Kita **wajib membersihkan dan mengkonversi** datanya secara eksplisit sebelum disimpan/diproses (hitung stok, harga, denda). Dengan begitu, sistem kita bekerja dengan data yang **jenisnya tepat dan konsisten**.

## Dipakai untuk Apa

- **Memproses form input** — ubah string dari $_POST menjadi int/float/bool untuk perhitungan & validasi.
- **Perhitungan keuangan** — harga, diskon, denda perpustakaan sebaiknya dalam bentuk **int/float** (bukan string).
- **Validasi data** — pastikan input angka benar-benar angka, boolean benar-benar boolean.
- **Perbandingan yang aman** — casting dulu baru `===` agar perbandingan lebih jelas & aman.
- **Normalisasi data** — mengubah berbagai bentuk input menjadi tipe standar yang konsisten.
- **Menyimpan ke database** — tipe kolom MySQL (INT, DECIMAL, BOOLEAN/TINYINT) butuh nilai dengan tipe sesuai.
- **Mencegah bug logika** — checkbox "tersedia" kalau tidak di-cast bisa salah tafsir.
- **Fungsi filter/validasi** — kombinasi casting + validasi bikin sistem lebih robust.

## Kesalahan Umum yang Sering Terjadi

- **Bergantung pada type juggling terus** — Praktis, tapi kurang eksplisit. Untuk input user, **lebih baik casting eksplisit**.
- **Lupa konversi input form** — Bandingkan `"5" === 5` false, padahal maksudnya sama. Bisa bikin validasi gagal.
- **Salah memahami casting boolean** — `"false"` (string) kalau di-cast ke bool hasilnya **true**! Karena string non-empty dianggap truthy. Ini sering mengecoh.
- **Casting tanpa validasi** — `(int)"abc123"` hasilnya `0`. Bisa lolos validasi kalau tidak dicek dulu. Sebaiknya **validasi dulu**, baru cast.
- **Menggunakan float untuk uang tanpa hati-hati** — Untuk harga perpustakaan bisa pakai **int** (rupiah bulat) atau DECIMAL di DB. Float punya precision kecil.
- **Tidak pakai null coalescing saat akses $_POST** — Bisa muncul Notice `Undefined index`. Gunakan `??` atau `isset()`.
- **Mengabaikan whitespace** — Input kadang ada spasi. Tambahkan `trim()` sebelum cast untuk string.

## Soal Latihan & Jawaban

### Soal

Simulasikan **form peminjaman buku perpustakaan** dengan data input mentah (string semua). Lakukan pembersihan dan konversi tipe secara eksplisit.

1. Buat array simulasi `$_POST` berisi:
   - `id_buku` = `"1"`
   - `nama_peminjam` = `" Andi Wijaya "` (ada spasi depan/belakang)
   - `jumlah_pinjam` = `"3"`
   - `lama_hari` = `"7"`
   - `setuju` = `"1"` (checkbox dicentang)
2. **Bersihkan dan cast** setiap data ke tipe yang tepat:
   - `nama_peminjam` → string, trim spasi
   - `id_buku`, `jumlah_pinjam`, `lama_hari` → integer
   - `setuju` → boolean
3. Tampilkan hasil dengan `var_dump` untuk tiap variabel.
4. Buat perbandingan: cek apakah `jumlah_pinjam` **sama dengan** batas maksimal (anggap batas = 5, integer). Bandingkan dengan `===` setelah casting.
5. Tampilkan hasilnya dengan penjelasan.
