# Clean Architecture — Arsitektur yang Scalable

## Penjelasan

**Clean Architecture** adalah cara menyusun aplikasi agar **inti logika bisnis tidak bergantung pada hal teknis** seperti database, framework, atau UI. Istilah ini dipopulerkan **Robert C. Martin ("Uncle Bob")**.

Aturan utamanya adalah **Dependency Rule**: **arah ketergantungan selalu menuju ke dalam**. Lapisan luar boleh tahu lapisan dalam, tetapi lapisan dalam **tidak boleh tahu apa-apa** tentang lapisan luar.

Lapisan (dari dalam ke luar):

- **Entities (Domain)** — aturan bisnis inti. Contoh: aturan "buku dengan stok 0 tidak bisa dipinjam". Tidak tahu apa pun soal database.
- **Use Cases (Application)** — alur kerja aplikasi. Contoh: "PinjamBuku" yang mengambil buku, memeriksa stok, lalu menyimpan.
- **Interface Adapters** — penghubung: controller (HTTP), presenter, dan **implementasi repository**.
- **Frameworks & Drivers** — hal teknis terluar: Laravel/Symfony, MySQL, antarmuka web.

Konsep pendukung:

- **Port & Adapter** — port = kontrak (interface) milik lapisan dalam; adapter = implementasi teknis di lapisan luar.
- **Dependency Inversion** — lapisan dalam mendefinisikan interface; lapisan luar yang mengimplementasikannya.
- **Testable** — use case bisa diuji tanpa database karena repository adalah interface.

Konteks perpustakaan: aturan peminjaman ada di **domain**, alur pinjam ada di **use case**, dan penyimpanan database hanyalah **adapter** yang bisa diganti.

## Fungsi

- **Melindungi logika bisnis** dari perubahan teknologi (ganti framework/database tanpa menulis ulang aturan).
- **Membuat bagian inti mudah diuji** tanpa menyentuh database.
- **Memisahkan tanggung jawab** dengan batas yang jelas.
- **Memudahkan pertumbuhan jangka panjang** — aplikasi besar tetap terkelola.
- **Memungkinkan tukar adapter** (MySQL, JSON, API) tanpa mengubah use case.
- **Menghubungkan semua konsep sebelumnya** (OOP, repository, DI, testing) jadi satu arsitektur.

## Cara Pengimplementasian / Code

Struktur folder memisahkan domain, application, dan infrastructure:

```text
src/
├── Domain/
│   ├── Buku.php                    # Entity (aturan inti)
│   └── BukuRepository.php          # Port (interface)
├── Application/
│   └── PinjamBukuUseCase.php       # Use case (alur kerja)
└── Infrastructure/
    └── PdoBukuRepository.php       # Adapter (implementasi teknis)
```

**Domain — `src/Domain/Buku.php` (aturan inti, tanpa database):**

```php
<?php
// src/Domain/Buku.php
namespace App\Domain;

use DomainException;

class Buku
{
    public function __construct(
        public int $id,
        public string $judul,
        private int $stok
    ) {
    }

    // Aturan bisnis ada DI SINI, bukan di controller/database
    public function pinjamSatu(): void
    {
        if ($this->stok <= 0) {
            throw new DomainException('Stok buku habis, tidak bisa dipinjam.');
        }
        $this->stok--;
    }

    public function stok(): int
    {
        return $this->stok;
    }
}
```

**Port — `src/Domain/BukuRepository.php` (kontrak, milik lapisan dalam):**

```php
<?php
// src/Domain/BukuRepository.php
namespace App\Domain;

interface BukuRepository
{
    public function cariId(int $id): ?Buku;
    public function simpan(Buku $buku): void;
}
```

**Use Case — `src/Application/PinjamBukuUseCase.php` (alur kerja):**

```php
<?php
// src/Application/PinjamBukuUseCase.php
namespace App\Application;

use App\Domain\BukuRepository;
use DomainException;

class PinjamBukuUseCase
{
    // Bergantung pada PORT (interface), bukan pada MySQL.
    public function __construct(private BukuRepository $repo)
    {
    }

    public function jalankan(int $bukuId): array
    {
        $buku = $this->repo->cariId($bukuId);
        if ($buku === null) {
            throw new DomainException('Buku tidak ditemukan.');
        }

        $buku->pinjamSatu();   // aturan bisnis dijalankan
        $this->repo->simpan($buku); // disimpan lewat port

        return [
            'id'     => $buku->id,
            'judul'  => $buku->judul,
            'sisa'   => $buku->stok(),
            'pesan'  => 'Buku berhasil dipinjam',
        ];
    }
}
```

**Adapter — `src/Infrastructure/PdoBukuRepository.php` (detail teknis):**

```php
<?php
// src/Infrastructure/PdoBukuRepository.php
namespace App\Infrastructure;

use App\Domain\Buku;
use App\Domain\BukuRepository;
use PDO;

class PdoBukuRepository implements BukuRepository
{
    public function __construct(private PDO $pdo)
    {
    }

    public function cariId(int $id): ?Buku
    {
        $stmt = $this->pdo->prepare('SELECT * FROM buku WHERE id = :id LIMIT 1');
        $stmt->execute([':id' => $id]);
        $r = $stmt->fetch();
        return $r !== false ? new Buku((int) $r['id'], $r['judul'], (int) $r['stok']) : null;
    }

    public function simpan(Buku $buku): void
    {
        $stmt = $this->pdo->prepare('UPDATE buku SET stok = :stok WHERE id = :id');
        $stmt->execute([':stok' => $buku->stok(), ':id' => $buku->id]);
    }
}
```

**Perakitan (di lapisan luar) — `public/pinjam.php`:**

```php
<?php
// public/pinjam.php
require __DIR__ . '/../vendor/autoload.php';

use App\Application\PinjamBukuUseCase;
use App\Infrastructure\PdoBukuRepository;

$pdo = new PDO('mysql:host=localhost;dbname=perpustakaan;charset=utf8mb4', 'root', '', [
    PDO::ATTR_ERRMODE            => PDO::ERRMODE_EXCEPTION,
    PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
]);

// Adapter disuntikkan ke use case — arah dependensi tetap menuju ke dalam
$useCase = new PinjamBukuUseCase(new PdoBukuRepository($pdo));

header('Content-Type: application/json; charset=utf-8');
try {
    echo json_encode($useCase->jalankan((int) ($_GET['id'] ?? 0)));
} catch (Exception $e) {
    http_response_code(400);
    echo json_encode(['error' => $e->getMessage()]);
}
```

**Cara menjalankan/menguji:** `php -S localhost:8000 -t public`, lalu buka `http://localhost:8000/pinjam.php?id=1`.

## Tracing Code (Step-by-Step)

Kita telusuri request **GET /pinjam.php?id=1**.

**Langkah 1 — lapisan terluar merakit objek**

`public/pinjam.php` membuat koneksi PDO, lalu:

```php
$useCase = new PinjamBukuUseCase(new PdoBukuRepository($pdo));
```

Perhatikan: **adapter (luar) yang mengambil inisiatif** menyuplai dirinya ke use case (dalam). Arah ketergantungan membuat use case tetap tidak tahu PDO.

**Langkah 2 — masuk ke use case**

`$useCase->jalankan(1)` dijalankan. Use case memanggil `$this->repo->cariId(1)` **lewat interface**.

**Langkah 3 — adapter menjalankan detail teknis**

Karena objek nyatanya `PdoBukuRepository`, `cariId(1)` berjalan: `prepare()` → `execute([':id' => 1])` → `fetch()`. Misal hasilnya `['id'=>1,'judul'=>'Clean Code','stok'=>1]`, lalu dibungkus menjadi objek `Buku` dengan **stok 1**.

**Langkah 4 — aturan bisnis dijalankan di domain**

Use case memanggil `$buku->pinjamSatu()`. Method itu memeriksa `stok <= 0`. Karena stok `1`, tidak error, lalu `stok--` membuat stok menjadi `0`. Aturan "stok habis" hidup di **domain**, terlepas dari database.

**Langkah 5 — simpan lewat port**

Use case memanggil `$this->repo->simpan($buku)`. Adapter menjalankan `UPDATE buku SET stok = 0 WHERE id = 1`.

**Langkah 6 — kembalikan hasil**

Use case mengembalikan array: `id = 1`, `judul = "Clean Code"`, `sisa = 0`, `pesan = "Buku berhasil dipinjam"`. File `pinjam.php` menjadikannya JSON dan mengirimkannya.

**Tabel lapisan yang tersentuh:**

| Langkah | Lapisan | Yang dilakukan |
|---|---|---|
| 1 | Frameworks & Drivers | koneksi PDO, merakit objek |
| 2 | Application | use case memanggil repository |
| 3 | Interface Adapters | adapter menjalankan query |
| 4 | Domain | aturan stok dijalankan |
| 5 | Interface Adapters | adapter menyimpan |
| 6 | Frameworks & Drivers | mengirim JSON ke client |

Perhatikan: **Domain tidak pernah memanggil ke luar** — ia hanya dipanggil.

**Output akhir (stok semula 1):**

```json
{"id":1,"judul":"Clean Code","sisa":0,"pesan":"Buku berhasil dipinjam"}
```

**Output bila stok 0:**

```json
{"error":"Stok buku habis, tidak bisa dipinjam."}
```

## Analogi

Bayangkan **membangun perpustakaan dengan pondasi dan dinding yang sengaja dipisah**.

- **Domain (Entities)** = **pondasi & tiang utama** yang menentukan bentuk dan kekuatan gedung. Ia tidak peduli warna cat atau merek lampu.
- **Use Case** = **prosedur pelayanan inti**: "cara meminjam buku langkah demi langkah".
- **Interface Adapter** = **pintu, loket, dan meja** yang menghubungkan pengunjung ke prosedur.
- **Frameworks & Drivers** = **cat, lampu, merek mesin, sistem rak** — hal teknis yang bisa diganti.
- **Port (interface)** = **lubang stopkontak standar**. Apa pun merek perangkat (adapter) yang dicolok, prosedurnya tetap jalan.
- **Dependency Rule** = aturan "dinding boleh menempel pondasi, tapi pondasi **tidak tahu** ada dinding."
- **Contoh nyata**: mengganti lampu (ganti database dari MySQL ke JSON) tidak perlu membongkar pondasi (aturan bisnis).

Intinya: **aturannya (pondasi) tetap, teknologinya (cat & lampu) bisa berganti.**

## Dipakai untuk Apa

- **Aplikasi besar berumur panjang** yang teknologinya kemungkinan berganti.
- **Proyek dengan logika bisnis rumit** yang harus terlindungi & teruji.
- **Microservice** dengan domain jelas.
- **Aplikasi multi-channel** (web, mobile, CLI) memakai use case yang sama.
- **Refactor proyek lama** agar tidak terkunci pada satu framework.
- **Kolaborasi tim besar** dengan batas modul yang tegas.

## Kesalahan Umum yang Sering Terjadi

- **Melanggar Dependency Rule** — domain mengimpor PDO/framework → inti jadi terkunci teknologi.
- **Terlalu banyak lapisan** untuk aplikasi kecil → jadi rumit tanpa manfaat. Sesuaikan skala.
- **Menaruh logika bisnis di controller** → aturan mudah terduplikasi & sulit diuji.
- **Entity bocor ke tampilan apa adanya** → gunakan DTO/presenter agar tidak mengikat.
- **Repository berisi aturan bisnis** → batasi hanya akses data.
- **Tidak memakai interface (port)** → adapter tak bisa diganti, dependency inversion hilang.
- **Menganggap Clean Architecture = wajib** di semua kasus → untuk proyek kecil, struktur sederhana lebih baik.

## Hubungan dengan Materi Sebelumnya

- **Materi 23–25 (OOP)**: entity & interface adalah dasar domain dan port.
- **Materi 26–27 (PDO & Prepared Statement)**: adapter memakai keduanya untuk akses data aman.
- **Materi 30 (Composer)**: autoload PSR-4 memisahkan Domain, Application, dan Infrastructure.
- **Materi 33 (Unit Testing)**: use case bisa diuji tanpa database karena bergantung pada interface.
- **Materi 34 (Repository & DI)**: Clean Architecture adalah kelanjutan alami — repository menjadi "port", DI menyusun arah dependensi.
- **Materi 35–36 (Laravel & Symfony)**: keduanya bisa dipakai sebagai "Frameworks & Drivers" di lapisan terluar, tanpa mengotori domain.

## Soal Latihan & Jawaban

### Soal

Buat use case **KembalikanBuku** dengan prinsip yang sama:

1. Tambahkan method `kembalikanSatu()` pada entity `Buku` (menambah stok satu).
2. Tambahkan method `simpan()` tetap dari port `BukuRepository`.
3. Buat `Application/KembalikanBukuUseCase` yang mengambil buku, memanggil `kembalikanSatu()`, lalu menyimpan.
4. Tulis adapter PDO yang sudah ada dipakai ulang (tanpa mengubahnya).

### Jawaban

```php
<?php
// src/Domain/Buku.php — tambahan method
namespace App\Domain;

use DomainException;

class Buku
{
    public function __construct(public int $id, public string $judul, private int $stok) {}

    public function pinjamSatu(): void
    {
        if ($this->stok <= 0) {
            throw new DomainException('Stok buku habis, tidak bisa dipinjam.');
        }
        $this->stok--;
    }

    // Method baru: kembalikan buku menambah stok
    public function kembalikanSatu(): void
    {
        $this->stok++;
    }

    public function stok(): int { return $this->stok; }
}
```

```php
<?php
// src/Application/KembalikanBukuUseCase.php
namespace App\Application;

use App\Domain\BukuRepository;
use DomainException;

class KembalikanBukuUseCase
{
    public function __construct(private BukuRepository $repo) {}

    public function jalankan(int $bukuId): array
    {
        $buku = $this->repo->cariId($bukuId);
        if ($buku === null) {
            throw new DomainException('Buku tidak ditemukan.');
        }

        $buku->kembalikanSatu();   // aturan bisnis
        $this->repo->simpan($buku); // lewat port, adapter PDO yang sama

        return [
            'id'    => $buku->id,
            'judul' => $buku->judul,
            'sisa'  => $buku->stok(),
            'pesan' => 'Buku berhasil dikembalikan',
        ];
    }
}
```

```php
<?php
// public/kembalikan.php
require __DIR__ . '/../vendor/autoload.php';

use App\Application\KembalikanBukuUseCase;
use App\Infrastructure\PdoBukuRepository;

$pdo = new PDO('mysql:host=localhost;dbname=perpustakaan;charset=utf8mb4', 'root', '', [
    PDO::ATTR_ERRMODE            => PDO::ERRMODE_EXCEPTION,
    PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
]);

// Adapter PDO yang sama dipakai ulang tanpa diubah
$useCase = new KembalikanBukuUseCase(new PdoBukuRepository($pdo));

header('Content-Type: application/json; charset=utf-8');
echo json_encode($useCase->jalankan((int) ($_GET['id'] ?? 0)));
```
