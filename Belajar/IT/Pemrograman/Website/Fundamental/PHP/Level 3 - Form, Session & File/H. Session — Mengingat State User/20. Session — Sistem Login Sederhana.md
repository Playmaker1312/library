# Session — Sistem Login Sederhana

## Penjelasan

**Session** adalah cara PHP untuk **mengingat data pengguna antar halaman**. Berbeda dengan `$_GET/$_POST` yang hilang saat pindah halaman, data session tersimpan di **server** selama user masih aktif (berdasarkan session cookie).

Saat `session_start()` dipanggil, PHP akan membuat ID unik (session ID) lalu menyimpannya di cookie browser (`PHPSESSID`). Server menggunakan ID ini untuk mengambil data session user.

Untuk sistem perpustakaan, session berguna untuk: **login admin/anggota**, melindungi halaman (auth middleware), menyimpan user yang sedang login, timeout session, dan mencegah akses tanpa izin.

**Penting untuk keamanan login:**
- Simpan password dengan **`password_hash()`** & verifikasi dengan **`password_verify()`** (JANGAN simpan plain text)
- Gunakan **`session_regenerate_id(true)`** setelah login sukses (cegah session fixation)
- Set session config aman saat development (httponly, use_strict_mode)
- Hancurkan session lengkap saat logout

## Fungsi

- **Mengingat state user** — siapa yang sedang login
- **Proteksi halaman** — batasi akses halaman admin/dashboard
- **Mencegah akses tanpa login** — redirect ke login
- **Session timeout** — otomatis logout jika idle
- **Regenerate ID** — keamanan pasca login
- **Penyimpanan sementara** — user info, role
- **Fondasi auth** — dasar sebelum pakai framework

## Tracing Code (Step-by-Step)

### Tracing A: Login sukses

1. User submit email+password
2. Cek kredensial: `password_verify('admin123', hash)` → true
3. `session_regenerate_id(true)` → ganti session ID baru (mencegah fixation)
4. Set `$_SESSION['user'] = [...]` & `$_SESSION['login_time'] = time()`
5. `header('Location: dashboard.php'); exit;`

### Tracing B: Proteksi dashboard

1. `session_start()` wajib
2. `!isset($_SESSION['user'])` → jika belum login, redirect ke login
3. Cek timeout: `time()-login_time > 3600` → destroy & redirect
4. Refresh `login_time = time()` (extend session aktif)

### Tracing C: Logout

1. `$_SESSION = []` kosongkan array
2. `session_destroy()` hapus session server
3. Hapus cookie `PHPSESSID` dengan setcookie expire masa lalu
4. Redirect ke login

## Analogi

- **Session = Kartu anggota sementara**. Saat login, petugas cetak kartu berisi "Siapa kamu, role apa". Kartu ini dibawa saat keliling perpustakaan (pindah halaman).
- **session_start() = Minta kartu** / buat sesi baru
- **$_SESSION = Brankas data terikat kartu** di server
- **session_regenerate_id(true) = Ganti nomor kartu** setelah berhasil masuk (lebih aman)
- **Session destroy = Kembalikan kartu / cabut akses**
- **Timeout = Kartu kedaluwarsa** jika tidak dipakai lama

## Dipakai untuk Apa

- **Sistem login** admin/anggota
- **Halaman protected** (dashboard, kelola buku)
- **Role-based access** (admin vs anggota)
- **Remember state** (nama user)
- **Session timeout**
- **Anti session fixation**

## Kesalahan Umum yang Sering Terjadi

- **Lupa `session_start()`** di SEMUA halaman yang pakai session
- **Simpan password plain text** → GUNAKAN `password_hash()`
- **Tidak regenerate ID setelah login** → rentan fixation
- **Hanya `session_destroy()` tanpa kosongkan `$_SESSION`** → kadang sisa data
- **Cek isset salah** → redirect loop
- **Timeout tidak dicek** → session bisa abadi
- **Cookie secure false di HTTPS** → kurang aman

## Hubungan dengan Materi Sebelumnya

- **Materi 18 ($_POST & $_GET)** dan **Materi 19 (Sanitasi & Validasi)**: form login menerima & memvalidasi input lewat `$_POST` sebelum diproses.
- **Materi 21 (Flash Messages)**: pesan sukses/gagal setelah login biasanya dikirim lewat session satu kali pakai — kelanjutan langsung dari materi ini.
- Session menjadi fondasi sebelum masuk ke penyimpanan data (materi 22) dan sistem autentikasi yang lebih besar (materi 29 — JWT).

## Soal Latihan & Jawaban

### Soal

Buat sistem login sederhana memakai session dengan ketentuan:

1. `login.php` — form email & password, validasi wajib isi, cek memakai `password_verify()`.
2. `dashboard.php` — hanya bisa diakses jika sudah login; tampilkan nama & role; ada link logout.
3. `logout.php` — kosongkan `$_SESSION`, `session_destroy()`, lalu hapus cookie session.
4. Gunakan `session_regenerate_id(true)` saat login sukses.
5. Tambahkan timeout **10 menit (600 detik)**; jika lewat, paksa logout.

### Jawaban

```php
<?php
// login.php
session_start();
$hash = password_hash('123456', PASSWORD_BCRYPT); // di aplikasi nyata: hash tersimpan di DB
$error = '';

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $email = trim($_POST['email'] ?? '');
    $pw    = $_POST['password'] ?? '';

    if ($email === '' || $pw === '') {
        $error = 'Email dan password wajib diisi';
    } elseif (password_verify($pw, $hash)) {
        session_regenerate_id(true);           // cegah session fixation
        $_SESSION['u'] = ['nama' => 'Siswa Demo', 'role' => 'anggota', 't' => time()];
        header('Location: dash.php');
        exit;
    } else {
        $error = 'Password salah';
    }
}
?>
<form method="post">
    <input type="email" name="email" placeholder="Email">
    <input type="password" name="password" placeholder="Password">
    <button type="submit">Login</button>
</form>
<?php if ($error): ?><p><?= htmlspecialchars($error) ?></p><?php endif; ?>
```

```php
<?php
// dashboard.php
session_start();

// Belum login -> tendang ke halaman login
if (!isset($_SESSION['u'])) {
    header('Location: login.php');
    exit;

if (time() - $_SESSION['u']['t'] > 600) {

    session_destroy();

    exit;
}

$_SESSION['u']['t'] = time(); // perpanjang selama masih aktif
?>
<h1>Dashboard</h1>

<a href="logout.php">Logout</a>
```

```php
<?php
// logout.php
session_start();
$_SESSION = [];                         // kosongkan semua data session
session_destroy();                      // hancurkan session di server
if (isset($_COOKIE[session_name()])) {
    setcookie(session_name(), '', time() - 3600, '/'); // hapus cookie session
}
header('Location: login.php');
exit;
```
