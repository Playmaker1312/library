# Flash Messages — Pesan Satu Kali Pakai

## Penjelasan

**Flash Message** adalah pesan notifikasi yang ditampilkan **hanya sekali** setelah terjadi redirect, lalu **hilang otomatis** saat halaman di-refresh.

Perbedaannya dengan variabel biasa: jika kita simpan pesan di variabel biasa, pesan itu akan tetap ada saat halaman di-refresh. Tapi dengan flash message, kita menyimpannya di **`$_SESSION`**, lalu kita **ambil dan hapus** setelah menampilkannya.

Konsep ini sangat berguna untuk memberikan feedback ke pengguna setelah aksi tertentu, seperti: *"Buku berhasil ditambahkan"*, *"Data berhasil dihapus"*, *"Login berhasil"*, atau *"Terjadi kesalahan saat menyimpan data"*.

Kita bisa menyimpan beberapa flash message sekaligus dengan tipe berbeda (`success`, `error`, `warning`, `info`) dalam bentuk array.

## Fungsi

- **Memberi feedback instan** kepada pengguna setelah melakukan aksi (CRUD, login, logout).
- **Mencegah pesan terulang** saat halaman di-refresh (hanya tampil 1 kali).
- **Terpusat dan reusable** — bisa dibuat jadi helper function (`setFlash()` dan `getFlash()`).
- **Mendukung multi-tipe pesan** — bisa tampilkan beberapa notifikasi berbeda dalam satu waktu.
- **Cocok untuk aplikasi web** dengan pola redirect-after-post (PRG: Post/Redirect/Get).
- **Praktis untuk sistem perpustakaan** — konfirmasi peminjaman, pengembalian, tambah/hapus buku, dll.

```php
<?php
// File: 21-flash-messages.php

session_start();
error_reporting(E_ALL);
ini_set('display_errors', 1);

// Fungsi untuk menyimpan flash message
function setFlash(string $tipe, string $pesan): void {
    // tipe bisa: 'success', 'error', 'info', 'warning'
    $_SESSION['flash'][] = [
        'tipe'  => $tipe,
        'pesan' => $pesan,
    ];
}

// Fungsi untuk mengambil & menghapus flash message
function getFlash(): array {
    $flash = $_SESSION['flash'] ?? [];
    unset($_SESSION['flash']); // Hapus setelah dibaca (agar hanya muncul 1 kali)
    return $flash;
}

// Simulasi aksi yang menghasilkan flash message
```

## Tracing Code (Step-by-Step)

Kita telusuri kasus ketika klik tombol **"Simulasi Sukses"** (`?aksi=sukses`).

**Langkah 1 — Browser mengirim request `GET ?aksi=sukses`**

User mengklik link `<a href="?aksi=sukses">`. Browser mengirim HTTP GET ke `21-flash-messages.php?aksi=sukses`.

**Langkah 2 — PHP menjalankan `session_start()`**

Session diinisialisasi. Jika belum ada session, PHP membuat session ID baru dan menyimpannya di cookie.

**Langkah 3 — Kondisi `isset($_GET['aksi']) && $_GET['aksi'] === 'sukses'` terpenuhi**

Blok if dieksekusi.

**Langkah 4 — Memanggil `setFlash('success', 'Buku berhasil ditambahkan ke katalog perpustakaan!')`**

Fungsi `setFlash()` dieksekusi:
- Mengecek `$_SESSION['flash']` — belum ada, jadi PHP menganggapnya array kosong `[]` (berkat null coalescing tidak diperlukan, tapi saat push pertama akan dibuat array).
- Menambahkan elemen baru: `$_SESSION['flash'][] = ['tipe' => 'success', 'pesan' => '...']`

Sekarang `$_SESSION['flash']` berisi:
```php
[
  ['tipe' => 'success', 'pesan' => 'Buku berhasil ditambahkan ke katalog perpustakaan!']
]
```

**Langkah 5 — Memanggil `setFlash('info', 'Silakan cek daftar buku terbaru.')` kedua kalinya**

Menambahkan elemen kedua ke array `$_SESSION['flash'][]`:
```php
[
  ['tipe' => 'success', 'pesan' => '...'],
  ['tipe' => 'info',    'pesan' => '...']
]
```

**Langkah 6 — Redirect dengan `header('Location: 21-flash-demo.php'); exit;`**

PHP mengirim header HTTP `Location: 21-flash-demo.php`. Browser menerima redirect dan melakukan **HTTP GET** baru ke `21-flash-demo.php`. Eksekusi skrip saat ini dihentikan oleh `exit;`.

**Langkah 7 — Halaman `21-flash-demo.php` dimuat**

Browser request `21-flash-demo.php`. PHP menjalankan `session_start()` lagi. Session yang sama (berdasarkan cookie PHPSESSID) dibuka, sehingga `$_SESSION['flash']` masih berisi 2 pesan tadi.

**Langkah 8 — Ambil flash message**

```php
$flashMessages = $_SESSION['flash'] ?? [];
```
Variabel `$flashMessages` sekarang menyimpan array berisi 2 pesan.

**Langkah 9 — Hapus flash message dari session**

```php
unset($_SESSION['flash']);
```
`$_SESSION['flash']` **dihapus** (unset). Sekarang session tidak lagi menyimpan pesan flash tersebut.

**Langkah 10 — Tampilkan pesan di HTML**

`foreach ($flashMessages as $msg)` mengiterasi array yang sudah di-copy ke `$flashMessages` (sebelum unset). Kedua alert sukses dan info ditampilkan dengan benar di halaman.

**Langkah 11 — User melakukan refresh halaman (F5)**

Browser mengirim HTTP GET ulang ke `21-flash-demo.php`. `session_start()` membuka session yang sama. Kali ini `$_SESSION['flash']` **sudah tidak ada** (sudah di-unset di langkah 9). Maka `$flashMessages = []` (empty array). `unset` tidak ada efek. Loop foreach tidak dijalankan, sehingga **tidak ada pesan yang ditampilkan**.

**Kesimpulan Tracing:** Pesan flash **hanya bisa dibaca sekali** karena kita langsung `unset($_SESSION['flash'])` setelah mengambilnya.

## Analogi

Bayangkan petugas perpustakaan memberikan **nota pemberitahuan** kepada pengunjung setelah ia selesai melakukan peminjaman buku.

- Petugas menulis nota: *"Peminjaman buku berhasil dicatat!"* (setFlash)
- Nota itu **diberikan langsung** ke pengunjung saat ia keluar loket (redirect ke halaman konfirmasi)
- Pengunjung membaca nota itu sekali di konfirmasi (`getFlash` + tampil)
- Setelah dibaca, pengunjung **membuang/melipat nota tersebut** (`unset($_SESSION['flash'])`)
- Kalau pengunjung bolak-balik/refresh halaman konfirmasi, ia **tidak mendapatkan nota yang sama lagi** — karena sudah dibuang.

Persis seperti itu: flash message adalah **pesan sekali pakai** yang hilang otomatis setelah dibaca.

Dalam konteks perpustakaan: "Buku berhasil ditambahkan", "Buku berhasil dikembalikan", "Anggota berhasil terdaftar" — pesan-pesan ini cukup muncul **sekali** sebagai konfirmasi, tidak perlu muncul lagi saat user refresh halaman.

## Dipakai untuk Apa

- **Notifikasi CRUD** — konfirmasi tambah/edit/hapus buku/anggota.
- **Feedback login/logout** — "Berhasil login", "Berhasil logout".
- **Validasi hasil** — tampilkan error/sukses setelah proses form.
- **Pola PRG (Post/Redirect/Get)** — standar aman agar form tidak ter-submit ulang saat refresh.
- **Dashboard sistem** — peringatan stok menipis, denda, dll.
- **Multi-notifikasi** — bisa kirim beberapa pesan sekaligus dalam satu aksi.
- **Meningkatkan UX** — memberi umpan balik jelas tanpa mengotori URL.

## Kesalahan Umum yang Sering Terjadi

- **Lupa `session_start()`** di halaman yang pakai getFlash/setFlash → session tidak bisa dibaca/ditulis.
- **Lupa `unset($_SESSION['flash'])` setelah ambil** → pesan akan muncul terus-menerus saat refresh (bukan flash lagi).
- **Memanggil getFlash() dua kali di halaman yang sama** → pemanggilan kedua akan mengembalikan array kosong (sudah di-unset).
- **Menyimpan string langsung** bukannya array multi-tipe → kurang fleksibel untuk styling (success/error).
- **Tidak pakai redirect** setelah setFlash (langsung tampil di halaman yang sama) → tidak benar-benar "flash" dan bisa bermasalah saat refresh.
- **Lupa `exit;` setelah `header('Location: ...')`** → eksekusi bisa lanjut dan menyebabkan perilaku tidak terduga.
- **Menampilkan pesan tanpa `htmlspecialchars()`** → potensi XSS jika pesan mengandung HTML.
- **Menggunakan nama key session lain yang bentrok** → hindari nama umum, pakai `flash` spesifik.

## Soal Latihan & Jawaban

### Soal

Buat sistem sederhana dengan flash message untuk simulasi tambah buku.

1. Buat file `tambah-buku-flash.php` dengan form sederhana (judul, pengarang). Gunakan metode POST.
2. Jika form disubmit dan **judul tidak kosong**, simpan flash message tipe `success` berisi "Buku '[judul]' berhasil ditambahkan!", lalu redirect ke `daftar-buku-flash.php`.
3. Jika form disubmit tapi **judul kosong**, simpan flash message tipe `error` berisi "Judul buku wajib diisi!", lalu redirect kembali ke `tambah-buku-flash.php` (atau halaman yang sama).
4. Di `daftar-buku-flash.php`, tampilkan flash message (jika ada) dengan styling berdasarkan tipenya, lalu hapus setelah ditampilkan.
5. Tambahkan link kembali ke form tambah buku.
