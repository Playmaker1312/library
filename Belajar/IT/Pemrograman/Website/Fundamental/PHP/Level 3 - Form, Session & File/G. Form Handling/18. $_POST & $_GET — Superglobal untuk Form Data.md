# $_POST & $_GET — Superglobal untuk Form Data

## Penjelasan

Sampai Level 2, data yang kita pakai masih **hardcode** (ditulis langsung di kode). Sekarang kita belajar menerima **input dari pengguna** melalui **HTML Form**.

Di PHP, data yang dikirim dari form bisa ditangkap melalui **superglobal**:

- **`$_GET`** — menangkap data yang dikirim melalui **URL (query string)**. Cocok untuk pencarian, filter, atau parameter yang boleh terlihat di URL.
- **`$_POST`** — menangkap data yang dikirim melalui **HTTP POST** (body request). Cocok untuk data sensitif/form penting (login, tambah buku, peminjaman).

**Perbedaan utama:**

| Aspek | `$_GET` | `$_POST` |
|---|---|---|
| **Cara kirim** | Melalui URL (`?key=value&key2=value2`) | Melalui body HTTP (tidak terlihat di URL) |
| **Batas panjang** | Terbatas (tergantung browser/server) | Tidak terbatas (untuk data normal) |
| **Keamanan** | Kurang aman (terlihat URL, bisa di-bookmark) | Lebih aman untuk data sensitif |
| **Penggunaan** | Pencarian, filter, pagination | Login, form tambah/edit data, upload |

**Penting:** Semua input dari user **HARUS dianggap tidak aman**. Kita tidak boleh langsung menampilkan/menyimpan tanpa validasi dan sanitasi (akan dipelajari Poin 19).

## Fungsi

- **Menerima input dari user** — menghubungkan form HTML dengan logika PHP.
- **Membuat halaman web interaktif** — user bisa mengirim data ke server.
- **Mengumpulkan data** — tambah buku, pencarian buku, login anggota.
- **Mengirim data secara terstruktur** — PHP mengubah data form jadi array associative di `$_GET`/`$_POST`.
- **Fondasi CRUD & validasi** — dasar untuk aplikasi web dinamis.
- **Membedakan metode GET vs POST** — memilih metode yang tepat sesuai kebutuhan.

    }

    // Jika tidak ada error
    if (empty($errors)) {
        $sukses = true;
        // Reset form setelah sukses
        $input = [];
    }
}

## Tracing Code (Step-by-Step)

Kita telusuri 2 kasus: **submit form POST** dan **akses link dengan GET**.

### Tracing A: Form dikirim dengan metode POST

**Langkah 1 — User mengisi form dan klik Submit**

User mengisi field Judul: `"Clean Code"`, Pengarang: `"Robert Martin"`, Tahun: `"2008"`, Harga: `"150000"`, Stok: `"5"`. Klik tombol "Simpan Buku".

**Langkah 2 — Browser mengirim HTTP POST**

Form punya `method="POST"`, `action=""` (kirim ke halaman yang sama). Browser mengirim **HTTP Request** dengan metode `POST`. Data form dikemas dalam **request body** (bukan di URL). Contoh body: `judul=Clean+Code&pengarang=Robert+Martin&tahun=2008&harga=150000&stok=5`

**Langkah 3 — PHP menerima request**

Server Apache meneruskan ke PHP. PHP membaca metode request: `$_SERVER['REQUEST_METHOD']` bernilai `"POST"`.

**Langkah 4 — Kondisi if ($_SERVER['REQUEST_METHOD'] === 'POST') terpenuhi**

Karena true, blok POST dieksekusi.

**Langkah 5 — Ambil data dari $_POST**

```php
$input = [
    'judul'     => trim($_POST['judul'] ?? ''),
    'pengarang' => trim($_POST['pengarang'] ?? ''),
    'tahun'     => trim($_POST['tahun'] ?? ''),
    'harga'     => trim($_POST['harga'] ?? ''),
    'stok'      => trim($_POST['stok'] ?? ''),
];
```

PHP mengambil nilai dari array superglobal `$_POST`. Karena form mengirim nama field sesuai `name="judul"`, maka `$_POST['judul']` berisi `"Clean Code"`, dst. Operator `?? ''` mencegah Notice jika field tidak ada. `trim()` menghapus spasi.

> `$input['judul'] = "Clean Code"`, `$input['tahun']="2008"`, dll.

**Langkah 6 — Validasi sederhana**

Semua field terisi dan numerik → **tidak ada error**. Array `$errors` tetap kosong.

**Langkah 7 — Jika empty($errors)**

Kondisi true → `$sukses = true`. Lalu `$input = []` (reset form agar field kosong kembali setelah sukses).

**Langkah 8 — PHP menghasilkan HTML response**

Di template HTML, `<?php if ($sukses): ?>` terpenuhi → menampilkan alert sukses "Data buku berhasil dikirim via $_POST". Form ditampilkan dengan `$input` kosong.

**Output akhir:** Halaman menampilkan pesan sukses. **Data form TIDAK terlihat di URL** (metode POST).

### Tracing B: Klik link dengan $_GET

Link: `?cari=Clean+Code&kategori=Teknologi`

**Langkah 1 — Browser mengirim HTTP GET**

Ketika klik link, browser mengirim request ke URL tersebut. Data setelah `?` disebut **Query String**: `cari=Clean+Code&kategori=Teknologi`. Metode request = `GET`.

**Langkah 2 — PHP mengisi $_GET**

PHP mem-parsing query string dan mengisi superglobal `$_GET` sebagai array associative:

```php
$_GET = [
  'cari'     => 'Clean Code',
  'kategori' => 'Teknologi'
];
```

**Langkah 3 — Blade/HTML mengecek !empty($_GET)**

Kondisi true → menampilkan `print_r($_GET, true)`. Karena kita pakai `htmlspecialchars()`, array ditampilkan dalam bentuk teks aman (tidak dieksekusi HTML).

**Output:** Terlihat struktur array $_GET di halaman. **Data terlihat jelas di URL bar browser**.

**Kesimpulan Tracing:** POST menyembunyikan data di body, GET menampilkannya di URL.

## Analogi

Bayangkan **perpustakaan** memiliki dua cara pengunjung mengirim permintaan ke petugas.

**Cara 1 — $_GET (Melalui papan pengumuman/URL)**  
Pengunjung menulis permintaannya di **selembar kertas kecil dan menempelkannya di papan pengumuman depan perpustakaan**: *"Mencari buku berjudul 'Clean Code', kategori Teknologi"*. Semua orang yang lewat bisa **membaca** permintaan itu (terlihat). Cocok kalau permintaan itu **umum/bisa dibagikan** (misal link pencarian buku ke teman).

**Cara 2 — $_POST (Melalui loket tertutup)**  
Pengunjung masuk ke **loket pelayanan**, mengisi formulir pengisian data buku baru, lalu menyerahkannya **langsung ke petugas** tanpa ditempel di papan pengumuman. Permintaan itu **tidak terlihat orang lain**. Cocok untuk data penting/rahasia (data buku baru, data anggota, login).

Jadi: **GET = permintaan terbuka (papan pengumuman), POST = permintaan tertutup (loket privat)**.

## Dipakai untuk Apa

- **Form tambah/edit buku** (POST) — mengirim data baru ke sistem
- **Pencarian buku** (GET) — `?cari=php` bisa di-bookmark/dibagikan
- **Filter katalog** (GET) — filter berdasarkan kategori, tahun, harga
- **Pagination** (GET) — `?halaman=2`
- **Login/registrasi** (POST) — hindari password terlihat di URL
- **Hapus data** (POST) — lebih aman dari accidental klik link
- **Form peminjaman/kembalikan** (POST) — mengubah state data

## Kesalahan Umum yang Sering Terjadi

- **Langsung echo $_POST['judul'] tanpa cek isset/??** — Bisa muncul Notice `Undefined index`
- **Pakai GET untuk data sensitif (password)** — Password akan terlihat di URL & history browser
- **Lupa htmlspecialchars() saat menampilkan ulang input** — Potensi XSS jika user input HTML
- **Tidak validasi kosong** — Form bisa dikirim kosong
- **Confusi method GET vs POST** — Klik refresh form POST bisa minta konfirmasi "resubmit", GET aman di-refresh
- **Action kosong `action=""` OK**, tapi kadang lebih eksplisit tulis nama file
- **Mengandalkan hanya client-side** — Validasi HTML (required) bisa dilewati, **wajib validasi server-side** (PHP)
- **Menerima data tanpa trim()** — Spasi depan/belakang bisa bikin validasi gagal

## Hubungan dengan Materi Sebelumnya

**Materi sebelumnya (Poin 17):** `Scope Variabel`. Kita pakai variabel lokal `$errors`, `$input`, `$sukses`.

**Hubungan:** Kita mulai menerima data eksternal (`$_POST/$_GET`) — berbeda dari variabel internal. Perlu kehati-hatian.

**Materi selanjutnya (Poin 19):** `Sanitasi & Validasi — Keamanan Input Dasar`. Setelah bisa menangkap data form, kita wajib **membersihkan (sanitize)** dan **memvalidasi** data agar aman dari XSS, CSRF, dan input tidak valid.
