# Sanitasi & Validasi — Keamanan Input Dasar

## Penjelasan

Setiap data yang berasal dari **luar server** (form, URL, cookie) **TIDAK BOLEH dipercaya**. User bisa mengirim apa saja: script berbahaya, angka negatif, email palsu, dll.

Kita perlu dua proses penting:

1. **Sanitasi (Sanitization)** — **Membersihkan** input dari karakter yang tidak diinginkan (spasi, tag HTML berbahaya). Tujuannya membuat data "lebih bersih".
2. **Validasi (Validation)** — **Memeriksa** apakah data sesuai aturan yang kita tetapkan (wajib diisi, format email, angka >= 0, dll). Tujuannya memastikan data "benar/sah".

Selain itu, untuk mencegah serangan **XSS (Cross-Site Scripting)**, kita **HARUS** menggunakan `htmlspecialchars()` setiap kali **menampilkan** input user ke halaman HTML.

Kita juga akan belajar dasar **CSRF (Cross-Site Request Forgery)** dengan token sederhana dan penggunaan `filter_var()` untuk sanitasi/validasi terstandar.

## Fungsi

- **Mencegah XSS** — blokir injeksi script `<script>...`
- **Mencegah input salah** — pastikan data valid sesuai bisnis (sistem perpustakaan)
- **Menstandarkan data** — trim, lowercase email
- **Melindungi form dari CSRF** — cegah pengiriman form dari situs lain
- **Meningkatkan UX** — tampilkan pesan error jelas
- **Persiapan simpan DB** — data bersih & valid
- **Defensive programming** — anggap semua input berbahaya
- **Praktik keamanan dasar** — wajib sebelum lanjut

session_start();

// Fungsi generate & verify CSRF token sederhana
function generateCsrfToken(): string {
    if (!isset($_SESSION['csrf_token'])) {
        $_SESSION['csrf_token'] = bin2hex(random_bytes(32));
    }
    return $_SESSION['csrf_token'];
}
function verifyCsrfToken(string $token): bool {
    if (!isset($_SESSION['csrf_token'])) return false;
    return hash_equals($_SESSION['csrf_token'], $token);
}

    $pengarang = trim($_POST['pengarang'] ?? '');
    $email     = trim($_POST['email'] ?? '');
    $tahun     = trim($_POST['tahun'] ?? '');
    $harga     = trim($_POST['harga'] ?? '');

    $tahunSanit = filter_var($tahun, FILTER_SANITIZE_NUMBER_INT);
    $hargaSanit = filter_var($harga, FILTER_SANITIZE_NUMBER_INT);
    $stokSanit  = filter_var($stok,  FILTER_SANITIZE_NUMBER_INT);

    // Simpan input untuk ditampilkan kembali
    $input = [
        'judul'     => $judul,
        'pengarang' => $pengarang,
        'email'     => $emailSanit,
        'tahun'     => $tahunSanit,
        'harga'     => $hargaSanit,
        'stok'      => $stokSanit,
    ];

    // 3. Validasi
    if ($judul === '') {
        $errors['judul'] = 'Judul buku wajib diisi';
    } elseif (strlen($judul) > 200) {
        $errors['judul'] = 'Judul maksimal 200 karakter';
    }

    if ($pengarang === '') {
        $errors['pengarang'] = 'Nama pengarang wajib diisi';
    }

    if ($emailSanit === '') {
        // boleh kosong? kita buat wajib contoh
        $errors['email'] = 'Email kontak wajib diisi';
    } else {
        if (filter_var($emailSanit, FILTER_VALIDATE_EMAIL) === false) {
            $errors['email'] = 'Format email tidak valid';
        } else {
            $input['email'] = strtolower($emailSanit);
        }
    }

    // Validasi tahun
    $tahunInt = (int)$tahunSanit;
    $tahunNow = (int)date('Y');
    if ($tahunSanit === '' || filter_var($tahunInt, FILTER_VALIDATE_INT) === false) {
        $errors['tahun'] = 'Tahun harus berupa angka';
    } elseif ($tahunInt < 1000 || $tahunInt > $tahunNow) {
        $errors['tahun'] = "Tahun harus antara 1000 - $tahunNow";
    } else {
        $input['tahun'] = $tahunInt;
    }

    // Validasi harga & stok
    $hargaInt = (int)$hargaSanit;
    if ($hargaSanit === '' || !filter_var($hargaInt, FILTER_VALIDATE_INT, ['options'=>['min_range'=>0]])) {
        $errors['harga'] = 'Harga harus angka >= 0';
    } else {
        $input['harga'] = $hargaInt;
    }

    $stokInt = (int)$stokSanit;
    if ($stokSanit === '' || !filter_var($stokInt, FILTER_VALIDATE_INT, ['options'=>['min_range'=>0]])) {
        $errors['stok'] = 'Stok harus angka >= 0';
    } else {
        $input['stok'] = $stokInt;
    }

    // 4. Jika valid
    if (empty($errors)) {
        // Di aplikasi nyata: simpan ke DB. Di sini hanya tampilkan sukses.
        $sukses = true;
        // Regenerate token baru untuk keamanan (opsional)
        unset($_SESSION['csrf_token']);
        $csrf_token = generateCsrfToken();
        $input = [];
    } else {
        // tetap pakai token lama
    }
}

## Tracing Code (Step-by-Step)

### Tracing A: Sanitasi dengan `filter_var`

`$email = "  test<script>@mail.com  ";`
- `trim()` → `"test<script>@mail.com"`
- `FILTER_SANITIZE_EMAIL` → menghapus karakter tidak valid untuk email (seperti `< > " ' \` dll). Hasil bisa `"testscript@mail.com"` tergantung aturan filter.

`$tahun = "2008abc"` → `FILTER_SANITIZE_NUMBER_INT` → ambil angka `"2008"`

### Tracing B: Validasi `FILTER_VALIDATE_EMAIL`

Setelah disanitasi, cek: `filter_var($emailSanit, FILTER_VALIDATE_EMAIL) !== false`. Jika format benar → valid. Jika salah (misal `test@com`) → error.

### Tracing C: CSRF Token Flow

**Saat load halaman (GET):**
1. `generateCsrfToken()` cek `$_SESSION['csrf_token']` belum ada → generate random 32-byte hex → simpan di session → return token
2. Ditampilkan di form: `<input type="hidden" name="csrf_token" value="...">`

**Saat submit POST:**
1. Ambil `$_POST['csrf_token']`
2. `verifyCsrfToken()` bandingkan dengan session pakai `hash_equals()` (timing attack safe)
3. Jika match → lanjut validasi. Jika tidak → `die('CSRF token tidak valid...')`

**Setelah sukses:** `unset($_SESSION['csrf_token'])` lalu generate baru (best practice) biar token tidak reuse.

### Tracing D: Mencegah XSS dengan `htmlspecialchars()`

Saat menampilkan ulang input: `value="<?= htmlspecialchars($input['judul'] ?? '') ?>"`

Jika user input `<script>alert(1)</script>`, `htmlspecialchars()` mengubah jadi `&lt;script&gt;alert(1)&lt;/script&gt;`. Browser **menampilkan teks**, bukan mengeksekusi JS.

## Analogi

Bayangkan **gerbang masuk perpustakaan**.

- **Sanitasi (trim/filter_var)** → Seperti petugas memeriksa tas pengunjung: membuang sampah/kertas tidak perlu, merapikan isi supaya tertib.
- **Validasi** → Seperti mengecek KTP/identitas: "Apakah nama terisi? Apakah tahun lahir masuk akal? Apakah email format benar?"
- **CSRF Token** → Seperti **kartu masuk resmi**. Hanya orang yang benar-benar ada di loket pendaftaran (halaman form kita) yang dapat kartu. Kalau ada orang kirim formulir dari luar (situs palsu), ia tidak punya kartu valid → ditolak.
- **htmlspecialchars() saat menampilkan** → Seperti **sensor bahasa kasar/instruksi berbahaya** saat menulis kembali di papan pengumuman. Yang ditampilkan hanya **teks aman**, bukan perintah.
- **hash_equals()** → Seperti mencocokkan sidik jari kartu masuk (sangat presisi) biar tidak bisa ditebak.

Konteks perpustakaan: data anggota/buku harus **bersih, valid, dan aman** sebelum dicatat di buku induk.

## Dipakai untuk Apa

- **Form tambah/edit buku/anggota** — validasi wajib
- **Login form** — minimal validasi email/password
- **Contact form** — cegah spam/script
- **Filter input** — angka, email, URL
- **Mencegah XSS** — saat tampilkan data user
- **Mencegah CSRF** — proteksi aksi penting
- **Sanitasi sebelum DB** — konsisten
- **Membangun trust** — sistem lebih aman

## Kesalahan Umum yang Sering Terjadi

- **Hanya validasi client-side (HTML required)** — mudah dilewati (curl/postman)
- **Lupa htmlspecialchars() saat echo** — sumber XSS paling umum
- **Pakai == untuk bandingkan token** — timing leak. Gunakan `hash_equals()`
- **Sanitasi BERLEBIHAN** sampai merusak data valid (jarang) — pilih filter tepat
- **Validasi tapi tidak sanitasi** — bisa lolos tapi kotor
- **Lupa regenerate CSRF token setelah sukses** — praktik baik
- **filter_var sanitize email bisa ubah email valid** — umumnya aman
- **Menaruh CSRF token di GET** — JANGAN. Gunakan hidden POST
- **Die saat CSRF invalid tanpa pesan ramah** — OK untuk belajar, perbaiki nanti

## Hubungan dengan Materi Sebelumnya

**Materi sebelumnya (Poin 18):** `$_POST & $_GET`. Kita bisa menangkap data.

**Hubungan:** Sekarang kita **membentengi** data yang ditangkap.

**Materi selanjutnya (Poin 20):** `Session — Sistem Login Sederhana`. Kita akan pakai `$_SESSION` lagi (sudah dipakai di sini untuk CSRF). Belajar login, logout, proteksi halaman.

## Soal Latihan & Jawaban

### Soal

Buat form **registrasi anggota perpustakaan** dengan sanitasi & validasi ketat.

1. Field: `nama`, `email`, `no_hp`, `password`, `konfirmasi_password`
2. Sanitasi: trim semua. Email → `FILTER_SANITIZE_EMAIL` + `strtolower`
3. Validasi:
   - nama wajib, min 3 karakter, max 100
   - email wajib & valid
   - no_hp wajib & hanya angka (minimal 10 digit)
   - password min 6 karakter
   - konfirmasi_password harus sama dengan password
4. Tambah **CSRF token**
5. Saat valid, tampil pesan sukses (JANGAN tampil password)
6. Saat menampilkan ulang, **WAJIB** pakai `htmlspecialchars()`
7. Simpan `latihan-sanitasi.php`
