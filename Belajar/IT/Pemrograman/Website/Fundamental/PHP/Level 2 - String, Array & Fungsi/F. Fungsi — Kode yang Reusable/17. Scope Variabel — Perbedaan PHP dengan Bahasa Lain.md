# Scope Variabel — Perbedaan PHP dengan Bahasa Lain

## Penjelasan

**Scope (jangkauan)** variabel adalah area di mana variabel bisa diakses dan digunakan. Di PHP, ada beberapa jenis scope yang perlu dipahami:

- **Local Scope** — variabel yang dideklarasikan **di dalam fungsi**. Hanya bisa diakses di dalam fungsi itu saja.
- **Global Scope** — variabel yang dideklarasikan **di luar fungsi**. Secara default **TIDAK bisa** diakses langsung di dalam fungsi PHP (ini beda dari JavaScript).
- **Superglobal** — variabel bawaan PHP yang bisa diakses dari mana saja (`$_GET`, `$_POST`, `$_SESSION`, `$_SERVER`, dll).
- **Static Scope** — variabel lokal yang **nilai-nya tetap bertahan** antar pemanggilan fungsi (`static $count = 0`).
- **Scope Closure** — berkaitan dengan `use()` dan auto-capture arrow function.

Perbedaan paling penting yang wajib diingat: **di PHP, variabel global TIDAK otomatis tersedia di dalam fungsi**. Kita harus "membawanya" dengan `global`, `use()` (untuk closure), atau **passing via parameter** (cara terbaik & paling aman).

## Fungsi

- **Menghindari konflik nama variabel** — scope memisahkan konteks
- **Memahami aksesibilitas** — kapan variabel bisa dipakai
- **Menulis kode aman** — mengurangi side effect (perubahan tak sengaja)
- **Membedakan PHP vs JS** — paham perbedaan fundamental
- **Memaksimalkan closure/arrow** — paham cara capture variabel
- **Menggunakan static dengan bijak** — counter, cache sederhana
- **Membentuk habit baik** — lebih suka **passing parameter** ketimbang `global`
- **Fondasi OOP** — konsep visibility/property mirip

## Tracing Code (Step-by-Step)

### Tracing A: Global vs Fungsi

```php
$namaAdmin = "Admin Perpustakaan";
function cobaAksesGlobal(): void {
    echo $namaAdmin; // Notice
}
```

PHP menjalankan fungsi terpisah. Scope fungsi = "ruangan" berbeda. Variabel `$namaAdmin` ada di "ruangan luar", tidak otomatis masuk. Jadi PHP bilang `Undefined variable`.

### Tracing B: `global $namaAdmin`

Dengan `global`, kita **"mengimpor" referensi** variabel global ke dalam scope fungsi. Jadi fungsi bisa baca & (bisa juga) ubah nilainya. Tapi **mengubah global di dalam fungsi bisa menciptakan side effect**.

### Tracing C: `static $count = 0`

- **Pemanggilan 1:** inisialisasi `$count = 0` (hanya sekali), lalu `$count++` → return 1
- **Pemanggilan 2:** TIDAK menginisialisasi ulang. `$count` masih 1, jadi `$count++` → return 2
- **dst.** Nilai "terekam" di memori fungsi

Tanpa `static`: tiap pemanggilan selalu inisialisasi 0 → return 1 terus.

### Tracing D: Closure `use($judulBuku)`

Closure dibuat di scope luar. `use()` **menyalin nilai** variabel saat closure didefinisikan (by value). Jadi meski variabel luar berubah setelah closure dibuat, closure tetap pakai nilai lama (kecuali pakai `&$judulBuku` by reference).

### Tracing E: Arrow Function Auto-Capture

Arrow `fn() => ...` otomatis menangkap variabel dari parent scope. Mirip closure tapi lebih ringkas. Di PHP, arrow function juga **by value** untuk capture variabel.

## Analogi

Bayangkan perpustakaan punya **berbagai ruangan**.

- **Global Scope** → Ruang pimpinan (kantor kepala). Ada papan pengumuman "Nama Perpustakaan". Semua karyawan tahu, tapi kalau mau "pakai" di ruang lain, perlu izin/salinan.
- **Local Scope** → Meja petugas di loket peminjaman. Di meja itu ada "kertas catatan peminjaman hari ini". Kertas itu **hanya ada di loket itu**. Petugas loket lain tidak bisa lihat.
- **Passing Parameter** → Alih-alih petugas lain masuk ke kantor minta data, kepala perpustakaan **mengirim fotokopi** papan pengumuman ke loket. Jelas, aman, rapi.
- **`global` keyword** → Petugas loket **langsung masuk kantor** ambil data dari papan asli. Praktis, tapi kurang terjaga (bisa merusak).
- **Static Variable** → Mesin penghitung pengunjung. Setiap kali ada pengunjung masuk (fungsi dipanggil), angka di mesin **bertambah**, **tidak reset** ke nol. Mesin itu "mengingat" jumlah sebelumnya.
- **Closure `use()`** → Petugas diberi **catatan tertulis** "Filter: harga <= 140000". Catatan dibawa saat menyaring buku. Meski aturan berubah besok, catatan yang dibawa tetap yang lama.
- **Arrow Function** → Sama, tapi petugas **langsung hafal** aturannya. Lebih praktis.

Konteks perpustakaan: lebih baik petugas **bertukar info via parameter** ketimbang saling mengubah data kantor secara langsung.

## Dipakai untuk Apa

- **Mengorganisir data** — pisahkan konteks agar aman
- **Mencegah side effect** — hindari ubah global sembarangan
- **Counter** — `static` untuk hitung kunjungan/transaksi
- **Callback dinamis** — closure use untuk filter
- **Fungsi reusable & testable** — passing parameter ideal
- **Memahami perbedaan PHP** — hindari kebiasaan JS yang salah diterapkan
- **Factory function** — closure membawa data kontekstual

## Kesalahan Umum yang Sering Terjadi

- **Langsung akses global di fungsi** → `Undefined variable`
- **Overuse `global`** → sulit debug, side effect tinggi
- **Lupa `static` saat butuh "mengingat" nilai** → selalu reset
- **Salah paham by value vs by reference di `use()`** → `use(&$var)` baru bisa ubah
- **Arrow function dipaksakan untuk multi-statement** — tidak bisa
- **Mengubah global via closure** → kurang disarankan
- **Menganggap local bisa diakses luar** → `Undefined variable`
- **Static di rekursi** — perlu diperhatikan
- **Mencampur global + parameter** → membingungkan
