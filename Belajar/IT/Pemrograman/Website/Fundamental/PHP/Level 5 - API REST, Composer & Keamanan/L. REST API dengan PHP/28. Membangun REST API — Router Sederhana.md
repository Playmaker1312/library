# Membangun REST API — Router Sederhana

## Penjelasan

**REST API (Representational State Transfer Application Programming Interface)** adalah cara client dan server berkomunikasi lewat protokol **HTTP**. Client mengirim permintaan, server membalas dengan data — biasanya berformat **JSON**.

Konsep inti REST:

- **Resource** = "benda" yang diakses, ditandai lewat URL. Contoh: `/buku`, `/anggota`, `/peminjaman`.
- **HTTP Method** = aksi terhadap resource: `GET` (ambil), `POST` (tambah), `PUT`/`PATCH` (ubah), `DELETE` (hapus).
- **Endpoint** = alamat spesifik, misal `http://localhost/perpustakaan/28-api.php/buku`.
- **Stateless** = setiap request berdiri sendiri; server tidak mengingat request sebelumnya (kecuali memakai token).
- **JSON** = format pertukaran data (`Content-Type: application/json`).
- **Status Code** = kode jawaban: `200 OK`, `201 Created`, `400 Bad Request`, `404 Not Found`, `405 Method Not Allowed`, `500 Internal Server Error`.
- **Routing** = proses mencocokkan **method + URL** ke **fungsi penangani (handler)**.

Di materi ini kita membangun **router sederhana manual** dengan PHP murni, supaya paham cara kerja router sebelum memakai framework (Laravel/Symfony).

Konteks perpustakaan: kita buat API katalog buku dengan data contoh (simulasi database).

## Fungsi

- **Memahami REST secara praktis**, bukan cuma teori.
- **Menjadi jembatan** antara backend PHP dan frontend terpisah (React/Vue/mobile).
- **Menyeragamkan format balasan** agar mudah diolah client.
- **Melatih routing manual** agar tidak "buta" saat memakai framework.
- **Menangani method, URL, dan error** dengan benar.
- **Fondasi** sebelum menambah autentikasi (materi 29) dan validasi ketat (materi 31).

## Cara Pengimplementasian / Code

Kita tulis satu file router. Endpoint disederhanakan memakai segmen terakhir URL (`/buku`, `/detail`, `/hapus`).

```php
<?php
// File: 28-api-router.php
declare(strict_types=1);

error_reporting(E_ALL);
ini_set('display_errors', 1);

// Semua balasan berupa JSON
header('Content-Type: application/json; charset=utf-8');
header('Access-Control-Allow-Origin: *');
header('Access-Control-Allow-Methods: GET, POST, PUT, DELETE, OPTIONS');
header('Access-Control-Allow-Headers: Content-Type, Authorization');

// Jawab preflight CORS (OPTIONS) lalu berhenti
if ($_SERVER['REQUEST_METHOD'] === 'OPTIONS') {
    http_response_code(200);
    exit;
}

// Ambil method & endpoint dari URL
$method   = $_SERVER['REQUEST_METHOD'];
$uri      = parse_url($_SERVER['REQUEST_URI'], PHP_URL_PATH);
$uri      = rtrim($uri, '/');                 // buang trailing slash
$endpoint = end(explode('/', $uri));          // ambil segmen terakhir

// Data katalog dummy (simulasi tabel buku)
$katalog = [
    ['id' => 1, 'judul' => 'Clean Code',              'pengarang' => 'Robert C. Martin', 'tahun' => 2008, 'stok' => 5],
    ['id' => 2, 'judul' => 'Atomic Habits',           'pengarang' => 'James Clear',      'tahun' => 2018, 'stok' => 0],
    ['id' => 3, 'judul' => 'The Pragmatic Programmer','pengarang' => 'Andrew Hunt',      'tahun' => 1999, 'stok' => 3],
];

// Fungsi balasan seragam
function kirim(int $code, array $data = [], string $message = ''): void
{
    http_response_code($code);
    echo json_encode([
        'status'    => $code >= 200 && $code < 300 ? 'success' : 'error',
        'code'      => $code,
        'message'   => $message,
        'data'      => $data,
        'timestamp' => date('Y-m-d H:i:s'),
    ], JSON_UNESCAPED_UNICODE | JSON_PRETTY_PRINT);
    exit; // hentikan agar tidak ada output tambahan yang merusak JSON
}

// Routing berdasarkan method + endpoint
if ($method === 'GET' && $endpoint === 'buku') {
    // GET /buku -> semua buku
    kirim(200, $katalog, 'Daftar buku berhasil diambil');

} elseif ($method === 'GET' && $endpoint === 'detail') {
    // GET /detail?id=1 -> satu buku
    $id    = (int) ($_GET['id'] ?? 0);
    $hasil = null;
    foreach ($katalog as $b) {
        if ($b['id'] === $id) { $hasil = $b; break; }
    }
    if ($hasil === null) {
        kirim(404, [], "Buku dengan id {$id} tidak ditemukan");
    }
    kirim(200, $hasil, 'Detail buku berhasil diambil');

} elseif ($method === 'POST' && $endpoint === 'buku') {
    // POST /buku -> tambah buku (simulasi)
    $input = json_decode(file_get_contents('php://input'), true);
    if (json_last_error() !== JSON_ERROR_NONE) {
        kirim(400, [], 'Format JSON tidak valid');
    }
    if (empty($input['judul']) || empty($input['pengarang'])) {
        kirim(400, [], 'Field judul dan pengarang wajib diisi');
    }
    $bukuBaru = [
        'id'        => count($katalog) + 1,
        'judul'     => trim($input['judul']),
        'pengarang' => trim($input['pengarang']),
        'tahun'     => (int) ($input['tahun'] ?? date('Y')),
        'stok'      => (int) ($input['stok'] ?? 1),
    ];
    kirim(201, $bukuBaru, 'Buku berhasil ditambahkan (simulasi)');

} elseif ($method === 'DELETE' && $endpoint === 'hapus') {
    // DELETE /hapus?id=2 -> hapus (simulasi)
    $id = (int) ($_GET['id'] ?? 0);
    kirim(200, ['id' => $id], "Buku id {$id} berhasil dihapus (simulasi)");

} else {
    kirim(404, [], 'Endpoint tidak ditemukan. Coba GET /buku, GET /detail?id=1, POST /buku');
}
```

**Cara menjalankan/menguji:** dengan ekstensi API Client (Thunder Client/Postman) atau `curl`.

```

Content-Type: application/json
```

## Tracing Code (Step-by-Step)

Kita telusuri request **GET /buku**.

**Langkah 1 — menjalankan `header(...)`**

PHP mengirim header balasan: `Content-Type: application/json`, aturan CORS, dan daftar method yang diizinkan. Karena method request bukan `OPTIONS`, blok preflight dilewati.

**Langkah 2 — baris `$method = $_SERVER['REQUEST_METHOD']`**

PHP membaca method dari superglobal. Di sini `$method` berisi `"GET"`.

**Langkah 3 — baris `$uri = parse_url($_SERVER['REQUEST_URI'], PHP_URL_PATH)`**

`$_SERVER['REQUEST_URI']` berisi `/perpustakaan/28-api-router.php/buku`. `parse_url` mengambil bagian path saja (membuang query seperti `?id=1`), hasilnya string `/perpustakaan/28-api-router.php/buku`.

**Langkah 4 — baris `$uri = rtrim($uri, '/')` lalu `end(explode('/', $uri))`**

`explode` memecah path jadi array: `["", "perpustakaan", "28-api-router.php", "buku"]`. `end()` mengambil elemen terakhir → `$endpoint = "buku"`.

**Langkah 5 — menyiapkan `$katalog`**

PHP membuat array berisi 3 buku (simulasi isi tabel). Belum ada query database.

**Langkah 6 — memeriksa kondisi routing**

Pemeriksaan pertama: `$method === 'GET' && $endpoint === 'buku'` → `"GET" === "GET"` benar dan `"buku" === "buku"` benar. Kondisi **terpenuhi**.

**Langkah 7 — memanggil `kirim(200, $katalog, ...)`**

Fungsi `kirim` menetapkan `http_response_code(200)`, lalu membentuk array:

```json
{
  "status": "success",
  "code": 200,
  "message": "Daftar buku berhasil diambil",
  "data": [ ...3 buku... ],
  "timestamp": "2026-10-17 10:00:00"
}
```

Array itu diubah jadi teks JSON oleh `json_encode`, dicetak dengan `echo`, lalu `exit` menghentikan skrip.

**Tracing POST /buku** (singkat): method `POST`, endpoint `buku` → cabang POST dijalankan. `file_get_contents('php://input')` membaca body mentah (bukan `$_POST`, karena JSON). `json_decode` mengubah JSON jadi array. Jika judul/pengarang kosong → `kirim(400, ...)`. Jika valid → bentuk `$bukuBaru` dan `kirim(201, ...)`.

**Output akhir (GET /buku):**

```json
{
  "status": "success",
  "code": 200,
  "message": "Daftar buku berhasil diambil",
  "data": [
    { "id": 1, "judul": "Clean Code", "pengarang": "Robert C. Martin", "tahun": 2008, "stok": 5 },
    { "id": 2, "judul": "Atomic Habits", "pengarang": "James Clear", "tahun": 2018, "stok": 0 },
    { "id": 3, "judul": "The Pragmatic Programmer", "pengarang": "Andrew Hunt", "tahun": 1999, "stok": 3 }
  ],
  "timestamp": "2026-10-17 10:00:00"
}
```

## Analogi

Bayangkan **loket informasi (front office) perpustakaan**.

- **Client** = pengunjung yang bertanya lewat aplikasi/web.
- **REST API** = **loket pelayanan terpusat** tempat pengunjung menyampaikan permintaan dengan format baku.
- **HTTP Method** = **jenis permintaan**: "Tampilkan daftar buku" (GET), "Tambahkan buku baru" (POST), "Hapus buku ini" (DELETE).
- **URL/Endpoint** = **nomor meja tujuan** atau benda yang diminta.
- **Router** = **resepsionis loket**. Ia mencocokkan: "GET ke /buku?" → arahkan ke petugas "Daftar Buku". "POST ke /buku?" → arahkan ke petugas "Pendaftaran Buku".
- **Handler** = **petugas khusus** yang menjalankan prosedur sesuai permintaan.
- **JSON Response** = **laporan tertulis rapi** yang dikembalikan, mudah dibaca aplikasi.
- **Status Code** = **status jawaban**: "berhasil", "berhasil dibuat", "data kurang", "yang diminta tidak ada".
- **Stateless** = loket tidak mengingat pengunjung sebelumnya, kecuali pengunjung menunjukkan **kartu akses (token)**.
- **CORS Header** = aturan "boleh tidak aplikasi dari alamat lain meminta data ke loket ini".
- **php://input** = **amplop tertutup** berisi data JSON saat POST, berbeda dari formulir biasa.

## Kesalahan Umum yang Sering Terjadi

- **Memakai `$_POST` untuk body JSON** → `$_POST` hanya terisi untuk form biasa. Untuk JSON pakai `php://input`.
- **Lupa mengirim `Content-Type: application/json`** saat membalas → client salah menafsirkan data.
- **Tidak menangani `OPTIONS` (preflight)** → request AJAX dari browser bisa gagal karena CORS.
- **Routing tanpa memeriksa method** → GET bisa dipaksa berperilaku seperti POST.
- **Tidak memanggil `exit` setelah `echo`** → peringatan/notice tambahan merusak JSON.
- **Lupa `http_response_code()`** → status tetap 200 padahal terjadi error.
- **Validasi kurang** saat POST → data kosong ikut masuk.
- **Menampilkan pesan error detail di production** → bocorkan informasi sistem ke client.
- **Format balasan tidak seragam** → frontend sulit menangani.
- **Bingung query param vs path param** → `?id=1` (query) dan `/buku/1` (path) keduanya sah, tinggal konsisten.

## Soal Latihan & Jawaban

### Soal

Kembangkan router di atas dengan:

1. Endpoint `GET /anggota` mengembalikan daftar anggota dummy (minimal 2 data: `id`, `nama`, `email`).
2. Endpoint `GET /cari-buku` dengan query `q` untuk memfilter katalog (judul atau pengarang mengandung keyword, tanpa peduli huruf besar/kecil). Kirim `404` bila kosong.
3. Validasi `POST /buku`: `tahun` harus angka, `stok` tidak boleh negatif. Jika salah → `400`.
4. Pertahankan struktur balasan seragam.

### Jawaban

```php
<?php
// Tambahan setelah blok routing sebelumnya

// Data anggota dummy
$anggota = [
    ['id' => 1, 'nama' => 'Andi Pratama', 'email' => 'andi@perpustakaan.test'],
    ['id' => 2, 'nama' => 'Budi Santoso', 'email' => 'budi@perpustakaan.test'],
];

// GET /anggota
if ($method === 'GET' && $endpoint === 'anggota') {
    kirim(200, $anggota, 'Daftar anggota berhasil diambil');
}

// GET /cari-buku?q=code
if ($method === 'GET' && $endpoint === 'cari-buku') {
    $q = trim($_GET['q'] ?? '');
    if ($q === '') {
        kirim(400, [], 'Parameter q wajib diisi');
    }
    $hasil = [];
    foreach ($katalog as $b) {
        // str_contains + strtolower agar pencarian tidak peduli besar/kecil huruf
        if (str_contains(strtolower($b['judul']), strtolower($q))
            || str_contains(strtolower($b['pengarang']), strtolower($q))) {
            $hasil[] = $b;
        }
    }
    if (empty($hasil)) {
        kirim(404, [], "Tidak ada buku dengan kata '{$q}'");
    }
    kirim(200, $hasil, 'Hasil pencarian berhasil diambil');
}

// POST /buku dengan validasi tambahan (menggantikan blok POST sebelumnya)
if ($method === 'POST' && $endpoint === 'buku') {
    $input = json_decode(file_get_contents('php://input'), true);
    if (json_last_error() !== JSON_ERROR_NONE) {
        kirim(400, [], 'Format JSON tidak valid');
    }
    if (empty($input['judul']) || empty($input['pengarang'])) {
        kirim(400, [], 'Field judul dan pengarang wajib diisi');
    }
    if (isset($input['tahun']) && !ctype_digit((string) $input['tahun'])) {
        kirim(400, [], 'Field tahun harus berupa angka');
    }
    if (isset($input['stok']) && (int) $input['stok'] < 0) {
        kirim(400, [], 'Field stok tidak boleh negatif');
    }
    kirim(201, $input, 'Buku berhasil ditambahkan (simulasi)');
}
```
