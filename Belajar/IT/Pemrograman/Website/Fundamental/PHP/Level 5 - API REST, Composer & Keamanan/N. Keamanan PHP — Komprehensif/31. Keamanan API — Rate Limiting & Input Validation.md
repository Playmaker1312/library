# Keamanan API — Rate Limiting & Input Validation

## Penjelasan

Membangun API tidak cukup hanya "bisa jalan". Kita wajib menerapkan **keamanan dasar** untuk mencegah penyalahgunaan: spam request, brute force, input berbahaya, hingga eksploitasi data.

Dua aspek yang paling relevan untuk pemula:

1. **Input Validation** → Memastikan data yang masuk **valid, lengkap & sesuai format**. "Benarkah yang dikirim user itu yang kita harapkan?"
2. **Rate Limiting** → Membatasi **jumlah request per pengguna/IP** dalam rentang waktu. "Jangan biarkan satu IP bisa kirim 1000 request/detik".

Selain dua di atas, kita juga perlu menyadari:

- **Sanitasi** → Membersihkan data (trim, strip_tags) sebelum diproses/ditampilkan.
- **HTTPS** → Wajib di production (enkripsi data antar client-server).
- **Output Encoding** → `htmlspecialchars()` kalau menampilkan HTML, atau cukup kirim JSON aman.
- **CORS** → Atur origin yang diizinkan.
- **JWT/Auth** → Sudah dibahas materi 29 (proteksi endpoint).
- **Error Handling** → Jangan bocorkan stack trace/detail sistem ke client.
- **Idempotency** (opsional) → Berguna untuk POST sensitif (pembayaran) tapi kurang wajib pemula.

Konteks perpustakaan: lindungi endpoint `POST /login` dari **brute force** (rate limit), dan validasi data `POST /buku`/`POST /anggota` agar tidak masuk data kotor.

## Fungsi

- **Mencegah brute force** pada endpoint sensitif (login).
- **Mencegah spam/abuse** dari IP yang sama.
- **Menjaga integritas data** (hanya data valid tersimpan).
- **Mengurangi beban server** akibat request berlebihan.
- **Mencegah input berbahaya** sejak awal.
- **Meningkatkan kepercayaan** & keamanan aplikasi.
- **Menerapkan prinsip "never trust user input"**.

## Cara Pengimplementasian / Code

Kita buat implementasi **sederhana & edukatif**:

- **Input Validation** pakai `trim`, `filter_var`, `strlen`, cek wajib isi, format email, tipe angka.
- **Rate Limiting** berbasis **file** (`rate_limit.json`) + **IP address** + **time window** (60 detik, max 5 request untuk login).

> Catatan: Untuk production, rate limit sebaiknya pakai Redis/Memcached. File-based cukup untuk latihan lokal.

**File: `31-api-security-rate-limit.php`**

```php
<?php
// File: 31-api-security-rate-limit.php
declare(strict_types=1);

error_reporting(E_ALL);
ini_set('display_errors', 1);

header('Content-Type: application/json; charset=utf-8');
header('Access-Control-Allow-Origin: *');
header('Access-Control-Allow-Methods: GET, POST, OPTIONS');
header('Access-Control-Allow-Headers: Content-Type, Authorization');

if ($_SERVER['REQUEST_METHOD'] === 'OPTIONS') {
    http_response_code(200);
    exit;
}

// Path file untuk simpan rate limit
define('RATE_LIMIT_FILE', __DIR__ . '/rate_limit.json');

// Fungsi respon seragam
function sendResponse(int $code, array $data = [], string $message = ''): void
{
    http_response_code($code);
    echo json_encode([
        'status'    => $code >= 200 && $code < 300 ? 'success' : 'error',
        'code'      => $code,
        'message'   => $message,
        'data'      => $data,
        'timestamp' => date('Y-m-d H:i:s')
    ], JSON_UNESCAPED_UNICODE | JSON_PRETTY_PRINT);
    exit;
}

// Ambil IP client
function getClientIP(): string
{
    if (!empty($_SERVER['HTTP_CLIENT_IP'])) {
        return $_SERVER['HTTP_CLIENT_IP'];
    }
    if (!empty($_SERVER['HTTP_X_FORWARDED_FOR'])) {
        // Bisa multiple IP, ambil yang pertama
        $ips = explode(',', $_SERVER['HTTP_X_FORWARDED_FOR']);
        return trim($ips[0]);
    }
    return $_SERVER['REMOTE_ADDR'] ?? '127.0.0.1';
}

// Input Validation helpers
function validateRequired(string $value, string $field): ?string
{
    $value = trim($value);
    if ($value === '') {
        return "Field '{$field}' wajib diisi";
    }
    return null;
}

function validateEmail(string $email): ?string
{
    $email = trim($email);
    if ($email === '') {
        return "Field 'email' wajib diisi";
    }
    if (!filter_var($email, FILTER_VALIDATE_EMAIL)) {
        return "Format email tidak valid";
    }
    return null;
}

function validateMinLength(string $value, int $min, string $field): ?string
{
    if (mb_strlen(trim($value)) < $min) {
        return "Field '{$field}' minimal {$min} karakter";
    }
    return null;
}

function validateIntRange($value, int $min, int $max, string $field): ?string
{
    // Coba konversi
    if (!is_numeric($value)) {
        return "Field '{$field}' harus berupa angka";
    }
    $intVal = (int)$value;
    if ($intVal < $min || $intVal > $max) {
        return "Field '{$field}' harus antara {$min} - {$max}";
    }
    return null;
}

// Rate Limiting
function checkRateLimit(string $key, int $maxRequests = 5, int $windowSeconds = 60): ?string
{
    $now = time();
    $data = [];
    
    // Baca file existing
    if (file_exists(RATE_LIMIT_FILE)) {
        $content = file_get_contents(RATE_LIMIT_FILE);
        if ($content !== false && trim($content) !== '') {
            $decoded = json_decode($content, true);
            if (json_last_error() === JSON_ERROR_NONE && is_array($decoded)) {
                $data = $decoded;
            }
        }
    }
    
    // Inisialisasi untuk key ini
    if (!isset($data[$key])) {
        $data[$key] = [
            'count'     => 0,
            'firstTime' => $now,
            'lastTime'  => $now
        ];
    }
    
    $entry = &$data[$key];
    
    // Reset window jika sudah lewat
    if ($now - $entry['firstTime'] > $windowSeconds) {
        // Reset
        $entry['count']     = 0;
        $entry['firstTime'] = $now;
        $entry['lastTime']  = $now;
    }
    
    // Cek batas
    if ($entry['count'] >= $maxRequests) {
        $wait = ($entry['firstTime'] + $windowSeconds) - $now;
        return "Terlalu banyak request. Coba lagi dalam {$wait} detik.";
    }
    
    // Increment
    $entry['count']++;
    $entry['lastTime'] = $now;
    
    // Simpan kembali
    file_put_contents(RATE_LIMIT_FILE, json_encode($data, JSON_PRETTY_PRINT), LOCK_EX);
    unset($entry);
    
    return null;
}

// Routing
$method   = $_SERVER['REQUEST_METHOD'];
$uri      = parse_url($_SERVER['REQUEST_URI'], PHP_URL_PATH);
$uri      = rtrim($uri, '/');
$segments = explode('/', $uri);
$endpoint = end($segments);

// 1. POST /login dengan RATE LIMIT + VALIDATION
if ($method === 'POST' && $endpoint === 'login') {
    $ip = getClientIP();
    $rateKey = 'login:' . $ip;
    
    // Cek rate limit: max 5 request per 60 detik per IP
    $limitErr = checkRateLimit($rateKey, 5, 60);
    if ($limitErr !== null) {
        sendResponse(429, ['retry_after' => 60], $limitErr); // 429 Too Many Requests
    }
    
    // Baca input
    $raw   = file_get_contents('php://input');
    $input = json_decode($raw, true);
    
    if (json_last_error() !== JSON_ERROR_NONE) {
        sendResponse(400, [], 'Format JSON tidak valid');
    }
    
    // Validasi input
    $errors = [];
    
    // Email
    $errEmail = validateEmail($input['email'] ?? '');
    if ($errEmail !== null) $errors[] = $errEmail;
    
    // Password
    $errPass1 = validateRequired($input['password'] ?? '', 'password');
    if ($errPass1 !== null) $errors[] = $errPass1;
    $errPass2 = validateMinLength($input['password'] ?? '', 6, 'password');
    if ($errPass2 !== null && $errPass1 === null) $errors[] = $errPass2;
    
    // Jika ada error validasi
    if (!empty($errors)) {
        sendResponse(422, ['errors' => $errors], 'Validasi gagal'); // 422 Unprocessable Entity
    }
    
    // Simulasi cek kredensial
    $email = strtolower(trim($input['email']));
    $pass  = trim($input['password']);
    
    if ($email === 'andi@perpustakaan.test' && $pass === 'rahasia123') {
        sendResponse(200, [
            'login' => true,
            'user'  => ['nama' => 'Andi Pratama', 'email' => $email, 'role' => 'anggota']
        ], 'Login berhasil');
    }
    
    sendResponse(401, [], 'Email atau password salah');
}

// 2. POST /buku dengan VALIDATION ketat (TANPA rate limit berat untuk demo)
if ($method === 'POST' && $endpoint === 'buku') {
    $raw   = file_get_contents('php://input');
    $input = json_decode($raw, true);
    
    if (json_last_error() !== JSON_ERROR_NONE) {
        sendResponse(400, [], 'Format JSON tidak valid');
    }
    
    $errors = [];
    
    // judul wajib
    $e1 = validateRequired($input['judul'] ?? '', 'judul');
    if ($e1 !== null) $errors[] = $e1;
    $e2 = validateMinLength($input['judul'] ?? '', 3, 'judul');
    if ($e2 !== null && $e1 === null) $errors[] = $e2;
    
    // pengarang wajib
    $e3 = validateRequired($input['pengarang'] ?? '', 'pengarang');
    if ($e3 !== null) $errors[] = $e3;
    
    // tahun: 1900 - 2100
    if (isset($input['tahun'])) {
        $e4 = validateIntRange($input['tahun'], 1900, 2100, 'tahun');
        if ($e4 !== null) $errors[] = $e4;
    } else {
        $errors[] = "Field 'tahun' wajib diisi";
    }
    
    // stok: 0 - 9999
    if (isset($input['stok'])) {
        $e5 = validateIntRange($input['stok'], 0, 9999, 'stok');
        if ($e5 !== null) $errors[] = $e5;
    } else {
        $errors[] = "Field 'stok' wajib diisi";
    }
    
    if (!empty($errors)) {
        sendResponse(422, ['errors' => $errors], 'Validasi gagal');
    }
    
    // Data valid -> simpan (simulasi)
    $book = [
        'judul'     => htmlspecialchars(trim($input['judul'])),
        'pengarang' => htmlspecialchars(trim($input['pengarang'])),
        'tahun'     => (int)$input['tahun'],
        'stok'      => (int)$input['stok'],
    ];
    
    sendResponse(201, $book, 'Buku berhasil ditambahkan (validasi lolos)');
}

// 3. GET /public
if ($method === 'GET' && $endpoint === 'public') {
    sendResponse(200, ['info' => 'Endpoint publik aman'], 'OK');
}

sendResponse(404, [], 'Endpoint tidak ditemukan');
```

**File pendukung: `rate_limit.json` akan terbuat otomatis** saat pertama kali ada request login (mode write).

**Cara menjalankan/menguji:**

1. Simpan file di `htdocs/perpustakaan/`
2. Pastikan folder bisa write (file `rate_limit.json` dibuat otomatis)

## Tracing Code (Step-by-Step)

Kita telusuri 2 skenario: **Input Validation (POST /buku)** dan **Rate Limiting (POST /login)**.

### Tracing A: Input Validation POST /buku (data invalid)

**Langkah 1 — Baca & decode JSON**

`$raw = file_get_contents('php://input')`, `json_decode($raw,true)`. Cek error → jika ada kirim 400.

**Langkah 2 — Kumpulkan errors array kosong**

`$errors = []`

**Langkah 3 — Validasi judul**

- `validateRequired('A', 'judul')` → trim 'A' != ''? 'A' bukan kosong → return `null`
- `validateMinLength('A', 3, 'judul')` → mb_strlen('A') = 1 < 3 → return `"Field 'judul' minimal 3 karakter"`

Karena `$e1 === null` tapi `$e2 !== null`, push `$e2` ke errors.

**Langkah 4 — Validasi pengarang**

`validateRequired('', 'pengarang')` → trim '' === '' → return `"Field 'pengarang' wajib diisi"`. Push ke errors.

**Langkah 5 — Validasi tahun**

`isset($input['tahun'])` true, tapi value `"abcd"`. `validateIntRange("abcd", 1900,2100,'tahun')`:
- `!is_numeric("abcd")` → true → return `"Field 'tahun' harus berupa angka"`

Push error.

**Langkah 6 — Validasi stok**

Value `-5`. `is_numeric('-5')` true, `$intVal = -5`. Cek `-5 < 0` → true → return `"Field 'stok' harus antara 0 - 9999"`

Push error.

**Langkah 7 — Cek errors**

`!empty($errors)` → true. Kirim `sendResponse(422, ['errors'=>$errors], 'Validasi gagal')`

Client menerima 422 dengan daftar error jelas.

**Jika data valid (skenario sukses):**

Semua validator return null → tidak ada errors. Lalu buat `$book` dengan `htmlspecialchars(trim(...))` untuk output aman (praktik sanitasi ringan saat kembalikan). Kirim **201 Created**.

### Tracing B: Rate Limiting POST /login

**Langkah 1 — Ambil IP & key**

`$ip = getClientIP()` → misal `127.0.0.1`. `$rateKey = 'login:127.0.0.1'`

**Langkah 2 — Baca rate_limit.json**

`checkRateLimit($rateKey, 5, 60)`:
- Cek file exists? Mungkin belum ada (pertama kali) → `$data = []`
- Belum ada key → inisialisasi `['count'=>0,'firstTime'=>$now,'lastTime'=>$now]`

**Langkah 3 — Cek window**

`$now - $entry['firstTime'] > 60?` Mungkin false (baru). Lalu cek `$entry['count'] >= 5?` 0>=5 false.

**Langkah 4 — Increment & simpan**

`$entry['count']++` → jadi 1. `file_put_contents` dengan `LOCK_EX` (mencegah race condition sederhana saat concurrent request).

Return `null` → boleh lanjut ke validasi login.

**Kejadian: request ke-6 dalam window 60 detik**

- Setelah 5x sebelumnya, `count` sudah 5, `firstTime` masih waktu request pertama.
- Request ke-6: `$now - firstTime < 60`, tapi `$entry['count'] >= 5` → true.
- Hitung `$wait = (firstTime + 60) - $now` → detik tersisa.
- Return `"Terlalu banyak request. Coba lagi dalam {$wait} detik."`
- Kirim **429 Too Many Requests** dengan `retry_after: 60`

**Setelah window lewat (>60 detik)**

`$now - $entry['firstTime'] > 60` → true. Reset `count=0`, `firstTime=$now`, `lastTime=$now`. Request kembali diizinkan.

## Analogi

Bayangkan **gerbang masuk perpustakaan digital**.

- **Input Validation** = **Petugas pemeriksa identitas di loket**. Ia cek: "Apakah formulir terisi lengkap? Email format benar? Password cukup panjang? Tahun antara 1900-2100?". Kalau ada yang salah, ia **kembalikan formulir berisi daftar koreksi** (422).
- **Rate Limiting** = **Sistem antrian & pembatasan**. "Satu pengunjung/IP hanya boleh coba login **maks 5 kali dalam 60 menit/jam latihan**". Jika nekat coba ke-6, gerbang **minta tunggu** (429 Too Many Requests) — mencegah orang mencoba ribuan kombinasi password.
- **getClientIP()** = **Mengenali pengunjung dari alamat** (nomor antrian berdasarkan IP).
- **rate_limit.json** = **Buku pencatat kunjungan login** per IP. Catat "kapan pertama, sudah berapa kali, kapan terakhir".
- **LOCK_EX** = **Kunci buku pencatat** saat ada yang update (mengurangi bentrokan).
- **filter_var(FILTER_VALIDATE_EMAIL)** = **Alat cek format email** standar.
- **htmlspecialchars()** saat return data (simulasi) = **Menyanitasi** agar tidak ada karakter HTML berbahaya.
- **422 Unprocessable Entity** = "Server paham format JSON, tapi **data tidak valid** sesuai aturan bisnis".
- **429 Too Many Requests** = "Kamu **terlalu sering** meminta, pelan-pelan".
- **401 Unauthorized** = "Kredensial salah".
- **201 Created** = "Data valid, berhasil dicatat".

Kaitan kuat: **Validasi mencegah data kotor. Rate limit mencegah penyalahgunaan. Keduanya melindungi "gerbang" & "sistem".**

## Dipakai untuk Apa

- **Melindungi endpoint login/register** dari brute force.
- **Validasi form API** (tambah buku/anggota).
- **Mencegah spam API** dari bot/IP jahat.
- **Filter request tidak wajar** sejak dini.
- **Meningkatkan UX** dengan pesan error validasi terstruktur (`errors[]`).
- **Menghemat resource** (CPU/DB) dari request berlebihan.
- **Prasyarat sebelum go-live** (production checklist).
- **Diterapkan hampir semua endpoint publik sensitif**.

## Kesalahan Umum yang Sering Terjadi

- **Rate limit hanya per endpoint, lupa per-IP** → kurang efektif. Kita pakai `login:<IP>`.
- **File-based rate limit di shared hosting multi-process** → bisa kurang akurat. Better Redis.
- **Tidak reset window** → count menumpuk selamanya.
- **Cek IP dari `HTTP_X_FORWARDED_FOR` tanpa trust proxy** → bisa dipalsu (spoof). Di production harus validasi trusted proxy.
- **Tampilkan wait time presisi** → cukup aman untuk edukasi.
- **Validasi terlalu longgar** → lolos data tidak berguna.
- **Validasi terlalu ketat** → UX buruk.
- **Kembalikan 200 untuk "salah password"** → tetap 401 (benar). Bedain "validasi gagal" (422) vs "auth gagal" (401).
- **Menyimpan rate_limit.json di web root** → idealnya diluar public (mis. `storage/`) biar tidak bisa diakses langsung.
- **Lupa `LOCK_EX`** → potensi race condition saat request bersamaan.
- **Gunakan `empty()` vs `isset()`** hati-hati saat value "0" diperbolehkan (stok 0 valid). Di contoh kita pakai `isset` lalu validasi range.
- **htmlspecialchars() hanya saat output** → kita lakukan saat return simulasi data. Untuk simpan DB, **jangan** over-sanitize sebelum prepared statement; fokus **validate**.
