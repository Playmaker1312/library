# Prepared Statements — Query yang Aman dari SQL Injection

## Penjelasan

**Prepared Statement** adalah cara menjalankan query SQL dengan **memisahkan perintah query dari datanya**. Query dikirim dulu sebagai *template* yang masih berlubang, lalu data dimasukkan lewat lubang itu secara terpisah.

Masalah yang dipecahkan bernama **SQL Injection**. Ini terjadi saat input user ikut disambung ke dalam query dengan cara digabung string. Contoh berbahaya:

```php
// BAHAYA: input user disambung langsung ke query
$id = $_GET['id']; // misal user isi: 1 OR 1=1
$sql = "SELECT * FROM buku WHERE id = $id";
// Hasilnya: SELECT * FROM buku WHERE id = 1 OR 1=1  -> semua data bocor
```

Kalau `$id` berisi `1; DROP TABLE buku; --`, query bisa merusak data. Prepared statement memutus celah ini karena **isi input tidak pernah dianggap sebagai perintah SQL**, hanya dianggap sebagai nilai/data.

Cara kerja singkat:

- **`prepare()`** → kirim template query ke server database. Template memakai penanda: `:nama` (named) atau `?` (positional).
- **`execute()` / `bindValue()`** → kirim data terpisah. Database mengisi penanda dengan data itu sebagai **nilai**, bukan perintah.
- Hasilnya: query tetap aman walau input berisi karakter aneh seperti `'`, `;`, atau `--`.

Aturan penting:

- **Data (nilai) selalu bisa di-bind.** Contoh: `WHERE id = :id`.
- **Identifier (nama tabel/kolom) TIDAK bisa di-bind.** `FROM :tabel` tidak berfungsi. Kalau perlu dinamis, pakai whitelist nama yang diizinkan.
- **Named parameter** (`:id`, `:judul`) lebih enak dibaca untuk query panjang.
- **Positional parameter** (`?`) lebih ringkas, tapi urutan harus pas.

Konteks perpustakaan: semua operasi **CRUD katalog buku** (tambah, cari, ubah, hapus) memakai prepared statement.

## Fungsi

- **Mencegah SQL Injection** — menyelamatkan data & aplikasi dari serangan.
- **Performa lebih baik** — database bisa memakai ulang rencana eksekusi query yang sama.
- **Kode lebih rapi & aman dibaca** — data dipisah dari struktur query.
- **Penanganan tipe otomatis** — PDO menangani tanda kutip pada string tanpa kita pikirkan.
- **Standar industri** — wajib dipakai setiap kali ada input dari luar (form, URL, API).
- **Melengkapi PDO (materi 26)** — PDO menyediakan koneksi, prepared statement mengamankan query.

## Cara Pengimplementasian / Code

Kita lanjutkan koneksi PDO dari materi 26, lalu tambahkan CRUD dengan prepared statement. Asumsi tabel `buku` berisi kolom `id, judul, pengarang, tahun, stok`.

```php
<?php
// File: 27-prepared-statements.php
declare(strict_types=1);

error_reporting(E_ALL);
ini_set('display_errors', 1);

// 1) Koneksi PDO (dari materi 26)
$dsn = 'mysql:host=localhost;dbname=perpustakaan;charset=utf8mb4';
$pdo = new PDO($dsn, 'root', '', [
    PDO::ATTR_ERRMODE            => PDO::ERRMODE_EXCEPTION, // error jadi exception
    PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,       // hasil berupa array asosiatif
    PDO::ATTR_EMULATE_PREPARES   => false,                  // pakai prepared asli MySQL
]);

// 2) SELECT dengan named parameter — ambil satu buku berdasarkan id
function ambilBuku(PDO $pdo, int $id): ?array
{
    $stmt = $pdo->prepare('SELECT * FROM buku WHERE id = :id LIMIT 1');
    $stmt->execute([':id' => $id]);          // data dikirim terpisah dari query
    $buku = $stmt->fetch();
    return $buku === false ? null : $buku;   // false = tidak ketemu
}

// 3) SELECT dengan positional parameter — pencarian judul (LIKE)
function cariBuku(PDO $pdo, string $keyword): array
{
    $stmt = $pdo->prepare('SELECT * FROM buku WHERE judul LIKE :kw ORDER BY judul');
    // Wildcard % ikut di dalam nilai yang di-bind, bukan di query
    $stmt->execute([':kw' => '%' . $keyword . '%']);
    return $stmt->fetchAll();
}

// 4) INSERT dengan named parameter — tambah buku baru
function tambahBuku(PDO $pdo, string $judul, string $pengarang, int $tahun, int $stok): int
{
    $sql  = 'INSERT INTO buku (judul, pengarang, tahun, stok)
             VALUES (:judul, :pengarang, :tahun, :stok)';
    $stmt = $pdo->prepare($sql);
    $stmt->execute([
        ':judul'     => $judul,
        ':pengarang' => $pengarang,
        ':tahun'     => $tahun,
        ':stok'      => $stok,
    ]);
    return (int) $pdo->lastInsertId(); // kembalikan id buku baru
}

// 5) UPDATE — ubah stok buku
function ubahStok(PDO $pdo, int $id, int $stokBaru): bool
{
    $stmt = $pdo->prepare('UPDATE buku SET stok = :stok WHERE id = :id');
    $stmt->execute([':stok' => $stokBaru, ':id' => $id]);
    return $stmt->rowCount() > 0;        // true jika ada baris yang berubah
}

// 6) DELETE — hapus buku
function hapusBuku(PDO $pdo, int $id): bool
{
    $stmt = $pdo->prepare('DELETE FROM buku WHERE id = :id');
    $stmt->execute([':id' => $id]);
    return $stmt->rowCount() > 0;
}

// 7) Demonstrasi
$idBaru = tambahBuku($pdo, 'Clean Code', 'Robert C. Martin', 2008, 5);
echo "Buku baru id: {$idBaru}" . PHP_EOL;

$buku = ambilBuku($pdo, $idBaru);
echo $buku ? "Judul: {$buku['judul']}" : 'Buku tidak ditemukan';
echo PHP_EOL;

$hasil = cariBuku($pdo, 'clean');
echo 'Ditemukan ' . count($hasil) . ' buku dengan kata "clean".' . PHP_EOL;

ubahStok($pdo, $idBaru, 3);
hapusBuku($pdo, $idBaru);
```

**Cara menjalankan/menguji:**

1. Pastikan MySQL/XAMPP aktif dan database `perpustakaan` berisi tabel `buku`.
2. Simpan `27-prepared-statements.php` di `htdocs/perpustakaan/`.
3. Jalankan lewat browser `http://localhost/perpustakaan/27-prepared-statements.php` atau terminal `php 27-prepared-statements.php`.
4. Amati buku tersimpan, lalu terhapus kembali tanpa error.

## Tracing Code (Step-by-Step)

Kita telusuri pemanggilan `ambilBuku($pdo, 1)` dan sebuah percobaan injection.

**Langkah 1 — baris `new PDO(...)`**

PHP membuka koneksi ke MySQL. Opsi `ERRMODE_EXCEPTION` membuat error query dilempar sebagai pengecualian (bukan didiamkan). `EMULATE_PREPARES => false` meminta MySQL menyiapkan query langsung di sisi server.

**Langkah 2 — baris `$stmt = $pdo->prepare('SELECT * FROM buku WHERE id = :id LIMIT 1')`**

PHP mengirim **template** ke MySQL: `SELECT * FROM buku WHERE id = ? LIMIT 1`. MySQL menyiapkan tempat kosong (lubang) untuk `:id`. Template ini belum berisi nilai apa pun.

**Langkah 3 — baris `$stmt->execute([':id' => 1])`**

PHP mengirim nilai `1` secara terpisah. MySQL mengisinya ke lubang tadi sebagai **data integer**, bukan potongan perintah.

**Langkah 4 — baris `$buku = $stmt->fetch()`**

MySQL mencari baris dengan `id = 1`. Misal ketemu:

| Kolom | Nilai |
|---|---|
| id | 1 |
| judul | Clean Code |
| pengarang | Robert C. Martin |
| tahun | 2008 |
| stok | 5 |

`fetch()` mengembalikan array asosiatif itu. Jika tidak ada baris, hasilnya `false`, dan fungsi mengembalikan `null`.

**Langkah 5 — percobaan injeksi**

Misalkan input user dipaksa menjadi `1 OR 1=1` lalu dimasukkan lewat parameter (bukan disambung ke string):

```php
$stmt->execute([':id' => '1 OR 1=1']);
```

MySQL menganggap seluruh teks `1 OR 1=1` sebagai **satu nilai** untuk `id`. Karena `id` bertipe angka dan nilainya bukan angka valid, hasilnya tidak cocok dengan baris mana pun (atau error tipe). Bagian `OR 1=1` **tidak pernah dibaca sebagai perintah**. Inilah bedanya dengan menyambung string, yang membuat `OR 1=1` benar-benar dieksekusi.

**Langkah 6 — pencarian `cariBuku($pdo, 'clean')`**

Query `WHERE judul LIKE :kw` dengan nilai `%clean%`. MySQL mencari semua judul yang **mengandung** `clean`. Wildcard `%` ikut sebagai bagian dari nilai yang di-bind, jadi tetap aman.

**Output akhir (contoh):**

```text
Buku baru id: 1
Judul: Clean Code
Ditemukan 1 buku dengan kata "clean".
```

## Analogi

Bayangkan **loket pemesanan buku di perpustakaan** yang memakai **formulir pesanan resmi**.

- **Query SQL** = **formulir pesanan** yang sudah dicetak rapi oleh perpustakaan.
- **Penanda `:id`, `:judul`** = **kolom kosong** di formulir yang harus diisi, misalnya "Judul buku: ______".
- **Data user** = **tulisan pengunjung** yang hanya masuk ke kolom kosong itu.
- **Prepared statement** = aturan bahwa **tulisan pengunjung hanya boleh mengisi kolom kosong**, tidak boleh mengubah kerangka formulir. Mau pengunjung menulis "Buku; hapus semua rak" sekalipun, petugas loket tetap menganggapnya sebagai **judul buku**, bukan perintah kepada petugas.
- **Menyambung string** = membiarkan pengunjung menulis **di bagian mana pun** formulir, termasuk menambah baris perintah palsu seperti "Tolong kosongkan rak A". Petugas yang polos bisa menurutinya.
- **`prepare()`** = mencetak formulir dengan kolom kosong.
- **`execute()`** = menyerahkan formulir yang kolomnya sudah diisi pengunjung.
- **Identifier yang tidak bisa di-bind** = nama bagian formulir ("Judul") harus sudah ditentukan petugas, tidak boleh ditentukan pengunjung.
- **`EMULATE_PREPARES => false`** = formulir disiapkan & diperiksa langsung oleh **petugas inti (server database)**, bukan disalin ulang oleh resepsionis depan.

Intinya: **data pengunjung dan kerangka formulir tidak pernah tercampur**, sehingga tidak ada celah menyusupkan perintah palsu.

## Dipakai untuk Apa

- **Semua operasi CRUD** ke database: tambah, baca, ubah, hapus.
- **Query login** (`WHERE email = :email`) agar tidak bisa di-bypass.
- **Pencarian/filter** dengan `LIKE` yang aman.
- **Endpoint API** yang menerima input dari client.
- **Import data** dalam jumlah banyak memakai satu prepared statement berulang.
- **Query dengan banyak parameter** agar rapi dan tidak salah urutan.
- **Melindungi data sensitif** perpustakaan (anggota, peminjaman) dari kebocoran.
- **Fondasi repository pattern** (materi 34) yang membungkus akses data.

## Kesalahan Umum yang Sering Terjadi

- **Menyambung input ke string query** (`"WHERE id = $id"`) → celah SQL Injection. Selalu pakai penanda dan `execute()`.
- **Mencoba bind nama tabel/kolom** (`FROM :tabel`) → gagal. Identifier tidak bisa di-bind; pakai whitelist nama.
- **Lupa `execute()` setelah `prepare()`** → query tidak pernah dijalankan.
- **Menaruh wildcard `%` di query** (`LIKE '%:kw%'`) → salah. Taruh wildcard di nilai: `[':kw' => "%$kw%"]`.
- **Tidak mengaktifkan `ERRMODE_EXCEPTION`** → error query gagal terdeteksi. Set di opsi PDO.
- **Mengandalkan `bindParam` tanpa menyebut tipe** saat perlu → kadang salah tipe. Gunakan `bindValue` dengan tipe bila perlu.
- **Menyamakan jumlah penanda dengan nilai** → `execute` melempar error bila tidak cocok. Hitung ulang.
- **Menganggap prepared statement tidak perlu validasi** → tetap validasi input di sisi aplikasi (materi 19) untuk pesan error yang ramah.
- **Memakai `query()` untuk input user** → `query()` tidak memisahkan data. Hanya untuk query tanpa input.

## Soal Latihan & Jawaban

### Soal

Buat dua fungsi dengan prepared statement pada tabel `anggota` (kolom `id, nama, email`):

1. `tambahAnggota(PDO $pdo, string $nama, string $email): int` — menyimpan anggota baru dan mengembalikan id-nya.
2. `cariAnggota(PDO $pdo, string $keyword): array` — mencari anggota berdasarkan nama yang mengandung keyword (case-insensitive tidak wajib).
3. Jelaskan singkat: kenapa nama tabel **tidak boleh** di-bind sebagai parameter?

### Jawaban

```php
<?php
declare(strict_types=1);

// 1) Tambah anggota baru dengan prepared statement
function tambahAnggota(PDO $pdo, string $nama, string $email): int
{
    $sql  = 'INSERT INTO anggota (nama, email) VALUES (:nama, :email)';
    $stmt = $pdo->prepare($sql);
    $stmt->execute([
        ':nama'  => $nama,
        ':email' => $email,
    ]);
    return (int) $pdo->lastInsertId(); // id anggota baru
}

// 2) Cari anggota berdasarkan nama (LIKE, wildcard di dalam nilai)
function cariAnggota(PDO $pdo, string $keyword): array
{
    $stmt = $pdo->prepare('SELECT * FROM anggota WHERE nama LIKE :kw ORDER BY nama');
    $stmt->execute([':kw' => '%' . $keyword . '%']);
    return $stmt->fetchAll();
}

// 3) Contoh pemakaian
$id = tambahAnggota($pdo, 'Andi Pratama', 'andi@perpustakaan.test');
echo "Anggota baru id: {$id}" . PHP_EOL;

$hasil = cariAnggota($pdo, 'Andi');
foreach ($hasil as $a) {
    echo "- {$a['nama']} ({$a['email']})" . PHP_EOL;
}
```

**Penjelasan singkat:** nama tabel/kolom adalah bagian dari **struktur perintah**, bukan data. Prepared statement hanya mengizinkan penanda (`:nama`, `?`) pada posisi **nilai**. Kalau butuh nama tabel dinamis, gunakan daftar putih, misalnya:

```php
$tabelDiizinkan = ['buku', 'anggota', 'peminjaman'];
$tabel = in_array($_GET['tabel'] ?? '', $tabelDiizinkan, true) ? $_GET['tabel'] : 'buku';
$stmt = $pdo->query("SELECT * FROM {$tabel} LIMIT 10"); // nama sudah divalidasi whitelist
```
