# 27. Specificity — Cara Menghitung Prioritas Selector

## Penjelasan

Specificity adalah sistem **skor** untuk selector CSS. Semakin spesifik selector, semakin tinggi prioritasnya.

```
Inline style:    1,0,0,0   (paling tinggi)
ID selector:     0,1,0,0
Class/Pseudo-class/Attribute: 0,0,1,0
Type/Pseudo-element: 0,0,0,1
Universal (*):   0,0,0,0   (paling rendah)
```

Contoh perhitungan:
```css
p                    /* 0,0,0,1 */
.card p              /* 0,0,1,1 */
#hero p              /* 0,1,0,1 */
.card .title         /* 0,0,2,0 */
nav ul li a:hover    /* 0,0,1,4 */
```

## Fungsi

- Prediksi selector mana yang menang dalam cascade
- Debugging CSS: lihat di DevTools properti mana yang dicoret (kalah specificity)
- Menulis CSS yang efisien: tidak perlu specificity tinggi jika tidak perlu

## Cara Pengimplementasian

```css
/* Specificity rendah — mudah di-override */
p { color: red; }                 /* 0,0,0,1 */
.text { color: blue; }            /* 0,0,1,0 — menang dari p */

/* Specificity sedang */
.card-text { color: green; }      /* 0,0,1,0 */
.card .text { color: yellow; }    /* 0,0,2,0 — menang */

/* Specificity tinggi */
#main .card .text { color: pink; } /* 0,1,2,0 */

/* Cara cek di DevTools: */
/* Buka Elements → Styles panel */
/* Properti yang dicoret = kalah specificity atau order */
```

## Analogi

Specificity seperti **rantai komando di rumah**:
- **Type selector** (0,0,0,1) = perintah "Semua anak" — umum, banyak yang kena
- **Class selector** (0,0,1,0) = perintah "Semua anak yang pakai seragam biru" — lebih spesifik
- **ID selector** (0,1,0,0) = perintah "Anak nomor 3, Andi" — sangat spesifik
- **Inline style** (1,0,0,0) = perintah langsung ke Andi secara pribadi — paling kuat

## Dipakai Untuk Apa

- Debugging: mengapa style tidak ter-apply?
- Menulis selector dengan specificity yang tepat — tidak terlalu rendah (mudah di-override), tidak terlalu tinggi (sulit di-override)

## Kesalahan Umum

- **Selector terlalu panjang**: `body > div > main > section > article > p` (0,0,0,6) — rapuh, specificity tidak lebih tinggi dari satu class
- **Specificity wars**: `.a.b.c.d.e { color: red; }` — kejar-kejaran specificity tidak produktif
- **ID untuk styling**: `#header` (0,1,0,0) — sulit di-override tanpa ID lain atau !important
- **Tidak memeriksa DevTools**: properti yang dicoret = kalah specificity — solusi: naikkan specificity atau turunkan selector pesaing

## Hubungan dengan Materi Sebelumnya

Poin 26: cascade menentukan aturan umum. **Specificity** adalah komponen terpenting cascade — alasan paling umum kenapa CSS "tidak jalan". Dengan memahami specificity, kita bisa menulis selector dengan percaya diri, tahu persis aturan mana yang akan menang.

## Soal Latihan

### Soal 1
Hitung specificity dari selector `nav .nav-link a:hover`.

**Jawaban:**
- nav = 0,0,0,1 (type)
- .nav-link = 0,0,1,0 (class)
- a = 0,0,0,1 (type)
- :hover = 0,0,1,0 (pseudo-class)
Total: **0,0,2,2**

### Soal 2
Selector mana yang menang: `p { color: red; }` atau `.text { color: blue; }`?

**Jawaban:**
`.text { color: blue; }` (0,0,1,0) menang dari `p { color: red; }` (0,0,0,1) — class lebih spesifik dari type.

### Soal 3
Mengapa ID selector tidak disarankan untuk styling?

**Jawaban:**
ID memiliki specificity tinggi (0,1,0,0) — sulit di-override tanpa selector yang lebih spesifik atau !important. Ini membuat CSS kaku dan sulit dimaintain. Gunakan class untuk styling.
