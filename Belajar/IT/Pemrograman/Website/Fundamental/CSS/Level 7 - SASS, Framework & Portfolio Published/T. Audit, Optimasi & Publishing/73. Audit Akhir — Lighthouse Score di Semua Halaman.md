# 73. Audit Akhir — Lighthouse Score di Semua Halaman

## Penjelasan

Lighthouse adalah tool audit otomatis di Chrome DevTools yang menilai 4 kategori:

| Kategori | Target Score | Fokus |
|----------|-------------|-------|
| **Performance** | ≥ 90 | Kecepatan loading, CSS/JS size |
| **Accessibility** | ≥ 95 | Kontras, focus, aria labels |
| **Best Practices** | ≥ 90 | HTTP, image size, console error |
| **SEO** | ≥ 95 | Meta tags, semantic HTML, alt text |

## Fungsi

- Standar kualitas website — objective, bukan subjective
- Deteksi masalah CSS yang tidak terlihat: render-blocking, unused CSS, kontras rendah
- Dokumentasi profesionalisme — lampirkan score di README

## Cara Pengimplementasian

**1. Jalankan Lighthouse:**
```
Chrome DevTools → Lighthouse tab → Generate report
Atau: npx lighthouse https://your-site.com --view
```

**2. Target berdasarkan kategori CSS:**

| Metrik | CSS Relevance |
|--------|---------------|
| **First Contentful Paint** | Font loading, critical CSS |
| **Speed Index** | Render-blocking CSS |
| **Cumulative Layout Shift** | Ukuran gambar, font swap |
| **Total Blocking Time** | CSS file size |

**3. Checklist audit CSS:**
```
PERFORMANCE:
[ ] CSS di-minify untuk production
[ ] Tidak ada render-blocking CSS (inline critical CSS)
[ ] Unused CSS < 10% (Coverage tab)
[ ] Font display: swap (FOUT > FOIT)
[ ] CSS file size < 50KB

ACCESSIBILITY:
[ ] Semua elemen interaktif punya :focus-visible
[ ] Kontras warna ≥ 4.5:1 (WCAG AA)
[ ] Warna bukan satu-satunya indikator
[ ] prefers-reduced-motion dihormati
[ ] Skip link tersedia

BEST PRACTICES:
[ ] Tidak ada !important yang tidak perlu
[ ] Tidak ada properti dengan prefix vendor yang tidak perlu
[ ] Gambar punya aspect-ratio untuk mencegah CLS

SEO:
[ ] Heading terstruktur h1 → h6
[ ] Meta viewport ada
[ ] Semantic HTML digunakan
```

**4. Dokumentasi:**
```markdown
## Performance
- Lighthouse Performance: 95
- Lighthouse Accessibility: 98
- File CSS: 32KB (minified + gzipped)
- Unused CSS: 4%
```

## Analogi

Seperti **sertifikat kelayakan huni rumah** — sebelum rumah bisa dihuni (deploy), harus diperiksa oleh inspektur (Lighthouse). Inspektur mengecek:
- Listrik aman (Performance)
- Tangga tidak licin (Accessibility)
- Atap tidak bocor (Best Practices)
- Alamat jelas (SEO)

Nilai ≥ 90 = rumah layak huni. Nilai < 50 = perlu renovasi besar.

## Dipakai Untuk Apa

- Final check sebelum deploy
- Dokumentasi kualitas
- Portofolio — tunjukkan bahwa kamu peduli kualitas

## Kesalahan Umum

- **Hanya cek satu halaman**: semua halaman perlu di-audit
- **Mengabaikan accessibility**: fokus hanya performance — accessibility juga penting
- **Tidak screenshot**: tidak ada bukti score — screenshot untuk portofolio
- **Lighthouse di localhost**: hasil mungkin berbeda dengan production — audit setelah deploy

## Hubungan dengan Materi Sebelumnya

Poin 71-72: aksesibilitas dan performa. **Lighthouse** adalah tools yang mengkuantifikasi usaha kita — memberi score objektif. Ini adalah "final exam" untuk semua yang sudah dipelajari dari Level 1 sampai Level 7.

## Soal Latihan

### Soal 1
Sebutkan 4 kategori Lighthouse.

**Jawaban:**
Performance, Accessibility, Best Practices, SEO.

### Soal 2
Berapa target score minimum untuk masing-masing kategori?

**Jawaban:**
Performance ≥ 90, Accessibility ≥ 95, Best Practices ≥ 90, SEO ≥ 95.

### Soal 3
Apa hubungan Cumulative Layout Shift (CLS) dengan CSS?

**Jawaban:**
CLS diukur dari seberapa banyak layout bergeser saat loading. Penyebab: gambar tanpa width/height, font swap tanpa ukuran cadangan, ads/content yang injected. CSS bisa mencegah dengan `aspect-ratio`, `min-height`, dan ukuran font fallback.
