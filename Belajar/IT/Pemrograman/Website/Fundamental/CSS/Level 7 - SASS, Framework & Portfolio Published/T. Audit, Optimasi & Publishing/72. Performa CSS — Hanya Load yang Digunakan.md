# 72. Performa CSS — Hanya Load yang Digunakan

## Penjelasan

CSS yang besar (100KB+) memperlambat loading website. Strategi optimasi:

1. **Kurangi unused CSS** — hanya style yang benar-benar dipakai
2. **Minifikasi** — hapus spasi, komentar, newlines
3. **Kompresi** — Gzip/Brotli di server
4. **Critical CSS** — CSS yang dibutuhkan untuk first render

## Fungsi

- Loading website lebih cepat (terutama di mobile)
- Mengurangi bandwidth
- Lighthouse Performance score lebih tinggi

## Cara Pengimplementasian

```css
/* SEBELUM OPTIMASI — 50KB unused CSS */
/* .card1, .card2, .card3-old, .experimental { ... } — banyak tidak terpakai */

/* SESUDAH — hanya CSS yang dipakai */
```

**Alat untuk deteksi unused CSS:**
```bash
# Chrome DevTools → Coverage tab
# Buka DevTools → Ctrl+Shift+P → "Coverage" → Record
# Lihat % unused CSS per file
```

**PurgeCSS — hapus CSS yang tidak dipakai:**
```javascript
// Dengan build tool (PostCSS)
// postcss.config.js
export default {
  plugins: {
    '@fullhuman/postcss-purgecss': {
      content: ['./*.html', './src/**/*.html'],
      defaultExtractor: content => content.match(/[\w-/:]+(?<!:)/g) || [],
    },
    'cssnano': { preset: 'default' }, // minifikasi
  },
}
```

**Minifikasi CSS:**
```bash
# SASS compressed
sass --style=compressed input.scss output.css

# Atau dengan cssnano, clean-css, csso
```

**Critical CSS (inline CSS yang dibutuhkan first render):**
```html
<head>
  <style>
    /* Critical CSS — inline untuk first render */
    header { background: #2563eb; color: white; }
    .hero { min-height: 50vh; display: flex; align-items: center; }
    /* Maksimal 14KB inline */
  </style>
  <link rel="stylesheet" href="styles.css" media="print" onload="this.media='all'">
  <!-- Non-critical CSS di-load async -->
</head>
```

**Best practices:**
```
├── File CSS tunggal < 100KB (idealnya < 50KB)
├── Tidak ada CSS yang tidak terpakai (>90% utilized)
├── Render-blocking CSS diminimalkan
├── Gunakan media queries di link untuk prioritaskan CSS
└── Server kompresi Gzip/Brotli aktif
```

## Analogi

Seperti **mengepak koper untuk pergi**:
- **Unused CSS** = membawa baju yang tidak akan dipakai — koper penuh, berat, tidak efisien
- **Minifikasi** = baju di-vakum — ukuran mengecil, isi tetap
- **Critical CSS** = baju ganti di tas tangan — yang paling penting dekat, sisa koper di bagasi
- **PurgeCSS** = buang baju yang sudah tidak muat — hanya yang diperlukan

## Dipakai Untuk Apa

- Production build
- Performance audit
- Lighthouse optimization

## Kesalahan Umum

- **Unused CSS tidak dibersihkan**: bertambah terus setiap fitur baru — akhirnya 200KB
- **PurgeCSS terlalu agresif**: class yang di-generate JavaScript ikut terhapus — perlu konfigurasi safelist
- **Lupa minifikasi di production**: development dan production sama — file besar
- **Terlalu banyak file CSS**: multiple HTTP request — gabung jadi satu file

## Hubungan dengan Materi Sebelumnya

Poin 64: organisasi file. Tapi banyak file = banyak request. **Optimasi performa** menggabungkan, minifikasi, purge — sehingga hasil akhirnya kecil dan cepat.

## Soal Latihan

### Soal 1
Sebutkan 3 cara mengurangi ukuran CSS.

**Jawaban:**
1. PurgeCSS (hapus unused CSS)
2. Minifikasi (hapus spasi/komentar)
3. Kompresi server (Gzip/Brotli)

### Soal 2
Apa fungsi Coverage tab di DevTools?

**Jawaban:**
Menampilkan persentase CSS/JS yang benar-benar digunakan (utilized) vs tidak terpakai (unused) saat halaman di-load.

### Soal 3
Apa itu critical CSS?

**Jawaban:**
CSS minimal yang dibutuhkan untuk menampilkan konten "above the fold" (bagian halaman yang terlihat tanpa scroll). Di-inline di `<head>` agar first render cepat, sisa CSS di-load async.
