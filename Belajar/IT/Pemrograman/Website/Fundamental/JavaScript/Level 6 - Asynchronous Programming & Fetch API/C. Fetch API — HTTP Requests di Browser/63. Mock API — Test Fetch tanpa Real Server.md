# Mock API — Test Fetch tanpa Real Server

## Penjelasan
Mock API adalah **tiruan API**: fungsi yang mengembalikan data palsu dengan bentuk yang **sama persis** seperti `fetch` asli, sehingga kode aplikasi tidak perlu diubah sama sekali. Dua cara umum memakainya:
- **API palsu online** — layanan seperti JSONPlaceholder (`https://jsonplaceholder.typicode.com/todos`) menyediakan data contoh yang bisa di-GET/POST/PUT/DELETE, tapi memang tidak benar-benar menyimpan apa pun.
- **Mock function sendiri** — buat fungsi yang mengembalikan Promise, lalu `resolve` dengan data setelah jeda biar terasa seperti request sungguhan.

Kunci agar mock berguna: hasilnya harus **meniru bentuk Response** `fetch` — minimal punya properti `ok`, `status`, dan method `json()` (yang juga mengembalikan Promise). Kalau bentuknya beda, kode aplikasi akan pecah begitu disambungkan ke server sungguhan.

## Fungsi
Backend sering belum siap saat frontend dikerjakan. Tanpa mock, kamu hanya bisa menatap layar kosong dan tidak bisa menguji apa pun. Dengan mock API, `loadTasks()` bisa diuji dari sekarang: tampilan data, indikator loading, sampai pesan error — semuanya bisa dicoba tanpa install server, tanpa internet, dan tanpa menghabiskan kuota API asli.

## Cara Pengimplementasian / Code
```js
// level6.js — mock fetch buatan sendiri, bentuknya meniru fetch asli
function mockFetch(url) {
  return new Promise((resolve) => {
    setTimeout(() => {
      if (url === "/api/tasks") {
        let tasks = [
          { id: 1, title: "Belajar mock API", completed: false },
          { id: 2, title: "Rapikan laci arsip", completed: true },
        ];
        resolve({ ok: true, status: 200, json: () => Promise.resolve(tasks) });
      } else {
        resolve({ ok: false, status: 404, json: () => Promise.resolve({}) });
      }
    }, 1000); // jeda supaya terasa seperti request sungguhan
  });
}

// Fungsi aplikasi tidak peduli sumbernya mock atau asli — bentuknya sama
function loadTasks(fetcher, url) {
  return fetcher(url).then((response) => {
    if (!response.ok) throw new Error("Status " + response.status);
    return response.json();
  });
}

loadTasks(mockFetch, "/api/tasks")
  .then((tasks) => console.log("Task pertama:", tasks[0].title, "| total:", tasks.length))
  .catch((error) => console.error("Gagal:", error.message));

loadTasks(mockFetch, "/api/riwayat") // URL tidak dikenal → meniru server yang menjawab 404
  .then((tasks) => console.log("Tidak akan jalan"))
  .catch((error) => console.error("Gagal:", error.message));

// Kalau server asli sudah siap, tinggal ganti mockFetch dengan fetch:
// loadTasks(fetch, "https://jsonplaceholder.typicode.com/todos?_limit=2");
```

Cara menjalankan: simpan kode di atas sebagai `level6.js`, lalu muat dari `level6.html` dengan `<script src="level6.js"></script>`. Buka file HTML itu di browser, tekan **F12** → tab **Console**. Untuk API palsu online, cukup pakai URL JSONPlaceholder seperti di baris komentar — tanpa instalasi apa pun.

## Tracing Code (Step-by-Step)
Kita telusuri kode di atas baris demi baris, seolah-olah kita mengikuti komputer.

```js
function mockFetch(url) { return new Promise(...); }
function loadTasks(fetcher, url) { return fetcher(url).then(...); }

loadTasks(mockFetch, "/api/tasks").then(...).catch(...);
loadTasks(mockFetch, "/api/riwayat").then(...).catch(...);
```

**Langkah 1 — baris deklarasi `mockFetch` dan `loadTasks`**
Keduanya hanya disimpan, belum ada yang berjalan.

**Langkah 2 — pemanggilan pertama `loadTasks(mockFetch, "/api/tasks")`**
Parameter `fetcher` diisi fungsi `mockFetch`, `url` diisi `"/api/tasks"`. Di dalamnya, `mockFetch("/api/tasks")` membuat Promise **pending** dan `setTimeout` mencatat jadwal: 1.000 ms lagi jalankan isi promise. `then` pertama `loadTasks` mendaftarkan pengecekan `response.ok`, lalu `.then`/`.catch` terluar juga mendaftarkan fungsinya. Belum ada output.

**Langkah 3 — pemanggilan kedua `loadTasks(mockFetch, "/api/riwayat")`**
Prosesnya sama, hanya beda URL. `"/api/riwayat"` tidak cocok dengan `"/api/tasks"`, jadi jalur `else` (status 404) yang akan disiapkan nanti. Jadwal `setTimeout` kedua dicatat — menyusul jadwal pertama, jadi nanti dia juga menyusul.

**Langkah 4 — setelah 1.000 ms, jadwal pertama dijalankan**
Promise pertama `resolve` dengan object `{ ok: true, status: 200, json: ... }` → statusnya **pending → resolved**. Di dalam `loadTasks`, `if (!response.ok)` → `ok` bernilai `true`, jadi `throw` **dilewati**, lalu `return response.json()` menghasilkan Promise yang sudah berisi array 2 task.

**Langkah 5 — array task sampai ke `.then` terluar**
Tercetak `Task pertama: Belajar mock API | total: 2`. Blok `.catch` dilewati.

**Langkah 6 — jadwal kedua menyusul, hasilnya 404**
Promise kedua `resolve` dengan `{ ok: false, status: 404 }` → **resolved**. Tapi di dalam `loadTasks`, `!response.ok` benar, sehingga `throw new Error("Status 404")` dijalankan dan promise-nya berpindah jadi **rejected**. `.then` terluar dilewati, `.catch` jalan dan mencetak `error.message` yang berisi "Status 404".

**Output akhir:**
```
Task pertama: Belajar mock API | total: 2
Gagal: Status 404
```

## Analogi
Sebelum gudang pusat benar-benar buka, pustakawan memasang **buku tiruan** di rak untuk latihan: sampulnya dibuat sama persis dengan buku asli (format data sama), isinya contoh (data palsu), dan di belakang sampul tertulis "ini tiruan". Anggota perpustakaan (kode aplikasi) tetap bisa meminjam seperti biasa tanpa tahu itu tiruan. Bahkan tiruannya juga meniru kebiasaan buku asli: datang terlambat satu menit, supaya pustakawan terbiasa menunggu.

## Dipakai untuk Apa
- Mengembangkan tampilan Task Manager sebelum backend siap
- Menguji indikator loading dan pesan error tanpa mematikan server
- Belajar tanpa takut menghabiskan kuota atau kena limit API asli
- Menjalankan pengujian otomatis secara deterministik (hasil selalu sama)

## Kesalahan Umum yang Sering Terjadi
- **Mock terlalu berbeda dari `fetch` asli**: kalau hasilnya tidak punya `ok`, `status`, dan `json()`, kode aplikasi error begitu disambungkan ke server sungguhan. Tirulah bentuk Response apa adanya.
- **Mock langsung `resolve` tanpa jeda**: hasil muncul seketika sehingga indikator loading tidak pernah sempat terlihat dan bug urutan kode tidak ketahuan. Beri `setTimeout` kecil.
- **Hanya menyiapkan jalur sukses**: kalau mock tidak pernah gagal, pesan error di aplikasi tidak pernah teruji. Sediakan skenario 404/reject.
- **Menganggap JSONPlaceholder menyimpan perubahan**: POST/PUT/DELETE di sana hanya pura-pura berhasil; data kembali seperti semula saat di-refresh. Untuk penyimpanan sungguhan, pakai mock server seperti json-server (materi 69).
- **Mock ditanam di tengah kode aplikasi**: sulit dilepas saat server sudah jadi. Bungkus jadi fungsi terpisah (`mockFetch`) supaya cukup ditukar dengan `fetch`.

## Soal Latihan & Jawaban
### Soal
Buat `mockFetch(url)` yang meniru `fetch`: ia menyiapkan 3 task setelah 800 ms lalu membalasnya dengan bentuk Response sungguhan (`ok: true`, `status: 200`, method `json()`), berapa pun URL-nya — ini tiruan endpoint `/api/tasks` milik aplikasi. Tulis juga `loadTasks(fetcher)` yang memakai URL JSONPlaceholder, lalu jalankan dua kali: sekali dengan `mockFetch`, sekali dengan `fetch` asli. Buktikan isi `loadTasks` tidak perlu diubah sama sekali.

### Jawaban
```js
function mockFetch(url) {
  return new Promise((resolve) => {
    setTimeout(() => {
      let tasks = [
        { id: 1, title: "Belajar mock API", completed: false },
        { id: 2, title: "Rapikan laci arsip", completed: true },
        { id: 3, title: "Cek buku terlambat", completed: false },
      ];
      // Mock tidak peduli URL: ia selalu membalas data tasks milik aplikasi
      resolve({ ok: true, status: 200, json: () => Promise.resolve(tasks) });
    }, 800);
  });
}

// URL asli dipakai untuk kedua fetcher; bentuk hasilnya sama, jadi kodenya sama
function loadTasks(fetcher) {
  return fetcher("https://jsonplaceholder.typicode.com/todos?_limit=3").then((r) => {
    if (!r.ok) throw new Error("Status " + r.status);
    return r.json();
  });
}

loadTasks(mockFetch)
  .then((tasks) => console.log("Mock:", tasks.length, "task masuk"))
  .catch((error) => console.error("Gagal:", error.message));

loadTasks(fetch) // fetch asli — urutan cetaknya bisa lebih cepat atau lambat
  .then((tasks) => console.log("API asli:", tasks.length, "task masuk"))
  .catch((error) => console.error("Gagal:", error.message));

// Output:
// Mock: 3 task masuk
// API asli: 3 task masuk
```
