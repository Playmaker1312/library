# fetch() dengan Method, Headers, Body — POST, PUT, DELETE

## Penjelasan
Mengambil data dengan GET hanya separuh jalan. Untuk **menambah, mengubah, atau menghapus** data di server, `fetch` menerima **objek options** sebagai argumen kedua: `fetch(url, opsi)`. Isinya:
- **`method`** — jenis permintaan. Default-nya `GET` (mengambil). Selain itu: **`POST`** (membuat baru), **`PUT`** (mengganti seluruh data), **`PATCH`** (mengubah sebagian), **`DELETE`** (menghapus).
- **`headers`** — keterangan tambahan untuk server. Untuk data JSON selalu pakai `{"Content-Type": "application/json"}` supaya server tahu isi body-nya JSON.
- **`body`** — data yang dikirim. Wajib berupa **string**, jadi object harus diubah dulu dengan `JSON.stringify(data)`.

Catatan penting:
- `GET` dan `DELETE` biasanya **tidak memakai body** — `GET` cukup URL, `DELETE` cukup URL tujuan.
- Balasan dari POST/PUT/DELETE juga berupa Promise Response; server umumnya membalas dengan data yang baru dibuat/diubah, jadi `response.json()` tetap bisa dipakai.
- Di materi ini kita memakai JSONPlaceholder: semua perubahan **terlihat berhasil tapi tidak benar-benar tersimpan** (server palsu).

## Fungsi
CRUD yang selama ini kamu kerjakan di memori dan localStorage (materi 27-30) baru lengkap kalau **berbicara dengan server**. POST membuat task di server, PUT menyimpan perubahan status selesai, dan DELETE menghapus task permanen — inilah yang membuat Task Manager bisa dipakai bersama dari banyak device. Tanpa method, headers, dan body, server hanya bisa membantu menyediakan data, bukan menerimanya.

## Cara Pengimplementasian / Code
```js
// level6.js — JSONPlaceholder menerima semua operasi (tapi menyimpannya palsu)
const BASE = "https://jsonplaceholder.typicode.com/todos";

// 1) POST — buat task baru; body wajib string JSON
fetch(BASE, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ title: "Belajar fetch POST", completed: false, userId: 1 }),
})
  .then((response) => response.json())
  .then((task) => {
    console.log("Task baru dibuat:", task.title);
    // 2) PUT — ganti seluruh isi task id 1, dijalankan setelah POST selesai
    return fetch(BASE + "/1", {
      method: "PUT",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ id: 1, title: "Task selesai!", completed: true, userId: 1 }),
    });
  })
  .then((response) => response.json())
  .then((task) => {
    console.log("Task diupdate:", task.title, "| completed:", task.completed);
    // 3) DELETE — hapus task id 1; cukup method, tanpa body
    return fetch(BASE + "/1", { method: "DELETE" });
  })
  .then((response) =>
    console.log("Delete sukses?", response.ok, "| status:", response.status))
  .catch((error) => console.error("Error:", error.message));
```

Cara menjalankan: simpan kode di atas sebagai `level6.js`, lalu muat dari `level6.html` dengan `<script src="level6.js"></script>`. Buka file HTML itu di browser, tekan **F12** → tab **Console**, dan cek **tab Network** untuk melihat method tiap request. Perhatikan juga bahwa ketiga operasi sengaja **dirangkai dengan `.then()`** supaya berjalan berurutan.

## Tracing Code (Step-by-Step)
Kita telusuri kode di atas baris demi baris, seolah-olah kita mengikuti komputer.

```js
fetch(BASE, { method: "POST", headers: {...}, body: JSON.stringify({...}) })
  .then((response) => response.json())
  .then((task) => { console.log(...); return fetch(BASE + "/1", { method: "PUT", ... }); })
  .then((response) => response.json())
  .then((task) => { console.log(...); return fetch(BASE + "/1", { method: "DELETE" }); })
  .then((response) => console.log(...))
  .catch((error) => console.error(...));
```

**Langkah 1 — `fetch(BASE, { method: "POST", ... })`**
`BASE` diisi `https://jsonplaceholder.typicode.com/todos`. Options dibaca: metode `POST`, ada header `Content-Type: application/json`, dan `body` sudah berupa **string JSON** (object di dalamnya sudah diubah oleh `JSON.stringify`). Browser mengirim request-nya, `fetch` mengembalikan Promise **pending**, lalu keenam `.then` mendaftarkan fungsinya masing-masing.

**Langkah 2 — server membalas POST**
Server menjawab `201 Created` dengan isi data yang dikirim + `id` baru. `.then` pertama jalan: `response.json()` mengubah balasan jadi object `task`. Lalu `.then` kedua jalan: tercetak `Task baru dibuat: Belajar fetch POST`, dan `return fetch(...)` mengirim **request PUT** — nilai yang diteruskan ke rantai berikutnya adalah Promise PUT (bukan object).

**Langkah 3 — server membalas PUT**
Server menjawab `200 OK` berisi isi terbaru task id 1. `.then` ketiga mengubahnya jadi object, lalu `.then` keempat jalan: tercetak `Task diupdate: Task selesai! | completed: true`. Setelah itu `return fetch(BASE + "/1", { method: "DELETE" })` mengirim **request DELETE** tanpa body.

**Langkah 4 — server membalas DELETE**
Server menjawab `200 OK` dengan body kosong `{}`. Karena tidak ada body JSON yang perlu dibaca, `.then` kelima langsung mencetak status responsenya.

**Langkah 5 — `.catch`**
Semua tahap sukses, jadi `.catch` **dilewati**. Kalau salah satu request gagal jaringan, rantai langsung lompat ke `.catch` dan mencetak `Error: <pesan>`.

**Output akhir:**
```
Task baru dibuat: Belajar fetch POST
Task diupdate: Task selesai! | completed: true
Delete sukses? true | status: 200
```

## Analogi
Di perpustakaan, tiap permintaan ke gudang pusat ditulis di **formulir** yang formatnya sudah disepakati. Isi formulir (body) harus ditulis rapi dalam format yang dimengerti pihak lain, lalu ditempeli **label jenis permintaan** (method): "TAMBAH BUKU" (POST), "GANTI DATA KARTU KATALOG" (PUT), atau "TARIK BUKU DARI RAK" (DELETE). Di atas formulir ada kolom keterangan format (headers) yang memberi tahu petugas gudang bahwa isinya berupa data terstruktur. Formulir tanpa label atau isi yang berantakan pasti ditolak.

## Dipakai untuk Apa
- Menambah task baru saat tombol **Add** ditekan (POST)
- Menyimpan perubahan status selesai / edit judul task (PUT, PATCH)
- Menghapus task dari server (DELETE)
- Mengirim form login, registrasi, atau komentar ke backend
- Mengirim data form ke API pihak ketiga (payment, notifikasi, dll.)

## Kesalahan Umum yang Sering Terjadi
- **`body` tidak di-`JSON.stringify`**: object yang dilempar langsung berubah jadi `"[object Object]"` atau request ditolak — data di server jadi rusak. Selalu bungkus dengan `JSON.stringify()`.
- **Lupa header `Content-Type: application/json`**: server tidak tahu isi body-mu JSON, sehingga request diabaikan atau dibuang diam-diam.
- **Memberi body pada GET/DELETE**: tidak didukung oleh sebagian besar server; ada yang error, ada yang diam-diam membuang body-nya. cukup URL dan `method`.
- **Menganggap JSONPlaceholder benar-benar menyimpan data**: server ini palsu — POST selalu membalas `id` baru, tapi data itu hilang saat di-refresh. Perubahan nyata baru terasa di materi 69 (mock server) atau backend sendiri.
- **Lupa cek `response.ok`**: operasi tulis gagal (400/500) tetap lolos ke `.then` berikutnya dan kamu mengira berhasil.

## Soal Latihan & Jawaban
### Soal
Server Task Manager menerima POST di `https://jsonplaceholder.typicode.com/todos` untuk task baru, lalu task id 1 akan dihapus dengan DELETE. Buat alur berantai: buat task baru bertuliskan "Rapikan laci arsip", cetak judul hasil POST, hapus task id 1, lalu cetak status responsenya. Jika ada error jaringan, tampilkan "Error: <pesan>".

### Jawaban
```js
const BASE = "https://jsonplaceholder.typicode.com/todos";

fetch(BASE, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ title: "Rapikan laci arsip", completed: false, userId: 1 }),
})
  .then((response) => response.json())
  .then((task) => {
    console.log("Task baru:", task.title);
    // Lanjut ke operasi berikutnya: hapus task id 1
    return fetch(BASE + "/1", { method: "DELETE" });
  })
  .then((response) => console.log("Delete sukses?", response.ok))
  .catch((error) => console.error("Error:", error.message));

// Output:
// Task baru: Rapikan laci arsip
// Delete sukses? true
```
