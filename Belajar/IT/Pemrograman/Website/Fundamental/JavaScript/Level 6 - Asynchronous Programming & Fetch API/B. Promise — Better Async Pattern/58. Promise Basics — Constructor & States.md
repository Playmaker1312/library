# Promise Basics — Constructor & States

## Penjelasan
Promise adalah **objek yang mewakili hasil sebuah operasi asinkron yang belum selesai**. Alih-alih menitipkan fungsi (callback), kamu menerima "tiket" berisi janji bahwa hasilnya akan datang nanti.

Cara membuatnya: `new Promise((resolve, reject) => { ... })`. Fungsi di dalam kurung itu disebut **executor** (pelaksana) dan **langsung dijalankan** saat Promise dibuat. Isinya: cara menunda pekerjaan, lalu memanggil `resolve` untuk sukses atau `reject` untuk gagal.

Tiga status Promise:
- **`pending`** (menunggu) — status awal, hasil belum ada.
- **`resolved` / fulfilled** (berhasil) — dipanggil lewat `resolve(value)`, membawa hasil.
- **`rejected`** (gagal) — dipanggil lewat `reject(error)`, membawa alasan kegagalan.

Aturan main:
- Dari `pending`, Promise hanya bisa berpindah ke **salah satu** dari dua status terakhir — sekali selesai, status dan isinya **tidak bisa diubah lagi**.
- Kalau `resolve` dipanggil dua kali, hanya panggilan pertama yang berlaku.
- Yang menunggu hasil memakai `.then()` / `.catch()` — itu materi berikutnya (59).

## Fungsi
Sebelum Promise, hasil operasi asinkron tidak bisa disimpan, diteruskan, atau digabung — semuanya harus lewat callback. Promise memberi **wakil hasil** yang bisa dipegang sebagai nilai: bisa dikembalikan dari fungsi, ditunggu, digabung dengan Promise lain, dan punya alur error resmi (`reject` → `catch`). Hampir semua API modern (`fetch`, `async/await`, `Promise.all`) berdiri di atas konsep tiga status ini.

## Cara Pengimplementasian / Code
```js
// level6.js
function fetchData(berhasil = true) {
  return new Promise((resolve, reject) => {
    // Baris di dalam executor langsung dijalankan saat Promise dibuat
    console.log("Executor langsung jalan — status masih pending");
    setTimeout(() => {
      if (berhasil) {
        resolve({ id: 1, title: "Belajar Promise" }); // → resolved, value dikirim
      } else {
        reject("Gagal memuat /api/tasks");            // → rejected, error dikirim
      }
    }, 1000);
  });
}

let tugas = fetchData(); // saat ini statusnya pending (belum selesai)
tugas
  .then((data) => console.log("Resolved:", data.title))
  .catch((error) => console.log("Rejected:", error));

let gagal = fetchData(false); // dibuat hampir bersamaan, tapi tujuannya rejected
gagal
  .then((data) => console.log("Resolved:", data.title))
  .catch((error) => console.log("Rejected:", error));
```

Cara menjalankan: simpan kode di atas sebagai `level6.js`, lalu muat dari `level6.html` dengan `<script src="level6.js"></script>`. Buka file HTML itu di browser, tekan **F12** → tab **Console**.

## Tracing Code (Step-by-Step)
Kita telusuri kode di atas baris demi baris, seolah-olah kita mengikuti komputer.

```js
function fetchData(berhasil = true) {
  return new Promise((resolve, reject) => {
    console.log("Executor langsung jalan — status masih pending");
    setTimeout(() => { ... }, 1000);
  });
}

let tugas = fetchData();
tugas.then(...).catch(...);
let gagal = fetchData(false);
gagal.then(...).catch(...);
```

**Langkah 1 — baris deklarasi `function fetchData`**
Fungsi hanya disimpan, belum ada Promise yang dibuat.

**Langkah 2 — `let tugas = fetchData()`**
Konstructor `new Promise` berjalan, dan **executor langsung dieksekusi**: tercetak `Executor langsung jalan — status masih pending`. Di dalamnya, `setTimeout` mencatat jadwal "1.000 ms lagi jalankan `resolve`". Promise lalu dikembalikan, jadi `tugas` kini **berisi Promise dengan status `pending`** — belum ada data sama sekali.

**Langkah 3 — `.then(...)` dan `.catch(...)` pada `tugas`**
Keduanya hanya **mendaftarkan** tindakan: "kalau nanti resolved, jalankan ini; kalau rejected, jalankan itu". Keduanya belum berjalan, status masih `pending`.

**Langkah 4 — `let gagal = fetchData(false)`**
Executor jalan lagi (tercetak baris "Executor" kedua) dan `setTimeout` kedua dicatat. Promise `gagal` juga masih `pending`, lalu handler-nya dipasang.

**Langkah 5 — setelah ±1.000 ms, jadwal pertama dijalankan**
`resolve({ id: 1, title: "Belajar Promise" })` dipanggil → status `tugas` berpindah **`pending` → resolved**, dan value dikirim ke `.then` → tercetak `Resolved: Belajar Promise`. `.catch` dilewati karena tidak ada error.

**Langkah 6 — jadwal kedua menyusul (terdaftar setelah yang pertama)**
`reject("Gagal memuat /api/tasks")` dipanggil → status `gagal` berpindah **`pending` → rejected**. `.then` dilewati, `.catch` yang jalan → tercetak `Rejected: Gagal memuat /api/tasks`.

**Output akhir:**
```
Executor langsung jalan — status masih pending
Executor langsung jalan — status masih pending
Resolved: Belajar Promise
Rejected: Gagal memuat /api/tasks
```

## Analogi
Saat kamu memesan buku dari gudang pusat, pustakawan tidak serta-merta memberi bukunya — dia menyerahkan **kartu antrian**. Kartu itu bertuliskan status: **"menunggu"** (pending), dan setelah gudang menjawab, statusnya dicabut dan diganti jadi **"buku siap diambil"** (resolved, lengkap dengan nomor raknya) atau **"pemesanan ditolak"** (rejected, beserta alasannya). Sekali ditulis, status di kartu tidak bisa diubah lagi — kamu tinggal menunggu dan datang saat statusnya berubah.

## Dipakai untuk Apa
- Membungkus operasi asinkron supaya hasilnya bisa disimpan dan diteruskan
- `fetch()` selalu mengembalikan Promise (materi 61)
- Menjalankan sukses dan gagal lewat jalur resmi `resolve` / `reject`
- Digabung dengan `Promise.all()` untuk menunggu banyak request sekaligus (materi 60)
- Dasar langsung dari `async/await` (materi 64)

## Kesalahan Umum yang Sering Terjadi
- **Executor dianggap jalan saat hasilnya dipakai**: executor justru jalan **saat Promise dibuat**, makanya log pertama muncul duluan sebelum `.then` dipasang.
- **`resolve` dipanggil berkali-kali atau `reject` setelah `resolve`**: hanya panggilan **pertama** yang berlaku; sisanya diabaikan diam-diam.
- **Promise dibuat tapi tidak disimpan atau dikembalikan**: hasilnya lenyap dan error-nya bisa muncul sebagai "unhandled promise rejection" tanpa keterangan jelas.
- **Menganggap `resolve` langsung menjalankan `.then`**: `resolve` hanya mengubah status; handler baru dijalankan **setelah kode sinkron selesai**. Selalu ada jeda satu langkah.
- **Lupa `return new Promise`**: tanpa `return`, pemanggil menerima `undefined`, jadi tidak ada yang bisa ditunggu hasilnya.

## Soal Latihan & Jawaban
### Soal
Buat fungsi `loadTasks(adaKoneksi)` yang mengembalikan Promise: kalau `adaKoneksi` bernilai `true`, resolve dengan array 3 task setelah 1 detik; kalau `false`, reject dengan pesan "Tidak ada koneksi". Cetak tulisan "Status awal: pending" tepat setelah Promise dibuat, lalu tampilkan hasil jalur sukses dan jalur gagal dengan `.then()` dan `.catch()`.

### Jawaban
```js
function loadTasks(adaKoneksi) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (adaKoneksi) {
        resolve([
          { id: 1, title: "Belajar Promise" },
          { id: 2, title: "Rapikan laci arsip" },
          { id: 3, title: "Cek buku terlambat" },
        ]);
      } else {
        reject("Tidak ada koneksi");
      }
    }, 1000);
  });
}

let permintaan = loadTasks(true); // Promise dibuat → status pending
console.log("Status awal: pending");
permintaan
  .then((tasks) => console.log("Task masuk:", tasks.length))
  .catch((error) => console.error("Gagal:", error));

loadTasks(false)
  .then((tasks) => console.log("Tidak akan jalan"))
  .catch((error) => console.error("Gagal:", error));

// Output:
// Status awal: pending
// Task masuk: 3
// Gagal: Tidak ada koneksi
```
