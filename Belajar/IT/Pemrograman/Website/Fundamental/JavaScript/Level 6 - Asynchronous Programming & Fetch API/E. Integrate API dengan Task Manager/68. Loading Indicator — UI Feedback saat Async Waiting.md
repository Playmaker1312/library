# Loading Indicator — UI Feedback saat Async Waiting

## Penjelasan
Saat operasi async berjalan (misalnya `addTask` yang menunggu server), layar **tidak berubah sama sekali** selama menunggu. Pengguna mengira aplikasi rusak, lalu menekan tombol berkali-kali — dan task pun tersimpan ganda. **Loading indicator** adalah elemen UI (spinner atau teks "Memuat...") yang ditampilkan selama menunggu dan disembunyikan begitu selesai.

Tiga prinsip dasar:
- **Show saat mulai**: sebelum `await`, tampilkan loader.
- **Hide saat selesai**: setelah `await` selesai (sukses atau gagal), sembunyikan loader. Karena itu logika "hide" diletakkan di blok `finally` — blok yang selalu jalan (materi 65).
- **Prevent double-click**: `button.disabled = true` selama loading, supaya satu klik hanya memicu satu request. Tombol dikembalikan di `finally` juga.

Prinsip ini sering disebut **UX feedback**: aplikasi yang baik selalu memberi tahu pengguna "apa yang sedang terjadi" di setiap momen.

## Fungsi
Tanpa indikator, jeda 1-2 detik terasa seperti error. Dengan loader, pengguna paham aplikasi sedang bekerja dan sabar menunggu. Disable tombol sekaligus mencegah data duplikat akibat klik ganda — bug klasik aplikasi async.

## Cara Pengimplementasian / Code
Di `level6.html` tambahkan elemen loader dan tombol:
```html
<div id="loader" style="display: none;">⏳ Memuat task...</div>
<input id="taskInput" placeholder="Judul task" />
<button id="addBtn">Add Task</button>
```

Di `level6.js`:
```js
function showLoading(show) {
  // tampilkan sembunyikan loader sesuai parameter
  let loader = document.getElementById("loader");
  loader.style.display = show ? "block" : "none";
}

async function handleAddTask() {
  let title = taskInput.value;
  if (!title.trim()) return;

  // 1. Kunci UI sebelum menunggu server
  addBtn.disabled = true;
  showLoading(true);

  try {
    // 2. Tunggu operasi async ke server
    await window.manager.addTask(title);
    taskInput.value = "";
    renderTasks();
  } catch (error) {
    // 3. Kasih kabar kalau gagal
    showError(error.message);
  } finally {
    // 4. Buka kembali UI — jalankan di semua keadaan
    addBtn.disabled = false;
    showLoading(false);
  }
}

addBtn.addEventListener("click", handleAddTask);
```
Cara menjalankan: simpan kode di atas sebagai file `level6.js`, muat dari `level6.html` (`<script src="level6.js"></script>`), lalu buka di browser dan tekan F12 → tab Console dan tab Network. Supaya terasa jeda loadingnya, gunakan throttle di tab Network (misalnya "Slow 3G") atau mock API dengan delay dari materi 69.

## Tracing Code (Step-by-Step)
Kita telusuri apa yang terlihat layar saat pengguna menekan **Add** dengan task "Belajar UX", dengan server yang butuh 2 detik.

```js
addBtn.disabled = true;
showLoading(true);
await window.manager.addTask("Belajar UX");
// ... finally:
addBtn.disabled = false;
showLoading(false);
```

**Langkah 1 — `addBtn.disabled = true`**
Tombol Add langsung berubah abu-abu dan tidak bisa diklik lagi. Ini terjadi **sebelum** menunggu server, jadi klik kedua dari pengguna langsung mentok.

**Langkah 2 — `showLoading(true)`**
`loader.style.display = "block"` — teks "⏳ Memuat task..." muncul di layar.

**Langkah 3 — `await window.manager.addTask(...)`**
Method mulai mengirim POST ke server dan **berhenti menunggu**. Dari sudut pandang pengguna: layar menunjukkan loader dan tombol mati — jelas bahwa aplikasi sedang bekerja.

**Langkah 4 — server merespons setelah 2 detik**
Karena tidak ada error, blok `catch` **dilewati**. `taskInput.value` dikosongkan dan `renderTasks()` menggambar ulang daftar task (termasuk task baru).

**Langkah 5 — blok `finally` berjalan**
`finally` tidak pernah bisa dilewati. `addBtn.disabled = false` mengaktifkan kembali tombol, lalu `showLoading(false)` menyembunyikan loader (`display = "none"`).

**Catatan skenario gagal:** kalau `addTask` melempar error, Langkah 4 yang dieksekusi adalah blok `catch` (`showError(error.message)` — task baru tampil dengan pesan merah). Setelah itu **Langkah 5 tetap jalan**, jadi loader hilang dan tombol aktif kembali. Inilah kenapa logika "buka kembali UI" diletakkan di `finally`, bukan di akhir `try`.

**Output akhir (skenario sukses):**
```
1. Sebelum klik: loader tersembunyi, tombol aktif
2. Saat menunggu (2 detik): loader tampil, tombol disabled
3. Setelah selesai: loader tersembunyi, tombol aktif, daftar task ter-update
```

## Analogi
Di perpustakaan, saat kamu memesan buku dari gudang pusat, pustakawan menempelkan kartu "Sedang dicari di gudang" di meja — tanda bahwa permintaan sedang diproses, bukan diabaikan. Kartu itu dilepas begitu buku datang atau kabar "tidak ditemukan" diterima. Kalau pustakawan tetap menerima pesanan baru selama menunggu, antrean bisa kacau — seolah-olah form "sedang diproses" juga mengunci penerimaan pesanan lain, sama seperti `button.disabled`.

## Dipakai untuk Apa
- Spinner saat `loadTasks()` memuat daftar task di awal aplikasi.
- Teks "Menyimpan..." selama `addTask()` mengirim data ke server.
- Mencegah double-click pada tombol Add, Delete, dan Save.
- Menampilkan pesan error singkat di UI ketika operasi async gagal.
- Menguji responsivitas UI dengan throttle jaringan di DevTools (tab Network).

## Kesalahan Umum yang Sering Terjadi
- **Loader disembunyikan hanya di `try`**: Kalau `await` gagal dan tidak ada `finally`, loader tetap terbuka selamanya dan pengguna mengira aplikasi hang. Selalu sembunyikan loader di `finally`.
- **Melupakan `disabled` saat loading**: Tanpa `disable` tombol, pengguna bisa klik 3 kali → 3 task identik terkirim ke server. Selalu kunci tombol selama menunggu.
- **Menampilkan loader setelah `await`**: `await manager.addTask(title); showLoading(true);` tidak ada gunanya — loading baru muncul setelah semuanya selesai. Tampilkan loader **sebelum** `await`.
- **Loader yang selalu tampil**: Elemen loader dibuat tanpa `style="display: none"` di HTML awal, sehingga sudah terlihat sebelum ada operasi apa pun. Sembunyikan dari awal, tampilkan hanya saat dibutuhkan.

function showLoading(show) {
  document.getElementById("loader").style.display = show ? "block" : "none";
}

async function handleDeleteTask(id) {
  showLoading(true); // tampilkan loader SEBELUM await

  try {
    await window.manager.deleteTask(id); // tunggu server
    renderTasks(); // gambar ulang daftar

    showError("Gagal menghapus task: " + error.message);
  } finally {
    showLoading(false); // loader pasti hilang, sukses maupun gagal
  }
}
