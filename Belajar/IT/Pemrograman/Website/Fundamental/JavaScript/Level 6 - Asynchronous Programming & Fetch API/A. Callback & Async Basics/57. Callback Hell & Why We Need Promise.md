# Callback Hell & Why We Need Promise

## Penjelasan
Callback hell adalah keadaan ketika **callback bersarang di dalam callback** sehingga kode bertingkat seperti piramida: indentasi makin ke kanan, makin sulit dibaca, dan makin sulit dirawat. Ciri-cirinya:
- Setiap langkah asinkron harus menunggu langkah sebelumnya, jadi harus dimasukkan ke dalam callback langkah itu.
- Penanganan error (`if (error) ...`) terulang di tiap tingkat, dan satu tingkat terlupa membuat error diam tanpa pesan.
- Mengubah satu langkah berarti menyusun ulang seluruh sarang.

Solusinya adalah **Promise** — objek yang mewakili hasil sebuah operasi asinkron: sukses (`resolve`) atau gagal (`reject`). Hasil Promise dikonsumsi dengan `.then()` dan `.catch()`, sehingga alurnya **datar** (berantai ke samping), bukan bersarang. Kuncinya: masalahnya ada di **struktur**, bukan di panjangnya kode.

## Fungsi
Callback hell membuat kode yang tadinya benar menjadi rapuh: sulit ditambah fitur, sulit di-debug, dan mudah salah urutan. Promise menghapus masalah itu sekaligus memberi standar menangani sukses/gagal yang seragam di seluruh JavaScript modern — dari `fetch()` sampai `async/await`. Memahami "kenapa Promise perlu ada" membuatmu tidak kembali ke pola bersarang saat menulis kode sendiri.

## Cara Pengimplementasian / Code
```js
// level6.js
function ambilUser(callback) {
  setTimeout(() => callback(null, { id: 7, nama: "Andi" }), 1000);
}

function ambilTasks(userId, callback) {
  setTimeout(() => {
    callback(null, [
      { id: 1, title: "Belajar callback", selesai: false },
      { id: 2, title: "Rapikan laci arsip", selesai: true },
    ]);
  }, 1000);
}

// ❌ Versi callback bersarang — perhatikan bentuk piramidanya
ambilUser((errorUser, user) => {
  if (errorUser) {
    console.error("Gagal ambil user:", errorUser);
  } else {
    console.log("User:", user.nama);
    ambilTasks(user.id, (errorTasks, tasks) => {
      if (errorTasks) {
        console.error("Gagal ambil tasks:", errorTasks);
      } else {
        console.log("Task pertama:", tasks[0].title);
        console.log("Jumlah task:", tasks.length);
      }
    });
  }
});

// ✅ Versi Promise: datar, satu cabang error di ujung (materi 58-59)
// ambilUserPromise()
//   .then(user => ambilTasksPromise(user.id))
//   .then(tasks => console.log("Jumlah task:", tasks.length))
//   .catch(error => console.error("Gagal:", error));
```

Cara menjalankan: simpan kode di atas sebagai `level6.js`, lalu muat dari `level6.html` dengan `<script src="level6.js"></script>`. Buka file HTML itu di browser, tekan **F12** → tab **Console**. Blok Promise sengaja dikomentari dulu supaya kamu bisa membandingkan bentuknya.

## Tracing Code (Step-by-Step)
Kita telusuri kode di atas baris demi baris, seolah-olah kita mengikuti komputer.

```js
function ambilUser(callback) { setTimeout(..., 1000); }
function ambilTasks(userId, callback) { setTimeout(..., 1000); }

ambilUser((errorUser, user) => {
  console.log("User:", user.nama);
  ambilTasks(user.id, (errorTasks, tasks) => {
    console.log("Task pertama:", tasks[0].title);
    console.log("Jumlah task:", tasks.length);
  });
});
```

**Langkah 1 — baris deklarasi kedua fungsi**
Keduanya hanya disimpan, belum ada yang berjalan.

**Langkah 2 — `ambilUser(...)` dipanggil**
Callback tingkat 1 (callback paling luar) disimpan sebagai parameter. Di dalamnya, `setTimeout` mencatat jadwal: 1.000 ms lagi jalankan callback itu. `ambilUser` langsung selesai — **tidak ada kode yang menunggu**.

**Langkah 3 — setelah 1.000 ms, callback tingkat 1 dijalankan**
`errorUser` berisi `null` (jalur sukses), jadi masuk `else` dan `user` berisi `{ id: 7, nama: "Andi" }`. Tercetak `User: Andi`. Lalu `ambilTasks(7, ...)` dipanggil dan mencatat jadwal baru: 1.000 ms lagi jalankan callback tingkat 2. Sarangnya kini dua lapis.

**Langkah 4 — setelah 1.000 ms berikutnya (total ±2.000 ms), callback tingkat 2 dijalankan**
`errorTasks` berisi `null`, jadi masuk `else` dengan `tasks` berisi 2 task. Tercetak `Task pertama: Belajar callback`, lalu `Jumlah task: 2`. Kedua `if (error)` tingkat atas tidak pernah terpakai karena tidak ada error.

**Langkah 5 — blok Promise yang dikomentari**
Tanda `//` membuat baris-baris itu **tidak dijalankan sama sekali**. Blok ini hanya contoh bentuk alternatif yang akan kamu pelajari di materi 58-59.

**Output akhir:**
```
User: Andi
Task pertama: Belajar callback
Jumlah task: 2
```

## Analogi
Di perpustakaan, memesan buku dari gudang pusat ternyata berantai: sebelum boleh minta buku, kamu minta petugas cek data anggota; setelah itu baru minta cek katalog; setelah itu baru kirim formulir pesanan. Tiap langkah harus **menitipkan janji "telepon saya setelah selesai"**, dan tiap titipan membuat formulirmu makin tebal bersarang di dalam formulir sebelumnya — makin dalam, makin miring, makin sulit dibaca. Itulah callback hell; Promise datang supaya semua janji itu cukup ditulis berjajar dalam satu baris.

## Dipakai untuk Apa
- Menyadari pola lama saat membaca kode atau library lama
- Membaca alasan kenapa `fetch`, Axios, dan `async/await` akhirnya dibuat
- Memutuskan kapan kode callback harus direfaktor ke Promise
- Bahan wawancara: "apa itu callback hell dan bagaimana mengatasinya?"

## Kesalahan Umum yang Sering Terjadi
- **Menganggap masalahnya cuma indentasi**: merapikan spasi atau mengganti gaya kurung tidak membuat alurnya mudah — struktur bersarangnya yang bermasalah.
- **Menangani error terpisah tiap tingkat**: tiap callback menulis `if (error)` sendiri; satu tingkat terlupa, error jadi senyap (tidak ada pesan sama sekali). Dengan Promise, satu `.catch()` di ujung sudah cukup.
- **Menambah callback lagi untuk "merapikan"**: makin banyak lapis, makin parah. Refaktor ke `.then()` (materi 59), jangan tambah sarang.
- **Menyerah sebelum mencoba Promise**: bentuk rantai `.then().then().catch()` jauh lebih pendek, dan `async/await` (materi 64) membuatnya terlihat seperti kode biasa.

## Soal Latihan & Jawaban
### Soal
Alur Task Manager butuh dua langkah berantai: ambil profil user (1 detik), lalu ambil daftar task miliknya (1 detik). Tulis ulang alur itu dengan Promise `.then()` memakai mock promise, supaya tidak ada callback yang bersarang, dan buktikan output-nya sama dengan versi bersarangnya.

### Jawaban
```js
// Mock versi Promise — hasil async dibungkus jadi Promise (materi 58)
function ambilUserPromise() {
  return new Promise((resolve) =>
    setTimeout(() => resolve({ id: 7, nama: "Andi" }), 1000)
  );
}

function ambilTasksPromise(userId) {
  return new Promise((resolve) =>
    setTimeout(() => resolve([
      { id: 1, title: "Belajar callback" },
      { id: 2, title: "Rapikan laci arsip" },
    ]), 1000)
  );
}

// Alur datar: tiap langkah jadi satu .then, error ditangkap sekali di .catch
ambilUserPromise()
  .then((user) => {
    console.log("User:", user.nama);
    return ambilTasksPromise(user.id); // hasil diteruskan ke .then berikutnya
  })
  .then((tasks) => {
    console.log("Task pertama:", tasks[0].title);
    console.log("Jumlah task:", tasks.length);
  })
  .catch((error) => console.error("Gagal:", error));

// Output:
// User: Andi
// Task pertama: Belajar callback
// Jumlah task: 2
```
