# Callback Function Pattern — Passing Function as Parameter

## Penjelasan
Callback adalah **fungsi yang diserahkan sebagai parameter** ke fungsi lain, untuk dipanggil (dijalankan) oleh fungsi itu — biasanya setelah suatu pekerjaan selesai. Jadi fungsi kamu "dititipkan" dulu, dan yang menjalankannya adalah pihak lain.

Cara kerjanya:
- Fungsi utama menerima callback, lalu **menyimpannya** tanpa menjalankannya.
- Setelah pekerjaan selesai (atau gagal), fungsi utama **memanggil** callback tersebut dengan hasilnya.
- Konvensi umum (pola error-first): `callback(error, hasil)` — argumen pertama berisi error (`null` kalau sukses), argumen kedua berisi hasil.
- Callback bisa sinkron (langsung dipanggil) atau asinkron (dipanggil setelah jeda waktu).
- Kamu sebenarnya sudah memakai callback tanpa sadar: `setTimeout`, `forEach`, `map`, dan `addEventListener` semuanya menerima callback.

## Fungsi
JavaScript tidak punya sintaks "berhenti di sini sampai datanya datang". Jawabannya: **titipkan fungsi** yang berbunyi "kalau sudah selesai, jalankan ini". Pola callback adalah cara asli JavaScript menangani operasi asinkron sebelum Promise dan `async/await` ada, dan pola ini masih hidup sampai sekarang di banyak library, event, dan kode lama.

## Cara Pengimplementasian / Code
```js
// level6.js
// Simulasi request ke /api/tasks — selesai setelah 1 detik
function fetchData(berhasil, callback) {
  console.log("Request /api/tasks dikirim");
  setTimeout(() => {
    if (berhasil) {
      callback(null, { id: 1, title: "Rapikan laci arsip" }); // sukses: error null
    } else {
      callback("Server sedang sibuk", null);                  // gagal: error terisi
    }
  }, 1000);
}

// Kita siapkan callback-nya, lalu serahkan ke fetchData
fetchData(true, (error, data) => {
  if (error) {
    console.error("Gagal:", error);
  } else {
    console.log("Task masuk:", data.id, "-", data.title);
  }
});

// Panggilan kedua: sengaja lewat jalur error
fetchData(false, (error, data) => {
  if (error) console.error("Gagal:", error);
  else console.log("Task masuk:", data.id, "-", data.title);
});
```

Cara menjalankan: simpan kode di atas sebagai `level6.js`, lalu muat dari `level6.html` dengan `<script src="level6.js"></script>`. Buka file HTML itu di browser, tekan **F12** → tab **Console**.

## Tracing Code (Step-by-Step)
Kita telusuri kode di atas baris demi baris, seolah-olah kita mengikuti komputer.

```js
function fetchData(berhasil, callback) { ... } // deklarasi

fetchData(true, (error, data) => { ... }); // panggilan 1
fetchData(false, (error, data) => { ... }); // panggilan 2
```

**Langkah 1 — baris deklarasi `function fetchData`**
JavaScript hanya menyimpan rencananya. Belum ada yang berjalan, belum ada "Request" yang tercetak.

**Langkah 2 — panggilan 1, `fetchData(true, ...)`**
Masuk ke dalam `fetchData`. Parameter `berhasil` berisi `true`, parameter `callback` berisi fungsi yang baru kita tulis — **disimpan saja, belum dijalankan**.

**Langkah 3 — baris `console.log("Request /api/tasks dikirim")`**
Langsung tercetak: `Request /api/tasks dikirim`. Ini bukti fungsi utama tetap berjalan biasa.

**Langkah 4 — baris `setTimeout(...)` di dalam `fetchData`**
JavaScript mencatat jadwal: "1.000 ms lagi, jalankan `callback(null, {...})`". Lalu `fetchData` selesai dan **mengembalikan `undefined`** — tanpa menunggu callback sama sekali.

**Langkah 5 — panggilan 2, `fetchData(false, ...)`**
Begitu pula untuk panggilan kedua: `berhasil` berisi `false`, callback disimpan, "Request" kedua tercetak, dan jadwal callback kedua dicatat 1.000 ms dari sini (menyusul jadwal pertama).

**Langkah 6 — setelah 1.000 ms, jadwal pertama dijalankan**
Callback pertama dipanggil dengan `error = null` dan `data = { id: 1, title: "Rapikan laci arsip" }`. `if (error)` → `null` itu dianggap salah (falsy), jadi masuk `else`: tercetak `Task masuk: 1 - Rapikan laci arsip`.

**Langkah 7 — jadwal kedua menyusul**
Callback kedua dipanggil dengan `error = "Server sedang sibuk"`. Kali ini `if (error)` benar, jadi tercetak `Gagal: Server sedang sibuk`. Jalur `else` dilewati.

**Output akhir:**
```
Request /api/tasks dikirim
Request /api/tasks dikirim
Task masuk: 1 - Rapikan laci arsip
Gagal: Server sedang sibuk
```

## Analogi
Bayangkan kamu memesan buku dari gudang pusat di perpustakaan. Di formulir pemesanan ada kolom **"hubungi saya kalau buku sudah datang"** — kolom itulah callback: instruksi + kontak yang kamu titipkan. Pustakawan mengurus formulirmu lalu langsung melayani antrean berikutnya (dia tidak berdiri menunggu gudang). Setelah buku tiba, dia "menjalankan" instruksi di kolom itu — dan kamu yang menentukan mau diapakan kabarnya.

## Dipakai untuk Apa
- Menangani hasil operasi asinkron jadul: `setTimeout`, `XMLHttpRequest`, timer
- Event handler: `addEventListener("click", () => {...})` adalah callback (materi 46)
- Metode array: `forEach`, `map`, `filter`, `sort` dengan pembanding
- Kirim fungsi "pengumum" ke komponen UI, misal `render(tasks, callbackSelesaiRender)`
- Pola error-first khas Node.js yang bertahan sampai sekarang

## Kesalahan Umum yang Sering Terjadi
- **Lupa memanggil callback**: fungsi utama selesai tapi tidak ada yang terjadi setelahnya — tanpa pesan error, tanpa output. Hindari: pastikan `callback(...)` ada di setiap jalur, termasuk jalur gagal.
- **Callback hanya dipanggil di jalur sukses**: saat data gagal, aplikasi diam tanpa keterangan. Selalu buat cabang untuk error.
- **Membalik urutan parameter `(data, error)`**: error jadi dianggap sebagai data, sehingga data valid dibuang dan pesan error dipakai sebagai isi.
- **Menganggap callback langsung berjalan saat dipanggil**: kalau callback ada di dalam `setTimeout`, ia baru jalan setelah jeda — kode setelah pemanggilan tetap berjalan lebih dulu (materi 55).
- **Menumpuk callback di dalam callback**: alurnya jadi bersarang dan sulit dibaca, lihat **57. Callback Hell & Why We Need Promise**.

## Soal Latihan & Jawaban
### Soal
Buat fungsi `loadTasks(callback)` yang mensimulasikan pengambilan data dari `/api/tasks` setelah 800 ms. Jika ada task berjudul kosong, panggil `callback("Judul task kosong", null)`; kalau semua valid, panggil `callback(null, tasks)` dengan 3 task. Pasang callback-nya yang menampilkan jumlah task dan judul task pertama, atau menampilkan error bila ada.

### Jawaban
```js
function loadTasks(callback) {
  setTimeout(() => {
    let tasks = [
      { id: 1, title: "Belajar callback" },
      { id: 2, title: "Rapikan laci arsip" },
      { id: 3, title: "Cek buku terlambat" },
    ];
    // Pola error-first: cek dulu apakah datanya layak
    let adaKosong = tasks.some((t) => !t.title.trim());
    if (adaKosong) callback("Judul task kosong", null);
    else callback(null, tasks);
  }, 800);
}

loadTasks((error, tasks) => {
  if (error) {
    console.error("Gagal:", error);
  } else {
    console.log("Task masuk:", tasks.length, "| pertama:", tasks[0].title);
  }
});
// Task masuk: 3 | pertama: Belajar callback
```
