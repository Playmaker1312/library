# Error Handling dengan try-catch

## Penjelasan
`try...catch` adalah blok penangkap error: kode yang mungkin gagal diletakkan di dalam `try`, dan kalau terjadi error (throw), alih-alih program crash, JavaScript **loncat ke blok `catch`** dan menjalankan isinya.

Cara kerja di dalam function `async`:
- `await promiseGagal` akan **melempar error** (throw) persis seperti error biasa — jadi bisa ditangkap `catch`.
- Di promise biasa, kamu memakai `.catch()`. Di `async/await`, kamu memakai `try...catch` — hasilnya sama, tapi kodenya lebih rapi dan tidak bersarang.
- `finally` adalah blok opsional yang **selalu dijalankan**, baik `try` sukses maupun gagal — cocok untuk membersihkan (misalnya menyembunyikan loading).
- Penting: `fetch()` **tidak otomatis error** kalau server balas 404 atau 500. Error baru terjadi kalau jaringan benar-benar putus. Karena itu cek `response.ok` sendiri dan `throw` error kalau false.

## Fungsi
Server bisa mati, internet bisa putus, data bisa korup — semua itu membuat operasi async gagal. Tanpa `try...catch`, promise yang gagal memunculkan `Unhandled Promise Rejection` dan aplikasi tampak "diam" tanpa penjelasan. Dengan blok ini, kamu bisa menampilkan pesan error yang jelas ke pengguna, sambil tetap menjalankan proses pembersihan di `finally`.

## Cara Pengimplementasian / Code
```js
// Mock fetch yang bisa gagal: meniru jarak ke server
function fetchTasksDariServer(url) {
  return new Promise((resolve) => {
    setTimeout(() => resolve({ ok: true, json: () => Promise.resolve([
      { id: 1, title: "Belajar JS" },
      { id: 2, title: "Bikin UI" }
    ]) }), 1000);
  });
}

class TaskManager {
  #tasks = [];

  async loadTasks() {
    try {
      let response = await fetchTasksDariServer("/api/tasks");

      // fetch tidak error otomatis saat status 404/500, jadi dicek manual
      if (!response.ok) throw new Error("Server menolak permintaan");

      let data = await response.json();
      this.#tasks = data;
      console.log("Data masuk:", this.#tasks.length, "task");
    } catch (error) {
      // Semua error dari await di atas masuk ke sini
      console.error("Load failed:", error.message);
    } finally {
      // Selalu jalan, sukses maupun gagal
      console.log("Proses load selesai");
    }
  }
}

let manager = new TaskManager();
manager.loadTasks().then(() => console.log("loadTasks() sudah selesai"));
```
Cara menjalankan: simpan kode di atas sebagai file `level6.js`, muat dari `level6.html` (`<script src="level6.js"></script>`), lalu buka di browser dan tekan F12 → tab Console. Untuk mencoba jalur error, ubah `resolve(...)` jadi `reject(new Error("Jaringan putus"))` pada `fetchTasksDariServer`.

## Tracing Code (Step-by-Step)
Kita telusuri dua skenario agar kelihatan blok mana yang jalan.

**Skenario sukses (kode seperti di atas):**

**Langkah 1 — `manager.loadTasks()` dipanggil**
Masuk ke blok `try`, lalu `await` berhenti menunggu `fetchTasksDariServer` selama 1 detik.

**Langkah 2 — setelah 1 detik**
`response` berisi objek `{ ok: true, json: ... }`. Karena `response.ok` bernilai `true`, `if` tidak jalan → `throw` **tidak dieksekusi**. `data` berisi array 2 task, `this.#tasks` berisi 2 task, dan `Data masuk: 2 task` tercetak.

**Langkah 3 — `catch` dilewati, `finally` jalan**
Tidak ada error, jadi JavaScript **loncat langsung** ke `finally`: `Proses load selesai` tercetak. Lalu promise `loadTasks` resolved dan `.then()` mencetak `loadTasks() sudah selesai`.

**Skenario gagal (server ditukar jadi `reject(new Error("Jaringan putus"))`):**

**Langkah 1 — `await` di baris pertama `try`**
Setelah 1 detik, promise datang dalam keadaan gagal (rejected). `await` **langsung melempar error** "Jaringan putus" — baris `response.ok` dan seterusnya **tidak pernah dijalankan**.

**Langkah 2 — loncat ke `catch`**
JavaScript berhenti menjalankan `try` dan masuk ke `catch`. Variabel `error` berisi Error "Jaringan putus". `console.error` mencetak `Load failed: Jaringan putus`.

**Langkah 3 — `finally` tetap jalan, lalu promise selesai**
Meski `try` gagal, `finally` tidak bisa dilewati: `Proses load selesai` tetap tercetak. Karena `catch` menangkap error dan tidak melempar ulang, promise `loadTasks` tetap resolved — `.then()` mencetak `loadTasks() sudah selesai`.

**Output akhir:**
```
# Skenario sukses:            # Skenario gagal:
Data masuk: 2 task            Load failed: Jaringan putus
Proses load selesai           Proses load selesai
loadTasks() sudah selesai     loadTasks() sudah selesai
```

## Analogi
Di perpustakaan ada aturan: sebelum buku dikembalikan ke rak, kartu katalog **wajib** dibersihkan dan distempel tanggal. Pustakawan membungkus pekerjaan itu dalam semacam "form pengembalian". Kalau buku ditemukan (sukses) atau ternyata rusak/hilang (gagal), stempel dan pembersihan tetap dilakukan — itu peran `finally`. Kalau ada masalah, pustakawan menuliskannya di kolom "keluhan" (`catch`) supaya kamu pulang dengan penjelasan, bukan dengan kebingungan.

## Dipakai untuk Apa
- Menangkap error jaringan saat `loadTasks()` mengambil data dari API.
- Menampilkan pesan "Gagal menyimpan, coba lagi" saat POST task gagal.
- Menjalankan `finally` untuk menyembunyikan loader dan mengaktifkan kembali tombol setelah operasi selesai.
- Mengecek status HTTP (`response.ok`) dan sengaja melempar error yang deskriptif.

## Kesalahan Umum yang Sering Terjadi
- **Mengandalkan `fetch` yang otomatis error**: `fetch` hanya reject kalau jaringan putus. Server balas 404/500 tetap dianggap sukses. Akibatnya data kosong tanpa pesan error. Cara menghindari: selalu `if (!response.ok) throw new Error(...)`.
- **Lupa `await` di dalam `try`**: `let data = response.json();` tanpa `await` membuat `data` berisi promise, dan error dari dalamnya tidak tertangkap `try`. Selalu `await` setiap promise di dalam `try`.
- **`catch` dibiarkan kosong atau menelan error**: `catch (e) {}` membuat kamu tidak tahu apa yang gagal, dan debugging jadi mustahil. Minimal `console.error(error)` dulu.
- **Salah urutan: `finally` sebelum `catch`**: Urutan yang benar selalu `try → catch → finally`. Menulis `finally` dulu menyebabkan error `SyntaxError`.

## Soal Latihan & Jawaban
### Soal
Buat method `async addTask(title)` pada class `TaskManager` yang memvalidasi input dan menyimpan ke "server". Jika `title` kosong, lempar error `"Judul task kosong"`. Jika "server" gagal (meniru jaringan putus), lempar error apa adanya. Panggil method itu dengan input kosong dan tangkap pesannya dengan `try...catch...finally` — pastikan `finally` selalu mencetak "Selesai menyimpan".

### Jawaban
```js
// Mock server: selalu gagal untuk meniru jaringan putus
function simpanKeServer(task) {
  return new Promise((resolve, reject) => {
    setTimeout(() => reject(new Error("Jaringan putus")), 1000);
  });
}

class TaskManager {
  #tasks = [];

  async addTask(title) {
    try {
      if (!title.trim()) throw new Error("Judul task kosong"); // validasi
      let response = await simpanKeServer(title);
      if (!response.ok) throw new Error("Create failed");
      this.#tasks.push({ id: this.#tasks.length + 1, title, completed: false });
      console.log("Task tersimpan:", title);
    } catch (error) {
      console.error("Add task error:", error.message); // tampilkan penyebab gagal
    } finally {
      console.log("Selesai menyimpan"); // selalu jalan
    }
  }
}

let manager = new TaskManager();

(async () => {
  await manager.addTask("   "); // input kosong → "Judul task kosong"
  await manager.addTask("Belajar try-catch"); // server gagal → "Jaringan putus"
})();
// Output akhir:
// Add task error: Judul task kosong
// Selesai menyimpan
// Add task error: Jaringan putus
// Selesai menyimpan
```
