# Spread dalam Event Handling & DOM Updates

## Penjelasan
Spread (`...`) memexpand isi object atau array menjadi potongan-potongan baru. Dalam event handling dan update DOM, spread dipakai untuk **menggabungkan data** dan untuk **update immutable**.

- **Immutable update**: membuat object **baru** berisi salinan data lama + perubahan, tanpa menyentuh object aslinya. Kata `immutable` artinya "tidak bisa diubah" — object lama sengaja dibiarkan utuh.
- Pola dasarnya: `{ ...task, completed: !task.completed }` — spread menyalin semua properti dulu, lalu property `completed` ditimpa nilai baru.
- Urutan penting: **spread dulu, perubahan belakangan**. Kalau terbalik, salinan lama yang menimpa perubahanmu.
- Spread juga bisa menggabungkan dua object: `{ ...dataForm, ...tambahan }` — property di `tambahan` menang kalau kunci sama.

## Fungsi
Di Task Manager, aksi complete/priority/delete terjadi di event handler, lalu datanya dikirim ke manager (bahkan `await` ke API). Kalau kamu memutasi object lama langsung, state di memori ikut berubah sebelum proses simpan benar-benar berhasil. Kalau prosesnya gagal, tampilan dan data jadi tidak konsisten.

Dengan pola immutable, object lama tetap bersih. Kamu mengirim object baru ke manager, dan kalau gagal kamu tinggal membuang object barunya — tidak ada yang perlu dikembalikan.

## Cara Pengimplementasian / Code
```js
// Dipanggil dari event listener tombol Complete (event delegation)
async function handleCompleteTask(taskId) {
  const task = window.manager.getTasks().find((t) => t.id === taskId);
  if (!task) return; // task tidak ditemukan, langsung berhenti

  // Immutable update: object BARU = salinan semua properti + satu perubahan
  const updated = { ...task, completed: !task.completed };
  await window.manager.updateTask(taskId, updated);
  renderTasks(); // gambar ulang daftar (materi 82)
}

// Spread menggabungkan data form dengan tambahan dari program
function buildTaskFromForm(formData, extras) {
  return { ...formData, ...extras }; // extras menang kalau kunci sama
}

// Percobaan langsung: bandingkan object lama dan object baru
const task = { id: 1, title: "Belajar spread", priority: "high", completed: false, createdAt: 100 };
const updated = { ...task, completed: !task.completed };
console.log("lama :", JSON.stringify(task));
console.log("baru :", JSON.stringify(updated));

const formData = { title: "Tulis dokumentasi", priority: "normal" };
const extras = { id: 42, completed: false, createdAt: 200 };
console.log("form :", JSON.stringify(buildTaskFromForm(formData, extras)));
```

Cara menjalankan: simpan kode di atas sebagai `level7.js`, muat dari `level7.html` (`<script src="level7.js"></script>`), buka file HTML di browser, lalu tekan F12 → tab Console.

## Tracing Code (Step-by-Step)
Kita telusuri kode di atas baris demi baris, seolah-olah kita mengikuti komputer.

**Langkah 1 — `const task = { ... }`**
Komputer membuat object berisi lima properti: `id: 1`, `title: "Belajar spread"`, `priority: "high"`, `completed: false`, `createdAt: 100`.

**Langkah 2 — `const updated = { ...task, completed: !task.completed }`**
Pertama, `...task` memexpand lima properti `task` ke dalam object baru. Belum ada yang berubah, isinya masih sama. Lalu `completed: !task.completed` menimpa properti `completed`: `!false` bernilai `true`.

| Properti | Nilai di `task` (lama) | Nilai di `updated` (baru) |
|---|---|---|
| `id` | `1` | `1` (hasil salinan) |
| `title` | `"Belajar spread"` | `"Belajar spread"` (hasil salinan) |
| `priority` | `"high"` | `"high"` (hasil salinan) |
| `completed` | `false` | `true` (ditimpa) |
| `createdAt` | `100` | `100` (hasil salinan) |

`task.completed` tetap `false` karena object aslinya tidak pernah disentuh.

**Langkah 3 — `console.log("lama :", ...)` dan `console.log("baru :", ...)`**
`JSON.stringify` mengubah object jadi teks. Console mencetak dua baris: object lama dengan `"completed":false` dan object baru dengan `"completed":true`.

**Langkah 4 — `buildTaskFromForm(formData, extras)`**
`formData` berisi `{ title: "Tulis dokumentasi", priority: "normal" }` dan `extras` berisi `{ id: 42, completed: false, createdAt: 200 }`. Di dalam function, `...formData` menyalin dua properti pertama, lalu `...extras` menambahkan tiga properti terakhir. Object hasilnya berisi lima properti.

**Langkah 5 — `console.log("form :", ...)`**
Console mencetak object hasil gabungan itu sebagai teks.

**Langkah 6 — jalannya `handleCompleteTask(1)` (saat tombol diklik)**
`find` menemukan task dengan `id: 1`. `updated` dibuat seperti langkah 2 (`completed` jadi `true`). `await updateTask(1, updated)` mengirim object baru itu ke manager, lalu `renderTasks()` menggambar ulang daftar. Task lama di manager baru berganti setelah update selesai.

**Output akhir:**
```
lama : {"id":1,"title":"Belajar spread","priority":"high","completed":false,"createdAt":100}
baru : {"id":1,"title":"Belajar spread","priority":"high","completed":true,"createdAt":100}
form : {"title":"Tulis dokumentasi","priority":"normal","id":42,"completed":false,"createdAt":200}
```

## Analogi
Ini seperti pustakawan yang **memfotokopi formulir anggota** lalu mengoreksi satu kolom di fotokopiannya. Formulir asli tetap bersih dan tidak pernah ditulis ulang; semua perubahan hanya ada di lembar baru. Kalau ternyata koreksinya salah, dia cukup membuang fotokopian dan membuat lagi dari formulir asli.

## Dipakai untuk Apa
- Toggle status Complete/Undo tanpa merusak data asli (event handler materi 52)
- Menggabungkan data form dengan tambahan seperti `id`, `createdAt` saat add task
- Mengubah prioritas atau judul task secara aman (`{ ...task, priority: baru }`)
- Update state berbasis Redux-style di library React/Vue
- Menyusun objek konfigurasi dari banyak sumber (`{ ...default, ...opsiPengguna }`)

## Kesalahan Umum yang Sering Terjadi
- **Urutan spread terbalik**: `{ completed: !task.completed, ...task }` membuat salinan lama menimpa perubahanmu, jadi `completed` kembali `false` dan aksi Complete terasa tidak jalan. Selalu tulis `...task` dulu, perubahan sesudahnya.
- **Mengira spread menyalin bersarang**: `{ ...task }` hanya menyalin satu tingkat. Kalau ada `task.meta = { tags }`, object `meta` di salinan tetap menunjuk object yang sama, sehingga perubahan bersarang ikut mengubah asli. Salin manual untuk isi bersarang: `{ ...task, meta: { ...task.meta } }`.
- **Mutasi langsung di event handler**: `task.completed = !task.completed` mengubah state sebelum `await updateTask` selesai. Kalau update gagal, tampilan sudah berubah tapi data tidak — tidak konsisten. Buat object baru, kirim, baru render ulang.
- **Lupa menyebarkan data lama**: `{ completed: true }` membuat object yang cuma punya satu properti, id dan judulnya hilang. Sertakan `...task` supaya data lain ikut terbawa.

## Soal Latihan & Jawaban
### Soal
Buat fungsi `handlePriorityChange(taskId, newPriority)` yang mengubah prioritas sebuah task secara immutable: temukan task-nya, buat object baru dengan spread, lalu "simpan" (cukup tampilkan object lama dan object baru ke Console memakai `JSON.stringify`). Uji pada task `{ id: 7, title: "Tulis dokumentasi", priority: "low", completed: false }` dengan `newPriority = "high"`.

### Jawaban
```js
// Data task tersimpan di manager (mini versi untuk percobaan)
const tasks = [{ id: 7, title: "Tulis dokumentasi", priority: "low", completed: false }];

function handlePriorityChange(taskId, newPriority) {
  const task = tasks.find((t) => t.id === taskId);
  if (!task) return; // task tidak ditemukan

  // Spread menyalin semua properti, lalu priority ditimpa nilai baru
  const updated = { ...task, priority: newPriority };

  console.log("lama :", JSON.stringify(task));
  console.log("baru :", JSON.stringify(updated));
}

handlePriorityChange(7, "high");
// lama : {"id":7,"title":"Tulis dokumentasi","priority":"low","completed":false}
// baru : {"id":7,"title":"Tulis dokumentasi","priority":"high","completed":false}
```
