# Handle Delete & Complete — Event Delegation + Manager

## Penjelasan
Task bisa dihapus dan ditandai selesai lewat tombol di tiap `<li>`. Masalahnya: `<li>` dibuat ulang terus oleh `renderTasks()`, jadi memasang listener langsung ke tiap tombol berarti memasang listener baru setiap kali render — boros dan rawan listener ganda.

Solusinya: **event delegation** (materi 48) — pasang SATU listener di `<ul id="taskList">`, elemen induk dari semua tombol. Saat tombol diklik, event "merambat" (bubbling) ke atas sampai `<ul>`, dan listener di `<ul>` menangkapnya. Dari `event.target` (elemen yang diklik) kita tahu tombol mana yang ditekan.

Alur di dalam callback:
- `event.target.closest(".task-item")` — naik ke atas dari elemen yang diklik sampai ketemu `<li>` pembungkus. Kalau tidak ketemu (misal klik area kosong), hentikan.
- `taskElement.getAttribute("data-id")` menghasilkan string `"1"`; ubah ke angka dengan `parseInt` karena id di manager bertipe number.
- `event.target.classList.contains("btn-delete")` → panggil `manager.deleteTask(id)`.
- `event.target.classList.contains("btn-complete")` → cari task-nya, lalu `manager.updateTask(id, { completed: !task.completed })` (toggle).
- Terakhir, `renderTasks()` agar tampilan mengikuti data.

## Fungsi
Delegation membuat kode hemat dan stabil: satu listener cukup untuk sebanyak apa pun jumlah item, dan tidak perlu dipasang ulang setelah render. Inilah cara umum menangani list dinamis di aplikasi nyata — tabel admin, feed media sosial, keranjang belanja.

## Cara Pengimplementasian / Code
```js
let taskList = document.getElementById("taskList");

taskList.addEventListener("click", (event) => {
  // cari <li> pembungkus; kalau tidak ketemu, berhenti
  let taskElement = event.target.closest(".task-item");
  if (!taskElement) return;

  // ambil id task dari atribut data-id, ubah ke number
  let taskId = parseInt(taskElement.getAttribute("data-id"));

  if (event.target.classList.contains("btn-delete")) {
    window.manager.deleteTask(taskId);   // hapus dari data
    renderTasks();                       // gambar ulang list
  } else if (event.target.classList.contains("btn-complete")) {
    // cari task lalu balik status completed (toggle)
    let task = window.manager.getTasks().find(t => t.id === taskId);
    window.manager.updateTask(taskId, { completed: !task.completed });
    renderTasks();
  }
});
```

Cara menjalankan: simpan di `level5.js` bersama `renderTasks()` dan `window.manager`. Buka `index.html` di browser (Live Server), tekan F12 → tab Console/Elements, lalu klik tombol Delete atau Complete pada task mana pun.

## Tracing Code (Step-by-Step)
Misal ada dua task: id 1 "Pinjam buku" (belum selesai) dan id 2 "Kembalikan buku" (sudah selesai). Kita klik **Delete** di task 2, lalu **Complete** di task 1.

**Kasus 1 — klik tombol Delete task 2**

**Langkah 1 — klik terjadi**
Browser membuat event `click`. `event.target` adalah tombol `.btn-delete` di dalam `<li>` task 2. Event merambat ke `<ul id="taskList">` dan callback kita jalan.

**Langkah 2 — `event.target.closest(".task-item")`**
Dari tombol, JS naik ke atas sampai ketemu `<li class="task-item" data-id="2">`. Hasilnya disimpan di `taskElement`.

**Langkah 3 — `getAttribute("data-id")` lalu `parseInt`**
`getAttribute` menghasilkan string `"2"`, lalu `parseInt` mengubahnya jadi angka `2`. Sekarang `taskId` bernilai `2`.

**Langkah 4 — cek `btn-delete`**
`classList.contains("btn-delete")` bernilai `true`, jadi `manager.deleteTask(2)` dijalankan: task id 2 dikeluarkan dari array dan localStorage.

**Langkah 5 — `renderTasks()`**
`<ul>` dikosongkan dan diisi ulang. Task 2 sudah tidak ada; tinggal task id 1.

**Kasus 2 — klik tombol Complete task 1**

**Langkah 6 — `closest`, `getAttribute`, `parseInt`**
Sama seperti langkah 1-3, tapi untuk task 1. Kali ini `classList.contains("btn-delete")` bernilai `false`, jadi alur jatuh ke `else if`.

**Langkah 7 — toggle status**
`getTasks().find(...)` menemukan task id 1 (`completed: false`). `updateTask(1, { completed: !false })` mengubahnya jadi `true` dan menyimpan ke localStorage.

**Langkah 8 — `renderTasks()`**
List digambar ulang. Task 1 kini punya class `completed` sehingga terlihat dicoret (sesuai CSS).

| Aksi | task id 1 | task id 2 |
|---|---|---|
| Sebelum | completed: false | completed: true |
| Klik Delete task 2 | ada, completed: false | terhapus |
| Klik Complete task 1 | completed: true | — |

**Output akhir:**
```
<ul id="taskList">
  <li class="task-item completed" data-id="1"><span>Pinjam buku</span> ...</li>
</ul>
```

## Analogi
Pustakawan tidak menempelkan pengawas di setiap kartu di papan pengumuman. Ia mengawasi SATU papan itu saja. Setiap kali ada pengunjung mencabut atau menempel kartu, pustakawan melihat nomor kartu (`data-id`) dan jenis aksinya — cabut berarti delete, coret berarti complete — lalu memperbarui katalog dan menulis ulang papan.

## Dipakai untuk Apa
- Menangani aksi tombol pada list yang isinya sering berubah: keranjang belanja, tabel admin, chat.
- Menghindari pemasangan listener berulang setiap render.
- Dasar pola "data berubah → tampilan dirender ulang" yang dipakai banyak framework.

## Kesalahan Umum yang Sering Terjadi
- **Pasang listener ke tiap tombol saat render**: Listener jadi ganda dan boros memory karena `<li>` dibuat ulang tiap render. Pakai satu delegation di `<ul>`.
- **Lupa `parseInt`**: `getAttribute` selalu mengembalikan string, jadi pembandingan `t.id === "2"` dengan id number `2` selalu `false` — task tidak pernah ditemukan. Selalu `parseInt` dulu.
- **Lupa `renderTasks()` setelah delete/complete**: Data berubah di manager tapi layar tidak berubah sampai refresh.
- **`closest` tidak dicek dulu**: Jika user mengklik area kosong di `<ul>`, `taskElement` bernilai `null` dan `getAttribute` akan error. Cek `if (!taskElement) return;` sebelum lanjut.

## Hubungan dengan Materi Sebelumnya
Konsep delegation datang dari **48. Event Delegation — Handle Multiple Elements**, pemakaian `event.target` dari **47. Event Object — target, type, preventDefault, stopPropagation**, dan pengecekan tombol lewat `classList` dari **45. Mengubah Attributes — setAttribute, getAttribute, classList**. Metode yang dipanggil (`deleteTask`, `updateTask`, `getTasks`) adalah CRUD dari **42. CRUD Methods dalam Class — addTask, getTasks, updateTask, deleteTask**. Setelah ini, materi **53. Form Validation — Client-side** menambahkan pemeriksaan input sebelum task masuk.

## Soal Latihan & Jawaban
### Soal
Sebelum task benar-benar dihapus, tampilkan dialog konfirmasi `confirm("Hapus task ini?")`. Jika user menekan **Cancel**, task tidak boleh dihapus dan tidak perlu render ulang. Terapkan hanya pada tombol Delete; tombol Complete tetap langsung menandai selesai tanpa konfirmasi.

### Jawaban
```js
let taskList = document.getElementById("taskList");

taskList.addEventListener("click", (event) => {
  let taskElement = event.target.closest(".task-item");
  if (!taskElement) return;

  let taskId = parseInt(taskElement.getAttribute("data-id"));

  if (event.target.classList.contains("btn-delete")) {
    // tanya dulu ke user; kalau batal, berhenti — jangan hapus apa pun
    if (!confirm("Hapus task ini?")) return;

    window.manager.deleteTask(taskId);
    renderTasks();
  } else if (event.target.classList.contains("btn-complete")) {
    let task = window.manager.getTasks().find(t => t.id === taskId);
    window.manager.updateTask(taskId, { completed: !task.completed });
    renderTasks();
  }
});
```
