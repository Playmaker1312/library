# Show dan Clear Error Messages — User Feedback

## Penjelasan
Validasi (materi 53) sudah tahu input salah di mana; tugas materi ini adalah **memberi tahu user lewat tampilan**. Tiga function kecil melakukan itu:

- `showError(message)` — menampilkan pesan error:
  - Cari `<div id="error">`; kalau belum ada, buat baru lewat `createErrorDiv()`.
  - Tulis pesan dengan `textContent` (lebih aman dari `innerHTML` karena tidak mengeksekusi HTML).
  - Tampilkan dengan `errorDiv.style.display = "block"`.
  - Tandai input: `taskInput.classList.add("error")` — nanti CSS yang mengatur tampilan merahnya.
- `clearError()` — membersihkan:
  - Sembunyikan `#error` dengan `style.display = "none"`.
  - Cabut penanda dari input: `taskInput.classList.remove("error")`.
- `createErrorDiv()` — membuat `<div id="error" class="error-message">`, menempelkannya ke `.input-group`, lalu mengembalikannya.

Pisahkan "kapan menampilkan" (tugas validasi, materi 53) dari "bagaimana menampilkan" (tugas materi ini). Function jadi bisa dipakai ulang di mana saja.

## Fungsi
Aplikasi yang diam-diam menolak input membuat user frustasi — mereka tidak tahu apakah aplikasinya rusak atau ketikannya yang salah. Pesan error yang jelas plus penanda visual (border merah) membuat aplikasi mudah dipakai dan terlihat profesional. Inilah yang dimaksud **user feedback**.

## Cara Pengimplementasian / Code
```js
let taskInput = document.getElementById("taskInput");

// buat elemen pesan error bila belum ada
function createErrorDiv() {
  let div = document.createElement("div");
  div.id = "error";
  div.className = "error-message";
  document.querySelector(".input-group").appendChild(div);
  return div;
}

// tampilkan pesan error
function showError(message) {
  let errorDiv = document.getElementById("error") || createErrorDiv();
  errorDiv.textContent = message;   // tulis pesan (teks biasa, aman)
  errorDiv.style.display = "block"; // tampilkan
  taskInput.classList.add("error"); // penanda merah di input
}

// sembunyikan pesan error
function clearError() {
  let errorDiv = document.getElementById("error");
  if (errorDiv) errorDiv.style.display = "none";
  taskInput.classList.remove("error"); // cabut penanda
}
```

Dengan CSS di `index.html`:
```css
.error-message { color: red; margin-top: 8px; }
input.error { border: 2px solid red; }
```

Cara menjalankan: simpan di `level5.js`. Buka `index.html` di browser (Live Server), tekan F12 → tab Console, ketik `showError("Task cannot be empty")` untuk melihat error muncul, lalu `clearError()` untuk menghilangkannya. Amati juga perubahannya di tab Elements.

## Tracing Code (Step-by-Step)
Kita telusuri `showError("Task cannot be empty")` diikuti `clearError()`. DOM awal: `#error` sudah ada (dari `index.html`) dengan `display: none`.

**Langkah 1 — `document.getElementById("error")`**
Elemen `#error` ketemu, jadi `|| createErrorDiv()` tidak dijalankan. `errorDiv` menunjuk ke `<div id="error">`.

**Langkah 2 — `errorDiv.textContent = "Task cannot be empty"`**
Isi `<div>` sekarang teks "Task cannot be empty". Di tab Elements terlihat teks itu muncul sebagai anak elemen.

**Langkah 3 — `errorDiv.style.display = "block"`**
`#error` yang tadinya `display: none` berubah jadi `block` — pesan terlihat di layar, di bawah tombol Add Task.

**Langkah 4 — `taskInput.classList.add("error")`**
`#taskInput` mendapat class `error`, sehingga CSS memberinya border merah. Di tab Elements: `<input id="taskInput" class="error">`.

**Langkah 5 — `clearError()` mulai, `if (errorDiv)`**
`#error` memang ada, jadi `errorDiv.style.display = "none"` dijalankan — pesan hilang dari layar.

**Langkah 6 — `taskInput.classList.remove("error")`**
Class `error` dicabut dari input dan border merah hilang. `classList` kini kosong.

| Panggilan | `#error` display | class `#taskInput` | Tampilan |
|---|---|---|---|
| awal | none | (kosong) | bersih |
| `showError(...)` | block | error | pesan merah + border merah |
| `clearError()` | none | (kosong) | bersih lagi |

**Output akhir:**
```
<div id="error" class="error-message" style="display: none;"></div>
<input id="taskInput" placeholder="Enter task...">  <!-- tanpa class error -->
```

## Analogi
Pustakawan menempel kertas catatan merah di formulir anggota yang salah isi, lengkap dengan alasannya. Begitu pengunjung memperbaiki formulir, kertas itu dicabut dan formulir diproses normal. Kertas dan pensil merah selalu tersedia di meja — tinggal dipakai saat ada yang salah.

## Dipakai untuk Apa
- Menampilkan pesan validasi di form login, registrasi, checkout.
- Notifikasi sukses/gagal (pola sama, hanya class-nya yang berbeda).
- Penanda visual fokus: input bermasalah diberi border merah atau background kuning.

## Kesalahan Umum yang Sering Terjadi
- **Pakai `innerHTML` untuk pesan**: `innerHTML = userInput` bisa mengeksekusi HTML berbahaya (XSS). Untuk teks biasa, selalu pakai `textContent`.
- **Lupa `clearError()`**: Setelah sekali error, pesan dan border merah menempel selamanya meski input sudah benar. Panggil `clearError()` saat input valid atau saat user mulai mengetik.
- **Membuat `<div>` error berulang kali**: `createErrorDiv()` dipanggil tanpa cek `getElementById` dulu sehingga ada banyak `#error` kembar. Cek dulu, buat hanya bila belum ada.
- **Mengandalkan `alert()` saja**: Dialog alert memblokir halaman dan hilang begitu diklik. Pesan inline di DOM lebih nyaman dan bisa dianimasikan.
