# Form Validation — Client-side

## Penjelasan
**Validasi** adalah pemeriksaan input sebelum data diproses lebih lanjut. **Client-side** berarti pemeriksaannya dilakukan di sisi pengguna (browser), bukan di server. Di Task Manager, validasi mencegah task kosong, task berisi spasi, dan task yang kepanjangan masuk ke manager.

Kuncinya adalah fungsi `validateTaskInput(title)` yang mengembalikan:
- **string pesan error** jika input tidak valid, contoh `"Task cannot be empty"`.
- **`null`** jika valid (tidak ada pesan yang perlu ditampilkan).

Mengembalikan pesan (bukan sekadar `true`/`false`) membuat pemanggilnya bisa langsung menampilkan alasan ke user. Aturan yang kita pakai:
- Input kosong atau hanya spasi → `"Task cannot be empty"`.
- Judul lebih dari 100 karakter → `"Task too long (max 100 characters)"`.
- Selain itu → valid.

Supaya lebih responsif, tombol Add juga bisa dinonaktifkan (`addBtn.disabled = true`) selama input belum valid, dengan memantau event `input` dari materi 47.

## Fungsi
Validasi menjaga kualitas data: tanpa task kosong, tanpa judul yang membanjiri tampilan. Ia juga membuat aplikasi terasa profesional — user langsung tahu apa yang salah, bukan kehilangan ketikan secara diam-diam atau melihat data aneh masuk ke list.

Validasi client hanya lapisan pertama. Untuk aplikasi berbasis server, server tetap harus memvalidasi ulang karena data dari client tidak bisa dipercaya. Untuk aplikasi localStorage seperti kita, client-side sudah cukup.

## Cara Pengimplementasian / Code
```js
function validateTaskInput(title) {
  // judul kosong atau hanya spasi
  if (!title || title.trim().length === 0) {
    return "Task cannot be empty";
  }
  // judul terlalu panjang
  if (title.trim().length > 100) {
    return "Task too long (max 100 characters)";
  }
  return null; // null berarti valid
}

let addBtn = document.getElementById("addBtn");
let taskInput = document.getElementById("taskInput");

addBtn.addEventListener("click", () => {
  let title = taskInput.value;
  let error = validateTaskInput(title); // periksa dulu

  if (error) {
    showError(error);   // tampilkan pesan (materi 54)
    return;             // hentikan alur, jangan tambah task
  }

  window.manager.addTask(title);
  taskInput.value = "";
  clearError();         // bersihkan pesan lama (materi 54)
  renderTasks();
});

// pantau input: tombol hanya aktif kalau input valid
taskInput.addEventListener("input", () => {
  addBtn.disabled = validateTaskInput(taskInput.value) !== null;
});
```

(`showError` dan `clearError` dibahas lengkap di materi 54.)

Cara menjalankan: simpan di `level5.js`. Buka `index.html` di browser (Live Server), tekan F12 → tab Console/Elements, lalu coba klik Add Task dengan input kosong, input spasi, input lebih dari 100 karakter, dan input normal.

## Tracing Code (Step-by-Step)
Kita telusuri dua percobaan: input kosong, lalu input valid.

**Percobaan 1 — klik Add Task dengan input kosong**

**Langkah 1 — `let title = taskInput.value;`**
Kolom input berisi `""`, jadi `title` bernilai `""`.

**Langkah 2 — `validateTaskInput("")`**
Cek pertama: `!title` bernilai `true` (string kosong itu "falsy"/dianggap tidak ada isinya). Fungsi langsung mengembalikan `"Task cannot be empty"`. Sekarang `error` berisi teks itu.

**Langkah 3 — blok `if (error)`**
Teks error bukan null, jadi dianggap benar → `showError("Task cannot be empty")` dijalankan: `#error` tampil dan input diberi class `error`. Lalu `return` menghentikan callback — `addTask` tidak pernah terpanggil.

**Percobaan 2 — user menulis "Belajar DOM" lalu klik Add Task**

**Langkah 4 — `validateTaskInput("Belajar DOM")`**
`trim()` menghasilkan `"Belajar DOM"` (panjang 10 karakter, tidak kosong). Kedua cek lolos, jadi fungsi mengembalikan `null`. Sekarang `error` bernilai `null`.

**Langkah 5 — blok `if (error)`**
`null` dianggap salah, jadi blok error dilewati. Alur lanjut: `manager.addTask("Belajar DOM")`, input dikosongkan, `clearError()` menyembunyikan `#error` dan mencabut class `error` dari input.

**Langkah 6 — `renderTasks()`**
List digambar ulang dan task baru muncul.

| Input | Nilai `error` | Tindakan |
|---|---|---|
| `""` | "Task cannot be empty" | pesan tampil, task tidak ditambah |
| `"   "` | "Task cannot be empty" | sama seperti di atas |
| 101 karakter | "Task too long..." | pesan tampil, task tidak ditambah |
| "Belajar DOM" | null | task ditambah, pesan dibersihkan |

**Output akhir (percobaan 2):**
```
<ul id="taskList">
  ... <li class="task-item" data-id="3"><span>Belajar DOM</span> ...</li>
</ul>
#taskInput value: "" (kosong)
#error: display none (tersembunyi)
```

## Analogi
Bayangkan petugas meja pendaftaran perpustakaan. Sebelum formulir anggota dicatat ke buku besar, ia mengecek isinya dulu: kolom kosong atau coretan tanpa isi dikembalikan dengan catatan "isi dulu", dan tulisan yang kepanjangan diminta diringkas. Baru formulir yang lolos dicatat.

## Dipakai untuk Apa
- Semua form web: login, registrasi, checkout, pencarian, unggah file.
- Mencegah data kotor masuk storage/database (lapisan pertama).
- Menampilkan respons real-time (tombol aktif/nonaktif) sebelum user submit.

## Kesalahan Umum yang Sering Terjadi
- **Hanya `if (!title)` tanpa `trim()`**: Input `"   "` dianggap valid dan masuk sebagai task tanpa nama. Selalu periksa `title.trim().length === 0`.
- **Validasi tanpa memberi tahu user**: Input ditolak tapi layar diam — user bingung ketikannya hilang ke mana. Selalu tampilkan pesan error (materi 54).
- **Tombol disabled permanen**: `addBtn.disabled = true` dipasang sekali tapi tidak pernah diaktifkan lagi. Pantau event `input` dan ubah `disabled` berdasarkan hasil validasi terbaru.
- **Mengandalkan validasi client untuk aplikasi multi-user**: Client bisa dimanipulasi lewat DevTools. Untuk aplikasi dengan server, ulangi validasi di server.

## Hubungan dengan Materi Sebelumnya
Sebelumnya, `addTask` di **42. CRUD Methods dalam Class — addTask, getTasks, updateTask, deleteTask** hanya menolak judul kosong secara internal. Materi ini memindahkan pemeriksaan ke depan — sebelum data masuk manager — sehingga user bisa diberi tahu alasannya. Pemakaian event `input` dan properti `disabled` berkaitan dengan **46. addEventListener — Attach Event Listener** dan **47. Event Object — target, type, preventDefault, stopPropagation**. Pesan error yang dihasilkan validasi ini baru ditampilkan ke DOM di materi **54. Show dan Clear Error Messages — User Feedback**.

## Soal Latihan & Jawaban
### Soal
Tambahkan satu aturan validasi: judul task tidak boleh sama persis (case-sensitive) dengan task yang sudah ada di manager. Gunakan `manager.getTasks().some(...)` — `some` mengembalikan `true` jika ada satu pun task yang judulnya cocok. Pesan errornya `"Task already exists"`. Uji lewat Console: tambahkan task "Belajar DOM", lalu coba validasi judul yang sama.

### Jawaban
```js
function validateTaskInput(title) {
  if (!title || title.trim().length === 0) {
    return "Task cannot be empty";
  }
  if (title.trim().length > 100) {
    return "Task too long (max 100 characters)";
  }
  // cek duplikat terhadap data yang sudah ada di manager
  let ada = window.manager.getTasks().some(t => t.title === title.trim());
  if (ada) {
    return "Task already exists";
  }
  return null; // valid
}

// uji cepat di tab Console:
manager.addTask("Belajar DOM");
console.log(validateTaskInput(""));             // "Task cannot be empty"
console.log(validateTaskInput("Belajar DOM"));  // "Task already exists"
console.log(validateTaskInput("Belajar CSS"));  // null (valid)
```
