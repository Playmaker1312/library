## 1. Penjelasan Singkat & Konsep Dasar

Dari Level 1 kita punya CLI TypeScript (Level 1-4). Sekarang kita berubah ke *aplikasi server*: **REST API** menggunakan **Express** + TypeScript. Express adalah framework HTTP paling populer untuk Node.

Konsep inti yang kita tanam:

```text
Alur request pada Express:
Client HTTP → Express app (routing middleware) → controller → service → repository → response JSON
```

Yang membuat "Express + TypeScript" menjadi menarik: **bahkan request/response menjadi typed**. Kombinasi ini memungkinkan API yang sepenuhnya safe:
- request body divalidasi **di runtime** (Zod, materi 20),
- tipe diperkuat di **compile-time** (interface, generics dari Level 2-4),
- response selalu punya struktur konsisten (`ApiResponse<T>`, materi 21).

**Struktur project (tingkatan layer) yang kita targetkan:**

```text
src/
├── index.ts            → entry (listen)
├── app.ts              → setup express
├── config/env.ts       → environment bertipe
├── types/              → tipe bersama + extend Express
├── middleware/         → errorHandler, validateRequest, authenticate
├── routes/             → definisi endpoint
├── controllers/        → penangan request/response
├── services/           → business logic
└── repositories/       → akses data (materi 15)
```

**Benang merah**: ini adalah *skip besar* — seluruh training di Level 1-4 (tipe, interface, class, generics, repository) kini dikokohkan dalam arsitektur nyata. Semua yang kamu bangun di API ini akan diuji di Level 6 (test) dan dihias ulang di Level 7 (React/Next.js memanggil API ini).

## 2. Fungsi & Kegunaan Utama

- **REST API**: endpoint `GET/POST/PUT/DELETE` untuk CRUD perpustakaan.
- **Type-safety di seluruh lapisan** — request body dijamin sesuai kontrak, response konsisten.
- **Testing-friendly arsitektur** — controller/service/repository terpisah (siap diuji di Level 6).
- **Environment typing** — tidak ada lagi "string kosong tak ketahuan di env".
- **Middleware typed** — auth, logging, error handling diekspresikan dengan tipe.

## 3. Contoh Kode & Implementasi (Real-world Example)

### Langkah 1 — Install dependency

```bash
# Dependencies runtime
npm install express
npm install zod cors helmet

# DevDependencies (types & tooling)
npm install --save-dev typescript @types/node @types/express @types/cors ts-node nodemon
```

### Langkah 2 — Struktur folder

```bash
mkdir -p src/{config,types,middleware,routes,controllers,services,repositories}
touch src/index.ts src/app.ts
```

### Langkah 3 — Config environment bertipe

```typescript
// src/config/env.ts
import "dotenv/config";

// Definisikan shape env secara eksplisit
interface Env {
    PORT: number;
    NODE_ENV: "development" | "production" | "test";
    ALLOWED_ORIGINS?: string;
}

function parseEnv(): Env {
    const port = Number(process.env.PORT ?? 3000);
    if (Number.isNaN(port)) throw new Error("PORT harus angka");
    return {
        PORT: port,
        NODE_ENV: (process.env.NODE_ENV as Env["NODE_ENV"]) ?? "development",
        ALLOWED_ORIGINS: process.env.ALLOWED_ORIGINS,
    };
}

export const env = parseEnv();
```

### Langkah 4 — Scripts package.json

```json
{
  "scripts": {
    "dev": "nodemon --exec ts-node src/index.ts",
    "build": "tsc",
    "start": "node dist/index.js",
    "type-check": "tsc --noEmit"
  }
}
```

### Langkah 5 — Entry point

```typescript
// src/index.ts
import { createApp } from "./app";
import { env } from "./config/env";

const app = createApp();

app.listen(env.PORT, () => {
    console.log(`🚀 API perpustakaan berjalan di http://localhost:${env.PORT}`);
});
```

## 4. Analogi Sederhana

**Sistem Perpustakaan.**

- **Express app** = **gedung perpustakaan dengan loket-loket**.
- **Routes** = **papan penunjuk** di lobi: `GET /api/buku` → "tunjukkan daftar buku", `POST /api/buku` → "daftarkan buku baru".
- **Controllers** = **petugas di loket** — menerima permintaan tamu dan memandunya ke proses yang benar, lalu menyerahkan hasilnya (response).
- **Services** = **aturan bisnis perpustakaan** (denda, batas pinjam) — otak di balik layar.
- **Repositories** = **gudang data** — tempat kartu katalog disimpan/dicari (implementasi dari materi 15).
- **Middleware** = **penjaga/pemeriksa di pintu**: memeriksa identitas (auth), memastikan format masuk valid (Zod), menangani kesalahan (error handler).
- **Type-safety** = **bangunan yang semua lantainya punya denah yang sama** — mulai dari pintu (request) sampai gudang (DB), jenis "barang" yang boleh lewat selalu diketahui.

## 5. Kapan Harus Digunakan (Use Cases)

- **Membangun REST API dengan Node** — terutama yang akan dikonsumsi frontend (materi 25-27).
- **Dari CLI ke server** — saat project mulai butuh berinteraksi dengan banyak client.
- **Arsitektur yang perlu diuji** — pemisahan layer memudahkan unit & integration test (Level 6).
- **Tim dengan kontrak API drs** — tipe & struktur endpoint dibagi dari awal.
- **Pengembangan bertahap yang aman** — API kecil dulu (`/api/v1/buku`), diperluas nanti.

## 6. Poin-poin Penting & Best Practices

1. **Selalu `strict: true`** — sekarang benar-benar "bernilai" karena banyak tipe lintas lapisan.
2. **Pisahkan `app.ts` (factory) dan `index.ts` (listen)** — `app.ts` bisa diimpor untuk test (supertest) di Level 6.
3. **Environment diparse & divalidasi di satu tempat** (`config/env.ts`) — tidak menyebar `process.env` di semua file.
4. **Gunakan `type-check` sebelum commit** — `tsc --noEmit` memastikan kontrak antar lapisan konsisten.
5. **Mulai dengan `cors` + `helmet`** sebagai baseline keamanan.
6. **Jangan memasukkan secrets di repo** — `.env` di `.gitignore`.

## 7. Kesalahan Umum (Common Pitfalls & Anti-patterns)

| Kesalahan | Contoh | Akibat | Perbaikan |
|---|---|---|---|
| Lupa `@types/express` | `import express` error / `Request` jadi `any` | safety hilang | `npm i -D @types/express` |
| Semua logic di controller | controller besar berisi query | tidak testable | pisah service/repository |
| `process.env` tersebar | salah pakai var env tanpa didefinisikan | bug runtime | parse terpusat di env.ts |
| Listen & app di file sama | sulit import app untuk test | test integration susah | pisahkan app.ts & index.ts |
| Strict dimatikan untuk "mudah" | request body jadi `any` | kontrak rusak di seluruh API | pertahankan strict |
| Melupakan error handler middleware | crash tidak ter-handle | `Cannot read...` raw ke client | buat errorHandler (materi 21) |

```typescript
// Soal 2
import "dotenv/config";

type NodeEnv = "development" | "production" | "test";

interface Config {
    PORT: number;
    NODE_ENV: NodeEnv;
    DATABASE_URL: string;
}

const DEFAULT_PORT = 3000;
const DEFAULT_DB = "postgres://localhost:5432/perpustakaan";

function loadEnv(): Config {
    const port = Number(process.env.PORT ?? DEFAULT_PORT);
    if (Number.isNaN(port) || port <= 0) {
        throw new Error("PORT tidak valid");
    }
    return {
        PORT: port,
        NODE_ENV: (process.env.NODE_ENV as NodeEnv) ?? "development",
        DATABASE_URL: process.env.DATABASE_URL ?? DEFAULT_DB,
    };
}

export const config = loadEnv();
```

**Pembahasan**: semua akses env terkumpul di satu tempat dan *divalidasi*; konsumen lain (app, service) hanya memakai `config.*` yang sudah bertipe & aman — menghindari `undefined` di tengah aplikasi.
