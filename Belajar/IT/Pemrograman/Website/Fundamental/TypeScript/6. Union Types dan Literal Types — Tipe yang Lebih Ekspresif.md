# 6. Union Types dan Literal Types — Tipe yang Lebih Ekspresif

> 🟢 **Level 1 — Bagian C** | 🧩 **Melanjutkan [[5. Primitive Types — Tipe Paling Dasar]]**

---

## 1. Penjelasan Singkat & Konsep Dasar

Primitive types (materi 5) hanya menyatakan *jenis* nilai. Kadang kita butuh lebih presisi:

- **Union Type (`|`)** — sebuah nilai boleh berupa **salah satu** dari beberapa tipe: `string | null`, `number | string`.
- **Literal Type** — sebuah nilai hanya boleh **tepat satu nilai tertentu**: `"Fiksi" | "Sains"` berarti nilainya *harus* literal `"Fiksi"` atau `"Sains"`, bukan string lain.

```text
string        → tipe luas: semua teks
"Fiksi"       → literal: khusus string "Fiksi"
string | null → union: string ATAU null
1 | 2 | 3     → union literal number
```

Konsep **Type Narrowing** adalah partner wajib dari union: karena nilai bisa beberapa tipe, TypeScript perlu "mempersempit" tebakan saat runtime berdasarkan kondisi (`typeof`, perbandingan) supaya kita bisa memakai nilai dengan aman.

**Benang merah**: materi 5 memberi kita primitif; materi ini membuat tipe *bermakna bisnis* (kategori, status) dan mempersiapkan **discriminated unions** yang akan dipakai besar-besaran di materi 11 dan seterusnya.

---

## 2. Fungsi & Kegunaan Utama

- **Menampung nilai opsional**: `string | null` untuk field yang boleh kosong.
- **Menampung nilai "dua jenis"**: `number | string` untuk ID yang bisa numerik atau ISBN teks.
- **Mengunci nilai yang valid**: `Kategori` dan `StatusPeminjaman` sebagai literal union — mencegah string acak masuk.
- **Template literal types**: menggabungkan literal jadi pola (misal `buku:ditambah`, `buku:diupdate`) — dasar sistem event yang type-safe di materi 24.
- **Narrowing**: memungkinkan kita membedakan cabang kode aman saat runtime.

---

## 3. Contoh Kode & Implementasi (Real-world Example)

```typescript
// src/types/union-literal.ts

// ─── Union Type: salah satu dari beberapa tipe ──────────────────────
let idBuku: number | string;
idBuku = 1;            // ✅
idBuku = "ISBN-001";   // ✅
// idBuku = true;       // ❌ boolean tidak dalam union

// Union + null — sangat umum; WAJIB dicheck
let pengarang: string | null = null;
pengarang = "Robert Martin";
if (pengarang !== null) {
    console.log(pengarang.toUpperCase());   // ✅ aman setelah guard
}
console.log(pengarang?.toUpperCase());       // ✅ optional chaining

// ─── Literal Types: nilai spesifik sebagai tipe ─────────────────────
// Autocomplete + pencegahan typo
type Kategori = "Fiksi" | "Non-Fiksi" | "Sains" | "Teknologi" | "Sejarah";

let kategori: Kategori = "Teknologi";    // ✅
// kategori = "Komik";                    // ❌ TS2322: "Komik" bukan kategori valid

// Literal number
let prioritas: 1 | 2 | 3 = 1;
// prioritas = 5;                         // ❌

// ─── Template Literal Types (TS 4.1+) ───────────────────────────────
type EventBuku = `buku:${"ditambah" | "diupdate" | "dihapus"}`;
let event: EventBuku = "buku:ditambah";    // ✅
// let salah: EventBuku = "buku:rusak";    // ❌

// ─── Type Narrowing: mempersempit tipe dalam kondisi ────────────────
function tampilkanId(id: number | string): string {
    if (typeof id === "number") {
        // Di sini TypeScript TAHU id adalah number
        return `#${id.toString().padStart(5, "0")}`;
    }
    // Setelah if, TypeScript tahu id adalah string
    return id.toUpperCase();
}

// Contoh pasar nyata: fungsi denda yang menerima durasi string ATAU number
function hitungDenda(durasi: number | string, dendaHarian: number): number {
    const hari = typeof durasi === "number" ? durasi : parseInt(durasi, 10);
    return Math.max(0, hari) * dendaHarian;
}
console.log(hitungDenda("7", 1000));   // 7000
console.log(hitungDenda(3, 1000));     // 3000
```

## 4. Analogi Sederhana

**Sistem Perpustakaan.**

- **Union type** seperti **loker dengan beberapa ukuran kunci**: kunci bernomor (number) *atau* kartu ISBN (string) keduanya boleh membukanya. Pustakawan memperbolehkan dua jenis identitas.
- **Literal type** seperti **daftar kategori resmi di papan pengumuman**: "Sains", "Teknologi", "Fiksi". Jika seorang mengajukan "Komik"?
  - Di perpustakaan ber-*literal type*, itu **ditolak di pintu** sebelum masuk rak — tidak ada rak dengan label itu.
  - Di perpustakaan *tanpa* literal (semua `string`), "Komik" masuk — dan baru ketahuan saat ada yang mencari "Sains" tapi tidak menemukan.
- **Narrowing** seperti **petugas yang bertanya lebih dulu**: "Ini kunci nomor atau kartu?" — lalu memilih meja pendaftaran yang benar, sehingga kartu tidak dirusak dan kunci tidak dicoba di lubang yang salah.

---

## 5. Kapan Harus Digunakan (Use Cases)

- **Union `T | null`** — setiap field yang boleh kosong (dengan strict, ini wajib dieksplisitkan).
- **Union untuk ID / identitas fleksibel** — API yang menerima ID numerik atau string (kode / slug).
- **Literal union untuk enumerasi domain** — kategori buku, status peminjaman, role pengguna, ukuran UI (`"sm" | "md" | "lg"`), arah sort (`"asc" | "desc"`).
- **Template literal types** — pola event (`onClick`), route pattern, prefix kode (`user:`), yang ingin tetap type-safe.
- **Discriminated union (fokus materi 11)** — kombinasi union + literal `type` untuk model state (misal `{ status: "loading" } | { status: "success"; data } | { status: "error"; message }`).

---

## 6. Poin-poin Penting & Best Practices

1. **Literals menangkap typo dan nilai ilegal di compile-time** — gunakan daripada `string` untuk hal yang sudah dikenal (kategori, status).
2. **Gunakan type alias untuk union yang dipakai berulang** (di materi 9 dibahas mendalam) — jangan tulis panjang union berkali-kali.
3. **Narrowing harus datang sebelum akses** — `if (x !== null)`, `switch (tipe)`, `typeof`. Dengan strict, TS menggiringmu ke sana.
4. **`??` (nullish) hanya menyentuh null/undefined**, bukan falsy (`0`, `""`). Jangan salah menerapkan pada stok yang bisa `0`.
5. **`as const` adalah shortcut literal** — `const kategori = ["Fiksi","Sains"] as const` menghasilkan literal tuple, berguna untuk membuat literal union sekaligus.
6. **Exhaustive check**: pada switch/if dari discriminated unions, beri default `never` untuk menjamin setiap case ditangani (rinci di materi 11).

---

## 7. Kesalahan Umum (Common Pitfalls & Anti-patterns)

| Kesalahan | Contoh | Akibat | Perbaikan |
|---|---|---|---|
| Literal terlalu luas | `let k: string = "Fiksi"` padahal hanya 4 kategori | nilai ilegal lolos | gunakan literal union |
| Lupa narrow union – null | `x.toUpperCase()` pada `string \| null` | TS18047 | guard / `??` / `?.` |
| `??` vs `\|\|` tertukar | `stok \|\| 10` padahal stok 0 valid | 0 jadi 10 | pakai `??` untuk null/undefined |
| Semua jadi `any` | `(id as any)` agar "cepat" | normalisasi: nilai ilegal lolos | narrowing atau cast presisi |
| Switch tanpa exhaustive | `default:` diabaikan | case baru tidak tertangkap | `default` + `assertNever` |
| Annotate literal di variabel `let` | `let k: "Fiksi" = ...; k = "Sains"` | baik tapi membatasi; perlu diperbarui manual | biarkan infer bila berubah |

## 8. Soal Latihan & Kunci Jawaban

### Soal 1
Definisikan tipe `StatusPeminjaman = "dipinjam" | "dikembalikan" | "terlambat" | "hilang"`, lalu tulis fungsi `warnaStatus(status)` yang menampilkan `"dikembalikan" | "terlambat"` dengan hijau/kuning/merah dan yang lain abu-abu — sempurnakan dengan `switch` dan pastikan *exhaustive* (kasus default melempar `never`).

### Soal 2
Buat fungsi `tampilkanHarga(harga: number | string): string`:
- jika `number`, tampilkan `Rp ${harga.toLocaleString("id-ID")}`,
- jika `string`, konversi dengan `Number(...)` lalu format, dan hadirkan penanganan bila tidak valid.

### Jawaban & Pembahasan

```typescript
// Soal 1
type StatusPeminjaman = "dipinjam" | "dikembalikan" | "terlambat" | "hilang";

function assertNever(nilai: never): never {
    throw new Error(`Status tidak terduga: ${JSON.stringify(nilai)}`);
}

function warnaStatus(status: StatusPeminjaman): string {
    switch (status) {
        case "dipinjam":   return "biru";
        case "dikembalikan": return "hijau";
        case "terlambat":  return "kuning";
        case "hilang":     return "merah";
        default:           return assertNever(status); // exhaustive
    }
}
console.log(warnaStatus("dipinjam"), warnaStatus("hilang")); // biru merah
```

**Pembahasan**: `default: return assertNever(status)` memastikan jika di masa depan kita menambah nilai literal ke `StatusPeminjaman` tetapi lupa menambah case, TypeScript akan *error* — pengawasan exhaustive.

```typescript
// Soal 2
function tampilkanHarga(harga: number | string): string {
    const angka = typeof harga === "number" ? harga : Number(harga);
    if (!Number.isFinite(angka)) {
        return "Harga tidak valid";
    }
    return `Rp ${angka.toLocaleString("id-ID")}`;
}

console.log(tampilkanHarga(150000));  // Rp 150.000
console.log(tampilkanHarga("175000"));// Rp 175.000
console.log(tampilkanHarga("abc"));   // Harga tidak valid
```

**Pembahasan**: narrowing `typeof harga === "number"` menentukan percabangan; selain itu kita *juga* menangani data string yang tak dapat dikonversi — contoh nyata ketika input datang dari form/API.
