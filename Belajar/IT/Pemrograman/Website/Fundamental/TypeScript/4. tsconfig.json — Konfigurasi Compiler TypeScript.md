# 4. tsconfig.json — Konfigurasi Compiler TypeScript

> 🟢 **Level 1 — Bagian B** | 🧩 **Melanjutkan [[3. Instalasi dan Setup Project Perpustakaan]]**

---

## 1. Penjelasan Singkat & Konsep Dasar

`tsconfig.json` adalah **"remote control" compiler TypeScript**. Ia memberi tahu `tsc`: *file mana yang dikompilasi, JavaScript versi apa yang dihasilkan, seberapa ketat type-checking-nya, ke mana output-nya.*

Tanpa tsconfig, `tsc` harus dipanggil per file dan memakai default yang longgar. Dengan tsconfig, satu file konfigurasi berlaku untuk seluruh project — inilah yang membuat TypeScript *predictable* di tangan semua anggota tim.

Konsep inti yang dibawa dari materi 3:

```text
materi 3: tsc berjalan
materi 4: KONTROL tsc — target, module, strictness, output
```

Tiga "kenop" paling penting yang akan kita atur:

| Opsi | Arti | Contoh nilai |
|---|---|---|
| `target` | JS versi mana yang dihasilkan | `"ES2022"` |
| `module` | sistem module apa | `"CommonJS"` (Node) / `"ESNext"` (browser) |
| `strict` | apakah type checking diperketat (termasuk null checks) | `true` |

**Benang merah**: dari materi 1 kamu tahu TS = JS + tipe. tsconfig adalah tempat kita memutuskan **sekuat apa** compiler "menolak" kode aneh. Kita (dan seluruh roadmap ini) memilih yang paling ketat: `strict: true`.

---

## 2. Fungsi & Kegunaan Utama

- **Konsistensi project**: satu sumber kebenaran untuk cara kompilasi di semua machine/developer/CI.
- **Mengaktifkan penjagaan tipe yang ketat** (`strict`), yang menangkap kelas bug null/any yang paling sering terjadi di JS.
- **Memisahkan source dan build output** via `rootDir`/`outDir`.
- **Mengaktifkan fitur `strictNullChecks`** agar null/undefined harus ditangani eksplisit — fondasi keamanan yang dipakai di materi 5-11.
- **Mendukung pengaturan import/path (`paths`)** — dasar arsitektur besar di Level 5-7.

## 3. Contoh Kode & Implementasi (Real-world Example)

### Generate file dengan default

```bash
npx tsc --init
```

Lalu ganti isinya dengan konfigurasi yang direkomendasikan untuk project Node (perpustakaan):

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "CommonJS",
    "lib": ["ES2022"],

    "outDir": "./dist",
    "rootDir": "./src",

    "strict": true,
    "noUnusedLocals": true,
    "noUnusedParameters": true,
    "noImplicitReturns": true,
    "noFallthroughCasesInSwitch": true,

    "moduleResolution": "node",
    "esModuleInterop": true,
    "resolveJsonModule": true,
    "forceConsistentCasingInFileNames": true,

    "sourceMap": true,

    "baseUrl": ".",
    "paths": {
      "@/*": ["src/*"]
    }
  },
  "include": ["src/**/*"],
  "exclude": ["node_modules", "dist", "**/*.test.ts"]
}
```

Demostrasi bahwa `strict` berpengaruh — buat dua file kecil:

```typescript
// src/cek.ts
// Dengan strict: true, akses null DITOLAK saat compile:
function tampilkanPengarang(pengarang: string | null): void {
    // console.log(pengarang.toUpperCase()); // ❌ TS18047: 'pengarang' is possibly 'null'
    if (pengarang !== null) {
        console.log(pengarang.toUpperCase()); // ✅ guard membuat aman
    }
}
```

```bash
npx tsc --noEmit   # 0 error ✓
# Coba hapus if guard → npx tsc --noEmit → error TS18047
```

## 4. Analogi Sederhana

**Sistem Perpustakaan.**

`tsconfig.json` adalah **peraturan internal perpustakaan** yang tertulis di papan pengumuman di pintu masuk — berlaku untuk semua pustakawan:

- **`target`** = *bahasa apa yang dipakai untuk menulis label buku* (misal tidak pakai ESM, tapi CommonJS) — menentukan "buku baru" (output JS) dalam format apa.
- **`outDir`/`rootDir`** = *ruang mana sumber kartu (src) dan ruang mana hasil fotokopi (dist)* — menjaga gudang tetap rapi.
- **`strict`** = *aturan "kartu katalog harus lengkap, tidak boleh ada kolom kosong/null"*. Jika seorang pustakawan mencatat `pengarang: null` lalu mengakses `pengarang.toUpperCase()`, aturan ini menolak kartu itu sebelum masuk rak.
- **`include`/`exclude`** = *rak mana yang dipindai* (semua di `src/`), dan mana yang diabaikan (`node_modules`).

Intinya: **tanpa peraturan, tiap pustakawan mencatat seenaknya; tsconfig membuat semua kartu ditulis menurut standar yang sama** — dan standar teraman (strict) dipilih.

## 5. Kapan Harus Digunakan (Use Cases)

- **Pembuatan setiap project TS** sejak hari pertama (bukan nanti). Ini keputusan "sulit diubah nanti", jadi pasang benar sejak awal.
- **Proyek kecil sampai monorepo**: tsconfig bisa di-extends antar project (contoh `extends: "./tsconfig.base.json"`).
- **Menyesuaikan lingkungan (environment)**:
  - Node backend → `module: "CommonJS"`, `lib: ["ES2022"]`.
  - Browser/React → `module: "ESNext"`, `jsx: "react-jsx"`, `lib: ["ES2022", "DOM"]`.
- **CI / pre-commit** → `tsc --noEmit` (type-checking tanpa menghasilkan file).
- **Library**: `declaration: true` untuk menghasilkan `.d.ts` publik.

---

## 6. Poin-poin Penting & Best Practices

1. **`strict: true` selalu — tidak ada kompromi** (aturan emas roadmap ini). Aktifkan di Level 1 dan tidak pernah dimatikan.
2. **Pahami bahwa `strict` mengaktifkan beberapa sub-flag sekaligus** — termasuk `strictNullChecks` (null harus ditangani), `noImplicitAny` (dilarang any tersembunyi), `strictPropertyInitialization` (property class harus diinisialisasi).
3. **`noUnusedLocals` + `noUnusedParameters`** mendeteksi kode mati.
4. **`noImplicitReturns`** memastikan semua jalur fungsi mengembalikan nilai.
5. **`esModuleInterop: true`** — wajib agar `import express from "express"` (default import) berfungsi dengan library CommonJS.
6. **Sering jalankan `tsc --noEmit`** daripada `tsc` yang menghasilkan file, supaya tidak menumpuk `dist`.
7. **Konsisten casing `forceConsistentCasingInFileNames`** mencegah bug import di Windows/macOS/Linux.

## 7. Kesalahan Umum (Common Pitfalls & Anti-patterns)

| Kesalahan | Gejala | Perbaikan |
|---|---|---|
| `strict` dimatikan | bug null/undefined lolos ke runtime | set `"strict": true` |
| Lupa `esModuleInterop` | `import x from "pkg"` error TS1259 | tambahkan `"esModuleInterop": true` |
| `outDir`/`rootDir` salah | output tidak terstruktur / `tsc` komplain memo rootDir | samakan struktur: `src/` & `dist/` |
| Mengetik `tsc file.ts` per file | mengabaikan tsconfig (strict dimatikan, paths tidak ada) | gunakan `npx tsc` saja |
| `include` tidak mencakup folder | file baru "tidak ter-compile" / tak tertangkap | `"include": ["src/**/*"]` |
| Mematikan error daripada memperbaiki | banyak `// @ts-ignore` | perbaiki tipe; `@ts-ignore` untuk kasus batas yang diketahui |

## 8. Soal Latihan & Kunci Jawaban

### Soal 1
Tulis konfigurasi tsconfig minimal untuk project Node yang:
- menargetkan ES2022, module CommonJS,
- output ke `dist`, source di `src`,
- **strict aktif**,
- mengaktifkan `noImplicitReturns`,
- mengaktifkan `esModuleInterop`.

### Soal 2
Apa yang terjadi jika kode berikut dikompilasi dengan `strict: true`? Perbaiki dengan dua cara berbeda (guard + nullish coalescing) dan tunjukkan bahwa `--noEmit` berhasil.

```typescript
function tampilkanKategori(kategori: string | null): void {
    console.log(kategori.toUpperCase()); // ?
}
```

---

### Jawaban & Pembahasan

**Soal 1 — tsconfig.json**

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "CommonJS",
    "outDir": "./dist",
    "rootDir": "./src",
    "strict": true,
    "noImplicitReturns": true,
    "esModuleInterop": true,
    "moduleResolution": "node"
  },
  "include": ["src/**/*"]
}
```

**Soal 2 — analisis & perbaikan**

Kode tersebut menghasilkan **TS18047** (`'kategori' is possibly 'null'`) karena `strict` mengaktifkan `strictNullChecks`. Dua perbaikan:

```typescript
// Perbaikan 1: guard dengan if
function tampilkanKategori(kategori: string | null): void {
    if (kategori !== null) {
        console.log(kategori.toUpperCase());
    }
}

// Perbaikan 2: nullish coalescing (??) — nilai default
function tampilkanKategori2(kategori: string | null): void {
    const hasil = (kategori ?? "Tanpa Kategori").toUpperCase();
    console.log(hasil);
}
```

**Pembahasan**: setelah perbaikan, `npx tsc --noEmit` mengembalikan 0 error. Ini justru *fitur* — TypeScript menahan kita dari `null.toUpperCase()` crash di runtime, yang persis jenis bug yang diceritakan di [[2. Mengapa TypeScript? — Masalah yang Dipecahkan]].
