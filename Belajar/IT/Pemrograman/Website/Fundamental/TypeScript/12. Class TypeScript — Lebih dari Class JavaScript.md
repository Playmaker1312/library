# 12. Class TypeScript — Lebih dari Class JavaScript

> 🟡 **Level 3 — Bagian F** | 🧩 **Melanjutkan [[11. Type Guards — Mempersempit Tipe Saat Runtime]]**

---

## 1. Penjelasan Singkat & Konsep Dasar

Di Level 2, **interface** memberi *bentuk* data. Namun interface **tidak punya perilaku** — ia hanya statis. Untuk entitas yang *melakukan sesuatu* (meminjam, menghitung denda, mengecek stok), kita butuh **class**: object yang memuat **data (property)** DAN **perilaku (method)**.

TypeScript menambahkan di atas class JavaScript:

```text
interface   → kontrak bentuk data (materi 8)
class       → kontrak + implementasi + perilaku
             + access modifiers: public / private / protected
             + readonly property
             + parameter properties (materi 13)
             + abstract class (materi 13)
             + implements (class mengikuti interface)
             + static method
```

**Konsep access modifiers (materi ini)**:

| Modifier | Bisa diakses dari | |
|---|---|---|
| `public` | mana saja | (default) |
| `private` | hanya di dalam class ini | |
| `protected` | di dalam class ini + class turunan | |
| `readonly` | bisa dibaca semua, tidak bisa diubah | |

**Benang merah**: materi 8 memberi kontrak (`interface`), materi 12 menambahkan *implementasi* berperilaku — jembatan ke *OOP + repository* (materi 13, 15) dan seterusnya di Level 5 (services, controllers) dan 7 (React hooks adalah kelas yang sama diformat lain).

---

## 2. Fungsi & Kegunaan Utama

- **Menggabungkan data + logika** pada satu entitas domain (`Buku.pinjam()`, `Buku.tersedia()`).
- **Enkapsulasi** — menyembunyikan detail (`private _stok`) dan memaparkan API yang aman (getter/setter).
- **Invariants** — mencegah state tidak valid (stok negatif ditolak di setter).
- **Reuse via inheritance** — class turunan mewarisi perilaku parent (materi 13: `Admin extends Anggota`).
- **Contract dengan interface** — `class implements X` menjamin bentuk & method.
- **Static utilities** — `Buku.fromJSON(data)` membuat instance dari data eksternal.

## 3. Contoh Kode & Implementasi (Real-world Example)

```typescript
// src/models/Buku.ts
import type { Kategori } from "../types/aliases";

class Buku {
    // ─── Access modifiers ────────────────────────────────────────────
    readonly id: number;          // hanya bisa dibaca, tidak berubah
    public judul: string;
    public pengarang: string;
    public isbn: string;
    public tahun: number;
    public harga: number;
    private _stok: number;        // private → dikendalikan getter/setter
    public kategori: Kategori;
    public deskripsi?: string;
    private readonly createdAt: Date;

    constructor(
        id: number, judul: string, pengarang: string, isbn: string,
        tahun: number, harga: number, stok: number,
        kategori: Kategori, deskripsi?: string,
    ) {
        this.id = id;
        this.judul = judul;
        this.pengarang = pengarang;
        this.isbn = isbn;
        this.tahun = tahun;
        this.harga = harga;
        this._stok = stok;
        this.kategori = kategori;
        this.deskripsi = deskripsi;
        this.createdAt = new Date();
    }

    // ─── Getter: akses _stok dengan penjagaan ────────────────────────
    get stok(): number {
        return this._stok;
    }

    // ─── Setter: validasi sebelum set ────────────────────────────────
    set stok(nilai: number) {
        if (nilai < 0) throw new Error("Stok tidak bisa negatif");
        this._stok = nilai;
    }

    tersedia(): boolean {
        return this._stok > 0;
    }

    pinjam(): void {
        if (!this.tersedia()) {
            throw new Error(`Buku "${this.judul}" tidak tersedia`);
        }
        this._stok--;
    }

    kembalikan(): void {
        this._stok++;
    }

    formatHarga(): string {
        return `Rp ${this.harga.toLocaleString("id-ID")}`;
    }

    // ─── Static method: dipanggil dari CLASS, bukan instance ─────────
    static fromJSON(data: unknown): Buku {
        if (!adalahDataBuku(data)) {
            throw new Error("Data buku tidak valid");
        }
        return new Buku(
            data.id, data.judul, data.pengarang, data.isbn,
            data.tahun, data.harga, data.stok, data.kategori as Kategori,
        );
    }

    toJSON(): Record<string, unknown> {
        return {
            id: this.id, judul: this.judul, pengarang: this.pengarang,
            isbn: this.isbn, tahun: this.tahun, harga: this.harga,
            stok: this._stok, kategori: this.kategori,
            deskripsi: this.deskripsi,
        };
    }
}

// Type guard untuk data eksternal (bisa diganti Zod di Level 5)
function adalahDataBuku(data: unknown): data is {
    id: number; judul: string; pengarang: string; isbn: string;
    tahun: number; harga: number; stok: number; kategori: string;
} {
    return (
        typeof data === "object" && data !== null &&
        "id" in data && typeof (data as { id: unknown }).id === "number" &&
        "judul" in data && typeof (data as { judul: unknown }).judul === "string"
    );
}

// ─── Pemakaian ──────────────────────────────────────────────────────
const buku = Buku.fromJSON({
    id: 1, judul: "Clean Code", pengarang: "Robert Martin",
    isbn: "9780132350884", tahun: 2008, harga: 150000, stok: 5,
    kategori: "Teknologi",
});
console.log(buku.tersedia());   // true
buku.pinjam();
console.log(buku.stok);         // 4 (lewat getter)
console.log(buku.formatHarga()); // "Rp 150.000"
```

## 4. Analogi Sederhana

**Sistem Perpustakaan.**

- **Class** seperti **prosedur & SOP untuk sebuah buku di perpustakaan**: buku bukan hanya data (judul, stok) tetapi juga **perilaku** — bisa dipinjam (`pinjam()`), bisa dikembalikan (`kembalikan()`), bisa didefinisikan "tersedia" (`tersedia()`).
- **`private _stok`** = **buku besar internal** yang *hanya* petugas gudang boleh menyentuh. Anggota tidak bisa langsung mengubah stok; harus lewat *loket* (method `pinjam`/`kembalikan`).
- **Getter/setter** = **loket pelayanan**: "Berapa stok buku X?" (getter) → petugas membacakan. "Ubah stok jadi -5?" (setter) → petugas *menolak* karena angka negatif tidak masuk akal.
- **`readonly id`** = **nomor registrasi** yang tercetak permanen — tidak bisa diubah setelah pembuatan kartu.
- **`static fromJSON`** = **petugas konversi kartu lama → kartu baru**: format data lama (JSON) disulap jadi kartu katalog modern `Buku`. Dipanggil dari "kantor pusat" (class), bukan dari kartu individual.
- **`protected`** dan **turunan** akan kita lihat di materi 13 (`Admin extends Anggota`).

## 5. Kapan Harus Digunakan (Use Cases)

- **Entitas domain dengan logika bisnis**: Buku (pinjam/kembali), Peminjaman (hitung denda), Anggota (batas pinjam).
- **Model yang perlu memvalidasi invariants** (stok tak negatif, batas pinjam) — getter/setter/private menjaga konsistensi.
- **Abstraksi repository / service** (materi 15, Level 5) — `BukuRepository`, `BukuService` sebagai class.
- **Factory/static methods** untuk membuat instance dari data luar (JSON, API).
- **Kapan TIDAK perlu class**: data polos tanpa perilaku cukup `interface` + object (Level 2); fungsi murni bisa lebih baik daripada class dengan satu method.

---

## 6. Poin-poin Penting & Best Practices

1. **Default `public`** — eksplisitkan `private`/`protected` saat diperlukan; jangan buka semua internal.
2. **Gunakan getter/setter untuk validasi** — jangan `public stok: number` bila stok punya aturan.
3. **`readonly` untuk field yang tak boleh berubah** setelah dibuat (id, createdAt) — diterapkan di compile-time.
4. **Sembunyikan detail (`private`) & ekspos minimal** — prinsip *least privilege*; state diubah lewat method domain.
5. **`static` untuk fungsi yang tidak butuh instance** — factory, konversi.
6. **Jangan semua jadi class** — untuk struktur data statis, `interface` (materi 8) lebih ringan dan sederhana.
7. **Guard data eksternal sebelum masuk class** (misal `fromJSON`) — prinsip yang sama dengan Zod (Level 5).

## 7. Kesalahan Umum (Common Pitfalls & Anti-patterns)

| Kesalahan | Contoh | Akibat | Perbaikan |
|---|---|---|---|
| Semua field `public` tanpa getter/setter | `stok` bisa di-set -5 dari luar | invariant rusak | getter/setter + private |
| Lupa deklarasi property (di JS) | menggunakan `this.x` tanpa deklarasikan | TS2339 | deklarasikan field (atau pakai parameter properties) |
| `readonly` di-*runtime*-bagian | mutasi via method yang lupa | tak terdeteksi sampai berjalan | jadikan tidak readonly bila berubah |
| Overuse class | 10 class dengan 1 method tiap | kompleks | gunakan function/interface |
| Static method diakses via instance | `buku.fromJSON(...)` | TS2576 | panggil lewat `Buku.fromJSON` |
| Getter tanpa setter | `get createdAt()` | hanya-baca — kadang memang diinginkan | pertimbangkan konsisten |

## 8. Soal Latihan & Kunci Jawaban

### Soal 1
Buat class `Buku` dengan:
- `readonly id: number`, `judul: string`, `private _stok: number`,
- getter `stok`, setter `stok` yang menolak nilai negatif,
- method `pinjam()` yang menolak bila stok habis dan mengurangi 1,
- method `kembalikan()` menambah 1.

### Soal 2
Mengapa getter/setter lebih aman daripada field `public stok: number` untuk bisnis perpustakaan? Beri satu contoh bug yang bisa terjadi tanpa proteksi.

---

### Jawaban & Pembahasan

```typescript
// Soal 1
class Buku {
    readonly id: number;
    judul: string;
    private _stok: number;

    constructor(id: number, judul: string, stok: number) {
        this.id = id;
        this.judul = judul;
        this._stok = stok;
    }

    get stok(): number {
        return this._stok;
    }

    set stok(nilai: number) {
        if (nilai < 0) throw new Error("Stok tidak bisa negatif");
        this._stok = nilai;
    }

    pinjam(): void {
        if (this._stok <= 0) throw new Error(`Buku "${this.judul}" habis`);
        this._stok--;
    }

    kembalikan(): void {
        this._stok++;
    }
}

const b = new Buku(1, "Clean Code", 2);
b.pinjam();
console.log(b.stok);          // 1
// b.stok = -5;               // ❌ throw "Stok tidak bisa negatif"
```

**Pembahasan**: setter memastikan tidak ada stok negatif — state class selalu konsisten dari *cara mana pun* diubah.

**Soal 2 — penjelasan**: dengan `public stok: number`, kode luar bisa `buku.stok = -3` tanpa pemberitahuan; kartu "tersedia: -3" akan muncul dan `pinjam()` mungkin memberi hasil aneh (misal `stok--` pada 0 menghasilkan -1). Getter/setter memusatkan *satu* tempat validasi — seluruh aplikasi melewati aturan yang sama. Inilah *invariant* yang dijamin oleh enkapsulasi.
