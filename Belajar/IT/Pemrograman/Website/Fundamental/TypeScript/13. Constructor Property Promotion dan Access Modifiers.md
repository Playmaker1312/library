## 1. Penjelasan Singkat & Konsep Dasar

Materi 12 memperkenalkan modifer akses (`public`/`private`/`protected`) dan `readonly`. Materi 13 memperkenalkan **Constructor Parameter Properties** — sintaks TypeScript yang *memangkas boilerplate*: daripada menulis field + assign di constructor secara terpisah, kamu mendeklarasikan dan menetapkan **dalam satu ekspresi parameter constructor**.

```typescript
// Tanpa parameter properties (verbose) — versi "lama"
class Anggota {
    readonly id: number;
    public nama: string;
    private _password: string;

    constructor(id: number, nama: string, _password: string) {
        this.id = id;
        this.nama = nama;
        this._password = _password;
    }
}

// Dengan parameter properties — satu parameter = satu deklarasi field
class Anggota {
    constructor(
        public readonly id: number,   // otomatis menjadi property!
        public nama: string,
        private _password: string,
    ) {}
}
```

**Aturan**: tambahkan modifier (`public`, `private`, `protected`, `readonly`, atau kombinasi `public readonly`) di *depan* parameter constructor — TypeScript otomatis mendeklarasikan field + assignment di constructor.

**Konsep tambahan di materi ini**:
- **Parameter default** (`role: RolePengguna = "anggota"`) tetap bisa dikombinasikan.
- **`super()`** memanggil constructor parent.
- **Abstract class** — template yang tidak bisa di-instantiate, dengan method konseptual `abstract` yang wajib diimplementasikan turunan.

**Benang merah**: materi 12 memberi `class` + modifiers. Materi 13 menyempurnakan sintaksnya (promotion) dan menutup konsep inheritance + abstraksi — dasar OOP penuh sebelum Generics (materi 14).

## 2. Fungsi & Kegunaan Utama

- **Mengurangi boilerplate** — deklarasi+assignment satu baris, kode lebih padat & mudah dibaca.
- **Konsistensi modifiers** — tidak ada lagi "declared but forgot to init".
- **`protected`** memungkinkan akses dari class turunan (tapi tidak publik).
- **`readonly` mencegah mutasi setelah konstruksi**.
- **Abstract class** memberikan *template* wajib (`abstract method`) sekaligus implementasi bersama yang bisa dipakai ulang.
- **`%hooks` React/Vue* juga memanfaatkan banyak konsep mirip yang familier.

## 3. Contoh Kode & Implementasi (Real-world Example)

```typescript
// src/models/Anggota.ts

type RolePengguna = "admin" | "pustakawan" | "anggota";

class Anggota {
    constructor(
        public readonly id: number,                       // param property
        public nama: string,
        public email: string,
        private _password: string,                        // rahasia
        protected role: RolePengguna = "anggota",         // default
        private pinjaman: Buku[] = [],                    // koleksi privat
    ) {}

    verifikasiPassword(kataSandi: string): boolean {
        return this._password === kataSandi;   // tiruan bcrypt compare
    }

    getBatasPinjam(): number {
        return this.role === "admin" ? Infinity : 5;
    }

    pinjamBuku(buku: Buku): void {
        if (this.pinjaman.length >= this.getBatasPinjam()) {
            throw new Error(`Batas peminjaman ${this.getBatasPinjam()} tercapai`);
        }
        buku.pinjam();
        this.pinjaman.push(buku);
    }

    getPinjaman(): readonly Buku[] {
        return [...this.pinjaman];   // copy, bukan referensi asli
    }
}

// ─── Turunan — Admin extends Anggota ────────────────────────────────
class Admin extends Anggota {
    constructor(id: number, nama: string, email: string, password: string) {
        super(id, nama, email, password, "admin");  // panggil parent constructor
    }

    hapusBuku(bukuId: number, katalog: Buku[]): Buku[] {
        return katalog.filter(b => b.id !== bukuId);
    }

    // role bersifat protected → bisa diakses/ tambahan method di sini
    tingkatkan(anggota: Anggota, roleBaru: RolePengguna): void {
        // demonstrasi akses protected dari subclass (secara konsep)
        console.log(`[Admin] ${anggota.nama} diubah ke ${roleBaru}`);
    }
}

// ─── Abstract class — template yang tak bisa di-instantiate ─────────
abstract class Pengguna {
    constructor(
        public readonly id: number,
        public nama: string,
    ) {}

    sapa(): string {
        return `Halo, ${this.nama}!`;          // implementasi bersama
    }

    abstract getRole(): RolePengguna;           // wajib diimplementasikan
    abstract getBatasPinjam(): number;
}

class Pustakawan extends Pengguna {
    constructor(id: number, nama: string) {
        super(id, nama);
    }
    getRole(): RolePengguna { return "pustakawan"; }
    getBatasPinjam(): number { return 10; }
}

// const p = new Pengguna(1, "X");  // ❌ CANNOT instantiate abstract class
const pst = new Pustakawan(1, "Siti");
console.log(pst.sapa());            // "Halo, Siti!"
console.log(pst.getBatasPinjam()); // 10
```

## 4. Analogi Sederhana

**Sistem Perpustakaan.**

- **Constructor Parameter Properties** = **formulir pendaftaran "sekali isi"**: saat pencatatan anggota, kolom (id, nama, email, password) langsung tercatat sebagai *data resmi* — tidak perlu lagi "menulis ulang" dari nota ke buku induk. Kode padat seperti satu baris formulir yang mengisi kartu sekaligus.

- **`public`** = beritanya bisa dibaca semua orang di papan pengumuman.
- **`private _password`** = **kotak penyimpanan rahasia** di meja pustakawan — hanya pustakawan yang boleh mengambil (verifikasi), anggota tidak.
- **`protected role`** = **catatan internal yang boleh dilihat oleh staf** (class turunan) tapi tidak oleh publik.
- **`readonly id`** = **nomor kartu permanen** yang tidak bisa dihapus/diganti.
- **Abstract class `Pengguna`** = **template "Staf Perpustakaan"**: ia mendefinisikan *SOP umum* (`sapa()`) yang diwarisi semua staf, tetapi menetapkan bahwa *setiap jabatan* harus mengisi sendiri `getRole()` dan `getBatasPinjam()` — tidak boleh ada staf tanpa spesifikasi jabatan. Oleh karena itu **template-nya sendiri tidak pernah dipekerjakan langsung** (abstract).

---

## 5. Kapan Harus Digunakan (Use Cases)

- **Selalu gunakan parameter properties** untuk field yang berasal dari parameter constructor — dipakai di hampir semua class domain/service.
- **`protected`** untuk field/method yang hanya dibutuhkan subclass (dasar polymorphic behavior).
- **`readonly`** untuk id & metadata timestamps.
- **Abstract class** ketika sekelompok class memiliki *perilaku bersama yang kongkret* tapi *sebagian perilaku spesifik per subclass* — misal hierarchy error (`AppError`) dan spesialisasi `BukuRepository` (materi 15) / `BukuService`.
- **Hati-hati**: abstract class untuk *kontrak murni tanpa implementasi* → lebih cocok `interface`.

---

## 6. Poin-poin Penting & Best Practices

1. **Parameter properties = deklarasi + asignment dalam satu tempat** — jangan juga menulis ulang `this.x = x` (duplikasi).
2. **Jangan pasang `readonly` pada parameter tanpa modifier** — `readonly id: number` dengan parameter `id: number` tidak otomatis jadi property; tulis `public readonly id: number`.
3. **`private` untuk yang benar-benar privat**, jangan cuma naming underscore — gunakan modifier, bukan konvensi.
4. **`protected` bukan "publik sebagian"** — tautan erat ke hierarchy; pertimbangkan `getter` bila hanya perlu read.
5. **Abstract class** — berikan method konkret bersama + method abstract; jangan buat semua abstract (itu tugas interface).
6. **Prefer composition** bila inheritance mulai berbelit (materi 24).

---

## 7. Kesalahan Umum (Common Pitfalls & Anti-patterns)

| Kesalahan | Contoh | Akibat | Perbaikan |
|---|---|---|---|
| Lupa modifier di parameter | `constructor(id: number)` padahal mau jadi property | property tidak dibuat — error TS2564 | tambah `public`/`private`/`readonly` |
| Menduplikasi deklarasi & assign | pakai parameter properties + tetap `this.x = x` | kode berlebihan | hapus bagian duplikat |
| `new` pada abstract class | `new Pengguna(1, "X")` | TS2511: cannot instantiate | instance subclass yang mengimplementasi |
| Terlalu banyak `protected` | semua method protected padahal tidak di-override | API bocor | gunakan `public` hanya yang perlu |
| Meng-bypass private dengan cast | `(x as any)._password` | kehilangan enkapsulasi | gunakan method publik `verifikasiPassword` |
| Memakai parameter properties pada semua termasuk yang tidak perlu property | `constructor(private sementara: number)` padahal lokal | field mubazir | tetap gunakan parameter biasa bila hanya lokal |

## 8. Soal Latihan & Kunci Jawaban

### Soal 1
Tulis ulang class berikut dengan **constructor parameter properties** dan tambahkan batas pinjam: `anggota` = 5, `pustakawan` = 10, `admin` = tak terbatas.

```typescript
class Anggota {
    readonly id: number;
    nama: string;
    role: string;
    private gaji?: number;

    constructor(id: number, nama: string, role = "anggota") {
        this.id = id;
        this.nama = nama;
        this.role = role;
    }
}
```

### Soal 2
Buat abstract class `SumberData` dengan:
- `abstract findAll(): string[]`,
- method konkret `hitung(): number { return this.findAll().length; }`,
lalu buat subclass `KatalogBuku` yang mengimplementasikan `findAll()` (misal daftar 3 judul). Buktikan `new SumberData()` tidak bisa dibuat.

---

### Jawaban & Pembahasan

```typescript
// Soal 1 — dengan parameter properties + batas pinjam
type Role = "anggota" | "pustakawan" | "admin";

class Anggota {
    constructor(
        public readonly id: number,
        public nama: string,
        public role: Role = "anggota",
        private gaji?: number,
    ) {}

    getBatasPinjam(): number {
        switch (this.role) {
            case "anggota":     return 5;
            case "pustakawan":  return 10;
            case "admin":       return Infinity;
        }
    }
}

const a = new Anggota(1, "Budi");
console.log(a.getBatasPinjam());       // 5
```

**Pembahasan**: semua field langsung terdeklarasi dari parameter; `gaji?` tetap optional via parameter property. Type safety dengan literal `Role` membatasi nilai role yang valid.

```typescript
// Soal 2 — abstract class + implementasi
abstract class SumberData {
    abstract findAll(): string[];

    hitung(): number {
        return this.findAll().length;
    }
}

class KatalogBuku extends SumberData {
    findAll(): string[] {
        return ["Clean Code", "Laskar Pelangi", "Pragmatic"];
    }
}

const katalog = new KatalogBuku();
console.log(katalog.hitung());          // 3

// new SumberData();                     // ❌ TS2511: cannot instantiate abstract class
```

**Pembahasan**: `abstract findAll` memaksa setiap subclass mengimplementasi cara *mencari* data; method konkret `hitung()` dipakai bersama. Inilah pola Design Pattern "Template Method" yang akan direferensikan di materi 24.
