## 3.5 Environment Variables (.env)

### Definisi Singkat

**Environment Variables** adalah variabel yang nilainya disimpan di luar kode program, biasanya dalam sebuah file bernama `.env`. Nilai-nilai ini digunakan untuk mengatur konfigurasi aplikasi sesuai dengan lingkungan tempat ia berjalan (seperti komputer lokal, server testing, atau server produksi).

### Analogi

Bayangkan aplikasi NestJS adalah sebuah **Mobil Canggih**:

- **Kode Program**: Adalah mesin, setir, dan rodanya. Semua mobil tipe ini punya komponen yang sama.
    
- **Environment Variables**: Adalah **Kunci Kontak dan Jenis Bahan Bakar**.
    
    - Saat mobil di Indonesia, ia memakai Pertamax (Database Lokal).
        
    - Saat mobil di Amerika, ia memakai Shell (Database Cloud).
        
    - Kamu tidak akan mengelas kunci kontak langsung ke mesin, kan? Kamu menyimpannya secara terpisah di saku (file `.env`) agar jika mobilnya dicuri, pencuri tidak bisa menyalakannya tanpa kunci tersebut.
        

### Poin-Poin Penting

- **Security**: Menghindari kebocoran data sensitif (API Key, Database Password, Secret Token) di repositori Git (seperti GitHub).
    
- **Flexibility**: Memungkinkan aplikasi berjalan dengan konfigurasi berbeda tanpa harus mengubah satu baris kode pun.
    
- **`.gitignore`**: File `.env` **WAJIB** dimasukkan ke dalam daftar `.gitignore` agar tidak ikut terunggah ke server publik.
    
- **Format**: Penulisan di dalam file `.env` menggunakan format `KEY=VALUE` tanpa spasi di sekitar tanda sama dengan.
    

### Contoh Implementasi

**1. File `.env` (Disimpan di root folder):**

Cuplikan kode

```
PORT=3000
DB_HOST=localhost
DB_PASSWORD=rahasia_banget
API_KEY=123456789abcdef
```

**2. Penggunaan di NestJS (setelah install `@nestjs/config`):**

TypeScript

```
// Di dalam service atau controller
const dbPassword = process.env.DB_PASSWORD;
const port = process.env.PORT ?? 3000;

console.log(`Aplikasi berjalan di port ${port}`);
```

### Koneksi dengan Web Development (NestJS)

Dalam **NestJS**, manajemen environment variables menjadi sangat profesional karena:

1. **ConfigModule**: NestJS menyediakan modul khusus `@nestjs/config` untuk memvalidasi dan membaca file `.env` secara otomatis.
    
2. **Type Safety**: Kita bisa menggabungkan ConfigService dengan TypeScript agar kita tahu pasti tipe data dari setiap variabel lingkungan (misal: PORT harus berupa _number_).
    
3. **Multiple Environments**: NestJS memudahkan kita memiliki banyak file env, seperti `.env.development` untuk coding sehari-hari dan `.env.production` untuk server asli.
    
4. **Deployment**: Saat menggunakan Docker atau platform seperti Heroku/AWS, nilai-nilai ini akan dimasukkan melalui panel kontrol mereka, bukan melalui file fisik, sehingga jauh lebih aman.
