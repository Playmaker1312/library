# 3. Node.js Fundamentals

## 3.5. Environment Variables (`.env`)

**Definisi Singkat:** Environment variables menyimpan konfigurasi seperti database URL, API keys, dan port. File `.env` menyimpannya secara lokal. NestJS menyediakan `@nestjs/config` untuk mengelolanya.

**Analogi:** Seperti formulir data diri — nama, alamat, nomor telepon (environment variables) diisi berbeda tergantung situasi (development, production). Formulirnya (`.env`) disimpan di laci masing-masing.

**Poin-Poin Penting:**
- Jangan commit `.env` ke git — tambahkan ke `.gitignore`
- Simpan template di `.env.example` (tanpa nilai rahasia)
- `@nestjs/config` menggunakan `dotenv` di belakang layar
- `process.env` global object di Node.js
- NestJS ConfigModule bisa load dari `.env`, YAML, atau custom source

**Contoh Kode:**
```
# .env — development environment
PORT=3000
DATABASE_URL=postgres://user:pass@localhost:5432/mydb
JWT_SECRET=my-super-secret-key
NODE_ENV=development
REDIS_HOST=localhost
REDIS_PORT=6379
```

```typescript
// app.module.ts — ConfigModule setup
import { Module } from '@nestjs/common';
import { ConfigModule, ConfigService } from '@nestjs/config';

@Module({
  imports: [
    ConfigModule.forRoot({
      isGlobal: true, // tersedia di semua module
      envFilePath: '.env',
    }),
  ],
})
export class AppModule {}

// database.service.ts — menggunakan ConfigService
@Injectable()
export class DatabaseService {
  constructor(private configService: ConfigService) {
    const url = this.configService.get<string>('DATABASE_URL');
    const port = this.configService.get<number>('PORT', 3000);
  }
}
```

**Kasus Penggunaan Nyata:**
Menyimpan konfigurasi database berbeda untuk dev/staging/production. API keys untuk third-party services. Feature flags untuk deployment bertahap. Port dan host untuk microservices.
