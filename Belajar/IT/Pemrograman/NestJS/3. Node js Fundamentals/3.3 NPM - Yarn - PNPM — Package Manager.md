## 3.3 NPM - Yarn - PNPM — Package Manager

### Definisi Singkat

**Package Manager** adalah alat bantu (tools) untuk mengelola pustaka (_library_ atau _dependency_) pihak ketiga dalam proyek JavaScript/Node.js. Alat ini memungkinkan kita untuk menginstal, memperbarui, dan menghapus kode tambahan yang kita butuhkan untuk membangun aplikasi.

### Analogi

Bayangkan kamu sedang membangun sebuah **Rumah (Proyek NestJS)**:

- **Package Manager** adalah **Mandor/Supplier Material**. Kamu tidak perlu membuat semen atau paku sendiri. Kamu cukup bilang ke Mandor, "Saya butuh semen merek A versi 2.0".
    
- **NPM**: Supplier tradisional yang membawa barang satu per satu. Kadang lambat dan gudangnya (folder `node_modules`) sangat berantakan.
    
- **Yarn**: Supplier yang lebih modern dan cepat karena dia mencatat dengan teliti daftar belanjaan agar tidak ada yang salah kirim.
    
- **PNPM**: Supplier paling efisien. Jika kamu membangun 10 rumah, dia tidak akan membeli 10 karung semen yang sama. Dia hanya beli satu, lalu menggunakan "lorong rahasia" agar semen itu bisa dipakai di semua rumah secara bersamaan.
    

### Poin-Poin Penting

- **NPM (Node Package Manager)**: Standar bawaan saat menginstal Node.js. Paling banyak digunakan dan memiliki komunitas terbesar.
    
- **Yarn**: Dibuat oleh Facebook untuk mengatasi masalah kecepatan dan keamanan pada versi awal NPM. Memiliki fitur _caching_ yang sangat baik.
    
- **PNPM (Performant NPM)**: Paling cepat dan hemat ruang penyimpanan. Menggunakan sistem _Content-addressable storage_ (menghindari duplikasi file yang sama di proyek berbeda).
    
- **package.json**: "Buku Manual" proyekmu. Di sini tercatat semua nama dan versi library yang kamu gunakan.
    
- **node_modules**: Folder tempat semua library yang kamu unduh disimpan. Folder ini biasanya sangat besar.
    

### Contoh Implementasi

Berikut perintah dasar yang sering digunakan (menggunakan NPM sebagai standar):

Bash

```
# 1. Inisialisasi proyek baru (membuat package.json)
npm init -y

# 2. Menginstal NestJS CLI secara global
npm install -g @nestjs/cli

# 3. Menginstal library ke dalam proyek (misal: TypeORM)
npm install @nestjs/typeorm typeorm mysql2

# 4. Menjalankan skrip yang ada di package.json
npm run start:dev
```

### Koneksi dengan Web Development (NestJS)

Mengapa pemilihan Package Manager penting di NestJS?

1. **Ekosistem NestJS**: NestJS terdiri dari banyak modul terpisah (core, common, platform-express, dll). Package manager memastikan semua modul ini memiliki versi yang kompatibel satu sama lain.
    
2. **Efisiensi Disk**: Saat belajar NestJS, kamu mungkin akan membuat banyak project latihan. Menggunakan **PNPM** akan sangat menghemat kapasitas harddisk kamu karena dia tidak akan menduplikasi folder `node_modules` yang isinya sama.
    
3. **Deployment**: Saat mengunggah aplikasi ke server (seperti Docker atau Heroku), package manager akan membaca `package-lock.json` atau `yarn.lock` untuk memastikan versi library di komputer kamu sama persis dengan yang ada di server.
