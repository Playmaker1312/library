## 3.1 Apa itu Node.js & Event Loop

### Definisi Singkat

**Node.js** adalah _runtime_ JavaScript yang dibangun di atas mesin V8 Google Chrome untuk menjalankan kode JS di sisi server. **Event Loop** adalah mekanisme inti Node.js yang memungkinkannya menangani ribuan koneksi secara bersamaan tanpa macet, meskipun Node.js hanya bekerja dengan satu jalur (Single-threaded).

### Analogi

Bayangkan sebuah **Restoran Cepat Saji dengan 1 Kasir**:

- **Blocking (Tradisional)**: Kasir menerima pesanan, lalu dia sendiri yang pergi ke dapur memasak burger, lalu menyajikannya. Selama dia memasak, antrean di depan kasir tidak bergerak sama sekali.
    
- **Event Loop (Node.js)**: Kasir (Event Loop) menerima pesanan, memberikan nomor antrean kepada pembeli, lalu melempar pesanan ke **Koki di Dapur** (Worker Pool). Setelah itu, kasir **langsung melayani orang berikutnya**. Ketika burger jadi, koki membunyikan lonceng (Callback), dan kasir akan memanggil nomor antrean tadi untuk memberikan burgernya. Kasir tidak pernah berhenti melayani antrean.
    

### Poin-Poin Penting

- **Asynchronous & Non-blocking**: Node.js tidak menunggu sebuah proses (seperti membaca file atau query database) selesai untuk lanjut ke perintah berikutnya.
    
- **Single-Threaded**: Secara default, Node.js menjalankan kode utamamu hanya di satu jalur. Ini membuatnya sangat hemat memori.
    
- **V8 Engine**: Mesin yang sangat cepat yang mengubah kode JavaScript menjadi kode mesin yang dimengerti komputer.
    
- **Event Loop Phases**: Proses ini berputar terus-menerus mengecek: "Apakah ada tugas yang sudah selesai? Apakah ada callback yang perlu dijalankan?".
    

### Contoh Implementasi

**Perbedaan Blocking vs Non-Blocking:**

JavaScript

```
const fs = require('fs');

// 1. Synchronous/Blocking (Dihindari di NestJS)
console.log("Mulai baca file...");
const data = fs.readFileSync('file_besar.txt'); // Program berhenti di sini sampai file selesai dibaca
console.log("Isi file: " + data);
console.log("Lanjut ke tugas lain");

// 2. Asynchronous/Non-Blocking (Standar Node.js/NestJS)
console.log("Mulai baca file...");
fs.readFile('file_besar.txt', (err, data) => {
    if (err) throw err;
    console.log("Isi file: " + data); // Ini dijalankan nanti oleh Event Loop setelah file siap
});
console.log("Lanjut ke tugas lain tanpa menunggu!");
```

### Koneksi dengan Web Development (NestJS)

Mengapa kamu harus tahu ini untuk belajar NestJS?

1. **High Scalability**: NestJS sangat hebat menangani aplikasi _real-time_ (seperti chat atau notifikasi) karena ia mewarisi sifat non-blocking dari Node.js.
    
2. **Avoid CPU Intensive Task**: Karena Node.js itu _single-threaded_, kamu harus hati-hati. Jika kamu melakukan perhitungan matematika yang sangat berat di dalam NestJS, "Kasir" tadi akan sibuk menghitung dan seluruh aplikasi akan terasa _lag_ bagi user lain.
    
3. **Efficiency**: NestJS menggunakan memori yang sangat efisien dibandingkan framework yang berbasis _multi-threading_ (seperti Java Spring atau .NET tradisional), sehingga biaya server biasanya lebih murah.
