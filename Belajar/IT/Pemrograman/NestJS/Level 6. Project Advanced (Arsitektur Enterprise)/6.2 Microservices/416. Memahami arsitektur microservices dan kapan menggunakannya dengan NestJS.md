# 416. Memahami arsitektur microservices dan kapan menggunakannya dengan NestJS

## Definisi & Target
Microservices memecah aplikasi menjadi service-service kecil yang independen, masing-masing dengan domain sendiri. NestJS mendukung arsitektur microservices dengan transport layer yang pluggable. Targetnya adalah memahami kapan dan mengapa menggunakan microservices.

## Komponen & Nest CLI Command
```
Flow komunikasi:
  Client -> API Gateway -> [Service A, Service B, Service C]
  Setiap service punya database sendiri
  Komunikasi via TCP/Redis/RabbitMQ/Kafka
```

## Kode Implementasi (Per File)
```typescript
// arsitektur-microservices.md
# Arsitektur Microservices

## Kapan menggunakan microservices:
- Tim besar (>10 orang) yang perlu bekerja paralel
- Domain kompleks yang bisa dipecah secara natural
- Skala yang berbeda untuk setiap service
- Kebutuhan teknologi stack berbeda per service

## Tradeoffs:
+ Isolasi failure
+ Deployment independen
+ Skala horizontal per service
- Complexity (network latency, data consistency)
- Operational overhead
- Testing lebih kompleks

## NestJS Microservices Stack:
- Transport: TCP (default), Redis, RabbitMQ, Kafka, MQTT, gRPC
- Pattern: request-response dan event-based
- Gateway: API Gateway pattern
```

## Cara Integrasi & Pengujian
Mulai dengan monolith dulu, refactor ke microservices saat sudah terbukti scale issue. Gunakan shared library untuk contract/shared types antar service.
