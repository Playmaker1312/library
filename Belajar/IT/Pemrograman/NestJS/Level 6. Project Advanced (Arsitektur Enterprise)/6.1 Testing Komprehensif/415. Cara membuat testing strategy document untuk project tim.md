# 415. Cara membuat testing strategy document untuk project tim

## Definisi & Target
Testing strategy document adalah dokumen yang mendefinisikan pendekatan testing di tim: jenis test, tools, coverage target, dan workflow. Targetnya adalah menyelaraskan ekspektasi testing antar anggota tim.

## Komponen & Nest CLI Command
Dokumen bisa disimpan di `docs/testing-strategy.md` atau di wiki repository.

```
Sections:
  1. Testing Pyramid (unit, integration, e2e)
  2. Tools & Framework
  3. Coverage Thresholds
  4. Test Naming Conventions
  5. CI Pipeline Integration
  6. Data Management
  7. Review Process
```

## Kode Implementasi (Per File)
```markdown
// docs/testing-strategy.md
# Testing Strategy

## Testing Pyramid
- **Unit Tests (70%)**: Mock all dependencies. Test one class/function.
- **Integration Tests (20%)**: Real database. Test module interactions.
- **E2E Tests (10%)**: Full HTTP to database. Critical paths only.

## Tools
- **Test Runner**: Jest with ts-jest
- **HTTP Testing**: Supertest
- **Factories**: @faker-js/faker
- **Testcontainers**: @testcontainers/postgresql (CI only)

## Conventions
- File naming: `*.spec.ts` (unit), `*.int-spec.ts` (integration), `*.e2e-spec.ts` (e2e)
- Folder: `test/factories/`, `test/seed/`, `test/mocks/`
- describe blocks: `describe('ServiceName.methodName')`
- it blocks: `it('should ... when ...')`

## Thresholds
- Statements: 80%, Branches: 75%, Functions: 80%, Lines: 80%
- Domain layer: 90% minimum

## CI Pipeline
- Run on push to main/develop and all PRs
- Stage: lint -> unit test -> integration test -> e2e test -> coverage upload
- Database: Testcontainers with PostgreSQL

## Data Management
- Clean database before each test run
- Use factory functions for test data
- Seed only necessary data per test
```

## Cara Integrasi & Pengujian
Review dokumen bersama tim di awal sprint. Update dokumen ketika ada perubahan tools atau workflow. Gunakan sebagai acuan code review untuk memastikan test sesuai standar.
