# 29. Testing
## 29.1 Filosofi Testing di NestJS
**Definisi Singkat:** NestJS didesain dengan testability sebagai prioritas utama — Dependency Injection, modularitas, dan decorator memudahkan pembuatan unit test, integration test, dan E2E test.
**Analogi:** Seperti merakit mobil dengan komponen yang bisa dilepas — Anda bisa menguji mesin (service) secara terpisah tanpa perlu seluruh mobil (modul lain), mengganti komponen asli dengan dummy (mock), dan memastikan setiap bagian berfungsi dengan benar sebelum mobil dijalankan.
**Poin-Poin Penting:**
- Dependency Injection memudahkan mocking
- `@nestjs/testing` package untuk TestModule
- Tiga level test: Unit, Integration, E2E
- Jest sebagai default testing framework
**Contoh Kode:**
```typescript
// app.module.ts — arsitektur yang testable
import { Module } from '@nestjs/common';
import { DatabaseModule } from './database/database.module';
import { UsersModule } from './users/users.module';
import { AuthModule } from './auth/auth.module';

@Module({
  imports: [
    // Dengan modularitas, kita bisa test per modul
    DatabaseModule.forRoot({}),
    UsersModule,
    AuthModule,
  ],
})
export class AppModule {}
```
```typescript
// Konsep test pyramid di NestJS:
//
//         /\
//        /E2E\        ← Test end-to-end (sedikit, mahal)
//       /------\
//      /Integr.\      ← Test integration (sedang)
//     /----------\
//    / Unit Tests \    ← Test unit (banyak, cepat, murah)
//   /--------------\
//
// Unit Test     : Test satu class, mock semua dependency
// Integration   : Test interaksi antar class/modul
// E2E Test      : Test seluruh aplikasi dari HTTP request ke response
```
```typescript
// Setiap file service/controller siap di-test:
// users.service.ts
import { Injectable } from '@nestjs/common';
import { InjectRepository } from '@nestjs/typeorm';
import { Repository } from 'typeorm';
import { User } from './entities/user.entity';

@Injectable()
export class UsersService {
  constructor(
    @InjectRepository(User)
    private usersRepository: Repository<User>, // Bisa di-mock
  ) {}

  async findAll(): Promise<User[]> {
    return this.usersRepository.find();
  }

  async findOne(id: number): Promise<User | null> {
    return this.usersRepository.findOneBy({ id });
  }
}
```
```typescript
// Prinsip test yang baik di NestJS:
// 1. Setiap service harus bisa di-test tanpa database nyata
// 2. Mock dependency eksternal (DB, API, file system)
// 3. Test behavior, bukan implementation detail
// 4. Gunakan TestModule untuk integration test
```
**Kasus Penggunaan Nyata:** Tim backend mengadopsi TDD (Test-Driven Development) dalam pengembangan NestJS. Setiap developer menulis unit test untuk service dan controller sebelum implementasi, integration test untuk interaksi database, dan E2E test untuk flow kritis seperti registrasi → login → beli produk.
