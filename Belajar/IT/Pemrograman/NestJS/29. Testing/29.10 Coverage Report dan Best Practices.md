# 29. Testing
## 29.10 Coverage Report dan Best Practices
**Definisi Singkat:** Coverage report mengukur persentase kode yang di-cover oleh test, membantu developer mengidentifikasi bagian kode yang belum diuji. Jest menyediakan laporan coverage built-in dengan berbagai format output.
**Analogi:** Seperti peta panas (heatmap) keamanan rumah — area hijau (high coverage) berarti sudah terpantau CCTV, area merah (low coverage) berarti rawan dan perlu tambahan kamera.
**Poin-Poin Penting:**
- `jest --coverage` untuk generate report
- `collectCoverageFrom` untuk menentukan file yang diukur
- `coverageThreshold` untuk batas minimum
- Format: `text`, `lcov`, `html`, `json`, `clover`
**Contoh Kode:**
```typescript
// jest.config.ts — konfigurasi coverage lengkap
import type { Config } from 'jest';

const config: Config = {
  // ... konfigurasi dasar

  // File yang diukur coverage-nya
  collectCoverageFrom: [
    '**/*.service.ts',
    '**/*.controller.ts',
    '**/*.guard.ts',
    '**/*.pipe.ts',
    '**/*.interceptor.ts',
    '**/*.strategy.ts',
    '**/*.resolver.ts',  // untuk GraphQL
    // Exclude:
    '!**/*.module.ts',     // Module biasanya boilerplate
    '!**/*.dto.ts',        // DTO tanpa logika
    '!**/*.entity.ts',     // Entity tanpa logika
    '!**/*.interface.ts',  // Interface tanpa implementasi
    '!**/*.input.ts',      // GraphQL input types
    '!**/main.ts',         // Entry point
    '!**/*.config.ts',     // Konfigurasi
    '!**/migrations/**',   // Database migrations
    '!**/seeds/**',        // Database seeds
  ],

  // Threshold — batas minimum coverage
  coverageThreshold: {
    global: {
      branches: 80,
      functions: 80,
      lines: 80,
      statements: -10,  // Maksimum 10 uncovered statements
    },
    // Threshold per modul
    './src/auth/': {
      branches: 90,
      functions: 90,
      lines: 90,
    },
    './src/payment/': {
      branches: 100,  // Payment kritis — harus 100%
      functions: 100,
      lines: 100,
    },
  },

  // Output coverage dalam beberapa format
  coverageReporters: [
    'text',          // Output di terminal
    'text-summary',  // Ringkasan di terminal
    'lcov',          // HTML report + lcov.info
    'html',          // HTML report interaktif
    'json',          // JSON machine-readable
    'clover',        // Clover XML (CI tools)
  ],

  // Direktori output coverage
  coverageDirectory: './coverage',
};

export default config;
```

```typescript
// Best Practices — contoh test yang baik

// 1. ARRANGE-ACT-ASSERT pattern
it('should calculate total price with tax', async () => {
  // ARRANGE: setup data
  const items = [{ price: 10000, quantity: 2 }];
  const taxRate = 0.11;

  // ACT: panggil method
  const total = await cartService.calculateTotal(items, taxRate);

  // ASSERT: verifikasi hasil
  expect(total).toBe(22200); // (10000 * 2) * 1.11
});

// 2. Test satu hal per test
it('should return user when valid id is provided', async () => { /* ... */ });
it('should throw NotFoundException when id does not exist', async () => { /* ... */ });
it('should throw BadRequestException when id is negative', async () => { /* ... */ });

// 3. Gunakan describe untuk grouping
describe('UsersService', () => {
  describe('findAll', () => {
    it('should return paginated results', () => {});
    it('should apply filters correctly', () => {});
    it('should return empty array when no results', () => {});
  });
});

// 4. Hindari test yang bergantung pada test lain
// ❌ JANGAN: test B bergantung pada state dari test A
// ✅ LAKUKAN: setup state di beforeEach atau tiap test

// 5. Test edge cases dan boundary conditions
it('should handle empty string', () => {});
it('should handle null values', () => {});
it('should handle maximum input length', () => {});
it('should handle concurrent requests', () => {});

// 6. Mock eksternal, jangan panggil API asli
// ✅ Mock repository, HTTP client, message queue
// ❌ JANGAN panggil API production atau database asli
```

**Kasus Penggunaan Nyata:** Di CI/CD pipeline, setiap pull request harus melewati threshold coverage minimum (misal 80%). Jika coverage turun, pipeline gagal dan developer harus menambah test. Laporan HTML coverage `coverage/lcov-report/index.html` bisa dibuka di browser untuk melihat bagian kode mana yang belum di-cover (ditandai merah).
