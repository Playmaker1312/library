# 222. Cara mengkonfigurasi ConfigModule.forRoot dengan file .env

## Definisi & Target
ConfigModule.forRoot() membaca file `.env` dan membuat environment variables tersedia melalui ConfigService. Opsi seperti `envFilePath`, `ignoreEnvFile`, dan `cache` mengontrol perilaku loading.

## Komponen & Nest CLI Command
Tidak ada CLI command.

## Kode Implementasi (Per File)
```typescript
// src/app.module.ts
import { Module } from '@nestjs/common';
import { ConfigModule } from '@nestjs/config';

@Module({
  imports: [
    ConfigModule.forRoot({
      envFilePath: ['.env.development', '.env.production', '.env'],
      ignoreEnvFile: process.env.NODE_ENV === 'production' ? false : false,
      isGlobal: true,
      cache: true,
      expandVariables: true,
    }),
  ],
})
export class AppModule {}
```

```env
# .env.development (specific)
PORT=3000
DATABASE_URL="postgresql://postgres:postgres@localhost:5432/blog_dev"
JWT_SECRET=dev-secret
```

```env
# .env.production
PORT=8080
DATABASE_URL="postgresql://admin:password@prod-db:5432/blog_prod"
JWT_SECRET=${JWT_SECRET}  # dari environment variable sistem
```

```env
# .env (default fallback)
PORT=3000
NODE_ENV=development
```

Penjelasan opsi:
- `envFilePath` — array file, prioritas dari kiri ke kanan
- `ignoreEnvFile` — true jika env dari sistem saja
- `isGlobal` — true agar ConfigModule tersedia di semua module
- `cache` — caching nilai untuk performa
- `expandVariables` — mendukung `${VAR}` di dalam .env

## Cara Integrasi & Pengujian
```bash
# Development:
NODE_ENV=development npm run start:dev
# Membaca .env.development dulu, lalu .env

# Production:
NODE_ENV=production node dist/main
# Membaca .env.production dulu, lalu .env
```
