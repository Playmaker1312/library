# 37. Deployment ## 37.4 Dockerfile untuk NestJS

**Definisi Singkat:** Dockerfile NestJS yang optimal menggunakan multi-stage build untuk memisahkan development dependencies dari production, menghasilkan image yang kecil, aman, dan cepat di-build.

**Analogi:** Dockerfile multi-stage seperti proses produksi mobil — ada pabrik komponen (stage build) yang kotor dan berdebu, lalu komponen jadi dikirim ke pabrik perakitan (stage production) yang bersih. Hasil mobil (image) tidak bawa kotoran dari pabrik pertama.

**Poin-Poin Penting:**
- **Multi-stage** separate build and runtime
- **Alpine base** image minimal (5MB base)
- **node:20-alpine** base image ringan
- **--only=production** hanya dependensi runtime
- **USER node** security (jangan root)
- **tini** init system untuk sinyal handling
- **Layer ordering** optimasi cache

**Contoh Kode:**
```typescript
// Dockerfile (optimized for NestJS)
# Stage 1: Install dependencies
FROM node:20-alpine AS deps
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci --only=production && \
    npm cache clean --force

# Stage 2: Build application
FROM node:20-alpine AS builder
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci
COPY tsconfig*.json nest-cli.json ./
COPY src/ ./src/
RUN npm run build

# Stage 3: Production image
FROM node:20-alpine AS runner
WORKDIR /app

# Security: non-root user
RUN addgroup --system --gid 1001 nodejs && \
    adduser --system --uid 1001 nestjs && \
    apk add --no-cache tini

ENV NODE_ENV=production
ENV PORT=3000

# Copy from stages
COPY --from=deps /app/node_modules ./node_modules
COPY --from=builder /app/dist ./dist

# Copy package.json for scripts reference
COPY package.json ./

HEALTHCHECK --interval=30s --timeout=3s --start-period=10s --retries=3 \
  CMD wget --no-verbose --tries=1 --spider http://localhost:3000/health || exit 1

USER nestjs
EXPOSE 3000

ENTRYPOINT ["/sbin/tini", "--"]
CMD ["node", "dist/main.js"]
```

```typescript
// Dockerfile (development — dengan hot reload)
FROM node:20-alpine AS development
WORKDIR /app

RUN apk add --no-cache tini

COPY package.json package-lock.json ./
RUN npm ci

COPY . .

EXPOSE 3000
ENTRYPOINT ["/sbin/tini", "--"]
CMD ["npm", "run", "start:dev"]
```

```typescript
// docker-compose.dev.yml
version: '3.8'
services:
  app:
    build:
      context: .
      dockerfile: Dockerfile
      target: development
    ports:
      - "3000:3000"
    volumes:
      - .:/app
      - /app/node_modules
    environment:
      - NODE_ENV=development
    command: npm run start:dev
```

**Kasus Penggunaan Nyata:** Monorepo NestJS dengan Prisma ORM — multi-stage build: stage 1 install dependencies + generate Prisma client, stage 2 build TypeScript, stage 3 production image (hanya dist + node_modules production). Ukuran image final: ~150MB (vs ~1GB tanpa multi-stage).
