# 34. CQRS dan Event Sourcing ## 34.7 Event Sourcing pengenalan

**Definisi Singkat:** Event Sourcing adalah pattern menyimpan state sebagai urutan events (immutable log), bukan state terkini. Setiap perubahan adalah append-only event. State saat ini bisa direkonstruksi dengan me-replay semua events dari awal.

**Analogi:** Event Sourcing seperti buku besar akuntansi — Anda tidak pernah menghapus atau mengubah entri lama. Jika ada kesalahan, Anda membuat "jurnal koreksi" (compensating event) baru. Saldo rekening (state) dihitung dari menjumlahkan semua transaksi.

**Poin-Poin Penting:**
- **Event Store** database khusus untuk events
- **Append-only log** tidak pernah menghapus/mengubah event
- **Event replay** rekonstruksi state
- **Snapshot** optimasi replay dari titik tertentu
- **Event versioning** handle schema evolution
- **EventBus** publish event ke subscribers

```typescript
// event-store/event-store.service.ts
import { Injectable } from '@nestjs/common';
import { InjectModel } from '@nestjs/mongoose';
import { Model } from 'mongoose';

interface StoredEvent {
  aggregateId: string;
  aggregateType: string;
  eventType: string;
  data: Record<string, any>;
  version: number;
  timestamp: Date;
}

@Injectable()
export class EventStoreService {
  constructor(
    @InjectModel('Event') private readonly eventModel: Model<StoredEvent>,
  ) {}

  async appendEvent(
    aggregateId: string,
    aggregateType: string,
    eventType: string,
    data: Record<string, any>,
    version: number,
  ): Promise<void> {
    await this.eventModel.create({
      aggregateId,
      aggregateType,
      eventType,
      data,
      version,
      timestamp: new Date(),
    });
  }

  async getEvents(aggregateId: string): Promise<StoredEvent[]> {
    return this.eventModel
      .find({ aggregateId })
      .sort({ version: 1 })
      .exec();
  }

  async getAllEvents(aggregateType: string): Promise<StoredEvent[]> {
    return this.eventModel
      .find({ aggregateType })
      .sort({ timestamp: 1 })
      .exec();
  }

  }
}
```

```typescript
// event-sourcing/account.ts
// Contoh reconstruct state dari events
interface Account {
  id: string;
  balance: number;
  owner: string;
  status: 'active' | 'frozen' | 'closed';
}

interface DomainEvent {
  type: string;
  data: any;
}

class AccountProjection {
  static applyEvent(state: Account | null, event: DomainEvent): Account {
    switch (event.type) {
      case 'AccountCreated':
        return {
          ...event.data,
          balance: 0,
          status: 'active',
        };

      case 'MoneyDeposited':
        return {
          ...state,
          balance: state!.balance + event.data.amount,
        };

      case 'MoneyWithdrawn':
        return {
          ...state,
          balance: state!.balance - event.data.amount,
        };

      case 'AccountFrozen':
        return {
          ...state,
          status: 'frozen',
        };

      default:
        return state!;
    }
  }

  static reconstruct(events: DomainEvent[]): Account {
    return events.reduce<Account | null>((state, event) => {
      return AccountProjection.applyEvent(state, event);
    }, null);
  }
}
```

**Kasus Penggunaan Nyata:** Sistem perbankan — setiap transaksi (deposit, withdraw, transfer) disimpan sebagai immutable event. Audit trail lengkap, bisa replay semua transaksi untuk debugging, dan memenuhi regulasi kepatuhan yang membutuhkan history lengkap.
