## 7.5 @Param() — Route Parameters

### Definisi Singkat

**Route Parameters** adalah bagian dinamis dari sebuah URL yang bertindak sebagai variabel. Di NestJS, kita menandai bagian dinamis ini dengan tanda titik dua (`:`) di dalam dekorator rute, dan mengambil nilainya menggunakan dekorator **`@Param()`** di dalam argumen fungsi.

### Analogi: Nomor Loker

Bayangkan sebuah **Ruang Loker** di tempat olahraga:

- Alamat dasarnya adalah `/loker`.
    
- Jika kamu ingin membuka loker nomor 42, kamu pergi ke `/loker/42`.
    
- Angka **42** di sini adalah "Route Parameter".
    
- **`@Param()`** adalah tangan petugas yang mengambil kunci nomor 42 tersebut dan memberikannya ke sistem untuk diproses.
    

### Cara Implementasi di NestJS

Ada dua cara utama untuk menggunakan `@Param()`:

#### 1. Mengambil Semua Parameter (Sebagai Objek)

Cocok jika kamu memiliki banyak parameter dinamis dalam satu URL.

TypeScript

```
@Get(':userId/posts/:postId')
getPost(@Param() params: any) {
  // params adalah objek: { userId: '10', postId: '99' }
  return `User ${params.userId} melihat post ${params.postId}`;
}
```

#### 2. Mengambil Parameter Spesifik (Rekomendasi)

Cara ini lebih bersih dan sangat disarankan karena langsung menunjuk ke variabel yang dibutuhkan.

TypeScript

```
@Get(':id') // Menandakan ada bagian dinamis bernama 'id'
findOne(@Param('id') id: string) {
  return `Mencari data dengan ID: ${id}`;
}
```

### Karakteristik Penting

1. **Dinamis**: Kamu tidak perlu membuat rute `/users/1`, `/users/2`, dst. Cukup buat satu rute `/users/:id` yang bisa menangani jutaan ID sekaligus.
    
2. **Tipe Data**: Secara default, data yang diambil dari URL selalu bertipe **string**. Jika ID kamu di database adalah angka, kamu perlu mengubahnya (Materi Bab 9 tentang Pipes akan menjelaskan cara otomatisnya).
    
3. **Wajib Ada**: Jika kamu mendefinisikan rute `@Get(':id')`, tapi user mengakses `/users/` (tanpa ID), maka rute tersebut tidak akan cocok dan user akan mendapatkan error 404.
    

### Perbedaan Route Params vs Query Params

Seringkali pemula bingung antara keduanya:

- **Route Params (`/users/123`)**: Digunakan untuk **identitas unik**. Wajib ada untuk menemukan resource.
    
- **Query Params (`/users?status=active`)**: Digunakan untuk **filter atau sorting**. Bersifat opsional.

### Kesimpulan

`@Param()` membuat API kamu menjadi fleksibel. Tanpa ini, kamu tidak akan bisa membuat fitur seperti "Lihat Profil" atau "Edit Produk" karena server tidak tahu data mana yang sedang diminta oleh user.

Sekarang kamu sudah bisa mengambil ID dari URL. Tapi bagaimana jika user mengirim data rahasia seperti Password lewat formulir? Kita akan mempelajarinya di materi **7.6 @Body() — Request Payload**.
