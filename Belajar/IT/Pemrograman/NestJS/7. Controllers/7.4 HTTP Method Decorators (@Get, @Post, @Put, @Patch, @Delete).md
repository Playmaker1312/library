## 7.4 HTTP Method Decorators

### Definisi Singkat

**Method Decorators** adalah dekorator yang diletakkan di atas fungsi (method) di dalam Controller untuk menentukan tipe permintaan HTTP yang diterima. Setiap dekorator mewakili satu aksi standar dalam protokol internet.

### Analogi: Jenis Layanan di Bank

Bayangkan Controller adalah **Meja Layanan Bank**:

- **`@Get()`**: Seperti nasabah yang datang hanya untuk **Mengecek Saldo**. Tidak ada data yang diubah, hanya melihat informasi.
    
- **`@Post()`**: Seperti nasabah yang ingin **Membuka Rekening Baru**. Menyerahkan formulir berisi data untuk disimpan secara permanen.
    
- **`@Put()`**: Seperti nasabah yang ingin **Mengganti Seluruh Data Profil** (Alamat, No HP, Nama). Mengganti data lama dengan data yang benar-benar baru secara total.
    
- **`@Patch()`**: Seperti nasabah yang hanya ingin **Mengganti Pin** saja. Hanya satu bagian kecil yang diubah, data lainnya tetap.
    
- **`@Delete()`**: Seperti nasabah yang ingin **Menutup Rekening**. Menghapus keberadaan data dari sistem.
    

### Cara Penggunaan di NestJS

Setiap fungsi di dalam Controller biasanya memiliki satu dekorator metode di atasnya:

TypeScript

```
@Controller('users')
export class UsersController {

  @Get() // URL: GET /users
  findAll() {
    return 'Ini akan mengambil semua user';
  }

  @Post() // URL: POST /users
  create() {
    return 'Ini akan membuat user baru';
  }

  @Put(':id') // URL: PUT /users/1
  updateAll(@Param('id') id: string) {
    return `Mengganti seluruh data user ${id}`;
  }

  @Patch(':id') // URL: PATCH /users/1
  updatePartial(@Param('id') id: string) {
    return `Mengupdate sebagian data user ${id}`;
  }

  @Delete(':id') // URL: DELETE /users/1
  remove(@Param('id') id: string) {
    return `Menghapus user ${id}`;
  }
}
```

### Karakteristik Penting

|Decorator|Aksi CRUD|Sifat|Penjelasan|
|---|---|---|---|
|**`@Get()`**|Read|Idempotent|Aman dipanggil berkali-kali tanpa mengubah data di database.|
|**`@Post()`**|Create|Non-Idempotent|Setiap kali dipanggil, ia akan mencoba membuat data baru.|
|**`@Put()`**|Update|Idempotent|Biasanya mengganti **seluruh** objek data. Jika dipanggil 10x dengan data yang sama, hasilnya tetap sama.|
|**`@Patch()`**|Update|Non-Idempotent|Hanya mengganti **sebagian** field (misal: hanya password).|
|**`@Delete()`**|Delete|Idempotent|Menghapus data. Jika sudah dihapus, dipanggil lagi tetap hasilnya "sudah terhapus".|

### Custom Route Path

Kamu bisa menambahkan string di dalam kurung dekorator untuk memperpanjang URL:

- `@Get('profile')` di dalam `@Controller('users')` akan menghasilkan rute: `/users/profile`.
    

---

### Kesimpulan

Dengan menggunakan dekorator yang tepat, kamu mengikuti standar **RESTful API** yang profesional. Ini memudahkan pengembang lain (seperti tim Frontend) untuk memahami maksud dari setiap fungsi yang kamu buat hanya dengan melihat tipenya.
