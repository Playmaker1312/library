# 10. Exception Handling

## 10.6. Menangani error secara konsisten standard error response

**Definisi Singkat:** Membuat format response error yang seragam di seluruh aplikasi agar mudah dipahami client.

**Analogi:** Seperti format surat resmi — semua surat keluar perusahaan punya kop, nomor, dan tanda tangan yang sama.

**Poin-Poin Penting:**
- Gunakan Exception Filter untuk format konsisten
- Struktur response: `statusCode`, `message`, `timestamp`, `path`
- Tambahkan `errorCode` untuk identifikasi error
- Environment: bedakan dev (stack trace) vs production
- Dokumentasikan format error response

**Contoh Kode:**
```typescript
import { ExceptionFilter, Catch, ArgumentsHost, HttpException } from '@nestjs/common';
import { Request, Response } from 'express';

@Catch(HttpException)
export class StandardErrorFilter implements ExceptionFilter {
  catch(exception: HttpException, host: ArgumentsHost) {
    const ctx = host.switchToHttp();
    const response = ctx.getResponse<Response>();
    const request = ctx.getRequest<Request>();
    const status = exception.getStatus();
    const exceptionResponse = exception.getResponse();

    const errorResponse = {
      success: false,
      statusCode: status,
      message: typeof exceptionResponse === 'string'
        ? exceptionResponse
        : (exceptionResponse as any).message || exception.message,
      error: typeof exceptionResponse === 'string'
        ? exceptionResponse
        : (exceptionResponse as any).error || 'Error',
      timestamp: new Date().toISOString(),
      path: request.url,
    };

    response.status(status).json(errorResponse);
  }
}
```

**Kasus Penggunaan Nyata:** Frontend cukup membaca `errorResponse.success === false` untuk mendeteksi error, lalu menampilkan `errorResponse.message` ke user — format konsisten memudahkan error handling di sisi client.
