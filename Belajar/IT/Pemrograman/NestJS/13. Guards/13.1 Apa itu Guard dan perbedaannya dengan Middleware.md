# 13. Guards

## 13.1. Apa itu Guard dan perbedaannya dengan Middleware

**Definisi Singkat:** Guard menentukan apakah request boleh diproses oleh route handler berdasarkan kondisi tertentu (biasanya otorisasi).

**Analogi:** Middleware seperti satpam di gerbang (periksa umum), Guard seperti satpam di pintu ruangan VIP (periksa izin khusus).

**Poin-Poin Penting:**
- Guard berjalan **setelah** Middleware, **sebelum** Interceptor/Pipe
- Middleware tidak tahu konteks eksekusi (class/method mana)
- Guard punya akses ke ExecutionContext (controller class & method)
- Guard hanya return boolean (true/false)
- Guard cocok untuk otorisasi (role/permission)
- Guard bisa di level controller, method, global

**Contoh Kode:**
```typescript
// Middleware — tahu request saja
function logger(req, res, next) { next(); }

// Guard — tahu konteks eksekusi
@Injectable()
export class RolesGuard implements CanActivate {
  canActivate(context: ExecutionContext): boolean {
    const handler = context.getHandler(); // method name
    const controller = context.getClass(); // controller class
    // Guard tahu endpoint mana yang akan dieksekusi
    return true;
  }
}
```

**Kasus Penggunaan Nyata:** Middleware mengecek apakah user punya token valid (autentikasi), lalu Guard mengecek apakah user punya role `admin` untuk mengakses endpoint `DELETE /users/:id` (otorisasi).
