# 13. Guards

## 13.6. Kombinasi Guard dan Custom Decorator

**Definisi Singkat:** Menggabungkan custom decorator (seperti `@CurrentUser`) dengan Guard untuk mengakses data user yang sudah diautentikasi.

**Analogi:** Guard ibarat satpam yang periksa ID, custom decorator ibarat stempel "SILAHKAN MASUK" yang memudahkan akses ke dalam.

**Poin-Poin Penting:**
- Guard menempatkan user di `request.user`
- Custom decorator `@CurrentUser()` mengambil `request.user`
- Keduanya bekerja berurutan: Guard dulu, baru decorator
- Mengurangi duplikasi kode di handler
- Membuat kode lebih ekspresif

**Contoh Kode:**
```typescript
import { createParamDecorator, ExecutionContext } from '@nestjs/common';

// Custom decorator
export const CurrentUser = createParamDecorator(
  (data: string, ctx: ExecutionContext) => {
    const request = ctx.switchToHttp().getRequest();
    const user = request.user;
    return data ? user?.[data] : user;
  },
);

// Controller
@Controller('users')
@UseGuards(AuthGuard)
export class UserController {

  @Get('profile')
  getProfile(@CurrentUser() user: User) {
    // user otomatis tersedia dari request.user
    return user;
  }

  @Get('email')
  getEmail(@CurrentUser('email') email: string) {
    // hanya email dari user yang login
    return { email };
  }
}
```

**Kasus Penggunaan Nyata:** Setelah `AuthGuard` memvalidasi token dan menyimpan user ke `request.user`, decorator `@CurrentUser()` mengambilnya — handler tinggal terima parameter tanpa perlu akses request object langsung.
