# 13. Guards

## 13.5. Role-based Access Control RBAC dengan Guard

**Definisi Singkat:** Guard untuk membatasi akses berdasarkan role user menggunakan custom metadata dan `Reflector`.

**Analogi:** Seperti akses hotel — tamu biasa hanya ke lantai 1-3, tamu VIP bisa ke lantai 4-7, staf bisa ke semua lantai termasuk basement.

**Poin-Poin Penting:**
- Gunakan `@SetMetadata('roles', ['admin'])` untuk definisi role
- Gunakan `Reflector` untuk membaca metadata di Guard
- Guard membandingkan role user dengan role yang dibutuhkan
- Bisa dikombinasi dengan custom decorator `@Roles()`
- Support multiple roles

**Contoh Kode:**
```typescript
import { Injectable, CanActivate, ExecutionContext, SetMetadata } from '@nestjs/common';
import { Reflector } from '@nestjs/core';

// Custom decorator
export const Roles = (...roles: string[]) => SetMetadata('roles', roles);

@Injectable()
export class RolesGuard implements CanActivate {
  constructor(private reflector: Reflector) {}

  canActivate(context: ExecutionContext): boolean {
    const requiredRoles = this.reflector.getAllAndOverride<string[]>('roles', [
      context.getHandler(),
      context.getClass(),
    ]);
    if (!requiredRoles) return true;

    const { user } = context.switchToHttp().getRequest();
    return requiredRoles.some(role => user.roles?.includes(role));
  }
}

// Penggunaan
@Controller('admin')
export class AdminController {
  @Roles('admin')
  @UseGuards(RolesGuard)
  @Delete('users/:id')
  deleteUser(@Param('id') id: string) { }
}
```

**Kasus Penggunaan Nyata:** Endpoint `DELETE /admin/users/:id` diberi `@Roles('admin')` — hanya user dengan role `admin` yang bisa akses, user `editor` atau `viewer` akan mendapat response 403 Forbidden.
