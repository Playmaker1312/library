# 85. Setup Winston - Structured Logging untuk Production

## Penjelasan
Di production, `console.log` tidak cukup. Winston adalah logging library yang powerful untuk Node.js yang mendukung **structured logging** — log yang diformat dalam JSON sehingga bisa diproses oleh tools seperti Elasticsearch, Logstash, Kibana (ELK Stack), atau Datadog. Dengan `nest-winston` (wrapper resmi untuk NestJS), kita bisa mengintegrasikan Winston langsung ke sistem logging NestJS tanpa mengubah kode yang sudah ada — cukup dengan import modul, semua log dari framework (termasuk log internal NestJS) akan otomatis melalui Winston.

Winston menggunakan konsep **transports** — tujuan output log. Di production, kita biasanya menggunakan tiga transport sekaligus: (1) **Console transport** dengan format JSON untuk dikonsumsi oleh sistem log aggregation (Docker logs → cloud logging); (2) **File transport** dengan rotasi harian (menggunakan `winston-daily-rotate-file`) sebagai backup jika logger eksternal mati; (3) **HTTP/Transport** opsional yang mengirim log langsung ke service eksternal seperti Datadog atau Logz.io. Format JSON sangat penting karena memungkinkan query terstruktur — misalnya cari semua log dengan `"level": "error"` dalam rentang waktu tertentu.

## Fungsi
- Menyediakan logging terstruktur (JSON) yang siap diproses oleh log management system
- Menggantikan `console.log` dengan logging level (debug, info, warn, error) dan metadata
- Memisahkan log berdasarkan level ke transport yang berbeda (error ke file terpisah, debug hanya di development)

## Cara Implementasi / Code

**Install package:**
```bash
npm install nest-winston winston winston-daily-rotate-file
```

**AppModule (WinstonModule.forRoot):**

```typescript
import { Module } from '@nestjs/common';
import { WinstonModule } from 'nest-winston';
import * as winston from 'winston';
import 'winston-daily-rotate-file';

@Module({
  imports: [
    WinstonModule.forRoot({
      level: process.env.NODE_ENV === 'production' ? 'info' : 'debug',
      format: winston.format.combine(
        winston.format.timestamp({ format: 'YYYY-MM-DD HH:mm:ss.SSS' }),
        winston.format.errors({ stack: true }),
        winston.format.json(),
      ),
      defaultMeta: {
        service: 'nestjs-api',
        environment: process.env.NODE_ENV || 'development',
      },
      transports: [
        // Console transport — untuk Docker logs / cloud logging
        new winston.transports.Console({
          format: process.env.NODE_ENV === 'production'
            ? winston.format.json()
            : winston.format.combine(
                winston.format.colorize(),
                winston.format.printf(({ timestamp, level, message, context, ...meta }) => {
                  return `${timestamp} [${context || 'App'}] ${level}: ${message} ${Object.keys(meta).length ? JSON.stringify(meta) : ''}`;
                }),
              ),
        }),

        // File transport dengan rotasi harian — hanya di production
        ...(process.env.NODE_ENV === 'production'
          ? [
              new winston.transports.DailyRotateFile({
                filename: 'logs/app-%DATE%.log',
                datePattern: 'YYYY-MM-DD',
                zippedArchive: true,
                maxSize: '20m',
                maxFiles: '14d',
                level: 'info',
              }),
              new winston.transports.DailyRotateFile({
                filename: 'logs/error-%DATE%.log',
                datePattern: 'YYYY-MM-DD',
                zippedArchive: true,
                maxSize: '20m',
                maxFiles: '30d',
                level: 'error',
              }),
            ]
          : []),
      ],
      exceptionHandlers: [
        new winston.transports.DailyRotateFile({
          filename: 'logs/exceptions-%DATE%.log',
          datePattern: 'YYYY-MM-DD',
          maxFiles: '30d',
        }),
      ],
      rejectionHandlers: [
        new winston.transports.DailyRotateFile({
          filename: 'logs/rejections-%DATE%.log',
          datePattern: 'YYYY-MM-DD',
          maxFiles: '30d',
        }),
      ],
    }),
    // ... modul lain
  ],
})
export class AppModule {}
```

**Cara menggunakan Winston Logger di service:**

```typescript
import { Injectable, Logger } from '@nestjs/common';

@Injectable()
export class BookService {
  private readonly logger = new Logger(BookService.name);

  async createBook(data: CreateBookDto) {
    this.logger.log(`Membuat buku baru: ${data.title}`);
    try {
      const book = await this.prisma.book.create({ data });
      this.logger.debug(`Buku berhasil dibuat dengan ID: ${book.id}`);
      return book;
    } catch (error) {
      this.logger.error({
        message: `Gagal membuat buku`,
        error: error.message,
        stack: error.stack,
        data,
      });
      throw error;
    }
  }
}
```

## Analogi
Bayangkan perpustakaan memiliki **buku catatan petugas** (logbook). Setiap kali pengunjung meminjam buku, mengembalikan buku, atau terjadi masalah, petugas mencatatnya dengan format standar: tanggal, jenis kejadian, detail. Jika ada masalah besar (error), dicatat di halaman khusus dengan tinta merah. Buku catatan ini kemudian diperiksa oleh kepala perpustakaan (developer) untuk melihat tren dan mencari masalah. Winston adalah logbook digital dengan format JSON yang bisa dicari dan dianalisis.

## Penggunaan
Dipakai di semua environment, terutama production. Log Winston digunakan untuk: debugging masalah production, audit trail, monitoring performa (response time logging), analytics (jumlah request per endpoint), dan compliance (log akses data sensitif).

## Kesalahan Umum yang Sering Terjadi
1. **Log terlalu banyak (log spam)** — Mencatat setiap detail termasuk request body besar. Ini membengkakkan biaya storage dan menyulitkan pencarian log penting. Atur level dengan bijak: `debug` untuk development, `info` untuk production.
2. **Log tidak menyertakan stack trace** — `this.logger.error('gagal')` tanpa menyertakan error object. Stack trace sangat penting untuk debugging.
3. **Log mengandung data sensitif** — Mencatat password, token JWT, atau nomor kartu kredit dalam log. Ini bisa menyebabkan kebocoran data dan masalah GDPR/PCI-DSS.
4. **File log tidak di-rotate** — Log file membesar hingga GB-an, menyebabkan disk penuh dan aplikasi crash.
5. **Tidak menangani uncaughtException / unhandledRejection** — Error yang tidak tertangani menyebabkan proses crash tanpa sempat mencatat log terakhir.

## Hubungan dengan Materi Sebelumnya
Sebelumnya kita menggunakan `console.log` dan logger bawaan NestJS di development (Level 1-5). Sekarang kita upgrade ke Winston yang memberikan structured logging, rotation, dan multiple transports. Di file berikutnya (86), kita akan menambahkan Correlation ID agar log dari satu request bisa dilacak dari awal hingga akhir.

## Soal Latihan

**Soal:** Kamu ingin menambahkan metadata tambahan (seperti `version` aplikasi dari `package.json` dan `nodeVersion`) ke semua log Winston. Modifikasi konfigurasi `defaultMeta` di atas.

**Jawaban:**

```typescript
import { version, engines } from '../package.json';

defaultMeta: {
  service: 'nestjs-api',
  environment: process.env.NODE_ENV || 'development',
  version: version,
  nodeVersion: engines?.node || process.version,
},
```
