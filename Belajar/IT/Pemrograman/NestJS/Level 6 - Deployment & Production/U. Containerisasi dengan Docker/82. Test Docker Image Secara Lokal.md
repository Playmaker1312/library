# 82. Test Docker Image Secara Lokal

## Penjelasan
Sebelum mendeploy aplikasi NestJS ke production, kita harus menguji Docker image secara lokal untuk memastikan semuanya berjalan dengan benar. Proses ini meliputi: membangun image dari Dockerfile, menjalankan container dengan docker-compose yang menghubungkan service NestJS dengan database PostgreSQL dan Redis, serta memverifikasi bahwa semua service saling terhubung melalui network internal Docker.

Docker Compose adalah alat yang mendefinisikan dan menjalankan multi-container Docker applications menggunakan file YAML. Dengan docker-compose.yml, kita bisa mendefinisikan service `app` (NestJS), `db` (PostgreSQL), `redis`, dan lainnya dalam satu file. Keyword `depends_on` memastikan container database dan Redis start terlebih dahulu sebelum aplikasi NestJS dijalankan. Semua service berkomunikasi melalui bridge network yang secara otomatis dibuat oleh Docker Compose.

## Fungsi
- Memvalidasi bahwa Docker image yang dibangun berfungsi dengan benar di lingkungan lokal
- Menjalankan seluruh stack aplikasi (NestJS + database + Redis) dengan satu perintah
- Memastikan konfigurasi network, environment variable, dan dependensi antar service sudah benar sebelum production

## Cara Implementasi / Code

**docker-compose.yml (update dengan service app):**

```yaml
version: "3.8"

services:
  app:
    build:
      context: .
      dockerfile: Dockerfile
    container_name: nestjs-app
    restart: unless-stopped
    ports:
      - "3000:3000"
    env_file:
      - .env.production
    environment:
      - DATABASE_URL=postgresql://postgres:password@db:5432/nestjs_db
      - REDIS_HOST=redis
      - REDIS_PORT=6379
      - NODE_ENV=production
    depends_on:
      db:
        condition: service_healthy
      redis:
        condition: service_started
    networks:
      - nestjs-network

  db:
    image: postgres:16-alpine
    container_name: nestjs-db
    restart: unless-stopped
    ports:
      - "5432:5432"
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: password
      POSTGRES_DB: nestjs_db
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 10s
      timeout: 5s
      retries: 5
    networks:
      - nestjs-network

  redis:
    image: redis:7-alpine
    container_name: nestjs-redis
    restart: unless-stopped
    ports:
      - "6379:6379"
    networks:
      - nestjs-network

volumes:
  postgres_data:

networks:
  nestjs-network:
    driver: bridge
```

**Cara menjalankan:**

```bash
# Build image dan jalankan semua service
docker compose build --no-cache
docker compose up -d

# Lihat log aplikasi
docker compose logs -f app

# Cek health endpoint
curl http://localhost:3000/api/health

# Matikan semua service
docker compose down

# Hapus volume juga (data database hilang)
docker compose down -v
```

Penjelasan tambahan:
- `depends_on` dengan `condition: service_healthy` memastikan aplikasi NestJS hanya mulai setelah PostgreSQL benar-benar siap menerima koneksi (bukan hanya setelah container-nya start).
- Volume `postgres_data` menyimpan data database agar tidak hilang saat container di-restart.
- Bridge network `nestjs-network` memungkinkan service saling berkomunikasi menggunakan nama service (misalnya `db`, `redis`) sebagai hostname — NestJS cukup menggunakan `DATABASE_URL=postgresql://postgres:password@db:5432/nestjs_db` tanpa perlu IP address.

## Analogi
Bayangkan perpustakaan memiliki **beberapa ruangan** yang saling terhubung: Ruang Baca (app NestJS), Gudang Buku (database PostgreSQL), dan Ruang Katalog Digital (Redis). Sebelum perpustakaan dibuka untuk umum, petugas (developer) mengecek semua jalur penghubung antar ruangan, memastikan lampu menyala (health check), dan memverifikasi bahwa buku-buku bisa diambil dari gudang. File docker-compose.yml adalah **denah perpustakaan** yang menunjukkan bagaimana semua ruangan terhubung.

## Penggunaan
Dipakai dalam tahap development dan staging untuk memvalidasi bahwa aplikasi NestJS berfungsi dengan baik dalam container sebelum dikirim ke production server. Juga digunakan oleh member tim lain untuk menjalankan stack lengkap di mesin lokal tanpa perlu menginstall database dan Redis secara manual.

## Kesalahan Umum yang Sering Terjadi
1. **Tidak menggunakan health check pada database** — Aplikasi NestJS crash karena mencoba koneksi ke database yang belum siap. Akibatnya container restart terus-menerus (crash loop).
2. **Port binding bentrok** — Port 5432 atau 6379 sudah dipakai oleh service lain di host. Solusi: matikan service lokal atau ganti port binding (misal `5433:5432`).
3. **Environment variable hardcode di compose file** — Menulis password database langsung di file yang di-commit ke git. Gunakan `.env` file dan tambahkan ke `.gitignore`.
4. **Lupa build ulang image** — Menjalankan `docker compose up` tanpa `--build` sehingga masih menggunakan image lama. Selalu jalankan `docker compose up --build` jika ada perubahan kode.
5. **Network tidak terdefinisi** — Service tidak bisa saling terhubung karena masing-masing berada di network default yang berbeda.

## Hubungan dengan Materi Sebelumnya
Sebelumnya (file 81) kita membuat Dockerfile. Sekarang kita menguji image tersebut bersama dengan infrastruktur pendukung (database, Redis) menggunakan Docker Compose. Ini adalah jembatan antara pengembangan lokal (Level 1-5) dan deployment ke production (file 83-90).

## Soal Latihan

**Soal:** Dalam docker-compose.yml di atas, ada service `app` yang bergantung pada `db` dan `redis`. Jika kamu ingin menambahkan service `adminer` (GUI untuk PostgreSQL) yang hanya bisa diakses dari host (port 8080) dan terhubung ke network yang sama, bagaimana konfigurasi YAML-nya?

**Jawaban:**

```yaml
adminer:
  image: adminer
  container_name: nestjs-adminer
  restart: unless-stopped
  ports:
    - "8080:8080"
  networks:
    - nestjs-network
  depends_on:
    - db
```

Tambahkan blok ini di bawah service `redis` (masih dalam indentasi yang sama) dan jalankan `docker compose up -d`. Akses Adminer di `http://localhost:8080`, login dengan server `db`, user `postgres`, password `password`, database `nestjs_db`.
