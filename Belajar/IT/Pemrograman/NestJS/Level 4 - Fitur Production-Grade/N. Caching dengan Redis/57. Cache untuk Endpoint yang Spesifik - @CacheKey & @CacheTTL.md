# 57. Cache untuk Endpoint yang Spesifik — @CacheKey & @CacheTTL

## Penjelasan

Selain caching manual via `CACHE_MANAGER` di service, NestJS menyediakan pendekatan **declarative** menggunakan interceptor bawaan `CacheInterceptor`. Dengan menambahkan decorator `@UseInterceptors(CacheInterceptor)` di controller, setiap response dari endpoint akan otomatis di-cache berdasarkan URL request dan query parameters. NestJS akan secara otomatis men-generate cache key dari URL (misal: `GET:/books:page=1&limit=10`).

Dua decorator penting untuk kustomisasi adalah `@CacheKey(key)` untuk mengganti cache key default, dan `@CacheTTL(ttl)` untuk mengatur TTL spesifik per endpoint (mengganti TTL global). Pendekatan ini sangat berguna ketika kita ingin endpoint tertentu memiliki perilaku caching yang berbeda, misalnya daftar buku di-cache 30 detik sementara daftar kategori di-cache 5 menit karena jarang berubah.

## Fungsi

`@CacheKey` dan `@CacheTTL` berfungsi untuk mengontrol perilaku caching secara granular di level endpoint. Mereka memungkinkan developer menentukan key dan durasi cache yang berbeda untuk setiap route tanpa harus menulis kode caching manual berulang-ulang.

## Cara Implementasi / Code

### 1. Aktifkan CacheInterceptor Global (Opsional)

```typescript
// src/main.ts
import { NestFactory } from '@nestjs/core';
import { AppModule } from './app.module';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);

  // Cache interceptor global — semua GET response otomatis di-cache
  app.useGlobalInterceptors(new (require('@nestjs/cache-manager').CacheInterceptor)());

  await app.listen(3000);
}
```

### 2. Cache di Controller dengan Custom Key & TTL

```typescript
// src/books/controllers/books.controller.ts
import {
  Controller, Get, Post, Patch, Delete, Param, Body, Query,
  UseInterceptors, UseGuards,
} from '@nestjs/common';
import { CacheInterceptor, CacheKey, CacheTTL } from '@nestjs/cache-manager';
import { BooksService } from '../services/books.service';

@Controller('books')
export class BooksController {
  constructor(private readonly booksService: BooksService) {}

  @Get()
  @UseInterceptors(CacheInterceptor) // Auto-cache berdasarkan URL
  @CacheKey('books:all') // Custom key, bukan URL
  @CacheTTL(30) // TTL 30 detik
  async findAll(@Query() query: QueryBooksDto) {
    return this.booksService.findAll(query);
  }

  @Get(':id')
  @UseInterceptors(CacheInterceptor)
  @CacheKey('books:detail') // Satu key untuk semua detail buku!
  @CacheTTL(60)
  async findOne(@Param('id') id: string) {
    return this.booksService.findOne(id);
  }

  @Get('popular')
  @UseInterceptors(CacheInterceptor)
  @CacheKey('books:popular')
  @CacheTTL(300) // 5 menit
  async getPopular() {
    return this.booksService.getPopularBooks();
  }

  @Post()
  async create(@Body() dto: CreateBookDto) {
    return this.booksService.create(dto); // Tidak di-cache (POST)
  }
}
```

### 3. Apa yang Terjadi di Balik Layar?

`CacheInterceptor` bekerja seperti ini:

```typescript
// Simplified logic of CacheInterceptor
async intercept(context: ExecutionContext, next: CallHandler) {
  const key = this.reflector.get(CACHE_KEY_METADATA, context.getHandler())
    || this.getRequestUrl(context); // Fallback ke URL

  const ttl = this.reflector.get(CACHE_TTL_METADATA, context.getHandler())
    || this.cacheOptions.ttl; // Fallback ke global TTL

  const cached = await this.cacheManager.get(key);
  if (cached) return of(cached);

  return next.handle().pipe(
    tap(response => this.cacheManager.set(key, response, ttl)),
  );
}
```

### 4. Kapan Pakai Auto vs Manual?

| Situasi | Pendekatan | Alasan |
|---------|-----------|--------|
| Endpoint sederhana, GET tanpa parameter dinamis | `@CacheInterceptor` (auto) | Cukup, tidak perlu boilerplate |
| Endpoint dengan pagination/filter | Auto + `@CacheKey` spesifik | Key harus mencakup query params |
| Data user-specific (riwayat pinjaman) | Manual di service | Tidak boleh di-cache global |
| Butuh control penuh (invalidation, conditional) | Manual via `CACHE_MANAGER` | Fleksibilitas maksimal |

## Analogi

Bayangkan **papan buletin** di perpustakaan yang menampilkan informasi berbeda di setiap sektor. Sektor "Buku Baru" diperbarui setiap 30 detik (TTL pendek). Sektor "Jam Buka" diperbarui setiap 1 jam (TTL panjang). Sektor "Pengumuman Khusus" hanya diperbarui saat petugas menggantinya (invalidation manual). Setiap sektor memiliki label unik (@CacheKey) — "new-books", "opening-hours", "announcement". Tanpa label, petugas bingung informasi mana yang harus diperbarui kapan.

## Penggunaan

- **@CacheKey**: Digunakan ketika endpoint yang berbeda secara tidak sengaja menghasilkan key yang sama (misal: `GET /books/1` dan `GET /books/2` tanpa `:id` di key akan tertimpa). Juga berguna untuk standardisasi key pattern.
- **@CacheTTL**: Digunakan untuk memberikan TTL berbeda per endpoint. Data master (kategori, author) bisa TTL panjang. Data yang sering berubah (stok, status pinjaman) butuh TTL pendek.
- **CacheInterceptor**: Cocok untuk endpoint GET publik yang tidak memerlukan logika invalidation kompleks.

## Kesalahan Umum yang Sering Terjadi

1. **CacheKey sama untuk semua resource** — contoh di atas `'books:detail'` adalah BUG! Semua detail buku akan mengembalikan data buku yang sama karena key tidak mengandung `:id`. Harusnya key dinamis: `book:${id}`. Sayangnya `@CacheKey` tidak bisa menerima parameter dinamis dari decorator — harus manual di service.
2. **CacheInterceptor di endpoint yang membutuhkan autentikasi** — response user A bisa dikirim ke user B jika key tidak mengandung userId. Jangan gunakan auto-cache untuk data personal.
3. **Lupa TTL di @CacheTTL** — nilai default dari global config akan dipakai. Jika global TTL terlalu panjang, data bisa basi.
4. **CacheInterceptor di method POST/PUT/PATCH** — interceptor hanya cocok untuk GET. Untuk mutation, gunakan manual cache agar bisa di-skip atau di-invalidate.

## Hubungan dengan Materi Sebelumnya

Materi **#55 (Cache-Aside)** dan **#56 (Cache Invalidation)** adalah pendekatan **manual/programmatic**. Materi ini (#57) adalah pendekatan **declarative** menggunakan decorator dan interceptor. Keduanya bisa digunakan bersama — gunakan interceptor untuk endpoint GET sederhana, dan manual untuk skenario yang membutuhkan kontrol lebih. Ini sejalan dengan filosofi NestJS yang mendukung berbagai paradigma.

## Soal Latihan

**Soal:**
Buat endpoint `GET /categories` dengan cache interceptor yang memiliki TTL 2 menit dan key `categories:list`. Kemudian buat endpoint `GET /categories/:id` tanpa cache interceptor (manual cache di service) karena perlu invalidation spesifik saat kategori diupdate.

**Jawaban:**

```typescript
// categories.controller.ts
@Get()
@UseInterceptors(CacheInterceptor)
@CacheKey('categories:list')
@CacheTTL(120)
async findAll() {
  return this.categoriesService.findAll();
}

@Get(':id')
async findOne(@Param('id') id: string) {
  return this.categoriesService.findOne(id);
}

// categories.service.ts — manual cache untuk detail
async findOne(id: string) {
  const cacheKey = `categories:${id}`;
  const cached = await this.cacheManager.get(cacheKey);
  if (cached) return cached;

  const category = await this.prisma.category.findUnique({
    where: { id },
    include: { books: true },
  });

  if (category) {
    await this.cacheManager.set(cacheKey, category, 120 * 1000);
  }

  return category;
}
```
