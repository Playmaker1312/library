# 54. Setup CacheModule dengan Redis

## Penjelasan

Seiring pertumbuhan data buku dan pengguna, query ke database menjadi semakin lambat. Untuk mengatasi ini, kita perlu **caching** — menyimpan hasil query yang sering diminta di memory sehingga request berikutnya tidak perlu lagi membebani database. NestJS menyediakan `@nestjs/cache-manager` yang merupakan abstraksi caching, dan kita akan mengintegrasikannya dengan Redis sebagai backend penyimpanan menggunakan package `cache-manager-ioredis-yet`.

Redis dipilih karena merupakan in-memory data store yang sangat cepat, mendukung TTL (Time-To-Live) untuk expiry otomatis, dan sudah umum digunakan sebagai caching layer di production. Dengan konfigurasi yang tepat, Redis dapat mengurangi latensi endpoint dari puluhan milidetik menjadi di bawah 1 milidetik untuk data yang sering diakses seperti daftar buku, detail buku, atau daftar kategori.

## Fungsi

Setup `CacheModule` bertujuan untuk mengintegrasikan Redis sebagai backend caching di aplikasi NestJS. Modul ini akan menyediakan `CACHE_MANAGER` yang bisa di-inject ke service mana pun untuk menyimpan dan mengambil data cache secara terprogram.

## Cara Implementasi / Code

### 1. Install Dependencies

```bash
npm install @nestjs/cache-manager cache-manager-ioredis-yet ioredis
```

### 2. Konfigurasi Redis

```typescript
// src/config/redis.config.ts
import { registerAs } from '@nestjs/config';

export default registerAs('redis', () => ({
  host: process.env.REDIS_HOST || 'localhost',
  port: parseInt(process.env.REDIS_PORT, 10) || 6379,
  password: process.env.REDIS_PASSWORD || undefined,
  ttl: parseInt(process.env.REDIS_TTL, 10) || 60, // default 60 detik
}));
```

### 3. Register CacheModule Global

```typescript
// src/cache/cache.module.ts
import { Module, CacheModule as NestCacheModule } from '@nestjs/common';
import { ConfigModule, ConfigService } from '@nestjs/config';
import * as redisStore from 'cache-manager-ioredis-yet';

@Module({
  imports: [
    NestCacheModule.registerAsync({
      imports: [ConfigModule],
      inject: [ConfigService],
      useFactory: async (config: ConfigService) => ({
        store: redisStore,
        host: config.get<string>('redis.host'),
        port: config.get<number>('redis.port'),
        password: config.get<string>('redis.password'),
        ttl: config.get<number>('redis.ttl'),
      }),
      isGlobal: true,
    }),
  ],
  exports: [NestCacheModule],
})
export class CacheModule {}
```

### 4. Environment Variables

```bash
# .env
REDIS_HOST=localhost
REDIS_PORT=6379
REDIS_TTL=60
```

### 5. Docker Compose untuk Redis (development)

```yaml
# docker-compose.yml
services:
  redis:
    image: redis:7-alpine
    container_name: nest-redis
    ports:
      - '6379:6379'
    volumes:
      - redis-data:/data

volumes:
  redis-data:
```

## Analogi

Bayangkan perpustakaan memiliki **rak buku favorit** di dekat pintu masuk. Buku-buku yang paling sering diminta (best-seller, buku referensi populer) diletakkan di rak ini. Ketika anggota bertanya "apakah ada buku X?", petugas cukup melihat ke rak favorit — lebih cepat daripada harus masuk ke gudang penyimpanan utama. Rak favorit ini adalah **cache**, gudang utama adalah **database**, dan aturan bahwa buku dipindahkan kembali setiap 60 menit adalah **TTL**. Redis adalah rak favorit yang super cepat dan bisa diatur ukurannya.

## Penggunaan

CacheModule digunakan di seluruh aplikasi untuk menyimpan:
- Daftar buku beserta kategori (endpoint `GET /books`)
- Detail buku tertentu (endpoint `GET /books/:id`)
- Data user yang sering diakses
- Hasil aggregasi atau kalkulasi berat
- Konfigurasi atau data master yang jarang berubah

## Kesalahan Umum yang Sering Terjadi

1. **Redis tidak berjalan** — aplikasi akan crash saat mencoba koneksi. Pastikan Redis service aktif atau tangani error dengan graceful fallback.
2. **TTL terlalu lama** — data bisa basi (stale). Misalnya, stok buku di-cache 1 jam padahal stok berubah setiap kali ada peminjaman.
3. **Cache di mana-mana tanpa strategi** — semua query di-cache tanpa memikirkan mana yang benar-benar perlu, malah membuang resource.
4. **Tidak menggunakan namespace/prefix** — key cache bentrok dengan aplikasi lain yang menggunakan Redis yang sama.
5. **Lupa install `cache-manager-ioredis-yet`** — package `cache-manager` v5+ tidak lagi bundled dengan store, harus manual.

## Hubungan dengan Materi Sebelumnya

Di **Level 3**, kita telah mempelajari optimasi query dengan Prisma — seperti `select`, `include`, dan pagination. Caching adalah **lapisan optimasi berikutnya** di atas optimasi query. Setelah query se-efisien mungkin, caching memberikan percepatan dramatis dengan menghindari query database sama sekali. Ini adalah skill production-grade yang membedakan aplikasi skala kecil dengan skala besar.

## Soal Latihan

**Soal:**
Buat konfigurasi Redis cluster dengan 3 nodes menggunakan `cache-manager-ioredis-yet`. Gunakan environment variables `REDIS_CLUSTER_NODES` yang berisi JSON array.

**Jawaban:**

```typescript
import * as redisStore from 'cache-manager-ioredis-yet';

useFactory: async (config: ConfigService) => {
  const clusterNodes = config.get<string>('REDIS_CLUSTER_NODES');
  const nodes = clusterNodes ? JSON.parse(clusterNodes) : undefined;

  return {
    store: redisStore,
    clusterConfig: nodes ? { nodes } : undefined,
    host: nodes ? undefined : (config.get<string>('redis.host') || 'localhost'),
    port: nodes ? undefined : (config.get<number>('redis.port') || 6379),
    ttl: config.get<number>('redis.ttl') || 60,
  };
},
```

```bash
# .env untuk cluster
REDIS_CLUSTER_NODES=[{"host":"127.0.0.1","port":7000},{"host":"127.0.0.1","port":7001},{"host":"127.0.0.1","port":7002}]
```
