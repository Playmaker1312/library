# 63. Setup Mailhog di Docker Compose — Email Catcher Development

## Penjelasan

Saat mengembangkan fitur email di environment development, kita tidak ingin benar-benar mengirim email ke alamat asli — selain berbahaya (bisa spam ke user nyata), juga merepotkan karena butuh SMTP server riil. **Mailhog** adalah solusi: sebuah email catching tool yang berpura-pura menjadi SMTP server. Semua email yang "dikirim" akan ditangkap oleh Mailhog dan bisa dilihat di Web UI-nya. Tidak ada email yang benar-benar terkirim ke luar.

Mailhog berjalan di Docker Container bersama Redis dan database PostgreSQL. Ia menyediakan SMTP port `1025` (untuk menerima email dari aplikasi NestJS) dan HTTP port `8025` (untuk Web UI di browser). Dengan Mailhog, developer bisa memeriksa tampilan email, memverifikasi template HTML, dan debugging pengiriman email tanpa risiko mengirim ke alamat asli.

## Fungsi

Mailhog berfungsi sebagai SMTP server palsu untuk environment development. Ia menangkap semua email yang dikirim oleh aplikasi dan menampilkannya di antarmuka web, memungkinkan developer untuk menginspeksi konten email tanpa benar-benar mengirimkannya ke penerima.

## Cara Implementasi / Code

### 1. Tambahkan Mailhog di Docker Compose

```yaml
# docker-compose.yml
version: '3.8'

services:
  postgres:
    image: postgres:15-alpine
    container_name: nest-postgres
    ports:
      - '5432:5432'
    environment:
      POSTGRES_DB: library_db
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: postgres
    volumes:
      - postgres-data:/var/lib/postgresql/data

  redis:
    image: redis:7-alpine
    container_name: nest-redis
    ports:
      - '6379:6379'
    volumes:
      - redis-data:/data

  mailhog:
    image: mailhog/mailhog:latest
    container_name: nest-mailhog
    ports:
      - '1025:1025'   # SMTP server
      - '8025:8025'   # Web UI
    environment:
      MH_STORAGE: maildir
      MH_MAILDIR_PATH: /tmp/maildir
    volumes:
      - mailhog-data:/tmp/maildir

volumes:
  postgres-data:
  redis-data:
  mailhog-data:
```

### 2. Konfigurasi Email di NestJS

```bash
# .env
MAIL_HOST=localhost
MAIL_PORT=1025
MAIL_USER=
MAIL_PASS=
MAIL_FROM=noreply@library.com
MAIL_FROM_NAME=Perpustakaan Digital
```

### 3. Jalankan Semua Service

```bash
# Jalankan semua container
docker-compose up -d

# Cek status
docker-compose ps

# Output:
# nest-postgres  Up  (port 5432)
# nest-redis     Up  (port 6379)
# nest-mailhog   Up  (port 1025, 8025)
```

### 4. Cek Mailhog Web UI

```
Buka browser: http://localhost:8025

Tampilan akan menunjukkan:
- Inbox kosong (belum ada email)
- Setelah aplikasi mengirim email, akan muncul daftar email di sini
- Klik email untuk melihat detail: From, To, Subject, Body (HTML & plain text)
- Tab JSON untuk melihat header SMTP
```

### 5. Production vs Development

```typescript
// src/config/email.config.ts
import { registerAs } from '@nestjs/config';

export default registerAs('email', () => ({
  host: process.env.MAIL_HOST,
  port: parseInt(process.env.MAIL_PORT, 10) || 587,
  user: process.env.MAIL_USER,
  pass: process.env.MAIL_PASS,
  from: process.env.MAIL_FROM || 'noreply@library.com',
  fromName: process.env.MAIL_FROM_NAME || 'Perpustakaan Digital',
  // Di development, gunakan Mailhog (ignore TLS errors)
  ignoreTLS: process.env.NODE_ENV === 'development',
  secure: process.env.NODE_ENV === 'production', // true untuk port 465
}));
```

## Analogi

Bayangkan perpustakaan memiliki **keranjang surat internal** di ruang belakang untuk keperluan latihan petugas baru. Petugas magang bisa berlatih menulis dan mengirim surat seperti biasa — amplop, perangko, alamat tujuan — tapi semua surat tidak pernah benar-benar dikirim ke kantor pos. Sebaliknya, surat-surat itu jatuh ke keranjang latihan (Mailhog) dan bisa diperiksa oleh pelatih untuk dinilai. Setelah mahir, petugas baru boleh menggunakan prosedur pengiriman asli (SMTP production). Mailhog adalah keranjang latihan untuk email.

## Penggunaan

Mailhog digunakan di:
- **Development lokal**: testing fitur email tanpa risiko spam
- **CI/CD pipeline**: verifikasi bahwa email terkirim dengan benar di integration test
- **QA/Staging**: preview tampilan email sebelum production
- **Demo**: menunjukkan fitur notifikasi email ke stakeholder
- **Debugging**: memeriksa isi, header, dan attachment email

## Kesalahan Umum yang Sering Terjadi

1. **Mailhog tidak berjalan** — aplikasi akan timeout saat mencoba koneksi SMTP. Cek `docker-compose ps` untuk memastikan container aktif.
2. **Port conflict** — port 1025 atau 8025 sudah dipakai aplikasi lain. Ganti port mapping di docker-compose.
3. **Email tidak muncul di Web UI** — periksa konfigurasi SMTP di aplikasi (host, port, credential). Mailhog tidak butuh auth, jadi `MAIL_USER` dan `MAIL_PASS` harus dikosongkan.
4. **Mengirim email asli dari development** — jika lupa mengganti konfigurasi SMTP ke Mailhog, email akan terkirim ke alamat asli. Selalu gunakan environment variable `NODE_ENV` untuk switching.
5. **Storage Mailhog penuh** — di development yang intensif, ribuan email bisa menumpuk. Setel `MH_STORAGE=memory` atau periodic cleanup.

## Soal Latihan

**Soal:**
Akses Mailhog API untuk mengambil daftar email yang sudah ditangkap menggunakan curl, tanpa membuka browser. Tulis command untuk mengambil dan menampilkan total email yang diterima Mailhog.

**Jawaban:**

```bash
# Mailhog menyediakan REST API di port 8025

# Ambil daftar semua email
curl http://localhost:8025/api/v2/messages

# Hitung total email (gunakan jq untuk parsing JSON)
curl -s http://localhost:8025/api/v2/messages | jq '.total'

# Ambil detail email pertama
curl -s http://localhost:8025/api/v2/messages | jq '.items[0]'

# Hapus semua email (cleanup)
curl -X DELETE http://localhost:8025/api/v1/messages
```

```typescript
// Integrasi Mailhog API untuk automated test
async function getCapturedEmails(): Promise<any[]> {
  const response = await fetch('http://localhost:8025/api/v2/messages');
  const data = await response.json();
  return data.items;
}

// Test example
const emails = await getCapturedEmails();
expect(emails.length).toBe(1);
expect(emails[0].Content.Headers.Subject[0]).toBe('Konfirmasi Peminjaman Buku');
```
