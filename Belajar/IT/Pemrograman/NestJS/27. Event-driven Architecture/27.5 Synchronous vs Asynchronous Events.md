# 27. Event-driven Architecture
## 27.5 Synchronous vs Asynchronous Events
**Definisi Singkat:** Event di EventEmitter2 bisa dikirim secara synchronous (`emit()`) yang memblokir eksekusi sampai semua listener selesai, atau asynchronous (`emitAsync()`) yang mengembalikan Promise dan bisa di-await.
**Analogi:** Synchronous seperti memberikan instruksi langsung ke rekan kerja dan menunggu dia selesai sebelum melanjutkan kerja. Asynchronous seperti mengirim email — Anda lanjut kerja, dan balasannya datang kemudian.
**Poin-Poin Penting:**
- `emit()` — blocking, semua listener jalan sequential
- `emitAsync()` — non-blocking, return Promise
- Konfigurasi `@OnEvent('evt', { async: true })`
**Contoh Kode:**
```typescript
// sync-vs-async.service.ts
import { Injectable } from '@nestjs/common';
import { EventEmitter2 } from '@nestjs/event-emitter';

@Injectable()
export class DemoService {
  constructor(private eventEmitter: EventEmitter2) {}

  // Synchronous event — semua listener dijalankan secara berurutan
  // Method ini akan menunggu hingga semua listener selesai
  syncEventDemo() {
    console.log('[1] Mulai proses synchronous');

    // emit() adalah blocking — method tidak lanjut sampai semua listener selesai
    this.eventEmitter.emit('data.processed', { id: 1 });
    
    // Baris ini akan dieksekusi SETELAH semua listener 'data.processed' selesai
    console.log('[3] Proses synchronous selesai');
  }

  // Asynchronous event — menggunakan emitAsync()
  async asyncEventDemo() {
    console.log('[1] Mulai proses asynchronous');

    // emitAsync() mengembalikan Promise
    // Kita bisa await untuk mendapatkan hasil dari semua listener
    const results = await this.eventEmitter.emitAsync('data.processed.async', { id: 2 });

    // results berisi array return value dari setiap listener
    console.log('[3] Hasil dari semua listener:', results);
    console.log('[4] Proses asynchronous selesai');
  }

  // Fire-and-forget — tidak perlu menunggu hasil listener
  fireAndForgetDemo() {
    console.log('[1] Fire and forget');

    // emit() tanpa menyimpan return value — tidak peduli kapan selesai
    this.eventEmitter.emit('notification.send', { message: 'Hello' });

    // Langsung eksekusi baris berikutnya
    console.log('[2] Kembali ke proses utama');
  }

  // Error handling untuk async events
  async asyncEventWithErrorHandling() {
    try {
      const results = await this.eventEmitter.emitAsync('payment.process', { amount: 100 });
      console.log('Semua listener berhasil:', results);
    } catch (error) {
      // Jika ada listener yang throw error, akan tertangkap di sini
      console.error('Listener gagal:', error.message);
    }
  }
}
```
```typescript
// listener-demo.service.ts
import { Injectable } from '@nestjs/common';
import { OnEvent } from '@nestjs/event-emitter';

@Injectable()
export class ListenerDemoService {
  // Listener synchronous — akan blocking emitter
  @OnEvent('data.processed')
  handleSyncListener(payload: any) {
    console.log('[2] Listener sync mulai proses');
    // Simulasi proses berat
    const start = Date.now();
    while (Date.now() - start < 1000) {
      // blocking selama 1 detik
    }
    console.log('[2] Listener sync selesai');
    return 'sync result';
  }

  // Listener async — tidak blocking emitter jika pakai emitAsync
  @OnEvent('data.processed.async', { async: true })
  async handleAsyncListener(payload: any) {
    console.log('[2] Listener async mulai');
    await new Promise((resolve) => setTimeout(resolve, 1000));
    console.log('[2] Listener async selesai');
    return 'async result';
  }

  // Listener dengan error — tidak akan crash aplikasi jika suppressErrors: true
  @OnEvent('notification.send', { suppressErrors: true })
  handleNotification(payload: any) {
    // Error di sini tidak akan merusak proses utama
    throw new Error('Gagal kirim notifikasi (tapi ini sengaja)');
  }
}
```
**Kasus Penggunaan Nyata:** Gunakan `emitAsync()` untuk operasi kritis yang memerlukan validasi dari listener — misalnya `order.placed` di mana listener `InventoryService` harus memverifikasi stok tersedia sebelum order dikonfirmasi. Gunakan `emit()` untuk fire-and-forget seperti logging, analytics, atau notifikasi yang tidak mempengaruhi alur utama.
