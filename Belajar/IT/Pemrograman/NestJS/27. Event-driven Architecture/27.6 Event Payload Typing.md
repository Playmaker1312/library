# 27. Event-driven Architecture
## 27.6 Event Payload Typing
**Definisi Singkat:** TypeScript typing untuk event payload memastikan type safety antara event emitter dan listener, mencegah kesalahan struktur data saat mengirim dan menerima event.
**Analogi:** Seperti formulir resmi — setiap event memiliki format tertentu yang harus diisi, dan penerima tahu persis data apa yang akan diterima, mengurangi kesalahan komunikasi.
**Poin-Poin Penting:**
- Interface typing untuk setiap event payload
- Type-safe event emitter wrapper
- Generic types untuk event handler
**Contoh Kode:**
```typescript
// events/order.events.ts
// Definisikan interface untuk setiap event payload
export interface OrderCreatedEvent {
  orderId: number;
  userId: number;
  items: OrderItem[];
  total: number;
  createdAt: Date;
}

export interface OrderItem {
  productId: number;
  productName: string;
  quantity: number;
  price: number;
}

export interface OrderShippedEvent {
  orderId: number;
  shippingAddress: string;
  trackingNumber: string;
  estimatedDelivery: Date;
}

export interface PaymentCompletedEvent {
  transactionId: string;
  orderId: number;
  amount: number;
  paymentMethod: string;
  paidAt: Date;
}
```
```typescript
// events/user.events.ts
export interface UserRegisteredEvent {
  userId: number;
  email: string;
  name: string;
  registeredAt: Date;
}

export interface UserUpdatedEvent {
  userId: number;
  changes: Partial<{
    name: string;
    email: string;
    avatar: string;
  }>;
  updatedAt: Date;
}

// Map event name ke payload type-nya — centralized typing
export interface EventPayloadMap {
  'user.registered': UserRegisteredEvent;
  'user.updated': UserUpdatedEvent;
  'order.created': OrderCreatedEvent;
  'order.shipped': OrderShippedEvent;
  'payment.completed': PaymentCompletedEvent;
}
```
```typescript
// typed-event-emitter.service.ts
import { Injectable } from '@nestjs/common';
import { EventEmitter2 } from '@nestjs/event-emitter';
import { EventPayloadMap } from './events/user.events';

// Type-safe wrapper untuk EventEmitter2
@Injectable()
export class TypedEventEmitter {
  constructor(private eventEmitter: EventEmitter2) {}

  // Generic method dengan constraint ke key dari EventPayloadMap
  emit<K extends keyof EventPayloadMap>(event: K, payload: EventPayloadMap[K]): boolean {
    return this.eventEmitter.emit(event as string, payload);
  }

  // Async version
  async emitAsync<K extends keyof EventPayloadMap>(
    event: K,
    payload: EventPayloadMap[K],
  ): Promise<any[]> {
    return this.eventEmitter.emitAsync(event as string, payload);
  }
}
```
```typescript
// typed-listener.service.ts
import { Injectable } from '@nestjs/common';
import { OnEvent } from '@nestjs/event-emitter';
import { OrderCreatedEvent, UserRegisteredEvent } from './events/order.events';

@Injectable()
export class TypedListenerService {
  // Listener dengan tipe payload yang eksplisit — type safety terjamin
  @OnEvent('order.created')
  handleOrderCreated(payload: OrderCreatedEvent) {
    // TypeScript tahu bahwa payload.total adalah number
    // TypeScript tahu bahwa payload.items adalah array of OrderItem
    console.log(`Order #${payload.orderId} senilai Rp${payload.total}`);
    payload.items.forEach((item) => {
      console.log(`  - ${item.productName} x${item.quantity}: Rp${item.price}`);
    });
  }

  @OnEvent('user.registered')
  handleUserRegistered(payload: UserRegisteredEvent) {
    // TypeScript akan error jika payload.email tidak ada
    console.log(`User baru: ${payload.name} (${payload.email})`);
  }
}
```
**Kasus Penggunaan Nyata:** Dalam aplikasi monolith yang besar dengan banyak service, typing event payload mencegah bug akibat perubahan struktur data. Misalnya, jika tim `PaymentService` mengubah struktur `PaymentCompletedEvent` dengan menambah field `installment`, TypeScript akan memastikan semua listener diperbarui sesuai.
