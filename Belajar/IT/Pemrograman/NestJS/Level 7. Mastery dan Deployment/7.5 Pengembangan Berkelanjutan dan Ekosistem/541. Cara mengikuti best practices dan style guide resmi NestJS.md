# 541. Cara mengikuti best practices dan style guide resmi NestJS

## Definisi & Target
NestJS memiliki pedoman resmi: struktur folder, naming convention, dependency injection, testing. Target: kode yang konsisten, mudah dibaca, dan scalable.

## Komponen & Nest CLI Command
```
npm install -g @nestjs/cli
npm install --save-dev eslint @nestjs/eslint-config
```

## Kode Implementasi (Per File)

```
// .eslintrc.js — ESLint konfigurasi NestJS
module.exports = {
  parser: '@typescript-eslint/parser',
  parserOptions: {
    project: 'tsconfig.json',
    sourceType: 'module',
  },
  plugins: ['@typescript-eslint/eslint-plugin'],
  extends: [
    'plugin:@typescript-eslint/recommended',
    'plugin:prettier/recommended',
  ],
  root: true,
  env: { node: true, jest: true },
  ignorePatterns: ['.eslintrc.js'],
  rules: {
    '@typescript-eslint/no-explicit-any': 'warn',
    '@typescript-eslint/explicit-function-return-type': 'warn',
    '@typescript-eslint/no-unused-vars': ['error', { argsIgnorePattern: '^_' }],
  },
};
```

```
// Best Practices Guide — NestJS
// 1. Struktur: modules/ → fitur bisnis, common/ → shared
// 2. Naming: *.service.ts, *.controller.ts, *.module.ts, *.dto.ts
// 3. 1 file per class, 1 class per file
// 4. Dependency Injection → constructor-based, bukan setter
// 5. Gunakan @nestjs/config, jangan process.env langsung
// 6. Semua input → DTO dengan class-validator
// 7. Error handling → Exception filters, bukan try-catch di controller
// 8. Testing → unit test untuk service, e2e untuk controller
// 9. Gunakan interfaces untuk kontrak, bukan classes
// 10. Functional -> gunakan custom decorators untuk cross-cutting concerns
```

## Cara Integrasi & Pengujian
Aktifkan ESLint dengan konfigurasi di atas. Jalankan `npm run lint` secara rutin. Ikuti struktur folder modular. Review PR untuk memastikan konsistensi.
