# 525. Cara melakukan incident response berdasarkan monitoring alerts

## Definisi & Target
SOP (Standard Operating Procedure) saat alert terpicu. Target: response cepat dan terstruktur — detect, diagnose, resolve, dan post-mortem.

## Komponen & Nest CLI Command
Tidak ada perintah CLI — ini adalah panduan prosedural.

## Kode Implementasi (Per File)

```
// INCIDENT_RESPONSE_PLAN.md (standar operasi)
# Incident Response Plan — NestJS App

## Severity Levels
- P1 (Critical): App down, data loss
- P2 (High): Feature degraded, high latency
- P3 (Medium): Non-critical bug
- P4 (Low): Cosmetic issue

## Response Steps
1. Acknowledge — respond di PagerDuty dalam 5 menit (P1) / 15 menit (P2)
2. Triage — cek Grafana dashboard, lihat metrics anomali
3. Diagnose — cek log (kibana/papertrail), trace (jaeger), health endpoint
4. Escalate — jika tidak bisa resolve dalam 30 menit, panggil senior engineer
5. Mitigate — rollback deploy, nonaktifkan feature flag, scale up
6. Resolve — deploy fix, verifikasi health check hijau
7. Post-mortem — analisis root cause, buat action item

## Runbooks
### Database CPU 100%
- Cek slow queries: `EXPLAIN ANALYZE`
- Tambah index: `CREATE INDEX CONCURRENTLY`
- Scale up read replicas

### Memory Leak
- Heap dump: `node --heapsnapshot-signal=SIGUSR2`
- Analisis dump di Chrome DevTools
- Restart pod jika urgent
```
