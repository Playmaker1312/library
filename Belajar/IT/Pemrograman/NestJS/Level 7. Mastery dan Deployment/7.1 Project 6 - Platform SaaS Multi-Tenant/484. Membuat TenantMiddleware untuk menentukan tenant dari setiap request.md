# 484. Membuat TenantMiddleware untuk menentukan tenant dari setiap request

## Definisi & Target
`TenantMiddleware` berjalan di setiap request, membaca tenant ID dari subdomain/header, lalu menyimpannya ke `TenantIdentificationService` dan `AsyncLocalStorage`. Target: semua request memiliki konteks tenant sebelum mencapai handler.

## Komponen & Nest CLI Command
```
nest g middleware tenancy/tenant
```

## Kode Implementasi (Per File)

```
// src/tenancy/tenant.middleware.ts
import { Injectable, NestMiddleware } from '@nestjs/common';
import { Request, Response, NextFunction } from 'express';
import { TenantIdentificationService } from './tenant-identification.service';
import { TenantContextService } from './tenant-context.service';

@Injectable()
export class TenantMiddleware implements NestMiddleware {
  constructor(
    private readonly identification: TenantIdentificationService,
    private readonly context: TenantContextService,
  ) {}

  use(req: Request, res: Response, next: NextFunction) {
    const tenantId = req.headers['x-tenant-id'] as string
      ?? this.identification.extractFromSubdomain(req.hostname);

    if (!tenantId) {
      return res.status(400).json({ message: 'Tenant ID required' });
    }

    this.identification.setTenantId(tenantId);
    this.context.run(tenantId, next);
  }
}
```

```
// src/app.module.ts
import { MiddlewareConsumer, Module, NestModule } from '@nestjs/common';
import { TenantMiddleware } from './tenancy/tenant.middleware';

@Module({ imports: [] })
export class AppModule implements NestModule {
  configure(consumer: MiddlewareConsumer) {
    consumer.apply(TenantMiddleware).forRoutes('*');
  }
}
```

## Cara Integrasi & Pengujian
Daftarkan middleware di `AppModule` untuk semua routes. Uji: `curl -H "X-Tenant-ID: tenant-abc" http://localhost:3000/protected` → middleware harus meneruskan request.
