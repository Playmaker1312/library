# 482. Memahami strategi multi-tenancy yaitu shared database, schema per tenant, dan database per tenant

## Definisi & Target
Tiga strategi isolasi data: **Shared Database** (satu DB, kolom `tenantId`), **Schema per Tenant** (satu DB, schema terpisah), **Database per Tenant** (DB terpisah). Target: pahami trade-off dan pilih berdasarkan kebutuhan keamanan & skalabilitas.

## Komponen & Nest CLI Command
Tidak ada CLI — keputusan arsitektural.

| Strategy | Isolasi | Biaya | Kompleksitas | Cocok untuk |
|---|---|---|---|---|
| Shared DB | Rendah | Rendah | Rendah | Aplikasi internal |
| Schema per Tenant | Sedang | Sedang | Sedang | Mid-market SaaS |
| Database per Tenant | Tinggi | Tinggi | Tinggi | Enterprise / Regulasi ketat |

## Kode Implementasi (Per File)

```
// src/common/constants/tenancy-strategy.enum.ts
export enum TenancyStrategy {
  SHARED_DATABASE = 'shared',
  SCHEMA_PER_TENANT = 'schema',
  DATABASE_PER_TENANT = 'database',
}
```

```
// src/config/configuration.ts
export default () => ({
  tenancy: {
    strategy: process.env.TENANCY_STRATEGY || 'database',
    tenantIdColumn: 'tenant_id',
  },
});
```

## Cara Integrasi & Pengujian
Pilih strategy di `.env` via `TENANCY_STRATEGY`. Untuk proyek ini kita gunakan **Database per Tenant** karena memberikan isolasi maksimal dan paling cocok untuk enterprise SaaS.
