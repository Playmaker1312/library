# 481. Merencanakan arsitektur SaaS multi-tenant dengan isolasi data yang baik

## Definisi & Target
Multi-tenant SaaS berarti satu instance aplikasi melayani banyak tenant (customer) dengan data terisolasi. Target: arsitektur modular menggunakan strategy **Database per Tenant** untuk isolasi maksimal, diidentifikasi lewat subdomain.

Alur: Request → Subdomain → TenantMiddleware → PrismaService → Database tenant-specific.

## Komponen & Nest CLI Command
```
nest g module tenancy
nest g middleware tenancy/tenant
nest g service tenancy/prisma
nest g module tenant-management
nest g resource tenant-management/tenants --no-spec
nest g module billing
nest g module feature-flags
```

## Kode Implementasi (Per File)

```
// high-level-architecture.ts — ilustrasi struktur folder
src/
  tenancy/
    tenant.middleware.ts
    prisma.service.ts
    tenant-context.service.ts
  modules/
    tenants/          # Tenant management (super admin)
    billing/          # Stripe integration
    feature-flags/    # Feature toggle per plan
  common/
    guards/           # tenant-aware guards
    interceptors/     # tenant injection
  prisma/
    schema.prisma
```

## Cara Integrasi & Pengujian
Arsitektur ini menjadi fondasi semua poin selanjutnya (482–495). Pastikan setiap modul terdaftar di `AppModule`. Uji dengan membuat dua tenant berbeda dan verifikasi data tidak tercampur.
