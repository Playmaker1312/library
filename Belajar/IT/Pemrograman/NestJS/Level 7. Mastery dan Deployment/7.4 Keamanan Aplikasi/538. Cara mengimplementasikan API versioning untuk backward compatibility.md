# 538. Cara mengimplementasikan API versioning untuk backward compatibility

## Definisi & Target
API versioning memungkinkan perubahan breaking tanpa memutus klien lama. Target: version via URL prefix (`/v1`, `/v2`) atau header.

## Komponen & Nest CLI Command
```
nest g module v1 --no-spec
nest g module v2 --no-spec
```

## Kode Implementasi (Per File)

```
// src/main.ts (URI versioning)
import { NestFactory } from '@nestjs/core';
import { AppModule } from './app.module';
import { VersioningType } from '@nestjs/common';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);

  app.enableVersioning({
    type: VersioningType.URI,
    prefix: 'v',
    defaultVersion: '1',
  });

  await app.listen(3000);
}
```

```
// src/modules/users/users.controller.ts (controller-level version)
import { Controller, Get, Version } from '@nestjs/common';

@Controller('users')
export class UsersController {
  @Get()
  @Version('1')
  findAllV1() {
    return { version: 1, data: [] };
  }

  @Get()
  @Version('2')
  findAllV2() {
    return { version: 2, data: [], meta: { total: 0 } };
  }
}
```

```
// src/modules/users/users.controller.ts (header versioning)
import { Controller, Get } from '@nestjs/common';

@Controller({
  path: 'users',
  version: '1',
})
export class UsersControllerV1 {
  @Get()
  findAll() {
    return { version: 1 };
  }
}

@Controller({
  path: 'users',
  version: '2',
})
export class UsersControllerV2 {
  @Get()
  findAll() {
    return { version: 2, pagination: true };
  }
}
```

## Cara Integrasi & Pengujian
Enable versioning di `main.ts`. Akses `GET /v1/users` → response versi 1. Akses `GET /v2/users` → response versi 2 dengan metadata.
