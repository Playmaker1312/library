# 540. Cara membuat security checklist untuk deployment NestJS ke production

## Definisi & Target
Checklist keamanan untuk memastikan aplikasi NestJS siap production. Target: verifikasi sistematis sebelum dan sesudah deploy.

## Komponen & Nest CLI Command
Tidak ada CLI — panduan checklist.

## Kode Implementasi (Per File)

```
# SECURITY_CHECKLIST.md
# Security Checklist — NestJS Production Deployment

## Pre-Deployment
- [ ] Semua secret menggunakan vault / environment variables
- [ ] .env.production tidak di-commit ke git
- [ ] `npm audit --audit-level=high` lulus
- [ ] class-validator DTO untuk semua input
- [ ] ValidationPipe global aktif
- [ ] Helmet middleware terpasang
- [ ] CORS terbatas ke domain frontend saja
- [ ] Rate limiting aktif (login: 5/menit, API: 100/menit)
- [ ] Request body size limit: 1MB (JSON), 10MB (file)
- [ ] JWT secret min 32 karakter, random
- [ ] HTTPS wajib, HSTS enabled
- [ ] API versioning aktif
- [ ] Role-based access control (RBAC) untuk semua endpoint
- [ ] Logging tidak mencatat password / credit card
- [ ] Prisma raw query menggunakan parameter binding

## Post-Deployment
- [ ] Health check endpoint berjalan (`/health` → 200)
- [ ] Security headers dicek (helmet)
- [ ] Penetration test (SQLi, XSS, IDOR) lulus
- [ ] SSL certificate valid (tidak expired)
- [ ] Docker image tidak berjalan sebagai root
- [ ] Database hanya accessible dari aplikasi (firewall)
- [ ] Redis membutuhkan password
- [ ] Backup database otomatis aktif
- [ ] Monitoring (Prometheus + Grafana) aktif
- [ ] Alerting (PagerDuty/OpsGenie) terkonfigurasi
- [ ] Log rotation aktif
- [ ] npm dependencies tidak ada yang deprecated

## Incident Response
- [ ] Rollback plan siap
- [ ] Kontak tim keamanan tercatat
- [ ] Post-mortem template siap
```

## Cara Integrasi & Pengujian
Cetak checklist, centang setiap item sebelum deploy ke production. Otomatiskan item yang bisa di-script (audit, headers check) di CI pipeline.
