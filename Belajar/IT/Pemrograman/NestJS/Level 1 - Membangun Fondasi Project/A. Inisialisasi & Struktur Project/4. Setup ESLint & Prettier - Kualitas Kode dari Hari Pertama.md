# Setup ESLint & Prettier — Kualitas Kode dari Hari Pertama

## Penjelasan

ESLint dan Prettier adalah dua tools esensial dalam pengembangan NestJS modern. **ESLint** bertugas menemukan dan memperbaiki masalah pada kode berdasarkan aturan yang bisa dikonfigurasi — seperti mendeteksi variabel yang tidak dipakai, penggunaan `any` yang tidak perlu, atau pola kode yang berpotensi error. **Prettier** adalah opinionated code formatter yang secara otomatis merapikan format kode seperti indentasi, panjang baris, penggunaan tanda kutip, dan trailing comma.

NestJS CLI secara default sudah menyertakan konfigurasi ESLint dan Prettier saat project dibuat dengan `nest new`. Konfigurasi ini menggunakan aturan dari `@nestjs/eslint-config` yang sudah dioptimalkan untuk project NestJS. Namun, kita bisa menambahkan aturan tambahan sesuai kebutuhan tim. Dengan menggabungkan ESLint (kualitas kode) dan Prettier (format kode), kita mendapatkan dua lapisan penjagaan yang saling melengkapi.

Untuk menghindari konflik antara ESLint dan Prettier, kita menggunakan package `eslint-config-prettier` yang menonaktifkan aturan ESLint yang bertabrakan dengan Prettier. Dengan setup ini, ESLint fokus pada logic error dan best practice, sementara Prettier menangani semua urusan format. Idealnya, kedua tools ini dijalankan secara otomatis setiap kali file disimpan (melalui extension VS Code) atau sebelum commit (melalui lint-staged).

## Fungsi

ESLint berfungsi untuk menjaga **kualitas logika kode** — mencegah bug dengan mendeteksi pola berbahaya, memastikan konsistensi gaya penulisan, dan menegakkan best practice TypeScript. Prettier berfungsi untuk menjaga **kerapian format kode** — sehingga seluruh anggota tim memiliki gaya penulisan yang identik tanpa perlu diskusi soal indentasi atau tanda kutip. Keduanya bersama-sama menghasilkan kode yang bersih, konsisten, dan mudah di-review.

## Cara Implementasi / Code

### Konfigurasi ESLint (`.eslintrc.js`)

```javascript
module.exports = {
  parser: '@typescript-eslint/parser',
  parserOptions: {
    project: 'tsconfig.json',
    tsconfigRootDir: __dirname,
    sourceType: 'module',
  },
  plugins: ['@typescript-eslint/eslint-plugin'],
  extends: [
    'plugin:@typescript-eslint/recommended',
    'plugin:prettier/recommended', // Wajib: gabung dengan Prettier
  ],
  root: true,
  env: {
    node: true,
    jest: true,
  },
  ignorePatterns: ['.eslintrc.js'],
  rules: {
    // Aturan kustom untuk project NestJS
    '@typescript-eslint/no-explicit-any': 'warn',   // Peringatan jika pakai any
    '@typescript-eslint/no-unused-vars': 'error',    // Error jika ada variabel tidak dipakai
    '@typescript-eslint/explicit-function-return-type': 'off', // Tidak wajib
    '@typescript-eslint/no-empty-function': 'warn',  // Peringatan fungsi kosong
    'no-console': 'warn',                            // Peringatan jika ada console.log
    'prefer-const': 'error',                         // Wajib const jika tidak reassign
    
    // Aturan NestJS spesifik
    '@typescript-eslint/interface-name-prefix': 'off', // Tidak perlu prefix I
    '@typescript-eslint/explicit-module-boundary-types': 'off',
  },
};
```

### Konfigurasi Prettier (`.prettierrc`)

```json
{
  "singleQuote": true,
  "trailingComma": "all",
  "tabWidth": 2,
  "semi": true,
  "printWidth": 100,
  "bracketSpacing": true,
  "arrowParens": "always",
  "endOfLine": "auto"
}
```

### Setup VS Code agar otomatis format on save

Buat file `.vscode/settings.json` di root project:

```json
{
  "editor.defaultFormatter": "esbenp.prettier-vscode",
  "editor.formatOnSave": true,
  "editor.codeActionsOnSave": {
    "source.fixAll.eslint": "explicit"
  }
}
```

### Script di package.json (bawaan NestJS CLI)

```json
{
  "scripts": {
    "lint": "eslint \"{src,apps,libs,test}/**/*.ts\" --fix",
    "format": "prettier --write \"src/**/*.ts\" \"test/**/*.ts\""
  }
}
```

### Cara menjalankan:

```bash
# Menjalankan ESLint (perbaiki otomatis dengan --fix)
pnpm run lint

# Menjalankan Prettier
pnpm run format

# Cek saja tanpa perbaiki
npx eslint "src/**/*.ts"
npx prettier --check "src/**/*.ts"
```

### Integrasi dengan Husky dan lint-staged (opsional, untuk auto-fix sebelum commit)

```bash
pnpm add -D husky lint-staged

# Setup husky
npx husky init

# Tambahkan hook pre-commit
npx husky add .husky/pre-commit "npx lint-staged"
```

Konfigurasi `lint-staged` di `package.json`:

```json
{
  "lint-staged": {
    "*.ts": ["eslint --fix", "prettier --write", "git add"]
  }
}
```

## Analogi

Bayangkan perpustakaan memiliki **dua orang petugas quality control** untuk setiap buku baru yang masuk:

- **ESLint** adalah **pemeriksa isi buku** — ia membaca setiap kalimat, memastikan tidak ada fakta salah (bug), tidak ada halaman kosong (variabel tidak dipakai), dan semua referensi ditulis dengan benar. Jika ada masalah, ia akan memberi tanda di pinggir halaman.

- **Prettier** adalah **penata letak buku** — ia memastikan setiap halaman memiliki margin yang rapi, font size konsisten, bab dimulai di halaman genap (format konsisten), dan tidak ada halaman yang terlalu penuh atau terlalu kosong.

Keduanya bekerja sama: setelah **Prettier** merapikan tata letak, **ESLint** memeriksa isinya. Jika ada konflik (misalnya Prettier ingin pakai tanda kutip tunggal tapi ESLint melarangnya), kita menggunakan **eslint-config-prettier** sebagai **mediator** yang memastikan kedua petugas tidak bertengkar.

File `.vscode/settings.json` seperti **papan peraturan** yang ditempel di meja setiap pustakawan — mengingatkan mereka untuk selalu memeriksa buku sesuai standar yang sudah ditetapkan, setiap kali mereka menyelesaikan sebuah halaman (save file).

## Penggunaan

ESLint dan Prettier dipakai di **semua project profesional** tanpa terkecuali. Di tahap development, developer menjalankan `pnpm run lint` sebelum commit untuk memastikan tidak ada error. Di CI/CD pipeline, linting biasanya menjadi langkah pertama sebelum testing dan build. Tim besar sering menambahkan aturan kustom sesuai standar mereka, seperti melarang `console.log` di production atau mewajibkan tipe eksplisit untuk function parameters.

## Kesalahan Umum yang Sering Terjadi

1. **Konflik ESLint vs Prettier** — Aturan ESLint bertentangan dengan Prettier (misalnya masalah indentasi). Solusi: pastikan `plugin:prettier/recommended` ada di urutan terakhir array `extends` di `.eslintrc.js`.

2. **Tidak menginstall extension VS Code** — ESLint dan Prettier hanya berfungsi sebagai CLI jika dijalankan manual. Agar otomatis format on save, install extension ESLint dan Prettier di VS Code.

3. **Over-riding aturan Prettier dengan ESLint** — Jika menambahkan aturan `indent` atau `quotes` di ESLint, akan konflik dengan Prettier. Biarkan Prettier yang menangani format, ESLint untuk logic.

4. **Mematikan semua aturan ESLint** — Beberapa pemula mematikan aturan seperti `no-explicit-any` di awal, yang sebenarnya sangat membantu. Sebaiknya biasakan menggunakan aturan strict dari awal.

5. **Lupa menjalankan lint sebelum commit** — Banyak bug sederhana (seperti variabel typo) yang bisa dicegah dengan linting. Gunakan husky + lint-staged agar linting otomatis berjalan sebelum commit.

## Hubungan dengan Materi Sebelumnya

Di materi ke-1 dan ke-2, kita membuat project dan memahami file-file yang dihasilkan CLI — termasuk `.eslintrc.js` dan `.prettierrc` yang sudah tersedia. Di materi ini, kita memodifikasi dan mengoptimalkan konfigurasi tersebut. Project kita sekarang memiliki fondasi kode yang berkualitas, yang akan sangat membantu saat kita mulai menulis kode di materi-materi berikutnya (materi 7-16).

## Soal Latihan

**Soal:** Konfigurasi ESLint dan Prettier untuk project `perpustakaan-api` dengan ketentuan berikut:
1. Ganti aturan `no-console` menjadi `error` (bukan warn)
2. Tambahkan aturan `@typescript-eslint/explicit-function-return-type` menjadi `error` untuk fungsi publik
3. Di Prettier, ganti `printWidth` menjadi 80
4. Jalankan linting pada semua file di folder `src/`
5. Perbaiki semua error yang muncul

**Jawaban:**

1. **Modifikasi `.eslintrc.js`:**

```javascript
module.exports = {
  parser: '@typescript-eslint/parser',
  parserOptions: {
    project: 'tsconfig.json',
    tsconfigRootDir: __dirname,
    sourceType: 'module',
  },
  plugins: ['@typescript-eslint/eslint-plugin'],
  extends: [
    'plugin:@typescript-eslint/recommended',
    'plugin:prettier/recommended',
  ],
  root: true,
  env: {
    node: true,
    jest: true,
  },
  ignorePatterns: ['.eslintrc.js'],
  rules: {
    '@typescript-eslint/no-explicit-any': 'warn',
    '@typescript-eslint/no-unused-vars': 'error',
    '@typescript-eslint/explicit-function-return-type': 'error', // Error
    'no-console': 'error', // Error (bukan warn)
    'prefer-const': 'error',
  },
};
```

2. **Modifikasi `.prettierrc`:**

```json
{
  "singleQuote": true,
  "trailingComma": "all",
  "tabWidth": 2,
  "semi": true,
  "printWidth": 80,
  "bracketSpacing": true,
  "arrowParens": "always",
  "endOfLine": "auto"
}
```

3. **Jalankan linting:**

```bash
pnpm run lint
```

Akan muncul error karena fungsi `getHello()` di `app.service.ts` dan `bootstrap()` di `main.ts` tidak memiliki return type eksplisit.

4. **Perbaiki dengan menambah return type:**

Di `src/app.service.ts`:
```typescript
getHello(): string {
  return 'Hello World!';
}
```

Di `src/app.controller.ts`:
```typescript
getHello(): string {
  return this.appService.getHello();
}
```

Di `src/main.ts`:
```typescript
async function bootstrap(): Promise<void> {
  // ...
}
bootstrap(): void {
  // ...
}
```

5. **Jalankan ulang linting untuk verifikasi:**

```bash
pnpm run lint
# Output: No errors found!
```
