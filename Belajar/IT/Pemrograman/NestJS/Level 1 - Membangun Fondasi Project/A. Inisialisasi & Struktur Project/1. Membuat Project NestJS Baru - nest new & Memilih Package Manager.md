# Membuat Project NestJS Baru — nest new & Memilih Package Manager

## Penjelasan

Langkah pertama dalam membangun aplikasi NestJS adalah membuat project baru menggunakan NestJS CLI. CLI ini menyediakan perintah `nest new` yang secara otomatis menghasilkan struktur project dasar lengkap dengan konfigurasi TypeScript, ESLint, Prettier, dan file-file penting lainnya. Proses ini menghemat waktu developer karena tidak perlu melakukan boilerplate setup secara manual.

Saat menjalankan `nest new`, CLI akan menanyakan beberapa pertanyaan interaktif, termasuk package manager mana yang akan digunakan. NestJS mendukung beberapa package manager seperti npm, yarn, dan pnpm. Di kelas ini, kita akan memilih **pnpm** karena lebih cepat dan efisien dalam pengelolaan disk space berkat fitur hard linking-nya. pnpm juga memiliki keamanan yang lebih baik dengan strict dependency resolution.

Setelah project selesai dibuat, kita bisa menjalankan aplikasi dalam mode development dengan perintah `pnpm run start:dev`. Perintah ini akan menjalankan NestJS dalam mode watch, di mana setiap perubahan kode akan secara otomatis memicu rekompilasi dan restart server. Ini sangat membantu produktivitas karena developer tidak perlu mematikan dan menjalankan ulang server secara manual setiap kali ada perubahan.

## Fungsi

Perintah `nest new` berfungsi untuk membuat skeleton atau kerangka awal project NestJS yang sudah siap pakai. Fungsinya mencakup pembuatan struktur folder standar, konfigurasi TypeScript yang optimal, integrasi tooling seperti ESLint dan Prettier, serta menyediakan script npm yang berguna seperti `start:dev`, `build`, dan `lint`. Dengan menggunakan CLI, developer bisa memulai project dengan cepat dan konsisten tanpa perlu mengkhawatirkan konfigurasi awal.

## Cara Implementasi / Code

Berikut adalah langkah-langkah membuat project NestJS baru:

```bash
# Install NestJS CLI secara global (jika belum punya)
npm install -g @nestjs/cli

# Buat project baru
nest new perpustakaan-api
```

Saat menjalankan `nest new`, CLI akan menampilkan pertanyaan:

```
? Which package manager would you like to use?
  npm
  yarn
❯ pnpm
```

Pilih **pnpm** menggunakan tombol panah, lalu tekan Enter. Setelah itu CLI akan mengunduh dependencies dan membuat struktur project.

```bash
# Masuk ke direktori project
cd perpustakaan-api

# Jalankan aplikasi dalam mode development
pnpm run start:dev
```

Setelah menjalankan `start:dev`, buka browser dan akses `http://localhost:3000`. Anda akan melihat pesan "Hello World!" sebagai tanda bahwa aplikasi berhasil berjalan.

Beberapa script penting yang tersedia di `package.json`:

```bash
# Mode development dengan hot-reload
pnpm run start:dev

# Build untuk production
pnpm run build

# Menjalankan mode production
pnpm run start:prod

# Menjalankan linter
pnpm run lint

# Menjalankan format kode
pnpm run format
```

Struktur folder yang dihasilkan setelah `nest new`:

## Analogi

Bayangkan Anda adalah seorang **kepala pustakawan** yang ingin membangun **perpustakaan baru** dari nol. Sebelum membeli buku-buku, Anda perlu menyiapkan **gedung perpustakaan** beserta **rak-rak, meja, dan sistem administrasi** dasarnya.

Perintah `nest new` seperti **memanggil kontraktor yang membangunkan gedung perpustakaan lengkap dengan infrastruktur dasarnya**. Kontraktor ini sudah tahu standar bangunan perpustakaan yang baik: di mana harus meletakkan pintu masuk (main.ts), di mana ruang administrasi (module), rak buku (controller), dan ruang penyimpanan (service).

Memilih package manager **pnpm** seperti memilih **sistem katalog digital** yang paling efisien — tidak boros tempat, cepat dalam pencarian, dan aman. Sedangkan menjalankan `pnpm run start:dev` seperti **menyalakan semua lampu dan sistem di perpustakaan** sehingga Anda bisa mulai bekerja dan melihat apakah semuanya berfungsi dengan baik.

## Penggunaan

Perintah `nest new` dipakai di awal setiap project NestJS baru, baik itu REST API, microservice, GraphQL API, atau aplikasi monolitik. Setiap developer di tim akan menjalankan perintah yang sama untuk memastikan semua anggota tim memiliki struktur project yang identik. Ini penting untuk konsistensi dan kolaborasi dalam tim.

## Kesalahan Umum yang Sering Terjadi

1. **Tidak menginstall NestJS CLI secara global** — Jika `nest` command tidak ditemukan, pastikan sudah menjalankan `npm install -g @nestjs/cli`. Jika tetap tidak dikenali, coba gunakan `npx @nestjs/cli new perpustakaan-api`.

2. **Lupa masuk ke direktori project** — Setelah menjalankan `nest new`, banyak developer lupa melakukan `cd perpustakaan-api` dan langsung menjalankan perintah `pnpm run start:dev`. Ini akan gagal karena tidak menemukan `package.json`.

3. **Memilih package manager yang salah** — Jika memilih npm saat diminta, project akan menggunakan npm. Konsistensi dalam tim penting — pastikan semua anggota tim menggunakan package manager yang sama untuk menghindari perbedaan `lock` file.

4. **Port 3000 sudah dipakai** — Jika aplikasi lain sudah menggunakan port 3000, jalankan dengan environment variable: `PORT=3001 pnpm run start:dev`.

5. **Tidak mengupdate npm/pnpm** — Versi yang terlalu lawas bisa menyebabkan error saat instalasi dependency. Jalankan `npm install -g npm@latest` atau `npm install -g pnpm@latest` untuk update.

## Hubungan dengan Materi Sebelumnya

Ini adalah materi **pertama** dalam roadmap NestJS, sehingga belum ada materi sebelumnya. Namun, materi ini menjadi **fondasi** untuk semua materi selanjutnya. Setelah project berhasil dibuat, kita akan mempelajari setiap file yang dihasilkan oleh CLI (materi ke-2), kemudian melakukan konfigurasi `main.ts` (materi ke-3), dan seterusnya. Semua materi berikutnya bergantung pada project yang sudah dibuat di langkah ini.

## Soal Latihan

**Soal:** Buatlah sebuah project NestJS baru bernama `library-catalog` menggunakan pnpm sebagai package manager. Setelah berhasil, jalankan aplikasi pada port 3005 dan pastikan endpoint `GET /` mengembalikan response dengan status 200.

**Jawaban:**

```bash
# Langkah 1: Buat project baru
nest new library-catalog

# Pilih pnpm saat diminta CLI

# Langkah 2: Masuk ke direktori
cd library-catalog

# Langkah 3: Jalankan dengan port custom
$env:PORT=3005
pnpm run start:dev

# Di terminal lain, verifikasi
curl http://localhost:3005
# Output: Hello World!
```

Untuk mengganti port secara permanen, edit file `src/main.ts`:

```typescript
import { NestFactory } from '@nestjs/core';
import { AppModule } from './app.module';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  await app.listen(process.env.PORT ?? 3005);
}
bootstrap();
```
