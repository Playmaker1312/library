# Membuat Global Exception Filter — Format Error yang Konsisten

## Penjelasan

Saat terjadi error di aplikasi NestJS — misalnya `NotFoundException` dari service atau `BadRequestException` dari validation — framework akan mengembalikan response error dengan format default. Format ini sebenarnya sudah cukup informatif: `{statusCode, message, error}`, tapi tidak konsisten dengan format sukses yang sudah kita buat di interceptor sebelumnya. Selain itu, format default tidak menyertakan informasi seperti timestamp dan path URL yang sangat berguna untuk debugging.

**Exception Filter** adalah mekanisme NestJS untuk menangani exception yang dilempar selama eksekusi request. Dengan membuat **Global Exception Filter**, kita bisa menangkap semua exception yang terjadi di aplikasi dan mengubahnya menjadi format response error yang konsisten. Filter ini bisa menangani baik exception built-in NestJS (seperti `NotFoundException`, `BadRequestException`) maupun exception kustom yang kita buat sendiri.

Global Exception Filter diimplementasikan dengan mengimplementasikan interface `ExceptionFilter` dari `@nestjs/common`. Method `catch(exception, host)` akan dipanggil setiap kali ada exception yang tidak tertangani. Di dalam method ini, kita bisa membaca informasi exception, menentukan status code, dan mengembalikan response dalam format yang kita inginkan. Filter ini didaftarkan secara global di `main.ts` menggunakan `app.useGlobalFilters()`.

## Fungsi

Global Exception Filter berfungsi untuk **menstandarisasi format response error** di seluruh aplikasi. Filter ini memastikan bahwa semua error — baik yang disengaja (seperti NotFoundException) maupun yang tidak terduga (seperti Internal Server Error) — dikembalikan dalam format yang sama: `{statusCode, message, error, timestamp, path}`. Ini memudahkan client untuk menangani error secara konsisten dan memudahkan developer untuk debugging.

## Cara Implementasi / Code

### 1. Buat Global Exception Filter

Buat file `src/common/filters/http-exception.filter.ts`:

```typescript
import {
  ExceptionFilter,
  Catch,
  ArgumentsHost,
  HttpException,
  HttpStatus,
  Logger,
} from '@nestjs/common';
import { Request, Response } from 'express';

// Interface untuk response error
interface ErrorResponse {
  statusCode: number;
  message: string;
  error: string;
  timestamp: string;
  path: string;
}

@Catch()
export class GlobalExceptionFilter implements ExceptionFilter {
  private readonly logger = new Logger(GlobalExceptionFilter.name);

  catch(exception: unknown, host: ArgumentsHost): void {
    const ctx = host.switchToHttp();
    const response = ctx.getResponse<Response>();
    const request = ctx.getRequest<Request>();

    let status: number;
    let message: string;
    let error: string;

    if (exception instanceof HttpException) {
      // Exception NestJS built-in
      status = exception.getStatus();
      const exceptionResponse = exception.getResponse();

      if (typeof exceptionResponse === 'string') {
        message = exceptionResponse;
        error = exception.name;
      } else if (typeof exceptionResponse === 'object') {
        const resp = exceptionResponse as Record<string, any>;
        message = Array.isArray(resp.message)
          ? resp.message.join(', ')
          : resp.message || 'Terjadi kesalahan';
        error = resp.error || exception.name;
      }
    } else {
      // Exception tidak dikenal (Internal Server Error)
      status = HttpStatus.INTERNAL_SERVER_ERROR;
      message = 'Terjadi kesalahan internal server';
      error = 'Internal Server Error';
    }

    // Log error untuk debugging
    this.logger.error(
      `${request.method} ${request.url} → ${status} - ${message}`,
      exception instanceof Error ? exception.stack : '',
    );

    const errorResponse: ErrorResponse = {
      statusCode: status,
      message,
      error,
      timestamp: new Date().toISOString(),
      path: request.url,
    };

    response.status(status).json(errorResponse);
  }
}
```

### 2. Daftarkan sebagai Global Filter di `main.ts`

```typescript
import { NestFactory } from '@nestjs/core';
import { AppModule } from './app.module';
import { GlobalExceptionFilter } from './common/filters/http-exception.filter';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);

  // Global prefix
  app.setGlobalPrefix('api/v1');

  // Daftarkan global exception filter
  app.useGlobalFilters(new GlobalExceptionFilter());

  await app.listen(process.env.PORT ?? 3000);
}
bootstrap();
```

### 4. Membuat Exception Kustom (Optional)

Buat file `src/common/exceptions/business.exception.ts`:

```typescript
import { HttpException, HttpStatus } from '@nestjs/common';

export class BusinessException extends HttpException {
  constructor(message: string, code: string) {
    super(
      {
        message,
        error: code,
        statusCode: HttpStatus.UNPROCESSABLE_ENTITY,
      },
      HttpStatus.UNPROCESSABLE_ENTITY,
    );
  }
}
```

Contoh penggunaan di service:

```typescript

        'BOOK_OUT_OF_STOCK',

    // ...
  }
}
```

### 5. Upgrade Filter dengan TypeScript yang Lebih Ketat

```typescript
import {
  ExceptionFilter,
  Catch,
  ArgumentsHost,
  HttpException,
  HttpStatus,
  Logger,
} from '@nestjs/common';
import { Request, Response } from 'express';

interface HttpExceptionResponse {
  message: string | string[];
  error?: string;
  statusCode?: number;
}

@Catch()
export class GlobalExceptionFilter implements ExceptionFilter {
  private readonly logger = new Logger(GlobalExceptionFilter.name);

  catch(exception: unknown, host: ArgumentsHost): void {
    const ctx = host.switchToHttp();
    const response = ctx.getResponse<Response>();
    const request = ctx.getRequest<Request>();

    let status = HttpStatus.INTERNAL_SERVER_ERROR;
    let message = 'Terjadi kesalahan internal server';
    let error = 'Internal Server Error';

    if (exception instanceof HttpException) {
      status = exception.getStatus();
      const exceptionResponse = exception.getResponse();

      if (typeof exceptionResponse === 'string') {
        message = exceptionResponse;
      } else {
        const resp = exceptionResponse as HttpExceptionResponse;

        if (Array.isArray(resp.message)) {
          message = resp.message.join('; ');
        } else if (resp.message) {
          message = resp.message;
        }

        error = resp.error || exception.name;
      }
    } else if (exception instanceof Error) {
      message = exception.message;
    }

    this.logger.error(
      `${request.method} ${request.url} ${status} - ${message}`,
      exception instanceof Error ? exception.stack : undefined,
    );

    response.status(status).json({
      statusCode: status,
      message,
      error,
      timestamp: new Date().toISOString(),
      path: request.url,
    });
  }
}
```

## Analogi

Bayangkan perpustakaan memiliki **papan pengumuman kesalahan** standar:

- **Tanpa exception filter** — Setiap kali terjadi masalah, petugas memberikan informasi dengan cara berbeda. Ada yang teriak "Buku tidak ada!", ada yang menulis catatan tempel, ada yang diam saja. Pengunjung bingung.

- **Dengan exception filter** — Semua masalah dicatat di **papan pengumuman resmi** dengan format baku:

  - **Halaman tidak ditemukan (404)** — Seperti pengunjung mencari buku dengan nomor rak yang tidak ada. Petugas menulis: "Kode: 404, Pesan: Buku tidak ditemukan, Dicatat oleh: Sistem, Jam: 14:30, Lokasi: Rak Fiksi".

  - **Data tidak valid (400)** — Seperti pengunjung mengisi formulir dengan data yang salah (nomor telepon huruf semua). Petugas menulis: "Kode: 400, Pesan: Nomor telepon harus angka, Dicatat oleh: Sistem, Jam: 14:31, Lokasi: Meja Pendaftaran".

  - **Server error (500)** — Seperti lampu perpustakaan mati total. Petugas menulis: "Kode: 500, Pesan: Terjadi gangguan sistem, hubungi petugas, Dicatat oleh: Sistem, Jam: 14:32, Lokasi: Seluruh gedung".

Dengan format standar ini, pengunjung (client) selalu tahu di mana mencari informasi error — dan kepala perpustakaan (developer) bisa dengan cepat melacak sumber masalah dari path dan timestamp.

## Penggunaan

Global Exception Filter digunakan di **setiap aplikasi NestJS** tanpa terkecuali. Filter ini memastikan bahwa error handling konsisten di seluruh API. Saat ada bug di production, informasi `path` dan `timestamp` sangat membantu untuk merekonstruksi kejadian. Format error yang konsisten juga memudahkan frontend untuk menampilkan pesan error yang user-friendly.

## Kesalahan Umum yang Sering Terjadi

1. **Lupa mendaftarkan filter secara global** — Filter yang dibuat tapi tidak didaftarkan tidak akan menangani exception apapun. Pastikan ada `app.useGlobalFilters()` di `main.ts`.

2. **Filter hanya menangani HttpException** — Exception non-HTTP (seperti `TypeError`, `ReferenceError`) akan menghasilkan response 500 tanpa format yang benar. Decorator `@Catch()` tanpa parameter akan menangani semua exception.

3. **Tidak logging exception** — Exception filter adalah tempat yang tepat untuk logging error. Jangan sampai error di production tidak tercatat. Gunakan Logger NestJS.

4. **Mengembalikan informasi sensitif di response** — Jangan pernah mengembalikan stack trace ke client di production. Stack trace hanya untuk logging internal.

5. **Filter terlalu spesifik** — Membuat banyak filter kecil untuk setiap jenis exception bisa membingungkan. Satu global exception filter sudah cukup untuk sebagian besar kasus.

## Hubungan dengan Materi Sebelumnya

Exception filter ini adalah **pasangan** dari Response Wrapper Interceptor (materi 13). Jika interceptor menangani format sukses, maka exception filter menangani format error. Bersama-sama, mereka memastikan **semua response** — baik sukses maupun error — memiliki format yang konsisten. Service yang sudah kita buat di materi 10 akan melempar exception (`NotFoundException`) yang kemudian ditangkap oleh filter ini.

## Soal Latihan

**Soal:** Buatlah Global Exception Filter yang:
1. Menangani semua jenis exception (HttpException dan non-HttpException)
2. Format response: `{success: false, statusCode, message, error, timestamp, path}`
3. Untuk HttpException, ambil message dari `exception.getResponse()` — jika berupa array, gabungkan dengan koma
4. Untuk exception non-HTTP (unexpected), log stack trace ke console
5. Di production mode (`NODE_ENV=production`), jangan tampilkan detail error untuk Internal Server Error — ganti dengan "Terjadi kesalahan internal"

**Jawaban:**

`src/common/filters/http-exception.filter.ts`:
```typescript
import {
  ExceptionFilter,
  Catch,
  ArgumentsHost,
  HttpException,
  HttpStatus,
  Logger,
} from '@nestjs/common';
import { Request, Response } from 'express';

@Catch()
export class GlobalExceptionFilter implements ExceptionFilter {
  private readonly logger = new Logger(GlobalExceptionFilter.name);

  catch(exception: unknown, host: ArgumentsHost): void {
    const ctx = host.switchToHttp();
    const response = ctx.getResponse<Response>();
    const request = ctx.getRequest<Request>();
    const isProduction = process.env.NODE_ENV === 'production';

    let status = HttpStatus.INTERNAL_SERVER_ERROR;
    let message = 'Terjadi kesalahan internal';
    let error = 'Internal Server Error';

    if (exception instanceof HttpException) {
      status = exception.getStatus();
      const resp = exception.getResponse();

      if (typeof resp === 'string') {
        message = resp;
      } else if (typeof resp === 'object') {
        const respObj = resp as Record<string, any>;
        message = Array.isArray(respObj.message)
          ? respObj.message.join(', ')
          : respObj.message || message;
        error = respObj.error || exception.name;
      }

      this.logger.warn(
        `${request.method} ${request.url} → ${status}: ${message}`,
      );
    } else {
      // Non-HTTP exception
      this.logger.error(
        `${request.method} ${request.url} → ${status}: ${message}`,
        exception instanceof Error ? exception.stack : undefined,
      );

      if (isProduction) {
        message = 'Terjadi kesalahan internal';
      } else if (exception instanceof Error) {
        message = exception.message;
      }
    }

    response.status(status).json({
      success: false,
      statusCode: status,
      message,
      error,
      timestamp: new Date().toISOString(),
      path: request.url,
    });
  }
}
```

`main.ts`:
```typescript
app.useGlobalFilters(new GlobalExceptionFilter());
```
