# Membuat Logging Interceptor — Setiap Request Tercatat

## Penjelasan

Salah satu aspek terpenting dalam aplikasi production adalah kemampuan untuk mengetahui apa yang terjadi di dalam aplikasi — request apa saja yang masuk, berapa lama waktu yang dibutuhkan, dan apakah ada yang error. NestJS menyediakan sistem **Logger** bawaan yang bisa digunakan untuk mencatat informasi, peringatan, dan error. Namun, untuk mencatat setiap request HTTP secara otomatis, kita perlu membuat **Logging Interceptor**.

Logging Interceptor akan menangkap setiap request yang masuk ke aplikasi, mencatat method HTTP dan URL, menjalankan request tersebut, mencatat status code response, dan mencatat berapa lama waktu eksekusinya. Informasi ini sangat berharga untuk **monitoring**, **debugging**, dan **analisis performa**. Dengan format log yang konsisten, kita bisa dengan mudah mencari pola masalah atau melihat endpoint mana yang paling lambat.

Interceptor ini menggunakan `Logger` dari `@nestjs/common` dan memanfaatkan **RxJS** operators (`tap`, `catchError`) untuk memantau aliran response. Waktu eksekusi dihitung menggunakan `Date.now()` atau `performance.now()` sebelum dan sesudah request diproses. Selisih waktu ini lalu dicatat bersama informasi request dan response.

## Fungsi

Logging Interceptor berfungsi untuk **mencatat setiap request HTTP** yang masuk ke aplikasi secara otomatis. Informasi yang dicatat meliputi: method HTTP, path URL, status code response, dan durasi eksekusi dalam milidetik. Log ini membantu developer untuk memonitor aktivitas aplikasi, mendeteksi endpoint yang lambat, dan melacak sumber error.

## Cara Implementasi / Code

### 1. Buat Logging Interceptor

Buat file `src/common/interceptors/logging.interceptor.ts`:

```typescript
import {
  Injectable,
  NestInterceptor,
  ExecutionContext,
  CallHandler,
  Logger,
} from '@nestjs/common';
import { Observable } from 'rxjs';
import { tap, catchError } from 'rxjs/operators';
import { Request, Response } from 'express';

@Injectable()
export class LoggingInterceptor implements NestInterceptor {
  private readonly logger = new Logger('HTTP');

  intercept(context: ExecutionContext, next: CallHandler): Observable<any> {
    const ctx = context.switchToHttp();
    const request = ctx.getRequest<Request>();
    const response = ctx.getResponse<Response>();

    const method = request.method;
    const url = request.originalUrl || request.url;
    const now = Date.now();

    return next.handle().pipe(
      tap(() => {
        // Log sukses — request selesai tanpa error
        const statusCode = response.statusCode;
        const duration = Date.now() - now;
        this.logger.log(`[${method}] ${url} → ${statusCode} (${duration}ms)`);
      }),
      catchError((error) => {
        // Log error — request gagal
        const duration = Date.now() - now;
        const statusCode = error.status || 500;
        this.logger.error(
          `[${method}] ${url} → ${statusCode} (${duration}ms) - ${error.message}`,
        );
        throw error; // Lempar kembali agar ditangani oleh exception filter
      }),
    );
  }
}
```

### 2. Daftarkan di `main.ts`

```typescript
import { NestFactory } from '@nestjs/core';
import { AppModule } from './app.module';
import { LoggingInterceptor } from './common/interceptors/logging.interceptor';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);

  app.setGlobalPrefix('api/v1');

  // Daftarkan logging interceptor
  app.useGlobalInterceptors(new LoggingInterceptor());

  await app.listen(process.env.PORT ?? 3000);
}
bootstrap();
```

### 4. Logging dengan Detail Response Body (Development Only)

Untuk environment development, kita bisa menambahkan logging response body (hati-hati dengan data sensitif):

```typescript
import {
  Injectable,
  NestInterceptor,
  ExecutionContext,
  CallHandler,
  Logger,
} from '@nestjs/common';
import { Observable } from 'rxjs';
import { tap } from 'rxjs/operators';
import { Request, Response } from 'express';

@Injectable()
export class LoggingInterceptor implements NestInterceptor {
  private readonly logger = new Logger('HTTP');

  intercept(context: ExecutionContext, next: CallHandler): Observable<any> {
    const ctx = context.switchToHttp();
    const request = ctx.getRequest<Request>();
    const { method, originalUrl } = request;
    const now = Date.now();

    // Log request body untuk POST/PATCH (hanya development)
    if (process.env.NODE_ENV !== 'production') {
      if (['POST', 'PATCH', 'PUT'].includes(method)) {
        const body = { ...request.body };
        // Sembunyikan field sensitif
        delete body.password;
        delete body.token;
        if (Object.keys(body).length > 0) {
          this.logger.debug(`[${method}] ${originalUrl} Body: ${JSON.stringify(body)}`);
        }
      }
    }

    return next.handle().pipe(
      tap(() => {
        const response = ctx.getResponse<Response>();
        const duration = Date.now() - now;
        this.logger.log(
          `[${method}] ${originalUrl} → ${response.statusCode} (${duration}ms)`,
        );
      }),
    );
  }
}
```

### 5. Logging dengan Duration yang Lebih Akurat

Gunakan `performance.now()` untuk akurasi yang lebih tinggi:

```typescript
intercept(context: ExecutionContext, next: CallHandler): Observable<any> {
  const request = context.switchToHttp().getRequest<Request>();
  const method = request.method;
  const url = request.originalUrl;
  const start = performance.now(); // High-resolution time

  return next.handle().pipe(
    tap(() => {
      const duration = performance.now() - start;
      const statusCode = context.switchToHttp().getResponse<Response>().statusCode;
      this.logger.log(`[${method}] ${url} → ${statusCode} (${duration.toFixed(2)}ms)`);
    }),
  );
}
```

### 6. Gabungan dengan Interceptor Lain

Jika kita memiliki banyak interceptor global, daftarkan semuanya di `main.ts`:

```typescript
app.useGlobalInterceptors(
  new LoggingInterceptor(),
  new ResponseWrapperInterceptor(),
);
```

Atau menggunakan `APP_INTERCEPTOR` di `app.module.ts`:

```typescript
import { Module } from '@nestjs/common';
import { APP_INTERCEPTOR } from '@nestjs/core';
import { LoggingInterceptor } from './common/interceptors/logging.interceptor';
import { ResponseWrapperInterceptor } from './common/interceptors/response-wrapper.interceptor';

@Module({
  providers: [
    { provide: APP_INTERCEPTOR, useClass: LoggingInterceptor },
    { provide: APP_INTERCEPTOR, useClass: ResponseWrapperInterceptor },
  ],
})
export class AppModule {}
```

**Catatan penting:** Urutan interceptor matters. `LoggingInterceptor` sebaiknya didaftarkan **pertama** (paling luar) agar bisa mencatat waktu dari awal hingga akhir.

### 7. Custom Logger (Optional)

Kita bisa mengganti Logger bawaan dengan custom logger yang lebih canggih (misalnya menyimpan log ke file atau database):

```typescript
import { LoggerService } from '@nestjs/common';

export class AppLogger implements LoggerService {
  log(message: string) {
    // Kirim ke file atau external service
    console.log(`[LOG] ${message}`);
  }

  error(message: string, trace?: string) {
    console.error(`[ERROR] ${message}`, trace || '');
  }

  warn(message: string) {
    console.warn(`[WARN] ${message}`);
  }

  debug(message: string) {
    console.debug(`[DEBUG] ${message}`);
  }

  verbose(message: string) {
    console.log(`[VERBOSE] ${message}`);
  }
}
```

Daftarkan di `main.ts`:

```typescript
const app = await NestFactory.create(AppModule, {
  logger: new AppLogger(),
});
```

## Analogi

Bayangkan perpustakaan memiliki **petugas keamanan** yang mencatat setiap orang yang masuk dan keluar:

- **Logging Interceptor** adalah **buku tamu digital** di pintu masuk perpustakaan. Setiap kali seseorang datang (request masuk), petugas mencatat:
  - **Waktu masuk** (timestamp)
  - **Siapa yang datang** (method: POST/GET)
  - **Tujuan ke mana** (path: /books, /members)
  - **Waktu keluar** (response)
  - **Berapa lama** mereka di dalam (duration)
  - **Apa hasilnya** (status: 200 sukses, 404 tidak ketemu, 500 error)

- Log untuk **request sukses** — "Pengunjung Budi masuk ke Rak Fiksi pukul 14:00, keluar pukul 14:01, membawa 3 buku (200 OK, 1 menit)".

- Log untuk **request error** — "Pengunjung Siti mencari Rak Non-Fiksi nomor 999 (tidak ada), keluar dengan tangan kosong pukul 14:02 (404 Not Found, 30 detik)".

- Log untuk **request lambat** — "Pengunjung Andi masuk ke Rak Referensi pukul 14:00, baru keluar pukul 14:30 (30 menit!) — perlu diperiksa apakah ada masalah di rak tersebut."

Dengan buku tamu ini, kepala perpustakaan (developer) bisa memonitor aktivitas, mendeteksi rak yang bermasalah (endpoint lambat), dan memastikan semua pengunjung mendapatkan pelayanan yang baik.

## Penggunaan

Logging Interceptor digunakan di **semua aplikasi production** untuk monitoring dan debugging. Di development, log membantu developer melihat request apa yang masuk dan berapa lama response time-nya. Di production, log bisa dikirim ke sistem monitoring terpusat seperti ELK Stack, Datadog, atau Sentry untuk dianalisis lebih lanjut.

## Kesalahan Umum yang Sering Terjadi

1. **Logging data sensitif** — Jika mencatat request body di log, pastikan field sensitif seperti password, token, atau API key tidak ikut tercatat.

2. **Terlalu verbose** — Mencatat setiap detail termasuk headers dan full response body bisa menyebabkan log file membengkak dengan cepat. Batasi logging sesuai kebutuhan.

3. **Tidak menangani error di catchError** — Jika `catchError` tidak melempar kembali exception (`throw error`), error akan "hilang" dan client tidak mendapatkan response error.

4. **Urutan interceptor salah** — Jika `LoggingInterceptor` didaftarkan setelah interceptor lain yang mengubah response, durasi yang tercatat mungkin tidak akurat.

5. **Menggunakan console.log() bukan Logger NestJS** — `console.log()` tidak memiliki format timestamp dan konteks seperti Logger NestJS. Selalu gunakan `Logger` bawaan.

## Hubungan dengan Materi Sebelumnya

Logging Interceptor (materi 15) bersama dengan Response Wrapper Interceptor (materi 13) dan Global Exception Filter (materi 14) membentuk **lapisan infrastruktur global** yang menangani semua request. Perbedaan utamanya:

| Komponen | Tugas | Response |
|---------|-------|----------|
| Logging Interceptor | Mencatat request & durasi | Tidak mengubah response (hanya log) |
| Response Wrapper | Membungkus response sukses | Mengubah shape response |
| Exception Filter | Menangani error | Mengembalikan response error |

Ketiganya bekerja secara berurutan: Logging Interceptor mencatat waktu mulai → Response Wrapper membungkus hasil → Exception Filter menangkap jika ada error.

## Soal Latihan

**Soal:** Buatlah Logging Interceptor dengan spesifikasi berikut:
1. Format log: `[METHOD] /path → STATUS (Xms) — USER-AGENT`
2. Catat juga User-Agent dari header request
3. Untuk request yang lebih lambat dari 1 detik (1000ms), gunakan `logger.warn()` bukan `logger.log()`
4. Jangan logging request ke path `/health` (health check endpoint)
5. Daftarkan menggunakan `APP_INTERCEPTOR` di `AppModule`

**Jawaban:**

`src/common/interceptors/logging.interceptor.ts`:
```typescript
import {
  Injectable,
  NestInterceptor,
  ExecutionContext,
  CallHandler,
  Logger,
} from '@nestjs/common';
import { Observable } from 'rxjs';
import { tap } from 'rxjs/operators';
import { Request, Response } from 'express';

@Injectable()
export class LoggingInterceptor implements NestInterceptor {
  private readonly logger = new Logger('HTTP');

  intercept(context: ExecutionContext, next: CallHandler): Observable<any> {
    const ctx = context.switchToHttp();
    const request = ctx.getRequest<Request>();
    const response = ctx.getResponse<Response>();

    const { method, originalUrl } = request;
    const userAgent = request.headers['user-agent'] || 'unknown';
    const now = Date.now();

    // Skip health check endpoint
    if (originalUrl === '/health') {
      return next.handle();
    }

    return next.handle().pipe(
      tap(() => {
        const statusCode = response.statusCode;
        const duration = Date.now() - now;
        const logMessage = `[${method}] ${originalUrl} → ${statusCode} (${duration}ms) — ${userAgent}`;

        if (duration > 1000) {
          this.logger.warn(logMessage);
        } else {
          this.logger.log(logMessage);
        }
      }),
    );
  }
}
```

`app.module.ts`:
```typescript
import { Module } from '@nestjs/common';
import { APP_INTERCEPTOR } from '@nestjs/core';
import { LoggingInterceptor } from './common/interceptors/logging.interceptor';

@Module({
  providers: [
    {
      provide: APP_INTERCEPTOR,
      useClass: LoggingInterceptor,
    },
  ],
})
export class AppModule {}
```
