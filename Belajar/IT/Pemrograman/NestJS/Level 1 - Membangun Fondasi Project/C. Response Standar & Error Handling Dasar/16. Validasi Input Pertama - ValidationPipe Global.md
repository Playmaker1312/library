# Validasi Input Pertama — ValidationPipe Global

## Penjelasan

Salah satu prinsip keamanan dan kualitas API yang paling penting adalah **jangan pernah percaya input dari client**. Setiap data yang masuk ke aplikasi — baik melalui request body, query parameter, atau path parameter — harus divalidasi sebelum diproses. NestJS menyediakan **ValidationPipe** yang secara otomatis memvalidasi input berdasarkan decorator validasi yang ada di DTO.

ValidationPipe bekerja dengan memanfaatkan library `class-validator` dan `class-transformer`. Saat request masuk, ValidationPipe akan:
1. **Transform** data dari plain object (JSON) menjadi instance class DTO (menggunakan `class-transformer`)
2. **Validasi** instance class tersebut berdasarkan decorator yang ada (menggunakan `class-validator`)
3. Jika validasi gagal, lempar `BadRequestException` dengan daftar error
4. Jika validasi berhasil, lanjutkan ke handler dengan data yang sudah tervalidasi

Dengan memasang ValidationPipe secara **global** di `main.ts`, semua endpoint di aplikasi akan otomatis memvalidasi input tanpa perlu menambahkan pipe di setiap controller. Ini adalah praktik terbaik yang memastikan tidak ada celah validasi — bahkan jika ada developer yang lupa menambahkan validasi di controller tertentu.

## Fungsi

ValidationPipe berfungsi sebagai **gerbang keamanan pertama** untuk semua input yang masuk ke aplikasi. Pipe ini memastikan bahwa data yang sampai ke service sudah sesuai dengan kontrak DTO — tipe data benar, field wajib terisi, format sesuai (misalnya email valid, ISBN valid), dan tidak ada field asing yang tidak diharapkan. Dengan whitelist mode, pipe ini juga bisa secara otomatis menghapus field yang tidak dideklarasikan di DTO, mencegah serangan mass assignment.

## Cara Implementasi / Code

### 1. Install dependencies (jika belum)

```bash
cd perpustakaan-api
pnpm add class-validator class-transformer
```

### 2. Setup ValidationPipe Global di `main.ts`

```typescript
import { NestFactory } from '@nestjs/core';
import { AppModule } from './app.module';
import { ValidationPipe } from '@nestjs/common';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);

  // Global prefix
  app.setGlobalPrefix('api/v1');

  // ValidationPipe Global dengan konfigurasi lengkap
  app.useGlobalPipes(
    new ValidationPipe({
      // --- Transformasi ---
      transform: true, // Ubah tipe data otomatis (string "5" → number 5)
      transformOptions: {
        enableImplicitConversion: true, // Konversi implicit tanpa decorator @Type()
      },

      // --- Validasi ---
      whitelist: true, // Hapus properti yang tidak ada decorator di DTO
      forbidNonWhitelisted: true, // Lempar error jika ada properti asing
      forbidUnknownValues: true, // Lempar error jika nilai tidak dikenal

      // --- Error Handling ---
      disableErrorMessages: false, // Tampilkan pesan error detail (false di production)
      exceptionFactory: (errors) => {
        // Kostumisasi format error
        const messages = errors.map((error) => {
          const constraints = error.constraints;
          if (constraints) {
            return Object.values(constraints).join(', ');
          }
          return `${error.property} tidak valid`;
        });
        return new BadRequestException(messages.join('; '));
      },
    }),
  );

  const port = process.env.PORT ?? 3000;
  await app.listen(port);
}
bootstrap();
```

### 3. Konfigurasi Opsi ValidationPipe

| Opsi | Nilai | Fungsi |
|------|-------|--------|
| `transform` | `true` | Mengubah tipe data secara otomatis (query string → number/boolean) |
| `whitelist` | `true` | Menghapus properti yang tidak punya decorator validasi |
| `forbidNonWhitelisted` | `true` | Melempar error jika ada properti yang tidak dikenal |
| `disableErrorMessages` | `false` | Menampilkan pesan error detail (set `true` di production) |
| `transformOptions.enableImplicitConversion` | `true` | Konversi tipe tanpa perlu decorator `@Type()` |

### 4. Update DTO Books dengan Validasi Lengkap

Sekarang kita update DTO yang sudah dibuat di materi 9 untuk memanfaatkan ValidationPipe:

`src/modules/books/dto/create-book.dto.ts`:
```typescript
import {
  IsString,
  IsNotEmpty,
  IsISBN,
  IsInt,
  Min,
  Max,
} from 'class-validator';

export class CreateBookDto {
  @IsString()
  @IsNotEmpty({ message: 'Judul buku tidak boleh kosong' })
  title: string;

  @IsString()
  @IsNotEmpty({ message: 'Nama penulis tidak boleh kosong' })
  author: string;

  @IsString()
  @IsISBN(undefined, { message: 'ISBN tidak valid' })
  isbn: string;

  @IsInt()
  @Min(1000, { message: 'Tahun harus >= 1000' })
  @Max(new Date().getFullYear(), { message: `Tahun tidak boleh melebihi ${new Date().getFullYear()}` })
  year: number;

  @IsInt()
  @Min(0, { message: 'Stok tidak boleh negatif' })
  stock: number;
}
```

`src/modules/books/dto/query-book.dto.ts`:

import { IsOptional, IsString, IsInt, Min, IsEnum } from 'class-validator';

export enum SortOrder {
  ASC = 'asc',
  DESC = 'desc',

export class QueryBookDto {
  @IsOptional()
  @IsString()
  search?: string;

  @IsOptional()
  @IsString()

  @IsOptional()
  @IsInt()

  year?: number;

### 6. Validasi di Level Controller (Opsional)

Kadang kita perlu validasi tambahan di level controller. Gunakan pipe secara lokal:

```typescript
import { ParseIntPipe, ParseBoolPipe, DefaultValuePipe } from '@nestjs/common';

@Get()
findAll(
  @Query('page', new DefaultValuePipe(1), ParseIntPipe) page: number,
  @Query('limit', new DefaultValuePipe(10), ParseIntPipe) limit: number,
  @Query('isActive', new DefaultValuePipe(true), ParseBoolPipe) isActive: boolean,
) {
  // ...
}
```

### 7. Validasi Array dan Objek Bersarang

Untuk kasus yang lebih kompleks, kita bisa memvalidasi array:

```typescript
import { IsArray, ValidateNested, ArrayMinSize } from 'class-validator';
import { Type } from 'class-transformer';

export class CreateBooksBatchDto {
  @IsArray()
  @ArrayMinSize(1)
  @ValidateNested({ each: true })
  @Type(() => CreateBookDto)
  books: CreateBookDto[];
}
```

## Analogi

Bayangkan perpustakaan memiliki **petugas keamanan di pintu masuk** yang memeriksa setiap formulir yang dibawa pengunjung:

- **ValidationPipe** adalah **petugas keamanan** yang sangat teliti. Setiap formulir yang masuk harus melewati pemeriksaannya:

  - **transform** — Jika pengunjung menulis "5" di kolom stok (string), petugas mengubahnya menjadi 5 (number) secara otomatis. Ini seperti mengubah tulisan tangan menjadi huruf cetak yang rapi.

  - **whitelist** — Petugas hanya menerima kolom yang ada di formulir resmi. Jika ada kolom tambahan yang ditulis pengunjung (misalnya "hackedField"), petugas akan **menghapusnya** tanpa memberi tahu. Kolom mencurigakan dibuang diam-diam.

  - **forbidNonWhitelisted** — Versi lebih ketat dari whitelist. Jika ada kolom asing, petugas **menolak seluruh formulir** dan meminta pengunjung mengisi ulang dengan benar.

  - **@IsString(), @IsInt(), @Min(), dll** — Aturan di setiap kolom. "Kolom Judul harus teks", "Kolom Tahun harus angka antara 1000-2026", "Kolom Stok harus angka minimal 0".

- **Tanpa ValidationPipe** — Seperti perpustakaan tanpa petugas keamanan. Siapa pun bisa masuk dengan formulir apa pun. Pengunjung bisa menulis "stok: minus lima" atau "tahun: abc" — dan petugas rak (service) akan kebingungan memprosesnya.

Dengan petugas keamanan yang ketat, hanya data yang bersih dan valid yang bisa masuk ke area layanan (service). Ini mencegah banyak bug dan potensi serangan keamanan.

## Penggunaan

ValidationPipe global digunakan di **setiap aplikasi NestJS** tanpa terkecuali. Di development, validasi membantu developer menemukan bug input lebih awal. Di production, validasi mencegah data kotor masuk ke database, melindungi dari serangan seperti mass assignment atau injection, dan memberikan feedback yang jelas ke client saat input mereka salah.

## Kesalahan Umum yang Sering Terjadi

1. **Lupa install class-validator dan class-transformer** — ValidationPipe bergantung pada kedua library ini. Jika tidak diinstall, validasi tidak akan berfungsi.

2. **Tidak mengaktifkan `whitelist`** — Tanpa whitelist, field asing akan tetap masuk ke service dan bisa menyebabkan bug atau celah keamanan.

3. **Mengaktifkan `forbidNonWhitelisted` tanpa `whitelist`** — `forbidNonWhitelisted` hanya berguna jika `whitelist` juga aktif. Tanpa whitelist, properti asing tidak dihapus tapi tetap ditolak — hasilnya sama.

4. **Tidak menggunakan `@Type()` atau `enableImplicitConversion`** — Tanpa transformasi, query parameter yang berupa string (misalnya `?year=2005`) akan tetap string meskipun DTO mendeklarasikannya sebagai number.

5. **Pesan error default tidak informatif** — Pesan seperti "title must be a string" kurang user-friendly. Gunakan parameter `message` di decorator untuk pesan kustom.

## Hubungan dengan Materi Sebelumnya

ValidationPipe adalah **puncak** dari materi validasi yang sudah kita mulai sejak materi 9 (DTO). Di materi 9 kita membuat DTO dengan decorator class-validator, dan sekarang kita mengaktifkan validasinya secara global. Tanpa ValidationPipe, decorator di DTO tidak akan berfungsi.

Ini juga adalah **materi terakhir** dari Level 1. Semua komponen yang sudah kita bangun:

| Level 1 | Komponen | Status |
|---------|----------|--------|
| A1-A6 | Inisialisasi & Struktur | ✅ Selesai |
| B7-B12 | Module Books (Interface, DTO, Service, Controller) | ✅ Selesai |
| C13 | Response Wrapper Interceptor | ✅ Selesai |
| C14 | Global Exception Filter | ✅ Selesai |
| C15 | Logging Interceptor | ✅ Selesai |
| C16 | ValidationPipe Global | ✅ Selesai |

Semua komponen ini bekerja bersama-sama sebagai fondasi yang kokoh untuk pengembangan Level 2.

## Soal Latihan

**Soal:** Setup ValidationPipe global dengan konfigurasi berikut dan update DTO Members:
1. `transform: true`, `whitelist: true`, `forbidNonWhitelisted: true`
2. `disableErrorMessages: false`
3. Di CreateMemberDto, tambahkan:
   - `memberCode` harus string, tidak boleh kosong, format "MBR-XXX" (gunakan custom validator atau regex via `@Matches()`)
   - `email` harus format email valid
   - `fullName` minimal 3 karakter, maksimal 100 karakter
   - `phone` harus string, cocok dengan regex nomor Indonesia (`^08[0-9]{8,11}$`)
4. Test dengan REST Client dengan mengirim data tidak valid

**Jawaban:**

`src/modules/members/dto/create-member.dto.ts`:
```typescript
import {
  IsString,
  IsNotEmpty,
  IsEmail,
  MinLength,
  MaxLength,
  Matches,
} from 'class-validator';

export class CreateMemberDto {
  @IsString()
  @IsNotEmpty()
  @Matches(/^MBR-\d{3}$/, {
    message: 'Kode anggota harus format MBR-XXX (contoh: MBR-001)',
  })
  memberCode: string;

  @IsString()
  @IsNotEmpty()
  @MinLength(3, { message: 'Nama minimal 3 karakter' })
  @MaxLength(100, { message: 'Nama maksimal 100 karakter' })
  fullName: string;

  @IsEmail({}, { message: 'Format email tidak valid' })
  email: string;

  @IsString()
  @IsNotEmpty()
  @Matches(/^08[0-9]{8,11}$/, {
    message: 'Nomor telepon harus diawali 08 dan 10-13 digit',
  })
  phone: string;

  @IsString()
  @IsNotEmpty({ message: 'Alamat tidak boleh kosong' })
  address: string;
}
```
