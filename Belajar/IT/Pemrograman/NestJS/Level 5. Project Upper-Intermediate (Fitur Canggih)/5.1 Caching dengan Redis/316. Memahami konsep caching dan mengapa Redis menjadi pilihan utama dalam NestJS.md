# 316. Memahami konsep caching dan mengapa Redis menjadi pilihan utama dalam NestJS

## Definisi & Target
Caching adalah teknik menyimpan hasil operasi yang mahal (seperti query database atau panggilan API eksternal) di media penyimpanan cepat agar request berikutnya tidak perlu mengulang proses yang sama. Redis menjadi pilihan utama karena berjalan di in-memory, mendukung TTL,数据结构 yang kaya, dan sangat cepat dengan latency sub-milidetik.

## Keunggulan Redis untuk Caching di NestJS
- **In-memory storage**: Kecepatan baca/tulis sangat tinggi
- **TTL (Time-To-Live)**: Otomatis menghapus data kadaluwarsa
- **Dukungan tipe data**: String, Hash, List, Set, Sorted Set
- **Atomic operations**: Operasi INCR, DECR, SETNX aman untuk concurrency
- **Pub/Sub**: Mendukung real-time messaging
- **Cluster & Sentinel**: Mendukung high availability
- **Integrasi NestJS**: Package `@nestjs/cache-manager` dengan Redis store

## Arsitektur Caching dengan Redis
```
Client -> Controller -> CacheInterceptor (check cache) -> Service -> Database
                           |                                  |
                           +--- Cache Hit: return response ---+
                           +--- Cache Miss: query DB, set cache, return
```

## Konsep Penting
- **Cache Hit**: Data ditemukan di cache, langsung dikembalikan
- **Cache Miss**: Data tidak ditemukan, lanjut ke database
- **TTL**: Waktu hidup data di cache
- **Cache Invalidation**: Menghapus atau memperbarui cache saat data berubah
- **Cache-Aside**: Aplikasi bertanggung jawab mengelola cache (paling umum)
