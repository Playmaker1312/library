# 381. Merencanakan arsitektur CMS API dengan multi-tenant dan role-based access

## Definisi & Target
Merencanakan arsitektur CMS API yang mendukung multi-tenant (setiap tenant punya data terisolasi) dan role-based access control (RBAC) dengan permission granular.

## Arsitektur Sistem
```
Client (Web/Mobile)
    |
API Gateway / Load Balancer
    |
NestJS Application
    |--- AuthModule (JWT, RBAC)
    |--- TenantModule (Multi-tenant isolation)
    |--- ContentModule (CRUD + Versioning)
    |--- MediaModule (Upload, S3, Optimization)
    |--- CategoryModule (Tag & Kategorisasi)
    |--- SearchModule (Elasticsearch/FTS)
    |--- WebhookModule (Event notifications)
    |--- AuditModule (Logging)
    |
Database (PostgreSQL)
Redis (Cache + Queue)
Elasticsearch (Full-text search)
S3/Cloud Storage (Media)
```

## Entity Relationships
```
Tenant
  |--- User (has Role)
  |--- Role (has Permission[])
  |--- Content (belongs to Category, has Tag[])
  |--- Category (hierarchical)
  |--- Tag
  |--- Media
  |--- AuditLog
  |--- Webhook
  |--- ApiKey
  |--- Setting
```

## Multi-tenant Strategy
| Strategy | Kelebihan | Kekurangan |
|----------|-----------|------------|
| Single DB, shared table | Sederhana, murah | Risiko data leak |
| Single DB, schema per tenant | Isolasi baik, mudah backup | Kompleksitas migration |
| Separate DB per tenant | Isolasi maksimal | Mahal, maintenance tinggi |

## RBAC Design
```
Role: Super Admin -> All permissions
Role: Admin -> Content + Media + User management
Role: Editor -> Content CRUD (publish/archive)
Role: Author -> Create/Edit own content (draft)
Role: Viewer -> Read-only
```
