# Menjalankan PostgreSQL dengan Docker Compose

## Penjelasan

Docker Compose adalah tools dari Docker yang memungkinkan kita mendefinisikan dan menjalankan multi-container Docker application hanya dengan satu file konfigurasi YAML. Dalam pengembangan aplikasi NestJS, kita biasanya membutuhkan database PostgreSQL sebagai persistent storage dan Redis sebagai caching atau message broker. Daripada menginstall PostgreSQL dan Redis secara native di sistem operasi, kita bisa menggunakan Docker Compose untuk menjalankan kedua service tersebut dalam container yang terisolasi. Pendekatan ini memastikan lingkungan development konsisten di seluruh tim, karena setiap developer akan menjalankan versi database yang sama persis.

File `docker-compose.yml` berisi definisi service, volume, network, dan environment variable yang diperlukan. Untuk PostgreSQL, kita perlu mendefinisikan image (misalnya `postgres:16-alpine`), port mapping (5432:5432), environment variables seperti POSTGRES_USER, POSTGRES_PASSWORD, dan POSTGRES_DB, serta volume persistence agar data tidak hilang ketika container di-restart. Untuk Redis, kita bisa menggunakan image `redis:7-alpine` dengan port 6379. Dengan perintah `docker compose up -d`, semua service akan berjalan di background.

Setelah container berjalan, kita bisa memverifikasi koneksi menggunakan tools seperti `psql`, `pgAdmin`, atau langsung dari aplikasi NestJS menggunakan Prisma. Penting untuk memastikan bahwa port yang digunakan tidak bentrok dengan service lain yang sudah berjalan di mesin lokal. Jika terjadi bentrok, kita bisa mengubah port mapping di sisi host (misalnya 5433:5432) dan menyesuaikan konfigurasi DATABASE_URL di Prisma.

## Fungsi

Menyediakan infrastruktur database PostgreSQL dan Redis yang konsisten dan reproducible untuk development lokal menggunakan Docker Container, sehingga developer tidak perlu install database secara manual.

## Cara Implementasi / Code

Buat file `docker-compose.yml` di root project:

```yaml
version: '3.8'

services:
  postgres:
    image: postgres:16-alpine
    container_name: nestjs-postgres
    ports:
      - '5432:5432'
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: postgres
      POSTGRES_DB: perpustakaan_db
    volumes:
      - postgres_data:/var/lib/postgresql/data
    networks:
      - nestjs-network
    restart: unless-stopped

  redis:
    image: redis:7-alpine
    container_name: nestjs-redis
    ports:
      - '6379:6379'
    volumes:
      - redis_data:/data
    networks:
      - nestjs-network
    restart: unless-stopped

volumes:
  postgres_data:
    driver: local
  redis_data:
    driver: local

networks:
  nestjs-network:
    driver: bridge
```

Jalankan perintah berikut di terminal (root project):

```bash
# Menjalankan semua service di background
docker compose up -d

# Melihat log container
docker compose logs -f

# Verifikasi container berjalan
docker compose ps
```

Verifikasi koneksi menggunakan Prisma atau CLI:

```bash
# Cek langsung via docker
docker exec -it nestjs-postgres psql -U postgres -d perpustakaan_db

# Di dalam psql, cek koneksi
\conninfo
\dt
```

Untuk menghentikan container:

```bash
docker compose down
```

Jika ingin menghapus volume data (hati-hati, data hilang):

```bash
docker compose down -v
```

## Analogi

Bayangkan perpustakaan sedang dibangun dari awal. Kita belum punya rak buku, meja, atau sistem pencatatan. **Docker Compose** adalah seperti kontraktor yang membawa dua kontainer prefabrikasi: satu kontainer khusus untuk penyimpanan buku (PostgreSQL — database utama) dan satu kontainer khusus untuk catatan sementara (Redis — cache). Kontraktor ini tinggal menempatkan kedua kontainer di lokasi yang sudah ditentukan, menyambungkan listrik dan pipa (port mapping), dan memberi label pada setiap kontainer (container_name). Dengan begitu, petugas perpustakaan tidak perlu repot membangun gudang dari nol — cukup "compose" dan semua siap pakai. Kontainer prefabrikasi ini juga bisa dengan mudah dipindahkan atau digandakan jika perpustakaan ingin punya cabang baru.

## Penggunaan

Dipakai untuk menyediakan infrastruktur database dan caching yang konsisten di lingkungan development, staging, dan production. Setiap developer cukup menjalankan satu perintah (`docker compose up -d`) untuk mendapatkan environment database yang identik. Juga digunakan dalam CI/CD pipeline untuk menjalankan integration test dengan database riil.

## Kesalahan Umum yang Sering Terjadi

1. **Port bentrok**: PostgreSQL atau Redis sudah berjalan di host pada port yang sama. Solusi: ganti port mapping di sisi host, misalnya `'5433:5432'`.
2. **Lupa menjalankan Docker**: Container tidak berjalan saat aplikasi NestJS mencoba koneksi. Selalu cek `docker compose ps` sebelum menjalankan aplikasi.
3. **Volume tidak dipasang**: Data hilang setelah container di-restart. Pastikan ada `volumes:` section di service dan top-level `volumes:`.
4. **Environment variable typo**: Nama database, user, atau password salah. Akibatnya aplikasi tidak bisa connect.
5. **Network isolation**: Service tidak bisa saling communicate karena berbeda network. Pastikan semua service dalam satu network yang sama.
6. **Versi image tidak cocok**: Menggunakan image PostgreSQL versi lama yang tidak kompatibel dengan Prisma.

## Hubungan dengan Materi Sebelumnya

Di Level 1, kita masih menggunakan array in-memory untuk menyimpan data buku. Sekarang kita menyiapkan database sungguhan sebagai persistent storage. Docker Compose adalah langkah pertama sebelum kita menghubungkan NestJS ke PostgreSQL melalui Prisma. Materi ini menjadi fondasi untuk materi selanjutnya: Inisialisasi Prisma, migrasi, dan seeding data.
