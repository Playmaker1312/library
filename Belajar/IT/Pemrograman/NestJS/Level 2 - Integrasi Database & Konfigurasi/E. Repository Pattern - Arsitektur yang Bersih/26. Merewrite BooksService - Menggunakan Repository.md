# Merewrite BooksService — Menggunakan Repository

## Penjelasan

Setelah interface repository dan implementasinya siap, langkah selanjutnya adalah merewrite `BooksService` agar tidak lagi menggunakan array in-memory, melainkan menggunakan repository yang sudah terdaftar di DI container. Ini adalah perubahan arsitektural yang signifikan: service sekarang berada di layer bisnis murni, tanpa tahu menahu tentang bagaimana data disimpan atau diambil. Service hanya bertanggung jawab untuk logika bisnis seperti validasi, transformasi data, dan orchestrasi.

Dengan menggunakan `@Inject(BOOKS_REPOSITORY)` daripada constructor langsung, service menjadi sangat fleksibel. Kita bisa mengganti implementasi repository tanpa menyentuh kode service sama sekali. Service juga menjadi mudah di-test karena kita bisa memberikan mock repository apa pun saat membuat testing module. Prinsip ini dikenal sebagai **Dependency Inversion Principle** — modul tingkat tinggi (service) tidak boleh bergantung pada modul tingkat rendah (database), keduanya harus bergantung pada abstraksi (interface).

Salah satu logika bisnis penting yang perlu ditambahkan di service adalah pengecekan duplikasi ISBN. Sebelum membuat buku baru, service harus mengecek apakah ISBN sudah ada di database menggunakan `findByIsbn()`. Jika sudah ada, service melempar `ConflictException` dengan pesan yang sesuai. Ini adalah contoh logika bisnis yang tidak boleh ada di repository — repository hanya bertugas menyimpan dan mengambil data, bukan memvalidasi aturan bisnis.

## Fungsi

Mengubah BooksService dari yang sebelumnya menggunakan array in-memory menjadi menggunakan repository pattern dengan dependency injection, serta menambahkan logika bisnis seperti validasi duplikasi ISBN.

## Cara Implementasi / Code

Buat file `src/books/books.service.ts` yang baru:

```typescript
// src/books/books.service.ts
import {
  Injectable,
  Inject,
  NotFoundException,
  ConflictException,
} from '@nestjs/common';
import { Book } from '@prisma/client';
import {
  IBooksRepository,
  CreateBookDto,
  UpdateBookDto,
} from './interfaces/books-repository.interface';
import { BOOKS_REPOSITORY } from './constants/tokens';

@Injectable()
export class BooksService {
  constructor(
    @Inject(BOOKS_REPOSITORY)
    private readonly booksRepository: IBooksRepository,
  ) {}

  async findAll(): Promise<Book[]> {
    return this.booksRepository.findAll();
  }

  async findById(id: string): Promise<Book> {
    const book = await this.booksRepository.findById(id);
    if (!book) {
      throw new NotFoundException(`Buku dengan ID ${id} tidak ditemukan`);
    }
    return book;
  }

  async create(dto: CreateBookDto): Promise<Book> {
    // Cek duplikasi ISBN
    const existingBook = await this.booksRepository.findByIsbn(dto.isbn);
    if (existingBook) {
      throw new ConflictException(
        `Buku dengan ISBN ${dto.isbn} sudah terdaftar`,
      );
    }
    return this.booksRepository.create(dto);
  }

  async update(id: string, dto: UpdateBookDto): Promise<Book> {
    // Cek apakah buku ada
    const book = await this.booksRepository.findById(id);
    if (!book) {
      throw new NotFoundException(`Buku dengan ID ${id} tidak ditemukan`);
    }

    // Jika ISBN diupdate, cek duplikasi
    if (dto.isbn && dto.isbn !== book.isbn) {
      const existingBook = await this.booksRepository.findByIsbn(dto.isbn);
      if (existingBook) {
        throw new ConflictException(
          `Buku dengan ISBN ${dto.isbn} sudah terdaftar`,
        );
      }
    }

    return this.booksRepository.update(id, dto);
  }

  async softDelete(id: string): Promise<Book> {
    const book = await this.booksRepository.findById(id);
    if (!book) {
      throw new NotFoundException(`Buku dengan ID ${id} tidak ditemukan`);
    }
    return this.booksRepository.softDelete(id);
  }
}
```

Update controller untuk menggunakan async/await:

```typescript
// src/books/books.controller.ts
import {
  Controller,
  Get,
  Post,
  Patch,
  Delete,
  Param,
  Body,
} from '@nestjs/common';
import { BooksService } from './books.service';
import { CreateBookDto, UpdateBookDto } from './dto';
import { Book } from '@prisma/client';

@Controller('books')
export class BooksController {
  constructor(private readonly booksService: BooksService) {}

  @Get()
  async findAll(): Promise<Book[]> {
    return this.booksService.findAll();
  }

  @Get(':id')
  async findById(@Param('id') id: string): Promise<Book> {
    return this.booksService.findById(id);
  }

  @Post()
  async create(@Body() dto: CreateBookDto): Promise<Book> {
    return this.booksService.create(dto);
  }

  @Patch(':id')
  async update(
    @Param('id') id: string,
    @Body() dto: UpdateBookDto,
  ): Promise<Book> {
    return this.booksService.update(id, dto);
  }

  @Delete(':id')
  async softDelete(@Param('id') id: string): Promise<{ message: string }> {
    await this.booksService.softDelete(id);
    return { message: 'Buku berhasil dihapus' };
  }
}
```

## Analogi

BooksService yang baru adalah **kepala layanan perpustakaan** yang duduk di meja depan. Ketika pengunjung datang, kepala layanan tidak langsung lari ke gudang mencari buku — ia punya staf khusus (repository) yang tugasnya mengambil dan menyimpan buku. Kepala layanan hanya bertugas:

1. Menerima permintaan dari pengunjung (controller).
2. Memeriksa apakah permintaan masuk akal (logika bisnis) — misalnya "Maaf, ISBN buku ini sudah terdaftar" (ConflictException) atau "Maaf, buku dengan ID ini tidak ditemukan" (NotFoundException).
3. Menyuruh staf (repository) untuk mengambil atau menyimpan buku sesuai permintaan.

Dulu (sebelum rewrite), kepala layanan merangkap sebagai staf gudang — ia sendiri yang mengambil buku dari rak (array in-memory). Sekarang tugasnya lebih terfokus pada layanan pengunjung, dan urusan gudang diserahkan ke ahlinya. Jika suatu saat staf gudang diganti (dari Prisma ke database lain), kepala layanan tidak perlu dilatih ulang — ia tetap bisa bekerja karena komunikasi menggunakan formulir standar (interface).

## Penggunaan

Dipakai sebagai service utama untuk operasi CRUD buku di seluruh aplikasi. Service ini akan dipanggil oleh controller (REST API) dan bisa juga dipanggil oleh service lain atau resolver GraphQL. Logika bisnis tambahan seperti validasi, authorization, atau transformasi data ditambahkan di sini.

## Kesalahan Umum yang Sering Terjadi

1. **Lupa `@Inject(BOOKS_REPOSITORY)`**: Constructor parameter menggunakan type annotation biasa tanpa decorator, menyebabkan NestJS tidak bisa resolve.
2. **Logika bisnis bocor ke repository**: Validasi duplikasi ISBN ditulis di repository, bukan di service.
3. **Tidak handle NotFoundException**: Service mengembalikan `null` tanpa throw exception, controller harus handle sendiri.
4. **Lupa async/await**: Method mengembalikan Promise, tapi controller tidak await, response dikirim sebelum query selesai.
5. **Error tidak throw HTTP exception**: Throw error biasa (misalnya `new Error()`) yang menghasilkan 500 Internal Server Error, bukan 404 atau 409.
6. **Tidak validasi input**: DTO diterima langsung tanpa validasi class-validator.

## Hubungan dengan Materi Sebelumnya

Ini adalah puncak dari repository pattern. Interface (`IBooksRepository` — materi 23), implementasi (`PrismaBooksRepository` — materi 24), dan custom provider (materi 25) sekarang bersatu di BooksService. Service yang dulu menggunakan array in-memory (Level 1) sekarang menggunakan database sungguhan melalui repository. Selanjutnya, kita akan mengkonfigurasi environment variable (materi 27-29) dan menambahkan pagination (materi 30-32).

**Soal 2:** Apa yang terjadi jika service tidak mengecek duplikasi ISBN dan langsung memanggil `create()`? Bagaimana Prisma merespon?

<details>
<summary>Jawaban</summary>

Prisma akan melempar error `PrismaClientKnownRequestError` dengan kode `P2002` (unique constraint violation) karena kolom `isbn` memiliki constraint `@unique`. Tanpa ditangani, error ini akan menghasilkan response HTTP 500 Internal Server Error, bukan 409 Conflict. Service perlu menangkap error ini dan melempar `ConflictException` yang lebih sesuai.
