## 4.4 Request or Response Cycle

### Definisi Singkat

**Request-Response Cycle** adalah urutan proses yang terjadi sejak klien mengirimkan permintaan ke server hingga server mengirimkan kembali tanggapan. Di NestJS, siklus ini melibatkan berbagai komponen seperti Middleware, Guards, Interceptors, Pipes, dan Exception Filters.

### Analogi

Bayangkan proses **Memesan Makanan di Restoran Mewah**:

1. **Request**: Kamu datang dan memesan makanan (Request dikirim).
    
2. **Middleware**: Petugas di pintu mengecek apakah kamu berpakaian rapi dan mencatat kunjunganmu.
    
3. **Guard**: Petugas keamanan mengecek apakah kamu punya reservasi (izin akses).
    
4. **Pipe**: Pelayan memastikan pesananmu tertulis dengan benar (misal: jumlah harus angka, bukan teks).
    
5. **Controller & Service**: Koki memasak makananmu (Logika utama dijalankan).
    
6. **Interceptor**: Sebelum disajikan, pelayan menghias piring agar terlihat cantik (Mengubah format respon).
    
7. **Response**: Makanan sampai di mejamu (Response diterima klien).
    

### Tahapan Siklus di NestJS

Berikut adalah urutan eksekusi yang terjadi di dalam NestJS:

1. **Incoming Request**: Permintaan HTTP masuk (misal: `GET /users`).
    
2. **Middleware**: Penanganan awal (seperti logging atau parsing body).
    
3. **Guards**: Menentukan apakah permintaan diizinkan (Autentikasi/Otorisasi).
    
4. **Interceptors (Pre-handler)**: Menjalankan logika sebelum sampai ke Controller.
    
5. **Pipes**: Validasi dan transformasi data (mengubah string menjadi number, dsb).
    
6. **Controller (Route Handler)**: Menerima data dan memanggil Service.
    
7. **Service**: Tempat logika bisnis utama (query ke database).
    
8. **Interceptors (Post-handler)**: Mengubah atau membungkus data sebelum dikirim balik.
    
9. **Exception Filters**: Jika terjadi error di tahap mana pun, filter ini akan menangkapnya dan memberikan respon yang rapi.
    
10. **Outgoing Response**: Respon JSON dikirim kembali ke klien.
    

### Contoh Sederhana

Jika seorang pengguna mencoba mengambil data profil tanpa login:

- **Request** masuk.
    
- **Middleware** mencatat waktu request.
    
- **Guard** mendeteksi tidak ada token, langsung memotong siklus dan mengirim **Response 401 Unauthorized**.
    
- **Controller** tidak pernah dijalankan, menghemat sumber daya server.
    

### Koneksi dengan Web Development (NestJS)

Memahami siklus ini sangat membantu dalam _debugging_ dan arsitektur aplikasi:

1. **Penempatan Logika**: Kamu jadi tahu bahwa validasi data sebaiknya di **Pipes**, bukan di dalam **Controller**.
    
2. **Keamanan**: Kamu paham bahwa pengecekan hak akses (Role-based access) paling tepat dilakukan di **Guards**.
    
3. **Konsistensi Data**: Menggunakan **Interceptors** memastikan semua respon API kamu memiliki format yang sama (misal: selalu dibungkus dalam objek `{ "success": true, "data": ... }`).
    
4. **Error Handling**: Dengan **Exception Filters**, kamu tidak perlu menulis _try-catch_ di setiap fungsi, karena NestJS akan menangkapnya secara global.
