## 4.3 REST API Principles

### Definisi Singkat

**REST API** adalah gaya arsitektur komunikasi web yang menggunakan protokol HTTP untuk mengelola data (_resource_). Sebuah API dikatakan **RESTful** jika ia mengikuti prinsip-prinsip utama seperti penggunaan URL yang unik, stateless, dan metode HTTP yang tepat.

### Analogi

Bayangkan sebuah **Restoran Internasional**:

- **Client (Pembeli)**: Siapa saja bisa datang (Web, Mobile, IoT) asalkan mengerti bahasa internasional (HTTP).
    
- **Resource (Menu)**: Setiap makanan punya nama unik (misal: `/nasi-goreng`, `/sate-ayam`). Kamu tidak memesan dengan bilang "Saya mau makan", tapi menyebutkan nama menunya secara spesifik.
    
- **Uniform Interface**: Aturan mainnya seragam. Semua pembeli memesan lewat kasir yang sama, menggunakan cara yang sama, tanpa peduli siapa koki yang memasak di dapur.
    

### Poin-Poin Penting

Ada 6 prinsip utama REST, namun 4 yang paling sering dirasakan dalam pengembangan NestJS adalah:

- **Stateless**: Server tidak menyimpan "ingatan" tentang permintaan sebelumnya. Setiap permintaan dari klien harus membawa informasi lengkap (seperti token akses) agar server bisa memprosesnya.
    
- **Resource-Based**: URL harus merepresentasikan **Benda** (Kata Benda), bukan tindakan (Kata Kerja).
    
    - _Salah:_ `GET /ambilSemuaUser`
        
    - _Benar:_ `GET /users`
        
- **Uniform Interface**: Penggunaan metode HTTP yang konsisten (`GET` untuk ambil, `POST` untuk buat, dll) dan format data yang standar (biasanya JSON).
    
- **Client-Server Separation**: Urusan tampilan (Frontend) dan urusan data (Backend) benar-benar terpisah. Mereka hanya berkomunikasi lewat jalur API.
    
- **Cacheable**: Respon dari API harus bisa disimpan sementara oleh klien untuk mempercepat performa dan menghemat bandwidth.
    

### Contoh Implementasi (Struktur URL)

Dalam NestJS, kita menerapkan prinsip REST melalui penamaan Controller dan Route yang bersih:

TypeScript

```
// --- Mengikuti Prinsip RESTful ---

@Controller('books') // Menggunakan kata benda jamak
export class BooksController {

  @Get() // GET /books -> Ambil semua buku
  findAll() {}

  @Get(':id') // GET /books/123 -> Ambil buku spesifik ID 123
  findOne(@Param('id') id: string) {}

  @Post() // POST /books -> Tambah buku baru
  create(@Body() createBookDto: any) {}

  @Delete(':id') // DELETE /books/123 -> Hapus buku ID 123
  remove(@Param('id') id: string) {}
}
```

### Koneksi dengan Web Development (NestJS)

Mengapa memahami prinsip REST sangat penting saat menggunakan NestJS?

1. **Scalability**: Karena bersifat _stateless_, server NestJS kamu bisa diperbanyak (didistribusikan) dengan mudah karena setiap _request_ tidak bergantung pada memori server tertentu.
    
2. **Interoperability**: API yang RESTful memungkinkan aplikasi Android, iOS, dan Website kamu menggunakan satu sumber data yang sama tanpa modifikasi khusus.
    
3. **Predictability**: Developer lain akan mudah menebak alamat endpoint kamu. Jika mereka tahu `/users` untuk daftar user, mereka otomatis tahu bahwa `/products` adalah untuk daftar produk.
    
4. **NestJS Decorators**: NestJS didesain sangat selaras dengan prinsip REST. Penggunaan `@Controller('name')` dan metode seperti `@Get()` adalah cara NestJS memaksa pengembang mengikuti aturan REST secara alami.
