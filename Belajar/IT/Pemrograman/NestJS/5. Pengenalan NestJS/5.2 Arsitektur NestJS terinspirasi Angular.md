# 5. Pengenalan NestJS

## 5.2. Arsitektur NestJS Terinspirasi Angular

**Definisi Singkat:** NestJS mengadopsi arsitektur Angular — modular, dependency injection, decorators, dan分层 komponen (module → controller → service). Ini membuat kode terstruktur, testable, dan scalable.

**Analogi:** Seperti organisasi perusahaan: Module = departemen (HR, Finance, IT). Controller = resepsionis (menerima tamu dan mengarahkan). Service = staff ahli (mengerjakan tugas). Provider = semua karyawan.

**Poin-Poin Penting:**
- Module — wadah logical terkait (mirip NgModule Angular)
- Controller — handle HTTP requests (mirip Angular Component)
- Service/Provider — business logic (mirip Angular Service)
- Dependency Injection — constructor-based, otomatis resolve
- Decorators — memetakan metadata (seperti Angular decorators)
- Pipe, Guard, Interceptor, Filter — lifecycle hooks (mirip Angular)

**Contoh Kode:**
```typescript
// Struktur arsitektur NestJS
import { Module, Controller, Get, Injectable } from '@nestjs/common';

// Layer 1: Service — business logic
@Injectable()
export class UserService {
  private users = [{ id: 1, name: 'Alice' }];

  findAll() {
    return this.users;
  }
}

// Layer 2: Controller — handle request/response
@Controller('users')
export class UserController {
  constructor(private readonly userService: UserService) {} // DI

  @Get()
  findAll() {
    return this.userService.findAll();
  }
}

// Layer 3: Module — mengorganisir komponen
@Module({
  controllers: [UserController],
  providers: [UserService],
  exports: [UserService], // untuk module lain
})
export class UserModule {}

// Layer 4: Root Module
@Module({
  imports: [UserModule],
})
export class AppModule {}
```

**Kasus Penggunaan Nyata:**
Arsitektur ini membuat setiap fitur (Users, Products, Orders) menjadi module independen. Developer bisa bekerja paralel. Testing lebih mudah — service di-test terpisah dari controller. Microservices bisa share module yang sama.
