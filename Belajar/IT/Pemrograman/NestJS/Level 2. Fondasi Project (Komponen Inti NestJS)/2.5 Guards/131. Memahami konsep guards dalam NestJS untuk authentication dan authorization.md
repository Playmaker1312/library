# 131. Memahami konsep guards dalam NestJS untuk authentication dan authorization

## Definisi & Target
Guard menentukan apakah request boleh dilanjutkan ke route handler berdasarkan kondisi tertentu (seperti ada/tidaknya token JWT, role user, atau permission). Guard dieksekusi setelah middleware tetapi sebelum interceptor/pipe. Guard mengembalikan `true` untuk mengizinkan atau `false`/exception untuk menolak request.

## Komponen & Nest CLI Command
```
nest g guard common/auth --no-spec
```
File: `src/common/guards/auth.guard.ts`

## Kode Implementasi (Per File)

```typescript
// src/common/guards/auth.guard.ts
import { Injectable, CanActivate, ExecutionContext, UnauthorizedException } from '@nestjs/common';
import { Request } from 'express';

@Injectable()
export class AuthGuard implements CanActivate {
  canActivate(context: ExecutionContext): boolean {
    const request = context.switchToHttp().getRequest<Request>();
    const token = request.headers['authorization'];

    if (!token) {
      throw new UnauthorizedException('No token provided');
    }

    request['user'] = { id: 1, role: 'user' };

    return true;
  }
}
```

```typescript
// src/users/users.controller.ts
import { Controller, Get, UseGuards } from '@nestjs/common';
import { AuthGuard } from '../common/guards/auth.guard';

@Controller('users')
@UseGuards(AuthGuard)
export class UsersController {
  @Get()
  findAll() {
    return [{ id: 1, name: 'Protected User' }];
  }
}
```

## Cara Integrasi & Pengujian

Guard bisa dipasang di level controller, method, atau global. Jika `canActivate` return `false`, NestJS mengembalikan `403 Forbidden`.

**Test dengan curl:**
```bash
curl http://localhost:3000/users
# {"message":"No token provided","statusCode":401}

curl -H "Authorization: Bearer token123" http://localhost:3000/users
# [{"id":1,"name":"Protected User"}]
```
