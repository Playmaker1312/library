# 160. Memahami urutan eksekusi middleware, guard, interceptor, pipe, dan exception filter

## Definisi & Target
Urutan eksekusi komponen NestJS dari request masuk hingga response keluar: **Middleware** -> **Guard** -> **Interceptor (sebelum handler)** -> **Pipe** -> **Route Handler** -> **Interceptor (setelah handler)** -> **Exception Filter** (jika ada error). Memahami urutan ini penting untuk debugging dan arsitektur yang benar.

## Komponen & Nest CLI Command
Tidak ada CLI command.
File: demonstrasi konsep

## Kode Implementasi (Per File)

```typescript
// Urutan eksekusi:
//
// 1. Middleware (global/spesifik)
//    - req -> middleware -> next()
//
// 2. Guard
//    - canActivate() -> true/false
//
// 3. Interceptor (before)
//    - intercept() -> sebelum next.handle()
//
// 4. Pipe
//    - transform() -> validasi/transformasi input
//
// 5. Route Handler
//    - @Get(), @Post(), dll.
//
// 6. Interceptor (after)
//    - setelah next.handle() -> pipe()
//
// 7. Exception Filter
//    - catch() jika ada error di langkah 2-6

// src/demo/diagram.ts
export const executionOrder = `
Request masuk
  |
  v
[1] Middleware (app.use / MiddlewareConsumer)
  |  - Logger, CORS, Helmet, dll.
  |  - Panggil next() untuk lanjut
  v
[2] Guard (canActivate)
  |  - AuthGuard, RoleGuard, dll.
  |  - Return true (lanjut) / throw exception (berhenti)
  v
[3] Interceptor (sebelum handler)
  |  - Kode sebelum next.handle()
  |  - Transformasi request, logging start
  v
[4] Pipe (transform)
  |  - ValidationPipe, ParseIntPipe, dll.
  |  - Validasi & transformasi input
  |  - Throw error jika tidak valid
  v
[5] Route Handler
  |  - Eksekusi logic bisnis
  |  - Return response
  v
[6] Interceptor (setelah handler)
  |  - Kode setelah next.handle()
  |  - Transformasi response, logging end
  v
[7] Exception Filter (jika error terjadi)
  |  - Tangkap exception dari langkah 2-5
  |  - Format error response
  v
Response keluar (JSON)
`;
```

```typescript
// src/demo/execution-demo.controller.ts
import { Controller, Get, UseGuards, UseInterceptors, UsePipes, ParseIntPipe } from '@nestjs/common';
import { AuthGuard } from '../common/guards/auth.guard';
import { LoggingInterceptor } from '../common/interceptors/logging.interceptor';
import { TransformInterceptor } from '../common/interceptors/transform.interceptor';

@Controller('demo')
@UseGuards(AuthGuard)
@UseInterceptors(LoggingInterceptor, TransformInterceptor)
export class DemoController {
  @Get(':id')
  @UsePipes(ParseIntPipe)
  getDemo(id: number) {
    return { message: 'Success', id };
  }
}

/* 
Eksekusi untuk GET /demo/123:
1. Middleware: mencatat request
2. AuthGuard: memeriksa token
3. LoggingInterceptor: log "Before: GET /demo/123"
4. ParseIntPipe: mengubah "123" string -> 123 number
5. Handler: return { message: 'Success', id: 123 }
6. LoggingInterceptor: log "After: GET /demo/123 - 5ms"
7. TransformInterceptor: wrap response
8. Response: {"success":true,"data":{"message":"Success","id":123},"timestamp":"..."}
*/
```

## Cara Integrasi & Pengujian

Setiap request melewati pipeline secara berurutan. Jika salah satu komponen gagal, eksekusi berhenti dan exception filter mengambil alih.

**Test dengan curl:**
```bash
curl -H "Authorization: Bearer token" http://localhost:3000/demo/123
# Response: transformed + wrapped
# Console: menampilkan log dari middleware, guard, interceptor

curl http://localhost:3000/demo/abc
# Guard belum dijalankan -> pipe menolak "abc" -> error 400
# (Pipe dieksekusi setelah guard lolos)
```
