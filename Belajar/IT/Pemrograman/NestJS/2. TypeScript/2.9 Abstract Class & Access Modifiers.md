## 2.9 Abstract Class & Access Modifiers

### Definisi Singkat

**Abstract Class** adalah class "setengah jadi" yang tidak bisa dibuat objeknya secara langsung, melainkan hanya untuk diwariskan. **Access Modifiers** (`public`, `private`, `protected`) adalah kata kunci untuk mengatur siapa saja yang boleh melihat atau mengubah variabel di dalam sebuah class.

### Analogi

- **Abstract Class**: Bayangkan sebuah **Resep Dasar Roti**. Kamu tidak bisa memakan "Resep", kamu hanya bisa memakan roti yang dibuat berdasarkan resep itu. Resep ini mewajibkan setiap pembuat roti untuk menentukan "Rasa"-nya sendiri (apakah cokelat atau keju), tapi cara memanggangnya sudah ditentukan di resep dasar.
    
- **Access Modifiers**:
    
    - **`public`**: Seperti **Halaman Depan Rumah**. Siapa saja yang lewat boleh melihat dan masuk.
        
    - **`private`**: Seperti **Buku Harian**. Hanya pemilik rumah (class itu sendiri) yang boleh membaca. Orang luar tidak boleh tahu.
        
    - **`protected`**: Seperti **Warisan Keluarga**. Hanya pemilik rumah dan anak-anaknya (class turunan) yang boleh tahu, tapi tetangga tetap tidak boleh.
        

### Poin-Poin Penting

- **Abstract Class**:
    
    - Ditandai dengan kata kunci `abstract`.
        
    - Bisa memiliki `abstract method` (fungsi tanpa isi) yang **wajib** diisi oleh class turunannya.
        
- **Access Modifiers**:
    
    - **`public` (Default)**: Bisa diakses dari mana saja.
        
    - **`private`**: Hanya bisa diakses di dalam class itu sendiri. Sangat penting untuk menyembunyikan logika internal.
        
    - **`protected`**: Bisa diakses di dalam class itu sendiri dan class-class yang mewarisinya.
        
- **Readonly**: Modifikator tambahan yang membuat variabel hanya bisa dibaca dan tidak bisa diubah setelah diinisialisasi.
    

### Contoh Implementasi

TypeScript

```
// --- 1. Abstract Class ---
abstract class BaseService {
    // Properti ini hanya bisa diakses oleh class ini dan turunannya
    protected tableName: string;

    constructor(name: string) {
        this.tableName = name;
    }

    // Abstract method: Wajib dibuat isinya di class turunan
    abstract findAll(): string[];
}

// --- 2. Implementasi & Access Modifiers ---
class UserService extends BaseService {
    // Private: Benar-benar rahasia di dalam UserService
    private secretKey: string = "12345";

    constructor() {
        super("users");
    }

    public findAll(): string[] {
        console.log(`Mengakses tabel: ${this.tableName}`);
        return ["Andi", "Budi"];
    }
}

const service = new UserService();
service.findAll(); // OK
// console.log(service.secretKey); // Error: Property 'secretKey' is private
```

### Koneksi dengan Web Development (NestJS)

Konsep ini adalah standar industri dalam pengembangan **NestJS**:

1. **Dependency Injection**: Di NestJS, kita hampir selalu menggunakan `private readonly` di dalam _constructor_ untuk menyuntikkan _service_.
    
    - `constructor(private readonly userService: UserService) {}`
        
    - Ini memastikan `userService` tidak bisa diubah-ubah dari luar controller.
        
2. **Base Classes**: Developer NestJS sering membuat `BaseController` atau `BaseService` yang bersifat `abstract` untuk menyimpan logika umum (seperti logging atau error handling) agar tidak perlu ditulis ulang di setiap file.
    
3. **Encapsulation**: Menggunakan `private` memastikan logika bisnis di dalam _Service_ tidak diacak-acak oleh _Controller_, menjaga integritas data aplikasi.
