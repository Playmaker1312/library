### 14. Tipe `unknown` — Alternatif Aman untuk `any`

Jika `any` adalah "kartu bebas" yang ceroboh, maka **`unknown`** adalah "satpam yang sangat waspada". Ini adalah tipe data yang diperkenalkan untuk memberikan keamanan maksimal pada data yang bentuknya belum pasti.

---

### Definisi Singkat

**`unknown`** adalah tipe data yang digunakan untuk variabel yang nilainya belum diketahui saat penulisan kode. Berbeda dengan `any`, Anda **tidak boleh** melakukan operasi apa pun (seperti memanggil fungsi atau mengakses properti) pada variabel `unknown` sebelum Anda melakukan pengecekan tipe (_type checking_) terlebih dahulu.

---

### Analogi

Bayangkan Anda menerima sebuah **Paket Misterius** di depan pintu rumah.

- **Tipe `any`**: Anda mengasumsikan isi paket itu adalah sebuah bola lampu. Anda langsung memasangnya ke fitting lampu tanpa membukanya. Jika isinya ternyata batu, listrik rumah Anda akan meledak (_crash_).
    
- **Tipe `unknown`**: Anda tahu ada "sesuatu" di dalam paket, tapi Anda tidak tahu apa itu. Anda **dipaksa** untuk membuka paketnya dan memeriksanya terlebih dahulu. Jika isinya benar-benar bola lampu, baru Anda boleh memasangnya. Jika bukan, Anda tidak akan melakukan apa-apa.
    

---

### Poin-Poin Penting

- **Top Type:** Sama seperti `any`, semua nilai (string, number, object, dll.) bisa dimasukkan ke dalam variabel `unknown`.
    
- **Type Guarding:** Anda harus menggunakan `typeof`, `instanceof`, atau logika pengecekan lainnya sebelum menggunakan nilainya.
    
- **Keamanan Ketat:** Mencegah kesalahan pemanggilan metode yang tidak ada pada tipe tertentu (misal: memanggil `.toUpperCase()` pada angka).
    
- **Assignment:** Variabel `unknown` hanya bisa diberikan ke variabel bertipe `unknown` atau `any`. Ia tidak bisa langsung dimasukkan ke variabel bertipe `string` tanpa bukti yang jelas.
    

---

### Contoh Implementasi

**Perbandingan Bahaya `any` vs Keamanan `unknown`:**

TypeScript

```
let nilaiApapun: any = 10;
let nilaiMisterius: unknown = 10;

// any: TIDAK ERROR saat coding, tapi error saat dijalankan (runtime)
nilaiApapun.toUpperCase(); 

// unknown: ERROR saat coding (TypeScript melindungi kita)
// @ts-expect-error
nilaiMisterius.toUpperCase(); 

// Cara yang benar menggunakan unknown:
if (typeof nilaiMisterius === "string") {
    // Di dalam blok ini, TypeScript tahu nilaiMisterius adalah string
    console.log(nilaiMisterius.toUpperCase()); 
} else {
    console.log("Ini bukan string, jangan diproses!");
}
```

---

### Koneksi dalam Bidang Web Development

Dalam pengembangan **Web Development**, `unknown` sangat berguna untuk:

1. **Fetching Data dari API:** Saat menerima respon JSON dari server, kita sering tidak tahu pasti apakah server mengirim data yang valid atau pesan error. Menggunakan `unknown` memaksa kita memvalidasi data tersebut sebelum menampilkannya di UI.
    
2. **Input User yang Kompleks:** Jika Anda membuat _library_ atau fungsi yang menerima input dari pengembang lain, menggunakan `unknown` memastikan fungsi Anda tidak akan rusak jika mereka mengirimkan tipe data yang salah.
    
3. **Refactoring:** Membantu mengubah kode JavaScript lama ke TypeScript dengan cara menandai variabel yang tidak jelas sebagai `unknown` terlebih dahulu, lalu memperbaikinya satu per satu dengan pengecekan logika yang benar.
