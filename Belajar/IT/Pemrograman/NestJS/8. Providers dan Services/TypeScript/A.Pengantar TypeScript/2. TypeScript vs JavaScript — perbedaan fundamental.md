### 2. TypeScript vs JavaScript — Perbedaan Fundamental

Setelah memahami apa itu TypeScript, penting untuk melihat perbandingan "head-to-head" dengan JavaScript untuk memahami mengapa banyak pengembang memilih untuk pindah ke TypeScript.

---

### Definisi Singkat

**JavaScript** adalah bahasa pemrograman dinamis yang berjalan di sisi klien (browser) dan server, sedangkan **TypeScript** adalah bahasa pemrograman yang dibangun di atas JavaScript dengan menambahkan sistem tipe data statis. TypeScript bertindak sebagai lapisan pelindung yang memastikan data mengalir dengan benar di dalam aplikasi.

---

### Analogi

Bayangkan Anda sedang mengemudi di jalan raya.

- **JavaScript** adalah mengemudi di jalan tanpa garis marka atau rambu lalu lintas yang ketat. Anda bisa melaju dengan cepat dan fleksibel, tetapi risiko tabrakan sangat tinggi jika Anda tidak sangat berhati-hati. Anda baru menyadari ada masalah saat kecelakaan sudah terjadi.
    
- **TypeScript** adalah mengemudi di jalan raya yang memiliki marka jalur yang jelas, lampu lalu lintas, dan sensor otomatis pada mobil yang mengerem jika Anda hampir menabrak. Anda mungkin merasa sedikit "terbatasi" oleh aturan, tetapi Anda sampai di tujuan dengan jauh lebih aman dan terprediksi.
    

---

### Poin-Poin Penting

|**Fitur**|**JavaScript**|**TypeScript**|
|---|---|---|
|**Tipe Data**|**Dynamic Typing:** Tipe variabel ditentukan saat aplikasi berjalan (_runtime_).|**Static Typing:** Tipe variabel didefinisikan saat kode ditulis dan diperiksa sebelum dijalankan.|
|**Deteksi Error**|Kesalahan biasanya baru ditemukan saat program sedang berjalan.|Kesalahan ditemukan saat penulisan kode atau saat proses kompilasi.|
|**Proses Eksekusi**|Bisa langsung dijalankan oleh browser atau Node.js.|Harus dikompilasi (transpilasi) menjadi JavaScript terlebih dahulu agar bisa dijalankan.|
|**Refactoring**|Berisiko tinggi; sulit mengubah nama fungsi/variabel di banyak file secara otomatis.|Sangat mudah dan aman berkat bantuan _Intelligence_ dari editor.|
|**Dokumentasi**|Bergantung pada komentar atau dokumentasi eksternal.|Kode adalah dokumentasi itu sendiri karena tipe data terlihat jelas.|

### Contoh Implementasi

**Kasus: Menangani Objek Pengguna**

**JavaScript (Beresiko):**

JavaScript

```
const user = { name: "Budi" };

// Tidak ada peringatan jika kita memanggil properti yang salah
console.log(user.age); // Output: undefined (Bisa menyebabkan error di baris kode selanjutnya)
```

**TypeScript (Aman):**

TypeScript

```
interface User {
    name: string;
    age: number;
}

const user: User = { name: "Budi", age: 25 };

// TypeScript akan langsung protes jika kita mencoba mengakses properti yang tidak ada
// @ts-expect-error
console.log(user.alamat); 
// Error: Property 'alamat' does not exist on type 'User'.
```

### Koneksi dalam Bidang Web Development

Dalam konteks **Modern Web Development**, perbedaan ini berdampak pada kecepatan pengembangan tim:

1. **Integrasi API:** Saat bekerja dengan data dari server, TypeScript memungkinkan kita mendefinisikan "kontrak" (melalui `interface`). Jika backend mengubah struktur data, TypeScript akan memberi tahu bagian mana saja di frontend yang akan rusak.
    
2. **Modern Frameworks:** Framework populer seperti **Next.js** atau **Angular** menyarankan atau bahkan mewajibkan penggunaan TypeScript karena kemampuannya meminimalkan _bug_ "undefined is not a function" yang sangat umum di dunia JavaScript.
