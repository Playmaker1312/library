# 8. Providers dan Services

## 8.4. `@Injectable` Decorator

**Definisi Singkat:** `@Injectable()` adalah decorator yang menandai class sebagai provider yang bisa dikelola oleh NestJS DI Container. Tanpa decorator ini, class tidak bisa di-inject.

**Analogi:** Seperti kartu identitas karyawan — `@Injectable()` adalah lanyard-nya. Tanpa lanyard, satpam (DI Container) tidak akan mengenali Anda sebagai staff dan tidak bisa masuk ke area (inject ke class lain).

**Poin-Poin Penting:**
- Harus ditambahkan agar class dapat di-inject
- Bisa ditambahkan ke: Service, Guard, Pipe, Interceptor, ExceptionFilter
- Bisa menerima options (jarang): `@Injectable({ scope: Scope.REQUEST })`
- Tidak perlu untuk Controller dan Module (sudah otomatis)
- TypeScript decorator — perlu `experimentalDecorators: true` di tsconfig
- Di belakang layar: menambahkan metadata ke class untuk DI Container

**Contoh Kode:**
```typescript
import { Injectable, Scope, Inject } from '@nestjs/common';

// Standard — singleton service
@Injectable()
export class UsersService {
  findAll() {
    return [];
  }
}

// Dengan scope — instance baru per request
@Injectable({ scope: Scope.REQUEST })
export class RequestService {
  private readonly requestId: string;

  constructor(@Inject('REQUEST') private readonly request: any) {
    this.requestId = request.id ?? 'unknown';
  }

  getRequestId(): string {
    return this.requestId;
  }
}

// Guard — juga @Injectable
@Injectable()
export class JwtAuthGuard implements CanActivate {
  canActivate(context: ExecutionContext): boolean {
    return true;
  }
}

// Pipe — juga @Injectable
@Injectable()
export class ParseIdPipe implements PipeTransform<string, number> {
  transform(value: string): number {
    return parseInt(value, 10);
  }
}
```

**Kasus Penggunaan Nyata:**
Setiap class yang akan di-inject ke class lain membutuhkan `@Injectable()`. Service, Repository (custom), Guard, Pipe kustom, Interceptor, ExceptionFilter. NestJS built-in providers (like `ValidationPipe`) tidak perlu — sudah otomatis.
