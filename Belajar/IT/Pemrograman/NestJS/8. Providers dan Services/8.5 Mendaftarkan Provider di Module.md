# 8. Providers dan Services

## 8.5. Mendaftarkan Provider di Module

**Definisi Singkat:** Provider harus didaftarkan di array `providers` dari `@Module()` agar NestJS DI Container mengenali dan dapat meng-inject-nya. Tanpa pendaftaran, inject akan gagal.

**Analogi:** Seperti mendaftarkan karyawan baru ke HRD — meskipun orangnya sudah ada (class), tanpa terdaftar di sistem (module providers), dia tidak bisa digaji (di-inject) dan tidak bisa bekerja (tidak tersedia).

**Poin-Poin Penting:**
- Provider array di `@Module({ providers: [ServiceA, ServiceB] })`
- Short-hand: `[UsersService]` — setara dengan `{ provide: UsersService, useClass: UsersService }`
- Provider bisa didaftarkan di beberapa module? — Tidak, cukup di satu module lalu di-export
- Global module otomatis menyediakan provider ke semua module
- Jika provider tidak terdaftar → error `Nest can't resolve dependencies`
- Urutan pendaftaran tidak penting — DI Container resolve otomatis

**Contoh Kode:**
```typescript
import { Module } from '@nestjs/common';

@Module({
  controllers: [UsersController],
  providers: [
    UsersService,           // short-hand: provide = class, useClass = class
    LoggerService,          // akan di-inject ke UsersService
    EmailService,           // akan di-inject ke UsersService
  ],
  exports: [UsersService],  // untuk module lain
})
export class UsersModule {}

// Module lain — butuh UsersService
@Module({
  imports: [UsersModule],  // import module yang export provider
  controllers: [OrdersController],
  providers: [OrdersService],
})
export class OrdersModule {}

// OrdersService bisa inject UsersService
@Injectable()
export class OrdersService {
  constructor(private readonly usersService: UsersService) {}
}
```

**Kasus Penggunaan Nyata:**
Setiap feature module mendaftarkan service-nya di `providers`. Service yang dibutuhkan module lain di-export. Best practice: Feature module hanya mendaftarkan provider miliknya sendiri. Shared/Global module untuk provider lintas fitur.
