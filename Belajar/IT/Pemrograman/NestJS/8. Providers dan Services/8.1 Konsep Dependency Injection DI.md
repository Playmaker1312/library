# 8. Providers dan Services

## 8.1. Konsep Dependency Injection (DI)

**Definisi Singkat:** Dependency Injection adalah design pattern di mana class menerima dependensinya dari luar (constructor), bukan membuatnya sendiri. NestJS memiliki DI Container bawaan yang mengelola instantiation dan lifecycle provider.

**Analogi:** Seperti restoran — koki (class) tidak perlu pergi ke pasar membeli bahan (dependency). Cukup order ke supplier, dan bahan datang sendiri. Koki tinggal masak (business logic). Supplier (DI Container) urus pengadaan.

**Poin-Poin Penting:**
- DI Container = registri semua provider
- Provider di-declare di `@Module({ providers: [...] })`
- Constructor injection: dependency dideklarasikan di constructor parameter
- NestJS otomatis resolve dependency graph
- Singleton per default — instance yang sama di-share
- Decoupling — class tidak tahu cara membuat dependensinya
- Testability — mudah ganti real implementation dengan mock

**Contoh Kode:**
```typescript
import { Injectable, Module } from '@nestjs/common';

// Tanpa DI — kode kaku, sulit di-test
class UserControllerWithoutDI {
  private service = new UserService(); // hard-coded
}

// Dengan DI — flexible, testable
// 1. Define provider
@Injectable()
export class DatabaseService {
  connect() {
    return 'Connected to DB';
  }
}

// 2. Consume via constructor injection
@Injectable()
export class UserService {
  constructor(private readonly db: DatabaseService) {} // DI!

  getUsers() {
    this.db.connect();
    return ['Alice', 'Bob'];
  }
}

// 3. Daftarkan di module
@Module({
  controllers: [UserController],
  providers: [UserService, DatabaseService], // DI Container tahu ini
})
export class UserModule {}

// 4. DI Container otomatis:
// - Buat instance DatabaseService
// - Inject ke UserService constructor
// - UserService tersedia untuk controller
```

**Kasus Penggunaan Nyata:**
Setiap service NestJS menggunakan DI. Service A inject Service B, Service B inject Repository/ORM. Controller inject Service. Guard inject AuthService. Pipe inject ConfigService. Semua otomatis oleh DI Container.
