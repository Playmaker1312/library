# 6. Modules

## 6.1. Konsep Modular Architecture

**Definisi Singkat:** Modular architecture adalah prinsip mengorganisir kode ke dalam module-module yang independen dan reusable. Setiap module membungkus domain fitur tertentu — controller, service, dan provider terkait.

**Analogi:** Seperti laci-laci di dapur — satu laci untuk sendok (Users module), satu untuk pisau (Products module), satu untuk panci (Orders module). Anda bisa membuka laci yang dibutuhkan tanpa mengacak-acak yang lain.

**Poin-Poin Penting:**
- Module adalah dekorator `@Module({})` pada class
- Setiap module punya: `imports`, `controllers`, `providers`, `exports`
- Separation of concerns — setiap modul tangani satu domain
- Module bisa import module lain untuk menggunakan provider-nya
- Singleton providers — instance yang sama di-share ke module yang import
- Testability — module independen mudah di-mock

**Contoh Kode:**
```typescript
// Setiap fitur adalah module independen
import { Module } from '@nestjs/common';

// Users module — fitur manajemen user
@Module({
  controllers: [UsersController],
  providers: [UsersService, UsersRepository],
  exports: [UsersService], // untuk module lain yang butuh
})
export class UsersModule {}

// Products module — fitur produk
@Module({
  controllers: [ProductsController],
  providers: [ProductsService],
  exports: [ProductsService],
})
export class ProductsModule {}

// Orders module — fitur order (menggunakan Users dan Products)
@Module({
  imports: [UsersModule, ProductsModule], // dependency module
  controllers: [OrdersController],
  providers: [OrdersService],
})
export class OrdersModule {}

// Root module — menggabungkan semua
@Module({
  imports: [UsersModule, ProductsModule, OrdersModule],
})
export class AppModule {}
```

**Kasus Penggunaan Nyata:**
Setiap fitur besar dalam aplikasi NestJS adalah module terpisah: AuthModule, UsersModule, ProductsModule, OrdersModule, PaymentsModule, NotificationsModule. Module bisa di-share antar microservices atau di-publish sebagai package npm.
