## 6.1 Konsep Modular Architecture

### Definisi Singkat

**Modular Architecture** adalah pola desain yang membagi aplikasi menjadi bagian-bagian kecil yang berdiri sendiri, yang disebut **Module**. Setiap Module bertanggung jawab atas satu fitur atau fungsionalitas tertentu secara utuh (misal: modul khusus User, modul khusus Produk, atau modul khusus Transaksi).

### Analogi

Bayangkan kamu sedang merakit sebuah **PC Gaming**:

- **Aplikasi**: Adalah PC utuh yang menyala.
    
- **Module**: Adalah komponen-komponennya seperti **RAM, GPU, dan Motherboard**.
    
    - RAM punya sirkuit sendiri (Service/Controller).
        
    - GPU punya kipas dan prosesor sendiri.
        
    - Semuanya terpisah, tapi ketika dicolokkan ke Motherboard (**AppModule**), mereka bekerja sama menjadi satu kesatuan.
        
- **Keuntungan**: Jika RAM rusak, kamu tinggal cabut dan ganti tanpa harus membongkar seluruh casing PC atau menyolder ulang kabel motherboard.
    

### Mengapa Harus Modular?

Tanpa modul, semua kode akan menumpuk di satu tempat (disebut _Monolithic Spaghetti Code_). Modularitas memberikan:

1. **Encapsulation (Pemisahan)**: Masalah di Modul User tidak akan merusak Modul Produk.
    
2. **Reusability**: Kamu bisa menyalin folder `AuthModule` dari satu project ke project lain dengan mudah.
    
3. **Organization**: Developer baru di timmu akan langsung tahu: "Oh, kalau mau ubah cara simpan produk, saya harus buka folder `ProductModule`."
    

### Struktur Sebuah Module

Setiap module di NestJS didefinisikan menggunakan dekorator `@Module()`. Di dalamnya terdapat empat properti utama:

- **`providers`**: Daftar Service yang akan digunakan di dalam modul ini.
    
- **`controllers`**: Daftar Controller yang harus dinyalakan di modul ini.
    
- **`imports`**: Daftar modul lain yang dibutuhkan oleh modul ini (misal: perlu akses ke database).
    
- **`exports`**: Daftar Service yang ingin kamu "pinjamkan" agar bisa dipakai oleh modul lain.
    

### Contoh Implementasi (Visualisasi Folder)

Dalam project nyata, folder `src` kamu akan terlihat rapi seperti ini:

Plaintext

```
src/
├── app.module.ts       (Motherboard/Root)
├── users/              (Module Fitur User)
│   ├── users.module.ts
│   ├── users.controller.ts
│   └── users.service.ts
├── products/           (Module Fitur Produk)
│   ├── products.module.ts
│   ├── products.controller.ts
│   └── products.service.ts
└── main.ts
```

### Cara Membuat Module dengan CLI

Kamu tidak perlu membuat file-file di atas secara manual. NestJS CLI punya perintah sakti:

Bash

```
nest generate module users
# atau versi singkatnya
nest g mo users
```

Perintah ini akan membuatkan folder `users`, file `users.module.ts`, dan **otomatis mendaftarkannya** ke dalam `app.module.ts`. Kamu tidak perlu repot melakukan _import_ manual!

### Kesimpulan

Modularitas adalah rahasia mengapa aplikasi NestJS sangat mudah dikelola meskipun skalanya sudah jutaan baris kode. Kamu memulai dari `AppModule`, lalu memecahnya menjadi modul-modul kecil sesuai kebutuhan fitur.

Setelah paham konsep wadahnya (Module), materi berikutnya adalah **6.2 Introduction to Controllers**. Kita akan belajar cara membuat "penerima tamu" di dalam modul yang baru saja kita buat.

**Pertanyaan untukmu:** Jika kamu ingin membuat fitur "Chat" di aplikasimu, apakah kamu akan menaruh kodenya di `AppModule` atau membuat modul baru bernama `ChatModule`?
