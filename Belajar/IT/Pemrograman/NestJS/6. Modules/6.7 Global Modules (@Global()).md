## 6.7 Global Modules (`@Global()`)

### Definisi Singkat

**Global Module** adalah modul yang ditandai dengan dekorator `@Global()`. Sekali modul ini di-import ke dalam **Root Module (AppModule)**, maka seluruh `providers` (Service) yang ada di dalam array `exports`-nya akan tersedia untuk digunakan oleh modul mana pun tanpa perlu melakukan `imports` lagi di level fitur.

### Analogi

Bayangkan aplikasi kamu adalah sebuah **Kota**:

- **Shared Module**: Seperti **Alat Bor Spesifik**. Jika Bengkel A butuh, dia harus meminjam secara resmi dari Gudang Pusat. Jika Bengkel B juga butuh, dia pun harus melakukan prosedur peminjaman yang sama.
    
- **Global Module**: Seperti **Udara atau Cahaya Matahari**. Begitu matahari terbit (di-import di AppModule), semua orang di seluruh penjuru kota bisa langsung menikmatinya tanpa perlu melakukan prosedur pendaftaran atau peminjaman lagi. Semuanya otomatis tersedia.
    

---

### Cara Membuat Global Module

Untuk membuat sebuah modul menjadi global, kamu cukup menambahkan dekorator `@Global()` di atas kelas modulnya.

**Contoh: Membuat `CommonModule` yang berisi `HelperService`**

TypeScript

```
import { Module, Global } from '@nestjs/common';
import { HelperService } from './helper.service';

@Global() // <--- Menandakan modul ini tersedia di mana saja
@Module({
  providers: [HelperService],
  exports: [HelperService], // <--- Tetap harus di-export agar bisa dipakai
})
export class CommonModule {}
```

**Langkah Terakhir: Daftarkan HANYA di `AppModule`**

TypeScript

```
@Module({
  imports: [CommonModule, UsersModule, ProductsModule],
  // Sekarang UsersModule dan ProductsModule bisa memakai HelperService 
  // tanpa perlu meng-import CommonModule lagi di dalam file mereka.
})
export class AppModule {}
```

---

### Kapan Harus Menggunakan Global Module?

Jangan jadikan semua modul sebagai Global! Gunakan hanya untuk fitur yang sifatnya **Utility** atau **Infrastructure** yang dipakai hampir di setiap sudut aplikasi, contohnya:

1. **Database Connection**: Modul koneksi database.
    
2. **Configuration**: Modul untuk membaca file `.env` (seperti `ConfigModule`).
    
3. **Logging**: Service untuk mencatat aktivitas sistem (logger).
    
4. **Helper/Utils**: Fungsi-fungsi umum seperti enkripsi password atau manipulasi tanggal.
    

### Bahaya Menggunakan Global Module Terlalu Banyak

- **Hidden Dependencies**: Kamu akan kesulitan melacak sebuah Service berasal dari mana karena tidak ada `imports` yang tertulis di modul fitur.
    
- **Bad Architecture**: Membuat kode menjadi terlalu saling ketergantungan (_tightly coupled_).
    
- **Testing**: Menjadi lebih sulit saat melakukan _unit testing_ karena banyak dependensi yang muncul secara "gaib".
    

> **Pesan Penting:** NestJS merekomendasikan untuk tetap menggunakan **Shared Modules** (import manual) sebagai pilihan utama. Gunakan `@Global()` hanya jika kamu benar-benar lelah mengetik `imports` untuk modul yang dipakai di 10+ modul lainnya.

### Kesimpulan

Global Modules adalah "pedang bermata dua". Ia memberikan kenyamanan luar biasa karena menghemat waktu koding, tetapi bisa merusak kejelasan struktur aplikasi jika tidak digunakan dengan bijak.
