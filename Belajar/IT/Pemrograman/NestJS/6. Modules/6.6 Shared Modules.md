## 6.6 Shared Modules

### Definisi Singkat

**Shared Module** adalah modul yang diciptakan untuk membagikan fungsionalitasnya (biasanya berupa Service) kepada modul-modul lain di dalam aplikasi. Di NestJS, setiap modul adalah **Singleton** secara default, artinya jika kamu membagikan sebuah modul, semua yang menggunakannya akan memakai _instance_ yang sama.

### Analogi

Bayangkan aplikasi kamu adalah sebuah **Gedung Perkantoran**:

- **UserModule**: Kantor HRD.
    
- **ProductModule**: Departemen Gudang.
    
- **Shared Module (DatabaseService)**: **Kantin atau Genset Gedung**.
    
    - HRD butuh listrik (Database), Gudang juga butuh listrik.
        
    - Alih-alih setiap ruangan punya mesin genset sendiri-sendiri (boros memori), mereka semua terhubung ke satu **Genset Pusat** yang dibagikan ke seluruh gedung.
        

### Cara Membuat Shared Module

Ada dua langkah wajib agar sebuah modul bisa menjadi "Shared":

1. **Exports**: Modul penyedia harus memasukkan Service-nya ke dalam array `exports`.
    
2. **Imports**: Modul pengguna harus memasukkan Modul penyedia ke dalam array `imports`.
    

#### Contoh Kasus: Membagikan `UsersService` ke `AuthModule`

**Langkah 1: Di dalam `UsersModule`** Kita harus "mengizinkan" `UsersService` keluar dari modulnya.

TypeScript

```
@Module({
  providers: [UsersService],
  exports: [UsersService], // <--- Penting! Agar bisa dilihat modul lain
})
export class UsersModule {}
```

**Langkah 2: Di dalam `AuthModule`** Kita "mengambil" fungsionalitas dari `UsersModule`.

TypeScript

```
@Module({
  imports: [UsersModule], // <--- Import modulnya, bukan service-nya
  controllers: [AuthController],
  providers: [AuthService],
})
export class AuthModule {}
```

**Langkah 3: Penggunaan di `AuthService`** Sekarang kamu bisa menggunakan `UsersService` melalui _Constructor_:

TypeScript

```
@Injectable()
export class AuthService {
  constructor(private usersService: UsersService) {} // <--- Langsung pakai!
}
```

### Manfaat Utama Shared Modules

1. **Hemat Memori**: NestJS tidak akan membuat ulang `UsersService` berkali-kali. Ia hanya membuat satu kali dan meminjamkannya ke mana-mana.
    
2. **Consistency**: Data yang ada di `UsersService` akan tetap konsisten meskipun diakses dari modul yang berbeda.
    
3. **Clean Code**: Menghindari penulisan ulang logika yang sama (DRY - _Don't Repeat Yourself_).
    

---

### Kesimpulan

Ingatlah rumus ini: **Export di tempat asal, Import di tempat tujuan.** Tanpa `exports`, modul lain tidak akan pernah bisa melihat "isi dapur" modulmu.
