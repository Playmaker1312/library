## 6.2 Root Module (AppModule)

### Definisi Singkat

**Root Module** (biasanya bernama `AppModule`) adalah modul utama yang menjadi titik awal bagi NestJS untuk membangun **Internal Graph** (peta hubungan antar komponen). Setiap aplikasi NestJS wajib memiliki setidaknya satu Root Module yang nantinya dipanggil di file `main.ts`.

### Analogi

Pikirkan `AppModule` sebagai **Terminal Listrik Utama** di sebuah rumah:

- Kamu punya modul-modul kecil seperti "Kamar Tidur", "Dapur", dan "Ruang Tamu".
    
- Semua kabel dari setiap ruangan harus bermuara ke **Terminal Utama** ini.
    
- Jika kabel "Kamar Tidur" tidak dicolokkan ke Terminal Utama, maka lampu di kamar tersebut tidak akan pernah menyala, meskipun saklarnya sudah kamu tekan.
    

### Anatomi Kode AppModule

Secara default, file `src/app.module.ts` terlihat seperti ini:

TypeScript

```
import { Module } from '@nestjs/common';
import { AppController } from './app.controller';
import { AppService } from './app.service';
import { UsersModule } from './users/users.module'; // Contoh modul fitur

@Module({
  imports: [UsersModule],     // 1. Tempat mendaftarkan modul fitur lain
  controllers: [AppController], // 2. Controller yang ada di level root
  providers: [AppService],     // 3. Service yang ada di level root
  exports: [],                 // 4. (Jarang digunakan di AppModule)
})
export class AppModule {}
```

### Penjelasan Properti Dekorator `@Module()`

1. **`imports`**: Ini adalah bagian paling penting. Di sinilah kamu mendaftarkan semua modul fitur yang kamu buat (seperti `UsersModule`, `AuthModule`). Tanpa didaftarkan di sini, NestJS tidak akan mengenali keberadaan fitur tersebut.
    
2. **`controllers`**: Berisi daftar controller yang didefinisikan langsung di level root (biasanya hanya `AppController` untuk cek status server).
    
3. **`providers`**: Berisi daftar service/provider level root.
    
4. **`exports`**: Digunakan jika kamu ingin membagikan provider dari modul ini ke modul lain. Namun, karena `AppModule` adalah level teratas, biasanya bagian ini dibiarkan kosong.
    

### Alur Inisialisasi

Saat kamu menjalankan aplikasi:

1. `main.ts` memanggil `NestFactory.create(AppModule)`.
    
2. NestJS membuka `AppModule` dan melihat daftar di `imports`.
    
3. NestJS pergi ke setiap modul yang di-import dan memeriksa isinya.
    
4. Setelah semua modul terbaca, barulah seluruh rute API (Endpoint) aktif.
    

### Best Practice (Tips Profesional)

- **Jangan menumpuk logika di AppModule**: Seiring berkembangnya aplikasi, pindahkan semua logika ke modul fitur masing-masing. Biarkan `AppModule` tetap bersih dan hanya berisi daftar `imports`.
    
- **Urutan Import**: Biasanya modul pihak ketiga (seperti `ConfigModule` atau `TypeOrmModule`) diletakkan di urutan paling atas dalam array `imports`, baru diikuti oleh modul fitur buatanmu.
