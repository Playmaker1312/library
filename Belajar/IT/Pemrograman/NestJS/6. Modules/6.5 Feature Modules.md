## 6.5 Feature Modules

### Definisi Singkat

**Feature Module** adalah sebuah modul yang mengelompokkan kode yang berkaitan dengan fitur spesifik aplikasi (misalnya: _User_, _Product_, _Order_, atau _Chat_). Tujuannya adalah untuk menjaga agar kode tetap terorganisir, modular, dan mengikuti prinsip **Single Responsibility**.

### Analogi

Bayangkan kamu sedang membangun aplikasi **E-Commerce**:

- **Root Module (AppModule)**: Adalah gedung mall-nya.
    
- **Feature Modules**: Adalah toko-toko di dalamnya.
    
    - **UserModule**: Mengurus pendaftaran dan profil pelanggan.
        
    - **ProductModule**: Mengurus stok barang dan kategori.
        
    - **OrderModule**: Mengurus keranjang belanja dan pembayaran. Setiap toko memiliki staf (Service) dan meja kasir (Controller) sendiri. Jika toko sepatu ingin pindah ke mall lain, mereka bisa pindah dengan mudah karena semua kebutuhannya sudah ada di dalam satu unit toko tersebut.
        

### Mengapa Kita Membutuhkan Feature Modules?

1. **Isolation**: Masalah di fitur _Order_ tidak akan mengganggu fitur _User_.
    
2. **Scalability**: Saat aplikasi tumbuh dari 5 fitur menjadi 50 fitur, kamu tidak akan pusing karena setiap fitur tersimpan rapi di foldernya masing-masing.
    
3. **Teamwork**: Developer A bisa bekerja sepenuhnya di dalam folder `src/products` sementara Developer B di `src/users` tanpa resiko bentrok kode (_merge conflict_) yang tinggi.
    
4. **Clean Code**: `AppModule` tidak akan menjadi file raksasa yang berisi ribuan baris kode, melainkan hanya daftar modul-modul fitur.
    

### Cara Kerja Feature Modules

Ketika kamu membuat feature module (misalnya `UsersModule`), urutan komunikasinya adalah:

1. **`UsersController`** dan **`UsersService`** didaftarkan di dalam **`UsersModule`**.
    
2. **`UsersModule`** kemudian di-import ke dalam **`AppModule`**.
    
3. NestJS membaca `AppModule`, lalu masuk ke `UsersModule`, dan akhirnya mengaktifkan semua rute API yang ada di sana.
    

### Contoh Struktur Folder yang Ideal

Plaintext

```
src/
├── app.module.ts
├── users/                <-- Feature Module: Users
│   ├── users.module.ts
│   ├── users.controller.ts
│   └── users.service.ts
├── products/             <-- Feature Module: Products
│   ├── products.module.ts
│   ├── products.controller.ts
│   └── products.service.ts
└── main.ts
```

### Tips CLI

Selalu gunakan CLI untuk membuat feature module agar struktur foldernya konsisten:

Bash

```
# Langkah 1: Buat Modulnya dulu
nest g mo users

# Langkah 2: Buat Controller di dalam folder modul tersebut
nest g co users

# Langkah 3: Buat Service di dalam folder modul tersebut
nest g s users
```

---

### Kesimpulan

Dengan menerapkan **Feature Modules**, kamu tidak lagi menulis kode secara acak. Kamu membangun aplikasi seperti menyusun Lego; bagian demi bagian dikerjakan secara terpisah, lalu disatukan di pusat kendali (`AppModule`).

Sekarang wadah fiturnya sudah sangat jelas. Kita akan masuk ke materi **6.6 Global Modules**, untuk mempelajari cara membuat modul yang "selalu tersedia" di mana saja tanpa perlu di-import berulang kali.

Relevant follow-up: Jika kamu punya fitur "Pencarian" yang digunakan baik oleh User maupun Product, menurutmu apakah fitur tersebut harus masuk ke salah satu modul yang ada atau dibuatkan `SearchModule` sendiri?
