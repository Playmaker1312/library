# 36. Memahami Dependency Injection secara mendalam dalam konteks NestJS

## Definisi & Target
Dependency Injection (DI) adalah pola desain di mana class menerima dependensinya dari luar (injected) daripada membuatnya sendiri. NestJS memiliki DI container yang mengelola pembuatan dan siklus hidup semua provider. Ini membuat kode lebih testable, modular, dan loosely coupled.

## Komponen & Nest CLI Command
Tidak ada perintah CLI spesifik. Semua provider menggunakan `@Injectable()`.

## Kode Implementasi (Per File)

```typescript
// src/products/products.service.ts
import { Injectable } from '@nestjs/common';

@Injectable()
export class ProductsService {
  async findAll() {
    return [];
  }
}

// src/products/products.controller.ts
import { Controller, Get } from '@nestjs/common';
import { ProductsService } from './products.service';

@Controller('products')
export class ProductsController {
  // NestJS meng-inject ProductsService secara otomatis
  constructor(private readonly productsService: ProductsService) {}

  @Get()
  async findAll() {
    return this.productsService.findAll();
  }
}
```

Cara kerja DI di NestJS:
1. `ProductsService` didaftarkan sebagai provider di module
2. NestJS membuat instance tunggal (singleton) dari `ProductsService`
3. Saat `ProductsController` dibuat, NestJS melihat constructor dan meng-inject instance `ProductsService`
4. Untuk testing, kamu bisa memberikan mock service langsung

## Cara Integrasi & Pengujian
DI memudahkan testing — saat unit test controller, kamu bisa inject mock service: `new ProductsController(mockService)`. Jangan pernah membuat instance service manual dengan `new ProductsService()` — biarkan NestJS yang mengelola siklus hidupnya.
