# 39. Memahami cara NestJS membangun dependency graph secara internal

## Definisi & Target
NestJS memiliki Dependency Injection container yang secara internal membangun graph dependensi. Saat aplikasi start, NestJS memeriksa semua provider, menganalisis constructor parameter, dan menentukan urutan inisialisasi. Jika ada circular dependency, NestJS akan mendeteksinya dan melempar error.

## Komponen & Nest CLI Command
Tidak ada perintah CLI. Ini adalah konsep internal NestJS.

## Kode Implementasi (Per File)

```typescript
// Cara kerja internal DI container NestJS:

// 1. NestJS membaca metadata dari decorators (@Module, @Injectable)
// 2. Membuat graph dependensi berdasarkan constructor parameter
// 3. Menyelesaikan dependensi (resolve) — membuat instance dalam urutan yang benar

// Contoh graph dependensi:
// AppModule
//   ├── ProductsModule
//   │   ├── ProductsController → depends on → ProductsService
//   │   └── ProductsService
//   └── UsersModule
//       ├── UsersController → depends on → UsersService
//       └── UsersService

// Jika terjadi circular dependency:
// ServiceA → ServiceB → ServiceA
// NestJS akan throw: "Circular dependency detected"

// Solusi circular dependency — gunakan @Inject(forwardRef(() => ServiceB))
import { Injectable, Inject, forwardRef } from '@nestjs/common';

@Injectable()
export class ServiceA {
  constructor(
    @Inject(forwardRef(() => ServiceB))
    private readonly serviceB: ServiceB,
  ) {}
}
```

## Cara Integrasi & Pengujian
NestJS menangani DI secara otomatis — kamu hanya perlu mendaftarkan provider di module. Jika terjadi error "circular dependency", gunakan `forwardRef()` untuk salah satu sisi dependensi. Hindari circular dependency sebisa mungkin dengan mendesain ulang arsitektur.
