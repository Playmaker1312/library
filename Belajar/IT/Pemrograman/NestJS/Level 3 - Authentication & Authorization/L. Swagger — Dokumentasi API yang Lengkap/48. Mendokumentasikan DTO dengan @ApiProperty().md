# 48. Mendokumentasikan DTO dengan @ApiProperty()

## Penjelasan

Agar Swagger UI menampilkan informasi yang lengkap tentang body request yang diharapkan, setiap properti di DTO perlu didekorasi dengan `@ApiProperty()` (atau `@ApiPropertyOptional()` untuk field opsional). Decorator ini memberi tahu Swagger tentang tipe data, contoh nilai, deskripsi, dan apakah field tersebut required atau opsional.

Meskipun plugin Swagger bisa membaca sebagian informasi dari dekorator `class-validator`, menambahkan `@ApiProperty()` secara eksplisit memberikan kontrol lebih terhadap dokumentasi. Kita bisa menambahkan contoh nilai (example), deskripsi yang lebih jelas, dan format data. Ini sangat membantu developer frontend yang mengonsumsi API.

## Fungsi

`@ApiProperty()` berfungsi untuk mendokumentasikan properti-properti DTO di Swagger UI. Ini meliputi: nama properti, tipe data (string, number, enum), deskripsi, contoh nilai, format (email, date-time, uri), dan apakah properti bersifat required atau opsional. Dokumentasi yang baik mengurangi miskomunikasi antara backend dan frontend developer.

## Cara Implementasi / Code

**1. RegisterDto dengan @ApiProperty() — `src/auth/dto/register.dto.ts`:**

```typescript
import { IsEmail, IsString, MinLength, MaxLength, Matches } from 'class-validator';
import { ApiProperty } from '@nestjs/swagger';

export class RegisterDto {
  @ApiProperty({
    description: 'Alamat email pengguna yang akan didaftarkan',
    example: 'john.doe@example.com',
    format: 'email',
  })
  @IsEmail()
  email: string;

  @ApiProperty({
    description: 'Nama lengkap pengguna',
    example: 'John Doe',
    minLength: 6,
    maxLength: 50,
  })
  @IsString()
  @MinLength(6)
  @MaxLength(50)
  name: string;

  @ApiProperty({
    description: 'Password akun (min 8 karakter, harus mengandung huruf kapital dan angka)',
    example: 'Password123',
    minLength: 8,
    maxLength: 100,
    format: 'password',
  })
  @IsString()
  @MinLength(8)
  @MaxLength(100)
  @Matches(/(?=.*[A-Z])(?=.*\d)/, {
    message: 'Password must contain at least one uppercase letter and one number',
  })
  password: string;
}
```

**2. LoginDto dengan @ApiProperty() — `src/auth/dto/login.dto.ts`:**

```typescript
import { IsEmail, IsString } from 'class-validator';
import { ApiProperty } from '@nestjs/swagger';

export class LoginDto {
  @ApiProperty({
    description: 'Alamat email pengguna',
    example: 'john.doe@example.com',
    format: 'email',

  email: string;

  @ApiProperty({
    description: 'Password pengguna',
    example: 'Password123',
    format: 'password',
  })
  @IsString()

}
```

**4. CreateBookDto dengan @ApiProperty() — `src/books/dto/create-book.dto.ts`:**

```typescript
import { IsString, IsInt, Min, Max, IsOptional } from 'class-validator';
import { ApiProperty, ApiPropertyOptional } from '@nestjs/swagger';

export class CreateBookDto {
  @ApiProperty({
    description: 'Judul buku',
    example: 'Clean Code: A Handbook of Agile Software Craftsmanship',
  })
  @IsString()
  title: string;

  @ApiProperty({
    description: 'Nama penulis buku',
    example: 'Robert C. Martin',
  })
  @IsString()
  author: string;

  @ApiProperty({
    description: 'ISBN (International Standard Book Number)',
    example: '978-0132350884',
  })
  @IsString()
  isbn: string;

  @ApiPropertyOptional({
    description: 'Tahun terbit buku',
    example: 2008,
    minimum: 1000,
    maximum: new Date().getFullYear(),
  })
  @IsOptional()
  @IsInt()
  @Min(1000)
  @Max(new Date().getFullYear())
  publishedYear?: number;
}
```

**5. UpdateBookDto dengan @ApiProperty() — `src/books/dto/update-book.dto.ts`:**

```typescript
import { PartialType } from '@nestjs/swagger';
import { CreateBookDto } from './create-book.dto';

```

Dengan `PartialType`, semua field dari CreateBookDto menjadi opsional dan dokumentasi swagger-nya otomatis terwariskan.

**6. Response DTO (untuk dokumentasi response) — `src/auth/dto/auth-response.dto.ts`:**

```typescript
import { ApiProperty } from '@nestjs/swagger';

class UserResponseDto {
  @ApiProperty({ example: 1 })
  id: number;

  @ApiProperty({ example: 'john.doe@example.com' })
  email: string;

  @ApiProperty({ example: 'John Doe' })
  name: string;

  @ApiProperty({ example: 'USER', enum: ['USER', 'LIBRARIAN', 'ADMIN'] })
  role: string;
}

export class AuthResponseDto {
  @ApiProperty({ type: UserResponseDto })
  user: UserResponseDto;

  @ApiProperty({
    example: 'eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...',
    description: 'Access token untuk autentikasi (berlaku 15 menit)',
  })
  accessToken: string;

  @ApiProperty({
    example: 'eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...',
    description: 'Refresh token untuk memperpanjang session (berlaku 7 hari)',
  })
  refreshToken: string;
}
```

## Analogi

`@ApiProperty()` di DTO seperti **label informasi** yang ditempel di setiap kolom formulir pendaftaran perpustakaan. Label ini memberi tahu:
- **Nama kolom**: "Email" — `name: 'email'`
- **Contoh isi**: "john@email.com" — `example: 'john@email.com'`
- **Penjelasan**: "Alamat email yang valid" — `description: '...'`
- **Format**: "email" — `format: 'email'`
- **Wajib diisi?**: Ya — `required: true` (default)

Tanpa label ini, formulir hanya menampilkan kolom kosong tanpa petunjuk — membingungkan pengunjung yang ingin mendaftar.

## Penggunaan

`@ApiProperty()` digunakan di semua DTO yang akan diterima atau dikembalikan oleh API. Ini termasuk DTO untuk request body (CreateDto, UpdateDto, RegisterDto, LoginDto) dan DTO untuk response (ResponseDto). Dengan dokumentasi yang baik, developer frontend bisa langsung memahami format data yang diharapkan.

## Kesalahan Umum yang Sering Terjadi

1. **Tidak konsisten antara @ApiProperty() dan @IsString()**: Jika @ApiProperty({ type: 'number' }) tapi @IsString(), akan membingungkan.
2. **Lupa @ApiPropertyOptional() untuk field opsional**: Jika suatu field bisa undefined, gunakan @ApiPropertyOptional() atau set required: false.
3. **Tidak memberikan example value**: Contoh nilai sangat membantu developer untuk memahami format data yang diharapkan.
4. **Duplicate code**: Gunakan `PartialType`, `PickType`, `OmitType` dari `@nestjs/swagger` untuk menghindari duplikasi dokumentasi.

## Soal Latihan

**Soal 1:** Apa perbedaan `@ApiProperty()` dan `@ApiPropertyOptional()`?

**Jawaban:** `@ApiPropertyOptional()` sama dengan `@ApiProperty({ required: false })`. Keduanya menandai bahwa properti tersebut opsional. Di swagger UI, properti opsional tidak akan ditandai dengan tanda bintang merah (required).

**Soal 2:** Bagaimana cara mendokumentasikan properti bertipe enum di Swagger?

**Jawaban:**

```typescript
import { ApiProperty } from '@nestjs/swagger';
import { Role } from '@prisma/client';

export class CreateUserDto {
  @ApiProperty({
    enum: Role,
    description: 'Role pengguna',
    default: Role.USER,
  })
  role: Role;
}
```

**Soal 3:** Gunakan `PickType` untuk membuat DTO yang hanya berisi field `email` dan `password` dari RegisterDto.

**Jawaban:**

```typescript
import { PickType } from '@nestjs/swagger';
import { RegisterDto } from './register.dto';

export class LoginDto extends PickType(RegisterDto, ['email', 'password'] as const) {}
```

Dengan `PickType`, semua dekorator (termasuk @ApiProperty) dari field yang dipilih akan otomatis diwariskan.
