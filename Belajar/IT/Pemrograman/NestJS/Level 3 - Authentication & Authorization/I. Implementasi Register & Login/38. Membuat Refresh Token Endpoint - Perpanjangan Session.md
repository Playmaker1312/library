# 38. Membuat Refresh Token Endpoint - Perpanjangan Session

## Penjelasan

Refresh token endpoint adalah mekanisme untuk memperpanjang session pengguna tanpa harus login ulang. Ketika access token kedaluwarsa (setelah 15 menit), client bisa mengirim refresh token ke endpoint ini untuk mendapatkan access token baru beserta refresh token baru. Konsep ini disebut **refresh token rotation** — setiap kali refresh, token lama di-invalidasi dan diganti dengan token baru. Ini meningkatkan keamanan karena jika refresh token dicuri, pencuri hanya bisa menggunakannya sekali.

Proses di backend meliputi: menerima refresh token dari body request, memverifikasi token menggunakan secret key khusus (jwtRefreshSecret), mengecek apakah token tersebut cocok dengan yang tersimpan di database, lalu generate token baru dan update database. Jika refresh token sudah tidak valid atau tidak cocok dengan database, user harus login ulang.

## Fungsi

Refresh token endpoint berfungsi untuk memberikan sepasang token baru (access + refresh) tanpa meminta user memasukkan email dan password lagi. Ini meningkatkan user experience karena session bisa bertahan selama refresh token masih valid (biasanya 7 hari) tanpa perlu login berulang kali.

**2. Update AuthService — tambahkan method refreshTokens:**

```typescript
import {
  Injectable,
  ConflictException,
  UnauthorizedException,
  ForbiddenException,
} from '@nestjs/common';
import { ConfigType } from '@nestjs/config';
import { JwtService } from '@nestjs/jwt';
import * as bcrypt from 'bcrypt';
import authConfig from './auth.config';
import { UsersService } from '../users/users.service';
import { RegisterDto } from './dto/register.dto';
import { LoginDto } from './dto/login.dto';
import { RefreshTokenDto } from './dto/refresh-token.dto';

@Injectable()
export class AuthService {
  constructor(
    private readonly usersService: UsersService,
    private readonly jwtService: JwtService,
    @Inject(authConfig.KEY)
    private readonly config: ConfigType<typeof authConfig>,
  ) {}

  // ... register, login, generateTokens methods ...

  async refreshTokens(dto: RefreshTokenDto) {
    try {
      // Verifikasi refresh token signature
      const payload = await this.jwtService.verifyAsync(dto.refreshToken, {
        secret: this.config.jwtRefreshSecret,
      });

      // Cari user berdasarkan sub (user ID)
      const user = await this.usersService.findById(payload.sub);

      // Validasi: user harus ada
      if (!user) {
        throw new ForbiddenException('Access denied');
      }

      // Validasi: refresh token harus cocok dengan yang di database
      if (!user.refreshToken || user.refreshToken !== dto.refreshToken) {
        throw new ForbiddenException('Access denied');
      }

      // Generate token baru (rotation)
      const tokens = await this.generateTokens(user.id, user.email, user.role);

      // Simpan refresh token baru di database
      await this.usersService.updateRefreshToken(user.id, tokens.refreshToken);

      return tokens;
    } catch (error) {
      if (error instanceof ForbiddenException) {
        throw error;
      }
      // Tangani error JWT (expired, invalid signature, dll)
      throw new UnauthorizedException('Invalid refresh token');
    }
  }
}
```

**3. Update AuthController:**

```typescript
import { Controller, Post, Body } from '@nestjs/common';
import { AuthService } from './auth.service';
import { RegisterDto } from './dto/register.dto';
import { LoginDto } from './dto/login.dto';
import { RefreshTokenDto } from './dto/refresh-token.dto';

@Controller('auth')
export class AuthController {
  constructor(private readonly authService: AuthService) {}

  @Post('register')
  async register(@Body() dto: RegisterDto) {
    return this.authService.register(dto);
  }

  @Post('login')
  async login(@Body() dto: LoginDto) {
    return this.authService.login(dto);
  }

  @Post('refresh')
  async refresh(@Body() dto: RefreshTokenDto) {
    return this.authService.refreshTokens(dto);
  }
}
```

```typescript
// Pseudocode untuk interceptor HTTP di frontend
async function handleResponse(error: any) {
  if (error.status === 401 && !error.config._retry) {
    error.config._retry = true;

    const refreshToken = localStorage.getItem('refreshToken');
    const response = await http.post('/auth/refresh', { refreshToken });

    localStorage.setItem('accessToken', response.accessToken);
    localStorage.setItem('refreshToken', response.refreshToken);

    error.config.headers.Authorization = `Bearer ${response.accessToken}`;
    return http.request(error.config);
  }
}
```

## Analogi

Di perpustakaan, refresh token seperti **proses perpanjangan kartu anggota**. Stempel akses harian (access token) sudah hampir habis masa berlakunya. Anggota pergi ke meja resepsionis dan menunjukkan stempel anggota (refresh token) yang masih berlaku. Resepsionis memeriksa apakah stempel itu asli dan masih terdaftar di buku besar (database). Jika valid, resepsionis memberikan stempel baru (refresh token rotation) — stempel akses harian baru dan stempel anggota baru, lalu mencoret stempel lama. Jika stempel anggota sudah kedaluwarsa atau tidak cocok, anggota harus mendaftar ulang (login).

## Penggunaan

Refresh token endpoint digunakan oleh aplikasi frontend secara otomatis melalui HTTP interceptor. Ketika request ke API mendapatkan response 401 (Unauthorized), frontend akan secara otomatis memanggil endpoint refresh sebelum mengulangi request yang gagal. Ini membuat transisi token kedaluwarsa menjadi transparan bagi pengguna.

## Kesalahan Umum yang Sering Terjadi

1. **Tidak melakukan refresh token rotation**: Jika refresh token tidak dirotasi, token lama tetap valid dan bisa digunakan berkali-kali jika bocor.
2. **Menggunakan secret key yang sama untuk access dan refresh token**: Ini mengurangi keamanan karena jika satu secret bocor, kedua jenis token bisa dipalsukan.
3. **Error handling yang tidak tepat**: JWT bisa kedaluwarsa (TokenExpiredError) atau signature tidak valid (JsonWebTokenError). Keduanya harus ditangani.
4. **Tidak membandingkan refresh token dengan database**: Hanya memverifikasi JWT signature saja tidak cukup. Refresh token yang sudah di-logout harus ditolak meskipun signature-nya valid.

## Hubungan dengan Materi Sebelumnya

Refresh token menggunakan `JwtService.verifyAsync` (dari materi 35) dengan secret key yang berbeda. UsersService digunakan untuk mencari user dan memperbarui refresh token. Konsep ini melanjutkan login flow dari materi 37 dan menjadi dasar untuk logout di materi 39.

## Soal Latihan

**Soal 1:** Apa keuntungan refresh token rotation dibandingkan hanya memberikan access token yang sama?

**Jawaban:** Refresh token rotation meningkatkan keamanan dengan cara: (1) jika refresh token dicuri, pencuri hanya bisa menggunakannya sekali karena server akan mengeluarkan token baru dan menginvalidasi yang lama, (2) jika refresh token lama digunakan setelah rotasi, itu bisa menjadi indikasi pencurian, dan server bisa menginvalidasi semua session user sebagai respons.

**Soal 2:** Apa yang terjadi jika ada attacker yang berhasil mencuri refresh token dan menggunakannya bersamaan dengan user yang sah?

**Jawaban:** Ini disebut race condition. Siapa yang lebih dulu menggunakan refresh token akan mendapatkan token baru. Pihak yang kedua akan mendapatkan error karena refresh token lama sudah tidak cocok dengan database. Sebaiknya server mendeteksi pola ini dan menginvalidasi semua token user yang bersangkutan sebagai tindakan keamanan.

**Soal 3:** Modifikasi kode refreshTokens untuk mendeteksi kemungkinan pencurian refresh token (refresh token reuse detection).

**Jawaban:**

```typescript
async refreshTokens(dto: RefreshTokenDto) {
  try {
    const payload = await this.jwtService.verifyAsync(dto.refreshToken, {
      secret: this.config.jwtRefreshSecret,
    });

    const user = await this.usersService.findById(payload.sub);
    if (!user) {
      throw new ForbiddenException('Access denied');
    }

    // Deteksi potensi pencurian: refresh token tidak cocok
    if (!user.refreshToken || user.refreshToken !== dto.refreshToken) {
      // Mungkin refresh token sudah digunakan atau dicuri
      // Invalidasi semua token user untuk keamanan
      await this.usersService.updateRefreshToken(user.id, null);
      throw new ForbiddenException('Session expired, please login again');
    }

    const tokens = await this.generateTokens(user.id, user.email, user.role);
    await this.usersService.updateRefreshToken(user.id, tokens.refreshToken);

    return tokens;
  } catch (error) {
    if (error instanceof ForbiddenException) {
      throw error;
    }
    throw new UnauthorizedException('Invalid refresh token');
  }
}
```
