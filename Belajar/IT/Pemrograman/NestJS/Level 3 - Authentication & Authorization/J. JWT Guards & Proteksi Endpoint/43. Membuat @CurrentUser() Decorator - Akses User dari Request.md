# 43. Membuat @CurrentUser() Decorator - Akses User dari Request

## Penjelasan

Setelah JwtStrategy berhasil memvalidasi token, data user akan tersimpan di `req.user`. Untuk mengaksesnya di controller, kita bisa menggunakan `@Req() req` lalu `req.user`. Tapi ini kurang praktis dan tidak type-safe. Solusinya adalah membuat **custom parameter decorator** `@CurrentUser()` yang langsung mengekstrak data user dari request dengan type yang benar.

NestJS menyediakan fungsi `createParamDecorator` untuk membuat decorator parameter kustom. Decorator ini bisa mengakses `ExecutionContext` dan mengambil data dari request. Kita juga bisa menambahkan parameter untuk mengambil field spesifik dari user, misalnya `@CurrentUser('email')` yang langsung mengembalikan string email, bukan seluruh object user.

## Fungsi

`@CurrentUser()` decorator berfungsi untuk mengekstrak data user yang sudah diautentikasi dari request object dengan cara yang bersih, type-safe, dan mudah digunakan. Ini mengurangi boilerplate code dan membuat controller lebih readable. Decorator ini juga bisa difleksibelkan untuk mengambil field tertentu dari user object.

## Cara Implementasi / Code

**1. CurrentUser Decorator — `src/auth/decorators/current-user.decorator.ts`:**

```typescript
import { createParamDecorator, ExecutionContext } from '@nestjs/common';
import { Request } from 'express';

// Interface untuk data user yang disimpan di req.user
export interface CurrentUserData {
  id: number;
  email: string;
  name: string;
  role: string;
}

export const CurrentUser = createParamDecorator(
  (data: keyof CurrentUserData | undefined, ctx: ExecutionContext) => {
    const request: Request = ctx.switchToHttp().getRequest();
    const user = request.user as CurrentUserData;

    // Jika tidak ada user di request (misalnya endpoint public)
    if (!user) {
      return null;
    }

    // Jika parameter field diberikan, kembalikan field spesifik
    // Contoh: @CurrentUser('email') => return 'john@example.com'
    if (data) {
      return user[data];
    }

    // Jika tidak ada parameter, kembalikan seluruh object user
    return user;
  },
);
```

**3. Penggunaan di AuthController:**

```typescript
import { Controller, Post, Get, Body } from '@nestjs/common';
import { AuthService } from './auth.service';
import { RegisterDto } from './dto/register.dto';
import { LoginDto } from './dto/login.dto';
import { Public } from '../decorators/public.decorator';
import { CurrentUser } from '../decorators/current-user.decorator';

@Controller('auth')
export class AuthController {
  constructor(private readonly authService: AuthService) {}

  @Public()
  @Post('register')
  async register(@Body() dto: RegisterDto) {
    return this.authService.register(dto);
  }

  @Public()
  @Post('login')
  async login(@Body() dto: LoginDto) {
    return this.authService.login(dto);
  }

  @Get('me')
  getProfile(@CurrentUser() user: CurrentUserData) {
    return { user };
  }

  @Post('logout')
  async logout(@CurrentUser('id') userId: number) {
    return this.authService.logout(userId);
  }
}
```

## Analogi

Di perpustakaan, `@CurrentUser()` seperti **asisten pribadi** yang langsung memberikan data diri Anda tanpa perlu mengeluarkan kartu anggota setiap kali. Ketika Anda sudah melewati satpam (JwtStrategy) dan identitas Anda tercatat, asisten ini tinggal menyodorkan data Anda ke petugas mana pun yang membutuhkannya. Jika petugas hanya perlu tahu nama Anda, cukup minta "nama" (`@CurrentUser('name')`) — asisten langsung menyebutkannya tanpa perlu membacakan seluruh data di KTP.

## Penggunaan

`@CurrentUser()` digunakan di semua controller yang membutuhkan data user yang sedang login. Contoh penggunaannya: menampilkan profil user, mencatat siapa yang membuat resource, log aktivitas, atau untuk validasi kepemilikan data (misalnya user hanya bisa mengedit data miliknya sendiri).

## Kesalahan Umum yang Sering Terjadi

1. **Menggunakan @CurrentUser() di endpoint public**: Jika endpoint tidak membutuhkan autentikasi, `req.user` akan undefined. Decorator harus meng-handle kasus ini dengan return null.
2. **Tipe data tidak sesuai**: Pastikan tipe data yang dikembalikan validate() di JwtStrategy cocok dengan CurrentUserData interface.
3. **Lupa menambahkan field baru di CurrentUserData**: Jika JwtStrategy mengembalikan field tambahan (misalnya `isBanned`), tambahkan juga di CurrentUserData.
4. **Mengakses field yang tidak ada**: Jika menggunakan `@CurrentUser('alamat')` tapi field tersebut tidak ada di user object, akan return undefined.

## Hubungan dengan Materi Sebelumnya

`@CurrentUser()` sangat bergantung pada JwtStrategy (materi 40). Data yang dikembalikan oleh `validate()` di JwtStrategy adalah data yang akan diakses melalui `req.user`. Tanpa JwtStrategy yang berfungsi dengan baik, `@CurrentUser()` tidak akan memiliki data untuk diekstrak. Decorator ini akan digunakan bersama JwtAuthGuard (materi 42) untuk membuat endpoint yang aman.

## Soal Latihan

**Soal 1:** Apa perbedaan antara `@Req() req` lalu `req.user` dengan `@CurrentUser()`?

**Jawaban:** `@Req() req` mengembalikan seluruh request object Express dan kita harus mengakses `req.user` secara manual. Ini tidak type-safe (req.user bertipe any) dan tidak praktis. `@CurrentUser()` langsung mengembalikan data user dengan tipe yang spesifik (CurrentUserData), lebih bersih, dan bisa mengambil field spesifik dengan parameter.

**Soal 2:** Bagaimana jika kita ingin @CurrentUser() mengembalikan user dari database lengkap (bukan hanya dari token)?

**Jawaban:** Kita bisa inject UsersService di decorator (menggunakan `Injectable`), tapi decorator parameter tidak bisa menggunakan dependency injection secara langsung. Solusinya: buat interceptor atau middleware yang mengambil user dari database, atau cukup lakukan di service layer saja.

**Soal 3:** Modifikasi CurrentUser decorator agar bisa melempar error jika user tidak ditemukan (strict mode).

**Jawaban:**

```typescript
import {
  createParamDecorator,
  ExecutionContext,
  UnauthorizedException,
} from '@nestjs/common';
import { Request } from 'express';

export const CurrentUser = createParamDecorator(
  (data: keyof CurrentUserData | undefined, ctx: ExecutionContext) => {
    const request: Request = ctx.switchToHttp().getRequest();
    const user = request.user as CurrentUserData;

    if (!user) {
      throw new UnauthorizedException('User not authenticated');
    }

    if (data) {
      if (!(data in user)) {
        throw new Error(`Field '${data}' not found in user object`);
      }
      return user[data];
    }

    return user;
  },
);
```
