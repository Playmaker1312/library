# 32. Microservices
## 32.9 Inter-service Communication
**Definisi Singkat:** Inter-service communication mencakup pola komunikasi antar microservices — synchronous (request-response via message pattern) dan asynchronous (event-driven via event pattern), serta saga pattern untuk distributed transactions.
**Analogi:** Seperti rantai perakitan mobil — setiap stasiun (service) melakukan tugasnya dan berkomunikasi dengan stasiun berikutnya. Ada yang langsung memberikan komponen (sync) dan ada yang mengirim sinyal bahwa komponen siap (async).
**Poin-Poin Penting:**
- Sync: `@MessagePattern` + `ClientProxy.send()`
- Async: `@EventPattern` + `ClientProxy.emit()`
- Saga pattern untuk distributed transaction
- Orchestration vs Choreography
**Contoh Kode:**
```typescript
// order-placement.flow.ts — Distributed transaction dengan Saga pattern
//
// Saga: Order placement flow (Orchestration-based)
//
// 1. Order Service → terima request create order
// 2. Order Service → call Inventory Service (reserve stock) [sync]
// 3. Stock tersedia? → Ya: lanjut, Tidak: cancel
// 4. Order Service → call Payment Service (process payment) [sync]
// 5. Payment sukses? → Ya: lanjut, Tidak: rollback stock + cancel
// 6. Order Service → emit event 'order_confirmed' [async]
// 7. Notification Service → handle event (send email) [async]
// 8. Shipping Service → handle event (create shipment) [async]
//
// Jika ada yang gagal, jalankan COMPENSATING TRANSACTIONS (rollback)

import { Injectable, Inject } from '@nestjs/common';
import { ClientProxy } from '@nestjs/microservices';
import { lastValueFrom } from 'rxjs';

@Injectable()
export class OrderSaga {
  constructor(
    @Inject('INVENTORY_SERVICE') private inventoryClient: ClientProxy,
    @Inject('PAYMENT_SERVICE') private paymentClient: ClientProxy,
    @Inject('NOTIFICATION_SERVICE') private notificationClient: ClientProxy,
    @Inject('SHIPPING_SERVICE') private shippingClient: ClientProxy,
  ) {}

  async placeOrder(orderData: any) {
    const saga = {
      steps: [] as string[],
      orderId: Date.now(),
    };

    try {
      // Step 1: Reserve stock — sync request-response
      console.log('[SAGA] Step 1: Reserve stock');
      await lastValueFrom(
        this.inventoryClient.send({ cmd: 'reserve_stock' }, {
          orderId: saga.orderId,
          items: orderData.items,
        })
      );
      saga.steps.push('stock_reserved');

      // Step 2: Process payment — sync
      console.log('[SAGA] Step 2: Process payment');
      const payment = await lastValueFrom(
        this.paymentClient.send({ cmd: 'charge_payment' }, {
          orderId: saga.orderId,
          amount: orderData.total,
          userId: orderData.userId,
        })
      );
      saga.steps.push('payment_charged');

      // Step 3: Confirm order — async event
      console.log('[SAGA] Step 3: Confirm order');
      this.notificationClient.emit('order_confirmed', {
        orderId: saga.orderId,
        userId: orderData.userId,
        email: orderData.email,
      });
      saga.steps.push('order_confirmed');

      // Step 4: Create shipment — async event
      console.log('[SAGA] Step 4: Create shipment');
      this.shippingClient.emit('create_shipment', {
        orderId: saga.orderId,
        address: orderData.shippingAddress,
      });
      saga.steps.push('shipment_created');

      return {
        success: true,
        orderId: saga.orderId,
        paymentId: payment.transactionId,
        steps: saga.steps,
      };

    } catch (error) {
      // 🚨 Saga rollback — compensating transactions
      console.log(`[SAGA] Failed at step ${saga.steps.length + 1}: ${error.message}`);
      console.log('[SAGA] Starting rollback...');

      // Rollback in reverse order
      if (saga.steps.includes('payment_charged')) {
        await lastValueFrom(
          this.paymentClient.send({ cmd: 'refund_payment' }, {
            orderId: saga.orderId,
          })
        );
        console.log('[SAGA] Rollback: Payment refunded');
      }

      if (saga.steps.includes('stock_reserved')) {
        await lastValueFrom(
          this.inventoryClient.send({ cmd: 'release_stock' }, {
            orderId: saga.orderId,
            items: orderData.items,
          })
        );
        console.log('[SAGA] Rollback: Stock released');
      }

      throw new Error(`Order failed: ${error.message}`);
    }
  }
}
```
```typescript
// inventory.controller.ts — service yang menangani request
@Controller()
export class InventoryController {
  // Stock mutation — bisa rollback
  private reservedStock = new Map<number, any[]>();

  @MessagePattern({ cmd: 'reserve_stock' })
  async reserveStock(@Payload() data: { orderId: number; items: any[] }) {
    // Cek dan reserve stock
    for (const item of data.items) {
      if (item.quantity > 10) {
        // Gagal — trigger rollback saga
        throw new RpcException({
          statusCode: 409,
          message: `Stok ${item.productId} tidak mencukupi`,
          code: 'INSUFFICIENT_STOCK',
        });
      }
    }

    this.reservedStock.set(data.orderId, data.items);
    return { success: true, reserved: data.items.length };
  }

  // Compensating action — release stock
  @MessagePattern({ cmd: 'release_stock' })
  async releaseStock(@Payload() data: { orderId: number }) {
    this.reservedStock.delete(data.orderId);
    return { success: true, message: 'Stock released' };
  }
}
```

```typescript
// Communication patterns summary:
//
// 1️⃣ SYNCHRONOUS (Request-Response)
//    - Service A → kirim pesan → Service B → response → Service A
//    - Service A MENUNGGU response dari Service B
//    - Cocok untuk: query data, validasi, operasi yang butuh konfirmasi
//    - Resiko: latency, cascading failure
//    - Implementasi: @MessagePattern + client.send()
//
// 2️⃣ ASYNCHRONOUS (Event-driven)
//    - Service A → emit event → Message Broker → Service B, C, D
//    - Service A TIDAK menunggu — lanjut proses
//    - Cocok untuk: notifikasi, logging, analytics
//    - Kelebihan: loose coupling, parallel processing
//    - Implementasi: @EventPattern + client.emit()
//
// 3️⃣ SAGA PATTERN (Distributed Transaction)
//    - Orchestration: satu coordinator (saga) mengatur urutan
//    - Choreography: setiap service publish event, yang lain react
//    - Compensating transaction: rollback jika ada yang gagal
//    - Cocok untuk: operasi multi-service yang butuh atomicity
```
**Kasus Penggunaan Nyata:** Aplikasi pemesanan tiket pesawat. Saga pattern mengkoordinasikan: (1) Reservasi kursi, (2) Pembayaran, (3) Update jadwal, (4) Kirim e-ticket. Jika pembayaran gagal, kursi yang sudah direservasi harus dilepaskan (compensating transaction) — semua terkoordinasi tanpa distributed transaction database.
