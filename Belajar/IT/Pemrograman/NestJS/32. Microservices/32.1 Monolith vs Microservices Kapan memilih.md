# 32. Microservices
## 32.1 Monolith vs Microservices Kapan memilih
**Definisi Singkat:** Monolith adalah satu aplikasi yang menangani semua fungsi, sedangkan Microservices memecah aplikasi menjadi service-service kecil yang independen dan berkomunikasi via network.
**Analogi:** Monolith seperti toko serba ada (semua di satu tempat, mudah dikelola tapi ribet saat skalasi). Microservices seperti pusat perbelanjaan — masing-masing toko (service) independen, punya staf sendiri (database sendiri), dan pengunjung (client) bisa ke toko mana saja.
**Poin-Poin Penting:**
- Monolith: satu codebase, satu deploy, shared database
- Microservices: banyak service, independent deploy, own database
- Pilih Monolith dulu, Microservices setelah scale butuh
**Contoh Kode:**
```typescript
// MONOLITH — satu aplikasi, semua fitur di sini
// app.module.ts
import { Module } from '@nestjs/common';
import { AuthModule } from './auth/auth.module';
import { UsersModule } from './users/users.module';
import { ProductsModule } from './products/products.module';
import { OrdersModule } from './orders/orders.module';
import { PaymentsModule } from './payments/payments.module';
import { NotificationsModule } from './notifications/notifications.module';

@Module({
  imports: [
    AuthModule,        // Autentikasi
    UsersModule,       // Manajemen user
    ProductsModule,    // Manajemen produk
    OrdersModule,      // Manajemen pesanan
    PaymentsModule,    // Proses pembayaran
    NotificationsModule, // Notifikasi email/push
  ],
})
export class AppModule {}
// Kelebihan: Sederhana, mudah develop, satu database
// Kekurangan: Sulit scale per-fitur, deploy besar
```
```typescript
// MICROSERVICES — service terpisah
// Masing-masing service adalah aplikasi NestJS sendiri
//
// auth-service/
//   ├── src/
//   │   ├── auth.module.ts
//   │   └── main.ts (port 3001)
//   └── package.json
//
// user-service/
//   ├── src/
//   │   ├── user.module.ts
//   │   └── main.ts (port 3002)
//   └── package.json
//
// product-service/
//   ├── src/
//   │   ├── product.module.ts
//   │   └── main.ts (port 3003)
//   └── package.json
//
// order-service/
//   ├── src/
//   │   ├── order.module.ts
//   │   └── main.ts (port 3004)
//   └── package.json
//
// Kelebihan: Scale per-service, independent deploy, teknologi bebas
// Kekurangan: Kompleksitas network, debugging sulit, distributed transaction
```
```typescript
// Decision matrix — kapan pilih apa?
//
//                   Monolith    Microservices
// Tim kecil (<5)       ✅            ❌
// Startup awal         ✅            ❌
// Prototype cepat      ✅            ❌
// Scale per-fitur      ❌            ✅
// Tim besar (>10)      ❌            ✅
// Deploy sering        ~             ✅
// Independent tech     ❌            ✅
// Complexity rendah    ✅            ❌
//
// Rekomendasi: Mulai dengan Monolith, extract ke Microservices
// saat tim sudah besar dan scale sudah terasa bottleneck
```
**Kasus Penggunaan Nyata:** Startup e-commerce memulai dengan monolith — semua fitur (auth, produk, order, payment) dalam satu aplikasi NestJS. Setelah 2 tahun, tim berkembang dari 3 ke 15 developer, traffic meningkat 100x. Mereka extract `payment-service` (butuh compliance PCI-DSS) dan `notification-service` (high throughput) menjadi microservices terpisah.
