# 2. TypeScript Wajib

## 2.1. Mengapa TypeScript — Static Typing

**Definisi Singkat:** TypeScript adalah superset JavaScript dengan static type checking yang mendeteksi error saat kompilasi, bukan saat runtime. NestJS dibangun di atas TypeScript.

**Analogi:** JavaScript seperti menulis surat tanpa amplop — isinya bisa saja hilang atau salah. TypeScript seperti amplop dengan alamat jelas — posisi dan isi sudah terverifikasi sebelum dikirim.

**Poin-Poin Penting:**
- Static typing = error terdeteksi saat `npm run build`, bukan di production
- Type inference — TypeScript bisa menyimpulkan tipe dari nilai
- IDE support — autocomplete, refactoring, navigation
- NestJS CLI generate TypeScript files secara default
- Interface, Generics, Decorators adalah fitur TypeScript esensial untuk NestJS

**Contoh Kode:**
```typescript
// JavaScript — error baru ketahuan saat runtime
function getLength(input) {
  return input.length; // undefined jika input adalah number
}

// TypeScript — error langsung di IDE
function getLength(input: string): number {
  return input.length; // aman — hanya menerima string
}

// TypeScript di NestJS Controller
import { Controller, Get, Param } from '@nestjs/common';

@Controller('users')
export class UsersController {
  @Get(':id')
  findOne(@Param('id') id: string): Promise<User> {
    return this.usersService.findOne(id); // return type jelas
  }
}
```

**Kasus Penggunaan Nyata:**
Setiap project NestJS menggunakan TypeScript. Static typing menjaga kontrak antar module — service, controller, repository semuanya memiliki tipe yang jelas. Error database/validation terdeteksi saat compile.
