# 248. Cara mengimplementasikan refresh token dengan expiry panjang yaitu 7 hari

## Definisi & Target
Refresh token memiliki masa berlaku lebih panjang (7 hari) sehingga user tidak perlu login berulang kali. Token ini ditandatangani dengan secret berbeda dari access token.

## Komponen & Nest CLI Command
Konfigurasi di AuthService saat sign refresh token.

## Kode Implementasi (Per File)
// src/auth/auth.service.ts (bagian generateTokens)
```typescript
import { Injectable } from '@nestjs/common';
import { JwtService } from '@nestjs/jwt';

@Injectable()
export class AuthService {
  constructor(private readonly jwtService: JwtService) {}

  private generateTokens(user: any) {
    const payload = { sub: user.id, email: user.email, role: user.role };

    const accessToken = this.jwtService.sign(payload, {
      expiresIn: '15m',
    });

    const refreshToken = this.jwtService.sign(payload, {
      secret: process.env.JWT_REFRESH_SECRET,
      expiresIn: '7d',
    });

    return { accessToken, refreshToken };
  }

  async refreshToken(refreshToken: string) {
    try {
      const payload = this.jwtService.verify(refreshToken, {
        secret: process.env.JWT_REFRESH_SECRET,
      });
      const user = await this.usersService.findById(payload.sub);
      return this.generateTokens(user);
    } catch {
      throw new UnauthorizedException('Invalid or expired refresh token');
    }
  }
}
```

## Cara Integrasi & Pengujian
Refresh token dikirim ke endpoint `POST /auth/refresh`. Gunakan secret `JWT_REFRESH_SECRET` berbeda di `.env`. Setelah 7 hari, refresh token expired dan user harus login ulang.
