# 14. Interceptors

## 14.7. Cache Interceptor pengenalan

**Definisi Singkat:** Interceptor untuk menyimpan response di cache agar request berikutnya tidak perlu mengeksekusi handler lengkap.

**Analogi:** Seperti foto copy KTP — setelah difotocopy sekali, tinggal ambil hasil copy-annya, tidak perlu antri lagi.

**Poin-Poin Penting:**
- Interceptor bisa cek cache sebelum `next.handle()`
- Jika cache ada, return cache (skip handler)
- Jika tidak ada, execute handler lalu simpan response ke cache
- Gunakan Map, Redis, atau cache store lain
- NestJS punya built-in `CacheInterceptor`
- Perhatikan cache invalidation

**Contoh Kode:**
```typescript
import { Injectable, NestInterceptor, ExecutionContext, CallHandler } from '@nestjs/common';
import { Observable, of } from 'rxjs';
import { tap } from 'rxjs/operators';

@Injectable()
export class SimpleCacheInterceptor implements NestInterceptor {
  private cache = new Map<string, any>();

  intercept(context: ExecutionContext, next: CallHandler): Observable<any> {
    const request = context.switchToHttp().getRequest();
    const cacheKey = `${request.method}-${request.url}`;

    const cached = this.cache.get(cacheKey);
    if (cached) {
      console.log(`Cache HIT: ${cacheKey}`);
      return of(cached);
    }

    console.log(`Cache MISS: ${cacheKey}`);
    return next.handle().pipe(
      tap(data => {
        this.cache.set(cacheKey, data);
        // Hapus cache setelah 60 detik
        setTimeout(() => this.cache.delete(cacheKey), 60000);
      }),
    );
  }
}
```

**Kasus Penggunaan Nyata:** Endpoint daftar produk yang jarang berubah dipasangi `SimpleCacheInterceptor` — 1000 request per detik hanya 1 request yang benar-benar ke database, sisanya dari cache in-memory.
