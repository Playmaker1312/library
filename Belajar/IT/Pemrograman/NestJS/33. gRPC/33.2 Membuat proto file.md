# 33. gRPC ## 33.2 Membuat proto file

**Definisi Singkat:** Proto file adalah file definisi service dan message dalam format Protocol Buffers yang menjadi kontrak antara gRPC server dan client. Proto file menentukan method, parameter, dan tipe data secara ketat.

**Analogi:** Proto file seperti blueprint kontrak kerja sama — sama seperti kontrak hukum yang mendefinisikan apa yang harus dikirim dan diterima, proto file memastikan server dan client "setuju" tentang format data.

**Poin-Poin Penting:**
- **syntax = "proto3"** menentukan versi protobuf
- **package** untuk namespace
- **service** mendefinisikan RPC methods
- **message** struktur data
- **stream** keyword untuk streaming
- **oneof, enum, map** fitur protobuf

**Contoh Kode:**
```typescript
// order.proto
syntax = "proto3";

package order;

service OrderService {
  rpc CreateOrder (CreateOrderRequest) returns (OrderResponse) {}
  rpc GetOrder (GetOrderRequest) returns (OrderResponse) {}
  rpc ListOrders (ListOrdersRequest) returns (ListOrdersResponse) {}
  rpc TrackOrder (GetOrderRequest) returns (stream OrderStatus) {}
}

message CreateOrderRequest {
  string userId = 1;
  repeated OrderItem items = 2;
  Address shippingAddress = 3;
  PaymentMethod payment = 4;
}

message OrderItem {
  string productId = 1;
  string name = 2;
  int32 quantity = 3;
  double price = 4;
}

message Address {
  string street = 1;
  string city = 2;
  string postalCode = 3;
  string country = 4;
}

enum PaymentMethod {
  CREDIT_CARD = 0;
  BANK_TRANSFER = 1;
  E_WALLET = 2;
}

message GetOrderRequest {
  string orderId = 1;
}

message OrderResponse {
  string orderId = 1;
  string status = 2;
  double total = 3;
  repeated OrderItem items = 4;
  string createdAt = 5;
}

message ListOrdersRequest {
  int32 page = 1;
  int32 limit = 2;
  string userId = 3;
}

message ListOrdersResponse {
  repeated OrderResponse orders = 1;
  int32 total = 2;
  int32 page = 3;
}

message OrderStatus {
  string status = 1;
  string timestamp = 2;
  string description = 3;
}
```

**Kasus Penggunaan Nyata:** Tim backend mendefinisikan proto file sebagai kontrak sebelum implementasi — memungkinkan tim frontend dan backend mengembangkan service secara paralel dengan tipe yang terjamin.
