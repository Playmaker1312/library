# 21. Serialization dan Response Shaping
## 21.2 Exclude dan Expose dari class-transformer
**Definisi Singkat:** `@Exclude()` menyembunyikan properti dari serialization output, `@Expose()` memastikan properti tetap muncul atau memberi alias/nama berbeda untuk response.

**Analogi:** Exclude seperti stiker "RAHASIA" di dokumen — jangan ditunjukkan ke publik. Expose seperti label "Nama Lengkap" yang menggantikan field `full_name` agar lebih rapi.

**Poin-Poin Penting:**
- **`@Exclude()`** — Sembunyikan properti dari serialized output
- **`@Expose()`** — Tampilkan properti (override exclude all)
- **`@Expose({ name: 'fullName' })`** — Alias nama properti di response
- **`@Exclude({ toPlainOnly: true })`** — Hanya untuk serialisasi (bukan deserialisasi)

**Contoh Kode:**
```typescript
// user.entity.ts
import { Entity, PrimaryGeneratedColumn, Column } from 'typeorm';
import { Exclude, Expose } from 'class-transformer';

@Entity('users')
export class User {
  @PrimaryGeneratedColumn()
  id: number;

  @Column()
  @Expose({ name: 'full_name' })
  fullName: string; // Jadi "full_name" di JSON

  @Column()
  email: string;

  @Column()
  @Exclude()
  password: string; // Hilang dari JSON

  @Column()
  @Exclude()
  refreshToken: string; // Hilang dari JSON

  @Column()
  @Exclude({ toPlainOnly: true })
  twoFactorSecret: string; // Hilang saat serialisasi ke plain object

  @Expose()
  get displayName(): string {
    return this.fullName || this.email;
  } // Virtual field di response
}

// Response JSON akan:
// { id: 1, full_name: "John Doe", email: "john@test.com", displayName: "John Doe" }
```

**Kasus Penggunaan Nyata:** Entity `User` dengan field internal `password`, `refreshToken`, `twoFactorSecret` — semua di-@Exclude agar tidak bocor via API.
