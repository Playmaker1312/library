# 9. DTO dan Validation

## 9.4. Validation Decorators IsString IsEmail IsNotEmpty dll

**Definisi Singkat:** Dekorator dari `class-validator` yang dipasang di property DTO untuk menegakkan aturan validasi.

**Analogi:** Seperti checklist koper — setiap barang diperiksa: apakah ada, apakah jenisnya benar, apakah formatnya sesuai.

**Poin-Poin Penting:**
- `@IsString()` — harus string
- `@IsEmail()` — format email valid
- `@IsNotEmpty()` — tidak boleh kosong
- `@IsNumber()` — harus number
- `@IsOptional()` — boleh tidak ada
- `@Min()/@Max()` — batas numerik
- `@MinLength()/@MaxLength()` — batas panjang string

**Contoh Kode:**
```typescript
import { IsString, IsEmail, IsNotEmpty, IsOptional, MinLength, IsNumber, Min } from 'class-validator';

export class CreateUserDto {
  @IsString()
  @IsNotEmpty()
  @MinLength(3)
  name: string;

  @IsEmail()
  email: string;

  @IsString()
  @MinLength(6)
  password: string;

  @IsOptional()
  @IsNumber()
  @Min(0)
  age?: number;
}
```

**Kasus Penggunaan Nyata:** Endpoint registrasi memvalidasi bahwa `name` minimal 3 karakter, `email` format valid, dan `password` minimal 6 karakter sebelum diproses lebih lanjut.
