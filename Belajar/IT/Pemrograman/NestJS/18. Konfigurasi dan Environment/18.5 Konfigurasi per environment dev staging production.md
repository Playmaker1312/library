# 18. Konfigurasi dan Environment
## 18.5 Konfigurasi per environment dev staging production
**Definisi Singkat:** NestJS mendukung konfigurasi berbeda untuk tiap environment (development, staging, production) melalui file `.env` terpisah dan environment variable `NODE_ENV`.

**Analogi:** Seperti seragam kerja — Anda pakai baju berbeda untuk latihan (dev), briefing (staging), dan presentasi (production). Fungsinya sama, detailnya beda.

**Poin-Poin Penting:**
- **`NODE_ENV`** — Menentukan environment aktif
- **`envFilePath`** — Load file sesuai environment
- **`.env.development`** — Debug logging, database lokal
- **`.env.staging`** — Mirip production, database staging
- **`.env.production`** — Optimasi, database production

**Contoh Kode:**
```typescript
// app.module.ts
import { Module } from '@nestjs/common';
import { ConfigModule } from '@nestjs/config';

const envFile = `.env.${process.env.NODE_ENV || 'development'}`;

@Module({
  imports: [
    ConfigModule.forRoot({
      envFilePath: [envFile, '.env'],
      isGlobal: true,
    }),
  ],
})
export class AppModule {}
```

```text
# .env.development
PORT=3000
DATABASE_URL=postgresql://localhost:5432/dev_db
LOG_LEVEL=debug
CORS_ORIGIN=http://localhost:4200

# .env.staging
PORT=3000
DATABASE_URL=postgresql://staging-db:5432/staging_db
LOG_LEVEL=info
CORS_ORIGIN=https://staging.example.com

# .env.production
PORT=8080
DATABASE_URL=postgresql://prod-db:5432/prod_db
LOG_LEVEL=warn
CORS_ORIGIN=https://example.com
```

**Kasus Penggunaan Nyata:** CI/CD pipeline set `NODE_ENV=staging` dan aplikasi otomatis menggunakan konfigurasi staging dengan database staging.
