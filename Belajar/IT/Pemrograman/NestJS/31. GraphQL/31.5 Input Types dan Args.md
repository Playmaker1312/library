# 31. GraphQL
## 31.5 Input Types dan Args
**Definisi Singkat:** Input Types (`@InputType()`) adalah class khusus untuk data yang dikirim dari client ke server (mutation/query arguments), sedangkan Args (`@Args()`) adalah decorator untuk mengakses parameter query/mutation.
**Analogi:** Input Type seperti formulir isian yang dikirim ke teller bank — berisi data yang diperlukan untuk transaksi. Args adalah amplop yang membawa formulir tersebut ke meja teller yang tepat.
**Poin-Poin Penting:**
- `@InputType()` untuk deklarasi input class
- `@Field()` di input type untuk setiap field
- `@Args()` untuk akses argument resolver
- `@ArgsType()` untuk argument terdistribusi
**Contoh Kode:**
```typescript
// dto/create-user.input.ts
import { InputType, Field, Int, registerEnumType } from '@nestjs/graphql';
import { IsEmail, IsString, MinLength, IsOptional, IsEnum, IsInt, Min } from 'class-validator';
import { UserRole } from '../entities/user.entity';

@InputType({ description: 'Input untuk membuat pengguna baru' })
export class CreateUserInput {
  @Field(() => String, { description: 'Nama lengkap pengguna' })
  @IsString()
  @MinLength(3)
  name: string;

  @Field(() => String, { description: 'Alamat email' })
  @IsEmail()
  email: string;

  @Field(() => String, { description: 'Password (min 8 karakter)' })
  @IsString()
  @MinLength(8)
  password: string;

  @Field(() => UserRole, {
    description: 'Role pengguna',
    defaultValue: UserRole.USER,
    nullable: true,
  })
  @IsOptional()
  @IsEnum(UserRole)
  role?: UserRole;

  @Field(() => Int, { description: 'Umur', nullable: true })
  @IsOptional()
  @IsInt()
  @Min(17)
  age?: number;
}
```

```typescript
// dto/pagination.input.ts
import { InputType, Field, Int } from '@nestjs/graphql';
import { IsOptional, IsInt, Min, Max } from 'class-validator';

@InputType({ description: 'Parameter pagination' })
export class PaginationInput {
  @Field(() => Int, { defaultValue: 1, nullable: true })
  @IsOptional()
  @IsInt()
  @Min(1)
  page?: number = 1;

  @Field(() => Int, { defaultValue: 10, nullable: true })
  @IsOptional()
  @IsInt()
  @Min(1)
  @Max(100)
  limit?: number = 10;
}
```

```typescript
// users.resolver.ts — menggunakan Input Types dan Args
import { Resolver, Query, Mutation, Args, Int } from '@nestjs/graphql';
import { User } from './entities/user.entity';
import { CreateUserInput } from './dto/create-user.input';
import { UpdateUserInput } from './dto/update-user.input';
import { PaginationInput } from './dto/pagination.input';
import { UserFilterInput } from './dto/user-filter.input';

@Resolver(() => User)
export class UsersResolver {
  // Single arg — langsung dari parameter
  @Query(() => User, { nullable: true })
  async user(@Args('id', { type: () => Int }) id: number) {
    // Args('id') → akses single argument
  }

  // Multiple args — kombinasi input type dan single args
  @Query(() => [User])
  async users(
    @Args('pagination', {
      type: () => PaginationInput,
      nullable: true,
      defaultValue: { page: 1, limit: 10 },
    })
    pagination: PaginationInput,

    @Args('filter', {
      type: () => UserFilterInput,
      nullable: true,
    })
    filter?: UserFilterInput,
  ) {
    console.log(`Page: ${pagination.page}, Limit: ${pagination.limit}`);
    if (filter) {
      console.log(`Filter: ${JSON.stringify(filter)}`);
    }
    // Query ke database
  }

  // Mutation dengan input type
  @Mutation(() => User)
  async createUser(
    @Args('input', { type: () => CreateUserInput })
    input: CreateUserInput,
  ) {
    // input.name, input.email, input.password
    return this.usersService.create(input);
  }

  // Mutation dengan multiple args
  @Mutation(() => User)
  async updateUser(
    @Args('id', { type: () => Int }) id: number,
    @Args('input', { type: () => UpdateUserInput }) input: UpdateUserInput,
  ) {
    return this.usersService.update(id, input);
  }
}
```

**Kasus Penggunaan Nyata:** Halaman admin dengan tabel user yang bisa di-filter, di-sort, dan di-paginate. Input types `PaginationInput` dan `UserFilterInput` memungkinkan frontend mengirim parameter kompleks dalam satu query, tanpa perlu multiple query parameters seperti di REST.
