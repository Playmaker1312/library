# 31. GraphQL
## 31.2 nestjs graphql Setup Code-first vs Schema-first
**Definisi Singkat:** NestJS GraphQL mendukung dua pendekatan: **Code-first** (mendefinisikan schema menggunakan decorator TypeScript) dan **Schema-first** (mendefinisikan schema file `.graphql` terpisah). Code-first lebih populer karena type safety dan deklarasi dekat dengan kode.
**Analogi:** Code-first seperti membuat blueprint rumah langsung dengan software arsitek (decorator) — Anda desain dan lihat hasilnya bersamaan. Schema-first seperti menggambar blueprint di kertas (file .graphql) lalu membangun rumah berdasarkan gambar itu.
**Poin-Poin Penting:**
- `@nestjs/graphql` dan `@nestjs/apollo` packages
- `GraphQLModule.forRoot()` setup
- Code-first: decorator `@ObjectType()`, `@Field()`
- Schema-first: file `*.graphql` + resolvers
**Contoh Kode:**
```typescript
// app.module.ts — CODE-FIRST approach (recommended)
import { Module } from '@nestjs/common';
import { GraphQLModule } from '@nestjs/graphql';
import { ApolloDriver, ApolloDriverConfig } from '@nestjs/apollo';
import { join } from 'path';
import { UsersModule } from './users/users.module';

@Module({
  imports: [
    GraphQLModule.forRoot<ApolloDriverConfig>({
      driver: ApolloDriver,              // Gunakan Apollo driver
      autoSchemaFile: join(process.cwd(), 'src/schema.gql'),  // Auto-generate schema
      sortSchema: true,                  // Sorting schema alphabetically
      playground: true,                  // Enable Apollo Playground
      debug: process.env.NODE_ENV !== 'production',
      csrfPrevention: true,
      cache: 'bounded',
      // formatError untuk custom error formatting
      formatError: (error) => ({
        message: error.message,
        code: error.extensions?.code || 'INTERNAL_ERROR',
        path: error.path,
      }),
    }),
    UsersModule,
  ],
})
export class AppModule {}
```
```typescript
// app.module.ts — SCHEMA-FIRST approach
import { Module } from '@nestjs/common';
import { GraphQLModule } from '@nestjs/graphql';
import { ApolloDriver, ApolloDriverConfig } from '@nestjs/apollo';
import { join } from 'path';
import { UsersModule } from './users/users.module';

@Module({
  imports: [
    GraphQLModule.forRoot<ApolloDriverConfig>({
      driver: ApolloDriver,
      // Tentukan path file schema (.graphql)
      typePaths: ['./**/*.graphql'],
      // Tentukan direktori untuk generated TypeScript definitions
      definitions: {
        path: join(process.cwd(), 'src/graphql.ts'),
        outputAs: 'class',
      },
    }),
    UsersModule,
  ],
})
export class AppModule {}
```

```typescript
// Kombinasi keduanya — code-first dengan schema first compatibility
@Module({
  imports: [
    GraphQLModule.forRoot<ApolloDriverConfig>({
      driver: ApolloDriver,
      autoSchemaFile: 'schema.gql',
      // Build schema dengan decorator, output ke file .gql
      // File .gql bisa digunakan untuk code generation frontend
      buildSchemaOptions: {
        numberScalarMode: 'integer',
      },
    }),
  ],
})
export class AppModule {}
```
**Kasus Penggunaan Nyata:** Tim baru memulai project NestJS + GraphQL. Code-first dipilih karena: (1) TypeScript decorator memberikan auto-completion, (2) schema selalu sinkron dengan kode, (3) tidak perlu belajar syntax SDL GraphQL terpisah, (4) lebih mudah refactoring karena schema adalah kode.
