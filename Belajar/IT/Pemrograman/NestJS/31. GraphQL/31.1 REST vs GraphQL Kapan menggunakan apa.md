# 31. GraphQL
## 31.1 REST vs GraphQL Kapan menggunakan apa
**Definisi Singkat:** REST menggunakan multiple endpoint dengan struktur response tetap, sedangkan GraphQL menggunakan satu endpoint dengan query fleksibel di mana client menentukan data yang dibutuhkan.
**Analogi:** REST seperti menu set menu di restoran — Anda dapat menu tetap (fixed response) dari masing-masing meja (endpoint). GraphQL seperti prasmanan — Anda ambil sendiri makanan yang Anda inginkan (query fields) dari satu tempat (satu endpoint).
**Poin-Poin Penting:**
- REST: multiple endpoints, fixed response, over-fetching/under-fetching
- GraphQL: single endpoint, client-defined query, no over-fetching
- REST cocok untuk: simple CRUD, caching mudah, file upload
- GraphQL cocok untuk: kompleks data relations, multiple clients, rapid frontend iteration
**Contoh Kode:**
```typescript
// REST approach — multiple endpoints
// GET /api/users → { id, name, email, avatar, createdAt, updatedAt, ... }
// GET /api/users/1/posts → [{ id, title, content, ... }]
// GET /api/users/1/posts/1/comments → [{ id, text, ... }]
//
// Masalah: Frontend harus panggil 3 endpoint untuk dapat user + posts + comments
// Kelebihan: Bisa cache tiap endpoint dengan CDN

// GraphQL approach — single endpoint
// query {
//   user(id: 1) {
//     name
//     posts {
//       title
//       comments {
//         text
//       }
//     }
//   }
// }
//
// Kelebihan: Satu query dapat semua data yang dibutuhkan
// Masalah: Kompleksitas query bisa membebani server
```
```typescript
// Kapan pilih REST?
// ✅ API sederhana dengan CRUD standar
// ✅ File upload/download
// ✅ Caching agresif dengan CDN/HTTP cache
// ✅ Integrasi dengan sistem yang hanya support REST
// ✅ Microservices internal dengan komunikasi sederhana

// Kapan pilih GraphQL?
// ✅ Dashboard dengan banyak tipe data berelasi
// ✅ Mobile app — minimal transfer data
// ✅ Multiple clients (web, mobile, third-party) dengan kebutuhan data berbeda
// ✅ Rapid prototyping — frontend tentukan kebutuhan data
// ✅ API dengan relasi data kompleks
```
```typescript
// Perbandingan kode:
// REST Controller:
@Controller('users')
export class UsersController {
  @Get(':id')
  findOne(@Param('id') id: string) {
    return this.usersService.findOne(+id);
  }
}

// GraphQL Resolver:
@Resolver('User')
export class UsersResolver {
  @Query(() => User)
  user(@Args('id', { type: () => Int }) id: number) {
    return this.usersService.findOne(id);
  }

  @ResolveField()
  posts(@Parent() user: User) {
    return this.postsService.findByUserId(user.id);
  }
}
```
**Kasus Penggunaan Nyata:** Aplikasi social media. Untuk timeline (campuran posts, comments, likes, user info), GraphQL unggul karena satu query bisa mendapatkan semua data dengan struktur yang persis dibutuhkan komponen React/Vue. Untuk upload foto profil, REST tetap digunakan karena file upload lebih sederhana.
