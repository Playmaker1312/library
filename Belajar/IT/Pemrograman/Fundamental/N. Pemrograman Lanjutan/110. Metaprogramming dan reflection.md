Selamat! Anda telah mencapai puncak tertinggi dalam hierarki pemrograman: **Metaprogramming**. Jika pemrograman biasa adalah menulis kode untuk memproses data, maka Metaprogramming adalah menulis kode untuk **memproses kode itu sendiri**.

Ini adalah teknik "sihir" di balik _framework_ besar seperti **Spring (Java)**, **Hibernate**, **Prisma (Node.js)**, atau **Ruby on Rails**. Dengan teknik ini, program Anda bisa menjadi sangat cerdas hingga mampu memeriksa, memodifikasi, dan beradaptasi dengan dirinya sendiri saat sedang berjalan.

---

## 1. Apa itu Metaprogramming?

**Metaprogramming** adalah teknik di mana sebuah program memperlakukan program lain (atau dirinya sendiri) sebagai data. Ia bisa membaca, menghasilkan, menganalisis, atau mengubah kode lain, bahkan saat aplikasi sedang menyala (_runtime_).

Salah satu cabang utamanya adalah **Reflection**.

---

## 2. Reflection (Refleksi)

**"Bercermin untuk Mengenal Diri Sendiri."**

### Definisi Singkat

**Reflection** adalah kemampuan sebuah program untuk melakukan introspeksi terhadap dirinya sendiri. Program bisa bertanya:

- _"Apa saja nama fungsi yang ada di kelas ini?"_
    
- _"Variabel ini tipenya apa ya?"_
    
- _"Bisakah saya menjalankan fungsi rahasia ini meskipun namanya belum saya ketahui saat mengetik kode?"_
    

### Analogi: Detektif vs Koki

- **Pemrograman Biasa (Koki):** Anda punya resep (kode) dan bahan (data). Anda memasak sesuai instruksi yang kaku.
    
- **Reflection (Detektif):** Detektif masuk ke dapur, memeriksa label di setiap botol bumbu (metadata), mencari tahu siapa yang memasak semalam, dan mengubah isi botol garam menjadi gula tanpa harus mengganti buku resepnya.
    

---

## 3. Mengapa Kita Butuh Metaprogramming?

1. **Otomatisasi Tugas Rutin:** Bayangkan Anda punya 100 kelas database. Daripada menulis kode simpan-ambil (_CRUD_) untuk 100 kelas, Anda gunakan Metaprogramming untuk membuat fungsi simpan otomatis yang bisa membaca struktur kelas apa pun.
    
2. **Decorators & Annotations:** Menambahkan fitur hanya dengan satu baris di atas fungsi, seperti `@Auth` untuk mengecek login atau `@Log` untuk mencatat aktivitas.
    
3. **Dependency Injection:** Seperti yang kita pelajari di materi 103, _framework_ menggunakan Reflection untuk mencari tahu objek apa yang dibutuhkan sebuah kelas dan "menyuntikkannya" secara otomatis.

## 4. Contoh Implementasi (JavaScript - Proxy & Reflect)

JavaScript modern memiliki objek `Reflect` dan `Proxy` untuk melakukan sihir ini.

### Contoh Reflection (Melihat Isi Objek):

JavaScript

```
const user = { nama: "Gemini", peran: "AI" };

// Menggunakan Reflect untuk mendapatkan semua kunci/properti
console.log(Reflect.ownKeys(user)); // Output: ["nama", "peran"]
```

### Contoh Proxy (Mengubah Perilaku Kode):

Kita bisa membuat objek yang "sadar" jika ada orang yang mencoba mengakses datanya.

JavaScript

```
const sensor = { rahasia: "12345" };

const detektor = new Proxy(sensor, {
    get(target, prop) {
        console.log(`⚠️ Seseorang mencoba melihat data: ${prop}`);
        return target[prop];
    }
});

console.log(detektor.rahasia); 
// Output: 
// ⚠️ Seseorang mencoba melihat data: rahasia
// 12345
```

## 5. Bahaya Metaprogramming: "Dengan Kekuatan Besar, Datang Tanggung Jawab Besar"

Metaprogramming adalah pedang bermata dua:

- **Sulit Di-debug:** Karena kodenya bisa berubah-ubah sendiri, mencari sumber kesalahan menjadi sangat sulit.
    
- **Performa:** Proses "bercermin" (Reflection) memakan waktu lebih lama daripada menjalankan kode biasa secara langsung.
    
- **Kode Menjadi "Sakti" tapi Gelap:** Rekan setim Anda mungkin bingung kenapa tiba-tiba ada fungsi yang berjalan padahal tidak pernah dipanggil secara eksplisit (sering disebut _Magic_).
