Selamat datang di fitur yang menjadi "kekuatan super" sesungguhnya dari Git. Di materi sebelumnya, Anda belajar berjalan maju dalam satu garis waktu lurus. Namun, bagaimana jika Anda ingin bereksperimen dengan fitur baru tanpa mengambil risiko merusak kode utama yang sudah berjalan sempurna?

Di sinilah kita menciptakan **Alam Semesta Paralel**.

---

## 1. Definisi Singkat

- **Branching (Percabangan):** Proses membuat salinan mandiri dari proyek Anda saat ini. Di cabang baru ini, Anda bisa menulis kode, menghapus file, atau bereksperimen secara brutal. Apa pun yang Anda lakukan di cabang ini **tidak akan menyentuh atau merusak** cabang utama.
    
- **Merging (Penggabungan):** Proses menyatukan kembali sejarah dan kode dari satu cabang ke cabang lainnya. Biasanya, setelah eksperimen di cabang Anda berhasil dan bebas _bug_, Anda akan menggabungkannya kembali ke cabang utama.
    

## 2. Analogi: Resep Rahasia Restoran

Bayangkan Anda adalah koki utama yang memegang Buku Resep Rahasia Restoran (Ini adalah cabang **`main`**).

Suatu hari, Anda punya ide liar: _"Bagaimana kalau burger kita ditambah saus mangga pedas?"_

1. **Branching:** Anda tidak mungkin mencoret-coret Buku Resep asli (risiko restoran bangkrut jika rasanya mengerikan). Anda pergi ke mesin fotokopi, menyalin resep burger tersebut, dan menamainya "Resep Eksperimen".
    
2. **Menulis Kode:** Anda mengotak-atik "Resep Eksperimen" di dapur belakang selama berminggu-minggu. Sementara itu, koki lain tetap bisa memasak burger normal menggunakan Buku Resep asli di dapur depan tanpa gangguan.
    
3. **Merging:** Ternyata saus mangga pedas itu sangat lezat! Anda membawa "Resep Eksperimen" ke dapur depan, lalu menyalin perlahan instruksi saus tersebut ke dalam Buku Resep asli secara permanen.
    

## 3. Poin-Poin Penting (Hukum Percabangan)

- **Cabang `main` (atau `master`):** Ini adalah cabang suci. Di dunia profesional, cabang ini mencerminkan apa yang sedang dilihat oleh pelanggan (Production). Anda **haram** hukumnya menulis kode eksperimen langsung di `main`.
    
- **Cabang Fitur (Feature Branch):** Setiap kali Anda mendapat tugas baru (Misal: "Buat halaman keranjang belanja"), Anda wajib membuat cabang baru dari `main` (misal dinamai `fitur-keranjang`), mengerjakannya di sana, dan baru menggabungkannya saat sudah selesai.
    
- **Merge Conflict (Tabrakan Penggabungan):** Ini adalah mimpi buruk setiap _programmer_. Terjadi ketika Anda dan rekan kerja Anda mengedit **file yang sama, di baris yang sama persis**, di cabang yang berbeda. Saat Anda mencoba menggabungkannya (`merge`), Git akan panik dan berhenti. Git akan meminta Anda sebagai manusia untuk menengahi dan memilih secara manual baris mana yang ingin dipertahankan.
    

## 4. Contoh Implementasi (Terminal)

Mari kita praktikkan cara membuat cabang, berpindah dimensi, dan menggabungkannya kembali menggunakan Terminal:

Bash

```
# 1. Mengecek kita sedang berada di cabang mana (Biasanya muncul * main)
git branch

# 2. MEMBUAT CABANG BARU bernama 'fitur-login'
git branch fitur-login

# 3. BERPINDAH ke cabang tersebut (Pindah dimensi!)
git checkout fitur-login
# Output: Switched to branch 'fitur-login'
# (Mulai dari Node.js / Git versi baru, Anda juga bisa menggunakan: git switch fitur-login)

# --- DI DIMENSI INI KITA BEBAS BEREKSPERIMEN ---
# Katakanlah Anda membuat file login.html, lalu melakukan add dan commit
git add .
git commit -m "Menyelesaikan desain halaman login"

# 4. KEMBALI KE DUNIA NYATA (Cabang Utama)
git checkout main
# Output: Switched to branch 'main'
# AJAIB: Jika Anda melihat folder Anda, file login.html tiba-tiba MENGHILANG! 
# Jangan panik, file itu aman di dimensi 'fitur-login'.

# 5. MENGGABUNGKAN CABANG (Merging)
# Kita berada di 'main', dan kita ingin menarik hasil kerja dari 'fitur-login' ke sini
git merge fitur-login
# Output: Updating a1b2c3d..e4f5g6h, Fast-forward...

# Sekarang file login.html sudah muncul kembali dan resmi menjadi bagian dari cabang utama!
```

## 5. Koneksi dengan Web Development

Pemahaman _Branching_ dan _Merging_ adalah tiket masuk Anda untuk bekerja di perusahaan teknologi modern:

1. **Kerja Tim Paralel:** Di perusahaan seperti Traveloka, ada 50 _developer_ yang bekerja bersamaan. _Developer_ A membuat `cabang-pembayaran`, _Developer_ B membuat `cabang-profil`, dan _Developer_ C membuat `cabang-promo`. Ketiganya mengedit aplikasi yang sama di laptop masing-masing tanpa pernah saling menimpa kode satu sama lain.
    
2. **Pull Request (GitHub/GitLab):** Saat Anda bekerja di industri, Anda jarang melakukan `git merge` secara langsung di terminal lokal Anda. Anda akan mendorong (_push_) cabang Anda ke internet (GitHub), lalu membuat dokumen penawaran bernama **Pull Request (PR)**. _Senior Developer_ akan membaca kode di cabang Anda. Jika kode Anda dinilai bagus, rapi, dan tidak mengandung _bug_, barulah _Senior_ tersebut menekan tombol hijau "Merge" di _website_ GitHub.
    
3. **Hotfix (Perbaikan Darurat):** Jika _website_ utama tiba-tiba _down_ karena ada _bug_ kritis, _developer_ langsung membuat cabang `hotfix` dari `main`, memperbaiki kodenya dalam 5 menit, dan langsung menggabungkannya kembali tanpa harus menunggu fitur lain yang belum selesai.
