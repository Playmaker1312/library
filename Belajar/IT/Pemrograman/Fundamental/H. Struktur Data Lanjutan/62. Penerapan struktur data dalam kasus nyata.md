## 1. Hash Table: Mesin Pencari dan Sistem _Cache_

Setiap kali Anda membutuhkan kecepatan pencarian yang instan ($O(1)$), _Hash Table_ adalah rajanya.

- **Sistem Caching (Redis/Memcached):** Ketika jutaan orang membuka halaman utama Tokopedia saat "Flash Sale", mengambil daftar barang dari _database_ SQL yang lambat akan membuat _server crash_. _Backend Developer_ menyimpan daftar barang tersebut di dalam RAM menggunakan _Hash Table_ (lewat teknologi seperti Redis). Hasilnya? Halaman web terbuka dalam hitungan milidetik.
    
- **Resolusi DNS (Domain Name System):** Saat Anda mengetik `google.com` di _browser_, komputer harus menerjemahkan nama itu menjadi deretan angka IP Address (misal: `142.250.190.46`). Server DNS dunia menggunakan _Hash Table_ raksasa untuk memetakan miliaran nama _domain_ ke IP Address secara instan.
    

## 2. Stack & Queue: Manajemen Antrean dan Riwayat

Struktur data linier yang mengatur urutan masuk dan keluar ini sangat krusial untuk menjaga ketertiban proses di dalam komputer.

- **Stack (LIFO - Last In, First Out):**
    
    - **Fitur Undo/Redo:** Setiap kali Anda mengetik di Microsoft Word atau VS Code, setiap aksi Anda ditumpuk di dalam _Stack_. Saat Anda menekan `Ctrl + Z`, program cukup mengambil tindakan terakhir dari pucuk tumpukan dan membatalkannya.
        
    - **Call Stack Browser:** Mesin JavaScript di _browser_ Anda menggunakan _Stack_ untuk melacak fungsi mana yang sedang dijalankan saat ini. Jika _Stack_ ini kepenuhan (misalnya karena _infinite loop_ rekursif), _browser_ akan memunculkan _error_ "Stack Overflow".
        
- **Queue (FIFO - First In, First Out):**
    
    - **Sistem Ticketing Konser:** Saat jutaan orang berebut tiket konser Coldplay, _server_ menggunakan _Priority Queue_ atau _Message Broker_ (seperti RabbitMQ atau Kafka) untuk membariskan _request_ pembelian secara adil. Siapa yang klik duluan, dia yang diproses duluan.
        
    - **Printer Spooler:** Jika Anda mengirim 5 dokumen berbeda ke mesin _printer_ di kantor, dokumen tersebut masuk ke dalam _Queue_ dan dicetak berurutan.
        

## 3. Tree: Mesin Pencari Kata dan Struktur Dokumen

Hierarki adalah cara paling alami untuk menyimpan data yang memiliki relasi induk-anak atau untuk mempersempit ruang pencarian.

- **Trie (Prefix Tree) untuk Autocomplete:** Pernahkah Anda mengetik "Cara membuat..." di Google, dan seketika muncul saran "Cara membuat kue", "Cara membuat kopi"? Google menggunakan struktur _Tree_ khusus bernama **Trie**. Setiap huruf yang Anda ketik akan menelusuri cabang pohon tersebut untuk menemukan kata yang paling sering dicari di daun bawahnya.
    
- **B-Tree untuk Database Indexing:** _Database_ relasional (seperti MySQL atau PostgreSQL) tidak menggunakan _Array_ untuk menyimpan data pengguna. Mereka menggunakan _B-Tree_ (variasi dari _Binary Search Tree_ yang lebih seimbang) agar pencarian data dari 10 juta baris tabel hanya butuh 3-4 kali langkah pemotongan.
    
- **DOM (Document Object Model):** Seluruh elemen HTML di layar Anda saat ini (`<div>`, `<p>`, `<img>`) disusun oleh _browser_ dalam bentuk pohon raksasa agar JavaScript bisa menargetkan dan mengubah warnanya secara spesifik.
    

## 4. Graph: Navigasi, Logistik, dan Jaringan Sosial

Jika datanya berupa jaringan yang saling terhubung tanpa ujung, _Graph_ adalah satu-satunya jawaban.

- **Google Maps & Gojek (Shortest Path):** Setiap persimpangan jalan adalah _Node_ (titik), dan jalan raya adalah _Edge_ (garis penghubung). Algoritma penelusuran graf (seperti Dijkstra atau A*) beroperasi di atas peta ini untuk menghitung rute paling optimal, menghindari macet, dan menghemat bensin.
    
- **Rekomendasi Teman di Media Sosial:** Facebook dan LinkedIn menggunakan _Adjacency List_ raksasa. Jika Anda (A) berteman dengan Budi (B), dan Budi berteman dengan Citra (C), algoritma _Graph_ akan mendeteksi relasi ini dan memunculkan Citra di kolom "Mungkin Anda Kenal".
    
- **Sistem Rekomendasi E-Commerce:** Amazon dan Shopee menggunakan jaringan _Bipartite Graph_. Jika _User A_ membeli "Laptop" dan "Mouse", dan _User B_ membeli "Laptop", sistem akan berjalan di atas garis _Graph_ tersebut untuk merekomendasikan "Mouse" kepada _User B_.
