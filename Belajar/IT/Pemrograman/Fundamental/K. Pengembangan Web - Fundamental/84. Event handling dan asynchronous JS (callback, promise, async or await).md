Selamat! Di materi sebelumnya, Anda sudah tahu cara JavaScript menjadi "Dalang" yang bisa mengubah susunan panggung HTML sesuka hati (Manipulasi DOM). Namun, pertunjukan wayang yang baik tidak berjalan sendiri—ia harus merespons tepuk tangan atau teriakan penonton.

Bagaimana caranya agar JavaScript hanya bergerak **ketika pengguna mengeklik tombol**? Dan bagaimana jika tindakan tersebut membutuhkan waktu lama (seperti mengunduh data dari _server_) tanpa membuat _browser_ membeku?

Mari kita kuasai dua konsep penyokong interaktivitas modern: **Event Handling** dan **Asynchronous JavaScript**.

---

## 1. Definisi Singkat

- **Event Handling:** Kemampuan JavaScript untuk "mendengarkan" kejadian (kejadian = _event_) yang dilakukan pengguna di halaman web, seperti mengeklik (_click_), mengetik (_keyup_), atau menggulir layar (_scroll_), lalu mengeksekusi sebuah fungsi sebagai responsnya.
    
- **Asynchronous JavaScript (Asinkron):** Kemampuan JavaScript untuk mendelegasikan tugas berat (yang memakan waktu) ke latar belakang, sehingga tugas-tugas ringan lainnya bisa terus berjalan tanpa harus menunggu tugas berat tersebut selesai.
    
- **Callback, Promise, Async/Await:** Ini adalah tiga fase evolusi (dari yang paling kuno hingga paling modern) tentang cara _programmer_ menulis kode asinkron.
    

## 2. Analogi: Restoran Cepat Saji yang Sibuk

**A. Event Handling (Resepsionis):** Bayangkan sebuah tombol di _website_ adalah lonceng di meja resepsionis. `addEventListener` adalah resepsionis yang telinganya selalu siaga. Lonceng itu bisa diam berjam-jam, tetapi begitu Anda memukulnya (_click_), resepsionis langsung bertindak menyapa Anda.

**B. Asynchronous (Sistem Antrean Makanan):** Anda memesan 100 potong ayam goreng ayam (Tugas Berat / Meminta data ke _Server_).

- **Synchronous (Sistem Kaku):** Kasir melayani Anda, lalu diam mematung menatap dapur selama 30 menit sampai ayam Anda matang. Puluhan pelanggan di belakang Anda marah-marah karena antrean macet total. Ini yang terjadi jika _website_ membeku (_freeze_).
    
- **Asynchronous (Sistem Modern):** Kasir menerima pesanan Anda, memberikan **Nomor Antrean (Promise)**, dan menyuruh Anda duduk. Kasir langsung melayani pelanggan berikutnya. Saat ayam Anda matang 30 menit kemudian, kasir memanggil nomor Anda melalui pengeras suara **(Callback/Await)**. Antrean berjalan lancar, semua orang senang!
    

## 3. Poin-Poin Penting

- **`addEventListener`:** Mantra utama untuk mengikat sebuah kejadian (_event_) pada elemen HTML tertentu.
    
- **Callback Hell (Piramida Kiamat):** Cara kuno menangani proses asinkron. Jika Anda punya 5 tugas yang saling bergantung berurutan, kodenya akan menjorok ke kanan membentuk piramida. Sangat sulit dibaca dan dirawat.
    
- **Promise (Janji):** Objek modern yang mewakili hasil dari operasi asinkron. Ia punya 3 status: _Pending_ (Menunggu), _Fulfilled_ (Berhasil/Ditepati), dan _Rejected_ (Gagal/Diingkari). Kita menangkap hasilnya pakai `.then()` dan `.catch()`.
    
- **Async / Await (Sihir Modern):** Sintaks terbaru (ES8) yang membuat kode asinkron (yang berantakan) terlihat dan dibaca persis seperti kode sinkron biasa dari atas ke bawah. Ini adalah standar industri wajib saat ini.
    

## 4. Contoh Implementasi: Sinergi Event & Async

Mari kita gabungkan kedua konsep ini. Kita akan membuat sebuah tombol yang, jika diklik (_Event_), akan berpura-pura mengambil data pengguna dari _server_ selama 2 detik (_Async_).

Kita akan menggunakan gaya penulisan paling modern: **Async / Await**.

HTML

```
<button id="tombol-unduh">Unduh Data Pengguna</button>
<p id="status-teks">Belum ada tindakan...</p>
```

JavaScript

```
// 1. Menangkap Wayang (DOM)
const tombol = document.getElementById('tombol-unduh');
const statusTeks = document.getElementById('status-teks');

// 2. Fungsi Asinkron (Simulasi Meminta Data ke Server)
// Kata kunci 'async' menandakan fungsi ini berisi tugas yang butuh waktu
async function ambilDataServer() {
    try {
        // Tampilkan pesan loading di layar
        statusTeks.textContent = "Sedang mengambil data dari server...";
        
        // --- PROMISE ---
        // Kita menggunakan Promise dan setTimeout untuk berpura-pura 
        // menunggu balasan server selama 2 detik.
        const janjiServer = new Promise((resolve, reject) => {
            setTimeout(() => {
                // Setelah 2 detik, kembalikan data ini (Berhasil/Resolved)
                resolve("✅ Data Budi, Umur 25 tahun berhasil diambil!");
                
                // (Jika server error, kita akan pakai reject("Server Mati!"))
            }, 2000); 
        });

        // --- AWAIT ---
        // Sihir terjadi di sini! JavaScript akan "berhenti sejenak" di baris ini 
        // (tanpa membuat browser freeze) sampai janjiServer ditepati.
        const hasilData = await janjiServer; 

        // Jika sudah ditepati, tampilkan datanya ke layar pengguna
        statusTeks.textContent = hasilData;

    } catch (error) {
        // Jika janji diingkari (Rejected/Error), tangkap dan tampilkan merah
        statusTeks.textContent = "❌ Gagal: " + error;
        statusTeks.style.color = "red";
    }
}

// 3. EVENT HANDLING (Resepsionis)
// "Hei Tombol, jika kamu di-'click', jalankan fungsi ambilDataServer!"
tombol.addEventListener('click', ambilDataServer);
```

## 5. Koneksi dengan Web Development

Dua konsep ini adalah urat nadi dari apa yang kita sebut **Aplikasi Web Interaktif (Web App)**:

1. **Fetch API (Komunikasi Client-Server):** Di dunia kerja, Anda tidak menggunakan `setTimeout` untuk menunggu. Anda akan menggunakan fungsi bawaan `fetch()` bersama `async/await` untuk memanggil URL API (misal: mengambil daftar film dari server Netflix). Fungsi `fetch()` selalu mengembalikan _Promise_ karena internet tidak bisa diprediksi kecepatannya.
    
2. **Validasi Formulir Instan (Event `keyup`):** Saat Anda mendaftar akun dan mengetik _password_, _website_ langsung memberi warna hijau atau merah di bawah kotak teks sebelum Anda mengeklik tombol _Submit_. Itu karena _programmer_ memasang _event listener_ pada _keyboard_ Anda yang bereaksi pada setiap ketikan huruf.
    
3. **Pengalaman Pengguna (Loading State):** Saat pengguna menekan "Bayar", proses verifikasi bank butuh waktu 5 detik (_Async_). Selama masa tunggu itu, Anda menggunakan _Event_ untuk mengubah tombol "Bayar" menjadi roda berputar (_loading spinner_) dan menonaktifkannya (`disabled`). Jika tidak, pengguna yang tidak sabaran mungkin mengeklik "Bayar" 3 kali, dan uang mereka terpotong 3 kali!
    

Dengan menguasai DOM Manipulation, Event Handling, dan Asynchronous JS, Anda kini telah menamatkan dasar-dasar kekuatan sisi _Client_ (Frontend).
