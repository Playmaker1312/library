Service Worker

Penjelasan

Service Worker adalah file JavaScript yang berjalan di background, terpisah dari halaman web. Ia bertindak sebagai proxy antara browser dan jaringan. Service Worker bisa mencegat (intercept) request jaringan, menyimpan respons ke cache, dan menyajikannya kembali — bahkan saat perangkat sedang offline. Service Worker tidak punya akses ke DOM, tapi bisa mengontrol halaman melalui event fetch, install, dan activate.

Fungsi

  • Menyimpan file website ke cache saat pertama dikunjungi
  • Melayani halaman dari cache saat offline (Cache First strategy)
  • Mempercepat loading dengan mengambil dari cache lokal
  • Memungkinkan notifikasi push (push notification)
  • Sinkronisasi data di latar belakang (background sync)

Cara Pengimplementasian

Daftarkan Service Worker dari file HTML utama:

<script>
  if ('serviceWorker' in navigator) {
    navigator.serviceWorker.register('sw.js')
      .then(function(registration) {
        console.log('Service Worker terdaftar:', registration.scope);
      })
      .catch(function(error) {
        console.log('Pendaftaran gagal:', error);
      });
  }
</script>

File sw.js — strategi Cache First:

const CACHE_NAME = 'portfolio-v1';
const ASSETS = [
  '/',
  '/index.html',
  '/style.css',
  '/script.js',
  '/icon-192x192.png'
];

self.addEventListener('install', function(event) {
  event.waitUntil(
    caches.open(CACHE_NAME).then(function(cache) {
      return cache.addAll(ASSETS);
    })
  );
});

self.addEventListener('fetch', function(event) {
  event.respondWith(
    caches.match(event.request).then(function(response) {
      return response || fetch(event.request);
    })
  );
});

Analogi (Rumah / Bangunan)

Service Worker itu seperti satpam dan gudang rumah. Saat rumah pertama kali dibangun (install), satpam menyimpan salinan semua barang penting (file HTML, CSS, JS) ke gudang (cache). Setiap kali ada tamu yang minta sesuatu (fetch), satpam cek gudang dulu — kalau ada, langsung kasih tanpa harus beli ke toko (jaringan). Kalau listrik padam (offline), tamu tetap bisa dapat barang dari gudang. Ini membuat rumah selalu bisa melayani tamu kapan saja.

Dipakai Untuk

  • Website portofolio agar bisa diakses offline
  • Aplikasi berita yang tetap bisa dibaca tanpa koneksi
  • E-commerce dengan loading cepat dari cache
  • Semua PWA yang membutuhkan mode offline

Kesalahan Umum

  • Service Worker hanya bekerja di localhost atau HTTPS — tidak akan jalan di HTTP biasa
  • Lupa menambahkan event.waitUntil() di install, sehingga cache belum selesai saat fetch terjadi
  • Tidak menangani versi cache — saat update file, pengguna masih mendapat versi lama karena cache tidak diganti
  • Path file di ASSETS salah, menyebabkan cache kosong dan halaman error
  • Menempatkan Service Worker di subfolder yang tidak bisa mengontrol root domain

Koneksi dengan Materi Sebelumnya

Service Worker bekerja bersama Web App Manifest (materi 71) — manifest untuk tampilan, Service Worker untuk offline. Keduanya diperlukan agar website bisa di-install sebagai PWA. Service Worker juga menjadi salah satu item yang diperiksa oleh Lighthouse (materi 73) pada kategori PWA.

Soal Latihan

  1. Apa perbedaan antara event install dan event fetch di Service Worker?

    Lihat Jawaban

    Event install terjadi saat Service Worker pertama kali didaftarkan/diupdate — digunakan untuk menyiapkan cache (menyimpan aset). Event fetch terjadi setiap kali browser melakukan request ke server — digunakan untuk mencegat request dan menentukan apakah akan mengambil dari cache atau dari jaringan.

  2. Mengapa Service Worker hanya bisa berjalan di lingkungan HTTPS atau localhost?

    Lihat Jawaban

    Karena Service Worker memiliki kemampuan mencegat dan memodifikasi request jaringan, ini adalah kekuatan besar yang bisa disalahgunakan. HTTPS memastikan komunikasi aman dan mencegah man-in-the-middle attack di mana pihak ketiga menyuntikkan Service Worker berbahaya.

  3. Jelaskan strategi Cache First yang digunakan dalam contoh di atas!

    Lihat Jawaban

    Cache First berarti setiap kali ada request, Service Worker pertama-tama mencari file yang diminta di dalam cache. Jika ditemukan, file dari cache langsung dikembalikan (sangat cepat). Jika tidak ditemukan di cache, barulah request diteruskan ke jaringan (fetch(event.request)). Strategi ini membuat halaman bisa diakses offline setelah pertama kali dimuat.
