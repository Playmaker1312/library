Deploy Website

Penjelasan

Deploy adalah proses mengupload file website agar bisa diakses publik melalui internet. Website statis (HTML, CSS, JS) bisa di-deploy secara gratis menggunakan GitHub Pages, Netlify, atau Vercel. GitHub Pages adalah pilihan utama karena terintegrasi langsung dengan repository GitHub — setiap push ke branch main otomatis memicu deploy.

Fungsi

  • Membuat website bisa diakses oleh siapa saja, 24/7
  • Memberikan URL publik untuk portofolio atau klien
  • Otomatisasi deploy — cukup push ke GitHub, website langsung update
  • Menyediakan hosting gratis dengan domain .github.io
  • Dukungan custom domain (opsional) — bisa pakai domain sendiri

Cara Pengimplementasian

GitHub Pages

  1. Buat repository di GitHub (contoh: portfolio).
  2. Push semua file website ke repository.
  3. Buka repository → Settings → Pages.
  4. Di Branch, pilih main dan folder / (root).
  5. Klik Save. Tunggu beberapa menit.
  6. Website live di: https://username.github.io/portfolio
# Init git dan push ke GitHub
git init
git add .
git commit -m "Deploy website"
git branch -M main
git remote add origin https://github.com/username/portfolio.git
git push -u origin main

Netlify Drop

  1. Buka app.netlify.com/drop.
  2. Seret folder project ke browser.
  3. Website langsung live dengan URL acak .netlify.app.

Analogi (Rumah / Bangunan)

Deploy itu seperti meresmikan rumah dan mengumumkan alamatnya ke publik. GitHub Pages adalah tanah kavling gratis yang diberikan pemerintah — kamu tinggal bangun rumah (push file) dan pasang plakat alamat (Settings → Pages). Netlify Drop seperti rumah pameran yang langsung jadi — tinggal seret furnitur (folder website) dan rumah langsung bisa ditinggali. Custom domain adalah seperti membeli nama jalan sendiri daripada pakai alamat standar. Setelah deploy, semua orang bisa datang berkunjung ke rumah digitalmu.

Dipakai Untuk

  • Mempublikasikan website portofolio ke publik
  • Menunjukkan hasil kerja ke klien atau recruiter
  • Testing website di lingkungan production sebelum rilis resmi
  • Proyek open source — dokumentasi langsung bisa diakses

Kesalahan Umum

  • File index.html tidak ada di root folder — GitHub Pages tidak tahu halaman mana yang dibuka
  • Path file menggunakan absolute alih-alih relative — gambar/stylesheet tidak muncul karena URL berubah
  • Push ke branch selain main tanpa mengatur branch di Settings Pages
  • Lupa commit file terbaru sebelum push — website tidak update
  • Belum menambahkan nojekyll jika ada folder yang diawali underscore — GitHub Pages menggunakan Jekyll secara default

Koneksi dengan Materi Sebelumnya

Deploy adalah tahap akhir setelah semua materi selesai. Sebelum deploy, pastikan website sudah lulus Validasi W3C (materi 74) dan Audit Lighthouse (materi 73) dengan target skor ≥ 90. Pastikan juga manifest.json (materi 71) dan Service Worker (materi 72) sudah terpasang dengan benar. Setelah deploy, hasil audit Lighthouse dan link ke repository akan dicantumkan di README.md (materi 76).

Soal Latihan

  1. Sebutkan langkah-langkah untuk mendeploy website ke GitHub Pages!

    Lihat Jawaban

    (1) Buat repository di GitHub. (2) Push file website ke repository (branch main). (3) Buka Settings → Pages → pilih branch main dan folder root. (4) Klik Save. (5) Website akan live di https://username.github.io/nama-repo dalam beberapa menit.

  2. Apa yang terjadi jika file index.html tidak ada di dalam repository saat di-deploy ke GitHub Pages?

    Lihat Jawaban

    GitHub Pages akan menampilkan halaman 404 atau daftar file (directory listing) karena tidak menemukan file index.html sebagai halaman utama. Website tidak akan berfungsi dengan benar.

  3. Sebutkan dua alternatif hosting gratis selain GitHub Pages untuk website statis!

    Lihat Jawaban

    Dua alternatif: (1) Netlify — dengan Netlify Drop, cukup drag-and-drop folder project. (2) Vercel — terintegrasi dengan GitHub dan otomatis deploy setiap push.
