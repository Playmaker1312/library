Dokumentasi Project README

Penjelasan

README.md adalah file dokumentasi utama di repository GitHub. File ini ditulis dalam format Markdown (.md) dan akan ditampilkan secara otomatis di halaman depan repository. README yang baik menjelaskan apa itu project, fitur apa saja yang ada, teknologi yang digunakan, cara menjalankan, serta bukti kualitas seperti screenshot dan skor Lighthouse.

Fungsi

  • Memberikan gambaran cepat tentang project kepada pengunjung repository
  • Menunjukkan profesionalisme — recruiter dan klien akan melihat README pertama kali
  • Memudahkan kontributor lain memahami cara menjalankan project
  • Menyediakan tautan langsung ke demo website yang sudah di-deploy
  • Menampilkan bukti kualitas seperti sertifikat Lighthouse dan validasi W3C

Cara Pengimplementasian

Buat file README.md di root repository. Contoh struktur README:

# Portfolio Saya

![Lighthouse Score](./screenshots/lighthouse.png)

**Demo:** [https://username.github.io/portfolio](https://username.github.io/portfolio)

## Fitur
- Tampilan responsif (mobile, tablet, desktop)
- Mode gelap/terang
- PWA — bisa di-install di HP
- Akses offline via Service Worker

## Teknologi
- HTML5, CSS3, JavaScript (Vanilla)
- Web App Manifest
- Service Worker
- GitHub Pages (deploy)

## Screenshot
![Tampilan Desktop](./screenshots/desktop.png)
![Tampilan Mobile](./screenshots/mobile.png)

## Lighthouse Score
| Kategori | Skor |
|----------|------|
| Performance | 95 |
| Accessibility | 92 |
| Best Practices | 100 |
| SEO | 90 |
| PWA | ✅ Lulus |

## Cara Menjalankan
1. Clone repo: `git clone https://github.com/username/portfolio.git`
2. Buka `index.html` di browser.

## Validasi W3C
✅ HTML valid — 0 error, 0 warning.

Analogi (Rumah / Bangunan)

README.md itu seperti papan informasi di depan rumah. Saat orang datang ke rumahmu (repository), mereka akan melihat papan ini dulu. Isinya: nama rumah (judul project), foto rumah (screenshot), denah dan spesifikasi (teknologi yang dipakai), sertifikat kelayakan (Lighthouse score), nomor telepon yang bisa dihubungi (link demo), dan jam berkunjung (cara menjalankan). README yang rapi dan lengkap membuat tamu merasa rumahmu terawat dan profesional.

Dipakai Untuk

  • Repository GitHub — sebagai halaman depan project
  • Portofolio — menjelaskan project ke recruiter
  • Project open source — menarik kontributor baru
  • Dokumentasi internal tim

Kesalahan Umum

  • README kosong atau hanya berisi nama repository
  • Tidak menyertakan link demo — pembaca tidak bisa melihat hasil langsung
  • Gambar screenshot tidak muncul karena path salah atau belum di-commit
  • Typo atau Markdown yang tidak terformat dengan benar
  • Terlalu panjang atau terlalu pendek — tidak memberikan informasi yang cukup

Koneksi dengan Materi Sebelumnya

README.md adalah dokumentasi akhir yang merangkum seluruh proyek. Ia berisi link ke website yang sudah di-deploy (materi 75), screenshot hasil Lighthouse (materi 73), status validasi W3C (materi 74), serta menyebutkan fitur manifest (materi 71) dan Service Worker (materi 72) yang digunakan. README yang baik membuktikan bahwa semua materi sebelumnya telah dikuasai.

Soal Latihan

  1. Apa saja informasi minimal yang harus ada dalam sebuah README project portofolio?

    Lihat Jawaban

    Informasi minimal: (1) Judul dan deskripsi project, (2) Link demo website, (3) Fitur-fitur utama, (4) Teknologi yang digunakan, (5) Screenshot atau GIF demo, (6) Cara menjalankan project secara lokal.

  2. Mengapa penting untuk menyertakan skor Lighthouse di dalam README?

    Lihat Jawaban

    Karena skor Lighthouse adalah bukti kuantitatif bahwa website memiliki performa, aksesibilitas, dan praktik terbaik yang baik. Ini menunjukkan profesionalisme dan memberi kepercayaan kepada recruiter atau klien bahwa website tidak hanya tampil cantik tapi juga berkualitas dari segi teknis.

  3. Apa ekstensi file README yang digunakan di GitHub dan bahasa markup apa yang digunakan?

    Lihat Jawaban

    Ekstensi file .md (README.md) dan menggunakan bahasa markup Markdown. Markdown menggunakan sintaks sederhana seperti # untuk heading, **tebal** untuk bold, dan ![alt](url) untuk gambar.
