Audit Akhir Lighthouse

Penjelasan

Lighthouse adalah alat otomatis dari Google Chrome yang mengaudit kualitas website. Lighthouse memberikan skor untuk lima kategori: Performance, Accessibility, Best Practices, SEO, dan PWA (Progressive Web App). Target akhir dari proyek ini adalah mencapai skor ≥ 90 untuk Performance, Accessibility, Best Practices, dan SEO, serta lulus semua cek PWA.

Fungsi

  • Mengukur kecepatan loading website (Performance)
  • Memeriksa kemudahan akses bagi penyandang disabilitas (Accessibility)
  • Memastikan kode mengikuti standar web modern (Best Practices)
  • Memvalidasi optimasi mesin pencari (SEO)
  • Memeriksa kelengkapan fitur PWA (manifest, Service Worker, HTTPS)
  • Memberikan rekomendasi perbaikan yang spesifik dan terperinci

Cara Pengimplementasian

  1. Buka Chrome, buka halaman website yang akan diaudit.
  2. Klik kanan → Inspect (atau F12).
  3. Pilih tab Lighthouse.
  4. Pilih mode: Navigation (untuk halaman biasa).
  5. Centang semua kategori: Performance, Accessibility, Best Practices, SEO, PWA.
  6. Pilih perangkat: Mobile atau Desktop.
  7. Klik Generate report.

Audit juga bisa dijalankan via terminal:

npx lighthouse https://namasite.web.app --view --preset=desktop

Analogi (Rumah / Bangunan)

Lighthouse itu seperti tim inspektur bangunan. Performance memeriksa seberapa cepat tukang kerja (kecepatan loading). Accessibility memeriksa apakah rumah punya ramp untuk kursi roda (tag alt, kontras warna). Best Practices mengecek apakah kabel listrik terpasang sesuai standar (kode modern, tidak pakai API deprecated). SEO memeriksa apakah alamat rumah mudah ditemukan di Google Maps (title tag, meta description). PWA memeriksa apakah rumah bisa berfungsi saat lampu padam (offline via Service Worker) dan punya papan nama jelas (manifest). Target skor ≥ 90 berarti rumah harus lulus inspeksi dengan nilai A di semua kategori.

Dipakai Untuk

  • Quality assurance sebelum website diluncurkan
  • Memastikan website ramah di perangkat mobile
  • Meningkatkan peringkat SEO Google (Core Web Vitals)
  • Validasi kelengkapan PWA sebelum deploy
  • Dokumentasi skor untuk klien atau portofolio

Kesalahan Umum

  • Hanya mengecek satu kali — skor bisa berbeda setiap audit karena kondisi jaringan
  • Mengabaikan rekomendasi Lighthouse — skor hanya naik jika issue diperbaiki, bukan hanya dibaca
  • Tidak mengaudit di mode Mobile — banyak masalah responsivitas yang terlewat
  • Skor PWA gagal karena tidak ada manifest atau Service Worker yang tidak aktif
  • Optimasi berlebihan yang merusak UX (misal menghapus gambar penting demi speed)

Koneksi dengan Materi Sebelumnya

Audit Lighthouse adalah puncak evaluasi dari semua materi sebelumnya. Materi Web App Manifest (71) dan Service Worker (72) akan diuji di kategori PWA. Semua praktik terbaik HTML dari seluruh level akan diuji di kategori Best Practices dan SEO. Hasil audit ini akan dicantumkan di README.md (materi 76) sebagai bukti kualitas website.

Soal Latihan

  1. Sebutkan lima kategori yang diaudit oleh Lighthouse!

    Lihat Jawaban

    Lima kategori Lighthouse: Performance (kecepatan), Accessibility (aksesibilitas), Best Practices (praktik terbaik), SEO (optimasi mesin pencari), dan PWA (Progressive Web App).

  2. Apa target skor minimum yang harus dicapai untuk setiap kategori dalam proyek ini?

    Lihat Jawaban

    Target skor minimum: Performance ≥ 90, Accessibility ≥ 90, Best Practices ≥ 90, SEO ≥ 90, dan PWA harus lulus (passed) semua cek.

  3. Bagaimana cara menjalankan audit Lighthouse selain melalui tab Lighthouse di Chrome DevTools?

    Lihat Jawaban

    Bisa melalui terminal dengan perintah npx lighthouse <URL> --view. Juga bisa via PageSpeed Insights, atau menggunakan Lighthouse CI untuk otomatisasi.
