Validasi HTML W3C

Penjelasan

Validasi HTML W3C adalah proses memeriksa apakah kode HTML kita mengikuti standar resmi yang ditetapkan oleh World Wide Web Consortium (W3C). Alat validasi resmi ada di validator.w3.org. Validator akan memindai kode dan melaporkan error (kesalahan yang harus diperbaiki) dan warning (peringatan, tidak wajib). Target kita adalah nol error.

Fungsi

  • Memastikan HTML ditulis sesuai standar internasional W3C
  • Menghindari bug lintas browser akibat kode yang tidak standar
  • Meningkatkan aksesibilitas untuk pengguna screen reader
  • Membantu SEO — mesin pencari lebih mudah memahami HTML yang valid
  • Mempermudah debugging dan pemeliharaan kode di masa depan

Cara Pengimplementasian

  1. Buka validator.w3.org.
  2. Pilih salah satu metode:
    • Validate by URI — masukkan URL website yang sudah di-deploy
    • Validate by File Upload — upload file .html
    • Validate by Direct Input — copy-paste kode HTML
  3. Klik Check dan tunggu hasilnya.
  4. Perbaiki semua error yang muncul (merah), lalu validasi ulang hingga nol error.

Contoh error umum dan perbaikannya:

<!-- ERROR: Tag <img> tanpa atribut alt -->
<img src="foto.jpg">
<!-- PERBAIKAN: -->
<img src="foto.jpg" alt="Deskripsi foto">

<!-- ERROR: Heading melompat dari h1 ke h3 -->
<h1>Judul</h1>
<h3>Subjudul</h3>
<!-- PERBAIKAN: -->
<h1>Judul</h1>
<h2>Subjudul</h2>

Analogi (Rumah / Bangunan)

Validasi W3C itu seperti sertifikasi layak huni dari dinas bangunan. Petugas memeriksa apakah fondasi sesuai aturan (DOCTYPE benar), apakah setiap ruangan punya jendela (alt text di gambar), apakah pintu tidak melompati anak tangga (heading tidak skip), dan apakah kabel listrik tidak pakai model lama (atribut deprecated). Website dengan HTML valid adalah rumah yang sudah lulus inspeksi dan aman dihuni — browser mana pun bisa "tinggal" di dalamnya tanpa masalah.

Dipakai Untuk

  • Validasi akhir sebelum website di-deploy ke publik
  • Memastikan kode HTML aman digunakan di semua browser modern
  • Meningkatkan skor Best Practices dan SEO di Lighthouse
  • Proyek akademik yang memerlukan HTML valid sebagai syarat penilaian

Kesalahan Umum

  • Heading tidak berurutan — misal dari <h1> langsung ke <h4>
  • Tag <img> tanpa atribut alt
  • Nesting salah — misal <ul><li><div>...</li></ul> padahal <div> tidak boleh langsung di dalam <ul>
  • Atribut deprecated — seperti align, bgcolor, font — gunakan CSS
  • Duplikasi ID — dua elemen dengan id yang sama dalam satu halaman

Koneksi dengan Materi Sebelumnya

Validasi W3C berhubungan erat dengan audit Lighthouse (materi 73) karena Lighthouse akan memeriksa Best Practices — salah satunya adalah validitas HTML. Halaman yang tidak valid akan kehilangan skor di kategori tersebut. Juga terkait dengan SEO — HTML yang valid lebih mudah diindeks Google. Proyek Portfolio harus lulus validasi W3C sebelum di-deploy ke GitHub Pages (materi 75).

Soal Latihan

  1. Apa perbedaan antara error dan warning di validator W3C?

    Lihat Jawaban

    Error adalah kesalahan yang melanggar spesifikasi HTML dan harus diperbaiki — bisa menyebabkan halaman tampil salah di browser. Warning adalah peringatan tentang praktik yang kurang optimal tetapi tidak melanggar spesifikasi — tidak wajib diperbaiki, namun sebaiknya diperhatikan.

  2. Sebutkan tiga error HTML umum yang sering muncul di validator W3C!

    Lihat Jawaban

    Tiga error umum: (1) Tag <img> tanpa atribut alt, (2) Heading yang tidak berurutan (skip dari h1 ke h3), (3) Elemen <div> di dalam <ul> secara langsung tanpa <li>.

  3. Mengapa heading yang tidak berurutan dianggap error oleh validator W3C?

    Lihat Jawaban

    Karena heading (h1 hingga h6) membentuk hierarki outline dokumen. Melompat dari h1 ke h3 berarti ada sub-bagian (h2) yang hilang, membingungkan screen reader dan mesin pencari dalam memahami struktur konten.
