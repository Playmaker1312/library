# Proses proposal dan adopsi fitur HTML baru melalui W3C Recommendation track

## Analogi: Perpustakaan Digital

Proses adopsi fitur HTML baru seperti prosedur pengadaan buku baru di perpustakaan. Pertama, anggota perpustakaan mengusulkan buku yang ingin ditambahkan (proposal). Tim kurator mendiskusikan apakah buku tersebut bermanfaat dan layak (working draft). Setelah disetujui, buku di-review oleh ahli dan diuji coba di beberapa perpustakaan (candidate recommendation). Jika lolos uji coba, buku resmi menjadi bagian koleksi perpustakaan (recommendation). Proses ini memastikan setiap buku yang masuk benar-benar berkualitas dan sudah teruji sebelum tersedia untuk semua pengunjung.

## Penjelasan Detail

W3C Recommendation Track adalah proses formal untuk mengadopsi teknologi web baru yang terdiri dari beberapa tahapan. Dimulai dengan "Note" berupa ide atau use case yang didokumentasikan. Kemudian menjadi "Working Draft" di mana spesifikasi teknis mulai ditulis dan didiskusikan oleh working group. Setelah cukup matang, naik ke "Candidate Recommendation" yang mengundang implementasi dari browser dan pengembang. Browser mulai mengimplementasikan fitur dan memberikan feedback. Jika ada dua implementasi independen yang berhasil, spesifikasi naik ke "Proposed Recommendation" untuk review akhir oleh W3C Advisory Committee. Tahap terakhir adalah "W3C Recommendation" yang merupakan standar resmi. Seluruh proses ini memakan waktu bertahun-tahun dan melibatkan banyak pemangku kepentingan. WHATWG menggunakan proses yang lebih cepat dan informal untuk HTML Living Standard.

## Contoh Kode Implementasi

```html
<!DOCTYPE html>
<html lang="id">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Tahapan W3C Recommendation Track</title>
</head>
<body>
  <h1>Proses Adopsi Fitur HTML Baru</h1>

  <ol class="timeline">
    <li>
      <h2>1. Working Draft (WD)</h2>
      <p>Draf pertama spesifikasi untuk diskusi publik. Masih mungkin berubah drastis.</p>
      <p class="contoh">Contoh: <code>&lt;dialog&gt;</code> pertama kali muncul di WD pada 2013.</p>
    </li>
    <li>
      <h2>2. Candidate Recommendation (CR)</h2>
      <p>Spesifikasi dianggap stabil. Browser mulai implementasi. Pengembang diundang mencoba.</p>
      <p class="contoh">Contoh: <code>&lt;dialog&gt;</code> mencapai CR dan Chrome mulai implementasi.</p>
    </li>
    <li>
      <h2>3. Proposed Recommendation (PR)</h2>
      <p>Review akhir oleh anggota W3C. Perubahan hanya minor.</p>
    </li>
    <li>
      <h2>4. W3C Recommendation (REC)</h2>
      <p>Standar resmi. Fitur siap digunakan secara luas.</p>
      <p class="contoh">Contoh: HTML5 menjadi W3C Recommendation pada Oktober 2014.</p>
    </li>
  </ol>

  <div class="note">
    <h2>Catatan Penting</h2>
    <p>Untuk HTML, WHATWG menggunakan proses berbeda: fitur masuk ke Living Standard setelah ada dua implementasi browser yang berhasil, tanpa perlu melalui Recommendation Track formal.</p>
  </div>

  <script>
    // Simulasi deteksi dukungan fitur
    const fitur = [
      { nama: 'dialog', didukung: typeof HTMLDialogElement !== 'undefined' },
      { nama: 'details', didukung: typeof HTMLDetailsElement !== 'undefined' },
      { nama: 'lazy loading', didukung: 'loading' in HTMLImageElement.prototype },
      { nama: 'web components', didukung: 'customElements' in window }
    ];

    const div = document.createElement('div');
    div.innerHTML = '<h3>Dukungan Browser untuk Fitur Ini:</h3>' +
      fitur.map(f =>
        `<p>${f.nama}: ${f.didukung ? '&#9989; Didukung' : '&#10060; Belum didukung'}</p>`
      ).join('');
    document.querySelector('.note').appendChild(div);
  </script>
</body>
</html>
```

## Poin Penting
- Recommendation Track melalui WD, CR, PR, dan REC sebelum menjadi standar resmi W3C.
- HTML Living Standard menggunakan proses lebih cepat oleh WHATWG tanpa tahapan formal ini.
- Setiap tahap melibatkan review publik, implementasi browser, dan pengujian interoperabilitas.
