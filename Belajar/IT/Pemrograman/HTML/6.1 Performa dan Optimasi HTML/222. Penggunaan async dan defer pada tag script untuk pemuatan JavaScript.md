# Penggunaan async dan defer pada Tag Script untuk Pemuatan JavaScript

## Analogi: Perpustakaan Digital

Di perpustakaan digital, ketika seorang anggota membuka halaman buku, ada beberapa cara halaman bisa dimuat. Tanpa async/defer, setiap bab harus selesai dimuat satu per satu sebelum bab berikutnya bisa dibaca — seperti membaca buku secara berurutan tanpa bisa melompat. Dengan `defer`, kita memberitahu sistem untuk membaca seluruh struktur buku terlebih dahulu, lalu memproses catatan kaki di akhir — tetap berurutan tapi tidak menghalangi. Dengan `async`, catatan kaki dimuat begitu tersedia, tanpa peduli urutan — lebih cepat tapi berantakan jika catatan itu bergantung satu sama lain.

## Penjelasan Detail

Tag `<script>` secara default bersifat "render-blocking": browser berhenti memproses HTML saat menemukan script, mengunduh dan mengeksekusinya, lalu melanjutkan. Atribut `async` membuat script diunduh secara paralel dengan parsing HTML dan dieksekusi segera setelah selesai diunduh, tanpa menunggu parsing selesai. Atribut `defer` juga mengunduh secara paralel, tetapi menunda eksekusi hingga parsing HTML selesai, dan menjalankan script sesuai urutan kemunculannya di dokumen. Pilih `async` untuk script mandiri (seperti analytics, widget iklan) yang tidak memanipulasi DOM. Pilih `defer` untuk script yang membutuhkan DOM penuh (seperti manipulator DOM, framework). Script tanpa atribut sebaiknya hanya ditempatkan di akhir `<body>`.

## Poin Penting
- Jangan gunakan `async` untuk script yang memanipulasi DOM atau memiliki dependensi script lain karena urutan eksekusi tidak dijamin.
- `defer` aman untuk sebagian besar kasus karena menjamin DOM tersedia dan urutan eksekusi terjamin.
- Script dengan `async` atau `defer` tidak berpengaruh pada event DOMContentLoaded: defer menunggu DOMContentLoaded, async tidak.
