# Kompresi Gzip dan Brotli untuk Memperkecil Ukuran Transfer Data dari Server

## Analogi: Perpustakaan Digital

Perpustakaan digital mengirimkan buku ke rumah anggota melalui pos. Tanpa kompresi, setiap buku dikirim dalam bentuk aslinya — tebal dan berat, sehingga ongkos kirim mahal. Dengan Gzip, buku dipadatkan seperti dikemas vakum hingga ukurannya menyusut setengahnya. Brotli bahkan lebih canggih, seperti mengubah buku menjadi mikrofilm yang jauh lebih kecil. Penerima kemudian mengembalikannya ke bentuk semula. Hasilnya: pengiriman lebih cepat dan biaya lebih murah, tanpa kehilangan satu huruf pun.

## Penjelasan Detail

Kompresi sisi server bekerja dengan mengompres respons HTTP sebelum dikirim ke klien. Browser memberi tahu server melalui header `Accept-Encoding` algoritma apa yang didukungnya (gzip, br untuk Brotli). Server kemudian mengompres respons dan menambahkan header `Content-Encoding`. Gzip adalah standar lama yang didukung semua browser dan mengurangi ukuran hingga 60-70%. Brotli adalah algoritma yang lebih baru dari Google, memberikan kompresi 20-30% lebih baik daripada Gzip untuk konten web, terutama file HTML dan CSS. Brotli bekerja lebih efektif karena menggunakan dictionary yang berisi pola umum kode web. Keduanya sangat efektif untuk konten berbasis teks (HTML, CSS, JS, JSON) tetapi tidak berguna untuk file yang sudah terkompresi seperti gambar JPEG atau video MP4.

## Poin Penting
- Brotli memberikan rasio kompresi lebih baik daripada Gzip, terutama untuk teks HTML dan CSS, tetapi membutuhkan lebih banyak CPU server.
- Kompresi tidak efektif untuk media biner (gambar, video, PDF) dan sebaiknya dilewati dengan memeriksa tipe MIME.
- Pastikan server mengatur header `Vary: Accept-Encoding` agar cache tidak salah menyajikan konten terkompresi ke klien yang tidak mendukungnya.
