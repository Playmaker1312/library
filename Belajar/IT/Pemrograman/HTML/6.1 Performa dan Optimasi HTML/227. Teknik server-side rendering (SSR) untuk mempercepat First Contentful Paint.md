# Teknik Server-Side Rendering (SSR) untuk Mempercepat First Contentful Paint

## Analogi: Perpustakaan Digital

Bayangkan dua cara perpustakaan menyajikan buku. Cara pertama (client-side rendering): pengunjung datang, pustakawan memberikan lembaran kosong, lalu menuliskan cerita satu per satu di depan pengunjung — pengunjung menunggu hingga seluruh cerita selesai. Cara kedua (SSR): pustakawan menyiapkan buku yang sudah dicetak lengkap. Ketika pengunjung datang, buku langsung diberikan — ia bisa langsung membaca halaman pertama tanpa menunggu. Inilah SSR: server menyiapkan HTML lengkap sehingga browser langsung bisa menampilkan konten tanpa harus menjalankan JavaScript terlebih dahulu.

## Penjelasan Detail

Server-Side Rendering (SSR) adalah teknik merender aplikasi JavaScript di server menjadi HTML lengkap, lalu mengirimkannya ke browser. Browser langsung menampilkan HTML tersebut (First Contentful Paint yang cepat), kemudian JavaScript diunduh dan dijalankan untuk membuat halaman menjadi interaktif (hydrate). Framework seperti Next.js (React), Nuxt.js (Vue), dan SvelteKit mendukung SSR secara native. Keuntungan SSR termasuk FCP yang lebih cepat, SEO yang lebih baik (karena crawler melihat HTML lengkap), dan performa yang lebih baik di perangkat lambat. Kerugiannya meliputi biaya server yang lebih tinggi, Time to First Byte (TTFB) yang lebih lambat, dan kompleksitas infrastruktur.

## Poin Penting
- SSR meningkatkan FCP secara signifikan karena HTML lengkap sudah tersedia saat pertama kali browser menerima data.
- Hydration adalah proses "menghidupkan" HTML statis menjadi aplikasi interaktif; proses ini bisa mahal untuk halaman besar.
- Pertimbangkan streaming SSR (React 18) untuk mengurangi TTFB dengan mengirim HTML secara bertahap.
