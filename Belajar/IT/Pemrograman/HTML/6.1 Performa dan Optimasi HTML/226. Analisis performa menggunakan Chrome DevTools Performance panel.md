# Analisis Performa Menggunakan Chrome DevTools Performance Panel

## Analogi: Perpustakaan Digital

Bayangkan perpustakaan digital yang lambat, dan Anda adalah detektif yang mencari penyebabnya. Performance Panel di Chrome DevTools seperti dasbor CCTV yang merekam setiap aktivitas di perpustakaan: siapa yang masuk (network request), berapa lama mereka di loket (script execution), kapan rak diakses (DOM manipulation), dan berapa lama buku dipindahkan (layout calculation). Dengan rekaman ini, Anda bisa melihat frame-by-frame apa yang terjadi dan menemukan bahwa misalnya, seorang petugas sedang memindahkan ribuan buku satu per satu (layout thrashing) yang menyebabkan antrean panjang di pintu masuk.

## Penjelasan Detail

Chrome DevTools Performance panel memungkinkan developer merekam dan menganalisis aktivitas runtime halaman web secara detail. Rekaman menampilkan timeline dalam bentuk flame chart yang menunjukkan fungsi mana yang memakan waktu paling lama. Panel ini terbagi menjadi beberapa bagian: Controls (record/stop), Overview (ringkasan FPS, CPU, Network), Flame Chart (aktivitas thread utama per frame), dan tab detail (Summary, Bottom-Up, Call Tree, Event Log). Metrik kunci yang perlu diperhatikan meliputi Long Tasks (tugas >50ms yang memblokir thread utama), forced reflow/layout, dan frame rate drop. Dengan Performance panel, developer dapat mengidentifikasi JavaScript yang lambat, layout yang tidak efisien, atau rendering yang bermasalah.

    function simulasiLongTask() {
      var output = document.getElementById('console-output');
      var start = performance.now();

      // Simulasi long task dengan loop berat
      var sum = 0;

## Poin Penting
- Fokus pada "Long Tasks" — tugas yang memblokir thread utama lebih dari 50ms akan menyebabkan halaman terasa lambat.
- Hindari forced reflow dengan memisahkan operasi baca dan tulis layout (batch read, lalu batch write).
- Gunakan tombol 「📷」 (screenshot) saat rekaman untuk melihat visual perubahan halaman di setiap titik timeline.
