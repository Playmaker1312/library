# Optimasi Font Web dengan font-display swap dan Subsetting

## Analogi: Perpustakaan Digital

Perpustakaan digital ingin menggunakan huruf kaligrafi indah untuk sampul bukunya. Namun, font khusus ini harus diunduh dulu. Tanpa optimasi, halaman buku akan kosong (invisible text) selama font diunduh — seperti buku dengan sampul kosong. Dengan `font-display: swap`, sistem akan menampilkan teks dengan font cadangan terlebih dahulu, lalu menggantinya dengan font indah setelah selesai diunduh. Subsetting seperti hanya menyimpan huruf yang benar-benar dipakai — jika buku hanya menggunakan huruf Latin, tidak perlu menyertakan aksara Arab atau Hanzi, sehingga file font menjadi jauh lebih kecil.

## Penjelasan Detail

Font web sering menjadi sumber masalah performa karena ukurannya bisa besar (200-500 KB per varian) dan menyebabkan FOIT (Flash of Invisible Text) atau FOUT (Flash of Unstyled Text). Property CSS `font-display` mengontrol perilaku rendering selama font diunduh: `swap` menampilkan teks dengan font fallback segera lalu mengganti saat font siap; `optional` memberikan waktu singkat lalu menggunakan fallback permanen jika font belum siap; `block` menyembunyikan teks hingga 3 detik. Subsetting mengurangi ukuran font dengan membuang glyph yang tidak diperlukan. Alat seperti `glyphhanger` atau Google Fonts API parameter `?text=` memungkinkan subsetting otomatis. Menggabungkan `font-display: swap` dengan subsetting memberikan keseimbangan terbaik antara estetika dan performa.

## Poin Penting
- `font-display: swap` mencegah FOIT tetapi menyebabkan FOUT (teks berkedip saat font diganti); gunakan untuk font display dan headline.
- Subsetting sangat penting untuk font dengan banyak glyph (seperti font Asia Timur) — bisa menghemat hingga 90% ukuran file.
- Pertimbangkan menggunakan variable font (satu file untuk banyak weight) untuk mengurangi jumlah file font yang harus diunduh.
