<form> — Wadah Input Data

Penjelasan

<form> adalah elemen wadah (container) yang membungkus semua elemen input dalam sebuah halaman web. Fungsinya mirip seperti gerbang utama gedung — semua data yang ingin dikirim ke server harus melewati <form>. Dua atribut paling penting pada <form> adalah action (menentukan alamat tujuan pengiriman data) dan method (menentukan cara pengiriman data).

Fungsi

  • Mengelompokkan semua input data dalam satu kesatuan logis
  • Menentukan ke mana data akan dikirim (action)
  • Menentukan cara data dikirim: GET (terlihat di URL) atau POST (tersembunyi di body)
  • Memicu proses submit saat tombol kirim ditekan

Cara Pengimplementasian

<!-- GET — data menempel di URL, cocok untuk pencarian -->
<form action="/cari" method="GET">
  <input type="text" name="q" placeholder="Cari...">
  <button type="submit">Cari</button>
</form>

<!-- POST — data dikirim di body, cocok untuk login/pesan -->
<form action="/login" method="POST">
  <input type="text" name="username">
  <input type="password" name="password">
  <button type="submit">Masuk</button>
</form>

Analogi — Gerbang Gedung

Bayangkan <form> adalah gerbang utama sebuah gedung. Atribut action bagaikan alamat gedung tujuan — ke mana semua orang harus pergi. Atribut method bagaikan cara mereka masuk: GET seperti berjalan melalui pintu kaca (semua orang bisa melihat apa yang Anda bawa — data terlihat di URL), sedangkan POST seperti menggunakan lift barang tertutup (apa yang Anda bawa tidak terlihat dari luar — data tersembunyi di body).

GET digunakan untuk mencari sesuatu di dalam gedung (misal mencari ruangan), sementara POST digunakan untuk menyerahkan sesuatu yang bersifat rahasia atau besar (misal menyerahkan berkas lamaran atau formulir pendaftaran).

Dipaki Untuk

  • GET: Formulir pencarian, filter produk, navigasi halaman — data tidak sensitif dan boleh terlihat di URL
  • POST: Login, registrasi, form pemesanan, upload file, komentar — data sensitif atau berukuran besar

Kesalahan Umum

  • Lupa menambahkan atribut action sehingga data dikirim ke halaman yang sama (mungkin tidak diinginkan)
  • Menggunakan GET untuk data sensitif (password akan terlihat di URL)
  • Tidak memberikan name pada elemen input di dalam form — data tidak akan terkirim karena server tidak tahu nama variabelnya
  • Bersarangnya <form> di dalam <form> lain — HTML melarang hal ini dan perilakunya tidak terdefinisi

Koneksi dengan Materi Sebelumnya

Sebelum mempelajari <form>, Anda sudah mengenal elemen-elemen input seperti <input>, <label>, <textarea>, dan <select>. Semua elemen itu adalah bagian dari sebuah form — ibarat perabot di dalam sebuah ruangan. <form> adalah ruangan itu sendiri. Materi selanjutnya akan membahas atribut-atribut lanjutan seperti enctype, target, dan autocomplete yang semakin memperkuat fungsi form.

Soal Latihan

  1. Apa perbedaan utama method GET dan POST pada tag <form>? Kapan masing-masing sebaiknya digunakan?

    Lihat Jawaban

    GET mengirim data melalui URL (querystring), sehingga data terlihat dan memiliki batas panjang. Cocok untuk pencarian atau filter. POST mengirim data melalui body HTTP, sehingga tidak terlihat di URL dan tidak terbatas ukurannya. Cocok untuk login, pendaftaran, atau upload data sensitif.

  2. Mengapa elemen input di dalam form harus memiliki atribut name agar datanya terkirim?

    Lihat Jawaban

    Karena saat form dikirim, browser membuat pasangan name=nilai untuk setiap input. Tanpa atribut name, browser tidak tahu nama variabel data tersebut, sehingga input tersebut tidak akan dikirim ke server. Atribut name ibarat label pada kotak surat — server tahu isi kotak itu milik siapa.

  3. Apa yang terjadi jika atribut action tidak ditulis pada tag <form>?

    Lihat Jawaban

    Jika action tidak ditentukan, data akan dikirim ke URL halaman yang sama (halaman tempat form berada). Ini bisa menyebabkan halaman me-refresh dirinya sendiri dengan data di URL (jika method GET) atau body (jika method POST).
