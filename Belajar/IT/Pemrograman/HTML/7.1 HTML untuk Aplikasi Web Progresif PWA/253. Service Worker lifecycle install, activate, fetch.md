# Service Worker lifecycle: install, activate, fetch

## Analogi: Perpustakaan Digital

Service Worker seperti pustakawan yang bekerja di latar belakang perpustakaan digital. Pustakawan ini melalui proses rekrutmen (install), penempatan tugas (activate), dan kemudian melayani permintaan pengunjung (fetch). Saat pustakawan baru direkrut, dia menyiapkan rak buku dan koleksi yang diperlukan. Setelah siap, pustakawan lama digantikan dan pustakawan baru mulai melayani permintaan peminjaman buku. Setiap kali pengunjung meminta buku, pustakawan bisa memutuskan untuk memberikan buku dari koleksi lokal atau mengambil dari gudang pusat.

## Penjelasan Detail

Service Worker memiliki siklus hidup yang terdefinisi dengan tiga fase utama: `install`, `activate`, dan `fetch`. Pada fase `install`, Service Worker diunduh dan dieksekusi, cocok untuk melakukan pre-caching resource statis. Event `install` hanya terjadi sekali selama umur Service Worker, dan jika gagal, Service Worker tidak akan aktif. Fase `activate` dipicu setelah instalasi berhasil dan Service Worker siap mengendalikan halaman. Di sinilah pembersihan cache lama biasanya dilakukan. Fase `fetch` terjadi setiap kali halaman yang dikendalikan melakukan request jaringan. Service Worker dapat mencegat request dan merespons dengan strategi caching yang telah ditentukan. Service Worker tidak memiliki akses ke DOM tetapi dapat berkomunikasi dengan halaman melalui `postMessage`. Setiap Service Worker hanya mengendalikan halaman dalam scope direktori tempat file tersebut berada.

## Contoh Kode Implementasi

```html
<!DOCTYPE html>
<html lang="id">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Service Worker Lifecycle</title>
</head>
<body>
  <h1>Demo Service Worker</h1>
  <button id="statusBtn">Cek Status</button>
  <pre id="log"></pre>
  <script>
    const log = document.getElementById('log');
    function logMsg(msg) {
      log.textContent += msg + '\n';
    }

    if ('serviceWorker' in navigator) {
      navigator.serviceWorker.register('sw.js')
        .then(reg => {
          logMsg('Service Worker terdaftar: ' + reg.scope);
          if (reg.active) {
            logMsg('Status: active');
          }
          if (reg.installing) {
            logMsg('Status: installing');
          }
          if (reg.waiting) {
            logMsg('Status: waiting (ada update)');
          }

          reg.addEventListener('updatefound', () => {
            logMsg('Update ditemukan!');
          });
        })
        .catch(err => {
          logMsg('Registrasi gagal: ' + err);
        });

      navigator.serviceWorker.addEventListener('controllerchange', () => {
        logMsg('Controller berubah - Service Worker baru aktif');
      });
    } else {
      logMsg('Service Worker tidak didukung browser ini');
    }
  </script>
</body>
</html>
```

```javascript
// sw.js
const CACHE_NAME = 'v1-cache';

self.addEventListener('install', event => {
  console.log('[SW] Install - menyiapkan cache');
  event.waitUntil(
    caches.open(CACHE_NAME).then(cache => {
      return cache.addAll([
        '/',
        '/index.html',
        '/style.css',
        '/app.js'
      ]);
    })
  );
});

self.addEventListener('activate', event => {
  console.log('[SW] Activate - membersihkan cache lama');
  event.waitUntil(
    caches.keys().then(cacheNames => {
      return Promise.all(
        cacheNames.filter(name => name !== CACHE_NAME)
          .map(name => caches.delete(name))
      );
    })
  );
});

self.addEventListener('fetch', event => {
  console.log('[SW] Fetch - mencegat:', event.request.url);
  event.respondWith(
    caches.match(event.request)
      .then(response => response || fetch(event.request))
  );
});
```

## Poin Penting
- Event `install` digunakan untuk pre-caching, sedangkan `activate` untuk pembersihan cache lama.
- Service Worker tidak aktif sampai halaman di-reload setelah fase activate selesai.
- Event `fetch` memungkinkan kontrol penuh atas setiap request jaringan dari halaman yang dikendalikan.
