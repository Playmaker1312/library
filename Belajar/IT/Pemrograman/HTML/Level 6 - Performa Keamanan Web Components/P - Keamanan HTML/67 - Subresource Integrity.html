Subresource Integrity (SRI)

Penjelasan

Subresource Integrity (SRI) adalah fitur keamanan yang memungkinkan browser memverifikasi bahwa file yang diambil dari server pihak ketiga (seperti CDN) tidak dimodifikasi. SRI menggunakan hash kriptografi yang ditempatkan pada atribut integrity dari elemen <script> atau <link rel="stylesheet">.

Saat browser mendownload file, ia menghitung hash-nya dan membandingkannya dengan hash yang tercantum. Jika tidak cocok, file tidak akan dieksekusi atau diterapkan.

Fungsi

  • Melindungi pengguna dari serangan supply chain di mana file CDN dirusak oleh pihak ketiga.
  • Memastikan integritas kode library yang digunakan tetap utuh seperti saat pertama kali ditulis.
  • Memberikan lapisan kepercayaan ketika mengambil sumber daya dari server yang tidak sepenuhnya kita kendalikan.
  • Mencegah eksekusi skrip yang telah diubah untuk menyisipkan kode berbahaya.

Cara Pengimplementasian

Untuk menerapkan SRI, tambahkan atribut integrity dengan nilai hash dan atribut crossorigin pada elemen:

<!-- Bootstrap CSS dengan SRI -->
<link
    rel="stylesheet"
    href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.3/dist/css/bootstrap.min.css"
    integrity="sha384-QWTKZyjpPEjISv5WaRU9OFeRpok6YctnYmDr5pNlyT2bRjXh0JMhjY6hW+ALEwIH"
    crossorigin="anonymous"
>

<!-- Bootstrap JS bundle dengan SRI -->
<script
    src="https://cdn.jsdelivr.net/npm/bootstrap@5.3.3/dist/js/bootstrap.bundle.min.js"
    integrity="sha384-YvpcrYf0tY3lHB60NNkmXc5s9fDVZLESaAA55NDzOxhy9GkcIdslK1eN7N6jIeHz"
    crossorigin="anonymous"
></script>

Hash untuk SRI dapat digenerate menggunakan alat seperti srihash.org atau melalui terminal:

# Contoh generate hash via OpenSSL
openssl dgst -sha384 -binary file.min.js | openssl base64 -A

Analogi

Bayangkan Anda memesan pintu rumah dari toko online. Pintu dikirim oleh kurir (CDN). Tanpa SRI, Anda tidak tahu apakah kurir mengganti pintu dengan yang lebih jelek atau bahkan memasang kunci duplikat.

  • integrity = Segel keamanan pada paket. Jika segel rusak, Anda tahu pintu sudah dirusak dan Anda tolak.
  • hash = Ciri unik pintu Anda — ukuran, warna, pola kayu — tidak ada duplikat yang tepat.
  • crossorigin = KTP kurir yang menunjukkan identitasnya. Tanpa ini, browser tidak akan mengecek segel dengan benar.

Hasilnya: Anda hanya pasang pintu yang benar-benar asli dan tidak rusak di rumah Anda.

Dipakai Untuk

  • Library CSS/JS dari CDN publik (Bootstrap, jQuery, Font Awesome, dll).
  • Framework frontend yang di-host di server pihak ketiga.
  • Website yang menerapkan kebijakan keamanan ketat dan ingin memverifikasi setiap file.
  • Aplikasi web yang melayani banyak pengguna dan harus menjamin kode tetap aman.

Kesalahan Umum

  • Lupa atribut crossorigin: SRI tidak akan berfungsi tanpa crossorigin="anonymous" pada file dari origin berbeda — browser akan mengabaikan integrity.
  • Hash tidak update: Menggunakan hash lama setelah file CDN diperbarui, menyebabkan file diblokir.
  • Hanya pada script, lupa CSS: SRI penting untuk <link> juga, bukan hanya <script>.
  • Typo hash: Satu karakter salah dalam hash menyebabkan verifikasi gagal.
  • Tidak regenerate hash: Meng-copy paste hash dari sumber tidak resmi tanpa memverifikasi.

Koneksi dengan Materi Sebelumnya

SRI bekerja sangat baik bersama Content Security Policy (CSP). Jika CSP membatasi sumber mana yang diizinkan (script-src), SRI memverifikasi integritas file dari sumber tersebut. Keduanya adalah lapisan pertahanan berlapis. SRI juga relevan dengan atribut sandbox iframe — keduanya membatasi apa yang bisa dilakukan oleh kode dari pihak ketiga.

Soal Latihan

1. Apa yang terjadi jika hash pada atribut integrity tidak cocok dengan hash file yang didownload?

Lihat Jawaban

Browser akan menolak mengeksekusi atau menerapkan file tersebut. Untuk <script>, skrip tidak akan dijalankan. Untuk <link>, CSS tidak akan diterapkan.

2. Mengapa atribut crossorigin diperlukan saat menggunakan SRI dengan file dari CDN?

Lihat Jawaban

Karena file dari origin berbeda dianggap cross-origin. Browser membutuhkan atribut crossorigin agar bisa mengakses respons secara transparan dan memverifikasi hash. Tanpa atribut ini, browser tidak akan mengecek integrity sama sekali.

3. Sebutkan dua alat yang bisa digunakan untuk menghasilkan hash SRI!

Lihat Jawaban

srihash.org dan terminal menggunakan perintah openssl dgst -sha384 -binary file.js | openssl base64 -A.
