Critical Rendering Path (CRP)

Penjelasan

Critical Rendering Path adalah urutan langkah yang dilakukan browser untuk mengubah HTML, CSS, dan JavaScript menjadi piksel di layar. Langkahnya: DOM → CSSOM → Render Tree → Layout → Paint. Browser tidak bisa menampilkan halaman sebelum HTML dan CSS selesai diproses.

Fungsi

  • Mengoptimalkan waktu render pertama halaman (First Paint)
  • Mengurangi waktu hingga halaman terasa interaktif
  • Mencegah blokade parsing oleh CSS dan JavaScript

Cara Pengimplementasian

<!-- CSS di head (blokir render) -->
<link rel="stylesheet" href="style.css">

<!-- JS di head: MEMBLOKIR parsing HTML -->
<!-- HINDARI ini: -->
<script src="app.js"></script>

<!-- SOLUSI: taruh JS di akhir body -->
<body>
  <!-- konten HTML -->
  <script src="app.js"></script>
</body>

<!-- SOLUSI: preload font/gambar penting -->
<link rel="preload" href="font.woff2" as="font" crossorigin>

<!-- SOLUSI: preconnect ke domain eksternal -->
<link rel="preconnect" href="https://fonts.googleapis.com">

Analogi

Bayangkan membangun rumah. HTML adalah kerangka rumah (tiang, dinding, atap). CSS adalah cat, wallpaper, dan dekorasi. Browser ibarat tukang yang tidak bisa memasang cat sebelum kerangka selesai — itulah kenapa CSS di head memblokir render. JavaScript di head seperti kontraktor yang tiba-tiba menghentikan semua tukang untuk diskusi ulang desain — parsing HTML terhenti sampai diskusi selesai.

Dipakai Untuk

  • Meningkatkan First Contentful Paint (FCP)
  • Menurunkan Time to Interactive (TTI)
  • Mengoptimalkan skor Core Web Vitals (LCP, FID)

Kesalahan Umum

  • Meletakkan <script> di <head> tanpa defer/async — memblokir parsing HTML
  • Memuat CSS yang tidak dibutuhkan di halaman awal — memperlambat render
  • Tidak menggunakan preload untuk font penting — menyebabkan FOUT (Flash of Unstyled Text)
  • Mengabaikan render-blocking resources — halaman kosong terlalu lama

Koneksi dengan Materi Sebelumnya

CRP berkaitan erat dengan 63 - defer vs async (cara memuat JS tanpa blokir) dan 65 - Resource Hints (preload/prefetch/preconnect untuk mempercepat CRP). Memahami CRP adalah fondasi untuk semua teknik optimasi performa halaman web.

Soal Latihan

1. Mengapa meletakkan <script> di <head> tanpa atribut dapat memperlambat rendering halaman?

Lihat Jawaban

Karena <script> tanpa atribut akan memblokir (block) parsing HTML hingga skrip selesai di-download dan dieksekusi. Browser tidak bisa melanjutkan membuat DOM sampai skrip selesai, sehingga halaman terlihat kosong lebih lama.

2. Sebutkan tiga langkah dalam Critical Rendering Path setelah DOM dan CSSOM terbentuk!

Lihat Jawaban

1. Render Tree — menggabungkan DOM dan CSSOM menjadi pohon render. 2. Layout — menghitung posisi dan ukuran setiap elemen. 3. Paint — menggambar piksel ke layar.

3. Apa yang dimaksud dengan render-blocking resource? Beri satu contoh!

Lihat Jawaban

Render-blocking resource adalah sumber daya yang harus selesai di-download dan diproses sebelum browser bisa me-render halaman. Contoh: file CSS yang diletakkan di <head>.
