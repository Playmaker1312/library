Resource Hints: preload, prefetch, preconnect

Penjelasan

Resource Hints adalah atribut pada tag <link> yang memberi tahu browser sumber daya apa yang harus dimuat lebih awal. Tiga yang paling umum: preload (pasti dibutuhkan sekarang), prefetch (mungkin dibutuhkan nanti), dan preconnect (buka koneksi ke domain lain lebih awal).

Fungsi

  • preload — Memuat sumber daya pasti dibutuhkan halaman ini (font, hero image, CSS kritis)
  • prefetch — Memuat sumber daya mungkin dibutuhkan nanti (halaman berikutnya, navigasi berikutnya)
  • preconnect — Membuka koneksi TCP/TLS ke domain eksternal lebih awal (mengurangi handshake latency)

Cara Pengimplementasian

<!-- preload: font penting yang pasti dipakai -->
<link rel="preload" href="fonts/roboto.woff2" as="font" type="font/woff2" crossorigin>

<!-- preload: hero image di atas layar -->
<link rel="preload" href="images/hero.webp" as="image">

<!-- preload: CSS kritis -->
<link rel="preload" href="critical.css" as="style">

<!-- prefetch: halaman berikutnya yang mungkin dikunjungi -->
<link rel="prefetch" href="/produk.html" as="document">

<!-- prefetch: gambar untuk halaman berikutnya -->
<link rel="prefetch" href="images/produk.jpg" as="image">

<!-- preconnect: buka koneksi ke Google Fonts lebih awal -->
<link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>

<!-- preconnect: API eksternal -->
<link rel="preconnect" href="https://api.example.com">

Analogi

preload seperti arsitek yang sudah menyiapkan cat, semen, dan batu bata di dekat tukang sebelum diminta — barang itu pasti dipakai hari ini. prefetch seperti membeli material tambahan dan menaruhnya di gudang — mungkin dipakai untuk kamar yang akan dibangun minggu depan. preconnect seperti menelpon pemasok material sebelum tukang datang — sambungan telepon sudah siap, tinggal pesan barang tanpa menunggu nada sambung.

Dipakai Untuk

  • preload — font custom, hero image, CSS kritis, resource yang baru ketahuan setelah CSS/JS diproses
  • prefetch — halaman berikutnya (berdasarkan pola navigasi user), gambar galeri berikutnya
  • preconnect — domain CDN, Google Fonts, API eksternal, server third-party

Kesalahan Umum

  • preload untuk resource yang tidak dipakai — membuang bandwidth dan memperlambat halaman
  • prefetch untuk resource besar — bisa menghabiskan kuota data pengguna (data waste)
  • Terlalu banyak preconnect — browser membuka banyak koneksi idle (boros sumber daya)
  • Lupa atribut crossorigin pada preload font — font tidak akan dimuat (CORS error)
  • Menggunakan preload untuk menggantikan <link rel="stylesheet"> — tidak selalu tepat karena preload tidak otomatis diterapkan

Koneksi dengan Materi Sebelumnya

Resource Hints adalah alat optimasi lanjutan untuk Critical Rendering Path (63). preload mempercepat pemuatan resource kritis yang memblokir render. preconnect mengurangi latency koneksi yang dibahas di CRP. Teknik ini juga melengkapi async/defer (64) karena resource seperti font dan gambar juga perlu dioptimalkan, bukan hanya JavaScript.

Soal Latihan

1. Kapan sebaiknya menggunakan preload dibandingkan prefetch?

Lihat Jawaban

preload digunakan untuk sumber daya yang pasti dibutuhkan oleh halaman saat ini dan harus segera tersedia (misal: font hero, gambar di atas lipatan). prefetch digunakan untuk sumber daya yang mungkin dibutuhkan di navigasi berikutnya (misal: halaman produk berikutnya).

2. Apa yang dimaksud dengan atribut crossorigin pada preload font? Mengapa penting?

Lihat Jawaban

crossorigin menandai bahwa request font akan menggunakan mode CORS (anonymous). Font dari domain berbeda (seperti Google Fonts) dianggap CORS resource oleh browser. Tanpa atribut ini, browser akan mengabaikan hasil preload font dan font tidak akan diterapkan.

3. Sebutkan satu situasi di mana preconnect sangat bermanfaat!

Lihat Jawaban

Saat halaman menggunakan font dari Google Fonts (fonts.googleapis.com dan fonts.gstatic.com). preconnect membuka koneksi TCP/TLS ke domain tersebut lebih awal, sehingga saat CSS benar-benar membutuhkan font, koneksi sudah siap — menghemat waktu handshake (DNS + TCP + TLS).
