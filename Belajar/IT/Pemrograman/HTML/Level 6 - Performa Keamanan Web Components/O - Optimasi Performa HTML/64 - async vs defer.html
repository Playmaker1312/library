async vs defer pada Script HTML

Penjelasan

async dan defer adalah atribut pada tag <script> yang mengubah cara browser mendownload dan mengeksekusi JavaScript. Tanpa atribut, script akan mendownload dan mengeksekusi secara sinkron — memblokir parsing HTML. Dengan async atau defer, download dilakukan paralel tanpa memblokir parsing.

Fungsi

  • Tanpa atribut: download + execute, blokir parsing HTML sepenuhnya
  • async: download paralel (tidak blokir), execute segera setelah download selesai — blokir parsing sesaat
  • defer: download paralel (tidak blokir), execute setelah HTML selesai di-parse — tidak ada blokir

Cara Pengimplementasian

<!-- Tanpa atribut — BLOKIR PARSING (hindari di <head>) -->
<script src="script.js"></script>

<!-- async — download paralel, execute segera -->
<script async src="analytics.js"></script>

<!-- defer — download paralel, execute setelah HTML selesai -->
<script defer src="app.js"></script>

<!-- Urutan: async tidak menjamin urutan, defer menjamin urutan -->
<script defer src="lib.js"></script>
<script defer src="app.js"></script>
<!-- lib.js akan jalan duluan, lalu app.js -->

Analogi

Bayangkan sedang membangun rumah. Tanpa atribut seperti: kontraktor berhenti total, pergi ke toko beli semen, pulang, baru lanjut bangun — semua tukang nganggur. async seperti: kontraktor mengirim pembantu ke toko, semen datang, langsung dipakai meskipun tukang sedang memasang bata — agak kaget tapi efisien. defer seperti: kontraktor mengirim pembantu ke toko, semen ditumpuk rapi, dan baru dipakai setelah semua tukang selesai memasang bata — teratur dan tidak mengganggu.

Dipakai Untuk

  • defer — script yang butuh DOM (manipulasi elemen, event handler, aplikasi utama)
  • async — script independen (analytics, iklan, tracking pixel)
  • Tanpa atribut — sangat jarang; hanya jika script harus dijalankan sebelum browser memproses apapun (misal: polyfill lama)

Kesalahan Umum

  • Menggunakan async untuk script yang bergantung pada DOM — script bisa jalan sebelum DOM siap
  • Menggunakan async untuk beberapa script yang saling bergantung — urutan eksekusi tidak dijamin
  • Meletakkan defer di <body> — sebenarnya tidak salah, tapi lebih baik di <head> agar download lebih awal
  • Tidak menggunakan atribut sama sekali untuk script non-kritis di <head> — memperlambat halaman

Koneksi dengan Materi Sebelumnya

async dan defer adalah solusi langsung untuk masalah render-blocking JavaScript yang dijelaskan di 63 - Critical Rendering Path. Dengan menggunakan atribut ini, kita mengurangi blokade pada CRP. Materi ini juga terkait dengan 65 - Resource Hints karena preload/prefetch bisa digunakan bersamaan untuk optimasi maksimal.

Soal Latihan

1. Apa perbedaan utama antara async dan defer dalam hal waktu eksekusi?

Lihat Jawaban

async mengeksekusi script segera setelah download selesai, kapanpun itu — bisa sebelum HTML selesai di-parse. defer mengeksekusi script setelah HTML selesai di-parse, tepat sebelum event DOMContentLoaded.

2. Mengapa async tidak cocok untuk script yang memanipulasi DOM?

Lihat Jawaban

Karena async bisa mengeksekusi script sebelum DOM selesai dibangun. Jika script mencoba mengakses elemen yang belum ada di DOM, akan terjadi error.

3. Mana yang menjamin urutan eksekusi jika ada dua script — async atau defer?

Lihat Jawaban

defer. Script dengan defer dieksekusi sesuai urutan kemunculannya di HTML. async tidak menjamin urutan — script yang lebih cepat selesai di-download akan dijalankan lebih dulu.
