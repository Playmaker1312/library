Navigasi Keyboard

Penjelasan

Navigasi keyboard adalah kemampuan pengguna untuk mengakses dan berinteraksi dengan seluruh elemen di halaman web hanya menggunakan keyboard — tanpa mouse. Ini penting bagi pengguna dengan keterbatasan motorik, tunanetra, atau pengguna power user yang lebih suka keyboard.

Elemen interaktif native seperti <a>, <button>, <input> sudah bisa diakses keyboard secara otomatis. Elemen non-semantik seperti <div> membutuhkan bantuan tabindex.

Fungsi

  • Memastikan semua interaksi dapat dilakukan dengan Tab, Enter, Space, dan panah
  • Menyediakan indikator fokus visual (outline) yang jelas
  • Menyediakan skip navigation link agar pengguna bisa melompati menu berulang
  • Mengatur urutan fokus yang logis sesuai urutan baca (kiri-ke-kanan, atas-ke-bawah)

Cara Pengimplementasian

<!-- Skip navigation link (WAJIB) -->
<a href="#main-content" class="skip-link">Lompat ke konten utama</a>

<nav>
    <ul>
        <li><a href="#">Beranda</a></li>
        <li><a href="#">Tentang</a></li>
    </ul>
</nav>

<main id="main-content">
    <!-- tabindex="0" tambah elemen ke tab order alami -->
    <div tabindex="0" role="button">Kotak Kustom</div>

    <!-- tabindex="-1" bisa fokus via JS tapi tidak di tab order -->
    <div id="pesan-error" tabindex="-1" role="alert">
        Terjadi kesalahan.
    </div>
</main>

<script>
    // Fokus ke elemen dengan tabindex="-1" via JavaScript
    document.getElementById('pesan-error').focus();
</script>

Analogi — Rumah dan Bangunan

Navigasi keyboard ibarat jalan setapak khusus di dalam rumah yang bisa dilewati tanpa perlu menyentuh dinding (mouse). Setiap ruangan (elemen) harus memiliki pintu yang bisa dibuka dari jalan setapak itu.

tabindex="0" seperti menambahkan pintu baru ke jalan setapak utama.

tabindex="-1" seperti pintu darurat yang hanya bisa dibuka dari dalam (via remote / JavaScript), tidak terlihat dari jalan setapak utama.

tabindex positif (1, 2, 3) seperti memotong jalan setapak secara paksa — sangat membingungkan dan TIDAK disarankan.

Skip navigation link seperti tangga darurat yang langsung menuju lantai tujuan tanpa perlu melewati koridor panjang.

Dipakai Untuk

  • Semua halaman web yang ingin diakses oleh pengguna keyboard
  • Komponen kustom seperti modal, dropdown, carousel
  • Halaman dengan navigasi berulang di bagian atas (skip link)
  • Pesan error yang perlu langsung mendapat fokus setelah validasi

Kesalahan Umum

  • tabindex positif: tabindex="5" mengacaukan urutan navigasi alami — HINDARI
  • Menghilangkan outline fokus: outline: none tanpa pengganti membuat pengguna keyboard tersesat
  • Tidak ada skip link: pengguna keyboard harus menekan Tab puluhan kali setiap halaman
  • Elemen non-interaktif diberi tabindex: judul, paragraf, atau gambar tidak perlu di-tab
  • Modal tidak mengunci fokus: setelah membuka modal, fokus bisa kabur ke belakang layar

Koneksi dengan Materi Sebelumnya

Navigasi keyboard melengkapi ARIA (materi 49) dan aria-label (materi 50). Jika ARIA memberi nama pada komponen, navigasi keyboard memastikan komponen itu bisa dikunjungi dan dioperasikan tanpa mouse. Semantic HTML (materi sebelumnya) menyediakan elemen interaktif native yang sudah mendukung keyboard — gunakan sebelum membuat custom widget.

Soal Latihan

  1. Apa fungsi tabindex="0" dan tabindex="-1"? Jelaskan dengan analogi rumah.

    Lihat Jawaban

    tabindex="0" menambahkan elemen ke dalam urutan navigasi Tab normal (seperti menambah pintu baru di koridor utama). tabindex="-1" membuat elemen bisa menerima fokus hanya melalui JavaScript, bukan dari tombol Tab (seperti pintu darurat yang hanya bisa dibuka dari dalam).

  2. Mengapa tabindex bernilai positif (misal tabindex="5") sebaiknya dihindari?

    Lihat Jawaban

    Karena tabindex positif membuat elemen dilompati terlebih dahulu sebelum urutan Tab normal dimulai. Ini melanggar ekspektasi pengguna dan menciptakan urutan navigasi yang tidak logis — seperti membuat jalan pintas yang melompati koridor utama secara tidak terduga.
