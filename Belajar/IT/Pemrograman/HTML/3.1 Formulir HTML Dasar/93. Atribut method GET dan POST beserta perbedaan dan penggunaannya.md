# Atribut method GET dan POST Beserta Perbedaan dan Penggunaannya

## Analogi: Perpustakaan Digital

Bayangkan dua cara **mengirim pesan** ke pustakawan:

**GET** → Kamu menulis pesan di **papan tulis di depan umum**. Semua orang bisa lihat, dan pesan itu tercatat di URL. Cocok untuk pertanyaan sederhana: "Cari buku 'Laskar Pelangi'"

**POST** → Kamu menulis pesan di **amplop tertutup** dan menyerahkannya ke pustakawan. Isinya tidak terlihat orang lain. Cocok untuk data pribadi: "Saya ingin daftar anggota, ini KTP dan alamat saya."

## Penjelasan Detail

`method` menentukan **cara pengiriman** data formulir.

### GET
Data dikirim melalui **URL** (query string).
```html
<form method="GET" action="cari.php">
```
Data akan muncul di URL seperti: `cari.php?q=laskar+pelangi&kategori=fiksi`

**Keuntungan:**
- Bisa di-bookmark
- Bisa di-share (URL menyimpan parameter)
- Tidak ada efek samping (idempotent)

**Kekurangan:**
- Data terlihat di URL (tidak aman)
- Terbatas (~2048 karakter)
- Tidak untuk data sensitif

**Cocok untuk:** Pencarian, filter, navigasi halaman

### POST
Data dikirim melalui **body HTTP request** (tidak terlihat di URL).
```html
<form method="POST" action="daftar.php">
```

**Keuntungan:**
- Data tidak terlihat di URL
- Tidak ada batasan ukuran
- Bisa upload file
- Lebih aman untuk data sensitif

**Kekurangan:**
- Tidak bisa di-bookmark
- Tidak bisa di-share via URL
- Halaman akan meminta konfirmasi jika di-refresh

**Cocok untuk:** Login, registrasi, upload file, data pribadi

### Tabel Perbandingan
| Aspek | GET | POST |
|-------|-----|------|
| Visibilitas data | URL (terlihat) | Body (tersembunyi) |
| Batasan ukuran | ~2048 karakter | Tidak ada batasan |
| Bookmark/Share | Bisa | Tidak bisa |
| Upload file | Tidak bisa | Bisa |
| Keamanan | Rendah | Sedang* |
| Cache | Bisa di-cache | Tidak di-cache |
| Gunakan untuk | Pencarian, filter | Login, daftar, upload |

*POST bukan jaminan aman — tetap perlu HTTPS untuk enkripsi.

## Contoh Kode Implementasi

```html
<!DOCTYPE html>
<html>
  <head>
    <title>GET vs POST</title>
  </head>
  <body>
    <h1>Perbedaan GET dan POST</h1>

    <h2>GET — Pencarian Buku</h2>
    <form method="GET" action="cari.php">
      <label for="q">Cari buku:</label>
      <input type="text" id="q" name="q" placeholder="Judul buku...">
      <label for="kategori">Kategori:</label>
      <select id="kategori" name="kategori">
        <option value="">Semua</option>
        <option value="fiksi">Fiksi</option>
        <option value="nonfiksi">Non Fiksi</option>
      </select>
      <button type="submit">Cari</button>
    </form>
    <p><small>Data akan muncul di URL setelah submit.</small></p>

    <h2>POST — Pendaftaran Anggota</h2>
    <form method="POST" action="daftar.php">
      <label for="nama">Nama:</label>
      <input type="text" id="nama" name="nama" required><br>
      <label for="email">Email:</label>
      <input type="email" id="email" name="email" required><br>
      <label for="pass">Password:</label>
      <input type="password" id="pass" name="pass" required><br>
      <button type="submit">Daftar</button>
    </form>
    <p><small>Data tidak terlihat di URL — lebih aman.</small></p>
  </body>
</html>
```

## Poin Penting
- **GET** = data di URL (pencarian, filter) — bisa di-bookmark
- **POST** = data di body (login, daftar, upload) — lebih aman
- Pilih sesuai kebutuhan: GET untuk baca, POST untuk tulis
- Tetap gunakan **HTTPS** untuk keamanan data
