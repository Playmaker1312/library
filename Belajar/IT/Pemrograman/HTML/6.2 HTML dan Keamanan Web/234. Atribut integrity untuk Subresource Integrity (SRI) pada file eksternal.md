# Atribut integrity untuk Subresource Integrity (SRI) pada File Eksternal

## Analogi: Perpustakaan Digital

Perpustakaan digital sering meminjam buku dari perpustakaan lain (CDN). Namun, bagaimana jika seseorang mengganti buku "JavaScript Dasar" dengan versi palsu yang berisi kode berbahaya di tengah perjalanan? Subresource Integrity (SRI) seperti segel keaslian pada buku: stempel hologram yang unik. Sebelum buku diberikan ke anggota, pustakawan memeriksa apakah segelnya cocok. Jika segel rusak atau berbeda, buku tersebut ditolak. Atribut `integrity` berisi hash kriptografis dari file yang sah. Browser akan menghitung hash file yang diterima dan membandingkannya — jika tidak cocok, file tidak akan digunakan.

## Penjelasan Detail

Subresource Integrity (SRI) adalah fitur keamanan yang memungkinkan browser memverifikasi bahwa file yang dimuat dari server pihak ketiga (atau CDN) belum dimodifikasi. Atribut `integrity` pada tag `<script>` atau `<link>` berisi hash base64 dari file (menggunakan algoritma sha256, sha384, atau sha512). Browser menghitung hash file yang diterima dan membandingkannya dengan nilai integrity; jika tidak cocok, browser memblokir eksekusi file. Untuk menghasilkan hash, gunakan alat online atau perintah `openssl dgst -sha384 -binary file.js | openssl base64 -A`. SRI sangat penting untuk melindungi dari serangan CDN compromise, di mana attacker berhasil memodifikasi file di server CDN. SRI bekerja paling baik bersama dengan CORS (atribut crossorigin) untuk resource dari origin yang berbeda.

## Poin Penting
- SRI tidak berguna jika resource dimuat dari domain yang sama (same-origin) — resource same-origin sudah tepercaya.
- Atribut `crossorigin` diperlukan bersama SRI untuk resource cross-origin; tanpa itu, SRI tidak akan berfungsi di beberapa browser.
- Jika SRI gagal, seluruh file diblokir — pastikan ada fallback yang memadai untuk fungsionalitas kritis.
