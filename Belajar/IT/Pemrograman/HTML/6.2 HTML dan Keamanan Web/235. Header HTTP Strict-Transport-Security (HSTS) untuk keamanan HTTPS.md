# Header HTTP Strict-Transport-Security (HSTS) untuk Keamanan HTTPS

## Analogi: Perpustakaan Digital

Perpustakaan digital memiliki dua pintu masuk: pintu biasa (HTTP) dan pintu aman (HTTPS). Tanpa HSTS, pengunjung bisa secara tidak sengaja masuk melalui pintu biasa yang tidak aman, di mana penjahat bisa menguping percakapan atau bahkan mengganti buku yang dibawa pulang. HSTS seperti memasang papan petunjuk besar di semua jalan menuju perpustakaan yang bertuliskan: "PERINGATAN: Semua pengunjung HARUS menggunakan pintu aman. Pintu biasa dilarang!" Setelah pengunjung pertama kali masuk melalui pintu aman, browser akan mengingatnya dan secara otomatis selalu menggunakan HTTPS untuk kunjungan berikutnya, bahkan jika pengunjung mengetik alamat biasa.

## Penjelasan Detail

Strict-Transport-Security (HSTS) adalah header HTTP yang memberitahu browser untuk hanya mengakses situs menggunakan HTTPS, bahkan ketika pengguna mengetik `http://` atau mengklik link HTTP. Header ini memiliki parameter `max-age` (durasi dalam detik browser harus mengingat kebijakan), `includeSubDomains` (terapkan ke semua subdomain), dan `preload` (daftarkan situs ke list HSTS preload browser). HSTS mencegah serangan downgrade attack, SSL stripping, dan cookie hijacking. Penting untuk menetapkan `max-age` yang wajar — mulai dari 1 jam saat pengujian, lalu tingkatkan ke 1 tahun setelah yakin semua subdomain sudah mendukung HTTPS. Daftar preload HSTS (hstspreload.org) memungkinkan browser memaksa HTTPS bahkan sebelum kunjungan pertama.

## Poin Penting
- HSTS hanya efektif setelah kunjungan pertama yang berhasil melalui HTTPS (kecuali menggunakan preload list).
- Jangan gunakan `includeSubDomains` jika ada subdomain yang belum mendukung HTTPS — subdomain tersebut akan menjadi tidak terjangkau.
- Setelah HSTS aktif dengan `max-age` panjang, browser akan menolak HTTP requests — pastikan konfigurasi benar sebelum menerapkan.
