# Layout Admin Dashboard

## Penjelasan

Layout admin dashboard adalah struktur kerangka utama dari sebuah panel administrasi. Ini adalah **ruang kontrol/command center** di dalam rumah — tempat semua monitor, panel saklar, dan lemari arsip ditata sedemikian rupa sehingga penghuni rumah bisa memantau dan mengendalikan seluruh isi rumah dari satu titik. Layout dashboard terdiri dari sidebar (panel saklar utama), topbar (panel notifikasi cepat), dan main content (area kerja utama).

Dalam konteks Bootstrap, layout ini menggunakan kombinasi `grid system`, `flexbox`, `viewport height`, dan `container-fluid` untuk menciptakan struktur yang kokoh, responsif, dan mudah dikelola.

## Fungsi

- Menyediakan struktur navigasi tetap (sidebar fixed) dan area konten utama
- Memisahkan area navigasi, kontrol, dan konten secara hierarkis
- Mendukung tampilan mobile dengan mengubah sidebar menjadi offcanvas
- Memberikan konsistensi halaman di seluruh bagian dashboard

## Analogi

**Rumah — Command Center / Ruang Kontrol**

- `#wrapper` (flex container) → **pondasi rumah** yang menopang seluruh struktur
- `sidebar` → **panel saklar utama** yang terpasang permanen di dinding, berisi semua tombol kontrol rumah
- `topbar` → **papan notifikasi cepat** di dekat pintu masuk, menampilkan informasi sekilas dan akses ke profil penghuni
- `#page-content` → **ruang keluarga + ruang kerja** tempat semua aktivitas pemantauan dilakukan
- `container-fluid` → **lantai yang fleksibel**, bisa muat furniture apa pun tanpa terbatas grid kaku
- `100vh` → **tinggi rumah** yang selalu penuh dari lantai dasar sampai plafon
- Sidebar offcanvas di mobile → **panel saklar portabel** yang bisa dilipat dan dibawa ke mana-mana saat ruangan sempit
- `sticky-top` pada topbar → **papan notifikasi yang tetap terlihat** walau penghuni sedang scroll laporan di meja kerja

## Dipakai untuk apa

Layout ini dipakai sebagai kerangka dasar untuk semua halaman admin, termasuk sistem informasi manajemen, CRM, ERP, analytics dashboard, panel hosting, CMS backend, dan aplikasi monitoring lainnya.

## Kesalahan umum yang sering terjadi

1. **Sidebar tidak fixed dan ikut ter-scroll** — menyebabkan pengguna harus scroll ke atas untuk navigasi. Solusi: gunakan `position: fixed` pada sidebar dan `margin-left` pada konten.
2. **Lupa menangani viewport height** — konten tidak memenuhi layar penuh, meninggalkan ruang kosong di bawah. Solusi: set `#wrapper { min-height: 100vh }`.
3. **Offcanvas tidak diinisialisasi JavaScript** — tombol toggle tidak berfungsi di mobile. Solusi: panggil `new bootstrap.Offcanvas(el)` di event listener.
4. **Sidebar dan konten tumpang tindih di mobile** — sidebar tetap terlihat walau layar sempit. Solusi: sembunyikan sidebar dengan `display: none` di breakpoint `md` dan tampilkan hanya offcanvas.
5. **Z-index tidak dikelola** — topbar menimpa sidebar atau sebaliknya. Solusi: atur `z-index: 1000` untuk sidebar, `z-index: 1020` untuk topbar (lebih tinggi karena sticky).

## Koneksi dengan materi sebelumnya

Di Bootstrap Level 1-3, Anda membangun komponen terisolasi (tombol, kartu, tabel). Di Level 4-6, Anda belajar grid system dan layout responsif. Level 7 menggabungkan semuanya: grid digunakan untuk mengatur posisi sidebar dan konten, flexbox (`d-flex`) untuk menyusun wrapper, utility spacing untuk padding yang presisi, dan offcanvas (dari Level 6) untuk navigasi mobile. Layout ini adalah **penerapan paling konkret dari seluruh materi Bootstrap sebelumnya**.

### Soal 2

Jelaskan mengapa `min-height: 100vh` penting untuk layout dashboard. Apa yang terjadi jika tidak digunakan?

<details>
<summary>Jawaban</summary>

`min-height: 100vh` memastikan wrapper dashboard selalu setinggi viewport penuh. Jika tidak digunakan, saat konten sedikit, sidebar dan latar belakang tidak menutupi seluruh layar sehingga terlihat "menggantung" — seperti rumah yang lantainya tidak mencapai dinding. Sebaliknya, jika konten banyak, `min-height` tetap aman karena elemen akan mengembang melebihi 100vh secara otomatis.

</details>

### Soal 3

Apa perbedaan `position: fixed` dan `position: sticky` pada konteks sidebar dan topbar?

<details>
<summary>Jawaban</summary>

- **Sidebar `fixed`**: selalu diam di posisinya meskipun halaman di-scroll. Cocok untuk navigasi utama yang harus selalu terlihat.
- **Topbar `sticky`**: diam saat elemen mencapai batas atas viewport, tapi tetap ikut dalam aliran halaman sebelum itu. Cocok untuk topbar yang tetap di atas saat konten di-scroll, tanpa mengganggu elemen lain di atasnya (jika ada). Pada dashboard, topbar sticky memungkinkan header tetap terlihat saat pengguna scroll tabel/grafik yang panjang.

</details>
