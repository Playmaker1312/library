# ARIA & Keyboard Navigation

## Penjelasan

ARIA (Accessible Rich Internet Applications) adalah atribut HTML yang membantu teknologi pembantu (screen reader) memahami elemen interaktif di halaman. Keyboard navigation memastikan semua fungsi bisa diakses hanya dengan keyboard (Tab, Enter, Escape, Arrow keys).

## Fungsi

- Memberi label pada elemen interaktif yang tidak memiliki teks visual
- Menginformasikan status elemen (expanded, selected, disabled) ke screen reader
- Memastikan navigasi logis dengan urutan tab yang benar
- Membuat modal, dropdown, carousel bisa dioperasikan keyboard

## Cara Pengimplementasian

```html
<!-- Skip link — langsung ke konten utama, skip navigasi -->
<a href="#main-content" class="visually-hidden-focusable">
  Langsung ke konten utama
</a>

<nav>
  <a href="#">Beranda</a>
  <a href="#">Tentang</a>
</nav>

<main id="main-content">
  <h1>Konten Utama</h1>
</main>

<!-- aria-label — tombol icon tanpa teks -->
<button aria-label="Tutup modal">
  ✕
</button>

<!-- aria-labelledby — grup input dengan label dari elemen lain -->
<h2 id="section-title">Data Diri</h2>
<div role="group" aria-labelledby="section-title">
  <label for="nama">Nama:</label>
  <input id="nama" type="text">
</div>

<!-- aria-describedby — deskripsi tambahan -->
<label for="password">Password:</label>
<input id="password" type="password" aria-describedby="password-hint">
<span id="password-hint">Minimal 8 karakter, kombinasi huruf dan angka</span>

<!-- Role atribut — landmark -->
<header role="banner">...</header>
<nav role="navigation">...</nav>
<main role="main">...</main>
<footer role="contentinfo">...</footer>

<!-- Focus trap modal — menggunakan Bootstrap modal -->
<div class="modal" tabindex="-1" role="dialog" aria-modal="true"
     aria-labelledby="modal-title">
  <div class="modal-dialog" role="document">
    <div class="modal-content">
      <div class="modal-header">
        <h5 id="modal-title">Konfirmasi</h5>
        <button type="button" class="btn-close" aria-label="Tutup"></button>
      </div>
      <div class="modal-body">
        <p>Apakah Anda yakin?</p>
      </div>
      <div class="modal-footer">
        <button class="btn btn-secondary" data-bs-dismiss="modal">Batal</button>
        <button class="btn btn-primary">Ya, Hapus</button>
      </div>
    </div>
  </div>
</div>

<!-- Keyboard navigation untuk custom dropdown -->
<div class="dropdown" role="listbox" tabindex="0" aria-label="Pilih warna"
     @keydown.enter="open" @keydown.escape="close"
     @keydown.down.prevent="nextItem" @keydown.up.prevent="prevItem">
  <div role="option" aria-selected="true">Merah</div>
  <div role="option" aria-selected="false">Biru</div>
  <div role="option" aria-selected="false">Hijau</div>
</div>
```

```html
<!-- Contoh implementasi skip link di Bootstrap -->
<style>

  }

```

## Analogi

ARIA = **papan braille/tanda tunanetra di rumah**. Tombol ✕ tanpa teks diberi `aria-label="Tutup"` seperti papan braille yang mengatakan "ini tombol tutup pintu". `role="navigation"` seperti tanda di pintu yang mengatakan "ini ruang tamu". `aria-expanded` seperti sensor pintu yang memberitahu "pintu terbuka/tertutup". Focus trap modal seperti ruangan yang pintunya terkunci — Anda tidak bisa Tab keluar sampai memutuskan.

## Dipakai untuk apa

- Skip link untuk pengguna screen reader agar cepat ke konten
- Tombol ikon (hamburger, close, search) tanpa teks visual
- Dropdown kustom yang bisa dioperasikan keyboard
- Modal dengan focus trap — Tab tidak keluar dari modal
- Validasi form yang dibacakan screen reader

## Kesalahan umum yang sering terjadi

- **ARIA overuse** — "No ARIA is better than bad ARIA." Jangan pakai ARIA jika HTML native sudah cukup (pakai `<nav>` saja, bukan `<div role="navigation">`)
- **Lupa fokus manajemen** — Modal terbuka tapi fokus tidak pindah ke dalam modal
- **Label tidak sinkron** — `aria-labelledby` pointing ke ID yang tidak ada
- **Keyboard trap tanpa escape** — User terjebak di elemen dan tidak bisa keluar
- **Mengabaikan urutan tab** — `tabindex` > 0 mengacaukan urutan navigasi alami

## Koneksi dengan materi sebelumnya

Setelah mengatur tampilan responsif (materi 34-36), kini kita memastikan website bisa diakses semua orang termasuk pengguna screen reader dan keyboard-only. Ini adalah lapisan aksesibilitas di atas fondasi responsif.

## Soal latihan & jawaban

**Soal 1:** Kapan sebaiknya menggunakan `<nav>` vs `<div role="navigation">`?

**Jawaban:** Gunakan `<nav>` (HTML native) karena lebih semantik dan sudah memiliki implied role "navigation". ARIA hanya diperlukan jika elemen HTML tidak menyediakan semantik yang dibutuhkan.

**Soal 2:** Apa fungsi `aria-describedby` pada elemen input?

**Jawaban:** Menghubungkan input dengan elemen deskripsi (misal petunjuk format, error message) sehingga screen reader membacakannya saat input mendapat fokus.

**Soal 3:** Lengkapi kode berikut dengan atribut ARIA yang tepat:
```html
<button>☰</button>
```

**Jawaban:**
```html
<button aria-label="Buka menu navigasi">☰</button>
```
