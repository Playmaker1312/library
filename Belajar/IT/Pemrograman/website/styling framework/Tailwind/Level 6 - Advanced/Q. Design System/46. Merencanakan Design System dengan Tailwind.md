# Merencanakan Design System dengan Tailwind

## Penjelasan

- Design System adalah kumpulan standar visual dan komponen yang dipakai konsisten di seluruh project. Dengan Tailwind, design system bisa didokumentasikan dalam satu file HTML (`design-system.html`) yang berfungsi sebagai *living documentation*.
- Dokumen ini mencakup: palet warna (solid, hover, state), tipografi (heading, body, font scale), spacing (margin, padding, gap), dan komponen (button, card, form, navigation).
- Setiap elemen ditampilkan langsung dengan kode Tailwind-nya, sehingga tim tinggal *copy-paste* utility class yang sudah ditentukan.
- Pendekatan ini memastikan konsistensi visual tanpa perlu menulis CSS kustom.
- Design system bisa diperluas dengan `@theme` di v4 atau `tailwind.config.js` di v3 untuk menstandarisasi nilai-nilai kustom.

## Fungsi

Menjadi satu sumber kebenaran (single source of truth) untuk semua keputusan desain di project. Mempercepat development karena komponen sudah siap pakai, mengurangi inkonsistensi antar halaman, dan memudahkan onboarding anggota tim baru.

## Analogi

Design system adalah seperti katalog showroom rumah contoh. Di showroom, semua model rumah dipajang lengkap dengan spesifikasi: warna cat, jenis lantai, ukuran ruangan, merek lampu. Pembeli tinggal memilih dan memberi tahu kontraktor "saya mau rumah tipe A dengan warna cat seperti contoh nomor 3". Tanpa katalog, setiap pembeli harus menjelaskan detail satu per satu dan hasilnya bisa berbeda. Design system adalah katalog itu untuk front-end.

## Dipakai untuk Apa

- Project dengan tim lebih dari 1 developer front-end.
- Aplikasi berskala besar yang punya banyak halaman dan komponen.
- Produk yang perlu menjaga konsistensi brand secara ketat.
- Saat ingin mempercepat proses desain-ke-kode dengan referensi visual yang sudah siap.

## Kesalahan Umum yang Sering Terjadi

- Design system tidak pernah diperbarui sehingga tidak sinkron dengan kode produksi.
- Membuat terlalu banyak varian komponen yang jarang dipakai, membuat dokumen membengkak.
- Tidak menyertakan state seperti hover, focus, disabled, error.
- Hanya fokus pada visual, lupa dokumentasi kapan menggunakan komponen A vs B.
- Menggunakan utility class yang sudah di-override di config sehingga tidak konsisten dengan produksi.

## Koneksi dengan Materi Sebelumnya

Di Level 4 kamu belajar membuat komponen seperti card, navbar, modal. Di Level 5 kamu belajar organisasi komponen reusable. Sekarang semua komponen itu diorganisir dalam satu sistem terpadu yang didokumentasikan secara visual. v4 memberikan `@theme` untuk menstandarisasi nilai-nilai kustom, dan container queries dari materi sebelumnya memastikan komponen adaptif di berbagai layout dalam sistem ini.

Setiap alert harus punya ikon (gunakan karakter teks biasa seperti "!", "i", "x"), judul, dan teks deskripsi. Tampilkan kode utility class di bawah setiap varian.
