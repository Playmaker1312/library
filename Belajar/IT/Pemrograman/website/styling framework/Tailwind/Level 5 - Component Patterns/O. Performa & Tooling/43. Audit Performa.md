# Audit Performa

## Penjelasan
- Target utama Tailwind di produksi: ukuran file CSS gzip kurang dari 30KB. Ini sangat kecil untuk framework CSS dan merupakan salah satu keunggulan Tailwind.
- **Content config** adalah kunci performa. Tailwind menggunakan teknik tree-shaking: hanya class yang ditemukan di file dalam path `content` yang akan masuk ke CSS final. Jika config `content` tidak tepat, class bisa hilang atau CSS membengkak.
- **Lighthouse Audit** adalah alat dari Chrome DevTools untuk mengukur performa, aksesibilitas, SEO, dan best practices. Skor performa dipengaruhi oleh ukuran CSS, waktu render, dan JavaScript.
- **Purge optimization** adalah proses menghapus utility yang tidak terpakai. Tailwind versi 3+ menggunakan JIT engine yang melakukan ini secara real-time saat development dan otomatis saat build.
- Cara kerja JIT: Tailwind membaca file di `content`, mencari string yang cocok dengan pattern class Tailwind, lalu generate CSS hanya untuk class itu.
- Debug class hilang: jika class Tailwind tidak muncul di hasil build, periksa apakah file tempat class itu ditulis sudah termasuk dalam `content` config.

## Fungsi
- Memastikan ukuran CSS final sangat kecil (<30KB gzip) sehingga website cepat dimuat
- Mengoptimalkan konfigurasi content agar tidak ada class yang terlewat
- Mengaudit performa dengan Lighthouse untuk mengidentifikasi bottleneck
- Mendebug class yang hilang saat build produksi
- Memahami cara kerja JIT engine Tailwind agar bisa memaksimalkannya

## Analogi
Content config seperti gerbang masuk gedung — hanya orang yang namanya tercantum di daftar yang boleh masuk. Jika nama tidak ada di daftar (file tidak di content path), orang itu tidak akan masuk ke dalam gedung (CSS tidak digenerate). JIT engine Tailwind seperti satpam yang super efisien: dia hanya mengizinkan orang yang benar-benar dibutuhkan, tidak ada yang nganggur di dalam. Target 30KB gzip seperti membawa satu tas kecil untuk perjalanan — kamu hanya bawa yang esensial, tidak ada yang mubazir.

## Dipakai untuk Apa
- Build produksi untuk semua project Tailwind
- Audit rutin sebelum deploy ke production
- Debugging ketika ada style yang tidak muncul di production tapi muncul di development
- Optimasi performa website untuk mencapai skor Lighthouse 90+
- CI/CD pipeline yang memeriksa ukuran CSS agar tidak membengkak

## Kesalahan Umum yang Sering Terjadi
- Content path tidak mencakup semua direktori yang menggunakan Tailwind — class hilang di production
- Menggunakan string dinamis untuk class Tailwind (contoh: `text-${color}-500`) — JIT tidak bisa membaca variable runtime
- Lupa menjalankan build produksi sebelum deploy — file development (400KB+) ikut terkirim
- Menambahkan class ke safelist secara berlebihan — membengkakkan ukuran CSS
- Tidak memeriksa ukuran gzip, hanya ukuran raw — file 200KB raw bisa jadi hanya 20KB gzip
- Class hilang karena typo: `text-whit` bukan `text-white` — tidak akan dianggap error, hanya tidak muncul
- Menggunakan framework yang build-nya berbeda cara (Next.js, Vite, Laravel Mix) — cek dokumentasi masing-masing

## Koneksi dengan Materi Sebelumnya
Seluruh Level 1-4 membangun kebiasaan menggunakan Tailwind dengan benar. Level 5 mengajarkan cara mengelola komponen (cn(), @apply), aksesibilitas (sr-only, motion-reduce), tooling (Prettier), dan sekarang audit performa. Semua ini adalah jembatan menuju production. Ukuran CSS <30KB adalah bukti bahwa utility-first bekerja: kamu mendapat konsistensi framework tanpa membayar mahal di ukuran file.

## Soal Latihan
Kamu memiliki project dengan struktur folder: `src/pages/`, `src/components/`, `src/lib/`, `src/data/` (berisi file JSON). Di file `src/lib/colors.js`, ada fungsi yang mengembalikan class seperti `bg-${color}-500`. Sebutkan:
1. Bagaimana config content yang benar?
2. Apa yang harus dilakukan agar class dinamis di `colors.js` tetap muncul di production?
3. Perintah untuk cek ukuran CSS hasil build.

1. **Config content:**
```js
// tailwind.config.js
module.exports = {
  content: [
    "./src/pages/**/*.{js,jsx,ts,tsx}",
    "./src/components/**/*.{js,jsx,ts,tsx}",
    "./src/lib/**/*.{js,jsx,ts,tsx}",
    "./src/data/**/*.json",
  ],
  // ...
};
```

2. **Class dinamis di colors.js:**
Karena class seperti `bg-${color}-500` tidak bisa dideteksi JIT (variabel runtime), gunakan safelist:
```js
module.exports = {
  // ...
  safelist: [
    { pattern: /bg-(red|green|blue|yellow|purple)-(500|600|700)/ },
    { pattern: /text-(red|green|blue|yellow|purple)-(500|600|700)/ },
  ],
};
```
Atau, jika hanya beberapa warna, tulis eksplisit:
```js
safelist: [
  "bg-red-500", "bg-green-500", "bg-blue-500",
  "text-red-500", "text-green-500", "text-blue-500",
],
```

3. **Cek ukuran CSS:**
```bash
# Jika menggunakan Next.js
Get-ChildItem -LiteralPath ".next\static\css" -Recurse -Filter "*.css" |
  Select-Object Name, @{N="SizeKB";E={[math]::Round($_.Length/1KB, 2)}}

# Untuk cek ukuran gzip (estimasi):
Get-ChildItem -LiteralPath ".next\static\css" -Recurse -Filter "*.css" |
  ForEach-Object {
    $content = Get-Content $_.FullName -Raw
    $bytes = [System.Text.Encoding]::UTF8.GetBytes($content)
    $stream = New-Object System.IO.MemoryStream
    $gzip = New-Object System.IO.Compression.GZipStream($stream, [System.IO.Compression.CompressionMode]::Compress)
    $gzip.Write($bytes, 0, $bytes.Length)
    $gzip.Close()
    $compressedSize = [math]::Round($stream.Length / 1KB, 2)
    $rawSize = [math]::Round($_.Length / 1KB, 2)
    Write-Output "$($_.Name): Raw=${rawSize}KB, Gzip≈${compressedSize}KB"
  }
```
