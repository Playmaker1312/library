# Mengapa Framework

## Penjelasan
Framework (seperti React, Vue, Angular) adalah kerangka kerja yang menyediakan struktur, aturan, dan alat bantu untuk membangun aplikasi JavaScript yang kompleks. Framework menyediakan solusi untuk masalah umum seperti manipulasi DOM, state management, routing, dan reaktivitas. Alasan utama menggunakan framework adalah untuk menulis kode yang lebih terstruktur, mudah dirawat, dan skalabel.

## Fungsi
- Abstraksi DOM — tidak perlu manual manipulasi DOM (seperti di Level 6)
- Reaktivitas — UI otomatis diperbarui saat data berubah
- Struktur proyek yang konsisten — mudah dipahami developer lain
- Ecosystem tools — routing, state management, testing built-in/terintegrasi
- Performa optimal — virtual DOM, tree shaking, code splitting otomatis

## Cara Pengimplementasian

```html
<!-- Tanpa Framework — seperti bangun rumah dari nol -->
<!DOCTYPE html>
<html>
<body>
  <div id="app"></div>
  <script>
    // Harus manual — update DOM, handle event, tracking state
    let counter = 0;
    const app = document.getElementById('app');
    app.innerHTML = `
      <h1>Rumah Saya</h1>
      <p>Kamar: ${counter}</p>
      <button id="tambah">Tambah Kamar</button>
    `;
    document.getElementById('tambah').onclick = () => {
      counter++;
      app.innerHTML = `
        <h1>Rumah Saya</h1>
        <p>Kamar: ${counter}</p>
        <button id="tambah">Tambah Kamar</button>
      `;
      // Harus re-attach event listener! Repot.
    };
  </script>
</body>
</html>
```

```javascript
// Dengan Framework (React) — seperti beli rumah siap huni
// import { useState } from 'react';

function RumahSaya() {
  const [kamar, setKamar] = useState(0);
  // state otomatis dilacak, UI update otomatis
  return (
    <div>
      <h1>Rumah Saya</h1>
      <p>Kamar: {kamar}</p>
      <button onClick={() => setKamar(kamar + 1)}>Tambah Kamar</button>
    </div>
  );
  // Tidak perlu innerHTML, tidak perlu re-attach event.
  // Framework urus semuanya.
}
```

## Analogi
Framework = **rumah siap huni** vs **bangun dari nol**. Tanpa framework, kamu seperti membangun rumah dari nol: harus buat fondasi sendiri (setup proyek), pasang pipa sendiri (routing), pasang listrik sendiri (state management), buat pintu sendiri (event handling). Dengan framework, kamu dapat rumah siap huni: fondasi sudah kuat, listrik sudah terpasang, pipa sudah mengalir. Kamu tinggal masuk dan atur dekorasi sesuai selera (tulis komponen aplikasi). Tapi rumah siap huni punya aturan: tidak bisa sembarang pindah tembok (ikuti pola framework). Bangun dari nol lebih bebas, tapi butuh waktu dan keahlian lebih.

## Dipakai Untuk Apa
- Single Page Application (SPA) — aplikasi yang tidak reload halaman
- Aplikasi dengan state kompleks (dashboard, e-commerce, sosial media)
- Proyek tim besar — butuh struktur dan konsistensi
- Aplikasi real-time — framework punya mekanisme reaktivitas bawaan

## Kesalahan Umum
1. **Framework dulu, belajar JS belakangan** — tanpa fondasi JS yang kuat, debugging framework jadi sulit
2. **Terlalu besar untuk kebutuhan** — untuk landing page sederhana, framework malah overkill
3. **Terlalu bergantung pada magic** — tidak paham konsep dasar (virtual DOM, reactivity) menyebabkan bug misterius
4. **Gonta-ganti framework** — setiap framework punya filosofi berbeda; kuasai satu dulu
5. **Mengabaikan bundle size** — framework + library bisa jadi bundle besar tanpa optimasi

## Keterkaitan dengan Materi Sebelumnya
Semua Level 1-8 adalah fondasi untuk memahami framework. Level 1-2 (dasar JS, struktur data) untuk logika komponen. Level 3 (fungsi, scope, closure) — hooks di React adalah closure. Level 4 (OOP, class, prototype) — class component di React, definisi komponen di Angular. Level 5 (async, promise, event loop) — fetch data di komponen, state async. Level 6 (DOM manipulation) — framework menghapus kebutuhan manual DOM, tapi tetap perlu paham DOM untuk debugging. Level 7 (module, tooling) — framework menggunakan Webpack/Vite. Level 8 (pattern, performa) — framework sudah menerapkan pattern dan optimasi ini.

## Soal Latihan

Apa keuntungan utama framework dibanding vanilla JavaScript untuk aplikasi dengan 50+ komponen?

>!Keteraturan struktur, reaktivitas otomatis (tidak perlu innerHTML manual), performa dengan virtual DOM, state management terpusat, dan ecosystem tooling. Vanilla JS akan kesulitan menjaga konsistensi data dan event binding di 50+ komponen.!
