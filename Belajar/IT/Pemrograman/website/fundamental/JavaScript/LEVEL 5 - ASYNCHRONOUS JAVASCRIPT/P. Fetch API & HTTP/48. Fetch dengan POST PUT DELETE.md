# 48. Fetch dengan POST PUT DELETE

## Penjelasan
HTTP memiliki beberapa method utama untuk berinteraksi dengan resource di server: **GET** (mengambil data), **POST** (membuat data baru), **PUT** (mengupdate data — mengganti seluruhnya), **PATCH** (mengupdate data — mengubah sebagian), dan **DELETE** (menghapus data). Dengan Fetch API, method ini ditentukan melalui opsi `method` di parameter kedua `fetch(url, options)`. Data dikirim melalui `body` (untuk POST/PUT/PATCH) dan biasanya dalam format JSON.

## Fungsi
POST/PUT/DELETE memungkinkan aplikasi web melakukan operasi CRUD (Create, Read, Update, Delete) penuh terhadap data di server. Ini memungkinkan fitur seperti: membuat akun baru (POST), mengedit profil (PUT/PATCH), menghapus postingan (DELETE), menambahkan komentar (POST), dan semua interaksi tulis lainnya dengan server.

## Cara Pengimplementasian
```js
const BASE_URL = "https://jsonplaceholder.typicode.com";

// POST — membuat resource baru
async function tambahRumah(dataRumah) {
  try {
    const response = await fetch(`${BASE_URL}/posts`, {
      method: "POST",
      headers: {
        "Content-Type": "application/json"
      },
      body: JSON.stringify(dataRumah)
    });

    if (!response.ok) throw new Error(`Gagal: ${response.status}`);

    const result = await response.json();
    console.log("Rumah baru dibuat:", result);
    return result;
  } catch (error) {
    console.error("Error POST:", error.message);
  }
}

tambahRumah({
  title: "Rumah Baru",
  body: "Rumah di pinggir danau dengan 3 kamar",
  userId: 1
});
```

```js
// PUT — mengupdate seluruh resource
async function updateRumah(id, dataBaru) {
  const response = await fetch(`${BASE_URL}/posts/${id}`, {
    method: "PUT",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(dataBaru)
  });
  return response.json();
}

updateRumah(1, {
  title: "Rumah Diperbarui",
  body: "Sudah direnovasi total",
  userId: 1
}).then(console.log);
```

```js
// DELETE — menghapus resource
async function hapusRumah(id) {
  try {
    const response = await fetch(`${BASE_URL}/posts/${id}`, {
      method: "DELETE"
    });

    if (response.ok) {
      console.log(`Rumah ${id} berhasil dihapus`);
    } else {
      console.log(`Gagal menghapus rumah ${id}`);
    }
  } catch (error) {
    console.error("Error DELETE:", error.message);
  }
}

hapusRumah(1);
```

```js
// PATCH — update sebagian (berbeda dengan PUT yang mengganti seluruhnya)
async function patchRumah(id, dataSebagian) {
  const response = await fetch(`${BASE_URL}/posts/${id}`, {
    method: "PATCH",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(dataSebagian)
  });
  return response.json();
}

patchRumah(1, { title: "Judul Rumah Diubah Saja" }).then(console.log);
```

## Analogi
**Method HTTP = cara pemilik rumah berinteraksi dengan tukang/toko bangunan:**
- **GET** = "Tolong cek, apakah cat sudah tersedia di toko?" — hanya lihat, tidak mengubah apapun
- **POST** = "Tolong buatkan lemari baru dengan ukuran 2x3 meter." — membuat resource baru
- **PUT** = "Ganti total lemari lama dengan yang baru, desain berbeda." — mengganti resource seluruhnya
- **PATCH** = "Tolong ganti gagang pintu lemari itu saja." — mengubah sebagian resource
- **DELETE** = "Lemari ini sudah tidak dipakai, tolong dibongkar dan dibuang." — menghapus resource

## Dipakai Untuk Apa
POST untuk registrasi akun, upload foto, tambah produk ke keranjang. PUT untuk edit profil (semua field diupdate). PATCH untuk ganti password saja atau toggle status. DELETE untuk hapus akun, hapus komentar, hapus postingan. Method-method ini adalah standar REST API dan dipakai di hampir semua backend modern.

## Kesalahan Umum
Lupa `JSON.stringify()` pada body — Fetch mengirim sebagai string `[object Object]`. Lupa header `Content-Type: application/json` — server tidak tahu format data yang dikirim. Mengirim data dengan format salah (string vs number). Mengira response.json() langsung mengembalikan data — padahal return-nya Promise. Juga: error handling tidak konsisten — beda endpoint pakai pola error handling yang berbeda.

## Keterkaitan dengan Materi Sebelumnya
Di Level 4 (class, OOP), kamu bisa membuat class Repository yang mengabstraksi CRUD dengan Fetch:
```js
class RumahRepository {
  constructor(baseURL) { this.baseURL = baseURL; }

  async getAll()   { return (await fetch(this.baseURL)).json(); }
  async getById(id){ return (await fetch(`${this.baseURL}/${id}`)).json(); }
  async create(data){ return (await fetch(this.baseURL, {
    method: "POST", headers: {"Content-Type":"application/json"},
    body: JSON.stringify(data)
  })).json(); }
  async update(id, data){ return (await fetch(`${this.baseURL}/${id}`, {
    method: "PUT", headers: {"Content-Type":"application/json"},
    body: JSON.stringify(data)
  })).json(); }
  async delete(id){ return (await fetch(`${this.baseURL}/${id}`, {
    method: "DELETE"
  })).ok; }
}
```
Ini adalah pola Repository yang menggabungkan OOP (Level 4) dengan HTTP methods (Level 5).

```js
async function kirimLaporan(judul, isi) {
  try {
    const res = await fetch("https://jsonplaceholder.typicode.com/posts", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({
        title: judul,
        body: isi,
        userId: 1
      })
    });

    const data = await res.json();
    console.log("Laporan terkirim:", data);
    return data;
  } catch (err) {
    console.error("Gagal kirim:", err);
  }
}

kirimLaporan("Kebocoran Pipa", "Pipa air di kamar mandi bocor");
// Output: Laporan terkirim: { title: "Kebocoran Pipa", body: "...", userId: 1, id: 101 }
```
