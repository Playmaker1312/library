# ES Modules — import & export

## Penjelasan
ES Modules (ECMAScript Modules) adalah sistem modular resmi di JavaScript yang memungkinkan pemisahan kode ke dalam file-file terpisah (module). Setiap module memiliki scope sendiri — variabel dan fungsi di dalamnya tidak bocor ke global secara otomatis. Untuk berbagi kode antar module, digunakan keyword `export` dan `import`.

## Fungsi
- Memecah kode besar menjadi potongan kecil yang terkelola (separation of concerns)
- Menghindari polusi global scope
- Memungkinkan *tree shaking* (penghapusan kode tak terpakai) oleh bundler
- Memberi kontrol eksplisit terhadap apa yang publik vs privat

## Cara Pengimplementasian
```js
// 📁 rumah.js — bagian dari rumah yang "dieksekpos" ke luar

// named export — seperti beberapa pintu dan jendela yang bisa diakses
export const luasTanah = 120;
export function bukaPintu() {
  return "Pintu terbuka";
}
export class Kamar {
  constructor(nama) {
    this.nama = nama;
  }
}

// default export — seperti pintu utama rumah
export default class Rumah {
  constructor(alamat) {
    this.alamat = alamat;
  }
}

// 📁 main.js — orang luar yang masuk ke dalam rumah

// import default (pintu utama) + named (pintu/jendela lain)
import Rumah, { luasTanah, bukaPintu, Kamar } from "./rumah.js";

const rmh = new Rumah("Jl. Merdeka No.1");
console.log(rmh.alamat);        // Jl. Merdeka No.1
console.log(luasTanah);         // 120
console.log(bukaPintu());      // Pintu terbuka

// import semua — seperti melihat denah seluruh rumah
import * sebagai RumahPackage from "./rumah.js";
console.log(RumahPackage.luasTanah); // 120

// rename import — memberi nama ulang akses masuk
import { Kamar sebagai Ruang } from "./rumah.js";
const tidur = new Ruang("Kamar Tidur");
```

### Variasi Export
```js
// Export di akhir file (seperti mendaftarkan semua akses di papan nama)
const dapur = "Granit";
const taman = 40;
export { dapur, taman };

// Export dengan alias (mengganti nama pintu)
const fungsiRahasia = () => "boo";
export { fungsiRahasia sebagai rahasia };
```

## Analogi
Sebuah **RUMAH** memiliki berbagai ruangan. `export` ibarat membuat pintu atau jendela agar isi ruangan bisa diakses dari luar. `default export` adalah **pintu utama** — satu akses utama yang paling natural digunakan. `named export` adalah **pintu samping, pintu belakang, dan jendela** — setiap akses punya nama spesifik. `import` adalah **seseorang dari luar yang masuk** melalui pintu tersebut. `import * as` adalah **menerima denah lengkap** seluruh akses rumah sekaligus. `import { sesuatu as alias }` adalah **mengganti papan nama pintu** sebelum masuk.

| Konsep | Analogi Rumah |
|---|---|
| Module | Satu rumah utuh |
| `export default` | Pintu utama (hanya satu) |
| `export` (named) | Pintu samping / jendela (banyak) |
| `import` | Orang masuk melalui pintu tertentu |
| `import * as` | Menerima peta semua akses rumah |
| `as` alias | Mengganti nama papan di pintu |

## Dipakai Untuk Apa
- Membagi kode frontend (React/Vue/Vanilla) ke dalam komponen, utils, dan hooks
- Menulis library atau package yang ekspos API terbatas
- Backend Node.js modern — menggantikan `require()` di CommonJS
- Semua proyek JavaScript modern yang menggunakan bundler (Vite, Webpack, Rollup)

## Kesalahan Umum
- Lupa menambahkan `type="module"` di tag `<script>` HTML — browser tidak kenali `import`/`export`
- Menggunakan `export default` lebih dari satu kali dalam satu file (hanya satu default diperbolehkan)
- Mencoba `import` tanpa export — akan error karena module kosong/tak punya akses
- Salah path: `./` atau `../` harus ditulis dengan benar — browser/resolver tidak otomatis menebak
- Mengira `import` itu destructuring — `import { a }` berbeda sintaks dari `const { a } = obj`

## Keterkaitan dengan Materi Sebelumnya
- **LEVEL 1 (Fundamental)**: Variabel (`let`, `const`) sekarang di-scope per module, bukan global
- **LEVEL 2 (Function)**: Fungsi yang di-export bisa dipanggil dari module lain — seperti memanggil tukang dari luar rumah
- **LEVEL 3 (Object & Array)**: Destructuring mirip sintaks `import { ... }`, tapi berbeda konteks
- **LEVEL 4 (DOM)**: `<script type="module">` adalah gerbang agar browser mengenali ES Module
- **LEVEL 5 (Asynchronous)**: Module di-load secara asynchronous; `import()` adalah pintu dinamis
- **LEVEL 6 (OOP)**: Class yang di-export bisa di-import dan di-extend di module lain — seperti cetak biru rumah dibawa ke luar

## Soal Latihan
1. Buat file `kamar.js` yang mengekspor class `Kamar` (default) dan fungsi `bersihkanKamar()` (named). Lalu import keduanya di `main.js`.

>!jawaban: ```js
>! // kamar.js
>! export default class Kamar {
>!   constructor(nama) { this.nama = nama; }
>! }
>! export function bersihkanKamar() { return "Kamar dibersihkan"; }
>!
>! // main.js
>! import Kamar, { bersihkanKamar } from "./kamar.js";
>! const k = new Kamar("Tidur");
>! console.log(k.nama);           // Tidur
>! console.log(bersihkanKamar()); // Kamar dibersihkan
>! ```
>!</details>

2. Apa beda `export default` dan `export` named? Mengapa dalam satu module hanya boleh satu default?

>!jawaban: `export default` adalah ekspor utama (pintu utama) — satu module hanya boleh memiliki satu pintu utama agar tidak ambigu saat di-import tanpa kurung kurawal. `export` named bisa banyak (pintu samping). Saat import, default tidak pakai `{}`, named wajib pakai `{}`.!
