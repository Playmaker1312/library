# ESLint & Prettier

## Penjelasan
**ESLint** adalah linter untuk JavaScript — alat yang menganalisis kode untuk menemukan masalah (error, bug, style yang tidak konsisten) tanpa menjalankannya. ESLint menggunakan aturan (rules) yang bisa dikonfigurasi. **Prettier** adalah formatter kode — alat yang secara otomatis memformat kode agar konsisten dalam hal indentasi, spasi, tanda kutip, titik koma, dll. Keduanya sering digunakan bersama: ESLint untuk kualitas kode (logic), Prettier untuk gaya kode (formatting).

## Fungsi
**ESLint:**
- Menangkap error sebelum runtime (misal variabel tidak terdefinisi, fungsi tidak dipanggil)
- Menegakkan best practices dan coding standards tim
- Mengotomatiskan code review untuk masalah umum

**Prettier:**
- Menghilangkan debat style (spasi vs tab, titik koma vs tidak)
- Memformat kode otomatis — simpan file, kode rapi
- Mendukung banyak bahasa (JS, TS, CSS, HTML, JSON, Markdown, YAML)

## Cara Pengimplementasian

### Setup ESLint
```bash
# Install ESLint (seperti memasang alat inspeksi rumah)
npm install --save-dev eslint

# Init konfigurasi (isi formulir aturan rumah)
npx eslint --init
# Atau buat manual: .eslintrc.json / eslint.config.js (Flat Config)
```

### Konfigurasi ESLint — Flat Config (eslint.config.js)
```js
// eslint.config.js — papan aturan rumah
export default [
  {
    rules: {
      "no-unused-vars": "error",     // Tak boleh ada material tak terpakai
      "no-console": "warn",          // Peringatan jika ada console.log
      "eqeqeq": "error",             // Wajib === bukan ==
      "semi": ["error", "always"],   // Wajib titik koma
      "quotes": ["error", "double"], // Kutipan harus double
    },
  },
];
```

### Setup Prettier
```bash
npm install --save-dev prettier

# Konfigurasi (opsional)
echo '{ "semi": true, "singleQuote": false, "tabWidth": 2 }' > .prettierrc
```

### Integrasi ESLint + Prettier
```bash
# Install plugin agar aturan Prettier tidak bertabrakan dengan ESLint
npm install --save-dev eslint-config-prettier eslint-plugin-prettier
```

```js
// eslint.config.js dengan integrasi Prettier
import js from "@eslint/js";
import prettier from "eslint-config-prettier";

export default [
  js.configs.recommended,
  prettier, // Matikan aturan ESLint yang bentrok dengan Prettier
  {
    rules: {
      "no-unused-vars": "error",
      "no-console": "warn",
    },
  },
];
```

### Script di package.json
```json
{
  "scripts": {
    "lint": "eslint src/",                   // Inspeksi seluruh ruangan
    "lint:fix": "eslint src/ --fix",          // Inspeksi + perbaiki otomatis
    "format": "prettier --write src/",        // Rapikan seluruh ruangan
    "format:check": "prettier --check src/"   // Cek tanpa menulis
  }
}
```

### Integrasi dengan Editor (VS Code)
```json
// .vscode/settings.json — aturan rumah untuk semua penghuni
{
  "editor.formatOnSave": true,
  "editor.defaultFormatter": "esbenp.prettier-vscode",
  "eslint.validate": ["javascript"],
  "editor.codeActionsOnSave": {
    "source.fixAll.eslint": true
  }
}
```

### Ignore File
```
# .eslintignore — ruangan yang tidak perlu diinspeksi
dist/
node_modules/
*.min.js

# .prettierignore — ruangan yang tidak perlu dirapikan
dist/
node_modules/
package-lock.json
```

## Analogi
**RUMAH** perlu dijaga kebersihan dan kerapiannya. **ESLint** adalah **inspektur rumah** yang berjalan keliling memeriksa: "Ada kabel terbuka di sini (error: unused variable)!" dan "Ini pintu berderit (warning: console.log di production)". **Prettier** adalah **tukang rapih** yang membereskan semua: merapikan karpet (indentasi), menyusun bantal (spasi), memastikan semua bingkai foto lurus (tanda kutip konsisten). Keduanya bekerja sama: inspektur memberi tahu masalah, tukang rapih memperbaiki tampilan. `.eslintrc` adalah **buku panduan inspeksi**. `.prettierrc` adalah **standar dekorasi rumah**. `eslint --fix` dan `prettier --write` adalah **tukang yang langsung merapikan** tanpa perlu disuruh ulang.

| Konsep | Analogi Rumah |
|---|---|
| ESLint | Inspektur rumah |
| Prettier | Tukang rapih interior |
| `eslintrc` | Buku panduan inspeksi |
| `.prettierrc` | Standar dekorasi rumah |
| `eslint --fix` | Inspektur sekaligus tukang |
| `formatOnSave` | Otomatis rapih setiap selesai di ruangan |
| Ignore file | Ruangan/area yang dikecualikan |
| VS Code settings | Aturan bersama untuk seluruh penghuni |

## Dipakai Untuk Apa
- Menjaga konsistensi kode di tim developer (semua pakai aturan yang sama)
- CI/CD pipeline — menjalankan `lint` dan `format:check` sebelum merge PR
- Onboarding developer baru — mereka langsung mengikuti standar tanpa diskusi
- Mencegah bug sederhana (undefined variable, typo) masuk ke production

## Kesalahan Umum
- Hanya install ESLint tapi tidak menjalankannya secara rutin — seperti punya inspektur tapi tidak pernah datang
- Konflik antara aturan ESLint dan Prettier — harus install `eslint-config-prettier` untuk mematikan aturan ESLint yang berurusan dengan formatting
- Mengabaikan warning — warning adalah bom waktu, sebaiknya dijadikan error di CI
- Tidak meng-commit file konfigurasi — setiap anggota tim punya aturan berbeda
- Prettier mengubah kode yang sudah benar secara logika — solusi: jalankan Prettier sebagai bagian dari pre-commit hook (Husky + lint-staged)
