# Lazy Loading & Code Splitting

## Penjelasan
Lazy loading adalah teknik menunda pemuatan resource (gambar, komponen, modul) sampai resource tersebut benar-benar dibutuhkan. Code splitting adalah teknik memecah bundle JavaScript menjadi potongan-potongan kecil yang dimuat sesuai permintaan, sehingga pengguna tidak perlu mengunduh seluruh kode aplikasi di awal.

## Fungsi
- Mengurangi ukuran bundle awal (initial load)
- Mempercepat waktu muat halaman (First Contentful Paint)
- Menghemat bandwidth dan resource pengguna
- Meningkatkan skor performa (Lighthouse)

## Cara Pengimplementasian

```javascript
// LAZY LOADING — analogi RUMAH: lampu yang nyala hanya saat ada orang di ruangan
// Tidak perlu menyalakan lampu seluruh rumah kalau kamu hanya di ruang tamu

// 1. Lazy loading gambar — gambar baru dimuat saat mendekati viewport
const gambarRumah = document.querySelectorAll('img[data-src]');
const observer = new IntersectionObserver((entries) => {
  entries.forEach(entry => {
    if (entry.isIntersecting) {
      const img = entry.target;
      img.src = img.dataset.src;          // baru load gambar sekarang
      img.removeAttribute('data-src');
      observer.unobserve(img);            // berhenti observasi
      console.log(`Gambar ${img.alt} dimuat — lampu ruangan menyala`);
    }
  });
});

gambarRumah.forEach(img => observer.observe(img));

// 2. Lazy loading fungsi/modul — import dinamis di ES Modules
// Bayangkan ini seperti memanggil tukang hanya saat ada yang rusak
function perbaikiPipa() {
  // dynamic import — hanya dimuat saat fungsi dipanggil
  import('./modules/tukangPipa.js')
    .then(mod => mod.perbaikiPipa())
    .catch(err => console.error('Tukang tidak tersedia', err));
}

// 3. Lazy loading dengan async/await
async function nyalakanLampuRuang(ruang) {
  if (ruang === 'tamu') {
    const lampu = await import('./lampu/ruangTamu.js');
    lampu.nyalakan();
  } else if (ruang === 'tidur') {
    const lampu = await import('./lampu/kamarTidur.js');
    lampu.nyalakan();
  }
  // Modul lain tidak ikut di-load — hemat resource!
}

// CODE SPLITTING — analogi RUMAH: membangun rumah bagian-per-bagian
// Daripada membangun seluruh rumah sekaligus, bangun dulu ruang tamu, lalu kamar, lalu dapur

// Contoh dengan dynamic imports (Webpack / Vite):
// Kamu bisa buat beberapa entry point:
//
// - home.js -> halaman utama (ruang tamu)
// - about.js -> halaman tentang (ruang keluarga)
// - contact.js -> halaman kontak (dapur)
//
// Atau split berdasarkan rute:
// const routes = {
//   '/': () => import('./pages/Beranda.js'),
//   '/profil': () => import('./pages/Profil.js'),
//   '/kontak': () => import('./pages/Kontak.js'),
// };
```

## Analogi
Lazy loading = **lampu yang nyala hanya saat ada orang di ruangan**. Tidak perlu menyalakan lampu di seluruh rumah (memuat semua resource) jika kamu hanya berada di ruang tamu. Lampu kamar tidur, dapur, garasi baru menyala ketika kamu masuk ke ruangan tersebut.

Code splitting = **membangun rumah bagian-per-bagian**. Daripada membangun seluruh rumah sekaligus (satu bundle besar), kamu bangun dulu ruang tamu agar bisa ditempati, lalu kamar tidur, lalu dapur. Pengguna bisa "tinggal" (menggunakan aplikasi) lebih cepat meskipun belum semua ruangan jadi (belum semua kode termuat).

## Dipakai Untuk Apa
- Lazy loading: gambar di halaman panjang, komponen di bawah fold, infinite scroll
- Code splitting: routing-based splitting (setiap halaman jadi chunk terpisah), vendor splitting (pisahkan library seperti React, Lodash), komponen modal/dialog jarang dipakai

## Kesalahan Umum
1. **Lazy loading berlebihan** — memecah terlalu kecil menyebabkan banyak request HTTP kecil yang malah lebih lambat
2. **Tidak fallback** — gambar lazy loading perlu placeholder agar tidak ada layout shift (CLS buruk)
3. **Cache tidak dioptimasi** — chunk kecil yang sering berganti nama tidak termanfaatkan cache browser
4. **Lupa preload yang penting** — resource di atas fold (above the fold) sebaiknya tidak di-lazy

## Keterkaitan dengan Materi Sebelumnya
Di Level 7, kamu belajar tentang Module (ES Modules) dan Tooling (Webpack/Vite). Code splitting adalah penerapan lanjutan dari ES Modules — `import()` adalah fungsi dynamic import dari spesifikasi ES2020. Webpack dan Vite yang kamu pelajari di Level 7 otomatis mendukung code splitting jika kamu menggunakan dynamic import. Konsep async dari Level 5 juga krusial untuk menangani promise dari `import()`.

## Soal Latihan

Apa perbedaan utama antara:

```javascript
import { helper } from './helper.js';  // A
const { helper } = await import('./helper.js');  // B
```

>!Pernyataan A (static import) dimuat **saat bundle diinisialisasi** — kode helper.js ikut dalam bundle awal. Pernyataan B (dynamic import) dimuat **saat await dipanggil** — helper.js dipisah menjadi chunk terpisah dan hanya dimuat saat dibutuhkan. Inilah dasar code splitting.!
