# Observer Pattern

## Penjelasan
Observer pattern adalah pola desain di mana satu objek (subject) memelihara daftar dependen (observer) dan memberi tahu mereka secara otomatis saat terjadi perubahan state. Subjek tidak perlu tahu detail observer — hanya perlu bisa memberi notifikasi.

## Fungsi
- Memisahkan logika utama dari efek samping (separation of concerns)
- Memungkinkan banyak bagian aplikasi bereaksi terhadap satu kejadian
- Mendukung komunikasi satu-ke-banyak secara longgar

## Cara Pengimplementasian

```javascript
// Observer Pattern — analogi RUMAH: sistem alarm rumah
// Setiap sensor (observer) akan mendapat notifikasi saat ada gerakan

class SistemAlarm {
  constructor() {
    this.sensorList = [];
    this.state = "aman";
  }

  daftarkanSensor(sensor) {
    this.sensorList.push(sensor);
  }

  hapusSensor(sensor) {
    this.sensorList = this.sensorList.filter(s => s !== sensor);
  }

  notifySemua(kejadian) {
    for (const sensor of this.sensorList) {
      sensor.update(kejadian);
    }
  }

  deteksiGerakan(lokasi) {
    this.state = "warning";
    this.notifySemua({ lokasi, waktu: new Date().toLocaleTimeString() });
  }
}

class SensorCCTV {
  constructor(nama) {
    this.nama = nama;
  }

  update(kejadian) {
    console.log(`[${this.nama}] Gerakan terdeteksi di ${kejadian.lokasi} pukul ${kejadian.waktu}`);
  }
}

class SensorPintu {
  constructor(nama) {
    this.nama = nama;
  }

  update(kejadian) {
    console.log(`[${this.nama}] Pintu ${kejadian.lokasi} — mengecek apakah terkunci...`);
  }
}

// Penggunaan
const alarmRumah = new SistemAlarm();
const cctvDepan = new SensorCCTV("CCTV Depan");
const sensorPintuBelakang = new SensorPintu("Sensor Pintu Belakang");

alarmRumah.daftarkanSensor(cctvDepan);
alarmRumah.daftarkanSensor(sensorPintuBelakang);

alarmRumah.deteksiGerakan("halaman depan");
// [CCTV Depan] Gerakan terdeteksi di halaman depan pukul ...
// [Sensor Pintu Belakang] Pintu halaman depan — mengecek apakah terkunci...
```

## Analogi
Observer pattern = **sistem alarm rumah**. Di rumah modern, ada banyak sensor (CCTV, sensor pintu, sensor jendela, alarm asap). Saat satu kejadian terjadi (misal: gerakan terdeteksi), sistem alarm pusat memberi tahu SEMUA sensor yang terdaftar. Setiap sensor bereaksi sesuai perannya — CCTV merekam, sensor pintu mengunci otomatis. Sensor baru bisa ditambahkan kapan saja tanpa mengubah sistem pusat. Begitu juga observer pattern: satu perubahan state memicu notifikasi ke semua observer yang sudah mendaftar.

## Dipakai Untuk Apa
- Event handling di DOM (addEventListener adalah implementasi observer)
- State management (Redux, Zustand — store memberi tahu komponen yang subscribe)
- Real-time updates (WebSocket — notifikasi ke semua client)
- Vue reactivity system (Properti reaktif memberi tahu komponen dependen)

## Kesalahan Umum
1. **Lupa menghapus observer** — menyebabkan memory leak karena objek tidak di-garbage collect
2. **Observer terlalu banyak** — notifikasi massal bisa menurunkan performa
3. **Notifikasi async yang tidak tertangani** — error di satu observer bisa mengganggu yang lain
4. **Update looping** — observer dan subject saling memicu tanpa henti

## Keterkaitan dengan Materi Sebelumnya
Di Level 5, kamu belajar EventEmitter dan callback pattern. Observer pattern adalah evolusi dari pola callback — daripada mengirim satu callback, observer mengelola banyak callback terdaftar. Di Level 6, addEventListener adalah contoh konkret observer pattern di DOM. Event loop di Level 5 juga relevan: observer sering memanfaatkan microtask/macrotask untuk notifikasi async.

## Soal Latihan

Buat instance SistemAlarm, daftarkan 3 sensor (SensorCCTV dengan nama berbeda), lalu panggil `deteksiGerakan("garasi")`. Apa yang terjadi?

>!Semua 3 sensor akan menerima notifikasi dan mencetak `[CCTV ...] Gerakan terdeteksi di garasi pukul ...` karena SistemAlarm memanggil `notifySemua()` yang mengitari seluruh observer terdaftar.!
