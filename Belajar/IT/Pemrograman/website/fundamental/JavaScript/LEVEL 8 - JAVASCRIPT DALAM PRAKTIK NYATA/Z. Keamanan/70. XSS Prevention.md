# XSS Prevention

## Penjelasan
XSS (Cross-Site Scripting) adalah celah keamanan di mana penyerang menyuntikkan skrip berbahaya ke halaman web yang dilihat pengguna lain. Skrip ini bisa mencuri cookie, token session, meredirect ke situs jahat, atau memodifikasi tampilan halaman. XSS terjadi ketika aplikasi menampilkan input user tanpa sanitasi yang benar.

Tiga jenis XSS:
- **Reflected XSS**: skrip ada di URL/request, langsung dijalankan
- **Stored XSS**: skrip disimpan di database, dijalankan setiap kali halaman diakses
- **DOM-based XSS**: skrip dijalankan karena manipulasi DOM yang tidak aman

## Fungsi
- Melindungi data pengguna (cookie, session, token)
- Mencegah defacement halaman web
- Menjaga integritas aplikasi web

## Cara Pengimplementasian

```javascript
// XSS Prevention — analogi RUMAH: pencuri yang menyamar sebagai tamu
// Jangan biarkan sembarang "tamu" masuk tanpa verifikasi

// ❌ RENTAN XSS — seperti buka pintu tanpa lihat lubang pintu
function tampilkanKomentarRentan(nama) {
  document.getElementById('komentar').innerHTML = nama;
  // Jika nama = "<script>curiCookie()</script>", skrip jalan!
}

// ✅ AMAN — seperti periksa identitas tamu dulu sebelum masuk
function tampilkanKomentarAman(nama) {
  // 1. Sanitasi dengan textContent (bukan innerHTML)
  document.getElementById('komentar').textContent = nama;
  // textContent otomatis meng-encode HTML, jadi <script> jadi teks biasa

  // 2. Atau encode manual
  const aman = document.createElement('div');
  aman.textContent = nama;
  document.getElementById('komentar').appendChild(aman);
}

// ✅ AMAN — sanitasi input sebelum dikirim ke server
function sanitasiInput(input) {
  const map = {
    '&': '&amp;',
    '<': '&lt;',
    '>': '&gt;',
    '"': '&quot;',
    "'": '&#x27;',
    '/': '&#x2F;',
  };
  return input.replace(/[&<>"'\/]/g, char => map[char]);
}

const namaUser = "<script>alert('xss')</script>";
console.log(sanitasiInput(namaUser));
// Output: &lt;script&gt;alert(&#x27;xss&#x27;)&lt;&#x2F;script&gt;

// ✅ AMAN — Content Security Policy (CSP)
// Di tag <meta> atau header HTTP:
// <meta http-equiv="Content-Security-Policy" content="default-src 'self'; script-src 'self'">
// CSP ibarat aturan rumah: "hanya orang dengan kartu identitas resmi yang boleh masuk"

// ✅ AMAN — hindari eval() dan innerHTML
// ❌ eval(userInput)   — seperti biarkan tamu bawa senjata
// ❌ new Function(userInput) — sama berbahaya
// ✅ gunakan JSON.parse untuk data, textContent untuk teks

// ✅ AMAN — HttpOnly cookie (tidak bisa diakses JavaScript)
// Set-Cookie: sessionId=abc123; HttpOnly; Secure
// Cookie ibarat kunci rumah — HttpOnly memastikan kunci tidak bisa dicuri meskipun ada XSS
```

## Analogi
XSS = **pencuri yang menyamar sebagai tamu**. Pencuri berpakaian rapi, membawa kado (input berbahaya), dan kamu mempersilakan masuk tanpa periksa identitas. Begitu di dalam rumah, pencuri mengambil barang berharga (cookie, session). Pencegahan XSS = **memasang sistem keamanan di pintu**: kartu identitas (sanitasi input), CCTV (CSP), brankas untuk barang berharga (HttpOnly cookie), dan aturan ketat siapa yang boleh masuk (validasi).

## Dipakai Untuk Apa
- Menampilkan input user di halaman (komentar, nama profil, review)
- Mengirim data ke server (form, search, API)
- Menyematkan konten dari sumber eksternal (iframe, widget)
- Aplikasi chat, forum, blog, e-commerce

## Kesalahan Umum
1. **Hanya sanitasi di client** — serangan bisa langsung ke server (gunakan Postman). Selalu sanitasi di server juga.
2. **Menggunakan innerHTML dengan input user** — ini penyebab utama DOM-based XSS
3. **Melewatkan library eksternal** — jQuery `.html()`, React `dangerouslySetInnerHTML`, Vue `v-html` harus hati-hati
4. **Anggapan bahwa API sendiri aman** — data dari database bisa saja berisi XSS (stored XSS)
5. **Lupa encode di atribut HTML** — `<img src="...">` juga perlu sanitasi

## Keterkaitan dengan Materi Sebelumnya
Di Level 6, kamu belajar DOM manipulation — `innerHTML`, `textContent`, `createElement`. Ini krusial untuk keamanan: paham kapan harus pakai `textContent` vs `innerHTML`. Di Level 7, module dan tooling bisa membantu: bundler seperti Vite punya perlindungan dasar. Di Level 4, class dan abstraction membantu membuat fungsi sanitasi reusable. Konsep async/fetch di Level 5 penting untuk memahami bagaimana data rentan dikirim dan diterima dari server.

## Soal Latihan

Apa output dari kode berikut? Aman atau berbahaya?

```javascript
const userMsg = "<b>Halo</b><script>alert('xss')</script>";
const el = document.createElement('p');
el.innerHTML = userMsg;
document.body.appendChild(el);
```

>!BERBAHAYA! `innerHTML` akan menginterpretasi `<script>alert('xss')</script>` sebagai elemen script nyata dan menjalankannya — meskipun `<script>` yang dimasukkan via innerHTML tidak dieksekusi di beberapa browser, tetap ada risiko injeksi HTML/event handler. Ganti dengan `textContent` agar semuanya menjadi teks biasa.!
