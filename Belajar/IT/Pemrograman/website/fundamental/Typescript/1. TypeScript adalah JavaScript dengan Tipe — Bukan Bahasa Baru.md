# 1. TypeScript adalah JavaScript dengan Tipe — Bukan Bahasa Baru

> 🟢 **Level 1 — Bagian A** | 🧩 **Materi pertama dari seluruh roadmap**

---

## 1. Penjelasan Singkat & Konsep Dasar

TypeScript **bukan** bahasa pemrograman yang terpisah. Ia adalah **superset dari JavaScript** — artinya, *semua* kode JavaScript yang valid juga merupakan kode TypeScript yang valid. Yang ditambahkan TypeScript hanyalah **anotasi tipe** (`: number`, `: string`, dsb.) dan **type checker** yang berjalan sebelum kode dieksekusi.

Karena ini materi *pertama*, konsep inti yang harus ditanamkan sejak sekarang:

```text
JavaScript (bahasa runtime) + Type System (sistem tipe) = TypeScript

Kamu tulis         TypeScript compile      Browser/Node jalankan
.ts file      →    tsc / transpiler   →    .js file
(TypeScript)       (type checking)         (JavaScript murni)
```

**Kunci pemahaman**: TypeScript *tidak berubah bentuk* saat dijalankan — ia selalu dikompilasi ulang menjadi JavaScript biasa. Anotasi tipe kamu *dibuang* pada saat kompilasi. Jadi TypeScript adalah "lapisan keamanan" yang hanya ada saat kamu menulis kode, bukan saat kode berjalan.

Perbandingan paling dasar:

```typescript
// ─── JavaScript ─────────────────────────────────────────────
// Tidak ada deklarasi tipe. value bisa berupa apa saja.
function tambah(a, b) {
    return a + b;
}

// ─── TypeScript ─────────────────────────────────────────────
// Anotasi tipe memberitahu compiler nilai apa yang BOLEH masuk.
function tambah(a: number, b: number): number {
    return a + b;
}
```

**Koneksi ke materi sebelumnya / sesudahnya**: Ini adalah fondasi dari [[2. Mengapa TypeScript? — Masalah yang Dipecahkan]]. Setelah memahami *apa itu* TypeScript, materi selanjutnya menjelaskan *mengapa* kita perlu menderita proses kompilasi demi keamanan tipe.

## 2. Fungsi & Kegunaan Utama

- **Menangkap bug saat menulis kode, bukan saat runtime.** Compiler membaca anotasi tipe dan menolak kode yang tidak konsisten ketika kamu menulisnya di editor.
- **Autocomplete yang akurat.** Karena editor (VS Code) tahu tipe sebuah nilai, ia bisa menawarkan properti dan method yang memang ada. Ini mempercepat menulis kode secara drastis.
- **Dokumentasi yang hidup.** Tipe adalah dokumentasi yang *selalu sinkron* dengan kode — tidak seperti komentar yang sering ketinggalan zaman.
- **Refactoring yang aman.** Rename variabel, ubah struktur object, pindahkan fungsi — TypeScript memberi tahu persis baris mana yang ikut berubah sehingga tidak ada yang tercecer.
- **Jembatan menuju JavaScript modern.** Karena TS adalah superset, semua fitur ES6+ (arrow function, destructuring, async/await) bisa langsung dipakai, plus fitur seperti `enum` dan parameter properties yang dimiliki TypeScript sendiri.

## 3. Contoh Kode & Implementasi (Real-world Example)

Bayangkan kita baru mulai membangun sistem perpustakaan. Tanpa tipe, kesalahan sepele — seperti mengetik `judl` alih-alih `judul` — tidak akan ketahuan sampai aplikasi crash di produksi.

```typescript
// src/dasar.ts
// Persiapan data perpustakaan — kecil tapi menggambarkan seluruh ide TypeScript

// ✅ TypeScript: setiap "slot" data sudah dikunci tipenya
interface Buku {
    judul: string;
    stok: number;
}

const buku: Buku = { judul: "Clean Code", stok: 5 };

// let buku = {};           // JS: bebas, belum ada kontrak
// buku.judl = "Clean Code" // JS: aman secara syntax... TIDAK menimbulkan error
// buku.judl = "..."        // TS: ❌ Error TS2551 - Property 'judl' does not exist

// Fungsi yang menjanjikan (kontrak) parameter dan hasil kembalian
function hitungDenda(hariTerlambat: number, dendaPerHari: number): number {
    return hariTerlambat * dendaPerHari;
}

// TS menolak pada saat compile, sebelum app dijalankan:
// hitungDenda("5", 1000);    // ❌ string tidak bisa jadi number
// hitungDenda(undefined, 1000); // ❌ undefined tidak bisa jadi number

const denda = hitungDenda(3, 1000); // ✅ return number: 3000
console.log(`Denda: Rp ${denda}`);   // Denda: Rp 3000
```

**Analogi alur kompilasi dalam konteks nyata:**

```bash
npx tsc src/dasar.ts   # jika ada error tipe, perintah GAGAL
node src/dasar.js      # barulah dijalankan
```

## 4. Analogi Sederhana

Bayangkan **Sistem Perpustakaan**. Setiap buku fisik di rak punya **kartu katalog** yang mencatat: judul, pengarang, ISBN, jumlah stok. Kartu ini *bisa* ditulis salah — misal kolom harga "Rp 15.000" tertulis "lima belas ribu" — tapi *petugas* tidak akan tahu sampai ada yang mencoba menghitung.

TypeScript itu seperti **petugas verifikasi di pintu masuk buku**:

- Sebelum buku masuk rak, petugas memeriksa kartunya, memastikan kolom `harga` diisi **angka**, kolom `judul` diisi **teks**, dst.
- Jika ada yang salah, buku itu **ditolak** — tidak pernah sampai ke tangan pembaca.
- JavaScript tanpa TypeScript adalah perpustakaan *tanpa verifikasi*: buku masuk apa adanya, baru ketahuan bermasalah ketika pembaca membaca halamannya.

Jadi TypeScript bukan perpustakaan yang berbeda — ia perpustakaan **yang sama**, hanya dengan satpam/verifikator di pintu masuknya.

## 5. Kapan Harus Digunakan (Use Cases)

*Kapan fitur ini "dipakai"?* Sebenarnya TypeScript digunakan setiap kali kamu menulis file `.ts`. Namun secara konsep:

- **Setiap project JavaScript yang berumur panjang (6 bulan ke atas)** — semakin besar kode, semakin bernilai keamanan tipe.
- **Setiap kode yang banyak melibatkan data terstruktur** — data buku, anggota, peminjaman, response API. Tipe membuat struktur data tersebut terlihat langsung di kode.
- **Project yang dikerjakan oleh tim** — tipe adalah *dark mode kontrak* antar anggota tim. Anggota baru langsung paham bentuk data tanpa membaca dokumentasi berlembar-lembar.
- **Project yang akan di-refactor / ditingkatkan secara bertahap** — persis roadmap ini: dari CLI → API → full-stack. Tipe menjamin peningkatan tidak memecahkan bagian lama.
- **Library / package yang akan dipakai orang lain** — tipe publik (`.d.ts`) membuat pengguna library mendapat autocomplete dan type-checking.

## 6. Poin-poin Penting & Best Practices

- **Semua JavaScript valid adalah TypeScript valid.** Jika kamu ragu, file `.js` bisa diubah ekstensinya jadi `.ts` dan tetap berjalan.
- **Tipe adalah kontrak, bukan hiasan.** Anotasi `: number` pada `hitungDenda` menjanjikan *semua* pemanggil bahwa parameter harus number.
- **Biarkan inference bekerja.** Jika `const judul = "Clean Code"` sudah jelas string, tidak perlu menulis `const judul: string = ...`. Anotasi eksplisit hanya perlu saat nilainya ambigu atau saat fungsi/param hasil dihitung.
- **Gunakan `tsc --noEmit` untuk type-checking cepat** tanpa menghasilkan file `.js`. Bagus untuk CI dan pre-commit.
- **Baca error TypeScript.** Pesan error TS memiliki format `TSxxxx` (misal TS2551) yang sangat informatif. Ini keterampilan inti yang akan dipakai seumur hidup.
- **Mulai dengan `strict: true`** di `tsconfig.json` sejak hari pertama (detail di [[4. tsconfig.json — Konfigurasi Compiler TypeScript]]).

## 7. Kesalahan Umum (Common Pitfalls & Anti-patterns)

| Kesalahan | Contoh | Perbaikan |
|---|---|---|
| **Mengira TS = JS tapi berbeda runtime** | "TypeScript tidak bisa jalan di browser" | TS selalu dikompilasi ke JS; browser hanya pernah melihat JS |
| **Menulis anotasi berlebihan** | `let x: number = 5;` padahal inference cukup | Biarkan `let x = 5` |
| **Tidak mengaktifkan `strict`** | tsconfig default tidak strict → banyak bug null lolos | Set `"strict": true`, diperkenalkan materi 4 |
| **Menggunakan `any` sebagai jalan pintas** | `function f(x: any) { return x.foo }` | Ganti dengan tipe konkret, atau `unknown` + narrowing (materi 5) |
| **Mengabaikan pesan error** | "Error aneh, langsung Stack Overflow" | Baca baris pertama — solusi biasanya jelas dari pesannya |

```javascript
let judul = "Laskar Pelangi";
let stok = 3;
function tambahStok(buku, jumlah) {
    return buku + jumlah;
}
console.log(tambahStok(stok, 2));
```

---

### Jawaban & Pembahasan

```typescript
// Soal 1
function formatHarga(harga: number): string {
    return `Rp ${harga.toLocaleString("id-ID")}`;
}

console.log(formatHarga(150000));   // ✅ "Rp 150.000"
// formatHarga("150000");           // ❌ TS2345: 'string' tidak assignable ke 'number'
```

```typescript
// Soal 2
let judul = "Laskar Pelangi";              // inference: string (tanpa anotasi)
let stok = 3;                              // inference: number (tanpa anotasi)

function tambahStok(buku: number, jumlah: number): number {
    return buku + jumlah;
}

// buku dan jumlah PERLU anotasi (parameter tidak bisa di-infer dari isi fungsi)
// return type: number juga bisa di-infer, tapi eksplisit di sini agar kontrak jelas

console.log(tambahStok(stok, 2));          // ✅ 5
```

**Pembahasan:**
- Variabel `judul` dan `stok` tidak perlu anotasi karena nilainya langsung terlihat — TypeScript *meng-infer* tipe (string, number).
- Parameter fungsi `buku` dan `jumlah` **wajib** dianotasi karena tanpa itu atau nilai awal, TypeScript tidak tahu tipenya — dan dengan `strict` + `noImplicitAny`, parameter tanpa tipe menghasilkan error.
- Return type bisa di-infer (`number`), tetapi menyatakannya eksplisit adalah kebiasaan baik untuk *dokumentasi kontrak*.
