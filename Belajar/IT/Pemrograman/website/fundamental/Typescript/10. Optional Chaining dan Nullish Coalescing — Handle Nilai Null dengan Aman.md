# 10. Optional Chaining dan Nullish Coalescing — Handle Nilai Null dengan Aman

> 🔵 **Level 2 — Bagian D** | 🧩 **Melanjutkan [[9. Type Alias — Nama untuk Tipe yang Kompleks]]**

---

## 1. Penjelasan Singkat & Konsep Dasar

Dengan `strict: true` (materi 4), null/undefined *harus* ditangani — dan data dari database/API *sering* null. Untuk menangani itu secara elegan, TypeScript (juga JavaScript) menyediakan tiga operator:

```text
?.  optional chaining    → berhenti (return undefined) bila salah satu null/undefined
??  nullish coalescing   → ambil default bila nilai null/undefined
!.  non-null assertion   → "percaya pada saya (developer), ini tidak null" — hati-hati!
```

**Kunci pembeda yang paling sering salah:**

```typescript
const stok = 0;
console.log(stok || 10);    // 10  — ❌ SALAH! 0 adalah falsy, tapi stok 0 VALID
console.log(stok ?? 10);    // 0   — ✅ benar; ?? hanya cek null/undefined
```

- `||` (OR) peduli **falsy** (`0`, `""`, `false`, `NaN`).
- `??` (nullish) peduli **hanya null/undefined**.

**Benang merah**: materi 5-9 membangun struktur data yang boleh null (optional, `T | null`). Operator-operator ini adalah alat *untuk mengonsumsinya* dengan aman dan ringkas — dan menghindari pernyataan `!= null` bertumpuk yang membosankan.

---

## 2. Fungsi & Kegunaan Utama

- **Akses properti bersarang (nested) tanpa "TypeError: Cannot read properties of null"**.
- **Error-handling default** saat data optional tidak terisi.
- **Menghindari "nesting of if"** yang dalam dan mudah lupa cabang.
- **Membuat kode lebih *declarative***: "ambil X, bila tidak ada pakai default" dalam satu ekspresi.
- **Menghubungkan rantai null dengan tipe** — TypeScript **menyempitkan tipe** setelah `?.` dan `??`, sehingga aman.

## 3. Contoh Kode & Implementasi (Real-world Example)

```typescript
// src/utils/null-safety.ts

interface Alamat {
    jalan: string;
    kota: string;
    kodePos?: string;
}

interface AnggotaLengkap {
    id: number;
    nama: string;
    alamat?: Alamat;                  // opsional
    preferensi?: { kategori?: string };
}

const anggota: AnggotaLengkap = {
    id: 1,
    nama: "Budi Santoso",
    // alamat TIDAK diisi
};

// ─── Cara lama: verbose dan mudah lupa ─────────────────────────────
if (anggota.alamat !== undefined && anggota.alamat.kota !== undefined) {
    console.log(anggota.alamat.kota);
}

// ─── Optional chaining (?.) — aman & ringkas ───────────────────────
console.log(anggota.alamat?.kota);       // undefined — aman
console.log(anggota.alamat?.kodePos);    // undefined

// ─── Nullish coalescing (??) — default bila null/undefined ──────────
const kota = anggota.alamat?.kota ?? "Tidak Diketahui";
const defKategori = anggota.preferensi?.kategori ?? "Umum";
console.log(kota);                        // "Tidak Diketahui"

// ─── Jangan tertukar !! vs ?: ──────────────────────────────────────
const stokBuku = 0;
console.log(stokBuku || 10);   // 10 — MENYESATKAN (0 stok adalah data valid)
console.log(stokBuku ?? 10);   // 0  — benar

// ─── ?. dengan pemanggilan fungsi ──────────────────────────────────
const panjangKota = anggota.alamat?.kota.length;   // undefined (karena alamat null)
console.log(panjangKota ?? 0);                     // 0

// ─── Non-null assertion (!) — gunakan SANGAT hati-hati ───────────────
// Ketika kamu YAKIN (sudah divalidasi) nilai tidak null:
function cariById(id: number): AnggotaLengkap | null {
    return null; // contoh: mencari di DB
}

function tampilkanNama(id: number): void {
    const hasil = cariById(id);
    // const nama = hasil!.nama;   // ! = "ini pasti ada"...
    // Lebih aman: throw bila tidak ada
    if (!hasil) {
        throw new Error(`Anggota ${id} tidak ditemukan`);
    }
    console.log(hasil.nama);   // setelah throw-guard, tipe disempitkan: AnggotaLengkap
}
```

## 4. Analogi Sederhana

**Sistem Perpustakaan.**

- **`?.`** seperti **petugas yang menghubungkan satu rak ke rak lain** *sambil melihat ke kiri/kanan*: "rak A ada? punya kotak kota? kalau ada baca petunjuknya." Jika rak atau kotak tidak ada, ia **berhenti dengan sopan** dan mengembalikan "tidak ada" (undefined) — bukan jatuh.
- **`??`** seperti **kebijakan "default"** di meja layanan: bila kolom "kota" kosong, otomatis tulis "Tidak Diketahui". Tapi *tidak* menimpa angka `0` — karena 0 *adalah* jawaban sah (misal stok 0 = benar-benar habis, bukan "kosong").
- **`||`** analogi untuk perbandingan: bila kita-kata "ambil 10 bila kolom kosong" dengan `||`, petugas akan *menganggap semua nilai falsy* — termasuk `0` dan `""` — sebagai kosong; itu kesalahan klasik saat menangani data seperti stok.
- **`!`** — istilah "trust me" — seperti petugas yang *meyakinkan semaunya* "ini pasti ada!" padahal mungkin lupa memeriksa; TypeScript mengijinkan, tapi **runtime tetap bisa mengecewakan**.

---

## 5. Kapan Harus Digunakan (Use Cases)

- **Mengakses data bersarang dari API/DB** di mana field bisa kosong (alamat user, preferensi, metadata).
- **Setting default yang harus diperlakukan null/undefined saja** — pakai `??`, terutama untuk angka & string kosong: harga, stok, batas, nilai.
- **Memanggil callback opsional** — `onPinjam?.(id)` di komponen UI (materi 25).
- **Rantai property di atas property lengkap** — alih-alih 5 baris `if`, satu ekspresi `?.`.
- **Setelah validasi eksternal** (misalnya Zod di Level 5) bila kamu *yakin* null tidak mungkin — tapi tetap lebih baik throw guard daripada `!`.

---

## 6. Poin-poin Penting & Best Practices

1. **Hindari `||` untuk default numerik/string** bila nilai `0`/`""` valid — selalu pertimbangkan `??`.
2. **`?.` & `??` hanya membersihkan null/undefined**, bukan "nilai kosong" (`""`, `0`) — perintah kondisi dibuat eksplisit.
3. **`!` adalah ode rendah kepercayaan**: gunakan hanya setelah validasi nyata; setiap penggunaan `!` adalah tempat potensial crash.
4. **Baca error `strictNullChecks`**: TS18047 akan menuntun kamu memakai guard — bukan alasan memakai `!`.
5. **`?.` tidak mengganti pengecekan** bila kamu butuh *melanjutkan logika berbeda* saat null — gunakan `if` biasa.
6. **Prefer early return + throw** daripada `!` untuk memproteksi jalur penting (terlihat di contoh `tampilkanNama`).

---

## 7. Kesalahan Umum (Common Pitfalls & Anti-patterns)

| Kesalahan | Contoh | Akibat | Perbaikan |
|---|---|---|---|
| `\|\|` untuk nilai numerik valid 0 | `stok \|\| 10` stok 0 jadi 10 | hasil salah | `??` |
| `?.` bukan null-guard penuh | `a?.b.c` — `b` ada tapi `.c`? | tetap bisa crash di `.c` jika `b` null | `a?.b?.c` sepenuh rantaian |
| Over-using `!` | `x!` di mana-mana "biar cepat" | crash runtime yang tak terdeteksi | validasi nyata di awal |
| Kurang menghubungkan `??` dengan `?.` | baca `a?.b ?? c` tapi mengabaikan `a` | salah ekspektasi | rantai lengkap dengan `?.` |
| Anggap `??` sama dengan `\|\|` | kesehatan data hilang | nilai default tak sesuai | baca falsy vs nullish |
| `!` pada variabel yang *akan* diisi | hasil dari fungsi yang bisa null | crash ketika null | guard + throw |

## 8. Soal Latihan & Kunci Jawaban

### Soal 1
Diberikan:

```typescript
interface Pengguna {
    id: number;
    profil?: {
        nama?: string;
        alamat?: { kota: string };
    };
    stokAkses: number;      // 0 = tidak ada akses membaca
}
```

Tulis baris yang (a) mengambil nama (default `"Anonim"`), (b) mengambil kota (default `"Kosong"`), (c) memutuskan "punya akses?" dengan benar memakai `??` (stok 0 = tidak ada akses), dan (d) jelaskan kenapa `||` salah di (c).

### Soal 2
Perbaiki kode yang rawan crash berikut dengan `?.` / `??`, tanpa mengubah makna:

```typescript
function cariKota(p: Pengguna): string {
    return p.profil.alamat.kota;   // apa yang terjadi bila profil/alamat undefined?
}
```

### Jawaban & Pembahasan

```typescript
// Soal 1
interface Pengguna {
    id: number;
    profil?: { nama?: string; alamat?: { kota: string } };
    stokAkses: number;
}

const user: Pengguna = { id: 1, stokAkses: 0 };

const namaCari = user.profil?.nama ?? "Anonim";        // (a) "Anonim"
const kotaCari = user.profil?.alamat?.kota ?? "Kosong"; // (b) "Kosong"
const punyaAkses = user.stokAkses > 0;                  // (c) false

// (d) Jika dipakai `user.stokAkses || true` — untuk nilai 0 (falsey)
//     hasilnya bukan "benar punya akses" yang benar, karena 0 dianggap kosong.
//     `??` tidak membantu di sini; perbandingan eksplisit `> 0` lebih tepat.
```

**Pembahasan**: `?.` menembus path property yang mungkin kosong; `??` memberi default hanya untuk null/undefined. Untuk logika boolean, bandingkan eksplisit.

```typescript
// Soal 2
function cariKota(p: Pengguna): string {
    return p.profil?.alamat?.kota ?? "Kota tidak terdaftar";
}
```

**Pembahasan**: versi awal akan melempar `TypeError` jika `profil` atau `alamat` undefined. Dengan `?.` di setiap level dan default `??`, fungsi selalu mengembalikan string yang aman — tanpa satu pun `if` berlapis.
