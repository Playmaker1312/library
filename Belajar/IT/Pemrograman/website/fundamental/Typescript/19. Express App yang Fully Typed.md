# 19. Express App yang Fully Typed

> 🔴 **Level 5 — Bagian I** | 🧩 **Melanjutkan [[18. Setup Express TypeScript Project]]**

---

## 1. Penjelasan Singkat & Konsep Dasar

Di materi 18 kita setup project. Sekarang kita **membangun aplikasi Express yang sepenuhnya typed**: request, response, middleware, dan bagaimana *extension* ke tipe Express.

Konsep inti:

```text
Tiga lapisan tempat tipe bermain di Express:
1. Tipe request/responses bawaan (@types/express): Request, Response, NextFunction
2. Custom augmentation (declare global): menambah field custom ke Request (req.user, req.requestId)
3. Structured response: respons konsisten ApiResponse<T> di seluruh endpoint
```

Poin paling menarik di sini adalah **declaration merging** yang kita pelajari di materi 8 — dipakai nyata untuk memperluas `Express.Request`:

```typescript
declare global {
    namespace Express {
        interface Request {
            user?: Anggota;
            requestId?: string;
        }
    }
}
```

**Benang merah**: ini adalah *produksi nyata* dari interface, type alias, dan middleware yang sudah kamu kenal. Dari Level 2 (kontrak object) kini *dunia luar* (HTTP) diikat ke tipe yang sama.

---

## 2. Fungsi & Kegunaan Utama

- **Request handler typed** — parameter `req, res, next` punya tipe, autocomplete penuh.
- **Custom augmentation** — `req.user`, `req.requestId` tersimpan dengan tipe yang diketahui di seluruh app.
- **Struktur respons konsisten** — client tahu formatnya (`{ success, data }`), frontend (materi 25-27) bisa mengetik response.
- **Route registration yang rapi** — memisahkan router per entitas.
- **Error contract** — error handler dijamin dijalankan terakhir (materi 21).

---

## 3. Contoh Kode & Implementasi (Real-world Example)

### Step 1 — Perluas tipe Express (declaration merging)

```typescript
// src/types/express.d.ts
import type { Anggota } from "./index";

declare global {
    namespace Express {
        interface Request {
            user?: Anggota;        // diisi oleh auth middleware
            requestId?: string;    // diisi oleh logging middleware
        }
    }
}

export {};
```

### Step 2 — app.ts: membangun aplikasi

```typescript
// src/app.ts
import express, { Application, Request, Response, NextFunction } from "express";
import cors from "cors";
import helmet from "helmet";
import crypto from "node:crypto";
import { bukuRouter }    from "./routes/buku.routes";
import { anggotaRouter } from "./routes/anggota.routes";
import { errorHandler }  from "./middleware/errorHandler";

export function createApp(): Application {
    const app = express();

    // ─── Middleware global ───────────────────────────────────────────
    app.use(helmet());
    app.use(cors({ origin: process.env.ALLOWED_ORIGINS?.split(",") }));
    app.use(express.json({ limit: "10mb" }));
    app.use(express.urlencoded({ extended: true }));

    // Request ID middleware
    app.use((req: Request, _res: Response, next: NextFunction) => {
        req.requestId = crypto.randomUUID();
        next();
    });

    // ─── Routes ─────────────────────────────────────────────────────
    app.use("/api/v1/buku", bukuRouter);
    app.use("/api/v1/anggota", anggotaRouter);

    // 404 handler
    app.use((_req: Request, res: Response) => {
        res.status(404).json({ success: false, message: "Endpoint tidak ditemukan" });
    });

    // Error handler HARUS paling akhir
    app.use(errorHandler);

    return app;
}
```

### Step 3 — index.ts: jalankan

```typescript
// src/index.ts
import { createApp } from "./app";
import { config } from "./config/env";

const app = createApp();
app.listen(config.PORT, () => {
    console.log(`API berjalan di http://localhost:${config.PORT}`);
});
```

### Step 4 — Contoh router type-safe (controller di materi 21)

```typescript
// src/routes/buku.routes.ts
import { Router } from "express";
import { BukuController } from "../controllers/buku.controller";

const router = Router();
const controller = new BukuController();

router.get("/", controller.getAll);
router.get("/:id", controller.getById);

export const bukuRouter = router;
```

## 4. Analogi Sederhana

**Sistem Perpustakaan.**

- **`app.ts`** = **bagan organisasi gedung perpustakaan**: ia menentukan bagaimana *setiap tamu* (request) diarahkan — melewati penjaga pintu (helmet/cors/logging), menuju loket sesuai rute (routes), dan bila ada masalah, berakhir di ruang khusus (error handler).
- **`get("/buku")`** = **petugas yang berdiri di depan rak buku** — menyambut tamu yang mencari koleksi.
- **`req.requestId`** = **nomor tiket antrian** yang dicap di pergelangan tamu — semua log di seluruh lantai mengacu pada nomor ini, sehingga bisa ditelusuri kalau ada keluhan.
- **Declaration merging (`Express.Request`)** = **menambah kolom ekstra pada formulir standar**: dari pemerintahan (library) formulir hanya punya `nama`, `email`; perpustakaan menambah kolom "berlaku untuk akses lantai 3" — dan semua loket otomatis membaca kolom itu.
- **Response terrain `{ success, data }`** = **format nota resmi**: "Status: Sukses / Pesan: / Data: ..." — semua loket menulis nota dengan format sama, sehingga tamu dan sistem lain (frontend) selalu memahami.

---

## 5. Kapan Harus Digunakan (Use Cases)

- **Setiap project Express + TypeScript** — typed request/response adalah inti "Express typed".
- **Saat perlu context tambahan pada request** (user dari auth, requestId, correlationId) — augmentation `Express.Request`.
- **API yang dikonsumsi frontend** — struktur respons konsisten untuk dibaca React/Next.js (materi 25-27).
- **Test integration** (materi 22): `createApp()` yang di-export bisa langsung dimasukkan ke supertest.
- **Tim yang ingin mendokumentasikan endpoint lewat tipe** — tipe rute = peta API.

---

## 6. Poin-poin Penting & Best Practices

1. **Ekspor `createApp()`** dari app.ts — bukan listen langsung, agar bisa diimpor test.
2. **Perluas `Express.Request` via declaration merging** — tipe custom (`user`, `requestId`) jadi tersedia di seluruh project.
3. **Passing tipe handler**: `(req: Request, res: Response, next: NextFunction)`. Jangan `any`.
4. **Structur respons standar** — pakai `ApiResponse<T>` (materi 21) dari awal agar seluruh endpoint seragam.
5. **Letakkan error handler & 404 di paling akhir** (setelah semua routes).
6. **Gunakan ENUM hanya untuk hal yang dibutuhkan runtime** — untuk union cukup literal (materi 6).

---

## 7. Kesalahan Umum (Common Pitfalls & Anti-patterns)

| Kesalahan | Contoh | Akibat | Perbaikan |
|---|---|---|---|
| Lupa augmentation di `.d.ts` | `req.user` tidak dikenal | TS2339 | tambahkan `declare global` |
| Error handler diletakkan sebelum route | `app.use(errorHandler)` di atas | error tidak tertangani | paling akhir |
| Tipe response tidak konsisten | tiap controller beda bentuk | frontend sulit memetakan | pakai `ApiResponse<T>` bersama |
| Semua controller `/buku` jadi string | respons `any` | kontrak pecah | interface respons (materi 21) |
| Tidak pakai `createApp()` | listen langsung di file utama | test susah | pisahkan app & listen |
| Auth user di-`any` | tetapi typeguard tidak ada | req.user bisa null tak terdeteksi | definisikan tipe + middleware isi |

## 8. Soal Latihan & Kunci Jawaban

### Soal 1
Tulis file `src/types/express.d.ts` yang menambahkan properti:

- `logData?: Record<string, unknown>`.

### Soal 2
Buat `createApp()` yang memuat:
- middleware `express.json()`,
- route `GET /api/v1/ping` mengembalikan `{ success: true, data: "pong" }`,
- 404 handler,
- errorHandler kosong (dummy). Sementara jangan import controller nyata.

---

### Jawaban & Pembahasan

```typescript
// Soal 1
declare global {
    namespace Express {
        interface Request {
            userId?: number;
            logData?: Record<string, unknown>;
        }
    }
}
export {};
```

**Pembahasan**: deklarasi `global` + `export {}` membuat TypeScript meng+hapus properties ke interface `Express.Request` yang ada di `@types/express` — memakai mekanisme declaration merging (materi 8).

```typescript
// Soal 2
import express, { Application, Request, Response, NextFunction } from "express";

export function createApp(): Application {
    const app = express();
    app.use(express.json());

    app.get("/api/v1/ping", (_req: Request, res: Response) => {
        res.json({ success: true, data: "pong" });
    });

    app.use((_req: Request, res: Response) => {
        res.status(404).json({ success: false, message: "Endpoint tidak ditemukan" });
    });

    app.use((error: unknown, _req: Request, res: Response, _next: NextFunction) => {
        console.error(error);
        res.status(500).json({ success: false, message: "Terjadi error server" });
    });

    return app;
}
```

**Pembahasan**: `createApp()` dapat di-reuse untuk supertest di Level 6; tipe handler ditandai eksplisit, respons seragam `{success, data/message}` — fondasi yang siap dikembangkan (Zod di materi 20, error hierarchy di materi 21).
