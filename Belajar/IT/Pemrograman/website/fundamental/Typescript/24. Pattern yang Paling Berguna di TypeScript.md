# 24. Pattern yang Paling Berguna di TypeScript

> ⚫ **Level 6 — Bagian K** | 🧩 **Melanjutkan [[23. Unit Test — Test Service dan Repository]]**

---

## 1. Penjelasan Singkat & Konsep Dasar

**Design pattern** adalah *solusi teruji* untuk masalah yang diulang. Di TypeScript, pattern bukan sekadar struktur — ia memakai perpaduan tipe, generics, dan class untuk menghasilkan kode yang **ekspresif, testable, dan type-safe**.

Dua pattern yang paling berdampak di project perpustakaan:

```text
Builder Pattern   → membangun query/config yang kompleks secara bertahap,
                    dengan chainable method yang typed (materi 2 & 3 level 3).
Observer Pattern  → sistem event pub/sub yang type-safe — object mempublikasi
                    perubahan, subscriber mendengarkan (basis materi 24 & 27).
```

Juga yang sudah kita gunakan dan akan tetap dipakai:

| Pattern | Sudah dipakai di | Nilai |
|---|---|---|
| **Repository** | materi 15, Level 5 | abstraksi akses data |
| **Dependency Injection** | materi 21 (constructor) | testability |
| **Factory / Static factory** | `Buku.fromJSON`, `createApp()` | pemusatan konstruksi |
| **Adapter** | penyesuaian skema/Zod DTO | boundary antar layer |
| **Template Method** | abstract class `SumberData` (materi 13) | reuse + kontrak turunan |

**Benang merah**: materi ini "meng-upgrade" keterampilan OOP & generics menjadi *seni membangun arsitektur*. Buildernya akan berguna di query layer, Observer di event logging/notifikasi — dan keduanya jadi dasar untuk pendekatan full-stack di Level 7.

---

## 2. Fungsi & Kegunaan Utama

- **Builder** — menyembunyikan kompleksitas konstruksi (query, objek config) dari pemanggil, dan memungkinkan *chaining* yang readable.
- **Observer** — memisahkan *publisher* dan *subscriber*, mendukung banyak listener tanpa saling tahu; sangat cocok untuk log, notifikasi, event*domain*.
- **Type-safety sebagai nilai utama** — *event map* generic (`EventEmitter<Events>`) menjamin handler terima data yang TEPAT untuk event-nya.
- **Testability** — publisher bisa di-test dengan subscriber yang di-mock.
- **Reusability / low coupling** — objek tidak perlu tahu siapa yang mendengarkan.

## 3. Contoh Kode & Implementasi (Real-world Example)

### Builder Pattern — query buku yang terbaca

```typescript
// src/patterns/query-builder.ts
type Kategori = "Fiksi" | "Non-Fiksi" | "Sains" | "Teknologi" | "Sejarah" | "Umum";

class BukuQueryBuilder {
    private kondisi: string[] = [];
    private orderField = "judul";
    private orderDir: "asc" | "desc" = "asc";
    private limitNilai?: number;
    private offsetNilai?: number;

    kategori(kategori: Kategori): this {
        this.kondisi.push(`kategori = '${kategori}'`);
        return this;                      // return this → chaining
    }

    tersedia(): this {
        this.kondisi.push("stok > 0");
        return this;
    }

    cari(keyword: string): this {
        this.kondisi.push(`(judul LIKE '%${keyword}%' OR pengarang LIKE '%${keyword}%')`);
        return this;
    }

    urutkan(field: string, arah: "asc" | "desc" = "asc"): this {
        this.orderField = field;
        this.orderDir = arah;
        return this;
    }

    halaman(page: number, perPage: number): this {
        this.limitNilai = perPage;
        this.offsetNilai = (page - 1) * perPage;
        return this;
    }

    build(): string {
        let q = "SELECT * FROM buku";
        if (this.kondisi.length > 0) {
            q += ` WHERE ${this.kondisi.join(" AND ")}`;
        }
        q += ` ORDER BY ${this.orderField} ${this.orderDir}`;
        if (this.limitNilai !== undefined) {
            q += ` LIMIT ${this.limitNilai} OFFSET ${this.offsetNilai ?? 0}`;
        }
        return q;
    }
}

// Pemakaian yang ekspresif:
const query = new BukuQueryBuilder()
    .kategori("Teknologi")
    .tersedia()
    .cari("clean")
    .urutkan("harga", "asc")
    .halaman(1, 10)
    .build();
```

### Observer Pattern — event emitter type-safe

```typescript
// src/patterns/event-emitter.ts
type Handler<T> = (data: T) => void | Promise<void>;

class EventEmitter<Events extends Record<string, unknown>> {
    private handlers = new Map<keyof Events, Handler<any>[]>();

    on<K extends keyof Events>(event: K, handler: Handler<Events[K]>): void {
        const list = this.handlers.get(event) ?? [];
        list.push(handler);
        this.handlers.set(event, list);
    }

    off<K extends keyof Events>(event: K, handler: Handler<Events[K]>): void {
        const list = (this.handlers.get(event) ?? []).filter(h => h !== handler);
        this.handlers.set(event, list);
    }

    async emit<K extends keyof Events>(event: K, data: Events[K]): Promise<void> {
        const list = this.handlers.get(event) ?? [];
        await Promise.all(list.map(h => h(data)));
    }
}

// Definisikan "peta event" yang type-safe
interface PerpustakaanEvents {
    "buku:dipinjam":     { bukuId: number; anggotaId: number; tanggal: Date };
    "buku:dikembalikan": { peminjamanId: number; denda: number };
    "anggota:daftar":    { anggotaId: number; email: string };
}

const emitter = new EventEmitter<PerpustakaanEvents>();

// Handler fully typed:
emitter.on("buku:dipinjam", ({ bukuId, anggotaId }) => {
    // TS tahu: bukuId & anggotaId adalah number
    void kirimEmailKonfirmasi(anggotaId, bukuId);
});

emitter.on("buku:dipinjam", ({ tanggal }) => {
    console.log(`Dipinjam pada ${tanggal.toLocaleDateString("id-ID")}`);
});

async function kirimEmailKonfirmasi(anggotaId: number, bukuId: number): Promise<void> {
    // ...
}

await emitter.emit("buku:dipinjam", {
    bukuId: 1, anggotaId: 42, tanggal: new Date(),
});
```

## 4. Analogi Sederhana

**Sistem Perpustakaan.**

- **Builder** = **petugas menyusun surat permintaan pencarian jadwal**: ia menambah satu per satu kenop di formulir ("kategori Teknologi", "hanya tersedia", "cari 'clean'", "urutkan harga", "halaman 1") dengan **mengembalikan formulir yang sama** untuk diisi lanjut — sampai `build()` menyerahkan surat jadi (`SELECT ...`). Pembaca puas karena alurnya linear & jelas.

- **Observer** = **sistem pengumuman perpustakaan (pager)**:
  - *Publisher* = modul yang memancarkan kejadian ("buku dipinjam").
  - *Subscriber* = petugas yang "meminjam pager": petugas email mendaftar untuk `buku:dipinjam` (kirim email), petugas log mendaftar untuk kejadian yang sama (catat tanggal) — keduanya *tidak saling tahu*.
  - Saat event dipancarkan (`emit`), semua pemegang pager menerima data yang sama — **dengan tipe yang sesuai event-nya** (materi 17: mapped types menghasilkan `on${Event}`).
  - Tidak ada yang bergantung pada yang lain → sistem longgar (low coupling).

---

## 5. Kapan Harus Digunakan (Use Cases)

- **Builder**: query yang kompleks, konfigurasi HTTP/DB, pembangunan objek dengan banyak optional — di mana konstruktor langsung jadi berantakan.
- **Observer/Event**: sistem log, notifikasi (email/push), integrasi audit trail, event sourcing, re-render UI (React prop drilling vs context, materi 25).
- **Repository + DI**: semua layer akses data & testability (sudah dipakai secara konsisten sejak Level 3).
- **Factory/static factory**: `fromJSON`, `createApp` — konstruksi dengan validasi/transformasi.
- **Template Method**: proses dengan langkah tetap tapi detail per-varian (dump/import data).

---

## 6. Poin-poin Penting & Best Practices

1. **Builder**: method mengembalikan `this` (tipe instance) agar *chaining* terus berlanjut; simpan state sampai `build()`.
2. **Builder**: `build()` melakukan validasi terakhir (contoh: pastikan kondisi tidak kosong).
3. **Observer**: **handle un-registration (`off`)** untuk mencegah memory leak saat subscriber tak lagi digunakan.
4. **Observer**: gunakan generic event map (`Events extends Record<string, unknown>`) — setiap handler *ter*typed.
5. **Jangan paksa pattern** — mulai dengan yang simpel; kembangkan saat kompleksitas benar-benar meningkat.
6. **Konsisten**: jika project sudah pakai Repository+DI, jangan mencampur pendekatan yang berbanding.

## 7. Kesalahan Umum (Common Pitfalls & Anti-patterns)

| Kesalahan | Contoh | Akibat | Perbaikan |
|---|---|---|---|
| Builder tanpa `this` return | method return `void` | tidak bisa chain | return `this` |
| Builder validasi di `build()` di-skip | query tanpa kondisi tetap dieksekusi | berbahaya (full scan) | validasi di build |
| Event handler `any` | `Handlers<Events>` → `any` hilang safety | event type tak terjaga | map generic, `EventEmitter<T>` |
| Memanggil tanpa `off` | subscriber lama bertahan | memory leak | simpan referensi & `off` |
| Emit sync vs async tertukar | `emit` memakai `Promise.all` tapi handler sync | urutan tak tentu | konsistenkan async |
| Pattern berlebihan | 5 klas untuk 1 fungsi sederhana | over-engineering | gunakan sesuai kebutuhan |

## 8. Soal Latihan & Kunci Jawaban

### Soal 1
Tulis Builder `MemberQueryBuilder` dengan method:
- `role(role: "admin" | "pustakawan" | "anggota"): this`
- `aktif(): this`
- `urutkan(field: string, arah: "asc"|"desc")`
- `build()` mengembalikan string SQL.
Gunakan chaining dengan semua method dalam satu ekspresi.

### Soal 2
Dengan `EventEmitter<Events>`, definisikan interface events `BayarEvents = { "bayar:selesai": { orderId: number; total: number } }` — daftarkan dua handler (satu menampilkan total, satu mengirim email) dan `emit`. Tunjukkan bahwa handler *menerima* tipe `total: number` dengan benar.

---

### Jawaban & Pembahasan

```typescript
// Soal 1
class MemberQueryBuilder {
    private kondisi: string[] = [];
    private orderField = "nama";
    private orderDir: "asc" | "desc" = "asc";

    role(r: "admin" | "pustakawan" | "anggota"): this {
        this.kondisi.push(`role = '${r}'`);
        return this;
    }

    aktif(): this {
        this.kondisi.push("status = 'aktif'");
        return this;
    }

    urutkan(field: string, arah: "asc" | "desc" = "asc"): this {
        this.orderField = field;
        this.orderDir = arah;
        return this;
    }

    build(): string {
        const where = this.kondisi.length ? ` WHERE ${this.kondisi.join(" AND ")}` : "";
        return `SELECT * FROM anggota${where} ORDER BY ${this.orderField} ${this.orderDir}`;
    }
}

// Chaining:
const sql = new MemberQueryBuilder()
    .role("anggota")
    .aktif()
    .urutkan("nama", "desc")
    .build();
// "SELECT * FROM anggota WHERE role = 'anggota' AND status = 'aktif' ORDER BY nama desc"
```

**Pembahasan**: setiap method mengembalikan `this`, sehingga metode bisa dirantai; akumulasi kondisi query menjadi string di `build()`. Prinsip yang sama diterapkan di query layer sesungguhnya (Prisma/TypeORM) dengan API chainable.

```typescript
// Soal 2
interface BayarEvents {
    "bayar:selesai": { orderId: number; total: number };
}

const pembayaran = new EventEmitter<BayarEvents>();

pembayaran.on("bayar:selesai", ({ total }) => {
    console.log(`Total: Rp ${total.toLocaleString("id-ID")}`);   // total → number
});

pembayaran.on("bayar:selesai", ({ orderId }) => {
    void simpanNota(orderId);
});

async function simpanNota(orderId: number): Promise<void> { /* ... */ }

await pembayaran.emit("bayar:selesai", { orderId: 7, total: 75000 });
```

**Pembahasan**: parameter handler dianotasikan lewat generic map — `{ total }` inferred sebagai `number` (sehingga `.toLocaleString` tersedia), dan pemanggilan `emit` wajib mengirim objek yang *persis* bentuknya; salah field langsung error TS.
