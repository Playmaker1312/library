# 20. Typed Request Validation dengan Zod

> 🔴 **Level 5 — Bagian I** | 🧩 **Melanjutkan [[19. Express App yang Fully Typed]]**

---

## 1. Penjelasan Singkat & Konsep Dasar

TypeScript memberi tipe di **compile-time**. Tapi *request di runtime* (masuk via network) bisa apa saja — helaian dari client bisa berupa string acak, field berlebih, tipedNumber yang ternyata string `"5"`. Menyatakan `req.body as Buku` bukanlah validasi — justru **bohong pada compiler**.

**Zod** mengisi celah ini: *runtime validation* yang sekaligus menghasilkan **tipe TypeScript** dari skema yang sama — satu definisi, dua fungsi.

```typescript
import { z } from "zod";

const BukuSchema = z.object({
    judul: z.string().min(1),
    harga: z.number().min(0),
});
type BukuDTO = z.infer<typeof BukuSchema>;   // otomatis jadi tipe TS!
```

Alur:

```text
Parse (safeParse) → validasi runtime → TIDAK valid: kirim error 422
                                   → VALID: data sudah bersih & typed → lanjut ke controller
```

**Benang merah**: dari Level 5 kita sudah kenal `unknown` (materi 5) dan user-defined type guard (materi 11) untuk data eksternal. Zod adalah *fppekuatan u-raised* dari ide itu — digunakan secara konsisten di seluruh API (dan di materi 26 di Next.js route handler).

---

## 2. Fungsi & Kegunaan Utama

- **Satu definisi, dua manfaat**: skema runtime (validasi) + tipe compile-time (`z.infer`).
- **Mencegah data kotor masuk ke service/repository** — prinsip "trust boundary" di pintu masuk.
- **Pesan error yang bermanfaat** — per field, mudah dibaca.
- **Transformasi**: konversi string → number/safe parse, `.transform()`.
- **Partial untuk update**: `schema.partial()` = menu `Partial<T>` (materi 16) di level runtime.
- **Komposisi**: nested object, array, enum, rekursif — konsisten dengan struktural typing.

## 3. Contoh Kode & Implementasi (Real-world Example)

### Skema & tipe (satu sumber)

```typescript
// src/schemas/buku.schema.ts
import { z } from "zod";

export const KategoriEnum = ["Fiksi", "Non-Fiksi", "Sains", "Teknologi", "Sejarah", "Umum"] as const;

export const CreateBukuSchema = z.object({
    judul:     z.string().min(1, "Judul wajib diisi").max(200),
    pengarang: z.string().min(1, "Pengarang wajib diisi").max(100),
    isbn:      z.string().length(13, "ISBN harus 13 digit").optional(),
    tahun:     z.number().int().min(1000).max(new Date().getFullYear()),
    harga:     z.number().min(0, "Harga tidak boleh negatif"),
    stok:      z.number().int().min(0, "Stok tidak boleh negatif"),
    kategori:  z.enum(KategoriEnum),
    deskripsi: z.string().max(2000).optional(),
});

export const UpdateBukuSchema = CreateBukuSchema.partial();

// Tipe diekstrak otomatis — tidak perlu mendefinisikan dua kali
export type CreateBukuDTO = z.infer<typeof CreateBukuSchema>;
export type UpdateBukuDTO = z.infer<typeof UpdateBukuSchema>;
```

### Middleware validasi yang generic

```typescript
// src/middleware/validateRequest.ts
import type { Request, Response, NextFunction } from "express";
import type { ZodType } from "zod";

export function validateBody<T>(schema: ZodType<T>) {
    return (req: Request, res: Response, next: NextFunction): void => {
        const result = schema.safeParse(req.body);

        if (!result.success) {
            const errors = result.error.flatten().fieldErrors;
            res.status(422).json({
                success: false,
                message: "Data tidak valid",
                errors,
            });
            return;
        }

        req.body = result.data;   // ← ganti dengan data yang sudah BERSIH & typed
        next();
    };
}
```

### Pemakaian di route

```typescript
// src/routes/buku.routes.ts (potongan)
import { validateBody } from "../middleware/validateRequest";
import { CreateBukuSchema, UpdateBukuSchema } from "../schemas/buku.schema";

router.post("/", authenticate, validateBody(CreateBukuSchema), bukuController.store);
router.put("/:id", authenticate, validateBody(UpdateBukuSchema), bukuController.update);
```

Di controller, `req.body` sudah ter-ty-cast valid:

```typescript
// src/controllers/buku.controller.ts (potongan)
store = (req: Request, res: Response, next: NextFunction): void => {
    try {
        const data: CreateBukuDTO = req.body;   // sudah divalidasi & typed
        const buku = service.create(data);
        res.status(201).json({ success: true, data: buku });
    } catch (error) {
        next(error);
    }
};
```

## 4. Analogi Sederhana

**Sistem Perpustakaan.**

- **Zod schema** = **formulir pendaftaran buku dengan aturan tertulis di kertas**: "judul wajib", "tahun harus angka antara 1000-sekarang", "kategori salah satu dari daftar". Form ini bukan sekadar catatan — ia *punya petugas yang mengecek setiap kolom sebelum diterima*.
- **`safeParse`** = **petugas verifikasi** yang memeriksa formulir & mengembalikan amplop berlabel: "VALID ✅" (bersama data bersih) atau "INVALID ❌" (bersama daftar bidang bermasalah).
- **`z.infer`** = **tipe kertas yang otomatis tercetak di kartu** dari formulir yang sama — sehingga lantai komputer (TypeScript) dan petugas lapangan (runtime) membaca *dari dokumen yang PASTI sama*, tidak mungkin beda.
- **`.partial()` untuk update** = **formulir "ubah data"** yang semua kolomnya opsional — persis `Partial<T>` di materi 16, tapi berlaku saat runtime juga.

---

## 5. Kapan Harus Digunakan (Use Cases)

- **Setiap input eksternal**: request body, query params, form, env vars, file JSON — semua yang melintasi trust boundary.
- **API layer (Express/Next.js route)** — validasi sebelum controller sees data.
- **Shared contracts antara frontend & backend** — skema Zod dibagi supaya tipe konsisten end-to-end (materi 26-27).
- **Parsing & transformasi** data saat masuk (misal `z.coerce.number()` untuk query).
- **Config/env validation** sekaligus memberi tipe (materi 18 bisa ditingkatkan dengan Zod).

---

## 6. Poin-poin Penting & Best Practices

1. **Jangan pernah `as` terhadap request body** — gunakan Zod (`safeParse`/`parse`) lalu pakai hasilnya.
2. **Gunakan `safeParse`** (bukan `parse`) di middleware agar error bisa di-handle dengan HTTP status (422); `parse` melempar exception yang harus ditangkap.
3. **`z.infer` sekali definisi dua-manfaat** — hindari menulis ulang tipe manual yang bisa basi.
4. **Pesan error yang jelas** — pass argumen `(msg)` untuk field penting.
5. **`.partial()` untuk update** — hindari skema terpisah yang berisiko diverging.
6. **Satu `import type` vs `import`** — `z` dipakai runtime; tipe hasil (`z.infer`) bisa dire-export `type`.
7. **Constrain jenis schema yang diizinkan di middleware** — ZodType generic menjaga fleksibilitas tapi tetap type-safe.

---

## 7. Kesalahan Umum (Common Pitfalls & Anti-patterns)

| Kesalahan | Contoh | Akibat | Perbaikan |
|---|---|---|---|
| `as` pada req.body | `const b = req.body as Buku` | runtime bisa tetap kotor | Zod + safeParse |
| `parse()` tanpa try-catch | throws di middleware | 500 bukannya 422 | `safeParse` atau bungkus |
| Tipe didefinisikan manual (bukan z.infer) | interface + schema terpisah | keduanya mudah beda | `z.infer<typeof Schema>` |
| Validasi terlalu longgar | `z.any()` pada field | kotor masuk | tipe spesifik per field |
| Mengabaikan `.coerce()` untuk query | `req.query.page` string diolah → NaN | angka tak valid | `z.coerce.number()` |
| Tidak menerapkan di semua route | hanya sebagian POST ter-valid | celah di route lain | pasang middleware di semua mutasi |

## 8. Soal Latihan & Kunci Jawaban

### Soal 1
Buat Zod schema untuk endpoint peminjaman buku `BuatPeminjamanSchema`:
- `bukuId: number` (int, positif),
- `anggotaId: number` (int, positif),
- `durasiHari: number` (int, min 1, max 30).

Dapatkan tipe `BuatPeminjamanDTO` dengan `z.infer`. Deklarasikan juga `UpdatePeminjamanSchema = BuatPeminjamanSchema.partial()`.

### Soal 2
Tulis middleware `validateBody` yang *sangat* ringkas: pakai `schema.safeParse(req.body)`; bila gagal, kirim `422` dengan `flatten().fieldErrors`; bila sukses, set `req.body = result.data` dan `next()`. Gunakan `ZodType<T>` agar generic.

---

### Jawaban & Pembahasan

```typescript
// Soal 1
import { z } from "zod";

export const BuatPeminjamanSchema = z.object({
    bukuId:      z.number().int("harus integer").positive("harus > 0"),
    anggotaId:   z.number().int().positive(),
    durasiHari:  z.number().int().min(1, "min 1 hari").max(30, "max 30 hari"),
});

export const UpdatePeminjamanSchema = BuatPeminjamanSchema.partial();

export type BuatPeminjamanDTO = z.infer<typeof BuatPeminjamanSchema>;
export type UpdatePeminjamanDTO = z.infer<typeof UpdatePeminjamanSchema>;
```

**Pembahasan**: skema menyimpan aturan bisnis (durasi 1-30 hari) sebagai satu entitas; tipe diturunkan dari skema — tidak ada duplikasi. `.partial()` menghindari skema update kedua yang terpisah.

```typescript
// Soal 2 — src/middleware/validateBody.ts
import type { Request, Response, NextFunction } from "express";
import type { ZodType } from "zod";

export function validateBody<T>(schema: ZodType<T>) {
    return (req: Request, res: Response, next: NextFunction): void => {
        const result = schema.safeParse(req.body);

        if (!result.success) {
            res.status(422).json({
                success: false,
                message: "Data tidak valid",
                errors: result.error.flatten().fieldErrors,
            });
            return;
        }
        req.body = result.data;
        next();
    };
}
```

**Pembahasan**: dengan `ZodType<T>`, skeleton generic — `req.body` diganti dengan nilai `T` setelah sukses, sehingga controller menerima data yang sudah typed & bersih. `503` vs `422`: ini menandakan *user error*, bukan server error — tepat.
