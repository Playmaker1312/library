# 7. Array dan Tuple — Koleksi Data yang Typed

> 🟢 **Level 1 — Bagian C** | 🧩 **Melanjutkan [[6. Union Types dan Literal Types — Tipe yang Lebih Ekspresif]]**

---

## 1. Penjelasan Singkat & Konsep Dasar

Hampir semua data perpustakaan adalah *kumpulan*: daftar buku, stok per kategori, log peminjaman. Dua cara menyimpan kumpulan data typed di TypeScript:

- **Array `T[]` / `Array<T>`** — sekumpulan nilai dengan **tipe sama**, panjang **bebas**.
- **Tuple `[A, B, C]`** — sekumpulan nilai dengan **urutan & tipe tetap**, panjang **fixed**.

```text
string[]        → banyak string, panjang bebas
[number, string] → TEPAT 2 elemen: number dulu, string kedua
readonly T[]    → array yang TIDAK bisa dimodifikasi
```

Konsep penting tambahan: **readonly** — kita bisa membuat kontrak bahwa array/tuple tidak akan dimutasi, sangat berguna ketika berbagi data antar modul (mencegah satu bagian kode merusak yang lain).

**Benang merah**: di materi 6 literal types membantu kita memvalidasi *satu nilai*. Array/tuple mengulang konsep ini *untuk kumpulan nilai* — fondasi sebelum kita masuk ke object/interface (materi 8) yang akan mendominasi struktur data aplikasi.

---

## 2. Fungsi & Kegunaan Utama

- **Koleksi yang homogeneous & aman**: `Buku[]` = daftar buku; compiler tahu semua elemen `Buku`.
- **Mencegah pencampuran tipe**: `string[]` menolak `push(123)`.
- **Tuple untuk data "baris berurutan"** dengan makna posisi: koordinat `[latitude, longitude]`, pasangan `[id, judul]`, baris CSV.
- **`readonly` sebagai pengaman** — memberi tahu pemanggil "jangan modifikasi", dan TypeScript *menegakkan*-nya.
- **Named tuples / rest pada tuple** membuat elemen posisional lebih terbaca.

## 3. Contoh Kode & Implementasi (Real-world Example)

```typescript
// src/types/koleksi.ts

// ─── Array ──────────────────────────────────────────────────────────
const judulBuku: string[] = ["Clean Code", "The Pragmatic Programmer"];
const hargaBuku: number[] = [150000, 175000, 200000];

// Bentuk alternatif identik
const stokBuku: Array<number> = [5, 3, 0];

// Array dari object — didukung di materi 8 secara penuh setelah interface
const katalog: Array<{ id: number; judul: string; stok: number }> = [
    { id: 1, judul: "Clean Code", stok: 5 },
    { id: 2, judul: "Laskar Pelangi", stok: 3 },
];

// readonly array — tidak bisa dimodifikasi
const kategoriTetap: readonly string[] = ["Fiksi", "Non-Fiksi", "Sains"];
// kategoriTetap.push("Baru");   // ❌ TS2339: 'push' tidak ada di readonly

// ─── Tuple — panjang dan tipe fixed ────────────────────────────────
type InfoBuku = [number, string, boolean];   // [id, judul, tersedia]

const buku1: InfoBuku = [1, "Clean Code", true];   // ✅
// const buku2: InfoBuku = ["Clean Code", 1, true]; // ❌ urutan salah
// const buku3: InfoBuku = [1, "Clean Code"];       // ❌ kurang elemen

// Destructuring tuple — setiap posisi sudah diketahui tipenya
const [id, judul, tersedia] = buku1;
console.log(id, judul, tersedia);   // type: number, string, boolean

// Named tuple (TS 4.0+) — lebih readable
type KoordinatPeta = [latitude: number, longitude: number];
const lokasi: KoordinatPeta = [-6.2088, 106.8456];

// Tuple dengan rest elements — log entries: [tanggal, level, ...pesan]
type LogEntry = [Date, string, ...string[]];
const log: LogEntry = [new Date(), "ERROR", "File tidak ditemukan", "Coba lagi"];

// ─── Kasus nyata: ringkasan stok per kategori (pasangan array+record) ───
type RingkasanKategori = [kategori: string, jumlah: number];
const ringkasan: RingkasanKategori[] = [
    ["Sains", 12],
    ["Teknologi", 34],
];

function cariJumlah(ringkasan: readonly RingkasanKategori[], k: string): number {
    return ringkasan.find(([nama]) => nama === k)?.[1] ?? 0;
}
console.log(cariJumlah(ringkasan, "Sains"));     // 12
console.log(cariJumlah(ringkasan, "Komik"));     // 0
```

## 4. Analogi Sederhana

**Sistem Perpustakaan.**

- **Array `string[]`** = **deretan label kartu katalog** di sebuah laci: semua adalah kertas katalog (semua string), panjang laci bebas (bisa 5, 50, atau 500 kartu).
- **Tuple `[number, string]`** = **baris pada rak inventaris**: kolom pertama selalu *kode rak (angka)*, kolom kedua selalu *nama buku (teks)*. Jika petugas menulis terbalik (nama lalu kode), rak-rak berantakan — tuple *menolak itu* di depan.
- **Tuple dengan named element** = **form isian dengan label**, seperti "Latitude: -6.2 / Longitude: 106.8" — posisinya tetap, tapi label membantu siapa pun membacanya.
- **Array of tuples** = **buku besar inventaris** dengan baris-baris `[kode, nama]` yang tidak boleh salah kolom.
- **`readonly`** = **buku besar yang memang ditulis hanya oleh petugas khusus** — anggota lain tidak boleh mencoret-coret; hanya menghitung jumlahnya.

---

## 5. Kapan Harus Digunakan (Use Cases)

- **Array `T[]`**: semua daftar koleksi — katalog buku, daftar anggota, log events.
- **`readonly T[]` / `ReadonlyArray<T>`**: parameter fungsi yang hanya dibaca (tidak dimutasi) — kontrak lebih kuat untuk fungsi `cariJumlah` di contoh.
- **Tuple**: 
  - pasangan tetap `[string, number]` (nama, nilai),
  - koordinat `[latitude, longitude]`,
  - argumen dengan posisi bermakna (misal `useState` mengembalikan `[state, setter]` di React, materi 25),
  - baris data CSV/table.
- **Jangan pakai tuple** untuk data yang *mudah salah posisi* lebih dari 3-4 elemen — beralih ke interface/object (materi 8) yang memberi nama tiap field.

---

## 6. Poin-poin Penting & Best Practices

1. **Gunakan `T[]` (atau `ReadonlyArray<T>`) untuk koleksi homogeneous**; gunakan tuple hanya saat urutan elemen *bermakna*.
2. **Prefer `readonly` pada parameter koleksi** — `cariJumlah(data: readonly Tuple[])` menyatakan "saya tidak akan mengubah isinya".
3. **Destructuring tuple** memberi nama lokal pada posisi — tambahkan `const [lat, lng] = lokasi`.
4. **Named tuples** (`[nama: string, jumlah: number]`) jauh lebih komunikatif daripada anonim.
5. **Tuple tidak menggantikan object**: untuk > 3-4 field atau field yang berubah-ubah, object/interface lebih aman (materi 8-9).
6. **Menggabungkan array + union**: `(string | number)[]` = array yang isinya bisa string/number; `[string, number]` = *posisi* tertentu — dua hal berbeda!

---

## 7. Kesalahan Umum (Common Pitfalls & Anti-patterns)

| Kesalahan | Contoh | Akibat | Perbaikan |
|---|---|---|---|
| Memakai array untuk data posisional | koordinat disimpan `[106, -6]` tanpa makna | salah urutan tak terdeteksi | pakai tuple ber-label atau object |
| Menambah field ke tuple berulang | `[id, judul, tahun, ...harga]` jadi panjang | mudah salah posisi | ganti object/interface |
| Lupa readonly pada param & membiarkan mutasi | fungsi `cariJumlah` memodifikasi array | state rusak di luar |`readonly`, gunakan `.filter`/spread |
| `push` ke tuple | `arr.push(...)` di tuple | TS2365 / rusak kontrak | gunakan tuple yang sudah lengkap atau array |
| Mengira `[]` = tuple | `const x: number[] = []` lalu `x[0]` diakses | `undefined` pake strict | cek `?.` dan index guard sebelum akses |
| Menggabung dua makna | `type A = number[];` lalu assign 0 | TS2322 | pisahkan array vs tuple vs union |

## 8. Soal Latihan & Kunci Jawaban

### Soal 1
Definisikan tipe `BukuRingkas` sebagai tuple `[id, judul]` (number, string). Buat array dari tipe itu, lalu tulislah fungsi `daftarJudul(buku: readonly BukuRingkas[]): string[]` yang mengembalikan daftar judul saja. Pastikan panggilan `buku.push(...)` di dalam fungsi **gagal type-check**.

### Soal 2
Klasifikasikan dengan benar (jawab setiap baris) apakah kode berikut valid dan apa tipenya:

```typescript
const a: number[] = [1, 2, 3];
const b: [number, number] = [1, 2];
const c = ["a", "b"];      // tipe?
const d: readonly string[] = ["x"];
const e: Array<{ id: number }> = [{ id: 1 }];
```

---

### Jawaban & Pembahasan

```typescript
// Soal 1
type BukuRingkas = [id: number, judul: string];

const daftar: BukuRingkas[] = [
    [1, "Clean Code"],
    [2, "Laskar Pelangi"],
];

function daftarJudul(buku: readonly BukuRingkas[]): string[] {
    // (sengaja tidak kita panggil .push — karena `buku` readonly, push TIDAK ada)
    return buku.map(([, judul]) => judul);
}

console.log(daftarJudul(daftar));   // ["Clean Code", "Laskar Pelangi"]
// daftarJudul(daftar).push("x");   // TS mangkir? ya, "expression has type ..."
```

**Pembahasan**: parameter `readonly BukuRingkas[]` membuat `push`/`splice`/`pop` hilang dari tipe — TypeScript menolak mutasi. Destructuring `[, judul]` mengubah posisi kedua ke nama `judul`.

**Soal 2 — tipe & validitas**

```typescript
const a: number[] = [1, 2, 3];       // ✅ array number
const b: [number, number] = [1, 2];  // ✅ tuple 2 elemen number
const c = ["a", "b"];                // ✅ tipe: string[] (infer)
const d: readonly string[] = ["x"];  // ✅ readonly array — d.push gagal
const e: Array<{ id: number }> = [{ id: 1 }];  // ✅ array of object
```

**Pembahasan**: `a` = array; `b` = tuple dengan *posisi*; `c` di-infer sebagai `string[]`; `d` readonly; `e` menunjukkan array sangat fleksibel — dan ini jembatan menuju materi berikut: object di dalam koleksi.
