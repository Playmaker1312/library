# 26. Next.js App Router dengan TypeScript

> 🟣 **Level 7 — Bagian M** | 🧩 **Melanjutkan [[25. React dengan TypeScript — Component yang Type-safe]]**

---

## 1. Penjelasan Singkat & Konsep Dasar

**Next.js** adalah framework full-stack React: satu codebase yang bisa merender UI di **server (Server Components / SSR)**, menyediakan **API routes**, dan juga **client** — semuanya TypeScript end-to-end.

Dua konsep inti App Router (Next.js 13.4+):

```text
Server Component (default)   → fetch data DI SERVER, kirim HTML jadi.
                               typing searchParams/params sebagai interface.
API Route Handlers           → GET/POST/PUT/DELETE di file route.ts,
                               memakai syntax Request/Response web standar.

┌─────────────────────────────────────────────┐
│  Server: fetch DB → render → streaming HTML │
│  Client: interaksi UI, React Query, hooks    │
└─────────────────────────────────────────────┘
```

**Mengapa ini "puncak" roadmap**: dari Level 1 (CLI) → Level 5 (API Express) → Level 6 (test) → hingga di sini, kita bisa membuat *satu* deployable app yang memuat backend & frontend dengan **típ_ yang sama** (`Buku`, `ApiResponse<T>`) di kedua sisi — "type-safe full-stack".

**Benang merah**: ini menyatukan semuanya: interface (materi 8), Zod (materi 20), generics (materi 14-15), dan pemisahan server/client. Skill yang sudah dipelajari *tak terbuang* — hanya diretas dalam paradigma full-stack.

---

## 2. Fungsi & Kegunaan Utama

- **Server Components** — fetch data langsung di server (bukan `useEffect` client), lebih cepat & aman (tidak mengekspos token/query ke browser).
- **App Router dengan typed props** — `searchParams`, `params` sebagai interface → autocomplete di page.
- **Route Handlers** — API endpoints di dalam app (untuk client-side revalidation), berbagi tipe dengan UI.
- **Metadata typed** — SEO/dokumen dengan tipe `Metadata` bawaan.
- **Berbagi jenis** antara server (DB) dan client (props) — batas terjelas dari "Satu source of truth".

### Step 2 — Page server component (fetch server-side)

```typescript
// src/lib/buku.ts
import type { Buku } from "@/types/buku";

export async function ambilBuku(params: {
    halaman: number;
    kategori?: string;
    cari?: string;
}): Promise<{ buku: Buku[]; total: number }> {
    // contoh: dari DB / API internal. Server-side → tidak expose creds.
    const result = await fetch(`${process.env.INTERNAL_API_URL}/buku?page=${params.halaman}&kategori=${params.kategori ?? ""}&cari=${params.cari ?? ""}`, {
        cache: "no-store",
    });
    if (!result.ok) throw new Error(`Gagal ambil buku: ${result.status}`);
    const body: { success: true; data: { buku: Buku[]; total: number } } = await result.json();
    return body.data;
}
```

```tsx
// src/app/buku/page.tsx  (Server Component — default)
import type { Metadata } from "next";
import { BukuGrid } from "@/components/BukuGrid";
import { ambilBuku } from "@/lib/buku";

export const metadata: Metadata = {
    title: "Katalog Buku | Perpustakaan Digital",
    description: "Temukan buku favorit Anda",
};

interface HalamanBukuProps {
    searchParams: {
        halaman?: string;
        kategori?: string;
        cari?: string;
    };
}

export default async function HalamanBuku({ searchParams }: HalamanBukuProps) {
    const halaman  = parseInt(searchParams.halaman ?? "1");
    const kategori = searchParams.kategori;
    const cari     = searchParams.cari;

    const { buku, total } = await ambilBuku({ halaman, kategori, cari });

    return (
        <main>
            <h1>Katalog Buku</h1>
            <p>{total} buku ditemukan</p>
            <BukuGrid buku={buku} />
        </main>
    );
}
```

### Step 3 — Route handler (API endpoint) type-safe

```typescript
// src/app/api/buku/route.ts
import { NextRequest, NextResponse } from "next/server";
import { z } from "zod";
import { db } from "@/lib/database";   // contoh ORM/client

const CreateBukuSchema = z.object({
    judul: z.string().min(1),
    pengarang: z.string().min(1),
    tahun: z.number().int(),
    harga: z.number().min(0),
    stok: z.number().int().min(0),
    kategori: z.string(),
});

export async function GET(request: NextRequest): Promise<NextResponse> {
    const { searchParams } = request.nextUrl;
    const page = parseInt(searchParams.get("halaman") ?? "1");
    const perPage = 15;

    const buku = await db.buku.findMany({
        skip: (page - 1) * perPage,
        take: perPage,
        orderBy: { judul: "asc" },
    });

    return NextResponse.json({ success: true, data: buku });
}

export async function POST(request: NextRequest): Promise<NextResponse> {
    const body = await request.json();
    const result = CreateBukuSchema.safeParse(body);

    if (!result.success) {
        return NextResponse.json(
            { success: false, errors: result.error.flatten().fieldErrors },
            { status: 422 },
        );
    }

    const bukuBaru = await db.buku.create({ data: result.data });
    return NextResponse.json({ success: true, data: bukuBaru }, { status: 201 });
}
```

## 4. Analogi Sederhana

**Sistem Perpustakaan.**

- **Server Component** = **pusat informasi perpustakaan**: pengunjung (browser) tidak perlu masuk ke gudang (DB/token) — petugas pusat kuliah (server) mengambil datanya di belakang layar, lalu *menyajikan kartu buku yang sudah jadi* (HTML) di rak tampilan. Pengunjung tidak pernah membawa kunci gudang — lebih aman (rahasia tetap di server).
- **`searchParams` typed** = **papan "cari" yang hanya menerima parameter resmi** — halaman ("halaman"), kategori, pencarian — dengan tipe yang jelas, bukan string acak.
- **Route Handler (`route.ts`)** = **loket API internal dalam gedung yang sama**: komponen UI di lantai depan bisa memanggil `/api/buku` (untuk revalidation client) — klien dan server berbicara dalam bahasa yang sama (`Buku`, `ApiResponse<T>`).
- **Zod di route handler** = **petugas verifikasi di loket**: memeriksa body POST sebelum masuk ke gudang (materi 20 — persis sama, hanya berpindah rumah).

## 5. Kapan Harus Digunakan (Use Cases)

- **App full-stack dalam satu deployable** — Next.js untuk server + client pada satu repo.
- **Data yang perlu di-render tanpa loading di server** — SEO-friendly katalog buku.
- **API yang butuh endpoints internal & tipe bersama** — shared types antara page & route handlers.
- **Memanfaatkan CDN/Vercel** untuk edge/serverless.
- **Kapan TIDAK**: kalau backend sudah terpisah & mapan (Express+Postgres, level 5-6) dan frontend hanya konsumen — SPA React (materi 25) mungkin lebih ringkas.

---

## 6. Poin-poin Penting & Best Practices

1. **Server Components default** — pindahkan kerja berat (fetch, transform) ke server; tambahkan `"use client"` hanya untuk komponen interaktif.
2. **Typed `searchParams`/`params`** — parse & buat interface untuk menghindari `any`.
3. **Zod di route handlers** — jangan `as` body; `safeParse` seperti di Express (materi 20).
4. **Satu source of truth tipe** — simpan tipe entitas di `types/` bersama & import di kedua sisi.
5. **Jangan expose internal**: jalur fetch server memakai env `INTERNAL_API_URL`/DB creds — tidak bocor ke client bundle.
6. **Adapt error state** — server component yang error bisa dipandu ke `not-found` / error boundary.
7. **Gunakan `React Query` hanya di client** — server sudah async; jangan fetch ganda di dua lapis tanpa alasan.

---

## 7. Kesalahan Umum (Common Pitfalls & Anti-patterns)

| Kesalahan | Contoh | Akibat | Perbaikan |
|---|---|---|---|
| Fetch di server lalu fetch lagi di client | server & client minta data sama | request ganda, redaman | satu sumber — biarkan Server Component |
| `searchParams` tanpa tipe | `any` | kehilangan autocomplete/null safety | interface props + parse |
| `as` pada body route | `db.create({ data: body as Buku })` | runtime kotor | Zod safeParse |
| Menyimpan secret di client | token DB di bundle | bocornya kredensial | jalur server pakai env internal |
| Semua komponen `"use client"` | file interaktif besar | kehilangan SSR | beri `"use client"` hanya yang perlu |
| Tipe duplikat front/back | definisikan `Buku` dua kali | drift | shared types / package |

## 8. Soal Latihan & Kunci Jawaban

### Soal 1
Buat Server Component `src/app/buku/[id]/page.tsx` yang:
- Menerima `params` (`id: string`),
- memanggil `ambilBukuDetail(id)` (return `Promise<Buku>`),
- menampilkan judul & pengarang.
Sertakan `metadata` typed sederhana.

### Soal 2
Tulis Route Handler `DELETE /api/buku/[id]` yang memvalidasi `id` (parse + positif) dan mengembalikan `404` bila buku tidak ada. Jelaskan bagaimana tipe `Buku` bisa di-share antara handler dan page.

---

### Jawaban & Pembahasan

```tsx
// Soal 1
// src/app/buku/[id]/page.tsx
import type { Metadata } from "next";
import { ambilBukuDetail } from "@/lib/buku";
import type { Buku } from "@/types/buku";

interface Props {
    params: { id: string };
}

export async function generateMetadata({ params }: Props): Promise<Metadata> {
    const buku: Buku = await ambilBukuDetail(Number(params.id));
    return { title: buku.judul };
}

export default async function HalamanDetail({ params }: Props) {
    const buku = await ambilBukuDetail(Number(params.id));

    return (
        <article>
            <h1>{buku.judul}</h1>
            <p>Pengarang: {buku.pengarang}</p>
            <p>Rp {buku.harga.toLocaleString("id-ID")}</p>
            <span>{buku.tersedia ? "Tersedia" : "Habis"}</span>
        </article>
    );
}
```

**Pembahasan**: `params` di-digitasi via interface; metadata digenerate sebagaiynchronously dari data (SEO dinamis); `Buku` dikonsumsi langsung sebagai tipe di dua sumber (fetch & render).

```typescript
// Soal 2 — src/app/api/buku/[id]/route.ts
import { NextRequest, NextResponse } from "next/server";
import { db } from "@/lib/database";
import type { Buku } from "@/types/buku";

export async function DELETE(
    _request: NextRequest,
    { params }: { params: { id: string } },
): Promise<NextResponse> {
    const id = Number(params.id);
    if (!Number.isInteger(id) || id <= 0) {
        return NextResponse.json(
            { success: false, message: "ID tidak valid" },
            { status: 400 },
        );
    }

    const ada: Buku | null = await db.buku.findUnique({ where: { id } });
    if (!ada) {
        return NextResponse.json(
            { success: false, message: `Buku dengan ID ${id} tidak ditemukan` },
            { status: 404 },
        );
    }

    await db.buku.delete({ where: { id } });
    return NextResponse.json({ success: true, data: null });
}
```

**Pembahasan**: Route Handler menggunakan `params.id` yang di-parse dan divalidasi; status HTTP sesuai kasus (400 invalid, 404 not found, 200 sukses). Tipe `Buku` di-import dari `@/types/buku` yang **sama** dipakai page — sehingga handler dan UI *dijamin strukturnya sinkron*, menghilangkan drift antar lapisan (ini inti "End-to-end Type Safety" dari roadmap).
