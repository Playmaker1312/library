# 25. React dengan TypeScript — Component yang Type-safe

> 🟣 **Level 7 — Bagian L** | 🧩 **Melanjutkan [[24. Pattern yang Paling Berguna di TypeScript]]**

---

## 1. Penjelasan Singkat & Konsep Dasar

Dari backend yang mature (Level 5-6), kita sekarang membangun **frontend dengan TypeScript**: komponen React yang **type-safe dari props sampai state**, serta **API client yang terkunci ke kontrak backend** (yang sudah kita bentuk dengan `ApiResponse<T>` di Level 5).

Konsep inti:

```text
Interface Props   → kontrak input komponen (materi 8)
FC / typed hooks  → return type JSX yang ditegakkan
API client typed  → response divalidasi terhadap tipe backend (axios generics)
Custom hooks      → reusable, generic, dan typed (materi 14-15)
```

Tiga *key pattern* yang membuat frontend TS menjadi kuat:

1. **Props interface** — setiap komponen mendeklarasikan *input apa yang ia butuhkan*.
2. **Custom hooks typed** — `useQuery<T>` dari React Query mengembalikan data bertipe T.
3. **API client generics** — `client.get<ApiResponse<Buku>>` memastikan response match kontrak backend.

**Benang merah**: seluruh fondasi tipe dari Level 1-4 (interface, generics, literal, discriminated union) dan kontrak API dari Level 5-6 (`ApiResponse<T>`, `Buku`) kini *di-consume* di UI. Ini adalah titik di mana "type-safe end-to-end" benar-benar terlihat.

---

## 2. Fungsi & Kegunaan Utama

- **Props & state typed** — mencegah komponen menerima data salah bentuk (misal `buku.stok` diakses padahal belum di-pass).
- **Autocomplete di JSX** — mengetik `buku.` muncul properti yang ada.
- **API safety** — client yang dibangun dengan tipe backend mencegah field salah/typo pada response.
- **Caching & state handling** — React Query + types menangani loading/error/data dengan aman.
- **Konsistensi front-back** — berbagi tipe (monorepo/shared package) menghapus drift antar tim.

### Step 3 — API client typed

```typescript
// src/api/buku.api.ts
import axios from "axios";
import type { Buku, ApiResponse, CreateBukuDTO } from "../types/api";

const client = axios.create({
    baseURL: import.meta.env.VITE_API_URL ?? "http://localhost:3000/api/v1",
    headers: { "Content-Type": "application/json" },
});

client.interceptors.request.use(config => {
    const token = localStorage.getItem("token");
    if (token) config.headers.Authorization = `Bearer ${token}`;
    return config;
});

export const bukuApi = {
    getAll: async (params?: { page?: number; kategori?: string }): Promise<Buku[]> => {
        const { data } = await client.get<ApiResponse<Buku[]>>("/buku", { params });
        return data.data;
    },
    getById: async (id: number): Promise<Buku> => {
        const { data } = await client.get<ApiResponse<Buku>>(`/buku/${id}`);
        return data.data;
    },
    create: async (bukuData: CreateBukuDTO): Promise<Buku> => {
        const { data } = await client.post<ApiResponse<Buku>>("/buku", bukuData);
        return data.data;
    },
    update: async (id: number, bukuData: Partial<CreateBukuDTO>): Promise<Buku> => {
        const { data } = await client.put<ApiResponse<Buku>>(`/buku/${id}`, bukuData);
        return data.data;
    },
    delete: async (id: number): Promise<void> => {
        await client.delete(`/buku/${id}`);
    },
};
```

// src/components/BukuCard.tsx
import type { Buku } from "../types/api";

interface BukuCardProps {
    buku: Buku;
    onPinjam?: (bukuId: number) => void;   // optional callback
    ukuran?: "sm" | "md" | "lg";            // literal type

export function BukuCard({ buku, onPinjam, ukuran = "md" }: BukuCardProps) {

### Step 5 — Custom hook typed (React Query)

```typescript
// src/hooks/useBuku.ts
import { useQuery, useMutation, useQueryClient } from "@tanstack/react-query";
import { bukuApi } from "../api/buku.api";
import type { CreateBukuDTO } from "../types/api";

export function useBukuList(page: number = 1, kategori?: string) {
    return useQuery({
        queryKey: ["buku", page, kategori],
        queryFn: () => bukuApi.getAll({ page, kategori }),
        staleTime: 5 * 60 * 1000,
    });
}

export function useBukuDetail(id: number) {
    return useQuery({
        queryKey: ["buku", id],
        queryFn: () => bukuApi.getById(id),
        enabled: id > 0,          // jangan fetch bila id tidak valid
    });
}

export function useCreateBuku() {
    const qc = useQueryClient();
    return useMutation({
        mutationFn: (data: CreateBukuDTO) => bukuApi.create(data),
        onSuccess: () => qc.invalidateQueries({ queryKey: ["buku"] }),
    });
}
```

## 4. Analogi Sederhana

**Sistem Perpustakaan.**

- **Props interface** = **formulir "yang harus diserahkan" setiap kali menampilkan kartu buku di papan**: papan (komponen `BukuCard`) *mewajibkan* diberi objek `Buku` lengkap — petugas UI menolak bila data tak lengkap/salah bentuk.
- **API client typed** = **loket pesan resmi antara papan dan gudang**: semua data yang lewat harus sesuai *format nota* (`ApiResponse<Buku>`). Jika gudang mengirim bentuk lain, terjadi error compile — bukan error tampilan aneh di layar pengguna.
- **Custom hooks** = **layanan terpusat di meja depan**: `useBukuList` menangani "cari daftar buku" di satu tempat; semua papan yang butuh memanggil layanan yang sama, dengan *jawaban bertipe* (array `Buku`, atau `error`).
- **React Query** = **sistem cache perpustakaan**: hasil pencarian disimpan 5 menit (staleTime); permintaan ulang yang sama tidak perlu pergi ke gudang lagi.

---

## 5. Kapan Harus Digunakan (Use Cases)

- **Setiap komponen UI yang menerima data** — selalu definisikan `Props` interface.
- **Fetching data** — gunakan React Query (+ custom hook) daripada `useEffect` manual; typed secara alami.
- **Form input & submit** — typed state & DTO memastikan data yang dikirim sesuai kontrak backend.
- **CRUD dashboard** (daftar buku, form tambah/ubah, tombol pinjam) — dikombinasikan dengan API client.
- **Monorepo/shared types** — bila memungkinkan, share `types/api.ts` & Zod schema antara frontend & backend (materi 27).

---

## 6. Poin-poin Penting & Best Practices

1. **Selalu tipekan Props** — jangan biarkan komponen menerima objek `any`.
2. **Jangan `as any` untuk response API** — gunakan generic (`client.get<ApiResponse<Buku>>`); bila tidak yakin bentuknya, validasi runtime (Zod) dulu.
3. **Prefer `useQuery` untuk read & `useMutation` untuk write** — handle loading/error/refetch secara terpusat.
4. **Bagi tipe** — buat `types/api.ts` sebagai satu sumber kebenaran; untuk project besar gunakan shared package.
5. **Komponen kecil & typed** — pecah UI menjadi komponen dengan props eksplisit (reusable, testable).
6. **`enabled` untuk mencegah fetch tak berguna** (misal `id > 0`).
7. **Jangan menyimpan token di localStorage bila rawan XSS** — pertimbangkan cookie httpOnly; minimal, jangan taruh di log.

---

## 7. Kesalahan Umum (Common Pitfalls & Anti-patterns)

| Kesalahan | Contoh | Akibat | Perbaikan |
|---|---|---|---|
| Props tidak ditype | `({ buku }: any)` | kehilangan autocomplete & safety | interface Props |
| `as` pada response API | `data as Buku[]` | bohong pada compiler; runtime tak terjamin | generic + optional runtime check |
| Data fetching manual di useEffect tanpa types | `setState(res.data)` | error & reload rumit | React Query + typed hook |
| Type tersebar/duplikat | tipe Buku didefinisikan di 3 file | drift antar file | satu `types/api.ts` (atau shared) |
| Menaruh logika bisnis di komponen | komponen berisi `fetch` langsung | sulit diuji | custom hooks |
| Mengabaikan error state | `useQuery` tanpa `isError` | UI diam saat gagal | tangani error state |

## 8. Soal Latihan & Kunci Jawaban

### Soal 1
Buat interface `Props` untuk komponen `FormBuku` dengan:
- `initial?: CreateBukuDTO`,
- `onSubmit: (data: CreateBukuDTO) => void | Promise<void>`,
- `isSubmitting?: boolean` (default false),
dan tulis *signature* komponen (tanpa detail JSX penuh) yang aman.

### Soal 2
Tulis `useBukuDetail(id)` hook dengan React Query yang **menonaktifkan fetch** bila `id <= 0`, dan mengembalikan tipe `Buku`. Jelaskan apa yang terjadi bila `getById` di sisi backend belum mengembalikan struktur `ApiResponse<Buku>` yang sama.

---

### Jawaban & Pembahasan

```typescript
// Soal 1
import type { FormEvent } from "react";
import type { CreateBukuDTO } from "../types/api";

interface FormBukuProps {
    initial?: CreateBukuDTO;
    onSubmit: (data: CreateBukuDTO) => void | Promise<void>;
    isSubmitting?: boolean;
}

export function FormBuku({ initial, onSubmit, isSubmitting = false }: FormBukuProps) {
    const handleSubmit = (e: FormEvent<HTMLFormElement>): void => {
        e.preventDefault();
        // kumpulkan state form → data: CreateBukuDTO → onSubmit(data)
    };

    return (
        <form onSubmit={handleSubmit}>
            {/* field judul, pengarang, tahun, harga, stok, kategori */}
            <button type="submit" disabled={isSubmitting}>
                {isSubmitting ? "Menyimpan..." : "Simpan"}
            </button>
        </form>
    );
}
```

**Pembahasan**: Props mengekspos kontrak jelas; `onSubmit` boleh async; `isSubmitting` default aman. Konsumen tidak bisa lupa field wajib (initial), dan compiler menegakkan bentuk DTO.

```typescript
// Soal 2
import { useQuery } from "@tanstack/react-query";
import { bukuApi } from "../api/buku.api";
import type { Buku } from "../types/api";

export function useBukuDetail(id: number) {
    return useQuery({
        queryKey: ["buku", id],
        queryFn: () => bukuApi.getById(id),
        enabled: id > 0,          // id <= 0 → tidak fetch
    });
}
```

**Pembahasan**: `enabled` mencegah request sia-sia. Jika backend mengembalikan struktur *berbeda* dari `ApiResponse<Buku>` (misal tidak ada `data`), maka `data.data` akan `undefined` dan `Buku` yang di-return tidak cocok — tanpa runtime check, aplikasi bisa tampil rusak meski *compile-time* lolos. Inilah alasan pentingnya **shared types** (materi 27) dan runtime validation (Zod) pada boundary.
