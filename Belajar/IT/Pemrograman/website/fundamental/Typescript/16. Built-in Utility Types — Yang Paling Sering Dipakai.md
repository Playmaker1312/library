# 16. Built-in Utility Types — Yang Paling Sering Dipakai

> 🟠 **Level 4 — Bagian H** | 🧩 **Melanjutkan [[15. Generic Class dan Interface]]**

---

## 1. Penjelasan Singkat & Konsep Dasar

Sering kita butuh **varian modifikasi** dari tipe yang sudah ada — "semua property jadi optional", "ambil hanya beberapa property", "buang id dari tipe create". Menulis semua itu manual membosankan & rawan error. **Utility types** adalah kumpulan tipe generik bawaan TypeScript untuk transformasi tersebut.

```typescript
interface Buku {
    id: number;
    judul: string;
    harga: number;
    stok: number;
    kategori: string;
    deskripsi?: string;
}

type UpdateBuku = Partial<Buku>;            // semua jadi optional
type CreateBuku = Omit<Buku, "id">;        // buang id (untuk create)
type KartuRingkas = Pick<Buku, "id" | "judul" | "harga">; // pilih sebagian
type Warna = Record<"merah" | "biru", string>;  // map kunci → nilai
```

**Utility yang paling sering dipakai** (dan akan muncul di seluruh Level 5-7):

| Utility | Efek |
|---|---|
| `Partial<T>` | semua property → optional |
| `Required<T>` | semua property → wajib |
| `Readonly<T>` | semua property → readonly |
| `Pick<T, K>` | ambil hanya K dari T |
| `Omit<T, K>` | T tanpa K |
| `Record<K, V>` | object: key K, value V |
| `Exclude<T, U>` | union T dikurangi U |
| `Extract<T, U>` | hanya bagian U dari union T |
| `NonNullable<T>` | T tanpa null/undefined |
| `ReturnType<F>` | tipe return dari fungsi F |
| `Parameters<F>` | tuple tipe parameter dari F |
| `Awaited<P>` | membuka Promise |

**Benang merah**: utility types *adalah generics yang sudah jadi* (materi 14-15). Kamu sudah melihat `Partial`/`Omit` dipakai di `InMemoryRepository` (materi 15); sekarang kita pahami mekanismenya secara utuh — termasuk cara membuat *versi sendiri* lewat mapped/conditional types di materi 17.

---

## 2. Fungsi & Kegunaan Utama

- **Menghindari mendefinisikan ulang tipe hampir sama** (DRY) — satu source of truth.
- **Update opsional** (`Partial`), **create tanpa id** (`Omit`), **response ringkas** (`Pick`).
- **Struktur key→value dengan key tertentu** (`Record`) — statistik per kategori.
- **Tipe yang berasal dari fungsi** (`ReturnType`, `Parameters`) — deklarasi tak perlu duplikat.
- **Unwrap promise** (`Awaited`) — memudahkan bekerja dengan `async`/fetch.
- **Membentuk dasar untuk API layer** (`ApiResponse<T>`, `Paginated<T>` di Level 5-7).

## 3. Contoh Kode & Implementasi (Real-world Example)

```typescript
// src/types/utility-examples.ts

interface Buku {
    id: number;
    judul: string;
    pengarang: string;
    isbn: string;
    tahun: number;
    harga: number;
    stok: number;
    kategori: string;
    deskripsi?: string;
}

type BukuUpdate = Partial<Buku>;       // { id?, judul?, ... }

function updateBuku(id: number, data: Partial<Buku>): Buku {
    const buku = katalog.find(b => b.id === id)!;   // (anggap sudah ada)
    return { ...buku, ...data };
}
updateBuku(1, { harga: 200000 });       // ✅ hanya harga
updateBuku(1, { stok: 0, harga: 0 });   // ✅ dua field

type BukuBaru = Omit<Buku, "id">;       // create → belum ada id
const dataBaru: BukuBaru = {
    judul: "TS Deep Dive", pengarang: "Basarat",
    isbn: "978", tahun: 2023, harga: 200000, stok: 5,
    kategori: "Teknologi",
};

type KartuBuku = Pick<Buku, "id" | "judul" | "pengarang" | "harga">;

type BukuImmutable = Readonly<Buku>;
const bukuTetap: BukuImmutable = katalog[0];
// bukuTetap.harga = 0;                 // ❌ readonly

type Kategori = "Fiksi" | "Non-Fiksi" | "Sains" | "Teknologi" | "Sejarah";
type Statistik = Record<Kategori, number>;

const statistik: Statistik = {
    "Fiksi": 45, "Non-Fiksi": 32, "Sains": 28,
    "Teknologi": 67, "Sejarah": 21,
};
// statistik["Komik"] = 3;              // ❌ bukan key dari Statistik

type Status = "dipinjam" | "dikembalikan" | "terlambat" | "hilang";
type Aktif = Exclude<Status, "dikembalikan" | "hilang">;   // "dipinjam" | "terlambat"
type Selesai = Extract<Status, "dikembalikan" | "hilang">; // "dikembalikan" | "hilang"
type Pasti = NonNullable<Buku | null | undefined>;         // Buku

// ─── Dari fungsi ─────────────────────────────────────────────────────
async function ambilBukuAPI(): Promise<Buku[]> { return []; }
type Hasil = Awaited<ReturnType<typeof ambilBukuAPI>>;   // Buku[]
type Params = Parameters<typeof updateBuku>;             // [id: number, data: Partial<Buku>]
```

## 4. Analogi Sederhana

**Sistem Perpustakaan.**

- **`Partial<T>`** = **formulir "perbarui data buku"** yang semua kolomnya *opsional* — cukup isi kolom yang berubah.
- **`Omit<T, "id">`** = **formulir "tambah buku baru"** — kolom *id* tidak kamu isi; sistem yang memberikannya otomatis.
- **`Pick<T, K>`** = **kartu ringkasan buku** di sampul — hanya kolom terpilih (`judul`, `harga`) yang ditampilkan.
- **`Readonly<T>`** = **buku-buku rujukan** di rak khusus — boleh dibaca, tidak boleh ditulis (hanya pustakawan yang memperbarui).
- **`Record<Kategori, number>`** = **tabel statistik** dengan satu baris per kategori (kunci tetap "Fiksi","Sains",...) dan nilai jumlah — kolom lain *tidak bisa* ditambahkan seenaknya.
- **`ReturnType` / `Parameters` / `Awaited`** = **meminjam "struktur hasil" dari fungsi lain** — jika fungsi `ambilBukuAPI` berubah, bentuk datanya otomatis mengikuti; tidak perlu menulis ulang definisi manual yang bisa basi.

---

## 5. Kapan Harus Digunakan (Use Cases)

- **Setiap operasi update** → `Partial<Entity>`; **setiap operasi create** → `Omit<Entity, "id" | "createdAt">`.
- **Response list/ringkas** → `Pick` untuk meminimalkan payload ke client.
- **Draft/immutable data** → `Readonly`.
- **Statistik & mapping kunci→nilai** → `Record`.
- **Menurunkan tipe dari fungsi/library tanpa duplikat** → `ReturnType`, `Parameters`, `Awaited`.
- **API & repository generik** (Level 5-7) → `ApiResponse<T>`, `Paginated<T>` yang dibangun di atas konsep ini.

---

## 6. Poin-poin Penting & Best Practices

1. **Pilih `Partial` untuk update, `Omit` untuk create** — pola API yang jelas.
2. **`Omit` untuk "kecuali", `Pick` untuk "hanya"** — sesuaikan dengan apa yang kamu tahan.
3. **`Record<K, V>` memastikan seluruh kunci terisi** — tidak boleh kurang (semua kategori ada).
4. **`Readonly` hanya compile-time** — seperti `readonly` di materi 8/12, ini pengaman developer.
5. **`Exclude`/`Extract` bekerja pada union**, bukan object — jangan salah tempat.
6. **`Awaited` lebih aman daripada `.then` manual** saat menurunkan tipe dari promise.
7. **Utility types tidak menghasilkan runtime** — murni compile-time, gratis.

---

## 7. Kesalahan Umum (Common Pitfalls & Anti-patterns)

| Kesalahan | Contoh | Akibat | Perbaikan |
|---|---|---|---|
| `Partial` untuk create | menerima `Partial<Buku>` saat tambah | field wajib bisa terlewat | `Omit<Buku, "id">` |
| `Pick` untuk "buang satu" | `Pick<Buku, banyak-field>` | panjang & salah satu | `Omit<Buku, "id">` |
| `Record` dengan key arbitrary | `Record<string, number>` padahal kategori fixed | kehilangan safety | key union (kategori) |
| `Exclude` pada object | `Exclude<Buku, ...>` | tidak sesuai sasaran (union-only) | gunakan `Omit` |
| Lupa `Readonly` hanya compile-time | berharap runtime tak berubah | perbedaan dengan runtime | anggap sebagai dokumentasi+safety compile |
| `ReturnType` pada fungsi overloaded | ambigu | hasil tak tentu | pilih signature spesifik |

## 8. Soal Latihan & Kunci Jawaban

### Soal 1
Untuk interface `Peminjaman` (id, bukuId, anggotaId, tanggalPinjam, batasKembali, tanggalKembali: Date|null, denda?), definisikan:
- `PeminjamanBaru` (tanpa id — untuk create),
- `PeminjamanUpdate` (semua optional),
- `RingkasanPeminjaman` (hanya id, bukuId, status),
- `ImmutablePeminjaman` (readonly),
- `DaftarPerBuku = Record<number, Peminjaman[]>` (key = bukuId).

### Soal 2
Tulis tipe `HasilFetch` dari `ReturnType<typeof ambilDariAPI>` di mana `ambilDariAPI` adalah async function returning `Promise<Buku[]>`. Gunakan `Awaited` agar hasilnya `Buku[]`. Jelaskan kenapa `Awaited` penting.

---

### Jawaban & Pembahasan

```typescript
// Soal 1
interface Peminjaman {
    id: number;
    bukuId: number;
    anggotaId: number;
    tanggalPinjam: Date;
    batasKembali: Date;
    tanggalKembali: Date | null;
    denda?: number;
}

type PeminjamanBaru = Omit<Peminjaman, "id">;
type PeminjamanUpdate = Partial<Peminjaman>;
type RingkasanPeminjaman = Pick<Peminjaman, "id" | "bukuId" | "tanggalKembali">;
type ImmutablePeminjaman = Readonly<Peminjaman>;
type DaftarPerBuku = Record<number, Peminjaman[]>;
```

**Pembahasan**: setiap transformasi mengekspresikan konteks penggunaan — create tanpa id, update sebagian, ringkasan sedikit field, dan grup peminjaman per buku id.

```typescript
// Soal 2
async function ambilDariAPI(): Promise<Buku[]> { return []; }

type HasilRaw = ReturnType<typeof ambilDariAPI>;          // Promise<Buku[]>
type HasilFetch = Awaited<HasilRaw>;                       // Buku[]

const data: HasilFetch = await ambilDariAPI();             // ✅ Buku[]
```

**Pembahasan**: `ReturnType` pada async function mengembalikan `Promise<...>`. `Awaited` "membuka" layer Promise tersebut sehingga tipe sesuai nilai aktual (`Buku[]`). Ini menghindari duplikasi definisi dan tetap sinkron bila `ambilDariAPI` berubah.
