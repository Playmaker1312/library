# 9. Type Alias — Nama untuk Tipe yang Kompleks

> 🔵 **Level 2 — Bagian D** | 🧩 **Melanjutkan [[8. Interface — Kontrak Struktur Object]]**

---

## 1. Penjelasan Singkat & Konsep Dasar

**Type alias** (`type`) memberi *nama* pada tipe kompleks agar kode lebih mudah dibaca dan di-ro reuse:

```typescript
type ID = number;
type Kategori = "Fiksi" | "Non-Fiksi" | "Sains";
type Status = "dipinjam" | "dikembalikan";
```

Perbedaan yang paling krusial dengan `interface` (materi 8):

| | `interface` | `type` alias |
|---|---|---|
| Bentuk object / class contract | ✅ (extends, implements) | ✅ (extends via `&`, implements) |
| Union types | ❌ tidak | ✅ |
| Intersection types | ❌ langsung | ✅ `A & B` |
| Mapped / conditional types | ❌ (tapi bisa digabung) | ✅ |
| Declaration merging | ✅ | ❌ (duplikat nama error) |
| Primitive / tuple alias | ❌ | ✅ |

**Filosofi praktis**: 
- **Bentuk object** → `interface`.
- **Union, intersection, mapped, conditional, primitif bernama, tuple bernama** → `type`.

**Hubungan ke materi 8 dan seterusnya**: materi 8 memberi kontrak object (`interface`). Materi 9 menambah cara *mengantar* tipe kompleks (union, intersection) sehingga kita bisa memodelkan data dengan ekspresif. Intersection `Buku & HasTimestamps` akan menjadi dasar `BukuFisik`/`BukuDigital` pada materi 11, dan `type` akan dipakai di seluruh Level 3–7.

---

## 2. Fungsi & Kegunaan Utama

- **Single source of truth** untuk union yang dipakai berulang (kategori, status) — mengubah di satu tempat.
- **Menamai tipe primitif** (`type Rupiah = number`) untuk dokumentasi.
- **Intersection types** — menggabungkan beberapa tipe jadi satu (`Buku & HasTimestamps`).
- **Menyederhanakan signature fungsi / property** yang bertipe kompleks.
- **Foundation untuk mapped/conditional types** (materi 17) dan generics (materi 14–15).

---

## 3. Contoh Kode & Implementasi (Real-world Example)

```typescript
// src/types/aliases.ts

interface Buku {
    id: number;
    judul: string;
    harga: number;
    stok: number;
}

// ─── Alias primitif ────────────────────────────────────────────────
type ID = number;
type Rupiah = number;

function formatHarga(harga: Rupiah): string {
    return `Rp ${harga.toLocaleString("id-ID")}`;
}

// ─── Alias untuk union yang sering dipakai ──────────────────────────
type Kategori = "Fiksi" | "Non-Fiksi" | "Sains" | "Teknologi" | "Sejarah" | "Umum";
type StatusPeminjaman = "dipinjam" | "dikembalikan" | "terlambat" | "hilang";
type RolePengguna = "admin" | "pustakawan" | "anggota";

interface Peminjaman {
    id: number;
    bukuId: ID;
    anggotaId: ID;
    status: StatusPeminjaman;      // hanya nilai valid!
}

// ─── Intersection (&) — gabungkan beberapa tipe ─────────────────────
interface HasTimestamps {
    createdAt: Date;
    updatedAt: Date;
}
interface HasSoftDelete {
    deletedAt: Date | null;
}

type BukuLengkap = Buku & HasTimestamps & HasSoftDelete;

const bukuLengkap: BukuLengkap = {
    id: 1,
    judul: "Clean Code",
    harga: 150000,
    stok: 5,
    createdAt: new Date(),
    updatedAt: new Date(),
    deletedAt: null,
};

// ─── Alias untuk function type ─────────────────────────────────────
type CariBuku = (keyword: string, kategori?: Kategori) => Buku[];

const cariBuku: CariBuku = (keyword, kategori) => {
    return keyword ? [bukuLengkap] : [];
};

// ─── Alias tuple yang bernama ──────────────────────────────────────
type KodeRak = [bagian: string, baris: number];
const rak: KodeRak = ["A", 3];
```

## 4. Analogi Sederhana

**Sistem Perpustakaan.**

- **`type Kategori = ...`** seperti **cetakan katalog resmi**: ada satu daftar kategori yang dicetak di papan pengumuman; semua formulir memakai *nama* "Kategori" itu, jadi tidak perlu menyalin panjang daftar ulang di setiap form (dan jika daftar berubah, cukup perubahan satu tempat).
- **`interface`** di sisi lain adalah **formulir fisik** — kontrak bentuk, bisa di-`extends`. Beda alat: formulir untuk object, papan pengumuman (union) untuk daftar pilihan.
- **Intersection (`&`)** seperti **menumpuk dua stempel yang berbeda tapi saling melengkapi**: kartu buku di-stempel "Dibuat: tanggal" (timestamps) dan "Dihapus: tanggal" (soft delete) — kartu final memuat *keduanya* dalam satu kartu.
- **Alias primitif (`Rupiah`)** = **satuan di label harga**: angka saja lebih ambigu; saat tertulis "harga: Rupiah", semua orang mengerti satuannya tanpa bertanya.

---

## 5. Kapan Harus Digunakan (Use Cases)

- **Union types** — kategori, status, role, ukuran (semua "pilihan terbatas").
- **Intersection types** — "entitas + fitur lintas entitas" (timestamps, soft-delete, ditandai flag).
- **Memodelkan tipe kompleks tanpa interface** — union of interfaces (dipakai pada discriminated union, materi 11), tuple, conditional/mapped types (materi 17).
- **Memberi nama primitif / semantik domain** — `ID`, `Rupiah`, `KodeISBN`.
- **Alias function types** yang akan dipass berulang (callback pattern).
- **API contract helper** seperti `type Result<T> = { success: true; data: T } | { success: false; error: string }` (generics, materi 15).

---

## 6. Poin-poin Penting & Best Practices

1. **`type` tidak bisa declaration merging** — jika kamu benar-benar perlu "menambah field dari luar", pilih `interface`.
2. **Interface untuk object biasa, `type` untuk yang lain** — aturan minimal yang paling luas dipakai komunitas.
3. **Gunakan `&` dengan hati-hati pada dua object dengan nama field yang sama** — TypeScript menggabungkan; bisa menghasilkan tak terduga. Untuk object hirarki lebih aman pakai `interface extends`.
4. **Alias tipe sama-sama "erased" saat compile** — tidak menghasilkan runtime (kecuali class/enum di materi 12-13).
5. **Nama alias sebaiknya noun** yang jelas: `StatusPinjam` bukan `S`.
6. **Alias bisa juga generik** (`type Repo<T> = ...`) — jembatan ke materi 15.

---

## 7. Kesalahan Umum (Common Pitfalls & Anti-patterns)

| Kesalahan | Contoh | Akibat | Perbaikan |
|---|---|---|---|
| Redeclare type yang sama | `type K = "a"; type K = "b";` | TS2300: dup nama | bedakan nama / pakai interface untuk merging |
| Salah memahami `&` vs `extends` | intersection antar property yang bertentangan tipe | tak terduga / error | pendekatan interface extends yang jelas |
| Menggunakan `type` untuk semuanya sampai melupakan interface | banyak `type X = { ... }` | hilang merging & dedup | gunakan interface untuk bentuk object |
| Alias primitif berlebihan | `type AngkaIndeks = number` tanpa nilai tambah | kebisingan | alias bila menambah makna/domain |
| Union terlalu lebar | `type S = string \| null \| undefined` | makna tak jelas | sempitkan pada yang dibutuhkan |
| Menyebut `&` "inheritance" | komentar "inherits Buku" | salah konsep | intersection = gabungan, bukan pewarisan |

## 8. Soal Latihan & Kunci Jawaban

### Soal 1
Buat type alias:
1. `Role = "admin" | "pustakawan" | "anggota"`
2. `StatusBuku = "dipinjam" | "dikembalikan"`
3. `JenisBuku = "fisik" | "digital"`
Lalu buat interface `Anggota` dengan `role: Role` dan interface `PeminjamanRecord` dengan field `jenis: JenisBuku` dan `status: StatusBuku`.

### Soal 2
Gunakan intersection untuk membuat tipe `BukuBersama` = `Buku` (id, judul, stok) `&` `BukuDigital` yang memiliki `formatFile: "PDF" | "EPUB"` dan `ukuranMB: number`. Buat satu instance yang valid. Jelaskan bedanya dengan bila kita definisikan `interface BukuDigital extends Buku`.

---

### Jawaban & Pembahasan

```typescript
// Soal 1
type Role = "admin" | "pustakawan" | "anggota";
type StatusBuku = "dipinjam" | "dikembalikan";
type JenisBuku = "fisik" | "digital";

interface Anggota {
    id: number;
    nama: string;
    role: Role;
}

interface PeminjamanRecord {
    id: number;
    bukuId: number;
    anggotaId: number;
    jenis: JenisBuku;
    status: StatusBuku;
    tanggalPinjam: Date;
}
```

**Pembahasan**: alias membuat "daftar pilihan" reusable & terkunci (nilai lain ditolak) — persis tujuan literal union.

```typescript
// Soal 2
interface Buku {
    id: number;
    judul: string;
    stok: number;
}

interface BukuDigital {
    formatFile: "PDF" | "EPUB";
    ukuranMB: number;
}

type BukuBersama = Buku & BukuDigital;

const ebook: BukuBersama = {
    id: 5,
    judul: "The Pragmatic Programmer",
    stok: 3,
    formatFile: "PDF",
    ukuranMB: 12,
};
```

**Pembahasan**: `Buku & BukuDigital` menghasilkan objek yang memuat semua field kedua-duanya — sama hasilnya dengan `interface BukuDigital extends Buku`. Bedanya: intersection memungkinkan menggabungkan *union/types lain* (materi 11) dan fleksibel tanpa merubah `Buku`; `extends` lebih ekspresif untuk *hubungan pewarisan* yang jelas. Pilih intersection saat hanya ingin "menggabung", `extends` saat ingin *kontrak turunan* yang disengaja.
