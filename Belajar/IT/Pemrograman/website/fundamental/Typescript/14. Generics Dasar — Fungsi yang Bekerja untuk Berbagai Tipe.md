# 14. Generics Dasar — Fungsi yang Bekerja untuk Berbagai Tipe

> 🟡 **Level 3 — Bagian G** | 🧩 **Melanjutkan [[13. Constructor Property Promotion dan Access Modifiers]]**

---

## 1. Penjelasan Singkat & Konsep Dasar

**Generics** adalah fitur yang memungkinkan sebuah fungsi, class, atau *type* bekerja dengan **tipe yang beragam** — namun **tetap type-safe** (tidak memakai `any`). Tipe ditentukan *saat pemanggilan*, bukan saat penulisan.

```typescript
// T = "type parameter" — placeholder yang diisi nanti
function ambilPertama<T>(array: T[]): T | undefined {
    return array[0];
}

const a = ambilPertama([1, 2, 3]);       // T disimpulkan = number
const b = ambilPertama(["x", "y"]);      // T = string
const c = ambilPertama<Buku>(katalog);   // eksplisit: T = Buku
```

**Konsep kunci**:
- **Type parameter `<T>`** — variabel tipe yang "diisi" saat pemanggilan.
- **Inference** — TypeScript menebak `T` dari argument.
- **Constraint `<T extends X>`** — membatasi `T` harus memiliki sifat/tipe tertentu (memiliki `id`, dll).
- **`keyof`** — mengambil *kunci* dari sebuah object type.

**Perbedaan dengan `any` (sering membingungkan):**

| | `any` | Generic `<T>` |
|---|---|---|
| Type safety | ❌ mati | ✅ hidup, terkunci ke konteks |
| Hubungan antar parameter/return | tiada | ✅ terjamin (`T[]` → `T`) |
| Autocomplete output | ❌ | ✅ mengikuti T |

**Benang merah**: materi 13 menutup OOP dasar. Generics-lah yang membuat kode kita bisa *reusable tanpa kehilangan safety* — pondasi yang dipakai untuk `Repository<T>` (materi 15), `Result<T>` (materi 15), dan seluruh utility types di Level 4.

---

## 2. Fungsi & Kegunaan Utama

- **Menulis satu fungsi/class untuk "banyak tipe" tanpa `any`** — DRY dan aman.
- **Mengikat relasi tipe antar parameter** (e.g. `cariDalam(array, predikat)` relasi `T`).
- **Constraint** — berbicara tentang "tipe yang memiliki property tertentu" (`T extends HasId`).
- **`keyof`** — akses properti object secara type-safe (dasar di materi 17 mapped types).
- **Komposisi fungsi generic untuk pipeline data** yang diulang.

## 3. Contoh Kode & Implementasi (Real-world Example)

```typescript
// src/utils/generics.ts
import type { Buku, Anggota, Kategori } from "../interfaces";

const katalogBuku: Buku[] = [];        // anggap sudah terisi
const daftarAnggota: Anggota[] = [];

// ─── Masalah: fungsi duplikat tanpa generics ────────────────────────
function ambilPertamaBuku(arr: Buku[]): Buku | undefined { return arr[0]; }
function ambilPertamaAnggota(arr: Anggota[]): Anggota | undefined { return arr[0]; }
// → harus menulis ulang untuk tiap tipe!

// ─── Solusi: satu fungsi generic ────────────────────────────────────
function ambilPertama<T>(array: T[]): T | undefined {
    return array[0];
}
const bukuPertama     = ambilPertama(katalogBuku);    // T = Buku
const anggotaPertama  = ambilPertama(daftarAnggota);  // T = Anggota
const angkaPertama    = ambilPertama([1, 2, 3]);      // T = number

// ─── Generic dengan predicate — relasi T dipertahankan ──────────────
function cariDalam<T>(array: T[], predikat: (item: T) => boolean): T | undefined {
    return array.find(predikat);
}
const bukuDitemukan = cariDalam(katalogBuku, b => b.judul.includes("Clean"));

// ─── Constraint `<T extends HasId>` ─────────────────────────────────
interface HasId { id: number; }

function cariById<T extends HasId>(array: T[], id: number): T | undefined {
    return array.find(item => item.id === id);
}
const b = cariById(katalogBuku, 1);        // ✅ Buku punya id
// cariById([1, 2, 3], 1);                  // ❌ number tidak extend HasId

// ─── Multiple type parameters ───────────────────────────────────────
function petakan<T, U>(array: T[], transformasi: (item: T) => U): U[] {
    return array.map(transformasi);
}
const judulSaja = petakan(katalogBuku, b => b.judul);   // U = string
const hargaSaja = petakan(katalogBuku, b => b.harga);   // U = number

// ─── keyof — akses property type-safe ───────────────────────────────
function ambilNilai<T, K extends keyof T>(obj: T, key: K): T[K] {
    return obj[key];
}
const judul = ambilNilai(katalogBuku[0], "judul");   // string
// ambilNilai(obj, "tidakAda");                       // ❌ bukan key dari Buku

// ─── Penerapan nyata: pencarian di banyak "entitas" ─────────────────
function buatPencari<T extends HasId>() {
    return function (array: T[], keyword: string): T[] {
        // logika umum: sama untuk buku & anggota (implementasi dikonkretkan)
        return array;   // placeholder logika pencarian
    };
}
const cariBuku = buatPencari<Buku>();
const hasil = cariBuku(katalogBuku, "clean");   // ✅ ber-return Buku[]
```

## 4. Analogi Sederhana

**Sistem Perpustakaan.**

- **Generic `<T>`** seperti **mesin fotokopi multi-guna**: satu mesin bisa menggandakan *kartu buku*, *kartu anggota*, ataupun *formulir denda* — terima saja "variabel" berupa dokumen apa pun (`T`), dan hasil salinannya selalu *jenis dokumen yang sama* (`T[]` → `T`) — tidak pernah tercampur. Mesin **tidak perlu tahu** detail setiap jenis dokumen.
- **Constraint `<T extends HasId>`** seperti **prasyarat formulir**: "semua dokumen yang boleh masuk harus punya kolom `id`" — mesin tahu, selama formulir punya `id`, ia bisa diproses.
- **`keyof`** = **pustakawan yang menunjuk kolom tertentu dari formulir**: "berikan kolom `judul`" akan selalu mengembalikan nilai ber-*tipe sesuai kolom itu* (string), bukan "apa pun".
- **Tanpa generic (duplikat)**: kamu harus memiliki 5 mesin terpisah — satu untuk buku, satu untuk anggota — padahal ujung mekanismenya sama. Dengan generic: satu mesin + 1 parameter tipe.

## 5. Kapan Harus Digunakan (Use Cases)

- **Fungsi utilitas umum** — `pertama`, `cariDalam`, `petakan` yang dipakai di banyak tipe.
- **Repository / service generic** (materi 15) — satu `InMemoryRepository<T>` untuk Buku, Anggota, Peminjaman.
- **Helper typed** — `ambilNilai`, `penggabung`, `keyBy` (menggaung entity).
- **Kontrak API-generic** — `Result<T>` (materi 15), `ApiResponse<T>` (Level 5).
- **Library komponen**: React generic components (materi 25).
- **Ketika analisis "hubungan antar tipe"** tetap dijaga (param & return) — inilah yang membedakan dengan `any`.

---

## 6. Poin-poin Penting & Best Practices

1. **Generics ≠ `any`** — generics *mempertahankan* hubungan tipe; `any` menghapusnya.
2. **Pakai inference bila memungkinkan** — `ambilPertama(katalog)` — jangan selalu menulis `<Buku>` eksplisit.
3. **Beri nama bermakna**: `<T>` umum, `<TItem>`, `<K>` untuk key, `<R>` untuk result; hindari `<X>`, `<Z>` terus-menerus.
4. **Gunakan constraint minimal yang perlu**: `T extends HasId` cukup bila hanya butuh `id`.
5. **Jangan over-generic** — jika fungsi hanya untuk satu tipe, jangan buat generic (kompleksitas tak perlu).
6. **Sediakan default type bila berguna** (`<T = Buku>`) untuk API yang most-likely dipakai dengan satu tipe.
7. **Type aliases, interface, dan class bisa generic** — konsisten menerapkan.

## 7. Kesalahan Umum (Common Pitfalls & Anti-patterns)

| Kesalahan | Contoh | Akibat | Perbaikan |
|---|---|---|---|
| Generic dipakai seperti `any` | `function f<T>(x: T): T { return (x as any).foo; }` | safety palsu | buat T lendir nyata sesuai penggunaan |
| Lupa constraint saat memakai property | `function g<T>(x: T) { x.id }` | TS2339: 'id' tidak ada di T | `T extends HasId` |
| Over-generic | `function h<T>(x: T[]): T[]` padahal hanya used string[] | kompleksitas | tulis tipe konkret |
| Inference lawan eksplisit bertabrakan | `<number>(...)` dengan array string | TS2345 | samakan, biarkan infer |
| `keyof` kurang dipakai | hardcode nama key sebagai string | rentan typo | pakai `K extends keyof T` |
| Mis memahami `extends` di placeholders vs interfaces | `T extends Person` tapi dipakai untuk class | salah kira | constraint berbicara struktur, bukan inheritance murni |

## 8. Soal Latihan & Kunci Jawaban

### Soal 1
Buat *generic function* `keyBy<T, K extends keyof T>(array: T[], key: K): Record<string, T>` yang mengelompokkan array menjadi object berdasarkan key — misal `keyBy(katalogBuku, "id")` menghasilkan `{ "1": Buku, ... }`. Lalu jelaskan bagaimana generic di sini menjaga safety.

### Soal 2
Perbaiki fungsi berikut sehingga dengan *constraint* cocok untuk Buku & Anggota, dan buktikan `cariById(["teks"], 3)` ditolak:

```typescript
function cariById(array: any[], id: number): any { /* ... */ }
```

---

### Jawaban & Pembahasan

```typescript
// Soal 1
function keyBy<T, K extends keyof T>(array: T[], key: K): Record<string, T> {
    const hasil: Record<string, T> = {};
    for (const item of array) {
        hasil[String(item[key])] = item;
    }
    return hasil;
}

interface Buku { id: number; judul: string; }
const katalog: Buku[] = [
    { id: 1, judul: "Clean Code" },
    { id: 2, judul: "Pragmatic" },
];
const byId = keyBy(katalog, "id");
console.log(byId["1"].judul);   // "Clean Code" — type-safety nyata
```

**Pembahasan**: `K extends keyof T` menjamin `key` adalah kunci *nyata* dari `T`; hasilnya `Record<string, T>` sehingga `byId["1"]` bertipe `Buku` (bukan `any`). Typo key langsung ditangkap compile-time.

```typescript
// Soal 2
interface HasId { id: number; }

function cariById<T extends HasId>(array: T[], id: number): T | undefined {
    return array.find(item => item.id === id);
}

cariById([{ id: 1, judul: "X" }], 1);   // ✅ object punya id → T ditemukan
// cariById(["teks"], 3);                // ❌ TS2345: string tidak mengacu HasId
```

**Pembahasan**: tanpa generic, `any[]` membiarkan string lolos (safety mati). Dengan `T extends HasId`, hanya tipe yang secara struktural memiliki `id` yang diterima — kompiler menolak input yang tidak relevan.
