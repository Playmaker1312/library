# Error Reporting — Baca Error, Jangan Takut

## Penjelasan
Error adalah bagian normal dari pemrograman. PHP memiliki sistem error reporting yang memberitahu apa yang salah, di baris berapa, dan di file mana. Ada beberapa level error:

- **Parse Error** (syntax error): Kode salah ketik, lupa titik koma, kurung tidak seimbang. File tidak dijalankan sama sekali.
- **Fatal Error**: Fungsi tidak ditemukan, memory habis. Eksekusi berhenti total.
- **Warning**: Ada yang salah tapi tidak fatal — eksekusi tetap lanjut. Contoh: `include` file yang tidak ada.
- **Notice**: Peringatan ringan — misal pakai variabel yang belum diinisialisasi. Eksekusi tetap lanjut.

PHP menyediakan fungsi `error_reporting()` dan setting di `php.ini` untuk mengontrol error apa yang ditampilkan. Di mode development, sebaiknya semua error ditampilkan (`E_ALL`). Di production, error disembunyikan dan dicatat ke log file.

## Fungsi
Membantu programmer menemukan dan memperbaiki kesalahan dengan cepat. Error message memberi tahu lokasi persis dan penyebab masalah — ini adalah debugging tool paling dasar.

## Cara Pengimplementasian / Code
### Mengaktifkan error reporting di file PHP:
```php
<?php
// Tampilkan semua error, warning, notice
error_reporting(E_ALL);
ini_set('display_errors', 1);

// Contoh notice: variabel belum diinisialisasi
echo $buku; // Notice: Undefined variable: buku

// Contoh warning
include 'file_tidak_ada.php'; // Warning: No such file

// Contoh fatal error
functionSaya(); // Fatal error: Call to undefined function
```

### Cek error dengan phpinfo():
```php
<?php
phpinfo();
// Cari bagian "display_errors" dan "error_reporting"
```

## Analogi
Di perpustakaan, ada buku catatan kesalahan petugas. Saat petugas salah meletakkan buku (error), akan tercatat: "Buku 'Sejarah Dunia' oleh Petugas Budi salah diletakkan di Rak F (baris 15)". Pustakawan senior (kamu) membaca catatan itu, bukan malah panik. Catatan itu justru mempermudah mencari dan membetulkan kesalahan. Error PHP adalah catatan itu.

## Dipakai untuk Apa
- Debugging saat development
- Mengetahui penyebab halaman putih kosong (White Screen of Death / WSOD)
- Validasi bahwa kode tidak memiliki bug sebelum dipublikasikan
- Logging error di production untuk dipelajari nanti (tanpa menampilkan ke user)

## Kesalahan Umum yang Sering Terjadi
- **Takut membaca error**: Programmer pemula sering panik dan langsung mencari solusi di Google tanpa membaca pesan errornya. 90% kasus, pesan error sudah menjelaskan masalahnya.
- **Mematikan error reporting**: `error_reporting(0)` saat development, sehingga tidak sadar ada notice atau warning yang bisa jadi bug serius.
- **Menampilkan error di production**: Sangat berbahaya — bisa membocorkan path file, struktur database, atau credential. Di production, error harus di-log, bukan di-display.
- **Mengabaikan Notice/Warning**: Programmer sering skip notice karena "kode masih jalan". Tapi notice bisa jadi cikal bakal bug yang lebih besar.

## Hubungan dengan Materi Sebelumnya
Di materi 1-4, kamu mungkin akan sering menemui error saat belajar. Tanpa memahami error reporting, kamu akan buta. Dengan mengaktifkan dan membaca error reporting, kamu bisa mendiagnosis sendiri masalah pada kode variabel, operator, sintaks, dan semua materi selanjutnya. Ini adalah "mata" untuk melihat kesalahan.

## Soal Latihan & Jawaban
### Soal
Buat file `cek_error.php` yang mengaktifkan error reporting level E_ALL. Kemudian buat tiga kesalahan berikut dan jalankan — amati pesan errornya:
1. Panggil variabel `$rak` yang belum pernah didefinisikan
2. Sertakan file `katalog_tidak_ada.php` dengan `include()`
3. Tulis `echo "Halo` tanpa menutup string dengan kutip

### Jawaban
```php
<?php
error_reporting(E_ALL);
ini_set('display_errors', 1);

// 1. Notice — variabel belum didefinisikan
echo $rak;

// 2. Warning — include file yang tidak ada
include 'katalog_tidak_ada.php';

// 3. Parse error — string tidak ditutup (sengaja dikomentari agar tidak menghentikan eksekusi)
// echo "Halo;
?>
```
