# 7. Selector Relasional — Descendant, Child & Sibling

## Penjelasan

Empat jenis selector relasional berdasarkan hubungan antar elemen di HTML:

| Selector | Simbol | Arti | Contoh |
|----------|--------|------|--------|
| **Descendant** | spasi | Semua elemen di dalam (semua level) | `nav a` → semua link di dalam nav |
| **Child** | `>` | Anak langsung (level 1) | `.nav > li` → li langsung di bawah .nav |
| **Adjacent sibling** | `+` | Saudara tepat setelahnya | `h2 + p` → p yang langsung setelah h2 |
| **General sibling** | `~` | Semua saudara setelahnya | `h2 ~ p` → semua p setelah h2 |

## Fungsi

- Men-style elemen berdasarkan **posisinya di struktur HTML** tanpa menambah class
- Membuat CSS lebih efisien — hindari class berlebihan

## Cara Pengimplementasian

```css
/* Descendant: semua a di dalam nav */
nav a { 
  color: white; 
  text-decoration: none; 
}

/* Child: hanya li langsung anak .main-nav */
.main-nav > li { 
  display: inline-block; 
}

/* Adjacent sibling: p yang langsung setelah h2 */
h2 + p { 
  font-size: 1.1rem; 
  color: #6b7280; 
  margin-top: 0; 
}

/* General sibling: semua p setelah h2 dalam container yang sama */
h2 ~ p { 
  padding-left: 20px; 
}
```

Struktur HTML:
```html
<nav class="main-nav">
  <ul>              <!-- child dari .main-nav -->
    <li>            <!-- descendant dari .main-nav, child dari ul -->
      <a href="#">Link</a>  <!-- descendant dari .main-nav -->
    </li>
  </ul>
</nav>
```

## Analogi

Seperti **silsilah keluarga di rumah**:
- **Descendant**: "Semua orang di keluarga Budi" — anak, cucu, cicit (semua level)
- **Child**: "Anak kandung Budi" — langsung lahir dari Budi
- **Adjacent sibling**: "Tetangga sebelah rumah" — tepat di samping
- **General sibling**: "Semua tetangga di jalan yang sama" — setiap rumah setelahnya

## Dipakai Untuk Apa

- Navigasi: semua link di dalam nav tanpa harus class tiap link
- Konten: style spesifik untuk paragraf yang mengikuti heading
- List: border hanya untuk item yang tidak terakhir

## Kesalahan Umum

- **Spasi vs `>` tidak dipahami**: `div p` (semua p di dalam div) vs `div > p` (hanya p anak langsung)
- **Selector terlalu panjang**: `body > div > main > section > article > p` — rapuh, mudah patah jika struktur HTML berubah
- **Mengira general sibling (`~`) sama dengan adjacent (`+`)**: `+` hanya satu elemen tepat setelah, `~` untuk semua

## Hubungan dengan Materi Sebelumnya

Poin 5-6: kita bisa pilih elemen berdasarkan tag (type) dan label (class/ID). Tapi bagaimana memilih "link yang ada di dalam navigasi"? Kita perlu **hubungan antar elemen**. Selector relasional menjawab ini — kita bisa men-style berdasarkan struktur HTML tanpa menambah class ke setiap elemen.

## Soal Latihan

### Soal 1
Apa perbedaan `nav a` dan `nav > a`?

**Jawaban:**
`nav a` memilih SEMUA tag `<a>` di dalam `<nav>` (semua level, termasuk di dalam `<ul>`). `nav > a` hanya memilih `<a>` yang langsung menjadi anak `<nav>`.

### Soal 2
Tulis CSS untuk memberi garis bawah pada paragraf yang langsung setelah `<h2>`.

**Jawaban:**
```css
h2 + p {
  text-decoration: underline;
}
```

### Soal 3
Dari struktur berikut, mana yang akan dipilih `article > p`?
```html
<article>
  <p>Ini dipilih</p>
  <div>
    <p>Ini tidak</p>
  </div>
</article>
```

**Jawaban:**
Hanya `<p>Ini dipilih</p>` karena `>` hanya memilih anak langsung. `<p>Ini tidak</p>` adalah cucu (descendant tapi bukan child).
