# 64. Organisasi File CSS — Struktur yang Scalable

## Penjelasan

Seiring pertumbuhan project, satu file `styles.css` menjadi tidak terkelola. Solusi: **pisahkan ke folder berdasarkan fungsi**.

```
css/
├── base/
│   ├── reset.css          ← reset dan normalisasi
│   ├── variables.css      ← semua CSS custom properties
│   └── typography.css     ← base typography styles
├── components/
│   ├── buttons.css        ← semua varian tombol
│   ├── cards.css          ← semua varian card
│   ├── forms.css          ← semua elemen form
│   └── navigation.css     ← header dan nav
├── layout/
│   ├── header.css         ← layout header
│   ├── footer.css         ← layout footer
│   ├── grid.css           ← layout grid umum
│   └── container.css      ← container dan wrapper
├── pages/
│   ├── home.css           ← style spesifik halaman beranda
│   ├── portfolio.css      ← style spesifik halaman portofolio
│   └── contact.css        ← style spesifik halaman kontak
├── utilities/
│   └── helpers.css        ← utility classes (hidden, sr-only)
└── styles.css             ← file utama yang mengimport semua
```

## Fungsi

- Scalability — tambah komponen baru = tambah file baru
- Team collaboration — developer berbeda bisa kerja di file berbeda tanpa konflik git
- Maintainability — cari style tombol? buka `components/buttons.css`

## Cara Pengimplementasian

**File utama `styles.css` — menggunakan CSS @import:**
```css
/* styles.css — file utama */
@import 'base/reset.css';
@import 'base/variables.css';
@import 'base/typography.css';

@import 'layout/container.css';
@import 'layout/header.css';
@import 'layout/footer.css';

@import 'components/buttons.css';
@import 'components/cards.css';
@import 'components/forms.css';
@import 'components/navigation.css';

@import 'pages/home.css';
@import 'pages/portfolio.css';

@import 'utilities/helpers.css';
```

**Aturan urutan import:**
1. Base (reset, variables, typography) — paling dasar
2. Layout (container, header, footer) — struktur halaman
3. Components (buttons, cards, forms) — komponen reusable
4. Pages (home, portfolio) — style spesifik halaman
5. Utilities — override terakhir

## Analogi

Seperti **organisasi alat di gudang rumah**:
- Tanpa organisasi: semua alat (palu, obeng, paku, cat) campur di satu kardus besar — susah cari, susah rapikan
- Dengan organisasi: rak khusus untuk alat listrik, laci untuk paku, lemari untuk cat — setiap alat punya rumah

Organisasi file CSS sama: setiap kategori punya file sendiri. Saat perlu cari style button, buka `buttons.css` — tidak perlu scroll 2000 baris di satu file.

## Dipakai Untuk Apa

- Project portofolio yang sudah besar (>500 baris CSS)
- Project tim
- Project dengan banyak halaman

## Kesalahan Umum

- **Over-engineering**: untuk project 200 baris CSS, satu file cukup. Jangan bikin struktur folder dulu sebelum dibutuhkan
- **Urutan import salah**: variables.scss setelah components — komponen tidak bisa pakai variables
- **File kosong atau hampir kosong**: jika satu file hanya 5 baris, mungkin bisa digabung
- **Lupa @import**: file dibuat tapi tidak di-import ke styles.css — tidak terbaca

## Soal Latihan

### Soal 1
Sebutkan 4 folder utama dalam struktur file CSS yang scalable.

**Jawaban:**
base/, components/, layout/, pages/ (dan utilities/).

### Soal 2
Mengapa base/ harus di-import pertama?

**Jawaban:**
Base berisi reset dan variables — fondasi untuk semua style lainnya. Components, layout, pages membutuhkan variables untuk warna, spacing, font.

### Soal 3
Apa risiko @import CSS untuk performa?

**Jawaban:**
`@import` di CSS menyebabkan **render-blocking** — file di-download serial, tidak paralel. Alternatif: gunakan SASS `@use` (di-compile jadi satu file) atau build tool.
