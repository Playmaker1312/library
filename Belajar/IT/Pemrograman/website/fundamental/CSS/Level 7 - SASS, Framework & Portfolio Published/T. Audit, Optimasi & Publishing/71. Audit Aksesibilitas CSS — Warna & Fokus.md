# 71. Audit Aksesibilitas CSS — Warna & Fokus

## Penjelasan

Aksesibilitas CSS memastikan website bisa digunakan oleh **semua orang** — termasuk yang memiliki keterbatasan penglihatan, pendengaran, motorik.

Checklist aksesibilitas CSS:
1. **Kontras warna**: WCAG AA minimal 4.5:1 (teks normal)
2. **Focus indicator**: semua elemen interaktif punya visible focus
3. **Ukuran teks**: bisa diperbesar 200% tanpa kehilangan fungsionalitas

```css
/* Focus visible — JANGAN dihapus */
:focus-visible {
  outline: 2px solid var(--color-primary);
  outline-offset: 2px;
}
```

## Fungsi

- Website bisa diakses pengguna dengan disabilitas
- SEO lebih baik (Google prioritaskan accessible website)
- Kepatuhan hukum (di beberapa negara)

## Cara Pengimplementasian

```css
/* 1. Focus visible — jangan pernah dihapus */
:focus-visible {
  outline: 3px solid var(--color-primary);
  outline-offset: 2px;
  border-radius: 2px;
}

/* 2. Skip link — untuk keyboard user */
.skip-link {
  position: absolute;
  top: -100%;
  left: var(--space-4);
  z-index: var(--z-toast);
  background-color: var(--color-primary);
  color: white;
  padding: var(--space-3) var(--space-6);
}

.skip-link:focus {
  top: var(--space-4);
}

/* 3. Teks tersembunyi tapi accessible — untuk screen reader */
.sr-only {
  position: absolute;
  width: 1px;
  height: 1px;
  padding: 0;
  margin: -1px;
  overflow: hidden;
  clip: rect(0, 0, 0, 0);
  border: 0;
}

/* 4. Animasi — hormati preferensi user */
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    transition-duration: 0.01ms !important;
  }
}

/* 5. Pastikan warna tidak jadi satu-satunya indikator */
.form-error {
  color: var(--color-error);
}

.form-error::before {
  content: "⚠ "; /* ikon sebagai indikator tambahan */
}
```

**Cek kontras warna:**
- Gunakan WebAIM Contrast Checker (webaim.org/resources/contrastchecker/)
- Ekstensi browser: "WCAG Color Contrast Checker"
- DevTools: Elements → Styles → Color picker → Contrast ratio

## Analogi

Seperti **rumah yang ramah untuk semua penghuni**:
- **Kontras warna** = **lampu yang cukup terang** — semua orang bisa baca buku, bukan hanya yang bermata tajam
- **Focus indicator** = **gagang pintu yang mencolok** — orang dengan penglihatan terbatas tetap bisa lihat mana yang bisa dipegang
- **Reduced motion** = **saklar untuk mematikan lampu disco** — tidak semua orang suka berkedip
- **Screen reader** = **plang braille di setiap pintu** — orang tunanetra tetap bisa navigasi

## Dipakai Untuk Apa

- Semua website production
- Sertifikasi aksesibilitas
- Pengecekan sebelum deploy

## Kesalahan Umum

- **Menghapus outline**: `outline: none` tanpa pengganti — musuh aksesibilitas nomor 1
- **Warna sebagai satu-satunya indikator**: tautan beda warna tapi tidak digarisbawahi — user buta warna tidak bisa bedakan
- **Kontras rendah**: teks abu-abu #999 di background putih — rasio 2.8:1, gagal WCAG AA
- **Animasi tidak bisa dimatikan**: gerakan konstan tanpa reduced motion

## Hubungan dengan Materi Sebelumnya

Level 1-6: kita membangun website yang keren. Tapi keren tidak berarti accessible. **Audit aksesibilitas** memastikan website bisa dinikmati semua orang. Ini adalah langkah yang membedakan developer pemula dari profesional.

## Soal Latihan

### Soal 1
Apa rasio kontras minimum WCAG AA untuk teks normal?

**Jawaban:**
4.5:1 (untuk teks kecil/besar: 3:1 untuk teks besar ≥18px bold atau ≥24px).

### Soal 2
Mengapa `outline: none` berbahaya?

**Jawaban:**
Pengguna keyboard (navigasi Tab) kehilangan indikator elemen mana yang sedang fokus — mereka tidak bisa menggunakan website.

### Soal 3
Apa itu `sr-only` class dan kapan digunakan?

**Jawaban:**
Class untuk menyembunyikan teks secara visual tapi tetap terbaca oleh screen reader. Digunakan untuk label tambahan, instruksi, atau konteks yang hanya relevan untuk pengguna screen reader.
