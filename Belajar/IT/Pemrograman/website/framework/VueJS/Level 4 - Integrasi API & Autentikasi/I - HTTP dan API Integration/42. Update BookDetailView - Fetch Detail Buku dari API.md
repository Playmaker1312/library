# 42. Update BookDetailView — Fetch Detail Buku dari API

## Penjelasan

BookDetailView adalah halaman yang menampilkan informasi detail satu buku berdasarkan ID yang ada di URL (route param `:id`). Sama seperti HomeView, data sebelumnya diambil dari array hardcode. Sekarang kita ganti dengan fetch data dari `booksApi.getById(id)`.

Tantangan khusus di halaman detail adalah:

- **Watch route params**: ketika user berpindah dari `/books/1` ke `/books/2`, komponen tidak di-recreate (karena masih di route yang sama). Kita perlu `watch` ID dan refetch.
- **Handle not found**: jika API mengembalikan 404, alihkan ke halaman 404
- **Loading dan error**: tampilkan skeleton dan error state khusus

## Fungsi

- Menampilkan data detail buku secara real-time dari server
- Merespon perubahan route param tanpa reload halaman
- Menangani kasus buku tidak ditemukan (404)
- Pengalaman pengguna yang halus — loading indicator, error state, retry

## Cara Implementasi

### 2. BookDetailView Sesudah (fetch dari API)

```vue
<script setup lang="ts">
import { watch, onMounted } from 'vue'
import { useRoute, useRouter } from 'vue-router'
import { useApi } from '@/composables/useApi'
import { booksApi } from '@/api/books.api'
import type { Book } from '@/types/book'

const route = useRoute()
const router = useRouter()

const { data: book, isLoading, error, execute } = useApi<Book>()

async function fetchBook(id: number) {
  const result = await execute(() => booksApi.getById(id))

  // Jika API return 404, redirect ke halaman not found
  if (result === null && error.value?.includes('404')) {
    router.replace('/404')
  }
}

onMounted(() => {
  fetchBook(Number(route.params.id))
})

// Watch perubahan route param — untuk navigasi buku ke buku
watch(
  () => route.params.id,
  (newId) => {
    if (newId) {
      fetchBook(Number(newId))
    }
  },
)
</script>

<template>
  <div class="book-detail">
    <!-- Loading State -->
    <div v-if="isLoading" class="detail-skeleton">
      <div class="skeleton-cover pulse" />
      <div class="skeleton-info">
        <div class="skeleton-title pulse" />
        <div class="skeleton-author pulse" />
        <div class="skeleton-desc pulse" />
      </div>
    </div>

    <!-- Error State (kecuali 404 yang sudah redirect) -->
    <div v-else-if="error && !error.includes('404')" class="error-state">
      <p>⚠️ {{ error }}</p>
      <button @click="fetchBook(Number(route.params.id))">
        Coba Lagi
      </button>
    </div>

    <!-- Data Tersedia -->
    <div v-else-if="book" class="detail-content">
      <img
        :src="book.coverImage"
        :alt="book.title"
        class="book-cover"
      />
      <div class="book-info">
        <h1>{{ book.title }}</h1>
        <p class="author">Penulis: {{ book.author }}</p>
        <p class="isbn">ISBN: {{ book.isbn }}</p>
        <p class="price">Rp {{ book.price.toLocaleString('id-ID') }}</p>
        <p class="stock">
          Stok: {{ book.stock > 0 ? book.stock + ' tersedia' : 'Habis' }}
        </p>
        <p class="description">{{ book.description }}</p>
      </div>
    </div>
  </div>
</template>
```

## Analogi — Toko Buku

Setelah etalase utama terhubung ke database (Poin 41), sekarang **detail buku** juga real-time.

Dulu: pelanggan lihat buku di etalase → ambil katalog cetak → cari halaman buku → lihat detail yang dicetak bulan lalu → **data mungkin sudah basi**.

Sekarang: pelanggan lihat buku di etalase → klik → **sistem panggil data dari gudang saat itu juga** → harga terbaru, stok terkini.

**Watch route params** berguna ketika pelanggan pindah dari detail buku A ke buku B:

1. Pelanggan lihat detail **"Vue.js Guide"** (id=1)
2. Pelanggan klik link **"Next: React Handbook"** (id=2) — URL berubah
3. Tanpa `watch`, halaman masih menampilkan "Vue.js Guide" — **salah!**
4. Dengan `watch(() => route.params.id, ...)`, sistem panggil ulang data untuk id=2

## Dipakai untuk Apa

- Halaman detail produk di e-commerce
- Halaman profil user
- Halaman artikel/blog
- Dashboard dengan detail item (order, transaksi)
- Aplikasi dengan navigasi antar item terkait

## Kesalahan Umum

| Kesalahan | Akibat | Solusi |
|---|---|---|
| Lupa `watch` route params | Navigasi `/books/1` → `/books/2` tidak refresh data | `watch(() => route.params.id, handler)` |
| Tidak handle 404 | Halaman putih terus atau infinite loading | Redirect ke /404 saat API return error 404 |
| Pakai `onBeforeUnmount` untuk cleanup | Race condition antara request lama dan baru | Gunakan AbortController atau flag `isCancelled` |
| Fetch sebelum route siap | `route.params.id` masih undefined | Panggil fetch di `onMounted` setelah route siap |
| Tidak handle `result === null` | Aplikasi lanjut render dengan `book` null | Guard dengan `v-if="book"` atau optional chaining |

## Hubungan dengan Materi Sebelumnya

Poin 41 mengupdate HomeView dengan fetch data + filter. Poin 42 menerapkan pola yang **sama** tetapi untuk single item:

| Aspek | HomeView (41) | BookDetailView (42) |
|---|---|---|
| Sumber data | `booksApi.getAll()` | `booksApi.getById(id)` |
| Trigger fetch | `onMounted`, `watch(filter)` | `onMounted`, `watch(route.params.id)` |
| Loading | Grid skeleton (8 card) | Skeleton cover + info |
| Error | Pesan + retry | Pesan + retry (kecuali 404 → redirect) |
| Empty | "Tidak ada buku" | Redirect ke 404 |

Di **Level 3**, BookDetailView hanya melakukan find di array lokal:

```typescript
const book = MOCK_BOOKS.find((b) => b.id === Number(route.params.id))
```

Sekarang:

```typescript
onMounted(() => fetchBook(Number(route.params.id)))
watch(() => route.params.id, (id) => fetchBook(Number(id)))
```

Data selalu **fresh** dari server setiap kali halaman dimuat atau ID berubah.

## Soal Latihan + Jawaban

### Soal 1

Bagaimana cara mencegah race condition jika user cepat-cepat berpindah dari `/books/1` ke `/books/2` ke `/books/3` sebelum request selesai? Implementasikan solusinya.

<details>
<summary>Jawaban</summary>

Gunakan `AbortController` untuk membatalkan request sebelumnya:

```typescript
import { ref } from 'vue'

const abortController = ref<AbortController | null>(null)

async function fetchBook(id: number) {
  // Batalkan request sebelumnya jika masih berlangsung
  abortController.value?.abort()
  abortController.value = new AbortController()

  isLoading.value = true
  error.value = null

  try {
    const result = await booksApi.getById(id, {
      signal: abortController.value.signal,
    })
    book.value = result
  } catch (err: any) {
    if (err.name === 'CanceledError') return // dibatalkan, abaikan
    error.value = err.message
  } finally {
    isLoading.value = false
  }
}
```

### Soal 2

Buat navigasi "Sebelumnya" dan "Berikutnya" di BookDetailView yang memungkinkan user berpindah ke buku sebelumnya/berikutnya tanpa kembali ke HomeView. Fungsi ini harus memanggil API lagi untuk buku baru.

<details>
<summary>Jawaban</summary>

```vue
<script setup lang="ts">
import { computed } from 'vue'

const currentId = computed(() => Number(route.params.id))

function goToPrev() {
  if (currentId.value > 1) {
    router.push(`/books/${currentId.value - 1}`)
  }
}

function goToNext() {
  router.push(`/books/${currentId.value + 1}`)
}

// Cek apakah buku dengan ID prev/next ada dengan HEAD request
async function checkBookExists(id: number): Promise<boolean> {
  try {
    await booksApi.getById(id)
    return true
  } catch {
    return false
  }
}
</script>

<template>
  <div class="navigation">
    <button
      :disabled="currentId <= 1"
      @click="goToPrev"
    >
      ← Sebelumnya
    </button>
    <button @click="goToNext">
      Berikutnya →
    </button>
  </div>
</template>
```
