# 58. Generic Composables — `useApi` yang Lebih Type-Safe

## Penjelasan

Generic composable adalah composable yang memanfaatkan **type parameter (generic)** agar TypeScript bisa **menginfer tipe secara otomatis** dari fungsi API yang di-pass. Daripada menulis tipe secara eksplisit di setiap komponen, generic composable membaca input (fungsi API) dan langsung tahu bentuk output-nya.

Refactor `useApi` dari versi Level 4 yang masih longgar menjadi versi yang **fully type-safe**:

- `execute` menerima `() => Promise<T>` — generic T di-infer dari fungsi yang di-pass
- Error handling menggunakan `catch (err: unknown)` — bukan `catch (err: any)`
- Return type `UseApiReturn<T>` — data, loading, error, execute semuanya bertipe
- Tidak perlu explicit type annotation di komponen — TypeScript infer secara otomatis

## Fungsi

- **Type inference otomatis** — komponen tidak perlu mendeklarasikan tipe data hasil API call
- **Type safety end-to-end** — dari API service sampai template komponen
- **Reusability maksimal** — composable yang sama bisa dipakai untuk API endpoint apapun
- **Error handling type-safe** — `catch (err: unknown)` memaksa pengecekan tipe error sebelum dipakai
- **Kode lebih bersih** — composable lebih sedikit boilerplate tipe

## Cara Implementasi

### 1. Definisikan tipe return

`src/composables/useApi.types.ts`:

```typescript
export interface UseApiState<T> {
  data: T | null
  loading: boolean
  error: string | null
}

export interface UseApiReturn<T> {
  data: ComputedRef<T | null>
  loading: ComputedRef<boolean>
  error: ComputedRef<string | null>
  execute: () => Promise<T | null>
}
```

### 2. Implementasi generic useApi

`src/composables/useApi.ts`:

```typescript
import { ref, computed, type ComputedRef } from 'vue'
import type { UseApiReturn } from './useApi.types'

export function useApi<T>(
  fetcher: () => Promise<T>
): UseApiReturn<T> {
  const data = ref<T | null>(null) as Ref<T | null>
  const loading = ref(false)
  const error = ref<string | null>(null)

  async function execute(): Promise<T | null> {
    loading.value = true
    error.value = null

    try {
      const result = await fetcher()
      data.value = result
      return result
    } catch (err: unknown) {
      if (err instanceof Error) {
        error.value = err.message
      } else if (typeof err === 'string') {
        error.value = err
      } else {
        error.value = 'Terjadi kesalahan yang tidak diketahui'
      }
      return null
    } finally {
      loading.value = false
    }
  }

  return {
    data: computed(() => data.value),
    loading: computed(() => loading.value),
    error: computed(() => error.value),
    execute
  }
}
```

### 3. Buat versi dengan auto-execute (optional)

`src/composables/useApiWithAuto.ts`:

```typescript
import { onMounted } from 'vue'
import { useApi } from './useApi'

export function useApiWithAuto<T>(fetcher: () => Promise<T>) {
  const composable = useApi(fetcher)

  onMounted(() => {
    composable.execute()
  })

  return composable
}
```

### 5. Error handling yang benar

```typescript
// ❌ Salah: catch (err: any) — bisa akses err.message tanpa pengecekan
catch (err: any) {
  error.value = err.message
}

// ✅ Benar: catch (err: unknown) — harus check instanceof
catch (err: unknown) {
  if (err instanceof Error) {
    error.value = err.message
  } else if (axios.isAxiosError(err)) {
    error.value = err.response?.data?.message ?? err.message
  } else if (typeof err === 'string') {
    error.value = err
  } else {
    error.value = 'Terjadi kesalahan yang tidak diketahui'
  }
}
```

### 6. Generic dengan parameter (versi lanjutan)

```typescript
export function useApiWithParams<TParams extends Record<string, unknown>, TData>(
  fetcher: (params: TParams) => Promise<TData>,
  initialParams: TParams
) {
  const params = ref<TParams>({ ...initialParams })
  const { data, loading, error, execute: baseExecute } = useApi(
    () => fetcher(params.value)
  )

  async function execute(newParams?: Partial<TParams>) {
    if (newParams) {
      params.value = { ...params.value, ...newParams }
    }
    return baseExecute()
  }

  return {
    data,
    loading,
    error,
    execute,
    params: readonly(params)
  }
}
```

## Analogi — Toko Buku

`useApi` yang generic seperti **"mesin fotokopi universal"** di Toko Buku "Baca Lagi".

**Sebelumnya (Level 4):** Mesin ini harus diberi tahu manual setiap kali dipakai:
- "Saya mau fotokopi **buku**, hasilnya **Buku**" — tulis `useApi<Book>(...)`
- "Saya mau fotokopi **katalog**, hasilnya **Book[]**" — tulis `useApi<Book[]>(...)`
- "Saya mau fotokopi **struk pembayaran**" — tulis `useApi<Receipt>(...)`
- Setiap kali pegawai harus jelasin ke mesin: "Ini output-nya apa ya?"
- Kadang pegawai salah sebut — bilang mau output Book, tapi yang dikasih Receipt -> error runtime

**Sekarang (Generic):** Mesin fotokopi PINTAR:
- Pegawai tinggal **masukkan dokumen asli** (fungsi API) ke mesin
- Mesin **membaca dokumen** dan langsung tahu bentuk output-nya
- Masukkan `getBooks()` — mesin tahu outputnya `PaginatedResponse<Book>`
- Masukkan `getBookById('abc')` — mesin tahu outputnya `ApiResponse<Book>`
- Masukkan `createOrder(orderData)` — mesin tahu outputnya `ApiResponse<Receipt>`
- **Pegawai tidak perlu jelasin ulang** — TypeScript infer secara otomatis

**Error handling** juga berubah:
- Dulu error ditangkap dengan `catch (err: any)` — "Ada yang salah ya?" tanpa tahu pasti apa
- Sekarang `catch (err: unknown)` — pegawai harus cek: "Ini Error beneran (instanceof Error)? String? Atau dari Axios?" — baru diproses. Lebih ribet sedikit, tapi lebih aman dan tidak ada error misterius.

## Dipakai untuk Apa

- **Semua komponen yang fetching data** — daftar buku, detail buku, keranjang, checkout
- **Form submission** — `useApi(() => createBook(payload))` — otomatis tipe sesuai payload
- **Search & filter** — `useApiWithParams` untuk search books dengan query parameter
- **Infinite scroll / pagination** — generic dengan page parameter
- **Bulk operations** — `useApi(() => deleteBooks(ids))` — return type menyesuaikan
- **Semua aplikasi Vue 3** yang memanggil API dengan pola loading/error/data yang berulang

## Kesalahan Umum

| Kesalahan | Dampak | Solusi |
|---|---|---|
| TypeScript error karena generic constraint terlalu longgar | Bisa passing fungsi yang tidak sesuai | Gunakan constraint `() => Promise<T>` bukan `Function` |
| Generic terlalu ketat (misal `T extends Book`) | Tidak bisa dipakai untuk tipe lain | Hanya constraint kalau perlu; biarkan T bebas |
| Lupa handle `err: unknown` dengan benar | Error `Property 'message' does not exist on type 'unknown'` | Check instanceof Error, string, atau type guard lain |
| `catch (err: any)` setelah refactor | TypeScript tidak bisa memvalidasi akses `err.message` | Selalu `catch (err: unknown)` dan lakukan narrowing |
| Tidak handle error di `.finally()` | `loading` jadi `false` meskipun execute gagal | Selalu reset `loading = false` di finally block |
| Type assertion di luar generic (`as any`) | Menghilangkan manfaat inference | Biarkan TypeScript infer; jangan paksa |
| Over-complicated generic dengan terlalu banyak parameter type | Sulit dibaca dan di-maintain | Cukup 1–2 type parameter; perlu lebih? Buat composable terpisah |

## Hubungan dengan Level 1–5

- **Level 1 (Dasar)** — Fungsi biasa, tidak ada generic. Kalau mau fungsi untuk tipe berbeda, harus copy-paste.
- **Level 2 (Reactivity)** — `ref<T>(...)` sudah mulai kenal generic, tapi masih sederhana. Belum ada generic composable.
- **Level 3 (Komponen)** — `defineProps<Book>()` — generic untuk props, tapi cuma di komponen.
- **Level 4 (Router & API)** — `useApi` pertama kali dibuat. Masih primitif: `function useApi<T>(url: string)` — T harus disebut manual di komponen. Error handling masih `catch (err: any)`.
- **Level 5 (State Management)** — Action store mulai pakai return type, tapi composable API call belum di-refactor menjadi generic.
- **Level 6 poin 57** — Dengan type system yang lengkap (`ApiResponse<T>`, `Book`, `PaginatedResponse<T>`), generic composable bisa memanfaatkan tipe-tipe ini untuk auto-completion dan type checking end-to-end.

**Alur lengkap dari API ke komponen sekarang:**

```
API endpoint (REST)
  → Service function: getBooks(): Promise<PaginatedResponse<Book>>
    → useApi(() => getBooks(1)) — T di-infer sebagai PaginatedResponse<Book>
      → data.value: PaginatedResponse<Book> | null — autocompletion penuh
        → Template: data?.data.forEach(book => book.title) — type-safe
```

Tidak ada titik lemah. Seluruh rantai tipe dari server sampai template terhubung.

```typescript
// src/composables/useMutation.ts
import { ref, computed } from 'vue'

export interface UseMutationReturn<TPayload, TResponse> {
  execute: (payload: TPayload) => Promise<TResponse | null>
  loading: ComputedRef<boolean>
  error: ComputedRef<string | null>
  isSuccess: ComputedRef<boolean>
}

export function useMutation<TPayload, TResponse>(
  mutationFn: (payload: TPayload) => Promise<TResponse>
): UseMutationReturn<TPayload, TResponse> {
  const loading = ref(false)
  const error = ref<string | null>(null)
  const isSuccess = ref(false)

  async function execute(payload: TPayload): Promise<TResponse | null> {
    loading.value = true
    error.value = null
    isSuccess.value = false

    try {
      const result = await mutationFn(payload)
      isSuccess.value = true
      return result
    } catch (err: unknown) {
      if (err instanceof Error) {
        error.value = err.message
      } else {
        error.value = 'Gagal melakukan operasi'
      }
      return null
    } finally {
      loading.value = false
    }
  }

  return {
    execute,
    loading: computed(() => loading.value),
    error: computed(() => error.value),
    isSuccess: computed(() => isSuccess.value)
  }
}
```

**Cara pakai:**

```typescript
import { useMutation } from '@/composables/useMutation'
import { createBook } from '@/services/bookService'

// TPayload = CreateBookPayload, TResponse = ApiResponse<Book> — otomatis
const { execute, loading, error, isSuccess } = useMutation(createBook)

async function handleSubmit() {
  const result = await execute({
    title: 'Belajar TypeScript',
    author: 'John Doe',
    isbn: '978-1234567890',
    price: 150000,
    stock: 10,
    category: 'technology'
  })
  // result: ApiResponse<Book> | null
}
```

### Soal 2

```vue
<script setup lang="ts">
import { ref, onMounted } from 'vue'
import { api } from '@/lib/api'

const books = ref<any[]>([])
const bookDetail = ref<any>(null)

    const res: any = await api.get('/books')
```
