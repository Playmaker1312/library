# 63. Lazy Loading Komponen dan Route

## Penjelasan

Lazy loading adalah teknik memuat kode hanya saat dibutuhkan, bukan saat aplikasi pertama kali dijalankan. Vue mendukung lazy loading di dua level:

1. **Route level** — menggunakan dynamic import `() => import()` di konfigurasi router. Setiap halaman menjadi file terpisah di bundle.
2. **Komponen level** — menggunakan `defineAsyncComponent` untuk komponen berat di dalam halaman yang sudah di-lazy load.

Vite secara otomatis melakukan **code splitting** — setiap `import()` dinamis dipisah menjadi file chunk sendiri. Browser hanya mengunduh file yang diperlukan untuk halaman yang sedang dibuka.

## Fungsi

- Bundle awal (`app.js`) jadi jauh lebih kecil
- Halaman pertama muat lebih cepat (First Contentful Paint turun)
- Pengguna hanya membayar (download + eksekusi) kode yang benar-benar mereka gunakan
- Cocok untuk komponen berat seperti rich text editor, chart library, peta interaktif

## Cara Implementasi

### 1. Route-level Lazy Loading (sudah otomatis sejak Level 3)

```typescript
// router/index.ts
import { createRouter, createWebHistory } from 'vue-router'

const routes = [
  {
    path: '/',
    name: 'Home',
    component: () => import('@/views/HomePage.vue') // lazy loading
  },
  {
    path: '/books/:id',
    name: 'BookDetail',
    component: () => import('@/views/BookDetail.vue')
  },
  {
    path: '/admin',
    name: 'AdminDashboard',
    component: () => import('@/views/AdminDashboard.vue')
  }
]

export default createRouter({
  history: createWebHistory(),
  routes
})
```

### 2. Komponen-level Lazy Loading dengan `defineAsyncComponent`

Untuk komponen berat yang tidak muncul di semua halaman:

```vue
<script setup lang="ts">
import { defineAsyncComponent } from 'vue'

// Basic — loader saja
const RichTextEditor = defineAsyncComponent(
  () => import('@/components/common/RichTextEditor.vue')
)

// Advanced — dengan loading & error state
const AdminPanel = defineAsyncComponent({
  loader: () => import('@/components/admin/AdminPanel.vue'),
  loadingComponent: {
    template: '<div class="skeleton-loader" />'
  },
  errorComponent: {
    template: '<div class="error-state">Gagal memuat panel admin</div>'
  },
  delay: 200, // tampilkan loadingComponent setelah 200ms (hindari flash)
  timeout: 10000 // timeout 10 detik
})

// Komponen chart berat
const BookSalesChart = defineAsyncComponent({
  loader: () => import('@/components/charts/BookSalesChart.vue'),
  loadingComponent: () => import('@/components/common/SkeletonChart.vue'),
  delay: 300
})
</script>

<template>
  <div class="admin-page">
    <AdminPanel />
    <BookSalesChart />
    <RichTextEditor v-if="isEditing" />
  </div>
</template>
```

### 3. Verifikasi Semua Route — Pastikan Tidak Ada yang Import Statis

```typescript
// ❌ BURUK — komponen besar di-load langsung saat app start
import AdminDashboard from '@/views/AdminDashboard.vue'

// ✅ BAIK — lazy loading
const AdminDashboard = () => import('@/views/AdminDashboard.vue')
```

Gunakan script atau ESLint rule untuk audit:

```bash
# Cari import statis dari views/ — seharusnya TIDAK ADA
rg "import .* from '@/views/" src/
```

## Analogi — Toko Buku

Toko buku besar tidak mungkin membuka **SEMUA ruangan** saat pembukaan pukul 08.00. Ruangan yang jarang dikunjungi — seperti **RichTextEditor** (ruang edit ulasan), **AdminPanel** (ruang manajemen stok), dan **BookSalesChart** (ruang analisis penjualan) — pintunya tertutup. Pintu hanya terbuka saat ada pengunjung yang ingin masuk (`defineAsyncComponent`).

Ruangan utama seperti **Beranda** (Home) dan **Detail Buku** (BookDetail) selalu terbuka karena paling sering dikunjungi.

Ini adalah **"code splitting" versi toko buku**: bangunan tidak perlu dibangun semuanya dari awal setiap pagi. Ruangan yang jarang dipakai dibangun hanya saat diperlukan — menghemat waktu, energi, dan biaya.

Pengunjung yang datang hanya untuk lihat buku tidak perlu menunggu ruang admin selesai dibangun.

## Dipakai untuk Apa

- **Rich text editor** (Quill, TipTap, TinyMCE) — library besar (200-500 KB)
- **Chart library** (Chart.js, ECharts, ApexCharts) — library besar
- **Admin panel / dashboard** — halaman internal yang jarang dikunjungi pengguna biasa
- **Halaman checkout** yang punya banyak logika kompleks
- **Komponen pihak ketiga** yang tidak dipakai di semua halaman
- **Halaman error / 404** — jarang dikunjungi

## Kesalahan Umum

| Kesalahan | Dampak | Solusi |
|-----------|--------|--------|
| Lazy loading **semua** komponen termasuk yang kecil dan sering dipakai | Banyak file kecil → overhead HTTP request > benefit ukuran | Hanya lazy-load komponen > 10 KB dan jarang dipakai |
| `delay` tidak diatur | Loading component muncul (flash) untuk komponen yang cepat dimuat | Set `delay: 200` ms |
| Tidak menyediakan loading/error state | Pengguna melihat layar kosong saat komponen dimuat | Selalu siapkan fallback UI |
| Lupa verifikasi route baru | Route baru tidak sengaja di-import statis | Audit rutin dengan grep/ESLint |
| `defineAsyncComponent` untuk komponen yang muncul di **atas fold** | Render tertunda — pengguna lihat loading | Hanya gunakan untuk komponen di bawah fold / jarang terlihat |

## Hubungan dengan Materi Sebelumnya

**Level 1 (Dasar Vue & TypeScript):** Dulu kita import komponen secara statis karena aplikasi masih kecil. Sekarang setelah aplikasi besar, lazy loading diperlukan.

**Level 2 (State Management & Composables):** Store Pinia di-load bersamaan dengan komponen yang membutuhkannya — pastikan store juga di-split jika besar.

**Level 3 (Vue Router):** Routing sudah menggunakan lazy loading sejak Level 3. Sekarang kita verifikasi dan tambahkan ke komponen di dalam halaman.

**Level 4 (Testing):** Komponen yang di-lazy-load tetap bisa di-test — import langsung di file test tanpa lazy loading.

**Level 5 (Backend Integration):** Setelah integrasi API, komponen seperti tabel data dan chart jadi besar — inilah saat tepat untuk lazy loading.

**Level 6 (Sekarang):** Ini langkah pertama optimasi performa. Setelah bundle size diperkecil, lanjut ke optimasi rendering (`v-memo`, `shallowRef`), bundle analysis, dan image optimization.

## Soal Latihan

### Soal 1

Di aplikasi BookStore, ada komponen `BookPreviewPDF` (300 KB, library PDF.js) yang hanya muncul saat pengguna klik tombol "Lihat Preview". Saat ini di-import statis:

```vue
<script setup lang="ts">
import BookPreviewPDF from '@/components/books/BookPreviewPDF.vue'
</script>
```

Perbaiki agar komponen hanya dimuat saat tombol diklik. Berikan solusi dengan `defineAsyncComponent`.

<details>
<summary>Jawaban</summary>

```vue
<script setup lang="ts">
import { ref, defineAsyncComponent } from 'vue'

const showPreview = ref(false)

const BookPreviewPDF = defineAsyncComponent({
  loader: () => import('@/components/books/BookPreviewPDF.vue'),
  loadingComponent: {
    template: '<div class="pdf-skeleton">Memuat PDF...</div>'
  },
  delay: 200
})

function openPreview() {
  showPreview.value = true
}
</script>

<template>
  <button @click="openPreview">Lihat Preview</button>
  <BookPreviewPDF v-if="showPreview" />
</template>
```

</details>

### Soal 2

Anda menemukan route Admin diimpor secara statis:

```typescript
import AdminPage from '@/views/AdminPage.vue'
||
const routes = [
  { path: '/admin', component: AdminPage }
]
```

Apa masalahnya? Perbaiki ke lazy loading dan jelaskan bagaimana Vite memperlakukan kedua bentuk import tersebut saat build.

<details>
<summary>Jawaban</summary>

**Masalah:** `AdminPage` akan di-include ke dalam bundle utama (`app.js` atau chunk utama) karena menggunakan import statis. Pengguna yang hanya mengunjungi halaman beranda tetap mengunduh kode admin yang tidak mereka butuhkan.

**Perbaikan:**

```typescript
const routes = [
  {
    path: '/admin',
    component: () => import('@/views/AdminPage.vue')
  }
]
```

**Cara Vite/Rollup memperlakukan:**
- Import statis (`import X from '...'`) → kode dimasukkan ke dalam bundle yang sama dengan file yang meng-import. Termasuk dalam initial load.
- Dynamic import (`() => import('...')`) → Vite membuat chunk terpisah (`AdminPage.[hash].js`). Chunk ini hanya diunduh saat route `/admin` diakses.

Dengan dynamic import, bundle awal mengecil ~300 KB (ukuran halaman admin), membuat First Contentful Paint lebih cepat untuk pengguna biasa.
</details>
