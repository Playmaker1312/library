# 36. Persist Cart Store — Data Tersimpan setelah Refresh

## Penjelasan

Saat ini, jika user menambahkan buku ke keranjang lalu **merefresh halaman**, semua data cart **hilang**. Ini karena state hanya ada di memori (RAM) — saat browser di-reload, seluruh aplikasi Vue di-render ulang dan state kembali ke nilai awal.

**pinia-plugin-persistedstate** adalah plugin resmi yang secara otomatis menyimpan (persist) state Pinia ke **localStorage** atau **sessionStorage**, dan mengembalikannya saat aplikasi dimuat ulang.

| Istilah | Arti |
|---|---|
| **Persist** | Menyimpan state agar bertahan setelah refresh |
| **localStorage** | Penyimpanan browser — data tidak hilang sampai dihapus manual |
| **sessionStorage** | Penyimpanan browser — data hilang saat tab ditutup |
| **Pick** | Memilih bagian state tertentu yang ingin di-persist |

---

## Fungsi

- **Cart tetap ada** meskipun user refresh halaman, pindah tab, atau tutup browser lalu buka lagi
- **Pengalaman pengguna** — tidak perlu memasukkan ulang barang ke keranjang
- Bisa memilih **state mana** yang di-persist (misal hanya `items`, tidak perlu persist computed)
- Bisa memilih **storage** — localStorage (permanen) atau sessionStorage (per tab)

---

## Cara Implementasi

### 1. Install plugin

```bash
npm install pinia-plugin-persistedstate
```

### 2. Setup plugin di `main.ts`

```typescript
import { createApp } from 'vue'
import { createPinia } from 'pinia'
import piniaPluginPersistedstate from 'pinia-plugin-persistedstate'
import App from './App.vue'
import router from './router'

const app = createApp(App)
const pinia = createPinia()

pinia.use(piniaPluginPersistedstate)  // ← daftarkan plugin

app.use(pinia)
app.use(router)
app.mount('#app')
```

**⚠️ Penting:** Plugin harus didaftarkan dengan `pinia.use()` **sebelum** `app.use(pinia)` atau setidaknya sebelum store digunakan.

### 3. Tambahkan opsi `persist` di cart store

```typescript
// src/stores/cart.ts
import { defineStore } from 'pinia'
import { ref, computed } from 'vue'
import type { CartItem } from '@/types/cart'
import type { Book } from '@/types/book'

export const useCartStore = defineStore('cart', () => {
  const items = ref<CartItem[]>([])

  const totalItems = computed(() =>
    items.value.reduce((sum, item) => sum + item.quantity, 0)
  )

  const totalPrice = computed(() =>
    items.value.reduce((sum, item) => sum + item.book.price * item.quantity, 0)
  )

  const isEmpty = computed(() => items.value.length === 0)

  function addItem(book: Book, quantity = 1) {
    const existing = items.value.find(item => item.book.id === book.id)
    if (existing) {
      existing.quantity += quantity
    } else {
      items.value.push({ book, quantity })
    }
  }

  function removeItem(bookId: number) {
    items.value = items.value.filter(item => item.book.id !== bookId)
  }

  function updateQuantity(bookId: number, quantity: number) {
    const item = items.value.find(i => i.book.id === bookId)
    if (item) {
      item.quantity = Math.max(1, quantity)
    }
  }

  function clearCart() {
    items.value = []
  }

  return {
    items, totalItems, totalPrice, isEmpty,
    addItem, removeItem, updateQuantity, clearCart
  }
}, {
  // ─── Konfigurasi persist ───
  persist: {
    key: 'bookstore-cart',       // key di localStorage
    storage: localStorage,        // atau sessionStorage
    pick: ['items']               // hanya persist state 'items'
  }
})
```

### 4. Verifikasi di browser

Buka DevTools → **Application** → **Local Storage**. Cari key `bookstore-cart`. Isinya adalah JSON dari `items` yang sudah di-stringify.

```
Key:   bookstore-cart
Value: [{"book":{"id":1,"title":"Vue.js untuk Pemula","author":"Rudi","price":95000},"quantity":2}]
```

Setiap kali ada perubahan `items`, plugin otomatis menulis ulang ke localStorage. Saat app di-load, plugin membaca localStorage dan mengisi `items` dengan data tersebut.

### 5. Konfigurasi tambahan

```typescript
persist: {
  key: 'bookstore-cart',
  storage: localStorage,
  pick: ['items'],
  serializer: {                    // opsional: kustom serialisasi
    serialize: JSON.stringify,
    deserialize: JSON.parse
  },
  beforeRestore: (context) => {   // hook sebelum restore
    console.log('Restoring cart...')
  },
  afterRestore: (context) => {    // hook setelah restore
    console.log('Cart restored!')
  }
}
```

Tanpa `pick`, semua state (termasuk getters — tapi getters tidak di-persist karena computed) ikut tersimpan. Dengan `pick: ['items']`, kita hanya persist data yang benar-benar perlu.

## Analogi — Toko Buku

Dulu (tanpa persist), papan informasi digital di toko di-**reset** setiap kali toko tutup dan buka lagi (refresh). Semua catatan penjualan dari hari sebelumnya **hilang**. Pelanggan harus memasukkan lagi barang ke keranjang.

Sekarang papan informasi punya **fotokopi otomatis** — setiap kali ada perubahan, isinya difotokopi ke **brankas** (localStorage).

| Proses | Analogi |
|---|---|
| **User tambah item** | Pegawai tulis di papan → fotokopi otomatis ke brankas |
| **User refresh halaman** | Toko tutup → bersihkan papan → buka lagi → ambil fotokopi dari brankas → tulis ulang ke papan |
| **Persist aktif** | Brankas menyimpan data dengan aman |
| **Tanpa persist** | Brankas kosong — setiap buka toko, papan mulai dari nol |

Pelanggan tidak perlu memasukkan barang ke keranjang dua kali. **Data tetap aman meskipun toko "ditutup sementara" (refresh).**

## Dipakai untuk apa

| Skenario | Data yang di-persist | Storage |
|---|---|---|
| **Cart e-commerce** | Items di keranjang | `localStorage` |
| **User preferences** | Dark mode, bahasa, ukuran font | `localStorage` |
| **Auth token** | JWT token (⚠️ hati-hati keamanan) | `localStorage` atau `httpOnly cookie` |
| **Draft form** | Isian form yang belum di-submit | `sessionStorage` (hilang saat tab tutup) |
| **Game progress** | Skor, level, inventory | `localStorage` |
| **Recently viewed** | Riwayat produk yang dilihat | `localStorage` |

## Kesalahan Umum

| Kesalahan | Akibat | Cara Benar |
|---|---|---|
| **Lupa register plugin di `main.ts`** | Opsi `persist` diabaikan — data hilang saat refresh | `pinia.use(piniaPluginPersistedstate)` |
| **Persist seluruh state (termasuk computed)** | Getters tidak perlu di-persist — boros storage | Gunakan `pick: ['items']` |
| **Persist data sensitif (token, password)** | Rentan XSS — siapa pun bisa baca localStorage | Jangan persist token sensitif; gunakan httpOnly cookie |
| **Key tidak unik antar store** | Dua store bisa timpa data yang sama | Beri key unik: `'bookstore-cart'`, `'bookstore-wishlist'` |
| **Lupa handle stale data** | Data lama (format berbeda) bisa merusak app | Validasi data saat restore — atau gunakan `beforeRestore` |
| **Persist state yang terlalu besar** | Ukuran localStorage terbatas (~5-10MB) | Hanya persist yang penting; gunakan `pick` |

**⚠️ Keamanan:** `localStorage` bisa diakses oleh JavaScript apa pun di domain yang sama. Jangan simpan **token JWT** atau data sensitif lain di localStorage tanpa enkripsi. Untuk auth, lebih aman gunakan **httpOnly cookie** yang tidak bisa diakses JS.

## Hubungan dengan Materi Sebelumnya

- **Poin 35 (CartView):** Cart sudah tampil, tapi **hilang saat refresh**. Sekarang dengan persist, data cart bertahan — user bisa refresh halaman cart, data tetap ada.
- **Poin 33 (defineStore):** Struktur store tetap sama — kita hanya tambahkan opsi `persist: { ... }` sebagai argumen kedua `defineStore`.
- **Poin 28 (Router):** Sebelumnya, pindah halaman dengan router tidak menghilangkan cart (karena Pinia menyimpan di memori). Tapi refresh halaman tetap hilang. Sekarang refresh pun aman.
- **Poin 1 (create-vue):** Plugin ini tidak include oleh default — harus install manual dengan npm.
- **Konsep localStorage (umum):** localStorage adalah Web Storage API — setiap domain punya penyimpanan sendiri, maksimal ~5MB.

### Soal 2

Apa yang terjadi jika kita persist getter `totalPrice` (misal karena typo di `pick`)? Jelaskan mengapa getter tidak perlu di-persist.

<details>
<summary>Jawaban Soal 2</summary>

Jika kita persist getter (misal karena `pick: ['items', 'totalPrice']`), maka:

1. **Getter tidak akan tersimpan** — Pinia's persistedstate internally hanya bisa persist `ref` dan `reactive`, bukan `computed`. Computed bersifat read-only dan tidak bisa di-serialize.
2. **Jika getter terlanjur tersimpan sebagai snapshot** — saat restore, nilainya mungkin sudah tidak relevan karena data `items` sudah berubah sejak snapshot diambil.
3. **Getter harus dihitung ulang dari state**, bukan dari penyimpanan.

**Mengapa getter tidak perlu di-persist:**
- Getters adalah **turunan** dari state — `totalPrice` dihitung dari `items`. Jika `items` sudah di-persist, `totalPrice` otomatis benar.
- Menyimpan getter hanya **boros storage** dan berpotensi **stale data**.
- Prinsip: persist **source of truth** (state), jangan persist **derived data** (getters).

</details>
