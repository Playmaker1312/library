# 37. Membuat Wishlist Store

## Penjelasan

Setelah cart store berhasil, sekarang kita buat **store kedua** — **Wishlist Store**. Wishlist adalah daftar buku yang "ditandai" user untuk dibeli nanti. Konsepnya mirip dengan cart, tapi dengan perilaku berbeda:

| Aspek | Cart | Wishlist |
|---|---|---|
| **Tujuan** | Siap dibeli | Ingin dibeli nanti |
| **Quantity** | Bisa lebih dari 1 | Hanya ada / tidak ada (tidak pakai quantity) |
| **Aksi** | Tambah, hapus, update qty | **Toggle** — tambah jika belum ada, hapus jika sudah ada |
| **Persist** | ✅ localStorage | ✅ localStorage |

Kita akan gunakan pola yang sama: `defineStore`, state `items: ref<Book[]>`, action `toggleWishlist`, getter `isInWishlist`, dan persist dengan `pinia-plugin-persistedstate`.

---

## Fungsi

- User bisa menandai buku favorit dengan ikon ❤️
- Cek status wishlist dengan `isInWishlist(bookId)` — untuk toggle icon
- Counter wishlist di AppHeader
- Wishlist di-persist agar tidak hilang saat refresh
- Data terpisah dari cart — dua store, dua domain berbeda

## Cara Implementasi

### 1. Buat file `src/stores/wishlist.ts`

```typescript
import { defineStore } from 'pinia'
import { ref, computed } from 'vue'
import type { Book } from '@/types/book'

export const useWishlistStore = defineStore('wishlist', () => {
  // ─── State ───
  const items = ref<Book[]>([])

  // ─── Getters ───
  const count = computed(() => items.value.length)

  function isInWishlist(bookId: number): boolean {
    return items.value.some(book => book.id === bookId)
  }

  // ─── Actions ───
  function toggleWishlist(book: Book) {
    const index = items.value.findIndex(b => b.id === book.id)
    if (index === -1) {
      items.value.push(book)           // belum ada → tambah
    } else {
      items.value.splice(index, 1)     // sudah ada → hapus
    }
  }

  function removeFromWishlist(bookId: number) {
    items.value = items.value.filter(book => book.id !== bookId)
  }

  function clearWishlist() {
    items.value = []
  }

  return {
    items, count, isInWishlist,
    toggleWishlist, removeFromWishlist, clearWishlist
  }
}, {
  // ─── Persist ───
  persist: {
    key: 'bookstore-wishlist',
    storage: localStorage,
    pick: ['items']
  }
})
```

## Analogi — Toko Buku

Wishlist seperti **"daftar buku incaran"** di toko. Berbeda dengan keranjang (siap beli), wishlist adalah **"tandai untuk nanti"** — seperti menempelkan stiker bintang pada buku yang menarik.

| Store | Analogi |
|---|---|
| **Cart store** | Keranjang belanja fisik — siap dibawa ke kasir |
| **Wishlist store** | Papan "Buku yang Saya Suka" di dinding toko — lihat nanti |

**Dua papan terpisah:**
- **Papan 1 (Cart):** Catatan barang yang akan dibeli sekarang — ada quantity, total harga
- **Papan 2 (Wishlist):** Daftar barang yang menarik — tanpa quantity, tanpa harga total

**Alur umum:**
1. Pelanggan lihat buku → tempel stiker ❤️ (wishlist)
2. Nanti pelanggan datang lagi → lihat papan wishlist → "Oh, ini buku yang saya suka"
3. "Clean Code" → ambil dari wishlist → pindahkan ke keranjang (cart) → bayar

Keduanya menggunakan fotokopi otomatis (persist) — brankas masing-masing:

| Key localStorage | Isi |
|---|---|
| `bookstore-cart` | Item siap dibeli |
| `bookstore-wishlist` | Item incaran |

## Dipakai untuk apa

| Skenario | Contoh |
|---|---|
| **E-commerce** | Wishlist produk — bandingkan nanti, notifikasi diskon |
| **Job portal** | Simpan lowongan pekerjaan untuk dilamar nanti |
| **Recipe app** | Simpan resep favorit |
| **Course platform** | Daftar kursus yang ingin diambil |
| **Property listing** | Tandai properti untuk di survey |

---

## Kesalahan Umum

| Kesalahan | Akibat | Cara Benar |
|---|---|---|
| **Wishlist dan cart pakai store yang sama** | Data campur aduk — wishlist item ikut ke checkout | Dua store terpisah: `useCartStore` dan `useWishlistStore` |
| **Wishlist pakai quantity** | Konsep wishlist tidak perlu quantity | Wishlist cukup ada/tidak; gunakan `toggle` |
| **Lupa persist wishlist** | Wishlist hilang saat refresh | Tambahkan `persist: { key: 'bookstore-wishlist', pick: ['items'] }` |
| **Ikon wishlist tidak toggle** | Ikon ❤️ tidak berubah saat diklik | Gunakan `isInWishlist(bookId)` untuk class binding |
| **Mutasi wishlist items langsung** | `items.value.push(book)` tanpa toggle | Selalu gunakan `toggleWishlist(book)` |
| **Duplicate key persist** | `key: 'bookstore-cart'` di wishlist → timpa data cart | Setiap store harus punya key UNIK |

---

## Hubungan dengan Materi Sebelumnya

- **Poin 33-36:** Pola pembuatan wishlist store **sama persis** dengan cart store. Bedanya hanya di konten dan perilaku (toggle vs add). Semua yang dipelajari — `defineStore`, state, getters, actions, persist — diterapkan kembali.
- **Poin 34 (Akses store):** Wishlist store diakses dari BookCard (toggle) dan AppHeader (counter) — sama seperti cart store.
- **Poin 22 (Emit):** Sebelumnya interaksi BookCard terbatas pada emit ke parent. Sekarang BookCard bisa berinteraksi dengan **dua store** sekaligus — cart dan wishlist.
- **Poin 23 (Cart State Level 2):** Di Level 2 hanya ada cart. Sekarang ada **wishlist** sebagai fitur tambahan yang memperkaya aplikasi.
- **Poin 28 (Router):** Route `/wishlist` sudah disiapkan sejak awal — sekarang halamannya benar-benar ada.
- **Poin 36 (Persist):** Wishlist juga di-persist dengan pola yang sama — `pick: ['items']`, `storage: localStorage`, key unik.

function moveAllToCart() {
  if (wishlist.count === 0) return

  const konfirmasi = confirm(
    `Pindahkan ${wishlist.count} buku dari wishlist ke keranjang?`
  )
  if (!konfirmasi) return

  wishlist.items.forEach(book => cart.addItem(book))

}

### Soal 2

Buat sebuah **computed** di wishlist store bernama `hasNewItems` yang mengembalikan `true` jika ada buku yang ditambahkan ke wishlist **setelah kunjungan terakhir user**. Gunakan timestamp.

<details>
<summary>Jawaban Soal 2</summary>

**Pendekatan:** Simpan timestamp kapan terakhir wishlist dilihat, lalu bandingkan dengan timestamp saat item ditambahkan.

```typescript
// Di wishlist store

// ─── State tambahan ───
const items = ref<Book[]>([])
const lastVisited = ref<number>(Date.now())  // timestamp saat terakhir buka halaman wishlist
const itemAddedAt = ref<Record<number, number>>({})  // { bookId: timestamp }

// ─── Getter ───
const hasNewItems = computed(() => {
  if (items.value.length === 0) return false
  return items.value.some(book => {
    const addedAt = itemAddedAt.value[book.id]
    return addedAt && addedAt > lastVisited.value
  })
})

// ─── Update action ───
function toggleWishlist(book: Book) {
  const index = items.value.findIndex(b => b.id === book.id)
  if (index === -1) {
    items.value.push(book)
    itemAddedAt.value[book.id] = Date.now()  // catat timestamp
  } else {
    items.value.splice(index, 1)
    delete itemAddedAt.value[book.id]
  }
}

// Panggil saat wishlistView di-mount
function markAsVisited() {
  lastVisited.value = Date.now()
}
```

Di `WishlistView.vue`:

```typescript
import { onMounted } from 'vue'
const wishlist = useWishlistStore()

onMounted(() => {
  wishlist.markAsVisited()
})
```

**Catatan:** Untuk production, pertimbangkan persist `lastVisited` dan `itemAddedAt` juga agar bertahan saat refresh.

</details>
