# 32. NotFoundView dan Transisi Halaman

## Penjelasan

Dua peningkatan UX di bagian akhir setup router:

### 1. NotFoundView (404)

Catch-all route `/:pathMatch(.*)*` menangkap **semua URL yang tidak cocok** dengan route lain. NotFoundView menampilkan pesan ramah + petunjuk ke halaman yang valid.

### 2. Transisi Halaman

Komponen `<Transition>` membungkus `<RouterView>` untuk memberikan **animasi** saat pindah halaman — fade, slide, scale, dll.

## Fungsi

- **NotFoundView**: Mencegah user melihat layar putih/kosong saat URL salah
- **Transisi**: Membuat navigasi terasa halus dan profesional, mengurangi lompatan visual yang mengganggu

### 2. Transisi di App.vue

```vue
<script setup lang="ts">
import { RouterView } from 'vue-router'
</script>

<template>
  <header>
    <nav>
      <RouterLink :to="{ name: 'home' }">Beranda</RouterLink>
      <RouterLink :to="{ name: 'cart' }">Keranjang</RouterLink>
      <RouterLink :to="{ name: 'wishlist' }">Wishlist</RouterLink>
    </nav>
  </header>

  <main>
    <RouterView v-slot="{ Component, route }">
      <Transition name="page" mode="out-in">
        <component :is="Component" :key="route.path" />
      </Transition>
    </RouterView>
  </main>
</template>

<style>
/* Fade transition */
.page-enter-active,
.page-leave-active {
  transition: opacity 0.25s ease, transform 0.25s ease;
}

.page-enter-from {
  opacity: 0;
  transform: translateY(12px);
}

.page-leave-to {
  opacity: 0;
  transform: translateY(-12px);
}
</style>
```

### Penjelasan kode transisi

- **`v-slot="{ Component, route }"`**: Slot scoped — `Component` adalah komponen halaman, `route` adalah objek route
- **`:key="route.path"`**: Vue perlu key unik untuk trigger transisi. Tanpa key, Vue re-use komponen yang sama dan transisi tidak jalan
- **`mode="out-in"`**: Halaman lama hilang **dulu**, baru halaman baru muncul. Mencegah overlap yang jelek
- **CSS classes**:
  - `.page-enter-active` / `.page-leave-active`: **durasi** dan **easing** transisi
  - `.page-enter-from`: **state awal** halaman baru (sebelum muncul)
  - `.page-leave-to`: **state akhir** halaman lama (setelah menghilang)

### Variasi transisi lain

```css
/* Slide from right */
.slide-enter-active,
.slide-leave-active {
  transition: transform 0.3s ease, opacity 0.3s ease;
}
.slide-enter-from {
  transform: translateX(100%);
  opacity: 0;
}
.slide-leave-to {
  transform: translateX(-100%);
  opacity: 0;
}

/* Scale */
.scale-enter-active,
.scale-leave-active {
  transition: transform 0.2s ease, opacity 0.2s ease;
}
.scale-enter-from,
.scale-leave-to {
  transform: scale(0.95);
  opacity: 0;
}
```

## Analogi — Pintu Ramah dan Efek Fade

**NotFoundView (pintu ramah)**:

Bayangkan di toko buku, ada pintu yang bertuliskan:

> **"Maaf, bagian ini belum dibuka"**
>
> Bagian yang Anda cari mungkin masih dalam renovasi,
> atau Anda salah membaca peta toko.
> — Silakan kembali ke pintu utama → [Beranda]

Bukan tembok bata yang galat, bukan layar komputer mati (white screen). Tapi **pintu dengan pegawai ramah** yang memberi petunjuk ke tempat yang benar.

**Transisi halaman (efek fade)**:

Saat pengunjung pindah dari Beranda ke Rak Buku, tanpa transisi:
- **BAM** — gambar beranda hilang, gambar rak muncul tiba-tiba. Mata butuh waktu untuk menyesuaikan.

Dengan transisi:
- Beranda perlahan **memudar (fade out)** sambil sedikit bergeser ke atas
- Rak Buku perlahan **muncul (fade in)** sambil bergeser dari bawah
- Mata nyaman, navigasi terasa profesional

## Dipakai untuk Apa

- **NotFoundView**: Semua aplikasi publik harus punya halaman 404 yang ramah — bukan white screen atau error message mentah
- **Transisi**: Aplikasi dengan banyak halaman (dashboard, e-commerce, blog) — transisi membuat navigasi terasa hidup
- **Transisi per route**: Bisa beda transisi untuk route yang berbeda (misal: slide untuk main pages, fade untuk modal)

## Kesalahan Umum

1. **Catch-all route tidak di akhir array** → Semua route di bawahnya tidak pernah kepanggil (lihat Soal 2 Poin 28)
2. **Lupa `:key="route.path"` di component** → Transisi tidak pernah jalan karena Vue menganggap komponen sama dan tidak trigger animasi
3. **`mode="out-in"` tidak cocok dengan layout** → Jika ada layout bersama (sidebar, header) yang FIX, transisi `out-in` bisa bikin layout ikut hilang. Solusi: gunakan `mode="out-in"` hanya untuk wrapper konten utama, atau pisahkan layout dari `RouterView`
4. **CSS transition lupa prefix** → `.page-enter-from` salah ketik jadi `.page-enter-form` (r dan m tertukar). Transisi tidak jalan tanpa error — debugging sulit
5. **NotFoundView tidak informatif** → 404 cuma tulisan "Not Found" tanpa link navigasi. User bingung harus ke mana

<details>
<summary>Jawaban</summary>
