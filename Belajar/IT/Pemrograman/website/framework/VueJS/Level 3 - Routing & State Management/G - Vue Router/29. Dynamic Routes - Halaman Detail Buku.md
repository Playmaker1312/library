# 29. Dynamic Routes — Halaman Detail Buku

## Penjelasan

**Dynamic route** menggunakan **dynamic segment** (`:id`) di path. Saat user mengunjungi `/books/5`, Vue Router menangkap `5` sebagai parameter route yang bisa diakses via `route.params.id`.

Route di router:
```typescript
{
  path: '/books/:id',
  name: 'book-detail',
  component: () => import('../views/BookDetailView.vue')
}
```

## Fungsi

Menampilkan halaman **dinamis** berdasarkan parameter URL. Satu route bisa menghasilkan halaman berbeda tergantung nilai `:id` — `/books/1` menampilkan buku #1, `/books/42` menampilkan buku #42.

## Cara Implementasi

### BookDetailView.vue — versi lengkap

```vue
<script setup lang="ts">
import { ref, watch } from 'vue'
import { useRoute, useRouter } from 'vue-router'
import { bookData } from '../data/books'

const route = useRoute()
const router = useRouter()

const book = ref<Book | null>(null)
const loading = ref(false)

function loadBook(id: string) {
  loading.value = true
  const found = bookData.find(b => b.id === Number(id))
  if (found) {
    book.value = found
  } else {
    // Redirect ke 404 jika buku tidak ditemukan
    router.replace({ name: 'not-found' })
    return
  }
  loading.value = false
}

// Load buku saat komponen mount
loadBook(route.params.id as string)

// Watch perubahan param — penting!
watch(() => route.params.id, (newId) => {
  if (newId) loadBook(newId as string)
})
</script>

<template>
  <div v-if="loading">Memuat data buku...</div>
  <div v-else-if="book" class="book-detail">
    <h1>{{ book.title }}</h1>
    <p class="author">Penulis: {{ book.author }}</p>
    <p class="price">Rp{{ book.price.toLocaleString() }}</p>
    <p class="description">{{ book.description }}</p>
    <button @click="router.back()">Kembali</button>
  </div>
</template>
```

### Data buku contoh (`src/data/books.ts`)

```typescript
export interface Book {
  id: number
  title: string
  author: string
  price: number
  description: string
}

export const bookData: Book[] = [
  { id: 1, title: 'Vue.js Dasar', author: 'Ahmad', price: 85000, description: 'Panduan lengkap Vue 3.' },
  { id: 2, title: 'TypeScript untuk Semua', author: 'Budi', price: 95000, description: 'TypeScript dari pemula hingga mahir.' },
  { id: 3, title: 'Reaktivitas Vue', author: 'Citra', price: 75000, description: 'Memahami reactivity system Vue.' }
]
```

## Mengapa Perlu `watch(() => route.params.id, ...)`?

**Masalah**: User di halaman `/books/1` lalu klik link ke `/books/2`. Karena komponen **BookDetailView** sudah di-mount, Vue _reuses_ komponen yang sama (tidak destroy & remount). Akibatnya `loadBook` di mount **tidak dijalankan lagi** — data tetap buku #1.

**Solusi**: `watch(() => route.params.id, ...)` — setiap kali `:id` berubah, kita jalankan `loadBook` dengan id baru.

## Analogi — Rak Bernomor di Toko Buku

Toko buku punya rak-rak bernomor 1 sampai 100. Setiap rak punya buku berbeda.

- `/books/5` → "Pergi ke rak nomor 5, ambil buku di sana"
- `/books/99` → "Pergi ke rak nomor 99"

`:id` adalah nomor rak. `route.params.id` membaca nomor yang ditulis pengunjung di peta (URL).

**Kalau rak tidak ada** (misal rak 999): pengunjung diarahkan ke lorong buntu (404) — di kode kita `router.replace({ name: 'not-found' })`.

**Watch** seperti pegawai yang siap sedia di rak: "Oh, pengunjung pindah dari rak 5 ke rak 2, saya ganti display bukunya."

## Dipakai untuk Apa

- **E-commerce**: `/products/:id` — halaman detail produk
- **Blog**: `/posts/:slug` — halaman artikel (slug seperti `vue-router-panduan`)
- **Profile user**: `/users/:username` — halaman profil
- **Dashboard**: `/dashboard/:section` — bagian tertentu di dashboard

## Kesalahan Umum

1. **Lupa `watch(() => route.params.id, ...)`** → Navigasi dari `/books/1` ke `/books/2` data tidak berubah. User bingung lihat buku 1 padahal URL menunjukkan `/books/2`.
2. **Tidak handle not-found** → User akses `/books/999`, data `undefined`, error `Cannot read properties of undefined`.
3. **`route.params.id` bertipe `string`** → `book.id` biasanya number. Bandingkan dengan `Number(id)` atau `=== String(book.id)`.
4. **Mengubah params langsung** → `route.params.id = '5'` tidak akan berpengaruh. Params hanya bisa berubah via navigasi (`router.push`, `RouterLink`).

### Soal 1
Buat `BookDetailView.vue` yang membaca parameter `slug` (string) dari URL `/books/:slug` dan mencari buku berdasarkan `slug` (bukan `id`). Jika tidak ditemukan, redirect ke halaman 404.

```vue
<script setup lang="ts">
import { ref, watch } from 'vue'
import { useRoute, useRouter } from 'vue-router'
import { bookData, type Book } from '../data/books'

const route = useRoute()
const router = useRouter()
const book = ref<Book | null>(null)

function loadBook(slug: string) {
  const found = bookData.find(b => b.slug === slug)
  if (found) {
    book.value = found
  } else {
    router.replace({ name: 'not-found' })
  }
}

loadBook(route.params.slug as string)

watch(() => route.params.slug, (newSlug) => {
  if (newSlug) loadBook(newSlug as string)
})
</script>

<template>
  <div v-if="book">
    <h1>{{ book.title }}</h1>
  </div>
  <div v-else>
    <p>Buku tidak ditemukan</p>
  </div>
</template>
```

### Soal 2
Apa perbedaan perilaku ketika user mengklik link dari `/books/1` ke `/books/2` jika:
a) Tidak pakai `watch`
b) Pakai `watch`

<details>
<summary>Jawaban</summary>

a) **Tanpa watch**: Komponen di-reuse, `loadBook` di `onMounted` tidak dijalankan lagi. Yang tampil tetap buku #1 meskipun URL menunjukkan `/books/2`. User melihat data yang salah.

b) **Dengan watch**: `watch(() => route.params.id, ...)` mendeteksi perubahan dari `'1'` ke `'2'`, lalu menjalankan `loadBook('2')`. Data buku berubah sesuai URL.
