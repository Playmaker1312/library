# 27. Membuat Composable `useBookFilter` — Refactor HomeView

## Penjelasan

Setelah memahami `useLocalStorage` (poin 26), saatnya membuat composable yang lebih spesifik untuk domain aplikasi: **useBookFilter**.

Composable ini akan **memindahkan semua logika filter** (search, sort by, kategori, pagination) dari `HomeView` ke dalam satu fungsi terpisah. Hasilnya:

- `HomeView` menjadi jauh lebih bersih — tinggal panggil composable dan render data
- Logika filter bisa diuji secara terpisah
- Jika nanti komponen lain perlu filter buku (misal halaman katalog), tinggal pakai composable yang sama

---

## Fungsi

- Menerima `books: Ref<Book[]>` sebagai input
- Mengembalikan state dan method filter: `searchQuery`, `sortBy`, `selectedCategory`, `filteredBooks`, `totalPages`, `currentPage`, `resetFilters`
- Otomatis menghitung ulang `filteredBooks` setiap kali input atau filter berubah (menggunakan `computed`)
- Menyimpan preferensi filter ke localStorage (menggunakan `useLocalStorage` di dalamnya)

## Cara Implementasi / Kode

### Composable `useBookFilter`

```typescript
// composables/useBookFilter.ts
import { computed, type Ref } from 'vue'
import { useLocalStorage } from './useLocalStorage'

export interface Book {
  id: number
  title: string
  author: string
  category: string
  price: number
  rating: number
}

export type SortOption = 'title' | 'price-asc' | 'price-desc' | 'rating'

const ITEMS_PER_PAGE = 8

export function useBookFilter(books: Ref<Book[]>) {
  const { data: searchQuery } = useLocalStorage('book-search', '')
  const { data: sortBy } = useLocalStorage<SortOption>('book-sort', 'title')
  const { data: selectedCategory } = useLocalStorage('book-category', '')
  const { data: currentPage } = useLocalStorage('book-page', 1)

  // Unique categories derived from books
  const categories = computed(() => {
    const cats = new Set(books.value.map((b) => b.category))
    return ['', ...cats]  // empty string = all categories
  })

  // Filter by search + category
  const filtered = computed(() => {
    return books.value.filter((book) => {
      const matchSearch =
        !searchQuery.value ||
        book.title.toLowerCase().includes(searchQuery.value.toLowerCase()) ||
        book.author.toLowerCase().includes(searchQuery.value.toLowerCase())
      const matchCategory =
        !selectedCategory.value || book.category === selectedCategory.value
      return matchSearch && matchCategory
    })
  })

  // Sort
  const sorted = computed(() => {
    const arr = [...filtered.value]
    switch (sortBy.value) {
      case 'price-asc':
        return arr.sort((a, b) => a.price - b.price)
      case 'price-desc':
        return arr.sort((a, b) => b.price - a.price)
      case 'rating':
        return arr.sort((a, b) => b.rating - a.rating)
      case 'title':
      default:
        return arr.sort((a, b) => a.title.localeCompare(b.title))
    }
  })

  // Pagination
  const totalPages = computed(() =>
    Math.max(1, Math.ceil(sorted.value.length / ITEMS_PER_PAGE))
  )

  const filteredBooks = computed(() => {
    const start = (currentPage.value - 1) * ITEMS_PER_PAGE
    return sorted.value.slice(start, start + ITEMS_PER_PAGE)
  })

  function resetFilters() {
    searchQuery.value = ''
    sortBy.value = 'title'
    selectedCategory.value = ''
    currentPage.value = 1
  }

  return {
    searchQuery,
    sortBy,
    selectedCategory,
    categories,
    currentPage,
    filteredBooks,
    totalPages,
    resetFilters,
  }
}
```

### `HomeView` setelah refactor

```vue
<script setup lang="ts">
import { useBookFilter, type Book } from '../composables/useBookFilter'
import { useLocalStorage } from '../composables/useLocalStorage'

const { data: books } = useLocalStorage<Book[]>('books', [])
const {
  searchQuery,
  sortBy,
  selectedCategory,
  categories,
  currentPage,
  filteredBooks,
  totalPages,
  resetFilters,
} = useBookFilter(books)
</script>

<template>
  <div>
    <h1>Katalog Buku</h1>

    <input v-model="searchQuery" placeholder="Cari buku..." />
    <select v-model="sortBy">
      <option value="title">Judul A-Z</option>
      <option value="price-asc">Harga termurah</option>
      <option value="price-desc">Harga termahal</option>
      <option value="rating">Rating</option>
    </select>
    <select v-model="selectedCategory">
      <option value="">Semua Kategori</option>
      <option v-for="cat in categories" :key="cat" :value="cat">{{ cat }}</option>
    </select>
    <button @click="resetFilters">Reset Filter</button>

    <div v-for="book in filteredBooks" :key="book.id" class="book-card">
      <h3>{{ book.title }}</h3>
      <p>{{ book.author }} — Rp{{ book.price }}</p>
      <p>Rating: {{ book.rating }}/5</p>
    </div>

    <div class="pagination">
      <button
        v-for="p in totalPages"
        :key="p"
        :disabled="p === currentPage"
        @click="currentPage = p"
      >
        {{ p }}
      </button>
    </div>
  </div>
</template>
```

> **Perhatikan:** `HomeView` sekarang tidak berisi logic filter sama sekali — semua sudah dipindahkan ke `useBookFilter`. Ini separasi tanggung jawab yang bersih.

## Analogi — Toko Buku

Sebelum refactor, toko buku seperti ini:

- **Pegawai etalase (HomeView)** melakukan semuanya sendiri: menerima pelanggan, mencatat stok, mengatur rak berdasarkan kategori, mengurutkan buku, menghitung halaman, dan menyimpan catatan ke brankas. Semua kertas kerja menumpuk di meja kasir. **Berantakan dan campur aduk.**

Sesudah refactor dengan `useBookFilter`:

- **Bagian administrasi (useBookFilter)** dibentuk sebagai departemen terpisah.
- Tugasnya: filter, sort, kategori, pagination — semua urusan pengolahan data.
- **Pegawai etalase (HomeView)** tinggal terima hasil jadi dari bagian administrasi dan menampilkannya ke pelanggan.
- Kalau ada perubahan aturan filter (misal: mau tambah filter harga minimum), cukup ubah di **satu tempat** (composable) — tidak perlu bongkar etalase.

Selain itu, `useBookFilter` juga mempekerjakan **mesin stok otomatis (`useLocalStorage`)** untuk menyimpan preferensi filter — jadi pelanggan tidak perlu mengatur ulang filter setiap kali datang ke toko.

## Kesalahan Umum

| Kesalahan | Dampak | Cara Menghindari |
|-----------|--------|------------------|
| Composable terlalu spesifik (hanya untuk satu komponen) | Tidak reusable, percuma buat composable | Jika hanya dipakai satu komponen, tanya diri: "Apakah komponen lain di masa depan perlu logika ini?" |
| Composable terlalu generic (menerima terlalu banyak parameter) | Sulit dipahami dan dipakai | Batasi parameter. Gunakan default value. Pisah jadi beberapa composable kecil jika perlu. |
| Memanggil composable di dalam callback / kondisi | State tidak reaktif (Vue warning) | Panggil composable di akar `setup()` / langsung di `<script setup>` |
| Composable mengubah props langsung | Mutasi tidak boleh | Composable harus menerima `Ref` atau nilai, bukan props mentah |
| Lupa bahwa composable dipanggil per-instance | State berbeda tiap pemanggilan (ini yang diinginkan) | Sadari bahwa setiap pemanggilan `useBookFilter(books)` menghasilkan instance filter sendiri |

## Hubungan dengan Materi Sebelumnya

- **Poin 26 (`useLocalStorage`):** `useBookFilter` **menggunakan** `useLocalStorage` di dalamnya — ini menunjukkan bahwa composable bisa memanggil composable lain. Komposisi seperti ini adalah inti dari pattern composable.
- **Bagian D (`ref`, `reactive`):** Input `books` adalah `Ref<Book[]>`. Output `searchQuery`, `sortBy`, dll juga ref.
- **Bagian E (`computed`):** Seluruh logika filter dan pagination menggunakan `computed` — otomatis reaktif.
- **Poin 25 (lifecycle):** `useLocalStorage` di dalamnya menggunakan `watch` yang merupakan pewatas lifecycle hooks.
- **Level 1:** Dulu logika filter ditulis langsung di Options API `methods`. Sekarang dipisah rapi ke fungsi mandiri.

> **Prinsip:** Composable yang baik berfokus pada satu tanggung jawab, menggunakan composable lain untuk subtugas, dan mengembalikan interface yang jelas dan minimal.

### Soal 2

Buat composable `useDebouncedSearch` yang menerima `source: Ref<string>` dan `delay: number`, lalu mengembalikan `debounced: Ref<string>` yang nilainya tertunda sesuai `delay` ms. Gunakan di dalam `useBookFilter` untuk mengganti `searchQuery` langsung dengan versi debounced.

<details>
<summary>Jawaban</summary>

```typescript
// composables/useDebouncedSearch.ts
import { ref, watch, type Ref } from 'vue'

export function useDebouncedSearch(source: Ref<string>, delay = 300): { debounced: Ref<string> } {
  const debounced = ref(source.value)
  let timer: ReturnType<typeof setTimeout> | null = null

  watch(source, (val) => {
    if (timer) clearTimeout(timer)
    timer = setTimeout(() => {
      debounced.value = val
    }, delay)
  })

  return { debounced }
}
```

Lalu di `useBookFilter`:

```typescript
import { useDebouncedSearch } from './useDebouncedSearch'

const { data: rawSearch } = useLocalStorage('book-search', '')
const { debounced: searchQuery } = useDebouncedSearch(rawSearch, 300)
```

Sekarang `filtered` menggunakan `searchQuery` yang sudah debounced — tidak memicu filter ulang setiap karakter diketik, hanya setelah 300ms user berhenti mengetik.
