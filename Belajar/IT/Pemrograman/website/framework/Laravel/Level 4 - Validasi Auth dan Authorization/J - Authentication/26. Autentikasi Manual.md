# 26. Autentikasi Manual — Memahami di Balik Layar

## Penjelasan

Setelah menggunakan Breeze (poin 25), penting memahami apa yang terjadi di balik layar. Autentikasi Laravel menggunakan **Auth facade** dan **guards**.

**Auth facade** menyediakan method untuk login/logout:
```php
Auth::attempt(['email' => $email, 'password' => $password]);
Auth::user();    // user yang login
Auth::id();      // ID user
Auth::check();   // apakah login?
Auth::guest();   // apakah belum login?
auth()->user();  // helper global (sama)
```

**Alur login:**
1. User submit email + password
2. `Auth::attempt()` cek di database
3. Jika cocok: buat session, regenerate token
4. Jika tidak: return false, redirect back dengan error

## Fungsi

- Mengelola session login user
- Menyediakan akses ke data user yang login
- Logout dan invalidasi session

## Cara Pengimplementasian

```php
<?php
// app/Http/Controllers/Auth/LoginController.php

namespace App\Http\Controllers\Auth;

use App\Http\Controllers\Controller;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Auth;

class LoginController extends Controller
{
    public function showLoginForm()
    {
        return view('auth.login');
    }

    public function login(Request $request)
    {
        // 1. Validasi input
        $credentials = $request->validate([
            'email'    => ['required', 'email'],
            'password' => ['required'],
        ]);

        // 2. Coba login
        if (Auth::attempt($credentials, $request->boolean('ingat_saya'))) {
            // 3a. Sukses: regenerate session (cegah session fixation)
            $request->session()->regenerate();

            return redirect()
                ->intended(route('dashboard'))  // ke halaman sebelum login
                ->with('sukses', 'Selamat datang kembali!');
        }

        // 3b. Gagal: redirect back dengan error
        return back()
            ->withErrors([
                'email' => 'Email atau password tidak cocok.',
            ])
            ->onlyInput('email');  // jangan kirim balik password
    }

    public function logout(Request $request)
    {
        Auth::logout();

        // Hancurkan session
        $request->session()->invalidate();
        $request->session()->regenerateToken();

        return redirect()->route('login');
    }
}
```

```php
<?php
// Cara akses user yang login
// Di controller:
$user = auth()->user();         // Model User atau null
$id   = auth()->id();           // ID atau null
$check = auth()->check();       // bool

// Di Blade:

@endauth

@guest
    <p>Silakan login.</p>
@endguest

// Kondisional di Blade:

@endauth
```

## Analogi

Auth facade seperti **sistem kartu anggota perpustakaan**:

- **`Auth::attempt()`** = Petugas memeriksa kartu anggota: "Apakah nomor anggota dan nama cocok dengan data?"
- **`Auth::check()`** = "Apakah pengunjung ini sudah terdaftar?" (true/false)
- **`Auth::user()`** = "Tunjukkan data anggota ini" (nama, alamat, no telepon)
- **`Auth::logout()`** = Pengunjung keluar, kartu dikembalikan
- **`session()->regenerate()`** = Ganti kunci loker yang dipakai — supaya orang lain tidak bisa pakai kunci lama

**Proses login detail:**
```
Pengunjung datang → berikan kartu (email + password)
    ↓
Petugas cek database → apakah kartu valid?
    ├── Ya: → berikan kunci loker (session) → "Silakan masuk"
    └── Tidak: → "Maaf, kartu tidak dikenali" (error)
```

**Session Fixation Prevention:**
Saat login, session lama dihancurkan dan dibuat baru. Ini mencegah attacker menggunakan session ID yang sudah diketahui untuk membajak akun.

## Dipakai untuk Apa

- **Setiap halaman yang butuh login** — menentukan user yang sedang login
- **Menampilkan informasi personal** — "Halo, {nama}!"
- **Otorisasi** — menentukan apakah user bisa melakukan aksi tertentu
- **Logout** — mengakhiri session

## Kesalahan Umum

1. **Password tidak di-hash** — `Auth::attempt()` compare dengan hash. Jika password di database plain text, tidak akan cocok. Selalu gunakan `bcrypt()` atau `Hash::make()`
2. **Lupa `regenerate()` setelah login** — rentan session fixation
3. **Lupa `invalidate()` dan `regenerateToken()` setelah logout** — session lama masih bisa dipakai
4. **`Auth::attempt()` tanpa validasi** — email/password bisa kosong atau aneh
5. **Mengirim password kembali ke form setelah error** — gunakan `->onlyInput('email')`, bukan `->withInput()`
