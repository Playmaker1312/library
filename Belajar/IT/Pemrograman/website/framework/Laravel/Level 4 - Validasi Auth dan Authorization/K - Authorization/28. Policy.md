# 28. Policy — Otorisasi Berbasis Resource

## Penjelasan

**Policy** adalah class yang mengatur **siapa yang boleh melakukan apa** terhadap resource tertentu. Auth (poin 25-27) menjawab "siapa kamu?" — Policy menjawab "apa yang boleh kamu lakukan?"

**Pertanyaan yang dijawab Policy:**
- Bolehkah user ini melihat daftar buku? (`viewAny`)
- Bolehkah user ini membuat buku baru? (`create`)
- Bolehkah user ini mengedit buku ini? (`update`)
- Bolehkah user ini menghapus buku ini? (`delete`)

## Fungsi

- Memisahkan logika otorisasi dari controller
- Otorisasi per-resource: buku, anggota, peminjaman masing-masing punya policy sendiri
- Bisa dipakai di controller (`$this->authorize()`) dan Blade (`@can`)
- Policy `before()` untuk super admin yang bypass semua

## Cara Pengimplementasian

```bash
php artisan make:policy BukuPolicy --model=Buku
php artisan make:policy PeminjamanPolicy --model=Peminjaman
```

```php
<?php
// app/Policies/BukuPolicy.php

namespace App\Policies;

use App\Models\Anggota;
use App\Models\Buku;

class BukuPolicy
{
    // Super admin bypass semua
    public function before(Anggota $user, string $ability): bool|null
    {
        if ($user->role === 'super_admin') {
            return true; // izinkan semua
        }
        return null; // lanjut ke method spesifik
    }

    // Boleh lihat daftar?
    public function viewAny(?Anggota $user): bool
    {
        return true; // semua, termasuk yang belum login
    }

    // Boleh lihat detail?
    public function view(?Anggota $user, Buku $buku): bool
    {
        return true;
    }

    // Boleh tambah buku?
    public function create(Anggota $user): bool
    {
        return in_array($user->role, ['admin', 'pustakawan']);
    }

    // Boleh edit buku ini?
    public function update(Anggota $user, Buku $buku): bool
    {
        return in_array($user->role, ['admin', 'pustakawan']);
    }

    // Boleh hapus buku?
    public function delete(Anggota $user, Buku $buku): bool
    {
        return $user->role === 'admin'; // hanya admin
    }

    // Boleh restore soft-deleted?
    public function restore(Anggota $user, Buku $buku): bool
    {
        return $user->role === 'admin';
    }

    // Boleh force delete?
    public function forceDelete(Anggota $user, Buku $buku): bool
    {
        return $user->role === 'admin';
    }
}
```

```php
<?php
// Cara pakai di Controller

class BukuController extends Controller
{
    public function index(): View
    {
        // Tidak perlu authorize — semua boleh lihat
        return view('buku.index', ['buku' => Buku::paginate(12)]);
    }

    public function create(): View
    {
        $this->authorize('create', Buku::class);
        // Jika tidak berhak → abort(403)
        return view('buku.create');
    }

    public function update(UpdateBukuRequest $request, Buku $buku): RedirectResponse
    {
        $this->authorize('update', $buku);
        // Policy akan cek apakah USER INI boleh update BUKU INI
        $buku->update($request->validated());
        return redirect()->route('buku.show', $buku);
    }

    public function destroy(Buku $buku): RedirectResponse
    {
        $this->authorize('delete', $buku);
        $buku->delete();
        return redirect()->route('buku.index');
    }
}
```

```blade
{{-- Di Blade — @can dan @cannot --}}
@can('create', App\Models\Buku::class)
    <a href="{{ route('buku.create') }}">+ Tambah Buku</a>
@endcan

@can('update', $buku)
    <a href="{{ route('buku.edit', $buku) }}">Edit</a>
@endcan

@can('delete', $buku)
    <form action="{{ route('buku.destroy', $buku) }}" method="POST">
        @csrf @method('DELETE')
        <button onclick="return confirm('Yakin?')">Hapus</button>
    </form>
@endcan

{{-- Alternative: @unless --}}
@cannot('create', App\Models\Buku::class)
    <p>Anda tidak memiliki izin menambah buku.</p>
@endcannot
```

## Analogi

Policy seperti **aturan siapa yang boleh melakukan apa di perpustakaan**:

- **`viewAny` / `view`** = "Melihat buku" — SEMUA ORANG boleh, termasuk pengunjung yang belum daftar
- **`create`** = "Menambah buku baru" — hanya **pustakawan** dan **admin**
- **`update`** = "Memperbaiki data buku" — hanya **pustakawan** dan **admin**
- **`delete`** = "Menghapus buku" — hanya **admin** (pustakawan pun tidak boleh)
- **`before`** = **Kepala perpustakaan** — bisa melakukan apapun, aturan tidak berlaku untuknya

Tanpa Policy, otorisasi ditulis di dalam controller — bercampur dengan logika bisnis. Dengan Policy, aturan "siapa boleh apa" terpusat di satu tempat.

**Perbedaan Auth vs Policy:**
```
Auth: "Apakah kamu terdaftar sebagai anggota?" (login check)
Policy: "Apakah kamu diizinkan menghapus buku?" (permission check)
```

## Dipakai untuk Apa

- **Setiap resource CRUD** — siapa yang boleh create, update, delete
- **Otorisasi spesifik** — "apakah user ini pemilik data ini?" (misal: hanya pemilik pinjaman yang boleh batalkan)
- **Blade conditional UI** — sembunyikan tombol yang tidak berhak diakses user
- **API authorization** — cek izin sebelum memproses request API

## Kesalahan Umum

1. **Policy tidak terdaftar** — error "This action is unauthorized." atau policy tidak dipanggil
2. **Lupa null di `before()`** — harus return `null` jika bukan super admin, bukan `false` — karena `false` akan menolak semua aksi
3. **Policy di controller tapi tidak di Blade** — tombol "Edit" tetap muncul meski user tidak berhak → user coba akses URL manual → 403
4. **Salah parameter `authorize()`** — `create` pakai model class: `Buku::class`, `update/destroy` pakai instance: `$buku`
5. **`view` dan `viewAny` tertukar** — `viewAny` untuk daftar, `view` untuk detail
6. **Guard tidak sesuai** — jika pakai guard `admin`, policy harus dipanggil dengan `$this->authorize('create', Buku::class)` — otomatis pakai guard user yang login

## Koneksi dengan Materi Sebelumnya

Poin 25-27 (Auth) menentukan siapa user-nya. Policy melangkah lebih jauh: setelah tahu siapa user-nya, atur apa yang boleh dilakukan. Form Request (poin 24) bisa memanggil policy di method `authorize()`.

**Benang merah ke depan:**
- Poin 29 (Middleware Kustom): Middleware untuk role-based access, Policy untuk resource-based
- Poin 35 (Testing): Policy bisa di-test dengan `$this->assertTrue($user->can('create', Buku::class))`

## Soal Latihan

1. **Praktik**: Buat `PeminjamanPolicy` dengan method `create` (semua anggota aktif), `delete` (hanya admin), dan `before` (super admin bypass)!
2. **Praktik**: Di Blade, tampilkan tombol "Batalkan Peminjaman" hanya jika user adalah pemilik peminjaman!
3. **Analisis**: Apa perbedaan `$this->authorize('create', Buku::class)` dengan `$this->authorize('update', $buku)`? Kenapa berbeda parameternya?

3. **Perbedaan parameter:**
   - `create` → butuh **nama class** (`Buku::class`) karena belum ada instance tertentu
   - `update`, `delete` → butuh **instance** (`$buku`) karena aksi spesifik pada record tertentu
   - Method `authorize()` cerdas: jika parameter adalah class → panggil policy tanpa model; jika instance → dengan model
