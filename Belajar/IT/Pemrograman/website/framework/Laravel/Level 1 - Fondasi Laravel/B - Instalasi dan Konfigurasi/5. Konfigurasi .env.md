# 5. Konfigurasi .env — Environment yang Benar

## Penjelasan

File `.env` (environment) menyimpan konfigurasi yang berbeda-beda antar lingkungan (local, staging, production). Ini adalah **file paling sensitif** di project Laravel karena berisi kredensial database, API key, dan pengaturan penting lainnya.

**File `.env.example`** adalah template yang aman di-commit ke git. Developer tinggal meng-copy-nya menjadi `.env` dan menyesuaikan.

```bash
APP_NAME="Perpustakaan Digital"
APP_ENV=local            # local | staging | production
APP_KEY=base64:...       # Generate dengan: php artisan key:generate
APP_DEBUG=true           # TRUE di local, FALSE di production!
APP_URL=http://localhost:8000

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=perpustakaan_db
DB_USERNAME=root
DB_PASSWORD=

SESSION_DRIVER=file      # file | cookie | database | redis
CACHE_STORE=file         # file | redis | memcached
QUEUE_CONNECTION=sync    # sync | database | redis
```

## Fungsi

- Memisahkan konfigurasi per environment: berbeda laptop, server staging, dan production
- Menyimpan rahasia (API key, password DB) — tidak boleh di-commit ke git
- Mengubah perilaku aplikasi tanpa mengubah kode (misal: ganti database cukup edit `.env`)

## Cara Pengimplementasian

```bash
# 1. Setup setelah buat project
cp .env.example .env   # copy template

# 2. Generate APP_KEY — WAJIB!
php artisan key:generate
# APP_KEY adalah kunci enkripsi untuk session, cookie, dan data terenkripsi

# 3. Buat database
# Di MySQL:
# CREATE DATABASE perpustakaan_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

# 4. Edit .env sesuai environment
DB_DATABASE=perpustakaan_db
DB_USERNAME=root
DB_PASSWORD=yourpassword

# 5. Test koneksi
php artisan db:show

# 6. Untuk production, optimize:
php artisan config:cache   # gabung semua config jadi 1 file
```

**Cara akses konfigurasi di kode:**
```php
// config/app.php
return [
    'name' => env('APP_NAME', 'Laravel'),  // default: 'Laravel'
];

// Di controller/view:
$appName = config('app.name');
$dbName  = config('database.connections.mysql.database');
```

## Analogi

`.env` adalah **buku catatan rahasia pustakawan**:

- Berisi informasi penting: kombinasi brankas (DB password), kunci lemari (APP_KEY), jam buka (APP_URL)
- Di perpustakaan utama (local), bukunya ada di meja kerja pustakawan
- Di cabang (staging), bukanya sedikit berbeda (database berbeda)
- Di pusat (production), buku ini disimpan di brankas dan tidak boleh dibaca sembarangan

File `.env.example` adalah **buku template** — menunjukkan formatnya tapi tidak berisi data asli. Pustakawan baru tinggal mengisi sesuai kebutuhannya.

## Dipakai untuk Apa

- **Setiap project Laravel** — tanpa `.env` yang benar, aplikasi tidak bisa jalan dengan baik
- **Production**: `APP_DEBUG=false` agar error tidak bocor ke user
- **Berganti database**: cukup edit `DB_DATABASE`, tidak perlu ubah kode
- **Tim development**: setiap anggota tim punya `.env` sendiri

## Kesalahan Umum

1. **`.env` di-commit ke git** — BAHAYA! Password database dan API key bisa bocor. Laravel sudah otomatis menambahkan `.env` ke `.gitignore`
2. **`APP_KEY` tidak di-generate** — error enkripsi, session tidak berfungsi
3. **`APP_DEBUG=true` di production** — user bisa melihat error detail, path file, bahkan kredensial
4. **Cache config tidak di-clear** — jika mengubah `.env`, jalankan `php artisan config:clear`
5. **Nama database salah ketik** — migration akan gagal. Cek dengan `php artisan db:show`
6. **Menggunakan database SQLite tanpa file** — pastikan file database ada di `database/database.sqlite`

## Koneksi dengan Materi Sebelumnya

Poin 4 menjelaskan struktur direktori — `.env` ada di root project dan merupakan file konfigurasi paling penting. Tanpa konfigurasi `.env` yang benar, aplikasi dari poin 3 tidak bisa terhubung ke database.

**Benang merah ke depan:**
- Poin 6 (Artisan): `php artisan key:generate` dan `php artisan config:cache` adalah perintah yang berkaitan dengan `.env`
- Poin 18 (Migration): Migration membutuhkan koneksi database dari `.env`

## Soal Latihan

1. **Praktik**: Copy `.env.example` menjadi `.env`, generate APP_KEY, lalu atur koneksi database MySQL. Jalankan `php artisan db:show` — pastikan berhasil!
2. **Analisis**: Apa yang terjadi jika `APP_DEBUG=true` di production? Sebutkan 2 risiko!
3. **Pemecahan Masalah**: Setelah mengubah `DB_DATABASE` di `.env`, aplikasi masih pakai database lama. Mengapa?

   - **Eksploitasi**: attacker bisa mempelajari struktur kode dan mencari celah keamanan
