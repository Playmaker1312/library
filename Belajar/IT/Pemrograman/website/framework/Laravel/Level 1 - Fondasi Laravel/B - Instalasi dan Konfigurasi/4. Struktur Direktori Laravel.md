# 4. Struktur Direktori Laravel — Setiap Folder Ada Tujuannya

## Penjelasan

Setelah project dibuat, kamu akan melihat struktur folder yang sudah diatur. Setiap folder punya tujuan spesifik — ini bagian dari **Convention over Configuration** yang dibahas di poin 2.

```
perpustakaan/
├── app/                    ← KODE APLIKASI UTAMA (paling sering disentuh)
│   ├── Http/
│   │   ├── Controllers/    ← File controller
│   │   ├── Middleware/     ← Middleware (filter request)
│   │   └── Requests/       ← Form Request (validasi)
│   ├── Models/             ← Eloquent Model
│   └── Providers/          ← Service Provider
│
├── bootstrap/              ← Inisialisasi aplikasi (jarang disentuh)
├── config/                 ← File konfigurasi (.php)
├── database/               ← Database stuff
│   ├── migrations/         ← Struktur tabel
│   ├── seeders/            ← Data awal
│   └── factories/          ← Data palsu untuk testing
├── public/                 ← SATU-SATUNYA yang diakses web
│   └── index.php           ← Entry point
├── resources/              ← Frontend
│   ├── views/              ← Blade template
│   ├── css/                ← Source CSS
│   └── js/                 ← Source JS
├── routes/                 ← Definisi URL
│   ├── web.php             ← Route web (session, CSRF)
│   ├── api.php             ← Route API (stateless)
│   └── console.php         ← Route Artisan command
├── storage/                ← File generated app (log, cache, upload)
├── tests/                  ← Unit & Feature test
├── .env                    ← Konfigurasi environment (JANGAN di-commit!)
├── artisan                 ← CLI tool
└── composer.json           ← Dependency PHP
```

## Fungsi

- Memisahkan kode berdasarkan tanggung jawab (Separation of Concerns)
- Memudahkan navigasi: tahu persis di mana mencari file tertentu
- Mengamankan aplikasi: hanya folder `public/` yang bisa diakses dari web

## Cara Pengimplementasian

Tidak perlu membuat struktur — sudah ada sejak project dibuat. Yang perlu kamu lakukan adalah **menaruh file di tempat yang benar**:

```php
// BUAT file route → routes/web.php
Route::get('/buku', [BukuController::class, 'index']);

// BUAT controller → app/Http/Controllers/
class BukuController extends Controller { ... }

// BUAT model → app/Models/
class Buku extends Model { ... }

// BUAT view → resources/views/
// file: resources/views/buku/index.blade.php

// BUAT migration → database/migrations/
// php artisan make:migration create_buku_table

// JANGAN pernah taruh file PHP di public/
// Kecuali asset: CSS, JS, gambar
```

## Analogi

Perpustakaan juga punya struktur:

| Folder Laravel | Bagian Perpustakaan |
|----------------|-------------------|
| `routes/web.php` | **Papan informasi**: daftar semua ruangan dan cara menuju ke sana |
| `app/Controllers/` | **Meja sirkulasi**: petugas yang menangani permintaan pengunjung |
| `app/Models/` | **Kartu katalog**: representasi buku di database |
| `resources/views/` | **Ruang baca**: tampilan yang dilihat pengunjung |
| `database/migrations/` | **Cetak biru**: blueprint cara membangun rak buku |
| `public/` | **Pintu masuk**: satu-satunya akses ke perpustakaan |
| `.env` | **Buku rahasia**: password, koneksi database — tidak boleh dilihat pengunjung |

## Dipakai untuk Apa

- Menemukan file dengan cepat: "saya mau ubah tampilan → buka `resources/views/`"
- Debugging: "error di route → cek `routes/web.php`"
- Kolaborasi: developer lain langsung paham struktur tanpa perlu dijelaskan

## Kesalahan Umum

1. **Menaruh file di folder salah** — misal: meletakkan file view di folder `controllers/`
2. **Mengubah file di `bootstrap/` atau `vendor/`** — folder untuk framework, bukan untuk kode kamu
3. **Menaruh file `.env` di `public/`** — ini bocor! `.env` hanya di root project
4. **Membuat folder sendiri di `app/`** — boleh, tapi ikuti konvensi namespace
5. **Folder `vendor/` tidak di-commit ke git** — benar, itu dependency yang diinstall via composer

## Koneksi dengan Materi Sebelumnya

Poin 3 membuat project dengan struktur ini. Sekarang kamu tahu arti setiap foldernya. Pengetahuan ini penting untuk semua pembelajaran selanjutnya — karena setiap file yang kamu buat akan ditaruh di folder yang sudah ditentukan.

**Benang merah ke depan:**
- Poin 5 (.env): File konfigurasi yang paling penting di root project
- Poin 7 (Route): Kamu akan mulai menulis kode di `routes/web.php`

## Soal Latihan

1. **Tebakan**: Di folder mana kamu akan mencari file yang menangani request ke `/buku`?
2. **Praktik**: Buat project Laravel baru, lalu identifikasi isi folder `app/`, `routes/`, dan `resources/views/`. Catat file apa saja yang sudah ada!
3. **Analisis**: Mengapa `public/` adalah satu-satunya folder yang diekspos ke web? Apa yang terjadi jika folder `app/` bisa diakses langsung?

<details>
<summary>Jawaban</summary>

1. **File controller** ada di `app/Http/Controllers/`, **definisi route** ada di `routes/web.php`.

2. Isi folder:
   - `app/` — berisi `Http/Controllers/Controller.php`, `Models/User.php`, `Providers/` (beberapa file provider)
   - `routes/` — berisi `web.php`, `api.php`, `console.php`, `channels.php` (tergantung versi)
   - `resources/views/` — berisi `welcome.blade.php`

3. **Mengapa hanya `public/` yang diekspos:**
   - Keamanan: file PHP di `app/`, `config/`, `.env` mengandung logika bisnis dan kredensial
   - Web server hanya perlu menyajikan `index.php` yang kemudian memuat sisanya
   - Jika `app/` bisa diakses langsung, attacker bisa membaca kode sumber dan mencari celah keamanan
</details>
