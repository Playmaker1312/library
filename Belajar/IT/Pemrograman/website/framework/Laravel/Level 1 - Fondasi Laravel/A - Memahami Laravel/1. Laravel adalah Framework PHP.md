# 1. Laravel adalah Framework PHP — Bukan Magic, tapi Struktur

## Penjelasan

Laravel bukan bahasa pemrograman baru — ini adalah **framework PHP** yang menambahkan struktur, keamanan, dan kemudahan di atas PHP murni. Framework artinya kerangka kerja: kamu tidak perlu memulai dari nol, tinggal mengisi bagian yang kosong.

Perbandingan PHP Murni vs Laravel:

| PHP Murni | Laravel |
|-----------|---------|
| `switch(\$_GET['page'])` untuk routing | `Route::get('/buku', ...)` |
| `\$_POST['judul']` manual | `\$request->input('judul')` |
| `echo json_encode(\$data)` | `response()->json(\$data)` |
| `include('header.php')` manual | `@extends('layouts.app')` |
| `session_start(); \$_SESSION['user']` | `session(['user' => ...])` |

**Alur Request di Laravel:**
```
Browser → public/index.php → bootstrap/app.php → Kernel → Route → Middleware → Controller → Response
```
Ini adalah alur hidup (lifecycle) yang wajib dipahami. Semua request masuk melalui `index.php`, lalu diproses melalui pipeline hingga menghasilkan response.

## Fungsi

- Memberikan struktur standar untuk aplikasi PHP agar kode lebih rapi, aman, dan mudah dipelihara
- Menyediakan komponen siap pakai (routing, database, autentikasi) sehingga developer tidak perlu membuat dari nol
- Memisahkan logika aplikasi ke layer yang jelas (Route → Controller → View)

## Cara Pengimplementasian

Buka file `public/index.php` di project Laravel:

```php
<?php
// public/index.php — ini SATU-SATUNYA file yang diakses web server

use Illuminate\Http\Request;

define('LARAVEL_START', microtime(true));

// Autoload composer
require __DIR__.'/../vendor/autoload.php';

// Bootstrap aplikasi
$app = require_once __DIR__.'/../bootstrap/app.php';

// Handle request dan kirim response
$kernel = $app->make(Kernel::class);
$response = $kernel->handle(
    Request::capture()
)->send();

$kernel->terminate($request, $response);
```

Beginilah sederhananya entry point Laravel. Semua kompleksitas ada di balik layar — kamu tinggal fokus pada routes, controllers, dan views.

## Analogi

Bayangkan perpustakaan:

- **PHP Murni** seperti membangun perpustakaan dari tumpukan batu bata — kamu harus membuat semuanya sendiri: rak buku, meja sirkulasi, sistem peminjaman, kartu katalog.
- **Laravel** seperti membeli paket perpustakaan lengkap yang sudah memiliki rak standar, meja yang sudah dirakit, sistem komputer, dan kartu anggota yang siap cetak. Kamu tinggal mengisi rak dengan buku dan menyesuaikan dekorasi.

**Public/index.php** adalah **pintu masuk utama** perpustakaan. Semua pengunjung (request) harus masuk lewat pintu ini, lalu petugas keamanan (Kernel) akan mengarahkan mereka ke bagian yang tepat (Route).

## Dipakai untuk Apa

Setiap aplikasi Laravel membutuhkan pemahaman ini karena:
- Semua request melewati `index.php` — jika ada error aneh, cek dulu file ini
- Memahami lifecycle membantu debugging: di titik mana request gagal?
- Menjelaskan mengapa file di `public/` bisa diakses langsung, tapi file di `app/` tidak

## Kesalahan Umum

1. **Menganggap Laravel adalah bahasa baru** — Laravel tetap PHP; semua fungsi PHP tetap bisa dipakai
2. **Menaruh file sembarangan di `public/`** — folder ini hanya untuk `index.php` dan asset (CSS, JS, gambar)
3. **Mengubah `index.php` tanpa paham** — file ini jarang disentuh; jika ada error, biasanya di tempat lain
4. **Menghapus `vendor/` atau `bootstrap/cache/`** — folder ini penting; jalankan `composer install` jika terhapus
