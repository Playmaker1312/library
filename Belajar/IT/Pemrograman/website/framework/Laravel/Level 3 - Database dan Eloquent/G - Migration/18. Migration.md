# 18. Migration — Definisikan Struktur Tabel

## Penjelasan

**Migration** adalah version control untuk database. Setiap perubahan struktur tabel (buat, ubah, hapus) ditulis dalam file migration yang bisa dijalankan (`php artisan migrate`) dan di-rollback (`php artisan rollback`).

Tanpa migration, tim harus saling kirim SQL manual — "tambah kolom ini di tabel itu". Dengan migration, semua orang tinggal `php artisan migrate` dan struktur database selalu sinkron.

Migration terdiri dari dua method:
- **`up()`** — perubahan yang dilakukan (CREATE TABLE, ADD COLUMN)
- **`down()`** — kebalikan dari `up()` (DROP TABLE, DROP COLUMN)

## Fungsi

- Version control untuk struktur database
- Sinkronisasi struktur antar developer dan environment
- Rollback jika ada kesalahan
- Dokumentasi otomatis tentang struktur tabel

## Cara Pengimplementasian

```bash
php artisan make:migration create_buku_table
php artisan make:migration create_anggota_table
php artisan make:migration create_peminjaman_table
php artisan make:migration add_deskripsi_to_buku_table  # modifikasi
```

```php
<?php
// database/migrations/xxxx_xx_xx_000001_create_buku_table.php

use Illuminate\Database\Migrations\Migration;
use Illuminate\Database\Schema\Blueprint;
use Illuminate\Support\Facades\Schema;

return new class extends Migration
{
    public function up(): void
    {
        Schema::create('buku', function (Blueprint $table) {
            $table->id();                          // BIGINT AUTO_INCREMENT PK
            $table->string('judul', 200);
            $table->string('pengarang', 100);
            $table->char('isbn', 13)->unique()->nullable();
            $table->string('penerbit', 100)->nullable();
            $table->year('tahun');
            $table->decimal('harga', 12, 2)->default(0);
            $table->unsignedInteger('stok')->default(0);
            $table->string('kategori', 50)->default('Umum');
            $table->text('deskripsi')->nullable();
            $table->string('sampul')->nullable();
            $table->timestamps();                  // created_at + updated_at
            $table->softDeletes();                 // deleted_at untuk soft delete
            $table->index('kategori');
        });
    }

    public function down(): void
    {
        Schema::dropIfExists('buku');
    }
};
```

```php
<?php
// Migration dengan foreign key
Schema::create('peminjaman', function (Blueprint $table) {
    $table->id();
    $table->foreignId('buku_id')
          ->constrained('buku')           // FK ke tabel buku
          ->cascadeOnUpdate()
          ->restrictOnDelete();           // tidak bisa hapus buku yang masih dipinjam
    $table->foreignId('anggota_id')
          ->constrained('anggota')
          ->cascadeOnUpdate()
          ->restrictOnDelete();
    $table->date('tanggal_pinjam');
    $table->date('batas_kembali');
    $table->date('tanggal_kembali')->nullable();
    $table->decimal('denda', 10, 2)->default(0);
    $table->enum('status', ['dipinjam', 'dikembalikan', 'terlambat'])->default('dipinjam');
    $table->timestamps();
    $table->index(['anggota_id', 'status']);
});
```

```bash
# Perintah migration
php artisan migrate               # jalankan semua yang belum dijalankan
php artisan migrate:status        # lihat status (run/pending)
php artisan migrate:rollback      # rollback batch terakhir
php artisan migrate:fresh         # drop semua + migrate ulang
php artisan migrate:fresh --seed  # reset + isi data
```

## Analogi

Migration seperti **cetak biru (blueprint) perpustakaan**:

- **`up()`** = "Bangun rak buku di sini" — instruksi untuk membangun
- **`down()`** = "Bongkar rak buku itu" — instruksi untuk membongkar
- **`php artisan migrate`** = "Jalankan semua cetak biru yang belum dikerjakan"
- **`php artisan migrate:rollback`** = "Bongkar pekerjaan terakhir"

Bayangkan tim konstruksi perpustakaan:
- Arsitek (developer A) membuat cetak biru rak buku (migration A)
- Arsitek lain (developer B) membuat cetak biru meja sirkulasi (migration B)
- Keduanya menjalankan `php artisan migrate` — rak buku dan meja sirkulasi terbangun bersamaan
- Jika ada error, `php artisan migrate:rollback` membongkar pekerjaan terakhir

Tanpa migration: developer A kirim SQL "CREATE TABLE buku..." ke group chat. Developer B harus copy-paste manual. Jika lupa, tabel tidak terbentuk. Kacau.

## Dipakai untuk Apa

- **Setiap perubahan struktur database** — tabel baru, kolom baru, index baru
- **Setiap project Laravel** — migration adalah standar, bukan opsional
- **Tim development** — sinkronisasi struktur antar anggota tim
- **Deployment** — struktur database otomatis terupdate saat deploy

## Kesalahan Umum

1. **Mengedit migration yang sudah dijalankan** — jangan! Buat migration baru untuk perubahan. Migration yang sudah dijalankan dianggap final.
2. **Lupa method `down()`** — jika `down()` tidak diisi, rollback tidak bisa dilakukan
3. **Menggunakan tipe data yang tidak tepat** — misal: `string` untuk `isbn` yang seharusnya `char(13)`
4. **Tidak menambahkan index untuk kolom yang sering di-query** — performa lambat
5. **Lupa `->nullable()` untuk kolom opsional** — error "field cannot be null"
6. **Migration tanpa foreign key constraint** — integritas data tidak terjamin

## Koneksi dengan Materi Sebelumnya

Poin 1-17: Semua data masih hardcode di array. Mulai Level 3, data akan disimpan di database. Migration adalah langkah pertama — membuat struktur tabel tempat data akan disimpan.

**Benang merah ke depan:**
- Poin 19 (Seeder & Factory): Mengisi tabel dengan data awal
- Poin 20 (Eloquent Model): Model membaca dari tabel yang dibuat migration

1. **Praktik**: Buat migration `create_kategoris_table` dengan kolom: `id`, `nama` (string 50), `slug` (string 50 unique), `deskripsi` (text nullable), dan timestamps!
2. **Analisis**: Mengapa migration lebih baik daripada menjalankan SQL manual di phpMyAdmin?
3. **Praktik**: Jalankan `php artisan migrate` lalu `php artisan migrate:rollback` — amati perubahan di database setelah setiap perintah!
