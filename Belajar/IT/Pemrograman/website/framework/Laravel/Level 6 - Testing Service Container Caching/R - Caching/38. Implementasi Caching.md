# 38. Implementasi Caching yang Strategis

## Penjelasan

**Caching** menyimpan hasil komputasi yang berat agar tidak perlu dihitung ulang setiap ada request. Cache disimpan di memory (Redis) atau file.

**Kapan perlu cache:**
- Query database yang berat (COUNT, SUM, JOIN banyak tabel)
- Data yang jarang berubah (kategori, daftar buku)
- Halaman yang sama dikunjungi banyak orang
- Hasil komputasi API eksternal

**Cache Drivers:**
| Driver | Kecepatan | Keterangan |
|--------|-----------|------------|
| `file` | Lambat | Default, simpan di `storage/framework/cache/` |
| `database` | Sedang | Simpan di tabel MySQL |
| `redis` | Cepat | In-memory, untuk production |
| `memcached` | Cepat | Alternatif Redis |

## Fungsi

- Mempercepat response — data dari memory, bukan database
- Mengurangi beban database — query berat di-cache
- Mengurangi biaya server — server bisa lebih kecil karena beban ringan
- Atomic lock — mencegah race condition pada operasi kritis

## Cara Pengimplementasian

```php
<?php
// app/Http/Controllers/BukuController.php

use Illuminate\Support\Facades\Cache;

class BukuController extends Controller
{
    public function index(Request $request): View
    {
        // Cache key unik per kombinasi parameter
        $key = 'buku.index.' . md5(json_encode($request->query()));

        // remember: ambil dari cache atau simpan hasil closure
        $buku = Cache::remember($key, now()->addMinutes(5), function () use ($request) {
            return Buku::query()
                ->when($request->filled('kategori'), fn($q) => $q->kategori($request->kategori))
                ->when($request->filled('cari'), fn($q) => $q->pencarian($request->cari))
                ->paginate(12);
        });

        return view('buku.index', compact('buku'));
    }

    // ─── INVALIDATE CACHE SAAT DATA BERUBAH ──────────────
    public function store(StoreBukuRequest $request): RedirectResponse
    {
        $buku = Buku::create($request->validated());

        // Metode 1: Hapus cache spesifik
        Cache::forget('buku.index.*');

        // Metode 2: Tags (butuh Redis/Memcached)
        // Cache::tags(['buku'])->flush();

        return redirect()->route('buku.show', $buku);
    }
}
```

```php
<?php
// ─── ATOMIC LOCK — Cegah Race Condition ───────────────

use Illuminate\Support\Facades\Cache;

public function pinjamBuku(int $bukuId, int $anggotaId): Peminjaman
{
    $lock = Cache::lock("pinjam.buku.{$bukuId}", 10); // lock 10 detik

    if (!$lock->get()) {
        throw new \RuntimeException('Permintaan sedang diproses. Coba lagi.');
    }

    try {
        $buku = Buku::lockForUpdate()->findOrFail($bukuId);

        if ($buku->stok < 1) {
            throw new \DomainException('Buku tidak tersedia.');
        }

        $buku->decrement('stok');

        return Peminjaman::create([
            'buku_id'    => $bukuId,
            'anggota_id' => $anggotaId,
            'tanggal_pinjam' => now(),
            'batas_kembali'  => now()->addDays(14),
        ]);
    } finally {
        $lock->release(); // selalu release lock
    }
}
```

## Analogi

Cache seperti **meja depan perpustakaan yang menyimpan buku-buku populer**:

- **Cache `remember`** = Pustakawan menyimpan buku-buku yang sering dipinjam di meja depan. Kalau ada yang minta, langsung ambil dari meja (cepat). Kalau tidak ada, baru ambil dari rak (lambat) dan simpan di meja untuk permintaan berikutnya.
- **TTL (Time To Live)** = Setiap 5 menit, buku di meja depan dikembalikan ke rak — supaya data tidak basi.
- **Cache invalidation** = Jika ada buku baru masuk, buku di meja depan yang sudah lama dikembalikan ke rak — biar yang baru yang dipajang.
- **Atomic lock** = Sistem peminjaman: dua orang tidak bisa meminjam buku yang sama di waktu bersamaan. Lock memastikan hanya satu yang selesai duluan.

**Tanpa cache:**
```
Setiap pengunjung → ambil dari rak → 2 detik
1000 pengunjung → 2000 detik beban total
```

**Dengan cache:**
```
Pengunjung pertama → ambil dari rak → 2 detik → simpan di meja
Pengunjung 2-1000 → ambil dari meja → 0.1 detik
Hemat: 1900 detik!
```

## Dipakai untuk Apa

- **Halaman daftar** — katalog buku, daftar anggota (jarang berubah)
- **Dashboard statistik** — hitungan yang berat
- **Menu navigasi** — kategori, daftar menu (hampir tidak pernah berubah)
- **Operasi kritis** — lock untuk mencegah double booking
- **API response** — cache response JSON untuk endpoint publik

## Kesalahan Umum

1. **Cache terlalu lama** — data basi. TTL sesuai frekuensi perubahan data
2. **Cache tidak di-invalidate** — data berubah tapi cache tidak dihapus → user lihat data lama
3. **Cache key tidak unik** — filter berbeda dapat cache yang sama. Sertakan parameter di key
4. **Cache untuk data real-time** — stok buku yang sering berubah jangan di-cache lama
5. **Lock tidak di-release** — deadlock! Selalu release di `finally` block
6. **Cache driver `file` di production** — lambat. Gunakan `redis` untuk production
