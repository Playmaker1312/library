# 36. Unit Test dan Mocking

## Penjelasan

**Unit Test** menguji satu unit kode secara terisolasi — biasanya satu method, tanpa melibatkan database, HTTP, atau dependency eksternal. Berbeda dengan Feature Test (poin 35) yang menguji alur lengkap.

**Mocking** adalah teknik mengganti dependency asli dengan versi palsu yang bisa dikontrol — berguna untuk mengisolasi kode yang diuji.

**Perbedaan Feature vs Unit Test:**
| Feature Test | Unit Test |
|-------------|-----------|
| Menguji alur lengkap | Menguji satu method |
| Butuh database | Tidak butuh database |
| Lebih lambat | Sangat cepat |
| PHPUnit + Laravel | PHPUnit murni |
| `Tests\Feature` | `Tests\Unit` |
| `RefreshDatabase` | Mocking |

## Fungsi

- Menguji logika bisnis murni tanpa interaksi eksternal
- Mendeteksi bug di level terkecil
- Menjaga kualitas method/class individual
- Mocking mengisolasi unit test dari dependency

## Cara Pengimplementasian

```php
<?php
// tests/Unit/BukuTest.php

namespace Tests\Unit;

use App\Models\Buku;
use PHPUnit\Framework\TestCase;

class BukuTest extends TestCase
{
    // Unit test: tidak perlu database, test logika murni
    public function test_buku_tersedia_jika_stok_lebih_dari_nol(): void
    {
        $buku = new Buku();
        $buku->stok = 5;

        $this->assertTrue($buku->tersedia());
    }

    public function test_buku_tidak_tersedia_jika_stok_nol(): void
    {
        $buku = new Buku();
        $buku->stok = 0;

        $this->assertFalse($buku->tersedia());
    }

    // Data provider — test satu method dengan berbagai input
    /** @dataProvider providerHarga */
    public function test_format_harga(int $harga, string $expected): void
    {
        $buku = new Buku();
        $buku->harga = $harga;

        $this->assertEquals($expected, $buku->harga_format);
    }

    public static function providerHarga(): array
    {
        return [
            'nol'    => [0,       'Rp 0'],
            'ribuan' => [1000,    'Rp 1.000'],
            'jutaan' => [1500000, 'Rp 1.500.000'],
        ];
    }
}

// ─── MOCKING ────────────────────────────────────────────

// tests/Unit/Services/PeminjamanServiceTest.php
class PeminjamanServiceTest extends TestCase
{
    public function test_tidak_bisa_pinjam_jika_stok_habis(): void
    {
        // Mock BukuRepository — kendalikan return value
        $bukuRepo = $this->createMock(BukuRepositoryInterface::class);
        $bukuRepo->method('findById')
                 ->with(1)
                 ->willReturn(new Buku(['id' => 1, 'stok' => 0]));

        $service = new PeminjamanService(
            $bukuRepo,
            $this->createMock(AnggotaRepositoryInterface::class),
        );

        $this->expectException(\DomainException::class);
        $this->expectExceptionMessage('Buku tidak tersedia');

        $service->pinjamBuku(bukuId: 1, anggotaId: 1);
    }

    public function test_berhasil_pinjam_buku(): void
    {
        // Mock
        $bukuRepo = $this->createMock(BukuRepositoryInterface::class);
        $bukuRepo->method('findById')
                 ->willReturn(new Buku(['id' => 1, 'stok' => 5]));

        $anggotaRepo = $this->createMock(AnggotaRepositoryInterface::class);
        $anggotaRepo->method('findById')
                    ->willReturn(new Anggota(['id' => 1, 'status' => 'aktif']));

        $peminjamanRepo = $this->createMock(PeminjamanRepositoryInterface::class);
        $peminjamanRepo->method('create')
                       ->willReturn(new Peminjaman(['id' => 1]));

        $service = new PeminjamanService($bukuRepo, $anggotaRepo, $peminjamanRepo);

        $result = $service->pinjamBuku(bukuId: 1, anggotaId: 1);

        $this->assertInstanceOf(Peminjaman::class, $result);
    }
}

// ─── MOCKING DI FEATURE TEST ────────────────────────────

// tests/Feature/PeminjamanTest.php
class PeminjamanTest extends TestCase
{
    use RefreshDatabase;

    public function test_pinjam_buku_dispatch_event(): void
    {
        // Fake: event tidak benar-benar di-dispatch
        Event::fake();

        $buku    = Buku::factory()->create(['stok' => 5]);
        $anggota = Anggota::factory()->create(['status' => 'aktif']);

        $this->actingAs($anggota)
             ->post(route('pinjam.store'), ['buku_id' => $buku->id]);

        // Assert: pastikan event di-dispatch
        Event::assertDispatched(BukuDipinjam::class);
    }

    public function test_pinjam_buku_dispatch_job(): void
    {
        // Fake: job tidak benar-benar jalan
        Queue::fake();

        // ...lakukan peminjaman...

        Queue::assertPushed(KirimEmailKonfirmasi::class);
    }

    public function test_kirim_email_setelah_pinjam(): void
    {
        // Fake: email tidak benar-benar terkirim
        Mail::fake();

        // ...lakukan peminjaman...

        Mail::assertSent(KonfirmasiPeminjamanMail::class);
    }
}
```

## Analogi

Unit test seperti **menguji alat-alat di perpustakaan secara terpisah**:

- **Feature test** = Uji coba sistem peminjaman lengkap: anggota datang → pinjam buku → dapat email
- **Unit test** = Uji satu fungsi stempel: "Apakah stempel 'Tersedia' mencetak dengan benar?" — tidak perlu anggota, buku, atau email

**Mocking** = Menggunakan **stempel palsu** untuk menguji, bukan asli:
- "Saya mau uji prosedur peminjaman — tapi belum punya stempel asli. Pakai stempel palsu dulu yang hasilnya bisa saya atur."
- Mock `BukuRepository` = Stempel palsu yang selalu mengembalikan "buku dengan stok 5"

**Tanpa Mock:**
```php
$service = new PeminjamanService(new EloquentBukuRepository(), ...);
// Test ini akan akses DATABASE ASLI — lambat, tergantung data
```

**Dengan Mock:**
```php
$bukuRepo = $this->createMock(BukuRepositoryInterface::class);
$bukuRepo->method('findById')->willReturn(new Buku(['stok' => 5]));
// Test cepat, tidak akses database, hasil bisa diatur
```

## Dipakai untuk Apa

- **Unit test untuk model** — test accessor, scope, method helper
- **Unit test untuk service/action class** — test business logic
- **Mocking dependency** — repository, API eksternal, mail, queue
- **Fake untuk Event, Mail, Queue, Notification** — pastikan dispatch tanpa benar-benar kirim

## Kesalahan Umum

1. **Unit test mengakses database** — gunakan mocking. Unit test harus cepat (ms), bukan detik
2. **Mock terlalu kompleks** — jika mock setup 20 baris, mungkin ada masalah desain
3. **Lupa `use RefreshDatabase` di Feature Test** — data test bercampur
4. **Test method terlalu panjang** — >20 baris → mungkin perlu dipisah
5. **Tidak menggunakan data provider** — copy-paste test untuk input berbeda
6. **Mock method yang tidak dipanggil** — test tetap hijau meski implementasi berubah

## Koneksi dengan Materi Sebelumnya

Poin 35 (Feature Test) menguji alur lengkap. Unit test menguji method spesifik. Poin 37 (Service Container) DI memudahkan mocking — interface bisa di-swap dengan mock.

**Benang merah ke depan:**
- Poin 37 (Service Container): DI memudahkan mocking via interface binding
- Poin 41 (CI/CD): Unit test berjalan cepat di pipeline

## Soal Latihan

1. **Praktik**: Buat unit test untuk method `tersedia()` di model Buku! Test stok > 0 → true, stok 0 → false!
2. **Praktik**: Mock `BukuRepository` untuk test service method tanpa database!
3. **Analisis**: Kapan menggunakan Feature Test dan kapan menggunakan Unit Test? (Jawab dengan kriteria yang jelas!)

   public function test_tersedia_kembalikan_true_jika_stok_positif(): void

2. **Mock repository:**
   ```php
   $bukuRepo = $this->createMock(BukuRepositoryInterface::class);
   $bukuRepo->expects($this->once())
            ->method('findById')
            ->with(1)
            ->willReturn(new Buku(['id' => 1, 'stok' => 5]));

   $service = new PeminjamanService($bukuRepo, ...);
   ```

3. **Kriteria pemilihan:**
   - **Feature Test** — menguji alur lengkap (route → controller → response → database). Butuh database. Lebih lambat. Cocok untuk: CRUD, autentikasi, API endpoint.
   - **Unit Test** — menguji satu method/class secara terisolasi. Tanpa database. Sangat cepat. Cocok untuk: accessor, scope, service method, business logic.
   - **Rekomendasi**: Feature Test untuk mayoritas (mirip user), Unit Test untuk logika kompleks.
