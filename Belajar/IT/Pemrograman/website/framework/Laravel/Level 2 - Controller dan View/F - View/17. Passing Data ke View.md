# 17. Passing Data ke View — Cara yang Tepat

## Penjelasan

Setelah controller mengolah data, hasilnya perlu dikirim ke view untuk ditampilkan. Ada beberapa cara untuk mengirim data dari controller ke Blade view.

Tiga cara utama:
1. **Array (eksplisit, recommended)** — `return view('buku.index', ['buku' => $buku]);`
2. **compact()** — dari nama variabel
3. **with() chaining** — `return view('buku.index')->with('buku', $buku);`

Selain dari controller, data juga bisa di-share ke semua view melalui **View::share** atau **View::composer**.

## Fungsi

- Mengirim data dari controller/logika ke template untuk ditampilkan
- Membatasi data yang dikirim — hanya kirim yang diperlukan view
- Menyediakan data global (seperti nama aplikasi) ke semua view

## Cara Pengimplementasian

```php
<?php
class BukuController extends Controller
{
    public function index(): View
    {
        $buku     = Buku::all();
        $kategori = ['Teknologi', 'Fiksi', 'Sains'];
        $jumlah   = count($buku);

        // Cara 1: Array literal (paling eksplisit — recommended)
        return view('buku.index', [
            'buku'     => $buku,
            'kategori' => $kategori,
            'jumlah'   => $jumlah,
        ]);

        // Cara 2: compact()
        return view('buku.index', compact('buku', 'kategori', 'jumlah'));

        // Cara 3: with() chaining
        return view('buku.index')
            ->with('buku', $buku)
            ->with('kategori', $kategori)
            ->with('jumlah', $jumlah);
    }
}
```

**Data Global — View::share dan View::composer:**
```php
<?php
// app/Providers/AppServiceProvider.php

use Illuminate\Support\Facades\View;

public function boot(): void
{
    // Tersedia di SEMUA view
    View::share('namaApp', config('app.name'));
    View::share('tahunSekarang', date('Y'));

    // View composer — hanya untuk view tertentu
    View::composer('layouts.app', function ($view) {
        $view->with('kategoriNav', Kategori::all());
    });

    // Composer untuk beberapa view sekaligus
    View::composer(['buku.index', 'buku.show'], function ($view) {
        $view->with('popularTags', Tag::popular());
    });

    // Class-based composer
    View::composer('layouts.app', KategoriComposer::class);
}
```

```php
<?php
// app/View/Composers/KategoriComposer.php
namespace App\View\Composers;

use App\Models\Kategori;
use Illuminate\View\View;

class KategoriComposer
{
    public function compose(View $view): void
    {
        $view->with('kategoriNav', Kategori::all());
    }
}
```

```blade
{{-- Di view — akses data yang dikirim dari controller --}}
<h1>{{ $judul }}</h1>
<p>Total: {{ $jumlah }} buku</p>

{{-- Data global dari View::share --}}
<footer>&copy; {{ $tahunSekarang }} {{ $namaApp }}</footer>
```

## Analogi

Passing data ke view seperti **petugas menyiapkan buku untuk dibaca**:

- Controller = **Petugas perpustakaan** yang mengambil buku dari rak
- View = **Ruang baca** tempat pengunjung melihat buku
- Data = **Buku-buku** yang dibawa ke ruang baca

**Cara 1 (array literal):** Petugas meletakkan buku di meja satu per satu: "Ini buku A, ini buku B, ini catatan kategori" — jelas dan rapi.

**Cara 2 (compact):** Petugas membawa setumpuk buku: "Ini buku-bukunya" — praktis tapi kurang jelas isinya.

**Cara 3 (with chaining):** Petugas membawa buku satu per satu: "Pertama buku, lalu kategori, lalu jumlah" — panjang.

**View::share:** Seperti papan pengumuman yang dipasang di seluruh ruang baca — "Jam buka: 08.00-16.00" — sekali pasang, semua ruangan melihat.

## Dipakai untuk Apa

- **Setiap method controller yang mengembalikan view** — data harus dikirim
- **Data global** — seperti nama aplikasi, tahun, atau menu navigasi
- **Data spesifik halaman** — seperti daftar buku, detail buku, profil user

## Kesalahan Umum

1. **Mengirim terlalu banyak data** — `return view('buku.index', $data->toArray())` — kirim SEMUA kolom padahal view hanya butuh 3 kolom
2. **Nama variabel di view tidak sesuai** — controller kirim `$buku` tapi view panggil `$data`
3. **Lupa mengirim data yang dibutuhkan view** — view panggil `$buku` tapi controller tidak mengirimnya → error undefined variable
4. **Menggunakan compact dengan variabel yang tidak ada** — `compact('buku', 'tidakAda')` → error
5. **Data global menimpa data lokal** — jika View::share mengirim `$judul` dan controller juga mengirim `$judul`, data controller yang menang

## Koneksi dengan Materi Sebelumnya

Poin 14-16 membahas controller dan request. Setelah controller mengolah data (filter, query), data tersebut dikirim ke view (poin 11-13) untuk ditampilkan. Ini melengkapi alur Route → Controller → View.

**Benang merah ke depan:**
- Poin 18 (Migration): Data hardcode → database. Tapi cara passing data ke view tetap sama.
- Poin 20 (Eloquent): Data dari Eloquen dikirim dengan cara yang sama ke view

## Soal Latihan

1. **Praktik**: Di method `index`, ambil data buku (hardcode), hitung jumlahnya, lalu kirim ke view menggunakan array literal!
2. **Praktik**: Di `AppServiceProvider`, share `$namaAplikasi` ke semua view menggunakan View::share!
3. **Analisis**: Kapan sebaiknya menggunakan View::share vs mengirim data langsung dari controller?

   - Jangan paksa View::share untuk data spesifik — itu akan dikirim ke halaman yang tidak butuh
