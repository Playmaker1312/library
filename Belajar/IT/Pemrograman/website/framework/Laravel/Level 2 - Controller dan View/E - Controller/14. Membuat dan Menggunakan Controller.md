# 14. Membuat dan Menggunakan Controller

## Penjelasan

**Controller** adalah class yang mengelompokkan logika penanganan request untuk resource tertentu. Sebelumnya (Level 1), semua logika ditulis sebagai closure di file route. Controller memindahkan logika tersebut ke class terpisah — lebih rapi, terorganisir, dan testable.

```bash
# Buat resource controller (7 method CRUD)
php artisan make:controller BukuController --resource

# Buat single-action controller
php artisan make:controller LandingController --invokable
```

**Resource Controller — 7 method standar:**
| Method | Route | Fungsi |
|--------|-------|--------|
| `index()` | GET /buku | Menampilkan daftar |
| `create()` | GET /buku/create | Form tambah |
| `store()` | POST /buku | Simpan data baru |
| `show($id)` | GET /buku/{id} | Detail satu item |
| `edit($id)` | GET /buku/{id}/edit | Form edit |
| `update($id)` | PUT /buku/{id} | Update data |
| `destroy($id)` | DELETE /buku/{id} | Hapus data |

## Fungsi

- Memisahkan logika aplikasi dari definisi route (separation of concerns)
- Mengelompokkan method yang terkait dengan resource yang sama
- Membuat kode lebih terorganisir, testable, dan mudah dipelihara

## Cara Pengimplementasian

```php
<?php
// app/Http/Controllers/BukuController.php

namespace App\Http\Controllers;

use Illuminate\Http\Request;
use Illuminate\View\View;

class BukuController extends Controller
{
    // Data sementara (hardcode) — nanti diganti database (Level 3)
    private array $katalog = [
        ['id' => 1, 'judul' => 'Clean Code', 'pengarang' => 'Robert Martin',
         'tahun' => 2008, 'harga' => 150000, 'stok' => 5, 'kategori' => 'Teknologi'],
        ['id' => 2, 'judul' => 'Laskar Pelangi', 'pengarang' => 'Andrea Hirata',
         'tahun' => 2005, 'harga' => 95000, 'stok' => 0, 'kategori' => 'Fiksi'],
    ];

    public function index(): View
    {
        return view('buku.index', ['buku' => $this->katalog]);
    }

    public function show(string $id): View
    {
        $buku = collect($this->katalog)->firstWhere('id', (int) $id);
        abort_if(!$buku, 404, 'Buku tidak ditemukan');
        return view('buku.show', compact('buku'));
    }

    public function create(): View
    {
        return view('buku.create', [
            'kategori' => ['Teknologi', 'Fiksi', 'Sains', 'Sejarah']
        ]);
    }
}
```

```php
<?php
// routes/web.php — panggil controller

use App\Http\Controllers\BukuController;

Route::get('/buku', [BukuController::class, 'index'])->name('buku.index');
Route::get('/buku/{id}', [BukuController::class, 'show'])->name('buku.show');
Route::get('/buku/tambah', [BukuController::class, 'create'])->name('buku.create');

// Atau dengan resource route (lebih ringkas):
Route::resource('buku', BukuController::class);
```

## Analogi

Controller seperti **meja sirkulasi perpustakaan**:

```
Meja Sirkulasi (BukuController)
├── index()   → "Tolong tunjukkan daftar semua buku" → petugas ambilkan daftar
├── show($id) → "Tolong ambilkan buku ID 5" → petugas ke rak 5
├── create()  → "Saya mau menambahkan buku baru" → petugas berikan formulir
├── store()   → "Ini data buku barunya" → petugas simpan di database
├── edit($id) → "Saya mau mengubah buku ID 5" → petugas berikan formulir edit
├── update($id) → "Ini data perbaikannya" → petugas update di database
└── destroy($id) → "Saya mau hapus buku ID 5" → petugas hapus dari database
```

Sebelum ada controller (poin 7), semua logika ditulis di **papan informasi** (file route). Itu masih ok untuk 2-3 route. Tapi jika ada 20+ route, papan informasi akan penuh sesak. Controller memindahkan logika ke meja sirkulasi — route hanya tinggal menunjukkan arah.

Dari segi analogi perpustakaan:
- Tanpa controller: semua petugas kerja di pintu masuk (route). Macet.
- Dengan controller: setiap resource punya meja sendiri. BukuController di meja 1, AnggotaController di meja 2.

## Dipakai untuk Apa

- **Setiap resource CRUD** — buku, anggota, peminjaman, kategori
- **Logika bisnis** — apapun yang lebih kompleks dari satu baris closure
- **API endpoints** — controller untuk API dengan response JSON

## Kesalahan Umum

1. **Controller terlalu gemuk (fat controller)** — satu controller berisi terlalu banyak logika. Pisahkan ke service/action class
2. **Lupa import class** — `use App\Models\Buku;` — error jika tidak di-import
3. **Method tidak mengembalikan response** — setiap method harus return view, redirect, atau response
4. **Menaruh logika di route** — setelah punya controller, jangan tulis logika di route. Route cukup panggil controller
5. **Nama method tidak sesuai konvensi** — resource controller harus pakai nama `index`, `create`, `store`, dll.

## Koneksi dengan Materi Sebelumnya

Poin 7-10: Route dengan closure. Sekarang closure diganti dengan controller — logika dipindahkan ke class terpisah. Route jadi lebih bersih.

**Benang merah ke depan:**
- Poin 15 (Dependency Injection): Controller menerima dependency melalui constructor/method
- Poin 16 (Request Object): Data dari HTTP request diakses melalui parameter type-hinted
- Poin 20 (Eloquent): Data hardcode diganti dengan query ke database
