# 15. Dependency Injection di Controller — Laravel yang Pintar

## Penjelasan

**Dependency Injection (DI)** adalah pola di mana Laravel secara otomatis menyediakan (inject) objek yang dibutuhkan oleh controller — tanpa perlu membuat instance manual dengan `new`. Cukup dengan type-hint parameter, Laravel akan memberikan instance yang diminta.

Ada dua jenis DI di controller:
1. **Constructor Injection** — inject ke constructor, tersedia di semua method
2. **Method Injection** — inject per method tertentu

```php
public function __construct(
    private BukuRepository $repository,  // otomatis di-inject
) {}

public function index(
    Request $request,  // otomatis di-inject
    BukuService $service,
): View {
    $buku = $service->getAll();
    return view('buku.index', compact('buku'));
}
```

**Route Model Binding** — bentuk khusus DI di mana parameter route otomatis di-fetch dari database:
```php
// Route: Route::get('/buku/{buku}', ...)
// Laravel otomatis: SELECT * FROM buku WHERE id = {buku}

public function show(Buku $buku): View  // otomatis 404 jika tidak ada
{
    return view('buku.show', compact('buku'));
}
```

## Fungsi

- Mengurangi kode boilerplate — tidak perlu `new Request()` manual
- Memudahkan testing — dependency bisa di-mock
- Memastikan dependency tersedia dengan konfigurasi yang benar
- Route Model Binding menghemat query manual

## Cara Pengimplementasian

```php
<?php
// Constructor injection — inject service/repository
class BukuController extends Controller
{
    public function __construct(
        private BukuRepository $bukuRepo,
        private LogService $logService,
    ) {}

    public function index(): View
    {
        $this->logService->info('Mengakses halaman katalog');
        $buku = $this->bukuRepo->getAll();
        return view('buku.index', compact('buku'));
    }
}

// Method injection — inject Request
class BukuController extends Controller
{
    public function index(
        Request $request,  // DI method
        BukuService $service,
    ): View {
        $kategori = $request->query('kategori');
        $buku = $service->getByKategori($kategori);
        return view('buku.index', compact('buku'));
    }

    public function store(
        StoreBukuRequest $request,  // Form Request (juga DI)
    ): RedirectResponse {
        Buku::create($request->validated());
        return redirect()->route('buku.index');
    }
}

// Route Model Binding
// routes/web.php: Route::get('/buku/{buku}', [BukuController::class, 'show']);

public function show(Buku $buku): View
{
    // $buku sudah berisi data dari database
    // Jika ID tidak ditemukan → otomatis 404
    return view('buku.show', compact('buku'));
}

// Jika parameter route berbeda dari nama model:
// routes/web.php: Route::get('/artikel/{post}', ...)
public function show(Buku $post): View
{
    // Laravel akan cari Buku berdasarkan nilai {post}
    return view('buku.show', compact('post'));
}
```

## Analogi

DI seperti **sistem pesan antar di perpustakaan**:

- **Constructor Injection**: Pustakawan (controller) punya telepon (service) yang selalu ada di mejanya. Setiap kali butuh informasi buku, tinggal angkat telepon — tidak perlu memasang telepon baru setiap hari.

- **Method Injection**: Pustakawan butuh **formulir (Request)** untuk mencatat peminjaman. Formulir ini dikirim dari pengunjung (browser) — pustakawan tidak perlu membuat formulir sendiri.

- **Route Model Binding**: Pengunjung bilang "saya mau buku di **rak 5**". Petugas langsung ke rak 5, ambil buku, dan bawa ke meja — tidak perlu tanya "rak 5 itu buku apa ya?" lalu cari lagi.

Tanpa DI, kamu harus melakukan:
```php
// Tanpa DI — manual
public function show($id)
{
    $request = new Request();  // harus buat sendiri
    $buku = Buku::findOrFail($id);  // harus query manual
    return view('buku.show', compact('buku'));
}

// Dengan DI — Laravel yang urus
public function show(Buku $buku)
{
    return view('buku.show', compact('buku'));
}
```

## Dipakai untuk Apa

- **Semua controller** — Request, Service, Repository perlu di-inject
- **Route Model Binding** — setiap route dengan parameter ID model
- **Form Request** — validasi yang di-inject ke controller method
- **Event/Listener** — dependency listener di-inject via constructor

## Kesalahan Umum

1. **Membuat instance manual dengan `new`** — jika ada DI, jangan `new Request()`, biarkan Laravel yang inject
2. **Lupa type-hint** — `$request` tanpa `Request` di depannya → tidak di-inject
3. **Nama parameter route tidak sesuai** — route pakai `{buku}` tapi method pakai `$id` → Route Model Binding tidak aktif
4. **Menggunakan `findOrFail` padahal sudah Route Model Binding** — `show(Buku $buku)` sudah otomatis, tidak perlu `Buku::findOrFail($id)` lagi
5. **Constructor terlalu banyak parameter** — lebih dari 5-6 dependency menandakan controller terlalu gemuk

## Koneksi dengan Materi Sebelumnya

Poin 14 memperkenalkan controller. DI membuat controller lebih pintar — tinggal type-hint, Laravel sediakan dependency-nya. Ini adalah fitur kunci dari **Service Container** Laravel (dibahas detail di Level 6).

**Benang merah ke depan:**
- Poin 16 (Request Object): Request adalah dependency yang paling sering di-inject
- Poin 20 (Eloquent): Route Model Binding sangat berguna dengan Eloquent
- Poin 37 (Service Container): Memahami DI membuka pintu ke pemahaman Service Container

## Soal Latihan

1. **Praktik**: Buat method `show` di BukuController menggunakan Route Model Binding!
2. **Analisis**: Apa yang terjadi jika parameter route `{buku}` tidak ditemukan di database saat menggunakan Route Model Binding?
3. **Praktik**: Inject `Request` ke method `index` dan gunakan `$request->query('kategori')` untuk filter!

<details>
<summary>Jawaban</summary>

1. **Route Model Binding:**
   ```php
   // routes/web.php
   Route::get('/buku/{buku}', [BukuController::class, 'show'])->name('buku.show');

   // BukuController
   public function show(Buku $buku): View
   {
       return view('buku.show', compact('buku'));
   }
   ```
   Laravel otomatis melakukan `Buku::findOrFail($id)` dan melempar 404 jika tidak ditemukan.

2. **Jika tidak ditemukan:** Laravel melempar `ModelNotFoundException` yang otomatis menjadi response 404. User melihat halaman error 404, bukan pesan "undefined" atau error aneh.

3. **Inject Request:**
   ```php
   public function index(Request $request): View
   {
       $kategori = $request->query('kategori');
       $buku = Buku::when($kategori, fn($q) => $q->where('kategori', $kategori))
                    ->get();
       return view('buku.index', compact('buku'));
   }
   ```
