# 26. Cascade — Urutan Menentukan Pemenang

## Penjelasan

Cascade adalah algoritma CSS yang menentukan **aturan mana yang menang** ketika ada konflik. Tiga faktor dalam urutan prioritas:

1. **Origin**: Browser default → User stylesheet → Author (kita) → !important user → !important author
2. **Specificity**: Seberapa spesifik selector
3. **Order**: Jika sama persis, yang terakhir ditulis menang

```css
/* Order: jika specificity sama, yang terakhir menang */
p { color: blue; }   /* ditulis pertama */
p { color: red; }    /* ditulis kedua — INI yang berlaku */
```

## Fungsi

- Menentukan aturan mana yang berlaku ketika ada konflik
- Memberi mekanisme prediksi — tidak acak
- Dasar untuk debugging CSS "yang tidak jalan"

## Cara Pengimplementasian

```css
/* 1. Origin: author stylesheet kita override browser default */
h1 { font-size: 2.5rem; }  /* override ukuran default browser */

/* 2. Order: urutan penulisan berpengaruh */
.btn { background: blue; }
.btn { background: red; }   /* red menang — ditulis setelah blue */

/* 3. Origin juga termasuk urutan file CSS yang di-link */
/* File yang di-link belakang menang jika specificity sama */
```

```html
<!-- File styles.css di-link setelah reset.css — styles.css menang -->
<link rel="stylesheet" href="reset.css">
<link rel="stylesheet" href="styles.css">
```

## Analogi

Cascade seperti **aturan berpakaian di rumah**:
1. **Origin**: Aturan global ("Semua orang di rumah pakai sandal") override preferensi pribadi
2. **Specificity**: Aturan spesifik ("Adik pakai baju biru") override aturan umum ("Semua anak pakai baju rapi")
3. **Order**: Jika ada dua aturan sama spesifiknya ("Baju biru" lalu "Baju merah"), yang terakhir diucapkan yang dipatuhi

## Dipakai Untuk Apa

- Memahami mengapa suatu style tidak ter-apply
- Mengatur urutan penulisan CSS
- Debugging properti yang di-override

## Kesalahan Umum

- **Mengira urutan HTML memengaruhi**: bukan urutan di HTML, tapi urutan di file CSS
- **Tidak sadar ada dua aturan dengan specificity sama**: yang terakhir menang — periksa urutan
- **Mengira semua properti di selector yang sama akan menang**: setiap properti dievaluasi sendiri — color bisa dari aturan A, font-size dari aturan B

## Hubungan dengan Materi Sebelumnya

Level 1-2: kita menulis CSS dan kadang style "tidak jalan". Ini karena **Cascade** — aturan yang lebih baru, lebih spesifik, atau dari origin tertentu menang. Memahami cascade adalah momen "aha" yang menjelaskan semua misteri CSS.

## Soal Latihan

### Soal 1
Apa 3 faktor cascade dalam urutan prioritas?

**Jawaban:**
1. Origin (browser → user → author)
2. Specificity (seberapa spesifik selector)
3. Order (yang terakhir ditulis menang)

### Soal 2
Jika ada dua aturan: `p { color: red; }` lalu `p { color: blue; }`, mana warna yang berlaku?

**Jawaban:**
Biru — karena order: yang terakhir ditulis menang (specificity sama).

### Soal 3
Apa yang dimaksud dengan origin cascade?

**Jawaban:**
Sumber asal CSS: browser default (paling lemah), user stylesheet, author CSS kita (paling kuat, kecuali !important). Kita sebagai author bisa override semua style default browser.
