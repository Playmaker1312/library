# Perbandingan Metodologi CSS

## Analogi: Perpustakaan Digital

Perpustakaan digital dapat menggunakan berbagai sistem organisasi: Dewey Decimal untuk klasifikasi universal, sistem kustom untuk koleksi lokal, atau tagging digital untuk fleksibilitas maksimal. Tidak ada sistem yang sempurna untuk semua situasi. Perpustakaan kecil mungkin cukup dengan tagging, sementara perpustakaan nasional membutuhkan Dewey. Memilih metodologi CSS juga bergantung pada skala, tim, dan kebutuhan proyek.

## Penjelasan Detail

Setiap metodologi CSS memiliki kekuatan dan kelemahan. BEM unggul dalam kejelasan struktur dan skala besar, tetapi nama kelas panjang dan bisa terasa verbose. OOCSS fokus pada reuse dan pemisahan concern, tetapi bisa menghasilkan HTML dengan banyak kelas. SMACSS memberikan organisasi fungsional yang jelas, tetapi implementasi bisa bervariasi antar tim. ITCSS mengelola spesifisitas dengan sangat baik, tetapi membutuhkan disiplin tim yang tinggi. Utility-first (Tailwind) mempercepat pengembangan dan memastikan konsistensi, tetapi menghasilkan HTML yang panjang dan memiliki kurva belajar. CSS Modules dan CSS-in-JS memberikan enkapsulasi teknis tetapi bergantung pada toolchain JavaScript. Pemilihan metodologi tergantung pada: ukuran tim, skala proyek, kebutuhan kustomisasi, preferensi tim, dan toolchain yang digunakan.

## Contoh Kode Implementasi

```css
/* BEM — eksplisit, verbose */
.card__title--highlighted { color: #f1c40f; }

/* OOCSS — reusable, dekoratif */
.box { padding: 1rem; border-radius: 8px; }
.theme-warning { background: #fff3cd; color: #856404; }
.theme-error { background: #f8d7da; color: #721c24; }

/* Utility-first — cepat, langsung */
<div class="p-4 bg-yellow-100 text-yellow-800 rounded-lg">
  Peringatan!
</div>

/* CSS Modules — terenkapsulasi teknis */
import styles from './Alert.module.css';
<div className={styles.warning}>Peringatan!</div>

/* CSS-in-JS — dinamis, terintegrasi */
const Alert = styled.div`
  background: ${props => props.type === 'error' ? '#f8d7da' : '#fff3cd'};
  color: ${props => props.type === 'error' ? '#721c24' : '#856404'};
`;
```

| Metodologi | Kelebihan | Kekurangan | Cocok Untuk |
|---|---|---|---|
| BEM | Jelas, skalabel | Verbose | Proyek besar, banyak komponen |
| OOCSS | Reusable, DRY | Banyak kelas | Sistem desain, library |
| SMACSS | Terorganisir | Variasi implementasi | Tim besar, proyek kompleks |
| ITCSS | Spesifisitas terkontrol | Disiplin tinggi | Proyek dengan CSS kompleks |
| Utility-first | Cepat, konsisten | HTML panjang | Prototipe, tim kecil |
| CSS Modules | Enkapsulasi otomatis | Butuh build tool | Aplikasi React/Vue |
| CSS-in-JS | Dinamis, powerful | Runtime overhead | Aplikasi dengan gaya dinamis |

## Poin Penting
- Tidak ada metodologi CSS yang sempurna untuk semua situasi.
- BEM dan SMACSS cocok untuk proyek besar dengan tim besar.
- Utility-first (Tailwind) cocok untuk prototipe cepat dan pengembangan iteratif.
- CSS Modules dan CSS-in-JS cocok untuk aplikasi berbasis komponen modern.
- Banyak proyek menggunakan kombinasi metodologi yang sesuai dengan kebutuhan spesifik.
