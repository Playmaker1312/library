# Menghindari Layout Thrashing

## Analogi: Perpustakaan Digital

Bayangkan seorang petugas perpustakaan yang terus-menerus menata ulang rak buku, lalu mengukur ulang ruangan, lalu menata ulang lagi, lalu mengukur lagi—siklus ini berulang terus tanpa henti. Ini membuang-buang waktu dan tenaga. Layout thrashing dalam CSS adalah situasi serupa di mana browser dipaksa menghitung ulang tata letak berulang kali dalam waktu singkat, menyebabkan animasi tersendat dan performa buruk.

## Penjelasan Detail

Layout thrashing terjadi ketika JavaScript membaca properti layout (seperti `offsetHeight`, `clientWidth`) setelah mengubah gaya, memaksa browser melakukan perhitungan ulang tata letak secara sinkron. Dalam CSS, ini berkaitan dengan properti mana yang kita animasikan. Beberapa properti memicu layout (paling mahal), beberapa memicu paint (sedang), dan beberapa hanya memicu komposisi (paling murah). Properti layout: `width`, `height`, `margin`, `padding`, `border`, `top`, `left`, `right`, `bottom`, `display`, `float`, `position`, `font-size`, `line-height`. Properti paint: `color`, `background`, `box-shadow`, `border-radius`, `outline`, `visibility`. Properti komposisi: `transform`, `opacity`. Dengan memilih properti yang tepat untuk animasi—khususnya `transform` dan `opacity`—kita menghindari layout thrashing dan memastikan animasi berjalan pada 60 frame per detik.

## Contoh Kode Implementasi

```css
/* ❌ BURUK: Animasi properti layout — memicu thrashing */
.bad {
  transition: margin-left 0.3s, width 0.3s, height 0.3s;
}
.bad.active {
  margin-left: 100px;
  width: 200px;
  height: 300px;
}

/* ✅ BAIK: Animasi properti komposisi — GPU friendly */
.good {
  transition: transform 0.3s;
}
.good.active {
  transform: translateX(100px) scale(1.2);
}

/* ❌ BURUK: Mengubah ukuran dengan height */
.expand-bad {
  overflow: hidden;
  transition: height 0.3s;
}
.expand-bad.active {
  height: 200px;
}

/* ✅ BAIK: Mengubah ukuran dengan transform scale */
.expand-good {
  overflow: hidden;
  transition: transform 0.3s;
}
.expand-good.active {
  transform: scaleY(1.5);
  transform-origin: top;
}

/* ❌ BURUK: Animasi posisi dengan top/left */
.move-bad {
  position: relative;
  transition: top 0.3s, left 0.3s;
}
.move-bad.active {
  top: 50px;
  left: 100px;
}

/* ✅ BAIK: Animasi posisi dengan transform translate */
.move-good {
  transition: transform 0.3s;
}
.move-good.active {
  transform: translate(100px, 50px);
}
```

## Poin Penting
- Layout thrashing terjadi ketika browser dipaksa menghitung ulang tata letak berulang kali.
- Properti layout (width, height, margin, padding, top, left) — PALING MAHAL untuk dianimasi.
- Properti paint (color, background, box-shadow) — SEDANG.
- Properti komposisi (transform, opacity) — PALING MURAH, hanya GPU.
- Selalu prefer `transform` dan `opacity` untuk animasi demi performa 60fps.
