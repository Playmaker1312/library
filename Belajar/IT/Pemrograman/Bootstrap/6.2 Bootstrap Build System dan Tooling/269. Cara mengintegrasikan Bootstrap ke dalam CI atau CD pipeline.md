# Cara mengintegrasikan Bootstrap ke dalam CI atau CD pipeline

## Analogi: Perpustakaan Digital

Perpustakaan digital memiliki jalur produksi otomatis: setiap kali penulis mengirimkan naskah baru, sistem akan memeriksa format, menjalankan proofreading, mengkonversi ke berbagai format, dan menerbitkannya ke katalog — semuanya tanpa campur tangan manusia. CI/CD pipeline adalah jalur produksi untuk kode: setiap push ke repository memicu build, test, dan deployment otomatis.

## Penjelasan Detail

CI/CD (Continuous Integration/Continuous Deployment) mengotomatiskan build, pengujian, dan deployment. Untuk project Bootstrap, pipeline biasanya terdiri dari: checkout kode, instalasi dependency, kompilasi Bootstrap Sass, menjalankan linter (Stylelint, ESLint), build production, dan deploy ke staging atau production. GitHub Actions, GitLab CI, atau Jenkins bisa digunakan. Pastikan pipeline menggunakan Node.js versi yang konsisten dengan project. Build Bootstrap yang sudah dikustomisasi harus diverifikasi dengan visual regression testing menggunakan Percy atau Chromatic. Deploy hasil build ke CDN (seperti Netlify, Vercel, atau AWS S3) untuk akses tim.

## Contoh Kode Implementasi

```yaml
# .github/workflows/bootstrap-ci.yml
name: Bootstrap CI Pipeline

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

jobs:
  lint-and-build:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        node-version: [18.x, 20.x]

    steps:
      - uses: actions/checkout@v4

      - name: Setup Node.js ${{ matrix.node-version }}
        uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node-version }}
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Lint CSS (Stylelint)
        run: npm run lint:css

      - name: Lint JS (ESLint)
        run: npm run lint:js

      - name: Build Bootstrap custom
        run: npm run build

      - name: Upload build artifact
        uses: actions/upload-artifact@v3
        with:
          name: bootstrap-dist-${{ matrix.node-version }}
          path: dist/

  visual-regression:
    needs: lint-and-build
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Install & Build
        run: npm ci && npm run build
      - name: Visual regression test
        run: npx percy snapshot dist/
        env:
          PERCY_TOKEN: ${{ secrets.PERCY_TOKEN }}

  deploy:
    needs: [lint-and-build, visual-regression]
    if: github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Install & Build
        run: npm ci && npm run build
      - name: Deploy to Netlify
        uses: nwtgck/actions-netlify@v2
        with:
          publish-dir: './dist'
          production-branch: main
        env:
          NETLIFY_AUTH_TOKEN: ${{ secrets.NETLIFY_AUTH_TOKEN }}
          NETLIFY_SITE_ID: ${{ secrets.NETLIFY_SITE_ID }}
```

```yaml
# .gitlab-ci.yml
image: node:18

stages:
  - lint
  - build
  - test
  - deploy

cache:
  paths:
    - node_modules/

lint-css:
  stage: lint
  script:
    - npm ci
    - npm run lint:css

lint-js:
  stage: lint
  script:
    - npm ci
    - npm run lint:js

build:
  stage: build
  script:
    - npm ci
    - npm run build
  artifacts:
    paths:
      - dist/

deploy-staging:
  stage: deploy
  script:
    - npm ci
    - npm run build
    - npx netlify deploy --dir=dist --alias=staging
  only:
    - develop

deploy-production:
  stage: deploy
  script:
    - npm ci
    - npm run build
    - npx netlify deploy --dir=dist --prod
  only:
    - main
```

## Poin Penting
- CI pipeline otomatis menjalankan linter, build, dan test setiap kali ada push atau PR
- Gunakan matrix strategy untuk menguji Bootstrap di beberapa versi Node.js
- Simpan hasil build sebagai artifact untuk digunakan di job selanjutnya
- Integrasikan visual regression testing untuk memastikan perubahan Bootstrap tidak merusak tampilan
