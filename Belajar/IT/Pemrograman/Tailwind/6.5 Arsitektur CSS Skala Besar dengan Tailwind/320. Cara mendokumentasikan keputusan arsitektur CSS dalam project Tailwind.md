# Cara mendokumentasikan keputusan arsitektur CSS dalam project Tailwind

## Analogi: Perpustakaan Digital

Dokumentasi arsitektur seperti peta dan buku panduan perpustakaan yang menjelaskan mengapa buku ditempatkan di rak tertentu, mengapa menggunakan sistem katalog tertentu, dan bagaimana prosedur penambahan buku baru. Tanpa dokumentasi ini, pustakawan baru hanya menebak-nebak alasan di balik tata letak. Ketika ada perubahan, mereka mungkin membuat keputusan yang bertentangan dengan filosofi awal perpustakaan.

## Penjelasan Detail

Dokumentasi arsitektur CSS dalam project Tailwind harus mencakup: alasan pemilihan Tailwind sebagai fondasi CSS, struktur folder dan organisasi komponen, design system yang digunakan (tokens, naming conventions), keputusan tentang kapan menggunakan `@apply`, `@layer`, dan custom CSS, strategi responsif (mobile-first, breakpoints), cara penanganan third-party libraries, dan konvensi tim (linting, formatting, code review). Gunakan format Architecture Decision Record (ADR) untuk mencatat keputusan penting: konteks, keputusan, konsekuensi. Dokumentasi ini hidup—perbarui ketika ada perubahan signifikan.

## Contoh Kode Implementasi

```md
# ADR-001: Penggunaan Tailwind CSS v4 sebagai Framework CSS

## Status
Accepted (2026-05-24)

## Konteks
Project membutuhkan framework CSS untuk membangun UI yang konsisten dan cepat. Tim terdiri dari 5 frontend developer dengan pengalaman React.

## Keputusan
- Menggunakan Tailwind CSS v4 sebagai satu-satunya framework CSS
- Desain system didefinisikan via @theme di CSS
- Komponen dibuat menggunakan React dengan class Tailwind
- Prettier + ESLint untuk konsistensi
- Container queries untuk komponen reusable

## Konsekuensi
Positif:
- Build time lebih cepat dengan engine Rust
- Konfigurasi lebih sederhana (CSS-based, bukan JS)
- Container queries built-in tanpa plugin

Negatif:
- Perlu migrasi dari v3 (jika project existing)
- Tim perlu adaptasi dengan at-rules baru

## Alternatif yang Dipertimbangkan
- Styled Components: ditolak karena runtime cost dan bundle size
- Vanilla CSS: ditolak karena scaling buruk di tim besar
- Bootstrap: ditolak karena terlalu kaku untuk design kustom
```

```md
# Panduan Arsitektur CSS — Project Tailwind

## Filosofi
1. **Utility-first**: 95% styling menggunakan utility class langsung di template
2. **Component boundaries**: komponen React membungkus class Tailwind
3. **Minimal custom CSS**: custom CSS hanya untuk animasi kompleks dan edge cases

## Struktur CSS
src/
└── styles/
    ├── main.css          # @import "tailwindcss" + @theme
    └── components.css    # @layer components (jika diperlukan)

## Aturan Penting
- @apply hanya untuk pola yang muncul 4+ kali
- @utility untuk utility baru yang tidak ada di Tailwind
- @custom-variant untuk varian kustom (dark mode, dll.)
- Semua warna menggunakan design tokens (bg-primary, bukan bg-blue-600)
```

## Poin Penting

- Gunakan ADR (Architecture Decision Record) untuk keputusan besar
- Dokumentasikan filosofi, struktur, dan aturan main tim
- Dokumentasi adalah "living document"—perbarui ketika arsitektur berubah
