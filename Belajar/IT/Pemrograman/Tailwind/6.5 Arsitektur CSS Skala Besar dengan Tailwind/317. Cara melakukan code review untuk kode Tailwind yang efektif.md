# Cara melakukan code review untuk kode Tailwind yang efektif

## Analogi: Perpustakaan Digital

Code review untuk Tailwind seperti pemeriksaan kualitas buku sebelum masuk ke koleksi perpustakaan. Pustakawan senior memeriksa: apakah label sesuai standar? Apakah sampul tidak rusak? Apakah kategori sudah benar? Sama halnya, reviewer memeriksa apakah class Tailwind sudah optimal, konsisten dengan design system, dan tidak ada pemborosan. Tujuannya bukan mengkritik, tetapi memastikan kualitas kode tetap tinggi.

## Penjelasan Detail

Code review untuk Tailwind harus fokus pada aspek spesifik. Pertama, periksa penggunaan design tokens: apakah ada arbitrary value (`text-[#123456]`) yang seharusnya menggunakan token yang sudah ada? Kedua, periksa konsistensi: apakah spacing menggunakan skala yang konsisten atau ada nilai acak? Ketiga, periksa duplikasi: apakah ada pola class yang berulang yang bisa diekstrak ke komponen? Keempat, periksa urutan class (sebaiknya sudah di-autofix oleh Prettier). Kelima, periksa aksesibilitas: apakah ada class yang mengganggu kontras atau focus visibility? Buat checklist review yang bisa digunakan semua anggota tim.

## Contoh Kode Implementasi

```md
# Code Review Checklist — Tailwind CSS

## 1. Design Tokens
- [ ] Tidak ada arbitrary value yang bisa diganti token (kecuali disepakati)
- [ ] Warna menggunakan semantik (bg-primary) bukan literal (bg-blue-600)
- [ ] Spacing menggunakan skala yang ditentukan (p-4, bukan p-[13px])

## 2. Konsistensi
- [ ] Class diurutkan sesuai konvensi (dicek Prettier)
- [ ] Tidak ada class yang bertentangan (flex + hidden, text-sm + text-lg)
- [ ] Responsive breakpoint menggunakan nilai yang ditentukan

## 3. Optimalisasi
- [ ] Tidak ada pola class berulang >3x yang sebaiknya jadi komponen
- [ ] Tidak ada utility yang tidak digunakan (dead code)
- [ ] Mobile-first: base class untuk mobile, breakpoint untuk larger screens

## 4. Aksesibilitas
- [ ] Warna teks memiliki kontras cukup dengan background
- [ ] Focus ring tidak dihapus (kecuali diganti custom)
- [ ] Interactive elements memiliki hover/focus states

## 5. Custom CSS
- [ ] @apply hanya untuk pola berulang >3x
- [ ] Custom CSS ditempatkan di @layer yang sesuai
- [ ] Tidak ada !important yang tidak perlu
```

```tsx
// Contoh review: sebelum
function BadBefore() {
  return (
    <div className="w-[400px] p-[20px] bg-[#f8fafc] text-[#1e293b] rounded-[8px] flex">
      <span className="text-[14px] font-medium">Konten</span>
    </div>
  );
}

// Contoh review: sesudah (gunakan design tokens)
function GoodAfter() {
  return (
    <div className="flex w-96 rounded-lg bg-neutral-50 p-5 text-neutral-800">
      <span className="text-sm font-medium">Konten</span>
    </div>
  );
}
```

## Poin Penting

- Fokus pada design tokens, konsistensi, duplikasi, dan aksesibilitas
- Gunakan checklist review yang terdokumentasi untuk konsistensi
- Prioritaskan otomatisasi (Prettier, ESLint) kurangi beban review manual
