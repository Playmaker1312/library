# Cara mengelola konsistensi class Tailwind dalam tim yang besar

## Analogi: Perpustakaan Digital

Dalam tim besar, setiap pustakawan mungkin punya gaya katalogisasi sendiri tanpa aturan yang jelas. Satu orang menulis "Fiksi - Ilmiah," yang lain "Fiksi Ilmiah," yang lain "Sci-Fi." Akibatnya, katalog menjadi kacau. Sama halnya dengan class Tailwind—tanpa standar, satu developer mungkin menulis `p-4`, yang lain `p-[16px]`, yang lain `px-4 py-4`. Konsistensi memerlukan aturan yang jelas dan tools yang menegakkannya.

## Penjelasan Detail

Konsistensi dalam tim besar dimulai dari aturan main yang didokumentasikan dan ditegakkan oleh tools. Gunakan Prettier plugin Tailwind untuk otomatis mengurutkan class (misal: layout, spacing, typography, visual). Gunakan ESLint dengan `eslint-plugin-tailwindcss` untuk melarang penggunaan arbitrary value yang tidak perlu atau class yang tidak konsisten. Definisikan design system yang ketat dan gunakan konfigurasi Tailwind yang sama di semua project. Lakukan code review dengan checklist spesifik Tailwind. Pertimbangkan membuat wrapper component untuk pola yang sering digunakan (misal `Button`, `Card`) yang sudah memiliki class tetap—anggota tim tinggal menggunakan komponen tersebut tanpa menulis class Tailwind langsung.

## Contoh Kode Implementasi

```json
// .prettierrc — konsistensi format dan urutan class
{
  "semi": true,
  "singleQuote": false,
  "tabWidth": 2,
  "plugins": ["prettier-plugin-tailwindcss"],
  "tailwindFunctions": ["cn", "clsx", "twMerge"]
}
```

```js
// eslint.config.js
import tailwind from "eslint-plugin-tailwindcss";

export default [
  ...tailwind.configs["flat/recommended"],
  {
    rules: {
      "tailwindcss/classnames-order": "error",
      "tailwindcss/no-custom-classname": ["warn", {
        whitelist: ["btn-.+"],
      }],
      "tailwindcss/no-unnecessary-arbitrary-value": "error",
      "tailwindcss/no-contradicting-classname": "error",
    },
  },
];
```

```tsx
// Contoh: review checklist untuk Pull Request
export const TAILWIND_PR_CHECKLIST = `
## Tailwind Review Checklist
- [ ] Tidak ada class yang bertentangan (flex + hidden, dll.)
- [ ] Prioritaskan design system tokens daripada arbitrary values
- [ ] Responsive breakpoints menggunakan nilai yang sudah ditentukan
- [ ] Class diurutkan sesuai Prettier plugin
- [ ] Tidak ada !important yang tidak perlu
- [ ] @apply hanya untuk pola yang benar-benar berulang (3+)
`;
```

## Poin Penting

- Prettier plugin untuk urutan class yang konsisten di seluruh tim
- ESLint plugin untuk melarang arbitrary values dan class bertentangan
- Code review checklist membantu menjaga standar kualitas
