# Cara menganalisis ukuran file CSS yang dihasilkan Tailwind
## Analogi: Perpustakaan Digital
Seperti petugas yang perlu mengecek apakah ada buku yang tidak pernah dipinjam dan hanya memenuhi rak, Anda perlu menganalisis CSS Tailwind untuk menemukan class yang tidak terpakai. Semakin sedikit "buku" di rak, semakin cepat pengunjung menemukan yang mereka cari.
## Penjelasan Detail
Menganalisis ukuran CSS Tailwind penting untuk memastikan performa loading halaman tetap optimal. Alat utama untuk analisis: (1) `purgecss` atau `@fullhuman/postcss-purgecss` untuk melihat class apa yang dipotong. (2) `cssnano` atau `clean-css` untuk minifikasi. (3) Browser DevTools — tab Network untuk melihat ukuran file CSS yang di-download. (4) WebPageTest atau GTmetrix untuk analisis mendalam. Dengan JIT, file CSS biasanya sudah sangat kecil, tetapi Anda tetap perlu memeriksa. Gunakan perintah `npx tailwindcss -i input.css -o output.css --minify` dan lihat ukuran file output-nya. Bandingkan ukuran sebelum dan sesudah gzip (karena CSS biasanya di-gzip oleh server). Ukuran CSS production Tailwind yang ideal adalah di bawah 20 kB (gzip). Jika lebih besar, periksa apakah ada pattern content yang tidak perlu atau safelist yang terlalu besar.

## Poin Penting
- Gunakan `--minify` untuk menghasilkan CSS production yang diminifikasi
- Ukuran gzip lebih relevan daripada ukuran raw karena kompresi server
- Target ukuran CSS Tailwind ideal: di bawah 20 kB setelah gzip
