# Cara memastikan konsistensi implementasi design system dalam tim

## Analogi: Perpustakaan Digital

Memastikan konsistensi dalam tim seperti memiliki kepala pustakawan yang mengawasi semua rak buku di setiap cabang. Tanpa pengawasan, satu pustakawan mungkin memberi label merah untuk fiksi, sementara yang lain menggunakan biru. Di tim development, konsistensi dijaga melalui tools otomatis (linting, formatting), code review, dan dokumentasi yang jelas. Semua orang harus mengikuti aturan yang sama—bukan berdasarkan preferensi pribadi.

## Penjelasan Detail

Konsistensi dalam tim dicapai melalui beberapa lapisan: tooling (ESLint, Prettier), proses (code review), dan budaya (dokumentasi). Gunakan `eslint-plugin-tailwindcss` untuk memvalidasi penggunaan class yang sesuai dengan design system—misalnya, larang penggunaan warna arbitrer seperti `text-[#123456]` jika sudah ada token yang sesuai. Gunakan Prettier plugin Tailwind untuk mengurutkan class secara konsisten. Buat checklist code review yang spesifik untuk Tailwind: apakah menggunakan design tokens? Apakah spacing konsisten? Apakah ada utility yang tidak perlu? Adakan session "design system sync" secara rutin untuk membahas perubahan dan masukan.

## Contoh Kode Implementasi

```js
// eslint.config.js — dengan plugin tailwindcss
import tailwind from "eslint-plugin-tailwindcss";

export default [
  ...tailwind.configs["flat/recommended"],
  {
    rules: {
      "tailwindcss/no-custom-classname": "warn",
      "tailwindcss/classnames-order": "error",
      "tailwindcss/no-unnecessary-arbitrary-value": "warn",
    },
  },
];
```

```json
// .prettierrc — Prettier dengan Tailwind plugin
{
  "plugins": ["prettier-plugin-tailwindcss"],
  "tailwindStylesheet": "./src/styles.css",
  "tailwindPreserveWhitespace": true
}
```

```md
<!-- CODE REVIEW CHECKLIST — Tailwind -->
## Tailwind Code Review Checklist
- [ ] Menggunakan design tokens (bg-primary, bukan bg-[#123456])
- [ ] Spacing menggunakan skala yang ditentukan (p-4, bukan p-[13px])
- [ ] Tidak ada utility yang bertentangan (flex + hidden bersamaan)
- [ ] Responsive class menggunakan breakpoint yang benar
- [ ] Class diurutkan sesuai Prettier plugin
- [ ] Custom CSS minimal, di @layer yang tepat
```

## Poin Penting

- Gunakan ESLint plugin Tailwind untuk validasi otomatis penggunaan design system
- Prettier plugin memastikan urutan class konsisten di seluruh tim
- Code review checklist spesifik Tailwind dan session sync rutin menjaga konsistensi
