# Cara membuat checklist quality assurance untuk project Tailwind

## Analogi: Perpustakaan Digital
Checklist QA untuk project Tailwind seperti daftar periksa sebelum membuka perpustakaan digital untuk umum—pastikan rak tertata, buku berlabel, katalog berfungsi, dan pintu masuk mudah diakses. Checklist sistematis mencegah masalah terlewat dan memastikan kualitas konsisten.

## Penjelasan Detail
Checklist QA untuk project Tailwind mencakup beberapa kategori: **Desain & Visual** (konsistensi spacing, typography, warna, responsivitas di semua breakpoint), **Fungsionalitas** (interaksi tombol, form, navigasi, dark mode toggle), **Kinerja** (ukuran bundle CSS, skor Lighthouse, waktu loading), **Aksesibilitas** (kontras warna, ARIA labels, keyboard navigation, screen reader), **Kode** (tidak ada kelas dinamis yang tidak terdeteksi, konfigurasi purge benar, tidak ada CSS kustom yang redundan), **Cross-browser** (render konsisten di Chrome, Firefox, Safari, Edge). Checklist dapat didokumentasikan di README project atau sebagai test cases otomatis. Integrasi dengan CI/CD menjalankan checklist otomatis (Lighthouse, axe-core, size-limit) di setiap PR. Checklist manual untuk review visual dan UX tetap diperlukan. Dokumentasi keputusan desain dan komponen memudahkan onboarding anggota tim baru.

## Contoh Kode Implementasi

```markdown
# QA Checklist - Tailwind Project

## Visual & Design
- [ ] Spacing konsisten (menggunakan skala Tailwind)
- [ ] Typography sesuai hierarki (prose untuk konten)
- [ ] Warna sesuai brand (tidak ada deviasi dari theme)
- [ ] Responsif di semua breakpoint (sm, md, lg, xl)
- [ ] Dark mode berfungsi tanpa masalah kontras

## Functional
- [ ] Semua tombol memiliki hover/focus states
- [ ] Form validation menampilkan error states
- [ ] Navigasi berfungsi di semua halaman
- [ ] Modal/dropdown terbuka dan tertutup dengan benar
- [ ] Animasi berjalan di motion-safe; tidak di motion-reduce

## Performance
- [ ] Bundle CSS < 30 KB gzipped
- [ ] Lighthouse performance score > 90
- [ ] Tidak ada render-blocking CSS
- [ ] Font dioptimalkan (swap display)

## Accessibility
- [ ] Kontras warna memenuhi WCAG AA
- [ ] Semua gambar memiliki alt text
- [ ] Keyboard navigation berfungsi penuh
- [ ] ARIA labels pada elemen interaktif
```

## Poin Penting
- Buat checklist terstruktur per kategori: visual, fungsional, kinerja, aksesibilitas, kode
- Otomatiskan sebanyak mungkin dengan Lighthouse, axe-core, dan size-limit di CI
- Checklist manual tetap diperlukan untuk review UX dan desain yang subjektif
- Dokumentasikan checklist di README agar seluruh tim memiliki standar yang sama
