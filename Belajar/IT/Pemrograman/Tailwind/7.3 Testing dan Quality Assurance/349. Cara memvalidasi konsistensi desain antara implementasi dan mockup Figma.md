# Cara memvalidasi konsistensi desain antara implementasi dan mockup Figma

## Analogi: Perpustakaan Digital
Validasi desain seperti membandingkan buku yang sudah dicetak dengan proofreader digital—setiap halaman harus sesuai dengan mockup yang disetujui. Tailwind membantu konsistensi melalui design tokens, tetapi perlu diverifikasi bahwa hasil akhir sesuai dengan desain Figma.

## Penjelasan Detail
Validasi konsistensi desain antara implementasi Tailwind dan mockup Figma melibatkan beberapa pendekatan. **Visual comparison** menggunakan tools seperti **Percy** atau **Chromatic** untuk membandingkan screenshot implementasi dengan Figma. **Design token audit** memastikan nilai di `tailwind.config.js` (warna, spacing, font, shadow) sesuai dengan Figma Design System. Tools seperti **`design-tokens`** atau **Style Dictionary** dapat menyinkronkan token antara Figma dan kode. **Pixel perfect testing** dengan overlay screenshot Figma di atas implementasi menggunakan ekstensi browser. **Layout shift analysis** memverifikasi spacing, margin, dan padding. Untuk workflow tim, gunakan **Figma API** untuk mengekstrak token desain dan mengonversinya ke format `tailwind.config.js`. Perbedaan umum: ukuran font tidak sesuai, spacing berbeda, atau warna tidak tepat. Tailwind utility classes memudahkan penyesuaian karena perubahan cukup pada konfigurasi.

## Contoh Kode Implementasi

```javascript
// Sinkronisasi token Figma ke tailwind.config.js
// Konversi dari Figma Design Tokens JSON
const figmaTokens = {
    "primary-500": { value: "#4f46e5" },
    "spacing-md": { value: "16px" },
    "font-size-xl": { value: "24px" },
}

module.exports = {
    theme: {
        extend: {
            colors: {
                primary: {
                    500: figmaTokens["primary-500"].value,
                },
            },
            spacing: {
                md: figmaTokens["spacing-md"].value,
            },
            fontSize: {
                xl: figmaTokens["font-size-xl"].value,
            },
        },
    },
}
```

```html
<!-- Gunakan data attributes untuk marking elements di visual test -->
<div class="p-4 bg-white rounded-xl" data-testid="pricing-card">
    <h3 class="text-xl font-bold" data-testid="card-title">Pro Plan</h3>
    <p class="text-gray-500" data-testid="card-description">Best for growing teams</p>
</div>
```

## Poin Penting
- Gunakan visual comparison tools (Percy, Chromatic) untuk membandingkan implementasi vs Figma
- Sinkronkan design token dari Figma ke tailwind.config.js melalui API atau manual
- Lakukan pixel perfect testing dengan overlay Figma screenshot di atas implementasi
- Data attributes memudahkan identifikasi elemen spesifik di automated visual tests
