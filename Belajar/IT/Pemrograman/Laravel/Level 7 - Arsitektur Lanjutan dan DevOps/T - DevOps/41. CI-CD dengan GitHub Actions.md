# 41. CI/CD dengan GitHub Actions

## Penjelasan

**CI/CD** (Continuous Integration / Continuous Deployment) adalah otomatisasi:
- **CI (Continuous Integration)**: Setiap push ke repository → otomatis test
- **CD (Continuous Deployment)**: Jika test lulus → otomatis deploy ke server

GitHub Actions adalah fitur GitHub yang menjalankan workflow berdasarkan trigger (push, pull request, schedule). Workflow didefinisikan dalam file YAML di `.github/workflows/`.

## Fungsi

- **CI**: Test otomatis setiap push — cegah kode rusak masuk ke production
- **CD**: Deploy otomatis jika test lulus — tidak perlu SSH manual
- **Quality Gate**: Test + static analysis + coverage minimum sebelum deploy
- **Konsistensi**: Setiap deploy menggunakan proses yang sama

## Cara Pengimplementasian

```yaml
# .github/workflows/ci.yml

name: CI/CD Pipeline

on:
  push:
    branches: [main, develop]  # trigger saat push
  pull_request:
    branches: [main]           # trigger saat PR

jobs:
  test:
    name: Test Suite
    runs-on: ubuntu-latest

    # Layanan yang dibutuhkan
    services:
      mysql:
        image: mysql:8.0
        env:
          MYSQL_ROOT_PASSWORD: password
          MYSQL_DATABASE: perpustakaan_test
        ports: ['3306:3306']
        options: --health-cmd="mysqladmin ping" --health-retries=3

      redis:
        image: redis:7
        ports: ['6379:6379']
        options: --health-cmd="redis-cli ping" --health-retries=3

    steps:
      - uses: actions/checkout@v4

      - name: Setup PHP
        uses: shivammathur/setup-php@v2
        with:
          php-version: '8.3'
          extensions: dom, curl, libxml, mbstring, zip, pdo, mysql, redis
          coverage: xdebug

      - name: Cache Composer dependencies
        uses: actions/cache@v3
        with:
          path: vendor
          key: ${{ runner.os }}-composer-${{ hashFiles('composer.lock') }}

      - name: Install dependencies
        run: composer install --prefer-dist --no-progress

      - name: Setup environment
        run: |
          cp .env.example .env.testing
          php artisan key:generate --env=testing

      - name: Run migrations
        run: php artisan migrate --env=testing
        env:
          DB_CONNECTION: mysql
          DB_HOST: 127.0.0.1
          DB_DATABASE: perpustakaan_test
          DB_USERNAME: root
          DB_PASSWORD: password

      - name: Run tests with coverage
        run: php artisan test --coverage --min=70 --parallel
        env:
          DB_CONNECTION: mysql
          DB_HOST: 127.0.0.1
          DB_DATABASE: perpustakaan_test
          DB_USERNAME: root
          DB_PASSWORD: password
          REDIS_HOST: 127.0.0.1

      - name: Run static analysis
        run: ./vendor/bin/phpstan analyse app tests --level=5

  deploy:
    name: Deploy to Production
    needs: test            # hanya jalan jika test sukses
    runs-on: ubuntu-latest
    if: github.ref == 'refs/heads/main'  # hanya dari branch main

    steps:
      - name: Deploy via SSH
        uses: appleboy/ssh-action@v1
        with:
          host: ${{ secrets.SERVER_HOST }}
          username: ${{ secrets.SERVER_USER }}
          key: ${{ secrets.SERVER_SSH_KEY }}
          script: |
            cd /var/www/perpustakaan
            git pull origin main
            composer install --optimize-autoloader --no-dev
            php artisan migrate --force
            php artisan optimize
            php artisan queue:restart
            sudo systemctl reload nginx
```

```yaml
# .github/workflows/laravel.yml — workflow lebih sederhana

name: Laravel CI

on: [push, pull_request]

jobs:
  laravel-tests:
    runs-on: ubuntu-latest

    steps:
    - uses: shivammathur/setup-php@v2
      with:
        php-version: '8.3'

    - uses: actions/checkout@v4

    - name: Copy .env
      run: php -r "file_exists('.env') || copy('.env.example', '.env');"

    - name: Install Dependencies
      run: composer install -q --no-ansi --no-interaction --no-scripts --no-progress

    - name: Generate key
      run: php artisan key:generate

    - name: Directory Permissions
      run: chmod -R 777 storage bootstrap/cache

    - name: Run Testsuite
      run: php artisan test
```

**Setup di GitHub:**
```bash
# 1. Buat file workflow di .github/workflows/ci.yml

# 2. Tambahkan Secrets di GitHub:
# Settings → Secrets and variables → Actions → New repository secret
# SERVER_HOST: alamat IP server
# SERVER_USER: username SSH
# SERVER_SSH_KEY: private key SSH

# 3. Push ke branch main
# → GitHub Actions otomatis jalan
```

## Analogi

CI/CD seperti **sistem quality control otomatis perpustakaan**:

**CI (Continuous Integration):**
Setiap kali pustakawan menambahkan buku baru ke katalog, sistem otomatis:
1. Mengecek: "Apakah format ISBN benar?" (test)
2. Mengecek: "Apakah judul tidak duplikat?" (static analysis)
3. Mengecek: "Apakah kategori tersedia?" (coverage)
4. Jika semua lolos → buku masuk katalog

**CD (Continuous Deployment):**
Setelah buku lolos QC, sistem otomatis:
1. Mencetak label buku
2. Menempatkan di rak yang benar
3. Mengupdate katalog online
4. Tanpa campur tangan manusia

**Tanpa CI/CD:**
```
Push kode → lupa test → error di production → panic → fix manual
```

**Dengan CI/CD:**
```
Push kode → otomatis test → otomatis deploy → production aman
```

## Dipakai untuk Apa

- **Setiap project yang serius** — tim > 1 orang
- **Production app** — jaminan kualitas sebelum deploy
- **Open source** — kontributor dari luar, CI menjaga kualitas
- **Regulatory compliance** — audit trail: "siapa deploy kapan?"

## Kesalahan Umum

1. **Workflow terlalu kompleks** — mulai sederhana (test saja), tambah deploy nanti
2. **Secrets tidak di-set** — workflow gagal karena tidak bisa SSH ke server
3. **Lupa cache Composer** — setiap workflow download vendor dari nol (lama)
4. **Test butuh service yang tidak tersedia** — MySQL/Redis harus di-setup di `services`
5. **Deploy gagal karena permission** — pastikan user SSH punya akses ke folder project
6. **Migrasi di production tanpa backup** — tambahkan backup sebelum migrate
7. **Test coverage terlalu rendah** — jangan set `--min=90` jika proyek masih baru

## Koneksi dengan Materi Sebelumnya

Poin 35-36 (Testing) adalah fondasi CI — test dijalankan otomatis. Poin 40 (Deployment) adalah yang diotomatisasi CD. Tanpa testing, CI/CD tidak berguna.

**Benang merah ke depan:**
- Poin 42 (Monitoring): Setelah deploy, pantau aplikasi
- Seluruh Level 7: CI/CD adalah puncak dari arsitektur yang matang

## Soal Latihan

1. **Praktik**: Buat workflow GitHub Actions sederhana yang menjalankan `php artisan test` setiap ada push!
2. **Praktik**: Tambahkan job deploy ke workflow, hanya jika test lulus dan push ke branch main!
3. **Analisis**: Mengapa cache Composer penting dalam workflow GitHub Actions? Apa yang terjadi tanpa cache?

<summary>Jawaban</summary>

1. **Workflow sederhana:**
   ```yaml
   # .github/workflows/test.yml
   name: Tests
   on: [push]
   jobs:
     test:
       runs-on: ubuntu-latest
       steps:
         - uses: actions/checkout@v4
         - uses: shivammathur/setup-php@v2
           with: { php-version: '8.3' }
         - run: composer install
         - run: php artisan test
   ```

2. **Deploy job:**
   ```yaml
   deploy:
     needs: test
     if: github.ref == 'refs/heads/main'
     runs-on: ubuntu-latest
     steps:
       - uses: appleboy/ssh-action@v1
         with:
           host: ${{ secrets.SERVER_HOST }}
           username: ${{ secrets.SERVER_USER }}
           key: ${{ secrets.SERVER_SSH_KEY }}
           script: |
             cd /var/www/perpustakaan
             git pull
             composer install --no-dev
             php artisan migrate --force
             php artisan optimize
   ```

3. **Pentingnya cache Composer:**
   - Tanpa cache: setiap workflow download vendor (~50MB+) dari awal → 2-3 menit
   - Dengan cache: hanya download package baru → 10-30 detik
   - Menghemat waktu dan resource GitHub Actions (batasan kuota)
