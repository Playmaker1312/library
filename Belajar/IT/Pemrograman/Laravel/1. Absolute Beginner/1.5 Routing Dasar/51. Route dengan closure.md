# 51. Route dengan closure

## Definisi Singkat
Route dapat didefinisikan langsung dengan Closure (fungsi anonim) tanpa controller — cocok untuk endpoint sederhana atau prototyping cepat.

## Analogi
Seperti warung pinggir jalan — Anda bisa langsung beli tanpa perlu toko formal (controller). Cocok untuk "jajan" cepat, bukan untuk bisnis besar.

## Poin-Poin Penting
- Sintaks: `Route::get('/path', function () { ... })`
- Tidak ada controller terpisah — logika ditulis langsung di route
- Cocok untuk: halaman statis, redirect, testing, prototyping
- **Tidak disarankan untuk proyek besar** — kode jadi sulit di-test dan di-maintain
- Masih bisa inject dependency: `Route::get('/', function (Request $request) { ... })`
- Bisa return view, JSON, redirect, atau string
- Closure tidak bisa di-cache oleh `route:cache` — pertimbangan performa
- Best practice: gunakan controller untuk logika bisnis; closure hanya untuk route sederhana

## Contoh Kode
```php
// Route Closure — return string
Route::get('/waktu', function () {
    return 'Sekarang: ' . now()->format('H:i:s');
});

// Route Closure — return view
Route::get('/', function () {
    return view('welcome');
});

// Route Closure — redirect
Route::get('/home', function () {
    return redirect('/dashboard');
});

// Route Closure — JSON response
Route::get('/api/health', function () {
    return response()->json([
        'status' => 'ok',
        'time' => now(),
    ]);
});

// Route Closure dengan Request
Route::post('/greet', function (Request $request) {
    $name = $request->input('name', 'Tamu');
    return "Halo, {$name}!";
});
```

## Kasus Penggunaan Nyata
Halaman "About Us" yang statis — cukup satu route dengan Closure return view: `Route::get('/about', fn() => view('pages.about'))` tanpa perlu controller.
