# 241. Middleware can route

## Definisi Singkat
Middleware `can` memungkinkan proteksi route di level routing dengan memeriksa Gate/Policy sebelum Controller dijalankan.

## Analogi
Seperti satpam di pintu lift — sebelum Anda naik ke lantai tujuan, ia periksa dulu apakah Anda punya akses ke lantai itu.

## Poin-Poin Penting
- Format: `->middleware('can:aksi,model')`
- Model bisa di-binding otomatis dari route parameter
- Jika tidak diizinkan, langsung lempar 403
- Lebih deklaratif daripada mengecek di Controller
- Bisa untuk aksi tanpa model: `->middleware('can:admin')`

## Contoh Kode
```php
<?php

use App\Models\Post;
use Illuminate\Support\Facades\Route;

// Proteksi aksi spesifik di route
Route::put('/posts/{post}', function (Post $post) {
    // update post
})->middleware('can:update,post');

// Atau pake controller
Route::put('/posts/{post}', [PostController::class, 'update'])
    ->middleware('can:update,post');

// Aksi tanpa model — Gate 'admin'
Route::get('/admin', [AdminController::class, 'index'])
    ->middleware('can:admin');

// Group dengan middleware can
Route::prefix('/admin')->middleware('can:admin')->group(function () {
    Route::resource('users', AdminUserController::class);
});

// Multiple middleware
Route::delete('/posts/{post}', [PostController::class, 'destroy'])
    ->middleware(['auth', 'can:delete,post']);

// Middleware can di route model binding
Route::get('/posts/{post}/edit', function (Post $post) {
    return view('posts.edit', compact('post'));
})->middleware('can:update,post');
```

## Kasus Penggunaan Nyata
Proteksi route di level routing tanpa perlu kode berulang di Controller, proteksi group route admin, dan pembatasan akses API endpoint.
