# 253. Middleware Pipeline Urutan Eksekusi

## Definisi Singkat
Middleware dijalankan dalam urutan pipeline: global → group → route. Request melewati setiap middleware sebelum ke Controller, lalu response melewatinya lagi dalam urutan terbalik.

## Analogi
Seperti jalur produksi di pabrik: barang (request) melewati mesin A, B, C (dalam urutan), lalu setelah diproses (Controller), barang jadi (response) melewati mesin C, B, A (urutan terbalik) untuk finishing.

## Poin-Poin Penting
- Urutan eksekusi: Global → Group → Route-specific
- `$next($request)` menyerahkan kontrol ke middleware berikutnya
- Setelah Controller selesai, response kembali naik ke middleware sebelumnya
- Middleware yang ditambahkan pertama dieksekusi pertama (sebelum controller)
- Urutan global ditentukan di `bootstrap/app.php`

## Contoh Kode
```php
<?php
// bootstrap/app.php — urutan middleware global
->withMiddleware(function (Middleware $middleware) {
    $middleware->append([
        \App\Http\Middleware\LogRequest::class,       // 1. Log request masuk
        \App\Http\Middleware\TrimStrings::class,       // 2. Trim input
        \App\Http\Middleware\TrustProxies::class,      // 3. Trust proxy
    ]);
})
```

```php
<?php
// Ilustrasi pipeline
// Request masuk:
//   1. Global middleware (urutan atas ke bawah)
//   2. Group middleware (web/api)
//   3. Route middleware
//   4. Controller → kembalikan Response
//   5. Route middleware (urutan terbalik)
//   6. Group middleware (urutan terbalik)
//   7. Global middleware (urutan terbalik)
// Response keluar

Route::get('/contoh', function () {
    return response('Hello');
})->middleware(['auth', 'verified']);
// Urutan: global → web group → auth → verified → Controller
// Lalu: verified → auth → web group → global → response
```

## Kasus Penggunaan Nyata
Memahami urutan middleware penting saat debugging, menambahkan middleware logging, dan mengatur middleware yang harus dijalankan sebelum/sesudah middleware lain.
