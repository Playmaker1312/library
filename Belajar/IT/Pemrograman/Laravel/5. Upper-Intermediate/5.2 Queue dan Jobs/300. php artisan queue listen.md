# 300. php artisan queue listen

## Definisi Singkat
`php artisan queue:listen` adalah perintah alternatif untuk menjalankan queue worker — bedanya, listen me-restart PHP process setiap kali menjalankan job (lebih aman untuk memory leak), tapi lebih lambat dari `queue:work`.

## Analogi
`queue:work` seperti chef tetap di dapur — terus masak tanpa istirahat. `queue:listen` seperti chef yang keluar-masuk dapur — cuci tangan setiap habis masak, lebih higienis (anti memory leak), tapi lebih lambat.

## Poin-Poin Penting
- `listen` me-restart framework setiap job — lebih aman, lebih lambat
- `work` lebih cepat (tidak reload framework) — rentan memory leak
- `listen` cocok untuk development / shared hosting
- `work` cocok untuk production dengan Supervisor
- Semua opsi (`--queue`, `--tries`, `--timeout`) sama dengan `work`

## Contoh Kode
```bash
# Basic listener
php artisan queue:listen

# Listen dengan queue spesifik
php artisan queue:listen database --queue=emails

# Listen dengan tries dan timeout
php artisan queue:listen database --tries=5 --timeout=120

# Listen dengan delay antar job
php artisan queue:listen redis --sleep=2

# Output lebih detail
php artisan queue:listen --verbose

# Perbandingan:
# queue:work  — 1 process, handle banyak job, cepat
# queue:listen — 1 process per job, lambat, aman memory

# Contoh when to use:
# Development  → queue:listen atau queue:work
# Shared hosting → queue:listen (sering ada memory limit)
# Production (VPS) → queue:work + Supervisor
```

```php
// Perbedaan implementasi di kernel
// queue:work
// - Loop terus dalam 1 process
// - Tidak boot Laravel lagi per job
// - Memory usage naik seiring waktu

// queue:listen
// - Jalankan php artisan queue:work sebagai sub-process
// - Boot Laravel baru setiap job
// - Memory usage stabil karena process restart
```

## Kasus Penggunaan Nyata
Shared hosting murah: tidak bisa install Supervisor, memory limit kecil — `queue:listen` dengan cron job setiap menit memastikan queue tetap diproses tanpa memory leak.
