# 302. Job timeout

## Definisi Singkat
Job timeout adalah batas waktu maksimal yang diizinkan untuk satu job dieksekusi — jika job melebihi batas, worker akan menganggap job gagal dan me-retry atau mem-fail-kannya.

## Analogi
Seperti batas waktu ujian: jika dalam 60 menit kamu belum selesai (job timeout), pengawas akan mengambil kertasmu dan menyatakan kamu tidak lulus (job failed), meskipun hampir selesai.

## Poin-Poin Penting
- `public $timeout = 120;` — di class job (per-job config dalam detik)
- `--timeout=60` — di Artisan command (harus selalu lebih besar dari job tertinggi)
- Timeout di CLI harus 5-10 detik lebih besar dari $timeout job terbesar
- Jika tidak set, default 60 detik
- Gunakan untuk mencegah job menggantung selamanya

## Contoh Kode
```php
// Setting timeout di job class
class GenerateReport implements ShouldQueue
{
    // Job ini butuh waktu hingga 10 menit
    public $timeout = 600;

    public function handle(ReportService $report): void
    {
        $report->generate($this->order);
    }
}

class SendEmail implements ShouldQueue
{
    // Email cepat — timeout 30 detik cukup
    public $timeout = 30;

    public function handle(): void
    {
        Mail::send(new WelcomeEmail($this->user));
    }
}

class ProcessImage implements ShouldQueue
{
    // ProcessImage bisa lama tergantung ukuran
    public $timeout = 300;
    public $tries = 2;

    public function handle(): void
    {
        // Resize high-res image...
    }
}

// PENTING: --timeout di Artisan harus lebih besar
// php artisan queue:work redis --timeout=610
// --timeout (610) > $timeout job (600)
// Jika --timeout = 300, job GenerateReport akan di-kill pukul 5 menit!

// Juga bisa set di config queue.php
'redis' => [
    'driver' => 'redis',
    'retry_after' => 600,  // Waktu tunggu sebelum job dikembalikan ke queue
    // retry_after harus > timeout terbesar
],
```

## Kasus Penggunaan Nyata
Job `GenerateVideoThumbnail`: ukuran video bisa 1GB — set `$timeout = 900` (15 menit) dengan `php artisan queue:work --timeout=920` untuk memastikan proses tidak di-kill sebelum selesai.
