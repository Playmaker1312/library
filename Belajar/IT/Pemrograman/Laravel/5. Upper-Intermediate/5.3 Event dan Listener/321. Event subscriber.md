# 321. Event subscriber

## Definisi Singkat
Event subscriber adalah class yang bisa mendengarkan multiple event sekaligus dalam satu class — menggunakan method `subscribe()` yang mendaftarkan event handler secara terprogram.

## Analogi
Seperti satpam gedung: dia menangani banyak kejadian — kebakaran (call pemadam), banjir (call pipa), maling (call polisi). Semua keahlian ada dalam satu orang (subscriber), bukan banyak orang terpisah (listener individu).

## Poin-Poin Penting
- Class subscriber punya method `subscribe(Dispatcher $events)`
- Di dalamnya, panggil `$events->listen(Event::class, 'methodName')`
- Didaftarkan via `$subscribe` array di `EventServiceProvider`
- Bisa mengelompokkan logika yang terkait (misalnya: semua event user)
- Alternatif lebih terorganisir dibanding banyak listener kecil

## Contoh Kode
```php
// app/Subscribers/UserEventSubscriber.php
namespace App\Subscribers;

use App\Events\UserDeleted;
use App\Events\UserRegistered;
use App\Events\UserUpdated;
use Illuminate\Events\Dispatcher;

class UserEventSubscriber
{
    // Handler untuk UserRegistered
    public function handleUserRegistered(UserRegistered $event): void
    {
        // Kirim email, buat workspace, dll
    }

    // Handler untuk UserUpdated
    public function handleUserUpdated(UserUpdated $event): void
    {
        // Log perubahan, sync ke CRM
    }

    // Handler untuk UserDeleted
    public function handleUserDeleted(UserDeleted $event): void
    {
        // Cleanup data, notify admin
    }

    // Method subscribe — daftarkan semua event + handler
    public function subscribe(Dispatcher $events): void
    {
        $events->listen(
            UserRegistered::class,
            [self::class, 'handleUserRegistered']
        );

        $events->listen(
            UserUpdated::class,
            [self::class, 'handleUserUpdated']
        );

        $events->listen(
            UserDeleted::class,
            [self::class, 'handleUserDeleted']
        );
    }
}

// app/Subscribers/OrderEventSubscriber.php
class OrderEventSubscriber
{
    public function subscribe(Dispatcher $events): void
    {
        $events->listen(OrderPlaced::class, [self::class, 'onOrderPlaced']);
        $events->listen(OrderShipped::class, [self::class, 'onOrderShipped']);
        $events->listen(OrderCancelled::class, [self::class, 'onOrderCancelled']);
    }

    public function onOrderPlaced(OrderPlaced $event): void { /* ... */ }
    public function onOrderShipped(OrderShipped $event): void { /* ... */ }
    public function onOrderCancelled(OrderCancelled $event): void { /* ... */ }
}

// Daftarkan subscriber di EventServiceProvider
// app/Providers/EventServiceProvider.php
protected $subscribe = [
    UserEventSubscriber::class,
    OrderEventSubscriber::class,
];
```

## Kasus Penggunaan Nyata
Module "Audit Trail": `AuditSubscriber` menangani `Created`, `Updated`, `Deleted`, `Restored` untuk semua model — mencatat perubahan ke tabel audit dengan user, timestamp, dan old/new values.
