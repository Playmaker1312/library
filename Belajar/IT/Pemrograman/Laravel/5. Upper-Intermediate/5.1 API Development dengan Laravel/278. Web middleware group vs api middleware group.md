# 278. Web middleware group vs api middleware group

## Definisi Singkat
Laravel membagi middleware ke dalam dua grup default: `web` (dengan session, CSRF, cookie) untuk aplikasi browser, dan `api` (tanpa session, ringan, throttle) untuk API stateless.

## Analogi
`web` seperti restoran fine dining — ada pramusaji, tata cara, identitas tamu. `api` seperti mesin kopi otomatis — cepat, tanpa basa-basi, token sebagai pengganti identitas.

## Poin-Poin Penting
- `web`: StartSession, EncryptCookies, VerifyCsrfToken, SubstituteBindings
- `api`: SubstituteBindings, throttle:api (rate limiter)
- `web` menyimpan state session, `api` tidak menyimpan state sama sekali
- `api` lebih ringan dan cepat karena middleware lebih sedikit
- Error handling tetap sama, format response JSON bisa diseragamkan

## Contoh Kode
```php
// app/Http/Kernel.php
protected $middlewareGroups = [
    'web' => [
        \App\Http\Middleware\EncryptCookies::class,
        \Illuminate\Cookie\Middleware\AddQueuedCookiesToResponse::class,
        \Illuminate\Session\Middleware\StartSession::class,
        \Illuminate\View\Middleware\ShareErrorsFromSession::class,
        \App\Http\Middleware\VerifyCsrfToken::class,
        \Illuminate\Routing\Middleware\SubstituteBindings::class,
    ],

    'api' => [
        \Illuminate\Routing\Middleware\SubstituteBindings::class,
        'throttle:api',
    ],
];

// Perbedaan response error
// web: redirect ke halaman error atau login
// api: JSON response dengan status code
app/Exceptions/Handler.php
public function render($request, Exception $e)
{
    if ($request->expectsJson() || $request->is('api/*')) {
        return response()->json([
            'message' => $e->getMessage(),
        ], $e->getStatusCode());
    }
    return parent::render($request, $e);
}
```

## Kasus Penggunaan Nyata
SaaS platform: route `web.php` untuk halaman admin Blade, route `api.php` untuk mobile app dan integrasi third-party — keduanya berbagi database yang sama.
