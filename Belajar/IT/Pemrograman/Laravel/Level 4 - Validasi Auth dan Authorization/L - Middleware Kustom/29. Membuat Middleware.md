# 29. Membuat Middleware — Logic yang Berjalan Sebelum Controller

## Penjelasan

**Middleware kustom** adalah filter yang kamu buat sendiri untuk kebutuhan spesifik. Middleware berjalan sebelum request mencapai controller — cocok untuk:
- Cek status anggota (aktif/nonaktif)
- Cek role user
- Logging aktivitas
- Maintenance mode spesifik
- Rate limiting kustom

```bash
php artisan make:middleware CekStatusAnggota
php artisan make:middleware LogAktivitas
php artisan make:middleware CekRole
```

## Fungsi

- Menambahkan logika yang berjalan SEBELUM controller
- Memfilter request berdasarkan kondisi tertentu (role, status, IP)
- Menambahkan header atau log di setiap request
- Memotong request jika tidak memenuhi syarat

## Cara Pengimplementasian

```php
<?php
// app/Http/Middleware/CekStatusAnggota.php

namespace App\Http\Middleware;

use Closure;
use Illuminate\Http\Request;
use Symfony\Component\HttpFoundation\Response;

class CekStatusAnggota
{
    public function handle(Request $request, Closure $next): Response
    {
        // Cek apakah user login dan statusnya aktif
        if (auth()->check() && auth()->user()->status !== 'aktif') {
            auth()->logout();
            return redirect()
                ->route('login')
                ->with('error', 'Akun Anda tidak aktif. Hubungi pustakawan.');
        }

        return $next($request); // lanjut ke controller
    }
}

// app/Http/Middleware/CekRole.php
class CekRole
{
    public function handle(Request $request, Closure $next, string ...$roles): Response
    {
        if (!auth()->check() || !in_array(auth()->user()->role, $roles)) {
            abort(403, 'Anda tidak memiliki izin.');
        }

        return $next($request);
    }
}

// app/Http/Middleware/LogAktivitas.php
class LogAktivitas
{
    public function handle(Request $request, Closure $next): Response
    {
        $mulai = microtime(true);

        $response = $next($request);  // proses controller

        $durasi = microtime(true) - $mulai;

        Log::info('Aktivitas', [
            'user'   => auth()->id(),
            'method' => $request->method(),
            'path'   => $request->path(),
            'status' => $response->getStatusCode(),
            'durasi' => round($durasi * 1000, 2) . 'ms',
        ]);

        return $response;
    }
}
```

```php
<?php
// bootstrap/app.php — daftarkan middleware (Laravel 11)

return Application::configure(basePath: dirname(__DIR__))
    ->withMiddleware(function (Middleware $middleware) {
        // Global middleware — semua request
        $middleware->append(LogAktivitas::class);

        // Alias — untuk dipakai di route
        $middleware->alias([
            'anggota.aktif' => CekStatusAnggota::class,
            'role'          => CekRole::class,
        ]);

        // Group middleware
        $middleware->appendToGroup('web', [
            CekStatusAnggota::class,
        ]);
    })
    ->create();
```

```php
<?php
// routes/web.php — pakai middleware alias

// Middleware dengan parameter role
Route::middleware(['auth', 'role:admin'])->group(function () {
    Route::get('/admin/dashboard', [AdminController::class, 'dashboard']);
    Route::resource('buku', Admin\BukuController::class);
});

// Middleware tanpa parameter
Route::middleware(['auth', 'anggota.aktif'])->group(function () {
    Route::post('/pinjam', [PeminjamanController::class, 'store']);
    Route::get('/profil', [ProfilController::class, 'show']);
});
```

## Analogi

Middleware kustom seperti **petugas keamanan tambahan di perpustakaan**:

- **`CekStatusAnggota`** = Petugas di pintu yang mengecek "Apakah kartu anggota masih berlaku?" — jika sudah expired, pengunjung diminta perpanjang

- **`CekRole`** = Petugas yang mengecek "Apakah kamu staf?" — hanya staf yang boleh masuk ke ruang administrasi

- **`LogAktivitas`** = CCTV yang mencatat setiap pengunjung yang masuk: "Jam 10.00, Pak Budi masuk ke ruang buku. Durasi: 5 menit."

**Alur request dengan middleware:**
```
Request → LogAktivitas (catat waktu) → CekStatus (aktif?) → CekRole (admin?) → Controller → Response
```

Setiap middleware bisa menghentikan request (return redirect/abort) atau melanjutkan (`$next($request)`).

**Middleware sebelum dan sesudah:**
- Sebelum controller: `CekRole`, `CekStatus`, `auth`
- Sesudah controller: `LogAktivitas` (mencatat durasi setelah response selesai)

## Dipakai untuk Apa

- **Role-based access** — middleware `role:admin`, `role:pustakawan`
- **Feature flag** — middleware `fitur:baru` untuk fitur yang baru rilis
- **Logging** — mencatat request, durasi, user
- **Maintenance** — redirect ke halaman maintenance
- **Throttle kustom** — batasi akses per user

## Kesalahan Umum

1. **Lupa daftarkan middleware** — error "Target class [CekRole] does not exist." — daftarkan di `bootstrap/app.php`
2. **Tidak return `$next($request)`** — aplikasi menggantung (tidak ada response)
3. **Tidak return redirect/abort jika gagal** — request tetap lanjut meski tidak memenuhi syarat
4. **Parameter middleware salah** — di route: `role:admin,pustakawan` → di handle: `string ...$roles` (array)
5. **Middleware terlalu berat** — jangan query database berat di middleware — ini berjalan di SETIAP request
6. **Lupa `auth()->check()` sebelum akses user** — error jika user belum login

## Koneksi dengan Materi Sebelumnya

Poin 27 (Middleware Auth) adalah middleware bawaan. Sekarang kamu tahu cara membuat middleware sendiri untuk kebutuhan spesifik. Policy (poin 28) mengatur otorisasi per resource; middleware role mengatur akses per area.

**Benang merah ke depan:**
- Poin 35 (Testing): Middleware bisa di-test dengan `$this->assertGuest()` atau `$response->assertForbidden()`
- Poin 40 (Deployment): LogAktivitas middleware membantu monitoring di production

## Soal Latihan

1. **Praktik**: Buat middleware `CekRole` yang menerima parameter role dan abort 403 jika role tidak cocok!
2. **Praktik**: Daftarkan middleware tersebut dengan alias `role` dan gunakan di route admin!
3. **Analisis**: Apa perbedaan middleware yang berjalan SEBELUM vs SESUDAH controller? Berikan contoh masing-masing!

3. **Perbedaan:**
   - **Sebelum controller** — memeriksa kondisi sebelum eksekusi. Contoh: `CekRole` (jika bukan admin, tolak sebelum controller jalan), `auth` (cek login)
   - **Sesudah controller** — memproses response setelah controller selesai. Contoh: `LogAktivitas` (mencatat durasi setelah response), menambahkan header
   - Eksekusi: `$next($request)` di middleware sebelum akan memanggil controller, sedangkan di middleware sesudah, response ditangkap setelah `$next($request)` selesai
