# 416. Memahami Konsep Microservices dan Kapan Menggunakannya dalam Ecosystem Laravel

## Definisi & Target
Memahami arsitektur microservices: definisi, karakteristik, perbedaan dengan monolitik, kelebihan dan kekurangan, serta kapan tepat menggunakan microservices dalam proyek Laravel. Targetnya adalah mampu memutuskan kapan harus split menjadi microservices.

## Komponen yang Terlibat
- Monolithic vs Microservices architecture
- Service decomposition patterns
- Domain-Driven Design (DDD)
- Bounded Context
- Inter-service communication
- API Gateway pattern
- Database per service
- Eventual consistency
- CI/CD pipeline
- Containerization (Docker)

## Kode Implementasi (Per File)

### Architecture Decision Record
```php
<?php
// docs/architecture/microservices-adr.md
/*
# ADR-001: Microservices Architecture

## Context
Aplikasi e-commerce berkembang pesat. Tim development 15+ orang.
Monolitik mulai sulit di-maintain karena:
- Deployment bottleneck (semua fitur deploy bersamaan)
- Scaling tidak efisien (bagian berat diskalakan semua)
- Codebase terlalu besar (500+ model)
- Teknologi coupling (harus pakai stack yang sama)

## Decision
Mengadopsi microservices architecture:
- Split per bounded context (DDD)
- Setiap service punya database sendiri
- API Gateway sebagai single entry point
- Event-driven untuk komunikasi antar service
- Setiap service bisa pakai stack berbeda

## Consequences
### Positive
- Tim bisa bekerja independen
- Scaling per service
- Isolasi fault
- Teknologi diversity
- Deployment independen

### Negative
- Kompleksitas distributed system
- Network latency
- Data consistency challenges
- Operational overhead
- Testing lebih kompleks
*/
```

### Monolithic vs Microservices Comparison
```php
<?php
// app/Console/Commands/ArchitectureComparison.php
/*
## Perbandingan Arsitektur

| Aspek | Monolithic | Microservices |
|-------|-----------|---------------|
| Deployment | 1 unit deploy | Banyak service deploy |
| Scalability | Vertical (semua) | Horizontal (per service) |
| Development | Satu codebase besar | Banyak repo kecil |
| Team autonomy | Rendah | Tinggi |
| Testing | End-to-end sederhana | Contract & integration |
| Performance | Internal calls (cepat) | Network calls (lambat) |
| Data consistency | Strong (ACID) | Eventual consistency |
| Complexity | Low code, high deployment | High code, low deployment |
| Fault isolation | Poor (1 bug = semua down) | Good (isolated per service) |
| Technology | Homogen | Heterogen |

## Kapan Microservices Tepat
1. Tim > 10 orang
2. Domain kompleks dengan bounded context jelas
3. Skalabilitas berbeda per fitur
4. Siklus rilis berbeda antar fitur
5. Teknologi diversity diperlukan
6. Organisasi mengikuti Conway's Law

## Kapan Tetap Monolitik
1. Tim kecil (< 5 orang)
2. MVP / Early stage
3. Domain sederhana
4. Performance critical (internal call > network)
5. Tim belum berpengalaman distributed system
6. Budget terbatas untuk infrastruktur
*/
```

### Anti-Corruption Layer Pattern
```php
<?php
namespace App\Services;

class AntiCorruptionLayer
{
    public function translateProductFromExternal(array $externalProduct): array
    {
        return [
            'id' => $externalProduct['product_id'],
            'name' => $externalProduct['title'],
            'price' => (int) ($externalProduct['amount'] * 100),
            'stock' => $externalProduct['inventory']['qty'],
            'is_active' => $externalProduct['status'] === 'active',
        ];
    }

    public function translateUserToExternal(array $internalUser): array
    {
        return [
            'user_id' => $internalUser['id'],
            'email' => $internalUser['email'],
            'full_name' => $internalUser['name'],
            'created_at' => $internalUser['created_at']->toISOString(),
        ];
    }
}
```

## Cara Integrasi & Pengujian
1. Pahami konsep bounded context dalam domain aplikasi
2. Identifikasi service boundaries
3. Buat ADR untuk setiap keputusan arsitektur
4. Tentukan communication pattern (sync/async)
5. Setup repository per service
6. Tentukan database strategy per service
7. Buat API contract specification (OpenAPI)
8. Setup CI/CD pipeline per service
9. Implementasi API Gateway
10. Test komunikasi antar service
