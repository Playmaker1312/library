# 401. Memahami Konsep Real-Time Communication dan Pilihan Teknologi dalam Laravel

## Definisi & Target
Memahami konsep real-time communication dalam Laravel: WebSocket, Server-Sent Events (SSE), Long Polling, dan pilihan teknologi seperti Laravel Reverb, Pusher, Soketi, dan Laravel Echo. Targetnya adalah memahami kapan dan bagaimana memilih teknologi yang tepat.

## Komponen yang Terlibat
- WebSocket protocol vs HTTP
- Laravel Broadcasting system
- Laravel Reverb (native WebSocket)
- Pusher (third-party service)
- Soketi (self-hosted Pusher alternative)
- Laravel Echo (JavaScript client)
- Laravel Livewire (real-time via HTTP)

## Perintah Artisan CLI
```bash
# Install broadcasting
php artisan install:broadcasting

# Install Reverb
composer require laravel/reverb

# Install Echo + Pusher (frontend)
npm install --save-dev laravel-echo pusher-js
```

### Technology Comparison
```php
<?php
// resources/views/docs/realtime-comparison.blade.php
/*
## Perbandingan Teknologi

| Fitur | Reverb | Pusher | Soketi | SSE | Long Polling |
|-------|--------|--------|--------|-----|--------------|
| Biaya | Gratis | Berbayar | Gratis | Gratis | Gratis |
| Hosting | Self-hosted | Cloud | Self-hosted | Built-in | Built-in |
| Protocol | WebSocket | WebSocket | WebSocket | HTTP | HTTP |
| Scalability | Horizontal | Auto | Horizontal | Terbatas | Terbatas |
| Laravel Support | Native | Native | Via Pusher | Manual | Manual |
| Private Channels | Ya | Ya | Ya | Manual | Manual |
| Presence Channels | Ya | Ya | Ya | Tidak | Tidak |
| Setup Complexity | Medium | Mudah | Medium | Mudah | Mudah |

## Kapan Menggunakan Masing-Masing

### Laravel Reverb
- Aplikasi self-hosted
- Traffic menengah-tinggi
- Kontrol penuh atas infrastructure
- Budget terbatas (tidak ingin bayar Pusher)

### Pusher
- Quick setup, minimal maintenance
- Traffic rendah-menengah
- Tidak ingin manage server WebSocket
- Budget tersedia

### Soketi
- Self-hosted alternative ke Pusher
- API kompatibel dengan Pusher
- Perlu lebih banyak resource

### Server-Sent Events (SSE)
- One-way communication (server ke client)
- Notification feeds
- Simple implementation
- Tidak perlu WebSocket

### Long Polling
- Fallback ketika WebSocket tidak tersedia
- Legacy browser support
- Simple, reliable
- Lebih lambat, lebih banyak overhead
*/
```

### Laravel Echo Setup (Frontend)
```javascript
// resources/js/echo.js
import Echo from 'laravel-echo';
import Pusher from 'pusher-js';

window.Pusher = Pusher;

const echo = new Echo({
    broadcaster: 'reverb',
    key: import.meta.env.VITE_REVERB_APP_KEY,
    wsHost: import.meta.env.VITE_REVERB_HOST,
    wsPort: import.meta.env.VITE_REVERB_PORT ?? 8080,
    wssPort: import.meta.env.VITE_REVERB_PORT ?? 443,
    forceTLS: (import.meta.env.VITE_REVERB_SCHEME ?? 'https') === 'https',
    enabledTransports: ['ws', 'wss'],
});

export default echo;
```

### Event Example - OrderStatusUpdated
```php
<?php
namespace App\Events;

use App\Models\Order;
use Illuminate\Broadcasting\Channel;
use Illuminate\Broadcasting\InteractsWithSockets;
use Illuminate\Contracts\Broadcasting\ShouldBroadcast;
use Illuminate\Foundation\Events\Dispatchable;
use Illuminate\Queue\SerializesModels;

class OrderStatusUpdated implements ShouldBroadcast
{
    use Dispatchable, InteractsWithSockets, SerializesModels;

    public function __construct(
        public Order $order
    ) {}

    public function broadcastOn(): Channel
    {
        return new Channel('orders.' . $this->order->id);
    }

    public function broadcastAs(): string
    {
        return 'order.status.updated';
    }

    public function broadcastWith(): array
    {
        return [
            'id' => $this->order->id,
            'status' => $this->order->status,
            'updated_at' => $this->order->updated_at,
        ];
    }
}
```
