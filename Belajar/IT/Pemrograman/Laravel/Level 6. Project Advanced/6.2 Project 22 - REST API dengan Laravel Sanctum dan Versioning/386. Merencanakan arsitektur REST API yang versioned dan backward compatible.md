# 386. Merencanakan Arsitektur REST API yang Versioned dan Backward Compatible

## Definisi & Target
Merencanakan arsitektur REST API yang mendukung multiple versi secara simultan (v1, v2, dst) tanpa merusak klien lama. Backward compatibility dijamin dengan strategi versioning via URL prefix, deprecation headers, dan migration guide untuk klien. Targetnya adalah API yang stabil, predictable, dan mudah di-maintain.

## Komponen yang Terlibat
- Route Service Provider untuk versioning
- API version namespace strategy
- Request/Response version negotiation
- Deprecation policy
- API documentation versioning
- Transformers/Resources per versi

### Route Service Provider - ApiRouteServiceProvider
```php
<?php
namespace App\Providers;

use Illuminate\Cache\RateLimiting\Limit;
use Illuminate\Foundation\Support\Providers\RouteServiceProvider as ServiceProvider;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\RateLimiter;
use Illuminate\Support\Facades\Route;

class ApiRouteServiceProvider extends ServiceProvider
{
    public function boot(): void
    {
        $this->configureRateLimiting();

        $this->routes(function () {
            Route::middleware('api')
                ->prefix('api/v1')
                ->name('api.v1.')
                ->group(base_path('routes/api/v1.php'));

            Route::middleware('api')
                ->prefix('api/v2')
                ->name('api.v2.')
                ->group(base_path('routes/api/v2.php'));
        });
    }

    protected function configureRateLimiting(): void
    {
        RateLimiter::for('api', function (Request $request) {
            return Limit::perMinute(60)->by($request->user()?->id ?: $request->ip());
        });

        RateLimiter::for('auth', function (Request $request) {
            return Limit::perMinute(5)->by($request->ip());
        });
    }
}
```

### API Version Gate - helpers.php
```php
<?php
if (!function_exists('api_version')) {
    function api_version(): string
    {
        return request()->segment(2) ?? 'v1';
    }
}

if (!function_exists('api_resource_class')) {
    function api_resource_class(string $baseClass, string $version = null): string
    {
        $version = $version ?? api_version();
        $class = "App\\Http\\Resources\\" . strtoupper($version) . "\\{$baseClass}";

        if (!class_exists($class)) {
            $class = "App\\Http\\Resources\\V1\\{$baseClass}";
        }

        return $class;
    }
}
```

### Version Detection Middleware
```php
<?php
namespace App\Http\Middleware;

use Closure;
use Illuminate\Http\Request;
use Symfony\Component\HttpFoundation\Response;

class SetApiVersion
{
    public function handle(Request $request, Closure $next): Response
    {
        $version = $request->segment(2);

        if (!in_array($version, ['v1', 'v2'])) {
            $version = 'v1';
        }

        $request->attributes->set('api_version', $version);

        $acceptVersion = $request->header('Accept-Version', $version);
        $request->attributes->set('accept_version', $acceptVersion);

        return $next($request);
    }
}
```

### Backward Compatibility Strategy
```php
<?php
namespace App\Http\Middleware;

use Closure;
use Illuminate\Http\Request;
use Symfony\Component\HttpFoundation\Response;

class ApiDeprecationHeaders
{
    private array $deprecatedVersions = [
        'v1' => ['sunset' => '2025-06-01', 'migration' => 'docs/migrate-v2.md'],
    ];

    public function handle(Request $request, Closure $next): Response
    {
        $response = $next($request);
        $version = $request->attributes->get('api_version', 'v1');

        if (isset($this->deprecatedVersions[$version])) {
            $deprecation = $this->deprecatedVersions[$version];

            $response->header('X-API-Version', $version);
            $response->header('Sunset', $deprecation['sunset']);
            $response->header('Link', "<{$deprecation['migration']}>; rel=\"migration\"");
        } else {
            $response->header('X-API-Version', $version);
        }

        $response->header('X-API-Latest-Version', 'v2');

        return $response;
    }
}
```

### Route Files - routes/api/v1.php
```php
<?php
use Illuminate\Support\Facades\Route;
use App\Http\Controllers\Api\V1\AuthController;
use App\Http\Controllers\Api\V1\UserController;
use App\Http\Controllers\Api\V1\ProductController;

Route::post('/auth/login', [AuthController::class, 'login'])->name('auth.login');
Route::post('/auth/register', [AuthController::class, 'register'])->name('auth.register');

Route::middleware('auth:sanctum')->group(function () {
    Route::get('/user', [UserController::class, 'show'])->name('user.show');
    Route::put('/user', [UserController::class, 'update'])->name('user.update');

    Route::apiResource('products', ProductController::class);
});
```

## Cara Integrasi & Pengujian
1. Daftarkan ApiRouteServiceProvider di config/app.php
2. Buat minimal satu controller per versi untuk testing
3. Akses GET /api/v1/products dan GET /api/v2/products
4. Verifikasi response berbeda antar versi
5. Cek header X-API-Version dan Sunset di response v1
6. Test backward compatibility: klien v1 tetap berfungsi
7. Buat unit test untuk setiap version endpoint
8. Dokumentasikan migration guide untuk upgrade v1 ke v2
