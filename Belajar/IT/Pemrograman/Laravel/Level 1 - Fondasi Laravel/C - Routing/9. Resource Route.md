# 9. Resource Route — CRUD dengan Satu Baris

## Penjelasan

**Resource Route** adalah cara cepat untuk mendefinisikan 7 route CRUD (Create, Read, Update, Delete) standar hanya dengan satu baris kode. Ini mengikuti RESTful convention yang sudah menjadi standar di Laravel.

```php
Route::resource('buku', BukuController::class);

// Sama dengan menulis 7 route ini manual:
// GET    /buku              → BukuController@index   → nama: buku.index
// GET    /buku/create       → BukuController@create  → nama: buku.create
// POST   /buku              → BukuController@store   → nama: buku.store
// GET    /buku/{buku}       → BukuController@show    → nama: buku.show
// GET    /buku/{buku}/edit  → BukuController@edit    → nama: buku.edit
// PUT    /buku/{buku}       → BukuController@update  → nama: buku.update
// DELETE /buku/{buku}       → BukuController@destroy → nama: buku.destroy
```

## Fungsi

- Membuat 7 route CRUD dengan satu baris — lebih cepat dan konsisten
- Mengikuti RESTful convention yang sudah standar
- Named route otomatis dengan pola `{resource}.{action}`

## Cara Pengimplementasian

```php
<?php
// routes/web.php

// Resource route lengkap — 7 route
Route::resource('buku', BukuController::class);

// Sebagian route saja
Route::resource('buku', BukuController::class)
     ->only(['index', 'show']);      // hanya lihat daftar dan detail

Route::resource('buku', BukuController::class)
     ->except(['destroy']);          // semua kecuali hapus

// Nested resource (resource bersarang)
Route::resource('buku.peminjaman', PeminjamanController::class);
// Menghasilkan: /buku/{buku}/peminjaman, /buku/{buku}/peminjaman/create, dll.

// API resource — tanpa create() dan edit() (tidak perlu form HTML)
Route::apiResource('buku', Api\BukuController::class);
// Hanya: index, show, store, update, destroy — 5 route

// Resource dengan custom nama
Route::resource('buku', BukuController::class)
     ->names([
         'index'  => 'katalog',
         'show'   => 'detail',
     ]);
```

**Controller yang sesuai:**
```php
<?php
// app/Http/Controllers/BukuController.php — dibuat dengan --resource

class BukuController extends Controller
{
    public function index()     {} // GET /buku — daftar
    public function create()    {} // GET /buku/create — form tambah
    public function store()     {} // POST /buku — simpan
    public function show($id)   {} // GET /buku/{id} — detail
    public function edit($id)   {} // GET /buku/{id}/edit — form edit
    public function update($id) {} // PUT /buku/{id} — update
    public function destroy($id){} // DELETE /buku/{id} — hapus
}
```

```bash
# Lihat route yang dihasilkan
php artisan route:list --path=buku
```

## Analogi

Resource route seperti **menu paket perpustakaan**:

- `Route::resource('buku', BukuController)` = **Paket Lengkap**: 7 kegiatan (index → create → store → show → edit → update → destroy)
- `->only(['index', 'show'])` = **Paket Ekonomis**: hanya lihat daftar dan detail — tidak boleh menambah/mengubah/menghapus
- `->except(['destroy'])` = **Paket Sedang**: semua kegiatan kecuali menghapus

Bayangkan jika setiap kali ada pengunjung datang, kamu harus menulis 7 peraturan secara manual:
- "Kalau mau lihat daftar buku, ke meja sirkulasi"
- "Kalau mau tambah buku, ke meja sirkulasi dengan form"
- "Kalau mau simpan buku baru, POST ke meja sirkulasi"
- ...dan seterusnya

Dengan `Route::resource`, semua peraturan itu sudah otomatis. Tinggal bilang "ini resource buku" — Laravel sudah tahu 7 pola URL standarnya.

## Dipakai untuk Apa

- **Setiap resource CRUD** — buku, anggota, peminjaman, kategori — semuanya pakai resource route
- **API endpoints** — `apiResource()` untuk REST API
- **Admin panel** — route admin dengan resource untuk setiap model

## Kesalahan Umum

1. **Controller tidak memiliki method yang sesuai** — resource route expect 7 method, jika kurang akan error
2. **Lupa urutan route spesifik** — `Route::resource` otomatis mengatur urutan yang benar
3. **Mendaftarkan route resource untuk non-CRUD** — jika butuh custom action (misal: cetak laporan), tambahkan route manual di luar resource
4. **Menggunakan `Route::resource` untuk API tanpa `apiResource`** — `apiResource` lebih ringan (tanpa create/edit)
5. **Route binding nama parameter** — parameter default adalah `{buku}` (singular), bukan `{id}`

```php
// Method show dengan Route Model Binding:
public function show(Buku $buku) { ... } // bukan $id
```

1. **7 route yang dihasilkan:**
   ```
   GET|HEAD   /anggota              → index     → anggota.index
   GET|HEAD   /anggota/create       → create    → anggota.create
   POST       /anggota              → store     → anggota.store
   GET|HEAD   /anggota/{anggota}    → show      → anggota.show
   GET|HEAD   /anggota/{anggota}/edit → edit    → anggota.edit

   ```

2. **Perbedaan:**
   - `Route::resource` — membuat 7 route (termasuk `create` dan `edit` yang mengembalikan form HTML)
   - `Route::apiResource` — membuat 5 route (tanpa `create` dan `edit`) karena API biasanya tidak butuh form HTML
   - API resource juga tidak menambahkan middleware CSRF (karena API stateless)

3. **Nested resource:**
   ```php
   Route::resource('buku.peminjaman', PeminjamanController::class);
   ```
   URL yang dihasilkan:
   ```
   GET    /buku/{buku}/peminjaman              → index
   POST   /buku/{buku}/peminjaman              → store
   GET    /buku/{buku}/peminjaman/create       → create
   GET    /buku/{buku}/peminjaman/{peminjaman} → show
   ...
   ```
