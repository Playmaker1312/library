# 10. Route Group — Organisasi Route yang Rapi

## Penjelasan

**Route Group** adalah cara mengelompokkan route yang berbagi atribut yang sama — seperti prefix URL, middleware, atau prefix nama. Tanpa group, kamu harus menambahkan atribut yang sama ke setiap route satu per satu.

```php
// TANPA GROUP — repetitif
Route::get('/admin/dashboard', ...)->name('admin.dashboard');
Route::get('/admin/buku', ...)->name('admin.buku.index');
Route::get('/admin/anggota', ...)->name('admin.anggota.index');

// DENGAN GROUP — bersih dan rapi
Route::prefix('admin')->name('admin.')->group(function () {
    Route::get('/dashboard', ...)->name('dashboard');       // admin.dashboard
    Route::resource('buku', ...);                           // admin.buku.*
    Route::resource('anggota', ...);                        // admin.anggota.*
});
```

## Fungsi

- Mengelompokkan route dengan atribut yang sama — prefix, middleware, nama
- Mengurangi pengulangan kode (DRY)
- Memudahkan perubahan: edit di satu tempat, semua route terpengaruh
- Memisahkan area publik dan admin

## Cara Pengimplementasian

```php
<?php
// routes/web.php

// ─── GROUP DENGAN PREFIX ────────────────────────────────
Route::prefix('admin')->group(function () {
    Route::get('/', [DashboardController::class, 'index']);
    Route::resource('buku', Admin\BukuController::class);
    Route::resource('anggota', Admin\AnggotaController::class);
});
// URL yang dihasilkan: /admin, /admin/buku, /admin/anggota

// ─── GROUP DENGAN MIDDLEWARE ────────────────────────────
Route::middleware(['auth'])->group(function () {
    Route::get('/profil', [ProfilController::class, 'show']);
    Route::put('/profil', [ProfilController::class, 'update']);
    Route::get('/pinjam/{buku}', [PeminjamanController::class, 'create']);
});

// ─── GROUP DENGAN NAMA ──────────────────────────────────
Route::name('admin.')->prefix('admin')->group(function () {
    Route::get('/dashboard', ...)->name('dashboard');
    // Nama lengkap: 'admin.dashboard'
});

// ─── GABUNGAN MULTIPLE ATRIBUT ─────────────────────────
Route::prefix('admin')
     ->middleware(['auth', 'role:admin'])
     ->name('admin.')
     ->group(function () {
         Route::get('/dashboard', [DashboardController::class, 'index'])
              ->name('dashboard');

         Route::resource('buku', Admin\BukuController::class);
         // Route: admin.buku.index, admin.buku.show, ...
     });

// ─── NESTED GROUP ───────────────────────────────────────
Route::prefix('api')->middleware('api')->group(function () {
    Route::prefix('v1')->name('v1.')->group(function () {
        Route::apiResource('buku', Api\V1\BukuController::class);
        Route::apiResource('anggota', Api\V1\AnggotaController::class);
    });
});
// URL: /api/v1/buku, /api/v1/anggota
```

## Analogi

Route group seperti **pengelompokan rak buku di perpustakaan**:

- **Prefix `admin/`** = Lantai 2 khusus petugas — semua route admin ada di sini
- **Middleware `auth`** = Hanya pengunjung yang punya kartu anggota — semua route di dalamnya butuh login
- **Name `admin.`** = Label kode untuk rak: `admin.buku`, `admin.anggota`, `admin.dashboard`

Tanpa pengelompokan, papan petunjuk perpustakaan akan kacau:
```
/lihat-buku               → tidak jelas
/data-anggota             → campur aduk
/kelola-buku              → bingung
/admin/anggota            → jelas: bagian admin, urusan anggota
/admin/buku               → jelas: bagian admin, urusan buku
```

Group membuat route lebih terstruktur dan mudah dimengerti.

## Dipakai untuk Apa

- **Admin panel** — semua route admin dengan prefix `admin/` dan middleware `auth`
- **API versioning** — `/api/v1/`, `/api/v2/`
- **Area publik vs terproteksi** — route publik tanpa middleware, route terproteksi dengan `auth`
- **Multi-role** — route untuk role admin, route untuk role petugas

## Kesalahan Umum

1. **Terlalu banyak nested group** — 3-4 level masih ok, lebih dari itu sulit dibaca
2. **Lupa `name()` di route group** — nama otomatis tidak ditambahkan prefix
3. **Middleware di group vs di route individual** — aturan group berlaku untuk semua; jika ada route yang perlu middleware berbeda, tempatkan di luar group
4. **Prefix dan name tidak konsisten** — jika prefix `admin` seharusnya name prefix juga `admin.`
5. **Route tanpa group untuk area yang sama** — 5 route admin ditulis manual tanpa group → sulit di-maintain

## Koneksi dengan Materi Sebelumnya

Poin 7, 8, 9 sudah membahas route dasar, named route, dan resource route. Route group adalah cara mengorganisir semua route tersebut. Setelah memahami resource route, group membantu mengelompokkan beberapa resource.

**Benang merah ke depan:**
- Poin 14 (Controller): Controller di dalam group bisa diorganisir dalam sub-namespace (`Admin\BukuController`)
- Poin 27 (Middleware Auth): Middleware `auth` digunakan di group untuk melindungi route

## Soal Latihan

1. **Praktik**: Buat route group dengan prefix `admin`, middleware `auth`, dan name prefix `admin.` yang berisi resource route untuk `buku` dan `anggota`!
2. **Analisis**: Apa keuntungan menggunakan route group dibandingkan mendefinisikan route satu per satu?
3. **Praktik**: Jalankan `php artisan route:list` setelah membuat group di atas — perhatikan bagaimana URL dan nama route terbentuk!

<summary>Jawaban</summary>

1. **Kode:**
   ```php
   Route::prefix('admin')
        ->middleware(['auth'])
        ->name('admin.')
        ->group(function () {
            Route::resource('buku', Admin\BukuController::class);
            Route::resource('anggota', Admin\AnggotaController::class);
        });
   ```

2. **Keuntungan route group:**
   - **DRY (Don't Repeat Yourself)** — prefix `admin` dan middleware `auth` ditulis sekali, bukan per route
   - **Konsistensi** — semua route dalam group punya prefix yang sama, tidak ada yang kelewat
   - **Mudah diubah** — ganti prefix dari `admin` ke `pustakawan` cukup edit satu baris
   - **Mudah dibaca** — sekilas terlihat "ini bagian admin"

3. **Hasil `php artisan route:list`:**
   ```
   GET|HEAD  /admin/buku              → admin.buku.index
   POST      /admin/buku              → admin.buku.store
   GET|HEAD  /admin/buku/create       → admin.buku.create
   ... (dan seterusnya untuk anggota)
   ```
   Semua route otomatis memiliki prefix `/admin` dan nama berawalan `admin.`.
