# 2. Filosofi Laravel — Convention over Configuration

## Penjelasan

**Convention over Configuration** artinya Laravel sudah membuat keputusan default yang masuk akal, sehingga kamu tidak perlu mengonfigurasi hal-hal kecil. Jika kamu mengikuti konvensi yang sudah ditetapkan, semuanya bekerja tanpa setup tambahan.

**Konvensi Utama yang Harus Diketahui:**

| Konvensi | Artinya |
|----------|---------|
| Model `Buku` → tabel `buku` | Snake case plural dari nama model |
| Model `AnggotaPerpustakaan` → tabel `anggota_perpustakaans` | Multi-word → snake_case + plural |
| Kolom `created_at` & `updated_at` | Dikelola otomatis oleh Eloquent |
| Method `index()` di controller → `GET /buku` | Resource convention 7 method standar |
| File `BukuController.php` → folder `app/Http/Controllers/` | Struktur file sudah ditentukan |
| File `buku/index.blade.php` → folder `resources/views/buku/` | View sesuai nama controller |

Laravel juga punya prinsip **Developer Happiness** — framework dibuat agar pengalaman ngoding menyenangkan, dengan syntax yang ekspresif dan intuitif.

## Fungsi

- Mengurangi keputusan trivial: tak perlu pusing menentukan nama tabel, struktur folder, atau format response
- Memudahkan kolaborasi: semua developer Laravel menggunakan struktur yang sama
- Mempercepat development: ikuti konvensi, semuanya jalan otomatis

## Cara Pengimplementasian

Tidak perlu melakukan apa-apa — konvensi sudah aktif secara default. Contoh:

```php
// 1. Nama tabel otomatis dari nama model
// Model: app/Models/Buku.php
class Buku extends Model {}
// Laravel otomatis cari tabel: `buku` (plural dari Buku)

// 2. Timestamps otomatis
$buku = new Buku();
$buku->judul = 'Clean Code';
$buku->save();
// created_at dan updated_at terisi otomatis — tanpa kode tambahan

// 3. Resource controller
// Route: Route::resource('buku', BukuController::class);
// Method index() otomatis untuk GET /buku
```

Satu-satunya yang perlu dilakukan: **ikuti pola yang sudah ada**. Jika ada model `Buku`, jangan buat tabel `daftar_buku`. Jika ada controller `BukuController`, jangan simpan di folder lain.

## Analogi

Di perpustakaan, ada konvensi yang sudah disepakati:
- Buku fiksi disimpan di rak Fiksi, buku referensi di rak Referensi
- Kartu katalog diurutkan berdasarkan abjad judul
- Nomor ISBN punya format tertentu

Jika seorang pustakawan baru mengikuti konvensi ini, dia langsung bisa bekerja tanpa perlu bertanya "bukunya ditaruh di mana?" setiap saat.

**Convention over Configuration** seperti ini: daripada setiap perpustakaan membuat sistem sendiri (yang membingungkan pengunjung), semua perpustakaan mengikuti standar yang sama. Laravel melakukan hal yang sama untuk aplikasi web.

## Dipakai untuk Apa

- Mempercepat pengembangan: tanpa konvensi, kamu harus konfigurasi routing, nama tabel, lokasi view, dll. secara manual
- Menghindari kesalahan: nama tabel salah ketik → tidak akan terjadi karena otomatis
- Onboarding tim baru: developer Laravel lain bisa langsung membaca kode kamu

## Kesalahan Umum

1. **Melawan konvensi tanpa alasan kuat** — misal: membuat tabel `buku` tapi modelnya `Book` (beda bahasa). Ini akan membingungkan
2. **Mengubah namespace default** — Laravel menggunakan `App\Models`, `App\Http\Controllers`, dll. Mengubahnya perlu konfigurasi tambahan
3. **Membuat struktur folder sendiri** — folder `app/` sudah ditentukan. Jangan buat folder `controllers/` di luar
4. **Tidak menggunakan plural untuk tabel** — Laravel expect `buku` (plural) untuk model `Buku`; jika tabelnya `bukus`, perlu properti `protected $table = 'bukus'`

## Koneksi dengan Materi Sebelumnya

Di poin 1, kamu memahami lifecycle Laravel. Sekarang kamu paham **mengapa** struktur yang ada seperti itu — karena Laravel mengikuti konvensi untuk mengurangi konfigurasi.

**Benang merah ke depan:**
- Poin 3 (Instalasi): Saat membuat project, kamu akan melihat struktur direktori yang sudah mengikuti konvensi ini
- Poin 4 (Struktur Direktori): Setiap folder memiliki tujuan yang sudah ditentukan oleh konvensi

## Soal Latihan

1. **Tebakan**: Jika model bernama `KategoriBuku`, apa nama tabel yang akan dicari Laravel secara otomatis?
2. **Analisis**: Mengapa Laravel memilih convention over configuration? Sebutkan 3 keuntungan!
3. **Praktik**: Buat model `Peminjaman` tanpa properti `$table`, lalu jalankan migration. Apakah nama tabel yang terbentuk sesuai konvensi?

<summary>Jawaban</summary>

1. **`kategori_bukus`** — Laravel mengubah `KategoriBuku` (PascalCase) menjadi `kategori_buku` (snake_case) lalu menambahkan `s` (plural).

2. **Tiga keuntungan:**
   - **Kecepatan**: Tidak perlu konfigurasi manual, langsung coding
   - **Konsistensi**: Semua developer Laravel menggunakan struktur yang sama
   - **Prediktabilitas**: Bisa tebak di mana file berada tanpa perlu lihat dokumentasi

3. Jika model `Peminjaman` tanpa properti `$table`:
   - Laravel akan mencari tabel `peminjamen` (bukan `peminjaman`)
   - Ini **salah** karena plural dari `peminjaman` dalam bahasa Indonesia seharusnya tetap `peminjaman`
   - Solusi: tambahkan `protected $table = 'peminjaman';` di model
   - Pelajaran: konvensi Laravel menggunakan aturan plural bahasa Inggris, jadi untuk bahasa Indonesia kadang perlu override
