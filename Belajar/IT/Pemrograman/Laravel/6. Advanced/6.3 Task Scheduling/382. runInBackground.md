# 382. runInBackground

## Definisi Singkat
Constraint `->runInBackground()` memerintahkan scheduler untuk menjalankan task di latar belakang (background process) tanpa menunggu selesai.

## Analogi
Seperti mencuci baju di laundry — Anda tinggalkan (background), lanjutkan aktivitas lain, nanti ambil hasilnya setelah selesai.

## Poin-Poin Penting
- `->runInBackground()` — jalankan di background process
- Scheduler tidak menunggu task selesai (non-blocking)
- Task berikutnya bisa langsung dijalankan
- Berguna untuk task berat agar tidak menghambat scheduler
- Hanya untuk command, bukan job

## Contoh Kode
```php
<?php

namespace App\Console;

use Illuminate\Console\Scheduling\Schedule;
use Illuminate\Foundation\Console\Kernel as ConsoleKernel;

class Kernel extends ConsoleKernel
{
    protected function schedule(Schedule $schedule): void
    {
        // Tanpa runInBackground — blocking
        // Jika task lama, scheduler menunggu
        $schedule->command('report:heavy')
            ->everyMinute();  // Bisa tertunda!

        // Dengan runInBackground — non-blocking
        $schedule->command('report:heavy')
            ->everyMinute()
            ->runInBackground();  // Langsung lanjut ke task berikutnya

        // Contoh konkret
        $schedule->command('sync:large-dataset')
            ->hourly()
            ->runInBackground()
            ->withoutOverlapping()
            ->appendOutputTo(storage_path('logs/sync.log'));

        // Multiple background tasks
        $schedule->command('analytics:process')
            ->everyFiveMinutes()
            ->runInBackground();

        $schedule->command('email:send-bulk')
            ->everyTenMinutes()
            ->runInBackground();
    }
}
```

```php
<?php
// runInBackground + withoutOverlapping — kombinasi ideal

$schedule->command('process:heavy')
    ->everyMinute()
    ->runInBackground()      // Tidak blocking scheduler
    ->withoutOverlapping();  // Tidak overlap dengan diri sendiri
```

```php
<?php
// Perbedaan blocking vs non-blocking

// BLOCKING (tanpa runInBackground):
// 08:00 — Task A mulai (lama 10 menit)
// 08:01 — Task B dijadwalkan → TERTUNDA (menunggu Task A)
// 08:10 — Task A selesai
// 08:10 — Task B mulai (terlambat 9 menit!)

// NON-BLOCKING (dengan runInBackground):
// 08:00 — Task A mulai di background
// 08:01 — Task B mulai (Task A masih jalan di bg)
// Kedua task berjalan PARALEL
```

## Kasus Penggunaan Nyata
Task berat yang perlu berjalan paralel, sinkronasi data besar, generate report massal, dan situasi di mana scheduler tidak boleh terblokir.
