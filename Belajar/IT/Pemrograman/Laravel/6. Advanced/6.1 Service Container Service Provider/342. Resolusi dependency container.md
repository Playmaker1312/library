# 342. Resolusi Dependency Container

## Definisi Singkat
Proses di mana Service Container secara otomatis menentukan dan memberikan dependency yang dibutuhkan oleh suatu kelas.

## Analogi
Seperti resep dokter — apoteker (container) membaca resep (constructor), lalu menyiapkan semua obat (dependency) yang dibutuhkan.

## Poin-Poin Penting
- Container membaca type-hint pada constructor
- Mencari binding yang cocok atau membuat instance baru
- Resolusi dilakukan secara rekursif (dependency di dalam dependency)
- Jika tidak ada binding, container akan otomatis membuat kelas dengan Reflection
- Bisa gagal jika dependency tidak bisa di-resolve

## Contoh Kode
```php
<?php

namespace App\Services;

class Logger
{
    public function log(string $message): void
    {
        \Illuminate\Support\Facades\Log::info($message);
    }
}

class UserService
{
    // Container akan otomatis meresolve Logger
    public function __construct(
        protected Logger $logger
    ) {}

    public function register(array $data): void
    {
        // logika registrasi...
        $this->logger->log("User registered: " . $data['email']);
    }
}
```

```php
// Penggunaan di controller — container meresolve semuanya
<?php

namespace App\Http\Controllers;

use App\Services\UserService;

class UserController extends Controller
{
    public function __construct(
        protected UserService $userService
    ) {}
}
```

## Kasus Penggunaan Nyata
Semua fitur Laravel bergantung pada resolusi otomatis: Controller, Middleware, Queue Job, Event Listener, dan Artisan command.
