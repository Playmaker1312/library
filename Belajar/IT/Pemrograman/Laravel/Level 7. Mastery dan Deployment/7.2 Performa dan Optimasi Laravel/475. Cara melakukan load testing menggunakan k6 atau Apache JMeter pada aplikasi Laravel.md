# 475. Cara Melakukan Load Testing Menggunakan k6 atau Apache JMeter pada Aplikasi Laravel

## Definisi & Target
Load testing mengukur bagaimana aplikasi Laravel berperilaku di bawah beban pengguna simultan. Targetnya adalah mengidentifikasi batas kapasitas, titik patah, dan area yang perlu dioptimasi sebelum aplikasi melayani traffic nyata.

## Komponen yang Terlibat
- k6 (modern, scriptable)
- Apache JMeter (GUI-based)
- Laravel application yang di-deploy
- Monitoring tools (Pulse, Debugbar)

## Perintah Artisan CLI
```bash
php artisan config:cache
php artisan route:cache
php artisan optimize
```

## Kode Implementasi (Per File)

**k6 Test Script (load-tests/smoke-test.js)**
```javascript
import http from 'k6/http';
import { check, sleep, group } from 'k6';
import { Rate, Trend } from 'k6/metrics';

const errorRate = new Rate('errors');
const responseTime = new Trend('response_time');

export const options = {
    stages: [
        { duration: '2m', target: 50 },
        { duration: '5m', target: 50 },
        { duration: '2m', target: 100 },
        { duration: '5m', target: 100 },
        { duration: '2m', target: 0 },
    ],
    thresholds: {
        http_req_duration: ['p(95)<500'],
        errors: ['rate<0.05'],
    },
};

const BASE_URL = __ENV.BASE_URL || 'http://localhost:8000';

export default function () {
    group('Homepage', () => {
        const res = http.get(`${BASE_URL}/`);
        check(res, { 'status is 200': (r) => r.status === 200 });
        responseTime.add(res.timings.duration);
        errorRate.add(res.status !== 200);
    });

    group('Product Listing', () => {
        const res = http.get(`${BASE_URL}/products`);
        check(res, { 'status is 200': (r) => r.status === 200 });
        responseTime.add(res.timings.duration);
        errorRate.add(res.status !== 200);
    });

    group('Login', () => {
        const res = http.post(`${BASE_URL}/login`, {
            email: 'test@example.com',
            password: 'password',
        });
        check(res, { 'status is 302': (r) => r.status === 302 });
        errorRate.add(res.status !== 302);
    });

    sleep(1);
}
```

**k6 Stress Test (load-tests/stress-test.js)**
```javascript
export const options = {
    stages: [
        { duration: '2m', target: 200 },
        { duration: '10m', target: 200 },
        { duration: '2m', target: 500 },
        { duration: '2m', target: 0 },
    ],
    thresholds: {
        http_req_duration: ['p(95)<1000', 'p(99)<2000'],
        http_req_failed: ['rate<0.01'],
    },
};
```

**JMeter Test Plan (load-tests/laravel-test-plan.jmx)**
```xml
<?xml version="1.0" encoding="UTF-8"?>
<jmeterTestPlan version="1.2">
  <hashTree>
    <TestPlan guiclass="TestPlanGui" testclass="TestPlan">
      <elementProp name="TestPlan.user_defined_variables">
        <collectionProp name="arguments">
          <argumentProp>
            <name>BASE_URL</name>
            <value>http://localhost:8000</value>
          </argumentProp>
        </collectionProp>
      </elementProp>
    </TestPlan>
    <hashTree>
      <ThreadGroup guiclass="ThreadGroupGui" testclass="ThreadGroup">
        <intProp name="ThreadGroup.num_threads">100</intProp>
        <intProp name="ThreadGroup.ramp_time">60</intProp>
        <boolProp name="ThreadGroup.same_user_on_next_iteration">false</boolProp>
      </ThreadGroup>
      <hashTree>
        <HTTPSamplerProxy guiclass="HttpTestSampleGui" testclass="HTTPSamplerProxy">
          <stringProp name="HTTPSampler.path">${BASE_URL}/api/products</stringProp>
          <stringProp name="HTTPSampler.method">GET</stringProp>
        </HTTPSamplerProxy>
      </hashTree>
    </hashTree>
  </hashTree>
</jmeterTestPlan>
```

**Running k6**
```bash
k6 run load-tests/smoke-test.js
k6 run --env BASE_URL=https://staging.example.com load-tests/stress-test.js
k6 run --out csv=results.csv load-tests/smoke-test.js
```

**Running JMeter**
```bash
jmeter -n -t load-tests/laravel-test-plan.jmx -l results.jtl
jmeter -g results.jtl -o reports/
```

## Cara Integrasi & Pengujian
Jalankan smoke test dulu (50 user) untuk baseline, lalu stress test (500+ user) untuk batas kapasitas. Analisis hasil dengan k6 dashboard atau JMeter report. Fokus pada p95 response time <500ms dan error rate <1%.
