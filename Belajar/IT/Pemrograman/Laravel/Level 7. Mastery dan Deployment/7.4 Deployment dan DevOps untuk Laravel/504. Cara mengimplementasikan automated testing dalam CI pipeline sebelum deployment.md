# 504. Cara Mengimplementasikan Automated Testing dalam CI Pipeline Sebelum Deployment

## Definisi & Target
Automated testing dalam CI pipeline memastikan bahwa kode yang di-deploy telah melewati seluruh pengujian. Targetnya adalah mencegah kode yang rusak atau tidak aman masuk ke production.

## Komponen yang Terlibat
- GitHub Actions CI pipeline
- PHPUnit test suite
- Static analysis tools
- Code style checkers
- Security audit

## Perintah Artisan CLI
```bash
php artisan test --parallel
./vendor/bin/phpstan analyse
./vendor/bin/pint --test
composer audit
```

## Kode Implementasi (Per File)

**Comprehensive CI Workflow (.github/workflows/pre-deploy-check.yml)**
```yaml
name: Pre-Deployment Quality Check

on:
  pull_request:
    branches: [production]
  push:
    branches: [production]

jobs:
  quality-gate:
    runs-on: ubuntu-latest

    services:
      mysql:
        image: mysql:8.0
        env:
          MYSQL_ALLOW_EMPTY_PASSWORD: yes
          MYSQL_DATABASE: laravel_test
        ports:
          - 3306:3306
        options: --health-cmd="mysqladmin ping" --health-interval=10s --health-timeout=5s --health-retries=3

    steps:
      - uses: actions/checkout@v4

      - uses: shivammathur/setup-php@v2
        with:
          php-version: '8.2'
          coverage: pcov

      - run: cp .env.testing .env
      - run: composer install --no-progress --prefer-dist
      - run: php artisan key:generate
      - run: php artisan migrate --force

      - name: 1. Run Unit Tests
        run: php artisan test --testsuite=Unit
        env:
          DB_HOST: 127.0.0.1

      - name: 2. Run Feature Tests
        run: php artisan test --testsuite=Feature
        env:
          DB_HOST: 127.0.0.1

      - name: 3. Check Code Coverage
        run: php artisan test --coverage --min=80
        env:
          DB_HOST: 127.0.0.1

      - name: 4. Static Analysis
        run: ./vendor/bin/phpstan analyse --level=max

      - name: 5. Code Style
        run: ./vendor/bin/pint --test

      - name: 6. Security Audit
        run: composer audit

      - name: 7. Check Duplicate Code
        run: |
          composer require --dev sebastian/phpcpd
          ./vendor/bin/phpcpd app/ --min-lines=10 --min-tokens=70

      - name: Quality Gate Summary
        run: |
          echo "## Quality Gate Results" >> $GITHUB_STEP_SUMMARY
          echo "- [x] Unit Tests Passed" >> $GITHUB_STEP_SUMMARY
          echo "- [x] Feature Tests Passed" >> $GITHUB_STEP_SUMMARY
          echo "- [x] Code Coverage >= 80%" >> $GITHUB_STEP_SUMMARY
          echo "- [x] PHPStan Level Max Passed" >> $GITHUB_STEP_SUMMARY
          echo "- [x] PSR-12 Compliance" >> $GITHUB_STEP_SUMMARY
          echo "- [x] No Security Vulnerabilities" >> $GITHUB_STEP_SUMMARY
```

**Branch Protection Rules (dikonfigurasi di GitHub UI)**
```
Settings > Branches > Add rule
- Branch name pattern: production
- Require status checks to pass before merging
  - Quality Gate
  - Laravel Tests
- Require pull request reviews before merging
- Dismiss stale pull request approvals
- Require up-to-date branches
```

**Commit Status Check di Feature Test**
```php
namespace Tests\Feature;

use Tests\TestCase;

class CommitStatusTest extends TestCase
{
    public function test_application_health()
    {
        $response = $this->get('/');
        $response->assertStatus(200);
    }

    public function test_database_connection()
    {
        $this->assertTrue(\DB::connection()->getPdo() !== null);
    }

    public function test_queue_connection()
    {
        $this->assertTrue(
            in_array(config('queue.default'), ['redis', 'database'])
        );
    }

    public function test_cache_connection()
    {
        $this->assertTrue(
            in_array(config('cache.default'), ['redis', 'memcached'])
        );
    }

    public function test_session_driver()
    {
        $this->assertTrue(
            in_array(config('session.driver'), ['redis', 'database'])
        );
    }
}
```

**PHPStan Configuration (phpstan.neon)**
```neon
includes:
    - vendor/larastan/larastan/extension.neon

parameters:
    level: max
    paths:
        - app
    excludePaths:
        - app/Providers
    checkMissingIterableValueType: true
    checkGenericClassInNonGenericObjectType: false
```

## Cara Integrasi & Pengujian
Push workflow file ke repository. Set branch protection rules di GitHub. PR ke branch production akan otomatis menjalankan quality gate. PR tidak bisa di-merge jika quality gate gagal.
