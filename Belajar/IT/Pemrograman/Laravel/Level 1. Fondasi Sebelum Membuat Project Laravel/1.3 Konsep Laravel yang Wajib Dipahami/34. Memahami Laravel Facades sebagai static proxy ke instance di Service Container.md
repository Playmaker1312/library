# 34. Memahami Laravel Facades sebagai Static Proxy ke Instance di Service Container

## Definisi & Target
Facade menyediakan antarmuka statis ke class di Service Container. Target: memahami cara kerja facade dan bedanya dengan static method biasa.

## Komponen yang Terlibat
- Facade class di Illuminate\Support\Facades
- Class target yang di-resolve dari container

## Perintah Artisan CLI
Tidak ada.

## Kode Implementasi (Per File)
### Contoh Facade Bawaan
`php
use Illuminate\Support\Facades\Cache;
use Illuminate\Support\Facades\Log;
use Illuminate\Support\Facades\DB;

Cache::put('key', 'value', 600);
Log::info('User logged in', ['id' => ->id]);
DB::transaction(fn() => User::create());
`

### Cara Kerja Facade â€” memanggil instance dari container
`php
// Ini sama dengan:
app('cache')->put('key', 'value', 600);
app('log')->info('User logged in', ['id' => ->id]);
`

### Membuat Facade Sendiri
`php
use Illuminate\Support\Facades\Facade;

class Payment extends Facade
{
    protected static function getFacadeAccessor(): string
    {
        return 'payment.logger';
    }
}
`

## Cara Integrasi & Pengujian
1. Facade memanggil method instance dari container
2. Gunakan facade untuk kode yang lebih pendek dibanding injeksi
3. Facade tetap bisa di-mock untuk testing (Payment::shouldReceive())
4. Jangan gunakan facade di dalam class yang sudah menerima dependency
