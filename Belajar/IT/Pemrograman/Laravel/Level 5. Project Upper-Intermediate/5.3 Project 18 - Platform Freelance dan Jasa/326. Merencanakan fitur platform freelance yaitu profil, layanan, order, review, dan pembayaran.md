# 326. Merencanakan Fitur Platform Freelance yaitu Profil, Layanan, Order, Review, dan Pembayaran

## Definisi & Target
Merencanakan arsitektur platform freelance yang mencakup profil freelancer, layanan/jasa, pemesanan, review, dan sistem pembayaran escrow. Target: dokumen perencanaan lengkap.

## Komponen yang Terlibat
- Profil freelancer dengan portofolio
- Layanan dengan multiple package
- Sistem order & revisi
- File delivery
- Escrow & pembayaran
- Review & rating

## Perintah Artisan CLI
Tidak ada perintah khusus untuk tahap perencanaan.

## Kode Implementasi (Per File)

### Perencanaan Fitur

**Freelancer Profile**
- Bio, foto profil, headline, skills
- Portofolio (gambar/link)
- Pendidikan, pengalaman kerja, sertifikasi
- Rating & review stats
- Jam kerja, respons time

**Services (Layanan)**
- Judul, deskripsi, kategori, tags
- Multiple package: Basic, Standard, Premium
- Setiap package: harga, waktu pengerjaan, revisi, fitur
- FAQ layanan
- Galeri contoh hasil

**Order System**
- Klien pilih package, kirim requirements
- Status: pending, accepted, in_progress, revision, delivered, completed, cancelled
- Revisi berdasarkan package
- File upload dari kedua pihak

**Payment & Escrow**
- Dana escrow saat order dibuat
- Dilepas saat order completed
- Refund jika dibatalkan

**Review & Rating**
- Review setelah order completed
- Rating 1-5
- Review dari klien dan freelancer

### Schema Concept
```
users (extended dengan role: client, freelancer, both)

freelancer_profiles
  - user_id, headline, bio, hourly_rate, skills (json)
  - response_time, experience_level
  - created_at, updated_at

services
  - id, user_id, title, slug, description, category_id
  - created_at, updated_at

service_packages
  - id, service_id, name (basic/standard/premium)
  - price, delivery_days, revisions, features (json)
  - created_at, updated_at

orders
  - id, service_id, package_id, client_id, freelancer_id
  - status, amount, requirements (text/files)
  - created_at, updated_at

order_files
  - id, order_id, user_id, file_path, type (requirement/delivery/revision)
  - created_at

reviews
  - id, order_id, from_user_id, to_user_id
  - rating, review, type (client_to_freelancer / freelancer_to_client)
  - created_at
```

## Cara Integrasi & Pengujian
1. Dokumentasikan alur: Register → Setup Profil → Buat Layanan → Order → Progress → Delivery → Complete
2. Identifikasi state machine untuk order status
3. Tentukan trigger notifikasi di setiap transisi status
4. Gunakan sebagai acuan implementasi poin 327-340
