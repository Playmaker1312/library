# 470. Zero-downtime Deployer PHP

## Definisi Singkat
Penggunaan library Deployer PHP untuk deployment Laravel tanpa downtime — dengan mekanisme symlink yang memungkinkan aplikasi tetap berjalan selama deploy.

## Analogi
Seperti mengganti ban mobil saat jalan — Deployer menyiapkan ban cadangan (release baru), lalu mengganti dengan cepat tanpa mobil berhenti (symlink switch).

## Poin-Poin Penting
- Deployer — tool deployment PHP yang powerful
- Zero-downtime via symlink ke folder release
- Rollback instant jika deploy gagal
- Shared folder untuk storage, .env, logs
- Task hooks — sebelum/sesudah deploy
- Multi-server deployment

## Contoh Kode
```php
<?php
// deploy.php — Deployer configuration

namespace Deployer;

require 'recipe/laravel.php';

// Project name
set('application', 'Laravel App');
set('repository', 'git@github.com:username/repo.git');

// Hosts
host('production')
    ->setHostname('example.com')
    ->setRemoteUser('forge')
    ->setPort(22)
    ->setIdentityFile('~/.ssh/id_rsa')
    ->setDeployPath('/var/www/app')
    ->set('branch', 'main');

host('staging')
    ->setHostname('staging.example.com')
    ->setRemoteUser('forge')
    ->setDeployPath('/var/www/staging')
    ->set('branch', 'develop');

// Shared files between releases
set('shared_files', ['.env']);
set('shared_dirs', ['storage', 'public/uploads']);

// Writable dirs
set('writable_dirs', ['bootstrap/cache', 'storage']);

// Laravel recipe akan handle:
// - composer install
// - migrate
// - config:cache
// - route:cache
// - view:cache
// - storage:link

// Custom task — build assets
task('build:frontend', function () {
    cd('{{release_path}}');
    run('npm ci --production');
    run('npm run build');
    run('rm -rf node_modules');
});

// Custom task — reload queue
task('queue:restart', function () {
    cd('{{current_path}}');
    run('php artisan queue:restart');
});

// Hooks
before('deploy:symlink', 'build:frontend');
after('deploy:symlink', 'queue:restart');
after('deploy:success', 'deploy:unlock');

// Rollback
after('deploy:failed', 'deploy:unlock');

// Deploy now!
// $ dep deploy production
```

```bash
# Install Deployer
composer require deployer/deployer --dev

# Deploy (setup pertama)
dep deploy production

# Deploy berikutnya
dep deploy production

# Rollback ke release sebelumnya
dep rollback production

# Lihat status release
dep releases production

// Struktur folder setelah deploy
// /var/www/app/
// ├── current -> releases/20250528_120000
// ├── releases/
// │   ├── 20250528_120000/
// │   ├── 20250528_110000/
// │   └── 20250528_100000/
// ├── shared/
// │   ├── .env
// │   ├── storage/
// │   └── public/uploads/
// └── .dep/
```

## Kasus Penggunaan Nyata
SaaS 24/7 — deploy 10x sehari tanpa maintenance window. User tidak sadar aplikasi sedang di-deploy karena zero-downtime mechanism Deployer.
