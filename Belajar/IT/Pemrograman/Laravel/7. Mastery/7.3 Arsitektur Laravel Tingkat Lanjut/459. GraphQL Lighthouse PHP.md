# 459. GraphQL Lighthouse PHP

## Definisi Singkat
Package Laravel untuk membuat GraphQL API menggunakan schema definition — menggantikan REST API dengan query yang lebih fleksibel dan efisien.

## Analogi
Seperti prasmanan (GraphQL) vs paket nasi kotak (REST). Di prasmanan, kita pilih lauk yang kita mau. Di nasi kotak, kita terima apa adanya.

## Poin-Poin Penting
- Define schema GraphQL di file `.graphql`
- Resolver untuk menghubungkan schema ke data
- Query, Mutation, Subscription
- N+1 problem otomatis teratasi dengan batched resolvers
- Built-in pagination, validation, authorization
- Playground/GraphiQL UI untuk testing

## Contoh Kode
```php
// Install
composer require nuwave/lighthouse

// Publish config
php artisan vendor:publish --provider="Nuwave\Lighthouse\LighthouseServiceProvider"

// Schema — graphql/schema.graphql
type Query {
    users: [User!]! @paginate
    user(id: ID! @eq): User @find
    posts(status: PostStatus): [Post!]!
        @all
        @where(key: "status")
        @orderBy(column: "created_at", direction: DESC)
}

type Mutation {
    createUser(input: CreateUserInput! @spread): User! @create
    updateUser(id: ID!, input: UpdateUserInput! @spread): User! @update
    deleteUser(id: ID!): User! @delete
    login(email: String!, password: String!): AuthPayload!
}

type User {
    id: ID!
    name: String!
    email: String!
    posts: [Post!]! @hasMany
    created_at: DateTime!
}

type Post {
    id: ID!
    title: String!
    content: String!
    status: PostStatus!
    author: User! @belongsTo
    comments: [Comment!]! @hasMany
}

enum PostStatus {
    DRAFT @enum(value: "draft")
    PUBLISHED @enum(value: "published")
    ARCHIVED @enum(value: "archived")
}

input CreateUserInput {
    name: String! @rules(apply: ["min:3"])
    email: String! @rules(apply: ["email", "unique:users"])
    password: String! @rules(apply: ["min:8"]) @hash
}

input UpdateUserInput {
    name: String @rules(apply: ["min:3"])
    email: String @rules(apply: ["email", "unique:users"])
}

type AuthPayload {
    token: String!
    user: User!
}

// Resolver custom untuk mutation login
namespace App\GraphQL\Mutations;

class Login
{
    public function __invoke($rootValue, array $args): array
    {
        if (!Auth::attempt(['email' => $args['email'], 'password' => $args['password']])) {
            throw new \GraphQL\Error\Error('Invalid credentials');
        }

        $user = Auth::user();
        $token = $user->createToken('graphql')->plainTextToken;

        return ['token' => $token, 'user' => $user];
    }
}

// Query GraphQL dari client
query {
    user(id: 1) {
        name
        email
        posts(status: PUBLISHED) {
            title
            comments {
                id
            }
        }
    }
}

// Mutation
mutation {
    createUser(input: {
        name: "Budi"
        email: "budi@test.com"
        password: "secret123"
    }) {
        id
        name
        email
    }
}
```

## Kasus Penggunaan Nyata
Mobile app perlu data user + posts + comments dalam satu request. REST butuh 3 request. GraphQL cukup 1 query — menghemat baterai dan bandwidth.
