# 446. Domain-Driven Design Laravel

## Definisi Singkat
Pendekatan arsitektur yang fokus pada domain bisnis (core business logic) — model kode mencerminkan bahasa dan konsep dari domain expert, bukan struktur database.

## Analogi
Seperti arsitek yang merancang rumah berdasarkan kebutuhan penghuni (domain), bukan berdasarkan ketersediaan batu bata (teknologi).

## Poin-Poin Penting
- Ubiquitous Language — bahasa yang sama antara developer dan domain expert
- Entities — objek dengan identitas unik
- Value Objects — objek tanpa identitas, dibedakan oleh nilai
- Aggregates — grup objek yang diperlakukan sebagai satu unit
- Domain Events — kejadian penting di domain bisnis
- Repositories — abstraksi penyimpanan aggregate

## Contoh Kode
```php
<?php

// 1. Value Object
namespace App\Domain\Shared\ValueObjects;

class Money
{
    public function __construct(
        private readonly int $amount,
        private readonly string $currency = 'IDR'
    ) {
        if ($amount < 0) {
            throw new \DomainException('Amount cannot be negative');
        }
    }

    public function add(Money $other): Money
    {
        if ($this->currency !== $other->currency) {
            throw new \DomainException('Currency mismatch');
        }
        return new self($this->amount + $other->amount, $this->currency);
    }

    public function multiply(int $quantity): Money
    {
        return new self($this->amount * $quantity, $this->currency);
    }

    public function format(): string
    {
        return number_format($this->amount, 0, ',', '.') . " {$this->currency}";
    }
}

// 2. Entity
namespace App\Domain\Order\Entities;

use App\Domain\Shared\ValueObjects\Money;

class Order
{
    public function __construct(
        private readonly string $id,
        private readonly string $customerId,
        private array $items = [],
        private string $status = 'pending',
    ) {}

    public function addItem(string $productId, string $name, Money $price, int $quantity): void
    {
        $this->items[] = new OrderItem($productId, $name, $price, $quantity);
    }

    public function getTotal(): Money
    {
        $total = new Money(0);
        foreach ($this->items as $item) {
            $total = $total->add($item->getSubtotal());
        }
        return $total;
    }

    public function confirm(): void
    {
        if ($this->status !== 'pending') {
            throw new \DomainException('Only pending orders can be confirmed');
        }
        if (empty($this->items)) {
            throw new \DomainException('Cannot confirm empty order');
        }
        $this->status = 'confirmed';
    }
}

// 3. Domain Event
namespace App\Domain\Order\Events;

class OrderConfirmed
{
    public function __construct(
        public readonly string $orderId,
        public readonly string $customerId,
        public readonly array $items,
        public readonly \DateTimeImmutable $occurredAt,
    ) {}
}

// 4. Repository Interface
namespace App\Domain\Order\Repositories;

use App\Domain\Order\Entities\Order;

interface OrderRepository
{
    public function findById(string $id): ?Order;
    public function save(Order $order): void;
    public function delete(string $id): void;
}

// 5. Domain Service
namespace App\Domain\Order\Services;

class OrderService
{
    public function __construct(
        private OrderRepository $orderRepo,
        private CustomerRepository $customerRepo,
    ) {}

    public function placeOrder(string $customerId, array $cartItems): Order
    {
        $customer = $this->customerRepo->findById($customerId);
        if (!$customer->isActive()) {
            throw new \DomainException('Customer is not active');
        }

        $order = new Order(Str::uuid()->toString(), $customerId);
        foreach ($cartItems as $item) {
            $order->addItem(
                $item['product_id'],
                $item['name'],
                new Money($item['price']),
                $item['quantity']
            );
        }

        $order->confirm();
        $this->orderRepo->save($order);
        return $order;
    }
}
```

## Kasus Penggunaan Nyata
Sistem pemesanan tiket maskapai — domain expert bicara "booking", "reschedule", "cancel". DDD memastikan kode menggunakan istilah yang sama, bukan "insert", "update", "delete".
