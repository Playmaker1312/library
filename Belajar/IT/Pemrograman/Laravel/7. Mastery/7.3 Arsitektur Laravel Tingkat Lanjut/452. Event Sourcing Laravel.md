# 452. Event Sourcing Laravel

## Definisi Singkat
Pola arsitektur dimana semua perubahan state aplikasi disimpan sebagai urutan event (kejadian) — bukan hanya state terakhir. State saat ini bisa direkonstruksi dari event history.

## Analogi
Seperti buku besar akuntansi — bukan hanya saldo akhir, tapi semua transaksi dicatat: "setor 100rb", "tarik 50rb", "transfer 200rb". Saldo saat ini dihitung dari semua transaksi.

## Poin-Poin Penting
- Event store — database khusus untuk menyimpan event
- Aggregate root — entity yang me-replay event
- Projection — read model yang dibangun dari event
- Snapshots — state sementara agar tidak replay dari awal
- Eventual consistency — read model mungkin tertunda

## Contoh Kode
```php
<?php

namespace App\Domain\Account\Events;

class MoneyDeposited
{
    public function __construct(
        public readonly string $accountId,
        public readonly int $amount,
        public readonly \DateTimeImmutable $occurredAt,
    ) {}
}

class MoneyWithdrawn
{
    public function __construct(
        public readonly string $accountId,
        public readonly int $amount,
        public readonly \DateTimeImmutable $occurredAt,
    ) {}
}

// Aggregate
namespace App\Domain\Account;

class AccountAggregate
{
    private int $balance = 0;
    private array $changes = [];

    public function __construct(
        public readonly string $id,
    ) {}

    public static function create(string $id): self
    {
        return new self($id);
    }

    public function deposit(int $amount): void
    {
        $this->apply(
            new Events\MoneyDeposited($this->id, $amount, new \DateTimeImmutable())
        );
    }

    public function withdraw(int $amount): void
    {
        if ($this->balance < $amount) {
            throw new \DomainException('Insufficient balance');
        }
        $this->apply(
            new Events\MoneyWithdrawn($this->id, $amount, new \DateTimeImmutable())
        );
    }

    // Rekonstruksi state dari event
    public function apply(object $event): void
    {
        match (true) {
            $event instanceof Events\MoneyDeposited =>
                $this->balance += $event->amount,
            $event instanceof Events\MoneyWithdrawn =>
                $this->balance -= $event->amount,
        };

        $this->changes[] = $event;
    }

    public function getChanges(): array
    {
        return $this->changes;
    }

    public function getBalance(): int
    {
        return $this->balance;
    }
}

// Event Store sederhana
class EventStore
{
    public function save(string $aggregateType, string $aggregateId, array $events): void
    {
        foreach ($events as $event) {
            DB::table('event_store')->insert([
                'aggregate_type' => $aggregateType,
                'aggregate_id' => $aggregateId,
                'event_type' => get_class($event),
                'event_data' => json_encode($event),
                'created_at' => now(),
            ]);
        }
    }

    public function load(string $aggregateType, string $aggregateId): array
    {
        return DB::table('event_store')
            ->where('aggregate_type', $aggregateType)
            ->where('aggregate_id', $aggregateId)
            ->orderBy('id')
            ->get()
            ->map(fn($row) => $row->event_data)
            ->toArray();
    }
}

// Projection — read model
class AccountBalanceProjection
{
    public function project(MoneyDeposited $event): void
    {
        DB::table('account_balances')
            ->upsert(
                [
                    'account_id' => $event->accountId,
                    'balance' => DB::raw('balance + ' . $event->amount),
                ],
                'account_id',
                ['balance']
            );
    }
}
```

## Kasus Penggunaan Nyata
Sistem audit keuangan — semua perubahan saldo dicatat sebagai event. Auditor bisa melihat history lengkap "siapa melakukan apa, kapan, dan saldo sebelum-sesudah".
