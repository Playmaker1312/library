# 447. Organisasi Kode Domain Based

## Definisi Singkat
Struktur folder aplikasi Laravel yang diorganisir berdasarkan domain bisnis (Billing, Inventory, CRM) bukan berdasarkan tipe file (Models, Controllers, Services).

## Analogi
Seperti supermarket — barang dikelompokkan berdasarkan kategori (buah, sayur, daging) bukan berdasarkan jenis kemasan (botol, kotak, plastik).

## Poin-Poin Penting
- Setiap domain punya folder sendiri
- Domain bisa berisi Entities, Services, Repositories, Events
- Pisahkan domain code dari framework code
- Bounded Context — setiap domain independent
- Lebih scalable untuk aplikasi besar

```
// Service Provider untuk domain
class BillingServiceProvider extends ServiceProvider
{
    public function register(): void
    {
        $this->app->bind(
            Billing\Repositories\InvoiceRepository::class,
            Billing\Repositories\EloquentInvoiceRepository::class
        );

        $this->app->singleton(
            Billing\Services\PaymentGateway::class,
            Billing\Services\StripePaymentGateway::class
        );
    }

    public function boot(): void
    {
        Route::prefix('api/billing')
            ->middleware('api')
            ->group(base_path('routes/domain/billing.php'));
    }
}
```

## Kasus Penggunaan Nyata
Aplikasi ERP dengan modul Sales, Finance, HR, Inventory — setiap modul adalah domain terpisah dengan struktur folder sendiri, memudahkan 5 tim berbeda mengerjakannya.
