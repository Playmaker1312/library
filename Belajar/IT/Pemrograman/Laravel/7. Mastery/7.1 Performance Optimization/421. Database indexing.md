# 421. Database Indexing

## Definisi Singkat
Teknik membuat struktur data indeks pada kolom database untuk mempercepat pencarian dan pengurutan data tanpa harus scan seluruh tabel.

## Analogi
Seperti indeks di buku — tanpa indeks kita harus baca halaman per halaman untuk menemukan topik tertentu. Dengan indeks, langsung tahu di halaman berapa.

## Poin-Poin Penting
- Index pada kolom yang sering di `WHERE`, `JOIN`, `ORDER BY`
- Jangan buat index pada kolom yang jarang di-query
- Composite index untuk multi-kolom
- Index mempercepat SELECT tapi memperlambat INSERT/UPDATE
- Gunakan `EXPLAIN` untuk cek penggunaan index

## Contoh Kode
```php
// Migration: single column index
Schema::table('users', function (Blueprint $table) {
    $table->index('email');
});

// Composite index
Schema::table('orders', function (Blueprint $table) {
    $table->index(['user_id', 'status', 'created_at']);
});

// Unique index
Schema::table('products', function (Blueprint $table) {
    $table->unique('sku');
});

// Full-text index
Schema::table('articles', function (Blueprint $table) {
    $table->fullText('content');
});

// Partial index (PostgreSQL)
Schema::table('users', function (Blueprint $table) {
    $table->index('email')->where('active', true);
});

// Drop index
Schema::table('users', function (Blueprint $table) {
    $table->dropIndex(['email']);
});

// Cek query dengan EXPLAIN
// Jalankan di database: EXPLAIN SELECT * FROM users WHERE email = 'test@test.com'
```

## Kasus Penggunaan Nyata
Tabel orders dengan 2 juta baris — query filter `user_id` butuh 5 detik tanpa index. Setelah index `user_id` — query selesai dalam 50ms.
