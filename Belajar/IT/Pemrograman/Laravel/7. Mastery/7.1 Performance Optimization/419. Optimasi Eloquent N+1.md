# 419. Optimasi Eloquent N+1

## Definisi Singkat
Masalah performa dimana query dijalankan berulang kali dalam loop karena relasi tidak di-load bersamaan, menghasilkan 1 query parent + N query child.

## Analogi
Jika ingin nama murid di 10 kelas — N+1 artinya kita cari 1 kelas, lalu untuk setiap kelas kita query murid lagi (10x). Padahal cukup 2 query total.

## Poin-Poin Penting
- Gunakan `with()` untuk eager loading
- Hindari akses relasi di dalam loop Blade
- Gunakan `load()` untuk lazy eager loading
- Gunakan `loadCount()` untuk menghitung tanpa load data
- Debugbar membantu mendeteksi N+1

## Contoh Kode
```php
// ❌ N+1 Query (berbahaya)
$posts = Post::all();
foreach ($posts as $post) {
    echo $post->author->name; // query author di setiap loop!
}

// ✅ Eager loading
$posts = Post::with('author')->get();
foreach ($posts as $post) {
    echo $post->author->name;
}

// ✅ Lazy eager loading (jika sudah terlanjur query)
$posts = Post::all();
if ($someCondition) {
    $posts->load('author');
}

// ✅ Load count saja
$posts = Post::withCount('comments')->get();
foreach ($posts as $post) {
    echo $post->comments_count;
}

// ✅ Nested relations
$posts = Post::with('author.profile', 'comments.user')->get();
```

## Kasus Penggunaan Nyata
Halaman blog menampilkan 50 artikel dengan penulis — tanpa eager loading menghasilkan 1 + 50 = 51 query. Dengan `with('author')` cukup 2 query.
