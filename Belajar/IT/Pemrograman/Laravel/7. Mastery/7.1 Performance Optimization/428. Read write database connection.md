# 428. Read Write Database Connection

## Definisi Singkat
Konfigurasi database di Laravel untuk memisahkan query read (SELECT) ke slave/replica dan query write (INSERT/UPDATE/DELETE) ke master — meningkatkan performa database.

## Analogi
Seperti perpustakaan — buku asli (master) disimpan di ruang aman, fotokopi (replica) diletakkan di ruang baca agar banyak orang bisa baca tanpa merusak buku asli.

## Poin-Poin Penting
- Otomatis — Laravel routing query read/write
- Support multiple read hosts
- Berguna untuk high-traffic application
- Replication lag perlu diantisipasi
- Gunakan `sticky` mode untuk konsistensi

## Contoh Kode
```php
// config/database.php
'mysql' => [
    'driver' => 'mysql',
    'read' => [
        'host' => [
            env('DB_READ_HOST_1', '192.168.1.10'),
            env('DB_READ_HOST_2', '192.168.1.11'),
        ],
        'database' => env('DB_DATABASE', 'forge'),
        'username' => env('DB_USERNAME_READ', 'readonly'),
        'password' => env('DB_PASSWORD_READ', ''),
    ],
    'write' => [
        'host' => [
            env('DB_WRITE_HOST', '192.168.1.5'),
        ],
        'database' => env('DB_DATABASE', 'forge'),
        'username' => env('DB_USERNAME', 'forge'),
        'password' => env('DB_PASSWORD', ''),
    ],
    'sticky' => env('DB_STICKY', false),
    'engine' => 'InnoDB',
    'charset' => 'utf8mb4',
    'collation' => 'utf8mb4_unicode_ci',
    'prefix' => '',
    'prefix_indexes' => true,
    'strict' => true,
],

// .env
DB_READ_HOST_1=10.0.0.101
DB_READ_HOST_2=10.0.0.102
DB_WRITE_HOST=10.0.0.100
DB_USERNAME_READ=readonly_user
DB_PASSWORD_READ=secret

// Sticky mode — pastikan baca data setelah write
// config/database.php
'sticky' => env('DB_STICKY', true),
// Dalam session yang sama setelah INSERT, read tetap ke master

// Paksa koneksi ke write/replica tertentu
DB::connection('mysql')->table('users')->get();
// atau paksa ke write connection
DB::connection('mysql::write')->table('users')->find(1);

// Monitoring replication lag
$result = DB::select("SHOW SLAVE STATUS");
$lagSeconds = $result[0]->Seconds_Behind_Master ?? null;

if ($lagSeconds > 30) {
    Log::warning('Database replication lag detected', ['lag' => $lagSeconds]);
}
```

## Kasus Penggunaan Nyata
Aplikasi media sosial dengan 1 juta request/detik — SELECT dipisah ke 3 read replica, sementara INSERT/UPDATE hanya ke 1 master, mengurangi beban master 70%.
