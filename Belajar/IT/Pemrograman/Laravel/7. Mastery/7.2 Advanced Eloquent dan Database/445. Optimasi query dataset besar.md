# 445. Optimasi Query Dataset Besar

## Definisi Singkat
Teknik mengoptimasi query Laravel ketika bekerja dengan dataset besar (>100.000 baris) — mencakup chunking, streaming, dan strategi memory management.

## Analogi
Seperti memindahkan gudang berisi 1 juta barang — tidak mungkin dibawa semua sekali angkut. Harus dipindah bertahap (chunk) dengan truk kecil.

## Poin-Poin Penting
- Gunakan `chunk()` atau `lazy()` daripada `get()`
- `cursor()` untuk streaming satu per satu
- Hindari `COUNT(*)` di tabel besar — pakai cached count
- Select hanya kolom yang diperlukan
- Gunakan distinct query daripada collection methods
- Batch processing untuk export/import

## Contoh Kode
```php
<?php

use App\Models\Order;
use Illuminate\Support\LazyCollection;

// ❌ JANGAN — semua data di-load ke memory
$orders = Order::all(); // crash jika 1 juta baris!

// ✅ chunk — proses per batch
Order::where('status', 'pending')
    ->chunk(200, function ($orders) {
        foreach ($orders as $order) {
            // proses 200 order per batch
            ProcessOrder::dispatch($order);
        }
    });

// ✅ lazy() — collection lazy loading (Laravel 8+)
$orders = Order::where('status', 'pending')->lazy();

foreach ($orders as $order) {
    // hanya 1 model dalam memory tiap iterasi
    ProcessOrder::dispatch($order);
}

// ✅ cursor() — menggunakan Generator, paling hemat memory
foreach (Order::where('status', 'completed')->cursor() as $order) {
    // proses — hanya 1 model di memory
}

// ✅ Export CSV dengan lazy
function exportCsv(): StreamedResponse
{
    return response()->stream(function () {
        $handle = fopen('php://output', 'w');
        fputcsv($handle, ['ID', 'Order No', 'Total', 'Date']);

        Order::lazy()->each(function ($order) use ($handle) {
            fputcsv($handle, [
                $order->id,
                $order->order_number,
                $order->total,
                $order->created_at,
            ]);
        });

        fclose($handle);
    }, 200, [
        'Content-Type' => 'text/csv',
        'Content-Disposition' => 'attachment; filename="orders.csv"',
    ]);
}

// ✅ Select spesifik — jangan SELECT *
$orders = Order::select('id', 'order_number', 'total', 'status')
    ->where('status', 'completed')
    ->get();

// ✅ Count via cache
$orderCount = Cache::remember('orders_count', 3600, function () {
    return Order::count();
});

// ✅ Batch update — hindari loop update
Order::where('status', 'pending_old')
    ->update(['status' => 'archived']);
```

## Kasus Penggunaan Nyata
Export 500.000 transaksi ke Excel — dengan `chunk()` memory stabil di 20MB. Jika pakai `all()` atau `get()`, memory bisa melonjak ke 500MB+ dan request timeout.
