# 444. Data Archiving Strategy

## Definisi Singkat
Strategi memindahkan data lama/ historis dari tabel utama ke tabel arsip atau storage terpisah untuk menjaga performa database tetap optimal.

## Analogi
Seperti lemari arsip kantor — dokumen lama yang jarang diakses dipindahkan dari meja kerja (tabel aktif) ke gudang arsip (storage arsip) biar meja tidak penuh.

## Poin-Poin Penting
- Pindahkan data > 6-12 bulan ke tabel archive
- Gunakan scheduled job untuk archiving berkala
- Hapus data asli setelah sukses archive
- Archive table bisa di database terpisah atau file
- Gunakan partitioning bawaan database jika memungkinkan

## Contoh Kode
```php
<?php

namespace App\Services;

use App\Models\OldOrder;
use App\Models\Order;
use Illuminate\Support\Facades\DB;

class ArchiveService
{
    public function archiveOrders(int $months = 12): int
    {
        $cutoffDate = now()->subMonths($months);

        $archived = 0;

        // Gunakan chunk agar tidak overload memory
        Order::where('created_at', '<', $cutoffDate)
            ->where('status', 'completed')
            ->chunk(200, function ($orders) use (&$archived) {
                DB::transaction(function () use ($orders, &$archived) {
                    foreach ($orders as $order) {
                        OldOrder::create($order->toArray());
                        $order->delete();
                        $archived++;
                    }
                });
            });

        Log::info("Archived {$archived} orders older than {$months} months");
        return $archived;
    }

    public function archiveSoftDeleted(int $days = 90): int
    {
        return SoftDelete::where('deleted_at', '<', now()->subDays($days))
            ->forceDelete();
    }
}

// Schedule archiving
// app/Console/Kernel.php
protected function schedule(Schedule $schedule): void
{
    $schedule->call(function () {
        app(ArchiveService::class)->archiveOrders(12);
    })->monthly()->at('02:00');

    $schedule->call(function () {
        app(ArchiveService::class)->archiveSoftDeleted(90);
    })->weekly()->at('03:00');
}

// Database partitioning (MySQL) — alternatif arsip
Schema::create('orders', function (Blueprint $table) {
    $table->id();
    $table->string('order_number');
    $table->decimal('total', 15, 2);
    $table->timestamp('created_at')->nullable();

    // Hanya bisa di raw SQL
    // PARTITION BY RANGE (YEAR(created_at)) (
    //     PARTITION p2023 VALUES LESS THAN (2024),
    //     PARTITION p2024 VALUES LESS THAN (2025),
    //     PARTITION p2025 VALUES LESS THAN (2026),
    //     PARTITION p_future VALUES LESS THAN MAXVALUE
    // );
});

// Archive ke file (JSON/CSV) untuk audit
$archivePath = storage_path("archives/orders-" . now()->format('Y-m-d') . ".json");
Order::where('created_at', '<', now()->subYears(2))
    ->chunk(500, function ($orders) use ($archivePath) {
        file_put_contents($archivePath, $orders->toJson(JSON_PRETTY_PRINT) . "\n", FILE_APPEND);
    });
```

## Kasus Penggunaan Nyata
Sistem ERP dengan 5 juta transaksi per tahun — data > 1 tahun diarsipkan ke tabel `old_orders`. Tabel `orders` aktif hanya 500.000 baris, query jadi sangat cepat.
