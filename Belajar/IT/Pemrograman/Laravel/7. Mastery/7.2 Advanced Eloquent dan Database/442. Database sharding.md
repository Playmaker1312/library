# 442. Database Sharding

## Definisi Singkat
Teknik mempartisi data secara horizontal ke beberapa database (shard) berdasarkan key tertentu (misal: user_id, region) untuk mendistribusikan beban.

## Analogi
Seperti perpustakaan yang memisahkan buku berdasarkan abjad — A-F di lantai 1, G-L di lantai 2, M-R di lantai 3, S-Z di lantai 4. Setiap lantai punya petugas sendiri.

## Poin-Poin Penting
- Setiap shard adalah database independen
- Sharding key sangat penting — tentukan distribusi data
- Query cross-shard sangat mahal — hindari
- Laravel tidak punya sharding bawaan — perlu custom
- Package: `mohammadrasoulof/laravel-sharding` atau manual
- Cocok untuk aplikasi dengan data massive

## Contoh Kode
```php
<?php

namespace App\Services;

use Illuminate\Support\Facades\DB;

class ShardingService
{
    protected array $shards = [
        'shard_1' => ['host' => '192.168.1.10', 'database' => 'app_shard_1'],
        'shard_2' => ['host' => '192.168.1.11', 'database' => 'app_shard_2'],
        'shard_3' => ['host' => '192.168.1.12', 'database' => 'app_shard_3'],
        'shard_4' => ['host' => '192.168.1.13', 'database' => 'app_shard_4'],
    ];

    public function getShardKey(int $userId): string
    {
        return 'shard_' . (($userId % 4) + 1);
    }

    public function connection(int $userId): \Illuminate\Database\Connection
    {
        $shard = $this->getShardKey($userId);
        $config = $this->shards[$shard];

        config([
            "database.connections.{$shard}" => [
                'driver' => 'mysql',
                'host' => $config['host'],
                'database' => $config['database'],
                'username' => env('DB_USERNAME'),
                'password' => env('DB_PASSWORD'),
            ]
        ]);

        return DB::connection($shard);
    }

    public function findUser(int $userId): ?object
    {
        return $this->connection($userId)
            ->table('users')
            ->find($userId);
    }
}

// Model dengan sharding
class User extends Authenticatable
{
    protected $connection = 'shard'; // default, akan di-override

    public function __construct(array $attributes = [])
    {
        parent::__construct($attributes);

        if ($this->id) {
            $shardKey = 'shard_' . (($this->id % 4) + 1);
            $this->setConnection($shardKey);
        }
    }
}

// Middleware untuk set shard connection
class ShardMiddleware
{
    public function handle(Request $request, Closure $next): Response
    {
        if ($userId = $request->user()?->id) {
            $shardKey = 'shard_' . (($userId % 4) + 1);
            DB::setDefaultConnection($shardKey);
        }
        return $next($request);
    }
}

// Query builder cross-shard (avoid if possible)
$allUsers = collect();
foreach (['shard_1', 'shard_2', 'shard_3', 'shard_4'] as $shard) {
    $users = DB::connection($shard)->table('users')->get();
    $allUsers = $allUsers->concat($users);
}
```

## Kasus Penggunaan Nyata
Platform sosial media dengan 50 juta user — data di-shard berdasarkan user_id ke 4 database. User 1-12,5 juta di shard 1, 12,5-25 juta di shard 2, dst.
