# 435. Optimistic Locking Version Column

## Definisi Singkat
Mekanisme mencegah konflik update data concurrent dengan menggunakan kolom `version` — hanya mengizinkan update jika versi data masih sama sejak dibaca.

## Analogi
Seperti edit dokumen Google Docs — jika ada yang sudah mengupdate sebelum kita, kita diberi tahu "dokumen sudah diubah, reload dulu" daripada timpa sembarangan.

## Poin-Poin Penting
- Tidak mengunci baris database — performa lebih baik
- Cocok untuk skenario update jarang konflik
- Laravel support via `lock` column atau manual
- Throw `ModelNotFoundException` jika versi berubah
- Kombinasikan dengan `updated_at` sebagai version

## Contoh Kode
```php
<?php

use Illuminate\Database\Eloquent\Model;
use Illuminate\Support\Facades\DB;

// Migration — tambah kolom version
Schema::table('products', function (Blueprint $table) {
    $table->unsignedInteger('version')->default(1);
});

// Optimistic locking manual di Service
class ProductService
{
    public function updateStock(int $productId, int $quantity, int $expectedVersion): Product
    {
        $affected = DB::table('products')
            ->where('id', $productId)
            ->where('version', $expectedVersion)
            ->update([
                'stock' => DB::raw("stock - {$quantity}"),
                'version' => DB::raw('version + 1'),
            ]);

        if ($affected === 0) {
            throw new \App\Exceptions\ConcurrentUpdateException(
                'Produk sudah diupdate pengguna lain, silakan reload'
            );
        }

        return Product::find($productId);
    }
}
```
