# 34. Event-Driven Architecture di Laravel

## Penjelasan

**Event** memungkinkan kamu memisahkan logika menjadi dua bagian:
1. **Event** — "sesuatu terjadi" (buku dipinjam, buku dikembalikan)
2. **Listener** — "reaksi atas kejadian itu" (kirim email, update stok, catat log)

Keuntungan: controller tidak perlu memanggil semua aksi secara manual. Cukup fire event, semua listener akan bereaksi secara otomatis.

```bash
php artisan make:event BukuDipinjam
php artisan make:event BukuDikembalikan
php artisan make:listener KirimNotifikasi --event=BukuDipinjam
php artisan make:listener UpdateStok --event=BukuDipinjam
```

## Fungsi

- Decoupling: controller tidak perlu tahu apa yang terjadi setelah aksi selesai
- Extensibility: tambah listener baru tanpa mengubah kode yang sudah ada
- Organization: logika reaktif dipisahkan dari logika bisnis utama
- Queue integration: listener bisa dijalankan di background

## Cara Pengimplementasian

```php
<?php
// app/Events/BukuDipinjam.php

namespace App\Events;

use App\Models\Peminjaman;
use Illuminate\Foundation\Events\Dispatchable;
use Illuminate\Queue\SerializesModels;

class BukuDipinjam
{
    use Dispatchable, SerializesModels;

    public function __construct(
        public readonly Peminjaman $peminjaman,
    ) {}
}
```

```php
<?php
// app/Listeners/KirimNotifikasiPeminjaman.php

namespace App\Listeners;

use App\Events\BukuDipinjam;
use App\Mail\KonfirmasiPeminjamanMail;
use Illuminate\Contracts\Queue\ShouldQueue;
use Illuminate\Support\Facades\Mail;

class KirimNotifikasiPeminjaman implements ShouldQueue
{
    // ShouldQueue = jalankan di background via queue!
    // Tanpa ShouldQueue = jalankan synchronous

    public function handle(BukuDipinjam $event): void
    {
        Mail::to($event->peminjaman->anggota->email)
            ->send(new KonfirmasiPeminjamanMail($event->peminjaman));
    }
}

// app/Listeners/CatatLogPeminjaman.php
class CatatLogPeminjaman
{
    public function handle(BukuDipinjam $event): void
    {
        Log::info('Buku dipinjam', [
            'buku_id'    => $event->peminjaman->buku_id,
            'anggota_id' => $event->peminjaman->anggota_id,
            'waktu'      => now(),
        ]);
    }
}
```

```php
<?php
// app/Providers/EventServiceProvider.php

namespace App\Providers;

use App\Events\BukuDipinjam;
use App\Events\BukuDikembalikan;
use App\Listeners\KirimNotifikasiPeminjaman;
use App\Listeners\CatatLogPeminjaman;
use App\Listeners\UpdateStokBuku;
use Illuminate\Foundation\Support\Providers\EventServiceProvider as ServiceProvider;

class EventServiceProvider extends ServiceProvider
{
    protected $listen = [
        BukuDipinjam::class => [
            KirimNotifikasiPeminjaman::class,  // kirim email
            CatatLogPeminjaman::class,         // catat log
            UpdateStatistik::class,            // update statistik
        ],
        BukuDikembalikan::class => [
            UpdateStokBuku::class,             // tambah stok
            HitungDenda::class,                // hitung denda
            KirimKonfirmasiKembali::class,     // kirim notifikasi
        ],
    ];

    public function boot(): void
    {
        parent::boot();
    }
}
```

```php
<?php
// Di controller — fire event
class PeminjamanController extends Controller
{
    public function store(Request $request): RedirectResponse
    {
        $peminjaman = Peminjaman::create([
            'buku_id'        => $request->buku_id,
            'anggota_id'     => auth()->id(),
            'tanggal_pinjam' => now(),
            'batas_kembali'  => now()->addDays(14),
        ]);

        // Kurangi stok
        $peminjaman->buku->decrement('stok');

        // 🔥 Fire event — semua listener akan berjalan
        BukuDipinjam::dispatch($peminjaman);

        return redirect()
            ->route('peminjaman.show', $peminjaman)
            ->with('sukses', 'Buku berhasil dipinjam!');
    }
}
```

## Analogi

Event seperti **sistem pengumuman di perpustakaan**:

- **Event `BukuDipinjam`** = Pengumuman: "Buku X baru saja dipinjam oleh Anggota Y!"
- **Listener `KirimNotifikasi`** = Petugas mendengar → kirim email konfirmasi ke anggota
- **Listener `CatatLog`** = Petugas lain mendengar → catat di buku besar
- **Listener `UpdateStatistik`** = Petugas statistik mendengar → update papan statistik

**Tanpa Event:**
```php
// Controller harus melakukan SEMUANYA — panjang dan kaku
$peminjaman = Peminjaman::create([...]);
Mail::send(...);         // kirim email
Log::info(...);          // catat log
Statistik::update(...);  // update statistik
```

**Dengan Event:**
```php
// Controller hanya fokus pada satu hal — fire event
$peminjaman = Peminjaman::create([...]);
BukuDipinjam::dispatch($peminjaman);
// Sisanya diurus listener!
```

Jika nanti butuh aksi baru (misal: kirim notifikasi WhatsApp), cukup buat listener baru — tidak perlu mengubah controller yang sudah ada.

## Dipakai untuk Apa

- **Notifikasi** — email, SMS, push notification setelah aksi
- **Logging** — catat semua kejadian penting
- **Sinkronisasi data** — update statistik, cache invalidation
- **Webhook** — kirim data ke layanan eksternal
- **Workflow** — update status, trigger proses berikutnya

## Kesalahan Umum

1. **Listener terlalu banyak** — 10+ listener untuk satu event → sulit di-debug. Maksimal 3-5 listener
2. **Listener synchronous untuk tugas berat** — implementasikan `ShouldQueue` jika listener butuh waktu lama
3. **Event terlalu umum** — `BukuBerubah` vs `BukuDipinjam`, `BukuDikembalikan`, `BukuDitambahkan` — lebih spesifik lebih baik
4. **Lupa register event-listener** — event di-dispatch tapi tidak ada reaksi
5. **Event mengirim data yang tidak perlu** — hanya kirim yang relevan (ID, atau model)
6. **Event fired di tempat yang salah** — misal: `BukuDipinjam` di-fire setelah validasi tapi sebelum simpan → data belum ada

## Koneksi dengan Materi Sebelumnya

Poin 33 (Queue) memperkenalkan proses background. Event + Queue = kuat: fire event, listener berjalan di queue. Poin 24 (Validasi) memastikan data valid sebelum event di-fire.

**Benang merah ke depan:**
- Poin 35 (Testing): Event bisa di-test dengan `Event::fake()` — pastikan event di-dispatch
- Poin 38 (Caching): Event untuk invalidate cache saat data berubah
