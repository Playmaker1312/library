# 32. Error Handling API — Response yang Konsisten

## Penjelasan

API harus mengembalikan error dalam format JSON yang konsisten, bukan halaman HTML. Laravel memungkinkan kamu mengkustomisasi bagaimana exception ditangani berdasarkan tipe request — jika request menginginkan JSON, berikan JSON.

**Format Error API yang Baik:**
```json
{
    "message": "Data tidak valid.",
    "errors": {
        "judul": ["Judul buku wajib diisi."]
    }
}
```

**HTTP Status Code yang Umum untuk API:**
| Kode | Arti | Contoh |
|------|------|--------|
| 200 | OK | Berhasil mengambil data |
| 201 | Created | Berhasil membuat resource |
| 204 | No Content | Berhasil menghapus |
| 400 | Bad Request | Input tidak valid |
| 401 | Unauthenticated | Token tidak ada |
| 403 | Forbidden | Tidak punya izin |
| 404 | Not Found | Resource tidak ditemukan |
| 422 | Unprocessable Entity | Validasi gagal |
| 429 | Too Many Requests | Rate limit |
| 500 | Internal Server Error | Error server |

## Fungsi

- Memberikan response error yang konsisten untuk setiap jenis exception
- Menyembunyikan detail error di production (APP_DEBUG=false)
- Mempermudah client (mobile app, frontend) menangani error

## Cara Pengimplementasian

```php
<?php
// bootstrap/app.php — konfigurasi exception handler (Laravel 11)

->withExceptions(function (Exceptions $exceptions) {
    $exceptions->render(function (Throwable $e, Request $request) {
        // Hanya untuk API request
        if ($request->expectsJson() || $request->is('api/*')) {
            return match (true) {
                // Validasi error
                $e instanceof ValidationException =>
                    response()->json([
                        'message' => 'Data tidak valid.',
                        'errors'  => $e->errors(),
                    ], 422),

                // Belum login
                $e instanceof AuthenticationException =>
                    response()->json([
                        'message' => 'Tidak terautentikasi. Silakan login.',
                    ], 401),

                // Tidak punya izin
                $e instanceof AuthorizationException =>
                    response()->json([
                        'message' => 'Anda tidak memiliki izin.',
                    ], 403),

                // Resource tidak ditemukan
                $e instanceof ModelNotFoundException =>
                    response()->json([
                        'message' => 'Data tidak ditemukan.',
                    ], 404),

                // Route tidak ditemukan
                $e instanceof NotFoundHttpException =>
                    response()->json([
                        'message' => 'Endpoint tidak ditemukan.',
                    ], 404),

                // Terlalu banyak request
                $e instanceof ThrottleRequestsException =>
                    response()->json([
                        'message' => 'Terlalu banyak request. Coba lagi nanti.',
                    ], 429),

                // Error server (hanya di dev)
                default => response()->json([
                    'message' => $e->getMessage(),
                    'file'    => $e->getFile(),
                    'line'    => $e->getLine(),
                ], $e->getCode() ?: 500),

                // Di production — sembunyikan detail
                // app()->environment('production') =>
                //     response()->json([
                //         'message' => 'Terjadi kesalahan server.',
                //     ], 500),
            };
        }
    });
})
```

**Error Response untuk Validasi (422):**
```json
{
    "message": "Data tidak valid.",
    "errors": {
        "judul": ["Judul buku wajib diisi."],
        "tahun": ["Tahun harus antara 1000 dan 2024."]
    }
}
```

**Error Response untuk Autentikasi (401):**
```json
{
    "message": "Tidak terautentikasi. Silakan login."
}
```

## Analogi

Error handling API seperti **papan pengumuman error di perpustakaan digital**:

- **401 Unauthenticated** = "Anda belum login. Silakan ambil kartu anggota."
- **403 Forbidden** = "Maaf, ruang administrasi hanya untuk staf."
- **404 Not Found** = "Buku dengan nomor rak itu tidak ditemukan."
- **422 Validation Error** = "Formulir tidak lengkap: kolom judul kosong, tahun tidak valid."
- **429 Too Many Requests** = "Anda sudah 100 kali cek buku dalam 1 menit. Istirahat dulu."
- **500 Internal Server Error** = "Server perpustakaan sedang bermasalah. Coba lagi nanti."

Yang membedakan API dengan web:
- Web: error → halaman HTML cantik (403.blade.php, 404.blade.php)
- API: error → JSON dengan status code dan message

## Dipakai untuk Apa

- **Setiap API** — error harus JSON, bukan HTML
- **Production** — sembunyikan stack trace dari user
- **Mobile app** — client perlu format error yang konsisten untuk parsing
- **Third-party API** — dokumentasi error yang jelas

## Kesalahan Umum

1. **Error mengembalikan HTML di API** — karena tidak cek `$request->expectsJson()`. Pastikan mendeteksi request API
2. **Stack trace bocor di production** — `APP_DEBUG=true` → message error detail. Set `APP_DEBUG=false` di production
3. **Status code tidak sesuai** — validasi error harus 422, bukan 400. NotFound harus 404, bukan 500
4. **Pesan error tidak informatif** — "Error" saja tidak membantu. Berikan pesan yang jelas
5. **Error handling terlalu umum** — semua exception jadi 500. Tangani masing-masing tipe exception
6. **Lupa handle ModelNotFoundException** — resource tidak ditemukan jadi 500, bukan 404

   - **400 Bad Request** — kesalahan sintaks request (format JSON salah, header salah)
   - **422 Unprocessable Entity** — request valid secara sintaks, tapi secara semantik tidak dapat diproses (validasi gagal)
