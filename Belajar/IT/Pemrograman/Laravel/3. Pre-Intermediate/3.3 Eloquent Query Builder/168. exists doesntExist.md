# 168. exists doesntExist

## Definisi Singkat
`exists()` mengembalikan `true/false` apakah ada record yang memenuhi kondisi. `doesntExist()` kebalikannya — `true` jika tidak ada record.

## Analogi
Seperti mengecek apakah lemari masih kosong atau sudah terisi — tanpa perlu menghitung atau melihat detail isinya.

## Poin-Poin Penting
- `exists()` return `boolean` — lebih cepat dari `count() > 0`
- `doesntExist()` return `boolean` — kebalikan exists
- Lebih efisien karena query menggunakan `SELECT EXISTS(...)` atau `LIMIT 1`
- Cocok untuk validasi, pengecekan kondisi sebelum aksi
- Bisa dikombinasikan dengan semua kondisi (where, dll.)

## Contoh Kode
```php
use App\Models\User;
use App\Models\Post;

// exists — cek apakah ada
$hasActiveUsers = User::where('is_active', true)->exists();
if ($hasActiveUsers) {
    echo 'Ada user aktif';
}

// doesntExist — cek apakah tidak ada
$noProducts = Product::where('stock', '>', 0)->doesntExist();
if ($noProducts) {
    echo 'Stok habis';
}

// Validasi email unik
$emailExists = User::where('email', 'john@example.com')->exists();
if ($emailExists) {
    return back()->withErrors(['email' => 'Email sudah terdaftar']);
}

// Cek sebelum aksi
$user = User::find(1);
if ($user->posts()->where('is_published', true)->exists()) {
    echo 'User memiliki post yang dipublikasi';
}

// exists vs count — mana lebih cepat?
// exists: SELECT EXISTS(SELECT 1 FROM users WHERE ...) → true/false
// count: SELECT COUNT(*) FROM users WHERE ... → 0, 1, 100

// Biasanya exists lebih cepat, terutama untuk dataset besar
$slow = User::where('is_active', true)->count() > 0;  // hitung semua
$fast = User::where('is_active', true)->exists();     // stop di record pertama

// Di form request validation
public function rules(): array
{
    return [
        'email' => [
            'required',
            'email',
            Rule::unique('users')->where(fn ($q) => $q->where('is_active', true)),
        ],
    ];
}
```

## Kasus Penggunaan Nyata
- Cek apakah email sudah terdaftar sebelum register
- Validasi: apakah produk tersedia sebelum checkout
- Cek apakah user punya akses ke resource tertentu
- Conditional logic: "Jika ada pesanan baru, kirim notifikasi"
- Pengecekan relasi sebelum edit/hapus (cegah error)
