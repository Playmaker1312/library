### Definisi Singkat

**Memory leak** terjadi ketika memori yang tidak lagi digunakan tidak dikembalikan ke sistem karena masih ada referensi (secara tidak sengaja). Di JavaScript (dengan GC otomatis), leaks biasanya disebabkan oleh **referensi yang tidak sengaja dipertahankan** — membuat objek tetap reachable padahal sudah tidak diperlukan.

---

### Analogi

Seperti **gudang yang terus diisi barang** tanpa pernah membuang yang sudah tidak dipakai. Pemilik gudang (programmer) lupa bahwa ia masih menyimpan kunci ke kotak-kotak lama (referensi), sehingga petugas kebersihan (GC) tidak bisa membuangnya. Lambat laun gudang penuh dan tidak bisa menampung barang baru.

---

### Poin-Poin Penting

- **Penyebab umum**:
  - Global variable yang tidak sengaja (lupa `let`/`const`).
  - **Timers/listeners** yang tidak dibersihkan (`setInterval`, `addEventListener`).
  - **Closures** yang mempertahankan scope object besar.
  - **Cache** yang terus bertambah tanpa batas.
  - **DOM references** yang disimpan meskipun elemen sudah dihapus.
- **Deteksi**: Chrome DevTools → Memory tab → Heap Snapshot, Allocation Timeline, atau Performance monitor.
- **Pola aman**: Cleanup di `useEffect` return function, gunakan `WeakMap`/`WeakSet` untuk cache.

---

### Contoh Implementasi

```javascript
// LEAK 1: Global variable tidak sengaja
function leak1() {
  leaked = 'Saya global!'; // Tanpa let/const — jadi global
}

// LEAK 2: Timer tidak dibersihkan
class TimerComponent {
  constructor() {
    this.intervalId = setInterval(() => {
      console.log(this.data); // 'this' tertangkap closure
    }, 1000);
  }
  destroy() {
    clearInterval(this.intervalId); // WAJIB!
  }
}

// LEAK 3: Cache tak terbatas
const userCache = new Map();
function cacheUser(user) {
  userCache.set(user.id, user); // Terus bertambah — perlu eviction policy
}

// LEAK 4: DOM reference
const elements = [];
document.querySelectorAll('button').forEach((btn) => {
  elements.push(btn); // Meskipun button dihapus dari DOM, referensi tetap ada
});

// DETEKSI di DevTools
// 1. Performance → Record → lihat JS Heap naik terus
// 2. Memory → Heap Snapshot → cari "detached" DOM nodes
// 3. console — gunakan performance.memory (jika tersedia)
console.log(performance.memory); // { usedJSHeapSize, totalJSHeapSize, jsHeapSizeLimit }
```

---

### Koneksi

Berkaitan dengan **Garbage Collection** (GC membersihkan, leak mencegah GC), **WeakMap/WeakSet** (solusi cache aman), **Closures** (sumber leak yang umum), **Event Listeners** (perlu cleanup), dan **Chrome DevTools** (alat deteksi).
