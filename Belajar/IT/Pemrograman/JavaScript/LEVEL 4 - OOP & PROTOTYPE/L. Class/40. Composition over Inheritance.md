# Composition over Inheritance

## Penjelasan
Komposisi adalah prinsip "has-a" (memiliki) alih-alih "is-a" (adalah). Daripada mewarisi semua properti dari induk (inheritance), objek cukup menggabungkan modul/fungsi kecil yang dibutuhkan. Prinsip ini mengurangi kekakuan hierarki dan meningkatkan fleksibilitas. Ibarat rumah modular: bukan rumah turunan yang kaku, melainkan rumah yang bisa ditambah modul sumur, garasi, panel surya — sesuai kebutuhan.

## Fungsi
- Menghindari hierarki class yang dalam dan rapuh.
- Membuat kode lebih modular, mudah diuji, dan reusable.
- Menerapkan prinsip "favor composition over inheritance" dari Gang of Four.

## Cara Pengimplementasian

```javascript
// Composition — analogi RUMAH MODULAR

// Modul-modul kecil — fungsi yang mengembalikan object mixin
const punyaGarasi = (state) => ({
  parkir: (mobil) => `${mobil} diparkir di garasi ${state.garasi}`,
  kapasitasGarasi: () => state.garasi
});

const punyaKolam = (state) => ({
  berenang: () => "Berenang di kolam renang",
  isiKolam: () => "Mengisi kolam..."
});

const punyaListrik = (state) => ({
  nyalakanLampu: () => state.listrik ? "Lampu menyala" : "Listrik padam"
});

// Factory function — komposisi, bukan inheritance
function buatRumah(tipe, kamar, garasi = 0, kolam = false, listrik = true) {
  const state = { tipe, kamar, garasi, kolam, listrik };

  return {
    tipe: state.tipe,
    kamar: state.kamar,
    info() {
      return `${state.tipe} dengan ${state.kamar} kamar`;
    },
    // Komposisi: gabung modul yang relevan
    ...punyaGarasi(state),
    ...(kolam ? punyaKolam(state) : {}),
    ...punyaListrik(state)
  };
}

const rmh1 = buatRumah("Minimalis", 3, 1, false, true);
const rmh2 = buatRumah("Mewah", 6, 2, true, true);
const rmh3 = buatRumah("Kosan", 10, 0, false, false);

console.log(rmh1.info());          // "Minimalis dengan 3 kamar"
console.log(rmh1.parkir("Avanza")); // "Avanza diparkir di garasi 1"
console.log(rmh2.berenang());      // "Berenang di kolam renang"
console.log(rmh3.nyalakanLampu()); // "Listrik padam"
console.log(rmh3.berenang);        // undefined — rmh3 tidak punya kolam
```

## Analogi
Komposisi = **rumah modular dari IKEA**. Bukan rumah turunan dengan cetak biru tetap, melainkan Anda beli modul-modul: modul dapur, modul kamar tidur, modul garasi, modul panel surya. Setiap rumah dirakit berbeda sesuai kebutuhan. Rumah A punya garasi + kolam. Rumah B punya garasi + bengkel. Tidak perlu hierarki class yang kaku.

## Dipakai Untuk Apa
- Sistem yang membutuhkan fleksibilitas tinggi (game, plugin architecture)
- Proyek dengan banyak kombinasi fitur (bukan hierarki vertikal)
- Codebase yang ingin menghindari masalah "gorilla-banana" (mewarisi yang tidak perlu)

## Kesalahan Umum
- Mengabaikan inheritance sepenuhnya — keduanya punya tempat
- Mixin name collision — dua modul punya method nama sama
- Over-engineering — komposisi berlebihan untuk masalah sederhana
- Kehilangan konteks `this` saat memisahkan fungsi dari objek induk

## Keterkaitan dengan Materi Sebelumnya
Di Level 3, closure digunakan untuk membuat fungsi dengan private state. Composition memanfaatkan pola yang sama: factory function + closure untuk menyembunyikan state internal, lalu mengembalikan object dengan method yang membutuhkan state tersebut.

## Soal Latihan

Apa outputnya?

```javascript
const bisaTerbang = (state) => ({
  terbang: () => `${state.nama} terbang!`
});

const bisaBerenang = (state) => ({
  berenang: () => `${state.nama} berenang!`
});

function buatMakhluk(nama) {
  const state = { nama };
  return { nama, ...bisaTerbang(state), ...bisaBerenang(state) };
}

const bebek = buatMakhluk("Bebek");
console.log(bebek.terbang());
console.log(bebek.berenang());
```

>!`"Bebek terbang!"` lalu `"Bebek berenang!"`. Dengan komposisi, bebek mendapatkan method `terbang` dan `berenang` tanpa inheritance. Jika pakai inheritance, bebek harus punya class `Burung` dan `Ikan` sekaligus — tidak mungkin di JS (single inheritance).!
