### Definisi Singkat

**Cross-Site Scripting (XSS)** adalah celah keamanan di mana penyerang menyuntikkan (inject) script berbahaya ke halaman web yang dilihat pengguna lain. Script ini bisa mencuri cookie, token sesi, atau memanipulasi DOM. Pencegahan utama: **sanitasi input** dan **escaping output**.

---

### Analogi

Seperti **surat yang tampaknya biasa** tetapi berisi **bubuk beracun** — ketika penerima membukanya di dalam ruangan (browser), racun menyebar dan membahayakan semua orang di ruangan itu.

---

### Poin-Poin Penting

- **Tipe XSS**:
  - **Reflected XSS**: Payload ada di URL/request, langsung dieksekusi.
  - **Stored XSS**: Payload disimpan di server/database, dieksekusi setiap kali halaman dimuat.
  - **DOM-based XSS**: Payload dimanipulasi via client-side JavaScript (tanpa server).
- Pencegahan: jangan pernah gunakan `innerHTML`, `document.write()` dengan input mentah.
- Gunakan **Content Security Policy (CSP)** sebagai lapisan pertahanan tambahan.
- Framework modern (React, Vue) secara otomatis melakukan escaping di JSX/template — tetapi tetap waspada dengan `dangerouslySetInnerHTML`.

---

### Contoh Implementasi

```javascript
// RENTAN — JANGAN DILAKUKAN
const userInput = "<img src=x onerror=alert('XSS')>";
document.getElementById('output').innerHTML = userInput;

// AMAN — escape HTML
function escapeHTML(str) {
  const div = document.createElement('div');
  div.textContent = str;
  return div.innerHTML;
}

document.getElementById('output').textContent = userInput; // Cara termudah
// Atau
document.getElementById('output').innerHTML = escapeHTML(userInput);

// Server-side sanitasi (Node.js dengan DOMPurify)
const createDOMPurify = require('dompurify');
const purify = createDOMPurify(window);
const clean = purify.sanitize(userInput);
```

---

### Koneksi

Berhubungan erat dengan **CSP** (pertahanan lapisan kedua), **CSRF** (sering dikombinasikan dalam serangan), **CORS** (membatasi akses cross-origin), dan **HTTPS** (mencegah man-in-the-middle injection).
