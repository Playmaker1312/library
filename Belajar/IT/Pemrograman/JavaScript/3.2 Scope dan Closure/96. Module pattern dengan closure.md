### Definisi Singkat

Module pattern adalah pola desain yang menggunakan closure untuk menciptakan kode yang terenkapsulasi — memiliki bagian publik (public API) dan bagian privat (private data/method) yang tidak bisa diakses dari luar. Pola ini dominan sebelum ES6 modules hadir.

---

### Analagi

Bayangkan **ATM (Anjungan Tunai Mandiri)**:

- **Public API:** Tombol-tombol yang bisa Anda tekan — "Cek Saldo", "Tarik Tunai", "Setor Tunai".
- **Private data/logic:** Mesin di dalam ATM — saldo sebenarnya, algoritma keamanan, koneksi ke bank — Anda tidak bisa mengakses ini langsung.
- Anda hanya bisa berinteraksi melalui antarmuka publik yang disediakan — persis seperti module pattern.

---

### Poin-Poin Penting

- Module pattern menggunakan **IIFE** yang mengembalikan objek dengan method-method publik.
- Data dan fungsi privat tetap aman di dalam closure — tidak bisa diakses langsung.
- Pola ini menciptakan **single instance** (singleton) jika menggunakan IIFE.
- Bisa juga dibuat **multiple instance** dengan fungsi factory (non-IIFE).
- Sebelum ES6 modules (`import`/`export`), ini adalah standar de facto untuk modularitas JavaScript.
- Module pattern masih digunakan di beberapa kode legacy dan situasi yang tidak menggunakan bundler.

---

### Contoh Implementasi

```javascript
// Module pattern — singleton dengan IIFE
const App = (function() {
    // Private data
    let versi = "1.0.0";
    const config = {
        apiUrl: "https://api.example.com",
        timeout: 5000
    };
    
    // Private function
    function validasiInput(input) {
        return input && input.trim().length > 0;
    }
    
    function log(action) {
        console.log(`[${versi}] ${action} pada ${new Date().toISOString()}`);
    }
    
    // Public API
    return {
        getVersi: function() {
            return versi;
        },
        setVersi: function(v) {
            versi = v;
            log("Versi diubah ke " + v);
        },
        prosesData: function(data) {
            if (!validasiInput(data)) {
                return "Data tidak valid";
            }
            log("Data diproses: " + data);
            return `Data "${data}" berhasil diproses`;
        },
        getConfig: function() {
            return { ...config }; // return copy agar tidak dimodifikasi
        }
    };
})();

console.log(App.getVersi());    // "1.0.0"
console.log(App.prosesData("Test")); // "Data 'Test' berhasil diproses"
App.setVersi("2.0.0");
console.log(App.getVersi());    // "2.0.0"
// console.log(App.versi);     // undefined — private
// console.log(App.config);    // undefined — private

// Factory pattern — multiple instance dengan closure
function buatLogger(nama) {
    const logs = [];
    
    return {
        tambahLog: function(pesan) {
            logs.push({ pesan, waktu: new Date() });
        },
        lihatLog: function() {
            return [...logs];
        },
        getNama: function() {
            return nama;
        }
    };
}

const logger1 = buatLogger("Modul A");
const logger2 = buatLogger("Modul B");
logger1.tambahLog("Mulai");
logger2.tambahLog("Proses");
console.log(logger1.lihatLog().length); // 1
console.log(logger2.lihatLog().length); // 1
```

---

### Koneksi

Module pattern adalah penerapan langsung dari **closure** dan **IIFE**. Pola ini menjadi cikal bakal **ES6 modules** (`import`/`export`), **CommonJS** (Node.js `require`), dan **AMD** (RequireJS). Memahami module pattern membantu developer memahami evolusi modularitas di JavaScript dan menghargai kemudahan ES6 modules modern.
