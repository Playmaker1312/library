### Definisi Singkat
**Circular dependency** terjadi ketika module A meng-import module B, dan module B (secara langsung atau tidak langsung) meng-import module A. ES Modules bisa menangani circular dependency karena binding bersifat **live**, tapi perlu hati-hati dengan **Temporal Dead Zone (TDZ)**.

---

### Analogi
Circular dependency seperti **dua telepon yang saling memanggil**. A menelepon B, B menelepon A — tidak ada yang bisa menyelesaikan panggilan. Dalam module, circular dependency bisa bekerja jika keduanya tidak langsung membutuhkan nilai satu sama lain saat inisialisasi.

---

### Poin-Poin Penting
- ES Modules menggunakan **live binding** — export yang di-import selalu mereferensi nilai terbaru
- Masalah utama terjadi saat **initialization order** — module yang belum selesai diinisialisasi dibaca
- Fungsi (function declaration) di-hoisted, aman untuk circular
- Const/let/class tidak di-hoisted — bisa menyebabkan error `ReferenceError` (TDZ)
- Solusi: **refactor** — extract dependency bersama ke module ketiga
- Solusi: gunakan function yang dipanggil setelah semua terinisialisasi

---

### Contoh Implementasi

```javascript
// a.js
import { b } from './b.js';
export const a = 'A';
export function getA() { return a; }
export function test() {
  console.log('A memanggil:', b); // OK — function dijalankan setelah inisialisasi
}

// b.js
import { a } from './a.js';
export const b = 'B';
export function test() {
  console.log('B memanggil:', a); // OK
}

// Masalah: initial value
// a.js
import { b } from './b.js';
export const aVal = b; // ERROR: b belum diinisialisasi (undefined)
// Karena a.js di-load dulu, b.js belum selesai

// Solusi: gunakan function
// a.js
export function getB() {
  return requireOrImportB(); // Panggil saat dibutuhkan
}

// Solusi lebih baik: extract shared
// shared.js
export const shared = 'shared';

// a.js
import { shared } from './shared.js';

// b.js
import { shared } from './shared.js';
// Tidak circular!
```
