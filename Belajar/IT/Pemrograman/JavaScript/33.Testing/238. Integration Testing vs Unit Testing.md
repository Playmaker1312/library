### Definisi Singkat

**Unit Testing** menguji komponen individu secara terisolasi (dengan mock). **Integration Testing** menguji interaksi antara beberapa komponen, modul, atau sistem secara nyata — memastikan bahwa unit-unit yang sudah lulus unit test bekerja sama dengan benar. Keduanya adalah bagian dari Test Pyramid.

---

### Analogi

Seperti **menguji pabrik mobil**:
- **Unit Test** = uji mesin, uji rem, uji roda secara terpisah di laboratorium
- **Integration Test** = pasang mesin ke mobil, nyalakan, injak gas — apakah roda berputar? Apakah speedometer naik?
- Unit test bilang komponen OK, integration test bilang komponen bekerja **bersama** dengan OK

---

### Poin-Poin Penting

#### Unit Testing
- Menguji satu unit kode (fungsi, method, class) dalam isolasi
- Dependensi eksternal di-mock/stub
- Sangat cepat (ms per test)
- Mudah di-maintain dan di-debug
- Coverage tinggi mudah dicapai

#### Integration Testing
- Menguji interaksi antar komponen (modul, database, API, file system)
- Dependensi nyata (atau seminimal mungkin mocking)
- Lebih lambat dari unit test (detik per test)
- Menangkap bug yang tidak terdeteksi unit test (masalah integrasi)
- Lebih sedikit jumlahnya daripada unit test

#### Test Pyramid
```
    /\
   /  \        ← E2E (End-to-End) — sedikit
  /    \
 /      \      ← Integration — sedang
/________\
  Unit Test    ← Unit — banyak
```

### Contoh Implementasi

```javascript
// === UNIT TEST ===
// Fungsi individual dengan mock
const userService = require('./userService');
const emailService = require('./emailService');

jest.mock('./emailService');

test('registerUser menyimpan user dan kirim email', () => {
  const mockEmail = { sendWelcome: jest.fn() };
  emailService.mockImplementation(() => mockEmail);

  const result = userService.registerUser('budi@test.com', 'Budi');

  expect(result).toHaveProperty('id');
  expect(mockEmail.sendWelcome).toHaveBeenCalledWith('budi@test.com');
});

// === INTEGRATION TEST ===
// Interaksi nyata antar modul (misal: dengan database test)
describe('User Registration Integration', () => {
  beforeAll(async () => {
    // Setup database test
    await db.connect(process.env.TEST_DATABASE_URL);
    await db.migrate();
  });

  afterAll(async () => {
    await db.disconnect();
  });

  test('register dan login flow berhasil', async () => {
    // Test alur lengkap tanpa mock
    const user = await userController.register({
      email: 'test@test.com',
      password: 'password123'
    });
    expect(user).toHaveProperty('id');

    const loginResult = await authController.login({
      email: 'test@test.com',
      password: 'password123'
    });
    expect(loginResult).toHaveProperty('token');

    // Bersihkan data test
    await db.clean();
  });
});
```

### Koneksi

Unit Testing (file 233) dan Integration Testing adalah dua level dalam Test Pyramid. Keduanya menggunakan **Jest** (file 234) dan **Matchers** (file 235). TDD (file 237) biasanya dimulai dengan unit test, tapi integration test juga penting untuk validasi alur. **Mock Functions** (file 236) lebih banyak digunakan di unit test.
