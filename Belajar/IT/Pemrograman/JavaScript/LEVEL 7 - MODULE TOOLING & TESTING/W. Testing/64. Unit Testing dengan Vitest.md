# Unit Testing dengan Vitest

## Penjelasan
**Vitest** adalah framework unit testing untuk JavaScript/TypeScript yang terintegrasi erat dengan Vite — menggunakan konfigurasi, plugin, dan pipeline transformasi yang sama. Vitest sangat cepat karena arsitekturnya berbasis Vite dan mendukung HMR untuk test (ubah kode → test ulang otomatis). Sintaksnya mirip Jest (`describe`, `it`, `expect`), sehingga mudah dipelajari.

## Fungsi
- **Unit testing** — menguji fungsi terkecil (unit) secara terisolasi
- **Test runner** — menjalankan test dan melaporkan hasil (pass/fail)
- **Assertion & matchers** — memverifikasi bahwa output sesuai ekspektasi
- **Mocking & spying** — mengganti dependensi nyata dengan versi palsu untuk isolasi
- **Coverage** — mengukur seberapa banyak kode yang tercakup test

## Cara Pengimplementasian

### Setup
```bash
npm install --save-dev vitest

# Tambahkan script di package.json
# "test": "vitest"
# "test:ui": "vitest --ui"      # visual interface
# "test:coverage": "vitest --coverage"
```

### Konfigurasi (vite.config.js)
```js
import { defineConfig } from "vite";

export default defineConfig({
  test: {
    globals: true,        // describe, it, expect tanpa import
    environment: "node",  // atau "jsdom" untuk DOM testing
  },
});
```

### Unit Test Sederhana
```js
// 📁 src/hitungLuas.js — fungsi menghitung luas rumah
export function hitungLuas(panjang, lebar) {
  if (panjang <= 0 || lebar <= 0) throw new Error("Dimensi tidak valid");
  return panjang * lebar;
}

// 📁 src/hitungLuas.test.js — test untuk fungsi di atas
import { describe, it, expect } from "vitest";
import { hitungLuas } from "./hitungLuas";

describe("hitungLuas — menghitung luas ruangan", () => {
  it("menghitung luas persegi panjang dengan benar", () => {
    expect(hitungLuas(10, 5)).toBe(50);
  });

  it("menghasilkan angka positif untuk dimensi positif", () => {
    expect(hitungLuas(3, 4)).toBeGreaterThan(0);
  });

  it("melempar error jika panjang <= 0", () => {
    expect(() => hitungLuas(0, 5)).toThrow("Dimensi tidak valid");
  });

  it("melempar error jika lebar <= 0", () => {
    expect(() => hitungLuas(5, -1)).toThrow();
  });
});
```

### Berbagai Matcher
```js
// Matcher umum — seperti alat ukur rumah
expect(hasil).toBe(50);               // Nilai persis (===)
expect(hasil).toEqual({ luas: 50 });  // Nilai sama (deep equality)
expect(arr).toContain("kamar");       // Array mengandung
expect(str).toMatch(/rumah/);         // Regex match
expect(fn).toThrow();                 // Fungsi melempar error
expect(val).toBeDefined();            // Tidak undefined
expect(val).toBeNull();               // Null
expect(val).toBeTruthy();             // Truthy
expect(val).toBeFalsy();              // Falsy
expect(val).toBeGreaterThan(10);      // > 10
expect(val).toBeLessThan(100);        // < 100
```

### Running Test
```bash
npm run test          # Jalankan sekali
npm run test --watch  # Jalankan terus (watch mode)
npm run test --coverage  # Dengan laporan coverage
npm run test src/rumah.test.js  # File spesifik
```

### Test dengan Setup/Teardown
```js
describe("Rumah", () => {
  // beforeAll: saat kontraktor tiba (sekali sebelum semua test)
  beforeAll(() => console.log("Mulai inspeksi rumah"));
  
  // afterAll: saat kontraktor pulang
  afterAll(() => console.log("Selesai inspeksi rumah"));
  
  // beforeEach: sebelum tiap ruangan diperiksa
  beforeEach(() => console.log("Masuk ruangan baru"));
  
  // afterEach: setelah tiap ruangan diperiksa
  afterEach(() => console.log("Keluar ruangan"));
  
  it("kamar tidur memiliki tempat tidur", () => {
    expect(true).toBe(true);
  });
});
```

## Analogi
**Unit Testing** ibarat **inspeksi kualitas rumah** sebelum dihuni. `describe` adalah **nama ruangan** yang akan diperiksa. `it` adalah **satu item inspeksi** — misal "pintu terbuka dengan benar" atau "jendela tidak pecah". `expect` adalah **alat ukur** yang membandingkan kondisi aktual dengan standar. `matcher` (`toBe`, `toThrow`, dll) adalah **berbagai alat inspeksi**: meteran (`toBeGreaterThan`), waterpass (`toEqual`), spirit level (`toMatch`). `vitest --watch` adalah **inspektur yang tinggal di rumah** dan langsung memeriksa ulang setiap ada perubahan. `coverage` adalah **laporan area rumah yang sudah diperiksa** — berapa persen yang sudah diinspeksi.

| Konsep | Analogi Rumah |
|---|---|
| Vitest | Kontraktor inspeksi kualitas |
| `describe` | Ruangan yang diperiksa |
| `it` / `test` | Satu item inspeksi |
| `expect` | Alat ukur/inspeksi |
| `matchers` | Jenis alat ukur (meteran, waterpass) |
| `beforeEach` | Persiapan sebelum masuk ruangan |
| `--watch` | Inspektur yang tinggal di rumah |
| Coverage | Laporan persentase area terinspeksi |
| Passing test | Semua item sesuai standar |
| Failing test | Ada cacat yang harus diperbaiki |

## Dipakai Untuk Apa
- Verifikasi fungsi matematika/utilitas bekerja dengan benar
- Test edge cases — input kosong, negatif, desimal, null
- Regression testing — memastikan fitur lama tidak rusak setelah perubahan
- TDD (Test-Driven Development) — menulis test sebelum implementasi
- CI/CD — test otomatis berjalan setiap kali ada commit/push

## Kesalahan Umum
- Testing terlalu banyak hal dalam satu `it` — satu test sebaiknya satu perilaku spesifik
- Lupa handle async — test terhadap Promise tanpa `await` lolos padahal belum selesai
- Test bergantung pada state global yang tidak di-reset antar test — test jadi flaky
- Menulis test yang terlalu umum (selalu pass) — tidak berguna, memberi false confidence
- Mengabaikan test yang fail — test fail adalah sinyal masalah, bukan gangguan
- Tidak menguji error path — hanya menguji "happy path" padahal error handling vital

## Keterkaitan dengan Materi Sebelumnya
- **LEVEL 1 (Fundamental)**: Testing memverifikasi fundamental seperti tipe data, truthy/falsy
- **LEVEL 2 (Function)**: Unit test terutama menguji fungsi — pure function paling mudah di-test
- **LEVEL 3 (Object & Array)**: `toEqual()` digunakan untuk membandingkan object/array
- **LEVEL 4 (DOM)**: Vitest dengan `environment: "jsdom"` bisa test manipulasi DOM
- **LEVEL 5 (Asynchronous)**: Vitest mendukung test async dengan `await`
- **LEVEL 6 (OOP)**: Class bisa di-test dengan membuat instance dan memverifikasi method
- **LEVEL 7 (File 62)**: Vitest diinstall via NPM dan terintegrasi dengan Vite config

1. Tulis unit test untuk fungsi `formatAlamat(jalan, kota)` yang mengembalikan string `"Jalan {jalan}, Kota {kota}"`. Uji juga jika jalan atau kota kosong.

>!jawaban: ```js

>! export function formatAlamat(jalan, kota) {

>! }
>!
>! // src/formatAlamat.test.js
>! import { describe, it, expect } from "vitest";
>! import { formatAlamat } from "./formatAlamat";
>!
>! describe("formatAlamat", () => {
>!   it("mengembalikan format alamat yang benar", () => {
>!     expect(formatAlamat("Merdeka", "Jakarta")).toBe("Jalan Merdeka, Kota Jakarta");
>!   });
>!   it("melempar error jika jalan kosong", () => {
>!     expect(() => formatAlamat("", "Jakarta")).toThrow();

2. Apa beda `toBe` dan `toEqual` di Vitest?

>!jawaban: `toBe` menggunakan `Object.is()` — cocok untuk primitive (angka, string, boolean). `toEqual` melakukan **deep equality check** — cocok untuk object dan array. Contoh: `expect({ a: 1 }).toBe({ a: 1 })` akan fail (beda referensi), sedangkan `toEqual` akan pass.!
