# 401. Monolith vs Microservices PHP

## Definisi Singkat
Monolith adalah arsitektur aplikasi dalam satu kesatuan kode, sedangkan Microservices memecah aplikasi menjadi layanan-layanan kecil yang independen dan berkomunikasi via API/network.

## Analogi
Monolith seperti rumah toko: semua ada di satu bangunan (toko, gudang, kantor). Microservices seperti kompleks pertokoan dengan bangunan terpisah untuk toko baju, toko buku, dan restoran — masing-masing berdiri sendiri dengan pintu sendiri.

## Poin-Poin Penting
- **Monolith**: lebih sederhana, development cepat di awal, satu database, mudah di-deploy
- **Microservices**: skala besar, tim bisa bekerja independen, tiap service punya database sendiri
- PHP cocok untuk monolith (Laravel/Symfony) dan microservices (Lumen/Symfony MicroKernel)
- Komunikasi antar service: REST API, gRPC, atau message queue
- Tantangan microservices: kompleksitas jaringan, data consistency, debugging

## Contoh Kode
```php
<?php
// Monolith — semua dalam satu proyek Laravel
Route::get('/orders', [OrderController::class, 'index']);
Route::get('/products', [ProductController::class, 'index']);

// Microservices — komunikasi via HTTP
// Service Order memanggil Service Product via HTTP
class OrderService {
    public function getProductData(int $productId): array {
        $response = Http::get('http://product-service/api/products/' . $productId);
        return $response->json();
    }
}
// Output: data produk dari service terpisah
?>
```

## Kasus Penggunaan Nyata
Startup biasanya mulai dengan monolith, lalu migrasi ke microservices ketika tim dan skala bertambah besar — seperti Tokopedia yang awalnya monolith PHP kemudian bertransisi.
