# 410. API versioned backward compatible

## Definisi Singkat
API versioning adalah strategi mengelola perubahan API dengan cara membuat versi berbeda sehingga client lama tetap berfungsi (backward compatible) saat API diperbarui.

## Analogi
Seperti aplikasi mobile — versi 1.0 punya tombol hijau, versi 2.0 ubah jadi biru. Tapi versi 1.0 tetap berjalan karena ada adapter. Pengguna versi lama tidak akan crash saat dapat update server.

## Poin-Poin Penting
- **URI Versioning**: `/api/v1/users`, `/api/v2/users`
- **Header Versioning**: `Accept: application/vnd.myapp.v1+json`
- **Query Parameter**: `/api/users?version=1`
- Aturan backward compatibility: jangan hapus field, jangan ubah tipe data, field baru bersifat opsional
- Deprecation: beri header `Deprecated: true` dan `Sunset: date`
- Gunakan transformer/adapter untuk mapping antar versi

## Contoh Kode
```php
<?php
// Route versioning di Laravel
// routes/api_v1.php
Route::get('/users', function () {
    return UserResource::collection(User::all());
});

// routes/api_v2.php
Route::get('/users', function () {
    return UserV2Resource::collection(User::with('profile')->get());
});

// AppServiceProvider
public function boot(): void {
    Route::prefix('api/v1')
        ->group(base_path('routes/api_v1.php'));
    Route::prefix('api/v2')
        ->group(base_path('routes/api_v2.php'));
}

// Transformer — backward compatible
class UserV2Resource extends JsonResource {
    public function toArray($request): array {
        return [
            'id' => $this->id,
            'name' => $this->name,
            'email' => $this->email,
            'avatar' => $this->avatar_url,
            // Field baru — tambahkan, jangan ubah field lama
            'phone' => $this->phone ?? null,  // Opsional
            'address' => $this->profile->address ?? null,  // Opsional
        ];
    }
}
// Output: /api/v1/users tetap berfungsi, /api/v2/users punya field tambahan
?>
```

## Kasus Penggunaan Nyata
Public API seperti Stripe, GitHub API, atau Twitter API — ribuan aplikasi pihak ketiga bergantung padanya. Versioning memastikan aplikasi lawas tidak rusak saat API ditingkatkan.
