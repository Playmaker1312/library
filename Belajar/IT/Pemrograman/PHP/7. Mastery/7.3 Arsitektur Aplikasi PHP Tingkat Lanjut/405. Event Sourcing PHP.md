# 405. Event Sourcing PHP

## Definisi Singkat
Event Sourcing adalah pola penyimpanan di mana setiap perubahan state disimpan sebagai urutan event (kejadian), bukan hanya state saat ini. State saat ini direkonstruksi dari history event.

## Analogi
Seperti buku harian keuangan — bukan hanya catatan saldo akhir, tetapi setiap transaksi (pemasukan, pengeluaran) dicatat. Untuk tahu saldo saat ini, Anda jumlahkan semua transaksi dari awal.

## Poin-Poin Penting
- Event bersifat immutable — tidak bisa diubah/dihapus setelah disimpan
- Aggregate Root menangani event dan menjaga konsistensi
- Event Store — database khusus untuk menyimpan event (bisa pakai DB biasa)
- Projection — membangun read model dari event untuk query cepat
- Keuntungan: audit trail lengkap, temporal query (state di masa lalu), debuggability tinggi

## Contoh Kode
```php
<?php
// Event
class MoneyDeposited {
    public function __construct(
        public string $accountId,
        public float $amount,
        public \DateTimeImmutable $occurredAt
    ) {}
}

// Aggregate
class BankAccount {
    private string $id;
    private float $balance = 0;
    private array $events = [];

    public static function open(string $id): self {
        $account = new self();
        $account->recordThat(new AccountOpened($id, new \DateTimeImmutable()));
        return $account;
    }

    public function deposit(float $amount): void {
        $this->recordThat(new MoneyDeposited($this->id, $amount, new \DateTimeImmutable()));
    }

    private function recordThat(object $event): void {
        $this->apply($event);
        $this->events[] = $event;
    }

    private function apply(object $event): void {
        match (true) {
            $event instanceof MoneyDeposited => $this->balance += $event->amount,
            $event instanceof MoneyWithdrawn => $this->balance -= $event->amount,
            default => null
        };
    }

    public function getEvents(): array { return $this->events; }
    public function getBalance(): float { return $this->balance; }
}
// Output: setiap transaksi tercatat, saldo dihitung dari event
?>
```

## Kasus Penggunaan Nyata
Sistem finansial (perbankan, akuntansi), audit trail (riwayat perubahan data), aplikasi dengan requirement compliance tinggi, dan sistem yang perlu rollback/replay.
