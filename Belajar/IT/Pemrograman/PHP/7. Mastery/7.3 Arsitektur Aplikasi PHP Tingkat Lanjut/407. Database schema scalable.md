# 407. Database schema scalable

## Definisi Singkat
Database schema yang scalable adalah desain skema database yang dapat menangani pertumbuhan data dan traffic tanpa degradasi performa signifikan.

## Analogi
Seperti sistem jalan tol yang dirancang untuk 10 tahun ke depan — bukan jalan kampung yang macet setelah 1 tahun. Ada jalur tambahan, pintu keluar strategis, dan sistem manajemen lalu lintas.

## Poin-Poin Penting
- **Indexing** strategis pada kolom yang sering di-query (WHERE, JOIN, ORDER BY)
- **Normalisasi** untuk integritas data, denormalisasi untuk performa baca
- **Partitioning** — membagi tabel besar menjadi partisi lebih kecil (by date, region)
- **Sharding** — membagi data ke beberapa database server (horizontal scaling)
- **Read Replicas** — database terpisah untuk operasi baca
- **Pagination** (LIMIT/OFFSET atau cursor-based) untuk data besar

## Contoh Kode
```php
<?php
// Migration: index + partition (MySQL)
Schema::create('orders', function (Blueprint $table) {
    $table->id();
    $table->foreignId('user_id')->constrained()->index();
    $table->decimal('total', 15, 2);
    $table->string('status', 20)->index();
    $table->timestamp('created_at')->index(); // untuk query by date
    // PARTITION BY RANGE (YEAR(created_at)) — via raw SQL
});

// Query dengan pagination cursor-based
$orders = Order::where('user_id', $userId)
    ->where('id', '>', $lastId)  // Cursor-based pagination
    ->orderBy('id')
    ->limit(20)
    ->get();

// Read Replica — di Laravel config/database.php
'mysql' => [
    'read' => ['host' => env('DB_READ_HOST', '127.0.0.1')],
    'write' => ['host' => env('DB_WRITE_HOST', '127.0.0.1')],
],
// Output: query cepat meski data jutaan baris
?>
```

## Kasus Penggunaan Nyata
Aplikasi SaaS dengan jutaan pengguna, e-commerce besar (TikTok Shop, Tokopedia), sistem log dengan miliaran baris, dan aplikasi real-time yang butuh respons cepat.
