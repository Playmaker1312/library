# 406. Clean Architecture PHP

## Definisi Singkat
Clean Architecture oleh Robert C. Martin (Uncle Bob) adalah pola arsitektur yang memisahkan kode ke dalam lapisan (layers) berbentuk lingkaran konsentris dengan aturan dependensi: inner layer tidak boleh tahu tentang outer layer.

## Analogi
Seperti bawang bombay — lapisan terdalam (domain) paling inti, makin ke luar makin detail teknis. Anda bisa kupas lapisan luar tanpa mengganggu inti.

## Poin-Poin Penting
- **Entities** (lapisan 0) — business rules paling inti, tidak tergantung apa pun
- **Use Cases** (lapisan 1) — application-specific business rules
- **Interface Adapters** (lapisan 2) — controller, presenter, gateway
- **Frameworks & Drivers** (lapisan 3) — database, web framework, UI
- Aturan dependensi: hanya outer layer yang tahu inner layer, jangan sebaliknya
- Dependency Inversion: interface di inner, implementasi di outer

## Contoh Kode
```php
<?php
// Layer 0 — Entity
class User {
    public function __construct(
        private string $id,
        private string $email,
        private bool $isActive = true
    ) {}

    public function deactivate(): void {
        if (!$this->isActive) {
            throw new \DomainException('User sudah tidak aktif');
        }
        $this->isActive = false;
    }
}

// Layer 1 — Use Case
class DeactivateUserUseCase {
    public function __construct(
        private UserRepositoryInterface $userRepo  // Interface, bukan implementasi
    ) {}

    public function execute(string $userId): void {
        $user = $this->userRepo->findById($userId);
        $user->deactivate();
        $this->userRepo->save($user);
    }
}

// Layer 2 — Interface (defined in inner layer)
interface UserRepositoryInterface {
    public function findById(string $id): User;
    public function save(User $user): void;
}

// Layer 3 — Implementation di framework layer
class LaravelUserRepository implements UserRepositoryInterface {
    public function findById(string $id): User { /* ... */ }
    public function save(User $user): void { /* ... */ }
}
// Output: kode independen dari framework, mudah di-test
?>
```

## Kasus Penggunaan Nyata
Aplikasi yang perlu di-maintain jangka panjang dengan framework yang mungkin berganti — logika bisnis tetap aman di lapisan terdalam, framework bisa diganti tanpa efek samping.
