# 408. Caching strategy aplikasi besar

## Definisi Singkat
Caching strategy adalah pendekatan sistematis untuk menyimpan data yang sering diakses di media penyimpanan cepat (memory) untuk mengurangi beban database dan mempercepat response.

## Analogi
Seperti kulkas di rumah — Anda tidak pergi ke supermarket (database) setiap kali mau makan. Anda simpan bahan makanan sering pakai di kulkas (cache), cukup ambil cepat saat dibutuhkan.

## Poin-Poin Penting
- **Cache tiers**: in-memory (Redis/Memcached), HTTP cache (Varnish/CDN), opcode cache (OPcache)
- **Strategy**: Cache-Aside (lazy loading), Write-Through, Write-Behind, Cache Invalidation
- **TTL (Time-To-Live)** — set waktu kadaluwarsa cache
- **Cache Invalidation** — tantangan terbesar: hapus/update cache saat data berubah
- **Cache Key** — gunakan prefix dan struktur yang konsisten

## Contoh Kode
```php
<?php
// Cache-Aside pattern dengan Redis di Laravel
class ProductService {
    public function __construct(
        private Cache $cache,
        private ProductRepository $repo
    ) {}

    public function getProduct(int $id): array {
        $cacheKey = "product:{$id}";

        return $this->cache->remember($cacheKey, 3600, function () use ($id) {
            // Cache miss — ambil dari DB, simpan ke cache
            return $this->repo->findById($id)->toArray();
        });
    }

    public function updateProduct(int $id, array $data): Product {
        $product = $this->repo->update($id, $data);
        // Invalidate cache
        $this->cache->forget("product:{$id}");
        return $product;
    }
}

// Cache full page response
Route::get('/products', [ProductController::class, 'index'])
    ->middleware('cache.headers:public;max_age=3600;etag');
// Output: response cepat dari cache, database tidak terbebani
?>
```

## Kasus Penggunaan Nyata
Landing page dengan traffic tinggi, katalog produk e-commerce, daftar artikel berita, session management, dan API rate-limited — semuanya butuh caching untuk performa.
