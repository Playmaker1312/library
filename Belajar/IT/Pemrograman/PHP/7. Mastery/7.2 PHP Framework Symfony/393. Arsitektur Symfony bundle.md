# 393. Arsitektur Symfony bundle

## Definisi Singkat
Bundle di Symfony adalah paket kode terstruktur (controller, entity, config, view) yang dapat dipasang dan digunakan ulang, mirip plugin di aplikasi lain, dan merupakan inti arsitektur Symfony.

## Analogi
Seperti kepingan puzzle yang bisa dipasang dan dilepas — setiap bundle adalah fitur mandiri yang bisa ditambahkan ke aplikasi tanpa mengganggu bundle lain.

## Poin-Poin Penting
- Setiap bundle adalah direktori dengan struktur standar: `Controller/`, `Entity/`, `Resources/`, `DependencyInjection/`
- Kernel mendaftarkan semua bundle di `config/bundles.php`
- Bundle bisa dari vendor pihak ketiga (doctrine, mailer, security) atau kustom
- Bundle kustom dibuat dengan `php artisan make:bundle` atau struktur manual
- Konvensi penamaan: `VendorNameBundle` (NamespaceBundle)

## Contoh Kode
```php
<?php
// Isi config/bundles.php
return [
    Symfony\Bundle\FrameworkBundle\FrameworkBundle::class => ['all' => true],
    Symfony\Bundle\TwigBundle\TwigBundle::class => ['all' => true],
    Doctrine\Bundle\DoctrineBundle\DoctrineBundle::class => ['all' => true],
    App\AppBundle\AppBundle::class => ['all' => true], // Bundle kustom
];

// Struktur bundle kustom:
// src/AppBundle/
// ├── Controller/
// ├── Entity/
// ├── Repository/
// ├── Resources/views/
// └── AppBundle.php
// Output: bundle terdaftar dan siap digunakan
?>
```

## Kasus Penggunaan Nyata
Memisahkan modul aplikasi seperti user management, product catalog, payment gateway — masing-masing bundle bisa dikembangkan tim berbeda dan digunakan di proyek lain.
