# 360. Testing di CI/CD Pipeline

## Definisi Singkat
Integrasi testing dalam CI/CD pipeline memastikan setiap perubahan kode di-test secara otomatis sebelum di-deploy.

## Analogi
Seperti jalur produksi pabrik — setiap produk melewati pos pemeriksaan kualitas sebelum sampai ke konsumen.

## Poin-Poin Penting
- CI: GitHub Actions, GitLab CI, Jenkins — jalankan test otomatis
- Setiap push/PR menjalankan test suite
- Pipeline biasanya: lint → unit test → integration test → coverage → deploy
- Fail fast: hentikan pipeline jika test gagal
- Environment terisolasi untuk test (Docker, test database)

## Contoh Kode (PHP)
```yaml
# .github/workflows/tests.yml — GitHub Actions
name: PHP Tests
on: [push, pull_request]

jobs:
  test:
    runs-on: ubuntu-latest
    services:
      mysql:
        image: mysql:8
        env:
          MYSQL_ROOT_PASSWORD: test
          MYSQL_DATABASE: test_db
        ports:
          - 3306:3306
    
    steps:
      - uses: actions/checkout@v4
      
      - name: Setup PHP
        uses: shivammathur/setup-php@v2
        with:
          php-version: '8.3'
          extensions: pdo, pdo_mysql, xdebug
          coverage: xdebug
      
      - name: Install dependencies
        run: composer install --prefer-dist --no-progress
      
      - name: Lint PHP
        run: vendor/bin/phpcs --standard=PSR12 src/
      
      - name: Run unit tests
        run: vendor/bin/phpunit --testsuite=Unit
        
      - name: Run integration tests
        run: vendor/bin/phpunit --testsuite=Integration
        env:
          DB_HOST: 127.0.0.1
          DB_DATABASE: test_db
          DB_USERNAME: root
          DB_PASSWORD: test
      
      - name: Upload coverage
        uses: codecov/codecov-action@v3
        with:
          file: ./coverage.xml
```

## Kasus Penggunaan Nyata
Semua proyek profesional — menjamin kualitas kode sebelum merge ke branch utama, mencegah regression di produksi.
