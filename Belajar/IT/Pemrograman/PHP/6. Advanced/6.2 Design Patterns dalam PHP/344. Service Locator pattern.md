# 344. Service Locator Pattern

## Definisi Singkat
Service Locator menyediakan pusat registrasi dan lookup untuk service-service yang dibutuhkan aplikasi.

## Analogi
Seperti meja resepsionis di hotel — Anda tidak perlu tahu kamar masing-masing staf, cukup tanya ke resepsionis.

## Poin-Poin Penting
- Kebalikan dari DI — objek secara aktif meminta dependensi
- Service Locator adalah "anti-pattern" menurut beberapa pendapat
- Menyembunyikan dependensi (tidak terlihat dari constructor)
- Lebih sederhana untuk prototype/proyek kecil
- DI Container lebih direkomendasikan untuk aplikasi besar

## Contoh Kode (PHP)
```php
<?php
class ServiceLocator {
    private static array $services = [];
    
    public static function set(string $name, object $service): void {
        self::$services[$name] = $service;
    }
    
    public static function get(string $name): object {
        if (!isset(self::$services[$name])) {
            throw new \RuntimeException("Service '$name' tidak ditemukan");
        }
        return self::$services[$name];
    }
}

class Logger {
    public function log(string $msg): void {
        echo "[LOG] $msg\n";
    }
}

class OrderController {
    public function proses(int $orderId): void {
        // Service Locator — dependensi tidak terlihat dari constructor
        $logger = ServiceLocator::get('logger');
        $logger->log("Memproses pesanan #$orderId");
        
        $db = ServiceLocator::get('database');
        // ... proses order ...
    }
}

ServiceLocator::set('logger', new Logger());
ServiceLocator::set('database', new \PDO('mysql:host=localhost;dbname=test', 'root', ''));

$controller = new OrderController();
$controller->proses(1001);
// Output: [LOG] Memproses pesanan #1001
?>
```

## Kasus Penggunaan Nyata
Prototype cepat, legacy code migration, framework yang menggunakan Service Locator (beberapa bagian Laravel, Zend Framework).
