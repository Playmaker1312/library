# 260. Best practice error production

## Definisi Singkat
Best practice menangani error di production: jangan tampilkan error ke user, log semua error, tampilkan halaman ramah, dan gunakan monitoring.

## Analogi
Restoran — jika masakan gagal (error), jangan bawa panci gosong ke meja tamu, cukup bilang "maaf, menu tidak tersedia" dan catat di dapur.

## Poin-Poin Penting
- Di production: `display_errors = 0`, `log_errors = 1`
- Gunakan try-catch di semua operasi kritis
- Log error dengan Monolog atau error_log
- Tampilkan halaman error yang ramah (500, 404)
- Gunakan monitoring: Sentry, Bugsnag, atau custom

## Contoh Kode (PHP)
```php
<?php
// config.php — konfigurasi production
error_reporting(E_ALL & ~E_DEPRECATED & ~E_NOTICE);
ini_set('display_errors', 0);
ini_set('log_errors', 1);
ini_set('error_log', __DIR__ . '/logs/php_errors.log');

// Global exception handler
set_exception_handler(function($e) {
    error_log("[FATAL] {$e->getMessage()} di {$e->getFile()}:{$e->getLine()}");
    http_response_code(500);
    if (php_sapi_name() !== 'cli') {
        include 'errors/500.html'; // halaman ramah
    }
});

// Global error handler
set_error_handler(function($level, $msg, $file, $line) {
    if (error_reporting() & $level) {
        throw new ErrorException($msg, 0, $level, $file, $line);
    }
});

// Shutdown handler untuk fatal error
register_shutdown_function(function() {
    $err = error_get_last();
    if ($err && in_array($err['type'], [E_ERROR, E_PARSE])) {
        error_log("[FATAL] {$err['message']} di {$err['file']}:{$err['line']}");
    }
});

// Contoh operasi aman
try {
    // Operasi database, file, dll
} catch (Exception $e) {
    error_log("[ERROR] {$e->getMessage()}");
    // Tampilkan pesan generik
}
?>
```

## Kasus Penggunaan Nyata
Semua aplikasi production PHP — e-commerce, CMS, API, sistem enterprise — wajib menerapkan ini.
