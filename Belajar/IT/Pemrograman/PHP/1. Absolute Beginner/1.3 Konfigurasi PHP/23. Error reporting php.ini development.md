# 23. Error reporting php.ini development

## Definisi Singkat
Error reporting di php.ini mengontrol tingkat keparahan error yang ditampilkan. Di lingkungan development, semua error harus ditampilkan (`E_ALL`). Di production, error disembunyikan untuk keamanan dan diganti logging.

## Analogi
Error reporting seperti alarm kebakaran: di bengkel (development), alarm sangat sensitif - setiap percikan api kecil bunyi keras (tampil di layar) agar segera diperbaiki. Di mal (production), alarm hanya mengirim sinyal ke petugas (log), tidak membuat panik pengunjung (user).

## Poin-Poin Penting
- **Development** (di `php.ini`):
  - `error_reporting = E_ALL`
  - `display_errors = On`
  - `display_startup_errors = On`
  - `log_errors = On`
- **Production**:
  - `error_reporting = E_ALL & ~E_DEPRECATED & ~E_STRICT`
  - `display_errors = Off`
  - `log_errors = On`
  - `error_log = /path/to/php-error.log`
- `E_ALL` menampilkan semua error termasuk notice dan warning
- `E_ALL` di PHP 8.4 mencakup semua level error (E_DEPRECATED, E_WARNING, E_PARSE, dll)
- Notice: masalah kecil seperti undefined variable
- Warning: masalah lebih serius tapi script tetap jalan
- Fatal Error: script berhenti
- Parse Error: syntax error, script tidak jalan sama sekali
- Gunakan `error_reporting(-1)` di PHP untuk menampilkan semua error tanpa terkecuali

## Contoh Kode (PHP)
```php
<?php
// Di development: menampilkan notice
echo $undefined_variable; // Notice: Undefined variable

// Set error reporting di runtime
error_reporting(E_ALL);
ini_set('display_errors', '1');

trigger_error("Ini error simulasi", E_USER_NOTICE);
// Output: Notice: Ini error simulasi
?>
```

## Kasus Penggunaan Nyata
Saat development aplikasi Laravel, set `APP_DEBUG=true` di `.env` yang otomatis mengaktifkan error display detail. Saat deploy ke server production, set `APP_DEBUG=false` agar user tidak melihat stack trace sensitif.
