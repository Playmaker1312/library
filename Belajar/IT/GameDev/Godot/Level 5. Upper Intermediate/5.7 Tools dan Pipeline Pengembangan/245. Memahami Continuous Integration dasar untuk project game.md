# 245. Memahami Continuous Integration dasar untuk project game

## Definisi Singkat
Continuous Integration (CI) adalah praktik otomasi yang menjalankan build dan test setiap kali ada perubahan kode yang di-push ke repository. Untuk game Godot, CI memastikan project selalu dalam kondisi buildable dan semua test berhasil sebelum dirilis.

## Analogi
CI seperti mesin otomatis di pabrik mobil. Setiap kali komponen baru masuk, mesin otomatis memeriksa kualitasnya, menjalankan serangkaian test, dan memberikan laporan. Jika ada komponen rusak, proses berhenti sebelum mobil jadi. Begitu juga CI — jika code baru memecah build, developer langsung tahu.

## Struktur Node (Scene Tree)
Tidak berlaku untuk konfigurasi CI. CI berjalan di platform seperti GitHub Actions:

```
.github/
└── workflows/
    └── godot-ci.yml
project_folder/
├── .github/workflows/
├── scenes/
├── scripts/
├── tests/
└── export_presets.cfg
```

## Kode GDScript (Godot 4)

```gdscript
# ci_export.gd - Script untuk memicu export dari command line
@tool
extends SceneTree

func _init() -> void:
    var args: PackedStringArray = OS.get_cmdline_args()
    if args.size() < 1:
        return
    match args[0]:
        "export":
            _run_export()
        "test":
            _run_tests()

func _run_export() -> void:
    var output: Array = []
    OS.execute("godot", ["--headless", "--export-release", "Windows Desktop", "build/game.exe"], output, true)
    print("Export completed: ", output)

func _run_tests() -> void:
    var output: Array = []
    OS.execute("godot", ["--headless", "-s", "res://addons/gut/gut_cmdln.gd", "-d", "res://tests/"], output, true)
    print("Tests completed: ", output)
```

```yaml
# .github/workflows/godot-ci.yml
name: Godot CI

on:
  push:
    branches: [ main, develop ]
  pull_request:
    branches: [ main ]

jobs:
  test:
    runs-on: ubuntu-latest
    container:
      image: barichello/godot-ci:4.2
    steps:
      - uses: actions/checkout@v4
      - name: Run Tests
        run: godot --headless -s res://addons/gut/gut_cmdln.gd -d res://tests/

  build:
    needs: test
    runs-on: ubuntu-latest
    container:
      image: barichello/godot-ci:4.2
    steps:
      - uses: actions/checkout@v4
      - name: Export Game
        run: godot --headless --export-release "Linux" build/game.x86_64
      - name: Upload Build
        uses: actions/upload-artifact@v4
        with:
          name: game-build
          path: build/
```

## Kasus Penggunaan Nyata
Studio indie menggunakan GitHub Actions untuk CI pipeline. Setiap pull request ke branch main otomatis menjalankan semua unit test dan build game untuk platform Windows, Linux, dan Web. Jika test gagal atau build error, PR tidak bisa di-merge. Ini memastikan kode yang masuk ke main selalu stabil dan playable.
