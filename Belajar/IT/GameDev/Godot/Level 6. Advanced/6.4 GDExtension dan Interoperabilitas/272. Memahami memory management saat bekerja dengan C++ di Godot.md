# 272. Memahami memory management saat bekerja dengan C++ di Godot

## Definisi Singkat
Memory management dalam GDExtension melibatkan pemahaman tentang bagaimana Godot mengelola objek melalui Reference Counting untukRefCounted objects dan manual memory management untuk Node-based objects, serta bagaimana menghindari memory leaks dan dangling pointers.

## Analogi
Memory management seperti mengelola perpustakaan. ObjekRefCounted seperti buku yang memiliki sistem peminjaman otomatis — buku akan dihapus dari rak saat tidak ada yang meminjamnya. Node seperti furnitur tetap yang harus dihapus secara manual oleh pustakawan (programmer) saat tidak diperlukan lagi.

## Kode GDScript (Godot 4)

```gdscript
extends Node

var ref_counted_obj: RefCounted
var node_obj: Node

func _ready():
    ref_counted_obj = RefCounted.new()
    node_obj = Node.new()
    add_child(node_obj)
    
    print("RefCounted references: ", ref_counted_obj.get_reference_count())
    
    var another_ref = ref_counted_obj
    print("After copy: ", ref_counted_obj.get_reference_count())
    
    another_ref = null
    print("After nullify: ", ref_counted_obj.get_reference_count())

func _exit_tree():
    if node_obj and is_instance_valid(node_obj):
        node_obj.queue_free()
        node_obj = null
    
    ref_counted_obj = null
```

## Kode C++ (Memory Management yang Benar)

```cpp
#include <godot_cpp/classes/node.hpp>
#include <godot_cpp/classes/ref_counted.hpp>
#include <godot_cpp/core/class_db.hpp>

using namespace godot;

class SafeRefCounted : public RefCounted {
    GDCLASS(SafeRefCounted, RefCounted)

protected:
    static void _bind_methods() {
        ClassDB::bind_method(D_METHOD("get_data"), &SafeRefCounted::get_data);
    }

private:
    int* data_buffer = nullptr;

public:
    SafeRefCounted() {
        data_buffer = new int[1024];
        UtilityFunctions::print("SafeRefCounted: Memory allocated");
    }
    
    ~SafeRefCounted() {
        if (data_buffer) {
            delete[] data_buffer;
            data_buffer = nullptr;
            UtilityFunctions::print("SafeRefCounted: Memory freed");
        }
    }
    
    int get_data() const {
        return data_buffer ? data_buffer[0] : 0;
    }
};

class MemoryManagedNode : public Node {
    GDCLASS(MemoryManagedNode, Node)

protected:
    static void _bind_methods() {
        ClassDB::bind_method(D_METHOD("create_child_ref"), &MemoryManagedNode::create_child_ref);
        ClassDB::bind_method(D_METHOD("cleanup_resources"), &MemoryManagedNode::cleanup_resources);
    }

private:
    Ref<SafeRefCounted> child_ref;
    Node* manual_child = nullptr;

public:
    MemoryManagedNode() {
    }
    
    ~MemoryManagedNode() {
        cleanup_resources();
    }
    
    void create_child_ref() {
        child_ref = Ref<SafeRefCounted>(memnew(SafeRefCounted));
        manual_child = memnew(Node);
        add_child(manual_child);
    }
    
    void cleanup_resources() {
        child_ref = Ref<SafeRefCounted>();
        
        if (manual_child && is_instance_valid(manual_child)) {
            manual_child->queue_free();
            manual_child = nullptr;
        }
    }
    
    void _exit_tree() override {
        cleanup_resources();
        Node::_exit_tree();
    }
};
```

## Best Practices Memory Management

```cpp
class OptimizedNode : public Node {
    GDCLASS(OptimizedNode, Node)

private:
    PackedByteArray buffer;
    std::vector<Ref<Resource>> resources;

public:
    void _notification(int p_what) {
        switch (p_what) {
            case NOTIFICATION_ENTER_TREE:
                buffer.resize(1024 * 1024);
                break;
            case NOTIFICATION_EXIT_TREE:
                buffer.resize(0);
                resources.clear();
                break;
        }
    }
    
    void add_resource(Ref<Resource> p_resource) {
        if (p_resource.is_valid()) {
            resources.push_back(p_resource);
        }
    }
    
    void clear_resources() {
        resources.clear();
        resources.shrink_to_fit();
    }
};
```

## Kasus Penggunaan Nyata
Memory management yang benar sangat krusial dalam game untuk menghindari memory leaks yang dapat menyebabkan game crash atau performa menurun seiring waktu. Sistem seperti inventory management, particle systems, atau dynamic level loading membutuhkan alokasi dan deallocation memory yang tepat. Game AAA menggunakan custom memory allocators dan profiling tools untuk memastikan penggunaan memory yang optimal.
