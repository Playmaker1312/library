# 273. Debugging GDExtension menggunakan tools seperti GDB atau LLDB

## Definisi Singkat
Debugging GDExtension menggunakan GDB atau LLDB memungkinkan developer untuk memeriksa kode C++ secara langsung saat running, memeriksa nilai variabel, menemukan crash points, dan menganalisis memory issues yang tidak bisa dideteksi dari GDScript saja.

## Analogi
Debugging GDExtension seperti melakukan operasi pada mesin mobil. GDScript debugger seperti mekanik yang bisa melihat dashboard, tapi untuk masalah mesin internal (C++), kamu butuh boroskop atau diagnostic tools khusus (GDB/LLDB) untuk melihat ke dalam.

## Struktur Debugging

```
Debugging Workflow
├── Compile dengan Debug Symbols
│   ├── gcc: -g flag
│   ├── clang: -g flag
│   └── MSVC: /DEBUG flag
├── Setup Debugger
│   ├── GDB (Linux/MingW)
│   ├── LLDB (macOS/clang)
│   └── Visual Studio Debugger (Windows)
├── Attach ke Godot Process
│   ├── Breakpoints
│   ├── Watch variables
│   └── Call stack inspection
└── Analyze Output
    ├── Memory access violations
    ├── Segmentation faults
    └── Logic errors
```

## Kode GDScript (Godot 4)

```gdscript
extends Node

var extension_node: MyCustomNode

func _ready():
    extension_node = MyCustomNode.new()
    add_child(extension_node)
    
    print("Starting debug test...")
    
    var result = extension_node.test_debug_function(42)
    print("Debug function result: ", result)
    
    extension_node.trigger_crash_test()

func _on_button_pressed():
    print("Button pressed - checking extension status")
    if extension_node:
        print("Extension node exists: ", extension_node.get_class())
```

## Setup GDB (Linux/MingW)

```bash
#!/bin/bash
# debug_gdb.sh

# Build dengan debug symbols
scons platform=linux target=debug

# Jalankan Godot dengan GDB
gdb --args godot --path /path/to/project --verbose

# Atau attach ke running process
gdb -p $(pgrep godot)
```

## GDB Commands untuk GDExtension

```bash
# Mulai debugging
(gdb) break my_custom_node.cpp:25

# Jalankan program
(gdb) run

# When breakpoint hit, check variables
(gdb) print value
(gdb) print *this

# Check call stack
(gdb) backtrace

# Step through code
(gdb) step
(gdb) next
(gdb) continue

# Watch memory locations
(gdb) watch *(int*)0x7fffffffe000

# Check for memory leaks
(gdb) info proc mappings
(gdb) find /b 0x600000, 0x601000, 0x41
```

## Setup LLDB (macOS)

```bash
# Build untuk macOS
scons platform=macos target=debug

# Jalankan dengan LLDB
lldb -- godot --path /path/to/project

# Basic LLDB commands
(lldb) breakpoint set --file my_custom_node.cpp --line 25
(lldb) run
(lldb) frame variable
(lldb) thread backtrace
(lldb) memory read --size 4 --format x 0x7fff5fbff8c0
```

## Kode C++ dengan Debug Helpers

```cpp
#include <godot_cpp/core/class_db.hpp>
#include <godot_cpp/variant/utility_functions.hpp>

#ifdef DEBUG_ENABLED
#define DEBUG_PRINT(msg) UtilityFunctions::print("[DEBUG] " + String(msg))
#define DEBUG_PRINT_VAR(var) UtilityFunctions::print("[DEBUG] " + String(#var) + " = " + String(var))
#else
#define DEBUG_PRINT(msg)
#define DEBUG_PRINT_VAR(var)
#endif

class DebuggableNode : public Node {
    GDCLASS(DebuggableNode, Node)

private:
    int internal_counter = 0;
    PackedByteArray debug_buffer;

protected:
    static void _bind_methods() {
        ClassDB::bind_method(D_METHOD("test_debug_function", "input"), &DebuggableNode::test_debug_function);
        ClassDB::bind_method(D_METHOD("trigger_crash_test"), &DebuggableNode::trigger_crash_test);
    }

public:
    DebuggableNode() {
        DEBUG_PRINT("DebuggableNode constructor called");
        debug_buffer.resize(256);
    }
    
    ~DebuggableNode() {
        DEBUG_PRINT("DebuggableNode destructor called");
        debug_buffer.resize(0);
    }
    
    int test_debug_function(int p_input) {
        DEBUG_PRINT_VAR(p_input);
        
        internal_counter += p_input;
        DEBUG_PRINT_VAR(internal_counter);
        
        if (internal_counter > 100) {
            DEBUG_PRINT("Counter exceeded threshold!");
        }
        
        return internal_counter;
    }
    
    void trigger_crash_test() {
        DEBUG_PRINT("Triggering controlled crash test...");
        
        int* null_ptr = nullptr;
        
        #ifdef DEBUG_ENABLED
        // This will cause a segfault for debugging demonstration
        // *null_ptr = 42;
        #endif
        
        DEBUG_PRINT("Crash test completed safely");
    }
    
    void _notification(int p_what) {
        switch (p_what) {
            case NOTIFICATION_ENTER_TREE:
                DEBUG_PRINT("Node entered tree");
                break;
            case NOTIFICATION_EXIT_TREE:
                DEBUG_PRINT("Node exiting tree");
                break;
        }
    }
};
```

## Kasus Penggunaan Nyata
Debugging GDExtension sangat penting untuk mengatasi crash yang terjadi di tingkat native code, seperti segmentation faults akibat null pointer dereferences atau memory corruption. Game yang menggunakan physics engines custom atau networking stacks membutuhkan debugging tingkat native untuk mengidentifikasi race conditions atau memory leaks yang sulit dideteksi dari GDScript.
