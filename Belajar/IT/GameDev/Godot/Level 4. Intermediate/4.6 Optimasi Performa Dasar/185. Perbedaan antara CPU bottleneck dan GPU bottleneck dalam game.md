# 185. Perbedaan antara CPU bottleneck dan GPU bottleneck dalam game

## Definisi Singkat
CPU bottleneck terjadi ketika unit pemrosesan pusat tidak mampu mengeksekusi logika game (script, physics, navigation) tepat waktu, sedangkan GPU bottleneck terjadi ketika kartu grafis tidak mampu merender semua visual (draw calls, shader, resolusi) dalam satu frame.

## Analogi
Bayangkan sebuah restoran. CPU bottleneck seperti koki yang terlalu lambat memasak pesanan, sehingga pelanggan menunggu lama meskipun meja dan ruang makan (GPU) masih kosong. GPU bottleneck seperti dapur yang sudah penuh dan lambat, meskipun koki sudah secepat mungkin menyiapkan pesanan.

## Struktur Node (Scene Tree)
```
GameWorld (Node2D)
├── PhysicsLayer (Node2D)
│   └── RigidBody2D nodes...
├── VisualLayer (Node2D)
│   ├── TileMap
│   ├── Sprite2D nodes...
│   └── Particles
└── UILayer (CanvasLayer)
    └── DebugInfo (Label)
```

## Kode GDScript (Godot 4)
```gdscript
extends Node2D

@onready var debug_label: Label = $UILayer/DebugInfo

func _process(_delta: float) -> void:
	var fps := Engine.get_frames_per_second()
	var rendering_time := Performance.get_monitor(Performance.TIME_PROCESS)
	var physics_time := Performance.get_monitor(Performance.PHYSICS_3D_TIME)
	var draw_calls := Performance.get_monitor(Performance.RENDER_TOTAL_DRAW_CALLS)
	
	var info := "FPS: %d\n" % fps
	info += "Rendering: %.2f ms\n" % rendering_time
	info += "Physics: %.2f ms\n" % physics_time
	info += "Draw Calls: %d\n" % draw_calls
	
	if rendering_time > 16.0:
		info += ">> GPU BOTTLENECK\n"
	elif physics_time > 16.0:
		info += ">> CPU BOTTLENECK\n"
	else:
		info += ">> PERFORMA BAIK\n"
	
	debug_label.text = info
```

## Kasus Penggunaan Nyata
Ketika FPS turun drastis, penting untuk menentukan apakah masalahnya di CPU atau GPU. Jika monitor menunjukkan render time tinggi namun physics time rendah, maka optimasi harus difokuskan ke rendering (mengurangi draw calls, menurunkan resolusi). Sebaliknya, jika physics atau script time tinggi, optimasi harus ke logika game (mengurangi jumlah physics body, optimasi script). Tool seperti Godot Profiler dan panel Debug > Monitors membantu membedakan keduanya.
