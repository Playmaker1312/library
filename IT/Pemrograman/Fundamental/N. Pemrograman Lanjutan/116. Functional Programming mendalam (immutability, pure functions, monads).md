Selamat! Anda telah sampai di materi yang akan mengubah cara Anda berpikir tentang kode. Jika **Object-Oriented Programming (OOP)** adalah tentang mengelola _state_ dan objek, maka **Functional Programming (FP)** adalah tentang alur data dan transformasi matematika.

Dalam FP, kita memperlakukan program sebagai sekumpulan fungsi matematika yang disusun, bukan sebagai urutan instruksi yang mengubah data. Mari kita bedah tiga pilar utamanya.

---

## 1. Pure Functions (Fungsi Murni)

**"Input yang sama, selalu menghasilkan Output yang sama."**

### Definisi

Sebuah fungsi dikatakan **Pure** jika:

1. **Predictable:** Tidak bergantung pada data di luar fungsi (seperti variabel global atau database).
    
2. **No Side Effects:** Tidak mengubah apa pun di luar dirinya sendiri (tidak mencetak log, tidak mengubah variabel luar, tidak menulis ke file).
    

### Mengapa Penting?

Fungsi murni sangat mudah diuji (**Unit Test**) dan sangat aman untuk **Multithreading** karena tidak ada risiko tabrakan data antar thread.

---

## 2. Immutability (Ketidakkekalan Data)

**"Sekali Dibuat, Tidak Boleh Diubah."**

### Konsep

Dalam FP, Anda tidak "mengubah" nilai sebuah variabel. Jika Anda ingin mengubah nama seorang User, Anda tidak melakukan `user.name = "Budi"`, melainkan membuat **objek User baru** yang merupakan salinan dari yang lama dengan nama yang sudah diganti.

- **Keuntungan:** Anda memiliki "Sejarah Data" (History). Jika ada _bug_, Anda bisa melacak status data di setiap langkah karena data lama tidak pernah hilang atau tertimpa.
    
- **Contoh:** Di JavaScript, gunakan `.map()`, `.filter()`, dan `.reduce()` karena fungsi-fungsi ini menghasilkan _array_ baru, bukan mengubah _array_ asli.
    

---

## 3. High-Order Functions & Composition

**"Fungsi sebagai Warga Kelas Satu."**

Di FP, fungsi bisa dikirim sebagai parameter ke fungsi lain, atau dikembalikan sebagai hasil. Kita bisa menyusun fungsi kecil-kecil menjadi satu fungsi besar yang sangat kuat.

- **Analogi:** Seperti pipa air. Air masuk ke Pipa A (Filter), lalu ke Pipa B (Transformasi), lalu keluar sebagai air bersih.
    

---

## 4. Monads (Konsep "Pembungkus")

**"Cara Menangani Sesuatu yang Tidak Pasti."**

Banyak orang takut dengan istilah **Monad**, tapi sebenarnya konsepnya sederhana. Monad adalah sebuah **Design Pattern** untuk membungkus sebuah nilai ke dalam "kotak" (konteks) agar kita bisa melakukan operasi pada nilai tersebut dengan aman.

### Mengapa Kita Butuh Monad?

Misalnya Anda ingin mengambil alamat dari seorang User: `user.profile.address.city`. Jika `profile` ternyata kosong (`null`), aplikasi Anda akan _crash_. **Monad (seperti Maybe atau Optional)** membungkus nilai tersebut. Ia akan mengecek secara otomatis: _"Kalau isinya ada, lanjut ke langkah berikutnya. Kalau kosong, berhenti di sini tanpa membuat aplikasi meledak."_

---

## 5. Keunggulan Functional Programming

1. **Bebas Bug Tersembunyi:** Karena data tidak bisa berubah tiba-tiba (_Immutability_), Anda tidak akan menemukan _bug_ di mana variabel "A" tiba-tiba berubah nilainya tanpa Anda tahu siapa pelakunya.
    
2. **Concurrency-Friendly:** Sangat mudah dijalankan di banyak CPU secara paralel karena tidak ada data yang diperebutkan oleh banyak fungsi.
    
3. **Declarative Code:** Kode Anda berfokus pada **"Apa"** yang ingin dicapai (misal: "Saring daftar ini"), bukan **"Bagaimana"** cara melakukannya (misal: "Buat loop, buat counter, cek kondisi...").
    

---

## 6. Contoh Singkat (JavaScript)

**Cara OOP/Imperatif:**

JavaScript

```
let angka = [1, 2, 3];
for (let i = 0; i < angka.length; i++) {
    angka[i] = angka[i] * 2; // Mengubah data asli (Mutasi)
}
```

**Cara Functional:**

JavaScript

```
const angka = [1, 2, 3];
const angkaBaru = angka.map(n => n * 2); // Menghasilkan data baru (Immutable)
```

## Kesimpulan

Functional Programming menuntut kedisiplinan tinggi, tetapi hasilnya adalah kode yang sangat bersih, mudah dirawat, dan minim kesalahan. Banyak bahasa modern seperti **Rust, Scala, Elixir,** dan bahkan **JavaScript/TypeScript** sekarang sangat mendorong penggunaan gaya fungsional ini.
