Selamat datang di momen yang paling ditakuti oleh setiap _programmer_ pemula, namun merupakan makanan sehari-hari para _Senior Developer_.

Di materi sebelumnya, kita melihat betapa mulusnya proses penggabungan (_merging_) dua cabang. Namun, dunia nyata tidak selalu berjalan semulus itu. Terkadang, proses penggabungan gagal di tengah jalan dan Git akan berteriak minta tolong. Inilah yang disebut dengan **Merge Conflict**.

---

## 1. Definisi Singkat

**Merge Conflict (Tabrakan Penggabungan)** adalah situasi di mana Git gagal menggabungkan dua cabang secara otomatis karena ada **perubahan yang saling bertentangan pada baris kode yang sama persis** di file yang sama.

Git adalah mesin yang pintar, tetapi ia tidak berani mengambil keputusan sepihak tentang kode siapa yang harus dihapus dan kode siapa yang harus dipertahankan. Oleh karena itu, Git menghentikan proses penggabungan dan meminta Anda (sebagai manusia) untuk menyelesaikannya secara manual.

## 2. Analogi: Dua Penulis Naskah Film

Bayangkan Anda dan rekan Anda sedang menulis naskah film "Batman" bersama-sama. Kalian membagi tugas menggunakan salinan naskah masing-masing (Cabang).

- Di baris ke-100, Anda menulis: _"Batman mengalahkan Joker dengan pukulan rahasia."_
    
- Di waktu yang sama, di salinannya sendiri, rekan Anda mengedit baris ke-100 menjadi: _"Batman berdamai dengan Joker sambil minum kopi."_
    

Saat produser (Git) mencoba menggabungkan kedua salinan naskah tersebut menjadi satu naskah final, ia akan kebingungan. _"Tunggu dulu! Di baris 100 ini Batman mau memukul atau minum kopi? Saya tidak tahu plot mana yang benar! Kalian berdua selesaikan ini sekarang juga!"_

## 3. Poin-Poin Penting (Anatomi Tabrakan)

Saat terjadi _conflict_, Git akan merusak file Anda dengan menyisipkan "Tanda Pembatas" (_Conflict Markers_) yang terlihat sangat aneh. Ini bukan _error_ bahasa pemrograman, melainkan cara Git berkomunikasi dengan Anda.

Anatominya terlihat seperti ini di dalam file teks/kode Anda:

Plaintext

```
<<<<<<< HEAD
(Kode yang ada di cabang Anda saat ini / Current Change)
=======
(Kode yang datang dari cabang rekan Anda / Incoming Change)
>>>>>>> nama-cabang-rekan-anda
```

Tugas Anda sangat sederhana: **Pilih salah satu kode, atau gabungkan keduanya, lalu HAPUS semua tanda pembatas aneh tersebut (`<<<<<<<`, `=======`, `>>>>>>>`).**

## 4. Contoh Penyelesaian (Langkah demi Langkah)

Anggaplah Anda sedang berada di cabang `main` dan mencoba menjalankan `git merge fitur-login`. Tiba-tiba terminal menampilkan pesan merah: `CONFLICT (content): Merge conflict in index.html. Automatic merge failed; fix conflicts and then commit the result.`

Jangan panik! Ikuti 4 langkah ini:

**Langkah 1: Cek file mana yang bertabrakan**

Bash

```
git status
# Output akan memberitahu Anda: "both modified: index.html"
```

**Langkah 2: Buka file tersebut di Code Editor (VS Code)** Saat Anda membuka `index.html`, Anda akan melihat ini:

HTML

```
<header>
<<<<<<< HEAD
    <h1>Selamat Datang di Aplikasi Kami</h1>
=======
    <h1>Login ke Portal Rahasia</h1>
>>>>>>> fitur-login
</header>
```

**Langkah 3: Selesaikan Tabrakannya (Edit Manual)** Anda sebagai manusia harus memutuskan. Apakah mau pakai judul A? Judul B? Atau gabungan keduanya? Mari kita gabungkan saja, lalu hapus sisa markernya. File Anda sekarang menjadi bersih seperti ini:

HTML

```
<header>
    <h1>Selamat Datang! Silakan Login ke Portal Rahasia</h1>
</header>
```

**Langkah 4: Lanjutkan Proses Commit yang Tertunda** Setelah file disimpan, kembali ke Terminal dan beritahu Git bahwa masalah sudah selesai.

Bash

```
# Masukkan file yang sudah bersih ke Staging Area
git add index.html

# Selesaikan penggabungan dengan melakukan commit tanpa pesan 
# (Git sudah menyiapkan pesan otomatis untuk kasus ini)
git commit
```

_Bum! Konflik berhasil diselesaikan dan dua cabang resmi menyatu!_

## 5. Koneksi dengan Web Development

Menyelesaikan _merge conflict_ adalah keterampilan sosial sekaligus teknikal di dunia kerja:

1. **Fitur Canggih VS Code:** Anda jarang harus menghapus marker `<<<<<<<` secara manual menekan tombol _backspace_. _Code editor_ modern seperti VS Code memiliki tombol otomatis di atas kode yang bertabrakan: **"Accept Current Change"**, **"Accept Incoming Change"**, atau **"Accept Both Changes"**. Anda tinggal klik!
    
2. **Komunikasi Tim (Etika Kerja):** Jika Anda melihat kode rekan Anda sepanjang 50 baris bertabrakan dengan kode Anda, **jangan pernah** sembarangan menghapus kode rekan Anda dengan menekan "Accept Current Change". Etika yang benar adalah memanggil rekan tersebut (lewat Slack atau langsung) dan bertanya: _"Bro, fungsi keranjang belanjamu nabrak sama desain header-ku. Enaknya digabung gimana, ya?"_
    
3. **Mencegah Lebih Baik Daripada Mengobati:** _Conflict_ besar biasanya terjadi jika sebuah cabang dikerjakan terlalu lama (berminggu-minggu) tanpa pernah diperbarui. _Developer_ profesional melakukan _pull_ (menarik kode terbaru dari _server_) setiap hari agar jika terjadi tabrakan, skalanya sangat kecil dan mudah diselesaikan.
