Selamat! Anda telah menguasai berbagai pola desain tingkat tinggi. Namun, di dunia nyata, sering kali kita harus berurusan dengan "Legacy Code" (kode lama) yang berantakan, atau bahkan kode yang kita tulis sendiri bulan lalu dan sekarang terasa sulit dibaca.

Di sinilah **Code Refactoring** berperan. Refactoring bukan tentang menambah fitur baru, melainkan tentang **membersihkan "jeroan" kode** agar lebih sehat tanpa mengubah perilakunya di mata pengguna.

---

## 1. Apa itu Code Refactoring?

**Refactoring** adalah proses sistematis untuk mengubah struktur internal kode agar lebih mudah dipahami, lebih murah untuk dipelihara, namun tetap menghasilkan _output_ yang sama persis seperti sebelumnya.

**Prinsip Utama:** Jika Anda sedang melakukan refactoring, Anda **tidak boleh** memperbaiki _bug_ atau menambah tombol baru. Jika perilaku aplikasinya berubah, itu bukan refactoring, itu _re-engineering_.

---

## 2. Kapan Harus Melakukan Refactoring?

Gunakan aturan **"The Rule of Three"** atau perhatikan tanda-tanda "Bau Kode" (_Code Smells_):

- **Saat Menambah Fitur:** Jika kode yang ada sekarang sangat sulit disisipkan fitur baru, bersihkan dulu kodenya, baru pasang fiturnya.
    
- **Saat Menemukan Bug:** Seringkali _bug_ bersembunyi di balik kode yang berantakan. Membersihkan kode akan membantu Anda melihat kesalahan dengan lebih jelas.
    
- **Saat Code Review:** Jika rekan setim Anda bertanya, _"Ini maksud baris ini apa ya?"_, itu tandanya kode tersebut perlu di-refactor agar lebih manusiawi.
    
- **The Rule of Three:** Pertama kali Anda menulis sesuatu, tulis saja. Kedua kali, Anda mungkin merasa risih karena menduplikasi. Ketiga kali Anda melakukan hal yang sama, **saatnya refactoring ke dalam fungsi/modul.**
    

---

## 3. Teknik Refactoring yang Paling Populer

Berikut adalah beberapa jurus "bersih-bersih" yang paling sering digunakan oleh para ahli:

### A. Extract Method (Ekstraksi Fungsi)

Jika Anda memiliki satu fungsi yang sangat panjang (misal 100 baris) dan melakukan banyak hal, pecahlah menjadi fungsi-fungsi kecil yang namanya jelas.

- _Sebelum:_ Fungsi `prosesOrder()` mengurus validasi, hitung diskon, simpan ke DB, dan kirim email.
    
- _Sesudah:_ `prosesOrder()` hanya memanggil `cekValidasi()`, `hitungDiskon()`, `simpanKeDatabase()`, dan `kirimEmail()`.
    

### B. Rename Variable (Pemberian Nama yang Layak)

Gantilah variabel yang namanya misterius menjadi deskriptif. Ini adalah refactoring paling sederhana tapi dampaknya paling besar.

- _Buruk:_ `let d = 86400;`
    
- _Baik:_ `let DETIK_DALAM_SEHARI = 86400;`
    

### C. Replace Nested Conditional with Guard Clauses

Jika Anda punya `if` di dalam `if` di dalam `if` (Piramida Kiamat), gunakan _Guard Clauses_ untuk "mengusir" kondisi yang tidak memenuhi syarat di awal fungsi.

- _Sebelum:_
    
    JavaScript
    
    ```
    function ambilGaji(user) {
        if (user != null) {
            if (user.isAktif) {
                return user.gaji;
            }
        }
    }
    ```
    
- _Sesudah (Guard Clause):_
    
    JavaScript
    
    ```
    function ambilGaji(user) {
        if (user == null) return 0;
        if (!user.isAktif) return 0;
        return user.gaji;
    }
    ```

## 4. Tantangan: Technical Debt (Hutang Teknis)

Refactoring adalah cara kita membayar **Technical Debt**. Jika Anda terburu-buru mengejar _deadline_ dan menulis kode asal-asalan ("pokoknya jalan dulu"), Anda sedang berutang. Jika hutang ini tidak dibayar dengan refactoring, suatu saat aplikasi Anda akan menjadi sangat lambat pengembangannya karena "bunga hutang" (kode yang rusak dan saling ketergantungan) sudah terlalu besar.

---

## 5. Tips Aman Melakukan Refactoring

1. **Gunakan Unit Test:** Sebelum mengubah kode, pastikan Anda punya tes otomatis. Jika setelah diubah tesnya tetap "Hijau" (Lulus), berarti refactoring Anda aman.
    
2. **Langkah Kecil:** Jangan merombak 1.000 baris sekaligus. Ubah sedikit, tes, _commit_ ke Git. Ubah lagi sedikit, tes, _commit_.
    
3. **Gunakan Tools:** Editor modern seperti VS Code memiliki fitur otomatis: Klik kanan pada variabel > _Rename Symbol_, atau blok kode > _Refactor_ > _Extract to Function_.
    

Refactoring adalah tanda kedewasaan seorang _programmer_. Kode yang hebat bukan yang paling rumit, melainkan yang paling bersih dan paling mudah dibaca oleh orang lain.
