## 1. Apa itu Debugging Sistematis?

**Debugging** bukan sekadar menebak-nebak baris kode mana yang salah. Debugging sistematis adalah proses detektif yang menggunakan metode ilmiah:

1. **Reproduce:** Pastikan _bug_ tersebut bisa dimunculkan kembali dengan langkah yang sama.
    
2. **Isolate:** Lokalisasi masalah. Apakah ini salah di Frontend, API, atau Database?
    
3. **Hypothesize:** Buat dugaan sementara berdasarkan bukti yang ada.
    
4. **Fix & Verify:** Perbaiki kodenya, dan pastikan _bug_ tersebut hilang tanpa memunculkan _bug_ baru.

## 2. Teknik Debugging Legendaris

### A. Rubber Duck Debugging (Bebek Karet)

Teknik ini terdengar konyol tapi sangat efektif. Jelaskan kode Anda baris demi baris kepada sebuah benda mati (seperti bebek karet). Saat Anda menjelaskan _"Fungsi ini mengambil ID, lalu mencari di... eh tunggu, kenapa saya pakai variabel X di sini?"_, otak Anda akan sering menemukan logikanya yang cacat secara otomatis.

### B. Binary Search Debugging (Divide & Conquer)

Jika Anda punya 1.000 baris kode dan tidak tahu di mana yang salah, matikan (beri komentar) setengah bagian bawah kode tersebut.

- Jika _bug_ masih ada, berarti masalahnya di 500 baris atas.
    
- Jika _bug_ hilang, berarti masalahnya di 500 baris bawah. Ulangi terus sampai Anda menemukan satu baris biang keroknya.
    

### C. The Scientific Method

Jangan mengubah kode secara acak ("Coba tambah `+1` di sini, coba hapus `if` ini"). Ubah **satu hal saja**, jalankan aplikasi, lihat hasilnya. Jika tidak berpengaruh, kembalikan ke semula sebelum mencoba hal lain.

## 3. Senjata Utama (Tools)

### A. Browser DevTools (F12)

Ini adalah "Lab Kimia" bagi _Web Developer_.

- **Console:** Tempat melihat _error_ merah yang dikirim JavaScript.
    
- **Network Tab:** Melihat apakah surat HTTP Request Anda sampai ke server atau ditolak (Error 404/500).
    
- **Sources/Debugger:** Anda bisa memasang **Breakpoint**—menghentikan waktu saat kode berjalan, lalu melihat isi semua variabel di detik itu juga.
    

### B. VS Code Debugger

Anda tidak perlu terus-menerus mengetik `console.log()`. Gunakan _Built-in Debugger_ di VS Code untuk menjalankan kode Node.js Anda selangkah demi selangkah (_step-over_) dan memantau perubahan data secara _real-time_.

### C. Logging (Winston / Bunyan)

Di _server_ yang sudah _live_ (Production), Anda tidak bisa memasang Breakpoint. Anda butuh sistem **Logging** yang mencatat setiap kejadian penting ke dalam sebuah file teks, sehingga saat terjadi _crash_ di malam hari, Anda bisa membaca "rekaman CCTV" kodenya di pagi hari.

## 4. Poin Penting: Cara Membaca Error (Stack Trace)

Jangan panik saat melihat tulisan merah panjang di terminal. Bacalah dari **baris paling atas**.

- **Type of Error:** (Contoh: `TypeError: Cannot read property 'map' of undefined`). Ini adalah diagnosa penyakitnya.
    
- **Location:** (Contoh: `at index.js:45:12`). Ini adalah alamat TKP-nya.
