Selamat! Anda telah menyentuh perdebatan paling fundamental dalam arsitektur perangkat lunak modern. Jika **Inheritance** (Pewarisan) adalah cara klasik untuk membangun hubungan antar objek, maka **Composition** (Komposisi) adalah pendekatan yang lebih fleksibel dan kini menjadi standar industri.

Memahami kapan harus menggunakan salah satunya adalah tanda Anda beralih dari seorang _coder_ menjadi seorang **Software Architect**.

---

## 1. Inheritance (Pewarisan)

**Hubungan "Is-A" (Adalah Sebuah).**

### Konsep

Inheritance membangun hierarki dari atas ke bawah. Kelas anak (_Subclass_) mewarisi semua sifat dan perilaku dari kelas induk (_Superclass_).

- **Kelebihan:** Sangat bagus untuk membagikan kode yang benar-benar identik secara alami.
    
- **Kekurangan (The Tight Coupling):** Kelas anak menjadi sangat bergantung pada kelas induk. Jika Anda mengubah satu baris di induk, ribuan anak bisa "meledak" (_Fragile Base Class Problem_).
    

---

## 2. Composition (Komposisi)

**Hubungan "Has-A" (Memiliki Sebuah).**

### Konsep

Bukannya mewarisi sifat, sebuah objek **memasukkan** objek lain ke dalamnya sebagai bagian dari kemampuannya. Anda merakit objek dari potongan-potongan kecil yang independen.

- **Kelebihan:** Sangat fleksibel. Anda bisa menukar "kemampuan" objek saat aplikasi sedang berjalan (_runtime_). Kode jadi lebih mudah dites secara terpisah.
    
- **Kekurangan:** Membutuhkan lebih banyak objek kecil dan sedikit lebih banyak kode di awal untuk merakitnya.

## 3. Analogi: Restoran vs LEGO

### Inheritance (Menu Paket Restoran)

Anda memesan "Paket Nasi Timbel". Paket ini sudah termasuk Nasi, Ayam, Tahu, dan Tempe.

- Jika Anda ingin Ayamnya diganti Ikan, Anda tidak bisa, karena itu sudah satu paket warisan dari menu pusat. Jika menu pusat berubah jadi Nasi Putih biasa, semua pelanggan Paket Timbel kena dampaknya.
    

### Composition (LEGO / Prasmanan)

Anda mengambil piring kosong.

- Anda ingin Nasi? Ambil blok Nasi.
    
- Ingin Ayam? Tambahkan blok Ayam.
    
- Ingin Ikan? Tinggal copot Ayamnya, pasang blok Ikan. Anda membangun piring Anda sendiri berdasarkan komponen yang tersedia.

## 4. Contoh Kode: Masalah Hierarki yang Kaku

Bayangkan Anda membuat game.

**Masalah dengan Inheritance:**

JavaScript

```
class Karakter {}
class Petarung extends Karakter { serang() {} }
class Penyihir extends Karakter { sihir() {} }

// Tiba-tiba ada karakter baru: "Paladin" (Bisa Serang DAN Sihir)
// Anda bingung: Paladin harus extends Petarung atau Penyihir? 
// Anda terjebak dalam hierarki yang kaku.
```

**Solusi dengan Composition:**

JavaScript

```
const bisaMenyerang = (state) => ({
  serang: () => console.log(`${state.nama} menebas pedang!`)
});

const bisaSihir = (state) => ({
  sihir: () => console.log(`${state.nama} mengeluarkan bola api!`)
});

// Anda tinggal merakit "Paladin" dari potongan kemampuan
const Paladin = (nama) => {
  let state = { nama };
  return Object.assign(state, bisaMenyerang(state), bisaSihir(state));
};

const lancelot = Paladin("Lancelot");
lancelot.serang();
lancelot.sihir();
```

## 5. Kapan Menggunakan yang Mana?

### Gunakan Inheritance JIKA:

- Hubungannya adalah **"Is-A"** yang murni (misal: `Sedan` adalah sebuah `Mobil`).
    
- Hierarkinya dangkal (tidak lebih dari 2-3 level).
    
- Anda ingin menggunakan fitur _Polymorphism_ secara maksimal di bahasa seperti Java atau C#.
    

### Gunakan Composition JIKA:

- Hubungannya adalah **"Has-A"** atau **"Can-Do"** (Memiliki atau Bisa Melakukan).
    
- Anda butuh fleksibilitas untuk mengubah perilaku objek di tengah jalan.
    
- Anda ingin menghindari "Piramida Pewarisan" yang rumit.
    
- **Aturan Emas:** _"Favor composition over inheritance"_ (Utamakan komposisi daripada pewarisan).
    

---

## Kesimpulan

Inheritance itu seperti **takdir** (lahir sebagai apa), sedangkan Composition itu seperti **pilihan hidup** (ingin punya kemampuan apa). Dalam pengembangan perangkat lunak modern yang perubahannya sangat cepat, **pilihan hidup** biasanya menang karena jauh lebih mudah diadaptasi.

Apakah Anda sedang menghadapi struktur kelas yang mulai terasa membingungkan dan ingin kita coba refactor menggunakan teknik komposisi?
