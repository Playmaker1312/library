Dalam pemrograman berorientasi objek (OOP), kita sering ingin sebuah kelas memiliki kemampuan dari beberapa sumber sekaligus. Namun, tidak semua bahasa pemrograman mengizinkan seorang "anak" memiliki dua "orang tua" kandung. Di sinilah perdebatan antara **Multiple Inheritance** dan solusi modern bernama **Mixins** dimulai.

---

## 1. Multiple Inheritance (Pewarisan Ganda)

**"Satu Anak, Banyak Orang Tua."**

### Definisi Singkat

Kondisi di mana sebuah kelas dapat mewarisi sifat, metode, dan data dari **lebih dari satu** kelas induk (_parent class_). Teknik ini lazim ditemukan di bahasa seperti C++ atau Python, namun **dilarang** di bahasa seperti Java, C#, dan JavaScript (ES6).

### Masalah Utama: The Diamond Problem

Mengapa banyak bahasa modern melarangnya? Bayangkan skenario ini:

1. Kelas **A** punya metode `tampilkan()`.
    
2. Kelas **B** dan **C** mewarisi **A** dan masing-masing mengubah isi `tampilkan()`.
    
3. Kelas **D** mewarisi **B** dan **C** sekaligus. Saat kita panggil `D.tampilkan()`, komputer bingung: _"Saya harus pakai versi milik B atau milik C?"_. Kebingungan ini disebut **Diamond Problem**.

## 2. Mixins

**"Prasmanan Kemampuan (Plugin)."**

### Definisi Singkat

Mixins adalah cara untuk "menyisipkan" sekumpulan fungsi ke dalam sebuah kelas tanpa harus menjadikannya orang tua kandung. Ini adalah cara yang jauh lebih bersih untuk berbagi kode antar kelas yang tidak berhubungan secara hierarki.

### Analogi: Smartphone dan Aksesori

Sebuah **Smartphone** adalah keturunan dari **Perangkat Elektronik**. Tapi, Anda ingin smartphone Anda bisa memotret dan bisa menjadi senter.

- Anda tidak perlu membuat smartphone mewarisi kelas **Kamera** dan kelas **Senter** secara ganda.
    
- Anda cukup "mencampurkan" (_mix-in_) kemampuan `Fotografi` dan kemampuan `Penerangan` ke dalamnya.
    

---

## 3. Implementasi Mixins di JavaScript

Karena JavaScript hanya mendukung _Single Inheritance_ (satu `extends`), kita menggunakan teknik **Object Composition** untuk membuat Mixins.

JavaScript

```
// 1. Definisikan Mixins (Kumpulan Kemampuan)
const terbangMixin = {
  terbang() {
    console.log(`${this.nama} meluncur ke angkasa!`);
  }
};

const berenangMixin = {
  berenang() {
    console.log(`${this.nama} menyelam ke air.`);
  }
};

// 2. Kelas Utama
class Hewan {
  constructor(nama) {
    this.nama = nama;
  }
}

// 3. Membuat "Bebek" yang bisa Terbang DAN Berenang
class Bebek extends Hewan {}

// Gunakan Object.assign untuk mencampurkan kemampuan
Object.assign(Bebek.prototype, terbangMixin, berenangMixin);

const donald = new Bebek("Donald");
donald.terbang();  // Output: Donald meluncur ke angkasa!
donald.berenang(); // Output: Donald menyelam ke air.
```

---

## 4. Kapan Menggunakan Mixins?

- **Cross-Cutting Concerns:** Saat Anda punya fitur yang dibutuhkan oleh banyak kelas berbeda (misal: fitur `Logging`, `Validation`, atau `Serializable`).
    
- **Menghindari Hierarki Dalam:** Daripada membuat silsilah keluarga yang sangat panjang (`Hewan` -> `Burung` -> `BurungAir` -> `Bebek`), lebih baik gunakan Mixins agar struktur kelas tetap datar dan sederhana.
    
- **Komposisi daripada Pewarisan:** Ini adalah prinsip desain modern (_Composition over Inheritance_). Fokuslah pada **apa yang bisa dilakukan** oleh sebuah objek, bukan **siapa identitas** objek tersebut.
    

---

## 5. Kesimpulan

- **Multiple Inheritance:** Kuat tapi berbahaya (risiko konflik nama dan kerumitan struktur).
    
- **Mixins:** Fleksibel, modular, dan menjadi standar di bahasa modern seperti JavaScript, Ruby, dan Dart.
    

Dengan memahami Mixins, Anda bisa merancang sistem yang sangat luwes. Anda bisa merakit objek seolah-olah sedang merakit LEGO, mengambil kepingan kemampuan dari mana saja dan memasangnya tepat di tempat yang dibutuhkan.
