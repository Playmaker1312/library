Setelah Anda menguasai cara kerja _Client_ (Browser) dan _Server_ (Database), kini saatnya kita mempelajari "jembatan" yang menghubungkan keduanya. Di era aplikasi modern, _Client_ dan _Server_ seringkali tidak berada di komputer yang sama, bahkan mungkin dibuat dengan bahasa pemrograman yang berbeda.

Bagaimana cara aplikasi Android (Java), aplikasi Web (JavaScript), dan aplikasi iOS (Swift) semuanya bisa mengambil data yang sama dari satu _Server_ (Python/Node.js)? Jawabannya adalah **REST API**.

---

## 1. Definisi Singkat

- **API (Application Programming Interface):** Sebuah perantara perangkat lunak yang memungkinkan dua aplikasi untuk saling "berbicara".
    
- **REST (Representational State Transfer):** Sebuah standar arsitektur atau "aturan main" dalam pembuatan API. Jika sebuah API mengikuti aturan ini, ia disebut **RESTful API**.
    
- **Konsep Utama:** REST memperlakukan segala sesuatu (User, Produk, Pesan) sebagai **Resource** (Sumber Daya) yang dapat diakses melalui URL unik.
    

## 2. Analogi: Pelayan di Restoran Global

Bayangkan Anda berada di sebuah restoran internasional:

1. **Client (Anda):** Anda adalah pelanggan yang lapar. Anda bisa berasal dari mana saja (Indonesia, Amerika, Jepang).
    
2. **Server (Dapur):** Dapur menyediakan makanan. Koki di dalamnya mungkin hanya bicara bahasa Prancis.
    
3. **REST API (Menu & Pelayan):** * **Menu** adalah daftar layanan yang tersedia (Lihat Menu, Pesan Makan, Batalkan Pesan).
    
    - **Pelayan** adalah perantaranya. Anda tidak perlu masuk ke dapur. Anda cukup melihat menu, lalu memberi tahu pelayan apa yang Anda inginkan menggunakan format pesanan yang sudah standar.
        
    - Tidak peduli Anda bicara bahasa apa, selama Anda menunjuk menu yang sama, pelayan akan memberikan hasil yang sama dari dapur.
        

## 3. Poin-Poin Penting (Aturan Main REST)

Untuk disebut sebagai RESTful, sebuah API biasanya mengikuti prinsip-prinsip berikut:

- **Stateless:** Setiap permintaan (_request_) dari _client_ ke _server_ harus mengandung semua informasi yang dibutuhkan. _Server_ tidak menyimpan "ingatan" tentang permintaan Anda sebelumnya.
    
- **HTTP Methods (Kata Kerja):** REST menggunakan metode HTTP standar untuk menentukan tindakan:
    
    - `GET` : Mengambil/Membaca data.
        
    - `POST` : Membuat data baru.
        
    - `PUT` / `PATCH` : Memperbarui/Mengubah data yang ada.
        
    - `DELETE` : Menghapus data.
        
- **Endpoint (Alamat):** Data diakses melalui URL yang rapi dan deskriptif.
    
    - Contoh: `https://api.toko.com/v1/produk`
        
- **Format Data (JSON):** Hampir semua REST API saat ini mengirim dan menerima data dalam format **JSON** karena ringan dan bisa dimengerti oleh semua bahasa pemrograman.
    

## 4. Contoh Implementasi: Berinteraksi dengan API

Mari kita simulasikan bagaimana _Client_ (JavaScript) mengambil data dari sebuah REST API menggunakan fungsi `fetch()`.

**Kasus:** Mengambil daftar pengguna dari server.

JavaScript

```
// Memanggil Endpoint API (Request)
// Method default adalah GET
fetch('https://jsonplaceholder.typicode.com/users')
  .then(response => {
    // Memastikan server membalas dengan status 200 (OK)
    if (!response.ok) throw new Error("Gagal mengambil data");
    return response.json(); // Mengubah teks JSON menjadi Object JS
  })
  .then(data => {
    // Data siap digunakan (Response)
    console.log("Daftar Pengguna:", data);
    // Di sini Anda bisa melakukan DOM Manipulation untuk menampilkan ke layar
  })
  .catch(error => {
    console.error("Terjadi Kesalahan:", error);
  });
```

## 5. Koneksi dengan Web Development

REST API adalah tulang punggung integrasi sistem di seluruh dunia:

1. **Pemisahan Frontend & Backend:** Di perusahaan besar, tim _Frontend_ dan _Backend_ bekerja terpisah. Tim _Backend_ hanya fokus membuat API (menyediakan data), sedangkan tim _Frontend_ fokus pada tampilan dan hanya "menembak" API tersebut untuk mendapatkan isinya.
    
2. **Aplikasi Multi-Platform:** Inilah alasan mengapa saldo GoPay Anda di aplikasi Android, iPhone, dan Smart Watch selalu sama. Ketiganya memanggil REST API yang sama ke _server_ pusat Gojek.
    
3. **Public API & Ekosistem:** Banyak perusahaan membuka API mereka untuk umum.
    
    - **Google Maps API:** Memungkinkan _website_ toko Anda menampilkan peta.
        
    - **RajaOngkir API:** Memungkinkan _website_ e-commerce Anda menghitung biaya kirim JNE/TIKI secara otomatis.
        
    - **OpenWeather API:** Memungkinkan aplikasi Anda menampilkan ramalan cuaca secara _real-time_.
        

Dengan memahami REST API, Anda telah naik level dari sekadar pembuat _website_ statis menjadi seorang **Full-Stack Thinker** yang paham bagaimana data mengalir secara global antar sistem.
