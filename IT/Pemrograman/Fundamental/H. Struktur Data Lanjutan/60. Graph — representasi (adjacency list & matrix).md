Mari kita bayar "hutang" materi yang sempat terlewat tadi. Anda telah menguasai data linier (_Array_) dan data hierarkis (_Tree_). Sekarang, kita akan membahas struktur data kasta tertinggi yang tidak memiliki aturan arah yang kaku: **Jaringan**.

Inilah struktur data yang menyokong raksasa teknologi seperti Google Maps, Facebook, dan algoritma rekomendasi Netflix.

---

## 1. Definisi Singkat

**Graph (Graf)** adalah struktur data non-linier yang terdiri dari kumpulan titik yang disebut **Vertices / Nodes (Simpul)**, yang dihubungkan oleh garis yang disebut **Edges (Sisi)**.

Tidak seperti _Tree_ yang memiliki "Akar" (atas ke bawah), _Graph_ bisa berbentuk acak, memutar, dan tidak memiliki titik awal yang pasti. Titik A bisa terhubung ke B, B ke C, dan C kembali ke A.

Karena bentuknya yang bebas, komputer membutuhkan cara khusus untuk "membaca" dan menyimpan peta jaringan ini. Ada dua cara utama untuk merepresentasikannya:

1. **Adjacency Matrix (Matriks Ketetanggaan):** Menggunakan tabel grid 2D (seperti _spreadsheet_) untuk mencatat koneksi.
    
2. **Adjacency List (Daftar Ketetanggaan):** Menggunakan _Dictionary/Hash Map_ di mana setiap titik hanya mencatat siapa saja tetangga langsungnya.
    

## 2. Analogi: Jejaring Sosial (Facebook / Instagram)

Bayangkan Anda ingin menyimpan data pertemanan 5 orang: Andi, Budi, Citra, Denis, dan Eka.

- **Cara 1: Adjacency Matrix (Buku Absen Raksasa)**
    
    Anda membuat tabel dengan 5 baris dan 5 kolom. Jika Andi berteman dengan Budi, Anda menaruh angka `1` di kotak pertemuan mereka. Jika tidak, angka `0`.
    
    _Kelemahan:_ Bagaimana jika Facebook punya 2 Miliar pengguna? Anda harus membuat tabel berukuran 2 Miliar x 2 Miliar! Padahal rata-rata orang hanya punya 300 teman. Sisa 1.999.999.700 kotak di tabel itu hanya berisi angka `0` (sangat boros memori!).
    
- **Cara 2: Adjacency List (Buku Kontak HP)**
    
    Anda membuat daftar sederhana. Anda menulis nama "Andi", lalu di sebelahnya Anda hanya menulis orang-orang yang **benar-benar** berteman dengan Andi (misal: Budi dan Citra). Anda mengabaikan miliaran orang lain yang tidak berteman dengannya.
    
    _Keunggulan:_ Ini sangat hemat memori dan menjadi standar industri untuk sebagian besar aplikasi dunia nyata.
    

## 3. Poin-Poin Penting (Pertarungan Efisiensi)

- **Space Complexity (Penggunaan Memori RAM):**
    
    - **Matrix:** $O(V^2)$ (di mana $V$ adalah jumlah _Vertices_/Titik). Sangat boros untuk jaringan yang longgar (_Sparse Graph_).
        
    - **List:** $O(V + E)$ (di mana $E$ adalah jumlah _Edges_/Garis). Sangat hemat karena hanya menyimpan garis yang benar-benar ada.
        
- **Time Complexity (Kecepatan Cek Koneksi):**
    
    - Jika Anda ingin bertanya, _"Apakah Andi berteman dengan Eka?"_
        
    - **Matrix:** $O(1)$ (Sangat cepat! Tinggal lihat baris Andi, kolom Eka. Apakah nilainya 1?).
        
    - **List:** $O(V)$ (Agak lambat. Anda harus membuka daftar teman Andi, lalu memutar _loop_ untuk mencari nama Eka satu per satu).
        
- **Kapan Menggunakan Apa?** Gunakan **Matrix** jika grafiknya sangat padat (_Dense Graph_ - hampir semua titik saling terhubung) atau memori bukan masalah. Gunakan **List** untuk hampir semua kasus dunia nyata (peta jalan, media sosial, jaringan internet).
    

## 4. Contoh Implementasi

Mari kita bangun jaringan pertemanan menggunakan **Adjacency List** di **JavaScript**. Kita akan memanfaatkan `Map` atau objek untuk menyimpan daftarnya:

JavaScript

```
class SocialNetworkGraph {
    constructor() {
        // Kita gunakan Object/Hash Map sebagai buku kontak
        this.bukuKontak = {}; 
    }

    // 1. Tambah Orang Baru (Vertex)
    tambahOrang(nama) {
        if (!this.bukuKontak[nama]) {
            this.bukuKontak[nama] = []; // Siapkan daftar teman kosong
        }
    }

    // 2. Tambah Pertemanan (Edge - Dua Arah)
    tambahPertemanan(orang1, orang2) {
        // Andi menambahkan Budi ke daftarnya
        this.bukuKontak[orang1].push(orang2);
        // Budi juga menambahkan Andi ke daftarnya (Undirected Graph)
        this.bukuKontak[orang2].push(orang1);
    }

    // 3. Cetak Jaringan
    cetakJaringan() {
        for (let orang in this.bukuKontak) {
            let daftarTeman = this.bukuKontak[orang].join(", ");
            console.log(`${orang} berteman dengan: [${daftarTeman}]`);
        }
    }
}

// --- MARI KITA BANGUN JEJARING SOSIAL KITA ---
let facebookMini = new SocialNetworkGraph();

// Mendaftar pengguna baru
facebookMini.tambahOrang("Andi");
facebookMini.tambahOrang("Budi");
facebookMini.tambahOrang("Citra");
facebookMini.tambahOrang("Denis");

// Membuat koneksi pertemanan
facebookMini.tambahPertemanan("Andi", "Budi");
facebookMini.tambahPertemanan("Andi", "Citra");
facebookMini.tambahPertemanan("Budi", "Denis");

facebookMini.cetakJaringan();
/* OUTPUT:
Andi berteman dengan: [Budi, Citra]
Budi berteman dengan: [Andi, Denis]
Citra berteman dengan: [Andi]
Denis berteman dengan: [Budi]
*/
```

## 5. Koneksi dengan Web Development

Pemahaman tentang _Graph_ adalah tiket masuk untuk membangun fitur-fitur "cerdas" di web:

1. **Fitur "Orang yang Mungkin Anda Kenal" (Rekomendasi):** Sistem melihat _Adjacency List_ Anda. Anda berteman dengan Budi. Budi berteman dengan Denis. Tetapi Anda belum berteman dengan Denis. Sistem akan menyarankan Denis kepada Anda (disebut _Mutual Friends Analysis_).
    
2. **Google Maps / Routing:** Saat Anda mencari rute ojek _online_, setiap persimpangan jalan adalah _Vertex_, dan jalan rayanya adalah _Edge_. Algoritma seperti Dijkstra berjalan di atas _Graph_ ini untuk mencari jalur terpendek dan menghindari kemacetan.
    
3. **Jaringan Server Internet:** Arsitektur _microservices_ (di mana puluhan _server_ saling berkomunikasi satu sama lain) divisualisasikan dan dipantau kinerjanya menggunakan struktur _Graph_ agar _developer_ tahu _server_ mana yang menjadi "leher botol" (_bottleneck_).
